# 原型精度分级与选型

> 三剪客原创方法。内容来自公开的快速原型实践与自身项目经验整理，正文为原创组织，不含任何第三方项目的源码或文档译文。

这一份只回答一个问题：**这个阶段该不该做原型，做的话做到哪一档就够。**

绝大多数原型浪费不是因为做得丑，而是因为**做过头了**——用一个高保真原型去验证一个纸面就能推翻的假设，或者用一个草图去说服一个必须看到真实数据才点头的人。选错档位，等于把钱和时间花在了错误的精度上。

---

## 1. 先过门槛：该不该做原型

动手前，四个问题逐个问。答不上来的那一条，就是你现在真正该干的活。

### 四问

| 问题 | 通过标准 | 答不上来时该干什么 |
|---|---|---|
| **1. 你要验证哪一个假设？** | 能用一句话说完，且这句话**可能被证伪**（「用户愿意为了省 10 分钟而多填一张表」而不是「用户需要效率工具」） | 假设太宽，先做目标收敛（见 `02-制作流程与模板.md` 第 1 步） |
| **2. 验证结果会改变你的行动吗？** | 会。说清「如果是 A 就做 X，如果是 B 就停」 | 不会改变行动 → 做原型毫无意义，直接按已有判断推进 |
| **3. 有没有更便宜的办法拿到同样答案？** | 没有。数据、访谈、竞品已有功能、已有用户反馈都用过了 | 有 → 先用便宜办法，别做原型 |
| **4. 有没有一个具体的观众和截止时间？** | 有名字或角色，有日期 | 没有 → 原型会无限膨胀，先定观众和 deadline |

**判定口径**：四问里有两条以上答不上来，就**不要开始做原型**。这不是拖延，是防止你用一个精心制作的错误答案替代真正的问题。

### 三种不做原型的正当理由

1. **答案已经在手里**：已有数据或反馈足够支撑决定，做原型只是自我安慰。
2. **成本低于判断成本**：这件事直接做出来的成本比做原型的成本还低（比如改一句文案、加一个按钮），那就直接做。
3. **不可逆性为零**：随时能改、改错没损失的事情，不需要原型来防风险。

### 一个容易搞混的分界

原型回答的是「**方向对不对**」，不是「**能不能做出来**」。技术可行性用技术验证（写一个只跑一次的脚本、搭一个最小接口调用）解决，那不是原型，是探针。两者都要做的时候，先做探针——因为方向对了但做不出来，比方向错了更贵。

## 2. 四档精度：各自的成本、适用场景与退出条件

四档的差别不在「好看程度」，而在**能验证什么、不能验证什么**。成本以「人·天」为单位，指**一个人从头到尾投入的工作日**；实际数字随熟练度和素材齐备程度浮动，当作量级参考，不要当报价。

| 档位 | 载体形态 | 成本量级（人·天） | 能验证什么 | 验证不了什么 | 退出条件（做到这一步就停） |
|---|---|---|---|---|---|
| **L0 纸面草图** | 手绘框图、便签、白板照片，5~10 张 | **0.2 ~ 0.5** | 概念是否被听懂、流程顺序是否合直觉、范围有没有跑偏 | 视觉、交互反馈、真实操作效率 | 关键路径的每一步都能指着图讲清楚，且听的人能复述回来 |
| **L1 低保真可点** | 线框图 + 跳转链接，无配色无真实内容，灰盒 | **1 ~ 2** | 信息架构、页面之间的流转、命名与措辞、用户能否自己找到路 | 视觉吸引力、品牌感受、微交互体验 | 5 个人能**无人指导**走完关键路径，卡点全部记录在案 |
| **L2 中保真交互** | 接近最终视觉的静态界面 + 点击跳转 + 少量假数据/动效 | **3 ~ 5** | 焦点是否清晰、文案是否说得动、用户对核心价值的反应、是否愿意留下联系方式 | 真实性能、真实数据规模下的体验、长期留存 | 关键动作的完成率达标，且**至少 3 人**主动问「这个什么时候能用」 |
| **L3 高保真 / 半可用** | 真实视觉 + 部分真实逻辑，后端可用假数据或半接通 | **7 ~ 20+** | 视觉与品牌的接受度、接近真实的操作成本、销售或融资演示的现场说服力 | 依然验证不了真实留存与付费意愿（这两件事只能靠真实上线看） | 演示能一次跑完不翻车；且**必须在开工前**写好「什么时候停止打磨」的日期 |

### 成本结构：钱花在哪

理解成本构成，才知道哪一刀能砍：

- **L0 → L1**：成本主要在「把流程想清楚」。砍法：减少页面数，只画关键路径。
- **L1 → L2**：成本主要在「视觉与文案」。砍法：复用现成设计系统或组件库，不自己调像素。
- **L2 → L3**：成本主要在**接真实逻辑**（接口、状态、异常分支、边界情况）。这一档的成本曲线最陡，因为「能跑通一次」和「能稳定跑通」之间隔着大量异常处理。
- **隐藏成本**：素材准备（真实文案、图标、图片、数据）往往占掉 L2/L3 的三成以上。提前一天把素材凑齐，能省掉后面反复停工等待。

### 关键判断：档位由「观众」和「风险」共同决定

| 你的观众是 | 需要的最低档位 | 理由 |
|---|---|---|
| 自己 / 一起做的人 | L0 | 你不需要说服任何人，只需要把想法外化 |
| 内部同事 / 跨部门评审 | L1 | 他们关心的是流程和范围，不是颜色 |
| 目标用户（做可用性测试） | L1 ~ L2 | L1 就能暴露大部分迷路问题；要测「想不想要」才需要 L2 |
| 老板 / 决策人 | L2 | 决策人靠**完整感**判断投入，灰盒容易被当成「没想清楚」 |
| 客户 / 投资人 | L3 | 现场说服力是硬要求，L2 之前基本无解 |

记住一句话：**观众越远、越不熟悉你的问题域，档位就得越高**——不是因为你做得不好，而是因为对方缺少替你补全想象力的上下文。

## 3. 选型决策树

从顶往下走，第一个匹配上的就是你要的档位，然后**在此停住**，不要顺手往上加。

```
你需不需要让「不是你自己」的人点头？
├─ 不需要（只给自己或同伴看）
│   └─ L0 纸面草图 —— 半天之内出，出完立刻拿去讨论
└─ 需要
    ├─ 你要验证的是「用户能不能自己走通」？
    │   └─ L1 低保真可点 —— 别配色，配了就会有人开始讨论颜色
    ├─ 你要验证的是「用户想不想要 / 愿不愿意留联系方式」？
    │   └─ L2 中保真交互 —— 视觉要对，因为它在替你说话
    └─ 你要拿去现场演示、卖、或融资？
        └─ L3 高保真 —— 但先写下停止打磨的日期，再动手
```

### 三种常见场景的直接结论

- **新功能验证（已有产品上）**：L1 起步。已有产品自带视觉语境，用户会自行脑补，不需要你重画配色。
- **0 到 1 的新产品方向**：L0 先做一轮，淘汰掉一半方向，剩下的升到 L2。**不要**一上来做 L3——你还没确定要做哪个。
- **对外演示 / 销售物料**：直接 L3，且明确它是**演示件**而不是产品：所有演示路径要手动钉死，不接真实支付，异常分支直接跳过。

## 4. 加档与减档信号

档位不是一次定死的，但改动必须有信号，不能凭感觉。

### 该加档的信号（出现两条以上）

- 用户反复问同一个功能**长什么样**，说明灰盒已经无法承载沟通
- 评审会总在讨论视觉和感受，而不是流程 —— 说明对方要的是完整感
- 已经连续两轮反馈命中同一个**没做出来的**东西，而这个东西正是要验证的核心
- 需要拿去现场演示，且现场不能出丑

### 该减档的信号（出现任何一条即可行动）

- 讨论时间超过制作时间：三轮会开下来还在争论，说明想得太细了，退回上一档
- 反馈开始重复：连续 3 个人的意见高度一致，说明当前档位的信息量已经饱和，再精致也不会带来新结论
- 时间超预算 50%：不要延长时间，**砍范围**（见 `02-制作流程与模板.md` 的裁剪规则）
- 有人开始问「这个能不能直接上线」：说明精度已经越过验证需要，进入生产错觉区，立刻收手

### 一条硬规则

**任何一轮原型都必须有一个时间盒。** 时间盒到了就停止制作，带着当前状态去做一轮反馈。半成品原型给出的反馈，比完美原型晚三天给出的反馈更值钱。

时间盒的粗口径：把上面表里的成本量级乘 1.5 作为上限，超过就砍范围而不是延工期。

## 5. 假设的分类：哪些能靠原型验，哪些不能

选错档位的深层原因，往往是**假设类型和原型能力不匹配**。

| 假设类型 | 原型能不能验 | 该怎么验 |
|---|---|---|
| 用户能不能理解这个概念 | **能**，L0/L1 就够 | 让 5 个人复述一遍，看是否走样 |
| 用户能不能自己走完流程 | **能**，L1 | 无人指导观察，记录卡点 |
| 用户觉得这个值不值 | **部分能**，L2 | 看是否有主动追问、是否愿意留联系方式；但意愿 ≠ 付费 |
| 用户会不会真的付钱 | **不能** | 真实上线、预售、定金、真实定价页 |
| 用户会不会长期用 | **不能** | 只有真实上线后看留存 |
| 这个方案技术上做不做得出来 | **不能** | 技术探针（一次性脚本、最小接口调用） |
| 团队内部能不能达成一致 | **能**，L1/L2 | 用原型当讨论载体，把分歧钉在具体界面上 |

**这条表最重要的用法**：如果一句话被归到「不能」那几行，就不要用原型去证明它——那是自欺。用原型硬撑出来的「用户说会付钱」，是所有错误投入里最贵的来源。

## 6. 选型层面的五种典型错误

1. **用高保真验证概念**：三周做出漂亮页面，结果概念本身就没被听懂。正确顺序是 L0 先过一遍听懂测试。
2. **在低保真上争论视觉**：灰盒阶段讨论配色，是典型的精力错配。灰盒阶段只允许讨论流程、命名和范围。
3. **档位随人涨**：每个人看完都想加一点，最后变成一个谁也不认得的四不像。对策是档位在开工前写进目标卡，中途改动要留记录。
4. **把技术探针当原型**：花两周搭了个能跑的接口，然后发现没人要这个功能。技术探针必须先有方向结论再动手。
5. **没有退出条件**：永远在「再改一版」。对策是把停止条件写成一句话，贴在目标卡第一行。

## 7. 一页速查

```
该不该做？  → 四问里至少 3 条能答上来，且结果会改变行动
做到哪档？  → 给自己看 L0 ｜ 验流程 L1 ｜ 验想要 L2 ｜ 对客户/投资人 L3
什么时候停？→ 时间盒一到就停；反馈开始重复就停；有人问「能不能上线」就停
会不会白做？→ 只要它推翻或确认了一个具体的假设，就不算白做
```
