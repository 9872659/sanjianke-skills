# 反馈收集与决策

> 三剪客原创方法。正文为原创组织。

原型做完只是拿到了一次提问的资格。**反馈收得好不好，直接决定这一轮是白做还是值回票价。** 这一份管三件事：怎么问、怎么记、怎么下结论。

---

## 1. 样本量与场次设计

| 项目 | 建议 | 理由 |
|---|---|---|
| 一轮人数 | **5 人**（至少 3 人） | 小样本足以暴露大部分「迷路」类问题；第 6 个人开始重复 |
| 场次形式 | **1 对 1，单独做** | 集体评审会产生从众，第一个发言的人定调，后面全在附和 |
| 单场时长 | **25~35 分钟** | 超过 40 分钟注意力下降，反馈质量断崖 |
| 轮次节奏 | 一轮做完改完再做下一轮 | 边做边问会让不同人的反馈指向不同版本，无法归因 |
| 记录人 | 1 人主持、1 人记录（能分工就分工） | 主持人一边问一边记，必然漏掉行为和表情 |

### 人怎么选（按优先级）

1. **真正的目标用户**，且**不是你团队的人**——最好。
2. 满足「目标用户的角色特征」的邻近岗位同事（比如为客服做的东西，找另一个部门的客服）。
3. **绝对不要**找：直接向你汇报的人、正在跟你竞争资源的人、参与过这个原型制作的人、你的直属领导（除非目的就是拿预算）。

### 一个必须提前接受的现实

熟人倾向于说好话。所以本方法的防线是：**不问意愿，只问过去的行为和现场的动作**。行为骗不了人，意愿可以。

---

## 2. 一场反馈的完整结构（30 分钟）

| 阶段 | 时长 | 做什么 | 关键动作 |
|---|---|---|---|
| 0 铺垫 | 3 分钟 | 说明「我在测这个原型，不是在测你」；请他放开吐槽 | 明确说「按钮点不动是正常的，你就说我期待出现什么」 |
| 1 背景 | 5 分钟 | 问他**现在**怎么做这件事 | 只问过去，不问未来；记录他用的工具和真实痛点 |
| 2 任务 | 10 分钟 | 给一个任务，让他自己操作，你不说话 | 任务用「你想完成某件事」的口吻，不要念功能名 |
| 3 追问 | 8 分钟 | 针对卡点逐个追问 | 用第 3 节的追问链，一次只问一个 |
| 4 收尾 | 4 分钟 | 让他给整体印象 + 一个必问问题 | 必问：「如果明天就能用，你第一件事会拿它干什么？」 |

### 主持人纪律（比问题设计更重要）

- **不解释**：他问「这个按钮干什么的」，回「你觉得它应该是干什么的？」
- **不辩护**：他说「这样很别扭」，回「哪里别扭，你本来期待什么？」，不要说「因为后面还要……」
- **不推销**：不描述未来功能，不给愿景。原型只呈现当下。
- **不承诺**：不说「下版加上」，那会让后面几场的人都在猜你要做什么。
- **接受沉默**：卡住时先数 5 秒，很多人会自己说出最关键的一句话。

### 任务该怎么出

| 差的出法 | 好的出法 |
|---|---|
| 「你试试这个汇总功能」 | 「假设现在是周五下午，你要把团队这周的进展整理给老板，你会怎么做」 |
| 「点右上角那个按钮」 | 不说话，观察他能不能自己找到 |
| 「你觉得这个流程顺吗」 | 「请把刚才的操作再做一遍，一边做一边说出你在想什么」 |

## 3. 五段式追问链

卡点出现后，按这五段往下钻。**一次只走一段**，走到答案具体为止。

```
① 复述：你刚才期待看到什么？
   → 目的：把「困惑」翻译成具体的预期
② 归因：是什么让你觉得这里应该是这样？
   → 目的：找出他心里参照的旧经验或竞品
③ 影响：如果这里真的没给你，你会怎么办？
   → 目的：判断卡点是致命的还是绕得过去
④ 频率：这件事你多久遇到一次？
   → 目的：区分真痛点还是偶发不便
⑤ 代价：你现在是怎么解决它的？花了多少时间/钱？
   → 目的：拿到「现在已经在付的成本」，这是最硬的证据
```

第 ⑤ 段是全链最值钱的一段。**已经在为这个问题付钱、付时间、付人力的人，才是真需求。** 只是说「挺需要的」的人，不是。

---

## 4. 分类问题库

按你要验证的东西挑，每场不要超过 8 个问题。

### A. 现状与频次（背景阶段用）

- 上一次遇到这个情况是什么时候？当时具体发生了什么？
- 这件事一周发生几次？谁最烦它？
- 你现在用什么工具/流程处理它？花了多久？
- 过去有没有因为这件事出过问题？怎么补救的？

### B. 任务过程（观察阶段用，多用于追问）

- 你刚才在找什么？找到了吗？
- 这里你停顿了一下，当时在想什么？
- 如果这一步不存在，你会怎么做？
- 你觉得这一步之后应该发生什么？

### C. 价值感知（收尾阶段用）

- 如果这个东西明天就能用，你第一件事会拿它做什么？
- 它替你省下的时间，你会用去做什么？
- 你会把它推荐给谁？为什么是他？
- 有什么会让你**不用**它？

### D. 替代方案与取舍

- 你现在是怎么绕开这个问题的？
- 如果只能保留这里的一个功能，你留哪个？
- 你愿意为它换掉现在的某个工具吗？换掉哪个？

### E. 意愿与承诺（谨慎使用）

- 如果它下个月能用，你愿意先当试用的人吗？（要让他**付出一个具体动作**：留联系方式、加群、约下一次）
- 你会为它付钱吗？—— 这个问题**只在已经有真实定价时**才问，否则答案没有参考价值

### 三类不问的问题

1. **假设性意愿**：「你会用吗」「你觉得好不好」——人情会给你一个假答案。
2. **引导性问题**：「是不是觉得这个流程有点绕？」——你在替他给答案。
3. **多选题**：「你觉得是 A 问题还是 B 问题？」——他会两个都选，或者顺着你的语气选。

## 5. 记录法：原话 + 行为

一边问一边记，格式固定成两列，缺一列就不算记录。

```markdown
## 场次 #__  时间：____  对象角色：____  是否目标用户：是/否

### 背景（他现在的做法）
- 原话：「____」
- 现状事实：每周 __ 次，用 ____ 工具，耗时约 __

### 任务过程
| 步 | 他做了什么 | 原话 | 行为观察 |
|---|---|---|---|
| 1 | | | 停留 __ 秒 / 皱眉 / 找不到入口 |
| 2 | | | |

### 卡点清单
| 卡点 | 追问链走到了哪一段 | 他的答案 | 我的判断（致命/可绕/噪音） |
|---|---|---|---|

### 收尾
- 第一件事会拿它做什么：____
- 主动提出的问题：____
- 是否愿意留下联系方式/约下一次：是 / 否

### 主持人自评
- 我有没有解释过？有没有辩护过？哪里引导了？
```

### 行为观察记什么（这些比原话更硬）

- **第一次点击的位置**：他想找的东西在哪里，比他说想要什么更真实
- **停留时长**：超过 5 秒的沉默就是一次困惑
- **回退与重复**：反复点同一个地方，说明预期和结果不匹配
- **跳过**：他没点你认为最重要的那一步，说明它的重要性没被感知
- **表情与语气**：突然来兴趣的瞬间，通常对应真正的价值点
- **他自己提出来的问题**：主动提问是最强的正向信号

---

## 6. 信号强度分级

5 场做完，把所有记录汇总成信号表。**只有强信号能支撑「加码」。**

| 强度 | 信号 | 说明 |
|---|---|---|
| **强** | 付出具体成本：留下联系方式、约下一次、问价格、要拿去给同事看 | 行为的成本越高，信号越真 |
| **强** | 主动提问：「能接我们的数据吗」「什么时候能用」 | 他在替你做需求延伸，说明进入了他的语境 |
| **强** | 复述准确：能用自己的话把核心价值讲对 | 概念传达到位 |
| **中** | 任务完成且无致命卡点，但全程平淡 | 可用，但不一定要 |
| **中** | 指出了同一个缺失功能（≥3 人提到同一处） | 方向对了，范围错了 |
| **弱** | 「挺好的」「有意思」这类无内容的正面评价 | 人情分 |
| **弱** | 建议加功能但没有对应的痛点故事 | 在替你设计，不是在表达需求 |
| **负** | 需要你反复解释才懂 | 概念不成立，或观众选错了 |
| **负** | 明确说「我们现在用 XX 就够了」 | 现状已经够好，除非你说清切换理由 |

### 归因规则

- 同一个卡点出现在 **≥3 人** 身上 → 是真问题，不是个人习惯，下一轮必须处理
- 同一个卡点只出现 **1 人** → 记下来，不要为它改方向
- 好评集中在**视觉**而任务完成率低 → 这是危险信号：好看掩盖了不好用

## 7. 决策矩阵

把汇总结果套进矩阵，出口只有三个。

| 观察到的组合 | 结论 | 下一步动作 |
|---|---|---|
| 任务完成率高（≥4/5 走通）**且**至少 2 个强信号 | **加码** | 重写目标卡，升档或接真实数据；下一轮验证「愿不愿意付钱/长期用」 |
| 任务能走通 **但**零强信号 | **改方向** | 价值点没被感知；回第 1 步重写假设——通常是把「工具」当成了「价值」 |
| ≥3 人命中同一缺失 | **改方向** | 假设方向对、切入点错；按被指出的那个缺口重设关键路径 |
| 需要反复解释才懂（≥3 人） | **止损或换观众** | 先确认是不是观众选错；观众没错就止损 |
| 任务完成率低（≤2/5 走通）**且**卡点分散 | **退回上一档** | 不是方向问题，是精度不够：L1 的信息量不足以支撑判断 |
| 明确被告知现状够用，且说不出切换理由 | **止损** | 写清停止理由存档，把资源移到下一个想法 |
| 连续三轮反馈命中同一个未解问题 | **止损（硬线）** | 见下方止损线 |

### 止损线（满足任一条即停止）

1. **三轮同一问题**：同一个未解决的问题连续出现三轮，说明这不是原型能解决的层次（可能是组织、数据或成本问题）。
2. **时间盒 ×2**：一轮原型的实际耗时超过原计划两倍，说明范围失控，先停再重设。
3. **零强信号两轮**：两轮下来没有任何人愿意付出具体成本，停止。
4. **只能靠解释存活**：你自己都发现「必须我站在这儿讲才成立」，停止。

止损不是失败。**一个被原型及时否掉的方向，就是这套方法最成功的一次使用。** 写下停止理由，半年后如果条件变了还能捡回来。

## 8. 常见偏差与对策

| 偏差 | 表现 | 对策 |
|---|---|---|
| **礼貌偏差** | 熟人一律说好 | 找非同事；只认行为信号 |
| **引导偏差** | 你的问法里带着答案 | 每场结束后自评「我有没有引导」，写进记录 |
| **确认偏差** | 只记住支持自己判断的反馈 | 强制汇总所有 5 场，先写「最反对的那条」 |
| **精致度偏差** | 高保真原型让人不好意思批评 | 高保真轮次里，主持人开场必须强调「视觉是临时占位」 |
| **首因偏差** | 前两场定了调，后面全在验证 | 记录按场次编号分开写，结论等 5 场齐了再下 |
| **抽样偏差** | 5 个人全是相似背景 | 至少留 1 个位置给「边缘用户」或「明确不需要的人」 |
| **成功学偏差** | 只汇报通过率，不汇报反例 | 结论里必须写「这一轮**没有**证明什么」 |

```markdown

## 原始假设（抄目标卡第 1 条）
____

## 关键数字
走通人数：__/5 ｜ 强信号数：__ ｜ 致命卡点数：__ ｜ 主动提问人数：__

## 三个最硬的证据（原话 + 行为）
1. ____
2. ____
3. ____

## 结论
加码 / 改方向 / 止损 —— 因为 ____

## 下一轮的目标卡要点（如果继续）
- 假设改为：____
- 档位：L__（升/降档理由：____）
- 时间盒：__ 天

## 这一轮【没有】证明什么
- ____（必须写，防止过度外推）

## 如果止损：停止理由与重启条件
- 停止理由：____
- 什么条件下值得重启：____
```

### 归档位置

放在项目自己的文档目录里，一轮一份，不要覆盖上一轮。**跨轮对比本身就是最有价值的数据**：三轮同一个卡点没解决，就是第 7 节止损线第 1 条的触发依据。

## 一页速查

```
问谁：5 个目标用户，1 对 1，30 分钟，绝不集体评审
怎么问：先问过去怎么做 → 给任务不说话 → 五段追问链 → 收尾问「明天会拿它干什么」
怎么记：原话 + 行为两列，缺一不算记录
怎么看：≥3 人同一卡点=真问题；强信号=愿意付出具体成本
怎么定：加码 / 改方向 / 止损，三选一，必须写「这一轮没证明什么」
```
