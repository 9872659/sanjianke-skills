# 制作流程与模板

> 三剪客原创方法。正文为原创组织，模板可直接抄用。

这一份是执行层：**目标收敛 → 关键路径抽取 → 最小可验证版本 → 反馈收集**，四步走完算一轮。每一步都有产出物、模板和完成判据，做完能立刻拿去讨论。

---

## 全流程一览

| 步 | 名称 | 耗时 | 产出物 | 完成判据 |
|---|---|---|---|---|
| 1 | 目标收敛 | 30~60 分钟 | 原型目标卡（一页） | 假设能被证伪，行动分支写死 |
| 2 | 关键路径抽取 | 30~60 分钟 | 关键路径表 + 不做清单 | 路径能一口气走完，无断点 |
| 3 | 最小可验证版本 | 时间盒内（0.5~5 天常见） | 可点的原型 + 演示脚本 | 陌生人能自己走完 |
| 4 | 反馈收集 | 每场 30 分钟 × 5 场 | 反馈记录 + 决策结论 | 落到加码/改方向/止损三选一 |

**循环节奏**：一轮走完再开下一轮。不要并行做两版原型——你会开始比较精致度而不是比较结论。

---

## 第 1 步：目标收敛（30~60 分钟）

目的不是把想法写全，而是把想法**砍到只剩一个待验证的问题**。

### 原型目标卡（模板，直接抄）

```markdown
# 原型目标卡 · <项目名> · 第 <N> 轮
日期：____  时间盒：____（不超过 __ 天）

## 1. 一句话假设（本轮唯一要验证的东西）
我认为 <某类人> 在 <某场景> 下，会因为 <某机制> 而 <某行为>。

## 2. 被证伪的样子（写清楚什么结果算「这个假设错了」）
如果出现 ____，就说明假设不成立。

## 3. 行动分支（结果会怎么改变我们的决定）
- 如果假设成立 → 下一步做 ____，在 ____ 之前
- 如果不成立 → 停止 ____，改为 ____

## 4. 观众与用途
谁看：____（具体角色）｜看完要做什么决定：____
需要的最低档位：L__（依据：references/01 的选型决策树）

## 5. 本轮不做什么（至少 3 条）
- 不做 ____
- 不做 ____
- 不做 ____

## 6. 止损条件
时间盒到期 / 反馈开始重复 / 有人问「能不能直接上线」→ 立刻停止制作，进入反馈
```

### 填写示例（内部工具的完整一轮）

```markdown
# 原型目标卡 · 周报汇总工具 · 第 1 轮
日期：3/12  时间盒：2 天

## 1. 一句话假设
我认为 5~20 人小团队的项目负责人在周五下午汇总周报时，
会因为「填表入口和上周数据同时可见」而把汇总时间压到 15 分钟以内。

## 2. 被证伪的样子
如果 5 个人里有 3 个人上手后仍然要说「我得先翻聊天记录」，
说明真正的瓶颈不是界面，而是数据来源本身没收拢。

## 3. 行动分支
- 成立 → 投入做真实版，先只接一个数据来源
- 不成立 → 停下界面工作，先解决「自动收集」这一层

## 4. 观众与用途
5 位内部项目负责人｜看完要决定是否投入 3 周做真实版
最低档位：L1（依据：验证的是「能不能自己走通」，不是想不想要）

## 5. 本轮不做什么
- 不做权限与账号体系
- 不做导出 PDF
- 不做历史版本对比
- 不做移动端

## 6. 止损条件
2 天到点即停；若 3 人以上反馈指向同一缺失功能，停止补功能，直接记录结论
```

### 三个常见坑

1. **假设写成口号**：「用户需要更高效的工具」不可证伪，等于没写。必须能被某个具体观察推翻。
2. **行动分支缺失**：写不出「如果不成立就怎样」，说明这个问题你其实不打算改主意，那就不必做原型。
3. **不做什么留空**：空着的「不做清单」等于默认全做。这一栏是本卡最有价值的部分。

### 完成判据（朗读测试）

把第 1 条和第 2 条念给一个不了解背景的人听，他能说出「所以你要看的是某某现象，对吧」——通过。他反问「这怎么测」——回去重写。

## 第 2 步：关键路径抽取（30~60 分钟）

关键路径 = **主要用户为了完成核心任务，必须走过的最短动作串**。不是全部功能，是那一条线。

### 关键路径表（模板）

```markdown
| # | 用户想干什么 | 他需要看到什么 | 他做什么动作 | 系统给出什么反应 | 本步要验证/记录什么 |
|---|---|---|---|---|---|
| 1 | | | | | |
| 2 | | | | | |
| 3 | | | | | |
```

规则：
- **只写一条路径**。分叉（比如「失败会怎样」）单独列成附注，不要塞进主表。
- 每一格的「系统反应」都必须具体。写「显示列表」不合格，写「显示最近 7 天的 12 条记录，按时间倒序」合格。
- 中间不能有「这里以后再说」。出现了就把这一步删掉，或者把它变成路径的一环。

### 填写示例（续上例）

| # | 用户想干什么 | 他需要看到什么 | 他做什么动作 | 系统给出什么反应 | 本步要验证/记录什么 |
|---|---|---|---|---|---|
| 1 | 知道谁还没交 | 5 人名单 + 已交/未交状态 | 打开页面 | 显示名单，未交的排在前面并高亮 | 一眼能不能看懂「谁没交」 |
| 2 | 提醒没交的人 | 未交人的名字 | 点某个人的名字 | 弹出提醒方式选择（不做真的发送） | 会不会去找「一键提醒全部」 |
| 3 | 汇总已交内容 | 上周同类内容的参照 | 点「汇总」 | 把已交内容拼成一页，上周内容缩在侧边 | 会不会先看上周再改 |
| 4 | 发出汇总 | 一个明确的发送入口 | 点「发出」 | 显示成功态 + 抄送对象 | 会不会犹豫「发出去还能改吗」 |

附注（非主路径，只在被问到才演示）：某人逾期 3 天后会发生什么。

### 从想法到路径的裁剪法

拿一张纸，把所有能想到的功能都写下来（这一步允许发散），然后逐个问三个问题，答「否」就划掉：

1. 没有它，核心任务完成不了吗？
2. 它属于**主要用户**吗？（次要角色的需求一律划掉）
3. 它能在本轮时间盒里做出来吗？

剩下的按完成任务的先后顺序排成一行，就是关键路径。

### 该切几条路径

| 情况 | 做法 |
|---|---|
| 只有一个明确角色 | 1 条主路径 + 1 条常见失败分支（只做说明，不做实现） |
| 两个角色但一个为主 | 只做主要角色；次要角色的入口画成静态说明页 |
| 两个角色同等重要 | **拆成两轮**，一轮一条。同轮做两条路径，反馈必然混在一起无法归因 |

### 完成判据

不看笔记，你能一口气把 4~6 步讲完，且每一步都能说出「用户此刻在想什么」。讲的时候出现「然后……呃，还要先……」——说明路径里有隐藏步骤，补上。

## 第 3 步：最小可验证版本

目标：**刚好够跑完关键路径，刚好够暴露假设**。多出来的每一分精致都在污染反馈。

### 裁剪矩阵（按维度砍，从上往下砍）

| 维度 | 这轮必须真 | 这轮可以用假的 |
|---|---|---|
| 流程节点 | 主路径每一步都存在且可点 | 失败分支、异常恢复、二次编辑 |
| 数据 | 1 条能说明问题的真实样例数据 | 分页、排序、搜索、批量、真实规模 |
| 视觉 | 焦点清楚、层级分明 | 配色系统、图标统一、动效、多端适配 |
| 账号 | 无（默认单一用户） | 登录、权限、团队协作、邀请 |
| 文案 | 主路径上的关键按钮和标题 | 帮助文案、空状态、错误提示 |
| 集成 | 用假数据或手填 | 真实接口、第三方登录、支付 |
| 端 | 只做一个端（观众会看的那个） | 另一个端的一切工作 |
| 埋点 | 手记或录屏 | 正式埋点系统 |

### 时间盒规则：时间固定、范围浮动

- 时间盒**不可延长**。到期就带着当前状态进入反馈。
- 范围**可以砍**。砍的顺序：先砍视觉精致度 → 再砍非主路径节点 → 最后砍路径长度（宁可少一步也不要多一个假按钮）。
- 如果砍到关键路径都不完整了，说明时间盒定得太短，**下一轮**再调，这一轮照常出结论。

### 每日同步卡（自用，15 分钟）

```markdown
日期：____
昨天路径走到第 __ 步 / 共 __ 步
今天要打通：____
卡住了：____（超过 2 小时没进展 → 直接跳过，用假数据顶上，记录下来）
是否已超出时间盒：是 / 否
```

### 演示脚本（做完必写）

原型做完了不等于会演示。写一段 5 句话的脚本，钉死**观众先看哪里、你点什么、你什么时候闭嘴**：

```markdown
1. 一句话交代场景：____（不讲背景超过 3 句，超过就说明原型没说服力）
2. 先点这里：____（第一屏必须能自己说明问题）
3. 走主路径的第 2、3 步，中途不说话，看对方反应
4. 到第 4 步停住，问一个开放问题：____
5. 不主动解释的坑：____（对方如果不提，就说明这个坑不重要）
```

最后一条很关键：**演示时不要替原型解释**。你自己解释掉的困惑，正是真实用户会当场流失的地方。

### 完成判据

找一个没参与制作的人（哪怕是同事），不给他任何提示，让他自己走。他能走完 → 通过。他卡住了 → 记录卡点，**不要当场改**，攒够一轮反馈再改。

## 第 4 步：反馈收集（每场 30 分钟 × 5 场）

完整方法（样本量、追问链、问题库、信号分级、决策矩阵）见 `references/03-反馈收集与决策.md`。这里给可以立刻抄的清单。

### 一轮反馈的执行清单

- [ ] **找 5 个人**，尽量不是自己团队的人；分成 5 场单独做，不要开成集体评审会
- [ ] **准备 4 类问题**：开场（他现在怎么做这件事）→ 任务（请他走一遍）→ 追问（为什么这么点）→ 收尾（如果明天能用，你会拿它干什么）
- [ ] **先问过去，不问未来**：「上一次你是怎么处理的」比「你会不会用」可靠十倍
- [ ] **不解释、不辩护、不引导**：对方卡住时，把「这里是这样的」换成「你本来期待看到什么」
- [ ] **双记录**：一份原话（直接引语），一份行为（点了哪、停了几秒、跳过哪、皱眉）
- [ ] **当场不做承诺**：不说「下版加上」，那会污染后面几场的反馈
- [ ] 5 场做完后**独自复盘 30 分钟**，再写结论；不要在最后一场的热度里下判断

### 反馈回来之后

按 `references/03` 的决策矩阵走，最终必须落到三选一：

| 结论 | 触发条件（简述） | 下一步动作 |
|---|---|---|
| **加码** | 关键路径通过率高 + 有人主动追问上线时间 | 定下一轮目标卡，升档或接真实数据 |
| **改方向** | 流程能走通但价值点没被感知 / 反馈集中在同一个缺失 | 回到第 1 步重写假设，档位可降可升 |
| **止损** | 概念需反复解释才懂 / 无人愿意留下联系方式 / 三轮反馈命中同一未解问题 | 写下停止理由并存档，把精力转走 |

## 五种废原型形态（对照自查）

| 形态 | 表现 | 根因 | 改法 |
|---|---|---|---|
| **过度精修** | 三周还在调阴影和间距，一次都没给人看过 | 把原型当作品集 | 立刻定反馈日期，到点就给人看 |
| **空心壳** | 界面很全，点下去全是「敬请期待」 | 关键路径没抽，直接开始画页面 | 回到第 2 步，只保留主路径 |
| **没有出口** | 做完发给对方，对方回「挺好的」，然后没有然后 | 缺目标卡和决策问题 | 每次演示必须绑一个待回答的决定 |
| **范围膨胀** | 每开一次会加两个功能，最后谁也说不清在验证什么 | 档位和「不做清单」中途被改 | 改动必须记录进目标卡，且要有人拍板 |
| **单向演示机** | 只能按写死的顺序演示，别人一点就崩 | 完全无真实逻辑，连假交互都没有 | 至少让主路径每个节点可点、可回退 |

## 两个完整示例（同一想法的不同档位）

### 示例 A：L0，半天出结论

- **想法**：给客服团队做一个「常见问题自动回」的助手。
- **该验证的**：客服能不能理解「助手建议 + 人工确认」这个概念。
- **做法**：10 张便签画 5 个画面：提问 → 助手给 3 条候选 → 选中 → 编辑 → 发送。白板照片即可。
- **问法**：让 3 位客服看一遍，请他们复述流程。有 1 人复述成「助手直接替我发」——概念没传达到，改文案和图形再测一轮。
- **成本**：半天。**结论**：概念可用，但「确认」这一步在视觉上必须比「发送」更重。

### 示例 B：L2，4 天出结论

- **想法**：把上面的助手做成真实产品方向，需要判断用户是否**想要**。
- **该验证的**：客服是否愿意把它加进日常工作流。
- **做法**：主路径可点，3 条候选用真实历史问答做假数据，视觉按最终稿做，不接任何真实接口。演示脚本 5 句，不做二次编辑。
- **问法**：5 位客服各 30 分钟；先问他们上周处理过的最烦的一个问题，再让他们走一遍。
- **结论**：流程能走通，但只有 1 人主动问「能不能接我们自己的知识库」——价值点感知不足，判定为**改方向**：真正的痛点在知识库维护，不在回复界面。
- **成本**：4 天，避免了一次 3 周的错误投入。

两个例子说明同一件事：**档位不是质量等级，是成本与问题的匹配**。示例 A 用半天干掉一个歧义，示例 B 用 4 天拦住一个错误方向，都算成功。

## 一页速查

```
1 目标收敛  → 一页目标卡：一个可证伪假设 + 行动分支 + 不做清单
2 关键路径  → 4~6 步，每步「看到什么/做什么/系统反应」写具体，只做一条主线
3 最小版本  → 时间固定、范围浮动；先砍精致度，再砍分支，最后砍步数
4 反馈收集  → 5 人 × 5 场单独做；问过去不问未来；双记录；结论三选一
```
