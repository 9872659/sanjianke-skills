# 三剪客 · 想法快速原型

把一个还模糊的想法快速做成能看、能点、能反馈的原型，先验证方向再决定是否投入

想法越模糊，越容易在「做出来再说」里烧掉几周甚至几个月。这套方法只干一件事：用最小的成本把一个想法变成**能看、能点、能得到真实反馈**的东西，然后让证据替你决定要不要继续投入。

它不追求好看的成品，追求的是**在最短时间内让最危险的假设暴露出来**。一个下午的纸面草图如果能推翻错误方向，它就比两周的精美界面更值钱。

## 触发场景

- 「我有个想法，但说不清到底要做什么，你能帮我理一下吗」
- 「这东西值不值得做？我想先做个东西给人看看再决定」
- 「要不要做原型？做到什么程度就够了，别让我白花时间」
- 「快速搭个能点的版本，下周拿去给老板/客户/几个用户看」
- 「已经做完一版了，接下来该问他们什么问题、怎么判断该不该继续」

## 快速开始

三步走，最快 40 分钟能出第一版结论：

1. **先过门槛**（10 分钟）：读 `references/01-原型精度分级与选型.md`，用「该不该做原型」四问筛一遍。四问里有两问答不上来，就不要动手做，先回到想法本身。
2. **再定档位与路径**（20 分钟）：按同一份里的四档精度对照表选一档，抄 `references/02-制作流程与模板.md` 里的**原型目标卡**和**关键路径表**，把「不做什么」写满。
3. **动手 + 收反馈**（半天到三天，看档位）：按流程做完最小可验证版本，用 `references/03-反馈收集与决策.md` 的追问链找 5 个人过一遍，再套决策矩阵出结论。

全程只产出 markdown 文档，不需要装任何工具。原型载体本身用什么（纸、画图工具、在线原型、可真机跑的页面）由用户按档位选，方法不绑定工具。

## 能力边界

**覆盖**：

- 判断某个阶段、某个想法**该不该**做原型，以及该做哪一档
- 低保真 / 中保真 / 高保真 / 半可用四档的**成本量级、适用场景、退出条件**
- 从模糊想法里**收敛出唯一一个待验证假设**，并抽出一条能跑通的关键路径
- 原型制作的四步流程，配可直接填写的目标卡、关键路径表、验收口径
- 一轮反馈的**问题清单、追问链、样本量与观察方法**
- 反馈回来之后的**决策矩阵**：加码 / 改方向 / 止损三种出路的判据

**不覆盖**：

- 具体原型工具的安装、配置、组件用法与代码实现（Figma、Axure、各种在线原型、前端脚手架等，一律不教）
- 生产级架构设计、数据库设计、性能与安全方案
- 真实用户招募渠道、投放买量、增长实验设计
- 商业计划的财务测算、融资材料撰写
- 替用户决定「这个想法好不好」——本 Skill 只给判据和流程，结论必须由真实反馈和用户自己拍板

## 依赖条件

- 一个**能被一句话说清的对象**：给谁、解决什么问题。说不清就先做目标收敛，不要跳到画界面
- 至少 5 个**能接触到的人**能做一轮反馈。一个都找不到时，先解决「找谁看」再谈原型
- 用户自己选定的原型载体（纸笔、画图工具、在线原型链接、能跑的页面都行），本 Skill 不指定工具

## 已知限制

- 方法论不能替代真实用户。所有示例、判据、阈值都来自公开的快速原型实践经验，具体到你的行业要自己校准
- 样本量小是这个方法的前提而不是缺陷：5 人一轮足以暴露大多数可用性问题，但**不适合**用来估市场规模或转化率，这两件事必须换成真实数据实验
- 高保真原型有强烈的「已经做完了」错觉，容易让人跳过验证直接投入；档位越高，越要强制写清退出条件
- 反馈会被人情污染：熟人倾向于说好话。所以本方法坚持问**过去的行为**而不是问**未来的意愿**
- 不覆盖工具教学，因此「怎么把草图变成可点击链接」这一步需要用户自己解决，或者在对话里单独问

## 自检清单

做完一轮，逐条核对：

- [ ] 这一轮只验证**一个**假设，而不是一口气验证五个
- [ ] 精度档位有明确理由，不是「顺手就做细了」
- [ ] 「本轮不做什么」写了至少 3 条，并且真的没做
- [ ] 关键路径能从头走到尾，中途没有断点或「这里以后再说」
- [ ] 反馈问题是问**过去发生过什么**，不是问「你觉得好不好」
- [ ] 至少找了 5 个人，且尽量不是自己的同事
- [ ] 观察记录里同时有**原话**和**行为**（哪里卡住、点了哪、跳过了哪）
- [ ] 结论落到了加码 / 改方向 / 止损三选一，并写了下一次的行动与时间点
- [ ] 结论里写清了「这一轮**没有**证明什么」，避免过度外推
