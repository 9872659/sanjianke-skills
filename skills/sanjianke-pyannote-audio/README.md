# 三剪客 · 说话人分离与日志化 Skill

pyannote-audio：说话人分离与日志化 的安装、常用命令与避坑要点

---

## 前置条件

- Python ≥ 3.10。
- `ffmpeg` 已安装且在 PATH 中。这是硬依赖：该库新版本只支持 ffmpeg 或内存中的音频作为解码后端。
- 一个模型托管站的访问令牌，并且已经在对应管线的页面上接受使用条款。没有这一步，加载预训练管线会直接被拒。
- 建议有 NVIDIA GPU。纯 CPU 也能跑，但官方教程说明可能慢到 10 倍实时，长音频不实用。
- 磁盘上要留出下载模型权重的空间，首次加载会从模型托管站拉取。

---

## 使用

拿到这个 Skill 后，Agent 会按这套顺序干活：

1. **先判断该不该用**。要的是「谁在什么时候说话」就用它；要的是文字转写、要实时流式、要认出具体是谁，都不该用它。
2. **确认环境**：`ffmpeg` 在不在、Python 版本够不够、令牌和条款有没有准备好。
3. **跑最小示例**：加载 `pyannote/speaker-diarization-community-1`，对一段两三分钟的音频跑通，看清返回对象的形状（新管线是 `output.speaker_diarization`，老管线是 `Annotation`）。
4. **切到 GPU**：`pipeline.to(torch.device("cuda"))`，否则默认跑在 CPU 上。
5. **按需调参**：说话人数已知就传进去；长音频按显存情况缩短输入或调小分段/批大小。
6. **对结果做校验**：抽查说话人切换点、核对人数，再决定要不要落盘成 RTTM 之类交给下游。

细节命令与完整避坑表见 `SKILL.md`。

## 依赖

- Python 包：`pyannote.audio`（推荐用 `uv add`，也可 `pip install`）。
- 系统依赖：`ffmpeg`。
- 深度学习栈：PyTorch 及其配套音频解码库，安装时由包自身的版本约束决定。官方曾专门钉住 `torch`/`torchcodec`/`torchaudio` 的版本以避免段错误，不要手工拆开升级其中某一个。
- 网络：首次加载需要访问模型托管站；离线部署要提前把整份管线仓库 clone 到本地。
- 凭证：模型托管站访问令牌；若用付费精度管线则另需对应的 API Key。

---

## 安全

- 不内嵌任何密钥，令牌与 API Key 一律由使用方通过参数或环境变量提供。
- 库内有一项**可选**的匿名用量上报。官方声明不采集可识别用户身份的信息（只记管线来源档次、管线类名、音频时长与说话人数参数），但合规敏感场景建议直接关闭：设环境变量 `PYANNOTE_METRICS_ENABLED=0`，或用 `pyannote.audio.telemetry.set_telemetry_metrics(False)`。
- 付费精度管线会把音频上传到第三方服务器处理。处理涉密、涉隐私素材前必须先过合规，或改用本地推理的开源管线。
- 处理他人录音前请自行确认取得授权；本 Skill 不提供任何合规判断，也不代为取得授权。
- 离线部署时，本地管线目录的读取权限应与普通模型文件同级管理，不要把令牌写进脚本里。
