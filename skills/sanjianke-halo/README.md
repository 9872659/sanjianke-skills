# 三剪客 · 自托管内容站点系统 Skill

一个可以自己掌控的建站与内容管理系统：带可视化后台、可换主题、可装插件，从个人博客到企业官网都能落地。

---

## 前置条件

- 一台能长期开机的机器（本地或云服务器均可），具备 Docker 环境或 Java 运行环境。
- 一个可选但强烈建议的域名；对外提供 HTTPS 时还需要证书与反向代理。
- 生产环境需要一个独立数据库：官方推荐 PostgreSQL，也支持 MySQL / MariaDB。
- 规划好数据目录的宿主机路径——所有内容、附件与配置都落在那里，也是备份对象。

---

## 使用

1. 用 Docker 快速体验：一条 `docker run` 起容器，映射 `8090` 端口并把工作目录挂到宿主机。
2. 进后台初始化：浏览器打开 `http://<ip>:8090/console`，首次启动进入初始化页面。
3. 定稿外部访问地址：初始化前先配好域名解析与反向代理，并用 `halo.external-url` 明确对外地址。
4. 转生产：改用 Docker Compose（或 JAR + systemd），数据库换成 PostgreSQL / MySQL，并按官方示例补上连接参数。
5. 日常运维：装主题与插件、开账号分角色、定期完整备份；升级走「备份 → 拉镜像 → 同参数重建容器」。

完整的六块操作说明（什么时候用 / 不用、安装、常用操作、常见坑、权限与用途说明、能力边界）见 `SKILL.md`。

## 依赖

- Docker 方式：Docker Engine；默认自带 H2 数据库，官方说明仅适合体验与测试。
- Docker Compose 方式：Docker + Compose，建议搭配独立的 PostgreSQL 容器或外部数据库。
- JAR 方式：2.21 以上版本需要 JRE 21，2.20 及以下版本需要 JRE 17；数据库需 MySQL 5.7+ / MariaDB / PostgreSQL 之一。
- 数据持久化：容器内工作目录固定为 `/root/.halo2`；JAR 方式默认工作目录为 `${user.home}/.halo2`。
- 反向代理：官方文档给出了 Nginx 与 Caddy 的配置示例，大附件场景要同步调整请求体大小限制。
- 可选：对象存储、短信等外部服务按需接入，属于使用方自行准备的资源。

---

## 安全

- 不内嵌任何密钥。数据库密码、管理员账号、对象存储密钥都由使用方自行生成与保管。
- 启动参数里会出现数据库明文密码，建议改用环境变量或配置文件并限制文件权限，不要把带密码的命令贴进公开仓库。
- 工作目录包含全部内容数据，务必纳入备份并限制访问权限；不要把工作目录放在可被公网访问的静态目录下。
- 管理后台不要在公网裸奔：对外暴露前配置 HTTPS、限流与访问控制，并给管理员设强密码。
- 官方明确不推荐在生产环境使用自带的 H2 数据库，理由正是数据文件损坏风险；请改用独立数据库。
- 不要在容器内以 `--privileged` 方式运行，宿主机目录权限只授予必要的用户与组。
- 上游软件自身的漏洞与安全问题请走上游仓库的 Issues 与安全公告渠道。
