# 三剪客 · 抖音与 TikTok 作品批量下载

你要把一个抖音账号的主页作品、点赞、收藏、合集，或者一个 TikTok 账号的播放列表，整批落到本地硬盘上——TikTokDownload 就是干这个的。它现在的主体是一个叫 `f2` 的 Python 库，装上之后你会得到一个 `f2` 命令，用 `f2 dy` / `f2 tk` 分别操作抖音和 TikTok。它能把视频、图集、封面、文案、原声（含歌词）一起存下来，并且跳过已下载过的文件。

用途上更贴近「素材入库」：二创剪辑、账号内容复盘、对标账号拆解，都需要先有一份干净的本地素材。这个 Skill 讲的是怎么把它装起来、怎么用命令行把一批作品拉下来、以及哪些坑会让你白等半小时。

**上游项目**：`TikTokDownload`　**仓库**：https://github.com/Johnserf-Seed/TikTokDownload

> 说明：仓库本身是入口与说明页，实际可执行的程序来自其配套的 `f2` 库（PyPI 包名就是 `f2`）。命令参数与配置说明以上游文档为准。

## 什么时候用 / 不用

**用它**：

- 「把这个抖音号最近 50 条作品无水印扒下来，我要剪二创」——主页作品批量下载正是它的主场景。
- 「我收藏夹里存了一堆素材，想一次性导到本地分类存档」——`collection` / `collects` / `music` 模式覆盖收藏类数据。
- 「这个号做了三个合集，我要按合集整段拿」——`mix` 模式支持合集链接，也支持合集里任意一条作品链接反查。
- 「TikTok 上那个账号的视频我要拿来做翻译」——`f2 tk` 支持主页作品、点赞、收藏、播放列表、搜索。
- 「我需要连文案、封面、原声一起存，还要按日期区间筛」——文案/封面/原声可分别开关，`--interval` 支持日期区间。

**不要用它**：

- 「帮我下载这个视频」只有一条——单条用网页端或手机端存本地更快，起一套 Python 环境不值当。
- 「帮我批量发视频/发笔记」——它是**只读下载器**，没有任何上传、发布、点赞、评论能力。
- 「帮我看看这条视频的数据表现、涨粉多少」——它落盘的是媒体文件与文案，不做数据看板与趋势分析；要报表请另找数据接口。
- 「在手机上装个 App 就能用」——它是命令行工具，需要 Python 环境，手机端没有可用形态。
- 「拿它采集抖音评论区做舆情分析」——评论提取在上游功能表里标注为未完成/规划中，不要按已有能力去承诺。
- 「我要 7×24 跑一个下载服务对外提供接口」——它面向本地一次性/批量任务，不是常驻服务；稳定对外服务要自己包一层并处理 Cookie 失效。

## 安装

前置：Python ≥ 3.10（上游推荐 3.11.1），命令行建议用 Windows Terminal。TikTokDownload 仓库提供 Dockerfile，但日常使用直接装 PyPI 包最省事。

```bash
# 通用（Windows / macOS / Linux 均可，Linux、macOS 上把 pip 换成 pip3）
pip install f2                # 安装最新版本
pip install -U f2             # 升级到最新版本
pip uninstall f2              # 卸载

# 网络慢时换国内镜像源
pip install -i https://pypi.tuna.tsinghua.edu.cn/simple f2

# 源码开发安装（需要改代码时用）
git clone https://github.com/Johnserf-Seed/f2.git
cd f2
pip install -e .

# 验证是否装上
f2 apps -h
```

TikTokDownload 仓库自带的 Dockerfile 用于它自身的服务端组件；容器化跑 CLI 属于自行拼装，上游没有给出开箱即用的镜像用法，需要的话以仓库内 `Dockerfile` 与官方文档为准。

## 常用操作

以下命令都可以直接粘贴运行，把链接和 Cookie 换成你自己的。

```bash
# 1) 下载抖音单个作品（-M one 单作品模式；f2 能从一堆分享文案里认出链接）
f2 dy -M one -u "7.64 gOX:/ w@f.oD 05/14 世界这本书 又多读了一页 #旅行 https://v.douyin.com/iRNBho6u/ 复制此链接，打开Dou音搜索"

# 2) 下载某个抖音用户主页的全部作品，存到指定目录
f2 dy -M post -u https://www.douyin.com/user/xxxxxxxx -p ./Download

# 3) 只下 2022 年之后发布的作品，最多 50 条，关掉封面只要视频和文案
f2 dy -M like -u https://www.douyin.com/user/xxxxxxxx \
  -i "2022-01-01|2023-12-31" -o 50 -v false -m false -d true

# 4) 下载一个合集（-u 可以给合集链接，也可以给合集里任意一条作品链接）
f2 dy -M mix -u https://www.douyin.com/collection/xxxxxxxx

# 5) 从浏览器自动取 Cookie（执行前先完全退出该浏览器）
f2 dy --auto-cookie edge

# 6) 手动更新配置文件里的 Cookie（配置文件最低优先，CLI 参数优先）
f2 dy -k "your_cookie" -c your_config.yaml --update-config

# 7) 抖音直播录制（-M live 模式）
f2 dy -c A.yaml -M live -u https://live.douyin.com/xxxxxxxxx

# 8) TikTok 侧同构：搜索关键字下载作品
f2 tk -M search -w "keyword" -o 20 -p ./Download

# 9) 只看帮助，不发请求
f2 dy -h
f2 tk --help
```

配置文件想从零开始就 `f2 dy --init-config <文件名>`，随后在里面固定 `mode`、`path`、`cookie` 等高频项，之后直接 `f2 dy` 即可。

写批处理时可以让一个配置文件对应一个账号，再用 `-c` 切换，比每次敲一长串参数稳：

```bash
f2 dy -c dy-A.yaml -M post     # 账号 A 的主页作品
f2 dy -c dy-B.yaml -M like     # 账号 B 的点赞作品
f2 dy -c dy-C.yaml -M live -u https://live.douyin.com/xxxxxxxxx
```

想直接调接口而不走命令行，F2 也提供异步的 Python 接口（例如 `fetch_user_profile`、`fetch_one_video`、`fetch_user_post_videos` 等）。具体签名、参数模型与返回的过滤器结构请以官方文档的开发者接口章节为准，本文不复制这些签名以免版本差异误导。

## 常见坑

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 刚装完运行报参数不存在 / 帮助里没有 `-M` | 老版本 F2 与 CLI 参数不匹配 | 先 `pip install -U f2` 升到最新版，再 `f2 dy -h` 对照参数表 |
| `--auto-cookie` 拿不到 Cookie，或拿到的是空值 | 2024-08-15 之后 Chromium 内核把 Cookie 加密升级到 V20，自动读取失效 | 关掉浏览器改用其他内核浏览器，或降级浏览器到 v128 之前；实在不行手动复制 Cookie 后 `--update-config` |
| 一跑就风控 / 返回空数据 / 提示需要登录 | 大部分接口需要登录态，Cookie 过期或未配置 | 更新 Cookie；确认 Cookie 里没有非 ASCII 字符；必要时把 `-e` 超时、`-r` 重试、`-x` 并发调保守一点 |
| 明明有几百条作品，只下到十几条 | `-i` 日期区间是全局生效的，默认可能只取近期 | `-i all` 下载全部，或明确写 `年-月-日\|年-月-日`；同时检查 `-o`（`0` 才是无限制） |
| 作品存成一堆扁平文件，找不到对应关系 | `--folderize` 默认为 `true`，但配了 `-f false` 就会拍平 | 保留 `-f true`；文件名模板用 `-n "{nickname}_{create}_{aweme_id}_{desc}"` 之类固定下来 |
| 文件名报错或乱码 | `--naming` 模板变量写错，或文案里含文件系统不允许的字符 | 只用 `{nickname}` `{create}` `{aweme_id}` `{desc}` `{uid}` 五个变量，分隔符只用 `_` 或 `-`；模板不符合规范会直接抛异常 |
| 下载到一半断流、部分文件 0 字节 | 并发过高或网络抖动 | 下调 `-x`（并发连接）与 `-t`（异步任务数），上调 `-r` 重试次数，重跑即可（已存在文件会跳过） |
| 直播模式报错 | `360°` 等特殊直播间不支持 | 换普通直播间；其它场景以 `f2 dy -h` 与官方 FAQ 为准 |
| 图集拿到的是 webp，剪辑软件不认 | 上游把图集格式统一为 webp | 自行批量转码，别在这个工具里找开关 |
| 在 Issues / 群里贴命令求排查，Cookie 泄漏 | 命令里带了明文 Cookie | 贴日志前把 `-k` 后面的值删掉；Cookie 等于账号登录凭证，泄漏后立刻登出重登 |

## 权限与用途说明

| 能力 | 是否申请 | 用途 |
|---|---|---|
| 网络访问 | 是 | 请求抖音 / TikTok 接口拉取作品元数据与媒体文件，可能还需访问代理 |
| 读取文件 | 是 | 读取 YAML 配置文件、已下载文件清单（用于去重）；`--auto-cookie` 会读浏览器本地 Cookie 数据库 |

| 子进程 / 后台常驻 | 否 | 命令跑完即退出；下载直播时是长时运行的前台命令，不是常驻服务 |

## 能力边界

**覆盖**：

- 抖音：用户信息、单个作品、主页作品、点赞、收藏夹、收藏、收藏原声、收藏合集、合集作品、首页推荐、相似推荐、好友作品、关注/粉丝信息、直播流与直播间弹幕等（以上游功能表标注为准）。
- TikTok：用户信息、单个作品、主页作品、点赞、收藏、播放列表、合集、作品搜索、直播流与弹幕等。
- 落盘可选视频原声、封面、文案、歌词（`.lrc`），支持自定义保存目录与文件名模板、代理、日期区间、并发与重试参数。
- 异步下载，多作品并发；下载前检查文件是否已存在以避免重复。

**不覆盖**：

- 不做任何发布、上传、点赞、评论、关注等写操作。
- 不做数据看板、涨粉趋势、投放效果分析。
- 不做视频去水印之外的后期处理（转码、切片、混剪、字幕）。
- 不保证评论区数据可用——评论相关能力在上游标注为未完成。
- 不提供 Web 界面与本地接口转发（上游标注为规划中），也不提供多用户共享的账号池。

## 依赖条件

- Python ≥ 3.10，上游推荐 3.11.1；纯命令行使用建议配 Windows Terminal。
- Node.js 相关工具链：F2 的部分应用依赖 Node 环境来跑签名算法，上游必备条件里列了 nvm。
- 一个可用的抖音 / TikTok 账号，用来取登录 Cookie；部分公开接口可以不带 Cookie 访问。
- 磁盘空间：图集与视频批量下载很容易上到几十 GB，先确认目标盘余量。
- 网络：直连不稳定时需要自备 HTTP/HTTPS 代理。

## 已知限制

- Cookie 有时效，且平台风控参数算法会变；老版本经常直接失效，属正常现象。
- `--auto-cookie` 受浏览器 Cookie 加密策略影响，最新 Chromium 内核浏览器可能读不到。
- 评论提取、关注作品下载、Web UI、本地接口转发等在上游仍是未完成或规划状态。
- 直播模式不支持 `360°` 等特殊直播间。
- 下载速度与成功率受平台限流影响，不承诺任何批量规模下的稳定产出。

## 自检清单

执行前：

- [ ] `f2 dy -h` 能正常打出帮助，确认当前版本的参数与本文一致（版本差异以 `--help` 为准）。
- [ ] 目标目录 `-p` 存在且磁盘余量够。
- [ ] Cookie 有效且不含非 ASCII 字符；知道它等同于账号凭证。
- [ ] 已确认这是自己有权下载与使用的素材，仅用于合规用途。

执行后：

- [ ] 抽查 2~3 个文件能否正常播放 / 打开，不是 0 字节。
- [ ] 核对数量与 `-o`、`-i` 的设定是否一致。
- [ ] 确认没有把 Cookie 明文留在日志、命令历史或提交记录里。
