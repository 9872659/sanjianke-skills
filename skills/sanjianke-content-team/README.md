# 三剪客 · 内容团队

**产品线 L3（多智能体协作型）的第一个包。**

给一个题材，四个立场不同的角色从选题开始协作，**一条命令出成品**：
定稿正文 + 全过程记录（谁在第几轮改了什么、谁否决了什么、引用哪句原话）。

## 这个包解决什么问题

内容团队真正的成本不在"写不出来"，在**没人能否掉别人**：

- 写手写完就交了，因为没人会打回他；
- 审稿说"整体不错，建议加强逻辑"，因为挑不出具体句子也不会有人追究；
- 合规最后一眼扫过就放行，因为前面都说没问题了。

一件作品被四个人看过，等于被零个人看过 —— 每个人的判断都建立在
"别人已经看过了"这个假设上。本包把这个假设**拆掉**：

| 常见做法 | 本包 |
|---|---|
| 一个模型分四次扮演不同角色，共享同一份上下文 | 四个角色各有**字段白名单**，看不到什么被写死成结构 |
| 审稿知道作者自己觉得哪里写得好 | 审稿的提示词里**没有**写手的自评 |
| 合规顺着审稿的结论走 | 合规的提示词里**没有**审稿意见，还明写「没人给你风险结论」 |
| "改了三轮，应该差不多了" | 未收敛会**明说**，附未决项，退出码 3 |
| 谁改了什么说不清 | 全过程记录：轮次 / 角色 / 动作 / **引用的原句** / 否决理由 |

## L1 / L2 / L3 三层分界

三剪客的内容产品线分三层，本包是 L3 的第一个：

| 层 | 形态 | 同族已有的包 |
|---|---|---|
| **L1 单点生成型** | 一个输入 → 一个产出，开箱即用 | 爆款标题工坊、一稿多平台改写 |
| **L2 智能体型** | **单循环**：抽档 → 写 → 自检 → 迭代（**一个声音在自我迭代**） | 内容质量闭环、风格克隆体、幻灯片套件 |
| **L3 多智能体协作型** | **多角色分工互审**，一条命令出成品 | ← **本包** |

### 与 L2 的分界表（拿 `内容质量闭环` 逐项对照）

| 维度 | L2 · 内容质量闭环 | **L3 · 内容团队（本包）** |
|---|---|---|
| 起点 | 一篇**别人已经写完的成稿** | 一个**题材** |
| 角色数 | **1** 个（一个裁判，兼评审与改写） | **4** 个（策划 / 写手 / 审稿 / 合规） |
| 目标函数 | 一套评分维度，五个维度加权 | **四个互不相同、甚至互相冲突**的目标 |
| 产出物 | 定稿 + 评分轨迹 + 逐句改动台账 | 选题卡 + 初稿&自评 + 问题清单 + 风险裁决 + 定稿 |
| 谁能否谁 | **没有人能否任何人**，只有分数没过目标线 | 审稿**能打回**写手；合规**一票否决**；策划**能重开**选题 |
| 上下文 | 所有步骤共享同一份上下文 | **信息不对称**：写手自评不进审稿；审稿意见不进合规 |
| 迭代对象 | 同一篇稿子的措辞与结构 | **选题可见被否**，稿子会被退回重写 |
| 终止 | 达标，或轮次用尽 | 达标，或四种**显式出口**之一（附未决项与理由） |
| 失败时说什么 | "未收敛，差 N 分" | "未收敛：**谁在第几轮否掉了什么，引用哪句原话**" |
| 调用成本（600 字） | 4~5 次 | 4~9 次 |

**一句话记住**：L2 回答"这篇稿子还能不能更好"，L3 回答"这篇稿子该不该这么写、
能不能发、**谁说了算**"。

**反过来说清楚**：如果你手里已经有一篇成稿、只想让它更好，用 L2 更省。
本包的价值在"从零开始的分工与对抗"，不在"多跑几次模型"。

## 四个角色与职权

| 角色 | 目标函数 | 产出物 | 否决权 |
|---|---|---|---|
| **策划** | 选题够不够打、角度有没有新意 | 选题卡（受众 / 痛点 / 角度 / 差异化 / 3 条论据支柱） | **能否掉平庸选题并重开** |
| **写手** | 严格按选题卡写出稿 | 初稿 + 自评（**审稿看不到这一栏**） | 无 |
| **审稿** | 结构 / 逻辑 / 可读性 / 信息密度 | **逐条问题清单，每条必须引用原句** | **能打回写手**（附必须修清单） |
| **合规** | 广告法 / 事实 / 平台规则 | 风险裁决（放行 / 可替换 / 打回 / **一票否决**） | **一票否决权** |

零成本看这张表：

```bash
python3 scripts/run.py roles
```

### 一条协作命令的走向

```
策划 plan ──▶ 写手 draft ──▶ 审稿 review ──┬─ pass ──▶ 合规 compliance ──┬─ pass/fix ──▶ 定稿
   ▲                ▲                     │                             ├─ send_back ─┐
   │                └─── 必须修清单 ───────┘ send_back                    └─ veto ──────┼─▶ 带未决项产出
   └── 选题卡不达标 → 重开（上限 --plan-retries）      └── 修订（上限 --rounds）──────────┘
```

**审稿与合规是串行关系，不是投票**：审稿不过，轮不到合规；审稿过了，合规仍可独立否决。

## 信息不对称：本包凭什么不是"一个模型演四个角色"

「一个模型分四次扮演不同角色」的致命之处是**四个角色共享同一份上下文**：
审稿永远看不到一个它不知道的自评，合规永远顺着审稿的结论走 —— **对抗是假的**，
产出里的"独立判断"其实是同一个声音的自言自语。

本包用两层机制把这件事做成结构性的：

1. **字段白名单**（`ROLES[*]["inputs"]` / `["forbidden"]`）—— 提示词模板按它拼装，
   被排除的字段在物理上没有进入 prompt 的路径。合规拿到的选题卡只是一份
   **窄字典**（8 个字段里的 2 个：标题 + 策划提示的风险点）。
2. **调用前实检**（`assert_isolation()`）—— 拿被禁字段的标记词对**真实提示词文本**
   扫一遍，泄漏就抛异常、**中止这次调用**（一个字都不发出去）。
   每次调用的判定结果逐条写进产物与 `REPORT.md`，外部可复核。

### 实测：注入能被拦住

```
A1 审稿正常 prompt       -> True   excluded=[self_check, writer_self_check]  检查 4 个标记词
A2 审稿 prompt 注入自评   -> False  leaked=[自评]  → IsolationBreach，调用中止
A3 合规正常 prompt       -> True   excluded=[self_check, issues, review_verdict] 检查 12 个标记词
A4 合规 prompt 注入审稿意见 -> False  leaked=[问题清单, 审稿的, 审稿结论]
B  合规提示词里含"问题清单"? False   含"审稿"? False   含"自评"? False
C  审稿提示词里含"自评"?   False   含"我认为写得好的地方"? False
```

### 因为看不到，合规才会独立发现问题

真机实测：合规在同一篇稿子上挑出 **5 条事实性问题**，而写手与审稿都没提：

- 7 个同事的小样本被外推成对读者的预测性结论（"结果大概率差不多"）
- 单一公司茶水间的耗材口径被写成"一年光滤芯就是 720 元"的**通用成本**
- 作者个人单次转手亏损被写成"**才是**真实持有成本"这样的一般性结论
- "维修一次通常要几百元"是无出处的价格断言
- "清洗习惯**决定**机器能用多久"是绝对化因果表述

这些不是措辞问题，是事实性问题 —— 所以它判 `send_back` 而不是 `fix`。
**一个顺着审稿结论走的合规角色不会发现这些。**

## 裁决与终止条件

**最多 N 轮**由 `--rounds` 定；**谁能否谁**是固定的：

| 否决方 | 条件 | 后果 | 上限参数 |
|---|---|---|---|
| 策划 | 选题卡不达标（角度太泛、支柱互相重义、受众太泛…） | 换角度重开 | `--plan-retries` |
| 审稿 | 有任何一条 **高** 严重度问题 | 打回，附必须修清单 | 受 `--rounds` 约束 |
| 合规 | 判 `send_back` | 写手按合规要求再改一轮 | `--compliance-sendback` |
| 合规 | 判 `veto` | **直接终止**，产出带未决项 | 无（一票否决） |

### 四种显式出口：谈不拢就说谈不拢

| 出口 | 什么时候走 | 怎么处理 |
|---|---|---|
| `rounds_exhausted` | 轮次用完，审稿仍判打回 | **升级给人看**，附全部未决项 |
| `plan_retries_exhausted` | 策划重开上限用尽仍交不出达标卡 | 升级给人看 |
| `no_effective_change` | 连续两轮修订"没有实质改动" | 升级给人看 —— 继续跑只是烧钱 |
| `stalled_same_quote` | 审稿连续两轮指向**同一段文字**仍被拒 | 升级给人看 —— 写手改不动它 |
| `compliance_send_back_exhausted` | 合规打回次数用尽仍不放行 | **带未决项产出** |

走任何一种出口，退出码都是 **3**，`escalation.unresolved` 逐条写明未决项，
stderr 打印标红汇总。

### 本地兜底：模型说了不算的三件事

1. **有 高 严重度问题却判 `pass`** → 强制改判 `send_back`
2. **有 高 风险发现却判 `pass`/`fix`** → 强制改判 `veto`
3. **本地违禁词扫描命中而合规说 `pass`** → 本地不放行，降级为 `fix` / `send_back`

## 六道本地硬闸门

1. **广告法违禁词** —— 内置正则表 + 「最X」可枚举上下文豁免（句首不豁免）
   + 「第一」序数豁免（`第一年`/`第一台` 属序数，`第一名`/`第一品牌` 照拦）
2. **占位符残留** —— `{}` / `[待填]` / `XXX` / `（此处省略）` / `待补充`
3. **照抄提示词示例** —— 三条判据（去标点相等 / 二元组 Jaccard ≥ 0.75 /
   **覆盖度 ≥ 0.60**）+ **相对**长度守卫 `max(6, len(示例)//2)`
   + 覆盖度判据的**适用窗口**（片段 ≥ 24 字才启用，防短串虚高）
4. **审稿锚点** —— 每条问题必须引用稿子里真实存在的句子；编造的引文被剔出、
   **不进写手的修订输入**；未锚定率 > 40% 判「定位失败」
5. **事实保全** —— 基准是**策划的 `must_keep`**；数字换写法（`3` → `三`）不算丢；
   材料里出现但**没被登记的未经核实说法**只列出、不拦
6. **篇幅** —— 目标 ±15% 再叠绝对容差 `max(15, 目标×2%)`

命中一律：**压分 + 标红 + stderr 汇总 + 退出码 3**。

### 为什么第 6 条要加绝对容差

600 字目标的 15% 区间是 510~690。实测模型写了 **693 字** —— 超 3 个字（0.5%），
只按百分比算会把整轮产出作废。那种噪声会让人把闸门关掉，
而闸门一关，真正该拦的（违禁词、丢事实）也一起失效。

### 为什么第 5 条的基准是 `must_keep` 而不是整份材料

实测踩到过：材料里有一句"看到一个说法：90% 的人买完咖啡机都没认真清洗过"，
最初它被当成必须保全的事实。写手按选题卡的提示把它**正确地**处理成
"这个说法没有出处，不能当成结论" —— 结果被判"丢了事实 90"。
**这是把未经核实的说法当成了必须复读的事实，方向正好反了。**
所以基准改成策划登记的 `must_keep`；没被登记的那些进 `untrusted_brief`，
照样列出来给人看，但不参与判定。

## 真机实测：多角色互审是真的发生了吗

这是本包最该被质疑的地方，所以直接摆数据。

### 一次真机运行（2 轮，未收敛）

| 轮 | 角色 | 裁决 | 内容 |
|---|---|---|---|
| 1 | 策划 | `accepted` | 选题卡达标 |
| 1 | 审稿 | **`send_back`** | 7 条问题，**全部成功锚定到原句**（未锚定率 0%），必须修 #1/#2/#3 |
| 1 | 写手 | 修订 | 517 → 685 字，自报修 3 条（点名 3 条），正文相似度 0.69 |
| 2 | 审稿 | **`send_back`** | 7 条问题，必须修 #5 |
| — | — | `rounds_exhausted` | **明确报未收敛**，附未决项 |

5 次调用、14,737 token、约 ¥0.206。

### 同题材另一次运行（一次放行收敛）

| 轮 | 角色 | 裁决 |
|---|---|---|
| 1 | 策划 | `accepted` |
| 1 | 审稿 | `pass` |
| 1 | 合规 | `pass`（风险等级：无） |

4 次调用、6,984 token、约 ¥0.086、**退出码 0**。

### 审稿是不是在"逐条放行"？

**不是。** 证据是它给出的问题必须**引用原稿真实存在的句子**，
而本地会校验这句引文在不在稿子里：

- 锚定成功 7 条 / 未锚定 0 条 —— 每条问题都指到了具体句子
- 引用的原句长这样：「公司茶水间那台全自动采购价4600元，行政说每3个月换一次」
- 它判打回时给出 `must_fix` 列表，第 2 轮只剩 **1 条**必须修（#5），
  说明第 1 轮那 3 条被写手真的改掉了，而不是每轮重复同一份清单

### 合规是不是永远不出问题？

**不是。** 同一题材上，合规在三种不同输入下给出三种不同裁决：

| 输入 | 合规裁决 | 说明 |
|---|---|---|
| 一次放行的定稿 | `pass`（风险等级：无） | 逐条核对了材料出处，确认没有无出处数字 |
| 2 轮未收敛那版稿子 | `send_back` | 独立挑出 **5 条事实性问题**（写手与审稿都没提） |
| 故意构造的黑稿 | **`veto`**（风险等级：高） | 5 处高风险：绝对化用语、虚假承诺、无出处实测数据、健康宣称、站外导流 |

黑稿那次合规的理由原文：

> 这些不是个别措辞可以替换的问题，而是整篇稿件的立论基础建立在虚构资质与
> 虚假承诺之上，换词无法救回，故一票否决。

同时本地违禁词扫描独立命中 10 处（`全网最低`/`行业第一`/`国家级`/`100%`/
`保证有效`/`纯天然`/`加微信` …），退出码 3。

### 结论

**多角色互审是真的发生了**，依据是三条可复核的事实：

1. **有真实的否决**：审稿打回 4 次、合规 veto 1 次、合规 send_back 1 次，都不是 0
2. **角色说的不是同一件事**：审稿谈结构与信息密度，合规谈事实性与无出处数据，
   两者的发现清单**不重叠** —— 这是信息不对称起作用的直接证据
3. **谈不拢就报谈不拢**：4 轮未收敛的那次退出码是 3，`REPORT.md` 里写清
   卡在哪一句，而不是把"改了三轮"讲成"已经改好"

同时也要如实说清**局限**：四个角色都是同一个模型（默认 `deepseek-chat`）扮演的，
只是上下文被结构性隔开。这不是四家不同的模型在互审，
所以"独立性"来自**信息边界**，不是来自模型多样性。

## 命令行

### 子命令一览

| 子命令 | 干什么 | 花钱吗 |
|---|---|---|
| `roles` | 列出四个角色的职权、产出物与否决权 | **不花** |
| `plan` | 策划出选题卡（不达标会自动重开） | 花 |
| `draft` | 写手按选题卡出初稿 + 自评 | 花 |
| `review` | 审稿出问题清单，**可打回** | 花 |
| `compliance` | 合规风险裁决，**可否决** | 花 |
| `run` | **一条命令跑完整协作**，带裁决与轮次上限 | 花 |
| `log` | 读回全过程记录 | **不花** |
| `cost` | 报价：只出 token，金额要你自己填单价 | **不花** |
| `models` | 列出在架模型 | **不花** |

加 `--dry-run` 时所有花钱的子命令都只打印提示词、不发起调用。

### 常用参数

| 参数 | 说明 |
|---|---|
| `--brief` | 用户材料（`.md` / `.txt`，UTF-8）：选题来源 + 事实基准 |
| `--target-chars` | 目标篇幅（不含空白），默认 600，可用 200~4000 |
| `--card` / `--draft` | 选题卡 JSON / 待审稿件文本 |
| `--rounds` | 审稿↔写手修订最多几轮，默认 2 |
| `--plan-retries` | 选题卡不达标最多重开几次，默认 1 |
| `--compliance-sendback` | 合规打回后最多再改几轮，默认 1 |
| `--outdir` | 目录产物落这里，**必须在包外** |
| `--force` | 忽略断点从头重跑 |
| `--budget` | 预算上限（点），超了就地中止退出码 5；**用它必须给单价** |
| `--price-in` / `--price-out` | 单价（点/百万 token）。不给就不给金额 |
| `--json` | 以 JSON 输出；**写在子命令前后都可以** |
| `--dry-run` | 只打印提示词，不调模型不花钱 |

### 退出码

| 码 | 含义 |
|---|---|
| 0 | 定稿：审稿放行 + 合规放行 + 无硬闸门命中 |
| 2 | 用法/配置错（文件不存在、`--outdir` 在包内、`--budget` 没配单价…） |
| 3 | 硬闸门命中，或**未收敛**（含合规 veto） |
| 4 | 调用失败（网络 / 鉴权 401 / 点数 402 / 模型名 404） |
| 5 | 预算超限，已就地中止（**未发起任何调用**） |
| 130 | 用户中断 |

## 排错速查

| 现象 | 处置 |
|---|---|
| `没有找到 API Key` | `--key` / `A7W_API_KEY` / `a7w.py login` 三选一 |
| `鉴权失败（401）`／`点数不足（402）` | 到 https://api.a7w.cn/ 重新创建 Key 或充值 |
| `模型不存在（404）` | `run.py models` 现查在架名，别写死 |
| `未收敛，出口 = rounds_exhausted` | **这是真实结论，不是 bug**。看 `REPORT.md` 的未决项 |
| `出口 = no_effective_change` | 写手在原地打转。继续加轮次只会烧钱 |
| `出口 = stalled_same_quote` | 审稿两次指向同一段文字，通常是两个要求互相冲突，需要人定口径 |
| `合规 veto` | 看 `findings` 里逐条的规则与引用。事实造假换词救不回来 |
| `--outdir` 在包内退出码 2 | 产出必须落包外 |
| `unrecognized arguments: --out` | 本包不允许长选项前缀缩写（故意的），请写全 |

更多见 `references/成本与排错.md` 与 `SKILL.md`。
