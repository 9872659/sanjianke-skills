## 这是产品线 L3：多智能体协作型

三剪客的内容产品线分三层，本包是 **L3 的第一个**：

| 层 | 形态 | 同族已有的包 |
|---|---|---|
| **L1 单点生成型** | 一个输入 → 一个产出，开箱即用 | 爆款标题工坊、一稿多平台改写 |
| **L2 智能体型** | **单循环**：抽档 → 写 → 自检 → 迭代（**一个声音在自我迭代**） | 内容质量闭环、风格克隆体、幻灯片套件 |
| **L3 多智能体协作型** | **多角色分工互审**，一条命令出成品 | ← **本包** |

### 与 L2 的分界（拿 `内容质量闭环` 对照）

| 维度 | L2 · 内容质量闭环 | **L3 · 内容团队（本包）** |
|---|---|---|
| 起点 | 一篇**别人已经写完的成稿** | 一个**题材** |
| 角色数 | 1（一个裁判，兼评审与改写） | **4**（策划 / 写手 / 审稿 / 合规） |
| 目标函数 | 一套评分维度，打分 → 重写 → 复评 | 四个**互不相同甚至冲突**的目标 |
| 产出物 | 定稿 + 评分轨迹 + 逐句台账 | 选题卡 + 初稿&自评 + 问题清单 + 风险裁决 + 定稿 |
| 谁能否谁 | **没有人能否任何人**，只有分数没过目标线 | 审稿**能打回**写手；合规**一票否决**；策划**能重开**选题 |
| 上下文 | 所有步骤共享同一份上下文 | **信息不对称**：写手自评不进审稿；审稿意见不进合规 |
| 终止 | 达标或轮次用尽 | 达标，或四种**显式出口**之一（附未决项） |
| 失败时 | 报"未收敛，差 N 分" | 报"未收敛 + **是谁在第几轮否掉了什么、引用哪句原话**" |

**一句话**：L2 是"这篇稿子还能不能更好"，L3 是"这篇稿子该不该这么写、能不能发，谁说了算"。

**如果你要的只是给一篇现成稿子打分改稿，用 L2 更省**（4~5 次调用 vs 本包 4~9 次）。
本包的价值在"从零到定稿的分工与对抗"，不在"多跑几次模型"。

## 四个角色与职权

| 角色 | 目标函数 | 产出物 | 否决权 |
|---|---|---|---|
| **策划** | 选题够不够打、角度有没有新意 | 选题卡（受众 / 痛点 / 角度 / 差异化 / 3 条论据支柱） | **能否掉平庸选题并重开**（上限 `--plan-retries`） |
| **写手** | 严格按选题卡写出稿 | 初稿 + 自评（`self_check`，**审稿看不到**） | 无 |
| **审稿** | 结构 / 逻辑 / 可读性 / 信息密度 | **逐条问题清单，每条必须引用原句** | **能打回写手**（附必须修清单） |
| **合规** | 广告法 / 事实 / 平台规则 | 风险裁决（放行 / 可替换 / 打回 / **一票否决**） | **一票否决权** |

零成本看这张表：

```bash
python3 scripts/run.py roles
```

### 一条协作命令的走向

```
策划 plan ──▶ 写手 draft ──▶ 审稿 review ──┬─ pass ──▶ 合规 compliance ──┬─ pass/fix ──▶ 定稿
   ▲                ▲                     │                             ├─ send_back ─┐
   │                └─── 必须修清单 ───────┘ send_back                    └─ veto ──────┼─▶ 带未决项产出
   └── 选题卡不达标 → 重开（上限 --plan-retries）      └── 修订（上限 --rounds）──────────┘
```

**审稿与合规是串行关系，不是投票**：审稿不过，轮不到合规；审稿过了，合规仍可独立否决。

```bash
# 一条命令出成品：策划 → 写手 → 审稿 → 修订 → 合规

## 信息不对称：本包凭什么不是"一个模型演四个角色"

「一个模型分四次扮演不同角色」的致命之处是**四个角色共享同一份上下文**：
审稿永远看不到一个它不知道的自评，合规永远顺着审稿的结论走 —— **对抗是假的**，
产出里的"独立判断"其实是同一个声音的自言自语。

本包用两层机制把这件事做成结构性的：

1. **字段白名单**（`ROLES[*]["inputs"]` / `["forbidden"]`）—— 提示词模板按它拼装，
   被排除的字段在物理上没有进入 prompt 的路径。合规拿到的选题卡只是一份
   **窄字典**（`title` + `risk_note`，8 个字段里的 2 个）。
2. **调用前实检**（`assert_isolation()`）—— 拿被禁字段的标记词对**真实提示词文本**
   扫一遍，泄漏就抛异常、**中止这次调用**（一个字都不发出去）。
   每次调用的判定结果逐条写进产物与 `REPORT.md`，外部可复核。

两条最关键的排除：

| 角色 | 看不到什么 | 为什么 |
|---|---|---|
| **审稿** | 写手的 `self_check`（自评） | 作者自己说"我觉得这里写得好"，会污染审稿的独立判断 |
| **合规** | 审稿的 `issues` 与 `verdict` | 合规若知道"审稿已经放行"，就会顺着放行 —— 它的提示词里明写「**本团队内部没有向你提供任何风险结论**，你不得假设前面已经审过了」 |

**实测证据**（可复现的两种）：

- 正常提示词：审稿检查 4 个标记词、合规检查 12 个标记词，全部通过。
- 往审稿提示词里注入一句"顺带附上：写手的自评如下"→ 当场拦下并抛
  `IsolationBreach`；往合规提示词里注入"审稿的问题清单：#1 … 审稿结论：pass"→
  三个标记词同时命中。

因为拿不到上游结论，**合规才会发现写手与审稿都没提的问题**。真机上它在同一篇
稿子里挑出 5 条事实性问题：小样本（7 个同事）被外推成对读者的预测性结论、
单一公司茶水间的耗材口径被写成"一年光滤芯就是 720 元"的通用成本、
个人单次转手亏损被写成"才是真实持有成本" —— 这些**不是措辞问题，是事实性问题**，
所以它判了 `send_back` 而不是 `fix`。

## 裁决与终止条件（谈不拢有明确出口）

**最多 N 轮**由 `--rounds` 定；**谁能否谁**是固定的：

| 否决方 | 条件 | 后果 | 上限参数 |
|---|---|---|---|
| 策划 | 选题卡不达标（角度太泛、三条支柱互为同义改写、受众太泛…） | 换角度重开 | `--plan-retries` |
| 审稿 | 有任何一条 **高** 严重度问题 | 打回，附必须修清单 | 受 `--rounds` 约束 |
| 合规 | 判 `send_back` | 写手按合规要求再改一轮 | `--compliance-sendback` |
| 合规 | 判 `veto` | **直接终止**，产出带未决项 | 无（一票否决） |

### 四种显式出口（**不许假装谈拢**）

| 出口 | 什么时候走 | 怎么处理 |
|---|---|---|
| `rounds_exhausted` | 轮次用完，审稿仍判打回 | **升级给人看**，附全部未决项 |
| `plan_retries_exhausted` | 策划重开上限用尽仍交不出达标卡 | 升级给人看 |
| `no_effective_change` | 连续两轮修订"没有实质改动"（正文相似度 ≥ 0.86 或自报修得不够） | 升级给人看 —— 继续跑只是烧钱 |
| `stalled_same_quote` | 审稿连续两轮指向**同一段文字**仍然被拒 | 升级给人看 —— 写手改不动它 |
| `compliance_send_back_exhausted` | 合规打回次数用尽仍不放行 | **带未决项产出** |

走任何一种出口，退出码都是 **3**，`escalation.unresolved` 里逐条写明未决项，
stderr 打印标红汇总。**跑不通就说跑不通。**

### 本地兜底：模型说了不算的三件事

1. **有 高 严重度问题却判 `pass`** → 强制改判 `send_back`（审稿不许自己给自己放行）
2. **有 高 风险发现却判 `pass`/`fix`** → 强制改判 `veto`（合规的一票否决权不许被模型放弃）
3. **本地违禁词扫描命中而合规说 `pass`** → 本地不放行，降级为 `fix` / `send_back`

## 六道本地硬闸门（确定性，跑两次结果一样，可直接进 CI）

1. **广告法违禁词** —— 内置正则表 + 「最X」可枚举上下文豁免（句首不豁免）
   + 「第一」序数豁免（`第一年`/`第一台` 属序数，`第一名`/`第一品牌` 照拦）
2. **占位符残留** —— `{}` / `[待填]` / `XXX` / `（此处省略）` / `待补充`
3. **照抄提示词示例（`prompt_echo`）** —— 三条判据：去标点相等、字符二元组
   Jaccard ≥ 0.75、**覆盖度 ≥ 0.60**；长度守卫是**相对阈值** `max(6, len(示例)//2)`；
   覆盖度判据外加**适用窗口**（片段 ≥ 24 字才启用，防短串虚高）
4. **审稿锚点** —— 每条问题必须引用稿子里真实存在的句子，本地校验
   （`exact` / `substring` / `fuzzy`）；编造的引文被剔出、**不进写手的修订输入**；
   未锚定率 > 40% 判「定位失败」
5. **事实保全** —— 两点：定稿里的**数字换写法**（`3` → `三`）**不算丢**；
   基准是**策划的 `must_keep`**（材料里有、但没被登记的未经核实说法，只列出不拦）
6. **篇幅** —— 目标 ±15% 再叠一个绝对容差 `max(15, 目标×2%)`。
   **为什么要绝对容差**：600 字目标的 15% 区间是 510~690，实测模型写了 **693 字**
   （超 3 个字，0.5%），只按百分比算会把整轮产出作废 —— 那种噪声会让人把闸门关掉，
   而闸门一关，真正该拦的（违禁词、丢事实）也一起失效

命中一律：**压分 + 标红 + stderr 汇总 + 退出码 3**。

## 参数说明

### 全局

| 参数 | 说明 |
|---|---|
| `--json` | 以 JSON 输出；**写在子命令前后都可以**。成功时结果里带 `"ok": true`，失败时 stdout 只有一个失败信封 |
| `--key` | 临时指定 API Key（也可用 `A7W_API_KEY` 或 `~/.a7w/config.json`） |
| `--dry-run` | 只打印将发送的提示词，**不调模型、不花钱** |
| `--out` | 把结果写到文件（`plan`/`draft`/`review`/`compliance`/`roles`/`cost` 有；**`run` 没有**） |
| `--model` / `--temperature` / `--max-tokens` | 模型与采样参数。模型名会变，用 `models` 现查 |
| `--no-json-mode` | 个别模型不支持 `response_format` 时用 |

### 输入与篇幅（`plan` / `draft` / `review` / `compliance` / `run` 共用）

| 参数 | 说明 |
|---|---|
| `--brief` | 用户材料（`.md` / `.txt`，UTF-8）。**选题来源 + 事实基准**；`compliance` 里可选 |
| `--target-chars` | 目标篇幅（不含空白），默认 600，可用区间 200~4000 |
| `--card` | 选题卡 JSON（`plan --json --out` 的产物）。`draft`/`review` 必填 |
| `--draft` | 待审 / 待裁稿件文本 |

### `run` —— 一条命令跑完整协作

| 参数 | 说明 |
|---|---|
| `--rounds` | 审稿↔写手修订最多几轮，默认 2（**至少 1**；只要质检不要协作用 L2） |
| `--plan-retries` | 选题卡不达标时最多重开几次，默认 1 |
| `--compliance-sendback` | 合规打回后最多再让写手改几轮，默认 1 |
| `--outdir` | 目录产物落这里（**必须在包外**）；默认 `%TEMP%/content-team-out` |
| `--force` | 忽略断点文件从头重跑（key 没命中就会重新花钱） |
| `--facts-warn-only` | 把「丢事实 / 硬信息没兑现」从硬闸门降级为提示（**已知会误报**） |

### `cost` —— 报价

| 参数 | 说明 |
|---|---|
| `--file` / `--text` | 按材料或直接文本估 |
| `--price-in` / `--price-out` | 单价，单位「点 / 百万 token」。**不给我就不给金额（不编价）** |
| `--budget` | 预算上限（点），超了退出码 5；**用 `--budget` 必须给单价**，否则退出码 2 |

python3 scripts/run.py models
```

## 退出码（可直接用于 CI）

| 码 | 含义 |
|---|---|
| 0 | 定稿：审稿放行 + 合规放行 + 无硬闸门命中 |
| 2 | 用法/配置错误（文件不存在、`--outdir` 在包内、`--budget` 没配单价、`--rounds 0`、`run` 用了 `--out`） |
| 3 | 硬闸门命中，或**未收敛**（含合规 veto） |
| 4 | 调用失败（网络 / 鉴权 401 / 点数 402 / 模型名 404） |
| 5 | 预算超限，已就地中止（**未发起任何调用**） |
| 130 | 用户中断 |

`--json` 的失败信封：`{"ok": false, "exit": <码>, "error": {"kind": …, "message": …}}`，
`kind` 取 `usage` / `gate` / `call` / `budget` / `interrupt` / **`internal`**。
未捕获异常一律 `kind: "internal"` + **完整 traceback 到 stderr**。

## 成本与预算

- **只出 token，不编金额**：文本模型网关不公布单价，`/api/v1/models` 里也没有价格字段。
- 字符 → token 标定（同族实测值）：输入 1 token ≈ 1.61 字符；输出 1 字符 ≈ 1.11 token。
  **这是估算，不是账单。**
- 真机实测（600 字目标、`deepseek-chat`）：

| 场景 | 调用次数 | token | 按 1000/2000 点每百万 token 折算 |
|---|---|---|---|
| 一次放行收敛（`live5`） | 4（策划 + 初稿 + 审稿 + 合规） | 6,984 | ≈ 8.6 点 ≈ ¥0.086 |
| 四轮未收敛（`live4`） | 9 | 28,411 | ≈ 39.8 点 ≈ ¥0.398 |
| 两轮未收敛（`live1`） | 5 | 14,737 | ≈ 20.6 点 ≈ ¥0.206 |

## 排错

| 现象 | 处置 |
|---|---|
| `没有找到 API Key` | `--key` / `A7W_API_KEY` / `a7w.py login` 三选一 |
| `鉴权失败（401）`／`点数不足（402）` | 到 https://api.a7w.cn/ 重新创建 Key 或充值 |
| `模型不存在（404）` | `run.py models` 现查在架名，别写死 |
| 上游 502/503/504 | 脚本自动退避重试 4 次；仍失败是网关侧问题 |
| `未收敛，出口 = rounds_exhausted` | **这是真实结论，不是 bug**。看 `REPORT.md` 的未决项：加 `--rounds`、人工介入，或按写手卡在哪一句决定并稿 |
| `出口 = no_effective_change` | 写手在原地打转（正文相似度 ≥ 0.86）。**继续加轮次只会烧钱**，看必须修清单是不是写得太抽象 |
| `出口 = stalled_same_quote` | 审稿两次指向同一段文字。通常是那两个要求互相冲突，需要人来定口径 |
| `审稿锚点` 闸门命中 | 模型在编引文。看 `unanchored_issues` 里被剔出的引文；反复出现说明该模型不擅长引用原文，换模型 |
| `合规 veto` | 看 `findings` 里逐条的规则与引用。事实造假 / 虚假承诺换词救不回来，必须重写或弃稿 |
| `事实保全` 闸门命中 | 看「丢了哪个 + 出处在哪」。真丢就重跑或人工补；合法改写用 `--facts-warn-only` |
| 合规把 `fix` 降级成 `send_back` | 本地登记的安全替代词表里没有对应词（比如「国家级」）。表在 `run.py` 的 `SAFE_REPLACEMENTS`，可自行扩充 |
| `--outdir` 在包内退出码 2 | 产出**必须落包外**：包里只应该有待发布的白名单文件（`.md .py .txt .json .sh .js .yaml .yml .csv`），产出写进去会污染交付物 |
| 断点续跑没生效 | key 含材料摘要、稿件摘要、选题卡摘要、轮次、目标篇幅、各角色提示词版本、裁决口径版本；任一变化都会重跑（故意的）。要强跑用 `--force` |
| `unrecognized arguments: --out` | 本包**不允许长选项前缀缩写**（故意的：`--out` 曾被静默吃成 `--outdir`）。请写全 |

更多排错见 `references/成本与排错.md`。
