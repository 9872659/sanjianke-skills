# 角色与职权设计

> 本文件是三剪客 · 内容团队（L3 多智能体协作型）的角色设计说明。
> 代码里对应的唯一数据源是 `scripts/run.py` 的 `ROLES` 与 `ISOLATION_MARKERS` ——
> **文档与实现来自同一份数据**，提示词模板按它拼装、隔离检查按它验证。

## 一、为什么要有四个角色

内容协作里最贵的一种浪费，是**一件作品被四个人看过，等于被零个人看过**：

- 写手写完就交了 —— 因为从来没人会打回他；
- 审稿说"整体不错，建议加强逻辑" —— 因为挑不出具体句子也不会有人追究；
- 合规最后一眼扫过就放行 —— 因为前面已经说没问题了。

每个人的判断都建立在"别人已经看过了"这个假设上。L3 要做的事，
就是把这个假设**从结构上拆掉**：给每个角色一个**只有它能负责的目标**，
再给它一个**能否掉下一环的权力**。

## 二、四个角色的目标函数、产出物与否决权

| 角色 | key | 目标函数 | 产出物 | 否决权 |
|---|---|---|---|---|
| **策划** | `planner` | 选题够不够打、角度有没有新意。交出一张换谁都能写的通用选题卡就是失职 | 选题卡：受众 / 痛点 / 拟定标题 / 角度 / 差异化 / 3 条论据支柱 / 必须写进正文的硬信息 / 风险提示 | **能否掉平庸选题并重开**，上限 `--plan-retries` |
| **写手** | `writer` | 严格按选题卡把稿子写出来。写得再顺，偏离选题卡就是不合格 | 初稿正文 + 自评（`self_check`，**审稿看不到**） | **无** —— 写手只能改，不能否掉审稿或合规的结论 |
| **审稿** | `reviewer` | 结构 / 逻辑 / 可读性 / 信息密度。挑不出具体问题就是没干活 | 逐条问题清单，每条**必须原样引用稿子里真实存在的一句话** | **能打回写手**（`pass` / `send_back`），打回必须附「必须修」清单 |
| **合规** | `compliance` | 广告法 / 事实 / 平台规则。写得再好，不能发就是不能发 | 风险裁决：`pass` / `fix` / `send_back` / `veto` | **一票否决权**：判 `veto` 直接终止，产出带未决项 |

零成本查看这张表（含提示词版本）：

```bash
python3 scripts/run.py roles
python3 scripts/run.py roles --json
```

### 写手为什么没有否决权

这是刻意的。写手是**被审的对象**，一旦它能否掉审稿，整条链就退化成
"写手自己决定自己过不过"。写手唯一的权力是"改"，而改的依据必须是
**审稿锚定成功、进了 `must_fix` 的那几条**，不是它自己觉得该改什么。

### 策划为什么只否选题、不否稿子

策划的目标函数是"选题够不够打"，一旦让它参与后续评审，它就会开始为
自己刚选的选题辩护（承诺升级）。所以策划在交出达标的选题卡之后就不再出现，
后续的否决权只归审稿与合规。

## 三、信息不对称：L3 的立身之本

### 3.1 为什么这是分界线

「一个模型分四次扮演不同角色」的致命之处是**四个角色共享同一份上下文**：

- 审稿永远看不到一个它不知道的自评，所以它没法对"作者自己觉得这里写得好"
  做出警惕；
- 合规永远顺着审稿的结论走，因为审稿的意见就在上下文里。

于是产出里的"独立判断"其实是**同一个声音的自言自语**，对抗是假的。
判断一个包是不是真的 L3，只需要看一件事：
**它有没有办法让某个角色看不到某些东西，并且能证明它真的没看到。**

### 3.2 两层机制

**第一层：字段白名单（结构性）**

每个角色的 `inputs` 与 `forbidden` 是提示词模板真实读取的数据。
被排除的字段在物理上**没有进入 prompt 的路径**。

| 角色 | 允许进入上下文（`inputs`） | **被显式排除（`forbidden`）** |
|---|---|---|
| 策划 `planner` | `brief`、`target_chars` | （无 —— 它是链条第一环，没有上游） |
| 写手 `writer` | `brief`、`card`、`target_chars` | （无 —— 它是被审对象，事前不该知道审查口径） |
| 审稿 `reviewer` | `brief`、`card`、`draft` | **`self_check`、`writer_self_check`** |
| 合规 `compliance` | `brief`、`card_meta`、`draft` | **`self_check`、`issues`、`review_verdict`** |

两条最关键的排除：

1. **写手的自评 `self_check` 不进审稿的上下文** —— 审稿只拿到选题卡与正文，
   不知道作者自己觉得哪里好、哪里弱。
2. **审稿的 `issues` 与 `verdict` 不进合规的上下文** —— 合规只拿到
   「用户材料 + 选题卡**元信息** + 稿件正文」。

### 3.3 合规拿到的选题卡只有 2 个字段

`card_digest_for_compliance()` 把完整选题卡（8 个字段）压成一份**窄字典**：

```python
{"title": card.get("title") or "", "risk_note": card.get("risk_note") or ""}
```

不给受众、痛点、角度、差异化、论据支柱。理由是：给得越少，
它越不得不从**稿件正文本身**独立判断，而不是顺着策划搭好的框架走。
这一层即使有人把 `ROLES` 配置改宽了也依然生效。

### 3.4 合规提示词里的那句硬性纪律

合规的 system prompt 第 1 条：

> **本团队内部没有向你提供任何风险结论**，也不提供上一道工序的意见。
> 你不得假设「前面已经审过了所以没问题」，一切风险由你从稿件正文独立判断。

审稿的 system prompt 第 3 条：

> 你**只依据稿件正文与选题卡**判断。任何「作者自己的评价」都不该影响你；
> 如果它出现在你看到的内容里，忽略它并照常独立判断。

### 3.5 第二层：调用前实检（可验证）

`assert_isolation(stage, prompt_text)` 在**每次调用前**对**真实提示词文本**
扫一遍被禁字段的标记词（`ISOLATION_MARKERS`）：

| 被禁字段 | 标记词 |
|---|---|
| `self_check` | 自评、`self_check`、我认为写得好的地方、我自己的评价 |
| `issues` | 问题清单、审稿意见、审稿的、`issues` |
| `review_verdict` | 审稿结论、`review_verdict`、上道已经放行、审稿已通过 |

命中就抛 `IsolationBreach`，**这次调用一个字都不发出去**（省额度、不留假证据），
退出码 3。判定结果逐条写进产物与 `REPORT.md` 的「信息不对称验证」表：

| 阶段 | 角色 | 轮次 | 提示词字符数 | 被排除的字段 | 检查的标记词数 | 泄漏 | 结论 |
|---|---|---|---|---|---|---|---|
| reviewer | 审稿 | 1 | 2389 | self_check、writer_self_check | 4 | 无 | 通过 |
| compliance | 合规 | 1 | 1782 | self_check、issues、review_verdict | 12 | 无 | 通过 |

### 3.6 实测：这个检查真的会拦

```
A1 审稿正常 prompt        -> ok=True   excluded=[self_check, writer_self_check]  检查 4 个标记词
A2 审稿 prompt 注入"写手的自评" -> ok=False  leaked=[自评]
                              -> IsolationBreach：已中止本次调用
A3 合规正常 prompt        -> ok=True   excluded=[self_check, issues, review_verdict] 检查 12 个标记词
A4 合规 prompt 注入"审稿的问题清单：#1 … 审稿结论：pass"
                          -> ok=False  leaked=[问题清单, 审稿的, 审稿结论]
B  合规提示词里含"问题清单"? False   含"审稿"? False   含"self_check"? False   含"自评"? False
C  审稿提示词里含"自评"? False   含"我认为写得好的地方"? False
```

**复现方式**（零成本，不调模型）。
注意 `sys.dont_write_bytecode = True` 必须写在 `import` **之前** —— 否则这个自检
本身就会在包里留下 `run.pyc`（本包踩过这个坑，详见 `成本与排错.md` 的「.pyc 与包洁净度」）：

```bash
cd scripts
python3 -c "
import sys; sys.dont_write_bytecode=True; sys.path.insert(0,'.')
import run as R
card={'title':'T','audience':'A','pain':'P','angle':'角度要够具体才行',
      'differentiation':'D','pillars':['p1','p2','p3'],'must_keep':[],'risk_note':'R'}
good=R.build_review_prompt('材料',card,'这是一段稿件正文。')
print('正常:',R.check_isolation('reviewer',good)['ok'])
bad=good+'\n（顺带附上：写手的自评 good/weak 如下）'
print('注入:',R.check_isolation('reviewer',bad))
try:
    R.assert_isolation('reviewer',bad); print('FAIL 没拦住')
except R.IsolationBreach as e: print('OK 已拦住')
"
```

## 四、信息不对称带来了什么（实测后果）

因为拿不到上游结论，合规**才会独立发现写手与审稿都没提的问题**。
真机实测：合规在同一篇稿子上挑出 **5 条事实性问题**，全部不是措辞问题：

| # | 合规的发现 | 为什么审稿没提 |
|---|---|---|
| 1 | 7 个同事的小样本被外推成对读者的预测性结论（"结果大概率差不多"） | 审稿管的是结构与信息密度，不管"样本能不能外推" |
| 2 | 单一公司茶水间的耗材口径被写成"一年光滤芯就是 720 元"的**通用成本** | 审稿看的是这句话有没有支撑结论，不看数字的来源口径 |
| 3 | 个人单次转手亏损被写成"**才是**真实持有成本"这样的一般性结论 | 同上 |
| 4 | "维修一次通常要几百元"是无出处的价格断言 | 审稿不管事实出处 |
| 5 | "清洗习惯**决定**机器能用多久"是绝对化因果表述 | 审稿不按广告法口径读 |

一个顺着审稿结论走的合规角色**不会**发现这些 —— 它会看到
"审稿已放行"，然后把注意力放在更表面的措辞上。这就是信息不对称的价值。

## 五、局限性（如实说明）

1. **四个角色都是同一个大模型（默认 `deepseek-chat`）扮演的**，
   只是上下文被结构性隔开。这不是四家不同的模型在互审，
   所以"独立性"来自**信息边界**，不是来自模型多样性。
2. 隔离检查是**标记词文本级**的，不是信息流级别的强制。
   它的作用是：让"我不小心把自评塞进了审稿的提示词"这件事**必然被发现**，
   而不是靠人记得别塞。标记词表可以扩充（`ISOLATION_MARKERS`）。
3. 合规角色的裁决是**模型对文本的独立判断**，可能漏报也可能误报，
   **不能替代专业法务意见**，也不等于平台官方审核结论。
   高风险类目（医疗、保健食品、食品、金融、母婴、特殊化妆品）必须人工复核。
