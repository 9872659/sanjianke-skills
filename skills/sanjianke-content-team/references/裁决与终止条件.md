# 裁决与终止条件

> 本文件是三剪客 · 内容团队（L3）的裁决机制说明。
> 代码里对应的唯一入口是 `scripts/run.py` 的 `check_escalation()`、
> `EXIT_KIND`、`revision_effective()`、`normalize_review()`、`normalize_compliance()`。

## 一、裁决不是投票：它是串行的否决链

```
策划 ──▶ 写手 ──▶ 审稿 ──┬─ pass ──▶ 合规 ──┬─ pass / fix ──▶ 定稿
                        │                   ├─ send_back ──┐
                        └─ send_back ──┐    └─ veto ───────┼──▶ 带未决项产出
                                       └──▶ 写手修订 ◀──────┘
```

- **审稿不过，轮不到合规。** 稿子还没到"能不能发"的阶段。
- **审稿过了，合规仍可独立否决。** 这是两条独立的判断线，不是一次投票。
- **写手没有否决权。** 它唯一的权力是"改"。

## 二、谁能否谁：完整的裁决表

| 否决方 | 触发条件 | 后果 | 上限参数 | 上限用尽后 |
|---|---|---|---|---|
| **策划** | 选题卡被本地判不达标：角度 < 10 字、角度/差异化含空话（"多维度""全面分析"）、论据支柱不足 3 条或互为同义改写（相似度 ≥ 0.55）、受众描述太泛 | 换一个角度重开 | `--plan-retries`（默认 1，即最多试 2 次） | `plan_retries_exhausted` → 升级给人看 |
| **审稿** | 有任何一条 **高** 严重度问题 | 打回写手，附「必须修」清单 | 受 `--rounds` 约束（默认 2） | `rounds_exhausted` → 升级给人看 |
| **合规** | 判 `send_back` | 写手按合规要求再改一轮 | `--compliance-sendback`（默认 1） | `compliance_send_back_exhausted` → **带未决项产出** |
| **合规** | 判 `veto` | **直接终止** | 无（一票否决） | 产出即带未决项 |

### 策划的"不达标"是本地判的，不是模型自己说的

`normalize_card()` 逐条检查，模型判自己"达标"没用：

- `title` < 6 字 → 不达标
- `angle` < 10 字 → 写手无法据此动笔
- `angle` / `differentiation` 里出现 `多维度|全面分析|全面覆盖|综合分析|深入探讨|浅谈` → 空话
- `pillars` 数量 ≠ 3 → 不达标
- 任意两条 `pillars` 的字符二元组 Jaccard ≥ 0.55 → 互为同义改写
- `audience` < 4 字 → 太泛

只要有一条命中，就触发重开，并把命中的原因**写进下一次策划的提示词**
（"请换一个角度重出，不要只是把上一版换几个词"）与记录。

## 三、四种显式出口：谈不拢就说谈不拢

`check_escalation()` 是纯函数，只读参数、不掺任何"也许还能再跑一轮"的模糊判断 ——
模糊判断正是"假装谈拢"的来源。

| 出口 key | 判定条件 | 处理方式 | 退出码 |
|---|---|---|---|
| `stalled_same_quote` | 审稿连续两轮指向**同一段文字**仍然被拒（本轮 `must_fix` 引文与上轮交集 ≥ 一半） | 升级给人看 | 3 |
| `no_effective_change` | 连续两轮修订"没有实质改动" | 升级给人看 | 3 |
| `plan_retries_exhausted` | 策划重开上限用尽仍不达标 | 升级给人看 | 3 |
| `compliance_send_back_exhausted` | 合规打回次数用尽仍不放行 | **带未决项产出** | 3 |
| `rounds_exhausted` | 轮次用完，审稿仍判打回 | 升级给人看 | 3 |

判定顺序即上表顺序（`stalled_same_quote` 优先，因为它比"轮次用尽"更具体）。

### 「没有实质改动」怎么判

`revision_effective()` 同时看两个量，缺一不可：

| 判据 | 阈值 | 阈值为什么这么定 |
|---|---|---|
| 新旧稿正文相似度（字符二元组 Jaccard） | **≥ 0.86 即判"等于没改"** | 实测判打回后正常修订的相似度是 0.69；0.90 那一次是写手只动了几个词 |
| 自报已修条数 / 被点名条数 | **< 0.50 即判"没修够"** | 防"说已修但正文没变"；单纯看自报会被模型的话术骗过 |

连续两轮命中（`MAX_NO_CHANGE_STRIKES = 1` → `strikes > 1`）才升级。
为什么不是一轮就升级：第一轮可能是模型理解错了清单，给它一次修正的机会；
连续两轮不动就是真的不动，继续跑只是烧钱。

**实测**：某一轮修订的正文相似度是 **0.90**，被本地判为
"本轮修订没有实质改动：新稿与上一稿的正文相似度 0.90 ≥ 0.86，等于没改"，
并记进裁决记录（`decision = ineffective`）。

### 为什么"未收敛"必须走退出码 3

`run` 的语义是「要么达标、要么明确不达标」。把未收敛的产出用退出码 0 交出去，
CI 里就分不出"这条稿子过关了"和"这条稿子还在打架"。所以：

- 收敛（审稿放行 + 合规放行 + 硬闸门全过）→ **退出码 0**
- 任何出口 → **退出码 3**，且 `escalation.unresolved` 逐条写明未决项

实测同题材的两种结局：

| 运行 | 结局 | 调用 | token | 退出码 |
|---|---|---|---|---|
| 一次放行 | 审稿 `pass` + 合规 `pass` | 4 | 6,984 | **0** |
| 四轮未收敛 | 审稿连续打回 → `rounds_exhausted` | 9 | 28,411 | **3** |

## 四、本地兜底：模型说了不算的三件事

模型可以给出任何裁决，但下面三种情况由**本地**强制改判：

| # | 模型给的裁决 | 本地发现 | 本地强制改为 |
|---|---|---|---|
| 1 | 审稿 `pass` | 清单里有 **高** 严重度问题 | `send_back`，并在 `verdict_forced_reason` 里说明 |
| 2 | 合规 `pass` 或 `fix` | 有 **高** 风险发现 | `veto`（一票否决权不许被模型自己放弃） |
| 3 | 合规 `pass` | 本地违禁词扫描命中 | `fix`（若全在安全替代词表里）否则 `send_back` |

第 2 条的实测记录（黑稿用例）：

```
合规自报 verdict: veto      风险等级: 高
本地违禁词扫描命中 10 处：[最低/高, 全网最低/高, 第一/高, 行业第一/高,
                          国家级/高, 100%/高, 保证有效/高, 独家/中,
                          纯天然/中, 加微信/中]
本地兜底 local_notes: []（模型自己就判了 veto，本地无需改判）
退出码: 3
```

## 五、合规的 `fix` 走的是本地替换，不是再调一次模型

合规判 `fix` 时，本包**不**让模型去改写（那会引入新的不确定），而是：

1. 查本地 `SAFE_REPLACEMENTS` 登记表，只替换**登记过安全替代词**的那些词
2. **复扫**：替换后重新跑一次本地违禁词扫描
3. 复扫干净 → `auto_fixed_verified`，放行（退出码 0）
4. 复扫仍不干净 → 按**否决**处理，走 `compliance_send_back_exhausted`
5. 表里没有安全替代词的（例如「国家级」）→ 直接降级为 `send_back`

替换记录逐条进流水（`「最好」→「较合适」`），不静默改稿。

## 六、审稿的锚点闸门：不可执行的清单不许往下走

审稿的每条问题必须引用稿子里真实存在的一句话。本地校验三步递进：

| 判据 | 门槛 | 说明 |
|---|---|---|
| `exact` | 归一化（去标点空白）后与某一整句完全相同 | — |
| `substring` | 归一化后是某一整句的一部分（或反之），且公共长度 ≥ 4 字 | 只引半句最常见 |
| `fuzzy` | 与最像的那一句 Jaccard ≥ 0.55，且引文 ≥ 8 字 | 轻改写式引用 |
| `unverified` | 以上都不成立 | **判为锚点幻觉** |

- 未锚定的引文**不进写手的修订输入**（它本来就不可执行）
- 未锚定率 > **40%** → 判「定位失败」，`anchor.ok = False`
- 判失败后走 `rounds_exhausted` 出口升级给人看，而不是拿一份编造的清单去改稿

**两个门槛为什么不一样**：「引文恰好是某句的连续片段」是**精确**判断，
短一点也几乎不误伤；「最像的那一句」是**统计**判断，短串的二元组集合太小、
相似度会虚高，所以必须卡长度。一个门槛管两件事，就会出现
"6 个字的真实引文被判成幻觉"这种把真问题算成假问题的情况。

**实测**：审稿第一轮给出 7 条问题，**全部锚定成功、未锚定率 0%**，
引用的是「公司茶水间那台全自动采购价4600元，行政说每3个月换一次」这样的原句。

## 七、全过程记录：谁在第几轮改了什么

`log` 写三张表，全部落在 `REPORT.md` 与 `log.json`：

1. **裁决记录**：`# / 角色 / 轮次 / 裁决 / 理由 / 引用原句 / 本地兜底`
2. **动作流水**：`# / 阶段 / 角色 / 轮次 / 动作 / 说明`（含每轮字数变化、自报修几条、相似度）
3. **信息不对称验证**：每次调用的被排除字段、检查的标记词数、是否泄漏

读回来：

```bash
python3 scripts/run.py log --outdir /tmp/ct
```

输出会直接回答一个尖锐的问题：

> 这份记录里 5 条裁决中有 4 条是否决/打回类决定 ——
> **如果这个数是 0，说明多角色互审没有真的发生。**

实测两次运行分别是 `4/5`（未收敛）与 `0/3`（一次放行）。
**前者证明对抗存在，后者证明对抗不是每次都必然发生** —— 两种都要如实报出来。
