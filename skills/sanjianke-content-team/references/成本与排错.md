# 成本与排错

> 本文件是三剪客 · 内容团队（L3）的成本口径与排错手册。
> 成本相关的常量在 `scripts/run.py`：`CHARS_PER_TOKEN_IN`、`TOKENS_PER_CHAR_OUT`、
> `POINTS_PER_YUAN`、`estimate_calls()`、`CostTracker`。

## 一、只出 token，不编金额

文本模型网关**不公布单价**，`/api/v1/models` 的返回里也没有价格字段。
所以本包只做两件事：

1. 按标定比例**估 token**（这是确定性的，可复核）
2. 金额**要你自己填单价**（`--price-in` / `--price-out`，单位「点 / 百万 token」）

不给单价时，`cost` 与 `run` 都会明确写「**网关不公布文本单价，未折算**」，
而不是给一个看起来像真的的数。**本包不编价。**

用 `--budget` 时**必须**同时给单价 —— 没有单价就无法核预算，
`check_budget()` 会直接报用法错（退出码 2），不会假装在预算内。

## 二、字符 → token 标定

| 方向 | 比例 | 来源 |
|---|---|---|
| 输入 | 1 token ≈ **1.61** 个字符 | 同族实测标定（真实 `rewrite --all` 的 5 次调用） |
| 输出 | 1 个字符 ≈ **1.11** token | 同族实测均值（平台间 0.93~1.63，差异几乎全来自换行） |
| 金额 | 1 元 = **100** 点 | 网关口径 |

**这是估算，不是账单。** 真实扣费以账户流水为准。

## 三、一次协作的调用构成

`estimate_calls()` 按**最坏情况**估（含策划重开与合规打回各一次的上界），
因为轮次是"最多几轮"，报价按上限才不会被低估。

| 阶段 | 次数 | 输入含什么 | 输出 |
|---|---|---|---|
| 策划 · 选题卡 | 1 + `plan_retries` | 只有用户材料 | 选题卡 JSON |
| 写手 · 初稿 | 1 | 用户材料 + 选题卡 | 初稿正文 + 自评 |
| 审稿 · 问题清单 | `rounds` | 用户材料 + 选题卡 + 稿件（**无写手自评**） | 问题清单 JSON |
| 写手 · 修订 | `rounds` | 当前稿 + 锚定过的必须修清单 + 事实清单 | 修订稿 + 改动说明 |
| 合规 · 风险裁决 | 1 + `compliance_sendback` | 用户材料 + 选题卡**元信息** + 稿件（**无审稿意见**） | 裁决 JSON |

**注意合规每轮都会重跑，而且不带上一次的合规意见**。这是刻意的：
带上一次意见会让它顺着自己上一轮的结论走。代价是 `send_back` 会多花一次调用。

## 四、真机实测成本（600 字目标，`deepseek-chat`）

| 场景 | 调用次数 | prompt | completion | total token | 按 1000/2000 点每百万折算 |
|---|---|---|---|---|---|
| 一次放行收敛 | 4 | 5,361 | 1,623 | **6,984** | 8.6 点 ≈ **¥0.086** |
| 两轮未收敛 | 5 | 8,831 | 5,906 | **14,737** | 20.6 点 ≈ **¥0.206** |
| 四轮未收敛 | 9 | 18,798 | 10,653 | **29,451** | 40.1 点 ≈ **¥0.401** |
| 合规单次裁决（独立调用） | 1 | 1,413 | 962 | 2,375 | ≈ 3.3 点 ≈ ¥0.033 |

**观测到的规律**：成本主要随"审稿打回几轮"线性增长，不随稿件质量波动。
一次放行只要 4 次调用；每多一轮打回就多 2 次调用（1 次审稿 + 1 次修订）。

### 怎么把成本压住

1. **先 `--dry-run`**：看清提示词再决定跑不跑，零成本
2. **先 `cost`**：按最坏情况看预算，零成本
3. **给 `--budget` 与单价**：超了会在**发起下一次调用前**停下（退出码 5），
   不是跑完才发现超了
4. **`--rounds` 别开太大**：2 轮能解决绝大多数情况。开到 4 轮还没收敛的，
   问题通常不在"轮次不够"，而在"必须修清单太抽象"或"两个要求互相冲突"
5. **断点续跑**：同一个 `--outdir` 重跑只打印"已在断点里，跳过"，0 次调用
6. **别对同一份材料反复跑**：选题卡与初稿都在断点里，参数没变就不会重跑

## 五、退出码

| 码 | 含义 | 典型原因 |
|---|---|---|
| **0** | 定稿 | 审稿放行 + 合规放行 + 无硬闸门命中 |
| **2** | 用法/配置错 | 文件不存在、`--outdir` 在包内、`--budget` 没配单价、`--rounds 0`、`--target-chars` 越界、`run` 用了 `--out`、长选项缩写 |
| **3** | 硬闸门命中，或**未收敛** | 违禁词 / 占位符 / 照抄示例 / 审稿锚点失败 / 丢事实 / 篇幅出区间 / 合规 veto / 四种出口 |
| **4** | 调用失败 | 网络、鉴权 401、点数 402、模型名 404 |
| **5** | 预算超限，已就地中止 | **未发起任何调用** |
| **130** | 用户中断 | Ctrl+C |

### `--json` 契约

- **成功**：结果对象里带 `"ok": true`；顶层是数组时包成 `{"ok": true, "data": [...]}`
- **失败**：stdout 输出 `{"ok": false, "exit": <码>, "error": {"kind": …, "message": …}}`，
  `kind` 取 `usage` / `gate` / `call` / `budget` / `interrupt` / **`internal`**
- **stdout 永远只有一个 JSON**（已经吐过结果的不再补信封）
- **未捕获异常**一律 `kind: "internal"` + 退出码 1 + **完整 traceback 到 stderr**
- `--json` **写在子命令前后都可以**

```bash
# 两种位置等价
python3 scripts/run.py roles --json
python3 scripts/run.py --json roles
```

## 六、排错表

### 配置与调用

| 现象 | 原因与处置 |
|---|---|
| `没有找到 API Key` | `--key` / `A7W_API_KEY` / `a7w.py login` 三选一 |
| `鉴权失败（401）` | Key 无效或过期，到 https://api.a7w.cn/ 重新创建 |
| `点数不足（402）` | 充值后重试 |
| `模型不存在（404）` | `run.py models` 现查在架名，别写死 |
| 上游 502/503/504 | 脚本对 5xx 与网络类错误退避重试 4 次；仍失败是网关侧问题 |
| `模型没返回 choices` | 网关侧异常，重试；持续出现换个模型 |
| `模型返回的不是合法 JSON` | 用 `--no-json-mode` 试；持续出现说明该模型不擅长结构化输出 |

### 协作流程

| 现象 | 原因与处置 |
|---|---|
| `出口 = rounds_exhausted` | **这是真实结论，不是 bug**。看 `REPORT.md` 的未决项，判断加 `--rounds` 还是人工介入 |
| `出口 = plan_retries_exhausted` | 策划交不出达标卡。加 `--plan-retries`，或把材料给得更具体（材料太空时策划只能写空话） |
| `出口 = no_effective_change` | 写手在原地打转（正文相似度 ≥ 0.86）。**继续加轮次只会烧钱**，看必须修清单是不是写得太抽象 |
| `出口 = stalled_same_quote` | 审稿两次指向同一段文字。通常是两个要求互相冲突（例如"要短"与"要信息密度"），需要人定口径 |
| `出口 = compliance_send_back_exhausted` | 合规打回次数用尽。加 `--compliance-sendback`，或按 `findings` 人工改写 |
| 合规判 `fix` 但被降级 | 本地 `SAFE_REPLACEMENTS` 里没有对应安全替代词（例如「国家级」）。表在 `run.py`，可自行扩充 |
| 合规把 `fix` 变成 `veto` | 有 **高** 风险发现。这是本地兜底，不是模型乱判；看 `findings` |
| 审稿 `pass` 被本地改判 `send_back` | 清单里有 **高** 严重度问题。看 `verdict_forced_reason` |

### 闸门误报

| 现象 | 处置 |
|---|---|
| `审稿锚点` 闸门命中 | 模型在编引文。看 `unanchored_issues` 里被剔出的引文；反复出现说明该模型不擅长引用原文，换模型 |
| `事实保全` 闸门命中 | 看「丢了哪个 + 出处在哪」。真丢就重跑或人工补；合法改写（`87%` → `接近九成`）用 `--facts-warn-only` |
| `篇幅` 闸门命中 | 区间是 目标 ±15% 再叠绝对容差 `max(15, 目标×2%)`。目标 600 → 495~705。真跑偏就调 `--target-chars` |
| 违禁词误报 | 看 stderr 的「本地放过 N 处疑似绝对化用语」提示与产物里的 `exempted`。已内置「最X」上下文豁免与「第一」序数豁免 |
| `--outdir` 在包内退出码 2 | 产出**必须落包外**：上传白名单只收 `.md .py .txt .json .sh .js .yaml .yml .csv` |

### 断点与参数

| 现象 | 处置 |
|---|---|
| 断点续跑没生效（重跑了） | key 含材料摘要、稿件摘要、选题卡摘要、轮次、目标篇幅、`model`、`temperature`、`rounds`、各角色提示词版本、裁决口径版本。**任一变化都会重跑（故意的）**。要强跑用 `--force` |
| `unrecognized arguments: --out` | 本包**不允许长选项前缀缩写**（故意的：`--out` 曾被静默吃成 `--outdir`）。请写全 |
| `run` 报 "没有单文件产出" | `run` 的产物是目录，用 `--outdir`。要单文件结果用 `plan`/`draft`/`review`/`compliance` 的 `--out` |
| `--target-chars` 越界 | 可用区间 200~4000 |
| `--rounds 0` 报错 | 本包语义是"策划 → 写手 → 审稿 → 修订"，0 轮没有协作可谈。只要质检不要协作用 L2 的内容质量闭环 |

### .pyc 与包洁净度

**先把一件事说清楚：`.pyc` / `__pycache__` 在 CLI 的排除清单里，本来就不会被打包上传，
不会导致上传被拒。** 清掉它只是让交付物保持干净，不是上传的硬前提。
（这一段早先写过"包内绝不能出现 .pyc，会直接 400"，那是错的，已更正。）

`scripts/run.py` 在 `import a7w` **之前**设了 `sys.dont_write_bytecode = True`。
实测（CPython 3.11.9，干净临时目录逐格对照）：

| 场景 | 结果 |
|---|---|
| `python run.py roles`（正常直跑） | 一个 `.pyc` 都不生成 |
| 另一个脚本 `import run`，**且先设了 flag** | 一个 `.pyc` 都不生成 |
| 另一个脚本 `import run`，**没设 flag** | 生成 `__pycache__/run.cpython-311.pyc` |
| `python -m py_compile run.py` | 生成 `__pycache__/run.cpython-311.pyc` |

三条结论：

1. **flag 有效**，但**必须设在被 import 的模块之前**。迟一行，那个模块就已经落盘了。
2. **入口脚本作为 `__main__` 永远不会被字节码缓存** —— 直跑不会产生 `run.pyc`。
3. **会生成 `run.pyc` 的情形只有两种**：有工具把入口当模块 `import` 了
   （零成本自检脚本、测试框架最常见），或者跑了 `py_compile`。

本项目就踩过第 1 种：一份自检脚本写了 `import run as R`，于是包里多了 `run.pyc`。
所以写自检脚本时要么**别 import 入口**，要么在 import 之前先设 flag：

```python
import sys
sys.dont_write_bytecode = True      # 必须在 import 之前
sys.path.insert(0, "scripts")
import run as R                     # 这样即使 import 了入口也不落 .pyc
```

复核（跑完任意命令之后）：

```bash
cd scripts
python3 -c "
import pathlib, sys
p = list(pathlib.Path('..').rglob('*.pyc'))
print('.pyc 数量:', len(p))
sys.exit(1 if p else 0)
"
```

`python3 -m py_compile run.py` 会生成 `.pyc`（编译检查的正常行为，与运行时 flag 无关），
检查完删掉即可：

```bash
rm -rf __pycache__
```

## 七、模型名怎么选

```bash
python3 scripts/run.py models
```

- 模型名会变，以现查为准，别写死
- `deepseek-chat` 这个别名实测可用（路由到 `deepseek-flash`），
  但它**不在** `/api/v1/models` 的返回列表里 —— 「列表里没有」不等于「不能用」
- 本包对模型的真实要求：**能被要求输出 JSON 对象**、**能原样引用原文句子**。
  第二点尤其重要（审稿锚点靠它）。若某模型锚定率持续偏低，换模型再试
