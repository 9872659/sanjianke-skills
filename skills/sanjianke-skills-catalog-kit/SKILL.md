# 三剪客 · 技能生态实战

在公开技能目录里读懂、挑对、装稳，并自己写出能被触发的技能。

现在的 Agent 技能生态已经过了「有没有」的阶段，进入「怎么挑」的阶段：一个公开目录里躺着几十个技能，官方精选、官方内置、社区实验混在一起；你装了一个，Agent 该用的时候不用，不该用的时候乱用；你想自己写一个，写完发现它从来不触发。

这套 Skill 讲的是技能生态本身的方法论——**目录是怎么组织的、一个技能凭什么值得装、你写的技能为什么触发不了**。它不替你搬运任何一个具体技能，只给你判断力和检查清单。

**读完你会拿到**：4 份参考文件（生态读法、选型打分、触发排查、安全审查）、1 张六维打分卡、1 张触发失灵速查表、1 份装前审查清单。

## 触发场景

- 「这个技能目录里几十个技能，我到底该装哪几个？」
- 「官方精选、官方内置、社区实验，这几层有什么区别？哪个能信？」
- 「这个技能看着挺好，装之前我该检查什么？」
- 「我装了个技能，Agent 从来不主动用它，是不是白装了？」
- 「我自己写了个技能，放进去根本不触发，跟没写一样。」
- 「两个技能好像干的事差不多，能一起装吗？」
- 「技能描述里那句『什么时候用』该怎么写？」

## 快速开始

最小可用路径是**先分层、再打分、最后才装**。整个过程 20 分钟，产出是一张打分卡和一份审查记录，不是一长串安装命令。

**第 1 步 · 认目录分层（3 分钟）**

不看技能名字，先看它躺在哪一层。层级决定了它的来源、可信度和可用性——同一件事，在三层里可能是三个完全不同的东西。分层读法和各层的取舍见 `references/reading-a-catalog.md`。

| 常见分层 | 大致含义 | 你要做的动作 |
|---|---|---|
| 内置层（随客户端版本走） | 出厂自带，随版本更新，不由你控制 | 知道它存在即可，别重复装 |
| 精选层（官方筛选过） | 有人筛过一遍，质量和维护有基本保证 | 优先从这里挑 |
| 实验层（社区/新提交） | 未经筛选，思路新但风险和维护性未知 | 想试就试，但必须走安全审查，且别用在生产路径上 |

一个信号值得记住：**很多目录的说明里会写「安装后重启客户端才生效」**。如果你装完没重启就说「没效果」，那不是技能的问题。

**第 2 步 · 过六维打分（7 分钟）**

拿你真正想解决的**一个具体任务**，对着候选技能逐维打分。**总分低于 70 就别装**——装了也是躺在目录里。打分卡的完整口径、每维的「0/1/2 分长什么样」见 `references/choosing-skills.md`。

| # | 维度 | 一句话判据 |
|---|---|---|
| 1 | 触发匹配 | 它的「何时使用」描述，和你张口会说的那句话对得上吗？ |
| 2 | 任务契合 | 它解决的是你的问题，还是它自己定义的问题？ |
| 3 | 依赖成本 | 装它要不要额外装 CLI、SDK、账号、密钥、运行时？ |
| 4 | 维护活力 | 最近半年有实质性更新吗？还是提交完就没人管了？ |
| 5 | 职责重叠 | 和你已有的技能撞不撞？会不会两个一起触发？ |
| 6 | 可审性 | 你能读懂它到底会做什么吗？读不懂就是不可接受的风险 |

**第 3 步 · 走安全审查（7 分钟）**

再好的技能，只要它带脚本、带钩子、带外部调用，装之前都要过一遍清单。**最需要盯的是「它会读什么、会往外发什么、会改什么」这三件事**。完整清单和逐项判据见 `references/security-review.md`。

**第 4 步 · 装、试、留痕**

装完不要凭感觉判断有没有用。用 3 个你真实会说的句子去试：它在该触发的时候触发了吗？在不该触发的时候安静吗？两次结果稳定吗？

**第 5 步 · 不好用就删，别将就**

技能是提示词层的约定，装了不用只会污染上下文——一个不触发的技能，代价不是零，是**它占着描述、干扰路由、还可能和别人打架**。删掉比留着更划算。

## 能力边界

**覆盖**：

- 读懂一个公开技能目录的**组织方式**：分层含义、目录内的文件约定、安装与生效机制
- 给一份**可打分的选型判据**（六维、每维三级、总分阈值），把「感觉不错」变成可复述的理由
- 提供技能**从想法到可用**的完整流程：先找具体用例、再定复用边界、然后才写正文
- 给出**描述字段（触发面）的写法**，以及渐进披露的拆分规则（正文放什么、`references/` 放什么）
- 提供**触发不稳定的排查路径**：从描述字段、命名、重叠、上下文四个方向定位
- 提供**第三方技能的安全审查清单**：脚本、网络、文件、凭证、注入五个面
- 提供「权限与用途说明」「能力边界」两个区块的**如实写法示例**

**不覆盖**：

- **不搬运、不复制任何具体技能的内容。** 它教你判断一个技能好不好，不会替你把某个技能的实现抄进来。需要具体技能就去装，别指望从这里拿到。
- **不做自动化的安全扫描。** 清单是给人读的检查表，不是静态分析器。真正的隔离靠沙箱和权限配置，本 Skill 给不了硬保证。
- **不替代技能客户端的官方文档。** 不同客户端对 frontmatter 字段、目录名、加载顺序的支持有差异，字段的权威定义以你所用客户端的文档为准。
- **不负责在团队里推行技能体系。** 「该不该沉淀、怎么评审、怎么排期铺开」是组织问题，属于另一套方法论，本 Skill 只处理生态层面的读、挑、审、写。
- **不生成具体领域的业务技能内容。** 不会替你写出「发版流程」的实际步骤，只给框架和检查点。
- **不做技能的版本管理与分发。** 多仓库共享、私有源、灰度发布需要你们自己定机制。

## 依赖条件

- **必需**：能读写 Markdown 文件。纯文本即可，不需要工具链。
- **必需**：一个能加载技能目录的 Agent 客户端（否则你只能纸上打分，验证不了触发）。
- **推荐**：本地已下载的技能目录副本。审查一项就得能看见 `SKILL.md` 和 `scripts/` 的真实内容，只看网页上的介绍等于没审。
- **推荐**：一个干净的一次性环境（容器或临时用户）。要试实验层的技能，别在自己的主力账号下试。
- **不需要**：网络、API Key、数据库、Docker、任何付费服务。本 Skill 自身不联网。

## 已知限制

1. **生态在快速变动，分层命名不统一。** 「内置 / 精选 / 实验」是当前常见的一种分法，换一个目录可能叫别的名字或换一种切法。本 Skill 给的是**识别分层的方法**，不是一份固定的目录名清单——看到新名字，用「来源是谁、谁筛过、凭什么叫这个名字」三问去套。
2. **打分卡压不住主观判断。** 六维打分能减少拍脑袋，但「任务契合」「可审性」这两维终究要你负责。分数一致而结论不同是正常的，把理由写下来比改分数有用。
3. **触发是概率行为，不是开关。** Agent 是否主动调用一个技能，取决于客户端实现、当前上下文、技能数量和其他技能的竞争。**没有任何描述字段能保证 100% 触发**。重要流程别指望自动触发，在项目级指令文件里显式指路更可靠。
4. **技能之间会互相污染。** 两个技能覆盖同一场景时，Agent 可能各取一半，产出比只用其中一个更差。这种冲突目前只能靠人工发现——所以第 2 步的「职责重叠」维度必须认真打。
5. **安全审查清单不覆盖混淆代码。** 它能拦住「明显越界」的脚本，拦不住刻意隐藏的恶意逻辑。审查通过不等于安全，只等于「我没看出问题」。
6. **不含任何可执行脚本。** 判断与审查全靠人按清单走，本 Skill 不带校验工具——避免把「格式合规」误当成「内容合格」。

## 自检清单

**挑技能时**，逐条打勾：

- [ ] **看过分层**：我知道它来自哪一层，以及那一层的可信度意味着什么
- [ ] **任务具体**：我是带着一个真实任务去挑的，不是「看着有用先装上」
- [ ] **打分完整**：六维都打了分，总分 ≥ 70，且没有任何一维是 0
- [ ] **读得懂**：我能用自己的话复述它「什么时候用、会做什么、做完是什么样」
- [ ] **不重叠**：我确认已有技能里没有覆盖同一个触发面
- [ ] **审查过关**：脚本、网络、文件、凭证、注入五个面都过了，没有触碰红线项
- [ ] **验证过触发**：装了之后用真实句子试过该触发和不触发两种情况
- [ ] **留了退路**：知道怎么卸载，并且是在能回退的环境里试的

**写技能时**，逐条打勾：

- [ ] **有具体用例**：动笔前先写了 3 个「用户会怎么开口」的真实句子
- [ ] **描述先行**：description 里明确写了「何时使用」，用的是用户真会说的话
- [ ] **命名干净**：小写连字符，名字本身就说明了做什么
- [ ] **正文精简**：正文只放每次都要用的步骤；长资料已分流到 `references/`
- [ ] **自由度对**：该由脚本硬约束的地方给了脚本，该留判断的地方没写成死步骤
- [ ] **边界成对**：同时写了「覆盖」和「不覆盖」，且「不覆盖」不是敷衍的「其他」
- [ ] **权限如实**：权限表逐项填了，没申请的能力如实写「否」
- [ ] **无凭证/无敏感信息**：正文、示例里没有真实密钥、Token、内网地址、客户名
- [ ] **可验证**：结尾有能让执行者自证的检查点，不是「完成后告知用户」
- [ ] **触发测过**：拿真实句子测过；不触发就按 `references/trigger-troubleshooting.md` 定位过
