# 三剪客 · 极速无损压缩命令行工具

`lz4` 是一个把速度放在第一位的无损压缩命令行工具：默认档位的压缩速度按项目文档是每核 500 MB/s 以上，解压能到 GB/s 级，所以它常出现在日志归档、备份流水线、镜像层压缩这类不能忍慢的地方。它的命令行长得很像 `gzip`，但有几处关键差异必须先记住：默认只压单个文件、`lz4 file1 file2` 是把 file1 压进 file2、以 `.lz4` 结尾的输入默认走解压、并且默认保留源文件。

**上游项目**：`lz4`　**仓库**：https://github.com/lz4/lz4

## 什么时候用 / 不用

**用它**：

- 需要快速压缩或解压一个文件、一条流，速度比压缩率重要（默认档位就是为速度调的）。
- 在流水线里做流式压缩：`tar -cf - dir | lz4 -9 > dir.tar.lz4`。
- 归档后想验证完整性（`lz4 -t`）或想知道包里的帧信息（`lz4 --list`）。
- 想把多个 `.lz4` 直接拼接成一个仍可解压的文件（连接语义天然支持）。
- 小文件多、重复度高，想用字典压缩提升效果；或愿意用 `-9`、`-12`、`--best` 换更高压缩率、用 `--fast` 换更快速度。

**不要用它**：

- 存储成本远高于 CPU 成本、追求极限压缩率——换更高压缩比的编码器更合适。
- 需要归档语义（一次打包整个目录树并保留权限、属主、时间戳）——它只压字节流，归档必须配 `tar`。
- 需要加密或口令保护——它不提供任何加密。
- 需要随机访问压缩包里的某一段——`.lz4` 是流式帧格式，不是可随机定位的容器。
- 接收端的工具链只认 gzip/bzip2/xz——很多老工具不认 `.lz4`，先确认对方能解再压。

## 安装

```bash
# 源码构建（任何平台都能走这条路）
make
sudo make install          # 可能需要 root 权限

# 各发行版包管理器（包名以发行版为准，拿不准先搜一下 lz4）
sudo apt install lz4       # Debian / Ubuntu
sudo dnf install lz4       # Fedora
brew install lz4           # macOS
sudo pacman -S lz4         # Arch
sudo apk add lz4           # Alpine
```

`make` 支持标准 Makefile 约定，包括 `DESTDIR` 分段安装与 `-j` 并行构建。

Windows 上可以用 vcpkg：

```bash
git clone https://github.com/Microsoft/vcpkg.git
cd vcpkg
./bootstrap-vcpkg.sh
./vcpkg integrate install
./vcpkg.exe install lz4
```

也可以自行用源码加 C 编译环境构建；Windows 预编译包以发行版页面为准。

## 常用操作

```bash
# 1) 压一个文件：默认生成 photo.png.lz4，并保留原文件
lz4 photo.png

# 2) 解压：输入以 .lz4 结尾时默认就是解压模式
lz4 photo.png.lz4

# 3) 显式指定输入与输出，脚本里务必这么写，别依赖隐式命名
lz4 photo.png photo.png.lz4
lz4 -d photo.png.lz4 restored.png

# 4) 管道流式压缩与解压（原始大小未知时不要指望 --content-size）
tar -cf - ./logs | lz4 -9 > logs.tar.lz4
lz4 -dc logs.tar.lz4 | tar -xf -

# 5) 速度与压缩率的取舍
lz4 -1 big.iso big.iso.lz4      # 最快档
lz4 -9 big.iso big.iso.lz4      # 文档推荐的高压缩档
lz4 --fast=5 big.iso out.lz4    # 比默认更快，代价是体积
lz4 -9 -T0 big.iso out.lz4      # 多线程压缩，-T0 表示按本机核心数自动定

# 6) 批量、校验、查看包内信息
lz4 -m *.log                    # 多个文件逐个压成 *.log.lz4，源文件保留
lz4 -t logs.tar.lz4             # 只做完整性校验，不产生也不删除文件
lz4 --list -v logs.tar.lz4      # 列出一个或多个包的帧信息
lz4 -m --rm *.log               # 压缩成功后删除源文件，行为更接近 gzip
```

也可以用环境变量设默认值：`LZ4_CLEVEL` 指定默认压缩档位，`LZ4_NBWORKERS` 指定默认压缩线程数；两者优先级低于命令行参数。

## 常见坑

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 想压两个文件，结果只有一个产物 | 语法是 `lz4 [输入] [输出]`，第二个参数被当成输出文件名 | 批量用 `-m`；要写标准输出用 `-c` |
| 脚本里产物跑到别处去了 | 不指定输出时：stdout 不是终端就写 stdout，是终端才写成 `<名字>.lz4` | 脚本里永远显式写 `-c` 或写全输入输出名，别依赖隐式命名 |
| 压完源文件还在（或反过来被删） | 默认保留源文件，只有 `--rm` 才删 | 想模拟 gzip 用 `lz4 -m --rm`；不确定就先不删 |
| 从管道压缩时 `--content-size` 不生效 | 原始大小未知，无法写进帧头 | 需要该字段就先落盘成文件再压；纯管道场景不要依赖它 |
| 解压报格式不识别或校验失败 | 加压两端用了不同的字典，或输入根本不是 `.lz4` 帧 | 字典压缩必须两端用同一个 `-D <字典文件>`；想把普通文件当 `cat` 用要加 `-f` |
| `-l` 和 `-m` 或 `-r` 一起用报错 | 旧式 legacy 格式与多文件模式不兼容 | 二选一；legacy 只留给确实需要它的老场景 |
| 加了 `-T` 却没更快 | 数据量太小，或本来就是单块；解压本身是单线程 | 用 `-T0` 让线程数跟随核心数；小文件别指望提速，解压速度在各档位都一样 |
| 旧压缩包被悄悄覆盖 | 目标已存在时默认不会强行覆盖，`-f` 才会 | 归档脚本里明确决定是否加 `-f`，避免无意覆盖旧包 |
| 以为 `-9` 会拖慢解压 | 档位只影响压缩速度与体积，所有档位解压速度相同 | 需要「压得小」就用高压缩档，不用担心解压变慢 |
| 拼接后的包行为不符合预期 | 拼接是被支持的，解压时按单个流依次处理 | `cat a.lz4 b.lz4 > c.lz4` 可以，`lz4cat c.lz4` 等价于按顺序 `cat` 原始内容 |
| 环境变量设了看不出效果 | 命令行参数优先级高于环境变量，环境变量高于程序内置默认值 | 想在全局统一默认值时才用 `LZ4_CLEVEL` 与 `LZ4_NBWORKERS` |

## 权限与用途说明

| 能力 | 是否申请 | 用途 |
|---|---|---|
| 网络访问 | 否 | 压缩与解压全部本地完成；只有你自行安装或下载时才联网 |
| 读取文件 | 是 | 读取待压缩的输入文件或标准输入流 |
| 写入文件 | 是 | 生成 `.lz4` 输出文件；加了 `--rm` 时还会删除源文件（默认不删） |
| 凭证 | 否 | 不需要账号、Token 或 Key；它也不提供加密功能 |
| 子进程 / 后台常驻 | 否 | 前台一次性进程；`-T` 只增加压缩线程，不常驻后台 |

## 触发场景

- 「帮我快点压一下这个几百 G 的日志文件」
- 「tar 出来的东西怎么压得更小、解压更快」
- 「这个 `.lz4` 文件坏没坏，校验一下」
- 「这个压缩包是什么时候压的、压了几帧」
- 「压完把原文件删掉，别留两份占空间」
- 「批量把一堆文件都压成 `.lz4`」

## 能力边界

**覆盖**：

- 单文件与流的无损压缩、解压与完整性校验。
- 批量模式（`-m`）与目录递归（`-r`）。
- 压缩档位 1~12、超快档 `--fast`、最高档 `--best`，以及多线程压缩。
- 块与帧层面的开关：块大小与依赖块（`-B#`、`-BD`、`-BI`）、块校验（`-BX`）、帧校验与内容大小开关。
- 字典压缩（`-D`），以及旧式 legacy 格式（`-l`）。
- 包信息查看（`--list`）、输出到标准输出或指定文件、多个 `.lz4` 拼接后的解压。
- 用环境变量设置默认压缩档位与线程数。

**不覆盖**：

- 归档语义：不打包目录树，不保留权限、属主、时间戳、符号链接，需要 `tar` 配合。
- 加密与口令保护。
- 随机访问包内某一段。
- 与其他压缩格式互转（不负责 gzip/zstd/xz 的转换）。
- 损坏数据的恢复：`-t` 只告诉你校验是否通过，不修复文件。
- 图形界面。

## 依赖条件

- 一个可执行的 `lz4`；源码构建只需要 C 编译环境与 `make`。
- 各发行版包管理器通常同时提供 `liblz4` 库与 `lz4` 命令行；包名以发行版为准。
- 多线程压缩需要构建时带多线程支持；工作线程数上限受 `LZ4_NBWORKERS_MAX`（默认 200）约束。
- Windows 可用 vcpkg 或源码构建；预编译包以官方发布页为准。
- 不需要网络、账号或 Key。

## 已知限制

- 压缩档位范围为 1~12，输入大于 12 时按 12 处理；档位只影响压缩速度与体积，解压速度不随档位变化。
- `-l` 与 `-m`、`-r` 不兼容。
- `--content-size` 只能在能确定原始大小时写入（文件可以，管道不行）。
- 字典压缩要求加压两端使用同一个字典，否则解压报错或校验失败。
- `--favor-decSpeed` 只在很高的压缩档位（不低于 10）下才有意义。
- 具体可用参数、默认值与环境变量以所用版本的 `--help` 或发行版 man page 为准。

## 自检清单

执行前：

- 确认输入是文件还是流，这决定能否使用 `--content-size`、是否必须显式写输出名。
- 确认目标文件是否已存在，决定要不要加 `-f`。
- 确认是否要保留源文件（`--rm` 会删）。
- 字典压缩时，确认加压两端用同一个字典文件。

执行后：

- 用 `lz4 -t` 校验一遍产物。
- 核对输出体积与所用档位是否符合预期。
- 确认源文件状态（在或不在）与你的预期一致。
- 批量场景检查每个输入都有对应的 `.lz4` 产物，没有漏项或被覆盖的旧包。
