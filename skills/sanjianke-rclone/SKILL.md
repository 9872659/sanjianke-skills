# 三剪客 · 云存储搬运与同步

要在两三个云盘之间、或者本地与某个远端之间来回搬文件，用各家自己的客户端就得装三四个、还得分别学一遍。rclone 把这些远端统一成同一套命令：配一次远程（remote），之后 `copy` / `sync` / `ls` / `mount` 的写法完全一样，换目标只改冒号前面的名字。它还支持加密远端、把云盘挂成本地盘符、以及两个远端之间的双向同步。

它最大的特点是**命令很危险也很诚实**：`sync` 会删目标端多余的文件，这是设计如此。用之前先把方向想清楚，用 `--dry-run` 空跑一遍。

**上游项目**：`rclone`　**仓库**：https://github.com/rclone/rclone

## 什么时候用 / 不用

**用它**：

- 现在按「把某个云盘目录整份搬到另一个位置」干活，需要一条命令跑完并能在脚本里复用。
- 要跨云端搬数据（不同云盘之间、云盘与本地/NAS 之间、对象存储与云盘之间）。
- 希望有一套统一命令做列举、拷贝、校验、挂载，而不是为每个服务商学一套接口。
- 需要加密远端：本地加密后再上传，云端只看到密文，`crypt` 远程负责透明加解密。
- 想把它挂载成盘符或目录，让普通程序按文件路径访问云盘内容。
- 需要双向同步两个目录（`bisync`），并接受它比单向同步脆弱、要按它的规则初始化。

**不要用它**：

- 你要的是**网盘图形客户端**：要看到缩略图、在线预览、拖拽上传、自动相册备份——命令行工具不提供这些。
- 你要的是**实时同步**：它是拉取式（按需运行或定时运行），不会盯着文件系统事件即时推送。
- 你要把云盘当**本地磁盘**做大量随机读写、装软件、跑数据库：网络延迟会让这类负载非常难受，且挂载在某些平台上还有稳定性限制。
- 你只在一台机器上整理本地文件：`cp` / `rsync` 更直接，不需要引入远端概念。
- 你面对的服务商它不支持（没有对应的后端类型），或服务商策略上禁止这类客户端访问。
- 你要的是**备份方案**：`sync` 的删除语义和备份需求相反，做备份要专门设计方向与保留策略。

## 安装

**Linux / macOS 一键脚本（官方安装脚本）**

```bash
sudo -v ; curl https://rclone.org/install.sh | sudo bash
```

**macOS（Homebrew）**

```bash
brew install rclone
```

**Windows（winget）**

```powershell
winget install Rclone.Rclone
```

**Windows（Chocolatey）**

```powershell
choco install rclone
```

要用 `rclone mount` 挂载的话，Windows 上还需要额外装文件系统驱动：

```powershell
choco install winfsp
```

**直接下载预编译包**

```bash
curl -O https://downloads.rclone.org/rclone-current-linux-amd64.zip
```

按你的系统与架构选对应包名即可；也可以从包管理器或自行编译安装。

**验证与定位配置**

```bash
rclone version
rclone config file      # 配置文件在哪
rclone config paths     # 配置、缓存、临时目录分别在哪
```

安装方式与可用后端列表以官方文档为准；后端类型很多，先确认你要用的那个在当前版本里叫什么。

## 常用操作

**1. 交互式配置一个远端**

```bash
rclone config
```

跟着问答走：新建远端 → 起名（比如 `mydrive`）→ 选后端类型 → 填凭证。非交互场景可以用下面的写法一次配好：

```bash
rclone config create myremote s3 provider Other env_auth false access_key_id '你的ID' secret_access_key '你的Key' endpoint 'https://你的端点'
```

问答里凡是出现「默认值」的地方，非交互模式下会自动取默认值，要改就显式传参数。

**2. 看远端状态与文件列表**

```bash
rclone lsd mydrive:
rclone ls mydrive:some/path
rclone size mydrive:some/path
rclone about mydrive:            # 支持的后端才能看容量占用
```

**3. 拷贝（只往目标加/更新，不删目标多余文件）**

```bash
rclone copy ./local-dir mydrive:backup/local-dir -P
rclone copy mydrive:a/ other:b/ --transfers 8 -P
```

`copy` 不删除目标端已有文件，是最安全的搬运方式。`-P` 显示实时进度。

**4. 同步（让目标端与源端一致，会删除目标端多余文件）**

```bash
rclone sync ./local-dir mydrive:mirror -P --dry-run
rclone sync ./local-dir mydrive:mirror -P
```

**先跑带 `--dry-run` 的那一条**，确认删除清单符合预期，再去掉它真跑。

**5. 校验两端一致性**

```bash
rclone check ./local-dir mydrive:mirror
rclone check ./local-dir mydrive:mirror --size-only
```

哈希校验需要两端都提供哈希值；如果某端不提供，就需要用 `--size-only` 或 `--download` 之类的替代方式，具体以 `rclone check --help` 为准。

**6. 加密远端（本地加密后上传）**

```bash
rclone config       # 新建一个类型为 crypt 的远端，指向已有的远端子目录
rclone copy ./secrets mycrypt: -P
```

配置 `crypt` 时会生成口令与盐值，务必单独保存——丢了就无法解密云端数据。

**7. 挂载成目录/盘符**

```bash
rclone mount mydrive: /mnt/mydrive --vfs-cache-mode writes
# Windows
rclone mount mydrive: X: --vfs-cache-mode writes
```

挂载行为由 VFS 缓存模式决定，不同平台可用选项不同，先看官方挂载文档与 `rclone mount --help`。

**8. 双向同步（要先初始化）**

```bash
# 第一次必须带 --resync
rclone bisync ./local-dir mydrive:mirror --resync --dry-run
rclone bisync ./local-dir mydrive:mirror --resync
# 之后正常跑就不要带 --resync
rclone bisync ./local-dir mydrive:mirror -P
```

`bisync` 会在本地维护工作目录记录两端状态；用 `rclone config paths` 能看到缓存目录在哪。它是进阶命令，出了问题可能丢数据，用之前把官方文档里的限制一节读完。

**9. 定时任务（把它交给系统调度）**

```bash
# 每天凌晨跑一次镜像（crontab 里的写法示意）
0 3 * * * /usr/bin/rclone sync /srv/data mydrive:mirror --log-file /var/log/rclone.log --log-level INFO
```

## 常见坑

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 目标端文件「莫名其妙」被删了 | 用的是 `sync`：它的语义就是让目标端与源端一致，多余文件会被删 | 拿不准就用 `copy`；确需 `sync` 时**永远先加 `--dry-run` 看清单**，并核对源与目标的顺序 |
| 源和目标的路径写反了 | `sync 源 目标`，反写会把云端当源、本地当目标，删掉本地文件 | 执行前把命令念一遍；脚本里把路径放进变量再检查一次 |
| 传了一半中断，重跑又从头发起 | 它按目标端已有的文件判断是否跳过，中断的临时文件可能被当成未完成 | 重跑本身是幂等的（已传输完的会跳过）；不要手工去删临时文件，除非确认过 |
| 云盘上出现了奇怪名字的中间文件 | 部分后端（尤其支持服务端复制的）会有分片与合并阶段 | 传输完成前别去动目标目录；确认传输真的结束后再看 |
| 传大文件特别慢，或者频繁重传 | 大文件分片、并发数与限速设置不合适；也可能被服务商限流 | 用 `--transfers` / `--checkers` 调整并发，`--bwlimit` 限速；被服务商限流就得降速而不是加并发 |
| 明明有改动却提示「未找到差异」 | 比较规则看的是大小与修改时间，时间精度或时区差异会让它误判 | 用 `--checksum` 按哈希比较；或临时 `--ignore-times` 强制重传一次 |
| 文件名里的特殊字符导致同步失败 | 某个后端不接受这些字符（如路径分隔符、控制字符） | 重命名冲突文件；必要时用 `--exclude` 先跳过，别指望它自动改名 |
| 配置里的口令被要求「混淆」后看不懂 | 密码字段会先做混淆再写入配置，不是明文 | 这是预期行为；要填原始口令的地方就填原始值，它会自己处理 |
| `rclone config` 里问答选项看不懂，选错了 | 各后端的选项差异大，问答文案很简略 | 用 `rclone config providers` 查选项定义；或先 `rclone config create` 生成再用 `config update` 修 |
| 拷贝到云盘后目录结构不对/多了一层 | 远端路径写法里的冒号与子路径没写对 | `远端名:子路径`，冒号不能省；不确定就先 `rclone lsd 远端名:` 看根目录 |
| 挂载后程序读写很慢或报错 | 挂载默认的 VFS 缓存策略不适合随机写 | 调整 `--vfs-cache-mode`；数据库/频繁随机写的场景不要用挂载方式 |
| 双向同步第一次就报错或提示必须先初始化 | `bisync` 首次运行必须带 `--resync` 建立基线 | 按官方流程先 `--resync`，之后去掉该参数；不要跳步 |
| 用 `bisync` 期间另一端也在被别的工具改 | 双向同步要求它掌握两端基线，第三方改动会造成冲突文件 | 一个目录只交给一个同步工具；`bisync` 是进阶命令，非必要不用 |
| 加密远端的口令丢了 | `crypt` 的口令与盐值是解密的唯一凭据，云端只有密文 | 配置好之后立刻单独备份口令；丢了没有任何办法恢复 |
| 定时任务里跑报「找不到配置」 | 计划任务的运行身份与交互用户不同，读不到用户目录下的配置文件 | 用 `--config` 显式指定配置文件路径，并确认运行身份对该文件有权限 |
| 云端被服务商判定为异常流量封了 Key | 并发过高、短时间大量请求 | 降低并发与速率；按服务商要求申请配额或改用其推荐接入方式 |

## 权限与用途说明

| 能力 | 是否申请 | 用途 |
|---|---|---|
| 网络访问 | 是 | 访问各个云盘/对象存储端点，上传下载与列举；`bisync` 与 `mount` 全程需要网络 |
| 读取文件 | 是 | 读取要上传的本地文件，以及校验时读取本地与远端数据 |
| 写入文件 | 是 | 在目标端写入对象；下载/同步时写本地目录；`bisync` 还会写本地状态缓存 |
| 凭证 | 是 | 各云盘的 Access Key / Secret / Token 存在配置文件里（多为混淆后存储）；`crypt` 的口令与盐值是解密关键 |
| 子进程 / 后台常驻 | 视情况 | 常规搬运是一次性命令；`mount` 需要常驻，`bisync`/定时同步通常交给计划任务 |

## 能力边界

**覆盖**：

- 把大量云存储与本地文件系统统一成同一套命令做列举、拷贝、同步、校验与挂载。
- 单向搬运的两种语义：`copy`（只增改不删）与 `sync`（让目标端与源端一致，会删）。
- 双向同步能力（`bisync`），带基线记录与冲突文件产出。
- 透明加密远端（`crypt`），本地加密后上传，云端只存密文。
- 挂载为目录/盘符（`mount`），并可通过 VFS 缓存策略适配不同访问模式。
- 一次性命令与定时任务两种用法，便于脚本化和自动化。

**不覆盖**：

- 不做图形化网盘客户端：没有缩略图、在线预览、拖拽上传、相册自动备份。
- 不做实时文件系统事件同步。
- 不保证把云盘当本地磁盘做高频随机读写时的体验与稳定性。
- 不做备份保留策略设计、版本治理与合规审计；这些要在流程层自己规划。
- 不替服务商做配额、速率与政策合规；被封禁或限流需要你与服务商侧解决。
- 不做内容处理（转码、压缩、去重），只负责搬。

## 依赖条件

- 操作系统：Linux / macOS / Windows 均可；挂载功能在 Windows 上额外需要文件系统驱动（如 WinFsp）。
- 安装方式：官方安装脚本、包管理器或直接下载预编译包；也可自行编译。
- 网络：能访问所配各云盘的端点；内网自建对象存储需要端点可达。
- 凭证：每个远端需要该服务的访问凭证；`crypt` 需要口令与盐值。
- 磁盘：同步/加密/挂载会用到本地缓存目录，需留出空间。
- **无模型、无 API Key 依赖**：纯文件搬运工具，不涉及大模型调用或 GPU 算力。

## 已知限制

- `sync` 会删除目标端多余文件，方向写错就可能删错东西。
- 默认比较依据是大小与修改时间，可能因时间精度/时区差异误判，需要时改用哈希比较。
- `bisync` 是进阶命令，有明确的初始化步骤与限制清单，不适合随手使用。
- 云端传输速度受服务商限流与网络条件约束，调并发不是万能的。
- 挂载模式的稳定性与性能取决于平台与缓存策略，不适合所有负载。
- `crypt` 口令与盐值一旦丢失，云端数据无法恢复。
- 后端能力不整齐：容量查询、哈希校验、服务端复制等能力取决于具体后端。

## 自检清单

执行前：

- [ ] 确认操作方向：谁是源、谁是目标，是否真的需要删目标端多余的 `sync` 语义。
- [ ] 涉及 `sync` 或 `bisync` 时先加 `--dry-run` 并逐条看清单。
- [ ] 确认远端配置可用：`rclone lsd 远端名:` 能正常列出。
- [ ] 确认凭证与 `crypt` 口令已单独留存。
- [ ] 估算数据量与剩余配额，必要时设置 `--bwlimit` 避免打满带宽。

执行后：

- [ ] 用 `rclone check` 或抽查文件确认两端内容一致。
- [ ] 确认目标端目录结构符合预期（没有多一层或少一层）。
- [ ] 涉及 `bisync` 时检查是否产生了冲突文件，并处理干净。
- [ ] 挂载场景确认程序能正常读写，并在结束时正确卸载。
- [ ] 定时任务场景确认运行身份能读到配置文件，日志有输出。
