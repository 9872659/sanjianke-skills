# 十阶段流水线与断点续跑

> 一条从「一段素材」到「一部成片」的流水线。**人工只在第 3 阶段确认一次，其余全自动。**

---

## 一、总览

```
① 需求分析  →  ② 制作前问询  →  ③ 项目规划  →  ④ 资产锚点  →  ⑤ 站位记忆
→  ⑥ 分镜设计  →  ⑦ 逐镜头出片  →  ⑧ 配音  →  ⑨ 合成成片  →  ⑩ 完成
```

| # | 阶段 | 做什么 | 产出 | 要人参与吗 |
|---|---|---|---|---|
| 1 | **需求分析** | 读素材，抽体量 / 核心矛盾 / 爽点 / 人物 / 场景道具 / **物料质检** | 分析报告 | 否 |
| 2 | **制作前问询** | 8 项制作参数 | 带来源的参数表 | 可选（默认自动） |
| 3 | **项目规划** | 制作计划 + 3 个剧情 brief | 基础信息表 + 制作清单 | 可选确认 |
| 4 | **资产锚点** | 生成角色 / 场景 / 道具参考图，**固定 seed + 稳定 ID** | 每个锚点一张图 | 否 |
| 5 | **站位记忆** | 算清「谁在哪、朝哪、道具在谁手上」，逐镜写起始快照 / 变化 / 末态 | 主锚 + 站位 + 轴线 + 视线 + **跨镜头状态承接** | 否 |
| 6 | **分镜设计** | 按九条铁律拆镜头，写光影时辰 / 音效 / 过渡桥梁 | 分镜表 | 否 |
| 7 | **逐镜头出片** | 每个镜头：出首帧图 → 图生视频 | 每镜一段视频 | 否 |
| 8 | **配音** | 按角色配声线 | 每镜音频 | 否 |
| 9 | **合成成片** | 拼接 + 烧字幕 | 成片 | 否 |
| 10 | 完成 | — | — | — |

---

## 二、阶段 1 · 需求分析（含物料质检）

不只是「读了一下素材」，而是明确报告**能提取什么 / 缺什么**。例如：

```
② 缺什么：素材里没有提供具体对白、分镜脚本、角色表演细节及场景调度。
   特别是——当前未提供参考图，不能直接承担视觉一致性锚点，
   需在资产锚点阶段生成。
```

**为什么这一步重要**：它把「素材缺什么」提前暴露出来，而不是等到出片阶段才发现没有参考图、人物开始漂。

---

## 三、阶段 2 · 制作前问询（唯一可能打断你的地方）

**而且默认不打断。**

| 参数 | 选项 |
|---|---|
| 生产模式 | A 真人实拍 / B 纯神话古代 / C 当代城市演播室 |
| 画幅 | 9:16 竖屏 / 16:9 横屏 / 1:1 方形 |
| 帧率 | 30 / 24 / 60 fps |
| 语言 | 普通话中文 / 中文（含方言） |
| 字幕策略 | 生成并烧录 / 不加字幕 / 只生成字幕文件 |
| 音频策略 | 画面内对白随视频原生生成 / 后期统一配音 |
| BGM 策略 | 后期按情绪曲线生成一条 / 不加 BGM |
| 目标时长 | 按剧本实量拆分 / 约 60 秒 / 3 分钟 / 5 分钟 |

- **默认全自动**：不打断，直接采纳推荐项，制作计划里标成「系统默认」
- 用户改过的项标成「**制作前问询**」，没动过的标「系统默认」

> 这个「来源」标注不是装饰——**回看制作计划时能一眼分清哪些是人定的、哪些是智能体替他定的**。

### 踩过的坑：推荐项要与题材一致

**实测问题**：都市情感题材，模型推荐了「生产模式 B 纯神话古代」。格式对齐了，但**推荐内容没校准**。

**修法**：加约束——推荐项必须与需求分析里的题材 / 时代判断一致，**且在提示词里给出判断依据**。

## 四、阶段 3 · 项目规划（人工确认点）

产出**基础信息表（项目 / 内容 / 来源三列）+ 制作清单 + 3 个剧情 brief**。

![项目规划阶段的确认卡片](../assets/ui/14-project-plan-cards.png)

每个 brief 约 150 字内，必须包含：**剧情发动机 / 人物关系 / 前 5 秒危机**。

---

## 五、阶段 4 · 资产锚点

系统自动提取**角色 / 场景 / 道具**，逐个出锚点图。

**两条硬要求**：

```
① 固定 seed —— 同一锚点重出要能复现
② 稳定 ID  —— 锚点 ID 不能因为重跑而变（下游靠它引用）
```

每个锚点可以**挂多张参考图**，每张标用途（脸 / 轮廓 / 服装 / 场景）。详见 `一致性双锁与禁文字原文.md` 第五节。

---

## 六、阶段 5 · 站位记忆（跨镜头一致性的核心）

**每个镜头一行**，写三件事：**起始快照 / 变化 / 末态**。

```
sg_001  起始：陈默在楼梯口端站立，面朝周桂芳；信闭合在陈默右手
        变化：陈默停步、收拢右手、换左手抬信
        末态：陈默举信至胸前；周桂芳视线在信上；信在陈默手中（开启）

sg_002  起始：陈默举信至胸前；周桂芳视线在信上；信在陈默手中（开启）  ← 与上镜末态逐字一致
```

### 出图时怎么用

```
本镜起始快照  +  上一镜末态  +  光影时辰   →  一起拼进提示词
```

> **参考图 + 固定 seed 保证「长得像」，快照保证「状态接得上」——两者叠加才稳。**
> 只有前者的话，人物是同一张脸，但手里的信可能一会儿在右手一会儿在左手。

### 还产出什么

| 产出 | 内容 |
|---|---|
| 主锚 | 这一场戏的空间基准 |
| 角色站位 | 每个角色在画面里的位置 |
| 轴线 | 视线方向与越轴规则 |
| 视线 | 谁在看谁 |
| 道具传递链 | 关键道具在谁手上、什么状态 |

### 服务端自检

第 N 镜的**末态与第 N+1 镜的起始不一致**时，**记警告并列出镜头对**。

**只警告不阻断**——因为有些连续快切确实是有意为之的。

## 七、阶段 6 · 分镜设计

按**九条铁律**拆镜头，外加**四类过渡桥梁**。详见 `分镜九铁律与过渡桥梁.md`。

### ⚠️ 上游 60 秒网关超时是硬约束

实测确认：`api.a7w.cn` 中继层有 **60 秒网关超时**。**请求越大越容易撞线**——大输入 + 8000 输出 → 502。

**已经用「分批」绕开了分镜**，但**其它长输出阶段仍可能撞线**（项目规划、站位记忆）。

实测数据：

```
每批 3 个镜头 → 单次 LLM 调用超过 3 分钟，必被上游 502 掐断
每批 1 个镜头 → 每批约 1 分钟，稳定通过
```

顺带好处：**每批落盘，断了能续**。

**通用修法**（建议对所有 LLM 调用都加）：

```
① 按输出规模自动分批
② 把超时失败做成自动降级重试（拆小后重试），而不是把项目判死
```

## 八、阶段 7 · 逐镜头出片

每个镜头两步：

```
出首帧图（把资产锚点当参考图 + 固定 seed）
    ↓
图生视频（只吃首帧）
```

**为什么必须这么拆**：Wan 3.0 的「首帧/尾帧模式不能与参考图混用」——**两道锁不能在同一支视频里同时上**。

### 按景别自动挑模型

```
全景 / 中景 / 远景  →  h3-video 768P
近景 / 特写 / 道具  →  wan3.0-video 480P
```

**判断顺序**：先判中景类再判近景（`中近景` 里含「近景」，顺序错了会误判）。

## 九、阶段 8 · 配音

按角色配声线。**零样本克隆在这里是 0 点**。

**一个坑**：`voice_tts/list_voices` 只返回**当前用户自己克隆的**音色，**预设音色库在 API 侧没有直接入口**。所以「每个角色选不同声线」目前只能用默认音色或用户自己克隆的音色。

**另一个坑**：视频模型**每镜会随机挑声音**（导致同一角色出现两个声音、配角随机变性别）。**固定 seed 是让原生音跨镜头音色一致的唯一希望。**

---

## 十、阶段 9 · 合成成片

**拼接 + 烧字幕**，用本地渲染器完成，**不扣平台点数**。

**为什么这一步留在本地**：平台上「智能剪辑」是**模板化混剪**（模板列表 / 真人口播混剪 / 素材混剪 / 新闻体），**不是「任意片段拼接 + 字幕烧录」**，对不上这个用法。

**字幕为什么必须在合成阶段烧**：模型提示词里已经全局禁文字了（见 `一致性双锁与禁文字原文.md`）。需要字幕就单独烧录，**不要指望模型自己生成**。

## 十一、断点续跑：长任务能管控

长任务最怕「跑到一半出问题，只能从头再来」。

### 任务中心给的五个操作

```
[暂停]  [续跑]  [重试失败(N)]  [对账]  [批量生成(N)]

进度：出片 8/13（62%）· 配音 8/13 · 在跑 1 · 失败 0 · 待办 4
```

### 「对账」值得单独说

**如果平台那边任务已经完成了，但本地因为网络问题没收到结果，点一下「对账」就能把已完成的结果捞回来，不重新扣费。**

这是**必须做**的一个功能——没有它，一次网络抖动就等于重复消费。

### 三条实现要点

| 要点 | 做法 |
|---|---|
| **逐镜台账** | 每个镜头记：任务号 / 状态 / 产物地址 / 实扣点数。以台账为准，不以内存状态为准 |
| **幂等** | 已完成（有产物）的镜头**直接跳过**，不重复提交 |
| **落盘** | 每批完成就落盘，进程重启/页面关闭都不丢 |

### 「关掉页面它也在跑」

**流水线在服务端执行**，关掉页面它继续。重新打开就能看到进度。

## 十二、拆集拆场（叠加在扁平分镜之上）

输出结构：

```
p.episodes = [{ no, title, summary, sceneNos: [1,2] }]
p.scenes   = [{ no, episodeNo, title, location, timeOfDay, chars: [], desc }]
shot.episodeNo / shot.sceneNo     ← 每个镜头归属哪一集哪一场
```

**关键设计**：**叠加在扁平 storyboard 之上，不改下游**。这样已有的出片链路一行都不用动。

## 十三、一句话 → 一本小说（分三步）

一次让模型写两万字，**后半段一定崩**。拆成三步：

```
① 立意   一句话 → 书名 / 题材 / 主角 / 对手 / 核心冲突 / 情绪基调 / 开篇钩子
② 大纲   立意 → N 章，每章标题 + 剧情梗概（80~150 字）
          要求"章与章有递进、最后两章有反转"
③ 扩写   逐章写正文，每章带上"上一章结尾 400 字"保证接得上
```

### 踩过的坑：某章失败导致整本中断

最初的处理是**整本中断**，重跑又从头烧钱。

**现在的做法**：

```
单章失败 → 跳过继续下一章
已写的   → 保留
随时     → 可以续跑
```

## 十四、推理模型的输出预算问题

**推理模型会把输出预算烧在思考上。** 实测某模型 `reasoning_tokens: 1405 / 2311`，极端情况下 `content` 为空串。

**原来的处理**（错的）：直接报「模型未返回内容」就失败。

**现在的处理**：

```
① 空内容自动重试 3 次
② 给足 max_tokens
③ 失败时把 finish_reason / 思考长度带进错误信息
```

## 十五、重试策略

**原则：传输层抖动是可重试的，业务错误不是。**

```javascript
const retryable = /502|503|504|超时|timeout|ETIMEDOUT|ECONNRESET|socket|上游|空|JSON 格式无效|请求内容不完整|429|限流|rate.?limit/i;
const wait = [0, 2000, 5000, 10000, 15000][Math.min(i, 4)];   // 递增退避
```

**教训**：规划阶段曾因上游一次 `upstream timeout（HTTP 502）` 就**整条流水线判死**。

**下一步该做**（如果还没做）：失败自动按 30s / 2min / 5min 退避重试 3 次，**仍失败才叫人**。

## 十六、自检

- [ ] 每个阶段**独立可重跑**，不依赖内存状态
- [ ] 逐镜台账**落盘**，进程重启不丢
- [ ] 已完成镜头**幂等跳过**，不重复扣费
- [ ] 有**对账**能力（平台完成了但本地没收到，能捞回来）
- [ ] 长输出阶段**分批**，避免撞 60 秒网关超时
- [ ] 5xx / 超时走**退避重试**，不把项目判死
- [ ] 空内容（推理模型烧完预算）**自动重试**并带出 `finish_reason`
- [ ] 锚点有**稳定 ID + 固定 seed**，重跑能复现
- [ ] 站位记忆做了**末态/起始一致性自检**（警告即可，不阻断）
