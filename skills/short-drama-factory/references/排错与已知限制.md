# 排错与已知限制

---

## 一、症状 → 原因 → 处置

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 提示「尚未配置 API Key」 | 没配 Key | 到 [`api.a7w.cn` 个人中心](https://api.a7w.cn/user-center.html) 创建，然后填进去 |
| 提示「点数不足，需要 X / 有 Y / 差 Z」 | 余额不够 | **这时候一个镜头都没生成，没花钱**。充值后点继续，已完成的镜头不会重复生成 |
| 游客身份配不了 Key | 强制先登录 | 先手机号登录——**顺序别反，先登录再配 Key**，Key 才绑在持久账号上 |
| 上传报「不支持老的 .doc」 | 格式不对 | 另存为 `.docx` 或 `.txt`（`.pdf` 同样不支持） |
| 某阶段失败，报「上游不可用（HTTP 502）」 | 上游网关超时 | 长输出阶段要**分批**；或自动降级重试（拆小后重试），别把项目判死 |
| 页面关了，任务还在跑吗 | **在跑** | 流水线在服务端执行，关掉页面它继续 |
| 画布一片空白 | 没选项目 | 用画布工具栏的项目下拉选一个 |
| `qwen-image` 报「parameters.n 必须为 1」 | 没给 `n` | 显式带 `parameters.n = 1` |
| `gpt-image` 出的人物全是凭空编的 | **参考图被丢了** | 参考图走**顶层 `image_urls`** 数组，不是 `input.messages` |
| `h3-video` 报「取值不在允许范围」 | 分辨率或时长不合法 | 分辨率只认 `768P`/`2K`；时长只认 `4/5/6/7/8/10/12/15` **且必须是字符串** |
| `wan` 报「当前请求未命中可用计费规格」 | 传了 `768P` | `768P` 是 h3 的取值，wan 只认 **480P / 720P** |
| `wan` 任务「处理失败」 | 时长不是整数或 <3 秒 | 时长**必须取整且 ≥3**（`3.5s` 失败、`4s` 正常） |
| 传了首帧又传参考图，被拒 | Wan 的硬约束 | **首尾帧模式不能与参考图混用**。拆成「首帧出图带参考图」+「视频只吃首帧」 |
| 模型报「模型不存在或未上架」 | 模型在列表里但不可用 | 加进死模型黑名单（见 `模型参数适配表.md` 第四节） |
| 模型报「未返回内容」 | 推理模型把预算烧在思考上 | 空内容**自动重试 3 次**并给足 `max_tokens`，失败时带出 `finish_reason` |
| 画面里长出乱码字幕 | 禁文字约束太弱 | 用**多角度 + 强否定 + 正面替代描述**的写法（原文见 `一致性双锁与禁文字原文.md`） |
| 配角的脸在不同镜头间漂 | 锚点描述不够具体 | 每个角色**至少 3 个具体造型特征** |
| 同一角色出现两个声音 / 配角变性别 | 视频模型每镜随机挑声音 | **固定 seed**（wan 的 seed 放在 `parameters` 内） |
| 网络超时后重提，被重复扣费 | 没查 `task_id` | **先查任务状态再决定是否重提**；并做「对账」把已完成结果捞回来 |
| 文本阶段的实扣点数对不上 | `/chat/completions` 不回传 `points_cost` | 用**调用前后余额差分**推算 |

## 二、已知限制（说清楚，别让用户踩）

### 1. 口型不逐字对应

**平台没有口型同步模型。** 本方案的做法是**后叠配音**——音色统一，但**口型不会逐字匹配**。

**行业里也没有好办法**：参考片是用**快切**来掩盖的（平均 5.8 秒一刀）。

### 2. 长镜头会漂移

**同一角色超过 8 秒的镜头，脸会开始变。**

**建议 4~8 秒短镜拼接**，不要做 15 秒以上的长镜。这也正好符合短视频节奏。

哪怕是双锁都上了也一样——这是模型能力边界，不是参数问题。

### 3. 配角一致性弱于主角

**原因**：主角锚点通常有 5 处具体造型约束（特征越具体越容易被模型抓住），配角描述往往相对笼统，**约束力弱一些**。

**修法**：配角也**强制要求填 3 个以上具体特征**，不接受「黑衣服、盘发」这种量级。

### 4. 图像模型参考图上限偏低

全站图像模型只有 2 个（Qwen Image 3.0 / 3.0 Pro），**参考图上限 3 张**。

锁一个角色要「正面 / 侧面 / 背面 + 服装 + 道具 + 场景」至少 **6~12 张**，3 张不够。

**绕法**：改用 `gpt-image-*`（上限 **12 张**）。

### 5. 预设音色库需单独接入

`voice_tts/list_voices` **只返回当前用户自己克隆的音色**。

产品侧的 **650 个预设音色**在 API 侧没有直接入口，所以「每个角色选不同声线」目前只能用默认音色或用户自己克隆的音色。

### 6. 视频侧可用档位受模型限制

近景用 480P、全景用 768P。平台上有支持 1080P/4K 的模型，但**视频侧实测可用档位受模型约束**（h3 只认 768P/2K，wan 只认 480P/720P）。

### 7. `/chat/completions` 不回传 `points_cost`

`/tasks` 会返回 `usage.points_cost`，**文本接口没有**。所以文本阶段的实扣点数只能靠余额差分推算。

### 8. 上游 60 秒网关超时

`api.a7w.cn` 中继层有 **60 秒网关超时**。**请求越大越容易撞线**（大输入 + 8000 输出 → 502）。

**长输出阶段必须分批。** 实测：每批 3 个镜头时单次调用超 3 分钟必被掐断；**改成每批 1 个后约 1 分钟，稳定通过**。

### 9. 文档口径与实测口径常有出入

平台的**模型数、价格、可选档位都会变**。本文档里的数字都是**快照**：

| 项目 | 快照值 | 注意 |
|---|---|---|
| 模型总数 | 87~103（不同页面/时间不一致） | 要准数**现场拉** |
| 预设音色 | 650 | 平台侧接口只返回自克隆的 |
| 单价 | 见成本文档 | 平台会调价，且**租户实收价可能与公示价不同** |

**要准数就现场拉，不要照抄文档里的快照数字。**

### 10. 素材格式支持有限

| 格式 | 支持 |
|---|---|
| `.txt` / `.md` | ✅ 直接读，UTF-8 优先，乱码时自动按 GBK 重试 |
| `.docx` | ✅ 服务端解包取正文 |
| `.doc` | ❌ 提示另存为 `.docx` 或 `.txt` |
| `.pdf` | ❌ 提示转成 `.txt` 或 `.docx` |

单文件 **8MB 内**；文本素材超过 20 万字会截断并标注。

## 三、运维速查（自建这套流水线时）

```bash
# 服务状态
systemctl status <你的服务名>
journalctl -u <你的服务名> -n 100 --no-pager

# 健康检查（示例端点）
curl -s http://127.0.0.1:<port>/agent/health | python3 -m json.tool

# 换 Key
echo 'sk-xxxx' > /path/to/key.txt && chmod 600 /path/to/key.txt
systemctl restart <你的服务名>

# 换模型（不改代码，走环境变量覆盖）
systemctl edit <你的服务名>   # 覆盖 SDF_MODEL_TEXT / SDF_MODEL_IMAGE / SDF_MODEL_VIDEO
```

### 账号与 Key 的三种归属方式

| 方式 | 特点 | 适合 |
|---|---|---|
| **平台账号统付** | 最简单，但用户等于免费出片 | 内部测试 |
| **平台账号付款 + 自己做点数扣减** | 接近「复用现有账号与计费」，工作量中等 | 有自己用户体系的平台 |
| **每个用户一把 `api.a7w.cn` Key（BYO Key）** | 最彻底，费用归属最清晰，但需打通两个用户体系 | **推荐**，也是本文档假定的模式 |

**BYO Key 模式下**：Key 由用户提供，页面只回显掩码，服务端**加密存储**（如 AES-256-GCM），保存时真调一次余额接口校验。

> **安全提醒**：Key 等同于余额。不要写进代码、不要提交进 Git、不要在日志里打印完整 Key。

## 四、Key 从哪来

```
① 注册算力集市
   打开 https://api.a7w.cn/user-center.html，注册并完成实名认证

② 创建 API 密钥
   「个人中心 → API 密钥」创建，形如 sk-xxxxxxxx
   可以给单个 Key 设消费上限（quota）

③ 充值点数
   1 元 = 100 点
   参考量级：一部 1 分钟的片子（13 镜）约 1700~2000 点

④ 保存并校验
   保存时真调一次余额接口验证，无效的 Key 存不进去
```

**注意 402 有两种**，别搞混：

| 错误码 | 含义 | 处置 |
|---|---|---|
| `insufficient_points` | **账号**余额不足 | 充值 |
| `key_quota_exceeded` | **这个 Key** 的额度打满 | 调高/重置该 Key 的 quota，或换 Key |

**分不清这两种，就会去充一个根本不需要充的账户。**

## 五、自检

- [ ] 遇到 402 时**先分清**是账号没钱还是 Key 额度满
- [ ] Key 走环境变量 / 配置文件，**没有硬编、没进 Git、没打印到日志**
- [ ] 长输出阶段**分批**了，没有单次撞 60 秒网关超时
- [ ] 网络超时时**先查 `task_id`**，没有直接重提
- [ ] 知道长镜头 8 秒会漂移，没有做 15 秒以上的长镜
- [ ] 知道口型是后叠配音，没有承诺逐字对口型
- [ ] 文档里的数字标了「快照」，要准数会现场拉
