# 模型参数适配表

> **同一个平台上的模型，参数格式并不统一。** 这份表是故意「缺参探测」平台校验错误反推出来的——比读文档准，因为文档经常与实测不一致。

---

## 一、为什么要做适配层

一句话：**界面上选了哪个模型，那个模型就得真能用。**

平台上这些模型族各吃一套完全不同的入参：

| 模型族 | 入参风格 |
|---|---|
| `qwen-image-*` | `input.messages` 只含一条用户消息 |
| `gpt-image-*` | **顶层 `prompt`**（和 qwen 完全不同的格式） |
| `nano-banana-*` | 顶层 `prompt`（同 gpt 一家） |
| `wan3.0-video` | `input.media[{type:'first_frame'}]` |
| `h3-video` | 顶层 `content` / `ratio` / `duration` / `resolution` |
| `veo3.1-*` | 顶层 `prompt` / `quality` |
| `grok-video` | 顶层 `prompt` / `duration` |

所以必须有一层「统一入参 → 具体模型格式」的翻译。**跳过这一层，就是不停地 400。**

---

## 二、图片模型

| 模型族 | 参考图字段 | 上限 | 必须注意 |
|---|---|---|---|
| `qwen-image-*` | message `content[]` 里的 `{type:'image', image:url}` | **3 张** | **必须显式给 `parameters.n = 1`**——不给会被判「parameters.n 必须为 1」。直连 submit 时没有兜底，必须写死 |
| `gpt-image-*` | **顶层 `image_urls`（数组）** | **12 张** | 字段名是探测出来的：故意传 `image: 123`，平台回「参数不符合模型约定: image_urls: 类型应为 array」 |
| `nano-banana-*` | 同 gpt-image | — | 走 `prompt` 分支 |

### 踩过的坑：gpt-image 曾经丢掉了参考图

早期实现里 `gpt-image` 分支只传了 `prompt`，**把参考图直接扔了**——结果是「人物/场景全是凭空编的」。

根因是当时以为它只支持文生图。实际上平台信息里 `gpt-image-2-pro` 的描述写着**「文生图与图生图」**，`max_reference_images = 12`。

**教训**：参考图上限要**从模型的 `capabilities.max_reference_images` 读**，不要靠猜。

### 画幅与清晰度换算

平台要的是 `宽*高`。比例基准按 **1K 短边 = 1024**，长边取偶数（8 的倍数）：

| 比例 | 1K 基准像素 | 已验证 |
|---|---|---|
| `1:1` | 1024\*1024 | ✅ |
| `16:9` | 1792\*1024 | ✅ |
| `9:16` | 1024\*1792 | ✅ |
| `4:3` | 1364\*1024 | |
| `3:4` | 1024\*1364 | |
| `3:2` | 1536\*1024 | |
| `2:3` | 1024\*1536 | |
| `21:9` | 2048\*880 | |
| `2:1` | 1448\*724 | |
| `1:2` | 724\*1448 | |

清晰度档位：`1K` = ×1，`2K` = ×1.5，`4K` = ×2。**换算后按 8 取整**，避免奇数边。

## 三、视频模型

### h3-video（MiniMax H3）——通用多模态首选

顶层字段：`content` / `ratio` / `duration` / `resolution`

| 参数 | 只认这些取值 | 坑 |
|---|---|---|
| `resolution` | **`768P` / `2K`** | 实测 `720P` / `1080P` / `4K` / `标清` / `高清` / `1280x720` **全部被拒**（"取值不在允许范围"） |
| `duration` | **`4` `5` `6` `7` `8` `10` `12` `15`** | **必须是字符串**——传数字 `5` 会被拒，传 `"5"` 才过。任意时长要**吸附到最近的合法值** |
| `ratio` | **`16:9` / `9:16` / `1:1` / `4:3`** | 其余一律回落到与项目方向一致的那个（`3:4`→`9:16`，其他→`16:9`） |
| `content` | `[{type:'text',text}, {type:'image_url',image_url:{url}}]` | 可放多张参考素材 |

官方描述：「支持文本、首尾帧和多模态参考素材的视频生成」。

**为什么主力选它**：平台上的 `full-video`（全能视频生成）实际报「**未上架**」，真正可用且定位是通用多模态的就是 H3。

### wan3.0-video（Wan 3.0）——性价比档

入参：`input.media` + `parameters`

| 参数 | 取值 | 坑 |
|---|---|---|
| `resolution` | **`480P` / `720P`** | **`768P` 不认**——那是 h3 的取值。传了被拒「当前请求未命中可用计费规格，请检查分辨率是否在支持范围内」。所以 `768P` 及以上一律映射成 `720P` |
| `duration` | **必须取整，下限 3 秒** | 实测 `3.5` 秒让任务「处理失败」，取整成 `4` 秒就正常；`2.5` 秒同样失败 |
| `media[].type` | `first_frame` / `reference_image` / `last_frame` | |
| `seed` | 放在 **`parameters` 内** | 见下面「seed 的重要性」 |
| `audio` / `watermark` | `true` / `false` | |

**⚠️ 最重要的硬约束**：官方明确「**首帧/尾帧模式不能与参考图片、参考视频、参考音频、文件或网页链接混用**」。

这直接决定了出片架构——**一致性拆成两把锁，不能在同一支视频里同时上**：

```
锁一：出首帧图时把资产锚点当参考图 + 固定 seed
锁二：视频阶段只吃首帧（图生视频）
```

### veo3.1 / grok-video

顶层 `prompt` / `duration`（veo 另有 `quality`），**只吃单张图**（`image` 字段）。多给会被判参数不符——适配层对这两个分支**只取第一张**。

## 四、已经上架但实测不可用的模型

**别再让用户选。** 维护一份黑名单，在选择器里过滤掉：

```
seedance
full-video
happy-horse
wan
flashvsr
Wan-AI/Wan2.2-T2V-A14B
Wan-AI/Wan2.2-I2V-A14B
```

其中 `seedance` 的报错是「**模型不存在或未上架**」——**列表里有，但不可用**。

> **这条要定期重测**：平台会上架，黑名单里的模型可能某天真的能用了。

## 五、按景别自动挑模型

不是所有镜头都值得用贵的模型：

```
全景 / 中景 / 远景  →  h3-video 768P（画面信息多，值得）
近景 / 特写 / 道具  →  wan3.0-video 480P（省一半以上）
```

**⚠️ 判断顺序有坑**：`中近景` 里含「近景」，**必须先判中景类再判近景**，否则 `中近景` 会被误判成 480P。

---

## 六、seed 的重要性

固定 seed 是让**「原生音跨镜头音色一致」的唯一希望**。

实测问题：视频模型**每镜会随机挑声音**，导致孙悟空出现两个声音、主持人随机变男声。

同时固定 seed 也是「长得像」的一部分——与参考图配合使用。

---

## 七、适配层的输出形态

翻译函数返回 `{ body, note }`：

- `body` —— 真正发出去的请求体
- `note` —— 人类可读的说明，写清「用了哪套风格、几张参考图、分辨率与时长落到了哪个值」

`note` 会写进节点详情与运行日志。**排查 400 时先看 `note`**，它能一眼告诉你适配层把参数翻译成了什么。

---

## 八、自检

- [ ] 参考图上限是**从 `capabilities.max_reference_images` 读的**，不是猜的
- [ ] `qwen-image` 显式带了 `parameters.n = 1`
- [ ] `h3` 的 `duration` 是**字符串**且落在 `{4,5,6,7,8,10,12,15}` 内
- [ ] `h3` 的 `resolution` 是 `768P` 或 `2K`
- [ ] `wan` 的 `resolution` 是 `480P` 或 `720P`（不是 768P）
- [ ] `wan` 的 `duration` 是**整数且 ≥3**
- [ ] 视频请求**没有把首尾帧与参考图混用**
- [ ] `veo` / `grok` 分支**只取了一张图**
- [ ] 死模型黑名单在选择器里生效了
