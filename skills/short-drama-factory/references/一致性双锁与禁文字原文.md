# 一致性双锁与禁文字原文

> 这一份是**可直接复制**的提示词原文。两段约束都设计成**幂等**——已经追加过就不再重复追加，所以可以在任意一层无脑调用。

---

## 一、为什么需要「双锁」而不是只传参考图

实测背景（这是踩出来的）：

> **只把参考图传进去是不够的。** 模型会把参考图当「**松散参考**」，然后按提示词里的文字描述重新「画」一个人——实测主持人换了脸。

必须在提示词里**明确要求「照抄参考图」**，而且要说清「这是同一个人在同一部戏里的不同镜头」，模型才会把参考图当硬约束。

另外，**Wan 3.0 有硬约束**：首帧/尾帧模式不能与参考图片、参考视频、参考音频、文件或网页链接混用。所以两道锁**不能在同一支视频里同时上**，必须拆：

```
锁一（出图阶段）：把资产锚点当参考图喂给图片模型 + 固定 seed
锁二（视频阶段）：只吃首帧（图生视频），由首帧把人物/场景锁住
```

---

## 二、锁二原文：人物 / 场景一致性硬约束

**触发条件**：只在**真的传了参考图**时追加。纯文生图场景不要加，否则会产生矛盾指令。

```
【人物一致性 · 最高优先级】画面中人物的**面孔、五官比例、脸型、年龄、发型、发色、肤色、服装款式与配色**必须与提供的角色参考图**完全一致**，是同一个人的同一套造型；不要换脸、不要改年龄、不要改发型、不要改服装、不要美化或年轻化。这是同一部戏里同一个角色的不同镜头，绝不能变成另一个人。场景与道具同样必须与对应的场景/道具参考图保持一致，不要替换或改造。
```

**幂等判据**：字符串里已含 `人物一致性 · 最高优先级` 就跳过。

### 为什么要写得这么啰嗦

| 写法要素 | 作用 |
|---|---|
| `【人物一致性 · 最高优先级】` | 给模型一个显式的优先级标记，压过其他风格性描述 |
| 逐项列出（面孔 / 五官比例 / 脸型 / 年龄 / 发型 / 发色 / 肤色 / 服装款式与配色） | 列全才能防「只锁脸不锁衣服」 |
| 「完全一致」「同一个人的同一套造型」 | 从「相似」提升到「同一」 |
| 连串否定（不要换脸 / 改年龄 / 改发型 / 改服装 / 美化 / 年轻化） | 模型默认倾向「美化」，必须显式禁止 |
| 「同一部戏里同一个角色的不同镜头」 | **关键**：告诉模型这是跨镜引用，不是新角色 |
| 场景与道具同样要锁 | 只锁人不锁场景，空间会串 |

## 三、禁文字硬约束原文

**触发条件**：**所有**出图 / 出视频请求，无条件追加。

> **为什么放在适配层统一追加**：所有出图/出视频的请求都必须经过同一个构建函数，在这里统一追加就不可能有哪条路径漏掉——无论调用方是自动流水线、单点重生，还是独立的维护脚本。

```
。**画面中绝对不要出现任何文字**：不要字幕、不要台词文字、不要标题、不要水印、不要 logo、不要台标、不要时间码、不要界面元素、不要任何可辨认的字母或汉字；画面里所有物体表面（桌面文件、名牌、墙面、屏幕、衣物）都不要出现可读的文字或符号，需要表现文件就用纯线条与色块示意，不要写字。这是一条硬性要求，必须严格遵守。
```

**幂等判据**：字符串里已含 `绝对不要出现任何文字` 就跳过。

### ⚠️ 实测：光写「不要字幕」压不住

长镜头里模型会把**环境纹理「读」成文字**，自己长出乱码字幕（实测出现过「你们的拷的老林味」这类乱码）。

所以要三个手段一起上：

1. **多角度**——不只说「不要字幕」，而是把所有可能出字的地方列出来（标题 / 水印 / logo / 台标 / 时间码 / 界面元素）
2. **强否定**——「绝对不要」「任何」「可辨认的」
3. **带正面替代描述**——「需要表现文件就用纯线条与色块示意，不要写字」，给模型一条替代路径

### 需要字幕怎么办

**成片阶段单独烧录**，用本地渲染器完成——不进模型提示词，**也不扣平台点数**。

## 四、组合顺序

两个约束**互不冲突**，顺序固定：

```
原始提示词
  → withNoText()   追加禁文字（无条件）
  → withRefLock()  追加一致性锁（仅当有参考图）
```

代码形状（零依赖，可直接抄）：

```javascript
function withRefLock(prompt, refs) {
  const s = String(prompt || '');
  if (!refs || !refs.length) return s;                       // 没参考图就不加
  if (s.indexOf('人物一致性 · 最高优先级') >= 0) return s;      // 幂等
  return s + REF_LOCK;
}

function withNoText(prompt) {
  const s = String(prompt || '');
  if (s.indexOf('绝对不要出现任何文字') >= 0) return s;          // 幂等
  return s + NO_TEXT;
}
```

## 五、参考图挂载策略

一个角色可以挂**多张**图，每张标用途：

| 用途 | 锁住什么 | 建议 |
|---|---|---|
| 正面照 | 脸型、五官比例 | **必挂** |
| 侧面照 | 轮廓、鼻梁、头骨 | 建议挂 |
| 背面照 | 发型后部、服装背部 | 建议挂 |
| 服装图 | 服装款式与配色 | 建议挂 |
| 道具图 | 关键道具的形制 | 有道具传递链时必挂 |
| 场景图 | 空间关系、光线 | 每场景挂 |

**各模型的参考图上限不一样**（这是实操里最容易撞的墙）：

| 模型 | 上限 | 备注 |
|---|---|---|
| `qwen-image-*` | **3 张** | 锁一个角色勉强够，角色+场景就超了 |
| `gpt-image-*` / `nano-banana-*` | **12 张** | 适合多参考图锁长相 |
| `h3-video` | 多条 | `content` 数组可放多张 |
| `wan3.0-video` | 10 图 / 5 视频 / 5 音频 | 但**不能与首尾帧混用** |
| `veo` / `grok` | **1 张** | 多给会被判参数不符 |

**固定 seed 也要一起上。** 实测经验：固定 seed 是让「原生音跨镜头音色一致」的唯一希望——视频模型每镜会随机挑声音，导致同一角色出现两个声音、或配角随机变性别。注意 `wan` 的 `seed` 放在 `parameters` 内，不是顶层。

## 六、锚点描述要「具体到可验证」

**这是决定一致性上限的那件事。**

实测对比（同一部片子里的两个角色）：

| 角色 | 锚点描述 | 结果 |
|---|---|---|
| 哪吒 | **5 处具体造型约束**：深红高马尾 / 左眉旧疤 / 黑灰夹克 / 脖子金属圈 / 手腕红绫 | **12 格全部同一张脸，稳** |
| 主持人 | 相对笼统：黑色中式立领 / 低发髻 / 翡翠平安扣 | **不同镜头间脸型有变化，漂了** |

**结论**：

```
锚点描述越具体   → 一致性越好
多挂几张参考图   → 一致性越好
```

**落成规则**：每个角色（包括配角）**强制要求填 3 个以上具体特征**，不接受「黑衣服、盘发」这种量级。

**什么叫「具体到可验证」**：写成一个可以拿着成片逐格核对的清单——

```
❌ 黑衣服、盘发
✅ 深红高马尾 / 左眉旧疤 / 黑灰夹克 / 脖子金属圈 / 手腕红绫
```

每一项都能在任意一帧上回答「有 / 没有」。

## 七、还有一个绕不开的边界：长镜头漂移

即使双锁都上了，**同一角色超过 8 秒的镜头，脸还是会开始变**。

**建议**：**4~8 秒短镜拼接**，不要做 15 秒以上的长镜。这也正好符合短视频的节奏。

行业里的同类做法是用**快切**掩盖——参考片平均 5.8 秒一刀。
