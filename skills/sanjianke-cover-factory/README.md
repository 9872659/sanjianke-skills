# 三剪客 · 封面图批量生成

给**一批标题**，批量产出**各平台的封面图**：

```
        plan            images              overlay
标题清单 ──► 封面方案 ──► 无字背景图 ──► 大字标题压上去
（一行一个）  画什么/      真花钱·先报价·   本地 PIL 渲染
             大字写什么/   断点续跑         零成本·零网络
             放哪
```

面向**批量做号**的运营：不是"画一张封面"，而是"30 个标题 × 5 个平台 = 150 张，
今晚要出完"。**跑之前先告诉你花多少钱**，闸门不放行就不给提交。

```
specs   →  各平台封面规格（比例 / 目标像素 / 安全区 / 大字上限）**零网络**
plan    →  封面方案（每个标题 × 每个平台：画什么、大字写什么、放哪）只花文本钱
images  →  批量出**无字背景图**，先报价、断点续跑
overlay →  把大字标题**本地渲染**压到图上（字号/断行/描边/安全区）
all     →  串起 plan → images → overlay，断点续跑
cost    →  只算钱，一次调用都不发
models  →  列出在架插件与模型（模型名会变，现查，别写死）
```

## 能做什么

给**一批标题**，一条链路批量产出**各平台的封面图**，并保证"图上文字一定清晰"。

它替代的是批量做号的人每天真正在做的那个动作：**不是"画一张封面"，
而是"30 个标题 × 5 个平台 = 150 张封面，今晚要出完"**。

| 子命令 | 干什么 | 花钱吗 |
|---|---|---|
| `specs` | 各平台封面规格（比例 / 目标像素 / 安全区 / 大字上限），**零网络** | **零成本** |
| `plan` | 按标题清单出封面方案 | **只花文本钱**（实测 4 条方案 1317 token） |
| `images` | 批量出**无字背景图** | **真花钱**，实测 **24 点/张 = 0.24 元**（1K），先报价 |
| `overlay` | 本地叠大字标题（字号/断行/描边/阴影/安全区） | **零成本、零网络** |
| `all` | 串起 plan → images → overlay，**断点续跑** | 按阶段花钱 |
| `cost` / `models` | 只算钱 / 现查在架模型 | 零成本 |

| 你最关心 | 答案 |
|---|---|
| 多少钱 | 出图实测 **24 点/张**（1K）= **0.24 元/张**，1 元 = 100 点，跑之前先把总价打出来 |
| 要多久 | 单张出图实测 **5~40 秒**；叠字每张 **1~2 秒**（纯本地） |
| 要装什么 | **零第三方依赖**；叠字需要 `pillow`，没有就**明确报降级（exit=2）** |
| 图上文字会不会糊 | **不会**：出图提示词里不许出现任何文字，大字由本地渲染压上去 |
| 大字太长怎么办 | **拦截**，并报出实际长度与多出来的那部分；绝不静默截断 |
| 中断了怎么办 | **断点续跑**：已完成的跳过、已提交的用 `task_id` 续查（不重复扣费） |

### 它和另外两个「工厂」不是一回事

同族三个工厂的输入与产出**刻意不同**，改代码前先看这张表：

| | 输入 | 产出 | 大字标题怎么来的 |
|---|---|---|---|
| `sanjianke-image-factory` | **一篇文稿** | 文章各段的配图 | 写进**出图提示词**，让模型画进画面 |
| `sanjianke-xhs-note-factory` | **一份母稿** | N 篇笔记 + 每篇一张 3:4 封面 | 写进**出图提示词**（`cover_text`） |
| **本包** | **一批标题清单** | **同一标题 × 5 平台封面矩阵** | **背景图无字 + 本地 PIL 叠字** |

最后一行是本质差别：前两个包全库里**没有 `ImageDraw` / `truetype` 的代码路径**
（它们用 PIL 只做裁剪），文字清不清晰由出图模型决定；本包把文字从模型手里拿回来了。

## 怎么用（命令行）

### 30 秒上手

```bash
# 1) 拿 Key（新用户有赠送点数）
#    到 https://api.a7w.cn/ 注册，创建一个 API Key

# 2) 配 Key
export A7W_API_KEY="<你的Key>"          # Windows: $env:A7W_API_KEY="<你的Key>"

# 3) 看平台规格（零网络、零成本）
python3 scripts/run.py specs

# 4) 出方案（标题清单一行一个）
python3 scripts/run.py plan --file 标题清单.md --out plan.json

# 5) 先算钱
python3 scripts/run.py cost --titles 30 --count 5     # 30 标题 × 5 平台 = 150 张
# 150 张 × 24 点/张（1K，实测价）= **3600 点 = 36.00 元**

# 6) 出背景图：先不带 --yes 报价，确认了再加
python3 scripts/run.py images --plan plan.json --outdir D:/covers
python3 scripts/run.py images --plan plan.json --outdir D:/covers --yes --snap

# 7) 本地叠大字标题（零成本、零网络）
python3 scripts/run.py overlay --plan plan.json --outdir D:/covers

# 8) 想一条命令跑完
python3 scripts/run.py all --file 标题清单.md --outdir D:/covers --yes --snap --budget 4000
```

**零第三方依赖**：只要 Python 3.7+，不用 `pip install` 任何东西。
`overlay`（本地叠字）需要 `pillow`；**没有它就明确报降级（`exit=2`）并说明**，
绝不静默产出一张没有字的图 —— 那会让你以为叠字成功了。

`scripts/a7w.py` 是**所有 Skill 包共用**的零依赖客户端（我们靠 SHA256 校验各包副本
是否一致），本包**逐字节没有改它**；本包的业务逻辑全在 `scripts/run.py` 里。

### 七道硬闸门

命中即**标红 + stderr 汇总 + 退出码非 0**，可以直接进 CI。

| # | 闸门 | 判定 | 退出码 |
|---|---|---|---|
| 1 | 合规 | 广告法违禁词；「最X」按**可枚举上下文**豁免，**句首不豁免** | 3 |
| 2 | 占位符残留 | `{}`、`[待填]`、`XXX`、`（此处省略）`、`TODO`/`TBD` | 3 |
| 3 | prompt_echo | 去标点相等 / Jaccard ≥ 0.75 / 覆盖度 ≥ 0.60 | 3 |
| 4 | **出图比例真伪** | 读**真实像素**，不信自报；容差 3%，`--snap` 裁准 | 3 |
| 5 | **叠字可读性** | 超平台字数上限 → **拦截并报出实际长度**；越出安全区 → 标红 | 3 |
| 6 | 成本上限 | 跑前必须报价 + `--yes` 或 `--budget` | 3 / 4 |
| 7 | 产出位置 | `--outdir` 指到包内 | 2 |

外加两条参数级拦截：`2K/4K` 没有实测单价 → **拒绝估算**（退出码 3）；
没有中文字体 / 没有 PIL → **明确报降级**（退出码 2）。

### 第 5 道闸门为什么是本包最值钱的那道

同族 `sanjianke-xhs-note-factory` 1.0.4 及以前写的是 `cover_text[:20]` —— **静默截断**：
用户改了封面文案、付了钱重出图，只有第 21 字之后被砍掉，图看起来一模一样，
用户以为"我的改动生效了"。1.0.5 起改成超限直接拦下。

本包从一开始就照修好的口径做，而且做得更狠一点：

- 上限按**平台**给（小红书/B站/视频号 16 字，公众号/抖音 14 字），是**算出来的**
  （可用宽度 ÷ 字号），`specs` 还会做一次**口径自检**
- 超限**报出实际长度 + 多出来的是哪几个字**，一个字都不许静默丢
- **不接受 `--allow-prompt-hits` 放行超长大字** —— 放行等于回到静默截断
- 这道闸门**在花钱之前**就判（`plan` 与 `images` 都判）

### 实测数据（真机跑出来的，不是估算）

| 项目 | 实测值 |
|---|---|
| 出图单价 | **24 点/张**（1K）= 0.24 元；两张共 **48 点** |
| 提交时冻结 | `frozen_points = 31.2`（**预冻结，不是最终扣费**） |
| 小红书 3:4 | 请求 3:4 → 真实像素 **864x1184**（偏差 **2.70%**，上游按 32 对齐） |
| 小红书 + `--snap` | 裁剪框 `(0, 16, 864, 1152)` → 真实像素 **864x1152**（偏差 **0.00%**） |
| 公众号 2.35:1 | 用 `21:9` 生成 → **1536x672**（偏差 2.04%） |
| 公众号 + `--snap` | 裁剪框 `(0, 9, 1536, 654)` → **1536x654**（2.3486，偏差 **0.06%**） |
| 叠字产出 | **1080x1440**（小红书）与 **900x383**（公众号），与平台目标像素一致 |
| 叠字产物大小 | 2.21 MB / 448 KB；纯本地、**0 点** |
| 出方案（文本） | 4 条方案 `prompt 679 + completion 638 = 1317 token`，约 4 秒 |
| 断点续跑 | 重跑同一条命令：**2 张全部跳过，本次扣 0 点**（另 48 点是上一轮已扣的） |
| 补下载 | 任务已完成但下载崩了 → 重跑按 `task_id` **补下载，0 点**（不重新提交） |

结算只认 `usage.points_cost`。平台的价格字段半数不可信：`image_human` 字段写
1.5/2/4/8 点/秒、实测 2/3/6/12；`voice_tts/stt` 字段写 30、实扣 40；
`frozen_points` 也不是最终扣费（实测冻结 31.2、实扣 24，差 30%）。

## 参数说明

### 全局

| 参数 | 说明 |
|---|---|
| `--key` | 临时指定 Key；优先级最高。**别把它写进脚本或文档** |
| `--json` | 以 JSON 输出，**写在子命令前面或后面都可以**；stdout 只有一个完整 JSON |
| `--version` | 打印版本号 |

### 标题清单输入（`plan` / `all` 共用）

| 参数 | 说明 |
|---|---|
| `--file <文件>` | **推荐**。标题清单，一行一个；`#` 开头算注释；自动剥 BOM |
| `--text "标题1，标题2"` | 直接给标题；逗号与换行都当分隔符 |
| `--titles N` | 最多取前 N 个标题，默认 200 |
| `--platform` | 目标平台，**可重复**：`xiaohongshu` / `wechat` / `shipinhao` / `douyin` / `bilibili`；默认 5 个全出 |
| `--style` / `--brief` | 统一视觉风格口径 / 作者补充要求 |

### `plan`（出封面方案）

| 参数 | 说明 |
|---|---|
| `--out` | 把方案写成 JSON，`images` / `overlay` / `all` 要用它 |
| `--dry-run` | 只打印将发送的提示词，**不调模型、不花钱** |
| `--model` / `--temperature` / `--max-tokens` | 文本模型参数，默认 `deepseek-chat` / 0.7 / 8192 |
| `--no-json-mode` | 不要求上游返回 JSON 对象 |

### `images`（批量出背景图）

| 参数 | 说明 |
|---|---|
| `--plan` | **必填**。`plan` 产出的方案 JSON |
| `--outdir` | 输出目录，默认 `%TEMP%\cover-factory-out`；**不可是包内目录** |
| `--platform` / `--count` / `--only` | 只出指定平台 / 前 N 条 / 指定 id |
| `--resolution` | `1K`（默认）/ `2K` / `4K`。只有 1K 有实测价；2K/4K 不给单价就**拒绝估算** |
| `--points-per-image` | 覆盖单张单价（点） |
| `--budget` | 成本上限（点）。预估超了直接停；每次提交前还会再核一次 |
| `--yes` | 确认真的花钱。**不加就只报价**（退出码 4），一个任务都不提交 |
| `--snap` | 出图后按**平台设计比例**居中裁剪，裁完**再读一次文件头复核** |
| `--ratio-tolerance` | 比例容差，默认 `0.03`；有 `0.0025` 的量化地板 |
| `--poll-timeout` | 单张轮询超时秒数，默认 `600`（**上限，不是期望时长**） |
| `--max-seconds` | 整批最长耗时，到点中断（退出码 5），重跑可续 |
| `--state` / `--force` | 断点文件路径 / 忽略断点全部重出（**会重复扣费**） |
| `--no-wait` / `--stop-on-error` / `--report` | 只提交不等待 / 一张失败就停 / 写证据 JSON |
| `--allow-prompt-hits` | 提示词命中闸门也出图（默认拦截）。**不接受它放行超长大字** |

### `overlay`（本地叠大字标题）

| 参数 | 说明 |
|---|---|
| `--plan` | **必填**。方案 JSON（大字从 `items[].overlay.text` 取） |
| `--outdir` / `--outdir-name` | 底图所在目录（也是产物目录）/ 另存目录 |
| `--font` | 指定中文字体文件（`.ttf` / `.ttc` / `.otf`）。不给就在系统字体里找 |

## 排错

| 现象 / 报错 | 原因 | 怎么办 |
|---|---|---|
| `这是一次真花钱的操作…加 --yes`（exit 4） | 成本前置生效，**正常的** | 看过报价后加 `--yes` 或 `--budget` |
| `大字标题 N 字，超过 上限 M 字（多出 …）`（exit 3） | 叠字可读性闸门 | 把超出的字移到正文或拆两张。**不接受放行** |
| `没有找到可用的中文字体`（exit 2） | 系统里没中文字体 | `--font` 指一个 `.ttf/.ttc/.otf`；`specs` 会打印可用字体 |
| `本地叠字需要 PIL`（exit 2） | 没装 pillow | `pip install pillow` 后**原样重跑**（背景图不重出、不重复扣费） |
| `真实像素 864x1184 … 偏差 2.70%` | 上游按 32 对齐，**不是错误** | 加 `--snap` 裁到 864x1152；容差内不会拦 |
| `2K 档没有实测单价，拒绝凭猜估算` | 我们没测过 2K/4K 价 | 给 `--points-per-image`，或先用 1K |
| `输出目录 … 在 Skill 包内`（exit 2） | `--outdir` 指到包里了 | 换到包外（`D:/covers`、`%TEMP%\...`） |
| `鉴权失败（401）` / `点数不足（402）` | Key 无效或点数用完 | 到 https://api.a7w.cn/ 重新领取 / 充值 |
| 轮询一直 `processing` | 上游排队 | 有 `--poll-timeout`（默认 600 秒）与断点，重跑按 `task_id` 续查 |
| 重跑又扣了一次钱 | 提示词/叠字样式/分辨率改了 → 断点 key 变了 | 设计如此；想省钱就别改，直接重跑即可跳过 |

**收集排错信息时请附上**：完整命令、`plan --dry-run` 的输出、`--report` 产出的证据 JSON、退出码。
**不要在报错信息或截图里带上你的 API Key。**

### 退出码

| 退出码 | 含义 |
|---|---|
| `0` | 全部成功且闸门全绿 |
| `1` | 没预料到的异常（代码 bug）；`--json` 下 `kind=internal` + stderr 完整栈 |
| `2` | 参数/配置错误（`--outdir` 在包内、没有字体、没有 PIL） |
| `3` | 硬闸门命中（违禁词/占位符/照抄示例/比例/叠字可读性/超预算） |
| `4` | 需要 `--yes` 确认（还没花钱）；或调用失败（网络/鉴权/点数/模型名） |
| `5` | 达到 `--max-seconds` 上限中断（可续跑） |
| `130` | 用户中断（Ctrl+C） |

### 三条实测确认的接口事实

```bash
python3 scripts/a7w.py schema nano_banana      # 出图的真实参数
```

1. **没有 `/generate` 这个端点。**「文生图」是 `submit` 的 `action=generate` **参数**。
2. **`status` 在 `data` 顶层，不在 `data.result` 里。** 平台文档写错了 ——
   照文档写会永远读不到状态、一路轮询到超时。
3. **`query` 是 POST 不是 GET**（schema 实查）；本包统一用 `GET /api/v1/tasks/<task_id>`。
   另外生成应用**`code == 1` 才是成功**，而 `/chat/completions` 的成功响应**不带 `code`**。

### 上游按 32 对齐，一半的比例给不出像素级精确值

| 请求 | 实测像素 | 数值比例 | 偏差 |
|---|---|---|---|
| `3:4` | 864x1184 | 0.7297 | **2.70%** |
| `16:9` | 1344x768 | 1.7500 | 1.56% |
| `9:16` | 768x1344 | 0.5714 | 1.56% |
| `21:9` | 1536x672 | 2.2857 | 2.04% |
| `1:1` / `4:3` / `2:3` / `3:2` | — | 精确 | 0% |

**这不是网关 bug**，是扩散模型先定总像素、再把每边向下取整到 32 的常规做法。
所以容差默认 3%，并且**把真实像素与偏差原样打印出来，不藏**。
要像素级精确就加 `--snap`（裁完**再读一次文件头复核**，只把真正裁准的记成合格）。

### 断点续跑：key 含全部影响产出的维度

本包的出图产出由 **6 个维度**决定，一个都不能少：

```
提示词全文摘要（不是前缀截断） + 比例 + resolution + 模型 + 叠字内容 + 叠字样式
```

后两维是本包特有的 —— 这就是「标题清单驱动 + 本地叠字」的直接后果：
**只改了大字标题（背景图一个字没改）也必须重出**，否则图上的字是旧的。

同族在"断点 key 少一维"上踩过三次，形态都是**静默复用过期产物**：

| 踩过的形态 | 后果 |
|---|---|
| 提示词只取前 24 字做摘要 | 只改第 25 字之后 → key 不变 → 复用旧图 |
| `resolution` 不入 key | 先跑 1K、改成 4K 重跑 → 复用 1K 的图 |
| 记录里的值与本次不一致却照样跳过 | 静默复用说不清来历的旧产物 |

本包的做法：全文摘要 + 分辨率/比例/模型 + 叠字内容与样式**全进 key**；
命中 key 之后**逐维复核**，对不上就打印「不复用旧图」并重出；
跳过的那张也要**重新读一遍真实像素**过比例闸门（断点文件可能被手工改过）。
