# 三剪客 · 算法题解语料库

遇到一道题不会做，真正缺的通常不是那几行代码，而是「这类题该往哪个方向想」：看到区间问题该想差分还是扫描线，看到求最值该想动规还是贪心，看到排列组合该套回溯还是状压。这类东西教科书讲得抽象，题解区又只给答案。这套资料的价值就在于把常见题型的思路整理成可检索的长文——它不是一个能装能跑的软件，而是一批**给人（和 Agent）读的讲解语料**。

**上游项目**：`labuladong 的算法小抄`　**仓库**：https://github.com/labuladong/fucking-algorithm

## 什么时候用 / 不用

**用它**：

- 用户说「这道题该用什么套路」「动态规划我一窍不通，能不能讲讲思路」「为什么这里要用双指针」。
- 需要**一类题的统一框架**：滑动窗口、回溯、二分、动规、并查集、图的最短路，想要模板而不是孤立的答案。
- 要**从一道题扩到同类题**：先看懂套路，再拿同专题的习题练手。
- 想把一份离线算法讲解语料挂进自己的 Agent，作为回答算法问题时的知识来源。
- 需要给自己的思路**找一个对照**：写完解法后比一比复杂度与边界处理是否一致。

**不要用它**：

- **要在线判题、要 AC 反馈**。它是讲解文本，没有编译运行、没有测试用例、不告诉你代码能不能过。
- **要保证与最新题库同步**。题目描述、函数签名、判题环境都会变，语料可能滞后；写进代码前必须回力扣原题核对。
- **要现成的可复制答案应付面试**。它讲的是思路，很多题只有片段代码，直接抄不保证能跑。
- **要覆盖一切算法**。它的重心在面试常考的数据结构与算法套路；冷门专题、竞赛级技巧、系统设计不在范围内。
- **把它的题号当成权威编号**。文章标题里的数字有历史包袱，必须以文章里的力扣链接为准。

## 安装

这套资料不是一个可安装的软件，所谓「安装」就是**把它拿到本地、挂到自己的 Agent 上**。

**拿到本地（任选一种）**：

```bash
# 方式一：整仓克隆（推荐，之后可以 git pull 更新）
git clone https://github.com/labuladong/fucking-algorithm.git

# 方式二：只要一份压缩包，不留版本库
# 在仓库页面用「Download ZIP」，或
curl -L -o algo-notes.zip https://github.com/labuladong/fucking-algorithm/archive/refs/heads/master.zip

# 方式三：只要某几个专题（稀疏检出，目录名按实际结构写）
git clone --filter=blob:none --sparse https://github.com/labuladong/fucking-algorithm.git
cd fucking-algorithm
git sparse-checkout set 动态规划系列 算法思维系列
```

**拿到之后看目录结构**（顶层就是几个专题目录 + 图片与说明，目录名是中文的）：

```text
fucking-algorithm/
├── README.md            # 仓库说明 + 在线目录（文章标题 → 线上链接）
├── 算法思维系列/         # 框架类：BFS 框架、二分查找、双指针、回溯、前缀和、差分、位运算…
├── 动态规划系列/         # 动规模板、编辑距离、背包、股票买卖、扔鸡蛋、正则匹配…
├── 数据结构系列/         # 链表、二叉树、二叉堆、单调栈 / 单调队列、图、拓扑排序、并查集…
├── 高频面试系列/         # LRU、接雨水、岛屿、子集排列组合、安排会议室、随机权重…
├── 技术/                # 刷题技巧、在线练习平台、Linux / 密码学等杂项长文
├── 多语言解法代码/       # 多语言解答的整理与贡献说明
└── pictures/            # 文章配图
```

**按专题定位**：每个目录下的 `README.md` 是该专题的索引，先看它找到目标文章，再打开对应的 `.md`。文件名的写法不统一，有中文长标题（`动态规划设计：最长递增子序列.md`）、有英文缩写（`LCS.md`、`BST1.md`）、也有纯英文单词（`dijkstra算法.md`）——所以**别靠猜文件名，用列目录 + 全文检索来找**。

**挂进自己的 Agent**：把克隆下来的目录当作只读知识源，让 Agent 在回答前先检索，再引用具体文件。最短做法：

- 在项目说明里写明这份资料的本地绝对路径，以及「回答算法问题前先检索该目录」的约束。
- 给出检索入口：按关键词在目录内全文检索，命中后读该文件；目录没有索引时，先列目录确定有哪些专题。
- 明确要求引用时带上具体文件相对路径，便于人工复核。

> 仓库的目录结构、文章数量与收录范围会随上游变动，上面这份结构来自实际检出结果；以你克隆到的版本为准。

## 常用操作

**1. 按专题关键词检索到具体文章**

```bash
# 只列某专题下有哪些文章
ls "动态规划系列"

# 在资料目录里按关键词检索，拿到文件与行号
grep -rn "状态转移方程" --include="*.md" .
grep -rln "滑动窗口" --include="*.md" .

# 想按标题找，就直接看各专题的索引
cat "算法思维系列/README.md"
```

Agent 侧等价动作：先把「专题目录 → 文章文件」列出来，再用关键词命中，最后只读命中的那一篇，而不是整目录塞进上下文。

**2. 按一道力扣题定位讲解**

先把题号或题名当关键词搜一遍：

```bash
grep -rn "接雨水" --include="*.md" .
grep -rn "leetcodes.com/problems/trapping-rain-water" --include="*.md" .
```

命中后**以文章开头的力扣链接为准**去核对原题：题目编号、函数签名、边界条件都可能已经变了。

**3. 抽取套路模板，而不是抄答案**

读一篇框架类文章时，把结构拆成三段再复述给用户：

- 适用范围（什么样的题该套这个框架）；
- 模板骨架（循环怎么写、状态怎么定义、边界怎么收）；
- 复杂度与常见变体（时间空间从哪来，哪些条件变化会破坏模板）。

这样得到的是可迁移的套路；只有片段代码的文章不适合直接当答案。

**4. 从一篇题解扩到同类练习**

同一目录下的其他文章往往就是配套习题。做法是：

```bash
# 先确定这篇属于哪个专题
ls "动态规划系列"
# 再把该专题下的其他文章列出来，挑同类型的做延伸
```

给用户的产出应当是「先看哪篇讲框架 → 再练哪几道同类型题」，而不是一次丢过去十篇长文。

**5. 生成同类练习题**

语料本身不含题库，但可以用来**指导出题**：从某篇文章里提取「输入形态 + 约束条件 + 目标」，让人或 Agent 照着改写一组自测数据，再用你自己的判题方式验证。

要清楚这条链路的边界：**资料负责给套路，判题得另找地方**（在线判题平台、本地测试用例、或你自己写的暴力对拍）。

**6. 交叉核对不同来源的写法**

同一道题在这套资料里可能出现在不同专题（例如接雨水既在数组专题也在面试专题的语境里）。检索时把命中的多篇都列出来，比较它们的做法差异，再说明哪种写法在那道题的数据规模下更稳。

## 常见坑

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 按题号搜不到文章 | 文章标题用的是描述性中文名或英文缩写，不是题号 | 用题目的中文名、英文 slug 或算法名去检索；先看专题索引再定位 |
| 文章里给的力扣链接编号和你看到的题号不一致 | 题库调整过编号与题名，语料相对滞后 | 以文章里的链接打开原题重新核对；编号对不上时按题意匹配，不要硬套 |
| 直接抄文章里的代码跑不过 | 很多文章只给核心片段，变量名、函数签名、边界处理都不完整 | 把代码当骨架，自己补输入输出与边界；以原题的判题要求为准 |
| 同一份代码在别的语言上跑不通 | 语料的代码示例偏某几种语言，多语言版本更是另一批人的整理成果 | 先确认这段代码是什么语言写的；换语言要重写语法细节，别逐字翻译 |
| 想看的文章打开只有一句提示 | 有一部分内容只在线提供，且部分专题与配套工具属于付费范围 | 换仓库里已经写全的同类文章；需要线上内容时按站点说明处理，不要假设仓库里有 |
| 目录名和文章标题对不上 | 线上目录按学习路径组织，仓库按文件目录组织，两套体系并不一一对应 | 以仓库实际目录为准检索；需要按学习顺序时，看专题索引文件确认先后 |
| 一些文章明显没写完 | 部分专题仍在更新中，线上会标注「正在更新」 | 优先用已经写全的框架类文章；把没写完的部分当作待补，不要基于残缺内容下结论 |
| 让 Agent 一次读进整个目录，回答变慢还答不准 | 资料体量大、长文多，全量塞进上下文会稀释重点 | 先检索命中的文件路径，只读相关的那一两篇；把「引用文件路径」作为输出要求 |
| 把仓库里的多语言目录当成可执行代码库 | 那一部分是解答整理的说明与索引，不是能直接跑的项目 | 需要可运行代码时以原题所在平台为准；这份资料只提供讲解与片段 |
| 以为它能验证答案 | 它没有编译、运行、判题能力 | 自测靠本地用例、对拍或在线判题；语料只用于讲思路 |
| 内容被当成官方题解引用 | 这是个人整理的学习资料，观点与方法都有主观取舍 | 引用时注明是学习资料，并与原题、其他来源交叉验证 |
| 整篇转载到自己的产品里 | 仓库内容有独立的授权与转载约定 | 引用只做摘要与指路，需要成篇使用先去看仓库的授权说明 |

## 能力边界

**覆盖**：

- 常见题型的思路讲解与框架总结：双指针、滑动窗口、二分、回溯、BFS / DFS、动规、贪心、并查集、图的最短路与最小生成树、单调栈 / 单调队列、前缀和 / 差分、位运算、经典数据结构设计（缓存、堆、Trie、线段树等）。
- 大量以力扣题目为背景的题解长文，含思路推导、复杂度讨论与代码片段。
- 一套按专题组织的目录，可作为离线讲解语料被检索、引用与二次整理。
- 若干配套说明类长文（刷题方法、练习平台、多语言解答整理等）。

**不覆盖**：

- 不提供在线判题、编译运行、测试用例或 AC 判定。
- 不保证与力扣最新题库同步：题号、题名、判题环境都可能变化。
- 不覆盖全部算法领域：冷门专题、竞赛级技巧、系统设计与工程实践不在范围内。
- 不是可安装的软件或服务，没有命令行参数、没有接口、没有常驻进程。
- 不提供多语言代码的权威版本：代码片段是讲解的一部分，不是可交付的实现。

## 依赖条件

- 获取资料需要能访问仓库（`git` 客户端，或能下载压缩包的网络环境）。
- 阅读只需要一个 Markdown 阅读器；检索需要能列目录与全文搜索的工具。
- 图片是文章配图，缺失时不影响正文理解。
- 想核对题目细节时，需要一个能打开原题页面的网络环境。
- 无需任何账号、Key 或算力。

## 已知限制

- 仓库以长文为主，体量不小；把整目录塞进上下文很低效，必须走「先检索、再精读」。
- 内容更新节奏取决于维护者，部分专题线上标注仍在更新，仓库内可能只到某一阶段。
- 目录命名与文章标题不统一，靠文件名猜测定位经常失败。
- 部分内容只在线提供，且有一部分属于付费范围，仓库不保证等价可得。
- 题目链接与题号会随时间漂移，引用前必须核对。
- 具体版本号、发布时间与 star 数请以仓库页面实时信息为准，此处不做断言。
