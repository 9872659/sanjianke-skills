# 通用说明 · 权限、异步机制、错误码、计费口径

本 Skill 用到的 api.a7w.cn 能力共用这几条规则。**动手前先过一遍，能省掉大部分白跑。**

---

## 一、权限与用途说明

| 能力 | 是否申请 | 用途 |
|---|---|---|
| 网络访问 | **申请** | 调用 `api.a7w.cn` 的模型网关与应用接口（本 Skill 唯一的联网行为） |
| 读取文件 | 仅读取你指定的输入文件（文本 / 图片 / 音频 / 视频） | 作为接口的素材入参 |
| 写入文件 | 仅在传入 `--out` 时 | 保存返回的 JSON 或下载产物 |
| 子进程 | 本地合成需要 `ffmpeg` / `ffprobe` | 拼接、字幕、混音、转码 |
| 凭证 | 读取**你自己**提供的 API Key | 从环境变量 `A7W_API_KEY` 或 `~/.a7w/config.json` 读取 |

**不内嵌任何密钥。** 脚本只把 Key 发往 `api.a7w.cn`，不发送到其他任何地址。

## 二、响应信封

应用接口与模型网关统一返回：

```json
{ "code": 1, "msg": "success", "data": { } }
```

| 规则 | 说明 |
|---|---|
| **`code == 1` 才是成功** | **HTTP 200 不等于业务成功** —— 失败时同样可能返回 HTTP 200，而 `code` 为 `0` |
| 失败时看 `msg` | `data` 可能为空数组或 `null`，原因写在 `msg` 里 |
| HTTP 状态码也要看 | `404` 通常是代号拼错；`401` / `402` / `403` / `429` 各有明确含义 |
| 少数端点是裸对象 | 如价格 / 账单类接口没有 `code`/`data` 外壳，直接返回对象 |

```python
# 判断成败的正确写法
payload = json.loads(resp)
if payload.get("code") != 1:
    raise RuntimeError(payload.get("msg"))
data = payload.get("data") or {}
```

## 三、异步任务机制

标记为「异步」的接口是**任务制**：

```
提交 → pending → processing → completed
                        └──→ failed / cancelled
```

| 环节 | 说明 |
|---|---|
| **提交** | 返回 `task_id`；同步接口则结果直接就在 `data` 里（没有 `task_id`） |
| **查询** | `GET /api/v1/tasks/{task_id}`，或用各应用自己的 `query` 接口。**查询免费** |
| **轮询** | 建议每 3~5 秒一次；`a7w.py call` 默认**自动轮询到结束**再返回 |
| **回调** | 提交时传 `callback_url`，任务终态时平台 POST 通知，可不轮询 |
| **冻结与结算** | 提交时按预估价**冻结点数**，完成后按实际用量**多退少补** |
| **失败** | 失败会把冻结的点数**全额退回**，只有成功产出才结算 |

```bash
# 只提交，不等结果
python3 scripts/a7w.py call <app> <api> --body '{...}' --no-wait

# 之后用 task_id 查状态（免费）
python3 scripts/a7w.py task <task_id>
```

### 3.1 不要重复提交（最贵的一类问题）

> **提交时就已经冻结点数了。** 网络超时、进程被杀、你以为失败了 ——
> 都可能只是「响应没收到」，而任务已经创建并冻结了钱。

规则：

1. 提交前**先落盘记录意图**（写进 `tasks.csv`）
2. 提交后**立刻写入 `task_id`**
3. 超时或异常时，**先按 `task_id` 或任务列表确认状态**，再决定是否重提
4. 重跑只处理 `failed` 与 `pending` 的行

### 3.2 回调与幂等

| 项 | 要求 |
|---|---|
| 你方接口 | **必须返回 2xx** 才算接收成功；非 2xx 会触发重试 |
| 重试次数 | 在用户中心 → 回调配置里设置，范围 **1~10 次** |
| 语义 | **「至少一次」** → 消费端必须按 `task_id` **幂等去重** |
| 地址 | 必须**公网可达**；内网地址收不到 |

### 3.3 并发建议

| 阶段 | 建议并发 |
|---|---|
| 出图 | 4~8 路 |
| 视频生成 | **2~4 路**（最贵最慢） |
| 配音 | 4~8 路 |
| 口型 | 2~4 路 |
| 超分 | 2 路 |

出现 `429 queue_limit_exceeded` 就是并发过高 —— 降下来，让队列消化。
**并发越高不一定越快，排队加重试可能比低并发更慢更贵。**

## 四、错误码全表

| HTTP | code | 含义 | 处理 |
|---|---|---|---|
| 400 | `invalid_request` | 参数缺失或格式错误 | 用 `schema <app>` 核对参数名与必填项 |
| 401 | `auth_failed` | API Key 缺失或无效 | 重建 Key 后重新配置 |
| 402 | `insufficient_points` | **账号**点数余额不足 | 充值；错误信息里含本次所需点数 |
| 402 | `key_quota_exceeded` | **该 Key** 的点数额度打满 | 调高 / 重置 Key 的 quota，**不用充值** |
| 403 | `permission_denied` | 该 Key 无权调用此模型 / 应用 | 检查是否已开通，与余额无关 |
| 404 | `not_found` | 模型 / 应用 / 任务不存在 | 用 `apps` / `models` 拿真名；应用代号用下划线 |
| 429 | `queue_limit_exceeded` | 排队任务已达上限 | 降并发，指数退避后重试 |
| 5xx | `server_error` | 服务异常 | 退避重试；持续失败换模型 / 线路 |
| 200 | `code: 0` | **业务失败**（HTTP 仍是 200） | 看 `msg`；最常见是用了中文展示名当接口代号 |

### 4.1 排查顺序

```
调用失败
├─ 到不了 api.a7w.cn          → 检查网络 / 代理 / 防火墙，确认 443 出口
├─ 401 auth_failed            → Key 过期、写错或带了多余空格
├─ 402
│    ├─ insufficient_points   → 账号余额不足，去充值
│    └─ key_quota_exceeded    → 只是这个 Key 的额度满了，别去充值
├─ 403 permission_denied      → Key 没开该应用的权限
├─ HTTP 200 但 code:0         → 业务失败。最常见是用中文展示名当接口代号
├─ HTTP 404 且响应体为空       → 应用代号拼错（检查是不是用了连字符）
├─ 400 invalid_request        → 参数名或必填项不对，跑 schema <app> 对齐
├─ 429 queue_limit_exceeded   → 并发太高，降并发 + 退避重试
└─ 任务 status: failed        → 看 error 字段；换素材或核对参数后重试
```

### 4.2 重试策略

| 情况 | 是否重试 |
|---|---|
| 4xx（参数 / 权限 / 余额） | **不重试** —— 重试只是浪费请求 |
| 429 / 5xx | **重试**，指数退避 + 抖动（1s → 2s → 4s → 8s，上限 5 次） |
| 提交类调用超时（可能已冻结） | **不要裸重试** —— 先查 `task_id` 或任务列表 |

> `a7w.py` 已经内置了这套逻辑：网络抖动与 5xx 自动退避重试（最多 4 次），
> 4xx 直接抛出带中文提示的错误。

## 五、计费口径

### 5.1 基本规则

| 规则 | 说明 |
|---|---|
| **单位** | **1 元 = 100 点，1 点 = 0.01 元** |
| **节奏** | **先冻结后结算**：提交时按预估价冻结，完成后按实际用量多退少补 |
| **失败** | **失败全额退回** —— 冻结的点数一分不扣，只有成功产出才结算 |
| **月费** | **没有月费**，用多少扣多少；点数不按月清零 |
| **查询免费** | 各类 `query` / `task` 接口不计费，可以放心轮询 |
| **余额不足** | 返回 `402`，**不产生欠费** |
| **调价** | 不影响已充值的点数余额 |

### 5.2 两套价格字段（最容易算错的地方）

| 字段 | 含义 | 用途 |
|---|---|---|
| `fixed_price` / `input_price` | **标准价**（公示价） | 对外展示、横向比价 |
| `tenant_fixed_points` / `tenant_points_per_1k_input` | **你所在租户的实际结算价** | **做预算只能用它** |

两者可能差很多。**任何按公示价做的预算都可能错一个数量级。**

```bash
# 查你的真实价（这才是完整口径）
python3 scripts/a7w.py schema nano_banana
python3 scripts/a7w.py schema full_video
python3 scripts/a7w.py points          # 看最近任务的实际消耗
```

### 5.3 计费单位随能力变化

| 能力类型 | 计费口径 |
|---|---|
| 文本大模型 | 点 / 百万 tokens（输入、输出分别计价；流式与非流式同价） |
| 图像生成 / 编辑 | 点 / 张，按模型与分辨率档位 |
| 视频生成 | **点 / 秒**，按分辨率分档；提交时冻结，完成后按实际时长结算 |
| 数字人 / 对口型 | 点 / 秒（按驱动音频时长）或点 / 次 |
| 语音 TTS | 点 / 千 tokens（按合成文本量） |
| 语音克隆 | 点 / 次 |
| 音乐生成 | 点 / 次（按 `type` 对应固定规格） |
| 音效生成 | 点 / 次 |
| 视频超分 | 固定 + 按用量 |
| 工具类（水印消除等） | 点 / 次 |

所以「这个接口多少钱」这句话本身不完整 —— 必须连着**用量口径**一起看
（多少 tokens、多少张、多少秒、多少千字）。

### 5.4 对账三处

| 层 | 来源 | 字段 |
|---|---|---|
| **单次调用** | 接口返回 | `data.usage.points_cost` —— **本次真实扣费** |
| **单个任务** | `GET /api/v1/tasks/{task_id}` | `usage` |
| **账号账** | 用户中心用量统计与流水导出 | 实际扣点 |

对账顺序：先把本地台账（`task_id` + 提交时间）与任务接口的用量对齐，
再去用户中心核对流水。三者对不上的常见原因：

- **重复提交**（同一任务两条流水）
- **回调重试导致下游重复登记**（流水只有一条，你的台账有两行）
- **拿标准价当实收价做预期**

> **预算一律读 `tenant_*`，最终以实际扣费为准。**
> 一集 2 分钟的完整测算见 [`成本估算.md`](成本估算.md)。

## 六、素材要求

| 类型 | 要求 |
|---|---|
| **通用** | **必须是公网可访问的 URL**，不支持本地路径、不支持 Base64 |
| 图片 | 常见格式；锁角色的参考图建议正面、单人、均匀布光、中性背景 |
| 音频 | `mp3` / `wav` / `ogg` / `flac`；音色克隆的参考要 10 秒 ~ 5 分钟**纯干声** |
| 视频 | 常见格式；超分与音效类接口传公网直链 |
| 文本 | 分镜表用 UTF-8；中文台词的配音长度按每秒 4~5 字估算 |

> 本地文件（如刚生成的图、刚合成的配音）要先传到对象存储 / 图床拿到公网链接，
> 再作为入参传给应用接口。

## 七、能力边界

- **不提供 API Key**：Key 必须由使用者自己在 api.a7w.cn 申请
- **不代付费用**：调用消耗的是使用者自己账号的点数
- **不保证可用性**：接口由平台提供，可用性、限流与计费以站内为准
- **不替代内容合规审查**：剧本、素材与成片的使用与合规责任由使用者承担
- **不替代肖像与声音授权**：用他人形象或音色前必须取得本人授权
- **接口会演进**：动手前先跑 `python3 scripts/a7w.py schema <app>`，**以实际返回为准**
