# 分镜方法 · 从剧本到可执行的分镜表

分镜表是整个流程的**唯一事实来源**：画布上的节点排布、每一镜的提示词、台词配音的文件名、
最后拼接的顺序，全部从它派生。表写不清楚，后面每一步都会返工。

---

## 一、分镜表模板

### 1.1 必填七列（少一列就会卡在某一环）

| 列 | 字段 | 类型 | 作用 |
|---|---|---|---|
| 1 | `shot_id` | 镜号，如 `S01-003` | 与画布节点编号一一对应；也是文件名前缀 |
| 2 | `shot_size` | 景别 | 决定提示词里的镜头语言 |
| 3 | `camera` | 运镜 | 写进视频提示词；静态镜留空 |
| 4 | `duration` | 时长（秒） | 视频生成的秒数，也是成本的主变量 |
| 5 | `visual` | 画面描述 | 出首帧图的提示词主体 |
| 6 | `dialogue` | 台词 | 无声镜头留空 |
| 7 | `transition` | 与下一镜的衔接方式 | 决定尾帧要不要出、怎么出 |

### 1.2 建议补四列（做批量与对账时省大量时间）

| 列 | 字段 | 说明 |
|---|---|---|
| 8 | `characters` | 本镜出场角色代号，如 `LIN,YE`；用来判断该塞哪几张定妆图 |
| 9 | `scene` | 场景代号，如 `SC-RAIN-STREET`；同场景的图可以复用 |
| 10 | `sfx` | 环境音 / 音效描述，喂给 `mmaudio` |
| 11 | `recipe` | 本镜走哪套配方（图+口型 / 视频生成 / 静帧推拉），见 `成本估算.md` |

### 1.3 表格样张

| shot_id | shot_size | camera | duration | visual | dialogue | transition |
|---|---|---|---|---|---|---|
| S01-001 | 远景 | 缓慢推进 | 5 | 雨夜老城区街道，路灯昏黄，女主撑黑伞由远及近 | — | 视线衔接：下一镜切她的脸 |
| S01-002 | 中景 | 固定 | 4 | 女主撑伞站定，雨水沿伞沿滴落，米色风衣被打湿 | 「这雨，下了整整十年。」 | 动作衔接：她抬头 |
| S01-003 | 近景 | 上摇 | 5 | 女主抬头看向路灯，光斑在雨幕里散开 | — | 空间衔接：切到男主视角 |

> 景别是递进的（远景 → 中景 → 近景），**相邻镜不要跳超过两级** ——
> 从远景直接切特写，观众会失去空间感。§5.2 的自检脚本会把这类跳级报出来。

### 1.4 CSV 版（直接给脚本用）

```csv
shot_id,shot_size,camera,duration,visual,dialogue,transition,characters,scene,sfx,recipe
S01-001,远景,缓慢推进,5,雨夜老城区街道，路灯昏黄，女主撑黑伞由远及近,,视线衔接,LIN,SC-RAIN-STREET,雨声渐起+远处车流,image
S01-002,中景,固定,4,女主撑伞站定，雨水沿伞沿滴落，米色风衣被打湿,这雨，下了整整十年。,动作衔接,LIN,SC-RAIN-STREET,雨打伞面,image_lip
S01-003,近景,上摇,5,女主抬头看向路灯，光斑在雨幕里散开,,空间衔接,LIN,SC-RAIN-STREET,雨声持续,image
```

> 存成 `shots.csv`（UTF-8，不带 BOM）。后面 `合成与导出.md` 里的 SRT 生成脚本、
> `成本估算.md` 里的预算脚本都直接读这个文件。

## 二、在哪一步生成分镜表

用**模型网关**（`POST /api/v1/chat/completions`）来出表，一把 Key、OpenAI 协议，
详见 `api-模型网关.md`。

```bash
python3 scripts/a7w.py schema nano_banana    # 顺手确认一下应用参数
```

```bash
curl -sS -X POST "https://api.a7w.cn/api/v1/chat/completions" \
  -H "Authorization: Bearer $A7W_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "<先用 GET /api/v1/models 查到可用模型名>",
    "temperature": 0.3,
    "messages": [
      {"role":"system","content":"你是短剧分镜师。只输出 CSV，表头固定为 shot_id,shot_size,camera,duration,visual,dialogue,transition,characters,scene,sfx,recipe。不要解释，不要代码块围栏。"},
      {"role":"user","content":"把下面这段剧情拆成分镜。要求：单镜 4~8 秒；对话戏用近景/特写；每镜只写一个动作；transition 只从「动作衔接/视线衔接/空间衔接/声音衔接」里选。<剧情略>"}
    ]
  }'
```

**要点**

- `temperature` 压到 **0.2~0.4**：分镜是结构化任务，不需要发散
- 让它**只输出 CSV**，拿回来直接存 `shots.csv`
- 模型名不要猜，先 `GET https://api.a7w.cn/api/v1/models` 拿在架名单
- 平台成功码是 **`1`**（`{"code":1,"msg":"success"}`），HTTP 200 不代表业务成功

## 三、景别词表

景别决定信息密度。**同一场戏里景别要有变化**，全程中景会像监控录像。

| 景别 | 画面范围 | 提示词写法 | 什么时候用 |
|---|---|---|---|
| **大远景 / 全景** | 环境为主，人物很小 | `大远景，人物在画面下三分之一，环境占主导` | 交代地点、时间、天气；开场与转场 |
| **远景** | 人物全身 + 周边环境 | `全身景，人物居中偏左，身后是……` | 走位、站姿、空间关系 |
| **中景** | 膝盖以上 | `中景，半身入画，膝盖以上` | 对话、动作过程，最常用的工作景别 |
| **近景** | 胸部以上 | `近景，胸部以上，面部清晰` | 情绪、台词重心 |
| **特写** | 面部或手部 | `特写，面部占画面三分之二，浅景深` | 情绪爆点、关键道具 |
| **大特写** | 眼睛、嘴、物件细节 | `大特写，只有眼睛与睫毛，极浅景深` | 悬念、卡点、片头钩子 |

**配比经验**：一集 25 镜里，远景/全景 3~5 镜、中景 10~12 镜、近景 5~7 镜、特写 3~4 镜。
特写不要连续超过两镜 —— 观众会失去空间感。

## 四、运镜词表

运镜写进**视频提示词**（`full_video` / `happy_horse` / `wan` 的 `content` 文本项）。
**一镜只写一种运镜**，写两种模型会互相打架。

| 运镜 | 描述 | 提示词写法 | 注意 |
|---|---|---|---|
| **固定** | 机位不动 | `固定机位，画面稳定` | 对话戏首选；也是唯一不会翻车的选项 |
| **推** | 靠近主体 | `镜头缓慢推近，主体逐渐占满画面` | 加强情绪；速度写「缓慢」 |
| **拉** | 远离主体 | `镜头缓慢拉远，环境逐渐显露` | 收尾、揭晓环境 |
| **摇** | 机位不动、镜头转 | `镜头水平向右摇，掠过窗外街景` | 交代空间；幅度别太大 |
| **移 / 跟** | 机位平移 | `镜头随人物向右平移，保持中景` | 走位戏；容易糊，动作要慢 |
| **升降** | 垂直移动 | `镜头缓缓升起，俯视整个街区` | 段落收束 |
| **环绕** | 绕主体转 | `镜头绕人物半圈，保持人物居中` | 帅镜头但贵，慎用 |
| **手持** | 轻微晃动 | `轻微手持晃动，纪实感` | 紧张、追逐；别写成「剧烈晃动」 |

**速度词只有三档**：`极其缓慢` / `缓慢` / `匀速`。不要写「快速地猛地推近」——
模型对速度副词不敏感，写猛了画面反而崩。

## 五、上下文连贯怎么校验

分镜表写完、开跑之前，用下面五条过一遍。**这一步花五分钟，能省掉整段重做。**

### 5.1 五条连贯校验

| # | 校验项 | 通过标准 | 不通过怎么办 |
|---|---|---|---|
| 1 | **时长与台词匹配** | 台词按每秒 4~5 字估算，能塞进 `duration` | 改台词，或把镜头拆成两镜 |
| 2 | **衔接方式可执行** | `transition` 是四类之一，且相邻镜的景别差不超过两级 | 补一个过渡镜，或改景别 |
| 3 | **角色与场景一致** | 同一 `scene` 下的 `visual` 描述里，环境要素（时间/天气/光位）不冲突 | 统一写进场景图，逐镜只写变化部分 |
| 4 | **画幅与分辨率锁死** | 全部镜头同一个 `aspect_ratio` 与 `resolution` | 中途改尺寸，最后拼接必须重裁 |
| 5 | **首尾帧可接** | 需要衔接的镜对，上一镜尾帧 = 下一镜首帧 | 补出尾帧图，或改用固定机位 |

> **衔接四类桥梁**：动作衔接（上一个动作没做完就切）、视线衔接（顺着人物目光切）、
> 空间衔接（同场景不同机位）、声音衔接（上一镜的声音延续到下一镜）。
> 写不出四类中的任何一类，说明这两镜之间缺一个过渡镜。

### 5.2 表格自检脚本

把下面这段存成 `check_shots.py`，和 `shots.csv` 放一起，改完分镜表就跑一次。

```python
# -*- coding: utf-8 -*-
"""分镜表自检：时长、衔接、画幅、台词容量。只用标准库。"""
import csv, sys, re

BRIDGES = {"动作衔接", "视线衔接", "空间衔接", "声音衔接"}
SIZES = ["大远景", "远景", "全景", "中景", "近景", "特写", "大特写"]
MAX_SECONDS = 8          # 单镜上限，超过就该拆
CPS = 4.5                # 中文口播经验值：每秒 4~5 字


def load(path="shots.csv"):
    with open(path, encoding="utf-8-sig", newline="") as f:
        return list(csv.DictReader(f))


def check(rows):
    bad = []
    for i, r in enumerate(rows):
        sid = r.get("shot_id") or "第%d行" % (i + 2)
        try:
            dur = float(r.get("duration") or 0)
        except ValueError:
            bad.append("%s 时长不是数字：%r" % (sid, r.get("duration")))
            continue
        if dur <= 0:
            bad.append("%s 缺少时长" % sid)
        if dur > MAX_SECONDS:
            bad.append("%s 时长 %.1fs 超过 %ds，建议拆镜" % (sid, dur, MAX_SECONDS))
        # 台词容量
        line = re.sub(r"[\s，。！？、；：\"'（）]", "", r.get("dialogue") or "")
        if line and len(line) > dur * CPS:
            bad.append("%s 台词 %d 字，%.1fs 塞不下（上限约 %d 字）"
                       % (sid, len(line), dur, int(dur * CPS)))
        # 衔接
        tr = (r.get("transition") or "").strip()
        if i < len(rows) - 1 and tr and tr not in BRIDGES:
            bad.append("%s 衔接方式 %r 不在四类桥梁里" % (sid, tr))
        # 景别跳级
        if i and r.get("shot_size") in SIZES:
            prev = rows[i - 1].get("shot_size")
            if prev in SIZES and abs(SIZES.index(r["shot_size"]) - SIZES.index(prev)) > 2:
                bad.append("%s 景别从「%s」跳到「%s」，建议补过渡镜" % (sid, prev, r["shot_size"]))
    return bad


if __name__ == "__main__":
    path = sys.argv[1] if len(sys.argv) > 1 else "shots.csv"
    rows = load(path)
    issues = check(rows)
    total = sum(float(r.get("duration") or 0) for r in rows)
    spoken = sum(len(re.sub(r"\s", "", r.get("dialogue") or "")) for r in rows)
    print("镜头 %d 个 · 总时长 %.1f 秒（%.1f 分钟）· 台词 %d 字"
          % (len(rows), total, total / 60.0, spoken))
    if issues:
        print("\n发现 %d 个问题：" % len(issues))
        for x in issues:
            print("  - " + x)
        sys.exit(1)
    print("✓ 分镜表自检通过")
```

```bash
python3 check_shots.py shots.csv
```

### 5.3 出片后的成片复检

单镜都合格不等于成片合格。每集出完立刻抽查（**不要等全剧跑完**）：

- [ ] **不缺镜**：`shots.csv` 里每个 `shot_id` 在成片里都有对应片段
- [ ] **画幅一致**：全片没有黑边、没有被拉伸的镜头
- [ ] **衔接不跳**：相邻片段之间有动作或视线的承接
- [ ] **音画同步**：有台词的镜头口型对得上，没有错位
- [ ] **音量平衡**：台词清楚，BGM 不盖过台词，无爆音
- [ ] **总时长**：符合投放要求
- [ ] **标识**：渠道要求 AI 生成标识的，确认已加

## 六、分镜表与画布节点的对应

```
shots.csv 的 shot_id  →  画布节点编号
        duration       →  该节点视频生成的秒数
        visual         →  节点首帧 prompt
        camera         →  节点视频 prompt 的运镜部分
        dialogue       →  节点配音任务与 SRT 的一行
        transition     →  决定该节点是否要出尾帧
```

**改哪一镜就只重跑那个节点。** 这就是把分镜表做成一列 `shot_id` 的价值 ——
它同时是文件名前缀、任务台账主键和断点续跑的判断依据。

任务台账建议字段：

```csv
shot_id,stage,app,api,task_id,status,points,input_url,output_url,updated_at
```

`status` 只认 `pending` / `completed` / `failed`；重跑时**只补 `status != completed` 的行**。
每提交一个任务就落盘一次，进程挂了也能续上。
