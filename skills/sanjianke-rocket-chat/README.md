# 三剪客 · Rocket.Chat 团队通讯 Skill

Rocket.Chat：可完全自建的团队通讯平台，把即时消息、频道、语音、联邦与外部集成收进一套自己掌控的部署里。

---

## 前置条件

- 一台能跑容器的服务器（Docker 或 Podman），或一个可用的 Kubernetes 集群。
- 一个 MongoDB 实例；生产环境建议以副本集方式运行，并准备好 oplog 账号。
- 对外提供服务时需要一个域名和反向代理（官方 compose 组合内置 Traefik 方案）。
- 持久化存储：数据库卷与文件存储目录。
- 可选的监控组件（Prometheus / Grafana）、SMTP 账号、单点登录凭据、推送服务。

---

## 使用

1. 先明确部署形态：单机试用用单容器；正式环境用官方 compose 组合仓库或 K8s。
2. 准备好 `.env`：至少设好 `ROOT_URL`、`DOMAIN`、数据库连接串。
3. 起服务后先看日志，确认没有数据库连接类报错。
4. 用浏览器实际登录并跑一遍：发消息、传文件、开视频通话。
5. 需要程序化接入时，用外部接口或应用框架；**接口的路径与字段以官方 API 文档为准**。
6. 升级前一定先备份数据库，再拉新镜像重建。

---

## 依赖

- Docker / Podman（或 Kubernetes）。
- MongoDB（副本集）。
- 反向代理与 TLS 证书（对外暴露时）。
- 持久化卷或兼容对象存储（图片、附件、头像）。
- 可选：NATS、Prometheus / Grafana、SMTP、身份提供方、推送服务。

---

## 安全

- 不内嵌任何密钥，数据库密码、token、证书都要在执行时提供。
- 数据库和密钥走 `.env` 或 Docker secrets，并确保 `.env` 在 `.gitignore` 里。
- 只对外暴露反向代理端口，不要把 MongoDB 端口直接暴露到公网。
- 多实例环境下按节点分别设置 `INSTANCE_IP`，避免实例间身份混淆。
- 上线前确认反代只做转发、没有引入 URL 重写；URL 重写会破坏鉴权与实时连接。
- 启用联邦或对外集成前，先确认数据出境与合规边界。
- 定期验证备份可恢复，而不是只验证备份文件存在。
