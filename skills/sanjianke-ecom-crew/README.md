# 三剪客 · 电商上新小组

> **L3 多智能体协作型**：四个角色分工互审，一条命令出整套上新物料 + 一份可读的裁决记录。
> 本包**不出图**（视觉只出文本方案），真出图交给既有电商主图包。

---

## 一、这个包解决的是什么问题

上新一个品，卡住人的从来不是"没有图"，而是**没人肯先说不**：

- 选品觉得能卖，视觉说图做不出来，合规说这文案发不出去 —— 三句话在三个地方说，
  谁也没听见谁；
- 等运营把主图、详情页、文案都做完，合规才说"这几句不能写" —— 全部返工；
- 更糟的是**看起来通过了**：没有人明确反对，物料就这么发出去了。

本包把这条链路做成**四个各有目标函数、互相能否掉对方的角色**，
一条命令跑完，产出整套物料**加一份写清了"谁在什么条件下否了谁、最多几轮、
谈不拢怎么办"的裁决记录**。

| 你最关心 | 答案 |
|---|---|
| 这是什么层级的包 | **L3 多智能体协作型**（多角色分工互审），不是"多跑几个角色" |
| 有哪几个角色 | 选品 / 文案 / 视觉 / 合规 —— 各有独立目标函数与产出物 |
| 谁能否掉谁 | **选品**能否掉这个品（含本地毛利判定线）；**视觉**能说某位"做不出来"并打回文案；**合规能一票否决** |
| 信息会不会串 | **本地强制隔离**：后一个角色看不到前一个的自评，`run` 会把各角色实际收到的输入打进 stderr 供核对 |
| 谈不拢怎么办 | 轮次用尽仍在否决 → **如实报「未收敛」**（退出码 3），逐轮裁决原样留档，**不假装谈拢** |
| 要装什么 | **什么都不用装**，只用 Python 标准库 |
| 会瞎编吗 | 提示词写死纪律；本地闸门扫真实文字 —— 违禁词、占位符、照抄示例、编造引文、缺主图位、裁决不自洽 |
| 中断了怎么办 | **断点续跑**：断点 key 含该阶段全部输入，命中就跳过，不重复花钱 |
| 多少钱 | `cost` 先报价（调用清单 + token）；**文本网关不公布单价，本包只报 token、不编金额** |
| 出图吗 | **不出**。视觉只出文本方案（每张图画什么、文字压哪、素材从哪来） |

## 二、L3 的四条硬要求，本包分别落在哪里

L3 的关键**不是"调多次模型"**。下面四条少一条，就退化成"一个人写了四遍"。

| L3 的要求 | 本包的做法 | 可以怎么验 |
|---|---|---|
| **每个角色有独立目标函数与产出物** | 四个系统提示词各写各的目标函数；产出契约互不重复（选品卡 / 五位文案 / 五位方案 / 裁决书） | `run.py roles` 一张表列全 |
| **角色之间会互相否掉东西** | 视觉打回 → 送回文案重写（一轮内最多 2 次）；合规打回 → 重开下一轮；合规点名选品卡 → **回传选品**重开 | `REPORT.md` 的「谁否了谁」交互日志；`result.json` 的 `interaction_log` |
| **信息不对称** | `role_input()` 是唯一入口，只挑该角色该看到的字段；合规走白名单，自评字段漏不出去 | `run` 的 stderr 逐条打印各角色输入摘要；`result.json` 的 `isolation` |
| **有裁决与终止机制** | `--rounds` 轮上限；合规三选一；轮次用尽仍在否决 → `final_status=未收敛`、退出码 3 | `result.json` 的 `rulings`（逐轮留档）+ `not_converged_why` |

### 信息隔离是**代码**，不是提示词里的礼貌请求

```
角色[选品] 输入 = 商品资料 340 字（**只有商品资料**）
  └ 隔离：（第一个角色，无上游）
角色[文案] 输入 = 商品资料 340 字；另有 选品卡的卖点与证据=5 条、本地毛利测算=9 项、选品的风险提示=3 条
  └ 隔离：看不到视觉的可产性结论、看不到合规口径、看不到任何角色的自评
角色[视觉] 输入 = 商品资料 340 字；另有 主图五位的文案（只给文字）=5 项、详情页文案=4 项、素材清单=77 字
  └ 隔离：看不到选品卡的风险清单细节、看不到合规结论、看不到文案的自评
角色[合规] 输入 = 商品资料 340 字；另有 最终物料=4 项
  └ 隔离：看不到任何角色的自我评价与内部打分，只拿到产出物本身
```

（以上是真机实跑的一次输出。合规那条是自测时真抓到的漏洞修好之后的形态：
早期版本把视觉对象**整体**喂给合规，连它给自己的 `8.8` 分一起漏了出去。）

## 三、与 `sanjianke-ecom-image`（电商主图工厂）的分界

**这两个包不是同一件事的两个版本。** 判断标准很简单：看**核心难点**和**失败模式**。

| 维度 | `sanjianke-ecom-image`（电商主图工厂） | **本包（电商上新小组）** |
|---|---|---|
| 形态层级 | **L1 单点生成型**：一个输入 → 一类产出 | **L3 多智能体协作型**：四个立场从选品开始协作 |
| 输入 | 商品信息 + 商品**实物图 URL** | 商品资料（含成本参数、资质、素材清单、风险提示） |
| 核心难点 | **出图**：平台规格、比例真伪、实物图改版式 | **协作与裁决**：谁能否掉谁、被否之后谁改、几轮谈不拢怎么办 |
| 产出物 | 主图 / 详情图**图片文件** + `plan.json` | **整套物料文本 + 裁决记录**（`REPORT.md` / `result.json`） |
| 会不会出图 | **会**（走 `nano_banana`，`generate` + `edit`） | **不会**（视觉只出文本方案；包内无图片文件） |
| 视角冲突 | 无（一个角色：出图） | **有**：选品要能卖 / 视觉要能做出来 / 合规要发得出去 |
| 谁能否决 | 本地闸门（比例、违禁词、主图位） | **角色之间**：选品否决品 / 视觉打回位 / 合规一票否决 |
| 合规扫描对象 | 它自己写的主图文案 + 出图提示词（**两类，同口径全拦**） | **三类口径**：材料侧只报不拦 / 创作者产出按面客与审类字段分开 / 评审文书开引用提到排除 |
| 特有闸门 | **比例真伪**（读回真实像素，上游按 32 对齐、3:4 实得 864x1184 偏差 2.70%） | **主图位完整性** + **裁决完整性**（有反对却判放行 = 假装谈拢） |
| 成本结构 | 按**张**计（实测 24 点/张），金额可算 | 按**轮次**计（1 次选品 + 每轮 3 次），网关不公布文本单价 → **只报 token** |
| 断点 key | 提示词摘要 + 比例 + 分辨率 + 模型 + action + 参考图 | 角色 + 模型 + 温度 + `max_tokens` + 轮次 + 平台 + 各上游产物摘要 + 重开标记 + 口径版本 |
| 什么时候用 | "把这个商品的五张主图做出来" | "这个品该不该上、上什么文案、图做不做得出来、能不能发、谁否了谁" |

**一句话**：`ecom-image` 解决"图怎么出"，本包解决"**这个品该不该上、以及谁说了算**"。
两者可以串起来用 —— 本包的视觉方案（每张图画什么、文字压哪）正好是
`ecom-image` 出图前的输入。

## 四、四角色一览

| 角色 | 目标函数 | 产出物 | 否决权 |
|---|---|---|---|
| **选品** | 能不能卖、毛利够不够、资质与风险兜不兜得住 | 选品卡 | **能**（模型 `venv_veto` + 本地毛利/退货率判定线） |
| **文案** | 主图与详情页能不能转化 | 五位文案 + 详情页 | 无（只能被否） |
| **视觉** | 图能不能真做出来、版式合不合规 | 五位方案 + 打回清单 | **能**（标 `not_producible` 即打回文案） |
| **合规** | 广告法与平台规则 | 风险裁决 | **一票否决** |

详细的职权、产出契约、信息隔离边界、裁决与终止条件见
`references/角色与职权.md`。

## 五、快速开始

```bash
# 0) 到 https://api.a7w.cn/ 注册领 Key（本包不内嵌任何密钥，也不代付）
export A7W_API_KEY=sk-你的key        # Windows PowerShell: $env:A7W_API_KEY="sk-你的key"

# 1) 先认角色与主图位（零成本、不联网）
python3 scripts/run.py roles

# 2) 报价（零成本）：这次协作大概几次调用、多少 token
python3 scripts/run.py cost --file 商品资料.md --rounds 2

# 3) 一条命令出整套物料（轮次上限 2）
python3 scripts/run.py run --file 商品资料.md --rounds 2 --outdir 输出目录

# 4) 事后想把裁决记录再读一遍（零成本）
python3 scripts/run.py log --outdir 输出目录
```

`--outdir` 里会落三个文件：

| 文件 | 内容 |
|---|---|
| `REPORT.md` | 人读主交付物：谁否了谁 / 信息隔离证据 / 选品卡 / 五位文案 / 视觉方案 / 逐轮裁决 / 闸门自检 / 成本 |
| `result.json` | 全量机器可读结果：各角色原始产出、逐轮裁决原样留档、闸门明细、真实 usage |
| `state.json` | 断点 |

只跑某一个角色也行（`pick` / `copy` / `visual` / `compliance`），
每个都支持 `--dry-run`（只打印提示词，不花钱）、`--json`、`--outdir`（断点）。

## 六、一次真实跑出来长什么样

真机实跑（`run --rounds 2`，11 次调用 / 51,294 token / 89.7 秒），
`REPORT.md` 里的「谁否了谁」日志：

| # | 轮 | 谁 | 动作 | 对象 | 理由 |
|---|---|---|---|---|---|
| 1 | 0 | 选品 | 出选品卡 | 麦香低糖代餐奶昔 30 条装 | 结论 可测试 |
| 2 | 1 | 文案 | 出文案 | 主图五位 + 详情页 | 5 位文案 |
| 3 | 1 | 视觉 | 判可产性 | 第 1 次视觉方案 | 可产 2 位，打回 3 位 |
| 4 | 1 | 视觉 | **打回** | 第 3 位 · 细节工艺、第 4 位 · 场景人群、第 5 位 · 资质售后 | `missing_asset` ×2；`no_real_cert` |
| 5 | 1 | 文案 | 重写（按打回意见） | 三位 | — |
| 6 | 1 | 合规 | **打回** | 整套物料 | 5 条整改要求（「低糖」缺糖含量依据、「代餐」缺标准符合性依据…） |
| 7 | 2 | 合规 | **打回上游** | 选品 | 整改要求点名了选品卡字段 → 回传重开 |
| 8 | 2 | 选品 | 按合规要求重开 | 选品卡 | 结论 可测试 |
| 9 | 2 | 视觉 | **打回** | 同上三位 | `missing_asset` ×2；`no_real_cert`（素材没变，仍然做不出来） |
| 10 | 2 | 合规 | **打回** | 整套物料 | 4 条整改要求 |
| — | — | — | **未收敛** | — | 退出码 3，`not_converged_why` 写清停在哪个结论上 |

**这次跑是真的在互否，不是各写各的**：视觉两次打回同一批位（因为素材确实没变，
它没有为了让流程跑通而假装能做）；合规两轮都在打回且整改项不同（第 2 轮在追
"上一轮要求的整改有没有真的做到"）。

## 七、六道硬闸门

| # | 闸门 | 判据 | 退出码 |
|---|---|---|---|
| 1 | **电商合规** | 广告法违禁词；不伪造销量/评价/资质/检测报告。**三套口径**（材料侧只报不拦 / 创作者按面客与审类字段分开 / 评审文书开引用提到排除） | 3 |
| 2 | **占位符残留** | `{}` / `[待填]` / `XXX` / `（此处省略）` / `TODO` | 3 |
| 3 | **照抄提示词示例** | 去标点相等 / Jaccard ≥ 0.75 / 覆盖度 ≥ 0.60（**带适用窗口**） | 3 |
| 4 | **锚点到句子** | 每条意见必须引用真实原文；未锚定率 > 0.40 判定位失败，编造引文剔出 | 3 |
| 5 | **主图位完整性** | 五个主图位缺位即标红；视觉方案必须正好五位 | 3 |
| 6 | **裁决完整性** | 打回/否决必须留理由与整改项；有反对却判放行 = **假装谈拢** | 3 |

另外还有两道：**成本上限**（超限就地中止且**未发起那次调用**，退出码 5）与
**产出不许进包**（`--outdir` 在包内 → 退出码 2）。

命中一律：**标红 + stderr 汇总 + 非 0 退出码**。
详细判据（含「最X」豁免、contain 适用窗口、三套口径的差异）见
`references/电商规格与合规.md`。

## 八、成本

- **调用构成**：`1 次选品 + 每轮（文案 + 视觉 + 合规）`；轮内还可能多出
  视觉打回后的文案重写（每轮最多 2 次）与合规点名上游后的选品重开（每轮最多 1 次）
- **只报 token，不编金额**：`GET /api/v1/models` 的返回里**没有价格字段**，
  文本模型网关不公布单价。所以结果里 `points` / `yuan` 都是 `null`，
  并带一句说明。要折算金额请自己传 `--price-in` / `--price-out`（点/百万 token）
- **`--budget` 是每个会花钱子命令的第一步**：超预算时**一次调用都不发**
- ⚠️ **诚实说明**：**没给单价时预算核不了验**（金额本来就不可知），
  此时只提示"预算无法核验"，不拦

排错与退出码见 `references/成本与排错.md`。

## 九、诚实边界

- **合规闸门是启发式自检**，来自公开经验整理与团队实测，**不构成法律意见**，
  也不等于任何平台的官方审核规则（官方规则不公开且会变）。医疗器械、食品、
  保健品、化妆品、金融这些高风险类目**必须人工复核**。
- **本包不生成资质、不替你取得授权**。没有真实资质就不许做资质宣称 ——
  视觉会标 `no_real_cert`、合规会据此否决，这是设计意图，不是故障。
- **"未收敛"是正常结局之一**。素材补不上、卖点无法举证、资质拿不到，
  不是多跑几轮能解决的；本包宁可如实报未收敛并留下每一轮的理由。
- **模型自评不可信**。合规角色看不到任何角色的自评；本地闸门也不采信模型结论
  （选品的账本地自己算，裁决的结论本地自己核）。
- **本包不出图**，包内不允许出现任何图片文件。
