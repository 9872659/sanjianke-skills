# 电商规格与合规（主图位、扫描口径、六道闸门）

> ⚠️ 本包里的违禁词表与所有判定都是**启发式自检**，来自公开经验整理与团队实测，
> **不构成法律意见**，也不等于淘宝 / 天猫 / 拼多多 / 抖音商城的官方审核规则
> （官方规则不公开且会变）。高风险类目必须人工复核。

---

## 一、五个主图位

电商主图的"位"不是排版偏好，是**平台约定**：每一张承担一个不同的说服任务。
所以缺位不是"少一张图"，是"少一个说服环节"。

| 位 | key | 要解决的事 | 文案上限 |
|---|---|---|---|
| 第 1 位 · 利益点 | `s1_benefit` | 一张图说清「买它我能得到什么」——最想让人在 0.5 秒内读到的那一句 | 14 字 |
| 第 2 位 · 规格与适用 | `s2_spec` | 规格、型号、容量、适用人群与**不适用人群**，一目了然 | 40 字 |
| 第 3 位 · 细节工艺 | `s3_detail` | 材质、工艺、做工细节的可验证呈现（能做微距就做微距） | 24 字 |
| 第 4 位 · 场景人群 | `s4_scene` | 真实使用场景与目标人群，让人对号入座 | 20 字 |
| 第 5 位 · 资质售后 | `s5_trust` | 售后承诺与**真实持有**的资质（没有真实资质就如实缺位，不许伪造） | 30 字 |

**字数上限是硬约束**，不是建议：主图上没人会读第 12 个字。
超限会被闸门五拦下（真机实测踩过：第 1 位写了 17 字、上限 14 字，整包返工）。

**第 5 位特别注意**：没有资质可展示时，写**售后口径**（退换规则），
**不要在图上解释自己缺什么**。真机实测踩过：模型把「无真实资质图」写进了第 5 位文案 ——
那是给运营看的内部状态，不是给消费者看的图。

## 二、视觉的「做不出来」理由码

| 理由码 | 含义 | 要谁能解决 |
|---|---|---|
| `missing_asset` | 缺真实素材（实物图 / 实拍图 / 包装图），且没有可用的替代 | 用户补拍 |
| `unverifiable_claim` | 画面要呈现的效果无法用现有素材验证（可能变成伪造演示） | 用户补证据或改画面 |
| `no_real_cert` | 该位要求资质，但没有真实持有的资质文件 | 用户补资质 |
| `text_overflow` | 文案字数超出该位可读上限 | 文案改短 |
| `platform_rule` | 该位形态与平台主图规则冲突（如白底位放场景） | 换位或换平台口径 |

**为什么理由码必须枚举**：自由文本没法做闸门，也说不清"到底缺什么"。
每个码对应一句"要谁能解决"，`missing_asset` 还必须写清 `asset_gap`（缺什么）
与 `ask_user`（要用户补什么）。

**`producible_with_placeholder` 的含义**：位可以做，但用的是占位素材
（例如先把渲染图当实拍用）。它**不算打回**，但会留在方案里给用户看，
让人知道哪几位是"先出稿、素材到位后要替换"。

## 三、广告法违禁词：三档风险 + 两类豁免

### 三档

| 档 | 例 | 处理 |
|---|---|---|
| 高 | 最好/最佳、第一（非序数）、国家级、100%、绝对有效、保证过审/达标、根治/治愈、稳赚、央视推荐、好评返现/刷单 | 必改；命中即压合规分并拦 |
| 中 | 免费领、秒杀/限时、独家/唯一/首创、纯天然/无添加、加微信/私域导流、标题党、月销 N 万 | 需可举证依据 |
| 低 | 标点堆砌（`！！` / `？？？`） | 易被判标题党/低质 |

### 豁免一：「最X」的可枚举上下文 + **句首不豁免**

真机实测踩出来的：`最大的区别` / `最主要的是` / 「可承受的最高获客成本」是
**普通中文程度用法与内部测算口径**，不是最高级商品宣称。一刀切拦下会把正常文案
整篇判死，用户就会干脆关掉整个合规闸门 —— 那比漏报更糟。

**两个条件缺一不可**：
1. 后文落在可枚举豁免表里（`不同/区别/差异/重要/关键/主要/先/后/…`）
2. 命中处**不在句首** —— 句首的「最大区别是…」是标题式宣称，**照拦**

| 文本 | 结论 |
|---|---|
| `同类里最便宜的先排除` | 豁免（句中 + 后接「先」） |
| `最便宜的先排除` | **拦**（句首） |
| `这个榨汁杯最好用` | **拦**（后接「用」不在表里） |

被豁免的**不静默放过**：全部带 `why_exempt` 记进 `exempted`，可人工复查。

**诚实说明一处死代码**：豁免表里还留着一档内部测算用语
（`获客/出价/预算/上限/成本/收益…`），但上游的正则只把
「最 + 好|佳|优|低|便宜|快|强|大|高|先进|新|流行|受欢迎」送进来，
所以「最获客」这种组合永远不会命中 —— **这一档当前不会被触发**。
保留它是因为它把"内部测算口径不算宣称"这条口径写在了代码里，
一旦上游正则扩宽就立刻生效。**不假装它在起作用。**

### 豁免二：「第一」的序数豁免

`第一年` / `第一步` / `第一款` 是**序数**，不是排他性宣称。同族原来那条只排除了
「第一次」，实测真实稿就被误判。

本包在枚举表里另加了「**眼**」：真机实测里视觉角色写
「主次关系为主标题第一眼、包装第二眼」—— 这是**阅读顺序**，不是"第一名"。

| 文本 | 结论 |
|---|---|
| `第一年做这个类目，第一款产品就是它` | 豁免（序数） |
| `销量第一的榨汁杯` | **拦** |
| `行业第一的康复效率` | **拦**（后缀是「的」，不在枚举表里） |
| `主标题第一眼、包装第二眼` | 豁免（阅读顺序） |

## 四、三套扫描口径（真机实测踩出来的，不是设计推演）

同一份违禁词表，**扫三种文本时口径不同**。混用会制造大量假警报，
而假警报会让人把整个闸门关掉。

### 口径 1：材料侧（用户给的商品资料）—— 只报不拦

全档（高/中/低）全查，但命中进 `material_hits`，**标红提示、写进报告，不改退出码**。

**为什么**：材料常常是把违规卖点原样贴进来的草稿。如果我们产出的主图文案一个字没错、
只因为用户材料里那句"100% 有效"就整包判死，那这道闸门就永远过不去，用户只会关掉它。

这也是本包与 `ecom-image` 的差别：那边材料就是出图提示词的来源，必须一起拦；
这边材料只是事实来源，面客文案是独立产出物，**拦错了地方等于没拦**。

### 口径 2：创作者产出侧 —— 按字段分两类

| 字段类型 | 例 | 口径 |
|---|---|---|
| **面客字段** | 主图文案、详情页标题/正文/开头/结尾、选品卡卖点、视觉的**画面**与文字样式 | **零豁免**，照发布口径查 |
| **审类字段** | 风险清单、依据、素材缺口、待补材料、否决理由、总结、who_can_fix、ask_user、视觉的**版式说明**/平台适配 | 允许「引用材料」与「提到/在禁止」两类排除，**被排除的必须留下原因** |

**为什么必须分**：真机实测第一次跑，选品卡的风险清单里写着
「功效宣称「100% 有效改善颈椎、行业第一的康复效率」没有检测报告支撑，
且含绝对化用语与最高级表述」—— 这是**在指出风险**，不是在宣称效果。
拿发布口径去量它，12 处命中全是这一类，整份产出被判违规、流水线被拦，
而它恰恰是**唯一把问题说清楚的那份东西**。

视觉那边同理：内部的版式说明「主标题第一眼」不该被当成最高级宣称。

**命中一律带 `in`（字段名）与 `field_kind`**：出问题时必须一眼看出是哪一处的字，
不然读报告的人只看到「命中 4 处」却不知道去哪改。

### 口径 3：评审文书侧（合规裁决、打回意见）—— 高风险 + 两类排除

只查高风险，再做两道排除：

1. **引用**：材料里已经出现过的词 → 判为引用材料，不计命中
2. **提到**：命中前后 **24 字**窗口内有 `禁止/不得/违规/无法举证/属于/删除/改为…`
   这类标记词 → 判为**在禁止它、在指出风险**，不计命中

窗口**不跨句末标点**：跨句取词会把上一句的"禁止"借给下一句的违规宣称。
用"窗口"而不是"整句"：中文逗号顿号极多，按标点切小句会把
「明确禁止代发、代拍、刷量」切碎成「刷量」，标记词正好被切掉（同族踩过）。

**闸门仍然有牙**：`本方案必须保证过审，效果 100% 达标。` 这种小句里
没有任何标记词，`exit=3` 照样拦。

**被排除的全部留档**：`quoted_from_material` / `mentioned_as_warning` /
`contextual_only` 三张表都带 `not_counted_reason`，随时可人工复查。

## 五、六道硬闸门的判据

| # | key | 判据 | 退出码 |
|---|---|---|---|
| 1 | `compliance` | 上列三套口径；不伪造销量/评价/资质/检测报告 | 3 |
| 2 | `placeholder` | `{}` / `[待填]` / `XXX` / `（此处省略）` / `TODO` / `TBD` | 3 |
| 3 | `prompt_echo` | 去标点相等 / Jaccard ≥ 0.75 / 覆盖度 ≥ 0.60（带适用窗口） | 3 |
| 4 | `anchor` | 每条意见必须引用真实原文；未锚定率 > 0.40 判定位失败 | 3 |
| 5 | `slot_complete` | 五个主图位缺位、文案超字数上限、视觉方案不是正好五位 | 3 |
| 6 | `ruling` | 打回/否决必须留理由与整改项；有反对却判放行 = 假装谈拢 | 3 |

命中一律：**标红（`✗` 前缀）+ stderr 汇总 + 非 0 退出码**。

### 闸门二的两处收紧（**都是为了不误报**）

- **空的 `{}` / `{ }` 一律放过**：它是 `json.dumps({})` 的正常产物，
  在正常提示词里到处都是。把它判成"模板没替换干净"就是假警报。
- 单层与双层都必须**里面有内容**（`{标题}` / `{{标题}}`）才算残留。

**诚实说明代价**：`{{}}` / `{ }` 这种**没有内容的**占位符现在抓不到。
但那种空占位在电商文案里没有意义，而误报会让用户把整个闸门关掉 —— 那更糟。

### 闸门三的 contain 适用窗口

覆盖度判据（示例被抄了多少）对**短示例**会饱和：示例归一后只有 3~5 字时，
长文本里被动凑齐两个二元组就有 0.5 的覆盖度 —— 离 0.60 只剩 0.10 余量。

同族在真实语料上标定过（105,863 字符 / 3,253 句）：13~20 字示例各长度比档位
覆盖度上限 0.125~0.333、≥0.60 命中 0 条；2~5 字短示例长度比 ≥2 时上限 0.500。

所以 `contain` 只在**两个条件都满足**时适用：

1. 目标片段长度 ≤ 示例长度 × **3.0**（长度比窗口）
2. 示例归一后长度 ≥ **8** 字（二元组数量够用）

不适用的地方记进 `skipped_windows`（按原因聚合计数），**不静默略过**。
长度守卫是**相对阈值** `max(6, len(示例)//2)`，不是绝对值 ——
绝对阈值（比如 12）在示例只有 15~17 字时占了七成以上，会把截断照抄整档放过。

### 闸门四的锚点：两个不同的长度门槛

| 判据 | 门槛 | 为什么 |
|---|---|---|
| `exact` / `substring` | 精确子串 ≥ **4** 字 | 去标点后逐字命中，短一点也几乎不会误伤 |
| `fuzzy` | ≥ **8** 字 且 Jaccard ≥ **0.55** | 统计判断，短串的二元组集合太小、相似度会虚高 |

一个门槛管两件事，就会出现"6 个字的真实引文被判成幻觉"——
把真问题算成假问题，直接污染未锚定率。

**四个角色各锚各的**：选品/文案锚到商品资料；视觉锚到「商品资料 + 该位文案」；
合规锚到「它审的那份物料」（由 `bundle_text_for_ruling` 拼出来，与提示词里给它看的
东西一致，否则它引的原文本地找不到，会污染未锚定率）。

**锚定成功的那条会被就地修正成目标文本里的真实句子** ——
模型引半句、连引两句时，报告里显示的是原文，不是模型的转述。

### 闸门四的一处真机发现：不许把 JSON 结构当引文

真机实测跑出来的：合规角色写 `quote` 为
`"product": "麦香低糖代餐奶昔 30 条装"` —— 这是 **JSON 结构**，不是内容。
本地锚点在物料里当然找不到它，就成了未锚定引文（`total=7 / verified=5`）。

处理：提示词里明确禁止把字段名/结构当引文，并给了正例形态
（要引就引 `麦香低糖代餐奶昔 30 条装`）。修好后同场景实测
`total=7 / verified=7 / unanchored=0`。

### 闸门六的「假装谈拢」判据

本地**不采信结论**，只看结论与事实是否自洽：

| 情形 | 判定 |
|---|---|
| 打回 / 否决，但 `required_fixes` 空 | 拦（打回必须说清改什么） |
| 一票否决，但 `veto_reason` 空 | 拦（否决必须留可读理由） |
| 有 `level=高` 违规 却判放行 | 拦 |
| 有无法举证宣称（`risk_claims`）却判放行 | 拦 |
| 有疑似伪造证据（`forged_evidence`）却判放行 | 拦 |
| `pending` 非空 却判放行 | 拦（自己都写了还有未解决问题） |
| 违规项没有引文 | 拦（说不清是哪里） |

## 六、本包**不**做什么

- **不出图**。视觉只出文本方案；包内不允许出现任何图片文件。
- **不生成资质**。没有真实资质就不许做资质宣称 —— 视觉标 `no_real_cert`，
  合规据此否决，这是设计意图。
- **不替用户取得授权、不做事实核查**。"不许编数据"是提示词里的一条纪律，
  不是核查；真实性与授权由使用者负责。
- **不预测平台审核结果**。违禁词表是粗筛，平台官方规则不公开且会变。
- **不编价格**。文本模型网关不公布单价，本包只报 token。
