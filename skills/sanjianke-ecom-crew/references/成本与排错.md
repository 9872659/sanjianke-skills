# 端点、成本与排错

---

## 一、端点与鉴权

| 用途 | 方法 | 地址 |
|---|---|---|
| 大模型（OpenAI 兼容） | POST | `https://api.a7w.cn/api/v1/chat/completions` |
| 在架模型清单（免费） | GET | `https://api.a7w.cn/api/v1/models` |

成功响应**不带 `code` 字段**；网关有时把它包一层 `{"code":1,"data":{...}}`，两种形态都认。

Key 三种给法（代码与文档里都不含任何 Key）：

```bash
python3 scripts/run.py run --file 商品资料.md --key sk-xxxx     # 1) 命令行
export A7W_API_KEY=sk-xxxx                                      # 2) 环境变量（Windows: $env:A7W_API_KEY="sk-xxxx"）
python3 scripts/a7w.py login --key sk-xxxx                      # 3) 写进 ~/.a7w/config.json 反复用
```

⚠️ **本包不走 `a7w._request(raw=...)`**。那边的 `raw` 参数是**原始请求体字节**
（给 multipart 上传用），**不是**"要原始响应"。同族有人把它当成后者用过，
结果崩在**钱已经扣之后**。本包一律自己发 `urllib` 请求，语义只有一种，不给误用的机会。

**退避重试**：上游 5xx（502/503/504）与网络抖动退避重试，最多 4 次（3s/6s/9s）；
4xx 是业务错误，直接报出来**不浪费额度**。模型输出用 `json.JSONDecoder().raw_decode()`
逐个 `{` / `[` 试解析，容忍围栏与多余字符。

## 二、调用构成与 token 标定

一次协作的调用次数：

```
1 次选品 + 每轮（1 次文案 + 1 次视觉 + 1 次合规）
```

轮内还可能多出：视觉打回 → 文案重写（**每轮最多 2 次**，即多 1~2 次文案 + 1~2 次视觉）；
合规点名上游 → 选品重开（**每轮最多 1 次**）。

`cost` 按**轮次上限**报价：真实跑起来可能第 1 轮就放行（省掉后面所有轮），
也可能轮次用尽仍在否决。

| 参数 | 值 | 来源 |
|---|---|---|
| 输入侧字符/token | `1.61` | 同族实测均值（**不是厂商文档**） |
| 输出侧 token/字符 | `1.11` | 同族实测均值（平台间 0.93~1.63，差异几乎全来自换行数） |
| 平台口径 | 1 元 = 100 点 | 账户口径 |

**这是估算，不是账单。** 真实扣费以账户流水为准；本包在结果里报的是**真实 usage**
（`prompt_tokens` / `completion_tokens`），不是按字符反推的估算值。
若某次调用没有真实 `usage`，会**如实计数并标注**（`estimated_flags`），不假装精确。

### ⚠️ 文本模型网关不公布单价 —— 只报 token，禁止编价

`GET /api/v1/models` 的返回里**没有价格字段**。所以：

- `cost` 不给金额，除非你传 `--price-in` / `--price-out`（点/百万 token）
- `run` / `pick` / `copy` / `visual` / `compliance` 的结果里 `points` 与 `yuan` 都是 `null`，
  并且带一句 `gateway_note` 说明原因
- **本包任何地方都不会出现一个编出来的金额**

## 三、`--budget` 的语义

```bash
python3 scripts/run.py run --file 商品资料.md --budget 0.5 --price-in 1000 --price-out 2000
```

- `--budget` 单位是**点**，必须 > 0
- `--price-in` / `--price-out` 要么都给、要么都不给（只给一个算不出金额 → 退出码 2）
- 校验放在**每个会花钱子命令的第一步**（`check_cost_opts()` 是
  `pick` / `copy` / `visual` / `compliance` / `run` / `cost` 的第一行）
- 超预算时**一次调用都不发**（退出码 5）

⚠️ **诚实说明**：**没给单价时预算核不了验** —— 金额本来就不可知。
此时 `check_cost_opts` 只提示「预算无法核验、只报 token」，**不拦**。
要真核预算请同时给单价。

事故复盘（同族踩过）：校验只写在 `cost` 子命令里，于是 `run --budget 0.5`
一路跑到报价之后才拦 —— 自测就真花了钱。所以本包把它提到每个子命令的第一行。

## 四、退出码

| 码 | 含义 | 处理 |
|---|---|---|
| 0 | 跑完且无硬闸门命中（`run` 还要求最终放行） | — |
| 2 | 参数/配置错 | 看 stderr 的「失败：…」，改命令重跑，不花钱 |
| 3 | 硬闸门命中（含**未收敛**） | 看 stderr 的闸门汇总，按 `REPORT.md` 处理 |
| 4 | 调用失败（网络 / 鉴权 / 点数 / 模型名） | 查 Key / 余额 / 模型名 |
| 5 | 预算超限，**未发起那次调用** | 调大 `--budget` 或跑更少轮次 |
| 130 | 用户中断 | — |

## 五、常见报错与处理

| 现象 | 原因 | 处理 |
|---|---|---|
| `鉴权失败（401）` | Key 无效/过期 | 重新到 api.a7w.cn 创建；确认环境变量或 `~/.a7w/config.json` |
| `点数不足（402）` | 余额不足 | 充值后重试（报告里已报真实 token，可据此估算） |
| `模型不存在（404）` | 模型名写死且已下线 | `run.py models --type text` 现查在架名 |
| `模型没返回 choices` | 上游返回结构异常 | 看报错里的原始响应片段；多为上游临时故障，重试一次 |
| `模型返回的不是合法 JSON` | 模型没按 `response_format` 输出 | 加 `--no-json-mode` 试试；或换模型 |
| `上游 502/503/504 … 重试` | 网关抖动 | 自动退避重试，不用管 |
| `内部状态写进主图文案` 被闸门拦 | 模型把「无真实资质图」这类运营侧说明写进第 5 位 | 提示词已写明禁止；若仍出现，本轮会被打回重写 |
| `主图文案超字数上限` | 模型没数字数 | 提示词已加"先数字数再交"；仍超会被闸门拦、下一轮重写 |
| `未收敛（打回）` + 退出码 3 | 轮次用尽仍在打回/否决 | **这是正常结局之一**。看 `REPORT.md` 的整改要求，补齐材料或改品后重跑 |
| `选品否决` 且停在第 0 轮 | 选品角色或本地判定线否决了品 | 换品；或按 `need_materials` 补齐材料后重跑 |
| `输出目录 … 在 Skill 包内`（退出码 2） | `--outdir` / `--out` 指到了包内 | 换到包外目录 |
| `商品资料缺 售价/成本` | 成本参数不全 | 账要本地算，必须给售价与成本；缺的会计入 `missing` |

## 六、断点续跑

`--outdir` 里落 `state.json`。**断点 key = 阶段名 + 该阶段全部输入的摘要**
（`hashlib.sha256(json.dumps(payload, sort_keys=True))[:20]`）——
不看参数名，而是把影响产出的每一样东西序列化后取摘要：角色、模型、温度、`max_tokens`、
`json_mode`、轮次、目标平台、各上游产物的内容摘要、是否重开、`fixes` 摘要，
以及口径版本（crew / prompt / gate）、闸门阈值、主图位上限、提示词示例、
选品本地判定线。

**输入变了 key 必变**，不存在"改了参数却复用旧产物"这种事
（同族踩过三次：内容截断没进 key、分辨率没进 key、死参数没进 key）。

命中就跳过并打印「已在断点里，跳过（零成本）」，不重复花钱。`--force` 强制重跑。

## 七、产出与包边界

- `run` 落三个文件：`result.json`（全量，机器可读）、`REPORT.md`（人读主交付物）、
  `state.json`（断点）
- `--outdir` / `--out` 落在 Skill 包内 → **退出码 2**（写操作在写之前就拦）
- **包内不允许有图片**：本包不出图
- Skill 包上传白名单只收 `.md .py .txt .json .sh .js .yaml .yml .csv`
- **`.pyc` 不会导致上传被拒**（CLI 的排除清单里有它）。本包只在
  `sys.dont_write_bytecode = True`（写在任何本地 import **之前**）上做干净，
  **不拿 .pyc 当理由吓人**

## 八、`--json` 契约速查

```bash
# 成功：stdout 只有一个 JSON，且带 ok:true
python3 scripts/run.py run --file 商品资料.md --outdir 输出目录 --json

# 失败：stdout 是 {"ok": false, "exit": N, "error": {"kind": ..., "message": ...}}
# kind ∈ usage | gate | call | budget | interrupt | internal
```

- 顶层是数组时包成 `{"ok": true, "data": [...]}`
- 只在**本次还没吐过任何 JSON 结果**时才补失败信封
- **未预料异常** → `kind:"internal"`、退出码 1，且**完整 traceback 打到 stderr**
- `--json` 写在子命令**前后都可以**（父级与每个子命令各挂一个同 dest 的开关）
- 人读文案走 stderr；**退出码语义一个都不变**

`--json` 契约、预算前置校验、产出不许进包、信息隔离、断点 key、渲染：

# 自测脚本不进包（包内只放交付物与文档）
