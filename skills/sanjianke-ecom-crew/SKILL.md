# 三剪客 · 电商上新小组

> ## ⚠️ 先申请你自己的 API Key
>
> **本 Skill 不内嵌任何密钥，也不代付费用。** 请到
> **[算力集市 api.a7w.cn](https://api.a7w.cn/)** 注册并创建**你自己的** API Key
> （新用户有赠送点数，可以先免费试跑）。
>
> 拿到后填进环境变量 `A7W_API_KEY`，或直接传给 `--key` 参数。
> **请勿使用他人提供的 Key** —— 用量与费用都记在 Key 所属账号上。

## 这个包是什么：L3 多智能体协作，不是「多跑几个角色」

上新一条链路，**四个角色的立场天生冲突**：选品想让品能卖（乐观），视觉要保证图真能做出来
（悲观），合规要保证发得出去（保守），文案夹在中间既要转化又要过审。
本包把这条链路做成四个**互相能否掉对方**的角色：

| 角色 | 目标函数 | 产出物 | 否决权 |
|---|---|---|---|
| **选品** | 这个品能不能卖、毛利够不够、资质与合规风险兜不兜得住 | 选品卡（卖点与证据 / 成本拆解 / 退货后毛利 / 保本 CPA / 资质状态 / 风险清单 / 结论） | **能**。`venv_veto=true` 时整条流水线**停在第 0 轮**；本地判定线（毛利过薄、退货率过高）也能否，模型措辞改不了账 |
| **文案** | 主图与详情页的文字能不能转化、能不能被图和平台容下 | 主图五位的文案 + 详情页文案 + 依据 | 无。它只能被否（被视觉要求改、被合规打回） |
| **视觉** | 每张图到底画什么、文字压哪、素材从哪来、能不能真做出来 | 五位的视觉方案（画面 / 素材 / 可产性 / 文字位置与字数 / 版式） | **能**。对任一位标 `not_producible` 即**打回文案**重写；改不动就在轮次用尽时报未收敛 |
| **合规** | 广告法与平台规则：这套物料能不能发出去 | 风险裁决（逐条违规项含原文引文 / 需补材料 / 整改要求 / 结论） | **一票否决**。否决时整包不许放行；轮次用尽仍在否决就如实报未收敛 |

**L3 的四条硬要求，本包分别落在哪里：**

| 要求 | 落点 |
|---|---|
| 每个角色有**独立目标函数与产出物** | 四个系统提示词各写各的目标函数（`PICK_SYSTEM` / `COPY_SYSTEM` / `VISUAL_SYSTEM` / `COMPLIANCE_SYSTEM`），产出契约各不相同（选品卡 / 五位文案 / 五位方案 / 裁决书） |
| 角色之间**会互相否掉东西** | 视觉打回 → 送回文案重写（一轮内最多 2 次）；合规打回 → 带着整改要求重开下一轮；合规点名要改选品卡 → **回传给选品**重开 |
| **信息不对称** | `role_input()` 是唯一入口，只挑该角色该看到的字段；`run` 把「各角色实际收到了什么」逐条打进 stderr |
| **裁决与终止机制** | 最多 `--rounds` 轮；合规三选一（放行/打回/一票否决）；轮次用尽仍在否决 → `final_status=未收敛`、退出码 3；裁决记录逐轮留档 |

### 信息隔离是**代码**，不是提示词里的礼貌请求

给某个角色看什么，由 `role_input()` 决定：

- **文案**只拿到选品卡的**结构化字段**（卖点与证据、本地毛利测算、风险等级），
  拿不到选品的自评与长篇论述（把上游的完整结论原文传下去，下游会顺着它复述一遍，
  四份产出读起来像一个声音 —— 同族踩过）。
- **视觉**只拿到**主图文案的文字**与素材清单，看不到选品卡的风险细节、看不到合规口径。
- **合规**只拿到**产出物本身**（白名单字段），任何角色的自评/打分字段都不进去。
  这条是自测时真抓到的：合规原本拿的是视觉对象**整体**，于是把视觉给自己的 `8.8` 分
  一起喂了进去 —— 那就不叫隔离了。现在走白名单，漏不出去。

跑 `run` 时 stderr 会长这样（可逐条核对）：

```
  · 角色[选品] 输入 = 商品资料 340 字（**只有商品资料**）
    └ 隔离：（第一个角色，无上游）
  · 角色[文案] 输入 = 商品资料 340 字；另有 选品卡的卖点与证据=5 条、本地毛利测算=9 项、选品的风险提示=3 条
    └ 隔离：看不到视觉的可产性结论、看不到合规口径、看不到任何角色的自评
  · 角色[视觉] 输入 = 商品资料 340 字；另有 主图五位的文案（只给文字）=5 项、详情页文案=4 项、素材清单（来自用户资料）=77 字
    └ 隔离：看不到选品卡的风险清单细节、看不到合规结论、看不到文案的自评
  · 角色[合规] 输入 = 商品资料 340 字；另有 最终物料=4 项
    └ 隔离：看不到任何角色的自我评价与内部打分，只拿到产出物本身
```

## 与 `sanjianke-ecom-image`（电商主图工厂）的分界

**这两个包不是同一件事的两个版本。** 分界表见 `README.md`，一句话概括：

- `ecom-image` 是**一个输入 → 一类产出**（商品信息 → 平台规格主图），它的核心是
  **出图能力、比例真伪、实物图改版式**；合规闸门扫的是它自己写的主图文案与出图提示词。
- 本包**不出图**，核心是**四个立场从选品开始协作**：视觉能不能说"这张做不出来"、
  合规能不能一票否决、被否之后谁来改、几轮谈不拢怎么办。产出是**整套上新物料 + 裁决记录**。

如果你要的只是"把这个商品的五张主图做出来"，用 `ecom-image`；如果你要的是
"这个品该不该上、上什么文案、图做不做得出来、能不能发、谁否了谁"，
用本包。**两者的产出物、失败模式、成本结构都不同。**

## 怎么用（命令行）

### 第 0 步：获取 API Key

到 **[api.a7w.cn](https://api.a7w.cn/)** 注册，创建一个 API Key（形如 `sk-...`）。

### 第 1 步：装依赖

**零依赖。** 不需要 `pip install` 任何东西，只要机器上有 Python 3.7+：

```bash
python3 --version
```

`scripts/a7w.py` 是**所有 Skill 包共用**的零依赖客户端（只用 `urllib` / `json` / `mimetypes`），
`scripts/run.py` 同样只用标准库。

> **约定**：我们靠「包内副本 SHA256 == 规范版」（16797 B）批量校验各包的客户端
> 有没有被意外改坏。所以本包**没有**为了自己的业务去改它 —— 需要应用专属接口
> 就写在 `run.py` 里。

### 第 2 步：填 Key

```bash
# Linux / macOS
export A7W_API_KEY=sk-你的key

# Windows PowerShell
$env:A7W_API_KEY="sk-你的key"
```

也可以存进配置文件反复用（推荐）：

```bash
python3 scripts/a7w.py login --key sk-你的key
```

### 第 3 步：先认角色与主图位（免费，不花点数、不联网）

```bash
python3 scripts/run.py roles
```

`roles` 会列出四个角色的职权、产出契约、否决权、信息隔离范围、
五个主图位的语义与文案上限、视觉的「做不出来」理由码、六道硬闸门的口径。
**这一步零网络、零成本**，先看清楚再花钱。

模型名会变，现查在架的：

```bash
python3 scripts/run.py models --type text
```

### 第 4 步：先报价，再决定跑不跑

```bash
python3 scripts/run.py cost --file 商品资料.md --rounds 2
```

`cost` 会把「1 次选品 + 每轮 3 次（文案/视觉/合规）」的调用清单与 token 估算列出来。
**金额要你自己填单价** —— 文本模型网关不公布单价，本包只报 token、**不编金额**。
给了 `--budget` 又没给单价时，它会明确告诉你"预算无法核验"，而不是假装核过了。

### 第 5 步：准备商品资料

`键：值` 一行一条。**成本参数必须给**，因为毛利是本地确定性算出来的
（沿用小红书带货包的公式口径，不另立一套）：

```text
商品名：轻食坚果燕麦脆 250g
类目：食品 / 休闲零食
平台：taobao
售价：59
成本：22
物流：5
包材：2
佣金率：0.05
退货率：0.08
资质：食品生产许可证 SC10123456789012、第三方营养成分检测报告（编号可查）
素材：实拍图 8 张（含微距细节 2 张）、场景实拍 3 张、包装图 2 张、参数表 1 份
卖点：每 100g 含膳食纤维 8.6g、独立小包装、开袋即食
详情：净含量 250g，每袋 25g 独立包装 10 袋，热量 458 大卡/100g
目标人群：早餐没时间、办公室加餐
风险提示：不写任何减重效果，没有对应的效果报告
```

毛利公式（本地算，不靠模型）：

```
单件毛利   = 售价 - 成本 - 物流 - 包材
佣金后毛利 = 单件毛利 - 售价 × 佣金率
退货后毛利 = 佣金后毛利 × (1 - 退货率)
保本 CPA   = 退货后毛利（投放超过就是纯亏）
建议 CPA 上限 = 退货后毛利 × 0.5
```

**本地判定线**（不因模型措辞而改变）：退货后毛利占售价 < 20% → 判放弃；
退货率 > 40% → 判放弃。命中了整条流水线不会往下走。

### 第 6 步：一条命令出整套物料

```bash
python3 scripts/run.py run --file 商品资料.md --rounds 2 --outdir 输出目录
```

轮次语义（**必须一眼看懂，否则"几轮"就会被误解**）：

- **一轮** = ①文案写 → ②视觉判可产性 → ③合规裁决
- 视觉打回 → **该轮的文案按打回意见重写**（一轮内最多 2 次）
- 合规打回/否决 → 进入**下一轮**，文案带着整改要求重写；
  合规点名要改**选品卡**的要求会**回传给选品**重开
- 轮次用尽仍在否决 → `final_status=未收敛`、**退出码 3**

产物落在 `--outdir`（**必须在包外**）：`result.json`（全量，含各角色原始产出、逐轮裁决、
闸门明细、真实 usage）、`REPORT.md`（人读的主交付物，含**谁否了谁**的交互日志、
信息隔离证据、闸门自检、成本）、`state.json`（断点）。

事后想把裁决记录再读一遍（零成本）：

```bash
python3 scripts/run.py log --outdir 输出目录
```

### 只跑某一个角色

```bash
# 选品（可能直接否掉这个品）
python3 scripts/run.py pick --file 商品资料.md --out 选品卡.json

# 文案（吃选品卡的 JSON）
python3 scripts/run.py copy --file 商品资料.md --pick 选品卡.json --out 文案.json

# 视觉（吃文案；可能说某位做不出来）
python3 scripts/run.py visual --file 商品资料.md --copy 文案.json --out 视觉.json

# 合规（吃整套物料；可能一票否决）
python3 scripts/run.py compliance --file 商品资料.md --bundle 物料.json --out 裁决.json
```

每个子命令都支持 `--dry-run`（**只打印将发送的提示词，不调模型不花钱**）、
`--json`（写在子命令前后都可以）、`--outdir`（断点续跑）。

## 端点

| 用途 | 方法 | 地址 |
|---|---|---|
| 大模型（OpenAI 兼容） | POST | `https://api.a7w.cn/api/v1/chat/completions` |
| 在架模型清单（免费） | GET | `https://api.a7w.cn/api/v1/models` |

成功响应**不带 `code` 字段**；网关有时把它包一层 `{"code":1,"data":{...}}`，两种形态都认。

## 退出码

| 码 | 含义 |
|---|---|
| 0 | 跑完且无硬闸门命中（`run` 还要求最终放行） |
| 2 | 参数/配置错（文件不存在、`--outdir` 在包内、给了 `--budget` 没给单价） |
| 3 | 硬闸门命中（合规/占位符/照抄示例/锚点/主图位/裁决完整性/**未收敛**） |
| 4 | 调用失败（网络 / 鉴权 / 点数 / 模型名） |
| 5 | 预算超限，**已就地中止且未发起那次调用** |
| 130 | 用户中断 |

## 六道硬闸门

| # | 闸门 | 判据 |
|---|---|---|
| 1 | **电商合规** | 广告法违禁词（最/第一/国家级/100%/保过…）；不伪造销量/评价/资质/检测报告。**材料侧 / 创作者产出侧 / 评审文书侧三套口径**（见下） |
| 2 | **占位符残留** | `{}` / `[待填]` / `XXX` / `（此处省略）` / `TODO` |
| 3 | **照抄提示词示例** | 去标点相等 / Jaccard ≥ 0.75 / 覆盖度 ≥ 0.60（**带适用窗口**） |
| 4 | **锚点到句子** | 每条意见必须引用真实原文；未锚定率 > 0.40 判定位失败，编造引文剔出 |
| 5 | **主图位完整性** | 五个主图位缺位即标红；视觉方案必须正好五位 |
| 6 | **裁决完整性** | 打回/否决必须留理由与整改项；有反对却判放行 = **假装谈拢** |

命中一律：**标红 + stderr 汇总 + 非 0 退出码**。

### 闸门一的三个口径（真机实测踩出来的，不是设计推演）

1. **材料侧**（用户给的商品资料）：全档全查，但**只报不拦**。
   为什么：材料常常是把违规卖点原样贴进来的草稿；如果我们产出的文案一个字没错、
   只因为用户材料里那句"100% 有效"就整包判死，这道闸门就永远过不去，用户只会把它关掉。
   所以材料侧命中进 `material_hits`，**标红提示、写进报告，但不改退出码**。
2. **创作者产出侧**（我们产出的物料）：**按字段分两类**
   - **面客字段**（主图文案、详情页、选品卡卖点、视觉画面）→ **零豁免**，照发布口径查
   - **审类字段**（风险清单、依据、素材缺口、待补材料、视觉的版式说明）→
     允许「引用材料」与「提到/在禁止」两类排除，**被排除的必须留下原因**，照样列在案上
3. **评审文书侧**（合规裁决、打回意见）：高风险 + 引用/提到排除。
   同族 `review-board` 踩过两轮：合规官写「无法举证为 100% 成立」
   「明确禁止刷单」是**在禁止它**，不是自己在做违规宣称。

**闸门仍然有牙**：「本方案必须保证过审、效果 100% 达标」这种小句里没有任何标记词，
`exit=3` 照样拦（自测用例覆盖）。

### 闸门三的 contain 适用窗口（**实测标定，不是拍的**）

覆盖度判据（示例被抄了多少）对**短示例**会饱和。本包沿用同族的标定结论
（真实语料 105,863 字符 / 3,253 句）：13~20 字示例各长度比档位覆盖度上限
0.125~0.333、≥0.60 命中 0 条；2~5 字短示例长度比 ≥2 时上限直接到 0.500
—— 离阈值只剩 0.10 余量。所以 `contain` 只在**两个条件都满足**时适用：

1. 目标片段长度 ≤ 示例长度 × 3.0（长度比窗口）
2. 示例归一后长度 ≥ 8 字（二元组数量够用）

不适用的地方记进 `contain_skipped`，**不静默略过**。

### 闸门五 / 六的口径

- **主图位完整性**：五位是平台约定（每位承担一个说服任务），缺位 = 少一个说服环节，
  一律标红。文案超字数上限也算命中（主图上没人会读第 12 个字）。
- **裁决完整性**（**不许假装谈拢**）：打回/否决没写整改要求 → 拦；
  一票否决没写理由 → 拦；有高等级违规 / 无法举证宣称 / 疑似伪造证据 / 未解决问题
  却判「放行」→ 拦。本地不采信结论，只看结论与事实是否自洽。

## 视觉的「做不出来」是枚举理由码

自由文本没法做闸门，也说不清"到底缺什么"。所以视觉说做不出来时必须给理由码，
每个码对应一句"要谁能解决"：

| 理由码 | 含义 |
|---|---|
| `missing_asset` | 缺真实素材（实物图 / 实拍图 / 包装图），且用户没提供可用的替代 |
| `unverifiable_claim` | 画面要呈现的效果无法用现有素材验证（可能变成伪造演示） |
| `no_real_cert` | 该位要求资质，但用户没有提供真实持有的资质文件 |
| `text_overflow` | 文案字数超出该位的可读上限，硬排会糊成一团 |
| `platform_rule` | 该位形态与目标平台的主图规则冲突（如白底位放场景） |

`missing_asset` 还必须写清 `asset_gap`（缺什么）与 `ask_user`（要用户补什么）——
不然闸门会拦：「说不清缺什么」等于没提。

## 主图五个位

| 位 | 要解决的事 | 文案上限 |
|---|---|---|
| 第 1 位 · 利益点 | 一张图说清「买它我能得到什么」 | 14 字 |
| 第 2 位 · 规格与适用 | 规格、型号、容量、适用与不适用人群 | 40 字 |

## 断点续跑

`--outdir` 里落 `state.json`。**断点 key = 阶段名 + 该阶段全部输入的摘要**
（不看参数名，而是把影响产出的每一样东西序列化后取摘要）——
输入变了 key 必变，不存在"忘了把某个维度写进 key"这种事。
口径版本（crew / prompt / gate）、闸门阈值、提示词示例、轮次、上游产物摘要全在里面。

命中就跳过并打印「已在断点里，跳过（零成本）」，不重复花钱。`--force` 强制重跑。

## `--budget` 是**每个会花钱子命令的第一步**

事故复盘（同族踩过）：校验只写在 `cost` 里，于是 `run --budget 0.5` 一路跑到报价之后
才拦 —— 自测就真花了钱。所以本包把 `check_cost_opts()` 放在
`pick` / `copy` / `visual` / `compliance` / `run` / `cost` **每一个**的第一行，
超预算时**一次调用都不发**（退出码 5）。

⚠️ **诚实说明一处**：没给单价时预算**核不了验**（金额本来就不可知），
此时 `check_cost_opts` 只提示、不拦。要真核预算请同时给 `--price-in` / `--price-out`。

## `--json` 契约

- **成功**：结果对象里多一个 `"ok": true`；顶层是数组时包成 `{"ok": true, "data": [...]}`
- **失败**：stdout 输出 `{"ok": false, "exit": <码>, "error": {"kind": ..., "message": ...}}`；
  只有在**本次还没吐过任何 JSON 结果**时才补信封
- **未预料异常** → `kind:"internal"`、退出码 1，且**完整 traceback 打到 stderr**（报 bug，不藏 bug）
- **stdout 永远只有一个 JSON**；`--json` 写在子命令**前后都可以**
- 人读文案照旧走 stderr；**退出码语义一个都不变**；非 `--json` 模式输出一个字符都不变

## 诚实边界

- **合规闸门是启发式自检**，来自公开经验整理与团队实测，**不构成法律意见**，
  也不等于淘宝/天猫/抖音等平台的官方审核规则（官方规则不公开且会变）。
  医疗器械、食品、保健品、化妆品、金融这些高风险类目**必须人工复核**。
- **本包不替你取得资质**。没有真实资质就不许做资质宣称 —— 视觉会标 `no_real_cert`，
  合规会据此否决，这是设计意图，不是故障。
- **"未收敛"是正常结局之一**。素材补齐不了、卖点无法举证、资质拿不到，
  这些都不是多跑几轮能解决的；本包宁可如实报未收敛并留下每一轮的理由，
  也不会输出一份"看起来通过了"的物料。
- **模型自评不可信**。所以合规角色看不到任何角色的自评，本地闸门也不采信模型的结论
  （选品的账本地自己算、裁决的结论本地自己核）。
