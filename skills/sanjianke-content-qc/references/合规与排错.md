# 合规、闸门与排错

本文件是四道确定性闸门的口径来源、退出码表，以及真机上踩过的坑。

---

## 一、闸门一：广告法违禁词（本地，确定性）

命中就**压分 + 标红 + stderr 汇总 + 退出码 3**。

| 等级 | 命中后合规分封顶 | 例子 |
|---|---|---|
| 高 | 1 | 最好/最佳/最优、全网最低、第一品牌、国家级、100%、绝对有效、根治、稳赚、央视推荐 |
| 中 | 4 | 免费领、秒杀/限时抢、独家/唯一/首创、纯天然/无添加、加微信/私信我/vx、震惊/不看后悔 |
| 低 | 7 | 连续感叹号或三个以上问号 |

这张表是**粗筛**，来自公开经验整理，**不构成法律意见**，也不等于任何平台的官方审核结论。
高风险类目（医疗、保健食品、食品、金融、母婴、特殊化妆品）必须人工复核。

### 「最X」的可枚举上下文豁免 + 句首不豁免

`最大区别` / `最主要的是` 这类是普通中文用法，不是最高级商品宣称。
一刀切拦下会把正常稿子整篇判死，用户就会干脆关掉闸门 —— 那比漏报更糟。

豁免条件**两个都满足**才放行：
1. 「最X」后面紧跟的是可枚举的比较/程度词（不同、区别、差异、重要、关键、主要、合适、保险…）；
2. 命中处**不在句首**（`。！？；：` 或换行之后算句首）。

所以：`这款产品和上一代最大的区别在于接口。` → 放过；
`最大的区别在于接口。` → **照拦**（句首的最高级宣称）。
被放过的每一处都会记进 `exempted` 并在报告里显示，**不静默放过**。

### 「第一」的序数豁免（本包新增，附实测理由）

同族原来的写法是 `第一(名|品牌|选择|名)?(?!次)`，只排除了「第一次」。
第一篇真实稿就被误判：**「第一年上了 3 部剧」**被判成"第一类排他性表述"。
长文里 `第一年 / 第一步 / 第一个 / 第一件事 / 第一批` 太常见了。

改法：**枚举序数后接词**——后接这些字的判为序数，不拦；
其余（`第一名` / `第一品牌` / `行业第一` / `销量第一。`）照拦：
`次年天步个条款批周月季轮种点部遍章节课集届期流层类句段行件桶手版稿封笔单场局盘组队线环圈代世阶时印梯`

## 二、闸门二：占位符残留（本地，确定性）

| 形态 | 说明 |
|---|---|
| `{}` / `{{标题}}` | 骨架被当正文写进去了 |
| `[待填]` `[待补充]` `（待定）` | 模型给自己留的空档 |
| `[略]` / `（此处省略）` | 模型懒得写，直接省略 |
| `XXX` / `xxx`（3 个以上） | 忘了替换的占位 |
| `待补充` / `待完善` / `TODO` / `TBD` | 内容没写完 |

**不误伤的写法**：`[1]`（引用序号）、`[图 2]`（配图位）是正常写法，
一刀切按括号内容判会把好文章全拦下。

## 三、闸门三：照抄提示词示例（`prompt_echo`，本地，确定性）

### 为什么要逐句比

长文正文 1000+ 字，而提示词里的跨主题示例只有十几个字。
把整段正文拿去算 Jaccard，分母被撑到 1000 多，相似度永远接近 0 ——
**模型把示例原样抄进某一段，这道闸门完全看不见**。
所以判定分两层：整段先比一次（只认 exact / jaccard），再**逐句**比一次（含覆盖度）。

### 三条判据（任一即命中）

| 判据 | 条件 |
|---|---|
| `exact` | 去标点归一化后**完全相同** |
| `jaccard` | 字符二元组 Jaccard ≥ **0.75** |
| `contain` | 示例的二元组**覆盖度 ≥ 0.60**（示例被夹带进更长的句子里） |

**为什么必须有第三条**：Jaccard 的分母是两份二元组的**并集**，产出越长，示例那一侧被摊薄得越狠。
实测：一条 17 字的示例原样嵌进去再补 7 个字（24 字）→ Jaccard 只有 0.696（旧判据放行），
而覆盖度是 1.000（新判据拦下）。覆盖度只看"示例被抄了多少"，不看产出有多长。

### 长度守卫是**相对阈值**

目标归一化长度 < `max(6, len(示例)//2)` 时就不比了（短串二元组太少，指标会虚高）。
**不用绝对阈值 12**：示例只有 15~17 字时，12 占了示例长度七成以上，
会把「≤11 字的截断照抄」整档放过。换成相对阈值后门槛变成 7~8，那一档收回来，
同时保留 6 的绝对下限防极短串噪声。

### 提示词里的跨主题示例

`PROMPT_SAMPLES` 里登记了两条**跨主题**示例（电动车充电桩，与本包任何真实选题都不搭）。
跨主题是故意的：模型不会主动抄过去；万一抄了，闸门兜住并让整份产出停下（退出码 3）。

## 四、闸门四：重写丢事实（本地，确定性 + 启发式）

口径见 `references/改稿方法.md` 第四节。要点：

- 数字是**确定性**检查；专有名词靠四类模式抓，**抓不全也可能多报**；
- 数字换了写法（`3` → `三`）**不算丢**；
- 行首列表序号与夹在拉丁词里的数字**不算事实**（都是踩过之后排除的）；
- 丢一条 → 标红 + 逐条列出（带原稿上下文）+ stderr 汇总 + 退出码 3；
- 已知误报（把「87%」合法改写成「接近九成」）可用 `--facts-warn-only` 降级。

**真机实测：11 / 11 保留，保全率 100%。**

## 五、`--outdir` 不许落在包内

写文件是**写操作**，写进去之前就拦住，不等打完卡再回滚。
`--outdir` 落在 `sanjianke-content-qc/` 里 → 退出码 **2**（用法错误，不是闸门判定，
也不是上游失败）。

原因很实际：Skill 包的上传白名单只收
`.md .py .txt .json .sh .js .yaml .yml .csv`，包内多一个别的后缀会让上传直接 400。
所以本包的产出全是 `.md` / `.json`，并且必须落在包外。

## 六、成本与预算

- **只出 token，不编金额**：文本模型网关不公布单价，`/api/v1/models` 里也没有价格字段。
  不给 `--price-in` / `--price-out` 时，`cost` 与所有产出里的金额字段都是 `null`，
  并附一句为什么。
- `--budget` 单位是**点**，而且**必须同时给单价** —— 否则退出码 2。
  拒绝"没有单价却假装在预算内"。
- 预算超限是**闸门**：在发起任何调用之前就停，退出码 5，一个字都不花。
- 字符 → token 的标定（**同族实测值，不是厂商文档**）：
  输入 1 token ≈ 1.61 字符；输出 1 字符 ≈ 1.11 token。**这是估算，不是账单。**
- 一次闭环的调用构成：基线单篇打分 1 次 + 每轮（改写 1 次 + 匿名双评 1 次）。
  **真机实测**：1203 字的稿、2 轮闭环 = **4~5 次调用、约 2 万 token**。
- 省钱的三个做法：`--baseline` 复用已有打分；`--rounds 0` 只体检；断点续跑
  （同一 `--outdir` 重跑只会打印"已完成，跳过"，0 次调用）。

## 七、退出码（可直接用于 CI）

| 码 | 含义 | 触发例子 |
|---|---|---|
| 0 | 达标：评分过线且没有硬闸门命中 | 收敛、事实保全、定稿五项闸门全过 |
| 2 | 用法/配置错误 | 文件不存在、平台名错、`--outdir` 在包内、`--budget` 没配单价、`--target > 100` |
| 3 | 硬闸门命中 | 违禁词 / 占位符 / 照抄示例 / 字数出区间 / 定位失败 / 丢事实 / **未收敛** |
| 4 | 调用失败 | 网络、鉴权（401）、点数不足（402）、模型名错（404） |

| 130 | 用户中断（Ctrl+C） | — |

## 八、排错

| 现象 | 原因与处置 |
|---|---|
| `没有找到 API Key` | 三种方式任选：`--key sk-xxx` / 环境变量 `A7W_API_KEY` / `python3 scripts/a7w.py login --key sk-xxx` 写进 `~/.a7w/config.json` |
| `鉴权失败（401）` | Key 无效或过期，去 https://api.a7w.cn/ 重新创建 |
| `点数不足（402）` | 账户点数不够，充值后重试 |
| `模型不存在（404）` | 用 `python3 run.py models` 现查在架模型名，别写死 |
| 上游 502/503/504 反复出现 | 脚本会自动退避重试 4 次；仍然失败就是网关侧问题，稍后重试 |
| `模型返回的不是合法 JSON` | 已用 `raw_decode` 扫第一个完整对象；仍失败说明模型确实没吐 JSON，换模型或加 `--no-json-mode` 观察原始输出 |
| `定位锚点` 闸门命中 | 模型在编引文。看 `unanchored_issues` 里被剔出的引文；偶发一次可以重跑，反复出现说明该模型不擅长引用原文，换模型 |
| `事实保全` 闸门命中 | 看报告里列出的"丢了哪个 + 原句上下文"。是真丢就重跑一轮或人工补；是合法改写（`87%` → 接近九成）就用 `--facts-warn-only` |
| 未收敛 | 报告里已写明差多少分。三条出路：加 `--rounds`、人工介入、或把 `--target` 调到这条稿子现实能达到的位置 |
| 分数看着"改了也没涨" | **先看口径**：单篇与双评不在同一把尺子上（实测差 11.5 分）。看 `scoring_scale` |
| 断点续跑没生效 | 断点 key 含稿件摘要、轮次、模型、平台、温度、目标线、`--baseline` 摘要、口径版本、提示词版本。**上述任何一项变了都会重跑**，这是故意的；要强制重跑用 `--force` |
| 输出中文乱码（Windows） | 脚本已把 stdout/stderr 重配成 UTF-8；若仍乱码，设 `$env:PYTHONIOENCODING="utf-8"` |
| `unrecognized arguments: --out` | 本包长选项**不允许前缀缩写**（故意的：`--out` 曾被静默吃成 `--outdir`，产出目录变成一个叫 `report.json` 的目录）。请写全 `--outdir` / `--out` |

## 九、三件写进代码的事故（都是真机踩出来的）

1. **单篇口径与双评口径差 11.5 分**（同一篇稿 81.5 vs 71.5/68.5）。
   现在两个口径的分都公示，`--target` 明确按哪个口径判定。
2. **改写照着 fix 把句子拉长，可读性从 9 掉到 7**。
   现在改写提示词第 6 条要求"明显变长就先拆成两句"。
3. **`--out` 被静默匹配成 `--outdir`**，产出目录变成一个 `.json` 目录且不报错。
   现在 `allow_abbrev=False`，`--out` 与 `--outdir` 严格区分。
