# 改稿方法（从"定位到句"到"真的改好"）

本文件讲三件事：怎么把一条句子级问题变成一次改写、怎么判断"改好了"还是"只换了说法"、
以及多轮迭代该怎么办。口径与阈值以 `references/质检维度与评分口径.md` 为准。

---

## 一、改写提示词里必须带的四样东西

`build_revise_prompt()` 一共喂四块，少一块都会出可预期的问题：

| 块 | 少了会怎样 |
|---|---|
| **稿件全文** | 模型只能凭清单猜上下文，改出来的句子跟前后文接不上 |
| **锚定过的问题清单**（带 `sent_no`、原句、问题、建议改法） | 会变成"重写一遍"，不是"按问题改" |
| **事实清单**（本地抽的数字与专有名词 + 原句上下文） | 数字被静默删掉（见第四节） |
| **目标平台字数区间 + 当前字数** | 改了问题却把字数带出区间，反而新增一条硬闸门 |

清单里的问题条数是**锚定成功的那些**；锚点没通过的一条都不进改写输入
（宁可不改，也不按一句假的引文去改）。

## 二、写进提示词的六条修改纪律（每条都有实测理由）

1. **只改清单点到的地方**，清单没点到的句子一个字都别动。
   - 理由：改写模型有"顺便润色一下"的强冲动。全篇重写会让台账从 5 处变成 40 处，
     评审没法逐条确认，等于把质检成本转嫁给审稿人。
   - 实测：`changed_ratio` 稳定在 0.12~0.36；逐轮只有 5~15 句被改动。
2. **事实清单逐条原样保留**，清单之外不许新增任何数字、案例、机构名、人名。
   - 理由：见第四节。
3. **不许改题材、不许换平台形态、不许重排结构骨架。**
   - 理由：这是"对成稿做质量迭代"，不是"重新创作"。想换平台形态用
     `sanjianke-multiplat-rewrite`；想从主题生成用 `sanjianke-longform-factory`。
4. **不许把清单编号、字段名、提示词词句写进正文**；不许输出代码围栏、不许留 `{}` 占位符。
   - 理由：这是模板污染，本地有专门的占位符闸门兜底。
5. **正文里不许出现绝对化用语。**
   - 理由：改写过程中模型很爱把"比较大"升级成"最大"，凭空制造合规问题。
6. **如果某条 fix 会让句子明显变长，先拆成两句**；中文单句尽量 60 字以内。
   - 理由（**真机实测踩到的**）：第一轮改写照着 fix 把句子拉长，
     可读性分从 9 掉到 7 —— 质量问题修好了，阅读体验反而变差。
     这条纪律是看着那次的评分轨迹加进去的，不是凭空写的。

## 三、"改好了"还是"只换了说法"：三个判据一起看

单看分数会被骗（评分与改写是同一个模型，存在自我偏好偏差）。
本包同时给三组证据，**三组一起看**：

### 判据 1：涨幅，而且必须是**同口径**的涨幅

- 同一次调用里的匿名双评给出"同轮原稿分"与"新稿分"，两者共享同一套上下文；
- 同一篇原稿在两次独立调用里分的极差约 **±3 分**（实测 71.5 / 68.5），
  所以**涨幅 ≤ 3 分不要当成改好了**；
- 跨口径的差（单篇 vs 双评，实测 11.5 分）不能当涨幅用。

### 判据 2：改动形态（`diff` 的逐句台账）

| 指标 | 含义 | 怎么读 |
|---|---|---|
| `replaced` / `inserted` / `deleted` | 替换 / 新增 / 删除 的句子数 | 只有 replaced 且全是高相似度 → 可疑 |
| `paraphrase_only` | 替换但相似度 ≥ **0.90** 的数量 | 占比高 = **只是换了说法** |
| `paraphrase_ratio` | 上者 / 替换总数 | 报告里直接给这个比例 |
| `body_sim` | 全文二元组 Jaccard | 单轮正常在 0.85~0.95；两轮累计 0.7 上下 |
| `changed_ratio` | 改动句数 / 原句数 | 低于 0.05 说明几乎没改，高于 0.5 说明改过头了 |

**真机实测（两轮闭环）**：

| 范围 | 改动句 | 替换 | 仅换词 | 仅换词占比 | body_sim |
|---|---|---|---|---|---|
| 第 2 轮（单轮） | 5 / 41 | 5 | 0 | 0% | 0.911 |
| 原稿 → 定稿（两轮累计） | 15 / 39 | 11 | 0 | 0% | 0.723 |

`paraphrase_only = 0` 意味着**没有一处改动是"只换了说法"**：
每一处替换的相似度都低于 0.90，即句子层面的信息结构真的变了。

### 判据 3：改动内容本身（台账的"原句 / 定稿 / 为什么"三列）

把实际改动读一遍，看它是**语义级**的还是**用词级**的。实测的 5 处改动：

| 原句 | 定稿 | 属于哪一类 |
|---|---|---|
| 这件事很麻烦，一条两小时的剧靠人眼拖时间轴，一集就要花半天，所以我们后来改成了机器转写。 | 这件事很麻烦，所以我们后来改成了机器转写。 | 删掉与前句重复的信息 |
| 这件事看起来小，但它是那种一旦搞混就要整批重做的坑。 | 这件事看起来小，但一旦账号之间混用音色，就要整批重做。 | 模糊指代 → 明确条件 |
| 在上面四件事之外，还有两个容易被忽略的前置条件，第一个就是素材授权。 | 除了上面四件事，还有两个前置条件必须在流程开始前确认，第一个是素材授权。 | 统一层级标记 |
| 第二个前置条件是数据复盘，它决定前面四件事往哪个方向调。 | 第二个前置条件是数据复盘，它决定上面四件事分别往哪个方向优化。 | 补回连与指向 |
| 这套流程跑下来，同样的两个人，一个月能稳定出 120 条左右。 | 同样的两个人，按每月 22 个工作日算，一个月能稳定交付 120 条通过质检的成片，这个数字不含被返工砍掉的片子。 | **补口径**：把"120 条"变成可验证的数字 |

全部是语义级改动，而且最后一条正是"信息密度"这一维要的东西。
**所以这次是"真的改善了"，不是"换了个说法"。**

## 四、事实保全：最容易发生、最难发现的损失

"AI 改稿"最隐蔽的失败形态不是文笔变差，是**原稿里的一个数字没了**。
语句更顺、分数更高，但报价/参数/结论数字被改掉——人眼在几千字里几乎发现不了。

### 机制

本地抽事实清单（`extract_facts`），两处使用：

1. **事前**：清单连同原句上下文一起进改写提示词，要求逐条保留（这是"修复"）；
2. **事后**：逐条核对定稿里还在不在（这是"闸门"）。

### 抽取规则（**诚实说明这是启发式**）

| 类别 | 规则 | 确定性 |
|---|---|---|
| 数字 | 所有阿拉伯数字串（含小数）；**排除**行首列表序号（`1.` `2、`）与夹在拉丁词里的数字（`A7W` 的 7） | 确定 |
| 书名/作品名 | `《…》` 内 2~24 字 | 高 |
| 引号短语 | `「…」` / `“…”` 内 2~20 字 | 中 |
| 英文专名 | 拉丁字母开头的 2~20 字符 token（`A7W`、`GPT-4`） | 高 |
| 机构/产品名 | `…公司 / 集团 / 大学 / 学院 / 研究院 / 实验室 / 基金 / 银行 / 医院 / 工作室 / 协会 / 出版社 / 电视台` | 中 |

**踩过的两个坑（都写进代码注释了）**：

1. 「平台 / 系统 / 模型 / 算法」这四个后缀**被删掉了**。第一次真机跑就把
   「我们也试过让模型」「原因不在模型」整段抓成了专名。这四个词在中文技术写作里太通用。
   假事实的危害不只是多一条：改稿把「模型」换成「大模型」就会被判"丢了专名"，
   台账一多报，人就不看台账了。
2. `A7W 商城` 会被抽出一个"事实 `7`"。改稿把 A7W 换成"某商城"就多报一条"丢了数字 7"。
   现在夹在拉丁 token 里的数字直接跳过。

### 数字的"换写法"不算丢

`87` → `八十七`、`3` → `三` 都算保留（本地有整数转中文的实现，覆盖 0~99999999），
会记进 `renumbered` 并在台账里显示 `87 → 八十七`，不报"丢"。

### 闸门与已知误报

| 条件 | 结果 |
|---|---|
| 有任何一条事实在定稿里找不到 | 标红 + 逐条列出（含原稿上下文）+ stderr 汇总 + 退出码 3 |
| `--facts-warn-only` | 降级为提示，退出码不变 |

**已知会误报**：把「87%」合法改写成「接近九成」——数字确实没了，但语义还在。
这种要人判断，所以给了 `--facts-warn-only`。但**默认仍然是硬闸门**：
宁可让人确认一次，也不放一条静默丢数字的稿子过去。

**真机实测**：两轮闭环后事实 **11 / 11 保留，保全率 100%**（事前把清单喂进去是有效的）。

## 五、台账（改动台账）怎么算，以及为什么不能只信模型

### 本地算，不听自报

台账的**实际改动**由本地 `difflib` 逐句对齐算出；模型自报的 `changes`
只用来补「为什么」那一栏。只信自报的后果很具体：模型经常漏报自己改过的句子，
那就不是"实际改了什么"，而是"它声称改了什么"。

### 替换块的配对按相似度贪心，不按下标硬配

**踩过的坑**：第一版在 `replace` 块里按下标配对，模型把一句话拆成两句之后，
台账里出现「还有一个坑是素材授权。」→「因为在每个环节省下来的时间，最后都会在返工里加倍还回去…」
这种完全不相干的一对。读的人会以为模型在乱改，其实是**配对配错了**。
改成按相似度贪心配对后，拆句如实显示成「替换 + 新增」。

### 自报与本地对不上时的三种归类

| 情形 | 归类 | 含义 |
|---|---|---|
| 自报的 `before` 锚点通过，且本地对齐里那一句确实改了 | 正常挂上 `why` | — |
| 自报的 `before` 锚点不通过，或那一句本地没改 | `phantom`（虚报） | 仅在**同一版底座**下才算虚报 |
| 自报清单针对的是**另一版稿子**（多轮闭环里最后一轮的自报是相对上一轮版本的） | `foreign`（中间版本） | **不计为虚报** |

第三条是**踩过之后加的**：`diff --before 最初原稿 --from all.json` 时，
all.json 里的自报改动是相对**倒数第二轮版本**的，锚不到最初原稿上。
第一版把 4 条真实改动全打成了「模型声称改了、本地却没有」—— 给模型扣了莫须有的帽子，
读的人会不信任整张表。现在会核对 `changes_base_sha`，不一样就走 `foreign` 并如实说明。

### 真机实测（第 2 轮，自报底座一致）

| 指标 | 值 |
|---|---|
| 改动句 / 总句 | 5 / 41 |
| phantom / foreign / unexplained | **0 / 0 / 0** |
| 模型自报的改动数 | 5（与本地对齐完全一致） |

5 处改动全部带「为什么」，且理由里明确引用了清单条目（"按清单第 1 条…"）。
两轮累计视角下 `unexplained = 14`（模型只自报了最后一轮），这是正常的，
如实显示比假装全覆盖要好。

## 六、多轮迭代怎么办

- **默认 2 轮**。实测第 1 轮涨 8.0 分、第 2 轮再涨 7.0 分（71.5 → 79.5 → 86.5）。
- **迭代不是单调的**：第 1 轮把可读性从 9 压到 7，第 2 轮才回到 8。
  所以**不要只看总分**，要看每一维的走向（`trajectory[].dims`），
  某一维连续两轮下滑就该人工介入了。
- **已经达标就别再改**：基线分已达 `--target` 时循环**不发起任何改写调用**，
  并如实写明"原稿已达目标线，未发起改写"。
- **批量质检省钱的办法**：先 `score` 一次并落盘，之后用
  `--baseline score.json` 复用基线（会核对稿件摘要，摘要不一致直接拒绝复用，退出码 2）。
- **`--rounds 0`** 是"只出体检报告不动刀"：只用单篇口径的基线分判定，零改写成本。

---

## 七、`--target` 怎么定

1. 先 `score` 一篇你自己认为**已经达到发布标准**的稿子，看它拿多少分；
2. 把 `--target` 定在那个分数附近（±3 分，因为噪声就是这么大）；
3. 注意 `--target` 是按**双评口径**判定的：如果你是按 `score` 的单篇分定的线，
   记得单篇分通常比双评高（本次实测高 11.5 分），线要相应下调，
   或者干脆 `--rounds 0` 只用单篇口径。
