# 三剪客 · 内容质量闭环

> ## ⚠️ 先申请你自己的 API Key
>
> **本 Skill 不内嵌任何密钥，也不代付费用。** 请到
> **[算力集市 api.a7w.cn](https://api.a7w.cn/)** 注册并创建**你自己的** API Key
> （新用户有赠送点数，可以先免费试跑几条）。
>
> 拿到后填进环境变量 `A7W_API_KEY`，或直接传给 `--key` 参数。
> **请勿使用他人提供的 Key** —— 用量与费用都记在 Key 所属账号上。

## 能做什么

给一篇**别人已经写完的成稿**（不是从主题生成），跑完整的改稿闭环：

```
score  → 五维打分 + 定位到句子的修改建议
revise → 按建议重写，每轮复评
diff   → 原稿 vs 定稿的逐句改动台账（纯本地，零成本）
```

它替代的是审稿环节最耗人的那一步：不是"看不出问题"，而是
**"看出来了，但说不清改哪一句、改完到底有没有变好"**。

| 你最关心 | 答案 |
|---|---|
| 什么是"定位到句子" | 每条问题必须带原稿里**原样的一句引文**；本地会校验这句引文在原稿里找不找得到，编造的直接剔出 |
| 会不会只给泛泛建议 | 会，但会被拦下：未锚定率 > 40% 判「定位失败」，压分 + 标红 + 退出码 3 |
| 改了怎么知道真的好了 | 同一次调用里**匿名双评**原稿与新稿（乱序、只给编号），涨幅不受跨调用漂移影响；再配逐句台账看是不是"只换了说法" |
| 会不会把数字改没了 | 原稿事实（数字 + 专有名词）先抽成清单喂进改写提示词，改完逐条核对；丢一条就报（实测 11/11 保留） |
| 多少钱 | 按 token 计费。实测：1200 字稿跑 2 轮闭环 = 4~5 次调用、约 2 万 token |
| 要装什么 | **什么都不用装**。只用 Python 标准库，不需要 pip install 任何东西 |
| 跟同类包什么关系 | 本包**不改题材、不换平台形态、不重排结构**，只做质量迭代；换平台形态用一稿多平台改写，从主题写长文用长文生产 |

### 四道本地硬闸门（都是确定性的，跑两次结果一样，可直接进 CI）

1. **广告法违禁词** —— 内置正则表 + 「最X」可枚举上下文豁免（句首不豁免）+ 「第一」序数豁免
2. **占位符残留** —— `{}` / `[待填]` / `XXX` / `（此处省略）`
3. **照抄提示词示例** —— 三条判据（去标点相同 / Jaccard ≥ 0.75 / 覆盖度 ≥ 0.60）+ 相对长度守卫
4. **重写丢事实** —— 原稿里的数字与专有名词必须仍在定稿里，丢了就逐条列出

命中一律：**压分 + 标红 + stderr 汇总 + 退出码 3**。

## 怎么用（命令行）

### 第 0 步：获取 API Key

到 **[api.a7w.cn](https://api.a7w.cn/)** 注册，创建一个 API Key（形如 `sk-...`）。

### 第 1 步：装依赖

**零依赖。** 只要机器上有 Python 3.7+：

```bash
python3 --version
```

包里自带的 `scripts/a7w.py` 是零依赖客户端（只用 `urllib` / `json` / `mimetypes`），
`scripts/run.py` 也只用标准库。

### 第 2 步：填 Key

```bash
# Linux / macOS
export A7W_API_KEY=sk-你的key

# Windows PowerShell
$env:A7W_API_KEY="sk-你的key"
```

也可以存进配置文件反复用（推荐）：

```bash
python3 scripts/a7w.py login --key sk-你的key
```

### 第 3 步：先做零成本自检（不联网、不花点数）

```bash
# 本地规则自检：违禁词 / 占位符 / 照抄示例 / 字数 / 结构 / 事实清单
python3 scripts/run.py rules --file 稿子.md --platform wechat

# 报价：这次闭环大概花多少 token（金额要你自己填单价）
python3 scripts/run.py cost --file 稿子.md --rounds 2
```

### 第 4 步：跑第一个例子

```bash
# 1) 单篇质检打分 + 定位到句的问题清单
python3 scripts/run.py score --file 稿子.md --platform wechat --json --out score.json

# 2) 完整闭环：评分 → 重写 → 复评，直到达标或轮次用尽
python3 scripts/run.py all --file 稿子.md --platform wechat \
    --rounds 2 --target 85 --baseline score.json \
    --outdir /tmp/content-qc-out --json --out /tmp/content-qc-out/all.json
```

`--outdir` 里会落 5 个文件：`final.md`（定稿）、`final.json`、
`ledger.json`（逐句台账）、`REPORT.md`（总报告：评分轨迹 + 台账 + 闸门 + 事实）、
`state.json`（断点）。**同一个 `--outdir` 重跑只会打印"已完成，跳过"，0 次调用。**

### 完整工作流

```bash
# 1) 零成本自检，先看这篇稿子有没有硬伤
python3 scripts/run.py rules --file 稿子.md

# 2) 出体检报告（1 次调用），落盘以便复用
python3 scripts/run.py score --file 稿子.md --platform wechat --json --out score.json

# 3) 闭环改稿（复用基线，省掉第 2 步那次调用）
python3 scripts/run.py all --file 稿子.md --platform wechat \
    --rounds 2 --target 85 --baseline score.json \
    --outdir /tmp/qc --json --out /tmp/qc/all.json

# 4) 逐句改动台账（纯本地，零成本）—— 带 --from 才能补上每处改动的「为什么」
python3 scripts/run.py diff --before 稿子.md --after /tmp/qc/final.md \
    --from /tmp/qc/all.json

# 5) 只用体检口径、不动刀（零改写成本）
python3 scripts/run.py all --file 稿子.md --rounds 0 --target 85
```

## 参数说明

### 全局

| 参数 | 说明 |
|---|---|
| `--json` | 以 JSON 输出；**写在子命令前后都可以**。成功时结果里带 `"ok": true`，失败时 stdout 只有一个失败信封 |
| `--key` | 临时指定 API Key（也可用 `A7W_API_KEY` 或 `~/.a7w/config.json`） |
| `--dry-run` | 只打印将发送的提示词，**不调模型、不花钱** |
| `--out` | 把结果写到文件 |

### 稿件输入与平台（`score` / `revise` / `all` / `rules` / `cost` 共用）

| 参数 | 说明 |
|---|---|
| `--file` | 待质检的稿件（`.md` / `.txt`，UTF-8，自动去 BOM） |
| `--platform` | `generic`（默认，只查通用发布形态）/ `wechat` / `xiaohongshu` / `douyin` / `zhihu` / `toutiao`。**指定平台会启用该平台的字数区间与结构口径** |

### `score` —— 多维打分 + 定位到句子的建议

| 参数 | 说明 |
|---|---|
| `--baseline` | 复用一份已有的 `score --json --out` 结果（零成本）。会核对稿件摘要与平台口径，**不一致直接拒绝复用**（退出码 2） |
| `--price-in` / `--price-out` / `--budget` | 见「成本与预算」 |

### `revise` —— 按建议重写

| 参数 | 说明 |
|---|---|
| `--rounds` | 最多迭代几轮（评分 → 重写 → 复评算一轮），默认 2 |
| `--target` | 目标线（加权总分 0~100），默认 85。**> 100 直接退出码 2** |
| `--baseline` | 复用已有打分当基线 |
| `--facts-warn-only` | 把「丢事实」从硬闸门降级为提示（**已知会误报**，默认仍是硬闸门） |

### `all` —— 完整闭环（带断点续跑）

除上面的迭代参数外：

| 参数 | 说明 |
|---|---|
| `--outdir` | 目录产物落这里，**必须在包外**；落在包内退出码 2。默认 `%TEMP%/content-qc-out` |
| `--force` | 忽略断点文件从头重跑（key 没命中就会重新花钱） |

### `diff` —— 逐句改动台账（纯本地零成本）

| 参数 | 说明 |
|---|---|
| `--before` / `--after` | 原稿 / 定稿 |
| `--from` | 可选：`revise` / `all` 的 `--json --out` 结果，用来补上每处改动的「为什么」。会核对自报清单针对的是哪一版稿子，**对不上就归入「中间版本」而不是判为虚报** |

### `rules` —— 本地规则自检（零成本）

查五件事：违禁词（硬）、占位符（硬）、照抄示例（硬）、字数区间（硬）、结构（**软提示，不拦**）。
另外把抽到的事实清单打出来 —— 那就是会进改写提示词的那份。

**为什么结构不拦**：审的是别人写好的成稿，「结尾没有 CTA」在不少稿子上是合理选择，
当硬闸门会天天误报，而误报会让人把整个闸门关掉。

### `cost` —— 报价

| 参数 | 说明 |
|---|---|
| `--file` / `--text` | 按稿件或直接文本估 |
| `--rounds` | 按几轮估，默认 2 |
| `--price-in` / `--price-out` | 单价，单位「点 / 百万 token」。**不给我就不给金额（不编价）** |
| `--budget` | 预算上限（点），超了退出码 5；**用 `--budget` 必须给单价**，否则退出码 2 |

### `models` —— 列出在架模型（免费）

```bash
python3 scripts/run.py models
```

模型名会变，以现查为准。`deepseek-chat` 这个别名实测可用（路由到 `deepseek-flash`），
但它**不在** `/api/v1/models` 的返回列表里 —— 「列表里没有」不等于「不能用」。

### 五维评分与权重

| 维度 | 权重 | 这个分在问什么 |
|---|---|---|
| 信息密度 | 0.25 | 单位字数里有多少可验证的具体信息 |
| 结构 | 0.20 | 有没有「开头给处境 → 中间拆解 → 结尾给结论/行动」的推进 |
| 可读性 | 0.20 | 句子长短、指代是否明确、有没有要读两遍的句子 |
| 合规 | 0.15 | 有无绝对化用语、无依据承诺、站外导流、敏感宣称 |
| 平台适配 | 0.20 | 字数、分段、语气、结尾引导是否符合目标平台 |

加权总分 = Σ(维度分 × 权重) × 10，落在 0~100。口径细节见
`references/质检维度与评分口径.md`。

### 两种评分口径（**别跨尺子比**）

| 口径 | 用在哪 |
|---|---|
| 单篇 `single` | `score`；闭环的第 0 轮基线 |
| 双评 `pair` | 闭环的第 1 轮起，同一次调用里给原稿与新稿各打一次 |

真机实测：同一篇稿，单篇口径 **81.5** 分，双评口径 **71.5 / 68.5** 分 —— **差 11.5 分**。
所以 `--target` 按**双评口径**判定，结果里的 `scoring_scale` 会把两种口径的分
和口径差都公示出来。口径差 ≥ 5 分时 stderr 还会提示一遍。

### 退出码（可直接用于 CI）

| 码 | 含义 |
|---|---|
| 0 | 达标：评分过线且没有硬闸门命中 |
| 2 | 用法/配置错误（文件不存在、平台名错、`--outdir` 在包内、`--budget` 没配单价、`--target > 100`） |
| 3 | 硬闸门命中（违禁词 / 占位符 / 照抄示例 / 字数出区间 / **定位失败** / **丢事实** / **未收敛**） |
| 4 | 调用失败（网络 / 鉴权 401 / 点数 402 / 模型名 404） |
| 5 | 预算超限，已就地中止（**未发起任何调用**） |
| 130 | 用户中断 |

### 成本与预算

- **只出 token，不编金额**：文本模型网关不公布单价，`/api/v1/models` 里也没有价格字段。
- 字符 → token 标定（同族实测值）：输入 1 token ≈ 1.61 字符；输出 1 字符 ≈ 1.11 token。**这是估算，不是账单。**
- 真机实测：1200 字稿、2 轮闭环 = 4~5 次调用、约 2 万 token。

## 排错

| 现象 | 处置 |
|---|---|
| `没有找到 API Key` | `--key` / `A7W_API_KEY` / `a7w.py login` 三选一 |
| `鉴权失败（401）`／`点数不足（402）` | 到 https://api.a7w.cn/ 重新创建 Key 或充值 |
| `模型不存在（404）` | `run.py models` 现查在架名，别写死 |
| 上游 502/503/504 | 脚本自动退避重试 4 次；仍失败是网关侧问题 |
| `定位锚点` 闸门命中 | 模型在编引文。看 `unanchored_issues` 里被剔出的引文；反复出现说明该模型不擅长引用原文，换模型 |
| `事实保全` 闸门命中 | 看报告里「丢了哪个 + 原句上下文」。真丢就重跑或人工补；合法改写用 `--facts-warn-only` |
| 未收敛 | 报告里写明差多少分。加 `--rounds`、人工介入、或把 `--target` 调到现实位置 |
| 分数看着"改了也没涨" | **先看口径**：单篇与双评不在同一把尺子上（实测差 11.5 分），看 `scoring_scale` 那一块 |
| 断点续跑没生效 | key 含稿件摘要、轮次、模型、平台、温度、目标线、基线摘要、口径版本、提示词版本；任一变化都会重跑（故意的）。要强跑用 `--force` |
| `unrecognized arguments: --out` | 本包**不允许长选项前缀缩写**（故意的：`--out` 曾被静默吃成 `--outdir`）。请写全 |

更多排错见 `references/合规与排错.md`。
