# 三剪客 · 内容质量闭环

给一篇**成稿**跑「生成 → 自评 → 重写 → 定稿」的闭环：多维打分 → **定位到句子**的修改建议
→ 按建议重写 → 复评 → 直到达标或轮次用尽 → 出定稿、逐句改动台账与评分轨迹。

> 本包**不是**从主题生成文章，也**不是**把一稿改写成多平台形态。
> 它审的是**别人已经写完的稿**，只做质量迭代。换平台形态用「一稿多平台改写」，
> 从主题写长文用「长文生产」。

---

## 能做什么

| 子命令 | 干什么 | 花不花钱 |
|---|---|---|
| `score` | 五维打分 + 定位到具体句子的修改建议 | 1 次调用 |
| `revise` | 按建议重写，`--rounds` 控制轮数，每轮复评 | 每轮 2 次调用 |
| `diff` | 原稿 vs 定稿的**逐句改动台账** | **纯本地，零成本** |
| `rules` | 本地规则自检：违禁词 / 占位符 / 字数 / 结构 | **纯本地，零成本** |
| `all` | 完整闭环：评分 → 重写 → 复评，**断点续跑** | 见下 |
| `cost` | 报价：这次闭环大概要花多少 token | **零成本** |
| `models` | 列出 api.a7w.cn 当前在架的模型 | **零成本** |

### 它替代的是审稿环节最耗人的那一步

不是"看不出问题"，而是**"看出来了，但说不清改哪一句、改完到底有没有变好"**。

- **定位到句子**：每条问题必须带原稿里**原样的一句引文**；
  本地会校验这句引文在原稿里找不找得到，编造的直接剔出改写输入。
  真机实测 11 条问题**全部锚定成功**，未锚定率 0%。
- **改完真的好了吗**：同一次调用里**匿名双评**原稿与新稿（乱序、只给编号），
  涨幅不受跨调用评分漂移影响；再配逐句台账看是不是"只换了说法"。
- **数字别被改没**：原稿的事实（数字 + 专有名词）先抽成清单喂进改写提示词，
  改完逐条核对。真机实测 **11 / 11 保留**。

## 怎么用（命令行）

### 1) 到 https://api.a7w.cn/ 注册领 Key

```bash
# Linux / macOS
export A7W_API_KEY=sk-你的key
# Windows PowerShell
$env:A7W_API_KEY="sk-你的key"
```

也可以写进配置文件反复用：`python3 scripts/a7w.py login --key sk-你的key`

### 2) 零依赖，不需要 pip install 任何东西，只要 Python 3.7+

```bash
python3 --version
```

`scripts/a7w.py` 与 `scripts/run.py` 都只用标准库（`urllib` / `json` / `difflib` / `hashlib` …）。

### 3) 先做零成本自检（不联网）

```bash
python3 scripts/run.py rules --file 稿子.md --platform wechat
python3 scripts/run.py cost  --file 稿子.md --rounds 2
```

`rules` 会打出四道本地闸门的结论、结构建议，以及**会被带进改写提示词的事实清单**。

### 4) 出体检报告 → 闭环改稿 → 看台账

```bash
# 单篇质检（1 次调用），落盘以便复用
python3 scripts/run.py score --file 稿子.md --platform wechat --json --out score.json

# 闭环：复用基线，最多 2 轮，目标线 85
python3 scripts/run.py all --file 稿子.md --platform wechat \
    --rounds 2 --target 85 --baseline score.json --outdir /tmp/qc

# 逐句改动台账（纯本地零成本）
python3 scripts/run.py diff --before 稿子.md --after /tmp/qc/final.md
```

`--outdir` 里落 5 个文件：`final.md` / `final.json` / `ledger.json` /
`REPORT.md`（评分轨迹 + 台账 + 闸门 + 事实）/ `state.json`（断点）。

**同一个 `--outdir` 重跑，只会打印「已完成，跳过」，0 次调用。**

### 真实运行长什么样

1203 字的公众号稿，`--rounds 2 --target 85`：

| 轮次 | 口径 | 加权总分 | 信息密度 | 结构 | 可读性 | 合规 | 平台适配 | 同轮原稿 | 涨幅 |
|---|---|---|---|---|---|---|---|---|---|
| 第 0 轮（原稿） | 单篇 | 81.5 | 8 | 8 | 9 | 9 | 7 | — | — |
| 第 1 轮（新稿） | 双评 | 79.5 | 8 | 8 | 7 | 9 | 8 | 71.5 | +8.0 |
| 第 2 轮（新稿） | 双评 | **86.5** | 9 | 9 | 8 | 8 | 9 | 68.5 | **+18.0** |

- 台账：第 2 轮改动 5 句 / 共 41 句，**仅换词 0 处**（占替换 0%），整体相似度 0.911
- 两轮累计：改动 15 句 / 39 句，整体相似度 0.723，**仅换词 0 处**
- 事实保全：**11 / 11**，保全率 100%
- 定稿五项闸门全过 → 已收敛，退出码 0

**这是"真的改善了"还是"只换了说法"？** 看实际改了什么：
删掉与前句重复的半天耗时、把「那种……的坑」换成明确条件、
把「120 条」补上口径（按 22 个工作日算、不含返工）。
全部是语义级改动，`paraphrase_only = 0`。

**但要诚实说明**：评分与改写是同一个模型，存在自我偏好偏差；匿名与乱序只能削弱、不能消除。
而且第 1 轮把可读性从 9 压到 7（改写把句子拉长了），第 2 轮才回到 8 ——
**迭代不是单调的**，所以报告里逐维给数，不只给一个总分。

## 参数说明

### 全局

| 参数 | 说明 |
|---|---|
| `--json` | JSON 输出，**写在子命令前后都可以**；成功带 `"ok": true`，失败 stdout 只有一个失败信封 |
| `--key` | 临时指定 Key（也可用 `A7W_API_KEY` / `~/.a7w/config.json`） |
| `--dry-run` | 只打印将发送的提示词，**不调模型不花钱** |
| `--out` | 把结果写到文件 |

### 稿件与平台（`score` / `revise` / `all` / `rules` / `cost` 共用）

| 参数 | 说明 |
|---|---|
| `--file` | 待质检稿件（`.md` / `.txt`，UTF-8，自动去 BOM） |
| `--platform` | `generic`（默认）/ `wechat` / `xiaohongshu` / `douyin` / `zhihu` / `toutiao` |

`generic` 的字数区间放得很宽，只查通用发布形态；**指定平台才会启用该平台的字数区间与结构口径**。

### 迭代参数（`revise` / `all`）

| 参数 | 说明 |
|---|---|
| `--rounds` | 最多几轮（评分 → 重写 → 复评算一轮），默认 2 |
| `--target` | 目标线（0~100），默认 85。**> 100 直接退出码 2** |
| `--baseline` | 复用已有 `score --json --out` 结果当基线（省一次调用）。会核对稿件摘要与平台口径，**不一致直接拒绝复用** |
| `--facts-warn-only` | 把「丢事实」从硬闸门降级为提示（**已知会误报**，默认仍是硬闸门） |
| `--outdir` | 目录产物落这里，**必须在包外**（落在包内退出码 2） |
| `--force` | 忽略断点从头重跑 |

### 打分与报价

| 子命令 | 参数 |
|---|---|
| `score` | `--baseline`（零成本复用） |
| `cost` | `--file` / `--text` / `--rounds` / `--price-in` / `--price-out` / `--budget` |
| `diff` | `--before` / `--after` / `--from`（补上每处改动的「为什么」） |

### 成本与预算

- **只出 token，不编金额**：文本模型网关不公布单价，`/api/v1/models` 里也没有价格字段。
  不给 `--price-in` / `--price-out`，金额字段就是 `null` 并附上原因。
- `--budget` 单位是**点**，且**必须同时给单价** —— 否则退出码 2（不假装在预算内）。
- 字符 → token 标定（同族实测值，不是厂商文档）：输入 1 token ≈ 1.61 字符；
  输出 1 字符 ≈ 1.11 token。**这是估算，不是账单。**
- 真机实测：1200 字稿、2 轮闭环 = 4~5 次调用、约 2 万 token。

### 退出码（可直接用于 CI）

| 码 | 含义 |
|---|---|
| 0 | 达标 |
| 2 | 用法/配置错误（含 `--outdir` 在包内、`--budget` 没配单价、`--target > 100`） |
| 3 | 硬闸门命中（违禁词 / 占位符 / 照抄示例 / 字数出区间 / 定位失败 / 丢事实 / 未收敛） |
| 4 | 调用失败（网络 / 401 / 402 / 404） |
| 5 | 预算超限，已就地中止（未发起任何调用） |
| 130 | 用户中断 |

### 五维评分与权重

| 维度 | 权重 | 这个分在问什么 |
|---|---|---|
| 信息密度 | 0.25 | 单位字数里有多少可验证的具体信息 |
| 结构 | 0.20 | 有没有「开头给处境 → 中间拆解 → 结尾给结论/行动」的推进 |
| 可读性 | 0.20 | 句子长短、指代是否明确、有没有要读两遍的句子 |
| 合规 | 0.15 | 有无绝对化用语、无依据承诺、站外导流、敏感宣称 |
| 平台适配 | 0.20 | 字数、分段、语气、结尾引导是否符合目标平台 |

加权总分 = Σ(维度分 × 权重) × 10。合规权重最低，但命中违禁词时**由本地把上限压死**
（高 1 / 中 4 / 低 7），模型给多高都不算。

### 两种评分口径（**别跨尺子比**）

| 口径 | 用在哪 |
|---|---|
| 单篇 `single` | `score`；闭环第 0 轮基线 |
| 双评 `pair` | 闭环第 1 轮起，同一次调用里给原稿与新稿各打一次 |

真机实测：同一篇稿，单篇 **81.5**，双评 **71.5 / 68.5** —— **差 11.5 分**。
结果里的 `scoring_scale` 会把两种口径的分与口径差都公示，`--target` 按双评口径判定。
同一篇原稿两次双评的极差约 ±3 分，**涨幅 ≤ 3 分不要当成改好了**。

## 排错

| 现象 | 处置 |
|---|---|
| `没有找到 API Key` | `--key` / `A7W_API_KEY` / `a7w.py login` 三选一 |
| `鉴权失败（401）` | Key 无效或过期，到 https://api.a7w.cn/ 重建 |
| `点数不足（402）` | 充值后重试 |
| `模型不存在（404）` | `run.py models` 现查在架名，别写死 |
| 上游 502/503/504 | 自动退避重试 4 次；仍失败是网关侧问题 |
| `模型返回的不是合法 JSON` | 已用 `raw_decode` 扫第一个完整对象；仍失败换模型 |
| **定位锚点**闸门命中 | 模型在编引文。看 `unanchored_issues`；反复出现说明该模型不擅长引用原文，换模型 |
| **事实保全**闸门命中 | 看报告里「丢了哪个 + 原句上下文」。真丢就重跑或人工补；合法改写用 `--facts-warn-only` |
| **未收敛** | 报告写明差多少分。加 `--rounds`、人工介入、或把 `--target` 调到现实位置 |
| 分数看着"改了也没涨" | **先看口径**：单篇与双评不是同一把尺子（差 11.5 分），看 `scoring_scale` |
| 断点续跑没生效 | key 含稿件摘要、轮次、模型、平台、温度、目标线、基线摘要、口径版本、提示词版本；任一变化都会重跑（故意的）。要强跑用 `--force` |
| `unrecognized arguments: --out` | 本包**不允许长选项前缀缩写**（故意的：`--out` 曾被静默吃成 `--outdir`）。请写全 |
| 中文乱码（Windows） | 脚本已把 stdout/stderr 重配 UTF-8；仍乱码就设 `$env:PYTHONIOENCODING="utf-8"` |

### 三件写进代码的事故（都是真机踩出来的）

1. **单篇口径与双评口径差 11.5 分** → 现在两个口径的分都公示，`--target` 明确按哪个口径判定。
2. **改写照着 fix 把句子拉长，可读性从 9 掉到 7** → 改写提示词现在要求"明显变长就先拆成两句"。
3. **`--out` 被静默匹配成 `--outdir`**，产出目录变成一个 `.json` 目录且不报错 →
   现在 `allow_abbrev=False`，两个参数严格区分。
