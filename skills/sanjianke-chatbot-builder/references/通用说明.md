# 平台通用说明：鉴权、入口、计费、错误码

这份文档是给**多平台聊天机器人接大模型**这个场景兜底用的。

机器人接大模型和普通应用接大模型，有三个地方不一样，决定了你排错时该往哪看：

- **Key 在服务端，不在客户端。** 机器人跑在你的服务器 / 容器 / 树莓派上，环境变量注入失败是最高频的 401 来源 —— 本地 `export` 成功了，但 systemd 或容器里的进程根本没拿到。
- **一次群消息可能触发多次调用。** 同一个群里并发、重投、重试都会放大调用次数，所以并发控制和幂等不是「优化」，是必需品。
- **报错不能直接抛给用户。** 机器人不能在群里贴一行 `HTTPError 402`，所有异常都得转成一句人话。

除这三点之外，鉴权、计费、错误码这些共性事实和别的场景完全一样。以下是对照表。

## 一、鉴权

所有接口共用同一套鉴权：

```
Authorization: Bearer <你自己的 API Key>
Content-Type: application/json
```

要点：

- Key 形如 `sk-...`，在 [算力集市](https://api.a7w.cn/) 用户中心创建。
- **`Bearer ` 后面有一个空格**，掉了就是 401。
- Key 读取顺序（包内脚本）：`--key` 参数 → 环境变量 `A7W_API_KEY` → `~/.a7w/config.json`。
- **机器人进程必须自己能读到这个环境变量。** 本机 shell 里 `export` 成功 ≠ 机器人进程能读到：systemd 要写 `Environment=`，Docker 要写 `environment:` 或 `--env`，Windows 服务要写服务级环境变量。**这是机器人 401 的第一嫌疑人。**
- **每个机器人一把独立 Key**，各自设 quota。某个机器人跑飞了，损失有上限，也不影响其他机器人。
- **Key 等同于余额。** 不要写进代码、不要提交进版本库、不要放前端、不要贴在群里。

## 二、两条调用入口

| 入口 | 路径 | 形态 | 机器人用来做什么 |
|---|---|---|---|
| **模型网关**（OpenAI 兼容） | `POST /api/v1/chat/completions` | 同步，直接返回 `choices` | 回话、总结、翻译、分类、改写 |
| **应用任务** | `POST /api/v1/apps/<应用代号>/<接口代号>` | 多为异步，返回 `task_id` | 发图、发语音、转写群里的语音、解析文件 |

对照记忆：

- **模型网关没有 `task_id`。**
- **应用任务不吃 `messages` 数组。**
- 应用任务的路径**永远**是 `/api/v1/apps/<应用代号>/<接口代号>`，两个代号都取自线上返回的 `code` 字段。**绝对不要用 `endpoint_path` 字段拼 URL** —— 有些应用那个字段指的是内部另一套路由，照抄拼出来的地址打不通。
- 应用代号用**下划线**（`voice_tts`），不是连字符（`voice-tts` 会 404）。

### 地址层数：`/api/v1` 还是 `/api`

同一个平台两种填法都对，区别只在**你用的框架或客户端会不会自己补 `/v1`**：

| 你的示例 / 表单长什么样 | 填什么 |
|---|---|
| 示例里带 `/v1`（如 `.../v1/chat/completions`），或表单标题是 Base URL | `https://api.a7w.cn/api/v1` |
| 示例里不带 `/v1`，或表单标题是 API Host / 服务器地址 | `https://api.a7w.cn/api` |

**判断方法只有这一条**：看它给的示例。填错的典型症状是请求打到 `/api/v1/v1/...` 而返回 404。

### 平台端点速查

| 用途 | 方法与路径 |
|---|---|
| 模型清单 | `GET /api/v1/models` |
| 对话 | `POST /api/v1/chat/completions` |
| 应用清单 | `GET /api/v1/apps` |
| 单应用 schema | `GET /api/v1/apps/<应用代号>` |
| 应用调用 | `POST /api/v1/apps/<应用代号>/<接口代号>` |
| 任务查询（免费） | `GET /api/v1/tasks/<task_id>` |
| 任务列表 | `GET /api/v1/tasks` |
| 余额 | `GET /api/v1/user/balance` → `{"available_points":..., "currency":"points"}` |

> **业务成功码是 `code == 1`**（`{"code":1,"msg":"success"}`）；`code == 0` 是失败，**但 HTTP 仍可能是 200**。机器人写健康检查时一定要看 `code`，不要只看 HTTP 状态码。

## 三、计费口径

### 3.1 点数

- **1 元 = 100 点，1 点 = 0.01 元。**
- **点数永久有效**，不按月清零。
- **先冻结、后结算**：消费优先扣会员点数，不足再扣充值额度。
- **调用失败直接退款；异步任务失败，冻结点数全额退回。**
- 充值：体验包 ¥10 = 600 点（含 7 天会员权益）；标准包 ¥99 = 10000 点。
- **查询任务状态免费。**

### 3.2 按能力分类的计量单位

| 能力类型 | 计费口径 |
|---|---|
| 文本大模型 | **点数 / 百万 tokens**（输入输出分别计价；流式与非流式同价） |
| 图像生成 / 编辑 | **点数 / 张**，或按分辨率档位 |
| 视频生成 / 超分 | **点数 / 秒**（分辨率分档） |
| 数字人 / 对口型 | **点数 / 次或时长** |
| 语音 TTS / 音色克隆 | **点数 / 千字** |
| 语音识别 ASR | **点数 / 分钟** |
| 工具类（水印消除等） | **点数 / 次** |

机器人最常用的是前两类和第四、五类：**文字回话按 token，发图按张，发语音按千字，转写群语音按分钟。**

### 3.3 两套价格字段（最容易算错的地方）

| 字段 | 含义 | 用途 |
|---|---|---|
| `fixed_price` / `input_price` | **公示标准价** | 对外展示、横向比价 |
| `tenant_fixed_points` / `tenant_points_per_1k_input` / `tenant_points_per_1k_output` | **你所在租户的实际结算价** | **做预算只能用它** |

> **两者可能差很多。任何按公示价做的预算都可能错一个数量级。**
>
> **做预算一律读 `tenant_*`，最终以账号里实际扣费为准。**

### 3.4 实测消耗参考

| 场景 | 消耗 |
|---|---|
| `DeepSeek-V4-Flash` 一次普通问答 | 约 **0.74 ~ 0.99 点** |
| 极小调用（`max_tokens=8`） | **0.00 点** |
| 查询任务状态 | **免费** |

### 3.5 机器人控成本四招

| 招 | 做法 | 省在哪 |
|---|---|---|
| **压 `max_tokens`** | 闲聊 256、总结 1024 | 输出 token 是主要成本 |
| **精简 system prompt** | 人设别写小作文 | 系统提示每次都随请求计费 |
| **长对话做摘要** | 只带最近 6 轮，超长会话用摘要替代早期原文 | 输入 token 不随轮数爆炸 |
| **给每个群设配额** | 每群每日点数上限，超了回一句「明天再聊」 | 防止单个群刷爆预算 |

> **机器人特有的成本风险**：群消息一多，调用量是**非线性增长**的。一次「@机器人」可能触发一次调用，但群里的重投、重试、上下文膨胀都会成倍放大。**上线第一个星期，每天看一次 `GET /api/v1/tasks`。**

## 四、错误码全表

| HTTP | code | 含义 | 机器人侧怎么办 |
|---|---|---|---|
| 400 | `invalid_request` | 参数缺失或格式错误 | 核对 `messages` 结构；不发则记日志，回用户「我这边出错了」 |
| 401 | `auth_failed` | API Key 缺失或无效 | **先查机器人进程有没有读到环境变量**，再重新复制 Key、确认 `Bearer ` 前缀 |
| 402 | `insufficient_points` | 账号点数余额不足 | 充值；给管理员发告警，回用户「额度用完了」 |
| 402 | `key_quota_exceeded` | 该 Key 自己的额度打满 | 去用户中心调高该 Key 的 quota，或换 Key，**不用充值** |
| 403 | `permission_denied` | 该 Key 无权调用此模型 / 应用 | 检查模型是否已开通、Key 是否被限权、IP 白名单 |
| 404 | `not_found` | 模型 / 应用 / 任务不存在 | 核对代码拼写；**先怀疑 `/v1` 层数** |
| 429 | `queue_limit_exceeded` | 排队任务已达上限 | 降并发（同群串行、全局 3~5），指数退避重试 |
| 5xx | `server_error` | 服务异常 | 退避重试；仍失败切降级模型 |

**两条容易读错的：**

- **两个 402 是不同的事。** `insufficient_points` 是账号没钱，去充值；`key_quota_exceeded` 只是这把 Key 的额度满了，**去调 quota，不用充值**。
- **403 和余额无关。** 它是权限问题（模型未开通、Key 被限权、IP 白名单不匹配）。

### 机器人侧的异常处理原则

**用户永远不该在群里看到错误码。** 每个错误码都要映射成一句人话：

| 错误码 | 回群里的话 |
|---|---|
| 401 / 403 | 「我这边配置有点问题，已通知管理员」 |
| 402 | 「额度用完了，请联系管理员」 |
| 429 / 5xx / 超时 | 「问的人太多啦，稍等一下再问」 |
| 400 / 404 | 「这个问题我暂时答不上来，换个说法试试」 |

**同时把这些错误打进你自己的日志**（含错误码与请求时间），否则出了问题无从排查。**告警只对 401 / 402 开** —— 这两种是必须人工介入的；429 和 5xx 自己退避重试就好，别半夜打电话。

### 重试策略

| 情况 | 重试吗 |
|---|---|
| 400 / 401 / 402 / 403 / 404 | **不重试**，重试只是浪费请求 |
| 429 | 重试，指数退避 + 抖动（1s → 2s → 4s → 8s） |
| 5xx / 超时 | 重试，同样退避；持续失败切降级模型 |
| 提交类异步任务超时 | **先查 `task_id` 再决定**，不要裸重提 |

包内 `scripts/a7w.py` 已经把这套策略编进去了：网络类错误与 5xx 退避重试 **4 次**，4xx 是业务错误不重试。

## 五、权限与联网边界

| 能力 | 是否申请 | 用途 |
|---|---|---|
| 网络访问 | **申请** | 调用 `api.a7w.cn` 的网关接口（唯一的联网行为） |
| 读取文件 | 仅读取你指定的输入文件 | 用作素材入参 |
| 写入文件 | 仅在传入 `--out` 时 | 保存返回的 JSON 或下载产物 |
| 凭证 | 读取**你自己**提供的 API Key | 从环境变量或 `~/.a7w/config.json` 读取 |
| 子进程 / 后台常驻 | 不申请 | `a7w.py` 执行完即退出，不注册服务、不常驻 |

**不内嵌任何密钥。** 请求只发往 `api.a7w.cn`，不发送到其他任何地址。

边界声明：

- **不提供 Key、不代付费用。** Key 必须你自己在 [api.a7w.cn](https://api.a7w.cn/) 申请。
- **不替代内容合规审查。** 机器人在群里说的话，合规责任在部署方 —— 出口层要有敏感词过滤与「AI 生成」标识。
- **不替代授权审查。** 音色克隆、群成员语音、群内图片的使用前，请自行确认授权与告知。
- **不保证默认就安全。** 机器人对外提供服务前，请自行做好 Key 隔离、配额与告警。
- **不保证消息不被重投。** 平台重投是常态，**去重必须由你的机器人侧做**（按 `message_id`）。

只允许访问的域名：`api.a7w.cn`、`aigc.a7w.cn`、`ks.a7w.cn`、`vr.a7w.cn`、`a7w.cn`。
