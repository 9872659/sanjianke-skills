# 三剪客 · 本地部署的中英双语对话模型 Skill

把一个 62 亿参数的中英双语对话模型跑在自己的显卡上，不联网、不调外部接口

---

## 前置条件

- **Python 环境 + PyTorch**，能正常 `import torch`
- **`transformers`**：官方推荐 4.27.1，理论上不低于 4.23.1 即可
- **磁盘空间**：权重文件体积不小，另外量化加载时还需要能放下 FP16 权重的内存
- **显存门槛**（上游官方硬件表给出的数字）：

  | 量化等级 | 推理最低显存 | 微调最低显存 |
  |---|---|---|
  | FP16（无量化） | 13 GB | 14 GB |
  | INT8 | 8 GB | 9 GB |
  | INT4 | 6 GB | 7 GB |

- **没有显卡也能跑**：CPU 完整精度推理大约需要 32GB 内存；CPU 上跑量化模型还需要 `gcc` 与 `openmp`
- **首次加载需要联网**下载模型实现与权重；要离线就先按 SKILL.md 里写的方式把权重下到本地目录
- **不需要账号或 API Key**

---

## 使用

加载这个 Skill 之后，Agent 会按 `SKILL.md` 里的六个板块来干活：判断该不该用、怎么装、常用操作怎么跑、有哪些坑、权限边界在哪、能覆盖到什么程度。

典型用法：

1. **部署咨询**——「我只有一张 8G 显卡，这个模型能跑吗」。Skill 里带了官方三档显存门槛，直接能对照。
2. **本地起服务**——要网页界面走 `web_demo.py`，要 HTTP 接口走 `api.py`（默认 8000 端口），要终端交互走 `cli_demo.py`。
3. **代码调用**——最小可用的三行加载代码、多轮对话的 `history` 传递写法、量化加载与直接加载量化权重的区别，都在「常用操作」里。
4. **排障**——「模型加载报错」「显存爆了」「第二轮对话像失忆」「英文回答质量差」这类现象，对照「常见坑」表逐条排查。
5. **合规确认**——代码和模型权重是两套许可，商用前需要先登记，Skill 里写明了这一点。

## 安全

- 不内嵌任何密钥：本 Skill 正文里没有任何 token、口令或私有地址
- **模型权重的下载与使用要遵守上游许可**：代码是 Apache-2.0，模型权重是另一份协议——学术研究完全开放，商业使用需要先按上游要求填写问卷登记
- **不要直接把 `api.py` 或 `web_demo.py` 暴露到公网**：它们默认没有任何鉴权，谁都能调；需要公网访问就自己在前面加一层网关和认证
- **首次加载会执行远端下发的模型实现代码**（这正是 `trust_remote_code=True` 的含义）：只在信任的权重仓库上用，别对这个参数掉以轻心
- **别把敏感内容喂给不明来源的权重仓库**：本地推理不等于安全，模型是别人训练的，权重是从网上拉下来的
- **量化加载有内存峰值**：`quantize()` 会先把 FP16 权重整个读进内存，峰值约 13GB，内存小的机器容易把系统拖死
