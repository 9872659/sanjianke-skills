## 一、四种形态，按需要选

向量库可以只活在一个进程里，也可以起成服务给多台机器共用。**先按数据量与并发选形态**：

| 形态 | 数据在哪 | 适合 | 要额外起服务吗 |
|---|---|---|---|
| **进程内** | 内存 | 边写边试、跑通链路、做 demo | 不用 |
| **文件持久化** | 你指定的目录 | 笔记本上长期用的本地知识库 | 不用 |
| **自托管服务端** | 服务端 | 多个进程 / 多台机器共享一份数据 | 要 |
| **托管云** | 云端 | 不想自己运维 | 不用，但要凭据 |

⚠️ **最容易漏的一步**：默认的进程内模式**进程退出数据就没了**。要留存就必须显式切到
「文件持久化」或「服务端」形态 —— 这是从原型走向「能留下东西」的第一处改动。

**什么时候该换更大的库**：上亿级向量、高并发在线检索、需要细粒度权限与多租户隔离时，
进程内/文件形态就不合适了，直接上专门的分布式向量库。

## 二、三分钟跑通

### 第一步：拿到你自己的 Key

到 **[api.a7w.cn](https://api.a7w.cn/)** 注册，创建 API Key（形如 `sk-...`）：

```bash
export A7W_API_KEY=sk-你的key      # Windows: $env:A7W_API_KEY="sk-你的key"
```

### 第二步：先定 embedding 模型（**维度定了就不能改**）

```bash
curl -sS "https://api.a7w.cn/api/v1/models" \
  -H "Authorization: Bearer $A7W_API_KEY"
```

从返回里挑一个 embedding 模型，**记下它的输出维度**。这个模型一旦用于建索引就不能再换 ——
换了要重新向量化全部文本。**模型名不要猜。**

### 第三步：向量化 —— 一个 base_url，一把 Key

```bash
curl -sS -X POST "https://api.a7w.cn/api/v1/embeddings" \
  -H "Authorization: Bearer $A7W_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "<上一步挑的 embedding 模型名>",
    "input": ["退款需在收货后 7 天内发起", "生鲜类不支持无理由退款"]
  }'
```

返回 `data[].embedding` 就是向量。**这就是全部魔法** —— 后面的存取与相似度计算都在本地。

### 第四步：写入 + 检索 + 元数据过滤（本地，免费）

本 Skill 把「向量库存取」抽象成三个动作，**任何向量库客户端都是这三步**：

```python
# 零依赖本地向量库：一个 JSON 文件 + 余弦相似度（完整实现见 references/本地向量库.md）
store.add(
    ids=["doc1", "doc2"],
    documents=["退款需在收货后 7 天内发起", "生鲜类不支持无理由退款"],
    metadatas=[{"source": "help-center"}, {"source": "policy"}],
)

hits = store.query(
    "怎么退款",            # 查询文本，客户端会先向量化再算相似度
    n=3,                   # 取前几条
    where={"source": "help-center"},   # 元数据过滤
)
```

**元数据过滤是刚需**：只搜某个来源、某个时间之后、某个标签下的文档，
这一步在本地做，不花钱。

## 四、素材要求

| 要求 | 说明 |
|---|---|
| 入库内容 | **先转成纯文本**。PDF / Word 的解析是上游工序，不属于向量库的职责 |
| 单条长度 | 300~500 字一条，重叠 10%~15%；一条太短语义不足，太长会稀释相似度 |
| 元数据 | **只放简单标量**（字符串 / 数字 / 布尔）。嵌套字典与列表先拍平成多个字段 |
| 命名 | id 用稳定的业务键（如 `文件名#序号`），**别用会变的随机串**，否则无法覆盖更新 |
| 维度 | 建索引前固定 embedding 模型与维度；换模型必须重建并重新灌数据 |
| 离线环境 | 要么先联网把向量算好落盘，要么改用不依赖模型的**关键词检索**（`references/` 里有 BM25 实现） |

## 五、常见坑

| 坑 | 表现 | 怎么避 |
|---|---|---|
| **默认进程内模式** | 关掉脚本再跑，之前写的数据全没了 | 要留存就显式切到**文件持久化**或**服务端**形态，别停在内存模式 |
| **用 `add` 重复写同一个 id 以为会覆盖** | 集合里出现重复数据、污染检索结果 | 覆盖语义用 **upsert**；只改元数据用 update；`add` 就是纯新增 |
| **元数据过滤报错** | 过滤条件不生效或直接报错 | 元数据值只放**简单标量**；多层条件用 `$and` / `$or` 显式组合 |
| **`n_results` 比库里实际条数还大** | 报错或结果异常 | 先取实际条数，再取 `min(n_results, count)`；本包示例代码已内置这个保护 |
| **embedding 模型名靠猜** | 报错或返回异常 | 先用 `GET /api/v1/models` 查一次，**以接口返回为准** |
| **换了 embedding 模型** | 旧向量与新向量不可比，结果全乱 | **索引与查询必须同一个模型**；换模型要重建全部向量 |
| **离线机器上跑不通** | 首次调用失败 | 先在联网机器把向量算好落盘；或改用纯本地关键词检索 |
| **多实例各写各自的本地目录** | 数据「各写各的」，互相看不见 | 多进程 / 多机共享统一走**服务端形态**，让服务端成为唯一写入方 |
| **把 Key 写进代码** | 泄露即等于泄露余额 | 只从环境变量 `A7W_API_KEY` 或 `~/.a7w/config.json` 读 |
| **一次塞几十条进上下文** | 又贵又跑题 | 先取 3~5 条；召回不准先改分块粒度，别急着加条数 |

1 元 = 100 点，1 点 = ¥0.01，**按量计费、没有月费**。

| 动作 | 点数 | 折合 |
|---|---|---|
| 本地存取、算相似度、元数据过滤、BM25 关键词检索 | **0** | 免费，不经过平台 |
| `file_qa` 文件问答 / 剧本解析 | **0** | 免费（实测口径） |
| **向量化** `embeddings` | 按 tokens 计点 | 一条文本一次，**只在写入与查询时发生** |
| 生成答案 `chat/completions` | 按 tokens 计点 | 每次问答一小笔，`max_tokens` 可控 |

**省点数的三条**：① 分块别切太碎（块越多、向量化次数越多）；② 已经算过的向量落盘复用，
不要每次重算；③ 纯关键词能解决的检索就用本地 BM25，**完全不花点数**。

> 平台同时给出**标准价**与**租户实际结算价**两套字段，两者可能差很多；
> **做预算一律按实际扣费算**，每次返回里的 `usage` 就是本次真实用量。
