# 选型指南：同一个需求，用哪个插件

市场里有 20 个插件，很多需求**不止一个方案**。这份文档按任务类型给判断依据。

---

## 一、出图（图片生成）

| 需求 | 用哪个 | 为什么 |
|---|---|---|
| 文生图、图生图、改图 | `nano_banana` | 唯一一个纯图片生成插件；`action=generate` 文生图，`action=edit` 基于参考图编辑 |
| 要高清档位 | `nano_banana` + `resolution` | 官方模型按 1K / 2K / 4K 分档计费，普通模型更便宜 |
| 要角色一致性 | `nano_banana` 的官方模型 | 描述里明确「官方模型适合更高一致性和高清档位」 |

> **注意**：`nano_banana` 的 `image_urls` 在 `action=edit` 时**必填**，`action=generate` 时不用传。

---

## 二、出视频（视频生成）

五个插件都能出视频，区别在**输入形态**和**模型族**：

| 插件 | 输入 | 适合 |
|---|---|---|
| `full_video` | 文 / 首尾帧 / 多模态参考 | **通用首选**。什么都吃，不知道选谁就用它 |
| `wan` | 文 / 角色参考（最多 9 图 5 音 5 视频）/ 视频编辑 | 要**多参考混合**时最强的；按 `model` 参数切版本 |
| `seedance` | 文本 / 图片 / 视频 / 音频任意组合 | 要 **480p / 720p / 1080p 分档**，且有 7 个接口（含素材管理） |
| `happy_horse` | 文 / 图 | 要**一阶段出声画**、多语言对白——它是统一多模态建模，声音和画面一起出 |
| `grok_video` | — | 要**快速出片**；支持「快速」和「标准」两档 |

### 怎么快速决定

```
要声音和画面一起出？        → happy_horse
要多种参考素材混着用？      → wan（9图/5音/5视频）
要按分辨率分档、要管理素材？ → seedance
只要快？                    → grok_video 的快速档
都不确定？                  → full_video
```

## 三、数字人与口播

三个插件听起来像，其实**输入完全不同**：

| 插件 | 输入 | 输出 | 适合 |
|---|---|---|---|
| `pic_lipsync`（图片数字人） | **一张人物图** + 音频或文案 | 数字人口播视频 | 有静态形象，想让它开口说话 |
| `image_human`（全驱动数字人） | 图片 + 参考音频 | 自然稳定的数字人视频 | 要**全驱动**（头部、表情、身体一起动），不只是嘴动 |
| `lipsync`（数字人对口型） | 视频 + 音频 | 对口型后的视频 | 已有真人视频，只需**换口型对齐新音轨** |

```
手上是照片？         → pic_lipsync（只要嘴动）或 image_human（要全身自然动）
手上是视频？         → lipsync（换口型）
```

## 四、视频剪辑与特效

| 需求 | 用哪个 | 关键点 |
|---|---|---|
| **把 A 的动作搬到 B 身上** | `action_transfer` | 参考图 ≤ 1 张、参考视频 ≤ 1 个；按**输入视频秒数**计费，分 fast / standard / max 三档（1 / 2 / 3 点每秒） |
| **把视频里的人换成另一个人** | `person_replacement` | 和动作迁移是同一类接口形态（submit + query） |
| **给人换衣服** | `dressing_diffusion` | 上传模特图 + 服装图，自动试穿；支持上衣 / 下装 / 全身 |
| **批量混剪、口播视频** | `smart_clip` | 5 个接口：模板列表、模板详情、真人口播混剪、素材混剪、新闻体视频 |
| **把糊视频救成 4K** | `flashvsr` | 只吃公网 URL；详见「视频超分」那个 Skill |

### `smart_clip` 值得单独说

它是市场里**接口最多**的剪辑类插件（5 个），而且有「模板」概念：

```
template        模板列表     → 先看看有哪些模板
template_detail 模板详情     → 选定了看它的参数
realman_broadcast 真人口播混剪 → 真人出镜的口播视频
broadcast_mixcut  素材混剪     → 纯素材拼接
news_mixcut       新闻体视频   → 新闻播报样式
```

**顺序**：先 `template` 拿模板 id → 再 `template_detail` 看要传什么 → 再调对应的混剪接口。

## 五、音频与音乐

| 需求 | 用哪个 | 关键点 |
|---|---|---|
| **文字转语音** | `voice_tts` | 6 个接口，最全：同步 `tts`（短文本，500 字内）、异步 `tts_async`（长文本）、`tts_live`（WebSocket 流式上游） |
| **克隆音色** | `voice_tts` 的 `clone_voice` | 上传参考音频或给音频 URL，创建专属音色；之后 `list_voices` 能查到 |
| **语音转文字** | `voice_tts` 的 `stt` | 支持文件上传或音频 URL |
| **生成整首歌** | `music_generation` | 13 个接口，市场里最庞大的一个：`create` 建任务、`lyrics` 生成歌词、`persona` 创建歌手风格、`style` 优化风格、`vox` 人声处理、`timing` 歌词时间轴、`midi` / `wav` / `mp4` 三种导出 |
| **找现成的音乐** | `music_search` | 只有 1 个接口，搜曲子用 |
| **给视频配音效** | `mmaudio` | 音效生成、视频配音 |
| **改音色 / AI 翻唱** | `seedsvc` | 传目标音色参考音频 + 原始音频，做音色转换 |

### 语音类怎么选（`voice_tts` 内部）

```
文本 < 500 字          → tts（同步，直接返回音频 URL）
文本很长               → tts_async（异步，回调或轮询）
要边说边出（流式）      → tts_live（WebSocket 上游，长文本）
要自己的声音           → 先 clone_voice，再拿返回的音色 id 去合成
不知道有哪些音色       → list_voices
```

### 音乐类怎么选（`music_generation` 内部）

```
只想出首歌             → create
还没词                 → lyrics 先生成歌词
想让某个人声风格唱     → persona 创建歌手风格
曲子风格不对           → style 优化
人声要处理             → vox
要卡拉OK字幕           → timing 出歌词时间轴
要交付                 → midi（编曲）/ wav（音频）/ mp4（视频）
```

## 六、文档与检索

| 需求 | 用哪个 | 关键点 |
|---|---|---|
| **问一份文档** | `file_qa` | 走**公网文档地址**，做问答、摘要、剧本结构化解析 |
| **只想解析文档内容** | `file_qa` 的 `parse` | 不问答，只把文档结构化出来 |

> `file_qa` **只吃公网 HTTP/HTTPS 地址**，不支持上传本地文件。本地文件要先传到能公网访问的地方。

---

## 七、通用决策原则

1. **先看输入形态**，而不是先看功能名。数字人那三个插件名字像，输入完全不同——照片、图片+音频、视频+音频，选错了直接跑不通。
2. **接口多的插件往往更灵活**。`music_generation` 13 个、`seedance` 7 个、`voice_tts` 6 个、`smart_clip` 5 个——它们把流程拆成了可组合的步骤，而不是一个大黑盒。
3. **公开接口只有 submit / query 的，基本是「弹性 GPU 任务」**。这类插件的参数都在 `params_schema` 里，但没有细化的分步接口。
4. **拿不准就用 `full_video` + `nano_banana` 起步**：一个出视频一个出图，覆盖面最广。

## 八、自己查最新情况

市场会变，用客户端现查最准：

```bash
python3 scripts/market.py list            # 全部插件（按能力分组）
python3 scripts/market.py find 视频        # 搜插件 / 接口
python3 scripts/market.py show seedance   # 看某插件的接口与必填参数
python3 scripts/a7w.py schema <app>       # 同上，原始输出
```
