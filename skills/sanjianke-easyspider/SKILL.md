# 三剪客 · 可视化无代码爬虫

要采的数据在页面上肉眼就能看见，但写选择器很烦：列表结构一变就全废，还得处理翻页、登录、iframe、验证码、下拉加载。EasySpider 的思路是不写代码——打开目标网页，直接在页面上点选"我要这一列"，工具把点击动作翻译成一条条流程图操作，再按这个流程图去跑。

它适合**结构化但不规整**的采集目标（列表加详情页、需要滚动加载、需要登录、有翻页按钮），也适合让不懂编程的同事自己维护采集任务。任务设计好之后，同一份任务可以本地跑、命令行跑、无头跑，或交给一台服务器统一管理。

**上游项目**：`EasySpider`　**仓库**：https://github.com/NaiboWang/EasySpider

## 什么时候用 / 不用

**用它**：

- "这个网站的内容想定期采下来，但页面结构老是变，写死的选择器维护不动。"——图形化点选，改起来成本低。
- "采集需要先登录、还有翻页和滚动加载。"——内置登录态处理、页面滚动、循环点击、iframe（含多层嵌套）支持。
- "不会写代码的同事要自己采数据。"——任务设计不需要编程基础，只需要懂一点点 XPath 就能微调流程。
- "采完想直接出 Excel / CSV / TXT，或者写进 MySQL。"——内置这些导出与写库方式。
- "要把采集嵌进自己的流程里，定时跑、后台跑。"——支持命令行执行、无头模式、API 调用、定时执行、并行多开。
- "数据量大、想用多台机器或多开并行。"——可开多个执行程序并行采集，也支持把任务信息统一存到服务器地址下管理。

**不要用它**：

- **目标站点明确禁止自动化访问，或要求绕过风控、破解验证码**——工具支持验证码识别不等于可以这么做。先看目标站点的条款与 robots 约定，涉及个人信息和版权内容的采集必须先拿到授权。
- **只抓一个静态页面、就采一次**——几行 requests 加解析库更快更轻，装一个图形程序反而重。
- **要百万级页面的大规模分布式采集**——浏览器自动化单页开销大，单机多开到一定程度就不经济了，这种量级该换分布式爬虫框架。
- **需要请求级精细控制**（自定义请求头顺序、HTTP/2、连接复用、超高并发）——浏览器自动化的抽象层次更高，这些细节不好控。
- **目标机器不满足系统版本要求**——见「安装」：Windows 7 完全不支持。

## 安装

软件是桌面程序，官方渠道有两个：上游仓库的 Releases 页面，以及官方站点的下载页（站点另提供境内网盘下载源）。**官方明确说明交流群不作为下载渠道**，不要去群里找安装包。

```text
1. 打开上游 Releases 页面：https://github.com/NaiboWang/EasySpider/releases
   或官方站点下载页：https://www.easyspider.net/download.html
2. 选择与自己系统对应的包下载并解压
3. 运行解压目录中的主程序，进入图形界面
```

系统版本要求（以下为官方下载页给出的口径）：

| 系统 | 要求 |
|---|---|
| Windows | 64 位 Windows 10 / Windows Server 2016 及以上；**不支持任何 Windows 7** |
| macOS | 支持 Apple 自研芯片与 Intel 芯片；系统最低 11.1。更低的系统版本官方建议改用 v0.2.0 的 Mac 版，或自行下载代码编译 |
| Linux | 仅适用于 Ubuntu 20.04 及以上、Deepin、Debian 及其衍生版本；其他发行版（如 CentOS）需自行编译 |

想跑在服务器上（无界面），用命令行执行加无头模式即可；官方 wiki 另有 Docker 运行示例页，镜像与挂载方式的细节以那一页为准。

## 常用操作

**1. 图形化设计一个任务**

打开主程序 → 输入目标网址并打开 → 在页面上点选要采集的元素（工具会高亮待选区域）→ 对每个操作设置提取字段、循环次数、翻页方式 → 保存任务。任务会出现在任务列表里，之后随时可编辑、试运行、复制到别的机器。

官方 wiki 的教程导航按场景给了对应视频与说明（登录后采集、滚动加载、循环进详情页、验证码、代理 IP、iframe、定时执行、并行多开等），遇到具体形态直接对照那一页找。

**2. 命令行执行任务（官方 wiki 的参数说明）**

执行程序位于解压目录内（例如 `EasySpider/resources/app/chrome_win64/easyspider_executestage.exe`）。官方 wiki 的 API 示例给出的是这种形式：

```bash
cd /path/to/EasySpider
./EasySpider/resources/app/chrome_win64/easyspider_executestage.exe \
  --ids [37] \
  --user_data 0 \
  --server_address http://localhost:8074 \
  --config_folder "/path/to/EasySpider/ElectronJS/" \
  --headless 0 \
  --read_type remote \
  --config_file_name config.json \
  --saved_file_name
```

具体参数以官方 wiki 的「Commandline Arguments Instruction」页为准，摘要如下：

| 参数 | 含义 |
|---|---|
| `--id` | 任务执行 ID；任务文件在 `execution_instances` 目录内。默认 `[0]` |
| `--saved_file_name` | 保存文件名；不指定则为随机数 |
| `--read_type` | `remote` 从服务器读取，`local` 直接读本地 `execution_instances` 下的 `id.json`。默认 `remote`；设为 `local` 时**不需要启动主程序**就能执行 |
| `--server_address` | 服务器地址，仅 `--read_type remote` 时使用。默认 `http://localhost:8074` |
| `--user_data` | 是否带用户配置执行，`1` 是 / `0` 否。默认 `0` |
| `--config_file_name` | 配置文件名。默认 `config.json`，其中的 `absolute_user_data_folder` 字段指向用户配置目录 |
| `--config_folder` | 配置文件所在路径；默认空，即程序根目录 |
| `--headless` | 无头模式（不显示浏览器界面），`1` 是 / `0` 否。默认 `0` |
| `--keyboard` | 是否监听键盘以实现暂停；`1` 是 / `0` 否。不监听适用于调试或执行完自动退出的场景 |
| `--pause_key` | 暂停/继续需长按的键。默认 `p`；多开时可给不同实例设不同按键分别控制 |
| `--docker_driver` | 是否用 Docker 执行，需给出容器地址，例如 `http://localhost:4444/wd/hub`；默认空表示不用 |
| `--user_folder` | 加载指定的用户目录；仅在 `--user_data 1` 时生效。用 Docker 时要写容器内路径 |

注意：官方 wiki 里部分参数标注了适用版本，中英文两版对个别参数的版本标注并不完全一致；不同版本的参数名也可能有差异（详见「常见坑」）。

**3. 用 API 拿到执行 ID（适合嵌进自己的流程）**

向本机 8074 端口发一个表单请求，返回的就是可交给命令行执行的执行 ID：

```bash
curl -X POST http://localhost:8074/invokeTask \
  -d "id=157" \
  -d 'EID=1' \
  -d 'params={"urlList_0":"https://www.baidu.com/s?wd=1","loopTimes_循环_1":"15","inputText_2":"TEST"}'
```

要点（出自官方 wiki 的 API 调用示例）：

- 方法 `POST`，地址 `http://localhost:8074/invokeTask`，Body 用 `x-www-form-urlencoded`
- `id`：任务 ID，在 API 调用网址后面能看到
- `EID`：已存在的执行 ID，传了就是**覆盖模式**，新配置会覆盖该执行 ID 对应的配置（0.6.0 以上支持）
- `params`：一个 JSON 字符串，键是各输入参数的调用名，值是要代入的值；**0.5.0 及之前版本请改用 `paras`**
- 后台逻辑本质上是把 `tasks` 目录里任务 JSON 的默认参数替换成你给的值，在 `execution_instances` 目录里生成一份新的任务 JSON，再交给执行程序

**4. 无头 + 定时：挂到服务器上跑**

```bash
# 无头模式，不弹浏览器窗口
./EasySpider/resources/app/chrome_win64/easyspider_executestage.exe \
  --ids [37] --headless 1 --read_type local --saved_file_name result_37
```

官方另提供定时执行能力（页面上的定时设置，或配合系统计划任务调用上面的命令）。

**5. 输入参数与导出**

- 可以从 Excel 文件读入大批量输入参数（例如一批 URL），一次跑完整批
- 结果可导出为 Excel / CSV / TXT，或写入 MySQL
- 支持下载文件（图片、PDF、压缩包）、元素截图与 OCR 识别、JSON 数据采集

**6. 并行多开**

开多个执行程序实例同时跑，每个实例用不同的 `--pause_key`，这样暂停/继续可以分别控制。多开前先算清楚机器内存和目标站点的承受能力。

## 常见坑

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 在 Windows 7 上双击没反应或直接报错 | 官方下载页明确：Windows 版仅支持 64 位 Windows 10 / Windows Server 2016 及以上，**不支持任何 Windows 7** | 换系统版本，或在另一台满足要求的机器上跑；不要试图在 Win7 上折腾兼容性 |
| macOS 上启动失败；Linux 非 Debian 系装不上依赖 | 官方口径：macOS 最低 11.1；Linux 仅支持 Ubuntu 20.04+、Deepin、Debian 及其衍生版 | macOS 低版本改用 v0.2.0 的 Mac 版或自行编译；CentOS 等其他发行版需自行编译（官方指向对应 issue） |
| 命令行报参数不认识，或照抄文档却跑不起来 | 官方 wiki 的命令行参数说明页写的是 `--id`，而 API 调用示例里用的是 `--ids`；部分参数还标注了不同的适用版本，中英文文档的版本标注也不完全一致 | 以本机版本实际接受的参数为准：先 `--help` 试一次，或对照官方 wiki 对应页；不要跨版本混抄示例 |
| 用 `--read_type remote` 直接跑，提示读不到任务 | 默认 `remote` 会去 `--server_address`（默认 `http://localhost:8074`）取任务，主程序没启动自然取不到 | 执行前先启动主程序；或者在服务器 / 无人值守场景改用 `--read_type local`，直接读本地 `execution_instances` 下的 `id.json`，无需启动主程序 |
| 无头模式下任务卡在登录页或验证码页，最后超时失败 | `--headless 1` 不显示浏览器界面，需要人工扫码、输验证码或手工调试的步骤没法进行 | 需要人工介入的环节不要开无头；保留 `--keyboard 1` 以便长按 `--pause_key`（默认 `p`）暂停后手动操作页面 |
| 多开之后按暂停键，几个实例一起停了 | 默认暂停键都是 `p`，按键被所有实例共同监听 | 给每个实例传不同的 `--pause_key`，分别控制；也可以在保存任务窗口里改 |
| 改了 `tasks` 目录里的任务 JSON，之后行为异常 | 任务定义与执行配置分别落在 `tasks` 和 `execution_instances` 两个目录；API 调用会拿任务的默认参数生成新的执行配置，手工改文件很容易产生不一致 | 尽量在图形界面里改任务；批量改输入参数用 API 的 `params`（0.5.0 之前是 `paras`）走覆盖模式，别直接编辑 JSON |
| 用 API 覆盖配置没生效 | `EID` 覆盖模式是较新版本才支持的（官方标注 0.6.0 以上），旧版本传了会被忽略 | 确认版本后再用 `EID`；旧版本只能每次生成新的执行 ID |
| 并行多开跑一会儿机器卡死或 IP 被限制 | 每个实例都是一个真实的浏览器进程，内存与目标站点的访问频率都是硬约束 | 控制并发数，配合代理 IP 与合理的请求间隔；大规模采集要评估是否该换分布式方案 |
| 换个操作系统打开任务跑不起来 | 任务本身可以复制迁移，但运行依赖浏览器内核与 Python 环境的版本 | 迁移时把运行环境一并对齐；官方 wiki 有针对源码编译与自定义 Python 环境的说明 |

## 权限与用途说明

| 能力 | 是否申请 | 用途 |
|---|---|---|
| 网络访问 | 是 | 打开目标网页并采集数据；命令行执行时还要访问本机 8074 端口的服务；写 MySQL、连代理 IP、调验证码服务同样需要网络 |
| 读取文件 | 是 | 读取任务定义与执行配置（`tasks` / `execution_instances`）、`config.json`、用户配置目录、以及从 Excel 导入的批量输入参数 |
| 写入文件 | 是 | 导出采集结果（Excel / CSV / TXT）、生成新的执行配置、下载目标文件、保存元素截图与 OCR 中间结果、写日志 |
| 凭证 | 是 | 目标站点的登录态与 Cookies、代理 IP 的账号、MySQL 连接信息、验证码服务密钥、统一管理用的服务器地址。这些应放在配置文件或用户配置目录里，不要硬编码进任务文件 |
| 子进程 / 后台常驻 | 是 | 图形界面本体与执行程序是两个进程；支持无头与定时执行，API 调用依赖本机 8074 端口上的服务常驻运行 |

## 触发场景

- "这个网站的数据我想定期采，但我不想写代码。"

- "任务设计好了，怎么让它在服务器上后台跑、不弹浏览器？"
- "怎么用命令行或者接口触发一个采集任务？"
- "想同时开好几个采集程序，各控各的暂停。"
- "采完的数据想直接导成 Excel 或者写进 MySQL。"
- "能不能采集 iframe 里的内容？"

## 能力边界

**覆盖**：

- 图形化设计：在目标网页上点选元素生成任务流程图，可视化配置提取字段
- 流程控制：无限循环嵌套、条件判断、Break 语句插到流程图任意位置、页面滚动、定时执行、随时暂停
- 复杂页面：多层嵌套 iframe 采集、Cookies 读取与修改、浏览器弹窗（Alert / Confirm）处理、模拟移动端设备
- 数据获取：Excel / CSV / TXT 导出、MySQL 写入、JSON 数据采集、文件下载（图片、PDF、压缩包）、元素截图与 OCR
- 扩展手段：执行自定义 JavaScript 与系统命令、正则表达式、修改网页内容、外挂自定义插件、修改执行时的 Python 环境与变量
- 运行方式：本地图形界面执行、动态调试试运行、命令行执行、无头后台执行、API 调用触发、并行多开、任务复制迁移
- 部署形态：Windows / macOS / Linux 桌面端，官方 wiki 另有 Docker 运行示例

**不覆盖**：

- 绕过目标站点的访问控制与风控：不负责"突破"反爬，验证码识别能力也不改变采集的合规前提
- 分布式调度与海量并发：单机多开是并行手段，不是集群调度，百万级页面需要换专门的分布式框架
- 请求级协议控制：不做精细的 HTTP 层控制（自定义头顺序、HTTP/2、连接复用等），它是浏览器自动化路线
- 数据清洗与建模：采下来的数据要分析、清洗、出报表，交给 pandas 之类的工具
- 合规判断：目标站点是否允许自动化访问、采集内容是否涉及个人信息与版权，由使用者自行确认
- 官方技术支持：软件本身的问题走上游仓库的 Issues 与官方教程

## 依赖条件

- 满足版本要求的操作系统：Windows 10 x64 / Server 2016 以上、macOS 11.1 以上、Ubuntu 20.04+ 或 Deepin / Debian 系
- 从上游 Releases 页面或官方站点下载页获取程序包；官方声明交流群不是下载渠道
- 用命令行执行需知道执行程序的路径；`--read_type remote` 需要先启动主程序，`--read_type local` 则不需要
- 用 API 触发任务时，本机需要在服务监听状态下（默认 `http://localhost:8074`）
- 写 MySQL、用代理 IP、调验证码服务时，需要相应的连接信息与账号
- Linux 上用 Docker 执行时需要一个 Selenium 容器地址（如 `http://localhost:4444/wd/hub`）
- 不需要注册账号，任务与数据默认保存在本地，不经过第三方服务器

## 已知限制

1. Windows 7 完全不被支持；macOS 11.1 以下、非 Debian 系的 Linux 发行版都需要自行编译，属于有门槛的路径。
2. 文档存在不一致：命令行参数页写 `--id`，API 示例里用 `--ids`；中英文文档对个别参数的适用版本标注也不同，跨版本使用前要实测。
3. `--read_type remote` 依赖主程序或服务端常驻，无人值守的服务器部署更稳妥的是 `local` 模式加本地任务文件。
4. 无头模式省掉了界面，也省掉了人工处理验证码、扫码登录的能力，需要人工介入的环节必须回到有界面模式。
5. 并行多开的成本是真实的浏览器进程，受机器内存与目标站点频率限制约束，不是无限扩展。
6. 任务可跨机器迁移，但依赖的运行环境（浏览器内核、Python 环境）要保持一致。
7. 官方文档更新节奏与软件版本不完全同步，参数的最终口径以本机版本行为与官方 wiki 对应页为准。
