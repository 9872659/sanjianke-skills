# 三剪客 · 客诉处置小组

> ## ⚠️ 先申请你自己的 API Key
>
> **本 Skill 不内嵌任何密钥，也不代付费用。** 请到
> **[算力集市 api.a7w.cn](https://api.a7w.cn/)** 注册并创建**你自己的** API Key
> （新用户有赠送点数，可以先免费试跑几条）。
>
> 拿到后填进环境变量 `A7W_API_KEY`，或直接传给 `--key` 参数。
> **请勿使用他人提供的 Key** —— 用量与费用都记在 Key 所属账号上。

> ## ⚠️ 本包不接真实支付 / 工单系统
>
> **它产出的是「处置建议与话术」，不是一笔已经发生的账。**
> 本包不连任何支付网关、不写任何工单系统的数据库、也不联网去改后台数据
> （唯一的外部调用是 api.a7w.cn 的大模型端点）。
>
> 真的要退款、要赠额、要延期、要改用户额度，**必须由人工在后台执行**。
> 报告里的"19800 点 ≈ ¥198"是**口径**，不是已退款金额。

## 能做什么

一张客诉工单进来，四个角色按流程把它处置完：

```
接报   → 类型 / 等级（P0~P3）/ 承诺时限 / 影响面
技术判断 → 产品缺陷 or 用户误用 or 环境问题 or 证据不足 + 可复现步骤 + 证据链
授权   → 补偿项（枚举内）+ 金额（点）+ 口径 + 给用户的话术（受权限矩阵硬约束）
复盘   → 根因 + 改文档 / 改产品 / 改口径 + 同类工单预警
```

它替代的是客诉处理里最危险的那一步：不是"话说得不好听"，
而是**"一线为了让用户满意，把超出自己权限的钱批出去了"**。

| 你最关心 | 答案 |
|---|---|
| 跟"多调几次模型"有什么不同 | 四步是**四次独立调用**，每一步只带它该看到的东西；**只有授权那一席手里有权** |
| 权限到底有没有用 | 有，而且是硬的：补偿合计超出本级上限 → **`exit=3`**，并要求输出 `escalate_to`；权限分封 0 |
| 会不会自创补偿 | 不会：补偿项是**8 项枚举**，枚举外一律拦（`unknown_compensation`） |
| 模型自己编个时限行不行 | 不行：承诺时限**必须等于权限矩阵里那级对那等级的分钟数**，编了就被拦 |
| 超时怎么办 | P0/P1 超出承诺时限 → **标红**并拦下；时限基准是工单的提交时间 |
| 判定会不会是空话 | 不会：每条判定/处置都要引用**工单里真实存在的句子**，编造的引文剔出（未锚定率 > 40% 判定位失败） |
| 会不会随口承诺 | 不会：「保证解决」「一定赔偿」「永久免费」进合规闸门，退出码 3 |
| 多少钱 | 按 token 计费。实测：626 字工单 = 4 次调用、9119~9539 token、约 21 秒 |
| 要装什么 | **什么都不用装**。只用 Python 标准库，不需要 pip install 任何东西 |

### 三个命令就够（零成本那两个先跑）

```bash
python3 scripts/run.py roles                                  # 看四个角色的职权与权限（零成本）
python3 scripts/run.py policy                                 # 看权限矩阵与补偿枚举（零成本）
python3 scripts/run.py cost --file 工单.md                     # 报价（零成本）
python3 scripts/run.py run  --file 工单.md --outdir D:/support  # 一条命令跑完四步
```

## L3 定位：这是「处置式」，不是「评价式」

L3 是**多角色分工互审、一条命令出成品**。同族已经有八种形态，本包是**第九种**：

| 形态 | 代表包 | 核心机制 | 输入 |
|---|---|---|---|
| 流水线式 | `content-team` | 角色顺序接力，打回重写 | 一个选题 |
| 对抗评审式 | `review-board` | 立场独立 + 当面对质 + 裁决 | 一份已有方案 |
| 剧组式 | `drama-crew` | 策划/编剧/分镜/出片 | 一本小说 |
| 教研式 | `course-crew` | 课程目标 ↔ 考核对齐 | 一个教学需求 |
| 小组式 | `ecom-crew` | 选品/文案/视觉互否 | 一份商品资料 |
| 跨语言式 | `localize-crew` | 术语统一 + 文化改写 | 一份原文 |
| 竞争式 | `bid-crew` | 多方竞争出价 | 一个标的 |
| 取证式 | `research-crew` | 逐条求证 + 反驳 | 一个问题 |
| **处置式（本包）** | `sanjianke-support-crew` | **权限矩阵 + 时效 + 升级路径** | **一张客诉工单** |

### 本包与 `review-board` 的分界（两处最容易混，写清楚）

| | `sanjianke-review-board`（对抗评审） | **本包（客诉处置）** |
|---|---|---|
| 处理的对象 | 一份**方案/稿件** | 一张**客诉工单** |
| 角色的目标 | 各自**评价**得对不对 | 各自**推进**一个流程 |
| 关键动作 | 对质 → 找真分歧 → 出裁决 | 定级 → 定性 → 授权 → 复盘 |
| 有没有"花钱"这件事 | **没有**。评价不花钱 | **有**。补偿要真的批出去 |
| 谁会拦你 | 立场失效（四席说同样的话） | **越权**（批了超出权限的钱） |
| 有没有时效 | 没有 | **有**。P0/P1 超承诺时限标红 |
| 有没有升级路径 | 没有。评审没有"上一级" | **有**。超权限必须 `escalate_to` |
| 产出 | 裁决书 + 条件清单 + 少数派意见 | 处置方案 + 话术 + 复盘 + 升级申请 |

**一句话分界**：`review-board` 回答"这事该不该过"；
本包回答"**这张工单该怎么办、谁有权这么办、超了怎么办**"。
后者的三根支柱（权限 / 时效 / 升级）在前者里**结构上不存在**。

## 四个角色

| 角色 | 目标函数 | 产出物 | 权限 |
|---|---|---|---|
| **接报** | 用最快的时间把工单接住 | 工单卡：类型 / 等级 / **承诺时限** / 影响面 / 诉求 | 只有**定级权**，不能给补偿 |
| **技术判断** | 定位真因并给可复现步骤 | 判定 + 归因 + 可复现性 + 步骤 + 证据链 | **无**。只能说"是什么问题" |
| **授权** | 在矩阵之内决定给什么补偿 | 处置方案：补偿项 / 金额 / 结论 / 话术 / 升级对象 | **受权限矩阵硬约束** |
| **复盘** | 让同类工单别再发生 | 根因 + 改进项 + 同类预警 + 复发指标 | 无。不能改这次处置的金额 |

**信息隔离**（本地强制，每次运行都把"各角色实际收到了什么"打进产物可逐条核对）：

- 技术判断看得到工单卡的类型/等级/影响面，**看不到**接报的整套论述
- 授权看得到**本级额度**，**看不到**别级的额度明细（知道"我只能批 50"就够了）
- 复盘拿得到全部三份产出，但**看不到**任何角色的自评

## 权限矩阵（写死在包里，可 `--policy` 覆盖）

单位统一是**点**（平台口径 1 元 = 100 点，与 `--budget` 同一单位）：

| 层级 | 单张工单可批上限 | 超权限升给 |
|---|---|---|
| `L1_一线客服` | 5000 点 ≈ ¥50 | `L2_二线主管` |
| `L2_二线主管` | 30000 点 ≈ ¥300 | `L3_运营负责人` |
| `L3_运营负责人` | 200000 点 ≈ ¥2000 | `L4_公司决策` |
| `L4_公司决策` | 不设上限 | —— |

**补偿项是枚举**（不许自创）：
`refund_full` 全额退款 / `refund_partial` 部分退款 / `extend_service` 服务延期 /
`grant_credit` 赠额 / `coupon` 优惠券 / `free_retry` 免费重试一次 /
`manual_repair` 人工修复数据 / `apology_only` 仅致歉不改动

**等级 → 承诺时限**（L1 口径，各层不同，`policy` 子命令现查）：

| 等级 | 判据 | L1 承诺时限 |
|---|---|---|
| `P0` | 资金/数据事故，且仍在持续 | 15 分钟 |
| `P1` | 核心功能不可用，阻塞主流程 | 60 分钟 |
| `P2` | 能用但不好用 | 240 分钟 |
| `P3` | 咨询 / 建议 / 吐槽 | 1440 分钟 |

## 八道硬闸门（全在本地、确定性判定）

| # | 闸门 | 命中后果 |
|---|---|---|
| 一 | **合规**：违禁词 + **承诺类话术**（承诺类：保证解决 / 一定赔偿 / 永久免费…） | `exit=3` |
| 二 | 占位符残留（`{}` / `[待填]` / `TODO`…） | `exit=3` |
| 三 | 照抄提示词示例（含 contain 覆盖度判据 + **适用窗口**） | `exit=3` |
| 四 | **锚点到工单原文**（每条判定/处置引真实句子，编造剔出，未锚定率 > 40% 判失败） | `exit=3` |
| 五 | **越权拦截**（本包核心）：超本级额度 / 补偿项不在枚举 / 越权却没给 `escalate_to` | **`exit=3`** |
| 六 | **时效**：承诺时限必须来自 policy；P0/P1 超出承诺时限 **标红** | `exit=3` |
| 七 | **处置完整性**：判需补偿却没写补偿项 / 判无需补偿却没写理由 / 话术缺失或超长 | `exit=3` |
| 八 | 成本上限（`--budget`，单位**点**）；产出不许进包（`--outdir` 在包内） | `exit=5` / `exit=2` |

### 闸门一的口径：产出侧与材料侧**分开**

- **材料侧**（用户提交的工单原文）：全档全查，**只报不拦**。用户生气时写"你们必须赔我"，
  那是用户的话，不是我们要发出去的字 —— 拦它等于"用户一激动就没法处理"。
- **面客字段**（`voice_to_user`，真的要发给用户的话术）：**零豁免**。
- **审类字段**（内部说明 / 升级理由 / 复盘）：开「引用工单原文」与「提到/在禁止」两类排除，
  **被排除的必须留下原因**，照样列在案上可复查。

「最X」走**可枚举上下文豁免 + 句首不豁免**。客服话术里「最迟 24 小时」「最长 3 个工作日」
是 **SLA 时限口径**，不是最高级宣称 —— 它们走一条**独立的 SLA 判据**
（`最迟/最长/最短/最快/最多/最少 + 数字 + 时间单位`）。
不带数字的「最迟明天」**不豁免**，照拦；句首的「最大区别是…」也照拦。

另有两条**独立判据**，都是真机全跑抓到的**假警报**逼出来的（写在这里，不假装它们不存在）：

| 假警报 | 原文 | 判据 | 仍然照拦的形态 |
|---|---|---|---|
| 「第一」当成排他性宣称 | 话术「现在给你两件事：**第一**，…… **第二**，……」 | 后面是标点**且**同段里有后续序号（第二/第三…）→ 判为**列举** | 「行业第一。」（段里没有后续序号） |
| 「100%」当成效果承诺 | 复盘「失败任务自动退点**率** 100%。」 | 指标名词在**前**（退点率/达成率/占比…）或**在后**（100% 达成）→ 判为**指标口径** | 「100% 有效」「100% 恢复」「100% 保证」 |

误报的代价比漏报更大：**假警报会让人把整个闸门关掉**。所以口径是
"先保证正常中文与内部指标口径能过，再把真宣称拦住"，而不是"宁可错杀"。

## 退出码

| 码 | 含义 |
|---|---|
| `0` | 跑完且没有任何硬闸门命中 |
| `2` | 参数/配置错（文件不存在、`--outdir` 在包内、`--policy` 不合法、`--budget` ≤ 0） |
| `3` | **硬闸门命中**（合规 / 占位符 / 照抄 / 锚点 / **越权** / 时效 / 完整性） |
| `4` | 调用失败（网络 / 鉴权 / 点数 / 模型名） |
| `5` | 预算超限，**已就地中止且未发起那次调用** |
| `130` | 用户中断 |

### `--grant-cap`：把闸门变成能亲手试的东西

`settle` 与 `run` 都收 `--grant-cap`，它把**本级实际可批额度**临时改成指定点数
（真实场景就是新人额度被临时收紧）。它**不绕过**层级判定，只改本级额度：

```bash
# 同一张工单、同一套权限口径，只把本级额度收到 0 点
python3 scripts/run.py settle --file 工单.md --card 卡.json --diag 判定.json --grant-cap 0
# → 授权角色只要给出任何大于 0 的补偿，硬闸门立刻 exit=3 并要求 escalate_to
```

### `--policy` 覆盖权限矩阵

```bash
python3 scripts/run.py policy --policy 我的矩阵.json
python3 scripts/run.py run --file 工单.md --policy 我的矩阵.json --outdir D:/support
```

覆盖文件**只能收窄**，不能扩张：`compensation_types` 里出现包里没有的补偿项 →
直接 `exit=2`（能新增就等于把"不许自创补偿"这条闸门关掉了）。
每个层级必须给全 `P0~P3` 的 `sla_minutes`，否则时效闸门没有口径可用。
`escalate_to` 必须指向存在的层级（或空串）—— 升级路径断了，越权就无处可去。

## 真实请求的端点

| 用途 | 端点 |
|---|---|
| 大模型 | `POST https://api.a7w.cn/api/v1/chat/completions`（OpenAI 兼容协议；成功响应**不带** `code`） |
| 模型清单 | `GET https://api.a7w.cn/api/v1/models` |

文本模型网关**不公布单价**（models 列表里也没有价格字段），所以本包**只报 token、不编价格**。
要折算金额请传 `--price-in` / `--price-out`（单位：点/百万 token）。

`finish_reason` 会记进调用台账：**只有 `length` 才表示被 `max_tokens` 截断**（那就加大
`--max-tokens`）；其它值（`stop` / `None`）说明是模型自己写错了或响应在路上断了，
**加大 max-tokens 没用**，该换模型重试或把工单拆短。**不要用 content 长度判断**。

|---|---|
| 调用次数 | **4**（接报 → 技术判断 → 授权 → 复盘，是**一条直线**，没有打回重跑） |
| 实测 token | 626 字工单跑三次：9119 / 9365 / 9539 token（每次 4 次调用） |
| 实测耗时 | 约 21~22 秒 |
| 预算闸门 | `--budget`（单位**点**）。超了就**不发起那次调用**，`exit=5` |

`--budget` 的校验写在**每个会花钱子命令的第一步** —— 不会先报价、跑一半才发现超预算。

## 断点续跑

`run --outdir` 会落 `state.json`。同一份工单 + 同一套权限矩阵 + 同一层级再跑一遍 →
**4 步全部断点命中，0 次调用、0 token**。

断点 key 含**全部影响产出的维度**：工单原文摘要、层级、**实际可批额度**、
policy 版本、**整张权限矩阵**、以及各上游产物的摘要。
少写任何一个维度（尤其权限矩阵），续跑就会把"旧权限下的产物"当成已完成 —— 那可能是一次越权。

## 用法示例

```bash
# 1) 先看口径（零成本）
python3 scripts/run.py roles
python3 scripts/run.py policy

# 2) 报价（零成本）
python3 scripts/run.py cost --file 工单.md

# 3) 一条命令跑完
python3 scripts/run.py run --file 工单.md --outdir D:/support --budget 30

# 4) 也可以分步跑，中间产物都是 JSON，可人工检查
python3 scripts/run.py intake   --file 工单.md --json --out 卡.json
python3 scripts/run.py diagnose --file 工单.md --card 卡.json --json --out 判定.json
python3 scripts/run.py settle   --file 工单.md --card 卡.json --diag 判定.json --json --out 处置.json
python3 scripts/run.py review   --file 工单.md --card 卡.json --diag 判定.json --settle 处置.json
python3 scripts/run.py log --outdir D:/support

python3 scripts/run.py run --file 工单.md --dry-run
```

`--json` 写在子命令**前面或后面都可以**；stdout **只有一个 JSON**。

`键：值` 一行一条（认得出就结构化，认不出就当正文），加上自由正文。
**最重要的两个字段是 `提交时间`（时效闸门的 T0）与 `实付金额`**：

## 边界与诚实说明

1. **不接真实支付 / 工单系统，也不联网改后台数据。** 产出的是处置建议与话术；
   退款、赠额、延期必须人工在后台执行。报告里的金额是**口径**，不是已发生的账。
2. **权限矩阵是制度口径，不是法律意见。** 那一组数字（5000 / 30000 / 200000 点）
   是**默认值**，请按你公司的实际授权制度用 `--policy` 改掉再上线使用。
3. **合规扫描是启发式自检。** 它拦不住所有该拦的话，也不代表平台规则。
   高风险类目（医疗、金融、母婴、特殊化妆品）必须人工复核。
4. **时效判定依赖工单里写的时间。** 时间解析不出来时**不猜** ——
   标 `timing_checked=false` 并说明未做超时判定，而不是默认"没超时"。
5. **本包不给"到底该不该赔"的最终答案。** 它给的是
   "按权限该赔多少、超出该升给谁、话术怎么说、下次怎么不出现"。
   责任认定与最终金额由人工负责。
6. **四席共用同一个模型**，靠**调用边界 + 提示词边界**隔离，不靠不同模型。
   换 `--model` 会整体改变四步的表达与结论。
