# 选题与头脑风暴

目标：把一句模糊的方向，收敛成 1~3 个**可证伪、可执行、有比较对象**的候选选题，
并留下完整的淘汰理由。这一段结束时你手上应该有一份别人能看懂、也能反驳的选题池。

一次完整流程约 60~90 分钟，分三步：发散 → 收敛 → 锐化。**绝对不要三步混着做**，
边想边否是头脑风暴最常见的死法。

---

## 一、先把方向写成三行

动手发散之前，逼自己把输入写清楚。写不出来的部分，就是你其实没想清楚的部分。

```text
领域 / 对象：        （在做哪一类系统、数据或现象）
我目前相信：        （一句话，可以是错的）
我最不确定的：      （一句话，这通常才是真正的研究问题）
约束：              （算力、数据、时间、可用的仪器或平台）
```

第 3 行最关键。一个成熟的研究问题，几乎总是从「我最不确定的那件事」长出来的，
而不是从「我想做个更大的模型」长出来的。

---

## 二、发散：九个入口，逐个走一遍

每个入口至少产出 2 个候选，写进 `00-选题池.md`。此阶段**只写不评**，
连自己觉得离谱的也先写下来——离谱的常常是唯一没被别人做过的。

### 1. 问题优先 vs 方法优先
- 问题优先：先确定一个值得解决的问题，再找方法。产出通常更扎实。
- 方法优先：先抓住一个新技术，问「它让什么以前做不到的事变得可行」。产出通常更新。
- 两个方向各想 3 个，然后看哪边更容易写出评价指标。

### 2. 抽象阶梯
把同一个对象在四个高度上各说一遍：
现象层（观察到的具体行为）→ 任务层（把它形式化成什么任务）→ 方法层（用哪类方法解）
→ 机制层（为什么这类方法在这里会成立）。
**换一层，往往就是一个新选题**。卡住时优先往下走一层，比横向换题有效。

### 3. 找矛盾
去读本领域近两年的论文，专门找这三类地方：
- 大家都这么做，但没人解释为什么有效
- 两篇论文的结论互相冲突，而且都发了
- 某个指标一直被报告，但没有公认的解释
这三类地方后面都藏着一个可做的题。

### 4. 类比迁移
从邻近领域借结构：他们怎么处理稀疏、长尾、噪声、分布漂移、标注成本？
把他们的**结构性做法**搬过来，而不是搬名词。迁移时要能说清两个领域的同构点在哪，
说不清就说明只是表面相似。

### 5. 什么变了
问：过去 12~24 个月里，什么条件变了（数据规模、算力单价、模型能力、用户习惯、法规）？
旧方法在什么新条件下会失效？**旧结论在新条件下的失效点**是性价比很高的选题来源。

### 6. 失败与边界
收集本领域公开的失败案例、被撤稿的工作、复现不出来的结果。
挑一个问：它失败的原因是可归因的，还是只是运气？可归因的那个原因，
往往就是别人还没解决的问题。

### 7. 简单性测试
假设你的方法有效，问：**有没有更笨但更便宜的做法能达到接近的效果？**
如果有，你的选题必须解释清楚为什么简单做法不够。这一问能筛掉大量伪创新。

### 8. 换角色
同一个问题，分别站在这些人的位置上各问一遍：使用者、维护者、标注员、
审稿人、下游系统的开发者、付钱的人。不同角色关心的指标经常完全不同，
**指标换了，题就换了**。

### 9. 组合与拆解
- 拆解：把一个系统拆成流水线，逐个部件问「这一步现在的瓶颈是什么」。
- 组合：把两个已有方法各取一半拼起来，前提是能说清为什么这两半互补。

### 10. 讲给外行听
用三句话向一个不在本领域的人解释你的候选。解释不顺畅，通常是问题本身没成形，
不是你表达能力的问题。

### 发散阶段的操作要求
- 一次只用一个入口，不要跳着来
- 每个候选写成一句「如果我们做 X，那么在 Y 条件下应该观察到 Z」
- 写下候选人时不要写「可能有用」「效果更好」这类无法验证的词

## 三、收敛：打分卡 + 硬门槛

### 第 1 关：硬门槛（不满足直接淘汰，不留恋）

| 门槛 | 判断方式 |
|---|---|
| 可证伪 | 能写出「观察到什么结果就说明我错了」 |
| 可测量 | 有明确指标，且该指标能在你的条件下被算出来 |
| 可获取 | 数据、算力、仪器在你能拿到的范围内 |
| 有比较对象 | 至少有一个基线，且基线是你跑得动的 |
| 不越界 | 不涉及需要另行审批的敏感数据或人类受试者 |

### 第 2 关：打分卡（每项 0~5 分）

| 维度 | 0 分 | 5 分 |
|---|---|---|
| 重要性 | 只有自己关心 | 明显影响本领域后续工作 |
| 新颖性 | 与已有工作实质相同 | 检索后未发现等价工作 |
| 可行性 | 需要不存在的资源 | 现在的条件下两周内能出第一版结果 |
| 可验证性 | 结论无法被证伪 | 有清晰指标与判别标准 |
| 增量清晰度 | 说不清比基线好在哪 | 能一句话说清改进来源 |
| 后续延展 | 做完就完了 | 结果无论正负都能长出下一篇 |

处理规则（避免自欺）：
- **新颖性低于 3 分**的候选，必须回到文献段做一次针对性检索再打分，不能凭印象
- **可行性低于 2 分**的候选不淘汰，但降级为「长期池」，写清缺什么资源
- 总分只用来排序，不用来裁决。排序第一不等于该做

### 第 3 关：反向预演（强烈建议）
对前 3 名各写一段「这篇工作被拒的理由」。写得出来的，说明你已经找到漏洞；
写不出来的，说明你还没真正理解自己的选题。

## 四、锐化：把候选写成一句主张

通过收敛的候选，逐个锐化成固定句式：

```text
【主张】在 <条件/数据集/场景> 下，<方法 A> 相对 <基线 B> 在 <指标 M> 上 <方向>，
        原因是 <机制 C>。
【证伪条件】若 <观察 O> 出现，则本主张不成立。
【最小实验】只做 <一件事> 就能初步判别真假，预计耗时 <T>。
【代价】做这件事需要放弃 <什么>。
```

四项里任何一项写不出来，就回到对应的阶段重做，不要带着模糊进实验段。

### 选题池的收尾动作
- 定稿的 1~3 个候选，各自写清「下一步第一件事做什么」
- 被淘汰的候选，**保留并写明淘汰理由**。三周后你会想不起为什么砍掉它
- 把「长期池」单独列出来，季度回顾时再看一次

## 五、AI 在这个阶段的正确用法

| 用法 | 说明 |
|---|---|
| 当发散陪练 | 让它按指定入口批量出候选，你负责筛选；不要让它替你决定方向 |
| 当反方 | 让它专门攻击你的主张，找出「这个结论在什么条件下会崩」 |
| 当检索雷达 | 让它把候选转成检索式，帮你确认是否有人做过（见下一份资料） |
| 当记录员 | 把口述想法整理成上面那套固定句式 |

**不要**让它做这些：判断选题值不值得做、承诺结果好坏、替你在打分卡上填分数。
打分的分歧本身是信息，交出去就没了。

## 六、阶段检查清单

- [ ] 方向的三行输入（领域 / 我相信 / 我不确定 / 约束）已经写下来
- [ ] 九个发散入口至少走了 6 个，每个入口都有产物
- [ ] 候选总数 ≥ 10，且全部写成了「若做 X，则观察到 Z」的句式
- [ ] 每个候选都过了硬门槛五问
- [ ] 新颖性存疑的候选都已做过针对性检索，而不是凭印象打分
- [ ] 前 3 名各写了一段「被拒理由」
- [ ] 最终候选写全了主张、证伪条件、最小实验、代价四项
- [ ] 被淘汰候选的理由已归档，长期池已单独列出
