# 论文写作与投稿

目标：把已经跑完的实验，组织成一份**审稿人读得下去、能复算、挑不出硬伤**的稿件，
并为投稿、返修、被拒后的重投准备好材料。

写作的难点从来不是词句，而是三件事：
说清你做了什么、证明它成立、承认它的边界。这三件事做好了，文字差一点也能过。

---

## 一、先定一句话主张

动笔之前，用一句话写下这篇稿子的主张，放在草稿最上方，写稿全程不删：

```text
我们证明/表明：在 <条件> 下，<方法 A> 相对 <基线 B> 在 <指标 M> 上 <方向>，
                原因是 <机制 C>。
```

判据：如果这句话和摘要、引言最后一段、结论三处说的不是同一件事，稿子一定散。
每改一版，回头看这句话还成不成立——不成立就改稿，不要改这句话。

---

## 二、读者只读四样东西

按实际被读的概率排序：

1. 标题
2. 摘要
3. 图表
4. 结论

很多人只会读这四样。所以**它们必须能独立成立**：把正文全部遮住，只看这四样，
读者应该知道：做了什么、怎么做的、结果多好、在什么条件下成立。

### 标题
- 具体优于花哨。写出对象、方法或结论，而不是「迈向……」「……的探索」
- 避免无法证实的最高级

### 摘要（四到五句，一句一职）
1. 问题与它的重要性
2. 已有做法的局限（要有依据，不要贬低）
3. 你做了什么，关键机制是什么
4. 量化结果（带基线对比与条件）
5. 边界或适用条件（写一句，能显著提高可信度）

### 图表
- 图表是稿子的骨架，先定稿再写正文（见第四节）
- 每张图/表都要能回答一个明确问题；回答不了就删
- 图注自足：不看正文也能读懂这张图在比什么

---

## 三、骨架与各节任务

| 章节 | 必须完成的任务 | 常见毛病 |
|---|---|---|
| 引言 | 建立问题的重要性 → 指出现有做法的具体缺口 → 一句话给出你的做法与贡献 | 从宇宙起源讲起；贡献到了第 8 段才出现 |
| 相关工作 | 按方法类/时间线/问题维度组织，段末落到缺口 | 文献罗列，每段收尾接不上自己的题 |
| 方法 | 别人能照着实现；关键设计决策要说明替代方案与取舍 | 只写"我们用了 X"，不写为什么不用 Y |
| 实验设置 | 数据、基线、指标、超参预算、重复次数，全部写清 | 基线设置一笔带过，无法判断公平性 |
| 结果 | 回答主张，先给主表，再给消融，再给定性例子 | 只报最好的那次；把波动说成提升 |
| 局限 | 主动列出 2~4 条真实边界 | 写成客套话；或干脆不写 |
| 结论 | 只重复已经证明的东西，不引入新主张 | 结论里冒出正文没验证的说法 |

### 引言的漏斗结构
宽（这个领域为什么重要，一到两句）→ 窄（现有做法的具体局限，逐条，每条带引用）
→ 点（你的做法与它怎么绕开这些局限）→ 贡献清单（3 条以内，动词开头，可核对）。

### 贡献怎么写
每条贡献都要能被验证：「我们提出 X」不算贡献，「我们证明 X 在 Y 条件下比 Z 好 W%」才算。
不成立的贡献宁可删掉——审稿人专门核对贡献清单。

---

## 四、图表先行

推荐写作顺序（与阅读顺序相反）：

1. 先定**主结果表**：哪些对比、哪些指标、哪些基线，一行一行排好
2. 再定**消融表**：收益来自哪一处
3. 再定**图**：主趋势图、机制验证图、定性示例
4. 然后写**结果**一节（其实是给图表配文字）
5. 再写**方法**
6. 再写**引言与相关工作**
7. 最后写**摘要与标题**（因为这时你才知道自己到底证明了什么）

图表规范：
- 坐标轴有单位，图例齐全，误差棒注明是标准差还是标准误
- 表格里加粗的必须是可比条件下最好的。不同设置的数字不要放同一张表里比
- 数字精度统一，不要一处两位小数一处四位
- 图在黑白打印下也要能分辨（线型 + 标记，不要只靠颜色）

---

## 五、写作纪律

- **每个数字都要有来源**：某次运行的台账编号，或某张原始表。写不出来的数字删掉
- **每个论断都要有支撑**：实验结果、引用，或明确标注为「我们的推测」
- **区分事实与解释**：「A 比 B 高 3 个点」是事实，「因为 A 的表示更紧凑」是解释，
  解释需要独立证据
- **不要过度声称**：把「在所有任务上更好」改成「在测试的 N 个数据集中的 M 个上更好」
- **术语一致**：同一个东西全文一个叫法，别换同义词
- **时态一致**：方法与结果用同一套时态，全文统一
- **删除空话**：显著地、有效地、大幅、众所周知——这些词要么删，要么换成数字

### 引用纪律（与文献段同一套）
- 每条引用都要能打开原文核对；禁止编造、禁止凭标题补全条目
- 引用管理器导入的条目也要核对年份、出处、作者顺序
- 稿件里保留一份「待核对」清单，标注哪些条目尚未核对，投稿前清零

### AI 使用声明
- 若使用了 AI 辅助写作、翻译、润色或代码生成，按目标刊物要求如实声明
- AI 不得被列为作者；AI 生成内容的责任由作者承担
- 不得用 AI 生成或补全参考文献、实验数据、审稿意见回应中的事实性内容

---

## 六、投稿前自检

### 内容层
- [ ] 主张在标题、摘要、引言末段、结论四处一致
- [ ] 贡献清单每条都可核对，且正文都有对应章节
- [ ] 所有基线在相同数据划分、调参预算、评测脚本下对比，或已说明差异
- [ ] 每个报告的数字都能追到台账某次运行
- [ ] 报告了波动（标准差/区间）与重复次数
- [ ] 消融能回答「收益来自哪一处」
- [ ] 局限写了 2~4 条真实边界，不是客套话
- [ ] 没有把波动范围内的差异说成提升

### 形式层
- [ ] 页数、字号、边距、模板符合目标刊物要求
- [ ] 格式转换是**在目标模板里重排**，不是把旧模板的样式硬挪过来
- [ ] 图表全部被正文引用，且编号连续
- [ ] 参考文献格式统一，无重复条目，无孤立条目（列了但正文没引）
- [ ] 匿名要求已满足（若为双盲）：正文、致谢、补充材料、代码链接、文件属性
- [ ] 补充材料能独立读懂，且与正文不冲突
- [ ] 复现声明：代码/数据是否公开、以何种方式、何时

### 流程层
- [ ] 投稿系统字段（摘要、关键词、领域、作者信息）已逐项确认
- [ ] 已通读一遍**打印稿**，而不是只在屏幕上读
- [ ] 至少一位合作者完整读过并签字认可（包括认可所有数字）

---

## 七、审稿人视角预演

投稿前，让另一个人（或让 AI 扮演，但结论由你判断）按下面的顺序读，把问题写下来：

1. 只读标题和摘要：我知道这篇要证明什么吗？
2. 只看图表：主结果清楚吗？有没有哪张图我不知道在看什么？
3. 读方法：我能照着实现吗？关键设计为什么这么选？
4. 读实验：基线公平吗？指标够吗？波动报了吗？消融能定位收益吗？
5. 找最弱的一环：如果我要拒这篇，我会写什么理由？

### 高频拒稿理由（提前消灭）
| 理由 | 灭火动作 |
|---|---|
| 增量太小 | 把差异量化说清，或补一个能体现差异的场景 |
| 基线不够强 | 补一个当前最强可比工作，或说明为什么不可比 |
| 缺消融 | 按机制逐条拆掉，补表 |
| 结果波动大 | 补种子，报告区间；若确实无差异就如实说 |
| 声称过度 | 收紧措辞，加条件与边界 |
| 无法复现 | 补配置、命令、种子、数据版本 |
| 相关工作漏了明显的一篇 | 检索段做前向滚雪球补齐 |
| 写作混乱 | 回到第一节的一句话主张，重排引言与结论 |

---

## 八、返修与回复

返修信的结构，逐条走：

```text
意见 <编号>：<原文照抄审稿人的话，不要改写>
我们的理解：<用一句话复述，确认没理解错>
修改内容：<在稿件第 X 节第 Y 段，改成了什么>
证据：<新增的实验/引用/图号>
若未采纳：<为什么，给出理由或替代方案>
```

三条纪律：
- **不辩论**。审稿人说看不懂，就是没写清楚，先改文字，再谈内容
- **不空口承诺**。写「我们会补充」就必须真的补上，并标出位置
- **不隐瞒**。新增的实验如果有反例，如实写进去

被拒之后：先放一周再读审稿意见，把它当免费的评审意见用。
改投时**不要只换模板**——要在新模板里重排，并把上一轮暴露的问题真正修掉。

---

## 九、阶段检查清单

- [ ] 一句话主张写在草稿最上方，且四处表述一致
- [ ] 遮住正文，只读标题、摘要、图表、结论仍能读懂
- [ ] 写作顺序是先定图表、再写结果、最后写摘要与标题
- [ ] 每个数字都能追到台账某次运行
- [ ] 每条引用都能打开原文核对，「待核对」清单已清零
- [ ] AI 使用情况已按刊物要求声明
- [ ] 已做完内容层、形式层、流程层三张清单
- [ ] 已完成一次审稿人视角预演，并列出最弱的一环与应对
- [ ] 已通读打印稿，不再只依赖屏幕
- [ ] 合作者已完整读过并认可所有数字
