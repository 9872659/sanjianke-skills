# 实验设计与复现

目标：把一句主张变成一个**跑得动、说得清、别人复算得出来**的实验计划，
并用台账把每次运行钉在文件上，而不是留在终端的历史滚动里。

这一段分两个循环：
- **内环**：单次实验——配置、运行、记录、对比。
- **外环**：方向决策——这轮结果说明什么，下一轮做什么，什么条件下该掉头。

小实验跑得勤，外环判断才不会迟。反过来，先想清楚外环，内环才不会白跑。

---

## 一、从主张到实验

先把选题段那句话拆开，逐项落到可执行：

```text
主张：      在 <条件> 下，<方法 A> 相对 <基线 B> 在 <指标 M> 上 <方向>，因为 <机制 C>
可证伪预测：若 <机制 C> 成立，则 <观察 O> 应出现；若不出现，主张被削弱
最小实验：  只改动 <一个变量>，跑 <N> 次，看 <指标 M> 的差值是否超出波动
判别标准：  差值 > <阈值> 判为支持；|<差值| < 阈值 判为无差异；反向超出判为反对
```

三条要求：
1. **一次只改一个变量**。同时改两处，结果好坏都无法归因。
2. **先写判别标准，再跑**。跑完再定阈值，等于没有标准。
3. **机制必须是可观察的**。如果机制只能通过最终指标间接推断，就额外设计一个中间观测
   （中间层的分布、注意力、误差类型、子集上的表现），否则你只是在拟合结果。

## 二、变量清单

| 类别 | 写什么 | 常见疏漏 |
|---|---|---|
| 自变量 | 你主动改的那一个（或一组，需说明为何不可分） | 一次改了一组，却按一个变量解释 |
| 因变量 | 主指标 + 至少一个辅助指标 | 只报一个指标，无法判断是否trade-off |
| 控制变量 | 数据划分、预处理、超参搜索预算、评测脚本、硬件与精度 | 基线用的预算比你的方法少 |
| 混淆因素 | 可能同时影响结果的东西：数据顺序、随机种子、缓存、并发、库版本 | 把环境差异当成方法效果 |
| 不变量 | 本次实验不允许变的东西，明确写下来 | 中途悄悄升级了依赖 |

**公平性三条**：同样的数据划分、同样的调参预算、同样的评测脚本。
只要有一项不同，你的对比就不成立，就要在稿子里说明并降到「非受控比较」。

## 三、基线与消融

### 基线怎么选
- 至少两个：一个**简单基线**（证明任务本身可解），一个**当前最强可比工作**（证明你的位置）
- 基线必须是你**跑得动**的。跑不动的基线只能引别人的数字，那就要注明来源与设置差异
- 引用他人数字时，写清对方的设置（数据版本、模型规模、评测工具版本），
  并说明为什么可比或不可比

### 消融怎么设计
围绕「机制 C」逐条拆掉：
1. 去掉你新增的部件 → 看掉多少
2. 换成更简单的替代品 → 看是否等价（如果等价，说明你的部件没必要）
3. 只保留部件的一半 → 看是否单调
4. 打乱部件的输入顺序或随机化 → 若结果不变，说明它没在起作用

消融表应该能回答一个问题：**你的收益究竟来自哪一处？** 回答不了，实验就是没做完。

## 四、重复、随机与方差

- 固定随机种子，并且**把种子写进台账**；只报一个种子的结果不算结论
- 至少跑 3 次不同种子；预算允许就 5 次
- 报告方式：均值 ± 标准差，或给出区间；同时报告最好与最差
- 差值小于运行间波动时，判定为「无差异」。**不要把波动说成提升**
- 如果不同种子结论方向不一致，这是重要发现，要如实报告，不要只挑有利的那次

---

## 五、数据纪律

- 划分前先查泄漏：同一实体是否同时出现在训练与测试；时间序列是否用了未来信息；
  预处理（归一化、特征选择）是否在划分之前做了
- 数据划分固定一次并**存档**（列表文件或哈希），以后所有对比都用它
- 数据版本写清：来源、抓取日期、过滤条件、样本数
- 测试集的使用次数要记账。反复用测试集调方向，测试集就不再是测试集；
  真正的最终确认应该只用一次

## 六、实验台账

每次运行一行（或一段），落进 `03-实验台账.md`。台账的验收标准：
**另一个没参与的人，能凭台账把这次运行重跑一遍。**

```markdown
### RUN-<编号>  <日期>
- 目的：           这次运行要回答什么（对应哪个预测）
- 改动：           相对上一次改了什么，只写改动点
- 配置：           配置文件名或关键超参全文
- 命令：           完整可复制的运行命令
- 环境：           依赖版本 / 硬件 / 精度 / 随机种子
- 数据：           数据版本与划分文件标识
- 结果：           指标 + 波动 + 原始结果文件路径
- 结论：           支持 / 反对 / 无差异（对照判别标准）
- 下一步：         因为以上，接下来做什么
- 异常：           崩过、警告、跑飞的记录（不要删）
```

台账三条纪律：
1. **失败与异常也记**。三次失败之间的共性，常比成功那次更有信息量。
2. **结果文件路径必须写**。只写数字的结果，等于口头汇报。
3. **结论一栏只能写三选一**。写「效果不错」「有提升」的，回去对照判别标准重写。

## 七、结果与预期不符时

先别改方法，按顺序排查：

1. **实现是否有错**：用一个已知答案的小例子验证，做一次「能过就说明实现没错」的健全性测试
2. **评测是否正确**：指标实现、聚合方式、边界样本处理；用一个人工能算的小集核对
3. **基线是否过强**：预算、调参、预训练权重、数据量是否对等
4. **数据是否有问题**：泄漏、标签噪声、类别分布、去重
5. **假设是否本来就错**：以上四项排除后，接受它，并把它写成发现

**负结果是有价值的**，前提是你能说清「在什么条件下、相对于什么、没有观察到什么」。
把它写进台账和稿子的局限部分，而不是删掉那次运行。

### 什么时候该掉头（外环决策）
出现以下任一情况，就暂停加实验，回到方向层：
- 连续 3 轮实验都没能让主指标超出波动范围
- 收益全部来自某个高成本部件，成本 / 收益明显不划算
- 每次改进都要重新定义指标才能显得有效
- 你自己已经说不清下一个实验要验证什么

掉头不等于失败。把掉头理由写进台账，它就是你下一篇的起点。

## 八、可复现三要素

| 要素 | 最低要求 |
|---|---|
| 代码 | 版本固定（提交号或压缩包），运行入口唯一且写清 |
| 配置 | 所有超参与随机种子落在文件里，不靠命令行记忆或默认值 |
| 环境 | 依赖版本清单、系统与硬件、精度设置 |

加上第四条：**数据**。来源、版本、划分文件与预处理脚本，缺一不可。

自检方法：换一台机器，只读台账，不看你的聊天记录，能不能跑出同样的结果。
不能的话，缺的就是上面四项中的某一项。

---

## 九、AI 在这个阶段的正确用法

| 用法 | 说明 |
|---|---|
| 当设计审查 | 给它你的实验计划，让它专门找「哪些对比不公平、哪些变量没控制住」 |
| 当泄漏扫描 | 让它逐条审你的数据划分与预处理顺序 |
| 当台账整理 | 把原始日志整理成台账条目，你核对数字 |
| 当异常归纳 | 把多次失败记录交给它，归纳共性 |

**不要**让它做这些：替你判断结果是否支持主张、替你决定掉头、凭空生成实验数字。
凡是要进稿子的数字，必须能追到台账里的某次运行。

## 十、阶段检查清单

- [ ] 主张已拆成可证伪预测 + 最小实验 + 判别标准，且标准写在跑之前
- [ ] 一次只改一个变量；不可分的一组变量已说明理由
- [ ] 自变量、因变量、控制变量、混淆因素、不变量五类都写下来了
- [ ] 基线与你的方法在数据划分、调参预算、评测脚本三方面一致
- [ ] 消融能回答「收益来自哪一处」
- [ ] 每个配置跑了 ≥3 个种子，报告了均值与波动
- [ ] 已完成泄漏检查，划分文件已存档
- [ ] 测试集使用次数已记账
- [ ] 台账每条都有：目的、改动、配置、命令、环境、数据、结果路径、结论、下一步
- [ ] 失败与异常记录保留，没有被删除
- [ ] 可复现四要素（代码、配置、环境、数据）齐全，且换台机器能重跑
