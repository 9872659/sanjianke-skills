# 平台通用说明：鉴权、计费、错误码与异步任务

这份文档是 `SKILL.md` 的**共性事实底稿**。它回答的是「不管你今天调的是
`DeepSeek-V4-Flash` 还是别的在架模型，都成立的那批规则」：Key 怎么管、走哪个入口、
钱怎么算、报错怎么读、异步任务怎么收尾。

**看这份的顺序建议是**：Key 管理 → 两条入口 → 计费口径 → 错误码。
接业务之前把这四块过一遍，能挡掉绝大多数返工。

## 一、鉴权与 Key 管理

所有接口共用同一套鉴权，没有第二种：

```
Authorization: Bearer <你自己的 API Key>
Content-Type: application/json
```

| 事项 | 做法 |
|---|---|
| 在哪创建 | [算力集市](https://api.a7w.cn/) 用户中心的 API Key 页；Key 形如 `sk-...` |
| 怎么传 | 请求头 `Authorization: Bearer sk-...`，**`Bearer ` 后面有一个空格**，掉了就是 401 |
| 包内脚本读取顺序 | `--key` 参数 → 环境变量 `A7W_API_KEY` → `~/.a7w/config.json` |
| 推荐放法 | 长期用环境变量 `A7W_API_KEY`；多 Key / 多环境用 `~/.a7w/config.json` |
| 注意事项 | **不要写进代码、不要提交进版本库、不要放在前端或客户端包里** |

### Key 等同余额

**Key 本身就是扣费凭证。** 拿到一把 Key，等于能花它所属账号的钱。所以：

- **一把 Key 只给一个用途**（一个环境、一项业务、一个人），别到处复制。
- **每把 Key 单独设 quota**（Key 级点数额度）——它是你的止损线。
  打满后返回 402 `key_quota_exceeded`，**这是保护，不是故障**，去用户中心调高即可，不用充值。
- **设 IP 白名单**——只允许你的服务器出口 IP 调用。Key 万一泄露，损失面也被压住。
- **泄露了就删掉重建**，不要试图靠改名补救。

## 二、两条调用入口对照

这是全部接口的顶层分叉，**选错入口是最常见的踩坑**：

| 入口 | 路径 | 形态 | 用途 |
|---|---|---|---|
| **模型网关**（OpenAI 兼容） | `POST /api/v1/chat/completions` | 同步，直接返回 `choices` | 对话、写作、翻译、分类、抽取、代码 |
| **应用任务** | `POST /api/v1/apps/<应用代号>/<接口代号>` | 多为异步，返回 `task_id` | 出图、出视频、配音、数字人、音乐、超分 |

三条硬记忆：

- **模型网关没有 `task_id`。**
- **应用任务不吃 `messages` 数组。**
- 应用任务的路径**永远**是 `/api/v1/apps/<应用代号>/<接口代号>`，两个代号都取自线上返回的 `code` 字段，
  **绝对不要用 `endpoint_path` 字段拼 URL**；应用代号用**下划线**（`voice_tts`），写成连字符会 404。

### 平台端点速查

| 用途 | 方法与路径 |
|---|---|
| 模型清单（实测 75 个） | `GET /api/v1/models` |
| 对话 | `POST /api/v1/chat/completions` |
| 应用清单（实测 21 个） | `GET /api/v1/apps` |
| 单应用 schema | `GET /api/v1/apps/<应用代号>` |
| 应用调用 | `POST /api/v1/apps/<应用代号>/<接口代号>` |
| 任务查询（**免费**） | `GET /api/v1/tasks/<task_id>` |
| 余额 | `GET /api/v1/user/balance` → `{"available_points":...,"currency":"points"}` |

> **业务成功码是 `code == 1`**（`{"code":1,"msg":"success"}`）；`code == 0` 是失败，
> **但 HTTP 仍可能是 200**。判断成败一定要看 `code`，不能只看 HTTP 状态码。

### 地址层数：`/api/v1` 还是 `/api`

同一个平台，两种填法都对，取决于客户端**会不会自己补 `/v1`**：

| 客户端文档里的示例地址 | 填什么 |
|---|---|
| 示例里已经带 `/v1`（例如 `.../v1/chat/completions`） | `https://api.a7w.cn/api/v1` |
| 示例里没有 `/v1`（例如 `.../chat/completions`） | `https://api.a7w.cn/api` |

**判断方法只有这一条**：看它给的示例地址。填错的典型症状是路径里出现 `/api/v1/v1/` 然后 404。

## 三、计费口径

### 3.1 点数

- **1 元 = 100 点，1 点 = 0.01 元。**
- **点数永久有效**，不按月清零，没有月费。
- 充值：**体验包 ¥10 = 600 点**（含 7 天会员权益）；**标准包 ¥99 = 10000 点**。
- **先冻结、后结算**：提交时按预估冻结，完成后按实际用量结算；消费**优先扣会员点数，不足再扣充值额度**。
- **调用失败直接退款；异步任务失败，冻结点数全额退回。**
- **查询任务状态免费。**
- **余额不足返回 402，不产生欠费。**

### 3.2 按能力分类的计量单位

「这个接口多少钱」这句话本身不完整 —— 必须连着**用量口径**一起看：

| 能力类型 | 计费口径 |
|---|---|
| **文本大模型** | **点数 / 百万 tokens**（输入、输出**分别计价**；**流式与非流式同价**） |
| 图像生成 / 编辑 | **点数 / 张**，或按分辨率档位 |
| 视频生成 / 超分 | **点数 / 秒**（分辨率分档） |
| 数字人 / 对口型 | **点数 / 次或时长** |
| 语音 TTS / 音色克隆 | **点数 / 千字** |
| 语音识别 ASR | **点数 / 分钟** |
| 工具类（水印消除等） | **点数 / 次** |

所以预算的正确问法是：「**跑多少次 × 每次大概多少 token**」，
而不是「这个模型多少钱」。

### 3.3 两套价格字段（最容易算错的地方）

平台在每个接口上同时给两套价格字段：

| 字段 | 含义 | 用途 |
|---|---|---|
| `fixed_price` / `input_price` | **公示标准价** | 对外展示、横向比价 |
| `tenant_fixed_points` / `tenant_points_per_1k_input` / `tenant_points_per_1k_output` | **你所在租户的实际结算价** | **做预算只能用它** |

> **两者可能差很多。任何按公示价做的预算都可能错一个数量级。**
>
> **做预算一律读 `tenant_*`，最终以账号里实际扣费为准。**

### 3.4 实测消耗参考

| 场景 | 消耗 |
|---|---|
| `DeepSeek-V4-Flash` 一次普通问答 | 约 **0.74 ~ 0.99 点** |
| 极小调用（`max_tokens=8`） | **0.00 点** |
| 查询任务状态 | **免费** |

> 真实扣费以返回里的 `usage` 与账号账单为准。**先跑几条小请求，看一眼点数变化，再估算批量成本**——
> 别拿别人的截图当预算。

## 四、成本控制（针对「用 DeepSeek 跑量」）

跑量的账不是靠砍单价省的，是靠**少花不该花的 token**。四条按收益排序：

| 做法 | 为什么有效 | 怎么落地 |
|---|---|---|
| **1. 压 `max_tokens`** | 输出按实际生成量计费，上限给大了开放式问题就会一路写下去 | 知道答案大概多长，就把上限卡在 **1.5 倍**左右；**推理型号不低于 256**（给太小正文会是 `null`） |
| **2. 日常走 `-Flash` 线，难题才切 `-Pro` 线** | 两档定位不同，日常问答用旗舰档是纯浪费 | 全量默认 `DeepSeek-V4-Flash`；只有「答不好要返工」的场景切 `DeepSeek-V4-Pro` |
| **3. 长文档先摘要再问** | 整篇长文每次请求都重复进上下文，等于为同一段字反复付钱 | 长文**先摘要一次**，后续问答都带摘要；确实需要全文的题才带全文 |
| **4. 批量任务用回调代替高频轮询** | 查询虽然免费，但高频轮询白占并发，容易撞 429 | 提交时带 `callback_url`，被通知后再取结果；非要轮询就拉长间隔（≥5 秒） |

另外两条同样有效但常被忽略：

- **精简 `system` 提示。** 它每次请求都随上下文计费，长系统提示是隐形开销。
- **长对话做摘要。** 不要把几十轮历史原样每次都发上去。

判断依据：**如果同一条信息会被重复发上去 N 次，它就是 N 倍成本。**
摘要、裁剪、缓存都是围绕这一条做的。

## 五、错误码全表

| HTTP | code | 含义 | 怎么办 |
|---|---|---|---|
| 400 | `invalid_request` | 参数缺失或格式错误 | 用 schema 核对参数名与必填项 |
| 401 | `auth_failed` | API Key 缺失或无效 | 重新复制 Key，确认 `Bearer ` 前缀 |
| 402 | `insufficient_points` | **账号**点数余额不足 | 充值；错误里带本次所需点数 |
| 402 | `key_quota_exceeded` | **该 Key 自己的**额度打满 | 去用户中心调高该 Key 的 quota，**或换 Key** |
| 403 | `permission_denied` | 该 Key 无权调用此模型 / 应用 | 检查模型是否已开通、Key 是否被限权、IP 白名单是否匹配 |
| 404 | `not_found` | 模型 / 应用 / 任务不存在 | 核对代码拼写；**先怀疑 `/v1` 层数** |
| 429 | `queue_limit_exceeded` | 排队任务已达上限 | 降并发，等队列消化后重试 |
| 5xx | `server_error` | 服务异常 | 退避重试；仍失败换模型 / 线路 |

**两条容易读错的：**

- **两个 402 是不同的事。** `insufficient_points` 是账号没钱，去充值；
  `key_quota_exceeded` 只是这把 Key 的额度满了，**去调 quota，不用充值**。
- **403 和余额无关。** 它是权限问题（模型未开通、Key 被限权、IP 白名单不匹配）。

### 重试策略

| 情况 | 重试吗 |
|---|---|
| 400 / 401 / 402 / 403 / 404 | **不重试**，重试只是浪费请求 |
| 429 | 重试，指数退避 + 抖动（1s → 2s → 4s → 8s） |
| 5xx | 重试，同样退避；持续失败换模型或换线路 |
| 提交类异步任务超时 | **先查 `task_id` 再决定**，不要裸重提 |

包内 `scripts/a7w.py` 已经把这套策略编进去了：网络类错误与 5xx 退避重试 **4 次**，
4xx 是业务错误不重试；`call` 遇到返回里有 `task_id` 会**自动轮询到终态**。

> **最贵的一类 bug：把「没收到响应」当成「没提交成功」，于是重提。**
> 提交类调用要么先落盘记录、要么先查 `task_id`，二选一。

## 六、异步任务与回调要点

绝大多数生成类接口是异步的，收尾方式有两种，**两种都建议做幂等**。

### 6.1 轮询

```
提交 → {"task_id":"tsk_xxx","status":"pending","created_at":...}
查询 → GET /api/v1/tasks/<task_id>        （免费）
```

| 项 | 说明 |
|---|---|
| 终态 | `completed` / `failed` / `cancelled` —— **只有这三个是终态，其余都还在跑** |
| 产物 | 在 `result` 字段里 |
| 用量 | 在 `usage` 字段里，核对预算就看它 |
| 轮询间隔 | 建议 ≥5 秒，不要高频打 |

### 6.2 回调

提交时带 `callback_url`，平台完成后会 POST 一份 JSON 到你的地址：

- 你的接口**必须返回 2xx**，才算接收成功；
- 没收到 2xx 就按「用户中心 → 回调配置」里设的次数重试，**1~10 次**；
- **所以消费端必须按 `task_id` 幂等** —— 同一份结果可能被投递多次，
  你的下游不能因此重复登记、重复发货、重复入库。

### 6.3 提交时就冻结，别重复提交

**提交的瞬间就预冻结点数。** 因此：

- 同一件事**只提交一次**；
- 超时了**先查 `task_id`**，确认没成再决定是否重提；
- 每批任务本地落盘记录 `task_id` + 提交时间，对账时才有依据。

## 七、权限与联网边界

| 能力 | 是否申请 | 用途 |
|---|---|---|
| 网络访问 | **申请** | 调用 `api.a7w.cn` 的网关接口（唯一的联网行为） |
| 读取文件 | 仅读取你指定的输入文件 | 用作请求体或素材入参 |
| 写入文件 | 仅在传入 `--out` 时 | 保存返回的 JSON |

**不内嵌任何密钥。** 请求只发往 `api.a7w.cn`，不发送到其他任何地址。
