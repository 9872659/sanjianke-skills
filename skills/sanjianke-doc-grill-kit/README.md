# 三剪客 · 带资料追问 Skill

先把资料读成事实索引，再基于索引逐条追问，标出矛盾与缺口

---

## 前置条件

- 一份明确的资料清单：一个目录（默认 `_data/`）或一组文件路径
- 一句本次追问想解决的核心问题，写在对话里就算
- 资料已转成可读文本：Markdown / txt / docx 导出的文本 / 带文本层的 PDF 皆可
- 扫描件、图片、加密文档需你先 OCR 或导出，本 Skill 不解析这类格式
- 一个可读写的本地目录，用来放 `_grill/` 工作区
- 不需要网络，不需要 API Key，不需要安装任何服务

---

## 使用

最小可用路径是「先立工作区 → 建索引 → 追问 → 扫矛盾与缺口」四步：

```text
_data/                      # 你放资料的地方，本 Skill 只读
_grill/                     # 所有产物都写在这里
├─ 01-资料总览.md           # 来源、时间、版本、权威等级、覆盖矩阵
├─ 02-事实索引.md / .json   # 一条事实一张卡，带编号与原文锚点
├─ 03-问题卡.md             # 每个问题挂事实编号
├─ 04-矛盾台账.md           # 资料互相打架的地方
└─ 05-缺口台账.md           # 资料没说、但绕不过去的地方
```

**第 1 步 分诊**：给每份资料标权威等级（L0 合同 → L4 二手转述）与时间，
做一张覆盖矩阵，找出「只有一份资料撑着」和「零覆盖」的主题。

**第 2 步 建索引**：逐份抽事实，每条必须能回指到具体出处；数值单独成卡。
抽完**随机抽检 10 条比对原文**——`引文错`、`语义漂移`、`凭空生成` 合计为 0 才算通过。
这一步不建议省。

**第 3 步 追问**：问题必须挂事实编号（`F-xxxx`），或明确标为缺口问题。
每个问题都要摊出原文短引，让别人三十秒内能验掉。

**第 4 步 扫矛盾与缺口**：按信号扫矛盾，按清单扫缺口，两者分开记账，
**只发现不定性**，裁决留给人。

三份参考文件分别对应第 1、3、4 步：

| 文件 | 用途 |
|---|---|
| `references/01-资料预处理与事实索引.md` | 分诊、分片、事实卡规范、编号法、两段式索引、抽检验收 |
| `references/02-基于索引的追问流程.md` | 四层防编造闸门、七类问法、问题卡模板、排序与止损 |
| `references/03-矛盾点与缺口检查清单.md` | 矛盾五型判定、八类缺口扫描、优先级与核对渠道 |

## 依赖

- 模型本身的阅读与归纳能力；不依赖任何外部 API
- 盘点目录时可选用 `find` / `Get-ChildItem`；统计卡数时可选用 `jq`。两者都是可选，不用也能跑
- 产物是纯 Markdown 与 JSON，任何编辑器都能打开，也可以直接进 Git

---

## 安全

- 不内嵌任何密钥
- 不联网、不上传：资料始终留在你的本地目录里
- 只读你指定的资料目录，不主动遍历工作区其它位置
- 只在 `_grill/` 下新建文件，不修改、不删除任何原始资料
- 资料里出现密钥、口令、内网地址、手机号时，索引中一律打码，只保留「此处有凭证」的记录
- 事实索引与问题卡是对原文的重述，**默认按资料本身的密级处理**，
  不要把它们复制到聊天窗口、外部工具或公开仓库
- 本 Skill 不替代法务、财务或合规意见
