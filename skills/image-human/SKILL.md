# AI 数字人 · 全驱动口播视频

**一张照片 + 一段录音 = 一条口播视频。**

不用架机位、不用出镜、不用背稿、不用后期剪辑。给了人物图片和驱动音频，
平台就能生成自然稳定的数字人视频——口型、表情、肢体一起动。

| 你最关心 | 答案 |
|---|---|
| 多少钱 | **最低 1.5 点/秒 = 0.015 元/秒**（1 元 = 100 点） |
| 一条 60 秒口播 | **最低 90 点 = 0.90 元**（fast 档） |
| 要多清晰 | 四档：`fast` / `standard` / `2k` / `4k`，价格差 5.3 倍，**先算钱再选档** |
| 要多久 | 异步任务，提交后轮询；`query` 免费 |
| 要装什么 | **什么都不用装**。零依赖 Python 客户端只用标准库，或者直接用 `curl` |

**没有 Key 先去领**：[算力集市 api.a7w.cn](https://api.a7w.cn/) 注册（新用户有赠送点数，
可以先白跑几条试试）。完整步骤见 [`references/getting-started.md`](references/getting-started.md)。

## 一、一条视频多少钱（分档计费）

**按驱动音频的时长计费**，不同清晰度档位单价不同。四档的真实价格：

| `mode` | 档位 | 点/秒 | 折合 | **60 秒视频** | 120 秒视频 |
|---|---|---|---|---|---|
| `fast` | 快速模式 | **1.5** | **0.015 元/秒** | **90 点 = 0.90 元** | 180 点 = 1.80 元 |
| `standard` | 标准模式（默认） | 2 | 0.02 元/秒 | 120 点 = 1.20 元 | 240 点 = 2.40 元 |
| `2k` | 高清模式 | 4 | 0.04 元/秒 | 240 点 = 2.40 元 | 480 点 = 4.80 元 |
| `4k` | 超清模式 | 8 | 0.08 元/秒 | 480 点 = 4.80 元 | 960 点 = 9.60 元 |

> **`fast` 到 `4k`，单价差 5.3 倍。** 同一段 60 秒音频，`fast` 花 0.90 元、
> `4k` 花 4.80 元。**先想清楚这条片子发在哪**，再选档 —— 这是这个接口最容易花冤枉钱的地方。

**`query` 查询任务免费**，可以放心轮询。

> ⚠️ 价格来自接口的 `pricing_matrix`（`fast:1.5 / standard:2 / 2k:4 / 4k:8`）。
> 平台另有标准价与智能路由后的结算价，**以你账号里实际扣费为准**。

## 二、四档清晰度怎么选

| 你的用途 | 建议档位 | 理由 |
|---|---|---|
| 抖音 / 小红书 / 视频号竖版口播 | **`fast` 或 `standard`** | 平台本身会二次压缩，4K 上传后也看不出来 |
| 批量铺矩阵号、先测脚本 | **`fast`** | 成本压到最低，跑量首选 |
| 正式投放素材、品牌片 | **`standard`** | 性价比平衡点，多数场景够用 |
| 大屏播放、官网宣传片、二次剪辑素材 | **`2k`** | 留出裁剪与放大余量 |
| 影院 / 展馆 / 需要交付母版 | **`4k`** | 只有真需要母版时才值得 |

**一句话原则**：**发布平台会压缩的，就别买 4K。** 需要留后期余量的，才往上升档。

## 五、操作文档：怎么调用

### 零安装用法（推荐先看这个）

本 Skill 自带一个只用 Python 标准库的客户端，**不需要装任何第三方包**：

```bash
# 1. 配置你自己的 API Key（只需一次）
export A7W_API_KEY=sk-你的key

# 2. 看这个插件的接口与参数
python3 scripts/client.py schema image_human

# 3. 提交任务（异步，客户端会自动轮询到结束）
python3 scripts/client.py call image_human submit \
  --json '{
    "file_url": "https://你的存储/人物照片.png",
    "ref_file_url": "https://你的存储/口播录音.mp3",
    "mode": "standard"
  }'
```

### 直接 curl

```bash
# 提交任务
curl -sS -X POST "https://api.a7w.cn/api/v1/apps/image_human/submit" \
  -H "Authorization: Bearer $A7W_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "file_url": "https://你的存储/人物照片.png",
    "ref_file_url": "https://你的存储/口播录音.mp3",
    "mode": "standard"
  }'

# 拿返回的 task_id 查结果（免费）
curl -sS -X POST "https://api.a7w.cn/api/v1/apps/image_human/query" \
  -H "Authorization: Bearer $A7W_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"task_id":"<上一步返回的 task_id>"}'
```

提交成功返回形如：

```json
{ "task_id": 123, "status": "pending" }
```

`client.py call` **默认自动轮询到结束**；加 `--no-wait` 只提交不等。

## 六、素材要求（决定成败）

这个接口只有两个必填参数，但**质量全压在这两份素材上**。

### `file_url` · 人物图片

| 要求 | 说明 |
|---|---|
| 类型 | **公网可访问的图片 URL**，不支持本地路径、不支持 Base64 |
| 数量 | **≤ 1 张**（`max_reference_images: 1`） |
| 建议 | 正面、清晰、五官无遮挡、光线均匀的半身或胸像；**眼睛要看镜头** |
| 避免 | 侧脸、大墨镜、强逆光、多人合影、低分辨率截图 |

### `ref_file_url` · 驱动音频

| 要求 | 说明 |
|---|---|
| 类型 | **公网可访问的音频 URL** |
| 作用 | 数字人的口型与表情跟着这段音频走 |
| **计费** | **平台按这段音频的时长计费** —— 音频多长，钱就是多少 |
| 建议 | 单人、干净、无背景音乐；语速平稳；和你要的口播稿一致 |

> **音频长度直接等于成本。** 提交前先用 `ffprobe` 看一下时长，心里有数：
> ```bash
> ffprobe -v error -show_entries format=duration -of default=noprint_wrappers=1:nokey=1 录音.mp3
> ```
> 没装 ffmpeg 的话，把 `duration` 参数显式传进去也行 —— 不传时平台会自己去音频地址探测。

### `prompt` · 可选提示词

不传就用默认值：**「人物说话自然，面对镜头，肢体语言自然，人物清晰可鉴。」**

大多数情况不用改。想让神态更放松 / 更正式，可以在这里微调。

## 七、完整流程：从一张照片到能发的视频

```bash
KEY=sk-你的key
API=https://api.a7w.cn/api/v1/apps/image_human

# ① 先量一下音频多长（决定这条片子的成本）
ffprobe -v error -show_entries format=duration \
  -of default=noprint_wrappers=1:nokey=1 口播录音.mp3
# 假设是 58.2 秒 → standard 档 = 58.2 × 2 ≈ 117 点 ≈ 1.17 元

# ② 提交任务
curl -sS -X POST "$API/submit" -H "Authorization: Bearer $KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "file_url": "https://你的存储/人物照片.png",
    "ref_file_url": "https://你的存储/口播录音.mp3",
    "mode": "standard",
    "duration": 58.2
  }'
# → 记下 task_id

# ③ 查结果（免费，可以循环轮询）
curl -sS -X POST "$API/query" -H "Authorization: Bearer $KEY" \
  -H "Content-Type: application/json" -d '{"task_id":"<task_id>"}'
```

**批量做矩阵号**：把「一张主图 + N 段文案音频」组合起来循环提交即可。
建议**先用 `fast` 档把 N 条全跑一遍测脚本**，确认哪条数据好，
再单独把那条用 `standard` / `2k` 重跑一遍发布 —— 比一上来全部 `2k` 省得多。

## 八、常见坑

| 坑 | 表现 | 怎么避 |
|---|---|---|
| **选错档位** | 成本差 5.3 倍 | 发布平台会压缩的，`fast` / `standard` 就够了；只有要留后期余量才上 `2k` / `4k` |
| **拿本地路径当入参** | 报参数错误 | 图片和音频都必须是**公网可访问的 URL**，不支持本地路径、不支持 Base64 |
| **以为 `resolution` 是新参数** | 传了不生效 | `resolution` 只是**兼容别名**（传 `2k` / `4k` 等价于 `mode`），**新接入直接用 `mode`** |
| **音频太长没预算** | 扣费超预期 | 计费 = 音频时长 × 档位单价。**提交前先 `ffprobe` 量时长** |
| **不传 `duration`** | 一般没事，但平台要自己去探测 | 已知时长就直接传，少一次探测、计费更可预期 |
| **传了多张参考图** | 只认第一张 / 报错 | **参考图 ≤ 1 张**，这是接口硬限制 |
| **重复提交异步任务** | 扣两次钱 | 提交后先记下 `task_id`，用 `query`（免费）确认状态 |
| **图片侧脸 / 遮挡** | 口型与表情崩坏 | 用正面、清晰、看镜头的照片 |
| **长音频任务先超时** | 客户端超时，服务端其实还在跑 | 加长超时，或 `--no-wait` 只提交、之后手动 `query` |
| **拿 `code == 0` 判断成功** | 明明成功却判成失败 | **这个平台的成功码是 `1`**（`{"code":1,"msg":"success"}`） |
