# 三剪客 · 极速文件查找

`find` 的问题是它的语法：想按名字找文件要写 `find . -iname '*关键词*' -type f`，还得记住 `-iname`、`-type`、`-path` 这些开关，而且找完文件想顺手做点什么（批量格式化、批量看行数）又得再接一层 `-exec` 或 `xargs`。

`fd` 把这件事压成一句话：`fd 关键词`。名字里的模式默认就是子串匹配（不用手动加 `**`），大小写默认智能、默认忽略隐藏文件和 `.gitignore` 里的东西——这几条默认值刚好是 80% 场景想要的，剩下的 20% 用开关覆盖。

**上游项目**：`fd`　**仓库**：https://github.com/sharkdp/fd

## 什么时候用 / 不用

**用它**：

- "这项目里所有 `.spec.ts` 文件列一下。"——`fd -e spec.ts`，扩展名过滤是它最常用的开关。
- "找出所有超过 100MB 的文件，看看是不是把构建产物提交进去了。"——`fd -S +100M -t f`。
- "最近两小时改过的文件有哪些。"——`fd --changed-within 2h`。
- "把这个目录下所有 `.jpg` 转成 `.png`。"——`fd -e jpg -x convert {} {.}.png`，`{}` 与 `{.}` 是内置占位符。
- "把所有命中的文件一次性交给一个命令处理。"——`fd -e rs -X wc -l`，比 `-x` 少起很多进程。
- "我想找的东西可能被 `.gitignore` 排除了，或者藏在隐藏目录里。"——`fd -u 关键词` 等价于 `--hidden --no-ignore`，一次性放开。
- "路径太深看不全，想连同目录结构一起匹配。"——`fd -p 关键词` 让模式匹配整条路径，而不是只匹配文件名。

**不要用它**：

- **要按 inode、挂载点、ACL、SELinux 标签这类元数据做复杂筛选**——`fd` 的筛选维度是有意做窄的，官方定位就不追求覆盖 `find` 的全部能力；这种需求用 `find` 或专门的工具。
- **要在非 git 仓库里依赖 `.gitignore` 生效**——默认只有当 fd 检测到你在一个 git 仓库里时才应用 gitignore 规则，仓库外要用得显式加 `--no-require-git`。
- **要跨整个文件系统做全量扫描**（比如 `fd 关键词 /` 找系统文件）——虽然能用，但会遍历到大量无关目录，还可能触发权限错误；这类活更适合专用索引工具（如 locate 类）。
- **要对文件名做替换、重命名、内容改写**——fd 只负责找到并可选地执行命令，"怎么改"由你给的那条命令决定，它自己不提供编辑能力。
- **要交互式挑选结果**——fd 本身不提供选择界面；通常的做法是把结果管道给模糊选择器（如 fzf）。
- **在 Debian / Ubuntu 上直接敲 `fd`**——这两个发行版因为与别的包重名，可执行文件被改叫 `fdfind`，直接敲 `fd` 会 command not found。

## 安装

各平台最常见的入口如下。Debian / Ubuntu 上的包名与可执行文件名为 `fd-find` / `fdfind`。

```bash
# Debian / Ubuntu（注意装完之后命令叫 fdfind）
sudo apt install fd-find

# Arch
sudo pacman -S fd

# Fedora
sudo dnf install fd-find

# macOS
brew install fd

# Windows
winget install sharkdp.fd
scoop install fd
choco install fd

# 已经装了 Rust 工具链：从源码编译
cargo install fd-find

# 没有包管理器的环境：从官方 Releases 页下载对应平台压缩包，
# 解压后把 fd 放到 PATH 里即可（fd 是单文件可执行程序）
```

装完验证：

```bash
fd --version
fd --help | head -n 20
```

如果你的发行版把命令改成了 `fdfind`，可以自己加个别名，或直接习惯用 `fdfind`：

```bash
# Linux/macOS：加到 shell 配置里
alias fd='fdfind'
```

## 常用操作

**1. 最基础的一条：按名字找**

```bash
fd needle                     # 当前目录下文件名含 needle 的条目
fd needle /var/log            # 在指定目录里找
fd '^test_' --type f          # 正则模式（默认就是正则），只找普通文件
fd .                          # 列全部条目（相当于把模式写成"匹配一切"）
```

**2. 按扩展名 / 类型 / 深度筛选**

```bash
fd -e py                      # 所有 .py 文件（可重复：-e py -e pyi）
fd -t d                       # 只要目录
fd -t f -t l                  # 文件与符号链接都要（同选项可重复）
fd -t x                       # 可执行文件
fd -t e -t f                  # 空文件
fd -d 2                       # 最多往下两层
fd --exact-depth 2            # 正好第二层
```

`-e` 的过滤默认对文件和目录都生效，要限定范围就再叠 `-t`。

**3. 排除、忽略与"什么都别忽略"**

```bash
fd -E node_modules -E '*.min.js'      # 排除指定目录/通配
fd -H                                 # 带上隐藏文件与目录
fd -I                                 # 不理会 gitignore / .ignore / .fdignore
fd -u                                 # = --hidden --no-ignore，全都放开
fd --no-ignore-vcs                    # 只忽略 .gitignore，不忽略 .ignore/.fdignore
fd --ignore-file .myignore            # 额外挂一个 gitignore 格式的忽略文件
```

**4. 按大小与修改时间筛选**

```bash
fd -S +100M                   # 大于 100MB
fd -S -10k                    # 小于 10KB
fd --changed-within 2h        # 最近两小时改过
fd --changed-before 2025-01-01
fd --newer 2weeks             # --changed-within 的别名
```

单位区分十进制与二进制：`k`/`m`/`g` 是 1000 进制，`ki`/`mi`/`gi` 是 1024 进制。

**5. 把结果交给别的命令**

```bash
fd -e jpg -x convert {} {.}.png          # 每个结果执行一次（并行）
fd -e h -e cpp -x clang-format -i        # 批量格式化
fd -e rs -X wc -l                        # 所有结果作为参数传给一条命令
fd -0 -e txt -x stat                     # 用 \0 分隔输出，方便再喂给 xargs
fd --format '{//}' -t f | sort -u        # 只输出父目录，做去重统计
```

占位符：`{}` 是完整路径、`{/}` 是文件名、`{//}` 是父目录、`{.}` 是去掉扩展名的路径、`{/.}` 是去掉扩展名的文件名。想让 `-x` 顺序执行就配 `--threads=1`。

**6. 脚本友好的两个开关**

```bash
fd -q pattern && echo "存在"    # 不打印结果，只给退出码：有匹配=0，无匹配=1
fd -1 pattern                   # 只取第一条结果就退出
fd --max-results 5 pattern      # 最多要 5 条
```

`-q` 比"先输出再判断是否有内容"更快，因为它一命中就能停。

## 常见坑

| 现象 | 原因 | 怎么办 |
|---|---|---|
| `fd: command not found`，但包管理器说装成功了 | Debian / Ubuntu 上因为文件名冲突，可执行程序被改名为 `fdfind` | 用 `fdfind`，或自己加 `alias fd='fdfind'` |
| 明明有这个文件，`fd 关键词` 就是找不到 | 默认不进入隐藏文件和目录，也默认按 gitignore 规则排除 | 加 `-H` 收进隐藏项、加 `-I` 忽略 gitignore，或一步到位 `-u` |
| 在非 git 目录里 `.gitignore` 不生效 | 默认只有检测到在 git 仓库内时才应用 gitignore 规则 | 加 `--no-require-git`；想反过来强制要求 git 仓库则用 `--require-git` |
| `fd '*.py'` 什么也没匹配到 | 默认模式是**正则**，`*` 在正则里表示"前一个字符重复零次或多次"，不是通配符 | 想用通配语义就加 `-g`（`fd -g '*.py'`），或干脆写 `fd -e py` |
| `fd -g 'a/**/b'` 行为不符合预期 | `**` 只在配合 `--full-path` 时才跨路径层级匹配 | 要跨层匹配就加 `-p`：`fd -g -p 'src/**/test_*.py'` |
| 大小写明明写了，结果却大小写不敏感 | fd 默认"智能大小写"：模式里全小写就不区分大小写，含大写才区分 | 想强制区分加 `-s`；想强制不区分加 `-i` |
| 输出带颜色、带转义序列，塞进管道就乱了 | 颜色默认只在输出到终端时开启（`--color auto`） | 管道里保持默认即可；如果被强制染色就设 `--color never`，或直接用 `NO_COLOR` 环境变量 |
| 输出路径前面多了 `./`，喂给别的命令时出问题 | 使用 `-x` / `-X` / `-0` 时，相对路径会加 `./` 前缀，避免路径以 `-` 开头被当成选项 | 用 `--strip-cwd-prefix` 控制（`always` / `never` / `auto`） |
| `-x` 里的命令参数被 fd 吃掉了 | fd 后面的位置参数都被当成命令参数，`-x` 之后的选项不再属于 fd | 把 `-x` 放在命令末尾；要再给 fd 传选项就用 `\;` 结束参数列表（多数 shell 里要转义成 `\;`） |
| `-x` 批量执行的结果顺序每次都不同 | `-x` 默认按 CPU 核数并行，`-X` 的参数顺序也明确不保证 | 需要顺序就加 `--threads=1`，并且不要依赖结果顺序做逻辑 |
| 遍历时一堆 permission denied | 遍历过程遇到的权限错误默认不打印，但确实是遇到了 | 加 `--show-errors` 把这类错误显式暴露出来，别把它当成"没有匹配" |
| 想让 `-X` 限制每次传多少个参数 | 默认批量大小是 0（不限制） | 用 `--batch-size N` 控制；注意受操作系统命令行长度上限影响，仍可能自动分批 |
| 跑到别的挂载点去了，很慢 | 默认会一直往下遍历，不区分文件系统 | 加 `--one-file-system`（别名 `--mount`、`--xdev`）限制在本文件系统内 |
| `--changed-within 2h` 和预期的时间对不上 | 时间参数支持多种写法：时长（`10h`、`1d`、`35min`）、RFC3339、本地时间 `YYYY-MM-DD`、`@秒` 时间戳 | 先用明确的时间点写法排除歧义；相对时长的解释以本机 `fd --help` 为准 |
| 全局忽略关不掉 | 全局忽略文件的优先级与 `--no-ignore*` 的组合规则容易记混 | 记住三档：`--no-ignore-vcs` 只放开 git 相关规则、`-I` 放开全部忽略规则、`-u` 再叠加隐藏文件 |

## 权限与用途说明

| 能力 | 是否申请 | 用途 |
|---|---|---|
| 网络访问 | 否 | 安装时包管理器或 cargo 需要联网；查找全程本地离线，不发起任何网络请求 |
| 读取文件 | 是 | 需要遍历目录元数据（名称、类型、大小、修改时间），并读取 `.gitignore` / `.ignore` / `.fdignore` / 全局忽略文件 |
| 写入文件 | 否 | fd 自身只往标准输出打印结果，不写任何文件；只有你通过 `-x` / `-X` 指定的命令才可能写文件 |
| 凭证 | 否 | 不需要账号、token 或 API Key |
| 子进程 / 后台常驻 | 是（条件性） | 只有在使用 `-x` / `-X` 时才会创建子进程去执行你给的命令，且是并行/批量执行；fd 本身是一次性命令，无常驻服务 |

- "找出最近改过的那几个文件。"
- "这个目录下有没有超过 100MB 的文件？"
- "把这些文件批量格式化一下。"
- "为什么我 `find` 出来的结果和预期不一样，有没有更简单的写法？"

## 能力边界

**覆盖**：

- 匹配方式：正则（默认）、glob（`-g`）、字面量（`-F`）、整名精确（`--exact`）、多模式与（`--and`）、整路径匹配（`-p`）
- 筛选维度：类型（`-t`，含 f/d/l/b/c/s/p/x/e）、扩展名（`-e`）、深度（`-d` / `--min-depth` / `--exact-depth` / `--prune`）、大小（`-S`，支持十/二进制单位）、修改时间（`--changed-within` / `--changed-before` 及别名）、属主（`-o`）、挂载点（`--one-file-system`）
- 忽略控制：`-H` / `-I` / `-u` / `--no-ignore-vcs` / `--no-ignore-parent` / `--require-git` / `--ignore-file`，识别 `.gitignore`、`.git/info/exclude`、全局 git 忽略、`.ignore`、`.fdignore`、全局 fd 忽略文件
- 输出：彩色输出（`--color`）、超链接转义（`--hyperlink`）、自定义模板（`--format`，含 `{}` / `{/}` / `{//}` / `{.}` / `{/.}`）、NUL 分隔（`-0`）、绝对路径（`-a`）、详细列表（`-l`）、路径分隔符（`--path-separator`）
- 执行：`-x` 逐个并行执行、`-X` 批量执行、`--batch-size` 控制批量、占位符替换
- 脚本友好：`-q` 只给退出码、`-1`、`--max-results`、`--show-errors`
- 性能与遍历：多线程（`-j` / `--threads`）、默认不跟随符号链接（`-L` 可开启）

**不覆盖**：

- 文件内容搜索（找"哪个文件里有这段话"要用 ripgrep 这类工具，`fd` 只看路径与元数据）
- 按 inode 号、访问控制列表、安全标签等做筛选；官方定位并非完整复刻 `find`
- 文件内容的修改、重命名、批量替换——`-x` / `-X` 只是把你给的命令跑起来
- 交互式结果选择界面（需要接模糊选择器）
- 对已删除目录的索引式秒查（那是 locate 类工具的能力，`fd` 每次都真实遍历）
- 跨机器的远程查找

## 依赖条件

- 官方提供 Windows / macOS / Linux（含 musl 静态构建）各架构的预编译发行包，是单文件可执行程序，不需要运行时
- 走包管理器安装时，版本以该发行版/包管理器的仓库为准（不同系统的版本差距可能较大，先用 `fd --version` 确认）
- 从源码构建需要 Rust 工具链（`cargo install fd-find`）
- 不需要账号、Key 或任何网络服务
- 终端支持彩色输出时体验更好；管道场景下颜色默认关闭
- Windows 上需注意原生路径分隔符与 shell 的参数转义差异

## 已知限制

1. Debian / Ubuntu 上可执行文件名是 `fdfind`，与上游示例不一致。
2. 默认模式是正则而不是 glob，带 `*` 的模式容易写出反直觉的结果。
3. 默认忽略隐藏项与 gitignore 内容，且 gitignore 只在 git 仓库内生效（除非加 `--no-require-git`）。
4. `-x` 并行执行与 `-X` 批量传参都不保证结果顺序。
5. `**` 跨路径层级匹配只在配合 `--full-path` 时有效。
6. 遍历时遇到的权限类错误默认静默跳过，需要 `--show-errors` 才可见。
7. 具体开关在不同版本间可能有增删，以本机 `fd --help` 与上游文档为准。

## 自检清单

执行前：

- [ ] `fd --version` 确认命令名（Debian/Ubuntu 上是 `fdfind`）
- [ ] 想清楚要不要带 `-H` / `-I` / `-u`：目标文件是不是隐藏的、是不是被 gitignore 排除了
- [ ] 模式里含 `*`、`?`、`.` 时先确认默认的正则语义是不是你要的；要通配就加 `-g`
- [ ] 结果要给 `-x` / `-X` 执行时，先不带执行开关跑一遍，确认命中集合正确
- [ ] 涉及删除、覆盖类命令时，先用 `-1` 或 `--max-results 3` 在少量结果上试跑
- [ ] 遍历范围是不是应该限制在单一文件系统（`--one-file-system`）

执行后：

- [ ] 结果数量与预期是否吻合；数量为 0 时先怀疑忽略规则而不是"文件不存在"
- [ ] 用 `-q` 做判断的脚本要确认退出码语义（有匹配为 0，无匹配为 1）
- [ ] 需要顺序的批量操作是否加了 `--threads=1`
- [ ] 管道场景下输出是否混入颜色转义；必要时 `--color never`
- [ ] 用 `-x` 跑过破坏性命令后，抽查几个文件确认结果
