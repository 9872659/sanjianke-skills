# 三剪客 · 开源协作工作空间 Skill

AppFlowy：开源协作工作空间 的安装、常用命令与避坑要点

---

## 前置条件

- **只用客户端**：按平台从官方渠道拿安装包即可，不需要服务端，也不需要命令行。移动端对系统版本有要求。
- **要自托管**：宿主机装好 Docker 与 Docker Compose；准备好一个域名（内网试用可用 IP）与 HTTPS 证书；宿主机能开放 80 / 443，或你自行改端口。
- **要有备份习惯**：数据库、对象存储目录、`.env` 与 compose 文件需要一起备份，缺一项恢复时都会缺数据。
- 需要自备一组凭据：数据库口令、对象存储 Access Key、认证签名密钥、后台管理员账户。

---

## 使用

1. 先判断目标形态：只是自己用 → 装客户端；团队要独立域名和数据主权 → 自托管。
2. 自托管按官方路径来：克隆自托管仓库 → `cp deploy.env .env` → 改凭据与域名 → `docker compose up -d`。
3. 服务起来后按路径进入各模块：`/` 主应用、`/web` 用户管理、`/pgadmin` 数据库面板、`/minio` 对象存储、`/portainer` 容器管理。
4. 客户端在登录页选择自托管入口，填部署好的地址。
5. 上线前过一遍 SKILL.md 里的自检清单，尤其是默认口令与 WebSocket 地址两项。

完整能力清单、部署变量表与避坑要点见 `SKILL.md`。

---

## 依赖

- 客户端：各平台原生运行时，随安装包分发。
- 自托管：Docker + Docker Compose。
- 自托管组件：PostgreSQL、Redis、S3 兼容对象存储（默认 MinIO）、认证服务、反向代理与后台任务，均由官方 compose 编排。
- 客户端的源码构建另需 Flutter 与 Rust 工具链，按官方开发文档准备。
- 可选外部服务：大模型接口（AI 能力）、SMTP（邮件确认）、OAuth / SAML 提供商（第三方登录）、实时转写服务。

---

## 安全

- 不内嵌任何密钥
- 默认口令（数据库、对象存储、JWT 密钥、管理员账户）必须在首次启动前全部替换，官方模板里的值是公开的。
- `.env`、compose 文件与数据库备份都含敏感信息，不要提交进版本库，也不要放在能被公网访问的目录。
- 自托管实例不要在没有 HTTPS 的情况下对公网开放；实时同步通道用 `wss://`。
- 服务端的当前发行版是闭源商业版本，使用前请自行确认授权范围与档位限制符合你的场景。
- 附件与协作数据存在你自建的对象存储里，备份与访问控制在部署方这一侧。
