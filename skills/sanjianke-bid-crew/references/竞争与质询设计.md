# 竞争与质询设计

本文件说明本包**最关键**的一层：怎么保证"竞争"真的发生了，
而不是"三个角色各写一段然后合并"。后者是协作，不是竞争 ——
如果做成那样，这个包就退化成了流水线式 L3，白做。

---

## 一、信息隔离：propose 阶段三组互相不可见

`propose` 是**三次独立调用**。每次的提示词里只有：

- 任务书全文
- 本组自己的取胜路线、天然倾向、最不能让步的一点、肯牺牲什么、盯的点

**没有**另外两组的任何文字，**也没有评分维度与权重**。

### 为什么连评分维度都不给提案组看

如果三组都照着同一把尺子优化，它们会**收敛成同一个形状** ——
都写足成本算式、都补验收口径、都加差异声称。三份方案会越来越像，
而"像"正好是闸门五要抓的假竞争。

让三组各自按自己的路线走到极致，评委再按尺子量 —— 这才是竞标。
差异来自"路线不同"，不是来自"谁更会猜评分标准"。

### 隔离证据是本地核对出来的，不是声明的

`propose` 与 `run` 会在产物里写 `isolation`：

```json
{
  "teams": {
    "team_a": {
      "prompt_chars": 3412,
      "prompt_sha": "…",
      "other_teams_in_prompt": [],
      "rubric_in_prompt": false
    }
  },
  "stage_inputs": {
    "propose": ["task", "own_stance"],
    "score": ["task", "all_proposals_anonymous"],
    "challenge": ["task", "own_proposal", "own_judge_feedback", "rival_digests_only"],
    "award": ["task", "all_proposals", "panel", "challenges_answers"]
  }
}
```

`other_teams_in_prompt` 是**真搜出来的**：把另外两组的 id / 显示名 / label
在提示词里搜一遍，命中就列出来（空数组 = 干净）。
`rubric_in_prompt` 同理，检查四个维度的名字有没有漏进提案提示词。
`run` 还会把逐条核对结果打到 stderr，供当场确认。

## 二、交叉可见性：质询阶段**故意**只给一半

题面写死的规则：**交叉质询时每组必须回答"为什么你的比另外两组好"，
但看不到对方的原文，只能看到对方的主张摘要。**

所以 `challenge` 阶段每一组的提示词里：

| 有 | 没有 |
|---|---|
| 它**自己**的全文方案 | 另外两组的**原文** |
| 评委对**它**的打分与批评 | 另外两组收到的批评与分数 |
| 另外两组的**主张摘要**（`headline` + `claims[].text`，匿名成"对手 1/2"） | 另外两组的交付物、成本、工期、风险清单 |

这样设计的两头都有用：

- **能辩**：它手上有对方的主张，所以"我为什么更好"是有对照物的论证，不是自夸；
- **不能抄**：它看不到对方原文，所以不可能把对方的方案改几个字交上来。

`cross_visibility` 字段记录这一阶段给了什么、以及本地核对的结果
（`rival_full_text_leaked`：把对方方案里的长句拿去提示词里搜一遍，命中即泄漏）。

**摘要里刻意不含成本、工期、交付物**。因为摘要是"主张"，成本与工期是"底牌"——
质询要辩的是方向，不是替对方把账算好。

## 三、评委为什么**同时**看三份方案，却仍是三次独立调用

评委的职责是**按同一把尺子横向量**。让它一次只看一份，它就不知道"这个成本在本次
三份里算高还是算低"，打出来的分没有可比性。所以每名评委的一次调用里
包含任务书与全部三份方案。

但三名评委**互相看不到对方打了多少分**（三次独立调用）。
这是刻意的：如果评委能看到别人给的分，就会向中间靠拢（锚定效应），
最后三份打分表变成一张。独立性保证的是"三张独立的尺子读数"。

方案给评委时是**匿名**的（只有"方案 1/2/3"编号），组名、各组的立场块都不给，
避免先入为主。

## 四、闸门五：提案独立性（本包的核心闸门）

这是"竞争"与"协作"的分水岭。**"三组各写一段然后合并"就是协作，不是竞争。**

判据全部在本地算，不采信模型的自我声明：

| 判据 | 阈值 | 处置 |
|---|---|---|
| **A（硬）** 任一对方案重合度 ≥ `INDEP_OVERLAP` 且短的一份二元组 ≥ `INDEP_MIN_GRAMS` | 0.75 / 30 | 判**假竞争**，标红 + stderr 汇总 + `exit=3` |
| **B（提示）** 重合度 ≥ `INDEP_RED_OVERLAP` | 0.55 | 标红提示人工看一眼，不单独拦 |
| **C（提示）** 某一份方案"自己的话"二元组 < `INDEP_MIN_OWN_GRAMS` | 40 | 提示"可能只有通用套话，没有本组立场" |

### 重合度为什么用 min 归一，不用 Jaccard

三份方案的篇幅天然不同（B 组可能写了 1500 字，A 组只有 700 字）。
Jaccard 的分母是并集，篇幅差一大就被摊薄，"三组交的是同一份东西"反而测不出来。
用 min 归一后，问的是"**短的那份有多少比例出现在长的那份里**" ——
这才是我们要问的问题。

### 为什么阈值取 0.75

与全族闸门口径一致。真机实测三份合格方案的两两重合度在 0.1~0.3 量级，余量很大；
一旦真的抄成一份，重合度会直接顶到 0.9 以上。中间地带（0.55~0.75）只提示不拦，
因为那可能是"同一份任务书带来的必要重合"（例如都引用了任务书里的预算上限）。

### 闸门命中时长什么样

```
闸门命中：[independence] 「team_a」与「team_b」的方案重合度 0.93 ≥ 0.75（短的一份 402 个二元组）—— **假竞争**：三组交的是同一份东西的三种说法，竞争没有发生，打分排序与合并建议都失去意义
本地闸门命中 1 项：independence（详见 <outdir>/REPORT.md）
```

退出码 3。这正是"如果做成三个角色各写一段然后合并，就退化成了协作式"这一条的机器判据。

## 五、质询阶段实际问什么

质询主持（`challenge`）对每一组出 3~6 个问题，每个问题**只针对这一组自己**：

1. 它的方案原文里哪一处最经不起追问？
2. 评委点出的问题，它打算怎么改、改到什么程度？
3. **面对另外两组已经亮出来的主张，它的差异化优势到底落在哪一点上？**
   （至少 1 条问题必须打在这一条上）

第 3 条是硬要求：没有它，"交叉质询"就退化成"逐组自查"。
但它只能在**摘要里已经出现的主张**上发问 —— 因为主持手里也只有摘要。

作答（`answer`）要求：

- `answers` 逐条对应问题（`q` 原样抄问题）；
- `why_better` **至少 2 条**，`than` 必须是摘要里已经出现的主张（编一条对方没说过的主张会被 prompt_echo 与锚点两侧一起抓）；
- `cannot_beat`：**如实说对方哪一条本组确实比不过**，写"无"也行。
  这一条是有意留的：只会硬撑的答辩没有信息量，评委也核不了。

## 六、本包与"评审委员会"（`sanjianke-review-board`）的分界

| | 评审委员会（对抗评审式） | **本包（竞争式）** |
|---|---|---|
| 输入 | **一份**已有的方案/稿件 | 一份任务书（**没有方案**，方案要现场写） |
| 谁产出 | 没有提案组，四席只评审 | **三个提案组各写一份**（信息隔离） |
| 有没有胜负 | **没有**。产出是"该不该过"（通过 / 有条件通过 / 否决） | **有**。产出是"谁赢、别人差在哪、什么可以合并" |
| 核心机制 | 分歧显性化 + 裁决 | **名额竞争** + 打分排序 + 落选稿回收 |
| 对抗发生在谁之间 | 四个**立场**之间（都在评同一份东西） | 三个**方案**之间（各自独立写，抢同一个名额） |
| 关键闸门 | 立场有效性（意见重合 → 立场失效） | **提案独立性**（方案重合 → 假竞争） |
| 产出物 | 裁决书 + 条件清单 + 少数派意见 | 获胜方案 + 落选原因 + **合并建议** + 打分明细 |
| 一句话 | 那边**裁一份稿** | 本包**选一份稿** |

**最容易被搞混的一点：** 两者都有"信息隔离"，但隔离的对象不同。
评审委员会隔离的是**席位之间**（防止四席互相妥协成一段综合意见）；
本包隔离的是**提案组之间**（防止三组互相抄成一份方案，那样就没有竞争了）。
