# 成本与排错

本文件说明：一道闸门各自判什么、退出码怎么读、token 怎么估、断点续跑为什么不会重复花钱，
以及实际踩到过并修掉的坑。

---

## 一、八道本地硬闸门

**命中一律：标红 + stderr 汇总 + 非 0 退出码。** 全部确定性，跑两次结果一样，可直接进 CI。

| # | 闸门 | 判据 | 退出码 |
|---|---|---|---|
| 1 | **合规** | 广告法违禁词（最 / 第一 / 国家级 / 100% / 保过…）；「最X」可枚举上下文豁免 + **句首不豁免**；**任务书侧全档全查，产出侧只查高风险并排除「引用」与「提到」** | 3 |
| 2 | **占位符残留** | `{}` / `[待填]` / `XXX` / `（此处省略）` / `TODO` | 3 |
| 3 | **`prompt_echo`** | 去标点相等 / Jaccard ≥ 0.75 / 覆盖度 ≥ 0.60（**适用窗口**：长度比 ≤ 3.0 且示例归一后 ≥ 8 字） | 3 |
| 4 | **打分锚点** | 每条打分理由必须引用**被评那一组**的方案原文；未锚定率 > 40% 判「定位失败」 | 3 |
| 5 | **提案独立性** | 任一对方案重合度 ≥ 0.75（短的一份 ≥ 30 个二元组）→ 判**假竞争** | 3 |
| 6 | **裁决完整性** | 一票否决的组被判获胜 / 没有打分明细 / 落选原因缺失 / 没有合并建议 / 判不出赢家 / 合并建议来自获胜组自己 | 3 |
| 7 | **成本上限** | `--budget`（单位**点**）超限就地中止（**未发起调用**） | 5 |
| 8 | **产出不许进包** | `--outdir` / `--out` 落在 Skill 包内 | 2 |

另有一组**顺序闸门**（本包特有，退出码 2，且都在**任何调用之前**判）：

| 顺序闸门 | 判据 | 退出码 |
|---|---|---|
| 未公示评分维度就 `score` | 产出目录里没有 `rubric.json` | 2 |
| 评分口径版本不一致 | `rubric.json` 里的 `rubric_version` ≠ 当前代码 | 2 |
| 没打分就 `challenge` | 缺 `panel.json` | 2 |
| 没质询就 `award` | 缺 `challenge.json` | 2 |
| 方案不齐 | 缺 `proposal_*.json`（缺一组就不构成竞标） | 2 |

## 二、退出码

| 码 | 含义 | 典型触发 |
|---|---|---|
| **0** | 跑完了，八道闸门全过 | 正常 |
| **2** | 参数 / 配置 / 顺序错 | 文件不存在、组名错、`--outdir` 在包内、`--budget` 没配单价、**未公示维度就打分** |
| **3** | 硬闸门命中 | 违禁词、占位符、照抄示例、锚点幻觉、**假竞争**、裁决不完整 |
| **4** | 调用失败 | 网络、鉴权（401）、点数不足（402）、模型名错（404） |
| **5** | 预算超限，已就地中止 | `--budget` 太小 |
| **130** | 用户中断（Ctrl+C） | —— |
| **1** | 未预料异常（只可能出现在 `--json` 下） | `kind:"internal"` 信封 + 完整 traceback 到 stderr |

## 三、成本：只报 token，不编价

文本模型网关**不公布单价**（`/api/v1/models` 里也没有价格字段），
所以本包只报 token、**绝不编金额**。要折算就自己传单价：

```bash
# 单位：点 / 百万 token
python3 scripts/run.py run --file 任务书.md --outdir D:/bid \
    --budget 45 --price-in 300 --price-out 600
```

- `--budget` 的单位是**点**（平台口径 1 元 = 100 点）；
- `--price-in / --price-out` 的单位是**点/百万 token**；
- 用了 `--budget` 就必须给两个单价 —— 不然预算无从判定，
  这道校验是**每一个会花钱的子命令的第一步**（见下面的事故复盘）。

### 一次完整竞标的调用清单（13 次）

| 阶段 | 调用 | 说明 |
|---|---|---|
| 三组独立提案 | 3 | 每组 1 次；只带任务书与本组立场 |
| 评委团打分 | 3 | 每位评委 1 次；匿名看全部方案 |
| 交叉质询（出题） | 3 | 每组 1 次；只给它自己的材料 + 对方摘要 |
| 交叉质询（作答） | 3 | 每组 1 次；论证"我为什么更该拿到名额" |
| 裁决 | 1 | 全量材料摆上桌，出终裁 |

调用次数是**结构性地**定下来的，不是"多跑几次模型"：
少了任何一环，竞争就不成立。`cost` 子命令会按任务书字符数给出逐项估算（零成本）。

### 字符 → token 的标定

| 方向 | 系数 | 来源 |
|---|---|---|
| 输入 | `CHARS_PER_TOKEN_IN = 1.61` | 拿真实调用标定（实测均值 1.612） |
| 输出 | `TOKENS_PER_CHAR_OUT = 1.11` | 实测均值 1.109（1 个原始字符 ≈ 多少 token） |

只用于**预算预检**。真实用量一律取网关返回的 `usage`，报出来的 token 全是实测值。

## 四、断点续跑：同一个 `--outdir` 重跑 0 次调用

断点 key 含**全部影响产出的维度**：

```
阶段 + 任务书 sha + 任务书字符数 + 提示词字符数 + 模型 + 温度
     + 组组合 + 评委组合 + 上游产物 sha + 评分口径版本 + 提示词版本 + 班组定义版本
```

漏一个就会出"改了参数却复用旧产物"的事故。同族踩过三次，本包一次都不许再踩：

| 事故 | 后果 | 本包对策 |
|---|---|---|
| 内容截断没进 key | 8000 字截成 4000 字重跑，静默复用旧产物 | `prompt_chars` 进 key |
| 口径没进 key | 换了闸门口径重跑，命中的还是上一版产物 | `RUBRIC_VERSION` 等三个版本号进 key |
| 评委/组数没进 key | 参数调了没生效，用户以为改过了 | `teams` / `judges` 进 key |

**评分口径版本这一条是本包多出来的**：改了维度或权重，旧尺子打的分配上新尺子的裁决
是直观的错，但很难被发现。所以口径一变，所有阶段的 key 全变，产物自动作废。

`--force` 忽略断点从头重跑（会重新花钱，key 没命中时本来就是重跑）。

### `--replay`：零成本回放

```bash
python3 scripts/run.py award --file 任务书.md --outdir D:/bid --replay D:/bid
```

只用存下来的 `panel.json / challenge.json / award.json` 重跑**本地闸门与渲染**，
一次调用都不发。而且它会**重新做一遍本地校验**（锚点、重合度、裁决完整性
都从 `raw` 字段重算），不直接信文件里存好的结论 ——
所以手工改过的产物绕不过闸门。闸门自测就是靠这条路径做到零成本的。

## 五、排错表

| 现象 | 原因 | 处置 |
|---|---|---|
| `鉴权失败（401）` | Key 无效 / 过期 | 换 Key：`--key`、`A7W_API_KEY` 或 `~/.a7w/config.json` |
| `点数不足（402）` | 账户点数用尽 | 到 https://api.a7w.cn/ 充值 |
| `模型不存在（404）` | 模型名写错 | `run.py models` 现查在架模型名 |
| `上游返回的 JSON 坏了（finish_reason='stop'）` | 模型自己写错了，或响应在路上断了 | **加大 `--max-tokens` 没用**；换模型重试，或把这一稿拆短 |
| `finish_reason=length` | 真被 `max_tokens` 截断 | 加大 `--max-tokens` **有用** |
| `顺序倒了：… 里没有 rubric.json` | 跳过了公示那一步 | 先跑 `rubric`（零成本），再 `propose` / `run` |
| `顺序倒了：… 里缺这些组的方案` | 三组没写齐 | 三组都写完才谈得上竞争 |
| `顺序/口径不一致` | 产物是旧口径跑的 | 重跑 `rubric`，再重跑后续阶段 |
| `闸门命中：[independence] … 假竞争` | 三份方案高度重合 | 这是**真问题**：三组没有各走各的路线。看 `REPORT.md` 的独立性明细，调三组的立场块或换更大的模型 |
| `闸门命中：[anchor] …` | 评委理由引了不存在或属于别组的句子 | 看 `panel.md` 里标 ✗ 的条目，`raw` 字段留了原始返回可复核 |
| `[anchor·跨组]`（只提示不拦） | 评委把别组原话挂到这组头上，但未到硬阈值 | 看 `panel.md`，这类错容易蒙混，建议人工扫一眼 |
| `闸门命中：[award] …没有合并建议` | 裁决人没回收落选稿 | 落选方案里有价值的部分是交付物的一部分，必须逐条给出 |
| 想先看提示词 | —— | `propose --dry-run` / `run --dry-run`，不花钱 |

### 一个真踩到的坑（如实记录）

自测时发现：`evaluate_gates` 里算锚点闸门时用了一个叫 `recs` 的变量，
而上面两道闸门已经用过同名变量记账 —— 覆盖之后**未锚定数永远是 0**，
闸门四看起来在跑、实际恒过。改成 `unanchored_reasons` 之后才真正生效。

同一类问题的第二例：`validate_panel()` 里算好了未锚定清单，却**忘了返回**，
于是闸门四的分母是对的、分子恒为 0。也是自测抓到的。

**这两例的共性值得记住：本地校验最危险的失败形态不是"报错"，
而是"看起来在跑、其实恒过"。** 所以闸门自测里专门有
「引文全是编的 → 必须 exit=3」这一条反向用例。

### 第三例：`prompt_echo` 的 `contain` 判据必须有适用窗口

覆盖度判据只看"示例被抄了多少"，不看产出有多长，所以对**短示例**会饱和：
示例归一后只有 3~5 字（2~4 个二元组）时，长文本里被动凑齐两个二元组就有 0.5 的覆盖度 ——
离 0.60 的阈值只差 0.10。所以 `contain` 只在**两个条件都满足**时适用：

1. 目标片段长度 ≤ 示例长度 × 3.0（长度比窗口）；
2. 示例归一后长度 ≥ 8 字（二元组数量够用）。

不适用的地方记进 `contain_skipped`，**不静默略过**。

## 六、产出目录长这样

```
D:/bid/
├── rubric.json / rubric.md        公示的维度与权重（提案之前定的）
├── proposal_team_a.json / .md     A 组方案（单组跑时）
├── proposal_team_b.json / .md
├── proposal_team_c.json / .md
├── proposals.md                   三组方案汇总 + **信息隔离证据**
├── panel.json  / panel.md         评委团打分表 + 锚点校验 + 一票否决
├── challenge.json / challenge.md  质询记录（含交叉可见性证据）
├── award.json  / award.md         裁决书：获胜 + 落选原因 + **合并建议** + 打分明细
├── task_brief.json / task_brief.md 任务书整理（纯本地）
├── REPORT.md                      总报告
└── state.json                     断点文件（重跑不重复扣费）
```

产出**一律落在包外**的 `--outdir` 里。包内只允许
`.md .py .txt .json .sh .js .yaml .yml .csv` 这几种后缀；指到包内直接 `exit=2`。

### 关于 `.pyc`

`run.py` 在**任何本地 import 之前**设了 `sys.dont_write_bytecode = True`，
所以它不会在 `scripts/__pycache__/` 下留 `.pyc`。
（顺带纠正一个说法：`.pyc` 本身**不会**导致 Skill 包上传被拒 —— 它在上传 CLI 的
排除清单里。留不留 `.pyc` 是干净问题，不是能不能传的问题。）

## 七、配 Key 的三种方式

代码与文档里**都不含任何 Key**：

```bash
# 1) 环境变量（推荐）
export A7W_API_KEY=sk-xxxx        # Windows PowerShell: $env:A7W_API_KEY="sk-xxxx"

# 2) 命令行临时传
python3 scripts/run.py run --file 任务书.md --outdir D:/bid --key sk-xxxx

# 3) 写进配置文件
python3 scripts/a7w.py login --key sk-xxxx     # 写入 ~/.a7w/config.json
```

到 https://api.a7w.cn/ 注册领取（新用户有赠送点数，可以先零成本试跑几条）。
