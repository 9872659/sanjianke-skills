# 三剪客 · 方案竞标小组

> ## ⚠️ 先申请你自己的 API Key
>
> **本 Skill 不内嵌任何密钥，也不代付费用。** 请到
> **[算力集市 api.a7w.cn](https://api.a7w.cn/)** 注册并创建**你自己的** API Key
> （新用户有赠送点数，可以先免费试跑几条）。
>
> 拿到后填进环境变量 `A7W_API_KEY`，或直接传给 `--key` 参数。
> **请勿使用他人提供的 Key** —— 用量与费用都记在 Key 所属账号上。

## 能做什么

给一个名额开一场**有胜负的竞标**，产出**获胜方案 + 落选原因 + 合并建议 + 打分明细**：

```
rubric    →  公示评分维度与权重（零成本，**必须在提案之前跑**）
propose   →  某个提案组独立出方案（信息隔离，1 次调用）
score     →  评委团按公示维度打分（每名评委 1 次调用）
challenge →  交叉质询：出题 + 每组作答（每组 2 次调用）
award     →  裁决：获胜 + 落选原因 + 合并建议 + 打分明细（1 次调用）
run       →  一条命令跑完整场竞标（rubric→propose→score→challenge→award），断点续跑
```

它替代的是决策会上最耗人的那一步：不是"没人提方案"，而是
**"三个方案摆在桌上，谁也说不清 A 比 B 好在哪，最后按谁先动手来定"**。

| 你最关心 | 答案 |
|---|---|
| 跟"多调几次模型"有什么不同 | 三组是**三次独立调用**，各写各的方案抢同一个名额，**有胜负**；不是角色接力做同一件事 |
| 会不会三组写成一样 | 会，但会被拦下：本地算三份方案的重合度，任一对 ≥ 0.75 判**假竞争**，`exit=3` |
| 尺子什么时候定 | **提案之前**。`rubric` 先公示维度与权重；没公示就 `score` → `exit=2` |
| 提案组知道评分维度吗 | **不知道**。知道了它们会照同一把尺子把自己优化成一个形状，那正好是"假竞争" |
| 评委会不会瞎打分 | 会，但会被锚点闸门拦下：每条理由必须引用**那一组**的方案原文，编造或跨组引用会被剔出 |
| 交叉质询是真质询吗 | 每组拿到的是「自己的全文 + 对方**主张摘要** + 只属于自己的评委意见」；对方原文不给，所以能辩、不能抄 |
| 落选方案会不会被丢掉 | 不会：**合并建议是必填**，逐条写清"从哪一组拿什么、补进获胜方案的哪一处、补上什么缺口" |
| 反对意见会不会被吞 | 不会：有评委一票否决或有不同意见时，必须逐条写进 `dissent`，原样保留 |
| 中断了怎么办 | 断点续跑：同一个 `--outdir` 重跑只打印「断点命中，跳过」，0 次调用 |
| `--replay` 会花钱吗 | **不会**。它是严格只读的：不写产物、不写断点文件，缺产物直接报错 |
| 多少钱 | `cost` 先报价（调用清单 + token）；文本网关不公布单价，**只报 token、不编价** |
| 要装什么 | **什么都不用装**。只用 Python 标准库，不需要 pip install 任何东西 |

### 三条命令就够（零成本那几条先跑）

```bash
python3 scripts/run.py roles                                   # 看三组 / 三评委 / 主持 / 裁决人（零成本）
python3 scripts/run.py rubric --file 任务书.md --outdir D:/bid  # 公示维度与权重（零成本）
python3 scripts/run.py cost   --file 任务书.md                  # 报价：大概花多少 token（零成本）
python3 scripts/run.py run    --file 任务书.md --outdir D:/bid  # 一条命令跑完整场竞标
```

### L3 定位：这是"竞争式"，不是"协作式"

| | 流水线式（`content-team`） | 对抗评审式（`review-board`） | **本包（竞争式 L3）** |
|---|---|---|---|
| 输入 | 一个选题，从零写 | **一份已有的方案/稿件** | 一份**任务书**（方案要现场写） |
| 谁出方案 | 角色按顺序接力，一起做一件事 | 没有提案组 | **三个组各出一份**（信息隔离） |
| 核心机制 | 打回重写 | 分歧显性化 + 裁决 | **名额竞争** + 打分排序 + 落选稿回收 |
| 有没有胜负 | 没有 | **没有**（判"该不该过"） | **有**（判"谁赢"） |
| 产出 | 定稿 | 裁决书 + 条件清单 + 少数派 | 获胜方案 + 落选原因 + **合并建议** |
| 一句话 | 一起把一件事做好 | **裁一份稿** | **选一份稿** |

**本包与其它 L3 最本质的不同：别的都是"协作"（角色们一起把同一件事做好），
本包是"竞争"（三组抢一个名额，必然有人输）。**
如果做成"三个角色各写一段然后合并"，那就退化成了协作式 ——
闸门五（提案独立性）就是用来当场抓住这件事的。

## 怎么用（命令行）

### 第 0 步：获取 API Key

到 **[api.a7w.cn](https://api.a7w.cn/)** 注册，创建一个 API Key（形如 `sk-...`）。

### 第 1 步：装依赖

**零依赖。** 只要机器上有 Python 3.7+：

```bash
python3 --version
```

包里自带的 `scripts/a7w.py` 是零依赖客户端（只用 `urllib` / `json` / `mimetypes`），
`scripts/run.py` 也只用标准库。

### 第 2 步：填 Key

```bash
# Linux / macOS
export A7W_API_KEY=sk-你的key

# Windows PowerShell
$env:A7W_API_KEY="sk-你的key"
```

也可以存进配置文件反复用（推荐）：

```bash
python3 scripts/a7w.py login --key sk-你的key
```

### 第 3 步：先做零成本自检（不联网、不花点数）

```bash
# 三组 / 三评委 / 质询主持 / 裁决人，以及"三组为什么会争起来"的对照表
python3 scripts/run.py roles

# 公示评分维度与权重（**必须在提案之前**；写进 rubric.json）
python3 scripts/run.py rubric --file 任务书.md --outdir D:/bid

# 报价：这场竞标大概花多少 token（金额要你自己填单价）
python3 scripts/run.py cost --file 任务书.md
```

### 第 4 步：跑第一个例子

```bash
# 一条命令跑完整场竞标，断点续跑
python3 scripts/run.py run --file 任务书.md \
    --outdir D:/bid --budget 45 --price-in 300 --price-out 600 \
    --json --out D:/bid/run.json
```

`--outdir` 里会落 12+ 个文件：`rubric.md/json`、`proposal_team_a|b|c.md/json`、
`proposals.md`、`panel.md/json`、`challenge.md/json`、`award.md/json`、
`task_brief.md/json`、`REPORT.md`（总报告）、`state.json`（断点）。
**同一个 `--outdir` 重跑只会打印"断点命中，跳过"，0 次调用。**

> **预算单位是「点」**（平台口径 1 元 = 100 点）：
> `--budget 45 --price-in 300 --price-out 600` 表示预算 45 点，
> 输入按 300 点/百万 token、输出按 600 点/百万 token 折算。
> 用了 `--budget` 就必须给两个单价，否则没法把 token 折成点数、预算无从判定 ——
> 这道校验在**每一个会花钱的子命令的第一步**判，缺了直接 `exit=2`，一次调用都不发。

### 分步跑（想看清每一步时）

```bash
python3 scripts/run.py rubric    --file 任务书.md --outdir D:/bid
python3 scripts/run.py propose   --file 任务书.md --team a --outdir D:/bid --json
python3 scripts/run.py propose   --file 任务书.md --team b --outdir D:/bid --json
python3 scripts/run.py propose   --file 任务书.md --team c --outdir D:/bid --json
python3 scripts/run.py score     --file 任务书.md --outdir D:/bid --json
python3 scripts/run.py challenge --file 任务书.md --outdir D:/bid --json
python3 scripts/run.py award     --file 任务书.md --outdir D:/bid --json
```

顺序**不可倒**：`score` 没有 `rubric.json` → `exit=2`；
`challenge` 没有 `panel.json` → `exit=2`；`award` 没有 `challenge.json` → `exit=2`。
理由：维度若在看到方案之后才定，评委就是在为已经写出来的东西找尺子。

### 只想预演提示词（不花钱）

```bash
python3 scripts/run.py propose --file 任务书.md --team a --outdir D:/bid --dry-run
python3 scripts/run.py run     --file 任务书.md --outdir D:/bid --dry-run
```

打印将发送的提示词，**不调模型**。想看完整链路又不愿意花钱：
`run --replay <已有产物目录>`（严格只读，缺产物直接报错）。

## 参数说明

### 全局

| 参数 | 说明 |
|---|---|
| `--json` | 以 JSON 输出（**写在子命令前后都可以**） |
| `--key` | 临时指定 API Key（也可用 `A7W_API_KEY` 或 `~/.a7w/config.json`） |
| `--model` | 模型名，默认 `deepseek-chat`（实测可用；`run.py models` 现查在架模型） |
| `--temperature` | 采样温度，默认 `0.7` |
| `--max-tokens` | 单次输出上限，默认 `8192` |
| `--dry-run` | 只打印提示词，不调模型 |
| `--no-json-mode` | 不要求上游返回 JSON 对象（个别模型不支持 `response_format` 时用） |

### 成本相关（`--budget` 的**单位是点**）

| 参数 | 说明 |
|---|---|
| `--budget` | 预算上限，单位**点**（1 元 = 100 点）；超了就地中止 `exit=5`。**用了它就必须给两个单价** |
| `--price-in` | 输入单价，单位**点/百万 token** |
| `--price-out` | 输出单价，单位**点/百万 token** |

### `propose` 专有

| 参数 | 说明 |
|---|---|
| `--team` | 哪个组：`team_a` / `team_b` / `team_c`（或写 `a` / `b` / `c`） |
| `--require-rubric` | 严格要求产出目录里已公示过评分口径（缺了就 `exit=2`） |

### `run` 专有

| 参数 | 说明 |
|---|---|
| `--file` | 竞标任务书（`.md` / `.txt`，UTF-8） |
| `--teams` | 只跑指定的组（逗号分隔，默认全部三组）；**少于两组报错**（一组不构成竞标） |
| `--outdir` | 产出目录（**必须在包外**）；默认在系统临时目录下建 `bid-crew-out` |
| `--replay` | 回放一个已有产物目录：**严格只读、0 调用**；缺产物直接 `exit=2` |
| `--force` | 忽略断点文件，从头重跑（会重新花钱） |

### `--json` 契约（给流水线与 agent 消费）

- **成功**：stdout 输出**一个** JSON 对象，第一层一定有 `ok: true`；
- **失败**：stdout 输出 `{"ok": false, "exit": <码>, "error": {"kind": ..., "message": ...}}`，
  `kind` ∈ `usage` / `gate` / `call` / `budget` / `interrupt` / `internal`；
- 闸门命中时，**结果本身就是那份失败报告**（`ok: false` + `exit` + `gates`），
  不再另补一个错误信封 —— 守住"stdout 永远只有一个 JSON"这条不变量；
- 人读文案照旧走 stderr；**退出码语义一个都不变**；
- 未预料的异常 → `kind:"internal"` 信封 + **完整 traceback 到 stderr**（报 bug，不藏 bug）。

### `rubric` 专有

| 参数 | 说明 |
|---|---|
| `--outdir` | 把 `rubric.json` / `rubric.md` 落这个目录（必须在包外） |
| `--out` | 把公示结果写到这个文件 |

## 八道本地硬闸门（都是确定性的，跑两次结果一样，可直接进 CI）

| # | 闸门 | 判据 | 退出码 |
|---|---|---|---|
| 1 | **合规** | 违禁词（最 / 第一 / 国家级 / 100% / 保过…）；「最X」可枚举上下文豁免 + **句首不豁免**；**任务书侧全档全查、产出侧只查高风险并排除「引用」与「提到」** | 3 |
| 2 | **占位符残留** | `{}` / `[待填]` / `XXX` / `（此处省略）` / `TODO` | 3 |
| 3 | **`prompt_echo`** | 去标点相等 / Jaccard ≥ 0.75 / 覆盖度 ≥ 0.60（**适用窗口**：目标长度 ≤ 示例 × 3.0 且示例归一后 ≥ 8 字，否则该判据不适用并记进 `contain_skipped`） | 3 |
| 4 | **打分锚点** | 每条打分理由必须引用**被评那一组**的方案原文；编造引文或跨组引用会被剔出并记账；未锚定率 > 40% 判「定位失败」 | 3 |
| 5 | **提案独立性** | 三份方案两两重合度（min 归一）≥ 0.75 且短的一份 ≥ 30 个二元组 → 判「**假竞争**」 | 3 |
| 6 | **裁决完整性** | 判了获胜却没有打分明细 / 落选原因缺失 / 没有合并建议 / 合并建议来自获胜组自己 / 被一票否决的组被判获胜 / 判不出赢家 | 3 |
| 7 | **成本上限** | `--budget` 超限就地中止（**未发起调用**） | 5 |
| 8 | **产出不许进包** | `--outdir` / `--out` 落在 Skill 包内 | 2 |

命中一律：**标红 + stderr 汇总 + 非 0 退出码**。

### 顺序闸门（本包特有，都在**任何调用之前**判）

| 判据 | 退出码 |
|---|---|
| 未公示评分维度就 `score`（缺 `rubric.json`） | 2 |
| 评分口径版本与当前代码不一致 | 2 |
| 没打分就 `challenge`（缺 `panel.json`） | 2 |
| 没质询就 `award`（缺 `challenge.json`） | 2 |
| 方案不齐（缺 `proposal_*.json`，缺一组就不构成竞标） | 2 |
| `--replay` 但缺产物 | 2 |

### 第 5 道闸门为什么是本包最值钱的那道

**"三组各写一段然后合并"就是协作，不是竞争 —— 那这包就白做了。**
这道闸门不采信任何声明，本地算：

- **重合度** = 较短那份有多少比例的内容出现在较长那份里（**min 归一**，不是 Jaccard：
  三份篇幅天然不同，Jaccard 的分母是并集，篇幅差一大就把相似度摊薄了）；
- 只算各方案**自己的话**（主张 / 交付物 / 成本工期 / 差异点 / 风险兜底 / 验收口径）；
- 任一对 ≥ 0.75 且短的那份 ≥ 30 个二元组 → 判**假竞争**，`exit=3`；
- 0.55~0.75 之间只标红提示（那可能是同一份任务书带来的必要重合）。

真机实测三份合格方案的两两重合度是 **0.165 / 0.198 / 0.213**，离阈值余量很大。

### 第 4 道闸门的两个本地动作

1. **引文必须锚到"被评的那一组"**：评委把 B 组的原话挂到 A 组头上时，
   本地会在 A 组方案里锚不上、却在 B 组方案里锚上 —— 于是判**跨组引用**：
   剔出、计入未锚定率，并在 stderr 里**点名**（这类错最容易蒙混过去，
   所以未到硬阈值时也要提示，只不单独拦）。
2. **裁决自报的分与评委团重算的分要交叉核对**：差 > 1.0 直接拦。
   同族与本包都强调过一件事：**本地校验最危险的失败形态不是"报错"，
   而是"看起来在跑、其实恒过"** —— 所以锚点闸门有专门的反向用例
   （引文全是编的 → 必须 `exit=3`）。

## 退出码（可直接用于 CI）

| 码 | 含义 |
|---|---|
| **0** | 跑完了，八道闸门全过 |
| **2** | 参数 / 配置 / 顺序错（文件不存在、组名错、`--outdir` 在包内、`--budget` 没配单价、未公示维度就打分、`--replay` 缺产物） |
| **3** | 硬闸门命中（违禁词、占位符、照抄示例、锚点幻觉、**假竞争**、裁决不完整） |
| **4** | 调用失败（网络 / 鉴权 401 / 点数不足 402 / 模型名错 404） |
| **5** | 预算超限，已就地中止（未发起调用） |
| **130** | 用户中断（Ctrl+C） |
| **1** | 未预料异常（只可能出现在 `--json` 下，`kind:"internal"`） |

## 踩到并修掉的三类真问题（如实记录）

### 1）产出侧合规把"列举式禁止"误报成违规宣称

真机第一轮跑，获胜方案里写着「对外话术**不包含**「保证过审」「100%有效」「稳赚」等词」——
这是在**禁止**这些词，却被判成"自己在主张"。两个原因：窗口只有前后各 24 字，
而"不包含"离第一个词超过了 24 字；而且原实现只检查这个词**第一次出现**的位置。
修法：窗口放到 32 字，并**遍历每一次出现**，只要有一次落在"禁止 / 举证 / 风险"语境里
就判为「提到」（被排除的条目全部带 `not_counted_reason` 保留在案，不静默丢弃）。
同时保留牙齿：「本方案必须保证过审，效果 100% 达标」这种小句里没有任何标记词，
照样 `exit=3`（自测用例覆盖）。

### 2）中文列举「第一，」被当成排他性宣称

真机第一轮跑，C 组方案里「复用场景：第一，D20 中期核算时用」被判「第一」类排他性表述。
「第一，」是中文列举，不是最高级宣称。修法：把逗号 / 顿号 / 冒号 / 右括号这类
**列举分隔符**补进「第一」的序数豁免表，同时保持**句首不豁免**与
「我们是第一品牌」照拦（自测用例覆盖两种方向）。

### 3）`--replay` 居然会花钱（这条最贵）

删掉 `challenge.json` 之后，`state.json` 里还写着该阶段 `done`：
续跑判定不成立、又没轮到回放分支，脚本**直接去调模型了** ——
用户以为自己在零成本回放，实际花了钱。修法三条：
`--replay` **优先于续跑判定**（缺产物直接 `exit=2`，不"顺手重新生成"）；
`--replay` **严格只读**（不写产物、不写断点文件，用 `_commit()` 统一挡住）；
回放时**重新做一遍本地校验**，所以手工改过的产物绕不过闸门。
自测里专门有一条反向用例：`--replay` 且缺产物 → `exit=2` 且**不得进入任何模型步骤**。
