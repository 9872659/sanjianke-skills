# 三剪客 · 方案竞标小组

给一个名额开一场**真竞标**，产出**获胜方案 + 落选原因 + 合并建议 + 打分明细**：

```
roles     →  三个提案组 / 三名评委 / 质询主持 / 裁决人（零成本）
rubric    →  公示评分维度与权重（零成本，**必须在提案之前跑**）
propose   →  某个提案组独立出方案（信息隔离：看不到另外两组，也看不到评分维度）
score     →  评委团按公示维度打分（每条理由必须引用该组方案原文）
challenge →  交叉质询：每组回答"我为什么比另外两组更该拿到名额"
award     →  裁决：获胜 + 落选原因 + 落选方案的可用部分（合并建议）+ 打分明细
run       →  一条命令跑完整场竞标，断点续跑
```

> 本包**不审稿**、**不改稿**、**不打一份稿子的分**。它解决的是另一件事：
> **三个组各自写一份，抢同一个名额，谁赢、别人差在哪、落选稿里什么还能用。**

---

## ⚠️ 三层的分界：本包是 L3，而且是"竞争式"那一种

### 先看 L1 / L2 / L3 的判据

| 层 | 形态 |
|---|---|
| **L1 单点生成型** | 一个输入 → 一个产出 |
| **L2 智能体型** | **单循环**：抽档 → 写 → 自检 → 迭代（一个声音自我迭代） |
| **L3 多智能体协作型** | **多角色分工互审**，一条命令出成品 |

L3 的关键**不是"调多次模型"**。调多次模型只说明花了更多钱。L3 的判据是：

> **每个角色有自己独立的目标函数，且会互相否掉对方。**

### L3 已有六种形态，本包是第七种

| 形态 | 代表包 | 一句话 |
|---|---|---|
| 流水线式 | `content-team` | 角色**按顺序**接力，后一个审前一个 |
| 对抗评审式 | `review-board` | 四个立场**同时**独立评审同一份材料，再对质、裁一份稿 |
| 剧组式 | `drama-crew` | 编剧 / 导演 / 摄影 各管一段 |
| 教研式 | `course-crew` | 教研组分工做一门课 |
| 小组式 | `ecom-crew` | 选品 / 文案 / 视觉 / 合规 协作做一套物料 |
| 跨语言式 | `localize-crew` | 译者 / 审校 / 本地化 协作做一版译文 |
| **竞争式（本包）** | **`bid-crew`** | **三个提案组各自独立出方案抢同一个名额，有胜负** |

**本包与它们最本质的不同：别的六种都是"协作"（角色们一起把同一件事做好），
本包是"竞争"（三组抢一个名额，必然有人输）。**

### 本包与 `review-board`（对抗式评审）的分界 —— 最容易搞混的那一对

| 维度 | `sanjianke-review-board`（对抗式评审） | **本包（竞争式竞标）** |
|---|---|---|
| 输入 | **一份**已有的方案/稿件 | 一份**任务书**（没有方案，方案要现场写） |
| 谁产出方案 | 没有提案组：四席只评审 | **三个提案组各写一份**（信息隔离） |
| 有没有胜负 | **没有**。结论是"该不该过"（通过 / 有条件通过 / 否决） | **有**。结论是"谁赢" |
| 核心机制 | **分歧显性化 + 裁决** | **名额竞争** + 打分排序 + 落选稿回收 |
| 对抗发生在谁之间 | 四个**立场**之间（都在评同一份东西） | 三个**方案**之间（各写各的，抢同一个名额） |
| 信息隔离的对象 | **席位之间**（防止四席互相妥协成一段综合意见） | **提案组之间**（防止三组互相抄成一份方案） |
| 核心闸门 | 立场有效性（意见重合 → 立场失效） | **提案独立性**（方案重合 → 假竞争） |
| 产出物 | 裁决书 + 条件清单 + 少数派意见 | 获胜方案 + 落选原因 + **合并建议** + 打分明细 |
| 一句话 | 那边**裁一份稿** | 本包**选一份稿** |

**两者都不是"多几个评分维度"的升级版，是两件不同的事。**
本包唯一与它像的地方是"都有信息隔离"，但隔离的对象不同（见上表倒数第三行）。

### 与 L2（内容质量闭环）的分界

| | 内容质量闭环（L2） | **本包（竞争式 L3）** |
|---|---|---|
| 输入 | 一篇别人写完的成稿 | 一份任务书 |
| 形态 | **一个声音**拿一张加权评分表自我迭代 | **三个方案**各自独立写，抢一个名额 |
| 核心机制 | 打分 → 重写 → 复评，直到**收敛** | 打分排序 + 交叉质询 + **单选获胜** |
| 产出 | 定稿 + 评分轨迹 + 逐句台账 | 获胜方案 + 落选原因 + 合并建议 |
| 终止 | 分数过线或轮次用尽 | 出终裁 |

L2 的分数是"这篇写得好不好"；本包的分数是"**这三份里哪份该拿这个名额**"。
前者没有对手，后者必然有对手。

## 一、这个包解决的是什么问题

要上新一个东西、要发一版活动、要选一条路线 —— 卡住人的从来不是"没有方案"，
而是**方案不止一个，却没人肯先说不，最后按谁嗓门大或者谁先动手来定**：

- 三个组的方案摆在桌上，**谁也说不清 A 比 B 好在哪** —— 因为当初没人用同一把尺子量；
- 评委是在**看完方案之后**才知道要评什么 —— 于是变成"为已经写出来的东西找理由"；
- 落选的那两份**被整份丢掉** —— 里面明明有能用的东西（一个别人抄不走的差异点、
  一套可验收的清单），只因为"它输了"就消失了；
- 最糟的是**假装有竞争**：三份方案其实是同一份东西换三种说法，
  排出来的名次是噪声，合并建议也无从谈起。

本包把这条链路做成**四条硬规矩**：

| 你最关心 | 本包的做法 |
|---|---|
| 尺子什么时候定 | **提案之前**。`rubric` 先公示维度与权重（写死为代码常量），没公示就 `score` → `exit=2` |
| 三组会不会互相抄 | 不会：`propose` 是三次独立调用，每次只带任务书与本组立场，**连评分维度都不给**（见 `isolation`） |
| 怎么知道竞争真的发生了 | **本地算重合度**：三份方案两两重合度 ≥ 0.75 → 判「**假竞争**」，标红 + `exit=3` |
| 评委会不会瞎打分 | 每条打分理由必须**引用该组方案原文**，本地校验；引文锚不上就剔出（未锚定率 > 40% 判定位失败） |
| 交叉质询是真质询吗 | 每组拿到的是「自己的全文 + 对方的主张摘要 + 只属于自己的评委意见」；**对方原文不给**，所以能辩、不能抄 |
| 落选方案怎么处理 | **合并建议是必填**：逐条写清"从哪一组拿什么、补进获胜方案的哪一处、补上什么缺口" |
| 会不会假装有竞争 | 判了获胜却没有打分明细 / 落选原因缺失 / 没有合并建议 / 被一票否决的组被判获胜 → 全拦 |
| 一票否决怎么用 | 只有**风险与合规评委**有；否决必须带理由与锚到该组原文的引文；被否决的组不能获胜 |
| 中断了怎么办 | 断点续跑：同一个 `--outdir` 重跑只打印「断点命中，跳过」，0 次调用 |
| `--replay` 安全吗 | **严格只读**：不写产物、不写断点文件、缺产物直接报错，**一次调用都不会发** |
| 多少钱 | `cost` 先报价；文本网关不公布单价，**只报 token，不编价** |
| 要装什么 | **什么都不用装**，只用 Python 标准库 |

## 二、四类参与者

| 参与者 | 目标 | 产出物 | 权限 |
|---|---|---|---|
| **提案组 A / B / C** | 各自赢 | 方案（**三组信息隔离，互不可见**） | 无 |
| **评委团**（3 席，不同侧重） | 按公示维度打分 | 打分表 + 理由 | **风险与合规评委有一票否决** |
| **质询主持** | 逼出差异 | 质询记录 | 无 |
| **裁决人** | 出结论 | 获胜方案 + 合并建议 + 落选原因 | **终裁** |

### 三个提案组的取胜路线（这一栏决定了竞争是否真实）

| 组 | 取胜路线 | 最不能让步的一点 | 为了赢肯牺牲 |
|---|---|---|---|
| **A 组 · 成本快打** | 用最少的钱和最短的时间把事做成 | 总成本与工期必须可核算 | 包装、视觉、长尾优化、品牌叙事 |
| **B 组 · 差异化造势** | 做别人做不出来的东西 | 必须给出可指认的差异化声称 | 成本、周期、毛利 |
| **C 组 · 稳控兜底** | 把风险与不确定性压到最低 | 必须给可验收口径与兜底动作 | 出彩、速度、成本 |

三组的"肯牺牲什么"正好是别人的强项 —— 所以它们**在同一张评分表上必然各有长短**，
"竞争"才真实存在。`roles` 子命令会把这张表和"三组为什么会争起来"的对照表打出来（零成本）。

### 公示的评分维度与权重

| 维度 | id | 权重 | 评什么 |
|---|---|---|---|
| **成本** | `cost` | 0.30 | 端到端总花的钱与人力，能不能核算到单价 × 用量 |
| **可行性** | `feasibility` | 0.25 | 以现有人力、时间与资源，能不能真的按期做出来 |
| **差异化** | `differentiation` | 0.25 | 有没有可指认、可验证、别人抄不走的差异 |
| **风险** | `risk` | 0.20 | 合规与执行风险的暴露面，以及翻车之后兜不兜得住 |

权重是**代码里的常量**（`RUBRIC_VERSION = bid-rubric-1.0.0`），不是让模型现编的：
竞标的公正性全押在"尺子先定"上。改了维度必须改版本号，否则断点续跑会把
旧尺子打的分配上新尺子的裁决。

## 三、30 秒上手

```bash
# 1) 拿 Key（新用户有赠送点数）：到 https://api.a7w.cn/ 注册，创建一个 API Key
export A7W_API_KEY="<你的Key>"          # Windows: $env:A7W_API_KEY="<你的Key>"

# 2) 零成本先看三样：角色表、公示维度、报价
python3 scripts/run.py roles
python3 scripts/run.py rubric --file 任务书.md --outdir D:/bid
python3 scripts/run.py cost  --file 任务书.md

# 3) 一条命令跑完整场竞标
python3 scripts/run.py run --file 任务书.md --outdir D:/bid --json --out D:/bid/run.json

# 4) 想先看提示词不花钱
python3 scripts/run.py propose --file 任务书.md --team a --outdir D:/bid --dry-run

# 5) 事后零成本重跑本地闸门（严格只读）
python3 scripts/run.py run --file 任务书.md --outdir D:/bid --replay D:/bid
```

**零依赖**：只要 Python 3.7+，不用 `pip install` 任何东西。
`scripts/a7w.py` 是**所有 Skill 包共用**的零依赖客户端（我们靠 SHA256 校验各包副本是否一致），
本包**逐字节没有改它**；本包的业务逻辑全在 `scripts/run.py` 里。

**预算单位是「点」**（1 元 = 100 点）：`--budget 45 --price-in 300 --price-out 600`
= 预算 45 点，输入 300 点/百万 token、输出 600 点/百万 token。

## 四、八道本地硬闸门

命中一律：**标红 + stderr 汇总 + 非 0 退出码**，全部确定性，跑两次结果一样，可直接进 CI。

| # | 闸门 | 判据 | 退出码 |
|---|---|---|---|
| 1 | 合规 | 违禁词（最 / 第一 / 国家级 / 100% / 保过…）；「最X」可枚举上下文豁免 + **句首不豁免**；**任务书侧全档全查、产出侧只查高风险并排除「引用」与「提到」** | 3 |
| 2 | 占位符残留 | `{}` / `[待填]` / `XXX` / `（此处省略）` / `TODO` | 3 |
| 3 | `prompt_echo` | 去标点相等 / Jaccard ≥ 0.75 / 覆盖度 ≥ 0.60（**适用窗口**：长度比 ≤ 3.0 且示例 ≥ 8 字） | 3 |
| 4 | **打分锚点** | 每条打分理由必须引用**被评那一组**的方案原文；编造或跨组引用会被剔出；未锚定率 > 40% 判「定位失败」 | 3 |
| 5 | **提案独立性** | 三份方案两两重合度 ≥ 0.75（短的一份 ≥ 30 个二元组）→ 判「**假竞争**」 | 3 |
| 6 | **裁决完整性** | 判了获胜却没有打分明细 / 落选原因缺失 / 没有合并建议 / 合并建议来自获胜组自己 / 被一票否决的组被判获胜 / 判不出赢家 | 3 |
| 7 | 成本上限 | `--budget` 超限就地中止（**未发起调用**） | 5 |
| 8 | 产出不许进包 | `--outdir` / `--out` 落在 Skill 包内 | 2 |

另有一组**顺序闸门**（本包特有，退出码 2，都在**任何调用之前**判）：
未公示评分维度就 `score` / 口径版本不一致 / 没打分就 `challenge` / 没质询就 `award` / 方案不齐。

### 第 5 道闸门为什么是本包最值钱的那道

**"三组各写一段然后合并"就是协作，不是竞争 —— 那这包就白做了。**
所以这道闸门不采信任何声明，本地算：

- **重合度** = 较短那份有多少比例的内容出现在较长那份里（**min 归一**，不是 Jaccard：
  三份方案篇幅天然不同，Jaccard 的分母是并集，篇幅差一大就把相似度摊薄了）
- 任一对 ≥ 0.75 且短的那份 ≥ 30 个二元组 → 判**假竞争**，`exit=3`
- 0.55~0.75 之间只标红提示（那可能是同一份任务书带来的必要重合）

真机实测三份合格方案的两两重合度是 **0.165 / 0.198 / 0.213**，离阈值余量很大；
一旦真的抄成一份，重合度会直接顶到 0.9 以上。

## 五、真机实测（跑出来的，不是估算）

任务书是一份 **859 字节的自撰竞标任务书**（"三剪客一句话批量出片"的新客获取活动，
预算 ≤ 8 万元、周期 ≤ 30 天、人力 ≤ 3 人），模型 `deepseek-chat`。

### 调用与 token

| 阶段 | 调用 | prompt | completion | 小计 |
|---|---|---|---|---|
| 三组独立提案 | 3 | 3,954 | 6,849 | 10,803 |
| 评委团打分 | 3 | 25,361 | 10,530 | 35,891 |
| 交叉质询（出题 + 作答） | 6 | 23,063 | 23,050 | 46,113 |
| 裁决 | 1 | 62,135 | 2,475 | 64,610 |
| **合计** | **13** | **91,450** | **19,854** | **111,304** |

`finish_reason` 全部是 `stop` —— **没有一次是被 `max_tokens` 截断的**
（所以"加大 `--max-tokens`"对这几次跑没有任何帮助；这一点本包在调用台账里逐条记着）。

按 `--price-in 300 --price-out 600`（点/百万 token）折算：
**39.35 点 ≈ ¥0.3935**。

### 打分明细（本地按公示权重重算，不采信模型自报）

| 组 | 成本(0.30) | 可行性(0.25) | 差异化(0.25) | 风险(0.20) | 加权总分 |
|---|---|---|---|---|---|
| A 组 · 成本快打 | **8.167** | **7.500** | 6.500 | 7.000 | **7.350** |
| B 组 · 差异化造势 | 2.667 | 4.167 | **7.833** | 6.667 | 5.133 |
| C 组 · 稳控兜底 | 6.500 | 5.833 | 4.500 | **8.000** | 6.133 |

**一票否决：无**（风险与合规评委没有对任何一组行使否决权）。

### 三组提案是真的在竞争，还是同一份稿子换三种说法？

**是真的在竞争。** 判据不是"它们读起来不一样"，而是可以直接复核的本地数字：

| 判据 | 实测值 | 阈值 | 结论 |
|---|---|---|---|
| A↔C 重合度 | **0.213** | 0.75 | 远低于阈值 |
| A↔B 重合度 | **0.198** | 0.75 | 远低于阈值 |
| B↔C 重合度 | **0.165** | 0.75 | 远低于阈值 |
| 三份方案字数 | 3,616 / 2,504 / 2,860 字 | —— | 篇幅相当，不是"一长两短" |

三份方案的开头一句话（原文）：

> **A 组**：不投流不拍片：用 37 个付费用户和 2600 人微信群，3 人 3 天跑通转化主干，总花 1.2 万
> **B 组**：把 120 条样片做成可拆解产线公开直播，让用户先看拆解再付费
> **C 组**：三剪客 30 天新客获取：先立验收与兜底，再跑四条可回滚渠道

三组走的是**三条不同的路线**（省钱的 / 造差异的 / 求稳的），而且各自在自己那条路上
走到了极端 —— 这正是闸门五要保护的东西。**如果三组交的是同一份东西的三种说法，
闸门五会直接判「假竞争」并让整条命令 `exit=3`**（这条用例在闸门自检里覆盖，
夹具是同一段话换三个抬头，重合度被算到 1.00）。

### 交叉质询记录（每组只看到对方的主张摘要）

质询主持对每一组出题，其中最硬的一条是"你凭什么比另外两组更该拿到名额"。
作答里必须给出 `why_better`（`than` 只能填摘要里已出现的主张）与 `cannot_beat`
（如实承认比不过的那一条）。真机实测三组各自答出了不同的落点：

- **A 组**比的是速度与现金效率（三天可投放 vs 十四天）；
- **B 组**比的是可复现的产线三件套（输入文本 + 参数面板截图 + 成片时间戳对照，
  第三方按 PDF 第 2 页口径可复跑，成功率 ≥ 66.7% 算差异成立）；
- **C 组**比的是兜底完整度（四渠道全部触发后的替代路径、停投阈值、回滚动作）。

**交叉可见性证据**（本地核对，不是声明）：每组提示词里是"自己的全文 + 对方摘要 2 条"，
对方**原文**泄漏 **0 处**（判据：对方方案里 ≥ 20 字的句子若出现在提示词里且不属于
"摘要"或"评委引文"，才算泄漏）。

### 裁决

**终裁：C 组获胜。** 这里有一个**必须说清楚的实测现象**：

> 模型判的赢家（C 组）**不是本地总分第一**（A 组 7.35 > C 组 6.13）。
> 裁决给出的理由是实质的、可复核的 —— A 组的成本算式**自己不闭合**：
> 主算式写"人力 3 人 × 10 天 × 300 元 = 9000 元"，而执行周期写到第 30 天，
> 第 11~30 天的人力没进算式，按 30 天口径重算应为 13,500 元、
> 总成本 16,500 元、单客成本 165 元，**120 元阈值失守**。

本包对这种情况的处理是刻意的：**不直接拦，但必须记下来并要求理由**。
`gates.award.audit.winner_not_top_by_total` 会原样记着

```json
{"winner": "team_c", "winner_total": 6.133,
 "top": "team_a", "top_total": 7.35,
 "note": "模型判的赢家不是本地总分第一——裁决里必须给出为什么"}
```

理由是"评委的定性判断可以压过算术，但必须解释"。如果 `why_winner` 是空的，
闸门六就拦住整条命令。这样既不把模型的判断权重抹掉，也不允许它无声地翻盘。

**落选原因**（逐组，都带锚定到该组方案原文的引文）：

- **A 组落选**：成本维度的端到端口径不闭合（人力只算 10 天，timeline 写 30 天）；
  同时风险维度的过程阈值设在 2.5%，与任务书的 4% 目标不一致。
- **B 组落选**：成本维度全篇只有 126 小时工时与"按人力成本口径折算"这类无金额表述，
  没有一项单价 × 用量、没有总价算式，按评分标准接近 0 分档；可行性上还要 3 人扛 30 场直播。

**合并建议**（落选方案的可用部分，四条，都带来源与锚点）：

| 从哪来 | 拿什么 | 补进哪里 | 补上什么缺口 |
|---|---|---|---|
| B 组 | 三件套（输入文本 + 参数面板截图 + 成片时间戳对照）与第三方复跑口径 | 获胜方案的差异化段落 | 把差异从"流程主张"变成"第三方可复跑"的可验证物 |
| A 组 | 37 个付费用户的素材二次剪辑授权书（含 30 天排他期、编号与 H5 同源、可抽查 3 份） | 获胜方案的授权口径一处 | 补上"授权只有泛化表述"的缺口，使其成为可指认的独占点 |
| A 组 | 第 2 天群发后 24 小时的点击阈值与私聊替代路径 | 获胜方案风险维度的"停投后替代路径" | 补上"全渠道停投后活动停摆"的缺口 |

**异议保留**：三名评委各自对获胜组的低分维度、以及对落选组的高分维度，
全部原样记在 `award.json` 的 `dissent` 里（"差异与传播评委给 B 组差异化 8.0，
是三份里最高"与终裁取向不同，照样在案，没有被抹平）。

## 六、产出目录长这样

```
D:/bid/
├── rubric.json / rubric.md        公示的维度与权重（**提案之前**定的）
├── proposal_team_a.json / .md     A 组方案
├── proposal_team_b.json / .md     B 组方案
├── proposal_team_c.json / .md     C 组方案
├── proposals.md                   三组方案汇总 + **信息隔离证据**
├── panel.json  / panel.md         评委团打分表 + 锚点校验 + 一票否决 + 本地点票
├── challenge.json / challenge.md  质询记录（出题 + 作答 + **交叉可见性证据**）
├── award.json  / award.md         裁决书：获胜 + 落选原因 + **合并建议** + 打分明细
├── task_brief.json / task_brief.md 任务书整理（纯本地，零成本）
├── REPORT.md                      总报告（八道闸门 + 全程明细 + token 台账）
└── state.json                     断点文件（重跑不重复扣费）
```

产出**一律落在包外**的 `--outdir` 里。包内只允许
`.md .py .txt .json .sh .js .yaml .yml .csv` 这几种后缀；`--outdir` 指到包内直接 `exit=2`。

**同一个 `--outdir` 重跑只会打印「断点命中，跳过」，0 次调用。**
断点 key 里含任务书摘要与字符数、提示词长度、模型、温度、**组组合、评委组合**、
上游产物摘要，以及三套口径版本（评分 / 提示词 / 班组定义）—— 少一个就会出现
"改了参数却复用旧产物"。

有一条额外的零成本路径 `--replay`：`run --replay <已有产物目录>` 只用存下来的
`panel.json / challenge.json / award.json` 重跑本地闸门与报告，**一次调用都不发**。
它是**严格只读**的：不写产物、不写断点文件；缺哪个产物就直接报错（退出码 2），
**绝不容许"回放时顺手把该有的东西重新生成一遍"** —— 那要花钱。
它还**重新做一遍本地校验**（锚点、重合度、交叉可见性、裁决完整性都从 `raw` 重算），
所以手工改过的产物绕不过闸门。
