# 接口速查（网页背后的那几条）

> 网页版点一下就出片，背后调的是 **api.a7w.cn** 的这几个接口。
> 这一页给两类人看：**想自己写脚本的**、**想排错看日志里任务号的**。
>
> 完整的命令行客户端（15 个命令、本地预检、dry-run、批量）见同系列技能 **`avatar-autoclip`**。
> 本页只列网页版实际用到的部分，参数口径按**实测**写。

---

## 0. 通用约定

| 项 | 值 |
|---|---|
| 根地址 | `https://api.a7w.cn/api/v1` |
| 鉴权 | 请求头 `Authorization: Bearer <你的 Key>` |
| 取 Key | 到 https://api.a7w.cn/ 注册创建（1 元 = 100 点） |
| 计费单位 | 点（`rate: 100` ⇒ 1 元 = 100 点） |

**⚠️ 根地址已锁定**：本产品只走 `api.a7w.cn`。改地址不会"换个上游"，只会一路报错。

---

## 1. 素材上传（0 计费）

```
POST /api/v1/upload
Content-Type: multipart/form-data
字段：file
```

返回一个地址（字符串，或 `{uri|url|file_url}`）。**上传不计费**，可以放心先传再决定。

---

## 2. 文案转配音

```
POST /api/v1/apps/voice_tts/tts_live
{ "text": "要念的文案", "voice": "<音色ID>" }
→ { "task_id": "task_xxx" }        # 异步，拿 task_id 去轮询
```

> **实测坑**：另一条同步路由 `voice_tts/tts` **在 api.a7w.cn 上是坏的**（任何参数都失败）。
> 必须走 `tts_live` / `tts_async` 这条异步线。

### 音色

```
GET /api/v1/apps/voice_tts/list_voices?page_number=1&page_size=50
```

> **实测坑（参数命名不一致）**：这个接口吃的是 **snake_case** 的
> `page_number` / `page_size`。传 camelCase 的 `pageSize` **会被静默忽略**，
> 结果只返回 10 条 —— 看起来像"音色变少了"，其实是参数没生效。

```
POST /api/v1/apps/voice_tts/clone_voice
{ "audio_url": "https://.../sample.mp3", "title": "我的音色" }
```
样本要求：**10~60 秒干净人声**（无背景音乐、无回声）。

## 3. 入口① 数字人（图片 + 文案）

```
POST /api/v1/apps/image_human/submit
{ "image_url": "https://.../face.jpg", "audio_url": "https://.../voice.mp3", "mode": "2k" }
→ { "task_id": "task_xxx" }
```

- `mode` 对应页面上的**生成模式**档位。
- ⚠️ 人像合成需持有该肖像的授权；未授权请勿提交。

## 4. 入口② 对口型（视频 + 文案）

```
POST /api/v1/apps/lipsync/submit
{ "video_url": "https://.../person.mp4", "audio_url": "https://.../voice.mp3", "model": "super-lipsync-pro" }
→ { "task_id": "task_xxx" }
```

> **实测坑（字段名不是你以为的那个）**：这里要的是 **`video_url` / `audio_url`**，
> 传 `video` / `audio` 会失败。

模型档位（点/秒，按**音频**真实时长计）：

| 页面档位 | model | 点/秒 |
|---|---|---|
| 大师版 | `super-lipsync-pro` | 21 |
| 全能版 | `super-lipsync` | 15 |
| 体验版 | `super-lipsync-lite` | 3 |

## 5. 套模板成片（智能剪辑）

### 取模板列表

```
GET /api/v1/apps/smart_clip/template/lists?scene=realMan&pageSize=50&sid=<游标>
```

- **`pageSize` 是 camelCase**（和上面音色列表相反！），单页最大 **50**，游标字段是 `sid`。
- `scene`：`realMan`（真人口播混剪）/ `oralMixCutting`（素材混剪）/ `newsMixCutting`（新闻体）。
- ⚠️ **数字人成片只能用 `realMan` 这组模板**；另两个场景不走数字人。

### 提交成片

```
POST /api/v1/apps/smart_clip/realman_broadcast
{
  "styleId":  "<模板ID>",
  "videoUrl": "https://.../dh.mp4",
  "title":    "成片标题",
  "processRules": { ... }
}
→ { "task_id": "task_xxx" }
```

**成片固定 999 点/条，与时长无关。**

## 6. 通用任务查询

```
GET /api/v1/tasks/<task_id>
```

网页版进度区日志里显示的 `task_id` 就是它 —— **拿到 ID，关了网页也能继续查**。

### 实测坑：刚 `completed` 时结果地址可能是空串

任务状态已经是 `completed`，但结果 URL 还是空的 —— 这是**实测到的竞态**，
数字人 / 剪辑 / TTS / 生图都会遇到。**正确做法是继续轮询直到结果字段非空**，
不要一看到 `completed` 就去读地址（会拿到空值，误判成失败）。

### 实测坑：上游偶发瞬时故障

日志里会看到这种：

```
task_id=task_xxx（第 1 次尝试）
  [   185s] #8 failed
  [重试] 上游瞬时故障，15 秒后重新提交…
```

- 这是**弹性 GPU 机器丢失**，跟你的参数无关；
- **失败任务不扣费**；
- 程序会**自动重试（默认 3 次）**；
- **别同时开多个任务** —— 并发更容易撞上，串行反而最快。

## 7. 响应信封（有四种形态，别只按一种解析）

| 形态 | 取值路径 |
|---|---|
| 平台标准 | `data.<字段>` |
| 中转二次包装 | `data.result.data.<字段>` |
| 列表 | `data.items[]` 或 `data.result.data.results[]` |
| 裸对象 | 直接就是 body（如余额 `{available_points, points, frozen, yuan, rate}`） |

写解析时建议**递归找目标键**，不要写死层级。
