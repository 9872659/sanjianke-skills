# 三剪客 · 评审委员会

> ## ⚠️ 先申请你自己的 API Key
>
> **本 Skill 不内嵌任何密钥，也不代付费用。** 请到
> **[算力集市 api.a7w.cn](https://api.a7w.cn/)** 注册并创建**你自己的** API Key
> （新用户有赠送点数，可以先免费试跑几条）。
>
> 拿到后填进环境变量 `A7W_API_KEY`，或直接传给 `--key` 参数。
> **请勿使用他人提供的 Key** —— 用量与费用都记在 Key 所属账号上。

## 能做什么

给一份**别人已经写完的方案/稿件**开一场**对抗式**评审，产出一份**裁决书**：

```
panel   → 四席独立评审（信息隔离，互相看不到对方的意见）
clash   → 对质：找出真实分歧，逐点辩清代价与裁法
verdict → 裁决书：结论 + 条件清单 + 少数派意见保留在案
```

它替代的是决策会上最耗人的那一步：不是"没人提意见"，而是
**"意见提了一堆，但谁支持谁反对、争的到底是什么、最后凭什么这么定，没人说得清"**。

| 你最关心 | 答案 |
|---|---|
| 跟"多调几次模型"有什么不同 | 四席是**四次独立调用**，每次只带本席位的立场块；对质阶段才把四份意见放到一起 |
| 会不会四个角色说同样的话 | 会，但会被拦下：本地算四席「自己的话」的重叠度，任一对 ≥ 0.75 判**立场失效**，`exit=3` |
| 它追不追求"达成一致" | **不追求**。四席零分歧且结论全同 → 同样判立场失效（材料确实无争议时用 `--unanimous-ok`） |
| 意见会不会是泛泛之谈 | 会，但会被锚点闸门拦下：每条意见必须引用材料原文真实句子，编造的引文剔出（未锚定率 > 40% 判定位失败） |
| 反对意见会不会被吞 | 不会：有席位反对却判「通过」→ 拦；与裁决方向不一致的席位没进少数派意见 → 拦 |
| 裁决是不是只有一句话 | 不是。条件清单（含"怎么算满足"）+ 少数派意见是**必填**，判「否决」时条件写的是"要翻案必须做到什么" |
| 多少钱 | 按 token 计费。实测：706 字符方案 = 6 次调用、30,751 token、约 70 秒 |
| 要装什么 | **什么都不用装**。只用 Python 标准库，不需要 pip install 任何东西 |

### 三个命令就够（零成本那两个先跑）

```bash
python3 scripts/run.py seats                              # 看四个席位的立场（零成本）
python3 scripts/run.py brief --file 方案.md --platform    # 把材料整理成评审材料（零成本）
python3 scripts/run.py cost  --file 方案.md               # 报价：大概花多少 token（零成本）
python3 scripts/run.py run   --file 方案.md --outdir D:/board   # 一条命令跑完整评审
```

### L3 定位：这是"对抗式"，不是"流水线式"

| | 流水线式（角色顺序协作） | 内容质量闭环（L2 单循环） | **本包（对抗式 L3）** |
|---|---|---|---|
| 输入 | 一个选题，从零写 | 一篇别人写完的成稿 | **一份已有的方案/稿件** |
| 形态 | 角色按顺序接力 | 一个声音自我迭代 | 多立场**同时**独立评审 + 当面对质 |
| 核心机制 | 打回重写 | 打分 → 重写 → 复评到收敛 | **分歧显性化 + 裁决** |
| 产出 | 定稿 | 定稿 + 评分轨迹 + 逐句台账 | **裁决书** + 条件清单 + 少数派意见 |
| 终止 | 跑完流水线 | 分数过线 / 轮次用尽 | 出裁决（**不追求收敛**） |

**和 L2 的差别不是"多几个评分维度"**：L2 的五个维度是同一把尺子上的五个刻度，
服务于同一个目标、越迭代越收敛；本包的四席是四个**互相冲突的目标函数**，
一旦收敛就说明立场没起作用。

## 怎么用（命令行）

### 第 0 步：获取 API Key

到 **[api.a7w.cn](https://api.a7w.cn/)** 注册，创建一个 API Key（形如 `sk-...`）。

### 第 1 步：装依赖

**零依赖。** 只要机器上有 Python 3.7+：

```bash
python3 --version
```

包里自带的 `scripts/a7w.py` 是零依赖客户端（只用 `urllib` / `json` / `mimetypes`），
`scripts/run.py` 也只用标准库。

### 第 2 步：填 Key

```bash
# Linux / macOS
export A7W_API_KEY=sk-你的key

# Windows PowerShell
$env:A7W_API_KEY="sk-你的key"
```

也可以存进配置文件反复用（推荐）：

```bash
python3 scripts/a7w.py login --key sk-你的key
```

### 第 3 步：先做零成本自检（不联网、不花点数）

```bash
# 看四个席位的立场与目标函数
python3 scripts/run.py seats

# 把待评方案整理成评审材料：大纲 / 数字 / 专有名词 / 本地预扫（合规·占位符·照抄示例）
python3 scripts/run.py brief --file 方案.md --json --out brief.json

# 报价：这次评审大概花多少 token（金额要你自己填单价）
python3 scripts/run.py cost --file 方案.md
```

### 第 4 步：跑第一个例子

```bash
# 一条命令跑完整评审（brief → panel → clash → verdict），断点续跑
python3 scripts/run.py run --file 方案.md \
    --outdir D:/board --json --out D:/board/run.json
```

`--outdir` 里会落 10 个文件：`brief.md/json`、`panel.md/json`、`clash.md/json`、
`verdict.md/json`、`REPORT.md`（总报告）、`state.json`（断点）。
**同一个 `--outdir` 重跑只会打印"断点命中，跳过"，0 次调用。**

### 分步跑（想看清每一步时）

```bash
python3 scripts/run.py panel   --file 方案.md --outdir D:/board --json --out D:/board/panel.json
python3 scripts/run.py clash   --file 方案.md --panel D:/board/panel.json --json --out D:/board/clash.json
python3 scripts/run.py verdict --file 方案.md --panel D:/board/panel.json \
                               --clash D:/board/clash.json --json --out D:/board/verdict.json
```

### 只想预演提示词（不花钱）

```bash
python3 scripts/run.py panel --file 方案.md --dry-run
```

`--dry-run` 打印**四席各自的完整提示词**（可以据此核对信息隔离：每份提示词里只有本席位的立场块）。
对质与裁决的提示词依赖四席产出，预演不出来——这一点在文档里明说了。

## 参数说明

### 全局

| 参数 | 说明 |
|---|---|
| `--json` | 以 JSON 输出；**写在子命令前后都可以**。**stdout 永远只有一个 JSON**（契约见下） |
| `--key` | 临时指定 API Key（也可用 `A7W_API_KEY` 或 `~/.a7w/config.json`） |
| `--dry-run` | 只打印将发送的提示词，**不调模型、不花钱** |
| `--out` | 把结果写到文件。**带 `--json` 时写的是结果 JSON**（可原样喂给下一个子命令） |

### `--json` 契约（给流水线与 agent 消费）

| 情形 | stdout | 退出码 |
|---|---|---|
| 成功 | 结果对象，含 `"ok": true` | 0 |
| **闸门命中，但结果已产出** | **结果对象本身**就带 `"ok": false`、`"exit": 3`、`"gate_failed": true` 与完整 `gates`（**不再另补错误信封**，守住"只有一个 JSON"） | 3 |
| 失败且结果未产出（参数错 / 调用失败 / 预算超限 / 未捕获异常） | `{"ok": false, "exit": <码>, "error": {"kind": …, "message": …}}` | 2 / 4 / 5 / 1 |

`error.kind` 取值：`usage` / `gate` / `call` / `budget` / `interrupt` / `internal`。
`kind: "internal"` 是未预料异常的兜底信封（退出码 1），**完整 traceback 原样打到 stderr**——
报 bug，不藏 bug。人读文案一律走 stderr，非 `--json` 模式的输出一个字符都没变。

### 材料输入与席位（`panel` / `clash` / `verdict` / `run` 共用）

| 参数 | 说明 |
|---|---|
| `--file` | 待评方案/稿件（`.md` / `.txt`，UTF-8，自动去 BOM） |
| `--seats` | 只跑指定席位（逗号分隔），默认全部四席：`user_advocate` / `competitor_analyst` / `compliance_officer` / `business_owner`。**至少两席**，否则 `exit=2` |
| `--model` | 模型名，默认 `deepseek-chat`（实测可用；用 `run.py models` 现查在架模型） |
| `--temperature` | 采样温度，默认 0.7（**进断点 key**） |
| `--max-tokens` | 单次输出上限，默认 8192 |
| `--replay` | 回放一份已保存的阶段产物（panel 传文件，run 传目录）：**零调用**，只跑本地闸门与渲染。panel 会**重算锚点**，不直接信文件里的结论 |

### `run` 专有

| 参数 | 说明 |
|---|---|
| `--outdir` | 目录产物落这里，**必须在包外**；落在包内 `exit=2`。默认 `%TEMP%/review-board-out` |
| `--force` | 忽略断点文件从头重跑（key 没命中就会重新花钱） |
| `--unanimous-ok` | 允许「四席结论全同且零分歧」不判立场失效（**只在确认材料本身无争议时用**；默认是硬闸门） |

### `cost` 专有

| 参数 | 说明 |
|---|---|
| `--file` / `--text` | 按材料或直接文本估 |
| `--seats` | 按几个席位估（默认四席） |
| `--price-in` / `--price-out` | 单价，单位「点 / 百万 token」。**不给我就不给金额（不编价）** |
| `--budget` | 预算上限（点），超了 `exit=5`；**用 `--budget` 必须给单价**，否则 `exit=2` |

### 四个席位

| 席位 | id | 目标函数 | 天然倾向 |
|---|---|---|---|
| 用户代言人 | `user_advocate` | 用户会不会觉得有用 / 被骗 | 自嗨、术语堆砌、承诺不清 |
| 竞品分析师 | `competitor_analyst` | 和市面上的比有没有可指认的差异 | 同质化、没声称、可替代 |
| 合规官 | `compliance_officer` | 法律与平台风险 | 违禁词、绝对化、资质、刷单话术 |
| 业务负责人 | `business_owner` | 投入产出与可执行性 | 成本过高、链路太长、没有 CTA |

四个立场在结构上就是对撞的：业务负责人要补 CTA 的时候，合规官正好在拦那句承诺；
用户代言人嫌术语多的时候，竞品分析师正好觉得那些术语就是差异化。
细节见 `references/席位与立场设计.md`。

## 八道本地硬闸门（都是确定性的，跑两次结果一样，可直接进 CI）

| # | 闸门 | 判据 | 退出码 |
|---|---|---|---|
| 1 | 合规 | 违禁词（最 / 第一 / 国家级 / 100% / 保过…）；「最X」可枚举上下文豁免 + **句首不豁免**；材料侧全档、产出侧只查高风险并排除「引用」与「提到」 | 3 |
| 2 | 占位符残留 | `{}` / `[待填]` / `XXX` / `（此处省略）` / `TODO` | 3 |
| 3 | 照抄提示词示例 | 去标点相等 / Jaccard ≥ 0.75 / 覆盖度 ≥ 0.60（带适用窗口：长度比 ≤ 3.0 且示例 ≥ 8 字） | 3 |
| 4 | **评审锚点** | 三层引文各锚各的文本；未锚定率 > 40% 判「定位失败」 | 3 |
| 5 | **立场有效性** | 任一对席位「自己的话」重叠度 ≥ 0.75；或四席结论全同 + 零分歧 | 3 |
| 6 | **裁决完整性** | 有反对却判「通过」/ 条件清单为空 / 少数派被抹平 | 3 |
| 7 | 成本上限 | `--budget` 超限就地中止（**未发起调用**） | 5 |
| 8 | 产出不许进包 | `--outdir` / `--out` 落在 Skill 包内 | 2 |

命中一律：**标红 + stderr 汇总 + 非 0 退出码**。

### 第 5 道闸门为什么是本包最值钱的那道

四个角色说同样的话，看起来像"一致通过"，实际上是**一场表演**——立场没起作用。
这道闸门不看模型的自述，本地算：

- **重叠度** = 较短那份有多少比例的内容出现在较长那份里（min 归一，不是 Jaccard：
  两席篇幅天然不同，Jaccard 的分母是并集，篇幅差一大就把相似度摊薄了）
- **只算「自己的话」**（`verdict / must_have / kill_switch / summary / why / ask`），
  **不算各自引用的材料原文**——四席引用同一句原文是正常的，算进去会误判
- 任一对 ≥ 0.75 且短的那份 ≥ 30 个二元组 → 判**立场失效**，`exit=3`
- 另一种失效形态：**对质一个真分歧都没找到，且四席结论完全相同** → 同样判失效
  （材料确实无争议时用 `--unanimous-ok` 降级为标红）

真机实测：四席结论全部为「反对」，但最大重叠度只有 **0.20**，各自的理由落在
事实口径、差异化、合规、预算对账四个互不重叠的维度上——这才是真的四个立场。

含 `--unanimous-ok` 在内，**25 个闸门自测用例全部零成本**（走 `--replay` 与参数校验路径）。

## 退出码（可直接用于 CI）

| 码 | 含义 |
|---|---|
| 0 | 裁决出来了，且没有硬闸门命中 |
| 2 | 用法/配置错误（文件不存在、席位名错、席位少于两个、产出路径在包内、`--budget` 没配单价） |
| 3 | 硬闸门命中（合规 / 占位符 / 照抄示例 / 锚点 / **立场失效** / **裁决不完整**） |
| 4 | 调用失败（网络 / 鉴权 401 / 点数 402 / 模型名 404） |
| 5 | 预算超限，已就地中止（**未发起任何调用**） |
| 1 | 未捕获异常（`--json` 下给 `kind:"internal"` 信封 + 完整 traceback 到 stderr） |
| 130 | 用户中断 |

## 产出目录长这样

```
D:/board/
├── brief.md / brief.json      评审材料（大纲 / 数字 / 专有名词 / 本地预扫）
├── panel.md / panel.json      四席独立意见 + 锚点校验 + 立场重叠度 + **隔离证据**
├── clash.md / clash.json      真实分歧 + 被剔出的伪分歧 + 背景共识
├── verdict.md / verdict.json  **裁决书**：结论 + 条件清单 + 少数派意见 + 票表核对
├── REPORT.md                  总报告（四席意见 + 分歧 + 裁决书 + 八道闸门 + token）
└── state.json                 断点文件（重跑不重复扣费）
```

产出**一律落在包外**的 `--outdir` 里。包内只允许
`.md .py .txt .json .sh .js .yaml .yml .csv` 这几种后缀。
