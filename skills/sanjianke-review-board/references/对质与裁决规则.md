# 对质与裁决规则

> 这份文档回答两个问题：**什么算"真分歧"**，以及**裁决书必须包含什么**。
> 两条都由本地闸门校验，不采信模型的自我声明。

---

## 一、对质（`clash`）：把隔离出来的差异摆到同一张桌上

`panel` 之后有四份互不相知的意见。`clash` 做的事只有一件：
**找出有人支持、有人反对的那个点**，并逐点辩清楚。

每条分歧固定输出七个字段：

| 字段 | 含义 | 为什么必须有 |
|---|---|---|
| `topic` | 争点的一句话概括 | 让人一眼看到在争什么 |
| `crux` | 争的到底是哪一点（不可再分） | 防"把一个大话题当分歧"糊过去 |
| `sides[]` | 两侧：`stance` + `seats` + `quote` | 支持 vs 反对，各自的原话 |
| `why_real` | 为什么这是真分歧，不是措辞差异 | 防注水 |
| `cost_of_each_side` | 各让一步分别要付出什么代价 | 让"裁"这个动作有成本感 |
| `tie_break` | 只能选一边的话，按什么证据/规则裁 | 给最终裁决铺路 |
| `seat_ids` | 涉及席位（本地算，不采信自报） | 便于统计"谁最常被反对" |

---

## 二、什么算"真分歧"

**判据：同一件事上有人支持、有人反对，且换一边会让结论不同。**

本地对每条分歧做四道校验（`validate_clash`），任何一道不过就剔进 `rejected_divergences`：

1. **至少两侧**——只有一侧写不出对质
2. **两侧立场必须真的对立**——有效侧里必须同时出现「支持/有条件支持」与「反对」。
   只有一边、或两边同向 → 不算分歧
3. **每个 side 的 `seats` 必须是真实存在的席位 id**（显示名也会被归一成 id）
4. **每个 side 的 `quote` 必须锚定到那个席位自己说过的话**——
   锚不上说明它在**替别的席位发言**或**编造引文**，该侧作废

第 4 条是本包特有的一道：**对质最容易注水的地方就是替别人发言**。
一份"分歧"里如果引用的话不是那个席位说的，那这个分歧是主席编出来的。

### 一种不拦但要标出来的情况：同一席位出现在两侧

真机实测出现过：业务负责人被同时放进一条分歧的「支持」侧与「反对」侧——
标注自相矛盾。本包的处置是**标出来但不作废这条分歧**：

- **不作废**：争点本身可能是真的（那一轮里该争点的核心矛盾确实存在），
  作废会把真内容丢掉，比留着更糟
- **要标出来**：`seat_on_both_sides` 字段 + 报告里一行警告，让人自己判断该信哪一边

理由和闸门设计的整体取向一致：**不静默丢弃，也不静默接受**。

`rejected_divergences` 会出现在报告里，**不删除**——它记录的是模型试图把什么当成分歧。

## 三、伪分歧的四类常见形态

| 形态 | 例子 | 本地判定 |
|---|---|---|
| 措辞差异 | 一个说"太术语"，一个说"不够口语" | 结论一致 → 不算 |
| 一边倒 | 两侧都是"支持"，只是一边更积极 | 立场没有对立 → 不算 |
| 替人发言 | 引用了某席位没说过的话 | `quote` 锚不上 → 该侧作废 |
| 虚空分歧 | 争的是一个材料里根本没提的东西 | `quote` 引不出原文 → 锚不上 |

反过来说，**判不出分歧也是一个结论**（`divergences: []`），但要走两条路：
模型要在 `no_divergence_reason` 里说明理由，而**闸门五会复核**——
四席结论全同 + 零分歧时，本包把它判为「立场失效」（`exit=3`），不是「一致通过」。

## 四、裁决（`verdict`）：三档结论 + 条件清单 + 少数派

### 结论只有三档

| 档 | 什么时候可以用 | 本地校验 |
|---|---|---|
| `通过` | 四席**全部无保留支持**，且**无未解决的真实分歧** | 有反对/有条件支持席位却判通过 → 拦 |
| `有条件通过` | 存在可被满足即可放行的路径 | **条件清单为空 → 拦** |
| `否决` | 反对理由在当前材料中已经成立（"现状即触发否决"） | **条件清单为空 → 拦** |

注意 `否决` 也**必须带条件清单**：否决时的条件写的是"**要翻案必须做到什么**"。
这是本包的一条硬纪律——只给一个"否"字的裁决书，下一版方案无从下手，
用户拿到的是一句情绪而不是一份交付物。

反过来，判 `通过` 时条件必须是空的：带条件就该判「有条件通过」。

### 每条条件必须可验证

```json
{
  "id": 3,
  "what": "必须满足什么（可落纸）",
  "from_seats": ["compliance_officer"],
  "quote": "提出这条的席位**原话**",
  "how_to_verify": "怎么算满足了"
}
```

- `what` 不许写成"注意合规""建议加强"这类空话
- `from_seats` 必须是真实席位 id
- `quote` 必须锚定到**它标注的那个席位**说过的话；
  锚不上会标 `problem`（不采信自报，请人工复核）
- `how_to_verify` 是给下一版方案的对账口径——**没有它，条件就不可验收**

### 少数派意见必须保留在案

**谁算少数派**（本地判，不采信模型自报）：

| 最终裁决 | 必须出现在 `minority` 里的席位 |
|---|---|
| `通过` / `有条件通过` | 所有 `verdict = 反对` 的席位 |
| `否决` | 所有 `verdict = 支持 / 有条件支持` 的席位 |

缺一个就判「少数派被抹平」→ `exit=3`。

`minority[*]` 要带 `position`（该席位的立场，原话或紧贴原话）与 `why_kept`。
**不许改写成主席自己的话**——真机实测里主席会写"该席位结论为反对，其合规底线为独立否决理由，
须原样保留"，这是合格写法。

### 票表以本地为准

`verdict` 允许模型自报 `vote_table`，但报告里展示的票表是**本地从四份意见里读出来的**
（`local_vote_table`）。两者不一致的地方会逐条列在 `vote_audit.mismatches` 里——
这是防"主席把自己的判断塞进别人的票里"。

## 五、闸门六：裁决完整性的三条纪律

```
1. 有席位反对（或有条件支持）却判「通过」        → 拦
2. 判「有条件通过」或「否决」而条件清单为空      → 拦
3. 与裁决方向不一致的席位没出现在少数派意见里    → 拦
```

三条都在本地判（`verdict_gate`），退出码 3。

## 六、评审锚点：三层引文，各锚各的文本

这是本包与同族最不一样的地方。一条引文必须锚到**它该锚的那份文本**上：

| 谁引用 | 必须锚到 | 不锚上意味着 |
|---|---|---|
| 席位意见的 `quote` | **待评材料**的某一句 | 意见是泛泛之谈，没落到原文 |
| 对质的 `side.quote` | **那个席位自己说过的话** | 替人发言 / 编造引文 |
| 裁决条件的 `quote` | **它标注的那个席位**说过的话 | 移花接木 |

四条判据递进（与全族一致）：

| 判据 | 条件 |
|---|---|
| `exact` | 归一化（去标点空白）后与某一整句完全相同 |
| `substring` | 归一化后是某句的一部分，或某句是引文的一部分（≥ 4 字） |
| `fuzzy` | 与最像的那句字符二元组 Jaccard ≥ 0.55，且引文 ≥ 8 字 |
| `unverified` | 以上都不成立 → **判为锚点幻觉**，剔出并计入未锚定率 |

**未锚定率 > 0.40 → 判「定位失败」**，压分 + 标红 + stderr 汇总 + `exit=3`。

为什么两个长度门槛不一样（4 与 8）："引文是某句的连续片段"是**精确**判断，门槛可以矮；
"最像的那一句"是**统计**判断，短串的二元组太少、相似度会虚高，门槛必须高。
用同一个门槛管两件事，就会出现"6 个字的真实引文被判成幻觉"，直接污染未锚定率。

## 七、与另外两个包的分界（三方表）

| | 流水线式内容团队包 | 内容质量闭环（L2） | **本包（对抗式 L3）** |
|---|---|---|---|
| 输入 | 一个选题，从零写 | 一篇别人写完的成稿 | **一份已有的方案/稿件** |
| 形态 | 角色按顺序接力 | 一个声音自我迭代 | 多立场同时独立评审 + 对质 |
| 核心机制 | 打回重写 | 打分 → 重写 → 复评到收敛 | **分歧显性化 + 裁决** |
| 分歧怎么处理 | 后一个角色覆盖前一个 | 不存在（只有一个声音） | **摊开、对质、保留少数派** |
| 产出 | 定稿 | 定稿 + 评分轨迹 + 逐句台账 | **裁决书** + 条件清单 + 少数派意见 |
| 终止条件 | 跑完流水线 | 分数过线或轮次用尽 | 出裁决（**不追求收敛**） |
| 关键闸门 | 结构/时长 | 五维评分 + 锚点 + 事实保全 | **立场有效性 + 裁决完整性** |

**和 L2 的差别不是"多几个评分维度"。** L2 的五个维度是一张加权表里的五个刻度，
服务于同一个目标（把分打上去），越迭代越收敛；本包的四席是四个**互相冲突的目标函数**，
它**不追求收敛**——如果收敛了，说明立场没起作用（闸门五）。
