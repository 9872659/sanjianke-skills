# 闸门口径、成本与排错

---

## 一、端点与鉴权

| 用途 | 方法 | 地址 |
|---|---|---|
| 大模型（OpenAI 兼容） | POST | `https://api.a7w.cn/api/v1/chat/completions` |
| 在架模型清单（免费） | GET | `https://api.a7w.cn/api/v1/models` |

成功响应**不带 `code` 字段**；网关有时把它包一层 `{"code":1,"data":{...}}`，两种形态都认。

Key 三种给法（代码与文档里都不含任何 Key）：

```bash
python3 scripts/run.py run --file 方案.md --key sk-xxxx     # 1) 命令行
export A7W_API_KEY=sk-xxxx                                  # 2) 环境变量（Windows: $env:A7W_API_KEY="sk-xxxx"）
python3 scripts/a7w.py login --key sk-xxxx                  # 3) 写进 ~/.a7w/config.json 反复用
```

⚠️ **本包不走 `a7w._request(raw=...)`**。那边的 `raw` 参数是**原始请求体字节**（给 multipart 上传用），
**不是**"要原始响应"。同族有人把它当成后者用过，结果崩在**钱已经扣之后**。
本包一律自己发 `urllib` 请求，语义只有一种，不给误用的机会。

## 二、八道硬闸门（全部本地、确定性、可进 CI）

命中一律：**标红（`✗` 前缀）+ stderr 汇总 + 非 0 退出码**。

| # | 闸门 | 扫哪份文本 | 判据 | 退出码 |
|---|---|---|---|---|
| 1 | **合规** | 材料 + 产出（口径不同，见下） | 广告法违禁词表；「最X」可枚举上下文豁免 + **句首不豁免**；「第一」序数豁免 | 3 |
| 2 | **占位符残留** | 材料 + 产出 | `{}` / `[待填]` / `XXX` / `（此处省略）` / `TODO` | 3 |
| 3 | **照抄提示词示例** | **产出** | 去标点相等 / Jaccard ≥ 0.75 / 覆盖度 ≥ 0.60（带适用窗口） | 3 |
| 4 | **评审锚点** | 三层引文各锚各的文本 | 精确 / 子串 / 模糊（Jaccard ≥ 0.55）；未锚定率 > 0.40 判定位失败 | 3 |
| 5 | **立场有效性** | 四席意见 | 任一对席位「自己的话」重叠度 ≥ 0.75；或四席结论全同 + 零分歧 | 3 |
| 6 | **裁决完整性** | 裁决书 | 有反对却判通过 / 条件清单为空 / 少数派被抹平 | 3 |
| 7 | **成本上限** | — | `--budget`（点）；**必须配单价**，超限就地中止、**未发起调用** | 5 |
| 8 | **产出不许进包** | `--outdir` / `--out` | 路径落在 Skill 包内 | 2 |

### 闸门一扫两份文本，但**口径不同**

这是真机实测踩出来的（两轮各踩一类误报），不是理论设计：

- **材料侧**：全档（高/中/低风险）全查。材料是会被公开发布的东西，宁可多报。
- **产出侧**：只查**高风险**（明令禁止的那一类），并排除两类**正常写法**：
  1. **引用**：材料里已经出现过的词 → 评审在引用被审对象，不是新宣称
  2. **提到**：命中前后 24 字里有 `禁止 / 不得 / 无法举证 / 属于 / 违规 / 删除 / 改为 …`
     这类标记词 → 评审在**禁止它、指出它**，不是自己在做违规宣称

第二轮真机实测的三处误报正是这样来的：合规官写「无法举证为 100% 成立」
「明确禁止代发、代拍、刷量」，用户代言人写「普通用户读到这组数字的第一反应」——
拿材料侧那把尺子去量评审文书，一天能误报十次，而误报会让人把整个闸门关掉。
被排除的条目**不静默丢弃**：它们带 `not_counted_reason` 列在 `contextual_only` /
`mentioned_as_warning` / `quoted_from_material` 里，随时可人工复查。

**闸门仍然有牙**：`本方案必须保证过审，效果 100% 达标` 这种小句里没有任何标记词，
照样 `exit=3`（自测用例覆盖）。

⚠️ 产出侧合规**不查 `最X`**：「最大的一块」「最高获客成本」是普通中文程度用法与内部测算口径。
材料侧照查。`最X` 的豁免表里另加了一档**商业测算用语**（获客 / 出价 / 预算 / 上限 / 限价 / 成本 / 收益），
仍然遵守同一条边界：**句首不豁免**。

### 闸门三的 contain 适用窗口（**实测标定，不是拍的**）

覆盖度判据（示例被抄了多少）对**短示例**会饱和。本包在真实语料上量过
（105,863 字符 / 3,253 句，脚本见下）：

| 示例长度 | 长度比档位 | 覆盖度上限 | ≥ 0.60 命中 |
|---|---|---|---|
| 13~20 字（跨主题） | 全部档位 | 0.125 ~ 0.333 | **0 条** |
| 2~5 字（2~4 个二元组） | 长度比 ≥ 2 | **0.500** | 0 条（余量只剩 0.10） |

结论：`contain` 只在**两个条件都满足**时适用——

1. 目标片段长度 ≤ 示例长度 × **3.0**（长度比窗口）
2. 示例归一后长度 ≥ **8** 字（二元组数量够用）

不适用时记进 `contain_skipped`（按原因合并计数，**不静默略过**）。
真机一次完整评审里这条判据会被跳过 100~200 次（都是"产出句子比示例长得多"），
这是**正常的**，不是异常。

标定脚本（复现用，纯本地零成本）：

```python
# 把示例与语料句子都做 _norm_anchor，再算 contain = |bigrams(句子) ∩ bigrams(示例)| / |bigrams(示例)|
# 按 len(句子)/len(示例) 分档统计 max 与 ≥0.60 的占比
```

### 闸门五的两个判据（**核心闸门**）

```
判据 A（硬）：任一对席位的「自己的话」重叠度 ≥ 0.75，且短的那份 ≥ 30 个二元组
判据 B（硬）：对质没找到任何真实分歧，且全部席位的结论相同
              → 用 --unanimous-ok 可降级为标红（材料确实无争议时）
```

**为什么重叠度用 min 归一，而不是 Jaccard**：两席的篇幅天然不同（有的写 8 条、有的写 2 条），
Jaccard 的分母是并集，篇幅差一大就被摊薄，"说了同样的话"反而测不出来。
min 归一回答的是"**短的那份有多少比例的内容出现在长的那份里**"。

**为什么只算「自己的话」**：四席经常引用**同一句材料原文**（这是好事，说明大家都看到了同一处问题）。
把 `quote` 算进重叠度，会让"引用同一句"被误判成"说了同样的话"。
所以重叠度只算 `verdict / must_have / kill_switch / summary / why / ask`——
**引文锚点另用一份文本（含 quote）**，两者分开，各司其职。

**门槛 30 的来历（改过一次）**：一开始写 60（防短文本虚高）。自测时发现四席写
**一模一样的 95 个字**（45 个二元组）时重叠度算出来 1.00，却因为没到 60 被判"不拦"——
而这正是本包要抓的形态。参考量级：真机实测四席各自的"自己的话"是 **986~1008 个二元组**
（约 1000 字），门槛 30 只是它的 3%，只能挡住"两席各用十几个通用词"这种真正无信息的噪声。

## 三、退出码（可直接用于 CI）

| 码 | 含义 |
|---|---|
| 0 | 裁决出来了，且没有任何硬闸门命中 |
| 2 | 用法/配置错误（文件不存在、席位名错、席位少于两个、`--outdir`/`--out` 在包内、`--budget` 没配单价） |
| 3 | 硬闸门命中（合规 / 占位符 / 照抄示例 / 锚点 / **立场失效** / **裁决不完整**） |
| 4 | 调用失败（网络 / 鉴权 401 / 点数 402 / 模型名 404） |
| 5 | 预算超限，已就地中止（**未发起任何调用**） |
| 1 | 未捕获异常（`--json` 下给 `kind:"internal"` 信封 + 完整 traceback 到 stderr） |
| 130 | 用户中断 |

### `--json` 与退出码的配合（契约）

| 情形 | stdout | 退出码 |
|---|---|---|
| 成功 | 结果对象，含 `"ok": true` | 0 |
| 闸门命中但**结果已产出** | **结果对象本身**带 `"ok": false`、`"exit": 3`、`"gate_failed": true`、完整 `gates` | 3 |
| 失败且结果未产出 | `{"ok": false, "exit": <码>, "error": {"kind": …}}` | 2 / 4 / 5 / 1 |

第二条是刻意这样设计的：闸门命中时那份**结果本身就是失败报告**，
再补一个错误信封就会破坏"**stdout 永远只有一个 JSON**"这条不变量。
所以消费方读 `ok` 与 `exit`，而不是去猜信封在哪。
（自测中正是因为这条不变量，才发现 `run` 早先把 `ok: true` 与 `exit: 3` 一起吐出来，
机器读不出失败——已改成结果对象自带 `ok: false`。）

⚠️ **`--budget` 必须配 `--price-in` / `--price-out`**，否则 `exit=2`。
这道校验**在每一个会花钱的子命令的第一步**。事故复盘：它原先只写在 `cost` 里，
于是 `panel --file x --budget 50`（没给单价）一路跑完 4 次真实调用才返回——
用户以为设了上限，实际一分钱都没被拦住。

## 四、成本：只出 token，不编金额

- **文本网关不公布单价**，`/api/v1/models` 里也没有价格字段。所以 `cost` 不给我单价就**只报 token**。
- 字符 → token 标定（全族真机实测值，**估算不是账单**）：
  输入 1 token ≈ **1.61** 字符；输出 1 字符 ≈ **1.11** token。
- 一次完整评审的调用构成：

| 阶段 | 次数 | 说明 |
|---|---|---|
| 四席独立评审 | 4 | 每席一次独立调用（信息隔离） |
| 对质 | 1 | 输入 = 材料 + 四份意见（**故意打破隔离**） |
| 裁决书 | 1 | 输入 = 材料 + 四份意见 + 对质结果 |

```bash
python3 scripts/run.py cost --file 方案.md                  # 只出 token
python3 scripts/run.py cost --file 方案.md --price-in 1000 --price-out 2000   # 你的单价 → 点数
```

**真机实测（706 字符的小方案，`deepseek-chat`）**：

| 阶段 | prompt | completion | 耗时 |
|---|---|---|---|
| panel: 用户代言人 | 1413 | 1531 | 9.5s |
| panel: 竞品分析师 | 1403 | 1580 | 9.6s |
| panel: 合规官 | 1427 | 1470 | 9.2s |
| panel: 业务负责人 | 1404 | 1676 | 11.7s |
| clash | 6997 | 2439 | 12.0s |
| verdict | 5367 | 4044 | 17.5s |
| **合计** | **18011** | **12740** | **约 70s** |

**共 6 次调用、30,751 token。** 由于网关不公布文本单价，**无法把 token 折成元**——
按 0.5 元预算反推：30,751 token 要花到 0.5 元（=50 点），等价单价约
**1,626 点/百万 token**；也就是说只要你的账号单价低于这个量级，这一跑就在预算内。
真实金额请以账户流水为准，或自己传 `--price-in/--price-out` 折算。

## 五、断点续跑

- 断点文件：`<outdir>/state.json`，key 形如 `panel:368ff83eb3dc11f0f5b7`
- key 里含：材料摘要与字符数、模型、温度、**席位组合**、口径版本（评分/提示词/席位定义三套），
  以及**上一阶段的产物摘要**（`panel_sha` / `clash_sha`）
- 命中即跳过并打印「断点命中，跳过（0 次调用）」
- 要强跑用 `--force`

**为什么 key 必须含全部影响产出的维度**（同族踩过三次事故）：
内容截断没进 key → 把 8000 字截成 4000 字重跑，静默复用了旧产物；
口径没进 key → 换了闸门口径重跑，命中的还是上一版产物；
席位数量没进 key → 参数调了但没生效，用户以为改过了。

`--replay <目录>` 是另一条零成本路径：读取该目录里的 `panel.json / clash.json / verdict.json`，
**一次调用都不发**，只跑本地闸门与报告渲染。它的用途是"改完闸门口径之后，用同一批真实产物重跑一遍检查"，
以及**闸门自测**（本包 25 个闸门用例全部零成本）。注意 panel 会**重新做一遍锚点校验**，
不直接信文件里存好的结论——否则一份手工改过的 `panel.json` 就能绕过锚点闸门。

## 六、排错

| 现象 | 处置 |
|---|---|
| `没有找到 API Key` | `--key` / `A7W_API_KEY` / `a7w.py login` 三选一 |
| `鉴权失败（401）`／`点数不足（402）` | 到 https://api.a7w.cn/ 重新创建 Key 或充值 |
| `模型不存在（404）` | `run.py models` 现查在架名，别写死 |
| 上游 502/503/504 | 脚本自动退避重试 4 次；仍失败是网关侧问题 |
| `stance` 闸门命中 | 四席意见高度重合或零分歧。先看 `stance.pairs` 的重叠度：真是同一套话，说明该换模型或改席位定义；材料确实无争议用 `--unanimous-ok` |
| `verdict` 闸门命中 | 看 `problems` 原文：吞反对意见 / 条件清单为空 / 少数派被抹平，三种处置完全不同 |
| `anchor` 闸门命中 | 模型在编引文。看 `unanchored_points` 与 `rejected_divergences`；反复出现说明该模型不擅长引用原文，换模型 |
| `output_compliance` 命中 | 看是不是评审自己造了违规宣称；如果只是**提到/引用**却被拦，把上下文发给维护者（标记词表可能需要补） |
| `prompt_echo` 命中 | 产出抄了提示词里的跨主题示例。换模型或降温度 |
| `分数/结论看着不对` | 先看 `isolation` 与 `panel.seats[*].unanchored_points`：意见有没有真正落到材料原文上 |
| 断点续跑没生效 | key 含材料摘要、模型、温度、席位组合、三套口径版本、上一阶段摘要；任一变化都会重跑（故意的） |
| `unrecognized arguments: --out` | 本包**不允许长选项前缀缩写**（故意的：`--out` 曾被静默吃成 `--outdir`）。请写全 |
| `--dry-run` 只打印了四席提示词 | 对质与裁决的提示词依赖四席产出，预演不出来（诚实的限制） |

## 七、本包明确的边界

1. **违禁词表是启发式自检**，来自公开经验整理与真机实测标定，**不构成法律意见**，
   也不代表任何平台官方审核标准。高风险类目（医疗、保健食品、金融、母婴、特殊化妆品）必须人工复核。
2. **产出侧合规是"宁松勿误"的**：只查高风险、排除引用与"提到"。它拦得住"评审自己造违规宣称"，
   但**不保证**产出里每一句都合规——不构成对外的合规背书。
3. **四席共用同一个模型**，隔离靠调用边界，不靠模型差异。
4. **评审质量取决于材料质量**：材料过短（例如只有几句话）时，锚点会大量落在同一两句上，
   四席的重叠度也会天然偏高——此时闸门五的告警要先排除"材料本身信息太少"这个原因。
5. **不能替你做发布决策**。裁决书给的是"该不该过 + 要满足什么条件"，最终发布与否由使用者负责。
