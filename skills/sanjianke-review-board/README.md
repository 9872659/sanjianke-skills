# 三剪客 · 评审委员会

给一份**已经有方案或稿件**开一场**对抗式评审**，产出**裁决书**：

```
seats   →  四个席位与各自的立场（零成本）
brief   →  把待评材料整理成评审材料（零成本）
panel   →  四席独立评审（信息隔离，互相看不到对方的意见）
clash   →  对质：找出真实分歧，逐点辩清代价与裁法
verdict →  裁决书：结论 + 条件清单 + 少数派意见保留在案
run     →  一条命令跑完整评审，断点续跑
cost    →  只算 token，一次调用都不发
models  →  列出在架模型（免费）
```

它替代的是决策会上最耗人的那一步：不是"没人提意见"，而是
**"意见提了一堆，但谁支持谁反对、争的到底是什么、最后凭什么这么定，没人说得清"**。

> 本包**不写稿**、**不改稿**、**不打分排序**。它审的是**别人已经写完的方案**，
> 只回答一个问题：**这份东西该不该过，要过的话必须满足什么。**

---

## ⚠️ 三层的分界：本包是 L3，而且是"对抗式"那一种

### 先看 L1 / L2 / L3 的判据

| 层 | 形态 |
|---|---|
| **L1 单点生成型** | 一个输入 → 一个产出 |
| **L2 智能体型** | **单循环**：抽档 → 写 → 自检 → 迭代（一个声音自我迭代） |
| **L3 多智能体协作型** | **多角色分工互审**，一条命令出成品 |

L3 的关键**不是"调多次模型"**。调多次模型只说明花了更多钱。L3 的判据是：

> **每个角色有自己独立的目标函数，且会互相否掉对方。**

### 再看两个 L3 的分工：流水线式 vs 对抗式

同为 L3，做法可以完全不同。有一个平行的包做**流水线式**（策划 → 写手 → 审稿 → 合规，
角色**按顺序**接力，后一个审前一个）。本包刻意做**对抗式**：

| | 流水线式（角色顺序协作） | **本包（对抗式）** |
|---|---|---|
| 形态 | 角色**按顺序**接力，后一个审前一个 | 多立场**同时**独立评审，然后**当面对质** |
| 输入 | 一个选题，从零写 | **一份已有方案/稿件**，要评判它该不该过 |
| 核心机制 | 打回重写 | **分歧显性化 + 裁决**：谁支持、谁反对、争点是什么、怎么裁 |
| 产出 | 定稿 | **裁决书**（通过 / 有条件通过 / 否决 + 争点纪要 + 少数派意见） |
| 信息流 | 单向（向后传） | **先隔离（panel）后合流（clash）** |

一句话：**流水线要把稿子改好，本包要把分歧裁清。**

### 最后看与 L2（内容质量闭环）的分界

这一条最容易搞混，所以单独说：

| | 内容质量闭环（L2） | **本包（对抗式 L3）** |
|---|---|---|
| 输入 | 一篇别人写完的成稿 | **一份已有的方案/稿件** |
| 形态 | **一个声音**拿一张加权评分表自我迭代 | **四个立场**各自独立评审后对质 |
| 核心机制 | 打分 → 重写 → 复评，直到**收敛** | 分歧显性化 + 裁决，**不追求收敛** |
| 产出 | 定稿 + 评分轨迹 + 逐句台账 | **裁决书** + 条件清单 + 少数派意见 |
| 终止 | 分数过线或轮次用尽 | 出裁决 |

**差别不是"多几个评分维度"。** L2 的五个维度是同一把尺子上的五个刻度，服务于同一个目标，
越迭代越**收敛**；本包的四席是四个**互相冲突的目标函数**——**一旦收敛，就说明立场没起作用**
（第 5 道闸门会拦，见下文）。评分表问的是"这篇写得好不好"，
评审委员会问的是"这份东西该不该过、谁反对、反对的理由处理了没有"。

## 四个席位

每个席位有一个**独立的目标函数**和一组**天然倾向**。"天然倾向"不是偏见，是**职责**——
一个不做自己那份挑剔的席位，等于没上场。

| 席位 | 目标函数 | 天然倾向 |
|---|---|---|
| **用户代言人** | 用户会不会觉得有用 / 被骗 | 自嗨、术语堆砌、承诺不清 |
| **竞品分析师** | 和市面上的比有没有可指认的差异 | 同质化、没声称、可替代 |
| **合规官** | 法律与平台风险 | 违禁词、绝对化、资质、刷单话术 |
| **业务负责人** | 投入产出与可执行性 | 成本过高、链路太长、没有 CTA |

四个立场在结构上就是对撞的：

| 场景 | 一个席位要 | 另一个席位正好在拦 |
|---|---|---|
| 加转化 | 业务负责人要补 CTA 与验收口径 | 合规官在拦那句承诺（无依据、无法举证） |
| 说人话 | 用户代言人嫌术语堆砌 | 竞品分析师觉得那些术语正是唯一可指认的差异 |
| 讲差异 | 竞品分析师要独家声称 | 合规官不许「独家 / 唯一」这类无依据表述 |
| 砍链路 | 业务负责人要砍掉纯消耗的一步 | 用户代言人说那一步正是用户信任的来源 |
| 补数据 | 业务负责人要补复购率与转化率 | 合规官说无出处的经营数据一律删掉 |

## 机制：先隔离，后合流

### 1）panel：四席各是**一次独立调用**（信息隔离）

每次调用的提示词里**只有本席位的**目标函数、评审视角与关心清单，**没有**席位花名册，
**没有**其它席位的任何文字。隔离证据写进产物：

```json
"isolation": {
  "seats": {"user_advocate": {"prompt_chars": 1682, "prompt_sha": "…", "other_seat_names_found": []}, "…": {}},
  "stage_inputs": {"panel": ["material"], "clash": ["material", "panel"], "verdict": ["material", "panel", "clash"]}
}
```

**为什么隔离必须是真的**：如果四席在一次调用里一起答，它们会互相读取、互相妥协，
最后收敛成一段四平八稳的"综合意见"。那样得到的不是四个立场，而是一个立场的四种说法。

### 2）clash：**故意**打破隔离

把四份此前互不相知的意见摆到同一张桌上，只找一件事：
**有人支持、有人反对，且换一边会让结论不同的那个点。**

每条分歧带 `crux`（争的到底是哪一点）、两侧各自的原话、`cost_of_each_side`（各让一步的代价）、
`tie_break`（只能选一边时按什么裁）。

本地对每条分歧做四道校验，不过的剔进 `rejected_divergences`（**保留在报告里**，让人看见模型
试图把什么当成分歧）：至少两侧 / 两侧立场必须真的对立 / 席位 id 必须真实 /
**每侧引文必须锚定到那个席位自己说过的话**（锚不上就是在替别人发言）。

### 3）verdict：裁决书三件套

```
结论      通过 / 有条件通过 / 否决（三选一）
条件清单  每条都带"怎么算满足"（可验收）
少数派    与最终裁决方向不一致的席位，原样保留在案
```

三条本地纪律（判 `exit=3`）：

```
有席位反对（或有条件支持）却判「通过」        → 拦
判「有条件通过」或「否决」而条件清单为空      → 拦
与裁决方向不一致的席位没出现在少数派意见里    → 拦
```

注意**判「否决」也必须带条件清单**——那时写的是"**要翻案必须做到什么**"。
只给一个"否"字的裁决书，下一版方案无从下手。

## 八道本地硬闸门

命中一律：**标红 + stderr 汇总 + 非 0 退出码**，全部确定性，跑两次结果一样，可直接进 CI。

| # | 闸门 | 判据 | 退出码 |
|---|---|---|---|
| 1 | 合规 | 违禁词（最 / 第一 / 国家级 / 100% / 保过…）；「最X」可枚举上下文豁免 + **句首不豁免**；材料侧全档、产出侧只查高风险并排除「引用」与「提到」 | 3 |
| 2 | 占位符残留 | `{}` / `[待填]` / `XXX` / `（此处省略）` / `TODO` | 3 |
| 3 | `prompt_echo` | 去标点相等 / Jaccard ≥ 0.75 / 覆盖度 ≥ 0.60（**适用窗口**：长度比 ≤ 3.0 且示例 ≥ 8 字） | 3 |
| 4 | **评审锚点** | 三层引文各锚各的文本；未锚定率 > 40% 判「定位失败」 | 3 |
| 5 | **立场有效性** | 任一对席位「自己的话」重叠度 ≥ 0.75；或四席结论全同 + 零分歧 | 3 |
| 6 | **裁决完整性** | 有反对却判「通过」/ 条件清单为空 / 少数派被抹平 | 3 |
| 7 | 成本上限 | `--budget` 超限就地中止（**未发起调用**） | 5 |
| 8 | 产出不许进包 | `--outdir` / `--out` 落在 Skill 包内 | 2 |

### 第 5 道闸门为什么是本包最值钱的那道

四个角色说同样的话，看起来像"一致通过"，实际上是**一场表演**——立场没起作用。
这道闸门不看模型的自述，本地算：

- **重叠度** = 较短那份有多少比例的内容出现在较长那份里（**min 归一**，不是 Jaccard：
  两席篇幅天然不同，Jaccard 的分母是并集，篇幅差一大就把相似度摊薄了）
- **只算「自己的话」**（`verdict / must_have / kill_switch / summary / why / ask`），
  **不算各自引用的材料原文**——四席引用同一句原文是正常的，算进去会误判
- 任一对 ≥ 0.75 且短的那份 ≥ 30 个二元组 → 判**立场失效**，`exit=3`
- 另一种失效形态：**对质一个真分歧都没找到，且四席结论完全相同** → 同样判失效
  （材料确实无争议时用 `--unanimous-ok` 降级为标红提示）

> 顺带说一个自测踩到的坑：这道闸门的"最短文本"门槛一开始定得过高（60 个二元组），
> 结果**四席写一模一样的 95 个字**时重叠度算出来 1.00 却被判"不拦"。已改成 30，
> 参考量级是真机实测四席各自的"自己的话"有 986~1008 个二元组。

## 30 秒上手

```bash
# 1) 拿 Key（新用户有赠送点数）：到 https://api.a7w.cn/ 注册，创建一个 API Key
export A7W_API_KEY="<你的Key>"          # Windows: $env:A7W_API_KEY="<你的Key>"

# 2) 零成本先看三样：席位、材料整理、报价
python3 scripts/run.py seats
python3 scripts/run.py brief --file 方案.md --json --out brief.json
python3 scripts/run.py cost  --file 方案.md

# 3) 一条命令跑完整评审
python3 scripts/run.py run --file 方案.md --outdir D:/board --json --out D:/board/run.json

# 4) 想先看提示词不花钱
python3 scripts/run.py panel --file 方案.md --dry-run
```

**零依赖**：只要 Python 3.7+，不用 `pip install` 任何东西。
`scripts/a7w.py` 是**所有 Skill 包共用**的零依赖客户端（我们靠 SHA256 校验各包副本是否一致），
本包**逐字节没有改它**；本包的业务逻辑全在 `scripts/run.py` 里。

## 产出目录长这样

```
D:/board/
├── brief.md / brief.json      评审材料（大纲 / 数字 / 专有名词 / 本地预扫）
├── panel.md / panel.json      四席独立意见 + 锚点校验 + 立场重叠度 + **隔离证据**
├── clash.md / clash.json      真实分歧 + 被剔出的伪分歧 + 背景共识
├── verdict.md / verdict.json  **裁决书**：结论 + 条件清单 + 少数派意见 + 票表核对
├── REPORT.md                  总报告（四席意见 + 分歧 + 裁决书 + 八道闸门 + token）
└── state.json                 断点文件（重跑不重复扣费）
```

产出**一律落在包外**的 `--outdir` 里。包内只允许
`.md .py .txt .json .sh .js .yaml .yml .csv` 这几种后缀；`--outdir` 指到包内直接 `exit=2`。

**同一个 `--outdir` 重跑只会打印「断点命中，跳过」，0 次调用。**
断点 key 里含材料摘要与字符数、模型、温度、**席位组合**、三套口径版本，
以及上一阶段的产物摘要——少一个就会出现"改了参数却复用旧产物"。

有一个额外的零成本路径 `--replay`：`run --replay <已有产物目录>` 只用存下来的
`panel.json / clash.json / verdict.json` 重跑本地闸门与报告，**一次调用都不发**。
它还**重新做一遍锚点校验**（不直接信文件里存好的结论），所以手工改过的产物绕不过闸门。

## 真机实测（跑出来的，不是估算）

材料是一份 **706 字符的自撰推广方案**（为实测专门写的待评材料，标明来源），模型 `deepseek-chat`。

| 项目 | 实测值 |
|---|---|
| 调用 | **6 次**：四席各 1 次 + 对质 1 次 + 裁决 1 次 |
| token | prompt **18011** + completion **12740** = **30751** |
| 耗时 | 约 70 秒 |
| 四席结论 | 全部「反对」，可接受度 2/10 |
| **四席理由** | **互不重叠**：事实口径自相矛盾 / 无差异化声称 / 无出处经营数据 / 预算无转化对账 |
| **立场重叠度** | 最大 **0.20**（阈值 0.75）——四席说的是不同的话 |
| 四席底线 | 各自指向事实、差异化、合规、预算四个维度 |
| **对质** | 真实分歧 **4~5 个**，伪分歧 0 个 |
| **裁决书** | 结论「否决」+ **条件清单 10 条**（含"怎么算满足"）+ **少数派意见 4 条原样保留** |
| 锚点 | 68 条引文，未锚定 11 条（16%，阈值 40%） |
| 闸门 | 八项全部通过 |

**这四席是真的立场不同，还是四个角色说了同样的话？** 这是本包唯一值得被质疑的地方，
所以给出可直接复核的数字：四席结论**相同**（都是"反对"），但**最大重叠度只有 0.20**，
而且四份意见各自引用**不同的材料句子**、给出**不同的改写要求**；对质阶段还找出了 4~5 个
**四席之间**的真实分歧，例如：

> **争点**：「已经服务 200+ 短剧团队，用户复购率 40%」这句该**删掉**还是**补口径保留**？
> 用户代言人要求"填不出真实值就整句删除"，业务负责人坚持"必须与第一节的 37 个付费用户对账"，
> 竞品分析师则给了"改成可核对口径后可在促销段落保留"的替代路径——
> 同一句话，一边可救、一边可能不可救，结论不同，属于真分歧。

**结论：不是假协作。** 四席的结论一致是巧合（材料确实问题多），不是立场失效——
判据是**理由与改写要求互不重叠 + 存在真实分歧**，两点都成立。
如果四份意见高度重合，第 5 道闸门会直接判「立场失效」并让整条命令 `exit=3`——
本包**不把四席说同样的话当成"一致通过"**。

## 实测踩到并修掉的三类误报（如实记录）

真机跑第二轮时，`output_compliance` 闸门误报了三处——都是评审文书的**正常写法**：

| 误报 | 为什么是正常写法 | 处置 |
|---|---|---|
| 「第一反应不是厉害」 | 「第一反应」是惯用语，不是排他性宣称 | 进「第一」的序数豁免表 |
| 「无法举证为 100% 成立」 | 合规官在**指出**这句话没有依据 | 命中前后 24 字内有「无法举证」→ 判为**提到**，不算命中 |
| 「明确禁止代发、代拍、刷量」 | 评审在**禁止**它 | 同上（窗口内「属于/禁止」）→ 判为**提到** |

修法是把产出侧的合规口径与材料侧**分开**：材料侧全档全查（它是会被公开发布的东西），
产出侧只查高风险并排除两类正常写法——**引用**（材料里已有的词）与**提到**
（命中前后 24 字里有禁止 / 举证 / 风险类标记词）。被排除的条目**不静默丢弃**，
全部带 `not_counted_reason` 列进产物。

同时保留一颗牙：`本方案必须保证过审，效果 100% 达标` 这种小句里没有任何标记词，
照样 `exit=3`（自测用例覆盖，见下）。

## 25 个闸门自测用例（**全部零成本**）

闸门要能在**不花钱**的前提下被验证，否则没人会去验证它。本包的自测全部走
`--replay`（回放夹具）与参数校验路径，**一次模型调用都不发**：

| 用例 | 期望退出码 |
