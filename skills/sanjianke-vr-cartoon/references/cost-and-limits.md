# `cartoon`（人像卡通化）· 计费口径、单条上限与输入规格

视频增强是**按秒计费**的，而用户对「这一条要多少钱」没有直觉。
这份文档把口径、上限、规格、成本与毛利一次说清 —— 也是 `cost` 子命令的依据。

---

## 1. 计费口径（必须与中继完全一致）

```
冻结 = ceil(输入秒数) × 单价         ← 先把时长向上取整到整秒，再乘费率
结算 = 完成后按实际时长结算，多退少补
失败 = 全额自动退回（有幂等保护，重复退款会被跳过）
1 元 = 100 点
```

**关键**：是「先向上取整到整秒，再乘费率」，不是「乘完再取整」。
1.4 秒 → 计 2 秒；10.01 秒 → 计 11 秒。

本包 `run.py` 里的实现：

```python
def bill_seconds(duration):
    return max(1, int(math.ceil(float(duration or 0))))
```

`cost` 与 `enhance` 用的是同一个函数，所以**报价与实际冻结一致**。

## 2. 单价与常见时长对照（本档 24 点/秒）

| 时长 | 计费秒数 | 点数 | 金额 |
|---|---|---|---|
| 1 秒 | 1 | 24 | ¥0.24 |
| 5 秒 | 5 | 120 | ¥1.20 |
| 10 秒 | 10 | 240 | ¥2.40 |
| 30 秒 | 30 | 720 | ¥7.20 |
| 60 秒 | 60 | 1440 | ¥14.40 |
| 300 秒 | 300 | 7200 | ¥72.00 |
| 600 秒 | 600 | 14400 | ¥144.00 |

（单位：点；除以 100 就是元。）

用 `cost` 可以随手算：

```bash
python3 scripts/run.py cost 12          # 288 点（¥2.88）
python3 scripts/run.py cost 600        # 14400 点（¥144.00）
python3 scripts/run.py cost 12.4        # 向上取整到 13 秒 → 312 点
```

不给时长时，`cost` **只报单价与样例，不编总价** —— 这是刻意的：宁可不报，也不给一个假数。

## 3. 单条时长上限（本档 600 秒）

本档上限 **600 秒（10 分钟）**。其余档位里只有 `upscale`（30s）与 `segment`（60s）比它紧。

**超上限会在提交时被拒**（本包在提交前就拦，`exit=3`）。长片请先切片：

```bash
# 切成 60 秒一段
ffmpeg -i long.mp4 -c copy -f segment -segment_time 60 -reset_timestamps 1 part_%03d.mp4
```

## 6. 成本控制建议（本包已内置前三条）

1. **先 `cost` 再 `enhance`** —— 报价是纯本地计算，一次请求都不发。
2. **`--dry-run` 白验** —— 把白名单、可达性、时长、上限、规格、预算全验一遍却不提交。
3. **`--budget` 硬上限** —— 单位是**点**，超了就 `exit=5` 且**不发提交请求**。适合放进批处理脚本：`--budget 720` 意味着「这一条最多 720 点（¥7.20）」。
4. **长片先切片再批量** —— 一次失败赔付更小，且能断点续跑（`tasks` + `status`）。
5. **失败会自动退款**，但**冻结期间占用额度**。批量跑时给 `--budget` 留余量。

---

## 7. 常见误区

| 误区 | 事实 |
|---|---|
| 「不传 duration 会按实际时长算」 | 会探测；**探测不到就按 5 秒**收费 |
| 「白名单没过会扣费」 | 不会。服务端在**扣费之前**就回 `url_not_allowed` |
