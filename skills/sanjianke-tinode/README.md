# 三剪客 · 可自托管的即时通讯服务端 Skill

Tinode：可自托管的即时通讯服务端 的安装、常用命令与避坑要点

---

## 前置条件

- 一个已启动、且允许服务所在主机连接的数据库：MySQL 5.7+（必须 InnoDB）、PostgreSQL 13+、MongoDB 4.4+（须单节点副本集），或已弃用的 RethinkDB。
- 现成二进制方式无需编译环境，从 Releases 下载与数据库匹配的那份即可；源码方式需 Go 1.18 及以上；Docker 方式需 Docker 1.8 及以上。
- 想用命令行客户端时需要 Python 2.7 或 3.4+、PIP 9.0.1 以上，并安装与服务端版本一致的 gRPC 客户端包。
- 若要从外部访问，需要能被客户端连到的地址与端口（默认 HTTP 6060、gRPC 16060），以及放行的防火墙规则。
- 若要做语音视频通话，需要自备 TURN/STUN 服务；若要推送，需要自备推送服务凭证；若要邮件校验，需要 SMTP 账号。
- 官方标注该软件为 beta 质量，接入生产前请自行评估。

## 使用

1. **二进制方式三步**：解压后进目录 → `./init-db -data=data.json` 初始化数据库（每个安装只跑一次）→ `./tinode` 启动，浏览器开 `http://localhost:6060/` 验证。
2. **Docker 方式三步**：`docker network create tinode-net` 建网络 → 起数据库容器（`--name` 必须是 `mysql` / `postgres` / `mongodb` 这类约定名，其他容器按名字找它）→ 起服务容器并映射 6060。
3. **MongoDB 后端要额外一步**：容器起来后进 `mongosh` 把它初始化成单节点副本集，否则事务能力不可用、服务也起不来。
4. **源码方式**：按数据库选构建标签，`go install -tags mysql|postgres|mongodb|rethinkdb ...`，然后核对 `tinode.conf` 的连接参数与 `store_config.use_adapter`。
5. **配置里改三处才能上生产**：令牌签名密钥、用户 ID 加密密钥、以及去掉调试用的通用验证码；顺带把数据库口令换成自己的。
6. **运维用命令行客户端**：`python tn-cli.py --login-basic=alice:alice123` 登录后可用 `acc` / `sub` / `pub` / `get` / `set` / `del` 等命令，以及 `useradd`、`passwd`、`resolve` 等宏；把命令序列写进文件后 `python tn-cli.py < sample-script.txt` 可批跑。
7. **新手可先用官方沙箱练手**：登录名 `alice` 等，口令是登录名加 `123`，验证码用 `123456`；沙箱每天凌晨清库，不要放任何真实数据。
8. 完整命令、参数与排查表见 `SKILL.md`；**所有参数以官方安装说明、配置文件内注释和 `--help` 为准。**

## 依赖

- **数据库**：MySQL 5.7+（InnoDB）／PostgreSQL 13+／MongoDB 4.4+（单节点副本集）／RethinkDB（已弃用）。低于门槛的版本不可用。
- **运行方式**：预编译二进制（按数据库分开发布）／Go 1.18+ 源码编译／Docker 镜像（按数据库分开发布，另有集成全部适配器的镜像）。
- **客户端**：Android、iOS、网页端各自独立发布，网页端也可以直接由服务进程托管静态资源；脚本化运维需 Python 与对应的 gRPC 客户端包（版本需与服务端匹配）。
- **可选外部服务**：TURN/STUN（音视频通话）、推送服务凭证（离线推送）、SMTP（邮件校验）、S3 兼容对象存储（大文件）。
- **网络**：客户端到 HTTP 端口与 gRPC 端口的入站；拉取镜像与依赖的出站。

## 安全

- 不内嵌任何密钥；数据库口令、令牌签名密钥、用户 ID 加密密钥、推送与邮件凭证全部由使用者自行配置。
- 配置文件里带的是模板默认值，并已被官方标注为**必须在生产环境替换**；不要直接照搬上公网环境。
- 生产环境务必移除调试用的通用验证码，否则任何人都能用假邮箱或假手机号注册。
- 只用选定的数据库适配器构建，避免把不需要的适配器打进生产二进制，减少暴露面。
- 启用 TLS 后再对外提供服务；反向代理场景下确认代理正确转发 WebSocket，并核对客户端从对外地址加载。
- 媒体上传目录与对象存储桶要检查读写策略，避免上传内容被公开列举或匿名写入。
- 服务会拦截 `SIGHUP` 并当作关闭请求，用 `nohup` 放后台时必须在之后立即 `exit`，否则 SSH 断开会导致服务退出。
- 数据库需纳入备份计划；升级前先确认结构版本，按官方说明升级或重置，不要盲目覆盖数据目录。
