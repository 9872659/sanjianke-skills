# 角色编排指南

多角色协作的活儿分四步：**拆角色 → 定顺序 → 传产出 → 收口**。
这份文档讲怎么把每一步做对，以及模型入口怎么指向 `api.a7w.cn`。

---

## 一、把模型入口指向网关

框架通常有一处集中声明模型入口，改 `base_url` 与 `api_key` 即可：

```bash
OPENAI_API_KEY=sk-你的key
OPENAI_BASE_URL=https://api.a7w.cn/api/v1
```

Python SDK：

```python
import os
from openai import OpenAI

client = OpenAI(
    base_url="https://api.a7w.cn/api/v1",
    api_key=os.environ["A7W_API_KEY"],
)
```

| 场景 | 接口 |
|---|---|
| 角色发言、评审、结构化输出 | `POST /api/v1/chat/completions` |
| 需要看图的角色 | 同上，`model` 换视觉模型 |
| 生成类产物（语音 / 图像 / 视频） | `POST /api/v1/apps/<应用代号>/<接口代号>` |

## 二、按环节分档选模型

**这是多角色协作里最值钱的一条**：不是所有角色都需要最强模型。

| 环节 | 要求 | 建议档位 | 例 |
|---|---|---|---|
| 调研 / 检索 / 摘要 | 快、便宜、能听话 | 快模型 | `DeepSeek-V4-Flash`、`Qwen3.6-Flash` |
| 撰写 / 分析 | 表达与逻辑稳 | 中档 | `Qwen3.7-Plus`、`GLM-5`、`MiniMax-M3` |
| 评审 / 定稿 | 能挑毛病、能推理 | 强模型 | `DeepSeek-V4-Pro`、`GLM-5.2`、`Kimi-K2.6` |
| 看图 / 读图 | 支持视觉输入 | 视觉模型 | `Qwen3-VL-30B-A3B-Instruct`、`ERNIE-4.5-Turbo-VL`、`qwen3.6-plus` |

换模型就是换一个字符串：**不用换 base_url、不用换 Key、账单还是同一份**。

> 模型清单会变。调用前读一次 `GET /api/v1/models`，或跑
> `python3 scripts/a7w.py apps`，以接口返回为准。

## 三、角色三件套怎么写

| 字段 | 作用 | 写法要点 |
|---|---|---|
| `role` | 岗位名 | 具体到职能，别写「助手」 |
| `goal` | 这一步要产出什么 | 写清交付物与验收标准 |
| `backstory` | 这个岗位的人怎么想事 | 给经验背景与判断偏好，不给形容词 |

**正例**：

```
role:      资深数据分析师
goal:      找出 3 个可落地的增长点，每个附数据依据与预期幅度
backstory: 你在消费品牌做了 8 年分析，习惯先看复购再看拉新，
           对「听起来很大但没有口径」的结论一律打回。
```

**审核类角色要把「什么算通过」写进提示**，例如：

```
认可时在回复里明确写出 APPROVE。
```

否则终止条件永远触发不了。

## 四、数据流与终止条件

### 数据流：显式声明

每个角色读到什么，要在代码里写清楚：

```python
transcript = []                      # 显式的产出链
for role in ROLES:
    context = "\n\n".join(
        "【%s】\n%s" % (t["name"], t["content"]) for t in transcript
    )
    # 把 context 拼进 user 消息
```

**不要把「谁读谁」交给模型自己理解** —— 长链路里它一定会漏。

### 终止条件：三类组合用

| 类型 | 用法 | 例 |
|---|---|---|
| **文本触发** | 出现关键词就停 | 评审输出 `APPROVE` |
| **步数上限** | 兜底，防止无限循环 | 最多 8 轮 |
| **消息类型触发** | 出现特定类型的消息就停 | 交接类消息 |

**两种都要有**：文本触发负责「正常收口」，步数上限负责「异常兜底」。
只设文本触发，一旦触发词写错就是无限循环。

## 五、成本估算

```
单次任务调用数 ≈ 角色数 × 平均轮数
单次任务成本   ≈ 调用数 × 单次调用 tokens × 对应模型的单价
```

**例**：3 个角色、评审循环 2 轮 ≈ 5–6 次调用。
按 `tenant_*` 实收价算，再乘日任务量得到日预算。

**三个降本手段**：

1. **按环节分档选模型** —— 最直接。
2. **把终止条件设准** —— 少转两轮就少一整轮全链路调用。
3. **结构化输出** —— 返工一次就是一次全链路重跑。

## 六、上线自检

- [ ] `base_url` 指向 `https://api.a7w.cn/api/v1`，Key 走环境变量
- [ ] 每个角色的 `model` 是从模型清单里拿的，不是猜的
- [ ] 角色三件套都写具体，审核角色写了触发词
- [ ] 数据流显式声明在代码里
- [ ] 同时设了文本触发与步数上限两类终止条件
- [ ] 生产运行关掉了详细日志开关
- [ ] 不相关的任务之间重置了会话状态
- [ ] 已按 `tenant_*` 估算过单次任务与日预算
