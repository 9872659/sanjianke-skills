# 剧组角色与职权

> 本文件是 `sanjianke-drama-crew` 的**角色说明书**：
> 四个角色各自要什么、产出什么、能否掉谁，以及**为什么它们看到的东西不一样**。
>
> `python3 scripts/run.py crew` 会把下面这张表完整打出来（**零成本**）。

## 一、四个角色

| 角色 | 代号 | 目标（**只对这一件事负责**） | 产出物 | 否决权 |
|---|---|---|---|---|
| **编剧** | `writer` | 故事好不好看、钩子够不够 | 分集大纲 + 剧本（场景/台词/情绪） | 无 |
| **导演** | `director` | 节奏与可视化：这场戏能不能拍出来 | 分镜表（景别/机位/时长/转场） | **能打回编剧** |
| **美术** | `art` | 场景/服化道是否可产出、一致性 | 场景与角色视觉设定卡（**文本**） | **能说「这场拍不出来」** |
| **场记** | `scripty` | 前后一致：人物/时间线/道具/服装 | **矛盾清单**（必须引用原文） | **能否决** |

## 二、立场边界（每个角色**不做**什么）

角色之所以是"立场"而不是"分工步骤"，关键在于**它有明确不做的事**。
提示词里逐条写死了这些边界，闸门七也会拦越界后的空转：

**编剧**
- 不评价这场戏能不能拍出来（导演的职权）
- 不管场景与服化道能不能产出（美术的职权）
- 不核对前后是否矛盾（场记的职权）

**导演**
- 不改故事走向与人物关系（编剧的职权）
- 不管服化道能不能做出来（美术的职权）

**美术**
- 不参与故事评价（好不好看不是美术的判断）
- 不评节奏与镜头（导演的职权）

**场记**
- 不提改戏建议（只报矛盾，怎么改是编剧的职权）
- 不评价故事与镜头

## 三、信息不对称（**本包的机制核心**）

四个角色的立场差异**来自输入差异**，不是来自"请你严格一点"这种话术。
如果四个角色都拿到剧本全文 + 同一条"请严格评审"的指令，出来的就是四段互不相干的话。

| 角色 | 看得到 | **看不到** |
|---|---|---|
| 编剧 | 题材、集数、目标受众、额外要求；（第二轮起）上一轮被打回的意见 | 导演的镜头偏好；美术的产能约束；场记的历史台账 |
| 导演 | 剧本全文；自己上一轮的打回记录 | **题材的创意意图与原始需求**；美术的产能结论；场记的矛盾台账 |
| 美术 | 场次清单 + 出场人物（**只有这些**） | 剧本全文与台词；**故事评价的邀请**（提示词里明确禁止它评故事） |
| 场记 | 剧本全文 + 分镜表 | 创作过程与修改痕迹；改戏建议的授权 |

### 为什么这样设计

- **编剧看不到导演的偏好**：否则编剧会"揣摩导演想要什么"，直接写出好拍的戏——
  那样导演就打回不了任何东西，"能不能拍"这道审查就废了。**打回通道是两者唯一的交流。**
- **导演看不到题材的创意意图**：导演只能对着**已经写出的字**判断，不能退回去说
  "这个题材本身不适合拍"。这正是"打回编剧"而不是"打回需求"的原因。
- **美术看不到剧本全文**：这是最关键的一条。美术拿到的是**结构化场次与人物清单**
  （场号、场名、地点、时间、出场人物、本场作用）。它**无从**评价故事好不好看，
  只能判断"这些场、这些人，能不能稳定产出、能不能保持一致"。
- **场记不参与改戏**：它只报矛盾、每条必须引用原文。一旦允许它提改法，
  它就会开始"重写剧本"，与编剧的职权撞车。

### 现场证据

`run` 每一轮都会把各角色的输入摘要打到 stderr（`--show-inputs` 默认开）。
实测原文：

```
---- 第 1 轮：各角色看到的信息 ----
  [编剧] 看到：题材 / 集数 / 目标受众 / 额外要求
       看不到：导演的镜头偏好；美术的产能约束；场记的历史台账
       输入摘要：题材=外卖骑手…；集数=2；上游文本 1412 字（sha a377b3a8）；意见=（无）
  [导演] 看到：剧本全文（2610 字，sha d889afef）
       看不到：题材的创意意图与原始需求；美术的产能结论；场记的矛盾台账
       输入摘要：输入=剧本全文 2610 字（sha d889afef）+ 自己上一轮的打回记录 0 条；**没有题材说明**
  [美术] 看到：场次清单 6 场 + 出场人物 5 人（**只有这些**）
       看不到：剧本全文；台词；**故事评价的邀请**
       输入摘要：输入是结构化场次/人物清单（sha 9f1c…），不是剧本全文——它无从评价故事好不好看
  [场记] 看到：剧本全文（sha d889afef）
       看不到：创作过程与修改痕迹；改戏建议的授权
       输入摘要：逐场核对前后一致性；每条必须引用原文，引文本地逐字校验
```

注意导演与场记看到的是**同一个 script sha**——他们看同一份文本，但**被允许看的维度不同**
（导演看"能不能拍"，场记看"一不一致"），这就是立场而非信息量的差异。

## 四、表决规则

| 规则 | 口径 |
|---|---|
| **打回** | 导演 `verdict=reject` 必须同时给 `reasons`（可读理由）与 `unshootable`（哪一场写不了） |
| **否决** | 美术 `verdict=not_producible` 必须同时给 `reasons` 与 `scenes`（哪一场拍不出来） |
| **否决** | 场记的中高等级矛盾 = 否决（`verdict=blocking`）；每条必须带能逐字找到的 `quote` |
| **空转** | 一份 reject 的意见里若既无具体问题词、又没指到具体场次 → 判为"说了话但等于没说话" |
| **自相矛盾** | 场记给了 `blocking`，但经过引文校验后**一条中高等级矛盾都没有** → 拦 |

## 五、终止与出口（**不许假装谈拢**）

轮次上限默认 2、最高 4（`--max-rounds`）。一轮里的顺序是固定的：
编剧（大纲 + 剧本）→ 导演 → 美术 → 场记 → 结算。

| 情形 | 行为 | 退出码 |
|---|---|---|
| 四角色同轮全过 **且** 该轮闸门无命中 | 收工 | **0** |
| 有裁决未决项（打回/否决未解决） | 显式列未决项（谁否了什么、为什么） | **6** |
| 四角色都点头但闸门仍有命中 | 也算未收敛，不写成"已通过" | **6** |
| 编剧返修后正文**一字未变** | 报"**空转**"，并作为未决项 | 6 |
| 未到上限就因其他原因停下 | 兜底 | 3 |

**为什么不允许"假装谈拢"**：一份报告如果把分歧写成"已通过"，
下游（出图、出片）会照着有问题的剧本一路做下去，返工代价远大于再跑一轮。
所以本包宁可 `exit=6` 让流水线**红着停**，也不给一个绿的假象。
报告里那节「是不是真的在互相否」也是同理：没有任何互否时会直接写"**没有**，
那就是假协作"。

## 六、闸门命中回流：意见不只来自角色

本地闸门命中也会**按角色派回下一轮的返修指令**：

| 命中类型 | 派给谁 |
|---|---|
| 剧本/大纲里的合规、占位符、照抄示例 | 编剧 |
| 分镜结构缺项 | 导演 |
| 分镜里带出的合规（源头在剧本台词） | 导演 **+** 编剧 |
| 设定卡缺角色、性别/年龄冲突、设定卡里的合规 | 美术 |
| 矛盾清单的引文锚点问题 | 场记 **+** 编剧（要给出可被逐字引用的台词） |

少了这一步就会出现"角色全过、报告一路红"的空转——
**闸门只在最后拦一下、却不让角色看到命中点**，等于每轮都在同一个坑里摔。
