# 剧本与分镜规则

> 本文件是 `sanjianke-drama-crew` 的**产出结构说明书**：
> 剧本长什么样、分镜表必须有哪些字段、矛盾清单的引文怎么锚定、角色一致性按哪些硬项判。
>
> 一句话：这些规则不是"建议"，**闸门是按它们逐条核的**。

## 一、剧本（`script.json` / `script.md`）

### 结构

```
script
├── title                  剧名
├── characters[]           人物表
│   ├── name               姓名（**闸门六拿它跟美术设定卡逐名对照**）
│   ├── gender             男/女（硬项）
│   ├── age                年龄段（硬项，用「青年/中年」这类词）
│   ├── role               身份
│   └── desc               关键特征
└── episodes[]
    ├── no                 第几集
    ├── title              集名
    ├── cliffhanger        集尾悬念
    └── scenes[]
        ├── no             场号
        ├── slug           场名（如「雨夜街头」，**分镜表靠它挂镜**）
        ├── location       地点
        ├── time           时间
        ├── characters[]   出场人物
        ├── beat           本场作用（这场戏在剧情里干什么）
        └── lines[]        逐句台词
            ├── who        说话人
            ├── emotion    情绪
            └── text       台词
```

### 硬要求

| 要求 | 为什么 |
|---|---|
| **每场都要有 `slug`** | 分镜表按 `slug` 挂镜；没有它，分镜指向的场次就找不到（闸门五会报"指向的场次在剧本里不存在"） |
| **台词逐句标注 `who` + `emotion`** | 情绪是配音与表演的依据；没有它，台词只是一段文字 |
| **人物表的 `name` 必须是剧本里真正出现的名字** | 闸门六要求：剧本里每个有名字的角色，美术设定卡里都要有卡 |
| **场景要写清 `location` / `time` / `出场人物`** | 美术只能拿到"场次 + 人物"清单来做可产出性判断，这几项缺了就判不了 |
| **不写旁白式说明** | 旁白无法被镜头呈现，是导演打回的最常见原因 |

### 台词写法

```
**陈默**（喘）：这单还有两分钟，你让我过去。
**苏晚**（平静）：合同上的名字，是你写的？
```

台词要求口语、有信息差与金句感。**不要写成解说**——
"他内心充满了愤怒与不甘"这种句子拍不出来，导演会打回。

## 二、分镜表（`board.json` / `board.md`）

### 结构

```
board
├── title
├── verdict                        **导演裁决**
│   ├── verdict                    approve | reject
│   ├── reasons[]                  打回理由（reject 时必填）
│   └── unshootable[]              哪一场写不了（reject 时必填）
└── episodes[]
    └── shots[]
        ├── episode                第几集
        ├── scene_slug             挂到剧本的场次（**必须存在**）
        ├── shot_size              景别（枚举）
        ├── camera                 机位（枚举）
        ├── visual                 画面描述（≥ 8 字，要能照着拍）
        ├── seconds                时长（秒；也接受 mm:ss）
        ├── transition             转场（枚举）
        └── audio                  这一镜的台词或音效
```

### 枚举（闸门五按它判）

**景别**：大远景 / 远景 / 全景 / 中景 / 中近景 / 近景 / 特写 / 大特写
（口语别名给兜底表：半身 → 中近景、全身 → 全景、局部 → 特写…）

**机位**：平视 / 微俯 / 俯视 / 仰视 / 过肩 / 越肩 / 主观视角 / 斜侧 / 背身 / 正面

**转场**：硬切 / 叠化 / 淡入 / 淡出 / 划像 / 闪白 / 黑场 / 甩镜 / 匹配剪辑

**单镜时长**：2 ~ 12 秒（短剧单镜口径）。超出区间会被报出来。

### 硬要求

| 检查项 | 判定 |
|---|---|
| 镜数为 0 | **直接拦**（"镜数为 0 的分镜表不能开工"） |
| 缺景别 | 拦（"景别是分镜的骨架"） |
| 景别不在枚举里 | 拦（报出可用值） |
| 缺画面描述 / 少于 8 字 | 拦（"'雨' 这种等于没写"） |
| 缺时长 / 时长不可识别 | 拦（接受 `4`、`"4秒"`、`"00:04"`、`"1分20秒"`） |
| 时长不在 2~12 秒 | 拦（报出实际秒数） |
| 缺机位 / 机位不在枚举 | 拦 |
| 缺转场 | 拦 |
| `scene_slug` 在剧本里不存在 | 拦（出片时没人知道拍什么） |

**闸门不替导演补字段。** 缺了就是缺了，报出「第几集第几镜缺了哪个字段」。
自动补全 = 假绿闸门，比没有闸门更危险。

### 导演打回时仍然要给分镜表

打回（`reject`）时导演**仍要输出分镜表**——但要标出哪些镜是为了指出问题而勉强写的。
这样"打回"才有具体靶子：编剧能看到"第 1 集第 1 场确实被拆成了一大堆没有动作的对话镜"。

## 三、矛盾清单（`continuity.json` / `continuity.md`）—— **本包最容易造假的一份**

### 结构

```
continuity
├── verdict
│   └── verdict                    clear | blocking（blocking = 否决）
├── conflicts[]
│   ├── category                   人物 / 时间线 / 道具 / 服装 / 空间 / 因果
│   ├── severity                   高 / 中 / 低（高+中 = 否决）
│   ├── where                      第几集 第几场
│   ├── quote                      **从剧本里逐字照抄的一小段原文**
│   ├── problem                    矛盾点
│   ├── clash                      与什么冲突
│   └── fix                        必须怎么改
└── dropped[]                      引文校验失败、被剔出的条目（附 dropped_why）
```

### 引文锚点规则（闸门四）

1. 每条矛盾**必须**带 `quote`
2. `quote` 去标点后长度 **≥ 4 字**（太短的引文在剧本里随便都能撞上，等于没有锚点）
3. `quote` 去标点后**必须真的出现在剧本归一化全文里**
4. 不满足的条目**剔出**，登记进 `dropped`，并**以非 0 退出码报出来**

### 为什么"剔出也要报错"

剔出本身是**信息**：它说明场记报了它无法举证的东西。
如果因为"剔掉之后还剩一条真矛盾"就放行，那种"编造引文"的行为就被奖励了
（反正顺便报一条真的就能过关）。所以：

```
闸门四：1 条矛盾的引文在剧本原文里**找不到**（编造引文，已剔出、不计入矛盾数）
  引文「他手里那把黑色的折叠伞后来变成了红伞」→ 在剧本原文里找不到
```

报告里仍保留原文与剔出理由供人工复核——**剔出不等于隐藏**。

### 等级口径

| 等级 | 含义 | 例子 |
|---|---|---|
| `高` | 会直接让观众出戏 | 人物身份/生死冲突、时间线倒错 |
| `中` | 细心观众会发现 | 道具/服装/空间冲突 |
| `低` | 瑕疵 | 措辞、称呼不一致 |

**中高等级 = 否决。** 低等级只算瑕疵，不足以构成否决。
所以"场记说 blocking，但清单里没有一条中高等级矛盾"会被判**自相矛盾的裁决**并拦下。

### 空清单是合格产出

没有矛盾就返回空数组——**空数组是合格产出**，提示词里明确写了这句。
不要为了凑数而报矛盾：编造引文会被逐字校验抓出来。

## 四、美术设定卡（`art.json` / `art.md`）

### 结构

```
art
├── verdict
│   ├── verdict                    producible | not_producible
│   ├── reasons[]                  否决理由（not_producible 时必填）
│   └── scenes[]                   哪一场拍不出来（not_producible 时必填）
├── characters[]
│   ├── name / gender / age        与剧本人物表**硬项对照**
│   ├── appearance                 外貌
│   ├── costume                    服装
│   ├── features[]                 **可视觉特征词**（4~8 条，每条 4~12 字，只写看得见的）
│   └── palette[]                  参考色（name + hex）
└── scenes[]
    ├── slug / space / props[] / light / palette
    ├── difficulty                 easy | medium | hard
    └── difficulty_why             理由
```

**本卡是文本，供出图包使用；本包不出图。**

### 角色一致性的硬项（闸门六）

| 硬项 | 判定 |
|---|---|
| **角色齐备** | 剧本里每个有名字的角色，设定卡里必须有同名卡（含只出场一次的角色） |
| **性别** | 两边都写了性别且不一致 → 拦 |
| **年龄段** | 两边都写了年龄段且不一致（"少女" vs "中年"）→ 拦 |
| **场景齐备** | 设定卡的场景卡要吃下场次清单（美术据此判断可产出性） |

刻意**不**比对软项（气质、色彩偏好）：那是风格软约束，两边措辞不同很正常，
硬比会大面积误报，反而让闸门被无视。

### 名字归一化

角色名里的**舞台提示后缀**会在比对前剥掉：
`阿深（电话）`、`陈默（画外音）`、`苏晚(旁白)` → 都归到 `阿深` / `陈默` / `苏晚`。
它们指的是**同一个角色**，不是另一个人。只剥括号提示，不剥真正的名字差异
（"陈默"和"陈默然"仍然是两个人）。

## 五、贯穿四份产出的通用闸门

| 闸门 | 扫的是 | 特别说明 |
|---|---|---|
| 合规 | 产出**正文** | 元信息（`<!-- -->` 里的模型/用量/轮次）与**逐字引文行**都不参与扫描——它们不是要发布的内容 |
| 占位符 | 产出正文 | `{}`、`[待填]`、`XXX`、`TODO` |
| prompt_echo | 产出正文 | 整段比对只认 exact/jaccard；逐句比对三层判据都启用 |

**为什么元信息与引文要排除**：实测过"自己拦自己"——
渲染器写的「本卡是**文本**设定…」被判命中「唯一」，于是一份完全合格的设定卡被整卡拦截。
而引文的作用是**可核对**（本地逐字校验过），把它也拿去扫合规，
就会让"引一段带敏感词的原文来说明矛盾"这件事变成不可能。
教训是通用的：**闸门只能扫产出内容，不能扫产出周围的元信息。**
