# 成本与排错

> 本文件是 `sanjianke-drama-crew` 的**花钱口径与排错手册**。
>
> 一句话结论：**本包只出 token，不编价。** 文本网关的单价平台不公开，
> 所以 `cost` 报的是**调用次数**与**实测 token 区间**，不报金额。

## 一、调用次数（唯一的确定量）

**每轮 5 次调用**：

| 角色 | 次数 | 干什么 |
|---|---|---|
| 编剧 | **2** | 大纲 + 剧本（分成两步，才能在大纲阶段就被打回，而不是写完一整篇才发现方向不对） |
| 导演 | 1 | 分镜表 + 裁决 |
| 美术 | 1 | 场景与角色设定卡 + 裁决 |
| 场记 | 1 | 矛盾清单 + 裁决 |

```
合计调用 = 5 × 轮次
```

```bash
python3 scripts/run.py cost --episodes 2 --max-rounds 2
# → 合计调用 10 次
```

## 二、token 量级（实测区间）

| 项目 | 实测值 |
|---|---|
| 单次调用 | 约 **1.3k ~ 8.7k total token** |
| 一轮 5 次 | 约 **1.6 万 ~ 3.5 万 token** |
| 2 集 2 轮（10 次） | 约 **3.5 万 ~ 5.5 万 total token** |
| 单次耗时 | 10 ~ 40 秒（剧本与分镜最长） |

实测样本（真机，2 集 2 轮）：

```
token 台账
| 轮 | 大纲 | 剧本 | 分镜 | 设定卡 | 矛盾清单 |
| 1  | 1617 | 4404 | 5481 | 4194   | 4190     |
| 2  | 1329 | 5844 | 6451 | 4947   | 6312     |
```

## 三、为什么**不报金额**

* 平台把图像/视频/语音的单价公布在**生成应用的 schema** 里，
  但**文本网关的单价平台不公开**（`GET /api/v1/pricing` 不覆盖 `chat/completions`）。
* 报一个自己编的"每千 token 几分钱"就是**编数据**。所以本包：

| 做法 | 说明 |
|---|---|
| 每次调用都把 `usage` 原文打出来 | `prompt_tokens` / `completion_tokens` / `total_tokens` |
| `cost` 不给 `--points-per-ktok` | **只报 token 数，不报金额** |
| 给了 `--points-per-ktok` | 按**你给的**口径折算点数，并在输出里标明那是**外部口径** |

```bash
# 只报 token（默认）
python3 scripts/run.py cost --episodes 2 --max-rounds 2

# 按你给的单价折算（本包不声称它是平台真实价）
python3 scripts/run.py cost --episodes 2 --max-rounds 2 --points-per-ktok 1.5
```

结算只认 `usage.total_tokens`。平台的 `pricing_matrix` / `tenant_*` 字段
**实测半数与结算价不一致**，本包不拿它们算钱。

## 四、预算闸门（`--budget`）的两套语义

| 情形 | `--budget` 的含义 |
|---|---|
| 同时给了 `--points-per-ktok` | **点数上限**（按 token 折算后判） |
| 没给 `--points-per-ktok` | **调用次数上限**（因为**不编换算率**，宁可不报也不算假账） |

两种情况都是**每次调用后立刻查**，不是跑完一轮才查——
预算闸门的意义是**止损**，跑完一轮才发现等于没有闸门。

```
预算超限(次数守) rc=5  ✗ 剧组协作 run 已超预算：已调用 1 次 > --budget 0.0
（未给 --points-per-ktok，无法把 token 折成点数，因此 `--budget` 被当作**调用次数上限**）
```

另外：**没有报价就开跑 = 拒绝执行**（`exit=2`，一分钱都不花）。
两种确认方式任选：`--yes` 明确同意，或 `--budget` 封顶。

## 五、省钱的四种办法

| 办法 | 怎么做 | 效果 |
|---|---|---|
| **先 dry-run** | `--dry-run` 只打印将发送的提示词 + 各角色输入摘要 + 提示词卫生自检 | **0 次调用** |
| **先算钱** | `run.py cost --episodes N --max-rounds M` | 本地计算，**0 次调用** |
| **靠断点续跑** | 同一份输入重跑任一子命令 | 命中缓存的部分 **0 次调用、0 token** |
| **别用 --force** | `--force` 会忽略断点全部重跑 | **重复花钱** |

另外：`crew` / `log` / `cost` / `models` 里有三个是**完全免费**的
（`crew` 纯本地、`log` 读文件、`cost` 本地计算）。

## 六、断点续跑：key 含**全部影响产出的八维**

```
role          角色              writer / director / art / scripty
stage         阶段              outline / script / board / cards / continuity
topic_sha     上游全文摘要       **剧本 / 大纲全文的 sha**（上游变了必须重出）
round         轮次              第几轮返修（同一输入在不同轮次产出不同）
prompt_ver    提示词版本         改了提示词必须失效
model         模型
temperature   温度
verdict_sha   上一轮裁决摘要     打回理由变了，返修方向就变了
```

**为什么必须八维齐全**：少一维就会出现"改了东西却静默复用旧产出"。
本库的其他包吃过这个亏（key 少了维度，改了模型却拿回上次的结果）。

命中缓存时会打印**命中的 key 与八维摘要**：

```
断点命中：编剧·剧本（第 1 轮）跳过调用，0 点
  key=8f2c1d…
  维度：{"role": "writer", "stage": "script", "topic_sha": "e398255eac54", "round": 1,
         "prompt_ver": "1.0.0", "model": "deepseek-chat", "temperature": 0.7,
         "verdict_sha": "4f53cda18c2b"}
```

## 七、退出码表

| 码 | 含义 | 常见触发 |
|---|---|---|
| **0** | 四角色同轮全过 + 该轮闸门无命中 | 正常收工 |
| **1** | 未预料异常 | `--json` 下给 `kind:"internal"` 信封 + stderr **完整 traceback** |
| **2** | 参数/环境错误 | `--outdir` 指到包内、没报价就开跑、`--max-rounds` 越界、缺上游产出文件 |
| **3** | 硬闸门命中 | 合规 / 占位符 / 照抄示例 / 矛盾清单锚点 / 分镜结构 / 角色一致性 / 裁决完整性 |
| **4** | 调用失败 | 网络 / 鉴权 401 / 点数不足 402 / 模型名 404 |
| **5** | 预算超限 | `--budget` 到顶，**就地中止** |
| **6** | **轮次用完仍有未决项** | 分歧如实报出，不许假装谈拢 |
| **130** | 用户中断 | Ctrl+C |

## 八、常见报错与处置

| 现象 | 原因 | 处置 |
|---|---|---|
| `拒绝执行：--outdir 指到了包内` | 产出路径落在包里 | 换到包外，例如 `%TEMP%\drama-crew` |
| `拒绝执行：… 会真的调模型花钱，必须先确认` | 没给 `--yes` 也没给 `--budget` | 加 `--yes`，或 `--budget` 封顶 |
| `run.py: error: unrecognized arguments: --outd` | 写错了参数名 | 本包**关掉了前缀缩写**（`allow_abbrev=False`），所以 `--outd` 不会被静默当成 `--outdir` |
| `鉴权失败（401）` | Key 无效或过期 | 到 [api.a7w.cn](https://api.a7w.cn/) 重新创建 Key |
| `点数不足（402）` | 账号余额不够 | 充值后重试 |
| `模型不存在（404）` | 模型名写错 | `run.py models` 现查在架模型 |
| `上游 502/503/504`，随后自动重试 | 网关上抖 | 不用管，客户端已**退避重试 4 次** |
| `闸门命中（分镜表）：…的景别 '主观视角' 不在枚举里` | 导演把机位写进了景别栏 | 加 `--max-rounds` 让它返修，或手工改 JSON 后重跑 |
| `闸门四：N 条矛盾的引文…找不到（编造引文）` | 场记报了它无法举证的东西 | 重跑 `continuity`；引文必须能**逐字**在剧本里找到 |
| `场记给的是否决（blocking），但…没有中高等级矛盾` | 自相矛盾的裁决 | 重跑 `continuity`；没有矛盾就返回空数组 |
| `未决项 N 条：轮次用完仍未收敛`（exit=6） | 有角色一直在否 | **这是设计**：加 `--max-rounds`、或按未决项里的理由改题材/改场次 |
| `第 2 轮编剧返修后剧本正文与第 1 轮一字未变` | 空转 | 检查打回意见是否可执行；必要时人工介入 |
| `断点文件损坏，按空状态重跑` | `crew-state.json` 坏了 | 会自动按空状态重跑；想彻底重来就删掉它 |

## 九、产出位置的红线

包内**只允许** `.md .py .txt .json .sh .js .yaml .yml .csv`。
所以：

* 产出（剧本、分镜、设定卡、矛盾清单、记录）**一律落包外**
* `--outdir` 指到包内 → **`exit=2` 拒绝执行**（不是警告）
* 包内**没有任何图片**：本包不出图，`art` 只出**文本**设定卡
* 脚本启动时设了 `sys.dont_write_bytecode = True`，不会在包里留下 `__pycache__`

## 十、`--json` 契约（给流水线与 agent 用）

```bash
python3 scripts/run.py run ... --json          # 写在子命令**后面**
python3 scripts/run.py --json run ...          # 写在子命令**前面**（两种都认）
```

| 情形 | stdout |
|---|---|
| 成功 | **一个** JSON 对象，顶层带 `"ok": true` |
| 失败（有结果） | 同一个对象里并入 `"ok": false` + `"exit"` + `"error"` |
| 失败（无结果） | `{"ok": false, "exit": <码>, "error": {"kind": …, "message": …}}` |
| 未预料异常 | 同上，`kind: "internal"`，且 stderr 有**完整 traceback** |

**stdout 只有一个 JSON 文档**（靠"暂存 + 最后 flush 一次"保证）。
人读文案走 stderr；退出码语义与非 `--json` 模式**完全一致**。
