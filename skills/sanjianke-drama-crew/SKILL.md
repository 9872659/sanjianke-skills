# 三剪客 · 短剧剧组

> ## ⚠️ 先申请你自己的 API Key
>
> **本 Skill 不内嵌任何密钥，也不代付费用。** 请到
> **[算力集市 api.a7w.cn](https://api.a7w.cn/)** 注册并创建**你自己的** API Key
> （新用户有赠送点数，可以先免费试跑几条）。
>
> 拿到后填进环境变量 `A7W_API_KEY`，或直接传给 `--key` 参数。
> **请勿使用他人提供的 Key** —— 用量与费用都记在 Key 所属账号上。

## 这个包是干什么的（L1 / L2 / L3 的分界）

| 层 | 形态 | 例子 |
|---|---|---|
| **L1 单点生成型** | 一个输入 → 一个产出 | 「给我一个标题」 |
| **L2 智能体型** | **单循环**：抽档 → 写 → 自检 → 迭代（**一个声音自我迭代**） | 长了再改、改完再自检 |
| **L3 多智能体协作型** | **多角色分工互审**，一条命令出成品 | **本包** |

**L3 的关键不是「调多次模型」，而是：每个角色有自己独立的目标与立场，且会互相否掉对方。**

所以本包的核心不是"一次写完"，而是「**剧本要过会**」：

```
编剧写 → 导演说"这场写不了" → 打回编剧
       → 美术说"这场拍不出来" → 要求改
       → 场记说"第 2 集第 4 场和第 1 集第 3 场对不上" → 行使否决
       → 编剧按意见返修 → 再会审 → 全部通过才收工
```

**本包不出图、不出片。** 产物是**剧本 + 分镜包**：

```
剧本（场景 / 台词 / 情绪）  +  分镜表（景别 / 机位 / 时长 / 转场）
+  美术设定卡（文本，供出图用）  +  矛盾清单（每条引用剧本原文）  +  全过程记录
```

出图交给既有包（`sanjianke-storyboard-art` 按设定卡出图），出片交给既有短剧包。
视频生成是它们的活，本包只把**剧本与分镜**做到能过会。

## 四个角色与职权

| 角色 | 代号 | 目标 | 产出物 | 否决权 |
|---|---|---|---|---|
| **编剧** | `writer` | 故事好不好看、钩子够不够 | 分集大纲 + 剧本（场景/台词/情绪） | 无 |
| **导演** | `director` | 节奏与可视化：这场戏能不能拍出来 | 分镜表（景别/机位/时长/转场） | **能打回编剧**（「这场写不了」） |
| **美术** | `art` | 场景/服化道是否可产出、一致性 | 场景与角色视觉设定卡（**文本**，供出图用） | **能说「这场拍不出来」**并要求改 |
| **场记** | `scripty` | 前后一致：人物/时间线/道具/服装 | **矛盾清单**（必须引用原文） | **能否决**（连续性错误必须修） |

`python3 scripts/run.py crew` 会把这张表和每个角色的"不做清单"完整打出来，**零成本**。

## 关键机制（这四条是 L3 与"假协作"的分界）

### 一、信息不对称（**机制核心，不是 bug**）

四个角色的立场差异**来自输入差异**，不是来自"请你严格一点"这种话术：

| 角色 | 看得到 | **看不到** |
|---|---|---|
| 编剧 | 题材、集数、受众、额外要求、上一轮被打回的意见 | 导演的镜头偏好；美术的产能约束；场记的历史台账 |
| 导演 | 剧本全文 + 自己上一轮的打回记录 | 题材的创意意图；美术的产能结论；场记的矛盾台账 |
| 美术 | 场次清单 + 出场人物（**只有这些**） | 剧本全文与台词；**故事评价的邀请**（提示词里明确禁止） |
| 场记 | 剧本全文 + 分镜表 | 创作过程与修改痕迹；改戏建议的授权 |

`run` 每一轮都会把**各角色的输入摘要**打到 stderr（`--show-inputs`，默认开），
用来**证明不对称真实存在**，而不是只在文档里声明。实测原文（片段）：

```
---- 第 1 轮：各角色看到的信息 ----
  [编剧] 看到：题材 / 集数 / 目标受众 / 额外要求
       看不到：导演的镜头偏好；美术的产能约束；场记的历史台账
  [导演] 看到：剧本全文（2610 字，sha d889afef）
       看不到：题材的创意意图与原始需求；美术的产能结论；场记的矛盾台账
  [美术] 看到：场次清单 6 场 + 出场人物 5 人（**只有这些**）
       看不到：剧本全文；台词；**故事评价的邀请**
  [场记] 看到：剧本全文（sha d889afef）
       看不到：创作过程与修改痕迹；改戏建议的授权
```

### 二、真实打回

* 导演 `verdict=reject` 必须同时给 `reasons`（可读理由）**和** `unshootable`（哪一场写不了）。
  只给结论不给理由 → 闸门七拦。
* 美术 `verdict=not_producible` 必须给 `reasons` **和** `scenes`（哪一场拍不出来）。
  判断依据只能是**可产出性**（要大规模实景/群演/特效、同场景空间自相矛盾、角色特征说不清）。
* 场记的中高等级矛盾 = **否决**。每条矛盾必须引用剧本原文，引文**本地逐字校验**。

还会拦"**空转评审**"：一份 reject 的意见里若既没有具体问题词、又没指到具体场次，
判为"说了话但等于没说话"。

### 三、闸门命中回流（不是只在最后拦一下）

本地闸门一旦命中，会**按角色派回下一轮的返修指令**：

| 命中类型 | 派给谁 |
|---|---|
| 剧本/大纲里的合规、占位符、照抄示例 | 编剧 |
| 分镜结构缺项、分镜里的合规 | 导演（带出的合规同时告诉编剧） |
| 设定卡缺角色、性别/年龄冲突 | 美术 |
| 矛盾清单的引文锚点问题 | 场记（同时让编剧给出可被逐字引用的台词） |

少了这一步就会出现"角色全过、报告一路红"的半成品状态——那不是协作，是空转。

### 四、终止与出口：**不许假装谈拢**

| 情形 | 行为 |
|---|---|
| 四个角色同一轮全部通过，且该轮闸门无命中 | **exit=0**，收工 |
| 轮次用完仍有裁决未决项 | **exit=6**，显式列未决项（谁否了什么、为什么） |
| 轮次用完但闸门仍有命中 | **exit=6**，同样算未收敛，不写成"已通过" |
| 编剧返修后正文**一字未变**（内容指纹相同） | 报"**空转**"，不算收敛 |

报告里那节标题就叫「**是不是真的在互相否**」——没人互否时它会直接写：

> **没有。**本次运行里没有任何一处打回或否决——如果没有出现真实的互否，
> 那就是**假协作**，本包不把它算成 L3 成功。

## 八道硬闸门

命中即**标红 + stderr 汇总 + 退出码非 0**，可以直接进 CI。

| # | 闸门 | 判定 | 退出码 |
|---|---|---|---|
| 1 | 合规 | 广告法违禁词 + **短剧常见风险**（血腥/软色情/赌博/迷信的表述边界）；「最X」按可枚举语境豁免、**句首不豁免** | 3 |
| 2 | 占位符残留 | `{}`、`[待填]`、`XXX`、`此处省略`、`TODO` | 3 |
| 3 | prompt_echo | 去标点相等 / Jaccard ≥ 0.75 / **覆盖度 ≥ 0.60**；含**相对长度守卫**与 **contain 适用窗口** | 3 |
| 4 | **矛盾清单锚点** | 每条矛盾**必须引用剧本原文**；本地逐字校验，**编造引文剔出并拦** | 3 |
| 5 | 分镜结构 | 每镜必须有**景别 + 画面描述 + 时长**（另查机位/转场/场次锚点）；**镜数为 0 → 拦** | 3 |
| 6 | 角色一致性 | 剧本里每个有名字的角色在设定卡里必须有卡；性别/年龄硬项两边一致 | 3 |
| 7 | 裁决完整性 | 打回/否决必须留可读理由；空转评审拦；**有否决却拿不出中高等级矛盾**也拦 | 3 |
| 8 | 成本上限 + 产出位置 | `--outdir` 指到包内 → 2；没报价就开跑 → 2；超预算 → 5 | 2 / 5 |

### 第 4 道闸门为什么是本包最值钱的那道

场记的任务是报"前后矛盾"。**矛盾清单读起来永远很像真的**——所以造假成本极低：
模型完全可能编一句"第 2 场说伞是黑色的，第 5 场变成红色"，而剧本里根本没写过伞。

这道闸门不采信模型自报的结构字段，而是拿 `quote` 去**剧本归一化全文里逐字找**：

```
引文「他手里那把黑色的折叠伞后来变成了红伞」在剧本原文里找不到
（去标点后逐字比对不上）——判为**编造引文**，剔出
```

被剔出的条目**不是悄悄删掉**，而是登记进 `dropped` 并**报错拦下**：
"剔出"本身就是要报的错，否则"编造引文"这个行为被奖励了（顺便报一条真的就能过关）。

### 短剧的「表述边界」是怎么划的

短剧是**剧情向**内容，"冲突"是它的燃料——不能把"打/杀/死"一律拦下（那样任何一部剧都过不了）。
所以短剧风险表只拦**表述边界**，不拦剧情设定：

| 类型 | 拦什么 | 放过什么 |
|---|---|---|
| 血腥 | 开膛剖腹、碎尸、血浆四溅（细节化展示） | 剧情里的死亡与冲突 |
| 软色情 | 床戏描写、裸露；「胸前」等部位词**与暴露类词同现**时 | 正常感情戏；"雨水顺着胸前流进衣领" |
| 赌博 | 具体玩法与下注动作（百家乐、押注、一把梭） | 剧情里的赌局设定本身 |
| 迷信 | 「照着做能改命」这类**可操作方案** | 剧情里的封建设定本身 |

同类收紧也用在广告法上：裸的「唯一」「震惊」「喘息」在剧情对白里是常用词，
一律拦会把整篇剧本判红。所以只在**商业宣称后缀**（唯一正品 / 全网独家）或
**标题党固定搭配**（震惊体）时命中。**闸门的假命中比漏判更有害**——
一个正确写法的稿子被判违规，使用者就会开始无视闸门。

## 30 秒上手

```bash
# 1) 拿 Key（新用户有赠送点数）→ https://api.a7w.cn/ 注册，创建 API Key
# 2) 配 Key
export A7W_API_KEY="<你的Key>"          # Windows: $env:A7W_API_KEY="<你的Key>"

# 3) 先看剧组配置（零成本）
python3 scripts/run.py crew

# 4) 先算钱（本地计算，一次调用都不发；**只出 token，不报金额**）
python3 scripts/run.py cost --episodes 2 --max-rounds 2

# 5) 一条命令跑完剧组协作
python3 scripts/run.py run \
  --topic "外卖骑手暴雨夜被逼停，车主递来一份遗嘱说他是财阀私生子" \
  --episodes 2 --max-rounds 2 --outdir D:/drama-crew/ep01 --yes

# 6) 看全过程记录（谁在第几轮否了谁、理由是什么）
python3 scripts/run.py log --outdir D:/drama-crew/ep01

# 想先看看不花钱：加 --dry-run 只打印将发送的提示词与各角色输入摘要
python3 scripts/run.py outline --topic "..." --dry-run
```

### 零成本验证闸门（`--from-file`）

闸门的行为必须能**零成本复现**，否则没人有动力去测它。所以 `outline` / `script` /
`board` / `art` / `continuity` 五个子命令都支持 `--from-file <json>`：
**不调模型**，直接拿一份 JSON 过闸门。

```bash
# 拿一份手写的分镜表过闸门（0 次调用、0 token）
python3 scripts/run.py board --outdir D:/drama-crew/ep01 --from-file my-board.json

# 每条闸门都会给出非 0 退出码，可直接进 CI：
#   3 = 闸门命中（合规/占位符/照抄示例/锚点/结构/一致性/裁决）
#   2 = 参数与环境（--outdir 在包内、没报价就开跑）
```

> `run.py` 里另有一个**只认环境变量**的测试桩（`DCP_MODEL_STUB=<目录>`）：
> 设了它就会去该目录读 `<角色>.<阶段>.json` 当作模型返回，用来**离线**复现整条
> 互审流程与"未决项"分支。它**不设就永不生效**，不是一个可以绕开真实调用的产品开关
> ——一个能绕过真实调用的产品开关，会让人拿假产出当真产出。

**零依赖**：只要 Python 3.7+，不用 `pip install` 任何东西。
`scripts/a7w.py` 是**所有 Skill 包共用**的零依赖客户端（我们靠 SHA256 校验各包副本一致），
本包**逐字节没有改它**；本包的业务逻辑全在 `scripts/run.py` 里。

## 断点续跑：key 含**全部影响产出的维度**

```
role          角色              writer / director / art / scripty
stage         阶段              outline / script / board / cards / continuity
topic_sha     上游全文摘要      **剧本/大纲全文的 sha**（改了上游就必须重出）
round         轮次              第几轮返修（同一输入在不同轮次产出不同）
prompt_ver    提示词版本        改了提示词必须失效
model         模型
temperature   温度
verdict_sha   上一轮裁决摘要    打回理由变了，返修方向就变了
```

命中缓存时会打印**命中的 key 与八维摘要**，免得出现"改了东西却静默复用旧产出"。

```bash
# 同一份输入重跑 → 全部命中，0 次调用、0 token
python3 scripts/run.py run --topic "..." --outdir D:/drama-crew/ep01 --yes
# 改了题材 / 轮次 / 提示词版本 / 模型 / 温度 / 上一轮裁决 → 对应那一步重出
# 想强制重跑某一步：加 --force（**会重复花钱**）
```

## 计费：**只出 token，不编价**

文本网关的单价平台**不公开**（`/api/v1/pricing` 不覆盖 `chat/completions`），
所以本包：

* 每次都把 `usage` 原文打出来（`prompt_tokens` / `completion_tokens` / `total_tokens`）
* `cost` 报的是**调用次数**与**实测 token 区间**（单次调用实测 1.5k ~ 6k token），
  不给 `--points-per-ktok` 就**不报金额**
* 给了 `--points-per-ktok` 才按**你给的**口径折算点数，并在输出里标明那是外部口径

一次性成本口径：**每轮 5 次调用**（编剧 2 次：大纲 + 剧本；导演 / 美术 / 场记各 1 次）。

`--budget` 的语义要说清：给了 `--points-per-ktok` 就按**点数**守；
没给口径时**不编换算率**，把 `--budget` 当作**调用次数上限**守。
两种情况都是**每次调用后立刻查**（不是跑完一轮才查）——预算闸门的意义是止损。

## 两条实测确认的接口事实

1. **`POST /api/v1/chat/completions` 的成功响应不带 `code`**。
   所以本包只判 `choices` 在不在，**不判 code**。
   `code == 1` 那套信封是**生成应用**的，不适用于文本端点。
2. **异步任务的状态在任务 `data` 顶层**（`data.status`），不在 `data.result.status`——
   平台文档写错了。本包不用生成应用，但 `a7w.py` 里按实测取值。

另外：平台的 `pricing_matrix` / `tenant_*` 字段**半数与结算价不一致**，
所以本包**不拿它们算钱**；结算只认 `usage.total_tokens`。

## 常见坑

| 坑 | 表现 | 怎么避 |
|---|---|---|
| **没确认报价就开跑** | `exit=2`，一分钱不花 | 加 `--yes`，或 `--budget` 封顶 |
| **`--outdir` 指到包内** | `exit=2` 拒绝执行 | 用包外目录，例如 `%TEMP%\drama-crew` |
| **以为 `--out` 是 `--outdir` 的缩写** | 拼错就报 `unrecognized arguments` | 本包关掉了前缀缩写（`allow_abbrev=False`），不会静默写错地方 |
| **故事写得太"内部"** | 导演打回"整场只有内心独白，无法切分镜头" | 这是**正常行为**：让编剧返修，或加 `--max-rounds` |
| **场记报了一堆矛盾但引文编造** | `exit=3`，剔出条数与理由都打出来 | 让场记重跑（引文必须能逐字找到） |
| **两个角色点了头就以为收工** | 报告里"闸门命中"仍非空 → `exit=6` | 闸门命中算未决项，加轮次返修 |
| **跑满轮次还谈不拢** | `exit=6` + 未决项清单 | 这是设计：**不许假装谈拢**；改题材或不一致的场次 |
