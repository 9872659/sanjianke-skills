# 三剪客 · 短剧剧组

给一个**题材**，一条命令跑完一个剧组：**编剧 → 导演 → 美术 → 场记**，四个角色各有目标与职权，
**互相否掉对方**，谈拢了才收工。

```
run  →  分集大纲 → 剧本 →（导演打回？→ 编剧返修）→ 分镜表
        →（美术说拍不出来？→ 改戏）→（场记否决？→ 修矛盾）→ 过会
产出：剧本 + 分镜表 + 美术设定卡 + 矛盾清单 + 全过程记录
```

面向短剧编剧室、AI 制片方。**跑之前先告诉你花多少钱**（只出 token，不编价），
剧本要过会才给你成品，谈不拢就明说谈不拢。

```
crew       →  列出四个角色与职权（零成本，一次调用都不发）
outline    →  编剧出分集大纲（钩子 / 付费卡点 / 集尾悬念）
script     →  编剧出剧本（场景 / 台词 / 情绪）
board      →  导演出分镜表（景别/机位/时长/转场）—— **可以打回编剧**
art        →  美术出场景与角色设定卡（文本）—— **可以说「这场拍不出来」**
continuity →  场记出矛盾清单（**每条必须引用剧本原文**）—— **能否决**
run        →  一条命令跑完剧组协作（多轮，含打回重写与未决项）
log        →  读全过程记录（每轮：输入摘要 / 裁决 / 理由 / 未决项 / token）
cost       →  只算钱，一次调用都不发
models     →  列出在架模型
```

## 这是 L3，不是「多调几次模型」

| 层 | 形态 |
|---|---|
| **L1 单点生成型** | 一个输入 → 一个产出 |
| **L2 智能体型** | **单循环**：抽档 → 写 → 自检 → 迭代（**一个声音自我迭代**） |
| **L3 多智能体协作型** | **多角色分工互审**，一条命令出成品 |

**L3 的关键不是「调多次模型」，而是：每个角色有自己独立的目标与立场，且会互相否掉对方。**

本包把它落成四条可验证的机制：

1. **信息不对称**——立场差异来自**输入差异**，不是"请你严格一点"这种话术。
   编剧看不到导演的镜头偏好与美术的产能约束；导演看不到题材的创意意图；
   美术只拿到**场次与人物清单**（拿不到剧本全文和台词，也就不可能去评故事）。
   `run` 每轮把**各角色的输入摘要**打印出来作为证据。
2. **真实打回**——导演 `reject` 必须给理由**并指出哪一场写不了**；美术 `not_producible`
   必须指出**哪一场拍不出来**。只给结论不给理由，闸门七直接拦。
3. **闸门命中回流**——本地闸门命中会**按角色派回下一轮的返修指令**，
   不是只在最后拦一下。少了这一步就会出现"角色全过、报告一路红"的空转。
4. **终止与出口**——四角色同轮全过**且该轮闸门无命中**才 `exit=0`；
   有未决项一律 `exit=6` 并显式列出。另有一条"编剧返修后**正文一字未变**"的**空转检测**。

所以报告里有一节标题就叫「**是不是真的在互相否**」。如果这一轮没有任何打回或否决，
它会直接写：**没有**——没有真实互否就是**假协作**，本包不把它算成 L3 成功。

## 八道硬闸门

命中即**标红 + stderr 汇总 + 退出码非 0**，可以直接进 CI。

| # | 闸门 | 判定 | 退出码 |
|---|---|---|---|
| 1 | 合规 | 广告法违禁词 + **短剧常见风险**（血腥/软色情/赌博/迷信的表述边界）；「最X」按可枚举语境豁免、**句首不豁免** | 3 |
| 2 | 占位符残留 | `{}`、`[待填]`、`XXX`、`TODO` | 3 |
| 3 | prompt_echo | 去标点相等 / Jaccard ≥ 0.75 / **覆盖度 ≥ 0.60**；含相对长度守卫与 contain 适用窗口 | 3 |
| 4 | **矛盾清单锚点** | 每条矛盾**必须引用剧本原文**；本地逐字校验，**编造引文剔出并拦** | 3 |
| 5 | 分镜结构 | 每镜必须有**景别 + 画面描述 + 时长**；**镜数为 0 → 拦** | 3 |
| 6 | 角色一致性 | 剧本里有名字的角色在设定卡里必须有卡；性别/年龄硬项两边一致 | 3 |
| 7 | 裁决完整性 | 打回/否决必须留可读理由；空转评审拦；有否决却拿不出中高等级矛盾也拦 | 3 |
| 8 | 成本上限 + 产出位置 | `--outdir` 指到包内 → 2；没报价就开跑 → 2；超预算 → 5 | 2 / 5 |

外加一条产出位置闸门：`--outdir` 指到包内直接 `exit=2`
（包内不许出现图片/音视频，SkillHub 的扩展名白名单只放
`.md .py .txt .json .sh .js .yaml .yml .csv`）。

### 第 4 道闸门为什么是本包最值钱的那道

场记的任务是报"前后矛盾"，而**矛盾清单读起来永远很像真的**——造假成本极低。
这道闸门不采信模型自报的结构字段，而是拿每条矛盾的 `quote` 去**剧本归一化全文里逐字找**：

```
引文「他手里那把黑色的折叠伞后来变成了红伞」在剧本原文里找不到
（去标点后逐字比对不上）——判为**编造引文**，剔出
```

被剔出的条目**不是悄悄删掉**，而是登记进 `dropped` 并**报错拦下**：
"剔出"本身就是要报的错——否则"编造引文"这个行为就被奖励了（顺便报一条真的就能过关）。

### 短剧的「表述边界」怎么划

短剧是**剧情向**内容，"冲突"是它的燃料——不能把"打/杀/死"一律拦下（那样任何一部剧都过不了）。
所以短剧风险表只拦**表述边界**：

| 类型 | 拦 | 放过 |
|---|---|---|
| 血腥 | 开膛剖腹、碎尸、血浆四溅（细节化展示） | 剧情里的死亡与冲突 |
| 软色情 | 床戏描写、裸露；部位词**与暴露类词同现**时 | 正常感情戏；"雨水顺着胸前流进衣领" |
| 赌博 | 具体玩法与下注动作（百家乐、押注、一把梭） | 剧情里的赌局设定本身 |
| 迷信 | 「照着做能改命」这类**可操作方案** | 剧情里的封建设定本身 |

同样的收紧也用在广告法上：裸的「唯一」「震惊」在剧情对白里是常用词，一律拦会把整篇剧本判红。
**闸门的假命中比漏判更有害**——一个正确写法的稿子被判违规，使用者就会开始无视闸门。

## 实测数据（真机跑出来的，不是估算）

| 项目 | 实测值 |
|---|---|
| 每轮调用次数 | **5 次**（编剧 2：大纲 + 剧本；导演 / 美术 / 场记各 1） |
| 单次调用 token | 约 **1.3k ~ 8.7k total token**（随集数与剧本长度变化） |
| 一轮 5 次调用 | 约 **1.6 万 ~ 3.5 万 token** |
| 2 集 2 轮（10 次调用） | 约 **3.5 万 ~ 5.5 万 total token** |
| 单次耗时 | 10 ~ 40 秒（剧本/分镜最长） |
| 断点命中 | 同输入重跑 → **0 次调用、0 token** |

结算只认 `usage.total_tokens`。平台的 `pricing_matrix` / `tenant_*` 字段实测半数与结算价不一致，
本包不拿它们算钱；**文本网关不公布单价，所以 `cost` 不给 `--points-per-ktok` 就只报 token 数、不报金额**。

## 两条实测确认的接口事实

1. **`POST /api/v1/chat/completions` 的成功响应不带 `code`**——本包只判 `choices` 在不在。
   `code == 1` 那套信封是**生成应用**的，不适用于文本端点。
2. **异步任务的状态在任务 `data` 顶层**（`data.status`），不在 `data.result.status`——
   平台文档写错了。

## 断点续跑

断点 key 含**全部影响产出的八维**：角色 / 阶段 / **上游全文摘要** / 轮次 /
**提示词版本** / 模型 / 温度 / **上一轮裁决摘要**。改一维就重出，
命中缓存时会打印命中的 key 与八维摘要（免得出现"改了东西却静默复用旧产出"）。

```bash
# 同一份输入重跑 → 全部命中，0 次调用、0 token
python3 scripts/run.py run --topic "..." --outdir D:/drama-crew/ep01 --yes
# 想强制重跑：--force（**会重复花钱**）
```
