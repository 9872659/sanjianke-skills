# 三剪客 · 自助式 BI 与数据看板 Skill

把公司的数据库接上来，让不会写 SQL 的同事用点选的方式提问、拼看板、定时收邮件

---

## 前置条件

- 一台能长期运行的服务器或本机，Docker 方式需装好并启动 Docker（也可用 Podman）
- JAR 方式需要 Java 运行时，官方建议 Java 25（HotSpot JVM），更早版本不受支持
- 至少一个要分析的业务数据库的连接信息（地址、端口、库名、账号密码）
- 生产环境另需一个正式数据库充当 Metabase 自己的应用库（Postgres 等，官方文档列了支持清单）
- 要发邮件订阅需准备 SMTP 服务器；要接企业账号需 LDAP 配置

---

## 使用

1. 起服务（官方推荐自托管用 Docker）：

   ```bash
   docker pull metabase/metabase:latest
   docker run -d -p 3000:3000 --name metabase metabase/metabase
   docker logs -f metabase
   ```

2. 等到日志出现初始化完成，浏览器打开 `http://localhost:3000`，按引导建管理员账号
3. 在管理设置里添加业务数据库，用**只读或最小权限**的账号
4. 用点选式查询构建器或原生 SQL 提第一个"问题"，保存到集合里
5. 把问题拼成看板，需要的话配定时订阅或告警
6. 生产环境务必把应用库从默认 H2 换成正式数据库，并规划备份与升级
7. 完整的部署参数、compose 示例、Docker Secrets 写法与坑位对照表，见 `SKILL.md`

关键约定：应用库（存问题、看板、设置的那个库）和业务数据库是两回事，前者丢了等于全丢。

---

## 依赖

- Docker / Podman，或 Java 25 运行时（JAR 方式）
- 生产环境需要一个正式数据库作应用库；应用库不用预先建表，服务启动时会自己建
- 一个或多个业务数据库的连接信息
- 可选：SMTP 服务器（邮件订阅）、Slack / Webhook 出口、LDAP（企业账号）
- 可选：JDBC 驱动 jar（Oracle、Vertica 或社区驱动），放进挂载到 `/plugins` 的目录

---

## 安全

- 不内嵌任何密钥
- 数据库与 SMTP、LDAP 密码优先用 Docker Secrets（环境变量名加 `_FILE` 后缀）；至少不要写进镜像层和代码仓库
- 接入业务库时使用只读或最小权限账号，不要直接给超级用户
- 不要把 3000 端口直接暴露到公网；走反向代理加 HTTPS，并限制来源
- 公开分享看板链接前确认权限设置，避免把含个人信息的结果公开出去
- 处理他人数据时注意合规：只接已获授权的数据源，看板与订阅内容不要包含不必要的个人标识字段
- 升级、迁移前先备份应用库；不要把生产应用库和试用环境共用一套
- 自定义驱动与第三方插件只从可信来源获取，插件目录对容器进程可写，等于可执行代码入口
