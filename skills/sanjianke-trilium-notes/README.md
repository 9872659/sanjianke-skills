# 三剪客 · 自托管层级知识库笔记 Skill

笔记按树状无限分层，同一条笔记还能同时挂在多个位置；正文、代码、画布、思维导图、关系图、地图都能记，还带全文搜索、版本历史、单条加密与对外分享。

---

## 前置条件

- 桌面版：Windows / macOS / Linux 桌面环境，从仓库 Releases 下载对应平台的二进制包。
- 服务器版：一台能常驻运行的机器（本机或服务器），具备 Docker 环境；或使用 Node + pnpm 从源码运行。
- 一个宿主机目录用于存放数据（默认 `~/trilium-data`），并规划好备份。
- 对外提供 HTTPS 时需要域名、证书与反向代理。
- 多设备同步需要一个同步服务器（可自建）。
- 浏览器访问时，官方说明只对最新版本的 Chrome 与 Firefox 做过支持与测试。

---

## 使用

1. 桌面使用：下载对应平台的包，解压后运行 `trilium`。
2. 服务器部署（推荐路径）：取官方 compose 文件后 `docker compose up -d`，默认数据目录 `~/trilium-data`、默认端口 `8080`。
3. 也可以不用 Compose，直接 `docker run` 并映射 `8080` 与数据目录；只给本机访问时绑定 `127.0.0.1:8080:8080`。
4. 需要更小的权限面时改用无 root 镜像，注意其数据目录是 `/home/trilium/trilium-data`。
5. 要自动化时，在界面里生成 ETAPI token，然后用 REST 接口批量读写或导出笔记。
6. 升级：固定具体版本标签，拉取目标版本后以相同卷与参数重建容器；跨版本升级前先备份。

完整的六块操作说明（什么时候用 / 不用、安装、常用操作、常见坑、权限与用途说明、能力边界）见 `SKILL.md`。

## 依赖

- 桌面版：对应操作系统的桌面环境；无需额外服务端。
- 服务器版：Docker（镜像覆盖 AMD64、ARMv7、ARM64/v8）；源码方式需要 Node 与 pnpm。
- 数据目录必须映射到宿主机：容器内路径随镜像变体不同（rootful 为 `/home/node/trilium-data`，无 root 为 `/home/trilium/trilium-data`）。
- 端口：默认 `8080`。
- 多端同步：需要同步服务器；使用第三方客户端时同步版本必须与服务端匹配。
- 可选：反向代理与 TLS 证书、OpenID 身份提供方。
- 配置来源：数据目录下的 `config.ini` 或环境变量，优先级为环境变量 > `config.ini` > 默认值。

## 安全

- 不内嵌任何密钥。ETAPI token、服务账号密码、OpenID 与 TOTP 的凭据都由使用方自行生成与保管。
- **不要把服务直接暴露在公网**：服务器版默认开启认证，但仍应通过反向代理提供 HTTPS，并按官方文档配置受信任代理。
- 不要为了图省事把免认证开关（`TRILIUM_GENERAL_NOAUTHENTICATION`）设为 `true`；这在服务器部署场景等于把知识库公开。
- 数据目录包含全部笔记、附件与自动备份，务必限制权限并纳入备份；不要把数据目录放在可被公网访问的位置。
- 使用 SMB / CIFS 共享作为数据目录时，按官方提示加上 `nobrl` 与 `noperm` 挂载选项，避免锁与权限语义导致的异常。
- 加密与多因素认证（按笔记加密、TOTP、OpenID）建议按需开启，尤其是服务器版。
- 第三方客户端与第三方同步托管服务不由本项目维护，使用前请自行评估其可信度。
- 上游软件自身的漏洞与安全问题请走上游仓库的 Issues 与安全公告渠道。
