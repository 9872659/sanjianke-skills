# 排错 · 按报错找原因

> 本包所有报错都来自实测。对照「你看到的」那一列，先看最后一列的处理办法。

## 一、网关返回体怎么读

```
HTTP 200 + {"code":1,"msg":"success","data":{...}}     成功
HTTP 200 + {"code":0,"msg":"input.xxx: ...","data":null}  参数 / 上游校验失败（不建单）
HTTP 500 + {"code":0,"msg":"服务内部错误","data":null}      上游异常（本包三条接口不复现）
```

**关键**：校验失败也是 HTTP 200，`code` 才是判据。本包按 `code` 判，不看状态码。

## 二、按报错找原因

| 你看到的 | 谁给的 | 原因 | 怎么办 |
|---|---|---|---|
| `input.text: 缺少必填参数` | 网关 | `vo` 没拿到文稿 | 加 `--text` 或 `--script` |
| `input.voice: 不在允许选项内` | 网关 | `--voice` 不是 67 个 ID 之一 | `catalog --voices` 复制完整 ID |
| `input.voice: 类型不正确` | 网关 | 传了数字 / 空值 | `--voice` 要 22 位字符串 ID |
| `input.custom_mode: 缺少必填参数` | 网关 | `bgm` 的 body 少了必填项 | 本包自动补 `model` / `custom_mode` / `instrumental`；自己发请求时三项都要给 |
| `input.instrumental: 缺少必填参数` | 网关 | 同上 | 同上 |
| `input.model: 缺少必填参数` | 网关 | 同上 | 同上 |
| `input.model: 不在允许选项内` | 网关 | `--model` 不在九档枚举 | `catalog` 看枚举，或直接用默认 `V6` |
| `input.task_id: 缺少必填参数` | 网关 | `subs` 少了 `--task-id` | 用 `bgm` 打出来的 task_id |
| `input.audio_id: 缺少必填参数` | 网关 | `subs` 少了 `--audio-id` | 用 `bgm` 打出来的 audio_id |
| `请使用本平台返回的任务或资源标识` | 网关 | `task_id` / `audio_id` 不是本站产出的 | 用 `task --task-id` 从台账里取本站真实 id |
| `任务处理失败，请稍后重试` | 上游任务 | 生成环节失败（`generation_failed`） | 失败任务全额退；按原参数重跑一次，或换 `--model` 轻档 |
| `任务不存在` | 查询 | `task_id` 写错 / 已经被清理 | `log` 查本地台账里的 task_id |
| `返回不是 JSON` | 本包 | 落到了别的路由或网关页 | 检查 `--host`；端点必须是 `/api/v1/apps/media_services_33/<code>` |
| `连不上 …（已重试 3 次）` | 本包 | 网络 / 代理 / DNS | 先 `doctor` 看余额接口通不通 |
| `HTTP 502 / 503 / 504` | 网关 | 上游瞬时不可用 | 本包对 502/503/504 自动退避重试 3 次；仍失败就过几分钟再跑 |
| 任务卡在 `processing` 超过 `--wait` | 本包 | 上游排队 / 慢 | `task --task-id <id>` 免费续查，**同一条结果不必重新提交** |

## 三、闸门类（本包自己退的）

| 退出码 | 提示长什么样 | 含义 | 怎么办 |
|---|---|---|---|
| `2` | `缺必填参数：--voice` / `缺必填参数：--task-id --audio-id` | 用法错 | 按提示补参数 |
| `2` | `voice 要填音色 ID（67 个之一）…` | 填了名字或半截 ID | 报文里带了你最接近的 ID，复制它 |
| `2` | `--duration 必须在 10–360 之间` | 数值越界 | 调到区间内 |
| `4` | `这会真实提交 N 条任务，下限 X 点（Y 元）…确认请加 --yes` | 少 `--yes` | 看到点数后加 `--yes` |
| `5` | `预计 X 点 … 超过 --budget Y 点 … 一个请求都没发` | 超预算 | `--budget` 单位是点，1 元 = 100 点；调大或减片数 |
| `6` | `第 2 片提交失败（没拿到 task_id）` | 上游没给 id | 原始返回已打印；先 `doctor` 再重试 |
| `6` | `等了 600 秒还没完成` | 轮询超时 | `task --task-id <id>` 续查，结果没丢 |
| `130` | `已中断。` | Ctrl-C | 已提交的任务照常跑，用 `task` 取 |

## 四、GBK / 中文控制台

Windows 上 stdout 被管道或重定向时，Python 用 `cp936` 编码。本包做了两件事：

```python
for _s in (sys.stdout, sys.stderr):
    _s.reconfigure(errors="replace")     # 个别符号编不出也不崩
```

- 状态符号统一用 `√` / `×`（cp936 有），`✓` / `✗` 一律不用；
- 金额写「1.80 元」不写 `¥`（`U+00A5` 不在 cp936 里，会被替换成 `?`）；
- 实测 `PYTHONIOENCODING=gbk python run.py doctor` → **exit 0，输出零个问号**。

文稿读取按 `utf-8-sig` → `utf-8` → `gb18030` 依次尝试，记事本存的中文稿也能直接吃。

## 五、计费相关

| 现象 | 说明 |
|---|---|
| 余额没动，但流水里有 `-60` 和 `+60` | 参数校验失败：先冻 60、立刻全退，净 0 |
| 任务失败但没退款记录 | 退款可能有几秒延迟；`GET /user/balance/logs` 再看一次 |
| 实际扣的点比 `cost` 高 | `cost` 是**下限**（60 点/条）；成交价 = 上游点数 × 2、保底 50 点 |
| 想核对真实花费 | `python3 scripts/run.py log` 看本地台账；`usage` 字段在任务详情里 |

## 六、doctor 的检查项

`doctor` 默认只打 4 条只读请求（余额 / apps 列表 / pricing / 假任务查询），全部 `cost: 0`。
`doctor --probe` 额外发 3 条空 body POST，验证三条接口的参数校验在位：

```
√ 探针净花费 = 0 点（冻 60 全退）    探前 999,997,393,482 点 → 探后 999,997,393,482 点
```

某一条 `×` 时先看它右边那半句：`HTTP 200 code=0 任务不存在` 是正常的；
如果 apps 列表里少了接口，说明该应用在架状态变了，`catalog` 会同步显示 `未在架 ×`。
