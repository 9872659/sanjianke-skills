# 文档一键转 Markdown

手上的资料格式五花八门 —— PDF、Word、TXT、Markdown —— 而你只想把它们变成
**一份能直接喂给模型的 Markdown 文本**。

**上传一个公网文档地址，说明要保留什么结构，几十秒拿回干净 Markdown。**
标题层级、列表、表格、链接都留住，不是抓成一坨无结构字符。

| 你最关心 | 答案 |
|---|---|
| 多少钱 | **按 Token 计费**（输入 2,600 点/百万 Token），1 元 = 100 点；一份 20 页 PDF 典型 0.5～1 元 |
| 要多久 | 同步返回，一般十几秒；超长文档可切异步拿 `task_id` |
| 要装什么 | **什么都不用装**。包里自带零依赖客户端，或者直接用 `curl` |
| 一次几份 | **同时最多 8 份**公网文档，可合并、可对比 |
| 能商用吗 | 可以。生成内容的使用与合规责任由使用者承担 |

## 一、转成什么样，由你的指令决定

同一个接口，换一句 `question` 就换一种输出。常用四款：

| 你要的 | `question` 怎么写 |
|---|---|
| **全文文字化（最常用）** | `把全文整理成结构化 Markdown：保留标题层级、有序与无序列表、表格（转 Markdown 表格）、超链接，不要概括、不要漏段` |
| **只要主干** | `输出 Markdown 大纲：只保留标题层级与每节要点，正文压成 2～3 句摘要` |
| **表格优先** | `把文档里所有表格转成 Markdown 表格，列名原样保留，表格之外的正文只保留表题` |
| **多份合并** | 一次传多份 `file_urls`，问 `把这几份文档合并成一份 Markdown，按主题分节，重复内容去重，标注各自来源` |

**指令越具体，越不需要二次整理。** 想要「不要概括」就明确写出来 —— 这是最省事的一句话。

## 二、三分钟跑通

### 第一步：拿到你自己的 Key

到 **[api.a7w.cn](https://api.a7w.cn/)** 注册，在控制台创建一个 API Key（形如 `sk-...`），
填进环境变量：

```bash
export A7W_API_KEY=sk-你的key      # Windows: $env:A7W_API_KEY="sk-你的key"
```

### 第二步：提交转换请求

`file_urls` 放**公网文档地址**（1～8 个），`question` 说清要什么结构：

```bash
curl -sS -X POST "https://api.a7w.cn/api/v1/apps/file_qa/chat" \
  -H "Authorization: Bearer $A7W_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "file_urls": ["https://你的存储/产品手册.pdf"],
    "question": "把全文整理成结构化 Markdown：保留标题层级、有序与无序列表、表格（转 Markdown 表格）、超链接，不要概括、不要漏段、不要改写措辞",
    "stream": false
  }'
```

### 第三步：取回 Markdown

返回里 `data.result.answer` 就是转好的 Markdown，直接存成 `.md`：

```json
{
  "code": 1,
  "data": {
    "result": { "answer": "# 产品手册\n\n## 一、概述\n\n...", "usage": { "total_tokens": 2492 } },
    "usage": { "points_cost": 16.55, "actual_points": 16.55 }
  }
}
```

> 超长文档把 `mode` 传 `async`，拿 `task_id`，再用 `GET /api/v1/tasks/{task_id}` 取结果。

## 四、素材要求

| 要求 | 说明 |
|---|---|
| 格式 | **PDF / DOC / DOCX / TXT / MD** 等常见文档格式 |
| 访问 | **必须是公网可访问的 URL**，不支持本地路径、不支持 Base64 |
| 数量 | 一次 1～8 个；多份可合并或对比 |
| 文档长度 | 超长文档建议切分成几份分别转，再本地拼接（更快也更省钱） |
| 本地文件 | **先传到对象存储 / 网盘直链 / 任何可公开访问的位置**，再来调 |

> 扫描件（图片型 PDF）里的文字，请走**视觉大模型**那条路：把每页导成图片，
> 用 `POST /api/v1/chat/completions` 的视觉模型提取文字后再整理成 Markdown。
> 两条路配合，纸质资料也能全流程数字化。

## 五、常见坑

| 坑 | 表现 | 怎么避 |
|---|---|---|
| **拿本地路径当入参** | 报参数错误 | 一律用**公网可访问的 URL** |
| **没写「不要概括」** | 拿回一篇摘要而不是全文 | 明确写「保留原文、不要概括、不要漏段」 |
| **没写「表格转 Markdown」** | 表格被压成一堆散字 | 指令里点名要 Markdown 表格并保留列名 |
| **一次塞十几份文档** | 报参数错误 | 一次最多 **8** 份；更多就分批 |
| **超长文档用同步** | 等很久甚至超时 | `mode` 传 `async`，拿 `task_id` 再查 |
| **拿到结果直接入库** | 切片质量差 | 先本地检查标题层级是否连续、表格是否闭合 |
| **拿 `code == 0` 判断成功** | 明明成功却判成失败 | 平台成功码是 **`1`**（`{"code":1,"msg":"success"}`） |

## 六、批量与入库

做知识库时通常一次几百份。推荐流程：

1. **先把所有文档上传**到对象存储，导出一份公网 URL 清单。
2. **分批调用**（每批 1～4 份，留出重试余量），结果写进 `out.jsonl`，一行一份。
3. **本地质检**：检查标题层级是否从 `#` 开始、表格管道符是否成对、有没有空文件。
4. **再切片入库**：按标题层级切、或按固定 token 数切，别直接整篇塞进向量库。

`references/转Markdown指南.md` 里给了批量脚本写法、并发建议和入库前的质检清单。
需要更贴合你流程的批量方案，加微信聊。
