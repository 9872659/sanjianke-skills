# 三剪客 · 开源项目管理

它把「需求池 → 迭代 → 模块 → 路线图」这条链装进一个界面：工作项当基本单位，用周期（Cycle）管迭代，用模块（Module）切大块工作，用视图把过滤后的工作项存下来共享给团队，另外还有页面和分析两块。

它的常见落点是团队不想把项目数据放在别人的云上，又希望工具别太复杂。这个 Skill 讲的是怎么把它自托管起来、装完该动哪些配置、以及仓库里那份编排文件为什么不能直接拿去生产用。

**上游项目**：`Plane`　**仓库**：https://github.com/makeplane/plane

## 什么时候用 / 不用

**用它**：

- 「我们要一个能自己部署的项目管理工具，管需求、迭代和路线图」。
- 团队从轻量看板工具迁移出来，需要**周期 + 模块 + 保存视图**这套比看板更结构化的组织方式。
- 关心**数据主权**：项目数据、附件都在自己的数据库与对象存储里。
- 需要给项目数据做**程序化读写**：Plane 有面向工作区维度的接口，脚本和集成可以走这条路。
- 要一套**开源自托管的替代品**来接替按人收费的项目管理 SaaS。

**不要用它**：

- **不想运维 Postgres、Redis、消息队列、对象存储这一套**。自托管是个多容器系统，比单容器服务重得多。
- **只是想要一个任务清单**。个人待办用轻量工具更合适，没必要上整套工作区模型。
- **要的是敏捷全套（燃尽图之外的复杂指标、审批流、工时报销）**。它的分析能力偏向进度洞察，不是完整的企业级 PMO 套件。
- **希望开箱即用、完全不用动配置**。自托管要你决定监听端口、对外地址、跨域来源，还得为生产外接数据库与存储。
- **要拿仓库源码直接编译部署**。仓库里的编排文件是给本地开发用的，生产部署走官方发行渠道。

## 安装

官方给了四条路：托管云（注册即用）、自托管、Kubernetes、以及第三方托管平台。自托管又分两种发行版，官方现在主推的是带免费档的商业版安装器。

### 商业版自托管（官方主推，走安装脚本）

前置（官方给出）：2 核 CPU（x64/AMD64 或 AArch64/ARM64）、4 GB 内存（生产建议 8 GB）；系统为 Ubuntu、Debian、CentOS、Amazon Linux、macOS，或在 WSL2 下的 Windows。先确认 Docker Compose 是最新版。

```bash
curl -fsSL https://prime.plane.so/install/ | sh -
```

按终端提示走：填访问用的域名（形如 `domain.tld` 或 `subdomain.domain.tld`），再选安装模式——**Express** 用默认配置直接装；**Advanced** 可以自定义数据库、Redis、存储等设置。生产环境官方明确建议外接数据库与存储，避免机器故障导致数据丢失。

### 社区版自托管（Docker Compose，用发行版携带的脚本）

前置：Docker 已安装并运行；需要 bash 环境（Windows 走 gitbash）；执行用户要有 Docker 权限（通常切到 root）。

```bash
mkdir plane-selfhost
cd plane-selfhost

curl -fsSL -o setup.sh https://github.com/makeplane/plane/releases/latest/download/setup.sh
chmod +x setup.sh
./setup.sh
```

脚本会给出动作菜单：安装（按架构）、启动、停止、重启、升级、查看日志、备份数据、退出。首次选安装（arm64 机器选对应项），它会在当前目录下创建 `plane-app`（预览部署则是 `plane-app-preview`），并把编排文件与 `plane.env` 下载进去。

装完先改 `plane.env` 里几项最关键的，再回到脚本里选启动：

| 变量 | 默认值 | 说明 |
|---|---|---|
| `LISTEN_HTTP_PORT` | `80` | 监听端口，务必确认没被占用，例如改成 `8080` |
| `LISTEN_HTTPS_PORT` | `443` | HTTPS 监听端口，例如改成 `4430` |
| `WEB_URL` | `http://localhost` | 对外访问地址，要带上端口，例如 `https://plane.example.com:8080` |
| `CORS_ALLOWED_ORIGINS` | `http://localhost` | 允许的跨域来源，与对外地址保持一致 |

`plane.env` 里还包含数据库、Redis、消息队列与对象存储（S3 兼容，含 MinIO 自建选项）的连接参数，以及上传大小上限与接口密钥限流等设置；变量清单以发行版携带的模板当前内容为准。

### 直接下载配置，不用安装器

不想用脚本的话，可以按版本直接取编排文件与变量文件：

```bash
curl "https://prime.plane.so/api/v2/setup/?version=v2.6.3" -o plane.zip
unzip plane.zip
```

这是公开接口，不需要认证。参数：`version` 必填（发行标签，形如 `v2.6.3`），`airgapped` 可选（默认 `false`，离线场景设 `true`），`platform` 可选（`amd64` 或 `arm64`，仅在 `airgapped=true` 时生效）。标准下载包含编排文件与变量文件；离线下载还会按架构给出对应的编排文件。离线部署另有单独文档，需要自行导入容器镜像。

## 常用操作

**1. 完整走一遍社区版部署（建目录 → 取脚本 → 安装）**

```bash
mkdir plane-selfhost && cd plane-selfhost
curl -fsSL -o setup.sh https://github.com/makeplane/plane/releases/latest/download/setup.sh
chmod +x setup.sh
./setup.sh          # 选安装，装完选退出
```

**2. 改完配置再拉起服务（脚本菜单里选启动，也可以直接操作编排文件）**

```bash
# 编辑完 plane.env 后
./setup.sh          # 选「启动」或「重启」
```

服务会拉起一组容器：Web 前端、管理后台、公开分享页、接口服务、后台任务、定时任务、一次性数据库迁移任务，以及 Postgres、Redis（Valkey）、RabbitMQ 与对象存储。

**3. 看日志排查启动问题**

```bash
./setup.sh          # 选「查看日志」
```

**4. 备份与升级**

```bash
./setup.sh          # 备份数据 / 升级，按菜单提示走
```

**5. 调接口（工作区维度，按工作区标识寻址）**

```bash
curl -H "X-API-Key: <你的接口密钥>" \
  "https://<你的实例地址>/api/v1/workspaces/<workspace-slug>/projects/"
```

接口覆盖项目、工作项、状态、标签、周期、模块、页面、集合、里程碑、估算、工时、史诗与倡议等资源。认证头与具体路径以官方接口参考当前内容为准。

**6. 控制接口调用频率**

```bash
# plane.env 里
API_KEY_RATE_LIMIT="60/minute"
```

**7. 调整上传大小上限**

```bash
# plane.env 里，单位是字节
FILE_SIZE_LIMIT=5242880
```

## 常见坑

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 照仓库里的编排文件部署，起来一堆本地构建的服务，怎么改都不对 | 仓库根目录的编排文件是给本地开发用的（各服务走源码构建），不是生产部署文件 | 生产部署统一走官方安装器或按版本下载的发行版配置文件，不要拿开发用文件当部署模板 |
| 换了端口或域名后前端能开，但登录、上传都失败 | `WEB_URL` 与 `CORS_ALLOWED_ORIGINS` 还停在默认的 `http://localhost` | 这两个必须和实际访问地址（含端口）保持一致，改完重启服务 |
| 服务起不来，报端口被占用 | 默认监听 `80` / `443`，这两个端口在宿主上通常已被别的服务占着 | 部署前先确认端口空闲，或在 `plane.env` 里改成 `8080` / `4430` 这类空闲端口 |
| 装完发现迁移容器退出了，以为装失败 | 数据库迁移是一次性任务，跑完退出属于正常 | 看它的退出码与日志；它成功退出、其余服务在跑就说明安装正常 |
| 机器磁盘/网络出问题后数据没了 | 默认依赖本机上的数据库与对象存储容器，本机故障即数据故障 | 生产环境按官方建议外接 Postgres 与对象存储；至少把备份跑通并验证恢复 |
| 用脚本备份了却恢复不出来 | 备份只覆盖了一部分组件，或备份与当前部署的配置版本不匹配 | 把数据库、对象存储内容与 `plane.env` 一起纳入备份；恢复前先确认版本一致 |
| 升级后服务起不来、数据异常 | 跨版本升级可能带数据库迁移，且部分历史版本有专门的升级路径 | 升级前备份、读该版本的升级说明；跨大版本严格按官方迁移文档走 |
| 接口突然返回限流错误 | 接口密钥有速率限制，默认每分钟有限次 | 在 `plane.env` 里按实际调用量调整 `API_KEY_RATE_LIMIT`，或降低调用频率、做退避重试 |
| 团队从别的系统迁数据，发现对不上 | 工具的数据模型是工作项 + 周期 + 模块这套，不是通用任务表 | 迁移前先做字段映射（状态、优先级、负责人、自定义属性），别指望直接导入就一致 |

## 权限与用途说明

| 网络访问 | 是 | 下载安装器与发行版配置文件、拉取容器镜像；客户端与自托管实例交互；接口集成调用 |

## 能力边界

**覆盖**：

- 部署路径：商业版自托管安装器（含 Express 与 Advanced 两种模式）、社区版 Docker Compose 脚本部署、按版本直接下载配置文件、Kubernetes、第三方托管平台；离线场景另有对应文档。
- 核心概念与操作面：工作项（含子属性与关联）、周期（含进度图）、模块、保存视图与共享、页面、分析。
- 配置面：`plane.env` 关键变量（监听端口、对外地址、跨域来源、数据库、缓存、消息队列、对象存储、上传上限、接口限流）、许可证与环境变量说明、自定义域名与证书、反向代理、外部密钥、遥测开关。
- 运维面：菜单化的启停/重启/升级/查日志/备份，健康检查，日志查看，实例管理员（God mode）设置。
- 接口面：按工作区寻址的 REST 接口（项目、工作项、状态、标签、周期、模块、页面、集合、里程碑、估算、工时、史诗、倡议等），使用接口密钥认证。

**不覆盖**：

- 不覆盖仓库的本地开发流程（从源码构建前端、接口与各子服务的工具链），那是另一条路径。
- 不负责部署方基础设施的运维细节：反向代理与证书的实际配置、Kubernetes 集群运维、对象存储的生命周期策略，都由你所在环境决定。
- 不提供第三方集成（代码托管、告警、检索服务等）的开通代办，只说明接入位置在官方文档里。
- 不提供该项目的官方技术支持，也不代办商业档位的授权与账单。
- 不做项目管理方法论的咨询。工具怎么用不等于流程该怎么定。

## 依赖条件

- 硬件（官方给出）：2 核 CPU（x64/AMD64 或 AArch64/ARM64）；4 GB 内存，生产建议 8 GB。
- 系统：Ubuntu、Debian、CentOS、Amazon Linux 2/2023、macOS，或 WSL2 下的 Windows；社区版脚本需要 bash 环境（Windows 用 gitbash），执行用户要有 Docker 权限。
- 软件：Docker 与 Docker Compose（官方要求使用最新版）。
- 组件依赖：PostgreSQL、Redis、消息队列、S3 兼容对象存储。生产环境官方建议外接数据库与存储，而不是用随部署拉起的本机容器。
- 对外提供服务需要域名、TLS 证书与反向代理；还需要在防火墙侧放行所选端口。
- 可选：代码托管 / 告警 / 检索等服务凭据（启用对应集成时）；商业档位可能需要授权密钥。

## 已知限制

- 自托管是多容器系统，资源占用与运维复杂度明显高于单容器服务；2 核 4 GB 是官方给出的下限，不是舒适配置。
- 监听端口默认是 `80` 和 `443`，与宿主上已有的 Web 服务容易冲突，部署前必须确认。
- 跨版本升级存在需要专门迁移路径的情况，且升级可能带数据库结构变更；不做备份就升级风险很高。
- 默认把数据库与对象存储跑在本机容器里，机器故障即数据丢失风险；生产环境需要外接组件。
- 接口密钥有速率限制（默认每分钟有限次），高频集成需要调整配置或自行做退避。
- 发行标签、变量名、接口路径与覆盖的资源范围会随版本变化，执行前请以官方文档与发行版配置文件当前内容为准。

## 自检清单

- [ ] 先确认要**托管云**还是**自托管**，两者步骤完全不同。
- [ ] 自托管前确认目标发行版（商业版安装器还是社区版脚本），并按对应文档操作。
- [ ] **不要**用仓库根目录的开发用编排文件做生产部署。
- [ ] 宿主已装 Docker 与最新版 Docker Compose；执行用户有 Docker 权限。
- [ ] `LISTEN_HTTP_PORT` / `LISTEN_HTTPS_PORT` 已确认空闲，避免和宿主已有服务撞端口。
- [ ] `WEB_URL` 与 `CORS_ALLOWED_ORIGINS` 都已改成实际访问地址（含端口），两者一致。
- [ ] 数据库、缓存、消息队列、对象存储的口令都已从默认值换掉。
- [ ] 生产环境已按官方建议外接数据库与对象存储；至少准备好了备份与恢复演练。
- [ ] 确认一次性迁移任务已成功退出，其余容器保持运行。
- [ ] 升级前完成备份并读过该版本的升级说明；跨大版本按官方迁移文档走。
- [ ] 需要程序化访问时，确认接口密钥认证方式与限流设置能承受预期调用量。
- [ ] 对外发布前确认域名、证书与反向代理已通，且管理后台入口不暴露给无关人员。
