# 三剪客 · 中文文本处理与情感分析

snownlp 是一个纯 Python 的中文文本处理小库：分词、词性标注、情感倾向、拼音、繁简转换、关键词、摘要、句子切分、TF-IDF、文本相似度，一个 `SnowNLP` 对象基本全包了。它的卖点是**轻**——不依赖 NLTK，也不用下模型，`pip install` 完就能离线跑，自带训练好的字典。做评论情感粗筛、关键词粗提、批量文本预清洗这类活儿，几十行代码就能收工。

**上游项目**：`snownlp`　**仓库**：https://github.com/isnowfy/snownlp

## 什么时候用 / 不用

**用它**：

- 「把这段中文切词 / 标一下词性」——最基础的入口，一行代码拿到结果
- 「这批商品评论是好评还是差评，先粗筛一遍」——情感倾向直接给一个 0~1 的正向概率
- 「把这段中文转成拼音」——`s.pinyin` 一次调用拿到整句拼音列表
- 「把繁体文案转成简体」——无外部依赖的繁简互转
- 「从长文里抽关键词、抽摘要句」——TextRank 实现，不需要联网也不需要模型文件
- 「算两段文本像不像」——给一个已分词的文档列表，用 `sim` 拿 BM25 相似度

**不要用它**：

- 要做高精度情感分类或领域自适应——内置情感字典偏电商评价语境，换领域掉分明显
- 要实体识别、句法依存、指代消解——它没有这些能力，别硬凑
- 要 GPU 加速或大规模分布式推理——纯 CPU，面向的是中小数据量
- 要长时间活跃迭代的依赖——这个库很久没有新的正式版本，遇到问题大概率得自己改
- 要专用领域分词（医学、法律、代码标识符）——通用分词在这种语料上会切得很碎，应换可加载自定义词典的方案

## 常用操作

### 1. 分词、词性、情感、拼音一把抓

```python
from snownlp import SnowNLP

s = SnowNLP(u'这个东西真心很赞')
print(s.words)        # 分词结果
print(s.tags)         # 词性标注，形如 [(词, 标记), ...]
print(s.sentiments)   # 正向概率，越接近 1 越正面
print(s.pinyin)       # 拼音列表
```

### 2. 繁体转简体

```python
from snownlp import SnowNLP

s = SnowNLP(u'「繁體字」「繁體中文」的叫法在臺灣亦很常見。')
print(s.han)
```

### 3. 关键词与摘要

```python
from snownlp import SnowNLP

text = u'（这里放一段几百字的中文长文）'
s = SnowNLP(text)
print(s.keywords(3))   # 抽 3 个关键词
print(s.summary(3))    # 抽 3 句摘要
print(s.sentences)     # 切成句子列表
```

### 4. 文本相似度（BM25）

```python
from snownlp import SnowNLP

s = SnowNLP([[u'这篇', u'文章'],
             [u'那篇', u'论文'],
             [u'这个']])
print(s.tf)              # 词频
print(s.idf)             # 逆文档频率
print(s.sim([u'文章']))  # 与每个文档的相似度
```

注意：这个用法要传**已经分好词的文档列表**（列表的列表），不是原始长字符串。

### 5. 用自备语料重训内置模型

分词、词性标注、情感分析三个模块提供了训练入口：

```python
from snownlp import seg
seg.train('data.txt')
seg.save('seg.marshal')

# 词性标注
# from snownlp import tag
# tag.train('199801.txt')
# tag.save('tag.marshal')

# 情感分析（需要正负样本两个文件）
# from snownlp import sentiment
# sentiment.train('neg.txt', 'pos.txt')
# sentiment.save('sentiment.marshal')
```

训练产物是 `.marshal` 文件，还要把对应模块 `__init__.py` 里的 `data_path` 指到这个新文件上才会生效。

### 6. 批量给评论打分

```python
from snownlp import SnowNLP

texts = ['质量很好，下次还来', '发货太慢了，包装还破了', '一般般吧']
for t in texts:
    print(round(SnowNLP(t).sentiments, 3), t)
```

按分值排序即可粗筛出负面评论，再人工复核。

## 常见坑

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 情感分和直觉相反，明明好评却只有 0.3 | `sentiments` 是**正向概率**，不是分差也不是百分制；0 最负面、1 最正面 | 阈值别拍脑袋定 0.5，先在自己语料上抽样看分布，再定切分点 |
| 换成数码、医美、金融评论后准确率暴跌 | 内置情感字典的语料以买卖评价为主，领域外泛化差 | 要么用自备语料重训情感模型，要么只把它当粗筛，关键结论换更专业的模型 |
| 传了一整个长字符串给 `sim`，结果没有意义 | `sim` 走的是 BM25，需要**已分词的文档列表** | 先把每篇文档切成词列表，组成「列表的列表」再丢进去 |
| 在很新的 Python 上导入或加载字典报错 | PyPI 上最后一次发布是 2015 年，当时的目标运行时远早于现在 | 先做最小自检（导入 + 分词 + 情感各跑一次）；不通就固定到能跑通的 Python 版本，或用虚拟环境隔离 |
| 分词把「人工智能」切成「人工 / 智能」 | 通用分词模型 + 内置词典的覆盖有限 | 不要指望它识别领域术语；术语多的场景换支持自定义词典的分词方案 |
| 重训后 `seg.train(...)` 跑过但结果没变 | 只训练、没有把 `data_path` 指向新生成的 `.marshal` | 训练完 `save`，再改对应模块 `__init__.py` 里的 `data_path`，最后重启进程 |
| 处理几十万条文本时越来越慢 | 每条都要构造对象、加载字典，纯 Python 无并行 | 把模型加载与循环拆开、按批处理并考虑多进程；超大规模改用带 C 扩展或 GPU 的方案 |
| 读文件时中文乱码 | 早期示例大量使用 `u'...'`，读写文件时编码不匹配就会乱码 | Python 3 里字符串默认 Unicode；读写文件时显式写 `encoding='utf-8'` |

## 能力边界

**覆盖**：

- 中文分词（基于字符的生成式模型）
- 词性标注（3-gram 隐马）
- 情感倾向（输出正向概率）
- 文本分类（朴素贝叶斯）
- 汉字转拼音（字典树最大匹配）
- 繁体转简体（字典树最大匹配）
- TextRank 关键词与摘要抽取
- 句子切分、TF-IDF、BM25 文本相似度
- 用自备语料重训分词 / 词性 / 情感三个模型
- 支持 Python 3（该项目后期版本已支持）

**不覆盖**：

- 命名实体识别、句法依存、指代消解、事件抽取
- 词向量训练与预训练语言模型推理
- 简体转繁体（只提供繁转简方向；反向需求要另找方案）
- 自定义用户词典热加载（术语覆盖需要靠重训或换方案）
- GPU 加速、批量化张量推理、分布式处理
- 命令行工具、HTTP 服务、Docker 镜像（纯 Python 库，需自己包一层）

## 依赖条件

- Python 3（该包已提供 Python 3 支持，但版本较老，建议先在目标解释器上做最小自检）
- 只需标准库；PyPI 元数据未声明任何安装依赖，也不需要 NLTK
- 字典随包分发（安装包体积较大，因为内含训练好的数据文件）
- 无网络、无账号、无 API Key、无显卡要求
- 重训功能需要一个可写的目录来落 `.marshal` 文件

## 已知限制

- PyPI 上最新版本为 0.12.3，发布于 2015 年，之后没有新的正式版本
- 情感分析只在买卖评价类语料上表现较好，其他语境效果有限（上游自己在说明里也标注了这一点）
- 分词与词性标注是通用模型，领域术语识别能力有限
- 只提供繁转简一个方向，没有简转繁
- 字典随包分发，冷启动内存占用与包体积都偏大
- 训练入口只覆盖分词、词性、情感三块，分类与摘要等能力没有公开的训练接口
