# 三剪客 · 调研取证小组

> ## ⚠️ 先申请你自己的 API Key
>
> **本 Skill 不内嵌任何密钥，也不代付费用。** 请到
> **[算力集市 api.a7w.cn](https://api.a7w.cn/)** 注册并创建**你自己的** API Key
> （新用户有赠送点数，可以先免费试跑几条）。
>
> 拿到后填进环境变量 `A7W_API_KEY`，或直接传给 `--key` 参数。
> **请勿使用他人提供的 Key** —— 用量与费用都记在 Key 所属账号上。

> ## 🚫 本包**不联网检索**
>
> 它没有检索端点，也不会去外部查证任何事实。它做的是**本地推理与评级**：
> 把「这句话凭什么被信」这件事拆开、摊平、判定强弱，并给出可采信的边界。
> **证据在现实世界里是否真的存在、数字是否真的对，仍然要人来核。**
> 不要把它当成事实核查服务——它是**取证流程的骨架**，不是数据库。

## 能做什么

对一份**已有材料**里的**事实主张**做取证与对抗验证，产出**可采信边界**：

```
claims    → 主张方：结论 + 逐条支撑主张 + 编号证据清单
challenge → 质疑方：逐条挑战书（必须指出挑战类型），信息隔离
evidence  → 取证方：证据强度评级（强 / 中 / 弱 / 无据）
verdict   → 裁决方：可采信边界 + 降级表述（可直接替换进稿子的说法）
```

它替代的是评审会上最耗人的那一步：不是"没人质疑"，而是
**"质疑提了一堆，但哪条主张真的站不住、站不住的话该怎么说，没人给得出可用的替代"**。

| 你最关心 | 答案 |
|---|---|
| 跟"再让模型挑挑毛病"有什么不同 | 四道工序是**四次独立调用**，且质疑方**看不到**主张方的推理过程（隔离证据写进产物） |
| 质疑会不会走过场 | 会，但会被拦下：本地检查挑战是否真的成立，**一条都没成立就判「质疑无效」**，`exit=3` |
| 会不会对每条都放行 | 会，但同样拦：所有主张的挑战结论都是「放行」时判质疑无效（`--all-passed-ok` 只在确认材料无争议时用） |
| 证据强度会不会随手写 | 不会：提示词里钉死一张**形态表**，本地按 `source_key` 分组核对，同组极差 > 1 档判「评级口径不一致」 |
| 裁决会不会只写一个"删"字 | 不会：判「降级表述」或「撤回」的**必须给替代表述**；替代表述不能与原句几乎同句、不许编新数字、不许把原数字删掉 |
| 会不会采信站不住的结论 | 不会：证据强度是「弱」或「无据」的主张，**不许判「可采信」**（追认门） |
| 引文会不会是编的 | 主张、挑战、裁决依据的引文都要**本地校验**能不能在原文里找到，编造的剔出并计入未锚定率 |
| 多少钱 | 按 token 计费。实测：324 字符材料 = 4 次调用、18,496 token、约 45 秒 |
| 要装什么 | **什么都不用装**。只用 Python 标准库，不需要 pip install 任何东西 |

### 三个命令就够（零成本那两个先跑）

```bash
python3 scripts/run.py roles                               # 看四道工序（零成本）
python3 scripts/run.py cost --file 材料.md                  # 报价：大概花多少 token（零成本）
python3 scripts/run.py run  --file 材料.md --outdir D:/crew  # 一条命令跑完
```

### L3 定位：这是"取证式"，不是"对抗评审式"

| | L2 内容质量闭环 | 对抗评审（`sanjianke-review-board`） | **本包（取证式 L3）** |
|---|---|---|---|
| 审的是 | **文本质量**（信息密度/结构/可读性…） | **方案可行性**（该不该过） | **事实主张能不能站得住** |
| 角色关系 | 一个声音自我迭代 | 四个**互相冲突的价值立场** | 同一件事的**四道工序** |
| 核心机制 | 打分 → 重写 → 复评到收敛 | 分歧显性化 + 裁决 | **信息隔离 + 质疑必须成立 + 降级表述必须给** |
| 产出 | 定稿 + 评分轨迹 | 裁决书 + 条件清单 + 少数派意见 | **证据强度评级 + 可采信边界 + 降级表述** |
| 核心闸门 | 未锚定率 / 丢事实 | 立场失效 | **质疑无效 / 降级缺失** |

**和对抗评审的差别不是"换个维度"。** 那边的四席是四个目标函数互相否掉对方，
产出是"该不该过"；本包的四道工序是一条链（缺一环就没有下游输入），
产出是"哪句话能原样说、哪句话必须换个说法"——**替代表述本身就是交付物**。

## 怎么用（命令行）

### 第 0 步：获取 API Key

到 **[api.a7w.cn](https://api.a7w.cn/)** 注册，创建一个 API Key（形如 `sk-...`）。

### 第 1 步：装依赖

**零依赖。** 只要机器上有 Python 3.7+：

```bash
python3 --version
```

包里自带的 `scripts/a7w.py` 是零依赖客户端（只用 `urllib` / `json` / `mimetypes`），
`scripts/run.py` 也只用标准库。

### 第 2 步：填 Key

```bash
# Linux / macOS
export A7W_API_KEY=sk-你的key

# Windows PowerShell
$env:A7W_API_KEY="sk-你的key"
```

也可以存进配置文件反复用（推荐）：

```bash
python3 scripts/a7w.py login --key sk-你的key
```

### 第 3 步：先做零成本自检（不联网、不花点数）

```bash
# 看四道工序的职权与信息隔离发生在哪一步
python3 scripts/run.py roles

# 报价：这次取证大概花多少 token（金额要你自己填单价）
python3 scripts/run.py cost --file 材料.md
python3 scripts/run.py cost --file 材料.md --price-in 1000 --price-out 1000
```

### 第 4 步：跑第一个例子

```bash
# 一条命令跑完（claims → challenge → evidence → verdict），断点续跑
python3 scripts/run.py run --file 材料.md \
    --outdir D:/crew --json --out D:/crew/run.json
```

`--outdir` 里会落 13 个文件：`brief.md/json`、`claims.md/json`、`challenge.md/json`、
`evidence.md/json`、`verdict.md/json`、`REPORT.md`（总报告）、`log.json`（动作流水）、
`state.json`（断点）。
**同一个 `--outdir` 重跑只会打印"断点命中，跳过"，0 次调用。**

### 分步跑（想看清每一步时）

```bash
python3 scripts/run.py claims    --file 材料.md --outdir D:/crew --json
python3 scripts/run.py challenge --file 材料.md --claims D:/crew/claims.json --json
python3 scripts/run.py evidence  --file 材料.md --claims D:/crew/claims.json \
                                 --challenge D:/crew/challenge.json --json
python3 scripts/run.py verdict   --file 材料.md --claims D:/crew/claims.json \
                                 --challenge D:/crew/challenge.json \
                                 --evidence D:/crew/evidence.json --json
python3 scripts/run.py log       --outdir D:/crew
```

### 只想预演提示词（不花钱）

```bash
python3 scripts/run.py claims --file 材料.md --dry-run
```

这一点在文档里明说了。**想核对信息隔离**，用 `challenge --dry-run`：那是质疑方
真正发出的提示词，可以直接看到里面没有 `reasoning`、没有 `coverage`。

## 参数说明

### 全局

| 参数 | 说明 |
|---|---|
| `--json` | 以 JSON 输出；**写在子命令前后都可以**。**stdout 永远只有一个 JSON**（契约见下） |
| `--key` | 临时指定 API Key（也可用 `A7W_API_KEY` 或 `~/.a7w/config.json`） |
| `--dry-run` | 只打印将发送的提示词，**不调模型、不花钱** |
| `--out` | 把结果写到文件。**带 `--json` 时写的是结果 JSON**（可原样喂给下一个子命令） |

### `--json` 契约（给流水线与 agent 消费）

| 情形 | stdout | 退出码 |
|---|---|---|
| 成功 | 结果对象，含 `"ok": true` | 0 |
| **闸门命中，但结果已产出** | **结果对象本身**就带 `"ok": false`、`"exit": 3`、`"gate_failed": true` 与完整 `gates`（**不再另补错误信封**，守住"只有一个 JSON"） | 3 |
| 失败且结果未产出（参数错 / 调用失败 / 预算超限 / 未捕获异常） | `{"ok": false, "exit": <码>, "error": {"kind": …, "message": …}}` | 2 / 4 / 5 / 1 |

`error.kind` 取值：`usage` / `gate` / `call` / `budget` / `interrupt` / `internal`。
`kind: "internal"` 是未预料异常的兜底信封（退出码 1），**完整 traceback 原样打到 stderr**——
报 bug，不藏 bug。人读文案一律走 stderr，非 `--json` 模式的输出一个字符都没变。

### 材料输入（`claims` / `challenge` / `evidence` / `verdict` / `run` 共用）

| 参数 | 说明 |
|---|---|
| `--file` | 待证材料（`.md` / `.txt`，UTF-8，自动去 BOM） |
| `--roles` | 四道工序（逗号分隔）。**必须给全**：本包是链条，缺一环就没有下游输入，否则 `exit=2` |
| `--outdir` | 目录产物落这里，**必须在包外**；落在包内 `exit=2` |
| `--replay` | 回放一份已保存的阶段产物（`run` 传目录）：**零调用**，只跑本地闸门与渲染。`run` 会**重做锚点与本地校验**，不直接信文件里的结论 |
| `--model` | 模型名，默认 `deepseek-chat`（实测可用；用 `run.py models` 现查在架模型） |
| `--temperature` | 采样温度，默认 0.7（**进断点 key**） |
| `--max-tokens` | 单次输出上限，默认 8192 |
| `--no-json-mode` | 不要求上游返回 JSON 对象（个别模型不支持 `response_format` 时用） |

### `run` 专有

| 参数 | 说明 |
|---|---|
| `--force` | 忽略断点文件从头重跑（key 没命中就会重新花钱） |
| `--all-passed-ok` | 允许「质疑方全部放行」不判「质疑无效」（**只在确认材料本身无争议时用**；默认是硬闸门） |

### `cost` 专有

| 参数 | 说明 |
|---|---|
| `--file` / `--text` | 按材料或直接文本估 |
| `--price-in` / `--price-out` | 单价，单位「点 / 百万 token」。**不给我就不给金额（不编价）** |
| `--budget` | 预算上限（**点**），超了 `exit=5`；**用 `--budget` 必须给单价**，否则 `exit=2` |

## 四道工序

| 工序 | id | 目标 | 权限 | 产出物 |
|---|---|---|---|---|
| **主张方** | `claimant` | 把结论说清、给每条主张**指名**依据 | 无 | 主张清单 + 证据引用 |
| **质疑方** | `challenger` | 每条主张找一个**能站住的**漏洞 | **能要求撤回** | 逐条挑战书（**必须指出挑战类型**） |
| **取证方** | `evidence` | 给每条主张一个**能用一句话解释**的强度评级 | 无 | 证据强度评级（强/中/弱/无据） |
| **裁决方** | `arbiter` | 定可采信边界 | **终裁** | 裁决 + **降级表述建议** |

**质疑类型七选一**（必须指出）：`样本` / `因果` / `口径` / `时效` / `来源` / `范围` / `利益`。
**证据强度四档**：`强` / `中` / `弱` / `无据`。
**裁定三档**：`可采信` / `降级表述` / `撤回`。

细节见 `references/角色与证据规则.md`。

### 信息隔离发生在哪一步

| 阶段 | 拿得到什么 | **拿不到什么** |
|---|---|---|
| `claims` | 材料全文 | — |
| `challenge` | 结论 + 主张原句 + `claim_type` + 证据**编号/名称/来源类型/时间** | 主张方的 `reasoning`（推理过程）、证据的 `coverage`、其它角色任何文字 |
| `evidence` | 主张 + 证据条目 + 挑战记录 | 主张方的 `reasoning` |
| `verdict` | 主张 + 挑战 + 证据强度 | —（终裁要看全部） |

**为什么隔离必须是真的**：如果质疑方能读到主张方的推理，它会顺着别人的论证往下补，
挑出来的都是措辞问题，而不是主张本身站不站得住。本地会**校验隔离有没有漏**：
把每条 `reasoning` 切成片段，看它们有没有出现在质疑方的提示词里（见 `isolation` 字段）。

## 八道本地硬闸门（都是确定性的，跑两次结果一样，可直接进 CI）

| # | 闸门 | 判据 | 退出码 |
|---|---|---|---|
| 1 | 合规 | 违禁词（最 / 第一 / 国家级 / 100% / 保过…）；**「最X」两类豁免**：可度量断言（`订单量最高`，不看句首）+ 句中程度用法；**句首的商品宣称照拦**；材料侧全档、产出侧只查高风险并排除「引用」与「提到」 | 3 |
| 2 | 占位符残留 | `{}` / `[待填]` / `XXX` / `（此处省略）` / **整段就是一个空档**（字段级判据，不误伤「…（均待补充）」这类正常说明） | 3 |
| 3 | 照抄提示词示例 | 去标点相等 / Jaccard ≥ 0.75 / 覆盖度 ≥ 0.60（带**适用窗口**：长度比 ≤ 3.0 且示例 ≥ 8 字） | 3 |
| 4 | **锚点** | 主张引文、挑战引文、裁决依据四层各锚各的文本；未锚定率 > 40% 判「定位失败」 | 3 |
| 5 | **质疑有效性** | 一条挑战都没成立 → 判「质疑无效」；全部放行（`passed`）同样判无效 | 3 |
| 6 | **降级表述完整性** | 判「降级表述 / 撤回」却不给替代表述 / 替代表述与原句相似度 ≥ 0.90 / 引入新数字 | 3 |
| 7 | **评级口径一致性** | 同一 `source_key` 在不同主张上的评级极差 > 1 档 | 3 |
| 8 | **追认门** | 弱 / 无据的主张判「可采信」；或强证据判「撤回」 | 3 |
| — | 成本上限 | `--budget` 超限就地中止（**未发起调用**） | 5 |
| — | 产出不许进包 | `--outdir` / `--out` 落在 Skill 包内 | 2 |

命中一律：**标红 + stderr 汇总 + 非 0 退出码**。

### 第 5、6 道闸门为什么是本包最值钱的那两道

**第 5 道（质疑有效性）** 防的是"走过场的质疑"。它不看模型的自述，本地算：

- 一条挑战要算「成立」，必须同时满足：`verdict=challenged`，**且** `reason` 与 `required_fix`
  归一后各 ≥ 8 字（空话不算）
- **成立数为 0 → 判「质疑无效」**，`exit=3`。本包**不把「全部放行」当成「证据充分」**
- 所有主张的挑战结论都是 `passed`（全部放行）→ 同样判无效
- 挑战**没有指出类型** → 标红（本包要求挑战必须落在七类里）

**第 6 道（降级表述完整性）** 防的是"把稿子掏空"。它同样在本地判：

- 判「降级表述」或「撤回」的主张，`downgraded_wording` **不能为空**
- 替代表述与原主张的 min 归一相似度 ≥ 0.90 → 判「没换说法」（抄一遍不算降级）
- 替代表述里出现材料里没有的数字 → 拦（**降级表述不许编新数据**）
- 替代表述把原主张里的数字全丢了 → 标红（那是删除，不是降级）

> 真机实测里这两道闸门各抓到过真东西：第 6 道抓到一条**「替代表述 = 原句 + 括号注」**
> （相似度 0.95）——那是把口径缺口贴上去了，但主张本身该怎么改还没说，属真命中。
> 第 6 道还标红过两条「替代表述把原数字丢了」。

含 `--all-passed-ok` 在内，**23 个闸门自测用例全部零成本**（走 `--replay` 与参数校验路径）。

## 产出目录长这样

```
D:/crew/
├── brief.md / brief.json      材料索引（大纲 / 数字 / 专名 / 本地预扫）——零调用
├── claims.md / claims.json    主张清单 + 证据清单 + 锚点校验
├── challenge.md / challenge.json  质疑书（挑战类型 / 要求撤回）+ **信息隔离证据**
├── evidence.md / evidence.json    证据强度评级 + 按 source_key 的分组核对
├── verdict.md / verdict.json      **可采信边界**：裁定 + 降级表述 + 裁决理由
├── REPORT.md                  总报告（四道工序 + 八道闸门 + token）
├── log.json                   动作流水（每条挑战、每条裁定一条记录）
└── state.json                 断点文件（重跑不重复扣费）
```

产出**一律落在包外**的 `--outdir` 里。包内只允许
`.md .py .txt .json .sh .js .yaml .yml .csv` 这几种后缀。

**断点 key 含全部影响产出的维度**：材料摘要与字符数、模型、温度、角色组合、
三套口径版本，以及上一阶段产物的摘要。少一个就会出现"改了参数却复用旧产物"。

有一个额外的零成本路径 `--replay`：`run --replay <已有产物目录>` 只用存下来的
`claims.json / challenge.json / evidence.json / verdict.json` 重跑本地闸门与报告，
**一次调用都不发**。它会**重新做一遍锚点校验与本地判定**（不直接信文件里存好的结论），
所以手工改过的产物绕不过闸门。

### 这一个直接回答"是假质疑还是真质疑"

**质疑方真的挑战掉了主张。** 10 条主张、10 条挑战，**成立 10 条、放行 0 条**——
不是每条都放行。而且**每一条都有具体的挑战类型**，不是笼统的"表述不严谨"：

```text
C1 样本  致命  18 人且全部来自核心社群活跃老客 = 极端非概率样本；
                用 12/18 冒充「产品整体复购率」，分母与目标人群不是一回事
C2 来源  重要  抽样名单由运营自己拟定、自己执行、自己记录，外部无法复核
C3 利益  重要  回访者与被访者有服务关系、绩效与「产品成立」挂钩 = 自采自证
C4 口径  重要  4200 单是否含取消/退款/刷单/测试/0 元赠单、客单价分母是谁，全没交代
C5 口径  重要  466 是 4200÷3÷3 的算术均值，三城体量悬殊时「典型城市」不存在
C6 因果  致命  订单量是绝对量，缺曝光/访问分母就谈不了转化；以相关当因果
C7 因果  重要  未排除季节性、大促、其他 SKU 调整、低基数效应
C8 因果  致命  「带动」是因果断言，但没做增量归因、没排除蚕食效应
C9 来源  致命  300 万营收无假设、无公式、无出处，无法复核
C10 范围 致命  一家竞品「没做」被外推成「全行业只有我们走得通」
```

**裁决不是简单删掉。** 10 条里 7 条给的是**可用的替代表述**，例如：

| 原主张 | 裁定的替代表述（可直接替换进稿子） |
|---|---|
| 复购率 67%（12/18 自报） | 「在 18 位来自核心社群的活跃老客回访中，有 12 位自述每周至少复购一次；该结果仅代表核心社群活跃老客的自我陈述复购意愿，不代表产品整体复购率。」 |
| 华南区订单量最高，说明南方转化更好 | 「华南区订单绝对量在三个区域中最高，其原因（门店数、投放、上线时长或人群偏好等）尚待进一步验证，不能据此判断南方转化更好。」 |
| 竞品没做，证明只有我们走得通 | 「截至观察日，在已观察渠道内未见竞品上线小程序团购；该模式是否具备排他性尚需对多家竞品渠道进行系统性排查并给出壁垒证据。」 |

金额：文本网关**不公布单价**，所以本包只报 token。按 0.5 元预算反推，
18,496 token 要花到 0.5 元（= 50 点），等价单价约 **2,703 点/百万 token**。
