# 闸门口径、成本与排错

---

## 一、端点与鉴权

| 用途 | 方法 | 地址 |
|---|---|---|
| 大模型（OpenAI 兼容） | POST | `https://api.a7w.cn/api/v1/chat/completions` |
| 在架模型清单（免费） | GET | `https://api.a7w.cn/api/v1/models` |

**除这两个端点外，本包不调用任何其它接口，也不做任何联网检索。**

成功响应**不带 `code` 字段**；网关有时把它包一层 `{"code":1,"data":{...}}`，两种形态都认。

Key 三种给法（代码与文档里都不含任何 Key）：

```bash
python3 scripts/run.py run --file 材料.md --key sk-xxxx     # 1) 命令行
export A7W_API_KEY=sk-xxxx                                   # 2) 环境变量（Windows: $env:A7W_API_KEY="sk-xxxx"）
python3 scripts/a7w.py login --key sk-xxxx                   # 3) 写进 ~/.a7w/config.json 反复用
```

⚠️ **本包不走 `a7w._request(raw=...)`**。那边的 `raw` 参数是**原始请求体字节**（给 multipart 上传用），
**不是**"要原始响应"。同族有人把它当成后者用过，结果崩在**钱已经扣之后**。
本包一律自己发 `urllib` 请求，语义只有一种，不给误用的机会。

## 二、八道硬闸门（全部本地、确定性、可进 CI）

命中一律：**标红（`✗` 前缀）+ stderr 汇总 + 非 0 退出码**。

| # | 闸门 | 扫哪份文本 | 判据 | 退出码 |
|---|---|---|---|---|
| 1 | **合规** | 材料 + 产出（口径不同，见下） | 广告法违禁词表；**「最X」两类豁免**；「第一」序数豁免 | 3 |
| 2 | **占位符残留** | 材料 + 产出 | `{}` / `[待填]` / `XXX` / `（此处省略）`；**字段级**「整栏就是一个空档」 | 3 |
| 3 | **照抄提示词示例** | **产出** | 去标点相等 / Jaccard ≥ 0.75 / 覆盖度 ≥ 0.60（带适用窗口） | 3 |
| 4 | **锚点** | 主张引文 / 挑战引文 / 裁决依据 | 精确 / 子串 / 模糊（Jaccard ≥ 0.55）；未锚定率 > 0.40 判定位失败 | 3 |
| 5 | **质疑有效性** | 挑战书 | 一条挑战都没成立 → 「质疑无效」；全部放行同样判无效 | 3 |
| 6 | **降级表述完整性** | 裁决书 | 判不能采信却不给替代表述 / 替代表述与原句相似度 ≥ 0.90 / 引入新数字 | 3 |
| 7 | **评级口径一致性** | 证据评级 | 同一 `source_key` 组内极差 > 1 档 | 3 |
| 8 | **追认门** | 裁决 × 评级 | 弱/无据判「可采信」；强证据判「撤回」 | 3 |
| — | **成本上限** | — | `--budget`（**点**）；**必须配单价**，超限就地中止、**未发起调用** | 5 |
| — | **产出不许进包** | `--outdir` / `--out` | 路径落在 Skill 包内 | 2 |

### 闸门一扫两份文本，但**口径不同**

这是真机实测踩出来的（三类误报），不是理论设计：

- **材料侧**：全档（高/中/低风险）全查。材料是会被公开发布的东西，宁可多报。
- **产出侧**：只查**高风险**（明令禁止的那一类），并排除两类**正常写法**：
  1. **引用**：材料里已经出现过的词 → 本包在引用被证对象，不是新宣称
  2. **提到**：命中前后 24 字里有 `禁止 / 不得 / 无法举证 / 属于 / 撤回 / 删除 / 改为 …`
     这类标记词 → 本包在**指出它、要求撤回它**，不是自己在做违规宣称

真机实测的误报正是这样来的：取证方写「未说明是否含退款、是否含**刷单**」被拦下；
而本包的材料本身就是"对一组主张做取证"的场所，产出里出现「全网最低价」的概率
远高于其它包——拿材料侧那把尺子去量取证文书，一天能误报十次，
而误报会让人把整个闸门关掉。被排除的条目**不静默丢弃**：它们带
`not_counted_reason` 列在 `contextual_only` / `mentioned_as_warning` /
`quoted_from_material` 里，随时可人工复查。

**闸门仍然有牙**：`本方案必须保证过审，效果 100% 达标` 这种小句里没有任何标记词，
照样 `exit=3`（自测用例 12 覆盖）。

### 「最X」的两类豁免（**边界是可判定的**）

| 类 | 判据 | 例 | 结果 |
|---|---|---|---|
| **可度量断言** | `度量名词 + 最X + 标点/句尾`，**不看句首** | 「华南区订单量最高」「转化率最高」「样本量的上限」 | 豁免（记 `exempt_rule=measured_claim`） |
| **句中程度用法** | `最X` 后接程度/比较词，**且不在句首** | 「最大的区别是…」「最大的缺口是…」 | 豁免（记 `exempt_rule=degree_usage`） |
| — | **句首**的标题式宣称 | 「最大的缺口是没有口径」 | **照拦** |
| — | 在给**商品名词**下定语 | 「最高品质」「最高性价比」「效果最好」 | **照拦** |

关键区别：`订单量最高` 里的「最高」是**谓语**（在断言一个可度量指标的比较结果）；
`最高品质` 里的「最高」是**定语**（在给商品下定语）。前者豁免，后者照拦。
还有一个边界：`质量最高` 里的「质量」不是度量单位，**不豁免**（保守）。

### 闸门二的字段级判据（**真机实测踩出来的**）

第一版拿"段落级"判据去扫整篇散文，于是裁决方写的
「统计窗口起止日、是否剔除取消/退款/测试单（**均待补充**）」被判成"占位符残留"——
可那是在**说明口径缺口**，是正常交付物。

现在拆成两份判据：

| 判据 | 扫什么 | 命中条件 |
|---|---|---|
| 段落级 `placeholder_hits` | 整篇散文 | 只认空档**本身**（`{}` / `[待填]` / `XXX` / 整段就是「待补充」） |
| 字段级 `field_placeholder_hits` | 逐个字段 | 字段的值**整段就是一个空档**（「待补充」「暂无」「N/A」「—」…） |

两者判据不同，**不能混用一把尺子**：一段正常的「…（均待补充）」不该被段落级判据误伤，
而一个只写了「待补充」的字段必须被拦。

### 闸门三的 contain 适用窗口

覆盖度判据（示例被抄了多少）对**短示例**会饱和：示例归一后只有 3~5 字时，
长文本里被动凑齐两个二元组就有 0.5 的覆盖度——离 0.60 的阈值只差 0.10。

所以 `contain` 只在**两个条件都满足**时适用：

1. 目标片段长度 ≤ 示例长度 × **3.0**（长度比窗口）
2. 示例归一后长度 ≥ **8** 字（二元组数量够用）

不适用时记进 `contain_skipped`（按原因合并计数，**不静默略过**）。
真机一次完整运行里这条判据会被跳过 100~200 次（都是"产出句子比示例长得多"），
这是**正常的**，不是异常。

### 闸门五：质疑有效性（**本包核心之一**）

```
判据 A（硬）：挑战书里一条挑战都没成立
              （没有任何 target 主张被判为 challenged **且** reason 与 required_fix 都不是空话）
              → 判「质疑无效」：质疑没发生。**不许把「全部放行」当「证据充分」**。
判据 B（硬）：所有主张的挑战结论都是 passed（全部放行），而主张数 ≥ 2
              → 同上判「质疑无效」。
判据 C（红）：挑战缺 `challenge_type`（或不在七类里）→ 标红。
判据 D（红）：被挑战成立的主张没出现在裁决里 → 标红（不许装作没看见）。
```

**一条挑战算「成立」的两条本地条件**（只看模型自报的 `verdict` 不算数）：

1. `verdict == "challenged"`
2. `reason` 与 `required_fix` 归一后**各 ≥ 8 字**（挡住"建议补充数据"式空话）

材料本身确实无争议时用 `--all-passed-ok`，把判据 A/B 降级为标红。

### 闸门六：降级表述完整性（**本包核心之二**）

```
判「降级表述」或「撤回」的主张，downgraded_wording 不能为空
替代表述归一后 < 6 字（太短）→ 拦
替代表述与原主张的 min 归一相似度 ≥ 0.90 → 判「没换说法」，拦
替代表述里出现材料里没有的数字 → 拦
替代表述把原主张的数字全丢了 → 标红（那是删除，不是降级）
判「可采信」却带替代表述 → 标红
判「可采信」却没给 basis_quote → 拦
```

**为什么相似度用 min 归一而不是 Jaccard**：原主张一句话、替代表述可能要带口径说明，
篇幅差一大，Jaccard 的分母是并集会被摊薄，"其实还是同一句话"反而测不出来。
min 归一回答的是"**短的那份有多少比例的内容出现在长的那份里**"。

### 闸门七：评级口径一致性（**本包特有**）

```
按 source_key 分组；组内把四档映射成数值（强=3 中=2 弱=1 无据=0）
极差 > 1 档 → 拦「评级口径不一致」
极差 ≤ 1 档 → 放行（同一来源支撑窄结论与外推结论，本来就可以差一档）
缺 source_key → 标红（同一来源的评级无法被本地核对）
归一到不了四档、也没有 confidence → 标红（不静默当「中」）
```

归一顺序：四档原样 → 前缀（「强，因为…」）→ `confidence` 兜底
（≥0.75 强 / ≥0.50 中 / ≥0.20 弱）→ `未标注`。

### 追认门：强度 → 裁定的逻辑底线

```
证据强度「弱」或「无据」的主张 → 不许判「可采信」
证据强度「强」的主张          → 不许判「撤回」（要撤回必须另给依据）
证据强度「无据」而裁定不是撤回 → 标红（通常只能撤回，建议人工复核）
同一主张有多条评级 → 本地取**最低**那一档（按最弱的支撑来定，不能挑有利的）
没有任何评级却定了档 → 标红
```

## 三、退出码（可直接用于 CI）

| 码 | 含义 |
|---|---|
| 0 | 四道工序跑完，且没有任何硬闸门命中 |
| 2 | 用法/配置错误（文件不存在、角色名错、角色不全、`--outdir`/`--out` 在包内、`--budget` 没配单价、回放目录不存在） |
| 3 | 硬闸门命中（合规 / 占位符 / 照抄示例 / 锚点 / **质疑无效** / **降级缺失** / **评级不一致** / **追认门**） |
| 4 | 调用失败（网络 / 鉴权 401 / 点数 402 / 模型名 404） |
| 5 | 预算超限，已就地中止（**未发起任何调用**） |
| 1 | 未捕获异常（`--json` 下给 `kind:"internal"` 信封 + 完整 traceback 到 stderr） |
| 130 | 用户中断 |

### `--json` 与退出码的配合（契约）

| 情形 | stdout | 退出码 |
|---|---|---|
| 成功 | 结果对象，含 `"ok": true` | 0 |
| 闸门命中但**结果已产出** | **结果对象本身**带 `"ok": false`、`"exit": 3`、`"gate_failed": true`、完整 `gates` | 3 |
| 失败且结果未产出 | `{"ok": false, "exit": <码>, "error": {"kind": …}}` | 2 / 4 / 5 / 1 |

第二条是刻意这样设计的：闸门命中时那份**结果本身就是失败报告**，
再补一个错误信封就会破坏"**stdout 永远只有一个 JSON**"这条不变量。
所以消费方读 `ok` 与 `exit`，而不是去猜信封在哪。

`--json` **写在子命令前后都可以**（父级与每个子命令各挂一个同 `dest` 的开关）。
⚠️ 但 argparse 报错时只有命令行里**真的有 `--json`** 才给信封；没有 `--json` 则 stdout 保持安静。

⚠️ **`--budget` 必须配 `--price-in` / `--price-out`**，否则 `exit=2`。
这道校验**在每一个会花钱的子命令的第一步**。事故复盘：它原先只写在 `cost` 里，
于是 `claims --file x --budget 50`（没给单价）一路跑完真实调用才返回——
用户以为设了上限，实际一分钱都没被拦住。

### `finish_reason`：解析失败时按它分叉（**不要用 content 长度判断**）

上游返回的 `finish_reason` 会被记进 `_LAST_FINISH`，并写进每次调用的 `usage_log`。
模型输出解析不出 JSON 时，本包**只认 `finish_reason`**：

| `finish_reason` | 诊断 |
|---|---|
| `length` | **确实**被 `max_tokens` 截断了，加大 `--max-tokens` 有效 |
| 其它（`stop` / …） | **不是截断**，加大 `--max-tokens` **没用**——多半是模型没按 JSON 输出（换模型或加 `--no-json-mode`） |
| 缺失 | 上游没返回，无法判断；先调大一次试试，仍报同样错就不是截断问题 |

**为什么不看 content 长度**：模型的 JSON 本来就可能比上限短得多，
用"长度接近上限"猜截断，会把"格式错"误报成"截断"，
于是用户去调大 `--max-tokens`，白花钱还解决不了问题。同族靠长度判断猜错过两次。

## 四、成本：只出 token，不编金额

- **文本网关不公布单价**，`/api/v1/models` 里也没有价格字段。所以 `cost` 不给我单价就**只报 token**。
- 字符 → token 标定（全族真机实测值，**估算不是账单**）：
  输入 1 token ≈ **1.61** 字符；输出 1 字符 ≈ **1.11** token。
- 一次完整取证的调用构成：

| 阶段 | 次数 | 说明 |
|---|---|---|
| 主张方 | 1 | 输入 = 材料全文 + 拆解要求 |
| 质疑方 | 1 | 输入 = 结论 + 主张原句 + 证据编号/名称/来源类型（**不含推理过程**） |
| 取证方 | 1 | 输入 = 主张 + 证据条目 + 挑战记录（含形态表口径） |
| 裁决方 | 1 | 输入 = 主张 + 挑战 + 证据强度 |

```bash
python3 scripts/run.py cost --file 材料.md                                    # 只出 token
python3 scripts/run.py cost --file 材料.md --price-in 1000 --price-out 1000    # 你的单价 → 点数
```

**真机实测（324 字符的自撰材料，`deepseek-chat`）**：

| 阶段 | prompt | completion | 耗时 | finish_reason |
|---|---|---|---|---|
| claims | 1217 | 2097 | 9.3s | stop |
| challenge | 1816 | 2717 | 15.2s | stop |
| evidence | 3250 | 1407 | 7.2s | stop |
| verdict | 3285 | 2707 | 12.6s | stop |
| **合计** | **9568** | **8928** | **约 45s** | 上游模型 `deepseek-flash` |

**共 4 次调用、18,496 token。** 由于网关不公布文本单价，**无法把 token 折成元**——
按 0.5 元预算反推：18,496 token 要花到 0.5 元（= 50 点），等价单价约
**2,703 点/百万 token**；只要你的账号单价低于这个量级，这一跑就在预算内。
真实金额请以账户流水为准，或自己传 `--price-in/--price-out` 折算。

### 报价偏保守（实测值 vs 预估值）

实测 completion 是 8,928 token，而 `cost` 的预估值是 4,800（四个阶段的输出经验值之和）。
原因：这份材料的主张数偏多（10 条），裁决书逐条给替代表述，输出自然更长。
**估算是下限口径**，材料复杂时会超。要卡预算就传 `--budget`，它按真实 usage 实时核。

## 五、断点续跑

- 断点文件：`<outdir>/state.json`，key 形如 `claims:00b213b3ed191dc6f280`
- key 里含：材料摘要与字符数、模型、温度、**角色组合**、口径版本（评分/提示词/角色定义三套），
  以及**上一阶段产物的摘要**
- 命中即跳过并打印「断点命中，跳过（0 次调用）」
- 要强跑用 `--force`

### 自测时抓到的一个真 bug（值得单独记一笔）

第一版 `--replay` **没有把规范产物写下来**，于是：
「`--replay` 用真实产物重跑一遍闸门」之后再正常跑一次 →
断点全部不命中 → **又付了 4 次调用的钱**。用户以为回放过的阶段不用再花钱。

现在做了两件事：

1. **回放与正常跑写同一份 `_pack_*` 结构**，序列化一致，下游摘要一致；
2. `_resume_key` 双算兜底：先按当下产物算 key，不命中再按「上一份产物摘要」算一次，
   两条都查。这样既保留了"产物变了要重跑"的语义（摘要仍在 key 里），
   也不会因为序列化漂移而白花钱。

自测用例 14 覆盖：回放之后正常跑 → **四个阶段全部断点命中、0 次调用、exit=0**。

`--replay <目录>` 是另一条零成本路径：读取该目录里的
`claims.json / challenge.json / evidence.json / verdict.json`，**一次调用都不发**，
只跑本地闸门与报告渲染。它的用途是"改完闸门口径之后，用同一批真实产物重跑一遍检查"，
以及**闸门自测**（本包 23 个闸门用例全部零成本）。注意它会**重新做一遍锚点与本地判定**，
不直接信文件里存好的结论——否则一份手工改过的产物就能绕过闸门。

> ⚠️ 写自测夹具时踩到两个坑，都记在这里：
> **(1)** `--replay` 会从产物 `raw` 字段重做归一化 → 喂坏数据必须**同时改 `raw` 里的字段**，
> 否则改动会被重算覆盖掉；**(2)** `--replay` 的 `--outdir` 若复用，断点命中会**复用上一个用例的产物**，
> 每个用例必须用独立的 outdir。

## 六、排错

| 现象 | 处置 |
|---|---|
| `没有找到 API Key` | `--key` / `A7W_API_KEY` / `a7w.py login` 三选一 |
| `鉴权失败（401）`／`点数不足（402）` | 到 https://api.a7w.cn/ 重新创建 Key 或充值 |
| `模型不存在（404）` | `run.py models` 现查在架名，别写死 |
| 上游 502/503/504 | 脚本自动退避重试 4 次；仍失败是网关侧问题 |
| **`challenge` 闸门命中** | 看 `problems`：一条都没成立，或全部放行。先看 `challenges[*].verdict` 与 `reason` 长度——真挑不动就如实写 `passed`，但**不许全部放行**；材料确实无争议用 `--all-passed-ok` |

| `output_placeholder` 命中 | 某个字段整段就是「待补充 / 暂无 / N/A」。**这不是**「…（均待补充）」那种正常说明 |

## 七、本包明确的边界

1. **不联网检索**。整条流水线只调用大模型与在架模型清单两个接口；
   证据在现实世界里是否真的存在，仍然要人来核。**「强」不等于「真」。**
2. **评级是启发式的**：形态表覆盖不到的证据形态会落到「未标注」并标红，需要人工定档。
3. **违禁词表是启发式自检**，来自公开经验整理与真机实测标定，**不构成法律意见**，
   也不代表任何平台官方审核标准。高风险类目（医疗、保健食品、金融、母婴、特殊化妆品）必须人工复核。
4. **产出侧合规是"宁松勿误"的**：只查高风险、排除引用与"提到"。它拦得住"本包自己造违规宣称"，
   但**不保证**产出里每一句都合规——不构成对外的合规背书。
5. **四道工序共用同一个模型**，隔离靠调用边界，不靠模型差异。
6. **取证质量取决于材料质量**：材料里只有"业内数据"这类无法指认的依据时，
   主张方列不出证据条目、取证方也无从评级——先回去把材料写实。
7. **不能替你做发布决策**。裁决书给的是"哪句能原样说、哪句必须怎么改"，最终发不发由使用者负责。
