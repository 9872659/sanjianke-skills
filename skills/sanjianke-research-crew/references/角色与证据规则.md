# 角色与证据规则

---

## 一、四道工序是一**条链**，不是四个立场

这是本包与同族"多席位"包最容易混淆的一点，先说清：

| | 四个**立场**（如对抗评审） | 本包的**四道工序** |
|---|---|---|
| 关系 | 四个目标函数**互相否掉对方** | 一条链，**缺一环就没有下游输入** |
| 判断"起作用了"的标准 | 分歧显性化；**一旦收敛就说明立场失效** | **质疑必须真的挑战掉一些主张** |
| 输入来源 | 各自独立看同一份材料 | 下一环吃上一环的产出 |
| 产出 | 一个裁决（谁支持谁反对怎么裁） | 一条**可采信边界**（哪句能说、怎么说） |

所以本包**不支持**"只跑两个角色"：链条缺一环，产出就不是取证。
`--roles` 给了但没给全 → `exit=2`。

---

## 二、四个角色

### 主张方（`claimant`）

**职责**：把结论与支撑说清，并给每条主张**指名依据**。

| 字段 | 要求 | 为什么 |
|---|---|---|
| `conclusion` | 一句话：读者被要求相信什么 | 后面所有主张都在为它服务；写不清就无法判断哪条主张是关键 |
| `claims[].text` | 一条主张只讲一件事 | 复合句无法被单独挑战（"既…又…而且…"里挑掉一半，结论仍成立） |
| `claims[].quote` | 材料里**原样**的一句 | 本地校验能不能找到；编造的会被剔出 |
| `claims[].claim_type` | 事实 / 因果 / 量化 / 预测 / 比较 / 因果+量化 / 规范 | 决定"这条主张最怕哪一类质疑"（见下一节） |
| `claims[].evidence_ids` | 指向证据编号 | 不许写"有数据支持"这种无法指认的说法 |
| `claims[].reasoning` | 为什么用它支撑结论 | **质疑方看不到这一栏**（信息隔离的关键） |
| `evidence[].name` | 一个**可指认的名字** | 「业内数据」「相关研究」不是证据，是无法指认的说法 |

**权限：无。** 主张方不能给自己的主张评级——那正是取证方的活。

### 质疑方（`challenger`）

**职责**：在每条主张上找一个**能站住的**漏洞，并说清是哪一类。

| 字段 | 要求 |
|---|---|
| `target` | 主张 id（`C1`…） |
| `quote` | 主张原句（锚到**主张**，不是材料） |
| `challenge_type` | 七选一：样本 / 因果 / 口径 / 时效 / 来源 / 范围 / 利益 |
| `severity` | 致命 / 重要 / 次要 |
| `reason` | 这条主张在这个类型上的漏洞**具体是什么**（不许是空话） |
| `required_fix` | 要补成什么样，这条主张才站得住 |
| `verdict` | `challenged`（成立）/ `passed`（挑不动） |
| `unable_reason` | `verdict=passed` 时必填：为什么挑不动 |
| `demand_retract` | 认为**必须撤回**（不是补正能救）时填 true |

**权限：能要求撤回。** `severity=致命` 或 `demand_retract=true` 的挑战，
裁决方必须正面处置（不许装作没看见——本地会检查）。

**信息隔离**（见第四节）：质疑方只看得到结论、主张原句、`claim_type`
与证据的**编号/名称/来源类型/时间**。看不到 `reasoning`，看不到 `coverage`。

### 取证方（`evidence`）

**职责**：给每条主张手里的那点东西评一个强度档位，并说清**为什么不是更高一档**。

| 字段 | 要求 |
|---|---|
| `claim_id` | 主张 id |
| `source_key` | **同一类证据必须用同一个 key**（本地按它核对尺子） |
| `strength` | 四档：强 / 中 / 弱 / 无据 |
| `confidence` | 0~1，作为强度的量化备注；与 `strength` 口径要一致 |
| `shape` | 落在形态表里的哪一档（见第三节） |
| `decisive_gap` | **决定性缺口**：为什么不是更高一档（不许空） |

**权限：无。** 它只评级，**不裁决**：不许写"建议撤回""可以保留"这类结论。

### 裁决方（`arbiter`）

**职责**：定可采信边界。

| 字段 | 要求 |
|---|---|
| `claim_id` | 主张 id |
| `decision` | 三档：可采信 / 降级表述 / 撤回 |
| `strength_seen` | 它看到的证据强度（本地会与本地的取档核对） |
| `basis` | 依据哪条挑战或哪条评级 |
| `basis_quote` | 判「可采信」时必填：材料里**原样**的一句（凭什么可采信） |
| `downgraded_wording` | 判「降级表述」或「撤回」时必填：**可直接替换进稿子**的更保守说法 |
| `how_to_use` | 这条替代表述怎么用（放哪一段、要不要配口径说明） |

**权限：终裁。** 但终裁有纪律（本地判）：

```
证据强度是「弱」或「无据」→ 不许判「可采信」
证据强度是「强」          → 不许判「撤回」（要撤回必须另给依据）
判「可采信」→ 不许带替代表述（自相矛盾）
```

同一主张有多条评级时，本地取**最低**那一档——裁决要按最弱的支撑来定，
不能挑对自己有利的那条。

## 三、挑战七类与证据形态表

### 挑战七类：每一类问一个不同的问题

| 类型 | 它的问法 | 典型形态 |
|---|---|---|
| **样本** | 这个样本能代表你想说的那个总体吗？ | 个案当规律；样本量没说；样本是自己筛的活跃用户；样本量下结论无法区分 |
| **因果** | 这是相关还是因果？ | 只有先后就断言因果；没排除同期其他因素；没做增量归因（蚕食效应） |
| **口径** | 这个数字是怎么算出来的？ | 分母没交代；是否含退款/取消/测试单没说；均值掩盖分布 |
| **时效** | 这份数据是什么时候的？ | 跨年预测没有底稿；市场条件已变；观察时点未写明 |
| **来源** | 凭什么信这个来源？ | 单一来源；二手转引无原始出处；来源本身有立场；无法核实 |
| **范围** | 这个结论能推多远？ | 局部推全体；单渠道推全平台；单一品类推全行业；一家竞品推"全行业没人做" |
| **利益** | 谁说这话谁受益？ | 自采自证；回访者与被访者存在利益关系；绩效与结论挂钩 |

**为什么必须指出类型**：类型是"这条挑战在问什么"的压缩。没有类型，
裁决方无法判断它属于"补正就能救"（口径 / 时效 / 来源）还是
"补正也救不回"（样本 / 因果 / 范围 / 利益）。本地对缺类型的挑战**标红**。

**真机实测的一次覆盖**：10 条主张用到了 样本 / 因果 / 口径 / 来源 / 范围 / 利益 六类，
**`时效` 没用上**——因为那份材料里确实没有时效类漏洞。这不扣分：
挑战类型是按需使用的清单，不是必须凑齐的指标。

### 证据形态表：**先判形态，再给档位**

```
单个案例 / 一次经历
单一来源（一个客户、一家供应商、一个渠道）
小样本自采（几十份以内、自己筛的样本）
二手转引（别人说的、没有原始出处）
行业公开报告（可核实到具体报告名与年份）
可核实的内部台账 / 平台后台数据（口径可交代）
多个独立来源互相印证
```

| 档位 | 判据 | 只能作什么表述 |
|---|---|---|
| **强** | 来源可核实、样本与口径交代清楚、结论不外推、时效在有效期内 | 可作一般性结论 |
| **中** | 方向可信但样本或口径有缺口 | **方向性**表述 |
| **弱** | 单一来源 / 单一个案 / 口径不明 / 时效存疑 | **假设**表述 |
| **无据** | 找不到实质依据，或依据只覆盖很小一部分却说成普遍结论 | 通常只能撤回 |

**为什么要把形态表钉进提示词**：不钉死，模型会凭"这条主张说得多确定"给分——
说得越斩钉截铁给得越高，正好与取证要问的问题相反。钉死形态表之后，
它必须先回答"这是哪一类证据"，再回答"这一类能撑到什么档"。

### 归一化：模型不按四档写怎么办

本地会把各种写法归一到四档，并**留下归一说明**（`strength_how`）：

1. 原样命中「强 / 中 / 弱 / 无据」→ `原样`
2. 以四档开头（「强，因为…」）→ 前缀归一
3. 认不出来但给了 `confidence`（0~1）→ 兜底映射：≥0.75 强 / ≥0.50 中 / ≥0.20 弱 / 其余无据
4. 两者都没有 → `未标注`，**标红**（不静默当"中"）

## 四、信息隔离：怎么实现、怎么验

### 实现：两样东西**故意不给**

`build_challenge_prompt()` 里只拼这些字段：

```
结论（claims.conclusion）
主张原句（claims.claims.text）
主张类型（claims.claims.claim_type）
证据的编号 / 名称 / 来源类型 / 时间（claims.evidence.id/name/source_type/timeframe）
```

**不给**：

| 不给的东西 | 为什么 |
|---|---|
| `claims[].reasoning` | 那是主张方的论证过程。看得到它，质疑方就会顺着别人的论证往下补，挑出来的都是措辞问题 |
| `evidence[].coverage` | 它泄露主张方自己承认的论证边界。质疑方的活是**自己**去找边界，不是复述别人的 |
| 其它角色的任何文字 | 质疑方不需要知道后面会怎么裁 |

### 验证：**不是"看一眼模板觉得没问题"**

`isolation_evidence()` 在本地做两件事：

```python
# 1) 把每条 reasoning 归一后切成 8 字窗口（头/中/尾最多 6 段），
#    逐段查它有没有出现在质疑方的提示词里
reasoning_fragments_found   # 必须为空
# 2) 把每条 evidence.coverage 归一后取前 12 字，查有没有泄漏
coverage_leaked             # 必须为空
```

为什么要切成多段而不是整条查：模型可能只抄了推理的半句；
为什么要归一：只改标点就能绕过纯字面比对。

真机实测：10 条推理全部核对，`reasoning_fragments_found = []`、`coverage_leaked = []`。

> **模板改一行就可能漏**，所以隔离必须用机器核，不能靠人工检查提示词模板。

## 五、为什么评级口径必须统一

### 问题长什么样

取证方最容易犯的错，是**同一类证据在不同主张上给不同档位**：

```
C1（同一个 18 人自采样本）→ 强
C2（同一个 18 人自采样本）→ 弱
```

那不是评级，是随手写的。用户无法知道该信哪一个，整份评级失去可用性。

### 本地判法：按 `source_key` 分组，看组内极差

```
同一 source_key 组内，四档映射成数值（强=3 中=2 弱=1 无据=0）
极差 > 1 档 → 判「评级口径不一致」，exit=3
极差 ≤ 1 档 → 放行
```

**为什么允许 1 档的差别**：同一来源在不同主张上确实可以有差别。同一个小样本：

- 支撑一条**窄结论**（"这 18 人里有 12 人自报每周复购"）→ 中
- 支撑一条**外推结论**（"产品整体复购率 67%"）→ 弱

这是**结论范围**的差别，不是尺子的差别。真机实测里那个 18 人样本正是这样评的：
C1（外推）弱、C2（抽样方式本身）弱、C3（谁做的回访）弱——
三条同 key、口径一致。

### 还有一条更基本：**取最低档**

同一主张有多条评级时（模型可能拆开评），本地取**最低**那一档给裁决方。
理由很直白：裁决要按**最弱的支撑**来定，不能挑对自己有利的那条。

## 六、为什么角色没有"最终决定权"，只有裁决方有

- 主张方只能提，不能自评
- 质疑方**能要求撤回**（这是一个真实的权力，裁决方必须正面处置）
- 取证方只能评级，不能裁决
- **裁决方是终裁**，但它的终裁被本地的追认门约束（弱/无据不许"可采信"）

这样安排的结果是：**四道工序的输出互为约束**，
而不是四个角色各说一段话然后由最后一个人总结。

---

## 七、本包明确的边界

1. **不联网检索**：证据在现实世界里是否真的存在，仍然要人来核。「强」不等于「真」。
2. **评级是启发式的**：形态表覆盖不到的证据形态会落到"未标注"并标红，需要人工定档。
3. **四道工序共用同一个模型**，隔离靠调用边界，不靠模型差异。
4. **取证质量取决于材料质量**：材料里没有可指认的证据名（只写"业内数据"）时，
   主张方列不出证据条目、取证方也无从评级——此时先回去把材料写实。
