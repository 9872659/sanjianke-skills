# 三剪客 · 调研取证小组

给一份**已有材料**里的**事实主张**做取证与对抗验证，产出**可采信边界**：

```
claims    →  主张方：结论 + 逐条支撑主张 + 编号证据清单
challenge →  质疑方：逐条挑战书（**必须指出挑战类型**），信息隔离
evidence  →  取证方：证据强度评级（强 / 中 / 弱 / 无据）
verdict   →  裁决方：可采信边界 + **降级表述**（可直接替换进稿子的说法）
run       →  一条命令跑完，断点续跑
log       →  读回动作流水：哪些主张被挑战掉、哪些被判必须降级
cost      →  只算 token，一次调用都不发
models    →  列出在架模型（免费）
```

它替代的是评审会上最耗人的那一步：不是"没人质疑"，而是
**"质疑提了一堆，但哪条主张真的站不住、站不住的话该怎么说，没人给得出可用的替代"**。

> ## 🚫 本包**不联网检索**（这条边界要说在最前面）
>
> 它**没有检索端点**，也不会去外部查证任何事实。整条流水线只调用两个接口：
> 大模型与在架模型清单。它做的是**本地推理与评级**：把「这句话凭什么被信」
> 拆开、摊平、判定强弱，并给出边界。
>
> **证据在现实世界里是否真的存在、数字是否真的对，仍然要人来核。**
> 不要把它当成事实核查服务——它是**取证流程的骨架**，不是数据库。

## ⚠️ 三层的分界：本包是 L3，而且是"取证式"那一种

### 先看 L1 / L2 / L3 的判据

| 层 | 形态 |
|---|---|
| **L1 单点生成型** | 一个输入 → 一个产出 |
| **L2 智能体型** | **单循环**：抽档 → 写 → 自检 → 迭代（一个声音自我迭代） |
| **L3 多智能体协作型** | **多角色分工互审**，一条命令出成品 |

L3 的关键**不是"调多次模型"**。判据是：

> **每个角色有自己独立的目标，且彼此的输出真的会改变最终结论。**

### 三方分界表（这一张表就够）

L3 已有多种形态：流水线式（`sanjianke-content-team`）、对抗评审式（`sanjianke-review-board`）、
剧组式（`sanjianke-drama-crew`）、教研式（`sanjianke-course-crew`）、小组式（`sanjianke-ecom-crew`）、
跨语言式（`sanjianke-localize-crew`）。本包是**第八种：取证式**。

最容易搞混的是 **L2 内容质量闭环** 与 **对抗评审**，所以单独列出来：

| | **`sanjianke-content-qc`**（L2 质量闭环） | **`sanjianke-review-board`**（对抗评审 L3） | **本包（取证式 L3）** |
|---|---|---|---|
| 审的是 | **文本质量** | **方案可行性** | **事实主张能不能站得住** |
| 一句话 | 这篇写得好不好，怎么改 | 这份东西该不该过 | 这句话凭什么被信、能被信到什么程度 |
| 角色关系 | 一个声音拿一张评分表自我迭代 | 四个**互相冲突的价值立场**（用户/竞品/合规/业务） | 同一条链的**四道工序**（提主张 → 打漏洞 → 评强度 → 定边界） |
| 核心机制 | 打分 → 重写 → 复评到收敛 | 先隔离后合流 + 分歧显性化 | **信息隔离 + 质疑必须成立 + 降级表述必须给** |
| 产出 | 定稿 + 评分轨迹 + 逐句台账 | 裁决书 + 条件清单 + 少数派意见 | **证据强度评级 + 可采信边界 + 降级表述** |
| 终止 | 分数过线 / 轮次用尽 | 出裁决（**不追求收敛**） | 出边界 |
| 核心闸门 | 未锚定率 / 改写丢事实 | **立场失效** | **质疑无效 / 降级缺失** |
| 能否互相替代 | 不能：它给的是"更好的文本" | 不能：它给的是"过不过" | 不能：它给的是"哪句能说、哪句怎么说" |

**三者的差别不是"换个评价维度"。**

- `content-qc` 的五个维度是**同一把尺子上的五个刻度**，服务于同一个目标，越迭代越**收敛**；
- `review-board` 的四席是**四个互相否掉对方的目标函数**，一旦收敛就说明立场没起作用；
- 本包的四道工序是**一条链**（缺一环就没有下游输入），它的价值不在"角色互相反对"，
  而在两件可以被本地实测的事：**质疑必须真的挑战掉一些主张**、
  **判不能采信的主张必须给得出可用的替代说法**。

> 反过来说：如果你要的是"这段话读起来怎么样"，用 `content-qc`；
> 要的是"这个方案该不该批"，用 `review-board`；
> 要的是"我们对外说的这几句，哪句撑得住"，才是本包。

## 四道工序

| 工序 | 目标 | 产出物 | 权限 |
|---|---|---|---|
| **主张方** | 把结论说清、给每条主张**指名**依据 | 主张清单 + 证据引用 | 无 |
| **质疑方** | 每条主张找一个**能站住的**漏洞 | 逐条挑战书（**必须指出挑战类型**） | **能要求撤回** |
| **取证方** | 给每条主张一个**能用一句话解释**的强度评级 | 证据强度评级（强/中/弱/无据） | 无 |
| **裁决方** | 定可采信边界 | 裁决 + **降级表述建议** | **终裁** |

**质疑类型七选一**（必须指出）：`样本` / `因果` / `口径` / `时效` / `来源` / `范围` / `利益`。

| 类型 | 它问的问题 |
|---|---|
| 样本 | 个案当规律？样本量没说？样本是自己筛的？ |
| 因果 | 只有相关就断言因果？把先后当因果？ |
| 口径 | 数字怎么算的没说？分母是什么？换口径结论会不会翻？ |
| 时效 | 数据是哪一年的？市场条件变了没有？ |
| 来源 | 单一来源？二手转引？来源本身有立场？无法核实？ |
| 范围 | 局部推全体？单渠道推全平台？单一品类推全行业？ |
| 利益 | 谁说这话谁受益？样本是不是自己筛的？有没有自证？ |

**证据强度四档**（取证方唯一可用）：`强` / `中` / `弱` / `无据`。
**裁定三档**（裁决方唯一可用）：`可采信` / `降级表述` / `撤回`。

## 机制：先隔离，再评级，最后给替代

### 1）claims：把"要被相信的东西"摊平

一条主张只讲一件事（可被单独挑战），每条主张必须标出**用了哪几条证据**，
每条证据落成编号条目（编号 / 名称 / 来源类型 / 时间 / 覆盖什么、没覆盖什么）。
主张方还要写 `reasoning`（为什么用这条主张支撑结论）——**这一栏质疑方看不到**。

### 2）challenge：**信息隔离**下的逐条挑战

质疑方拿到的只有：**结论 + 主张原句 + `claim_type` + 证据的编号/名称/来源类型/时间**。
拿不到：主张方的 `reasoning`、证据的 `coverage`、其它角色任何文字。

```json
"isolation": {
  "challenge": {
    "prompt_chars": 2512,
    "prompt_sha": "2cf1d37532069e01d21d3fef0db28ed99efa7be363a437cc93694c8e7ab0b46a",
    "reasoning_fragments_found": [],
    "coverage_leaked": [],
    "reasoning_checked": 10
  },
  "stage_inputs": {
    "challenge": ["claims.conclusion", "claims.claims.text",
                  "claims.claims.claim_type",
                  "claims.evidence.id/name/source_type/timeframe"]
  }
}
```

**为什么隔离必须是真的**：如果质疑方能读到主张方的推理，它会顺着别人的论证往下补，
挑出来的都是措辞问题，而不是主张本身站不站得住。

**隔离不是"看一眼模板觉得没问题"**：本地把每条 `reasoning` 切成片段，
逐一查它们有没有出现在质疑方的提示词里（`reasoning_fragments_found` 必须为空），
`coverage` 同样查（`coverage_leaked`）。模板改一行就可能漏，所以要用机器核。

每条挑战必须写：`challenge_type`（七选一）、`severity`、`reason`、`required_fix`、
`verdict`（`challenged` / `passed`）、`unable_reason`（放行时必填）、`demand_retract`。

### 3）evidence：按**形态表**给四档强度

不看"这条主张说得多确定"，只看"手里那点东西有多硬"。提示词里钉死一张形态表：

```
单个案例 / 一次经历
单一来源（一个客户、一家供应商、一个渠道）
小样本自采（几十份以内、自己筛的样本）
二手转引（别人说的、没有原始出处）
行业公开报告（可核实到具体报告名与年份）
可核实的内部台账 / 平台后台数据（口径可交代）
多个独立来源互相印证
```

每条还要给 `source_key`（同类证据必须同一个 key）与 `decisive_gap`（为什么不是更高一档）。

### 4）verdict：三档裁定 + **必给的替代表述**

```
可采信    原样可用（必须给 basis_quote，且不许带替代表述）
降级表述  换个更保守的说法（**必须给 downgraded_wording**）
撤回      不能用（**同样必须给替代表述**——写的是"要恢复这句话需要做到什么"）
```

**只删不给替代不是裁决，是毁稿。** 用户拿到裁决书之后要能直接改稿。

## 八道本地硬闸门

命中一律：**标红 + stderr 汇总 + 非 0 退出码**，全部确定性，跑两次结果一样，可直接进 CI。

| # | 闸门 | 判据 | 退出码 |
|---|---|---|---|
| 1 | 合规 | 违禁词；**「最X」两类豁免**（可度量断言如「订单量最高」不看句首；句中程度用法）+ **句首商品宣称照拦**；材料侧全档、产出侧只查高风险并排除「引用」与「提到」 | 3 |
| 2 | 占位符残留 | `{}` / `[待填]` / `XXX` / `（此处省略）` / **整段就是一个空档**（字段级判据，不误伤「…（均待补充）」这类正常说明） | 3 |
| 3 | `prompt_echo` | 去标点相等 / Jaccard ≥ 0.75 / 覆盖度 ≥ 0.60（**适用窗口**：长度比 ≤ 3.0 且示例 ≥ 8 字） | 3 |
| 4 | **锚点** | 主张引文 / 挑战引文 / 裁决依据三层各锚各的文本；未锚定率 > 40% 判「定位失败」 | 3 |
| 5 | **质疑有效性** | 一条挑战都没成立 → 判「质疑无效」；全部放行同样判无效 | 3 |
| 6 | **降级表述完整性** | 判「降级表述 / 撤回」却不给替代表述 / 替代表述与原句相似度 ≥ 0.90 / 引入新数字 | 3 |
| 7 | **评级口径一致性** | 同一 `source_key` 在不同主张上的评级极差 > 1 档 | 3 |
| 8 | **追认门** | 弱 / 无据的主张判「可采信」；或强证据判「撤回」 | 3 |
| — | 成本上限 | `--budget` 超限就地中止（**未发起调用**） | 5 |
| — | 产出不许进包 | `--outdir` / `--out` 落在 Skill 包内 | 2 |

### 第 5 道闸门：**不许把「全部放行」当「证据充分」**

本包最容易变成的一场表演：质疑方客客气气写一句"整体方向可信，建议补充一些数据"，
然后裁决方宣布"证据充分，全部可采信"——那不是取证，那是**盖章**。
这道闸门不看模型的自述，本地算：

- 一条挑战要算「成立」，必须**同时**满足：`verdict=challenged`，
  **且** `reason` 与 `required_fix` 归一后各 ≥ 8 字（空话不算）
- **成立数为 0 → 判「质疑无效」**，`exit=3`
- 所有主张的挑战结论都是 `passed`（全部放行）→ 同样判无效
- 挑战**没有指出类型** → 标红（本包要求挑战必须落在七类里）
- 被挑战成立的主张**没出现在裁决里** → 标红（不许装作没看见）

材料本身确实无争议时用 `--all-passed-ok` 把它降级为标红提示。

### 第 6 道闸门：**降级表述必须真的换了个说法**

判「不能采信」只给一个"删"字，用户拿到裁决书之后不知道那句该怎么说。
这道闸门同样在本地判：

```
判「降级表述」或「撤回」的主张，downgraded_wording 不能为空
替代表述与原主张的 min 归一相似度 ≥ 0.90 → 判「没换说法」（抄一遍不算降级）
替代表述里出现材料里没有的数字 → 拦（**降级表述不许编新数据**）
替代表述把原主张里的数字全丢了 → 标红（那是删除，不是降级）
判「可采信」却带替代表述 → 标红（判据自相矛盾）
```

> 相似度用 **min 归一**（较短那份有多少比例的内容出现在较长那份里），不用 Jaccard：
> 原主张一句话、替代表述可能要带口径说明，篇幅差一大，Jaccard 的分母是并集会被摊薄，
> "其实还是同一句话"反而测不出来。

### 第 7 道闸门：同一类证据必须用同一把尺子

取证方最容易犯的错：同一个来源，在一条主张上评「强」、在另一条上评「弱」。
那不是评级，是随手写的。本地按 `source_key` 分组核对，**组内极差 > 1 档即判口径不一致**。

极差 1 档以内放行——同一来源在不同主张上确实可以有差别
（同一个小样本支撑一条窄结论评「中」、支撑一条外推结论评「弱」，
那是**结论范围**的差别，不是尺子的差别）。

### 追认门：强度 → 裁定的逻辑底线

- 证据强度「弱」或「无据」的主张，**不许判「可采信」**
- 证据强度「强」的主张，**不许判「撤回」**（要撤回必须另给依据）
- 同一主张有多条评级时，本地取**最低**那一档——裁决要按最弱的支撑来定，
  不能挑对自己有利的那条

## 30 秒上手

```bash
# 1) 拿 Key（新用户有赠送点数）：到 https://api.a7w.cn/ 注册，创建一个 API Key
export A7W_API_KEY="<你的Key>"          # Windows: $env:A7W_API_KEY="<你的Key>"

# 2) 零成本先看两样：四道工序、报价
python3 scripts/run.py roles
python3 scripts/run.py cost --file 材料.md

# 3) 一条命令跑完
python3 scripts/run.py run --file 材料.md --outdir D:/crew --json --out D:/crew/run.json

# 4) 想先看提示词不花钱
python3 scripts/run.py claims --file 材料.md --dry-run
python3 scripts/run.py challenge --file 材料.md --claims D:/crew/claims.json --dry-run
```

**零依赖**：只要 Python 3.7+，不用 `pip install` 任何东西。
`scripts/a7w.py` 是所有 Skill 包共用的零依赖客户端
（我们靠 SHA256 校验各包副本是否一致），本包**逐字节没有改它**；
本包的业务逻辑全在 `scripts/run.py` 里。

## 产出目录长这样

```
D:/crew/
├── brief.md / brief.json          材料索引（大纲 / 数字 / 专名 / 本地预扫）——零调用
├── claims.md / claims.json        主张清单 + 证据清单 + 锚点校验
├── challenge.md / challenge.json  质疑书 + **信息隔离证据**
├── evidence.md / evidence.json    证据强度评级 + 按 source_key 的分组核对
├── verdict.md / verdict.json      **可采信边界**：裁定 + 降级表述 + 裁决理由
├── REPORT.md                      总报告（四道工序 + 八道闸门 + token）
├── log.json                       动作流水（每条挑战、每条裁定一条记录）
└── state.json                     断点文件（重跑不重复扣费）
```

产出**一律落在包外**的 `--outdir` 里。包内只允许
`.md .py .txt .json .sh .js .yaml .yml .csv` 这几种后缀；`--outdir` 指到包内直接 `exit=2`。

**同一个 `--outdir` 重跑只会打印「断点命中，跳过」，0 次调用。**
断点 key 里含材料摘要与字符数、模型、温度、角色组合、三套口径版本，
以及上一阶段产物的摘要——少一个就会出现"改了参数却复用旧产物"。

另有一条零成本路径 `--replay`：`run --replay <已有产物目录>` 只用存下来的
`claims.json / challenge.json / evidence.json / verdict.json` 重跑本地闸门与报告，
**一次调用都不发**。它会**重新做一遍锚点与本地判定**（不直接信文件里存好的结论），
所以手工改过的产物绕不过闸门。

## 真机实测（跑出来的，不是估算）

材料是一份 **324 字符的自撰材料**（为实测专门写的虚构团购复盘，含 10 条可质疑主张，
标明来源），模型 `deepseek-chat`。

| 项目 | 实测值 |
|---|---|
| 调用 | **4 次**：主张方 1 + 质疑方 1 + 取证方 1 + 裁决方 1 |
| token | prompt **9,568** + completion **8,928** = **18,496** |
| 耗时 | 约 45 秒（9.3s + 15.2s + 7.2s + 12.6s） |
| `finish_reason` | 四次全部 `stop`；上游模型 `deepseek-flash` |
| 主张 | **10 条**，引文锚定 26/30（未锚定率 13.3%，阈值 40%） |
| **挑战** | 记录 **10 条**，其中**挑战成立 10 条**、放行 0 条 |
| 挑战类型 | 样本 / 因果 / 口径 / 来源 / 范围 / 利益——**`时效` 没用上**（材料里确实没这类漏洞，如实记录） |
| 证据强度 | 弱 ×7、中 ×2、无据 ×1；按 `source_key` 分组核对**口径一致** |
| **裁定** | 降级表述 **7 条** + 撤回 **3 条** |
| **降级表述** | **10 条**（判「不能采信」的全部给了替代表述） |
| 信息隔离 | 质疑方提示词 2,512 字符；本地核对 10 条推理，**`reasoning` 片段命中 0**、`coverage` 未泄漏 |
| 闸门 | 十项里**闸门六命中 1 项**（C4 的替代表述相似度 0.95），另两处标红；其余通过 |

### 是假质疑还是真质疑？——直接回答

**质疑方真的挑战掉了主张。** 10 条主张、10 条挑战，**成立 10 条、放行 0 条**，
而且每条都指出了具体的挑战类型：

```text
C1 样本  致命  18 人且全部来自核心社群活跃老客 = 极端非概率样本；
                用 12/18 冒充「产品整体复购率」，分母与目标人群不是一回事
C2 来源  重要  抽样名单由运营自己拟定、自己执行、自己记录，外部无法复核
C3 利益  重要  回访者与被访者有服务关系、绩效与「产品成立」挂钩 = 自采自证
C4 口径  重要  4200 单是否含取消/退款/刷单/测试/0 元赠单、客单价分母是谁，全没交代
C5 口径  重要  466 是 4200÷3÷3 的算术均值，三城体量悬殊时「典型城市」不存在
C6 因果  致命  订单量是绝对量，缺曝光/访问分母就谈不了转化；以相关当因果
C7 因果  重要  未排除季节性、大促、其他 SKU 调整、低基数效应
C8 因果  致命  「带动」是因果断言，但没做增量归因、没排除蚕食效应
C9 来源  致命  300 万营收无假设、无公式、无出处，无法复核
C10 范围 致命  一家竞品「没做」被外推成「全行业只有我们走得通」
```

**裁决不是简单删掉。** 10 条里 7 条给的是可直接替换进稿子的替代表述：

| 原主张 | 裁定的替代表述 |
|---|---|
| 复购率 67%（12/18 自报） | 「在 18 位来自核心社群的活跃老客回访中，有 12 位自述每周至少复购一次；该结果仅代表核心社群活跃老客的自我陈述复购意愿，不代表产品整体复购率。」 |
| 华南区订单量最高，说明南方转化更好 | 「华南区订单绝对量在三个区域中最高，其原因（门店数、投放、上线时长或人群偏好等）尚待进一步验证，不能据此判断南方转化更好。」 |
| 竞品没做，证明只有我们走得通 | 「截至观察日，在已观察渠道内未见竞品上线小程序团购；该模式是否具备排他性尚需对多家竞品渠道进行系统性排查并给出壁垒证据。」 |

**闸门六那一处命中是真命中，不是误报。** 裁决方给 C4 的替代表述是
「上线三个月，三个城市后台累计订单 4200 单、客单价 38 元（统计窗口起止日、
是否剔除取消/退款/测试单、客单价计算口径均待补充）」——它把**口径缺口**贴了上去，
但**主张本身该怎么改还没说**，与原文相似度 0.95。本地判「没换说法」，属真命中。

## 实测踩到并修掉的三类误报（如实记录）

闸门的第一版在真机上误报了三处，都是**取证文书的正常写法**：

| 误报 | 为什么是正常写法 | 处置 |
|---|---|---|
| 「华南区订单量**最高**」 | 可度量的指标比较陈述，不是商品宣称 | 新增第二类豁免：**度量名词 + 最X + 标点**（不看句首）；同时保留边界——「最高品质」「效果最好」照拦 |
| 「…（均**待补充**）」 | 这是裁决在**说明口径缺口**，是正常交付物 | 占位符判据拆成两份：段落级只认空档本身；字段级认「整栏就是一个空档」 |
| 「本包必须保证过审」 | 这是**反向用例**——它就该被拦 | 保留：产出侧仍然拦「评审自己造违规宣称」（自测用例 12 覆盖） |

修法的原则跟全族一致：**把口径写清楚、把两类正常写法显式排除，并且不静默丢弃**
（被豁免的条目带 `exempt_rule`、被排除的带 `not_counted_reason`，全部留在产物里可复查）。

### 自测时还抓到一个真 bug：回放之后断点不命中

`--replay` 用它自己的 `--outdir` 时，第一版**没有把规范产物写下来**，
于是"回放一遍看看闸门"之后再正常跑一次，断点全部不命中，**又付了 4 次调用的钱**。
现在回放与正常跑写的是同一份 `_pack_*` 结构，并用 `_resume_key` 做双算兜底
（先按当下产物算 key，不命中再按上一份产物算一次），自测用例 14 覆盖：
回放之后正常跑 → **四个阶段全部断点命中、0 次调用、exit=0**。
