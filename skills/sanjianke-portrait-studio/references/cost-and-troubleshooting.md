# 计费口径、实测数据与排错

> 本文件里的每个数字都是三剪客团队**真机跑过、对过账**的，不是从平台文档里抄的。
> 平台文档里有若干字段与实测不符，本文逐条标出「以什么为准」。

## 一、结算口径：只信 `usage.points_cost`

### 实测记录（本包真机出图）

```json
{
  "code": 1,
  "msg": "success",
  "data": {
    "task_id": "task_6f23b15cc63097a9e3ad260e",
    "status": "completed",
    "result": { "…": "…" },
    "usage": { "input_tokens": 0, "output_tokens": 0, "total_tokens": 0, "points_cost": 24 }
  }
}
```

| 项 | 实测值 | 说明 |
|---|---|---|
| `usage.points_cost` | **24**（1K 出图，单张） | **这才是最终扣费**，结算只认它 |
| 提交时 `frozen_points` | **31.2** | **预冻结**，比实扣高 30%，**不是最终扣费** |
| 充值比例 | 1 元 = 100 点 | 所以 1K 单张 = 0.24 元 |
| 失败 | 全额退回 | 冻结的点数会回来 |

### 平台字段里哪些不可信

| 字段 | 问题 | 我们怎么处置 |
|---|---|---|
| `pricing_matrix` | 验证过半数与实扣不符（`image_human` 写 1.5/2/4/8 点/秒、实测 2/3/6/12；`voice_tts/stt` 写 30、实扣 40） | **只当参考**，不写进结算口径 |
| `tenant_fixed_points` / `tenant_*` | 同上，租户配置与最终快照可能不一致 | 同上 |
| `frozen_points` | 是预冻结，不是结算（31.2 vs 24） | 只用来判断「有没有提交成功」 |
| 任务返回里的比例 / 尺寸字段 | 与真实像素不一致（见 `platform-specs.md`） | **读文件头真实像素**，不信自报值 |

### 单价的实测边界（重要）

| 档位 | 单价 | 依据 |
|---|---|---|
| `1K` | **24 点/张** | 本包与同族包多次真机实测 |
| `2K` / `4K` | **没有实测** | `cost` / `gen` 会**拒绝估算并退出 3**，除非显式给 `--points-per-image` |

**为什么宁可拒绝也不给个数**：2K/4K 的官方档按分辨率分档计费（平台文档写「35.76 点/次起」、
「61.52 点/次起」，但那是文档值，我们没跑过）。给一个没实测的数写进成本前置，
等于把「成本前置」变成「成本估算游戏」——超预算时用户会以为闸门坏了。
想估 2K 就自己给单价：

```bash
python3 scripts/run.py cost --count 6 --resolution 2K --points-per-image 40
```

## 二、成本前置与逐张复核

成本闸门是**两层**，缺一层都不够：

1. **提交前**：先把整批总价算出来，超 `--budget` 直接停，**一个任务都不提交**。
2. **逐张提交前再核一次**：前面的真实扣费可能比预估高，一旦「已花 + 待花」超预算就**就地停**，
   已完成的图与断点都保留。

第一层只能保证「开头不超」，真正兜住预算的是第二层。

## 三、断点续跑（异步任务会失败，不能重复扣费）

出图是**异步 + 按次扣费**的：一次网络抖动、一次 Ctrl+C，都会让「已经提交并冻结了点数」
的任务悬在那里。没有断点记录，重跑就会把同一张图再买一遍。

每张图提交前先落一条 `pending`（带 `task_id`），完成后再写 `completed` + `points_cost`。
重跑时：

| 上一轮状态 | 重跑行为 | 花不花钱 |
|---|---|---|
| `completed` | 直接跳过，并把上次真实扣费累计进来 | **不花** |
| `pending` | 用 `task_id` **续查**，而不是重新提交 | **不花** |
| 没有记录 | 正常提交 | 花 |
| 提示词改了 | 断点 key 变了，被当成新的一项 → 重出 | 花（这是设计如此） |

```
[1/2] #1 已完成，跳过（上次扣费 24.0 点，不再重复扣）
[2/2] #2 发现未完成的 task_id=task_xxx，续查而不重新提交
```

断点文件默认在 `<outdir>/portrait-studio-state.json`，可用 `--state` 换位置。

## 四、对账：`--report`

`gen --report evidence.json` 会把本次证据逐张写成 JSON，字段用途如下：

| 字段 | 内容 | 对账用途 |
|---|---|---|
| `request` | 实际发给上游的请求体原文 | 证明「我请求的是什么」 |
| `raw_task` | 任务查询接口的完整原始返回 | 证明「上游回了什么」，含 `code` / `msg` / `usage` |
| `first_check` | **裁剪前**的真实像素、比例标签、偏差、判定 | 证明「上游原始给了什么像素」 |
| `snap` | 裁剪方式、裁剪框、裁后复核结果 | 证明「裁准了多少」；`method: null` 就是没裁成 |
| `points_cost` | 该张的实际扣费 | 与账单逐张对上 |
| `points_cost_this_run` / `yuan_this_run` | 本次实际花费（点 / 元） | 快速确认「这一轮花了多少」 |

> **注意**：`first_check` 与 `snap.after` 是两份**不同的**证据。
> 裁剪之后不要拿裁后结果冒充「上游原始产出」——本包把两者都留着，就是为了这个。

## 五、退出码

| 退出码 | 含义 |
|---|---|
| `0` | 全部成功且闸门全绿 |
| `2` | 调用失败 / 配置不合法（网络、鉴权、点数、模型名、**`--outdir` 指到包内**） |
| `3` | **闸门拦下**：人物合规、未成年人、恶俗/违背物理、违禁词、照抄示例、比例不符、超预算、无实测单价 |
| `4` | 需要 `--yes` 确认（还没花钱，也没提交） |
| `5` | 达到 `--max-seconds` 上限中断（可续跑） |
| `130` | 用户中断（Ctrl+C） |

闸门执行顺序（前面拦下就不往后走）：

```
--outdir 合法性（2）
  → 提示词闸门：人物合规 / 恶俗 / 违禁词 / 照抄 / 占位符（3）
    → 成本上限（3）
      → --yes 确认（4）
        → 提交 → 轮询 → 下载 → 比例真伪（3）
```

## 六、排错表

| 现象 / 报错 | 原因 | 怎么办 |
|---|---|---|
| `鉴权失败（401）` | Key 无效、过期或写错 | 到 https://api.a7w.cn/ 重新领取；确认没把 `Bearer` 重复写进环境变量 |
| 点数不足（HTTP 402） | 账号点数用完 | 到 https://api.a7w.cn/ 充值后重试 |
| `code: 0` 但 HTTP 是 200 | **网关信封里 `code == 1` 才是成功，不是 0** | 看 body 里的 `msg`；脚本已按这个口径判断，别改成 `code == 0` |
| 轮询一直读不到状态、最后超时 | **`status` 在 `data` 顶层，不在 `data.result` 里**（平台文档写错） | 脚本已按实测结构取；别看文档改回去 |
| `当前请求未命中可用计费规格` | `model` 与 `resolution` 组合不支持（如普通模型传 `2K`） | 普通 `nano-banana` 只支持 `1K`；要高清档换 `nano-banana-2:official` 之类 |
| 上游 `502` / `upstream timeout` | 网关到上游的瞬时抖动，**实测很频繁** | 脚本已内置退避重试（4 次）。连续失败就换模型或降低批次 |
| 轮询一直 `processing` | 任务卡住了 | 已设 `--poll-timeout`（默认 600 秒）上限；超时会报出来并保留 `task_id`，可 `python scripts/a7w.py task <task_id>` 续查 |
| 图片真实像素和请求比例差 1%~3% | **上游按 32 对齐**，不是 bug | 加 `--snap` 精确裁；或放宽 `--ratio-tolerance` |
| `预估 N 点超过预算上限` | 超了 `--budget` | 提高预算、减少张数，或先 `cost` 试算 |
| `2K 档没有实测单价，拒绝凭猜估算` | 我们没有 2K/4K 的实测价 | 给 `--points-per-image` 指定单价，或先用 1K 出 |
| `输出目录 ... 在 Skill 包内`（退出码 2） | `--outdir` 指到了包里的目录 | 换到包外（`./out`、`%TEMP%\...`）。包内放图片会让上传失败 |
| `提示词命中闸门 ... 已拦截，未提交任何任务` | 人物合规 / 未成年 / 恶俗 / 违禁词 / 照抄示例 / 占位符残留 | 改提示词后重跑；确实要带违禁词才加 `--allow-prompt-hits`（人物合规与未成年人不建议绕过） |
| `action=edit 需要参考图 URL` | 图生图没给 `--photo-url` | 加 `--photo-url`；**上游只接受公网 HTTP/HTTPS 地址，没有本地上传接口** |
| `读不出真实像素` | 下载被截断，或不是图片 | 删掉那条断点记录重出（`--force`），或检查网络 |
| 重跑又扣了一次钱 | 提示词改了 → 断点 key 变了，被当成新的一项 | 设计如此（改了提示词就该重画）。想省钱就别改提示词，直接重跑即可跳过 |
| `没有找到 API Key` | 三种方式都没配 | `--key` / `A7W_API_KEY` / `python scripts/a7w.py login --key sk-xxx` |
| Windows 下中文乱码 | 控制台不是 UTF-8 | 脚本已尝试把 stdout/stderr 掰到 UTF-8；仍乱码就 `chcp 65001` 或设 `PYTHONIOENCODING=utf-8` |

**收集排错信息时请附上**：完整命令、`plan` 的输出、`--report` 产出的证据 JSON、原始报错文本。
**不要在报错信息或截图里带上你的 API Key。**

## 七、端点速查

算力集市（api.a7w.cn）的出图是**两步异步任务**：

| 用途 | 方法与路径 |
|---|---|
| 提交出图任务 | `POST https://api.a7w.cn/api/v1/apps/nano_banana/submit` |
| 查任务结果（本包用它） | `GET https://api.a7w.cn/api/v1/tasks/<task_id>` |
| 查任务结果（应用级，备用） | `POST https://api.a7w.cn/api/v1/apps/nano_banana/query` |
| 看该应用的接口与参数 | `GET https://api.a7w.cn/api/v1/apps/nano_banana` |
| 在架应用清单 | `GET https://api.a7w.cn/api/v1/apps` |
| 在架模型清单 | `GET https://api.a7w.cn/api/v1/models` |

**没有 `/generate` 这个端点。**「文生图」是 `submit` 的 `action=generate` **参数**，
不是独立的 api 路径。「图生图」是 `action=edit` 参数 + `image_urls`。

`submit` 的参数名（用 `python scripts/a7w.py schema nano_banana` 实查，别猜）：

```
prompt / action(generate|edit) / resolution(1K|2K|4K) / aspect_ratio / image_urls / model / callback_url
```
