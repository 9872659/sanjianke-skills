# 三剪客 · 商城前台 Vue3 源码

你手上有一个商城后端（商品、购物车、下单、支付、订单接口都有了），但缺一个能直接用手机打开的买家端页面。它就是这个买家端：用 Vue 3 写的移动端商城前台，包含首页商品流、分类、搜索、商品详情、购物车、下单结算、地址管理、订单列表与个人中心这一整套页面，一套代码同时适配手机浏览器与微信内置浏览器。

它的用法是「拿来改」而不是「拿来运营」：代码结构清晰、页面齐全，适合当作自研 H5 商城或小程序内嵌商城的起点，把接口地址指到你自己的后端，再按品牌改视觉与页面。不适合期待装完就能卖货的人——它只是前台，商品和订单数据全靠后端提供。

**上游项目**：`newbee-mall-vue3-app`　**仓库**：https://github.com/newbee-ltd/newbee-mall-vue3-app

## 什么时候用 / 不用

**用它**：

- 已经有商城后端接口，缺一个移动端买家前台，要快速拿到一套完整的 Vue 3 页面。
- 要自研 H5 商城或给小程序做内嵌页面，需要一个工程化、可分模块改造的起点。
- 想学一个完整电商前端的工程结构：路由、状态管理、请求封装、组件拆分怎么组织。
- 需要一套现成的购物车、结算、地址、订单页面来改视觉、换品牌。
- 做前端与后端接口联调，需要一个能跑起来的真实页面做对照。

**不要用它**：

- 没有后端接口、也不打算搭后端——它自己不含任何商品与订单数据。
- 想要开箱即用的 SaaS 店铺或拖拽装修的系统，它是要写代码改的源码。
- 需要一套面向 PC 桌面端的商城前台，它是按移动端 H5 设计的。
- 团队不做前端工程、不接受 Node.js 构建链路；它的部署离不开打包产物。
- 只想改改文字图片就上线：接口域名、支付、登录态都要与你的后端对齐后才能跑通。

## 安装

前提：Node.js 与 npm（用哪个版本以项目 `package.json` 的 `engines` 字段和仓库说明为准，别拿最新版硬套）。

```bash
# 1. 取源码
git clone https://github.com/newbee-ltd/newbee-mall-vue3-app.git

# 2. 进目录装依赖
cd newbee-mall-vue3-app
npm install

# 3. 起本地开发服务（端口以终端输出为准）
npm run serve
```

打包上线：

```bash
npm run build
```

构建产物在项目约定的输出目录里（通常是 `dist/`），把它交给 Nginx 或任意静态站点服务托管即可。

如果习惯用 Yarn 或 pnpm，把 `npm install` 换成对应命令即可，其余脚本不变：

```bash
yarn install && yarn serve
# 或
pnpm install && pnpm serve
```

**接口地址要先改**：项目通过环境变量文件（形如 `.env` / `.env.development` / `.env.production`）与请求封装配置后端地址。请在项目内确认实际的变量名与请求库配置文件位置，再把它指向你自己的商城后端；变量名以仓库里的环境变量文件为准，不要凭猜测填写。

## 常用操作

**1. 起本地开发服务**（改代码热更新）

```bash
npm run serve
```

**2. 打包生产产物**

```bash
npm run build
```

**3. 本地预览打包结果**（确认构建产物能正常跑）

```bash
npx serve -s dist
```

**4. 查看项目实际定义的脚本与依赖版本**（排查命令对不上时先看它）

```bash
npm run
```

```bash
node -p "require('./package.json').scripts"
```

**5. 查当前 Node / npm 版本**（构建报错时第一步要确认的）

```bash
node -v
npm -v
```

**6. 启动前清理依赖重装**（依赖装坏或版本冲突时）

```bash
rm -rf node_modules package-lock.json && npm install
```

> 上面脚本名取自这类 Vue CLI 工程的通用约定；若 `npm run serve` 报错说脚本不存在，用第 4 条命令看项目真实的脚本名再执行。

## 常见坑

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 页面能开但商品列表空白 | 后端地址没配，或后端没启动，请求全失败 | 先确认后端在跑，再把环境变量里的接口地址指到正确的域名与端口 |
| 请求全部 404 | 接口路径前缀写错，或后端部署在子路径下没配对 | 对照后端真实路由调整前缀；子路径部署要在构建配置里处理公共路径 |
| 浏览器控制台报跨域（CORS） | 前端域与后端域不同，后端没放行 | 开发阶段用构建工具的代理，生产环境由后端允许来源或同域反向代理 |
| `npm install` 装不上 / 一堆 peer 冲突 | Node 版本与项目要求不匹配，或依赖锁文件与本地环境冲突 | 按 `package.json` 的要求切换 Node 版本；必要时删掉 `node_modules` 与锁文件重装 |
| `npm run serve` 报脚本不存在 | 项目实际脚本名与预期不同 | 用 `npm run` 或读 `package.json` 的 `scripts` 确认真实脚本名 |
| 打包成功但刷新子路由 404 | 静态服务器没配 history 回退到 `index.html` | 在 Nginx 等服务器上加 fallback 到 `index.html`，或改用 hash 路由 |
| 部署后静态资源 404 | 公共路径（publicPath / base）没按部署目录设置 | 按部署的实际路径调整构建配置，重新打包 |
| 登录后刷新就掉登录态 | 登录态存的是内存变量，没落到本地存储 | 检查登录态与 token 的持久化逻辑，按需改为本地存储并处理过期 |
| 手机上样式错位 | 移动端适配方案（rem / viewport）与设计稿基准不一致 | 确认适配脚本已引入且缩放基准与设计稿一致，再对页面逐个核对 |
| 购物车数量与后端不一致 | 前端本地改了数量但没同步接口，或没重新拉取 | 改数量后调用后端接口，并在页面回到前台时重新拉取购物车 |
| 微信里能开但支付走不通 | 微信内支付需要后端配合签名与授权域名 | 支付签名与授权域名在后端与公众号/开放平台配置，前端只负责调起 |
| 构建产物很大、首屏慢 | 依赖全量打包、路由没做懒加载、图片没压缩 | 开路由懒加载、按需引入组件库、压缩图片，并对产物做体积分析 |

## 能力边界

**覆盖**：

- 本地跑通这套 Vue 3 移动端前台的完整路径：取源码 → 装依赖 → 起服务 → 打包。
- 前端工程的关键配置点：接口地址、代理、公共路径、路由回退、移动端适配。
- 页面范围：首页、分类、搜索、商品详情、购物车、下单结算、地址、订单、个人中心。
- 常见问题的定位方向（空白页、404、跨域、构建失败、刷新 404、样式错位）。
- 把它接到自有多端后端的改造起点（改接口地址、改请求封装、换视觉）。

**不覆盖**：

- 不含后端：商品、库存、订单、支付逻辑必须由你自己的服务提供。
- 不含微信支付、支付宝等支付通道的开通与签名实现，这些在后端与平台侧配置。
- 不保证各页面接口字段与你的后端一致，字段映射需要自己对齐。
- 不提供 PC 端商城前台或后台管理系统。
- 不覆盖具体上线运维（CDN、HTTPS 证书、灰度发布），取决于你的托管方案。

## 依赖条件

- Node.js 与 npm（或 Yarn / pnpm）；具体版本要求以项目 `package.json` 的 `engines` 与仓库说明为准。
- 一个可访问的商城后端服务，提供商品、购物车、订单等接口。
- 构建产物需要一个静态站点服务器（如 Nginx）托管，并配置路由回退。
- 若要在微信内使用，需要相应的公众号 / 开放平台配置与后端签名支持。
- 无需任何模型服务与密钥；它是纯前端工程。

## 已知限制

- 它是前端源码，没有配套后端就无法展示任何真实数据。
- 接口字段与路径需要与你的后端逐一对齐，联调工作量取决于后端差异。
- 面向移动端 H5 设计，直接投到 PC 大屏上布局不会理想。
- 依赖生态会随时间变化，长期不更新依赖可能遇到构建告警与安全告警。
- 视觉与品牌改动属于设计工作，工具只提供结构与页面骨架。
