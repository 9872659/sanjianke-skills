# 三剪客 · 微信小程序商城前端模板

一套可以直接导入微信开发者工具的**小程序商城前端**：首页、分类、商品详情、购物车、下单、订单与售后、优惠券、拼团与秒杀、地址与收藏这些页面都已经成型。它自带的是一层接口 SDK，数据来自你配置的后台服务，所以「换个店名就开张」这件事不用从零写页面。

**上游项目**：`wechat-app-mall`　**仓库**：https://github.com/EastWorld/wechat-app-mall

## 什么时候用 / 不用

**用它**：

- 「我要一个微信小程序商城的前端，商品和订单的后台我已经有了」——它负责页面与接口对接，不负责后端。
- 「想拿一套成熟的微店模板改改，两天内出可提交审核的版本」——页面、组件、图标、分包目录都是齐的。
- 「我要在小程序里加拼团、秒杀、优惠券、直播带货这些玩法」——模板里已有对应入口，按后台配置打开即可。
- 「客户是小门店，不需要我维护服务器，只要前端」——配合现成的小程序后端服务最省事。
- 「我要把现有店铺换一套皮，但保留原来的后端和商品数据」——模板与后台数据是分离的，换前端不会动数据。

**不要用它**：

- 想自己搭后端数据库、自己写一套商品与订单接口：这套前端只对接它约定的服务端接口，改造成本比重写还高。
- 需要 App 或 H5 版本：这里是小程序代码，跨端要另找对应版本的项目。
- 团队完全不懂小程序开发、也不打算用微信开发者工具：代码交付后没人能调试和提交审核。
- 想把别人的商品图、文案直接搬过来上架：版权与平台合规风险，工具不解决这个问题。
- 需要平台级深度定制（例如自建多商户结算体系）：前端模板只到页面层，结算与分账在服务端。

## 安装

它是小程序项目，没有需要编译安装的服务端组件。最小前置条件只有一个：**微信开发者工具**（从微信官方下载页获取）。

步骤：

1. 取到代码（克隆或直接下载压缩包解压）：

```bash
git clone https://github.com/EastWorld/wechat-app-mall.git
```

2. 打开微信开发者工具，选择「导入项目」，目录选到**仓库根目录**（`project.config.json` 所在的那一层），编译类型是 `miniprogram`。

3. 把 `project.config.json` 里的 `appid` 换成你自己小程序的 AppID。

4. 填自己的后端配置。`config.js` 里至少有这两个值：

```js
// config.js（只贴需要你改的字段）
module.exports = {
  version: '26.8.31',   // 前端版本号，自行维护
  subDomain: 'tz',      // 改成你自己的专属域名（后台分配，不是 https 地址）
  merchantId: 951,      // 改成你自己的商户 ID
  bindSeller: false,    // 是否开启分销抢客
  customerServiceType: 'QW', // 客服类型
  openIdAutoRegister: true,
  couponUseMultiple: true,
}
```

`subDomain` 与 `merchantId` 的取值来自后台的商户信息页；具体在哪查、专属域名怎么开，以该后台的说明文档为准。

5. 本地调试时在开发者工具里勾选「不校验合法域名、web-view（业务域名）、TLS 版本以及 HTTPS 证书」；正式发布前必须在微信公众平台把接口域名加进服务器域名白名单，并**取消**该勾选。

6. 首次编译前确认 `miniprogram_npm/` 目录在仓库里（仓库已经带上了构建产物）。若你改动了 `package.json` 依赖，需要在开发者工具里执行「构建 npm」重新生成该目录：

```bash
npm install
```

依赖清单（照仓库 `package.json`）：`@vant/weapp`、`apifm-wxapi`、`dayjs`、`mp-html`、`wxa-plugin-canvas`、`wxbarcode`。

## 常用操作

```bash
# 1) 取代码并查看当前前端版本号（发版时自己往上改）
git clone https://github.com/EastWorld/wechat-app-mall.git
grep -n "version" config.js

# 2) 只有改了依赖时才需要重新装依赖并构建 npm（然后在开发者工具点「构建 npm」）
npm install

# 3) 确认接口 SDK 与后端基础地址是怎么初始化的（排「接口 404 / 域名不对」时先看这里）
grep -rn "WXAPI.init\|setMerchantId\|subDomain" app.js config.js utils/

# 4) 确认页面清单与分包边界（改导航、加页面从这里入手）
cat app.json

# 5) 定位某个业务用的是哪个接口（例如购物车）
grep -rn "cart/" config/api.js pages/cart/
```

改完代码后的发布动作在开发者工具里完成：上传代码 → 微信公众平台提交审核 → 审核通过后发布新版本。用户不需要重新扫码，关闭小程序再打开即是最新版本。

## 常见坑

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 打开就是别人的演示数据 | `config.js` 里的 `subDomain` / `merchantId` 还是示例值 | 换成自己后台的专属域名与商户 ID，重新编译 |
| 一直提示无法登录、接口报错 | 没填商户 ID，或专属域名填成了带 `https://` 的完整地址 | `subDomain` 填后台给的域名标识而不是 URL；确认 `merchantId` 是数字且正确 |
| 真机预览接口全失败，开发工具里却正常 | 开发工具勾了「不校验合法域名」，手机上不生效 | 到微信公众平台把接口域名加进服务器域名白名单，并配好 HTTPS 证书 |
| 提交审核被打回说类目或资质不符 | 小程序类目没选对，或缺少经营资质 | 按实际经营内容选类目并上传资质；上线前补齐隐私政策与用户协议 |
| 打包上传提示体积超限 | 主包太大 | 把非核心页面继续往 `packageStreamMedia` 这类分包里放，图片改走 CDN 或对象存储 |
| 支付点了没反应 | 微信支付没开通或商户配置没填 | 在后台配置支付参数并把商户号与小程序的绑定关系打通；未开通时先用货到付款流程测试 |
| 富文本详情显示异常 | 渲染组件的用法或版本变了 | 检查 `mp-html` 的使用方式，按它当前版本文档调整 |
| 构建 npm 后组件找不到 | `miniprogram_npm` 没重新生成，或构建目录配错 | 在开发者工具里重新执行「构建 npm」，确认生成的目录与 `app.json` 引用一致 |
| 改了商品文案但小程序没变 | 商品和配置存在后台，不在代码里 | 到后台改商品与系统参数；小程序启动时会批量拉取配置项，确认对应 key 已配置 |
| 上传成功但线上还是旧界面 | 审核通过后没有点「发布」 | 回到微信公众平台发布新版本，再关闭小程序重开验证 |
| 用了仓库里的示例 AppID 导致上传失败 | AppID 不是自己的 | 换成自己小程序的 AppID，并确认当前微信号是该小程序的开发者 |
| 换了一套前端后担心数据丢 | 担心代码与后台数据绑在一起 | 前端与后台数据是独立的，覆盖代码不影响后台商品与订单；升级前仍建议备份当前代码目录 |

## 能力边界

**覆盖**：

- 从零导入到本地跑通的完整路径：导入目录、换 AppID、填专属域名与商户 ID、编译预览。
- 调试期与发布期在域名校验上的差别，以及发布动作的先后顺序（上传 → 审核 → 发布）。
- 页面与分包结构的定位方法，以及依赖变更后重新构建 npm 的操作。
- 换皮与换后端配置的边界：哪些在代码里改、哪些必须去后台改。
- 常见故障的定位顺序（配置值 → 域名白名单 → 依赖构建 → 后台数据）。

**不覆盖**：

- 后端服务的搭建与运维，商品、订单、库存、优惠券的业务数据维护。
- 微信支付、直播带货、客服等能力的开通、签约与资质审核。
- 小程序类目选择、备案、隐私政策文本的合规审核。
- 从零开发原生小程序组件或从别的框架迁移过来的改造工作。

## 依赖条件

- 微信开发者工具（本地调试与上传都通过它完成）。
- 一个已注册的小程序 AppID，以及该小程序的开发者权限。
- 一个可用的后端服务（模板按约定的接口规范调用），以及后台分配给它的专属域名与商户 ID。
- 仓库自带的 `miniprogram_npm/` 构建产物；若要改依赖，需要本机有 Node.js 与 npm。
- 正式发布需要已备案的域名与 HTTPS 证书，并在微信公众平台配置服务器域名白名单。

## 已知限制

- 仓库的 `version` 与依赖版本会随上游更新变化，具体值以仓库 `package.json` 与 `config.js` 为准。
- 没有后端就没有数据：这个包不包含服务端，也不含数据库结构。
- 默认配置指向的是示例商户，未改配置时看到的是演示内容而不是你的店铺。
- 微信登录、微信支付、直播等功能需要开发者自行开通与配置后才能实际使用。
- 本 Skill 不提供小程序代码的跨端改造，也不能替代平台侧的审核与资质流程。

## 自检清单

- 动手前：确认拿到了自己的 AppID、后台专属域名与商户 ID；确认微信开发者工具已安装并能登录。
- 导入后必查：编译无报错、首页出的是自己的商品、登录流程能走通、购物车与下单能看到真实数据。
- 发布前必查：接口域名已加白名单且 HTTPS 正常、开发工具的域名校验开关已取消勾选、类目与资质已就绪、隐私政策与用户协议已配置。
- 改依赖后必查：`miniprogram_npm` 已重新构建，组件引用不报缺失。
- 升级前必做：备份当前代码目录，逐页确认新版本页面无回归，再上传提交审核。
