# 三剪客 · 低代码企业级开发平台

JeecgBoot 面向的是「又一套企业管理系统」这类重复劳动：用户角色、菜单权限、组织架构、字典、定时任务、数据权限这些每个后台都要重写一遍的东西，它已经封装好了；业务表建好之后，增删改查的前后端代码可以直接生成出来。

它的开发方式是三段式——简单功能用在线配置零代码搭出来，复杂功能用代码生成器出骨架再手工合并，最后落到自己的业务代码里。所以它比纯零代码平台灵活，但代价是团队得先接受它的这套约定。

平台本身还带了一套 AI 应用模块（模型管理、知识库问答、流程编排、对话助手），可以接主流大模型。

**上游项目**：`JeecgBoot`　**仓库**：https://github.com/jeecgboot/JeecgBoot

## 什么时候用 / 不用

**用它**：

- 要**从零做一套企业内部系统**（OA、ERP、CRM、MIS 这类），并且希望开箱就有用户、角色、菜单、部门、字典、数据权限、定时任务这些基础设施。
- 想**先把表结构和表单配出来看效果**：在线表单支持多种控件，不用写代码就能让业务人员自己配出增删改查，确认需求之后再把复杂逻辑下沉到代码。
- 需要**代码生成器产出前后端骨架**：单表、树形、一对多、一对一几种模型都能一次生成，生成物自带导入导出，省掉脚手架部分。
- 技术栈就是 **Java + SpringBoot + Vue3**，团队不想为了低代码换语言，也愿意用 Maven 分模块的开发方式。
- 需要**信创环境适配**，或者要对接国产数据库与中间件。

**不要用它**：

- 项目**只想要一个简单的 CRUD 后台**，几张表搞定。为这点量引入整套平台，学习成本远大于收益，直接用轻量脚手架更快。
- 团队**不是 Java 技术栈**（Python、Go、Node），或者前后端要换掉 Vue。
- 只有一个**很小的后台管理页**、可预见的未来也不会扩展成系统。平台的价值来自「反复生成」，一次性页面体现不出来。
- 团队**不接受约定式开发**：不想用它的权限模型、不想走代码生成 + 手工合并的流程，希望所有代码自己从零写。那就没必要背这套框架。
- 需要**零代码拖拽出完整业务系统**、完全不做二次开发。那类需求应该看纯零代码产品，这个平台的定位是低代码而不是无代码。

## 安装
### 版本与分支怎么选

先明确一点：上游把基于 SpringBoot2 的 `master` 分支标记为**不再维护**，并建议升级到 SpringBoot3 分支。仓库里有三条分支，对应两套安全框架：

| 分支 | 技术组合 | 说明 |
|---|---|---|
| `springboot3` | JDK17 + SpringBoot3.3 + Shiro | 三份里优先考虑这条 |
| `springboot3_sas` | JDK17 + SpringBoot3.3 + SpringAuthorizationServer | 需要另一套认证授权方案时选它 |
| `master` | JDK17 / JDK8 + SpringBoot2.7 | 已明确不再维护，只用于兼容老项目 |

仓库本身分成两个源码项目：后端 Java 项目（支持单体与微服务切换）、前端 Vue3 项目（Vue3 + Vite6 + TS）。

### 环境要求

前端：

- Node.js **20+**（上游特别说明：Vite 不再支持已停止维护的 Node 18，需要用 20.19+ 或 22.12+）
- 包管理：npm / pnpm，pnpm 要求 **9+**

后端：

- Java，默认 JDK17（同时支持 JDK8、JDK21）
- Maven 做依赖管理
- IDE 建议用 IntelliJ IDEA，并且**必须装 lombok 插件**

数据库：平台默认只提供 MySQL 5.7+ 的建库脚本，其它数据库要自己转。

### 启动

上游文档给了四条启动路径，具体步骤**以官方文档为准**（它们随版本调整较频繁）：

- 开发环境搭建
- IDEA 启动前后端（单体模式）
- Docker 一键启动（单体模式）
- Docker 一键启动（微服务方式）

默认登录账号是 `admin` / `123456`。这个默认口令必须在上线前改掉。

### 微服务模式

平台基于 Spring Cloud Alibaba 提供微服务方案（注册与配置中心、网关、限流熔断、链路跟踪、消息中间件、分布式任务等），并支持单体与微服务之间切换。切换步骤以官方文档为准。

## 常用操作

**1. 取代码（按选定的分支）**

```bash
# SpringBoot3 + Shiro 分支
git clone -b springboot3 https://github.com/jeecgboot/JeecgBoot.git

# 需要 SpringAuthorizationServer 时
git clone -b springboot3_sas https://github.com/jeecgboot/JeecgBoot.git
```

**2. 前端依赖安装与启动**

```bash
# 前端是独立的 Vue3 项目目录，进入后再装依赖
pnpm install      # 或 npm install；pnpm 要求 9+
pnpm dev          # 具体脚本名以该版本 package.json 为准
```

**3. 后端编译**

```bash
# 后端是 Maven 多模块工程
mvn clean install -DskipTests
```

**4. 建库**

先创建数据库，再导入平台自带的 MySQL 建库脚本（脚本随源码提供）。**只提供 MySQL 脚本**，用其它数据库要先按上游的转库说明自己转。

**5. 用代码生成器出增删改查**

流程是：先在数据库里建好业务表 → 在平台里进入 Online 代码生成器，选中该表 → 配置字段与页面形态（单表 / 树 / 一对多 / 一对一，四套模板可选）→ 生成前后端代码 → 手工合并进自己的模块。生成物自带 Excel 导入导出。

**6. 用 Online 在线表单做零代码页面**

进入 Online 在线表单，通过在线配置表单实现增删改查，不用编码；支持在线增强开发，页面里带代码编辑器，可以写 Java、SQL、JavaScript 片段。

**7. 切换 AI 大模型**

平台默认使用 DeepSeek，也支持 ChatGPT、Ollama 等。切换入口在 AI 模型管理里，**具体配置字段以官方文档为准**。

**8. 接单点登录**

平台提供了 CAS 单点登录的集成方案与对接代码。

## 常见坑

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 前端 `install` 或启动直接报 Node 版本相关的错 | 前端技术栈要求 Node 20+；上游明确说明 Vite 不再支持已 EOL 的 Node 18 | 升到 Node 20.19+ 或 22.12+；如果机器上有多个版本，先确认当前 `node -v` 生效的是哪一个 |
| 后端一编译就报找不到 getter/setter、找不到符号 | 后端大量依赖 lombok，IDE 没装插件就不会在编译期生成方法 | 在 IDEA 里安装并启用 lombok 插件，再重新导入 Maven 工程 |
| 换了数据库（PostgreSQL / Oracle / 达梦 / 人大金仓等）之后建库就卡住 | 平台默认**只提供 MySQL 脚本**，其它库需要先转 | 先按上游给出的转库说明把脚本转成目标库方言，再导入；别直接拿 MySQL 脚本往别的库里灌 |
| 按老资料部署，发现依赖版本对不上 | 基于 SpringBoot2 的 `master` 分支上游已声明不再维护，建议迁移到 SpringBoot3 分支 | 新项目直接从 `springboot3` 分支起步；老项目升级时把 Shiro 与 SpringAuthorizationServer 两条路线的差异一并确认 |
| 想用微服务跑，但按单体（或反过来）的步骤启动失败 | 单体与微服务是两套启动方式（微服务依赖 Spring Cloud Alibaba 那一套组件），步骤不通用 | 明确自己走哪条路，分别去查对应的「IDEA 启动」「Docker 一键启动」文档；微服务模式下注册与配置中心等中间件要按顺序就绪 |
| 代码生成器生成后直接改生成物，下次重新生成被覆盖 | 生成物是骨架，平台的设计是「生成 + 手工合并」，把业务逻辑写在生成物里就会和再生成冲突 | 业务逻辑写到合并后的自有模块中；保留生成物的可重生成性，别把不可逆的改动放进模板产物 |
| 上线后忘了改默认口令 | 平台默认账号是 `admin` / `123456` | 上线前必须修改默认密码，并复核角色与菜单权限配置 |
| 打算把平台本身拿去做竞品或对外售卖 | 开源版是 Apache-2.0 附加补充条款：允许商用、允许基于它做业务系统开发，但**不得用它开发可能与本软件竞争的软件** | 商用前先读仓库里的 LICENSE 与补充条款；需要额外企业功能与技术支持时走商业版，不要指望开源版包含全部能力 |
| 想要的功能在开源版里找不到 | 商业版才提供流程监控、流程审批、表单设计器、报表企业版、OA 办公、零代码应用等能力，开源版不包含 | 先比对开源版与企业版的功能差异清单，再决定是自研还是买商业版；不要在开源版里找这些模块 |

## 能力边界

**覆盖**：

- 三条分支的取舍与各自的技术组合，避免在新项目里误用已停止维护的分支。
- 前后端的环境要求：Node 20+ / pnpm 9+、JDK 版本区间、Maven、IDEA + lombok。
- 四条启动路径的定位（开发环境搭建 / IDEA 单体 / Docker 单体 / Docker 微服务），以及单体与微服务不能混用这一前提。
- 代码生成器与 Online 在线表单的用法边界：什么场景用零代码配置，什么场景用代码生成后手工合并。
- 建库脚本只用 MySQL 这一事实，以及换库前需要先转库。
- 开源版与商业版的功能差异判断，帮用户把「找不到的模块」归因准确。
- 平台内置 AI 应用模块的存在与作用（模型管理、知识库问答、流程编排、对话助手）。

**不覆盖**：

- 逐条的启动与部署命令细节、配置文件字段含义。这些随版本变化频繁，**以官方文档为准**，本包不复制也不猜测。
- 具体版本号与发布日期以外的时效性结论；引用到的版本信息只用于说明分支维护状态。
- 代码生成器模板的定制开发、自定义组件的编写方法。
- 商业版独有的功能实现，以及购买与授权事宜。
- 转库的具体 SQL 改写工作：上游只提供思路，实际改写需要按目标库方言逐个处理。
- 移动端配套框架的细节，本包只把它作为存在的能力提及。

## 依赖条件

- 前端：Node.js 20+（20.19+ 或 22.12+）、npm 或 pnpm 9+。
- 后端：Java（默认 JDK17，支持 JDK8 / JDK21）、Maven；IDE 需安装 lombok 插件。
- 数据库：MySQL 5.7+（平台默认脚本）。使用 PostgreSQL、Oracle、SQL Server、MariaDB、达梦、人大金仓、TiDB、kingbase8 等需要先自行转库。
- 缓存：Redis。
- 文件存储：可选对接对象存储，也支持本地存储。
- 微服务模式额外需要：注册与配置中心、网关、限流熔断与链路跟踪等组件的配合。
- AI 应用模块需要至少一个大模型服务的接入配置。

## 已知限制

- 基于 SpringBoot2 的 `master` 分支已声明不再维护，只适合兼容存量项目。
- 数据库脚本只提供 MySQL 版本，其它库的适配由使用者完成。
- 开源版不含流程监控与审批、表单设计器、报表企业版、OA 办公、零代码应用等商业版功能。
- 授权是 Apache-2.0 加补充条款：可商用，但不得用来开发可能与本软件竞争的产品。
- 平台体量较大，编译与首次启动都比较吃机器资源；前端构建对内存有要求。
- 低代码的收益来自反复生成，只有一两个页面时框架的学习成本收不回来。

## 自检清单

执行前：

- [ ] 确认用户的技术栈是 Java + SpringBoot + Vue3，不是别的语言
- [ ] 确认分支选择：新项目不用已停止维护的 SpringBoot2 分支
- [ ] 检查 Node 版本是否满足 20+，pnpm 是否 9+
- [ ] 检查 JDK 版本是否在支持区间内，IDEA 是否装了 lombok 插件
- [ ] 确认目标数据库是不是 MySQL；不是则先安排转库
- [ ] 明确走单体还是微服务，二者启动步骤不通用

执行后：

- [ ] 前后端都能起来，用默认账号能登录进后台
- [ ] 默认口令已修改，权限与菜单符合预期
- [ ] 换库场景下，建库脚本导入无报错且数据可读写
- [ ] 代码生成器产物已放进自有模块，业务改动没有写在可重新生成的产物里
- [ ] 汇报时不夸大能力：开源版没有的模块不承诺，启动命令细节以官方文档为准
