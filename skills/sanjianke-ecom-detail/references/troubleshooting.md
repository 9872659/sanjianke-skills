# 电商详情页 —— 排错

**先跑 `python3 scripts/run.py doctor`** —— 免费、0 点，10 项检查能一次排掉一半问题。
它最后两条是「余额与流水前后一致」和「会话窗口内新流水 0 条」，看过这两条就知道刚才没花钱。

---

## 一、Key 相关

### `失败：没有 API Key`（exit 2）

三处都没读到。按优先级检查：

1. `--key sk-...`
2. `echo $env:A7W_API_KEY`（PowerShell） / `echo $A7W_API_KEY`（bash）
3. `~/.a7w/config.json` 里的 `{"key": "sk-..."}`

最省事：

```bash
python3 scripts/a7w.py login --key sk-你的key
```

### `拉模型清单失败（HTTP 401）`

Key 本身的问题，去 [api.a7w.cn](https://api.a7w.cn/) 重新创建一个。

---

## 二、出图失败

### `出图失败（HTTP 422）prompt: String should have at least 1 character`

`prompt` 是空的。`--plan` 出来的结构单里每位的提示词都已经写好；手写 `--product` 时
至少要给商品名，`plan` 会把「商品 + 卖点 + 画幅」拼进提示词。

### `出图失败（HTTP 400）… size …`

尺寸不合规。四条硬约束：

- 宽高都是 **16 的倍数**
- 长边 / 短边 **≤ 3:1**
- 单边 **≤ 3840**
- 总像素 **655,360 – 8,294,400**

本包在本地先验这四条，不合格直接退 2，不发请求。走过 400 就说明 `size` 绕过了本地校验，
用 `plan` 生成的 `requestSize` 最稳。

### `出图失败（HTTP 404）The model 'xxx' does not exist or you do not have access to it`

模型名写错或 Key 没权限。模型 ID 是 `gpt-image-2.6`（点号），
用 `doctor` 第 4 项确认它在架。

### 响应里没有图，但 HTTP 200

本包打印「响应里没有图」并带原始返回片段。常见原因：内容审核拦了（会带说明，**不扣费**）、
返回结构变了。看 `data` 数组长度：本包按实际返回张数计费，0 张就是 0 点。

### `失败：D0x 出图失败（HTTP 502）`

网关到上游这一段抖了。重跑同一句会**再扣一次 6 点**，先 `cost` 看一眼再决定。

## 三、尺寸与平台

### 淘宝主图要 800×800，为什么请求 1024×1024？

800×800 只有 **640,000 像素**，低于下限 655,360，会被参数校验拦下。
1024×1024 满足「1:1 且不小于 800」，**本身就能直接上架**。
`check` 默认按「出图尺寸」验收；要看上架口径就加 `--publish`。

### 抖音主图 1200×1600 会不会更贵？

不会。gpt-image 按张计费，**与尺寸、质量、输出格式都无关**，1200×1600 也是 6 点。

### 参数图为什么是 768×1024 而不是 750×1000？

750 不是 16 的倍数。768×1024 是 3:4，落在详情页 750 宽的口径里，上传后按页面宽度自适应。

---

## 四、上传与素材地址

### `400 url_not_allowed`

上游只收本站托管的地址：

- `*.a7w.cn`（含 `vr.a7w.cn`）
- `cdn2.jiujiushuyuan.cn/vr/…`
- `oss.gpu.likeadmin.cn/openapi/…` ← `upload` 返回的就是这个

正确顺序：`upload --file 实拍.jpg` → 拿 `data.url` → 再给 `--images` / `--model-url` / `--garment-url`。

### 上传返回 `code: 0`「请使用 file 字段提交一个文件」

multipart 的字段名固定是 `file`，本包已经按这个发。手写 curl 时别改成 `image` 或 `files`。

### 上传要钱吗？

价目表 `/api/v1/upload` 写着 `cost: 0`，实测空表单与真文件都不扣点。
返回的地址约 24 小时有效，出完图尽快落盘。

---

## 五、异步线（nano / 换装）

### `gen --engine nano` / `--engine dress` 没有图，只有一个 task_id

这两条是异步：拿到 `task_id` 后用

```bash
python3 scripts/run.py status --task-id task_xxx
```

查询只走免费的 `GET /api/v1/tasks/{id}`。

### 想轮询等结果，会不会一直扣钱？

只要走 `/api/v1/tasks/{id}` 就不会。**应用层 query 是计费路**：
`nano_banana/query` 实测 72 点/次，轮询一次就是一张商品图的价。
本包没有任何代码打应用层 query。

### `dress` 提了但没拿到 task_id

看返回里的 `code` 与 `msg`。换装的两个必填是 `model_url` 与 `garment.data[].url`，
缺一个都会 400；本包在本地就拦下，退 2。

## 六、花钱相关

### `失败：预计 78 点超过 --budget 10 点`（exit 5）

闸门在工作。**一个请求都没发。** 调大 `--budget`（单位是点，1 元 = 100 点，默认 500）。

### `失败：一整页 13 位 × 6 点 = 78 点预计 78 点（0.78 元）… 确认请加 --yes`（exit 4）

缺 `--yes`，**还没花钱**。想先看请求：

```bash
python3 scripts/run.py gen --plan ./out/plan.json --dry-run
```

### 实扣比预估多？

不会超过 `6 × 位数`（nano 72/次、换装 200/次同理）。可能更少：某一位只回 0 张就只收 0 张。
`gen` 结束会打「实扣 N 点」并记账到 `~/.a7w/ecom-detail-ledger.json`。

### 请求失败了会扣钱吗？

参数错误、请求失败、没出图都不扣费；内容审核拒绝也不扣费。
**客户端中途断开或同步请求超时，仍按请求张数计费** —— 这是唯一要留神的一条。

## 七、`check` 验收不过（exit 3）

### `D07 卖点2 材质工艺：缺图`

`check` 按结构单的 13 位逐个数文件。缺哪一位就把那一位补出来：
`gen --plan … --slot 7`。

### `命名不合规范`

规范是 `<SKU>_D<位号两位>_<类型>_<宽x高>_v<版本两位>.<png|jpg|webp>`。
手改文件名时位号与类型要跟结构单对齐，`gen` 落盘时已经按规范命名。

### `实际 1024x1024，结构单要 800x800`

你加了 `--publish`，而图还是出图尺寸。两种用法：

- 默认（不带 `--publish`）按 **出图尺寸** 验 → 现在就能过
- 要按 **上架尺寸** 验，就先把图缩到 800×800 / 750×1000 再跑 `--publish`

### `文案位命中 5 处，按合规改写表换成可验证事实`

`--copy 文案.json` 里出现了绝对化用语。打开 `out/page.md` 的「合规改写对照」，
把「全网最低价」换成「同款比价截图 + 到手价（附链接）」这类可验证写法，再跑一次。
`check` 把命中词和原文都打出来了，照着改即可。

## 八、慢 / 超时

- 一张图通常 **20–50 秒**；`gen` 默认超时 **240 秒/张**，可用 `--timeout 400` 调大
- 13 位是 13 次请求，整页通常 **5–12 分钟**
- 只补某几位用 `--slot` / `--kind`，别整页重跑
