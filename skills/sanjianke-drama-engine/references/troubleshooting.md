# 排错与运维

按**症状**查，不按模块查。左列是你看到的现象。

---

## 一、装不上 / 起不来

| 症状 | 可能原因 | 怎么查 |
|---|---|---|
| `yarn install` 编译原生模块失败 | Node 版本低于 23.11.1 | `node -v`。`better-sqlite3` 和 `sharp` 是原生模块，低一个主版本就编译不过 |
| `yarn dev` 起来了，但浏览器打开 10588 是空的 | 这是正常的 | `yarn dev` **只启后端 API，不含前端**。要看到界面用 `yarn dev:gui` |
| Docker 起来后访问根路径看不到界面 | 路径不对 | 要访问 `/web/index.html`，例如 `http://localhost:10588/web/index.html` |
| macOS 双击安装包没反应 | 证书被拦 | 设置 → 隐私与安全性 → 放行 |
| 容器重建后数据全没了 | 没挂载 `/app/data` | `docker run` 时加 `-v <本地路径>:/app/data` |
| 云端部署后生成的图/视频链接打不开 | `OSSURL` 填的是内网地址 | 改成**外部能访问到的地址**。填 `127.0.0.1` 时只有本机能看 |

---

## 二、模型配了但不生效

这一类的根因几乎都是**两处检查漏了一处**：

- [ ] **模型服务**里的三个调用开关是否都开着
- [ ] **Agent 配置**里各 Agent 引用的模型是否与你配的一致

| 症状 | 怎么查 |
|---|---|
| 填了 Key 和地址，跑起来报模型不存在 | 模型名要**完整粘贴**。预设里没有的模型用「手动添加」把完整名称填进去 |
| 三个开关开了，但某个环节还是不动 | 去 Agent 配置看那个 Agent 引用的是哪个模型。默认值往往是空的或旧的 |
| 换了模型没反应 | 改完点空白处，要等提示「供应商配置已更新」 |
| 想让请求走自己的网关 | 用供应商的**可编程 TypeScript** 能力改请求，不用改源码 |

## 三、编剧阶段

| 症状 | 可能原因 | 怎么查 |
|---|---|---|
| 骨架里出现原著没有的章节 | 事件图谱没做好，或模型在编 | 拿事件表对照，章节号对不上的一律清掉 |
| 剧情跳、前面埋的线没了 | 事件提取粒度太粗，或没走事件图谱直接喂全文 | 抽一章看事件表能否还原该章剧情 |
| 压缩比超标 | 该删的场次没删 | 压缩比硬约束是 ≤40%，看「全局删减决策表」 |
| 每集结尾没钩子 | 骨架阶段没落实「黄金单集公式」 | 公式 = 情节承接 + 冲突升级 + 价值币环 + 下集勾连 |
| 人物小传超过 4 人 | 铺了群像 | 短剧是单线型，大三角最多 4 人（主角 + 反一号 + 1~2 关键配角） |
| 反派动机很弱（「纯嫉妒所以害人」） | 低级写法，要打回 | 反派必须有合理动机 |
| 核心矛盾平淡 | 矛盾等级不够 | 爆款骨架须达**矛盾四级阶梯**的第 3~4 级 |
| 金手指像无敌外挂 | 没写约束 | 金手指必须有边界，无边界即贬值 |
| 卡点位置不对 | 没按比例公式 | 按 N×10% / 30% / 50% / 70% / 90% 定位 |
| 卡点炸但没用 | 卡点脱离主线 | **铁律：卡点必须卡在主线上** |

**通用处理**：让**监督层**打回重做，别带着问题往下走。骨架阶段改一句话，
到出片阶段就是几百块的视频生成费。

## 四、制片阶段

| 症状 | 可能原因 | 怎么查 |
|---|---|---|
| 同一角色不同镜头长得不一样 | 图片资产没建齐，或四视图规范没定好 | 出图前先把角色/场景/道具资产做齐。资产不齐模型会自己编外观 |
| 分镜表里出现了服装/发型/长相的描述 | 违反铁律 8 | 人物外观归图片资产，不进分镜提示词 |
| 分镜表里写了「暖黄色逆光」「BGM 渐强」 | 违反红线 7 | 光影色调归画风包，配乐归后期。分镜表只写环境音 + 音效 |
| 有些人物在分镜里人间蒸发 | 违反铁律 6 | 对照 `$ 出场人物` 列表逐片段数人。剧本没写「离开」就还在场，要有视觉痕迹 |
| 台词被精简或合并了 | 违反铁律 4 | 台词**零删改**，引号内内容 100% 逐字搬运 |
| 长台词挤在一个固定镜头里 | 违反铁律 3 | 超 20 字必须拆镜，按**语义停顿点**切，不平均切 |
| 片段之间跳跃感强 | 没做过渡设计 | 四类桥梁：动作的桥梁 / 情绪的接力 / 空间与视线的链接 / 台词与动作的黏合 |
| 分镜表前后不一致或漏场 | 执行流程被打断 | 六步是**严格线性不可回退**的；第 1 步一次性读完全部数据后不许再读 |
| 编造了不存在的资产名或 ID | 违反红线 6 | 只引用 `assets` 里已存在的资产，缺失的只在画面内容里体现 |

## 五、成本失控

| 症状 | 原因 | 处理 |
|---|---|---|
| 账单比预期高很多 | 视频生成占九成以上，重生成次数多 | `python3 scripts/cost_estimate.py` 先算，再决定批量规模 |
| 一路跑下来大半是废片 | 分镜设计不到位 | 官方 Demo 废片率约 1/3。明显更高说明在用生成挑片来代替分镜 |
| 想省钱不知道从哪下手 | 省错了地方 | 图片成本不足 1%，别省图；**要省就省视频秒数** |

**正确顺序**：先拿 1 集跑通全流程 → 定风格 → 定全剧骨架 → 批量出分镜 →
分批出片，每批质检后再往下。

**别一上来就全剧开跑。** 模型配置或画风的问题在第 1 集就能暴露，
拖到第 20 集才发现，损失的是几十倍的费用。

## 六、自定义技能包不生效

| 症状 | 原因 |
|---|---|
| 新加的画风包完全没效果 | 目录名写成了 `director_skills`。**上游用的是 `driector_skills`**（拼写错误但必须照抄），写错不报错、只静默不加载 |
| 提示词里混进了解释文字 | `prefix.md` 开头缺「仅输出提示词正文，不得附加任何解释」的强约束 |
| 色彩每次都不同 | 色彩盘只写了色名，没写色值 |
| 某些场景突然变成别的画风 | 「严禁」栏没列全漂移方向 |
| 包加了但列表里没有 | 放错目录（画风要进 `art_skills/`，题材要进 `story_skills/`），或没刷新页面 |

自查：

```bash
python3 scripts/check_toonflow_skill.py <你的包目录>
```

## 七、数据与备份

Toonflow 用 **SQLite**（`better-sqlite3` + `knex`），所有项目数据都在 `data/` 下：

| 目录 | 内容 | 要不要备 |
|---|---|---|
| `data/oss/` | 素材、角色、场景 | **要**，这是你最贵的东西 |
| `data/skills/` | 技能提示词 | **要**，你调过的提示词都在这里 |
| `data/models/` | ONNX 本地模型 | 可不备，能重新下 |
| `data/web/` | 前端编译产物 | 不用，能重新构建 |
| 数据库文件 | 项目 / 剧本 / 分镜数据 | **要** |

**改提示词前先备份 `data/skills/`。** 这是最容易改坏又最值钱的目录。

云端部署时，把整个 `data/` 做成定期快照最省事。
