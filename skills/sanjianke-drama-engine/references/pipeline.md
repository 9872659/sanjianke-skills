# 生产流水线：从小说到成片

Toonflow 的流程不是线性的表单，而是**无限画布 + 三层 Agent 协作**。理解这两点，
才不会用错姿势。

---

## 一、两类 Agent，各自三层

Toonflow 把「把小说变成剧」拆成两个 Agent，各自再分三层：

| 层级 | Script Agent（编剧） | Production Agent（制片） |
|---|---|---|
| **决策层** | 项目初始化、拆流水线、派发任务 | 制作流水线规划、派发任务 |
| **执行层** | 骨架 / 改编策略 / 剧本 | 导演规划 / 分镜表 / 分镜图 / 资产生成 |
| **监督层** | 审剧本、挑问题、打回重做 | 审分镜与素材一致性 |

决策层负责「怎么拆、派给谁」，执行层负责「具体产出」，监督层负责「挑错打回」。
**监督层是这套系统稳定的关键**——它让错误在阶段内被发现，而不是等到出片才发现人物换脸了。

## 二、全流程六步

| 步骤 | 在哪做 | 产出 | 卡点 |
|---|---|---|---|
| 1 | 设置中心 | 三类模型接好 | 三个开关都开、Agent 引用的模型一致 |
| 2 | 项目管理 | 新项目 + 导入原著 | 原著的章节结构是否清晰 |
| 3 | 小说管理 | **章节事件图谱** | 事件粒度是否够细、章节号是否对得上 |
| 4 | ScriptAgent | 故事骨架 → 改编策略 → 结构化剧本 | 压缩比 ≤40%、每集有集末钩子 |
| 5 | ProductionAgent | 导演规划 → 分镜表 → 分镜图 → 视频节点 | 角色一致性、片段间连贯性 |
| 6 | 画布 | 精调 → 拼接 → 导出 | 废片率、音画对位 |

## 三、为什么是「章节事件图谱」而不是「全文喂给模型」

上游把「章节事件图谱驱动改编」列为核心能力，这是有原因的：

长篇小说动辄几十万字，直接塞进上下文会**信息丢失**——模型会忘记前面埋的线、
记错人物关系、把后面的情节提前用掉。事件图谱的做法是：

1. 先把每一章拆成结构化事件（谁、在哪、做了什么、结果、牵扯谁），存进数据库；
2. 写骨架时按需 `get_novel_events(ids)` 拉取**指定章节**的事件，而不是全文；
3. 章节号严格对齐，模型不可能凭空造出原文没有的章节。

所以**第 3 步的质量决定后面所有环节的质量**。事件图谱做得粗，后面再好的提示词也救不回来。

## 四、两个 Agent 阶段的输入输出契约

### Script Agent

```
章节事件图谱
   ↓
故事骨架      一句话故事核 / 隐线 / 人物小传 / 三幕结构 / 分集决策 / 付费卡点
   ↓
改编策略      哪些章节合并、哪些删、压缩比怎么分配
   ↓
结构化剧本    分场、台词、动作提示
```

### Production Agent

```
结构化剧本
   ↓
导演规划      全局视觉基调、节奏曲线、声音方向（严格线性五步）
   ↓
分镜表        逐片段：景别 / 运镜 / 时长 / 台词 / 转场（严格线性六步）
   ↓
分镜图        按分镜表逐条出图
   ↓
视频节点      图生视频，回流画布拼接
```

注意两个「严格线性、不可回退」的标注：**导演规划五步、分镜表六步**。这不是建议，
是上游写死在提示词里的执行流程。你改提示词时如果把步骤改成可回退，产出质量会明显下降
——因为每一步都依赖上一步的结构化结果。

## 五、无限画布怎么用

画布上每一种东西都是一个**节点**：剧本、角色、场景、道具、分镜、素材、视频。

它的价值在于**不受线性步骤限制**：

- 某个角色的形象不满意 → 只重跑这个角色节点，不用重跑全剧
- 某几集要换风格 → 把那几集的节点接新的画风资产
- 想并行试两种画风 → 复制一份节点分支，各跑各的

**实践建议**：先在 Script Agent 把剧本定稿，再进 Production Agent。剧本没定就开跑，
后面改一句台词可能意味着重出十几张分镜图。

## 六、成本意识要贯穿全程

官方 Demo 的账单很说明问题：

| 项目 | 费用 | 占比 |
|---|---|---|
| 视频模型（全量生成） | 约 ¥120 | 92% |
| 语言模型 | 约 ¥10 | 8% |
| 图片模型 | 不足 ¥1 | <1% |
| **合计** | **约 ¥130** | |

（成片约 2 分钟，原始素材 3 分钟）

**视频生成占了九成以上。** 这意味着省钱的方向只有一个：**减少要生成的视频秒数**。
具体做法：

- 剧本阶段就把不拍的场次删掉，别等生成了再剪
- 分镜表先审到位，别用「多生成几条挑一条」代替分镜设计
- 先出 480p / 低分辨率试节奏，定稿后再吃高分辨率

反过来，图片成本低到可以忽略——**分镜图多出几张挑一挑，比省图片钱划算得多**。

用 `scripts/cost_estimate.py` 可以按你的集数和时长先算一笔：

```bash
python3 scripts/cost_estimate.py --episodes 30 --minutes 2
```

## 七、推荐的项目推进顺序

1. **先跑通一个最短闭环**：拿原著第一章做 1 集，把六步全走完，确认模型都通、画风能接受。
2. **定风格**：从 11 个画风包里选一个，或自己做一个（见 `custom-skills.md`）。
3. **定全剧骨架**：这一步要在 Script Agent 里反复磨，磨到监督层不再打回。
4. **批量出分镜**：Production Agent 跑全剧分镜表。
5. **分批出片**：按集或按场次分批生成视频，每批出来先质检再往下。

**别一上来就全剧开跑。** 模型配置或画风选择上的问题，在第 1 集就能暴露，
拖到第 20 集才发现，损失的是几十倍的视频生成费用。
