# 记忆接入指南

记忆层的活儿分三步：**写入（抽取）→ 存储 → 召回（检索）**。
这份文档讲怎么把每一步的工程细节做对，以及模型入口怎么指向 `api.a7w.cn`。

---

## 一、把模型入口指向网关

记忆框架通常把模型拆成三段配置，三段都可以指向同一个网关：

| 段 | 作用 | 指向 |
|---|---|---|
| LLM | 从对话里抽取事实 | `https://api.a7w.cn/api/v1` + `chat/completions` |
| Embedder | 把文本变成向量 | 同上网关（键名以框架当前版本为准） |
| Reranker（可选） | 对召回结果重排 | 同上网关，或先用框架默认 |

```json
{
  "llm": {
    "provider": "openai",
    "config": {
      "model": "DeepSeek-V4-Flash",
      "base_url": "https://api.a7w.cn/api/v1",
      "api_key": "sk-你的key"
    }
  },
  "embedder": {
    "provider": "openai",
    "config": {
      "base_url": "https://api.a7w.cn/api/v1",
      "api_key": "sk-你的key"
    }
  }
}
```

> **键名风格**：Python 侧多为下划线（`base_url` / `api_key`），TypeScript 侧多为驼峰
> （`baseUrl` / `apiKey`）。**值永远是同一个网关地址和同一把 Key。**

## 二、作用域设计

先把「谁记得谁」定清楚，再写代码。

| 维度 | 典型取值 | 用在什么场景 |
|---|---|---|
| `user_id` | 用户 / 客户 ID | 最常用。必须与业务账号体系对齐 |
| `agent_id` | 角色名 | 一个系统里多个助手各记各的 |
| `app_id` | 应用名 | 多产品共用一套记忆服务时区分 |
| `run_id` | 会话 / 工单 ID | 只在本轮对话内有效的事实 |

**规则一：ID 生成收在一个函数里。**
写入用 `user_id="A"`、检索用 `user_id="a"`，结果就是「存进去了却搜不到」——
这类 bug 排查起来最费时间，往前一步就能避免。

**规则二：检索必须带作用域过滤。** 别做全库向量搜索，
既慢又贵，还会把别的用户的事实召回进来。

**规则三：作用域要跟着业务走。** 用户注销时，对应的记忆条目要能按同一维度批量清掉。

## 三、写入节流

每次写入都是一次模型调用，所以写入频率直接决定成本。

**值得写：**

- 偏好（「我喜欢深色模式」「回复要短」）
- 决定（「这个项目用方案 B」）
- 目标（「下个月要上线」）
- 新实体（人名、产品名、订单号这类后续会复用的东西）
- 约束（「不要碰生产库」）

**不值得写：**

- 寒暄、确认语、「好的」「收到」
- 对上一句的纠错重述
- 一次性的临时信息

**判断口径**：这条信息在下一轮对话里还有用吗？没有就不写。

---

## 四、检索提准

1. **`top_k` 从 3 起步。** 召回太多会污染提示词，成本也更高。
2. **召回后按语义去重。** 加法式存储会让同一事实沉淀多条，去重放在应用层做。
3. **拼进 prompt 时带上来源与时间。** 让回答模型知道哪条更新、以哪条为准。
4. **冲突处理显式化。** 新事实和旧事实矛盾时，明确以新为准并回写，
   不要让两条矛盾的记忆同时躺在库里。
5. **抽取值与检索值同一套口径。** 同一个事实不要一半存原文、一半存抽取结果。

---

## 五、批量回填历史数据

把历史工单 / 聊天记录变成长效记忆：

1. 按 `user_id` 分组，组内按时间排序。
2. 逐条（或按会话窗口）抽取事实。
3. 攒成批次后再写库，控制单次提交的条目数。
4. 控制并发：抽取是模型调用，并发过高会撞限流。
5. 记下已处理的游标（最大时间戳 / 最大 ID），失败可以断点续跑。

> 回填的量决定了成本。先拿一个 `user_id` 试跑，看一下抽出的条目数与消耗，再决定全量跑。

---

## 六、上线自检

- [ ] 三段模型配置（LLM / embedder / reranker）都指向同一个网关
- [ ] Key 走环境变量或配置文件，**没有硬编码进代码、没有提交进仓库**
- [ ] 写入点和检索点用同一套作用域 ID
- [ ] 每次检索都带了作用域过滤，`top_k` 有上限
- [ ] 写入只发生在高信息量事件上
- [ ] 召回结果在应用层做了去重与冲突处理
- [ ] 已确认送出的对话内容符合你的隐私与合规要求
- [ ] 批量回填有游标、可断点续跑
