# 三剪客 · QQ 机器人协议端 Skill

把 QQ 协议翻译成 OneBot v11 接口的中间层：部署、配置、排错与迁移评估

---

## 前置条件

- 一个用于登录的 QQ 账号；新账号需要一段"养号"期才能稳定发消息
- 一台可长期在线的机器（官方口径：内存小于 128M 建议关闭内置数据库）
- 需要发送任意格式语音时，额外安装 `ffmpeg` 并加入 `PATH`
- 从源码构建时需要一个可用的 Go 工具链
- 清楚并接受这个项目已停止维护、依赖非官方协议、账号存在风控风险这三件事

---

## 使用

1. 从 release 下载对应平台的压缩包并解压，或按 `SKILL.md`「安装」一节用容器 / 源码方式部署。
2. 首次运行会生成 `config.yml`；填好 `account` 与 `servers` 两段后再次运行。
3. 按需选择 http / ws / ws-reverse 通信方式，公网可达的接口务必设置 `access-token`。
4. 遇到登录 45 错误或发消息被风控，按「常用操作」配置签名服务器，并留意 `refresh-interval` 不要超过 60 分钟。
5. 用进程管理器（systemd / screen）保证常驻；把 `config.yml`、`device.json`、`session.token` 一起纳入备份。
6. 面向新项目时，先读「什么时候用 / 不用」与「已知限制」，评估是否应该改选仍在维护的方案。

---

## 依赖

- 运行 release 二进制无额外依赖（静态链接单文件）
- 源码构建需要 Go 工具链与 `go mod` 拉取依赖的能力
- 语音 / 短视频相关能力依赖 `ffmpeg`
- 登录与发消息在风控环境下依赖外部签名服务
- 配置文件支持 `${ENV:默认值}` 形式的环境变量占位符，可用于注入敏感项

---

## 安全

- 不内嵌任何密钥
- QQ 账号密码建议用环境变量占位符注入，不要明文写进 `config.yml`，并限制该文件权限
- 公网服务器必须设置接口 `access-token`，并用防火墙限制可访问来源
- `device.json` 与 `session.token` 等同于登录凭据，不要提交到版本库或公开分享
- 使用非官方协议登录存在账号被风控、限制或封禁的风险，请勿用于重要账号
- 上游已停止维护，不再有安全修复；请尽早评估迁移
