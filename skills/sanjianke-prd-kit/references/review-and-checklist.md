# 评审与自检清单

这份文档解决两件事：**怎么把评审会开成收敛会而不是争吵会**，以及**发出前用一张表判断这份 PRD 能不能开工**。

---

## 一、评审会之前：先自检，别拿半成品占用人

评审会最贵的成本不是会议时长，是"讨论了 40 分钟后发现文档第一段就没立住"。
**发送评审邀请前，作者必须先过一遍下文的 A 档 + B 档自检。** 未过 B 档的文档不进评审——退回作者补，不是会上补。

给评审者的前置材料固定三样，缺一样就推迟：

1. PRD 全文（版本号 + 更新时间）
2. 明确列出**这次希望大家决定什么**（3 条以内，写清要拍板的问题）
3. 背景材料原件（数据、工单、访谈记录），供质疑时追溯

---

## 二、评审分三档，不要一次问完

一份文档在不同阶段回答不同问题。把三档混在一次会上问，必然变成逐字挑刺。

| 档 | 时机 | 只问一个问题 | 不讨论什么 |
|---|---|---|---|
| **第一档：问题是否成立** | 文档 v0.1 出来后立刻 | 这个痛是真的吗？有没有更值得做的事？ | 不讨论怎么实现、不讨论工期、不讨论文案 |
| **第二档：范围与决定是否合理** | 第一档通过后 | 边界切得对吗？关键决定的理由站得住吗？ | 不讨论字段名、不讨论交互细节 |
| **第三档：验收是否可测** | 定稿前 | 每条验收标准换个人测能得出同一结论吗？ | 不重新讨论范围 |

**只有第一档通过了才开第二档。** 问题不成立的文档，越往下评审越浪费——这是评审最重要的一条纪律。

---

## 三、评审会怎么开

**参会人**：作者、能拍板的人、一个没参与过讨论的读者、执行方代表（开发/设计）。
**没参与过讨论的那一位最关键**——他读不懂的地方就是文档的空洞，而且他的困惑不会因为"你当时不在场"而消失。

**流程（40 分钟为限）**：

| 分钟 | 环节 | 要点 |
|---|---|---|
| 0–3 | 作者只讲问题定义 | 不讲方案、不讲进度，只讲谁的什么痛、有多大 |
| 3–8 | 陌生人复述 | 那位没参会的读者用自己的话复述问题；复述偏了就是文档没说清 |
| 8–25 | 逐条过关键决定 | 每条问三句：备选是什么？为什么排除？代价承认了吗？ |
| 25–35 | 过验收与开放问题 | 每条验收标准现场问"怎么测"；每条开放问题确认"谁定、何时定" |
| 35–40 | 当场记录结论 | 决定、待定、负责人、截止时间，写在文档里而不是会议纪要里 |

**主持人守则**：

- 任何"我们是不是应该考虑一下 XX"的发言，当场归到三处之一：**本期范围 / 非目标 / 开放问题**。归不进这三处的，就是没想清楚，记录下来下次再谈。
- 禁止在第二档会上重新打开第一档的结论。想推翻问题定义，另开一次第一档会。
- 争议超过 8 分钟没有结论的，**不要现场投票**，转为开放问题并指定决定人和截止时间。

## 四、争议收敛的四种情形

| 情形 | 表现 | 处理 |
|---|---|---|
| **口径之争** | 两边说的其实是同一件事，只是定义不同 | 当场把争议词写下来，各自给出一个可测的定义，选其中能测的那个 |
| **优先级之争** | 都承认该做，争的是先后 | 不争了，把未选的那条写进非目标并附触发条件 |
| **事实之争** | 争的是"到底有多少用户受影响" | 现场查数据；查不到就转为开放问题，指定补测人，**不许凭印象定论** |
| **判断之争** | 数据一致，但风险偏好不同 | 由能拍板的人定，并在关键决定里记录"谁定的、基于什么"——留痕比正确更重要 |

**一个实用判据**：如果这场争议在半年后还会被重新提起，那它就必须进「关键决定与理由」章节，而不是留在会议记录里。

## 五、A 档自检：格式与完备性（5 分钟）

发出前扫一遍，任何一条不合格，文档不要发。

- [ ] 八个章节齐全（问题定义 / 目标与非目标 / 用户与场景 / 范围边界 / 关键决定与理由 / 验收标准 / 风险 / 开放问题）
- [ ] 非目标 ≥ 3 条，且每条写了原因
- [ ] 关键决定 ≥ 3 条，每条有备选、理由、代价
- [ ] 验收标准覆盖了每一条目标（逐条挂钩核对）
- [ ] 每条开放问题都有「谁定」和「最晚何时定」
- [ ] 有版本号与更新时间
- [ ] 全文没有「赋能 / 闭环 / 抓手 / 极致 / 全面提升」这类填充词

---

## 六、B 档自检：逻辑一致性（15 分钟）

这一步查的是**章节之间有没有互相打架**。多数废稿的问题就出在这里。

- [ ] **目标 vs 验收**：每条目标都能在验收表里找到至少一条对应项？找不到的目标是许愿
- [ ] **非目标 vs 范围边界**：非目标提到的不做项，范围边界里有没有漏出个"半做"（例如非目标说不做多语言，范围里却保留了语言下拉框）
- [ ] **关键决定 vs 范围边界**：决定的代价（如"300 条以上不承诺"）有没有写进范围边界的降级说明？
- [ ] **风险 vs 验收**：风险预案会不会改变验收标准？若会，验收标准要按预案补一条
- [ ] **开放问题 vs 全篇**：每条开放问题影响的章节，是否已在文中标注为待定，而不是当成已定事实在写
- [ ] **数字来源**：每个数字后面能不能说出出处？说不出就改成"待补测"并说明补测方式

**交叉核对的小技巧**：把目标编号（G1、G2）和验收编号（A1、A2）做成一张对照表，中间留空。凡是找不到对应关系的编号，都是问题所在。示例见 `prd-worked-example.md` 的验收标准表。

---

## 七、C 档自检：决策质量（10 分钟，需他人参与）

前三档作者自己能做，这一档必须借外部视角。三个测试，全过才算合格。

### 测试 1：陌生人测试

找一个没参加过任何讨论的人，让他读完文档后回答四个问题：

1. 这是要解决谁的什么问题？
2. 这次明确不做什么？
3. 为什么选了现在这条路线？
4. 怎么算做完了？

**四个都答对**才算过。答错哪个，回去补哪一章——不要解释，解释不解决问题。

### 测试 2：换方案测试

假设实现方案全部换掉（前端改后端、串行改队列、自研改采购），逐章问：这一章还成立吗？

- 第 1、2、3、5、6、7、8 章应当全部成立
- 只有第 4 章（范围边界）和附录允许随方案变化

**若第 1 章就随方案变化**，说明你把方案写成了问题，回去重写问题定义。

### 测试 3：删形容词测试

把全文的形容词去掉（高效、流畅、稳定、智能、灵活、友好），读一遍。

- 信息量**没减少** → 这些词是填充物，删掉
- 信息量**减少了** → 说明那个形容词承载了真实约束，把它改写成可测的表述（例如"灵活"→"允许用户自定义片头时长，范围 1~10 秒"）

## 八、退回重写的判定线

不要修补，直接重写。出现以下任一情况就重写——补丁只会让文档更长更难读。

| 判定线 | 为什么重写比修补快 |
|---|---|
| **问题定义不可证伪** | 后面的目标、范围、验收全靠它推导，根不对，枝叶全错 |
| **非目标 < 3 条或全是软柿子** | 说明范围根本没讨论过，需要重新拉一次范围会，而不是加几行字 |
| **关键决定全无备选** | 意味着讨论过程没被记录，需要重新走一遍决策，而非补写理由 |
| **验收标准超过一半不可测** | 通常是目标本身没定口径，要回到第 2 章重来 |
| **同一处有三种以上说法互相矛盾** | 文档经历过多次局部修补，结构已经不可信 |
| **超过 6000 字且一半在讲实现** | 需要拆分：PRD 留下"为什么"，实现细节另立技术方案文档 |

**修补仍然可行的情形**：单章缺失、开放问题缺主缺期、个别数字来源不明、格式与编号混乱。这些是补丁级问题。

## 九、发版与变更管理

| 版本 | 含义 | 门槛 |
|---|---|---|
| v0.1 | 草案，内部对齐用 | 八章齐全，允许有"待确认" |
| v0.5 | 评审版 | A 档 + B 档自检通过，开放问题已排序 |
| v1.0 | 开发基线 | C 档三个测试全过，开放问题 ≤ 5 条且全部有主有期 |
| v1.x | 定稿后修订 | 每次修改在变更记录里写一行：改了什么、为什么、谁要求的 |

**变更记录格式**（放在文末，永远追加不删除）：

```text
v1.1  2026-04-02  新增失败条目重试次数的限制说明（S5）
       原因：试运行发现无限重试会重复消耗素材配额
       提出：技术负责人
```

**重要纪律**：PRD 定稿后，**范围类变更必须回到评审**；文案、字段名、交互微调这类不影响范围的改动，作者自行更新版本号即可。判断标准是——这个改动会不会让某条验收标准变得不可测？会，就要回评审。

## 十、一页速查表

```text
发之前问自己五个问题：
1. 问题能证伪吗          → 什么现象出现就说明写错了？
2. 边界切了吗            → 开发能不能自己判断"这件事不归我做"？
3. 决定留痕了吗          → 半年后有人问"为什么不用 B"，文档能答吗？
4. 验收能测吗            → 换个人测，结论一样吗？
5. 未知有主有期吗         → 每条开放问题谁定、最晚何时定？

三档评审：
第一档 只问问题是否成立
第二档 只问范围与决定
第三档 只问验收是否可测

三个测试：
陌生人测试 / 换方案测试 / 删形容词测试

一条纪律：
问题不成立的文档，不要往下评审。
```
