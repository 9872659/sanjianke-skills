# 三剪客 · 需求文档 PRD Skill

把讨论记录、背景资料和零散想法整理成一份真正能用的 PRD

---

## 前置条件

- 一个支持自定义技能/提示词的对话客户端即可，无需插件、无需联网、无需任何账号
- 手上至少要有**原始材料**：会议记录、群聊片段、用户反馈、客服工单、实测数据中的任意一种
- 如果只有一句"做个 XX 功能"，请先补齐问题现象再使用本 Skill——输入太薄，产出必然是许愿池
- 最好有一位能拍板的人参与，否则「关键决定与理由」章节只能停在待定

---

## 使用

**三步：**

1. 把原始材料整段贴进对话，不管多乱
2. 说清三件事：给谁做的、这次要做到哪一步、有没有已经拍板的前提
3. 说一句「按 PRD 结构整理成 v0.1」

最小提示词：

```text
按「三剪客 · 需求文档 PRD」的结构，把下面这些材料整理成一份 PRD v0.1。
八个章节都要有；没有信息支撑的章节写「待确认」并列出要问谁、问什么，不许编造填充。
非目标至少 3 条并说明原因；验收标准必须能被第三方独立验证。

材料如下：
（粘贴）
```

**出稿后别急着发**，先跑 `references/review-and-checklist.md` 的 A 档与 B 档自检，再找一个没参与讨论的人做陌生人测试。

**四类常见诉求对应看哪份：**

| 诉求 | 看哪份 |
|---|---|
| 八章分别怎么写、每章几行、有哪些坑 | `references/prd-structure-and-writing.md` |
| 要一份填好的完整例子照着改 | `references/prd-worked-example.md` |
| 准备开评审会，或判断文档能不能开工 | `references/review-and-checklist.md` |
| 只想快速判断合格与否 | `SKILL.md` 的「合格 PRD 的五条判据」与「自检清单」 |

## 依赖

| 项 | 要求 |
|---|---|
| 运行环境 | 无。纯 Markdown 文档，无脚本、无依赖包 |
| 网络 | 不需要 |
| 外部服务 | 无 |
| 模型能力 | 需能稳定遵循结构约束；弱模型容易把"待确认"写成看似确定的句子 |
| 文件 | `SKILL.md` + `references/` 三份；只装 `SKILL.md` 也能产出可用的 v0.1 |

---

## 安全

- 不内嵌任何密钥、Token、Cookie、账号
- 不联网、不抓取、不调用任何接口
- 不主动读取本地文件；材料由用户自己贴入对话
- `references/` 全部是静态 Markdown，没有任何可执行文件
- 不在文档中留存聊天记录、客户信息或内部价格；示例中的数字与人名均为虚构演示
