# 三剪客 · 长文自动生产线

> 给一个主题，一条链路产出**可发布的长文**：选题角度 → 大纲 → 正文 → 配图 → 平台适配。
> 不是单点生成，是**多步流水线**；七个子命令，每一步的产出都能单独拿去用。

---

## 这是什么

一篇能发出去的长文，卡人的从来不是"写"，是这三件事：

1. **写之前想不清角度** —— 于是写出一篇正确但没人转发的文章
2. **写完之后配图乱来** —— 随便找张图插进去，或者干脆不配
3. **同一篇稿子发给所有平台** —— 头条要结论前置、知乎要先给判断，一个版本打天下就是两个都不讨好

本包把这条链路做成七个命令，每一步都能单独交付、单独验收：

| 子命令 | 做什么 | 产出 |
|---|---|---|
| `outline` | 选题角度 + 大纲 | 4 个互不重叠的角度（受众 / 钩子 / 凭什么站得住）+ 选定角度 + 分节大纲 |
| `write` | 按大纲写正文 | 标题 + 摘要 + 2500~4500 字正文 + 结尾引导 |
| `images` | 按正文出配图方案并出图 | 自动决定**画什么、几张、什么比例**，先报价再出图 |
| `adapt` | 长文改写成平台版 | 公众号 / 头条 / 知乎版 |
| `all` | 串起全链路 | 大纲 + 正文 + 图 + 平台版 + 合并稿 + 质检报告，**断点续跑** |
| `cost` | 只算钱 | 预估 token 与点数，一次调用都不发 |
| `models` | 现查在架模型 | 模型清单（免费） |

## 快速开始

**零依赖。** 只要机器上有 Python 3.7+，不需要 `pip install` 任何东西。

```bash
# 1) 到 https://api.a7w.cn/ 注册，创建自己的 API Key
export A7W_API_KEY=sk-你的key        # Windows: $env:A7W_API_KEY="sk-你的key"

# 2) 先算钱（不出网、不花钱）
python3 scripts/run.py cost --platform wechat --sections 5

# 3) 一条命令跑完整条链路（--images 0 = 先不配图，纯文本最便宜）
python3 scripts/run.py all --topic "短视频二创批量出片的产能瓶颈" \
    --platform wechat --images 0 --outdir "%TEMP%\longform-out"

# 4) 看着正文还行，再决定配不配图（不加 --yes 只报价）
python3 scripts/run.py images --article "%TEMP%\longform-out\article.json" \
    --platform wechat --count 2 --budget 50 --yes --outdir "%TEMP%\longform-images"
```

产出目录（**一定在包外**）：

```
longform-out/
├── outline.md / outline.json      选题角度 + 分节大纲
├── article.md / article.json      正文四件套
├── longform.md                    合并稿，可直接发
├── AUDIT.md / audit.json          质量与合规自检报告
└── longform-state.json            断点文件（原样重跑即可续；出图断点含提示词内容，改提示词会重出重扣）
```

## 八道本地硬闸门（都是拦截，不是警告）

| # | 闸门 | 拦什么 | 退出码 |
|---|---|---|---|
| 1 | 合规 | 广告法违禁词 + 站外导流 / 标题党 | 3 |
| 2 | 占位符残留 | `{}` / `[待填]` / `XXX` / `（此处省略）` | 3 |
| 3 | `prompt_echo` | 照抄提示词里的示例 | 3 |
| 4 | 字数区间 | 不在平台区间（**不替你截断**） | 3 |
| 5 | 结构完整性 | 缺标题 / 缺正文 / 没分节 / 缺结尾引导 | 3 |
| 6 | 出图比例真伪 | 接口自报与**真实像素**不符 | 3 |
| 7 | 成本上限 | 超 `--budget` | 3 |
| 8 | `--outdir` 落包内 | 产出图进包（上传必 400） | 2 |

闸门判定**全部在本地做确定性判定**，不采信模型自评（"我检查过了"不算数）。

## 三条实测记下来的口径

1. **`/chat/completions` 的成功响应不带 `code` 字段**，直接读 `choices[0].message.content`；
   `{"code":1,"data":{...}}` 那层信封是给生成应用的。别拿 `code == 0` 判成功。
2. **出图任务的 `status` 在 `data` 顶层，不在 `data.result` 里。** 平台文档写的是
   `data.result.status`，照文档写会永远读不到状态、一路轮询到超时。
   实际扣费只信 `data.usage.points_cost`。
3. **`deepseek-chat` 不在 `/api/v1/models` 的返回列表里，但实测可用**（路由到
   `deepseek-flash`）。所以"列表里没有"不等于"不能用"。

### 出图比例：上游按 32 对齐，一半的比例给不出精确值

上游不是按比例给像素，而是先定总像素、再把每边向下取整到 32 的倍数。实测（1K 档）：

| 请求 | 实测像素 | 实得比例 | 偏差 |
|---|---|---|---|
| `1:1` | 1024x1024 | 1.0000 | 0.00% |
| `4:3` | 1184x864 | 1.3704 | 0.00% |
| `3:2` | 1248x832 | 1.5000 | 0.00% |
| `2:3` | 832x1248 | 0.6667 | 0.00% |
| `21:9` | 1536x672 | 2.2857 | 0.00% |
| `16:9` | 1344x768 | 1.7500 | **1.56%** |
| `9:16` | 768x1344 | 0.5714 | **1.56%** |
| `3:4` | 864x1184 | 0.7297 | **2.70%** |
| `4:5` | 896x1152 | 0.7778 | **2.78%** |
| `5:4` | 1152x896 | 1.2857 | **2.86%** |

本包**只认文件头里的真实像素**，不采信任何返回字段。容差默认 3%，容差内也会
把真实像素与偏差打印出来；要像素级精确就用 `--snap` 本地裁准（裁完再读文件头复核）。

## 成本口径（分两截，别混）

| 项目 | 口径 | 说明 |
|---|---|---|
| 出图 | **实测价 24 点/张**（1K，= 0.24 元） | 两张实测扣费 **48 点**（`usage.points_cost` = 24/张） |
| 出图 2K / 4K | **没有实测价** | 必须用 `--points-per-image` 指定；我们不猜 |
| 文本 | **只出 token，不出金额** | 网关不公布文本模型单价（pricing 表不含文本模型、models 无价格字段、usage 无 points_cost） |
| 文本金额 | 要你自己传 `--yuan-per-ktok` | 传了才算，且明确标成"按你填的单价估算"，不是账单 |
| 币值 | 1 元 = 100 点 | —— |

**真实用量看每次调用返回的 `usage` 与出图任务的 `usage.points_cost`；账单以 api.a7w.cn 控制台为准。**

实测一篇长文的量级：大纲 ~2000 token、正文 ~3300~3900 token、一个平台版 ~4400~4950 token、
配图方案 ~3450 token；**2 张图 = 48 点 ≈ 0.48 元**。

## 参数速查

### 全局

| 参数 | 说明 |
|---|---|
| `--key` | 临时指定 Key。**别写进脚本或文档** |
| `--model` | 默认 `deepseek-chat`（实测可用）。用 `models` 现查在架模型 |
| `--temperature` / `--max-tokens` | 默认 `0.7` / `8192`；正文一次几千字，别调低 |
| `--budget` | 上限。出图按**点**、文本按 `--yuan-per-ktok` 折算；超了就地停，退出码 3 |
| `--yuan-per-ktok` | 文本单价（元/千 token）。**默认不折算金额** |
| `--json` | JSON 输出，**写在子命令前后都行**；stdout 只有一个完整 JSON |
| `--out <文件>` | 把结果写到文件（**是文件不是目录**） |
| `--dry-run` | 只打印将发送的提示词，不调模型不花钱 |

| 子命令 | 关键参数 |
|---|---|
| `outline` | `--topic`(必填)、`--platform`、`--angles`(默认 4)、`--sections`(默认 5)、`--audience`、`--requirements`、`--tone` |
| `write` | `--outline`(必填)、`--from-file`(闸门复检)、`--trust-chars`(闸门自检) |
| `images` | `--article`、`--platform`、`--count`、`--ratio`、`--resolution`、`--points-per-image`、`--budget`、`--yes`、`--outdir`、`--snap`、`--local-image` |
| `adapt` | `--article`(必填)、`--platform`、`--all-platforms`、`--chars-min` / `--chars-max` |

| `cost` | `--platform`、`--sections`、`--images`、`--all-platforms`、`--points-per-image`、`--budget` |

### 三个平台的口径（`--platform` 改了什么）

| 平台 | 正文字数区间 | 建议配图 | 出图比例 | 结构口径 |
|---|---|---|---|---|
| `wechat` 公众号 | 2500~4500 | 2~5 张 | 16:9 | 开头钩子 + 3~6 个小节 + 结尾引导 |
| `toutiao` 头条 | 1800~3500 | 3~6 张 | 16:9 | 结论前置 + 分点展开 + 结尾引导 |
| `zhihu` 知乎 | 2500~6000 | 1~4 张 | 4:3 | 先给判断 + 依据与边界 + 结尾引导 |

字数按"去掉 Markdown 符号与空白后的字符数"算，中英文都按字符算。

## 退出码

| 退出码 | 含义 |
|---|---|
| `0` | 全部干净，闸门全绿 |
| `2` | **用法错误**（`--outdir` 落在包内 / 参数写错） |
| `3` | **被闸门拦下**（违禁词 / 占位符 / 照抄示例 / 字数越界 / 结构残缺 / 比例不符 / 超预算） |
| `4` | 调用失败（网络 / 鉴权 / 点数 / 模型名），或出图没给 `--yes` |
| `130` | 用户中断（Ctrl+C） |

`--json` 模式下，失败时会输出 `{"ok": false, "exit": <码>, "error": {"kind":…, "message":…}}`；
如果本次已有产出要报，则把 `exit` / `error` **并入**结果主体，**stdout 始终只有一个 JSON 文档**。

## 三个实测踩到的坑（写在这里免得你再踩）

1. **模型会贴着字数下限走。** 只写"落在区间内"时，实测 5 次里有 3 次写下限少 5%~10%，
   被闸门四拦下。本包已在提示词里明确"瞄准区间中上段、宁可比下限多两百字"，
   但仍偶有偏短 —— **偏短就重跑一次，脚本不会替你硬凑**。
2. **断点不能只看状态标记。** 手工改坏 `article.json` 之后重跑，如果只信状态就会
   被当成"已完成"直接跳过，闸门变假绿。所以本包的断点命中要求**状态 ok 且产出文件本身合格**。
   同一个道理也用在出图上：出图的断点记录里存着上次的提示词，**跟本次对不上就直接重出**，
   绝不复用旧图。提示词改一个字就重出重扣（内容变了就该重做，这是设计如此）；反过来，
   改过后半段也**不会**被静默当成同一张图 —— 静默复用过期产物，比多扣一次费难发现得多。
3. **配图提示词里不能提"文字"。** 文生图模型会把中文字画成乱码，所以
   `images` 的出图提示词由闸门二/三先扫一遍，命中就直接**不提交任何任务**（不花一分钱）。
