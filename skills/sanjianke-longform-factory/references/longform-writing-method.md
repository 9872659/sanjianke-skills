# 长文写作方法与判定口径

本文件是 `outline` / `write` / `adapt` 三个子命令背后的方法说明，以及**每一步的判定口径为什么这么定**。
所有阈值都不是拍脑袋来的，凡是实测标定过的都标了出处。

---

## 一、为什么先出「选题角度」再出大纲

给一个主题直接让模型写大纲，它会给出一份**看起来合理**的大纲：是什么 / 为什么 / 怎么办，
每节字数均匀，四个小标题都以主题词开头。这份大纲的问题不是质量差，是**没有取舍**——
它把话题的所有常规切面平铺了一遍，读者看标题就知道内容，没有点开的理由。

所以本包把 `outline` 拆成两段：

1. **先要 4 个互不重叠的角度**，每个角度必须给出四件东西：

   | 字段 | 要回答的问题 | 不合格的形态 |
   |---|---|---|
   | `angle` | 从哪个切面写 | 「谈谈 XX 的重要性」（无切面） |
   | `audience` | 写给谁 | 「所有对 XX 感兴趣的人」（等于没写） |
   | `hook` | 读者为什么会点开 | 「很有价值」（空话） |
   | `why_me` | 凭什么这篇站得住 | 「我很有经验」（不可核） |

2. **再从中选一个**写进 `chosen`，然后才展开成分节大纲。

`outline` 的结构校验会逐项核对上面四项，并且要求：

- 角度数 ≥ 2（只有 1 个不叫选题），给了 `--angles` 就按指定数核对
- 每个角度的 `angle` 不少于 6 个字（少于 6 个字基本是空话）
- 每个角度都要有 `hook`
- 必须有 `chosen`（模型没说最后写哪个角度，等于没做取舍）
- 分节 ≥ 3，每节要有标题、要点、正数计划字数
- **分节计划字数合计要落在目标平台的字数区间内**

最后一条容易被忽略但很重要：大纲阶段就把总量定在区间内，正文才有机会一次写够。
大纲自己就超区间的话，正文一定会被闸门四拦下。

### 反模板污染：小标题不许都以主题词开头

提示词里写了一条硬约束：**以主题词开头的分节不超过一半**。
原因是大模型有一个很强的倾向——把"短视频二创"这个主题词塞进每一节标题：

> 短视频二创的素材管理 / 短视频二创的模板使用 / 短视频二创的审片流程 / …

这种大纲读起来完全正常，但它是一份**填空题**：换掉主题词就能套到任何领域。
所以提示词要求其余小节用具体做法、场景或对象命名。

## 二、正文的四件套与字数口径

### 四件套

`write` 的产出必须齐这四样，缺一项结构化校验标红：

1. **`title`** —— 具体到读者能判断"这篇是不是写给我看的"。
   泛题有专门的判据（`GENERIC_TITLE_RE`）：`关于XX的思考 / 浅谈XX / 随便聊聊 / 杂谈`。
2. **`summary`** —— 30~70 字，用于平台摘要位。
3. **`content`** —— Markdown 正文，从 `## 第一个小标题` 开始。
4. **`ending`** —— 结尾引导那一句，单独再给一份，方便别的流程单独取用。

### 字数为什么按「字符数」而不是「汉字数」算

`count_chars()` 的口径是：**去掉 Markdown 符号与空白之后剩下的字符数**，中英文一律按字符算。

不按汉字数算的理由：长文里中英混排、数字、代码块、URL 都很常见。
只数汉字的话，一段 400 字的英文说明会被算成 0 字，判定会比实际情况宽松得多——
而平台折叠是按**视觉长度**来的，不是按汉字个数。

去掉的 Markdown 符号集是 `#*>`-[]()|~` 与空白。**不去掉中文标点**，
因为中文标点占字宽，平台也算。

### 分节判据

`content` 里的小节数取下面两者的**较大值**：

- `^#{2,4}\s+\S`：Markdown 二到四级标题
- `^\s*(?:\d{1,2}[.、)]|第[一二三四五六七八九十]{1,3}[节部分])`：数字或中文编号小节

要求 ≥ 3 节。**没有分节的长文没法读，也没法被截图转发。**

### 结尾引导的判据（含一处实测修正）

判据是：**正文最后 5 个非空行**或 `ending` 字段里，出现下面任一词：

`关注 / 在看 / 转发 / 收藏 / 点赞 / 留言 / 评论 / 订阅 / 追更 / 分享 / 点个 / 加个星标 / 下篇 / 下一篇`

**实测修正记录**：一开始只取 `body.split("\n")` 的**原始最后 3 行**，结果真机跑 `adapt`
时出现假阴性——模型在结尾用小标题或列表收尾，最后 3 行正好是列表项，而引导句是列表的父级那一行。
真实产出被打回，用户要为此重跑一次。
修法是两条：① 先 `strip()` 掉每行再筛非空，取最后 **5** 行；② 同时看 `ending` 字段
（模型本来就单独产出这一句，它是最权威的信号）。

### 字数为什么必须由脚本自己数

`write` / `adapt` 都是一次吐几千字。**只要采信产出侧自报的字数，闸门就会变成假绿**：
一份声明 `chars: 4000`、实际只有几十字的产出会顺利过关。

所以字数字段一律由脚本自己数（`count_chars`），产出侧的 `chars` 只用于对照。
`write --trust-chars` 这个开关存在的唯一目的，就是**故意采信自报值**来演示这道闸门真的会拦。

## 三、实测：模型会贴着字数下限走

这是本包实测最值得记下来的一条。

`deepseek-chat` 在"公众号 2500~4500 字"这个要求下，连续 5 次实测的字数分布：

| 次 | 字数 | 是否过闸门 |
|---|---|---|
| 1 | 2400 | ❌ 低于下限 100 字 |
| 2 | 3223 | ✅ |
| 3 | 2373 | ❌ |
| 4 | 2332 | ❌ |
| 5 | 2697 | ✅（但命中违禁词） |

**5 次里 3 次写下限少 4%~7%。**

处理方式（两面都做）：

1. **提示词侧**：明确写"瞄准区间中上段，目标 N 字左右，宁可比下限多两百字，也不要少写"。
   加上这条之后实测确实改善，但仍偶有偏短——模型对字符数的感知本来就不精确。
2. **闸门侧**：偏短就拦下并**如实报出字数**，不替你硬凑、不偷偷截断。
   重跑一次的成本约 3300~3900 token，比"发一篇撑不起来的文章"便宜得多。

> 想省这一次重跑的钱，可以在 `--outline` 阶段就把 `--sections` 调大一点
> （比如 6 节而不是 5 节），让大纲的 `planned_chars` 落在区间中上段。

## 四、平台适配（`adapt`）≠ 复制粘贴

`adapt` 是**重写**，不是搬运。三个平台的口径差别是结构性的：

| 平台 | 字数区间 | 结构口径 | 读者行为 |
|---|---|---|---|
| 公众号 | 2500~4500 | 开头钩子 + 3~6 个小节 + 结尾引导 | 从订阅里点进来，愿意读完 |
| 头条 | 1800~3500 | **结论前置** + 分点展开 + 结尾引导 | 信息流里只看前两屏 |
| 知乎 | 2500~6000 | **先给判断** + 依据与边界 + 结尾引导 | 带着具体问题来，看推理链 |

改写约束写在提示词里：

- **保留原文的核心观点与事实**，不许新增原文没有的数据、案例与结论
- 标题按目标平台重写（头条的标题要 3 秒读懂）
- 结尾引导要合平台调性
- 遵守同样的底线：不编数据、不编人名机构、不做效果承诺、不留待补空档
- 产出里要有 `changed` 字段，逐条说明**改了什么**——方便人工核对有没有改坏

`adapt` 的产出同样过全部本地闸门（违禁词 / 占位符 / 照抄示例 / 字数区间 / 结构）。

> **实测提醒**：知乎的下限是 2500 字，而改写往往会**压缩**原文。
> 实测一次"公众号 3223 字 → 知乎"改出了 2488 字，差 12 字被闸门四拦下。
> 这是闸门按设计工作，不是误报。要么让原文长一点再改，要么用 `--chars-min` 显式下调下限。

## 五、配图方案是怎么定下来的

`images` 不是"每篇文章配 3 张图"这种固定规则，而是**读正文再决定**。提示词里给模型的信息是：

- 文章标题、目标平台、平台建议张数区间、统一出图比例
- **正文的小标题清单**（让它知道文章分了几块）
- 正文节选（最长 6000 字）

要求每张图给出：

| 字段 | 要回答的问题 |
|---|---|
| `role` | 这张图是干什么的（`cover` / `flow` / `compare` / `data` / `scene` / `quote` / `ending`） |
| `why` | **这张图解决正文的哪个问题**（要写清对应哪一节/哪一句） |
| `prompt` | 可直接提交给文生图模型的中文提示词 |

`prompt` 的硬约束（都来自实测教训）：

- 写清主体、场景、光线、构图、风格；**不写尺寸数字**（尺寸由 `aspect_ratio` 参数控制）
- **不许出现任何文字、字幕、水印、logo 的描述**——文生图模型会把中文字画成乱码
- 数据图只许画正文里**真实出现过**的数字，不许自己造数

### 张数是建议档，不是硬闸门

平台建议张数（公众号 2~5 / 头条 3~6 / 知乎 1~4）只作为提示词输入：

- 少于下限 → 记一条 `notice`，**不判失败**（正文短的时候 1 张图是合理的）
- 多于上限 → 记一条 `notice`，**不判失败**（多画一张属创作自由，脚本只按实际张数计费）
- **一张都没有 → 硬失败**（配图方案是空的说明这一步没做成）

`--count` 才是**真闸门**（它直接决定花多少钱）：传了就把方案截断到前 N 张。

### 出图前的两道自检

在提交任何任务（也就是花任何钱）之前：

1. **正文自身先扫一遍**（闸门一/二/三）：正文里有违禁词或占位符，就别基于它配图
2. **每张图的提示词再扫一遍**（闸门二/三）：命中就**不提交任何任务**

这两道是"零成本拦截"：不通过时一分钱都不花。

## 六、断点续跑的两个条件

`all` 的断点 key 是"阶段 + 内容标识"。命中跳过要求**两个条件同时成立**：

1. 状态文件里这个阶段的 `ok` 为真
2. **对应的产出文件存在，且文件里的内容本身也合格**

第 2 条是实测补上的。只信状态的话会出这种事：
手工把 `article.json` 里的正文改坏（比如改出一个违禁词），然后原样重跑——
状态说"正文已完成"，脚本直接跳过，闸门**从这一步开始就是假绿**，
后面的配图和平台适配全都基于一份已经不合格的正文。

所以本包的 `cmd_all` 在跳过正文前会重新读 `article.json` 并检查 `article.ok`；
不合格就**不跳过、重新生成**，并在 stderr 明确打印：

```
[2/4] 断点说正文已完成，但文件里的正文不合格 → **不跳过**，重新生成
```

改内容会不会导致重复扣费？会，而且这是设计如此：内容变了就该重做。
想省钱就别改，直接重跑即可全部跳过。

**出图那一档多一条**：出图的断点记录里存着上次的提示词，跟本次对不上就直接重出
（提示词改一个字就重出重扣）。反过来说，改过后半段也**不会**被静默当成同一张图 ——
静默复用过期产物比多扣一次费难发现得多。想强行重出用 `--force`。

## 七、一篇长文的生产成本（实测量级）

| 阶段 | 调用 | 实测 token（prompt / completion） |
|---|---|---|
| `outline` | 1 次 | 755 / 866~1272 |
| `write` | 1 次 | 1111~1293 / 1925~2611 |
| `images`（方案） | 1 次 | 2935 / 513 |
| `adapt` × 3 | 3 次 | 2325~2334 / 2060~2106（每次） |
| `all` 全链路合计 | 6 次 | **11309 / 10291 = 21600 token** |
| 出图 | 2 张 | **48 点 = 0.48 元**（实测扣费 24 点/张） |

**文本金额不折算**：网关不公布文本模型单价，要金额就自己传 `--yuan-per-ktok`。
出图金额按实测价算，实际扣费以任务返回的 `usage.points_cost` 为准。
