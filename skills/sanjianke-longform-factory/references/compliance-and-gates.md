# 合规红线与八道闸门判据

本文件写清两件事：**哪些内容不能写**，以及**八道闸门具体怎么判、为什么这么判**。
所有阈值都标了标定依据；凡是从同族包的实测事故里继承来的，都注明了出处。

> **免责声明**：内置违禁词表与判定口径是**启发式自检工具**，来自公开经验整理，
> 不构成法律意见，也不代表任何平台的官方审核标准。
> 发布前请人工复核；医疗健康、金融投资、母婴、特殊化妆品等高风险类目**必须**人工复核。

## 一、合规红线（闸门一）

违禁词表在 `run.py` 的 `BANNED_PATTERNS`，每行是「正则 → 风险等级 → 人话解释」。
按风险等级排序输出，高风险的排前面。这是**粗筛**，宁可多报也别漏报。

### 广告法绝对化用语（高风险）

| 类别 | 拦截形态 |
|---|---|
| 最高级 | `最好 / 最佳 / 最优 / 最低 / 最便宜 / 最快 / 最强 / 最大 / 最高 / 最先进 / 最新 / 最流行 / 最受欢迎 / 最顶尖` |
| 绝对化价格 | `全网最低 / 全网最便宜 / 史上最低 / 全国最低 / 全国第一` |
| 排他性排名 | `全国第一 / 全球第一 / 行业第一 / 销量第一 / 口碑第一 / 人气第一 / 第一品牌 / 排名第一 / No.1 / TOP 1` |
| 权威性词汇 | `国家级 / 世界级 / 全球级 / 国际级 / 国家级产品` |
| 绝对化承诺 | `100% / 百分之百 / 百分百`；`绝对有效 / 绝对安全 / 绝对放心 / 绝对正确 / 绝对专业`；`保证有效 / 保证成功 / 保证学会 / 保证通过 / 保证就业 / 无效退款` |

### 「最 X」的可枚举上下文豁免（**这一条必读**）

「最」在正常中文里到处都是，一刀切会把好文章全拦下。

**实测事故出处**（继承自同族课程包）：真机连跑 4 次讲义，1 次被拦，拦下的是

> 做菜和剪辑**最大**的共同点是：先做减法，再做加法

这是在讲一件常识，不是给商品贴"最大"的标签。长文里的形态更常见：

> 长文和短视频**最大**的区别是…… / 新手**最**容易踩的坑是……

这些是文章的正文骨架，拦下来的代价比漏报更大。

**豁免规则**：命中以「最」开头，**且**后文（允许夹一个「的」）落在下面这张可枚举表里：

```
不同 / 区别 / 差异 / 共同 / 相同 / 相似 / 常见 / 容易 / 重要 / 关键 / 主要 /
先 / 后 / 基本 / 简单 / 难 / 麻烦 / 省事 / 常用 / 合适 / 适合 / 保险 / 稳妥
```

→ 判为普通用法，放行。

**⚠️ 句首不许误豁免。** 第二个条件：命中处前面只有空白、或前一个非空白字符是
句末标点（`\n 。！？!?；;：:`）时，**视为句首 → 不豁免**。

因为「最大区别是……」这种**句首**写法经常正是标题式的最高级宣称。
两个条件缺一不可。

**反例（仍然照拦）**：`最好的工具` / `最强` / `最高级` / `最大优惠` —— 后文不在豁免表里。

**同类修正的另一例**：排他性规则原来写成裸的 `唯一`，而真机跑习题时模型在题干里写了
「判断一段画面是不是废片，**唯一标准**是够不够清晰稳定」——
这是把"唯一"当普通词用，属必然误伤，已收紧为
`唯一(选择|指定|授权|官方|认证|品牌|推荐|渠道|合作)`。

### 命中判定的粒度

同一个词可能在文中出现多次（一次是广告语、一次是普通用法），
所以命中判定**按每一处出现**做：任一处未被豁免就算命中。

## 二、占位符残留（闸门二）

长文是大模型一次吐几千字，模板没替换干净的形态比短文本多得多。六条正则：

| 形态 | 正则要点 | 为什么 |
|---|---|---|
| `{}` / `{{标题}}` | `\{\{?\s*[\u4e00-\u9fffA-Za-z0-9_]*\s*\}?\}` | JSON 骨架被当正文写进去了 |
| `[待填]` / `[填空]` / `[待补充]` / `[待完善]` / `[待定]` | `[\[【(（]\s*(待填\|填空\|待补充\|待完善\|待定)\s*[\]】)）]` | 模型给自己留的空档 |
| `[略]` / `[此处省略]` | `[\[【]\s*(略\|此处省略)\s*[\]】]` | 省略标记 |
| `（此处省略）` | `[(（]\s*此处省略[^)）]{0,12}[)）]` | **最常见的一种**：模型懒得写，直接省略 |
| `XXX` / `xxx` | `(?<![A-Za-z0-9])X{3,}(?![A-Za-z0-9])` | 忘了替换的占位 |
| `待补充` / `待完善` / `后续补充` / `此处略` / `TODO` / `TBD` | 字面量 | 内容没写完 |

### 为什么括号那条只认枚举词

`[1]`（引用序号）、`[图 2]`（配图位）是**完全正常**的写法。
一刀切按"括号里有内容"判，会把好文章全拦下。
所以只在"括号里是个占位词"时才判命中。

本包的显式要求点名了 `[待填]`，所以枚举表里必须有它。

## 三、`prompt_echo`：照抄提示词示例（闸门三）

### 事故复盘（两次都真被抓到，出自爆款标题工坊）

1. 提示词里写过正例 `结论先说：便携榨汁杯不适合三类人` → 模型直接产出近似句
2. 提示词里留过 `便携榨汁杯不适合这三类人，理由有三个` → 公众号那一轮
   **最高分 89.0 的标题一字不差就是它**

第 2 例性质更重：最高分那条是"抄了标准答案"，不是"真的最好"，
而排序是那个包的核心产出。**哪怕示例明确标着"这是错的"，模型照样照抄。**

### 本包的形态

示例小标题或示例开头句被照抄 → 整篇文章变成"把示例换个主题词"，
段落顺序、句式全部雷同。**看起来完全正常，直到你发现它是模板填空题。**

### 三条命中路径（任一即命中）

| 路径 | 判据 | 抓什么 |
|---|---|---|
| 1 | 去标点后**完全相同** | 最直接的照抄 |
| 2 | 字符二元组 **Jaccard ≥ 0.75** | 长度相当的同构改写 |
| 3 | 示例的二元组**覆盖度 ≥ 0.60** | 长文里夹带示例 |

归一化：只留中文、字母、数字，丢掉所有标点与空白
（抄示例往往只改标点 `，`↔`、`↔空格，所以必须先抹平）。

### 阈值标定依据

- **0.75**：标题工坊实测 196 条正常产出与跨主题示例的最高相似度只有 **0.174**，
  而"少两个字的同构照抄"是 **0.765**。0.75 既能兜住轻改写，离正常上限还有 4 倍余量。
- **0.60（覆盖度）为什么必需**：Jaccard 在两个长度差几十倍的对象之间会被**稀释**。
  实测把一条 40 字的示例原样塞进一份 2400 字的讲义，Jaccard 只有 **0.171**
  （远低于 0.75，**侥幸放行**），因为分母是两份二元组的并集，产出那一侧把相似度摊平了。
  覆盖度只看"示例被抄了多少"，不看产出有多长：同一次照抄的覆盖度是 **1.00**，
  而真实讲义对这条示例只有 **0.05**。
  **长文比讲义更长（2500~4500 字），稀释只会更严重，所以这条对本包是必需的。**
- **长度守卫用相对阈值** `max(6, len(示例)//2)`：目标归一化长度小于它时就不比相似度与覆盖度
  —— 短串的二元组太少，指标会虚高。用绝对阈值 12 会让短示例漏掉「≤11 字的截断照抄」；
  本包示例 18~40 字 → 门槛 9~20。四个同族包逐档实测（对每条示例做逐字截断，共 321 档）：
  相对阈值比绝对 12 多抓 5 档、少抓 0 档。

### 治本的一面在提示词侧

**提示词里不许出现任何一份可直接复制的完整产出。**
举例一律用登记在 `PROMPT_SAMPLES` 里的**跨主题**示例，与真实业务明显不搭：

```
为什么养殖户开始用无人机看蚝排
手工木工为什么先学磨刀而不是学开料
业余天文爱好者第一次买赤道仪会后悔的三件事
先把结论放在第一段，再用三个要点展开，最后给一句能带走的话
```

模型不会把"蚝苗"这种词搬进"短视频二创产能"的文章里。
万一以后有人把真实示例加回提示词，`PROMPT_SAMPLES` + 这道闸门会兜住。

**新增示例必须登记到 `PROMPT_SAMPLES`。**

## 四、字数区间（闸门四）

按平台口径校验产出侧数字数。详见 `platform-specs.md`。

关键行为：**超出的部分不偷偷截断**，让用户自己决定删哪句。
偏短就拦下并如实报出字数，不硬凑。

`--trust-chars`（`write`）是**故意采信产出侧自报值**的开关，
用来演示"声明 4000 字、真实只有几十字"会被抓出来 —— 也就是闸门假绿的反例。

## 五、结构完整性（闸门五）

文章是要发出去的，半截稿子比没稿子更糟。逐项校验，缺项标红：

| 检查项 | 判据 | 不合格的形态 |
|---|---|---|
| 有标题 | 标题非空 | 空标题 |
| 标题不是泛题 | 不匹配 `^(关于.{2,12}的(一些)?(思考\|想法\|看法\|总结)\|浅谈.{2,12}\|随便聊聊\|杂谈)$` | 「关于效率的思考」 |
| 有正文 | 去符号后字符数 > 0 | 空正文 |
| 正文有分节 | `#{2,4}` 标题或数字/中文编号小节，取较大值 ≥ 3 | 一整段到底 |
| 有结尾引导 | 最后 5 个非空行或 `ending` 字段里有引导词 | 「感谢阅读。」 |

引导词表：`关注 / 在看 / 转发 / 收藏 / 点赞 / 留言 / 评论 / 订阅 / 追更 / 分享 / 点个 / 加个星标 / 下篇 / 下一篇`

### 实测修正：结尾判定的一处假阴性

一开始只取 `body.split("\n")` 的**原始最后 3 行**。
真机跑 `adapt` 时出现假阴性：模型用小标题或列表收尾，最后 3 行正好是列表项，
而引导句是列表的父级那一行。真实产出被打回，用户要为此重跑一次。

修法两条：① 先 `strip()` 掉每行再筛非空，取最后 **5** 行；② 同时看 `ending` 字段
（模型本来就单独产出这一句，它是最权威的信号）。

### 大纲结构校验（闸门五的前半段）

`outline` 阶段单独一套，`write` / `images` / `adapt` 载入大纲时会**再跑一遍**：

| 检查项 | 判据 |
|---|---|
| 有选题角度 | ≥ 2 个 |
| 角度数符合 `--angles` | 给了就按指定数核对 |
| 角度不是空话 | 每个 `angle` ≥ 6 字 |
| 每个角度有钩子 | 每个都有 `hook` |
| 选定了唯一角度 | 有 `chosen` |
| 有分节 | ≥ 3 节 |
| 分节数符合 `--sections` | 给了就按指定数核对 |
| 每节都有小标题 / 要点 / 正数计划字数 | 逐项 |
| 计划字数落在平台区间 | 合计在区间内 |

**为什么要再跑一遍**：大纲是 JSON 文件，**手工改坏它是最容易被忽略的失败入口**。
拿一份结构残缺的大纲去写正文，等于把错误放大到几千字。不合格直接退出码 3。

## 六、出图比例真伪（闸门六）

**只认文件头里的宽高**，不采信任何接口/模型自报的 `aspect_ratio`。
读法是 `imgprobe.image_size()`（纯标准库 `struct`，支持 PNG/JPEG/GIF/WebP）。

### 为什么不信自报值

教训来自同族包的实测事故：只信模型自报字段的闸门变成**假绿**，
该被判命的那条恰好漏判。出图场景的形态是「接口说 `aspect_ratio=16:9`，真实像素却是别的」。
用户拿去排版才发现全错了。

详细的比例实测表与容差地板见 `platform-specs.md`。

## 七、成本上限（闸门七）

两道：

1. **报价阶段**（提交任何任务之前）：预估点数 > `--budget` → 中断，退出码 3
2. **逐张提交前**：已花 + 待花 > `--budget` → 就地停下，退出码 3

出图不给 `--yes` 时**只报价、不提交任何任务**（退出码 4，`kind=usage`）。
没有可信单价（2K/4K）时**拒绝盲跑**，要求 `--points-per-image`，退出码 3。

文本侧：默认只出 token；要金额必须用户自填单价。

## 八、`--outdir` 不许落在包内（闸门八）

Skill 包的上传白名单只收 `.md .py .txt .json .sh .js .yaml .yml .csv`，
**包内塞一张 png 会让上传直接 400**。

出图是**写操作**，写进去之前就要拦住，不能等用户打完卡再回滚。
判定方式：把 `--outdir` 解析成绝对路径，看它是不是包目录的子路径。
命中 → **退出码 2**（这是用法错误，不是闸门判定，也不是上游失败）。

`images` 的 `--outdir` 与 `all` 的 `--outdir` / `--img-outdir` 都过这道闸门。

## 九、退出码与 `--json` 契约

| 退出码 | 含义 | `kind` |
|---|---|---|
| `0` | 全部干净 | —— |
| `2` | 用法错误（outdir 在包内 / 参数写错） | `usage` |
| `3` | 被本地闸门拦下 | `gate` / `budget` |
| `4` | 调用失败（网络/鉴权/点数/模型名），或出图没给 `--yes` | `call` / `usage` |
| `130` | 用户中断 | `interrupt` |
| `1` | 未预料异常（代码 bug）的兜底 | `internal` |

**`3` 与 `4` 分开是有意的**：`3` = "上游没问题，是被本地规则拦了"，
`4` = "上游/网络有问题，或你还没确认花钱"。CI 里这两种要采取完全不同的动作。

### `--json` 输出契约

- 成功：结果对象里多一个 `"ok": true`；顶层是数组时包成 `{"ok": true, "data": [...]}`
- 失败且**本次有产出要报**：把错误**并入**结果主体
  （`"ok": false` + `"exit": <码>` + `"error": {"kind":…, "message":…}`），
  这样正文、逐条闸门命中原因、配图真实像素这些失败时最需要机读的东西不会丢
- 失败且**本次没有任何产出**：只发独立信封
  `{"ok": false, "exit": 3, "error": {"kind": "gate", "message": "…"}}`
- 两种情况都保证 **stdout 只有一个完整 JSON 文档**，`json.loads` 一次通过
- `--json` 写在子命令**前面或后面都可以**（每个子命令都补了同 dest 的开关，
  用 `default=argparse.SUPPRESS` 保证父级已设的值不被子命令默认值覆盖）
- 人读文案照旧走 stderr；**退出码语义一个都不变**
- 非 `--json` 模式输出与 `--json` 之前完全一致

### 实现上的一处关键设计

`_emit` / `_json_out` 在命令函数里被调用时只能给出 `ok=not bad`，
**还不知道最终退出码**（退出码是 `_main` 兜住异常之后才定下来的）。

如果调用时就写 stdout，`_main` 发现 `rc != 0` 再想补 `error` 字段，
就只能**在同一个 stdout 上再写一份** —— 实测立刻变成两个 JSON 文档，`json.loads` 直接失败。

所以本包把写出**统一推迟**：`_stage_json()` 只暂存，
