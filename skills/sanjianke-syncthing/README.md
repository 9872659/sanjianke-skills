# 三剪客 · 跨设备文件持续同步 Skill

Syncthing：跨设备文件持续同步 的安装、常用命令与避坑要点

---

## 前置条件

- 至少两台设备（Windows / macOS / Linux / NAS 容器均可），且它们在网络上是互通的。
- 每台设备上有一个**专用目录**用于同步，目录所在分区要留足剩余空间。
- 端口可用性：默认 GUI/API 用 `8384`，设备间直连用 `22000`（TCP 与 UDP），本地发现用 `21027`（UDP）。只做内网同步时按需放行；无法直连也能靠中继连通，但速度会明显下降。
- 容器方式需要已装好容器运行时，并能把上述端口映射到宿主。
- 无需注册账号、无需云端 Key。配置目录（含设备证书与管理口令）是唯一需要保护的敏感物。

---

## 使用

最短跑通路径（两台设备，文中记作 A 与 B）：

1. 两台都装好并启动一次，拿到各自的设备 ID：

   ```bash
   syncthing device-id
   ```

2. 在 A 的 Web 界面（默认 `http://127.0.0.1:8384`）里新建一个文件夹，填本地路径与一个文件夹 ID，然后在「远程设备」里加上 B 的设备 ID。
3. 回到 B 的界面，接受 A 发来的共享请求，并为 B 端指定本地路径。文件夹 ID 两端必须一致。
4. 在 A 端往该目录丢一个测试文件，看 B 端是否在几分钟内出现；确认后两边都删掉。
5. 交给服务常驻——`brew services start syncthing`，或发行版自带的用户级 systemd 单元，或容器方式 `docker run -d`。
6. 用 `.stignore` 排除不该跨机同步的目录，并在界面里给文件夹设一个最小可用空间水位。

无头机器上不方便开浏览器时，用子命令和 REST API 操作，例如：

```bash
syncthing serve --no-browser --gui-address=127.0.0.1:8384
curl -s -H "X-API-Key: <APIKey>" http://127.0.0.1:8384/rest/system/status
```

子命令树与 API 端点会随版本演进，动手前先看 `syncthing --help`、`syncthing cli --help` 与官方文档。

## 依赖

- **运行时**：单文件二进制，除操作系统本身外无额外运行时依赖；容器方式依赖容器运行时。
- **磁盘**：同步目录空间 + 配置/索引数据库空间（索引随文件数量增长）；开启版本控制时还会额外占用历史版本空间。
- **网络**：出网能力用于连接中继与全球发现服务器；纯内网环境需要自行配置静态设备地址。
- **可选**：图形化托盘启动器（Windows/macOS 社区包）用于后台常驻与状态提示。
- **无模型、无 API Key 依赖**：本 Skill 不涉及大模型调用或 GPU 算力，纯 CPU 与磁盘 IO。

## 安全

- 不内嵌任何密钥；本 Skill 正文中的所有示例都要求你自己填入口令与 API Key。
- 配置目录里有**设备私钥**（设备身份凭据）和 HTTPS 证书，等于这台设备的身份证：不要提交到版本库、不要打进镜像层、不要随手打包发给别人。
- GUI 默认只监听本机。一旦改成 `--gui-address=0.0.0.0:8384` 或做端口映射，管理面就等于对同网段开放——务必同时设置管理密码，或只绑内网地址并加访问控制。绝不要把 8384 直接暴露到公网。
- REST API 的 `X-API-Key` 权限等同于管理界面，泄露后对方能改文件夹配置；轮换 Key 要同步更新所有调用方。
- 同步是**双向删改传播**的：一端删除会传播到对端。不要把它当备份用，重要数据要有独立的、只增不删的备份。
- 与他人共享文件夹前，确认目录里没有不该外传的文件；共享单元是整个文件夹，没有子目录级权限。
