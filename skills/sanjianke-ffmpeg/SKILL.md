# 三剪客 · 音视频转码与处理

手里有一段视频，要换封装、压小一点、只抽音频、裁一段、拼起来、抽帧做封面——这些事都不需要打开剪辑软件，用一条命令行就能做完，而且能批量、能写进脚本。FFmpeg 就是干这个的：它是音视频处理的底座，绝大多数剪辑/转码软件内部都在用它。

它难的地方不在装，在于**参数组合**：容器、编码器、码率、时间轴，四样东西各自有坑，写错了要么报错要么悄悄失败。这一节把常见的正确写法和高频翻车点摊开写。

**上游项目**：`FFmpeg`　**仓库**：https://github.com/FFmpeg/FFmpeg

## 什么时候用 / 不用

**用它**：

- 视频换容器/换编码（`mp4` 转 `mkv`、`mkv` 转 `mp4`），或者只是想换个能播的封装而不重编码。
- 压缩体积：重编码降码率，或者按目标大小反推码率。
- 只处理音频：抽音轨、转 `mp3`/`wav`、重采样、调音量、拼接音频。
- 裁剪/截取/拼接/变速/旋转/缩放/加水印/加字幕，以及从视频里抽帧、从图片序列合成视频。
- 批处理：一个目录几百个文件，用脚本循环调用它跑，比手工开软件快得多。
- 需要读媒体文件的真实参数（分辨率、帧率、码率、音轨语言、像素格式）来做后续判断。

**不要用它**：

- 你要的是**剪辑工程**：多轨时间线、转场特效、字幕样式编排、反复微调——这类活交给剪辑软件，用命令行做会非常痛苦。
- 你要的是**播放**：它是处理工具，不是播放器。
- 你要做**高质量去噪/修复/超分/变声**这类模型推理：那是 AI 应用的活，命令行滤镜给不了同等效果。
- 目标平台对编码有硬性认证要求（某些硬件播放器只认特定 profile/level）：得先确认规格再压，直接压完发现放不了。
- 只想**转个格式**却对画质/时长/音轨数量敏感：一条 `-c copy` 改封装很安全，一旦重编码就要接受有损，别以为「无脑转一下」没有代价。
- 你的发行版自带的构建缺你需要的编码器（比如没编进某个专利受限编码器）：先换一份构建，别在参数上绕。

## 安装
**Windows（winget）**

```powershell
winget install --id Gyan.FFmpeg -e
```

也有静态构建发行包（GPL / LGPL、static / shared 多种变体），下载解压后把 `bin` 加入 `PATH` 即可。

**macOS（Homebrew）**

```bash
brew install ffmpeg
```

**Debian / Ubuntu**

```bash
sudo apt update
sudo apt install ffmpeg
```

**Fedora / RHEL 系**

```bash
sudo dnf install ffmpeg
```

**Arch 系**

```bash
sudo pacman -S ffmpeg
```

**从源码构建**：需要先有编译环境与目标编码器的依赖库，配置项决定最终能用哪些编码器与滤镜。发行构建各自编进了什么，用下面的命令自己查，别照抄别人的参数：

```bash
ffmpeg -version            # 构建信息与配置项
ffmpeg -encoders           # 本机构建支持的全部编码器
ffmpeg -decoders
ffmpeg -filters            # 本机构建支持的滤镜
ffmpeg -hwaccels           # 支持哪些硬件加速方式
```

**容器方式**：用官方或社区维护的镜像跑，注意把工作目录挂载进去：

```bash
docker run --rm -v "$PWD:/work" -w /work <镜像名> ffmpeg -i input.mp4 output.mkv
```

镜像标签与可用构建以所选镜像的说明为准。

装完先跑 `ffmpeg -version`，把 `configuration` 那一行看一遍——后面所有「参数对不对」的疑问，答案大多在这里。

## 常用操作

下面每条都假设输入文件叫 `input.mp4`、输出叫 `output.*`，可直接改路径替换。

**1. 换封装但不动编码（快、无损、最安全）**

```bash
ffmpeg -i input.mp4 -c copy output.mkv
```

音视频流原样搬过去，只重新封装。前提是目标容器支持里面的编码格式，否则会报错——报错就说明必须重编码。

**2. 重编码为 H.264 + AAC（兼容性优先）**

```bash
ffmpeg -i input.mp4 -c:v libx264 -crf 23 -preset medium -c:a aac -b:a 128k output.mp4
```

`-crf` 是 libx264 的质量参数（数值越小越清晰、体积越大，常用 18~28）；`-preset` 是 libx264 的速度/压缩率权衡（越慢压得越小）。

**3. 只抽音频**

```bash
ffmpeg -i input.mp4 -vn -c:a libmp3lame -q:a 2 output.mp3
ffmpeg -i input.mp4 -vn -c:a copy output.m4a
```

`-vn` 丢掉视频流；`-q:a` 是 libmp3lame 的质量档。第二条只有在原音轨本身就是 AAC 系时才可用。

**4. 截取一段（推荐把 `-ss` 放在 `-i` 前面做关键帧定位）**

```bash
ffmpeg -ss 00:01:30 -i input.mp4 -t 30 -c copy output.mp4
ffmpeg -ss 00:01:30 -i input.mp4 -t 30 -c:v libx264 -c:a aac output.mp4
```

第一条秒开不重编码，但切点会落在关键帧上、不完全精确；要精确切点就用第二条重编码。也可以用 `-to` 指定结束时间，它与 `-t` 互斥且 `-t` 优先。

**5. 缩放 / 裁剪 / 旋转**

```bash
ffmpeg -i input.mp4 -vf "scale=1280:-2" -c:a copy output.mp4
ffmpeg -i input.mp4 -vf "crop=w=1280:h=720:x=0:y=0" -c:a copy output.mp4
ffmpeg -i input.mp4 -vf "transpose=1" -c:a copy output.mp4
```

`scale=1280:-2` 表示宽固定 1280、高按比例自动算并取偶数（`-2` 而不是 `-1`，因为多数编码器要求偶数尺寸）。`transpose=1` 是顺时针旋转 90 度。

**6. 抽帧 / 连成视频 / 生成缩略图**

```bash
ffmpeg -i input.mp4 -vf "fps=1" frames/%04d.png
ffmpeg -i input.mp4 -ss 00:00:05 -frames:v 1 cover.jpg
ffmpeg -framerate 25 -i frames/%04d.png -c:v libx264 -pix_fmt yuv420p output.mp4
```

**7. 提取基本信息做判断（先探测再动手，别猜）**

```bash
ffprobe -v error -show_entries stream=index,codec_name,codec_type,width,height,r_frame_rate,bit_rate -of default=noprint_wrappers=1 input.mp4
ffprobe -v error -show_format input.mp4
```

**8. 直接用硬件编码器（有对应显卡时）**

```bash
ffmpeg -i input.mp4 -c:v h264_nvenc -b:v 6M -c:a copy output.mp4
ffmpeg -i input.mp4 -c:v h264_qsv  -b:v 6M -c:a copy output.mp4
ffmpeg -i input.mp4 -c:v h264_amf  -b:v 6M -c:a copy output.mp4
```

`nvenc` / `qsv` / `amf` / `vaapi` 分别对应不同的硬件加速后端，能不能用取决于本机构建与驱动，先用 `ffmpeg -encoders | grep 硬件关键字` 查。硬件编码快，但同码率画质通常不如软件编码，别默认它更优。

## 常见坑

| 现象 | 原因 | 怎么办 |
|---|---|---|
| `-c copy` 报错说某个流不能被该容器容纳 | 目标容器不支持源编码格式 | 换容器，或对不兼容的那一路单独重编码（用 `-c:v` / `-c:a` 分别指定） |
| 转出来的视频「能播但没声音」 | 音轨没被选进输出，或者音轨编码不被目标容器接受 | 用 `-map 0:a` 显式带音轨（末尾加 `?` 表示没有音轨时不报错），并确认音频编码；先 `ffprobe` 看清有几条音轨 |
| `mp4` 文件要下载完才能播、拖动进度条要等 | `moov` 索引在文件尾部 | 输出时加 `-movflags +faststart` 把索引前置，适合网页播放 |
| 截取出来第一帧是黑的 / 开头有花屏 | `-ss` 放在 `-i` 后面做精确解码时，前面的参考帧不足 | 优先把 `-ss` 放在 `-i` **前面**；要求帧级精确时重编码 |
| 截取时长比要求的短一截 | 用了 `-c copy`，切点只能落在关键帧上 | 需要精确时长就重编码；或者用 `-ss` 前置定位 + 后置微调 |
| 输出体积反而变大了 | CRF 值偏小，或用了 ffmpeg 默认的默认码率策略 | 调大 `-crf`（`libx264` 常用 18~28），或明确指定 `-b:v` |
| 报「height not divisible by 2」之类的尺寸错误 | 缩放后宽高出现奇数，编码器不接受 | 用 `scale=1280:-2`，`-2` 会自动取偶数 |
| 转出来的图/视频发灰、颜色不对 | 像素格式或色彩范围不匹配 | 明确指定 `-pix_fmt yuv420p`（兼容性最好）；色彩空间问题用 `-vf scale=...:out_color_matrix=...` 之类显式处理 |
| 水印/字幕/叠加滤镜报「Cannot find a matching stream」 | 滤镜图里引用的输入流编号没对上 | 多输入时用 `-map` 明确指定，滤镜图里也写清 `[0:v]` `[1:v]` 的对应关系 |
| 加 `-c copy` 做滤镜时报错 | 滤镜必须解码再编码，与流复制互斥 | 用了任何 `-vf` / `-af` / `-filter_complex` 就不能复制那一路流 |
| 硬件编码命令在本机能跑、到服务器上就报找不到编码器 | 服务器构建没编进该硬件后端，或缺驱动 | 先 `ffmpeg -encoders` 确认；没有就退回软件编码 |
| 处理到一半磁盘满了 | 中间过程会产生临时数据，输出文件也在写 | 预估输出体积并留足空间；大批量用脚本串行跑，别同一时刻起几十个进程 |
| 中文路径/文件名在 Windows 上跑批处理失败 | 命令行编码与脚本编码不一致 | 用 UTF-8 写脚本；路径统一加引号；必要时先改到 ASCII 临时目录处理 |
| 日志刷屏看不出哪里错 | 默认日志级别是 info，海量逐帧信息 | 加 `-v error` 或 `-loglevel warning` 压低噪音；调试时用 `-v verbose` |

## 能力边界

**覆盖**：

- 音视频的解复用、解码、滤镜处理、编码、复用全链路，命令行一条跑完。
- 容器与编码格式的转换，流复制（不重编码）改封装。
- 时间轴操作：截取、拼接、变速、首尾对齐；音视频流的选择、丢弃、替换。
- 常用滤镜：缩放、裁剪、旋转、叠加、水印、字幕烧录、像素格式与色彩参数调整、音频重采样与音量处理。
- 配合 `ffprobe` 读取媒体元信息与逐流参数，用于批处理前的判断。
- 硬件加速编解码（取决于本机构建与驱动，如 `nvenc` / `qsv` / `amf` / `vaapi` 后端）。

**不覆盖**：

- 不做剪辑工程：没有多轨时间线、转场编排、字幕样式可视化编辑。
- 不做 AI 类修复/超分/去噪/变声/语音识别，这些靠滤镜给不出同等效果。
- 不做播放、不做媒体库管理、不做转码任务队列与调度（批处理要自己在脚本层做）。
- 不提供编码器的质量调优结论：同码率下不同编码器的画质差异需要你自己压片比对。
- 不保证特定播放器/平台的认证兼容性，需要你按目标规格核对 profile/level。

## 依赖条件

- 操作系统：Windows / macOS / 主流 Linux 均可；也可在容器里跑。
- 安装方式二选一：包管理器安装（省事，但编进的编码器受发行版策略影响）或下载/自行构建静态包（编码器齐全）。
- 磁盘：至少能容纳输出文件与中间临时数据；批量任务要按总量预留空间。
- CPU：软件编码是多核重负载，按并发数评估；硬件编码需要对应显卡与驱动（NVIDIA / Intel / AMD 各自的加速后端）。
- **无模型、无 API Key 依赖**：纯本地音视频处理，不调用大模型服务。
- 需要字体文件时（烧字幕、画文字水印）要保证字体可用且路径正确。

## 已知限制

- 音视频质量与体积是权衡关系：重编码一定是有损的，「无损压缩」只在特定编码与参数下成立。
- `-c copy` 的切点受关键帧约束，精确到帧必须重编码。
- 滤镜处理会强制解码-编码，无法与流复制共存。
- 硬件编码器速度快，但同码率画质一般低于软件编码，且不同驱动版本行为可能变化。
- 不同发行版的构建包含的编码器/滤镜不同，同一条命令换台机器可能就不成立。
- 进度不可中断续跑：长任务中断后需要重跑，脚本层要自己做幂等判断。

## 自检清单

执行前：

- [ ] 先 `ffprobe` 看清输入的流结构（几条音轨、编码格式、分辨率、时长），别凭想象写参数。
- [ ] 确认本机构建支持要用的编码器与滤镜（`ffmpeg -encoders` / `-filters`）。
- [ ] 确认输出路径不会被误覆盖（或明确接受覆盖）。
- [ ] 估算输出体积与剩余磁盘空间，批量任务尤其要算总量。

执行后：

- [ ] 抽查输出：`ffprobe` 看时长、流数量、编码格式是否符合预期。
- [ ] 抽几帧看图/听一段音频，确认没有黑帧、静音、颜色异常。
- [ ] 确认输出文件能正常播放（不是只看命令退出码为 0）。
- [ ] 批量任务记录失败的单个文件，别让一个坏文件中断整批。
