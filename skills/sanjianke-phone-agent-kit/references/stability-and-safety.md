# 稳定性与安全边界

这一份是纪律部分。前面两份教你「怎么接上、怎么调」，这一份说清「什么时候不能做、怎么知道做成了」。

---

## 一、先认清权限的量级

接入之后，Agent 拿到的是**一台真手机的读屏权与输入权**：

- **它能看见屏幕上的一切**。截屏与 OCR 会把屏幕内容送进模型上下文——通知、聊天记录、短信验证码、账号名、余额、订单，看到什么就带什么。
- **它的动作等同于用户本人操作**。点击、滑动、输入会被 App 当作真实用户行为，可能触发真实的发送、下单、扣费、删除、改设置。

所以：

1. **只操作自有或已获明确授权的设备。** 不碰别人的手机，不用于绕过他人设备的访问控制。
2. **敏感界面不要停留在被读取的屏幕上。** 支付、银行、私密聊天、验证码页——能避开就避开，必须经过就把范围压到最小。
3. **不夸大能力。** 它不会「自动搞定一切」：识别不到的图标要人看，锁屏要人解，连接要人连。把它当成一个手很快、但眼睛只认文字、还会误点的助手。

---

## 二、必停清单：这些动作先问用户

| 动作 | 为什么 |
|---|---|
| 发送消息 / 邮件 / 评论 | 一发不可撤回，代表用户的身份 |
| 下单、支付、确认购买 | 直接产生金钱后果 |
| 删除内容、清空数据、卸载应用 | 多半不可逆 |
| 修改任何手机设置 | 影响用户后续所有使用 |
| 登录、绑定、授权第三方 | 涉及账号安全 |
| 提交表单、确认验证码 | 常与账号或交易绑定 |

配套规则：

- **永远不输 PIN、不输密码、不代做解锁。** 手机解锁用的密码只由用户本人输入，也不写进任何文件。
- **永远不点镜像窗口上的 `Connect` / `Continue`。** 手机锁着的时候点它没有用；只有用户本人能连接或恢复。
- **永远不循环轮询等连接。** 连接非 `ready` 时停下、转述提示、等用户确认已处理，然后**只重试一次**。

## 三、验证循环：没有返回值的世界

这里的根本困难是：**没有任何返回值代表「操作成功了」**。adb 对空点一下也报成功；手势发出去和屏幕上真的变了是两件事。所以方法本身就是循环：

1. **先命名「什么该变」。** 一个标题、一行记录、一个用户名、输入框里的内容。说不出来，就无法分辨成功与空操作——而手机上的失败大多是静默的。
2. **做一步，就查那一件事。** 查法随你：`ocr()` 便宜，给出全部可见文字和可点坐标；`screenshot()` 贵一些，但能看到文字之外的一切（图标、图片、某行是否高亮）。循环里用便宜的，卡住或答案本身是视觉的时候再上图。
3. **一段流程验证过之后再打包。** 一次调用跑完整个子任务，比一次一步快得多。但**只能打包已经亲眼看过成功的步骤**，并在结尾留一个廉价检查。
4. **检查失败就隔离。** 把那个单步单独重跑，看一眼屏幕，提一个原因假设，验证它，再调整。不要整段重跑指望它自己好。
5. **把学到的留下。** 可复用的检查和修好的步骤写进 `agent-workspace/agent_helpers.py`，下一个任务起点更高。

**比较方式由你定，不要指望工具替你判定。** 比两次 OCR 的差集、盯一个标签、数行数、比一块裁切、轮询等出现——写符合你这次任务的检查。列表的规则套到信息流上会崩，信息流的规则套到内嵌滚动条上也会崩。

## 四、静默失败清单

| 现象 | 真实原因 | 处置 |
|---|---|---|
| 手势毫无反应 | 焦点被别的窗口抢走 | 先查焦点，别急着换方案；优先用默认后台路径 |
| 列表 / 信息流滚不动 | 用了竖向 `swipe()` | 改用 `scroll()`；横向 `swipe` 仍然可用 |
| `type_text` 后文本不见 | 输入框没聚焦 | 先点那个框，等键盘出现，再输入 |
| 文字被自动改写 | 走了逐键输入 | 用默认的粘贴路径；只有确需真实按键才 `keystrokes=True` |
| 点到别的东西 | 缓存了坐标 | 每次都按当前 `screen_info()` 重新取 |
| 安卓读屏取不到节点 | 界面持续动画，等不到 idle | 改 `screenshot()` 或换到会静止的界面 |
| `scroll_collect` 提前结束 | 提取器漏行 | 先修提取器，再去怀疑滚动 |
| 桌面上点标签无效 | 桌面标签不是点击目标 | 用 `tap_icon()`，图标在标签上方约 35 点 |
| 截屏全黑 | 终端没重启 / 有提示层 / 手机被解锁 | 逐项排除，见 `setup-and-connection.md` |

**共同点**：这些都不报错。觉得「动作发出去了所以应该成了」是这里最贵的错觉，唯一解药是回读屏幕。

## 五、两个硬边界：锁屏与连接

**锁屏**：安卓锁屏后 `tap()` 和 `ocr()` 直接被拒（`screenshot()` 还能用，所以你可以把屏幕拿给用户看）；iPhone 解锁会暂停镜像会话，窗口上会显示「iPhone 在使用中」。

处置只有一条：**停下，请用户解锁或锁屏，然后重试一次。** 没有别的路，轮询不会有结果，也不要试图点掉恢复界面。长任务开始前用 `phone-harness android awake --bg` 把锁屏这件事从变量里去掉。

**连接**：`connection_state()` 给出 `ready` / `blocked` / `no-window` / `not-running`。除 `ready` 外全部是用户侧动作。转述原文、等确认、重试一次。

## 六、节奏与成本

| 动作 | 大致耗时 | 用法建议 |
|---|---|---|
| `wait_for_app` 轮询 | 约 0.1 秒 / 次 | 判断「到了吗」最便宜的方式 |
| `screenshot()` | 约 0.5 秒 | 看图片、看图标、看是否高亮 |
| 安卓无障碍树 `ocr()` / `ui()` | 约 2–3 秒（慢机器更久） | 精确但贵，别在紧循环里反复整屏读 |
| 滚动一步 | 一次手势 | 配合 `scroll_until` / `scroll_collect` 用你的判断收口 |
| 输入 | 一次粘贴或一次按键序列 | 之前必须已聚焦 |

由此得到三条实践：

1. **便宜的判断放前面**：`wait_for_text` / `wait_for_app` 先确认状态到了，再整屏读一次内容。
2. **打包已看过的步骤**，别一步一轮对话。
3. **不重试循环**。同一个失败重复第三次，就停下、看一眼屏幕、说明卡在哪，而不是继续烧时间。

## 七、隐私与数据

- **不内嵌任何密钥**：本 Skill 不含 Key、Token、Cookie，也不代理转发你的请求。
- **屏幕内容会离开你的机器**：读屏结果会进入模型上下文。涉及个人隐私的界面，尽量不进入被操作流程；必须经过时压到最小范围。
- **截图会落盘**：`screenshot()` 产生的图片记得清理，别把敏感画面留在磁盘上。
- **剪贴板会被占用**：`type_text` 默认走粘贴，输入的文字会留在 Mac 剪贴板上，之后别把剪贴板内容当成私密。
- **匿名统计**：上游默认开启，`phone-harness config set telemetry false` 关掉。
- **不采集、不上传、不保存**任何用户数据到本 Skill 里。

---

## 八、合规底线

- 只操作自有或已获明确授权的设备。
- 遵守目标 App 的服务条款与当地法律；自动化操作可能被平台规则限制，风险由使用者承担。
- 不用它批量注册、刷量、绕过风控或验证码——那不是「自动化」而是滥用。
- 上层项目为 MIT 许可；本 Skill 只做原创整理，不含任何第三方源码。
