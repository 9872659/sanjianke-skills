# 三剪客 · 自建 IM 服务端与消息中台 Skill

OpenIM：自建 IM 服务端与消息中台 的安装、常用命令与避坑要点

---

## 前置条件

- 一台资源充足的服务器：这套服务端由网关加一组 RPC 服务组成，并依赖 MongoDB、Redis、etcd、Kafka、MinIO，CPU、内存、磁盘都要留余量。
- 已安装 Docker 与 Docker Compose v2（容器方式）；源码方式另需 Go 工具链、`make`、`jq`。
- 支持 Linux / Windows / macOS，ARM 与 AMD 架构均可。
- 已规划好对外端口：API、WebSocket 长连接、对象存储是客户端必须能访问的三个方向。
- 已想清楚用户 ID 规则与令牌签发放在自己的哪一端业务后端。
- 生产环境需额外准备：域名、网关、限流策略、TLS 证书、监控。

## 使用

1. **先选路径**。最容易复现的是容器方式：`git clone` 仓库，改好 `.env` 参数后 `docker compose up -d`，用 `docker compose ps` 确认状态；需要监控组件时加 `--profile m`。
2. **一键脚本**：`bash install.sh --help` 看清全部参数，再 `sudo bash install.sh -i`；国内网络可用脚本的代理参数加速。默认用户与默认口令见脚本头部注释。
3. **源码方式三步**：`bash bootstrap.sh` 装构建工具并拉依赖 → `make install V=1` 编译安装 → `make check` 自检。构建目标由仓库内 magefile 定义，以实际版本为准。
4. **两侧口令必须对齐**：`.env` 是给容器组件的，`config/` 下是给服务连组件用的。不一致时会表现为"容器全在跑但服务连不上"。组件数据卷一旦按旧口令初始化，改口令前需先停掉并清理组件数据。
5. **对完端口再对接客户端**：默认 API 在 `10002`、WebSocket 在 `10001`、对象存储 endpoint 默认 `127.0.0.1:10005`。`127.0.0.1` 只对本机有效，客户端在别的机器上必须换成可达 IP 或域名。
6. **业务集成**：业务后端用 REST API 管用户、群组、会话与消息推送；需要插入自己的逻辑时编辑 `config/webhooks.yml` 挂钩子。**接口路径与字段随版本变化，以官方接口文档为准。**
7. 完整命令、端口表与排查表见 `SKILL.md`。

## 依赖

- **容器运行时**：Docker + Docker Compose v2。
- **组件**：MongoDB、Redis、etcd、Kafka、MinIO；compose 会一并拉起，也可自备后按 `config/` 填连接信息。
- **源码构建**：Go 工具链、`make`、`mage`（`bootstrap.sh` 会安装）、`jq`。
- **存储**：消息与媒体文件会持续增长，磁盘规划要按业务量留足。
- **网络**：镜像与依赖的下载出网；客户端到 API / WebSocket / 对象存储的入站。

## 安全

- 不内嵌任何密钥；数据库口令、对象存储口令、REST API 管理员密钥均由使用者自行配置。
- 默认口令只适合本地跑通，**上公网前必须全部更换**；`.env` 与 `config/` 不要提交到代码仓库。
- 只暴露必要端口，其余组件端口尽量只在内网可达；API 前置网关与限流。
- 对外服务应启用 TLS，并确认客户端使用的是加密后的连接地址。
- 对象存储的匿名读写策略要单独检查，避免上传目录被公开列举。
- 部署前确认数据目录已持久化到宿主机绝对路径，避免重启或换目录导致数据丢失。
- 日志可能包含用户 ID 与消息元数据，注意采集与留存策略的合规性。
