# 三剪客 · 话题制团队聊天服务器 Skill

自托管一套按「频道 + 话题」组织的团队聊天服务：安装器用法、管理命令、备份升级回滚，以及用 REST API 把通知接进来。

---

## 前置条件

- 一台**干净、专用**的机器或虚拟机。安装器会接管系统包并配置数据库、缓存、队列与反向代理，官方不支持与其他服务混布。
- 受支持的 Linux：Ubuntu 22.04 / 24.04 / 26.04 或 Debian 12 / 13；架构 x86-64 或 aarch64。
- 至少 2GB 内存（不足 5GB 需配 swap，官方建议 2GB）；预计 100+ 用户时 4GB 内存 + 2 核。
- 至少 10GB 专用空闲磁盘，官方建议 SSD。
- 一个在 DNS 里可解析的域名。
- 一套可用的发信 SMTP 凭据（注册确认、通知、密码重置都依赖它）。
- 端口规划：443 对外；80 可选；要用入站邮件集成时开 25；4369 必须用防火墙挡住。

---

## 使用

1. 按 `SKILL.md` 的「安装」一节下载发行包、跑安装器，填好维护者邮箱与访问域名。
2. 用安装结束时打印的一次性链接创建组织与管理员账号（失效可用 `manage.py generate_realm_creation_link` 重开）。
3. 日常运维用 `/home/zulip/deployments/current/` 下的 `manage.py` 与 `scripts/` 脚本；升级、备份、回滚命令都在「常用操作」里。
4. 要把系统通知接进聊天，用 `POST /api/v1/messages`（HTTP Basic，账号邮箱 + API Key），Python 绑定与 `zulip-send` 都可以。
5. 出问题先看「常见坑」表：整机独占、universe 仓库、低内存升级 OOM、配置被覆盖、4369 端口、推送注册都在里面。

---

## 依赖

- 受支持的 Linux 发行版（或官方 Docker 镜像 + Compose / Helm，官方说明容器方式运维成本更高）。
- 应用运行期自带并托管：反向代理、PostgreSQL、Redis、队列服务、缓存、进程管理器（由安装器配置）。
- 发信 SMTP 服务。
- 可选：对象存储（附件后端）、外部视频会议服务、身份提供方（SSO / SCIM）、外部模型服务（AI 功能）。
- 可选：Python 的 `zulip` 包（官方 API 绑定与 `zulip-send` 命令行）或其他语言的客户端库。

---

## 安全

- 不内嵌任何密钥；维护者邮箱、SMTP 凭据、API Key、证书都由使用方配置与保管。
- 4369 端口必须被防火墙挡住（队列依赖的 Erlang 服务无法只绑本机），这是官方明确的安全要求。
- 证书优先用安装器的 `--certbot` 自动申请与续期；自签证书只用于测试或放在反向代理之后。
- 消息不是端到端加密的，服务端以可检索形式保存；涉及高度敏感内容请先评估是否适用。
- 用 `manage.py shell` / `dbshell` 直接改数据会绕过缓存刷新、客户端通知与审计记录，生产环境避免直接 `save()`。
- API 使用机器人或专用账号的 Key，不要复用人账号；Key 不进代码仓库与前端。
- 备份文件包含全部消息与配置，要按敏感数据处理并验证可恢复。
