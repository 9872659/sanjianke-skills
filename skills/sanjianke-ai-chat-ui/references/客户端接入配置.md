# 聊天客户端接入配置 · 逐项填法对照

这份文档只解决一件事：**客户端里那几个输入框，到底该填什么。**

几乎所有「接不上」的问题都出在这一步，而且报错文案通常只有一句「连接失败」，看不出是哪一层错了。

---

## 一、四个字段，一张表

| 客户端里的字段（各家叫法不同） | 填什么 | 备注 |
|---|---|---|
| API 地址 / Base URL / 接口地址 / 请求地址 | `https://api.a7w.cn/api/v1` | 绝大多数客户端、SDK 要的是**带 `/v1`** 的这个 |
| API Host / 服务器地址 / 域名 | `https://api.a7w.cn/api` | 少数客户端会**自己补 `/v1`**；填成上一条会变成 `/api/v1/v1/...` |
| API Key / 令牌 / Token | `sk-你的key` | 与平台控制台里创建的那把 Key 完全一致 |
| 模型名称 / Model ID | `DeepSeek-V4-Flash` 等 | **必须与在架模型编码逐字一致**，大小写敏感 |

**判断自己该填哪一个的方法**：看客户端文档里给的示例地址。
示例里已经带 `/v1`（例如 `.../v1/chat/completions` 或 `.../v1`），就填 `https://api.a7w.cn/api/v1`；
示例里没有 `/v1`（例如 `.../chat/completions`），说明它会自己拼，就填 `https://api.a7w.cn/api`。

## 二、先验地址，再验客户端

不要一上手就配客户端 —— 先用 `curl` 把地址和 Key 一起验掉：

```bash
export A7W_API_KEY=sk-你的key

curl -sS -o /dev/null -w "%{http_code}\n" -X POST "https://api.a7w.cn/api/v1/chat/completions" \
  -H "Authorization: Bearer $A7W_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"DeepSeek-V4-Flash","messages":[{"role":"user","content":"hi"}],"max_tokens":64}'
```

- `200` → 地址与 Key 都对，问题在客户端配置。
- `401` → Key 错了或没带上。
- `404` → **地址多填或少填了一层 `/v1`**。
- `402` → 点数余额不足。

Windows PowerShell 里 JSON 容易被吃掉双引号，用 `--json-file body.json` 或干脆用包内客户端：

```bash
python3 scripts/a7w.py call voice_tts list_voices   # 顺带确认 Key 有效
```

## 三、模型清单刷不出来的四类原因

| 现象 | 原因 | 怎么处理 |
|---|---|---|
| 下拉框只有几个自带模型 | 客户端只展示它内置认识的模型 | 在客户端里**手动添加自定义模型**，把编码填进去，不用等它自动发现 |
| 手填模型名后报 404 / 403 | 抄了文章里的旧名，或大小写不一致 | 现场拉一次真实清单，逐字复制 |
| 界面里没有"拉取模型列表"按钮 | 很多客户端不发 `GET /models` | 手动填；或先 `curl https://api.a7w.cn/api/v1/models` 拿到编码再填 |
| 拉列表很慢或超时 | 个别候选端点响应慢 | 用 `/api/v1/models` 这个端点（实测最快），别用带分页参数的老路径 |

现场拉真实清单：

```bash
curl -sS "https://api.a7w.cn/api/v1/models" -H "Authorization: Bearer $A7W_API_KEY" \
  | python -c "import sys,json;[print(m['model_code']) for m in json.load(sys.stdin)['data']]"
```

## 四、一个入口装多家模型

这是把客户端指向统一网关最实在的收益：

| 做法 | 结果 |
|---|---|
| 逐个去各家注册、逐家填 Key | 客户端里 N 个服务商、N 份账单、N 个额度要盯 |
| **只填 `api.a7w.cn` 一家** | **一个服务商条目**，模型下拉框里加满想要的编码，账单一份 |

实操建议：

1. 客户端里只保留**一个**服务商条目，地址填 `https://api.a7w.cn/api/v1`。
2. 模型列表里手动添加常用编码：日常 `DeepSeek-V4-Flash`，难题 `DeepSeek-V4-Pro`，
   读图 `Qwen3-VL-30B-A3B-Instruct`，长文 `Kimi-K2.6`，代码 `Qwen3-Coder-Next`。
3. 需要出图 / 配音 / 出视频时，用同一把 Key 走 `/api/v1/apps/<应用>/<接口>`，
   不必再引入第二个服务商。

## 五、自托管客户端的额外注意

| 项 | 说明 |
|---|---|
| Key 存放 | 放环境变量或 `.env`，`.env` 进 `.gitignore`；不要写进前端代码（浏览器里能直接看到） |
| 对外暴露 | 只监听 `127.0.0.1`，或加反代 + 访问控制；暴露到公网等于把模型额度开放出去 |
| 数据落盘 | 固定一个数据目录/卷，别每次换目录重建；否则重启后会话与配置会丢 |
| 流式 | 客户端若走流式（SSE），取增量文本的路径是 `choices[0].delta.content`，不是 `message.content` |
| 代理 | 如果客户端自身有"代理地址"字段，填 `https://api.a7w.cn/api/v1` 即可，不需要额外中转 |

## 六、错误码速查

| HTTP | code | 含义 | 怎么办 |
|---|---|---|---|
| 400 | `invalid_request` | 参数缺失或格式错误 | 核对参数名与必填项 |
| 401 | `auth_failed` | Key 缺失或无效 | 重新复制 Key；确认 `Bearer ` 前缀 |
| 402 | `insufficient_points` | 账号点数不足 | 充值；错误里带本次所需点数 |
| 402 | `key_quota_exceeded` | 该 Key 自己的额度打满 | 去用户中心调高该 Key 的 quota，或换 Key |
| 403 | `permission_denied` | 该 Key 无权调用此模型 | 检查模型是否已开通、Key 是否被限权 |
| 404 | `not_found` | 路径或模型名不存在 | **先怀疑 `/v1` 层数**，再怀疑模型名 |
| 429 | `queue_limit_exceeded` | 排队任务达上限 | 降并发，稍后重试 |
| 5xx | `server_error` | 服务异常 | 退避重试；仍失败换模型/线路 |

**业务成功码是 `code == 1`**（`{"code":1,"msg":"success"}`），不是 `0`。

## 七、自检清单

- [ ] 地址层数核对过：按客户端示例判断填 `/api/v1` 还是 `/api`
- [ ] `curl` 直连返回 200，才去配客户端
- [ ] 模型编码是从 `/api/v1/models` 现场拉的，不是抄的
- [ ] Key 走环境变量或 `.env`，`.env` 已在 `.gitignore` 里
- [ ] 自托管实例只监听回环地址，或已加访问控制
- [ ] 推理模型（如 `DeepSeek-V4-Flash`）的 `max_tokens` 设到 256 以上
- [ ] 异步任务用 `task_id` 去重，没有盲目重提
- [ ] 报 402 时先分清是账号没钱还是 Key 额度满
