# 平台通用说明：鉴权、入口、计费、错误码

这份文档是给**聊天客户端接网关**这个场景兜底用的：连接相关的共性事实都在这里，客户端里任何字段配不通时，先回来对一遍。

## 一、鉴权

所有接口共用同一套鉴权，没有第二种：

```
Authorization: Bearer <你自己的 API Key>
Content-Type: application/json
```

要点：

- Key 形如 `sk-...`，在 [算力集市](https://api.a7w.cn/) 用户中心创建。
- **`Bearer ` 后面有一个空格**，掉了就是 401。
- Key 读取顺序（包内脚本）：`--key` 参数 → 环境变量 `A7W_API_KEY` → `~/.a7w/config.json`。
- **Key 等同于余额。** 不要写进代码、不要提交进版本库、不要放前端。
- 每个用途建议单独一把 Key，各自设 quota 与 IP 白名单 —— 出事时损失可控、来源可查。

## 二、两条调用入口

这是全部接口的顶层分叉，**选错入口是最常见的踩坑**：

| 入口 | 路径 | 形态 | 用途 |
|---|---|---|---|
| **模型网关**（OpenAI 兼容） | `POST /api/v1/chat/completions` | 同步，直接返回 `choices` | 对话、写作、翻译、分类、抽取、代码 |
| **应用任务** | `POST /api/v1/apps/<应用代号>/<接口代号>` | 多为异步，返回 `task_id` | 出图、出视频、配音、数字人、音乐、超分 |

对照记忆：

- **模型网关没有 `task_id`。**
- **应用任务不吃 `messages` 数组。**
- 应用任务的路径**永远**是 `/api/v1/apps/<应用代号>/<接口代号>`，两个代号都取自线上返回的 `code` 字段。**绝对不要用 `endpoint_path` 字段拼 URL。**
- 应用代号用**下划线**（`voice_tts`），不是连字符（`voice-tts` 会 404）。

### 地址层数：`/api/v1` 还是 `/api`

同一个平台，两种填法都对，取决于客户端**会不会自己补 `/v1`**：

| 客户端文档里的示例地址 | 填什么 |
|---|---|
| 示例里已经带 `/v1`（例如 `.../v1/chat/completions`） | `https://api.a7w.cn/api/v1` |
| 示例里没有 `/v1`（例如 `.../chat/completions`） | `https://api.a7w.cn/api` |

**判断方法只有这一条**：看它给的示例。填错的典型症状是 `.../api/v1/v1/...` 而返回 404。

### 平台端点速查

| 用途 | 方法与路径 |
|---|---|
| 模型清单 | `GET /api/v1/models` |
| 对话 | `POST /api/v1/chat/completions` |
| 应用清单 | `GET /api/v1/apps` |
| 单应用 schema | `GET /api/v1/apps/<应用代号>` |
| 应用调用 | `POST /api/v1/apps/<应用代号>/<接口代号>` |
| 任务查询（免费） | `GET /api/v1/tasks/<task_id>` |
| 任务列表 | `GET /api/v1/tasks` |
| 余额 | `GET /api/v1/user/balance` → `{"available_points":..., "currency":"points"}` |

> **业务成功码是 `code == 1`**（`{"code":1,"msg":"success"}`）；`code == 0` 是失败，**但 HTTP 仍可能是 200**。判断成败一定要看 `code`，不能只看 HTTP 状态码。

## 三、计费口径

### 3.1 点数

- **1 元 = 100 点，1 点 = 0.01 元。**
- **点数永久有效**，不按月清零。
- **先冻结、后结算**：消费优先扣会员点数，不足再扣充值额度。
- **调用失败直接退款；异步任务失败，冻结点数全额退回。**
- 充值：体验包 ¥10 = 600 点（含 7 天会员权益）；标准包 ¥99 = 10000 点。
- **查询任务状态免费。**

### 3.2 按能力分类的计量单位

「这个接口多少钱」这句话本身不完整 —— 必须连着**用量口径**一起看：

| 能力类型 | 计费口径 |
|---|---|
| 文本大模型 | **点数 / 百万 tokens**（输入输出分别计价；流式与非流式同价） |
| 图像生成 / 编辑 | **点数 / 张**，或按分辨率档位 |
| 视频生成 / 超分 | **点数 / 秒**（分辨率分档） |
| 数字人 / 对口型 | **点数 / 次或时长** |
| 语音 TTS / 音色克隆 | **点数 / 千字** |
| 语音识别 ASR | **点数 / 分钟** |
| 工具类（水印消除等） | **点数 / 次** |

### 3.3 两套价格字段（最容易算错的地方）

平台在每个接口上同时给两套价格：

| 字段 | 含义 | 用途 |
|---|---|---|
| `fixed_price` / `input_price` | **公示标准价** | 对外展示、横向比价 |
| `tenant_fixed_points` / `tenant_points_per_1k_input` / `tenant_points_per_1k_output` | **你所在租户的实际结算价** | **做预算只能用它** |

> **两者可能差很多。任何按公示价做的预算都可能错一个数量级。**
>
> **做预算一律读 `tenant_*`，最终以账号里实际扣费为准。**

### 3.4 实测消耗参考

| 场景 | 消耗 |
|---|---|
| `DeepSeek-V4-Flash` 一次普通问答 | 约 **0.74 ~ 0.99 点** |
| 极小调用（`max_tokens=8`） | **0.00 点** |
| 查询任务状态 | **免费** |

### 3.5 控成本的三招

1. **压 `max_tokens`。** 这是最直接的旋钮；推理模型不低于 256，其余按实际需要给。
2. **精简 system prompt。** 它每次都随请求计费，长系统提示是隐形开销。
3. **长对话做摘要。** 不要把几十轮历史原样每次都发上去。

## 四、错误码全表

| HTTP | code | 含义 | 怎么办 |
|---|---|---|---|
| 400 | `invalid_request` | 参数缺失或格式错误 | 用 schema 核对参数名与必填项 |
| 401 | `auth_failed` | API Key 缺失或无效 | 重新复制 Key，确认 `Bearer ` 前缀 |
| 402 | `insufficient_points` | 账号点数余额不足 | 充值；错误里带本次所需点数 |
| 402 | `key_quota_exceeded` | 该 Key 自己的额度打满 | 去用户中心调高该 Key 的 quota，或换 Key |
| 403 | `permission_denied` | 该 Key 无权调用此模型 / 应用 | 检查模型是否已开通、Key 是否被限权 |
| 404 | `not_found` | 模型 / 应用 / 任务不存在 | 核对代码拼写；**先怀疑 `/v1` 层数** |
| 429 | `queue_limit_exceeded` | 排队任务已达上限 | 降并发，等队列消化后重试 |
| 5xx | `server_error` | 服务异常 | 退避重试；仍失败换模型 / 线路 |

**两条容易读错的：**

- **两个 402 是不同的事。** `insufficient_points` 是账号没钱，去充值；`key_quota_exceeded` 只是这把 Key 的额度满了，**去调 quota，不用充值**。
- **403 和余额无关。** 它是权限问题（模型未开通、Key 被限权、IP 白名单不匹配）。

### 重试策略

| 情况 | 重试吗 |
|---|---|
| 400 / 401 / 402 / 403 / 404 | **不重试**，重试只是浪费请求 |
| 429 | 重试，用指数退避 + 抖动（1s → 2s → 4s → 8s） |
| 5xx | 重试，同样退避；持续失败换模型或换线路 |
| 提交类异步任务超时 | **先查 `task_id` 再决定**，不要裸重提 |

包内 `scripts/a7w.py` 已经把这套策略编进去了：网络类错误与 5xx 退避重试 **4 次**，4xx 是业务错误不重试。

## 五、权限与联网边界

| 能力 | 是否申请 | 用途 |
|---|---|---|
| 网络访问 | **申请** | 调用 `api.a7w.cn` 的网关接口（唯一的联网行为） |
| 读取文件 | 仅读取你指定的输入文件 | 用作素材入参 |
| 写入文件 | 仅在传入 `--out` 时 | 保存返回的 JSON 或下载产物 |
| 凭证 | 读取**你自己**提供的 API Key | 从环境变量或 `~/.a7w/config.json` 读取 |
| 子进程 / 后台常驻 | 不申请 | `a7w.py` 执行完即退出，不注册服务、不常驻 |

**不内嵌任何密钥。** 请求只发往 `api.a7w.cn`，不发送到其他任何地址。

边界声明：

- **不提供 Key、不代付费用。** Key 必须你自己在 [api.a7w.cn](https://api.a7w.cn/) 申请。
- **不替代内容合规审查。** 生成内容的使用与合规责任由使用者承担。
- **不替代版权审查。** 抓取、二次创作、商用前请自行确认授权。
- **不保证默认就安全。** 自托管客户端对外暴露前，请自行硬化（回环监听、访问控制、Key 隔离）。

只允许访问的域名：`api.a7w.cn`、`aigc.a7w.cn`、`ks.a7w.cn`、`vr.a7w.cn`、`a7w.cn`。

## 六、自检清单

- [ ] 地址层数核对过：按客户端示例判断填 `/api/v1` 还是 `/api`，没有出现 `/api/v1/v1`
- [ ] 用 `curl` 直连 `/api/v1/chat/completions` 返回 200，才去配客户端
- [ ] `whoami` 与 `/api/v1/user/balance` 都通过，确认 Key 权限与余额
- [ ] 模型编码是从 `/api/v1/models` 现场拉的 `model_code`，逐字一致、大小写正确
- [ ] 推理模型的 `max_tokens` 不低于 256；代码对 `content == null` 做了容错
- [ ] 流式解析取的是 `choices[0].delta.content`，不是 `message.content`
- [ ] 生成类能力走的是 `/api/v1/apps/<应用代号>/<接口代号>`，没有用 `endpoint_path` 拼 URL
- [ ] 判断成败看的是 `code == 1`，不是 HTTP 状态码
- [ ] Key 走环境变量或本机配置，`.env` 已在 `.gitignore` 里，前端代码里没有 Key
- [ ] 已设 Key 级 quota 与 IP 白名单；预算按 `tenant_*` 算
