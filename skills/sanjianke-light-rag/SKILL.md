把文档切成块、算成向量，检索时只能找回「和问题长得像的那几段」。
问「这几个业务板块之间是什么关系」，它答不上来 —— **因为关系从来不在任何一个块里**。

这个 Skill 的做法是**双层级**：一边保留向量检索，一边用大模型把文档抽成**实体—关系图**。
查询时既能在图上找具体实体，也能顺着关系链看全局，再和向量召回合到一起。

**抽图与回答都走 [算力集市 api.a7w.cn](https://api.a7w.cn/) 的 OpenAI 兼容网关。**
一个 `base_url`、一把 Key，本地只留图谱与索引，**零显卡、不部署模型**。

## 一、向量检索答不了的那类问题，交给图谱层

| 问题长什么样 | 靠什么答 | 为什么 |
|---|---|---|
| 「这段话说了什么」局部事实 | 向量召回 | 答案就在某一段里，找相似段落就够 |
| 「这几家公司之间有什么关联」 | **图谱 · 实体邻域** | 关系横跨多个段落，得顺着边去找 |
| 「这个制度的适用范围和例外分别是什么」 | **图谱 · 实体邻域** | 条件是分散在多处的实体关系 |
| 「这份年报里几个业务板块是什么关系」 | **图谱 · 关系链** | 需要顺着多跳关系走 |
| 「整体上有哪些趋势」 | **图谱 · 社区摘要** | 没有任何一段话在讲「主题」，得先归纳 |

**两类一起用效果最好**：图谱给你「准」的实体与关系，向量给你「全」的相似段落。

## 二、三分钟跑通

### 第一步：拿到你自己的 Key

到 **[api.a7w.cn](https://api.a7w.cn/)** 注册，在控制台创建一个 API Key（形如 `sk-...`），
填进环境变量：

```bash
export A7W_API_KEY=sk-你的key      # Windows: $env:A7W_API_KEY="sk-你的key"
```

顺手确认一下可用的模型名（**不要猜**）：

```bash
curl -sS "https://api.a7w.cn/api/v1/models" \
  -H "Authorization: Bearer $A7W_API_KEY"
```

### 第二步：让模型把每个文本块抽成实体与关系

这是图谱层唯一的模型调用，提示词里把输出格式写死：

```bash
curl -sS -X POST "https://api.a7w.cn/api/v1/chat/completions" \
  -H "Authorization: Bearer $A7W_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "DeepSeek-V4-Flash",
    "messages": [
      {"role": "system", "content": "你是信息抽取器。只输出 JSON，不要解释、不要代码块围栏。格式：{\"entities\":[{\"name\":\"\",\"type\":\"\"}],\"relations\":[{\"source\":\"\",\"target\":\"\",\"relation\":\"\"}]}"},
      {"role": "user", "content": "文本：<你的一个文本块，300~500 字>"}
    ],
    "temperature": 0,
    "max_tokens": 1200
  }'
```

把每个块的结果合并成一张图（实体去重、边累加权重），**存成 JSON 就是你的图谱**。
完整写法与合并规则见 `references/图谱检索.md`。

### 第三步：双层级检索 —— 先召回，再回答

```bash
curl -sS -X POST "https://api.a7w.cn/api/v1/chat/completions" \
  -H "Authorization: Bearer $A7W_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "DeepSeek-V4-Flash",
    "messages": [
      {"role": "system", "content": "只根据资料回答；资料里没有就说不知道，不要编。"},
      {"role": "user", "content": "资料（图谱关系）：\nA 公司 --控股--> B 公司\nB 公司 --供应--> C 公司\n资料（原文片段）：\n1) ……\n\n问题：A 和 C 之间是什么关系？"}
    ],
    "temperature": 0.2,
    "max_tokens": 800
  }'
```

「图谱关系」那几行，就是你从本地图上按实体邻域或关系链走出来的边 —— 这一步**本地免费**。

### 第四步：只取上下文不生成（做评测用）

把 `messages` 里的资料段直接打印出来核对召回质量，**不调用模型就不扣点**。
召回不准先修分块与提示词，别急着换模型。

## 四、素材要求

| 要求 | 说明 |
|---|---|
| 内容类型 | **垂直领域长文档**最合适：法律条文、金融研报、学术论文、操作规范、访谈记录 |
| 不合适的素材 | 短文本、碎片化聊天记录、纯表格 —— 抽关系的收益很小 |
| 单块长度 | 300~500 字一块，重叠 10%~15%；块太大实体太多，抽取容易超时 |
| 块的质量 | **参考文献、目录、附录这类低信息密度的块先丢掉**，它们产生的低价值关系会淹没图谱 |
| 实体命名 | 提示词里要求「实体名用文中最完整的写法」，否则同一个对象会裂成多个节点 |
| 抽取模型 | 建议用**非推理型**的对话模型做抽取（推理模型会把 token 花在思维链上），生成答案再用更强的模型 |

## 五、常见坑

| 坑 | 表现 | 怎么避 |
|---|---|---|
| **拿 `code == 0` 判断成功** | 明明成功却判成失败 | 平台成功码是 **`1`**（`{"code":1,"msg":"success"}`） |
| **模型名靠猜** | 404 或直接报错 | 动手前先跑 `GET /api/v1/models`，**以接口返回为准** |
| **`max_tokens` 给得太小** | `content` 返回 `null`、`finish_reason` 是 `length` | 推理型模型会先花 token 说思维链；**先把这个值调大**，不是接口坏了 |
| **抽出来的 JSON 被代码块围栏包住** | 解析直接失败 | 提示词里写「只输出 JSON、不要代码块围栏」，解析前再把 ```json 围栏剥掉一层 |
| **一个块里关系太多导致超时** | 抽取阶段频繁超时 | 先把块切小；再用 `max_tokens` 限制输出长度；偶发一次重跑通常就好 |
| **低信息密度块灌进图谱** | 图谱被噪声淹没、问答跑偏 | 分块阶段就把参考文献、目录这类块扔掉 |
| **同一个对象裂成多个节点** | 关系链走不通 | 提示词固定命名规范；合并阶段做一次名称归一化 |
| **换了 embedding 模型** | 旧向量不能用、结果全乱 | **索引与查询必须同一个模型**；换模型就要重建向量那一层，图谱可以保留 |
| **语料没处理完就提问** | 召回为空、答非所问 | 抽图是批处理，跑完再查；把每个文档的处理状态记下来 |
| **一次塞几十条关系** | 又贵又跑题 | 邻域只取 1~2 跳、边数控制在 10 条以内 |
| **把 Key 写进代码** | 泄露即等于泄露余额 | 只从环境变量 `A7W_API_KEY` 或 `~/.a7w/config.json` 读 |
