# 图谱检索：抽图、合并、邻域召回、增量更新

这份文档给出一套**只用 Python 标准库**的双层级检索实现：
用 `api.a7w.cn` 的网关抽实体关系，图存在本地 JSON 里，遍历与召回全部免费。

## 1. 抽图提示词（把输出格式写死）

```python
EXTRACT_SYSTEM = (
    "你是信息抽取器。只输出 JSON，不要解释、不要 markdown 代码块围栏。\n"
    "格式：\n"
    '{"entities":[{"name":"","type":"","description":""}],\n'
    ' "relations":[{"source":"","target":"","relation":"","description":""}]}\n'
    "规则：\n"
    "1) name 用文本中出现的最完整写法，不要用代词；\n"
    "2) type 用中文短标签，如 人物 / 组织 / 制度 / 条款 / 时间 / 地点 / 事件；\n"
    "3) relation 用动词短语，如 控股 / 适用于 / 修订自；\n"
    "4) source 与 target 必须是上面 entities 里出现过的 name；\n"
    "5) 没有关系的实体也要列在 entities 里。"
)

EXTRACT_USER = "文本：\n%s"
```

调用要点：

- `temperature` 给 **0**，抽取任务不需要创造性。
- `max_tokens` 给足（**1200 起**）：推理型模型会先花 token 说思维链，给小了正文会是 `null`。
- **一次只送一个块**（300~500 字）。一个块里实体太多，模型容易漏、也容易超时。
- 抽取阶段建议用**非推理型**模型，省 token 也更快。

## 2. 解析模型返回：先剥围栏，再容错

```python
import json, re

def parse_json(text):
    """模型返回可能是裸 JSON，也可能被 ```json 围栏包住，还可能有前后闲话。"""
    if not text:
        return None
    s = text.strip()
    s = re.sub(r"^```(?:json)?\s*", "", s)
    s = re.sub(r"\s*```$", "", s)
    try:
        return json.loads(s)
    except ValueError:
        pass
    m = re.search(r"\{.*\}", s, re.S)          # 兜底：抠出最外层大括号
    if not m:
        return None
    try:
        return json.loads(m.group(0))
    except ValueError:
        return None
```

**解析失败要记下来**：把失败的原文存成一个文件，改完提示词只重跑这些块，
不要整批重跑 —— 那是白花钱。

## 3. 图合并：实体归一化 + 边累加权重

```python
import re
from collections import defaultdict

def norm(name):
    """实体名归一化：去掉空格与常见修饰，降低同名裂开的概率。"""
    return re.sub(r"[\s　]+", "", (name or "").strip())

class Graph:
    def __init__(self):
        self.nodes = {}                 # key -> {name, type, desc, docs:set}
        self.edges = defaultdict(float)  # (src,dst,rel) -> weight
        self.edge_desc = {}
        self.edge_docs = defaultdict(set)

    def add_chunk(self, parsed, doc_id):
        if not parsed:
            return
        for e in parsed.get("entities") or []:
            if not isinstance(e, dict):
                continue
            k = norm(e.get("name"))
            if not k:
                continue
            node = self.nodes.setdefault(
                k, {"name": e["name"], "type": e.get("type") or "",
                    "desc": e.get("description") or "", "docs": set()})
            node["docs"].add(doc_id)
            if e.get("description") and not node["desc"]:
                node["desc"] = e["description"]
        for r in parsed.get("relations") or []:
            if not isinstance(r, dict):
                continue
            a, b = norm(r.get("source")), norm(r.get("target"))
            if not a or not b or a == b:
                continue
            rel = (r.get("relation") or "相关").strip()
            self.edges[(a, b, rel)] += 1.0
            if r.get("description"):
                self.edge_desc[(a, b, rel)] = r["description"]
            self.edge_docs[(a, b, rel)].add(doc_id)

    def to_json(self):
        return {"nodes": self.nodes,
                "edges": [{"source": a, "target": b, "relation": r, "weight": w,
                           "description": self.edge_desc.get((a, b, r), ""),
                           "docs": sorted(self.edge_docs[(a, b, r)])}
                          for (a, b, r), w in self.edges.items()]}
```

**归一化为什么重要**：同一个对象被写成「甲公司」「甲公司（下称甲方）」就会裂成两个节点，
关系链于是走不通。归一化 + 提示词里要求「用最完整的写法」是两手都要抓。

## 4. 邻域召回与多跳关系链（本地，免费）

```python
def neighbors(graph_json, entity, hops=2, max_edges=12):
    """从某个实体出发走 N 跳，返回边走出来的关系行。"""
    adj = defaultdict(list)
    for e in graph_json["edges"]:
        adj[e["source"]].append((e["target"], e["relation"], e["weight"]))
        adj[e["target"]].append((e["source"], e["relation"], e["weight"]))

    start = next((k for k in graph_json["nodes"] if entity in k), None)
    if not start:
        return []

    seen, frontier, lines = {start}, [start], []
    for _ in range(max(1, hops)):
        nxt = []
        for cur in frontier:
            for dst, rel, w in sorted(adj[cur], key=lambda x: -x[2]):
                if len(lines) >= max_edges:
                    return lines
                lines.append("%s --%s--> %s（权重 %.1f）"
                             % (graph_json["nodes"][cur]["name"], rel,
                                graph_json["nodes"].get(dst, {}).get("name", dst), w))
                if dst not in seen:
                    seen.add(dst)
                    nxt.append(dst)
        frontier = nxt
    return lines
```

**控制规模**：`hops=2`、`max_edges=12` 是经验值。边给多了既贵又跑题。

## 5. 双层级合并：图 + 文本一起进上下文

```python
def build_context(question, graph_json, bm25_hits, entity_hint):
    rel = neighbors(graph_json, entity_hint, hops=2, max_edges=10)
    parts = []
    if rel:
        parts.append("资料（图谱关系）：\n" + "\n".join(rel))
    if bm25_hits:
        parts.append("资料（原文片段）：\n" + "\n\n".join(
            "[%d] %s" % (i + 1, h["text"]) for i, h in enumerate(bm25_hits)))
    return "\n\n".join(parts)
```

- **图谱给「准」**：实体与关系是显式抽出来的，不会被相似度误导。
- **文本给「全」**：原句能补上图里没抽到的细节。
- 两者一起拼进上下文，答案质量通常比单用任何一路都稳。

`entity_hint` 可以简单地在问题里做一次子串匹配（在节点名里找问题中出现的实体）；
也可以用一次很短的模型调用让模型从问题里提实体 —— 但那要花点数，能用规则就别用模型。

## 6. 增量更新与按文档删除

图是按文档 ID 归属的，所以增删都很直接：

```python
def drop_doc(graph_json, doc_id):
    """按文档删除：节点与边只属于该文档就一起删掉。"""
    keep_edges = [e for e in graph_json["edges"] if doc_id not in e["docs"]]
    used = {e["source"] for e in keep_edges} | {e["target"] for e in keep_edges}
    keep_nodes = {k: v for k, v in graph_json["nodes"].items() if k in used}
    return {"nodes": keep_nodes, "edges": keep_edges}
```

**做法与纪律**：

1. 每张边与每个节点都记 `docs`（来源文档 ID 集合）。
2. 新增文档：只跑新文档的块，结果**合并**进现有图，旧图不动。
3. 删除文档：按上面这段代码把「只属于该文档」的节点与边摘掉。
4. **删除是不可逆操作**，动之前把图 JSON 备份一份。
5. 记录每个文档的处理状态（待处理 / 处理中 / 已完成），别在没跑完时就提问 —— 召回会是空的。

## 7. 存储选型

| 规模 | 存法 | 说明 |
|---|---|---|
| 几千个块、几万条边 | **一个 JSON 文件** | 最简单，全量读写足够快，适合起步 |
| 十万条边以上 | 按文档分片成多个 JSON，内存里建合并视图 | 避免每次全量读写 |
| 多人共用 / 需要并发写 | 换成服务端图数据库或关系库 | 文件是单写者模型，并发管理写会互相覆盖 |

**文件型存储是单写者模型**：不要在文件后端上并发调用增删改。
一次一个，或者换成服务端存储。
