# 三剪客 · 风格克隆体

**学一个账号的调性，然后按它写。**

喂 3~20 篇同一个账号的稿子 → 抽出一份**可测量的风格档案** → 按档案写新稿 →
**风格一致性自检**（新稿逐指标 vs 档案）→ 迭代到贴合。面向矩阵号、代运营、品牌统稿。

这是产品线里的 **L2 智能体型**技能包：不是一次生成，是「抽档 → 写 → 自检 → 迭代」的闭环。

## 它解决什么问题

矩阵号和代运营最常见的失败不是写不出来，是**写出来不像那个号**。

多数工具在这一点上给的是"照着这几篇的调性写"或者"让模型模仿这个风格"。
这两种做法都没有验收标准——**"像不像"没人能反驳，也就没人能用它做门禁。**

本包换了个做法：**把调性变成数字。**

```
喂样本 →  抽档案         →  按档案写   →  逐指标自检      →  迭代
3~20 篇   平均句长/人称占比   新稿一篇      新稿 vs 档案对照表    偏离项喂回模型
          /标点密度/段长      （要 token）  超出容差即标红       定点修
          /口头禅/开场结尾
          （纯本地，零成本）                （纯本地，零成本）
```

## 可测量，还是读起来像

**这是本包唯一值得你花时间看的一节。** 如果指标区分不了"同风格"与"不同风格"，
那它就是假绿，这个包就不该存在。

实测：6 篇同一作者的样本（推广长文体，均 ~1850 汉字）抽出档案；
对照组是 4 篇**别的风格**的稿子（学术论文体），主题还在同一个圈里，只换调性。

| 被测稿子 | 一致度 | 偏离项 | verify 结论 |
|---|---|---|---|
| 样本 1~6（同账号，逐篇） | 86.0 ~ 93.0 | **0 / 26** | ✅ 6/6 通过 |
| 产出的新稿（迭代第 2 轮，跑通的那次） | 80.6 | **0 / 26** | ✅ 通过 |
| 同一产线重跑一次（迭代第 2 轮） | 57.6 | 4 / 26 | ❌ 拦下 |
| 异风格 01 | **10.3** | 10 / 26 | ❌ 拦下 |
| 异风格 02 | **19.4** | 8 / 26 | ❌ 拦下 |
| 异风格 03 | **37.7** | 6 / 26 | ❌ 拦下 |
| 异风格 04 | **38.0** | 6 / 26 | ❌ 拦下 |

**同风格 6/6 全过**（容差就是按"样本自己必须先过得去"标定的）；
**异风格 4/4 被拦下**——判"像"容易，判"不像"才需要指标真有判别力。

判别力主要来自这几项：

| 指标 | 档案（同账号） | 异风格实测 | 相对偏差 |
|---|---|---|---|
| 第一人称占比 | 0.77 | **0.00** | 3.83 |
| 第三人称占比 | 0.16 | 1.00 | 4.18 |
| 平均句长 | 23.75 汉字 | 38.79 汉字 | 1.00 |
| 长句(≥30字)占比 | 0.32 | 0.64 | 2.15 |
| 平均段长 | 65.43 汉字 | 100.17 汉字 | 1.52 |
| 口头禅命中 | 需 ≥2 个 | **0 个** | 1.00 |

另外做了一次**花 token 的独立检验**（不依赖本包的指标）：把 3 篇样本的首尾片段
当"作者原文"给裁判模型，再给三份候选——本包产出、别人的稿子、同一作者的另一篇样本
——打乱顺序问"哪几份同一人写的"。两轮不同顺序结果一致：

| 候选 | 第 1 轮 | 第 2 轮 |
|---|---|---|
| 本包产出 | same_author=**True**（8/10） | same_author=**True**（7/10） |
| 别人的稿子 | same_author=**False**（1/10） | same_author=**False**（1/10） |
| 作者另一篇原文 | same_author=True（9/10） | same_author=True（8/10） |

裁判给的可指认证据："开场同样是具体场景+身体细节的第一人称（「手心是潮的」），
与原文「我盯着后台看了很久」同款；核心修辞是「不是A，是B」的重新定义句……"
—— 与本包的指标指向同一批证据。

**结论：真的可测量。** 边界是：它测的是"调性"这一层（句长/人称/段落/标点/口头禅），
不是"主题"这一层。同风格换选题照样成立；换了作者的调性，指标塌得很明显。

## 风格档案长什么样

全部是数字或可枚举的类别，**没有一项是"幽默风趣"这类形容词**：

| 类别 | 指标 |
|---|---|
| 句长分布 | 平均句长 23.8 汉字（允许 8.8~38.7）、标准差、篇间离散、中位数、p10/p90、短句占比 20%、长句占比 32% |
| 段落节奏 | 平均段长 65.4 汉字（允许 42.5~88.3）、最长段、序数开头段占比 3% |
| 人称分布 | 我/我们 77%｜你/你们 7%｜他/她 16%｜**主导人称：我/我们** |
| 标点密度 | 每百字：破折号 1.03｜逗号 5.74｜顿号 1.36｜冒号 0.79… |
| 词组密度 | 每百字：缓和词 0.18｜转折词 0.27｜序数词 0.62… |
| 口头禅 | top-5，按"出现在几篇里"排序 |
| 开场/结尾 | 句式类别 + 票数（疑问式×4、第一人称叙事×1…） |
| 自相似基线 | 样本两两风格指纹相似度 + **自相似阈值** |
| 容差自标定 | 每个指标的 `dev_limit` + 样本观测到的最大相对偏差 |

同一批样本抽两次，档案**逐字节相同**——它是数出来的，模型插不进话。

```bash

    --iterations 3 --outdir D:/styleclone/out
```

## 六件事，一条命令

| 子命令 | 干什么 | 花钱吗 |
|---|---|---|
| `profile` | 从样本抽风格档案（全部指标） | **不花** |
| `baseline` | 自证通过率 + 自相似阈值 + 自标定容差表 | **不花** |
| `write` | 按档案写新稿 | 花 token |
| `verify` | 新稿逐指标 vs 档案，给偏差表与结论 | **不花** |
| `diff` | 档案 vs 新稿的并排指标对照表 | **不花** |
| `all` | 抽档 → 写 → 自检 → 迭代 | 花 token |
| `cost` / `models` | 只算钱 / 列在架模型 | **不花** |

`profile` / `verify` / `diff` / `baseline` **一个请求都不发**。

## 六道硬闸门

命中即**标红 + stderr 汇总 + 退出码非 0**，可以直接进 CI。

| # | 闸门 | 判定 | 退出码 |
|---|---|---|---|
| 1 | 合规 | 广告法违禁词；「最X」按可枚举语境豁免，**句首不豁免** | 3 |
| 2 | 占位符残留 | `{}`、`[待填]`、`XXX`、`待补充`、`TODO` | 3 |
| 3 | prompt_echo | 去标点相等 / Jaccard ≥ 0.75 / 覆盖度 ≥ 0.60 + **片段级有序覆盖 ≥ 0.75** | 3 |
| 4 | **风格偏离** | 新稿逐指标 vs 档案，超出自标定容差即拦，逐项列偏差值 | 3 |
| 5 | 样本量 | 有效样本 < 3 篇 → 拒绝抽档 | 2 |
| 6 | 成本 / 产出位置 | `--budget` 超限；`--outdir` 指到包内 | 5 / 2 |

外加防换皮：新稿与样本全文的二元组 Jaccard ≥ 0.50 → 拦。

### 第 3 道闸门为什么在本包里格外重要

**本包的提示词里确实放样本**——不放，模型无从知道这个账号的句式长什么样。
但只放**每个样本的开场句与结尾句**（最多 2N 句），不放正文：

- 放正文 → 模型的最优策略就是"把样本改几个词"，闸门会一直响，它也确实没别的办法；
- 只放首尾句 → 模型必须自己造正文，这才是"学调性"与"抄样本"的分界。

代价是"把首尾句原样搬进新稿"变成最省力的写法，所以这道闸门是**防必然**，不是防意外。
把示例原句后面接几个字，`exact` 不成立、`jaccard` 只有 0.53、`contain` 被长度窗口挡住
—— 三条全漏，而人眼一看就是抄的。所以补了一条"等长窗口 + 最长公共子序列"的判据：

| 形态 | 有序覆盖度 | 是否抓住 |
|---|---|---|
| 原句照抄 / +补3字 / 揉进长句开头 / 揉进长句中间 | 1.000 | ✅ |
| 同构改写（换 4 处词） | 0.778 | ✅ |
| **非照抄语句（133 条实测）** | **最高 0.148** | 不误伤 |

阈值 0.75，两侧余量都在 5 倍以上。

### 第 4 道闸门为什么不是"差不多就行"

`verify` 的输出是一张**逐指标对照表**：档案值、允许区间、新稿值、偏差、相对偏差、结论。
超容差的项标红并列出偏差值——**不许只给一个"很像"的结论**。

容差也不是拍脑袋定的，而是**从样本自身的偏差分布自标定**：

1. 先按标准口径算出指标带宽 `band`；
2. 拿每篇样本逐篇与（含它自己在内的）档案比对，记录每项的相对偏差；
3. `dev_limit = clamp(最大相对偏差 × 1.5, 1.0, 2.0)`；
4. 类别型指标（开场/结尾句式）：样本内部类别不统一 → 这一项放开。

**这四步的意义是：同一个人写的稿子必须先过得去，闸门才有资格拦别人。**
容差写死只有两种结局——严到样本自己都过不去（闸门一直响，最后没人看），
或者松到什么都能过（假绿，比闸门失效更糟）。`baseline` 会把整张自标定表打出来。

## 迭代不是单调变好的

`all` 的迭代是"把偏离项喂回模型定点修"。但实测它会到天花板后来回摆：

| 轮次 | 一致度 | 偏离项 |
|---|---|---|
| 1 | 47.7 | 5 |
| 2 | 71.0 | **1** |
| 3 | 75.8 | **1** |

第 2、3 轮卡在同一批指标上。所以本包**保留"最好的一轮"**，不是最后一轮——
否则产出质量就取决于轮数奇偶。采用第几轮会写进结果（`best_round`）与 stderr。

## 成本口径（实测标定）

| 项目 | 实测值 |
|---|---|
| `profile` / `verify` / `diff` / `baseline` | **0 token、0 元** |
| 单次 `write` | 约 2500 token，5~8 秒 |
| `all --iterations 2`（6 篇样本） | **4715 token**（prompt 2788 + completion 1927），约 12 秒 |
| 输入标定 | 1 原始字符 ≈ **0.621** token（1 token ≈ 1.61 字） |
| 输出标定 | 1 原始字符 ≈ **1.11** token |

**不编单价**：实测 `GET /api/v1/pricing` 的规则里不含文本大模型，
`GET /api/v1/models` 的记录里也没有任何价格字段，
`chat/completions` 的成功响应里 `usage` 只有 token 数、没有点数。
所以 token 数我们估，**金额必须由你给单价**（`--price-in` / `--price-out`，单位「点/百万 token」）。

## 算力接入

只用大模型，端点：`POST https://api.a7w.cn/api/v1/chat/completions`（OpenAI 兼容协议）。
模型清单用 `GET https://api.a7w.cn/api/v1/models` 现查。

- **不留任何密钥在代码或文档里**，Key 从环境变量 `A7W_API_KEY` 读
- **模型名会变，用 `models` 子命令现查，别写死**
- `deepseek-chat` 这个别名**实测可用**（路由到 `deepseek-flash`），
  但它**不在** `/api/v1/models` 的返回列表里——"列表里没有"不等于"不能用"
- 大模型调用带退避重试（网关 `upstream timeout` / HTTP 502 实测很常见）
- JSON 解析用 `json.JSONDecoder().raw_decode()` 扫描第一个完整对象，
  模型在合法 JSON 后多吐字符也不会炸
- **`/chat/completions` 的成功响应不带 `code` 字段**，别拿 `code` 判成败
