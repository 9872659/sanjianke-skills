# 社区摘要与全局问答：让「主题、趋势、概览」有答案

全局问题的难点在于：**没有任何一段原文在讲「主题」**。所以要先归纳，再回答。
这份文档给出**纯标准库**的社区划分与分层摘要实现，模型调用只发生在抽图、写摘要与回答三步。

---

## 1. 全流程四步

```
① 抽图      每块文本 → 实体 / 关系 / 声明        （模型调用）
② 社区划分   图 → 若干社区                        （本地，免费）
③ 分层摘要   每个社区 → 一段主题摘要              （模型调用）
④ 问答       全局问摘要 / 局部问邻域              （模型调用）
```

**中间产物全部落盘**（JSON），随时可以打开检查、也可以只重跑某一层。

---

## 2. 抽图：实体 + 关系 + 声明

```python
EXTRACT_SYSTEM = (
    "你是信息抽取器。只输出 JSON，不要解释、不要 markdown 代码块围栏。\n"
    "格式：\n"
    '{"entities":[{"name":"","type":"","description":""}],\n'
    ' "relations":[{"source":"","target":"","relation":"","description":""}],\n'
    ' "claims":[{"subject":"","statement":""}]}\n'
    "规则：\n"
    "1) name 用文本中出现的最完整写法；\n"
    "2) source / target 必须是 entities 里出现过的 name；\n"
    "3) claims 记下以某个实体为主语的断言，一句话一条；\n"
    "4) 用中文输出。"
)
```

- `temperature = 0`，`max_tokens >= 1500`。
- **一次只送一个块**（300~500 字）。
- 解析返回时**先剥 ```json 围栏**、再用正则抠最外层大括号，两级兜底：

```python
import json, re

def parse_json(text):
    """模型返回可能是裸 JSON，也可能被 ```json 围栏包住，还可能有前后闲话。"""
    if not text:
        return None
    s = text.strip()
    s = re.sub(r"^```(?:json)?\s*", "", s)
    s = re.sub(r"\s*```$", "", s)
    try:
        return json.loads(s)
    except ValueError:
        pass
    m = re.search(r"\{.*\}", s, re.S)          # 兜底：抠出最外层大括号
    if not m:
        return None
    try:
        return json.loads(m.group(0))
    except ValueError:
        return None
```

**解析失败要记下来**：把失败的原文存成一个文件，改完提示词只重跑这些块，不要整批重跑。

## 3. 社区划分：连通分量打底，标签传播精修

```python
from collections import defaultdict, Counter

def build_adj(edges):
    adj = defaultdict(set)
    for e in edges:
        a, b = e["source"], e["target"]
        adj[a].add(b)
        adj[b].add(a)
    return adj

def label_propagation(nodes, edges, rounds=10):
    """无权标签传播：每轮把节点标签改成邻居里最多的那个。纯标准库。"""
    adj = build_adj(edges)
    label = {n: i for i, n in enumerate(nodes)}
    for _ in range(rounds):
        changed = False
        for n in nodes:
            if not adj[n]:
                continue
            top = Counter(label[m] for m in adj[n]).most_common(1)[0][0]
            if label[n] != top:
                label[n] = top
                changed = True
        if not changed:
            break
    comm = defaultdict(list)
    for n, l in label.items():
        comm[l].append(n)
    return [sorted(v) for v in comm.values() if v]
```

**社区粒度调优**：

| 现象 | 怎么调 |
|---|---|
| 社区太多太碎，摘要全是流水账 | 减少轮数、或把只含 1~2 个节点的社区并入邻接社区 |
| 社区太大，摘要又空又泛 | 增加轮数、或先按主题/章节预分组，再在组内划社区 |
| 有的节点完全孤立 | 单独成一类，摘要就是它的 `description`，不必再调模型 |

**省钱技巧**：节点数少于 3 的社区**不用调模型写摘要**，直接把成员实体的
`description` 拼起来当摘要，效果够用且零成本。

## 4. 分层摘要：一层不够就再来一层

```python
SUMMARY_SYSTEM = (
    "你是社区摘要器。用 200 字以内概括这个社区在讲什么主题，"
    "列出关键实体与它们在社区里的角色。"
    "只使用给定内容，不要编造社区里没有的信息。用中文输出。"
)

def summary_prompt(entities, relations, claims):
    return ("社区成员实体：\n" + "\n".join(entities) +
            "\n\n社区内关系：\n" + "\n".join(relations) +
            "\n\n相关声明：\n" + "\n".join(claims))
```

- `temperature` 给 `0.3`：既稳定又不像抽图那样死板。
- `max_tokens` 给 600 上下，**摘要长不等于好**，200 字以内足够。
- **分层**：对「社区的摘要」再划一次社区、再写一层摘要，就得到更宏观的一层。
  全局问题先问最上层，问不到细节再往下一层走。

## 5. 全局问答：把摘要当资料

```python
GLOBAL_SYSTEM = (
    "你是一个宏观分析助手。只根据给定的社区摘要回答；"
    "摘要里没有的信息就说「现有摘要未覆盖」，不要编造。"
    "回答用要点式，每条后面标注来自哪个社区编号。"
)

def global_messages(question, summaries):
    ctx = "\n\n".join("[社区 %d] %s" % (i + 1, s) for i, s in enumerate(summaries))
    return [{"role": "system", "content": GLOBAL_SYSTEM},
            {"role": "user", "content": "社区摘要：\n%s\n\n问题：%s" % (ctx, question)}]
```

**社区一多，摘要也放不下**：先做一次「摘要的摘要」挑选，或按问题关键词先粗筛出
最相关的 5~8 个社区，再把它们的摘要拼进上下文。

## 6. 局部问答：从实体邻域入手

```python
def local_messages(question, edge_lines):
    return [{"role": "system",
             "content": "只根据给定的关系与声明回答；没有提到就说不知道。"},
            {"role": "user",
             "content": "资料（图谱关系）：\n%s\n\n问题：%s"
                        % ("\n".join(edge_lines), question)}]
```

从问题里找出实体名（在节点表里做子串匹配即可），走 1~2 跳取边，控制在 10 条以内。

## 7. 增量更新：按批次跑，别等全量

```python
def merge_graph(old, new):
    """新批次结果合并进旧图：节点去重、边权重累加。"""
    nodes = dict(old.get("nodes", {}))
    for k, v in new.get("nodes", {}).items():
        if k in nodes:
            nodes[k]["docs"] = sorted(set(nodes[k].get("docs", [])) | set(v.get("docs", [])))
        else:
            nodes[k] = v
    edges = {}
    for e in old.get("edges", []) + new.get("edges", []):
        key = (e["source"], e["target"], e["relation"])
        if key in edges:
            edges[key]["weight"] += e["weight"]
            edges[key]["docs"] = sorted(set(edges[key]["docs"]) | set(e["docs"]))
        else:
            edges[key] = dict(e)
    return {"nodes": nodes, "edges": list(edges.values())}
```

纪律：

1. **分批索引**：按文件 / 目录分批，每批完成即可查询，不必等全量。
2. **新批次只影响新增的社区**：新增内容划出的新社区单独写摘要，旧社区摘要不动。
3. **删除文档**时把只属于该文档的节点与边摘掉，并**重跑受影响的社区摘要**。
4. **每一步都落盘**，中断了可以从最近一层续跑，不用从头再来。

## 8. 成本控制：四条纪律

| 纪律 | 为什么 |
|---|---|
| **先用 10 个块的小样本跑通** | 小样本的账单几乎可以忽略，但足以判断抽取质量与社区摘要讲得对不对 |
| **低信息密度的块不入库** | 目录、参考文献、附录、页脚对社区摘要毫无贡献，省下的抽取费最多 |
| **小社区不调模型** | 少于 3 个节点的社区直接拼 `description`，零成本 |
| **提示词把输出格式写死** | 模型少说废话，token 就省下来了；抽取与摘要都适用 |

**估算方法**：先跑 10 个块，记下 token 用量，乘以「总块数 / 10」就是索引阶段的量级。
把「小样本实测 → 线性放大」当作预算流程，比事后看账单安全得多。
