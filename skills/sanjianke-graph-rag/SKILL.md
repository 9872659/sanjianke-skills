普通向量检索只能回答「哪几段话和问题像」。所以你问「这本书的主要主题是什么」，
它给不出答案 —— **因为没有任何一段话在讲「主题」**。

这个 Skill 走另一条路：先让模型把整批文档读成一张**实体关系图**，
再把图切成一层层**社区**并给每个社区写一份**摘要**，最后靠这些摘要回答**全局性**的问题。
**摘要本身就是在讲主题**，所以全局问题终于有答案。

抽图、写摘要、回答问题，全部走 [算力集市 api.a7w.cn](https://api.a7w.cn/) 的 OpenAI 兼容网关：
**一个 `base_url`、一把 Key、75 个在架模型**，本地零显卡。

## 一、全局问题与局部问题，问法不一样

| 问题长什么样 | 用哪条路 | 资料从哪来 |
|---|---|---|
| 「整体上有哪些主题 / 趋势 / 概览」 | **全局** | 社区摘要（本地生成，免费） |
| 「某个人物/某个实体及它的主要关系」 | **局部** | 实体邻域（本地图上走，免费） |
| 「既要宏观又要具体」 | **两者都给** | 社区摘要 + 实体邻域一起拼进上下文 |
| 「这句话在第几页」 | 普通检索 | 向量或关键词召回就够，不必上图谱 |

**索引是「先贵后准」的投入**：建图与写摘要要花 token，换来的是全局问题答得上来。

## 二、三分钟跑通

### 第一步：拿到你自己的 Key

到 **[api.a7w.cn](https://api.a7w.cn/)** 注册，创建 API Key（形如 `sk-...`）：

```bash
export A7W_API_KEY=sk-你的key      # Windows: $env:A7W_API_KEY="sk-你的key"
```

确认可用模型名（**不要猜**）：

```bash
curl -sS "https://api.a7w.cn/api/v1/models" \
  -H "Authorization: Bearer $A7W_API_KEY"
```

### 第二步：抽图 —— 把每个文本块变成实体、关系与声明

```bash
curl -sS -X POST "https://api.a7w.cn/api/v1/chat/completions" \
  -H "Authorization: Bearer $A7W_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "DeepSeek-V4-Flash",
    "messages": [
      {"role": "system", "content": "你是信息抽取器。只输出 JSON，不要解释、不要代码块围栏。格式：{\"entities\":[{\"name\":\"\",\"type\":\"\",\"description\":\"\"}],\"relations\":[{\"source\":\"\",\"target\":\"\",\"relation\":\"\",\"description\":\"\"}],\"claims\":[{\"subject\":\"\",\"statement\":\"\"}]}"},
      {"role": "user", "content": "文本：<你的一个文本块，300~500 字>"}
    ],
    "temperature": 0,
    "max_tokens": 1500
  }'
```

**先用 10 个块试，别一次全量。** 效果对了再往下跑。

### 第三步：社区摘要 —— 这一步才让全局问题答得上来

在图（本地 JSON）上做一次社区划分，然后对每个社区调一次模型写摘要：

```bash
curl -sS -X POST "https://api.a7w.cn/api/v1/chat/completions" \
  -H "Authorization: Bearer $A7W_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "DeepSeek-V4-Flash",
    "messages": [
      {"role": "system", "content": "你是社区摘要器。用 200 字以内概括这个社区在讲什么主题，列出关键实体与它们的角色。不要编造社区里没有的内容。"},
      {"role": "user", "content": "社区成员实体：……\n社区内关系：……\n相关声明：……"}
    ],
    "temperature": 0.3,
    "max_tokens": 600
  }'
```

社区划分与摘要调度用**纯 Python 标准库**就能写，完整实现见 `references/社区摘要与全局问答.md`。

### 第四步：全局问答 —— 把摘要当资料

```bash
curl -sS -X POST "https://api.a7w.cn/api/v1/chat/completions" \
  -H "Authorization: Bearer $A7W_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "DeepSeek-V4-Flash",
    "messages": [
      {"role": "system", "content": "只根据给定的社区摘要回答；摘要里没有就说不知道，不要编。"},
      {"role": "user", "content": "社区摘要：\n1) ……\n2) ……\n\n问题：整体上有哪些主要趋势？"}
    ],
    "temperature": 0.3,
    "max_tokens": 1200
  }'
```

**局部问答**换成实体邻域：在本地图上找出问题里的实体，走 1~2 跳把边取出来拼进上下文即可。

## 四、素材要求

| 要求 | 说明 |
|---|---|
| 内容类型 | **叙事类或档案类文本**最合适：小说、卷宗、访谈记录、工单、会议纪要、行业报告 |
| 规模 | 从**几页纸**起步验证效果；语料越大，索引成本越接近线性增长 |
| 单块长度 | 300~500 字一块，重叠 10%~15%；块太大实体太密，抽取会超时且噪声大 |
| 块的质量 | **目录、参考文献、附录、页眉页脚先清掉** —— 它们对社区摘要毫无贡献，还会稀释主题 |
| 中文语料 | 提示词里明确要求「用中文输出实体名与摘要」，否则中英混杂 |
| 中间产物 | 实体、关系、社区、社区摘要都**落盘成 JSON**，随时可以打开检查、也便于复跑 |

## 五、常见坑

| 坑 | 表现 | 怎么避 |
|---|---|---|
| **拿 `code == 0` 判断成功** | 明明成功却判成失败 | 平台成功码是 **`1`**（`{"code":1,"msg":"success"}`） |
| **模型名靠猜** | 404 或直接报错 | 动手前先跑 `GET /api/v1/models`，**以接口返回为准** |
| **一上来就全量索引** | 账单远超预期 | **先跑 10 个块**：确认抽取质量与社区摘要讲得对，再全量。成本随语料近似线性增长 |
| **`max_tokens` 给得太小** | `content` 返回 `null`、`finish_reason` 是 `length` | 推理型模型先花 token 说思维链；**先把这个值调大**，不是接口坏了 |
| **抽出来的 JSON 被代码块围栏包住** | 解析直接失败 | 提示词写「只输出 JSON、不要代码块围栏」，解析前再剥一层 ```json 围栏 |
| **社区切得太碎** | 摘要全是流水账、答不出主题 | 社区粒度往上调一级，让每个社区有足够多的实体与边 |
| **社区切得太大** | 摘要又空又泛 | 往下调一级；宁可多几个社区，摘要质量更重要 |
| **摘要里出现幻觉** | 问到的东西原始语料里没有 | 提示词写「不要编造社区里没有的内容」；抽查摘要与原始块的对应关系 |
| **问细节问题却答得很宏观** | 全局路线不擅长细节 | 细节问题改走**局部**路线：在图上按实体邻域召回 |
| **换了模型后效果变差** | 抽取质量明显下滑 | 抽取提示词是针对模型调的，换模型后**把提示词重新对一遍** |
| **索引跑完找不到产物** | 以为白跑了 | 产物是你自己写的 JSON（图 + 社区 + 摘要），路径记清楚；建议按语料分目录 |
| **把 Key 写进代码** | 泄露即等于泄露余额 | 只从环境变量 `A7W_API_KEY` 或 `~/.a7w/config.json` 读 |

## 六、计费与成本控制

1 元 = 100 点，1 点 = ¥0.01，**按量计费、没有月费**。

| 动作 | 点数 | 折合 |
|---|---|---|
| 本地分块、建图、存图、社区划分、图遍历 | **0** | 免费，不经过平台 |
| `file_qa` 文件问答 / 剧本解析 | **0** | 免费（实测口径） |
| **抽实体关系**（`chat/completions`） | 按 tokens 计点 | **索引阶段的主要成本** |
| **写社区摘要**（`chat/completions`） | 按 tokens 计点 | 每个社区一次，社区越多这笔越大 |
| 全局 / 局部问答（`chat/completions`） | 按 tokens 计点 | 每次一小笔，`max_tokens` 可控 |

**四条成本纪律**：

1. **先用小样本**：10 个块的账单几乎可以忽略，但足以判断要不要往下走。
2. **低信息密度块不入库**：目录、参考文献、附录直接丢掉，省下的抽取费比什么都多。
3. **分批跑**：按目录/文件分批索引，每批完成即可查询，不必等全量。
4. **提示词写死输出格式**：模型少说废话，token 就省下来了。

> 平台同时给出**标准价**与**租户实际结算价**两套字段，两者可能差很多；
> **做预算一律按实际扣费算**，每次返回里的 `usage` 就是本次真实用量。
