# 出图提示词写法与各平台视觉风格

> 适用于 `sanjianke-image-factory`。`plan` 产出的 `prompt` 就是直接发给文生图模型的提示词。

## 一、一条好提示词的六段结构

按这个顺序写，模型最不容易漏元素：

```
主体 + 动作/状态 → 构图与视角 → 背景 → 光线 → 色调 → 画风
```

实例（小红书 3:4 封面）：

```
俯拍视角的现代简约桌面，一台笔记本电脑屏幕亮着，旁边散落着几部竖屏手机，
桌面整洁，上方留出大面积纯净背景，柔和的窗光从左上角斜射进来，
浅灰蓝与珊瑚橙双色调，点缀少量暖黄色，扁平插画风格，干净通透
```

| 段落 | 要写什么 | 常见错误 |
|---|---|---|
| 主体 + 动作 | 具体到能画出来 | 只写"一个人"（性别年龄动作全没有） |
| 构图与视角 | 俯拍/平视/特写/三分法；比例对应的留白方向 | 不写视角 → 模型随机给，一套图视角全乱 |
| 背景 | 场景或"纯色背景" | 不写 → 背景里冒出莫名其妙的杂物 |
| 光线 | 方向 + 质感（窗光/棚拍柔光/侧逆光/阴天散射） | 只写"好看的光" |
| 色调 | 2 主色 + 1 点缀色，写具体颜色名 | 写"高级感"（不是颜色） |
| 画风 | 扁平插画 / 实拍质感 / 3D 渲染 / 水彩 | 不写 → 相邻两张一个插画一个写实 |

长度建议 **40~120 字**。太短元素不全，太长模型开始丢元素。

## 二、四条铁律

### 1. 不要在图上要求生成文字

AI 出图的文字**基本都是错的**——中文尤甚，笔画会糊成乱码。提示词里写：

> ❌ `画面中央写"三剪客"三个大字`
> ✅ `上方留出大面积纯净背景`（留出压字区，文字后期用工具压）

如果确实需要画面里的"文字感"，用"模糊的图标""色块示意"代替，别让模型写具体字符。

### 2. 不编造文稿里没有的事实

方案阶段就写死了这条约束。**不要**让提示词出现：

- 文稿里没有的数字、销量、检测结论
- 文稿里没有的品牌 logo、机构名、人名（还会踩商标权和肖像权）
- "国家级认证""权威推荐"这类背书（广告法高风险）

需要数据可视化就写"把一组数字视觉化，用柱状色块示意"，让模型画抽象图形而不是具体数字。

### 3. 一套图必须视觉统一

单张好看、九张打架，是配图最常见的失败。统一三件事：**同色板、同光线方向、同画风**。
`plan` 默认会把这句塞进提示词；用 `--style` 覆盖成自己的口径。

### 4. 相邻两张构图不要重复

八张图全是"俯拍桌面 + 居中主体"，用户翻到第三张就腻了。
可以在 `--style` 里补一句：**相邻两张的构图不要重复**。

## 三、各平台视觉风格

### 小红书 —— 明亮生活感

- 关键词：明亮、干净、生活感、奶油色调、自然光、真实场景、浅景深
- 饱和度略高一点更抓眼；避免暗调、避免重工业风
- 主体占画面 40%~60%，上方留白给标题
- 常用画风：清新实拍质感 / 扁平插画（配图文时更稳）

### 公众号 —— 克制理性

- 关键词：极简、留白、高级灰、低饱和、理性、信息感
- 长条构图（2.35:1）：一个主体 + 大片留白，别塞满
- 分享到会话只显示左半部分，**主体靠左中**
- 常用画风：扁平插画 / 线条画 / 单色摄影

### 抖音 —— 高冲击力

- 关键词：高对比、强光比、霓虹、动感、第一眼冲击、全屏竖版
- 主体集中在中间 60% 垂直区间（上下都被 UI 遮挡）
- 颜色可以更狠：黑金、赛博、撞色
- 常用画风：3D 渲染 / 高对比摄影 / 潮流插画

### 头条 —— 纪实信息感

- 关键词：纪实摄影、自然、真实场景、信息密度、无滤镜感
- 避免过度插画化（头条读者对"假图"敏感）
- 主体居中偏右，左侧留标题压字区
- 常用画风：纪实摄影 / 半写实插画

## 四、`prompt_echo` 闸门与示例登记

**这条规则是从事故里来的**：提示词里写过的示例，哪怕明确标着"这是错的写法"，
模型照样照抄。标题工坊实测过——公众号那一轮最高分 89.0 的标题
**一字不差就是提示词里的示例**，排序因此作废。

出图场景更隐蔽：你不会一眼看出这张图和测试用例长得一样，而是"看起来挺正常"，
直到发现整套配图是同一个模子。

### 规则

1. 提示词里**不许出现任何一条可直接复制的完整出图提示词**
2. 举例只用**跨主题**的示例（比如"香蕉形状的蓝牙音箱"——正常业务不会是这个）
3. **新增示例必须登记到 `scripts/run.py` 的 `PROMPT_SAMPLES`**

```python
PROMPT_SAMPLES = [
    "一只黄色香蕉形状的蓝牙音箱，纯白背景，柔光棚拍，主体居中",
    "a yellow banana-shaped bluetooth speaker on a pure white background, soft studio light",
    "橙色渐变背景上一个白色圆形图标，极简扁平插画风，无文字",
]
```

### 判定口径（实测标定）

**三条判据，任一命中即拦**（去标点与空白后比，只留中文/字母/数字）：

| # | 判据 | 阈值 | 抓的是什么 |
|---|---|---|---|
| 1 | 去标点后**完全相同** | — | 逐字照抄、只改标点 |
| 2 | 字符二元组 **Jaccard** | ≥ 0.75 | 长度相当的同构改写 |
| 3 | 示例二元组的**覆盖度** | ≥ **0.60** | 把示例**夹带进更长的提示词**里 |

长度门槛是**相对**的：目标归一化长度 < `max(6, 示例长度/2)` 就不比（短串二元组太少，
指标会虚高）。示例 25 字 → 门槛 12，示例 72 字 → 门槛 36。

判据 3 是补上的漏洞：出图提示词动辄 60~120 字，示例只有 25 字，而 Jaccard 的分母是
两份二元组的**并集**，示例那一侧被长提示词摊薄得极狠——示例原样嵌进去也照样放行。

| 输入 | Jaccard | 覆盖度 | 结果 |
|---|---|---|---|
| 逐字照抄 | 1.000 | 1.000 | 拦 |
| 只改标点 | 1.000 | 1.000 | 拦 |
| 少两个字 | 0.840 | — | 拦（判据 2） |
| 加一个尾巴（+4 字） | 0.857 | 1.000 | 拦（判据 2） |
| 同构照抄（换一个词） | 0.778 | 0.875 | 拦（判据 2） |
| 英文示例的近亲 | 0.766 | — | 拦（判据 2） |
| 示例原样嵌入 + 补 9 个字（34 字） | 0.727 | **1.000** | **拦（判据 3）** |
| 示例原样嵌进 102 字的六段结构提示词 | 0.245 | **1.000** | **拦（判据 3）** |
| 换两个词 | 0.714 | **0.833** | **拦（判据 3）** |
| 真实业务提示词 | 0.042 | 0.167 | 放行 |
| 另一条业务提示词 | 0.000 | 0.000 | 放行 |

真实产出与示例的安全距离：17 条真实/正常提示词里 **Jaccard 最大 0.443、覆盖度最大 0.547**，
误伤 0 条。覆盖度那一侧余量最薄的一条是上游文档里与英文示例同源的句子（0.547），
离 0.60 还有 1.1 倍余量。

**已知边界**：判据 3 确实把「换两个词」也拦了（覆盖度 0.833）——这是**刻意的口径变更**：
一条 25 字的示例里 83% 的二元组都被抄走，落进产出里就是同一个模子。
若不想拦，把 `ECHO_CONTAIN` 调高即可，但那样"示例原样嵌入"的漏洞就又回来了。

## 五、提示词模板

### 封面（小红书 3:4）

```
{俯拍/平视}视角的{场景}，{主体}正在{动作}，{场景细节}，
上方留出大面积纯净背景，{光线方向与质感}，{色1}与{色2}双色调，
点缀少量{色3}，{画风}，干净通透，无文字
```

### 内文配图（把抽象变具体）

```
{主体}的{特写/中景}，{具体动作或状态}，背景{虚化/纯色}，
{光线}，{色调}，{画风}，焦点单一，无文字
```

### 对比图（左右分栏）

```
左右分栏对比构图，左侧是{状态A的具体画面}，光线偏冷偏暗；
右侧是{状态B的具体画面}，光线明亮温暖，中间用一条细竖线分隔，
{色1}与{色2}主色调，{画风}，简洁清晰，无文字
```

### 数据图（抽象化数字）

```
极简构图，{若干柱状/圆形色块}按高低排列示意数据对比，
背景大面积留白，{色调}，{画风}，画面中没有任何数字与文字
```

## 六、反复画不对怎么办

| 问题 | 调法 |
|---|---|
| 主体太小 / 太满 | 加"主体占画面约 50%""四周留白" |
| 视角不对 | 明确写"俯拍/平视/低角度特写"，别用"好看的视角" |
| 颜色跑偏 | 用具体颜色名（"珊瑚橙 #FF7F50 一类"），别写"高级感" |
| 风格不统一 | 把画风词写成固定的一句，所有条目逐字复用 |
| 画面里冒出文字 | 检查提示词有没有要求文字；补一句"画面中无任何文字" |
| 同一套图风格打架 | 用 `--style` 统一色板/光线/画风，重跑 `plan` |

改完提示词重跑 `gen` 会**重新出图并重新扣费**——因为断点 key 含提示词哈希，
改了提示词就是新的一项。这是设计如此（改了就该重画）。
只改摆放位置、不改提示词的话，重跑会被直接跳过、不重复扣费。
