# 各平台尺寸规范与安全区

> 本文件是三剪客 · 新媒体配图工厂的口径依据。所有比例都对应 `scripts/run.py` 里的
> `PLATFORMS` preset，改口径请同时改代码与本文档。

## 一、preset 对照表

| preset | 平台 | 设计比例 | 生成用 `aspect_ratio` | 目标像素 | 实测产出像素 |
|---|---|---|---|---|---|
| `xiaohongshu` | 小红书 | 3:4 | `3:4` | 1080x1440 | **864x1184**（偏差 2.70%） |
| `wechat` | 公众号头图 | 2.35:1 | `21:9` | 900x383 | **1536x672**（需 `--snap` 裁到 2.35:1） |
| `douyin` | 抖音 | 9:16 | `9:16` | 1080x1920 | **768x1344**（偏差 1.56%） |
| `toutiao` | 头条 | 16:9 | `16:9` | 1280x720 | **1344x768**（偏差 1.56%） |
| `square` | 通用方图 | 1:1 | `1:1` | 1024x1024 | **1024x1024**（精确） |

「实测产出像素」是 1K 档真金白银跑出来的数，不是文档抄的。

## 二、为什么公众号要用 21:9 生成

公众号头图口径是 **2.35:1（900x383）**。但 `nano_banana` 的 `aspect_ratio` 可选值只有：

```
auto / 1:1 / 16:9 / 9:16 / 4:3 / 3:4 / 3:2 / 2:3 / 5:4 / 4:5 / 21:9
```

最宽只到 `21:9` = 2.333:1，**没有 2.35:1**。所以本包：

1. 用 `21:9` 生成（视觉上几乎无差别，1536x672）
2. 加 `--snap --snap-on-design` 居中裁到 2.35:1（裁后 1536x653 附近）

**不要**去请求不存在的比例——上游会兜到 `auto`。

## 三、上游按 32 对齐（影响所有比例）

实测结论：上游先定总像素、再把每边向下对齐到 **32 的倍数**，所以一半的比例给不出像素级精确值：

| 请求 | 实测像素 | 数值比例 | 目标比例 | 偏差 | 是否精确 |
|---|---|---|---|---|---|
| `1:1` | 1024x1024 | 1.0000 | 1.0 | 0% | ✅ |
| `3:4` | 864x1184 | 0.7297 | 0.75 | **2.70%** | ✗ |
| `4:3` | 1184x864 | 1.3704 | 1.3333 | 2.78% | ✗ |
| `16:9` | 1344x768 | 1.7500 | 1.7778 | **1.56%** | ✗ |
| `9:16` | 768x1344 | 0.5714 | 0.5625 | **1.56%** | ✗ |
| `21:9` | 1536x672 | 2.2857 | 2.3333 | 2.04% | ✗ |
| `2:3` | 832x1248 | 0.6667 | 0.6667 | 0% | ✅ |
| `3:2` | 1248x832 | 1.5000 | 1.5 | 0% | ✅ |
| `4:5` | 896x1152 | 0.7778 | 0.8 | **2.78%** | ✗ |
| `5:4` | 1152x896 | 1.2857 | 1.25 | **2.86%** | ✗ |

（`4:3` / `21:9` 也在 32 对齐下产生偏差，只是 `1:1` / `2:3` / `3:2` 恰好整除。）

**这不是网关 bug**，是扩散模型按 32 对齐的常规做法。但它意味着
「请求比例 == 产出比例」这个断言对一半的比例天然不成立——所以闸门默认容差 3%，
并且**把真实像素与偏差原样打印出来**，不藏。

要像素级精确就加 `--snap`：按请求比例居中裁剪，裁完再读一次文件头复核。

### 裁剪后的量化地板

裁到精确比例时，**像素只能是整数**，本身带舍入误差：

| 目标比例 | 裁后像素 | 偏差 | 相邻整数像素间隔 |
|---|---|---|---|
| `3:4` | 864x1152 | 0.0000% | 0.087% |
| `1:1` | 864x864 | 0.0000% | 0.116% |
| `2.35:1` | 864x368 | **0.0925%** | 0.272% |

所以脚本里有一个 **0.0025 的容差地板**（`RATIO_TOLERANCE_FLOOR`）：
用户把 `--ratio-tolerance` 调到比它还小时，会把"本来就必须存在"的舍入误差判成不合格。
地板仍能抓住真错——请求 `3:4` 却给 `2:3` 的偏差是 11%，比地板大 40 倍。

## 四、各平台构图与安全区

### 小红书 3:4（1080x1440）

- 信息流里 3:4 占位最高，是笔记首图的默认选择
- **上方约 1/4 留白**：标题与账号角标会压在左上角，主体不要放那儿
- 底部约 1/8 是互动条遮挡区
- 风格：明亮、干净、生活感；饱和度略高一点更抓眼
- 图上不要放文字——AI 出图的文字基本都是错的

### 公众号头图 2.35:1（900x383）

- 长条形，**横向信息带**：适合"一个主体 + 大片留白"
- 分享到会话时只显示**左半部分**，所以主体尽量靠左中
- 右侧留出标题压字区
- 风格：克制、理性，色调偏冷或高级灰

### 抖音 9:16（1080x1920）

- 全屏竖版，**上下各留 12% 安全区**
- 底部约 20% 被作者信息、评论区入口遮挡
- 右侧约 15% 是点赞/评论按钮区
- 主体必须集中在**中间 60%** 的垂直区间
- 风格：高对比、强光比、第一眼有冲击力

### 头条 16:9（1280x720）

- 横版封面，主体居中偏右，**左侧留标题压字区**
- 三图模式下会被裁成方图，所以主体不要贴边
- 风格：纪实、信息密度高，避免过度插画化

### 通用方图 1:1（1024x1024）

- 头像、商品主图、社群分享卡
- 主体居中，四周留 10% 安全边距（圆形裁切场景）

## 五、一套图的视觉统一

方案阶段就要求同一套配图**同色板、同光线方向、同画风**，否则出来是一堆风格打架的图。
默认口径：**2 主色 + 1 点缀色**、同一光线方向、同一画风（如"扁平插画"或"实拍质感"），
相邻两张构图不重复。用 `--style` 可以覆盖：

```bash
python3 scripts/run.py plan 文章.md --style "莫兰迪灰绿主色 + 陶土橙点缀，柔和顶光，纸质感噪点插画风"
```

## 六、自定义比例

想加自己的 preset，改 `scripts/run.py` 的 `PLATFORMS` 字典即可，
`gen_ratio` 必须是 `ASPECT_RATIOS` 里的值（在 `scripts/a7w.py`）：

```python
"video-cover": {
    "name": "视频号封面",
    "design_ratio": "6:7",
    "gen_ratio": "4:5",       # 6:7 上游不支持，取最接近的 4:5
    "pixel_hint": "1080x1260",
    "note": "……",
},
```
