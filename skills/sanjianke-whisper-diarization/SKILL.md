# 三剪客 · 说话人分离转写

普通的语音转写只给你「说了什么」，但访谈、会议、播客、庭审这类素材真正需要的答案是「**谁**在什么时候说了什么」。这两件事在技术上完全不是一回事：转写关心文字，说话人分离关心「这一段声音属于同一个人吗」。

这个工具把两件事串成一条流水线：先从音频里分离出人声（减少背景音乐对声纹判断的干扰），用语音识别得到文字，再通过说话人嵌入判定每个片段的说话人，最后用强制对齐把词级时间戳校准一遍，让「文字」和「谁说的」能精确地落到同一条时间轴上。产出物是一份带说话人前缀的文稿和一个 SRT 字幕文件。

它的价值在于**把两个独立模型的结论缝合到词一级**。代价是依赖链不轻——需要 FFMPEG 与 Cython 作为前置，还要从源码安装几个 Git 依赖，并且默认跑在 GPU 上。

**上游项目**：`whisper-diarization`　**仓库**：https://github.com/MahmoudAshraf97/whisper-diarization

## 什么时候用 / 不用

**用它**：

- 用户说「把这段访谈转成文字，标出每句话是谁说的」「会议记录要区分发言人」。
- 要把多人对话做成分角色字幕：播客、圆桌、双人访谈、多嘉宾直播回放。
- 需要**词级时间戳**再往上做后续加工：切片段、对齐画面、做逐字稿检索。
- 素材有背景音乐或音效，希望先分离人声再识别，以提高说话人判定的准确度。
- 想做离线本地处理，不想把会议录音传到第三方转写服务上。
- 长音频、想缩短总耗时，且机器显存充足（可走并行脚本让两个模型同时跑）。

**不要用它**：

- **说话人同时开口（重叠语音）**。上游把这个列为已知限制——两个人抢话的部分目前处理不了。
- **只想要一份纯文字转写、不关心谁说的**。那就是普通 ASR 的活，用轻量方案更快，不必背上这套重依赖和模型组合。
- **只想做语音识别或只想做说话人分离中的一件**。这条流水线是端到端耦合的，单要一半属于杀鸡用牛刀。
- **环境里装不了 PyTorch / NeMo 这一整套，或有硬前置缺失**：它需要 FFMPEG 与 Cython，还要从源码装若干 Git 依赖；显存/内存小又要处理长音频同样别硬上，默认会依次加载多个模型，容易 OOM。
- **要求把说话人映射到真实身份**。输出的是聚类编号，不做声纹身份确认。

## 安装
**前置条件（必须先满足）**：Python >= 3.10；**FFMPEG** 与 **Cython**。上游说明 Python 3.9 也能用，但需要手工逐个安装依赖。

先装 Cython：

```bash
pip install cython
```

或者用系统包管理器：

```bash
sudo apt update && sudo apt install cython3
```

再装 FFMPEG（按平台选一条）：

```bash
# Ubuntu / Debian
sudo apt update && sudo apt install ffmpeg

# Arch Linux
sudo pacman -S ffmpeg

# macOS (Homebrew)
brew install ffmpeg

# Windows (Chocolatey)
choco install ffmpeg

# Windows (Scoop)
scoop install ffmpeg

# Windows (WinGet)
winget install ffmpeg
```

最后按仓库的约束文件安装依赖（**不要漏掉 `-c constraints.txt`**，它负责把版本卡在兼容区间）：

```bash
pip install -c constraints.txt -r requirements.txt
```

依赖清单里包含来自 Git 仓库的若干包（人声分离、标点恢复、强制对齐），因此安装过程需要能访问代码托管站点；其中还有 `nemo_toolkit[asr]` 这类体积较大的组件。

## 常用操作

**1. 最简用法：给一个音频文件，拿文稿和字幕**

```bash
python diarize.py -a AUDIO_FILE_NAME
```

输出写在**输入音频同目录、同主文件名**下：`.txt`（带说话人前缀的文稿）和 `.srt`（带说话人标签的字幕），编码为带 BOM 的 UTF-8。

**2. 长文件、音乐少的素材：关掉人声分离加速**

```bash
python diarize.py -a meeting.mp3 --no-stem
```

人声分离那一步对长音频很耗时；上游说明素材里音乐不多时可以直接关掉。若这一步执行失败，它会记录警告并回退用原始音频继续，不会中断。

**3. 显存吃紧：调小批大小，或关掉批式推理**

```bash
python diarize.py -a long_talk.wav --batch-size 4
python diarize.py -a long_talk.wav --batch-size 0
```

`--batch-size 0` 表示回到非批式的长音频推理路径。

**4. 指定模型与设备**

```bash
python diarize.py -a talk.mp3 --whisper-model large-v2
python diarize.py -a talk.mp3 --device cpu
```

`--whisper-model` 默认是 `medium.en`；`--device` 默认在检测到 GPU 时用 `cuda`，否则用 `cpu`，可以显式指定。

**5. 语种指定与数字处理**

```bash
python diarize.py -a talk.mp3 --language zh          # 语言检测失败时手动指定
python diarize.py -a talk.mp3 --suppress_numerals    # 数字按读法转写，提升对齐准度
```

`--suppress_numerals` 会把所有数字转成文字读法，换来更好的对齐效果——但这意味着**输出里不会再有阿拉伯数字**。

**6. 显存充足时走并行脚本**

```bash
python diarize_parallel.py -a AUDIO_FILE_NAME
```

它与普通脚本的差别是把说话人分离和语音识别**并行**跑（两个模型互相不依赖，所以结果一致），适合显存 >= 10GB 的机器。上游把这个脚本标注为实验性。

**7. 自检：确认参数清单以当前版本为准**

```bash
python diarize.py --help
python diarize_parallel.py --help
```

注意两个脚本的参数默认值**不完全相同**（例如模型名与批大小），以 `--help` 输出和源码为准。

## 常见坑

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 装依赖时某些包编译失败、报缺 Cython | Cython 是安装这些依赖的**前置条件**，必须**先**装好再装依赖 | 先 `pip install cython`（或系统装 `cython3`），再执行 `pip install -c constraints.txt -r requirements.txt` |
| 跑起来报找不到 ffmpeg / 无法解码音频 | FFMPEG 是硬前置，且必须能被命令行调用 | 按平台装好 ffmpeg 并确认在 PATH 中，再重跑 |
| 装完出现 numpy 相关的报错或诡异的数值异常 | 仓库用约束文件把 numpy 卡在 2.0 以下，绕过它自己装最新版会破坏兼容 | 安装时**带上** `-c constraints.txt`；不要事后单独升级 numpy |
| 一跑就显存不足（OOM） | 流水线里会依次加载多个模型，批式推理又额外吃显存 | 先调小 `--batch-size`（不行就设 0 走非批式路径）；换更小的 `--whisper-model`；或改 `--device cpu`（会慢很多） |
| 看到「Source splitting failed, using original audio file」 | 人声分离那步执行失败（依赖缺失、显存不足、音频异常等），它会**回退**用原始音频继续 | 这只是警告不是崩溃；但说话人判定准确度可能下降。检查人声分离依赖是否装全，或接受回退结果 |
| 想让并行脚本更快，却报多进程相关的错误 | 并行脚本用的是 spawn 启动方式，且上游标注为实验性 | 先确认显存是否 >= 10GB；确认脚本本身作为主程序入口运行（不要在外层乱包一层）；不稳定就退回普通脚本 |
| 长音频跑得非常慢，或中途卡住 | 默认会做人声分离，这一步对长文件开销很大 | 用 `--no-stem` 跳过（素材音乐少时尤其合适）；或先切成小段分别处理再合并 |
| 输出里一个阿拉伯数字都没有，全是文字读法 | 打开了 `--suppress_numerals`，它的设计就是把数字转成读法 | 这是预期行为。要保留阿拉伯数字就别加这个参数，但要对对齐精度下降有预期 |
| 文稿里同一句话被安到了错误的人头上 | 两个人同时说话，或音频里说话人声音高度相似 | 重叠语音是上游明确的已知限制。可以尝试开启人声分离（不要加 `--no-stem`）、换用更合适的模型，或人工复核 |
| 英文以外的素材，标点恢复被跳过 | 标点恢复模型只覆盖部分语种，不在覆盖范围内时会记录警告并沿用原标点 | 属预期行为；需要标点就自己做后处理，或确认语种在覆盖清单内 |
| 输出文件里出现奇怪的乱码前缀字符 | 输出用的是**带 BOM 的 UTF-8** | 用支持 BOM 的编辑器打开；程序化读取时按 `utf-8-sig` 解码 |
| 工作目录里多出一堆 `temp_outputs_<pid>` 目录，进程被强杀后残留 | 人声分离的中间产物写在进程号命名的临时目录里，正常结束会清理，异常终止则残留 | 确认没有进程还在用之后手工删除；下次运行前清一下避免占满磁盘 |
| 中文素材的识别结果不理想 | 默认模型是英文模型 | 用 `--whisper-model` 换成多语种模型，并用 `--language` 显式指定语种 |
| 用 CPU 跑，慢到无法接受 | 这套流水线（人声分离 + 识别 + 声纹嵌入 + 对齐）在 CPU 上开销极大 | 尽量用 GPU；或先确认是否真的需要说话人分离这条完整链路 |

## 触发场景

- 「把这段访谈转成文字，标清楚每句话是谁说的」
- 「会议录音要分角色整理成纪要」
- 「这个播客帮我出分角色字幕」
- 「双人对话的逐字稿，要能看出谁在说」
- 「音频有背景音乐，先分离人声再识别」
- 「transcribe this interview and diarize the speakers」

## 能力边界

**覆盖**：

- 端到端流水线：人声分离 → 语音识别 → 说话人嵌入与分段 → 强制对齐修正时间戳 → 标点恢复重排句子 → 按句子聚合说话人。
- 产出**带说话人标签**的文稿（`.txt`）与字幕（`.srt`），时间戳修到词级后再聚合到句级。
- 说话人聚类编号：输出「说话人 0 / 1 / 2 …」这类标签，足以区分不同发言者。
- 可选的静音排除与分段：流水线里包含 VAD 分段环节以剔除静音。
- 语种：可自动检测，也可用 `--language` 手动指定；识别模型可用 `--whisper-model` 切换。
- 设备选择：GPU 或 CPU 显式指定。
- 批式推理可调（`--batch-size`），设 0 可回到非批式长音频路径。
- 两种执行形态：默认顺序脚本，以及显存充足时的并行脚本（两个模型并行跑，结果一致）。
- 数字读法转写选项（`--suppress_numerals`），用于提升对齐精度。

**不覆盖**：

- **重叠语音**：多人同时说话无法正确归属，这是上游明确列出的已知限制。
- **身份识别**：不做声纹验证，也不把说话人编号映射成真实姓名。
- **翻译**：只转写原文，不做翻译。
- **音视频剪辑**：不切片段、不出片、不做后期；它只产出文稿和字幕。
- **说话人数量与名字的交互式编辑**：没有「把说话人 1 改名成张三」这种界面能力，需要自己在输出文件上改。
- **每句最大长度的强制约束**：上游把它列在待改进项里，说明当前没有按句长切分的控制。
- **不做实时/流式**：是离线批处理式的整文件流水线。

## 依赖条件

- **Python >= 3.10**（上游说明 3.9 可用但需手工逐个装依赖）。
- **Cython**：作为安装这些依赖的前置条件，必须先装。
- **FFMPEG**：必须安装且能被命令行调用。
- 仓库的 `requirements.txt`，其中包含语音识别库、说话人分离所需的重型工具包、标点恢复模型库、以及若干从 Git 安装的包（人声分离、标点恢复、强制对齐）。
- **`constraints.txt` 必须一起用**：它把 numpy 限制在 2.0 以下，并固定了一个额外来源的依赖。
- 模型权重首次运行时下载，需要网络与磁盘空间。
- GPU 强烈建议：默认 `--device` 在检测到 GPU 时用 `cuda`；并行脚本上游建议显存 >= 10GB。
- 不需要账号或 API Key。

## 已知限制

- **重叠说话人尚未解决**。上游提出的思路是先分离音频、只保留单一说话人再送进流水线，但那意味着高得多的计算量。
- 上游在 README 中说明：语音识别与说话人分离的参数目前**写死在脚本与辅助模块里**，命令行只暴露其中一部分，后续才计划补齐。
- 并行脚本被明确标注为**实验性**，预计会有报错和粗糙之处。
- 按句最大长度切分 SRT 尚未实现，属上游的未来改进项。
- 人声分离失败时不会中断，而是回退到原始音频继续——好处是流程不崩，代价是说话人准确度可能下降，需要自己判断结果是否可用。
- 输出固定为带 BOM 的 UTF-8，程序化消费时注意按 `utf-8-sig` 解码。
- 两个脚本的默认参数不一致（模型名、批大小等），复制命令时容易串；以各自的 `--help` 为准。
- 具体版本号、发布日期与 star 数请以仓库页面实时信息为准，此处不做断言。
- 参数名与默认值可能随版本调整：执行前请以 `python diarize.py --help` 与仓库当前内容为准。

## 自检清单

- [ ] Python 版本 >= 3.10。
- [ ] **先**装好了 Cython，**再**装其余依赖。
- [ ] FFMPEG 已安装且能在命令行调用。
- [ ] 安装时带了 `-c constraints.txt`；没有事后自行升级 numpy。
- [ ] 输入音频格式能被本机 ffmpeg 解码；路径中没有会被 shell 误解析的字符。
- [ ] 确认设备：GPU 就用 `--device cuda`，纯 CPU 就对耗时与内存有心理预期。
- [ ] 素材语种确认过，必要时用 `--language` 指定、用 `--whisper-model` 换多语种模型。
- [ ] 长音频且音乐少：考虑 `--no-stem` 加速；有背景音乐则保留人声分离。
- [ ] 显存不够时先降 `--batch-size`，再考虑换小模型或切分音频。
- [ ] 想用并行脚本前确认显存 >= 10GB，并接受它的实验性。
- [ ] 阅读结果时注意输出是带 BOM 的 UTF-8；程序化读取用 `utf-8-sig`。
- [ ] 跑完后确认 `temp_outputs_<pid>` 已被清理；异常终止后手工清掉残留。
- [ ] 抽查若干片段，确认说话人归属正确、时间戳与音频对得上；对重叠对话部分人工复核。
- [ ] 需要真实姓名而非编号时，明确告诉用户输出是聚类编号，改名要自行处理。
