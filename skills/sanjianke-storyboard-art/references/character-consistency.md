# 角色一致性与画风：让同一个角色在 N 格里长得一样

这是本包存在的理由。这份文档写清三件事：设定卡怎么写、提示词怎么约束、
参考图怎么用——以及**哪些事这三道加起来也压不住**。

---

## 一、为什么一致性难

文生图每次都是从头采样。同一个提示词跑两次，脸就会变；换了景别与构图，变化更大。
所以"写一句「同一个角色」"是没用的——模型不知道上一格长什么样。

能压住一致性的只有三样东西：

1. **一份稳定的文字描述**（设定卡的特征词）—— 让模型每次都收到同样的约束
2. **参考图**（`action=edit` + `image_urls`）—— 让模型看到上一格/锚点图长什么样
3. **每一次都真的把 1 写进提示词** —— 这一步最容易被省掉，然后一致性就崩了

本包把第 3 步做成**硬闸门**，因为它是唯一能零成本、100% 客观核对的一步。

## 二、角色设定卡怎么写（`characters`）

### `features`：跨格复述的唯一凭据

规则只有一条：**一个画师只看这几条，画 10 次都能画出同一张脸。**

| 该写 | 不该写 |
|---|---|
| 发型 + 发色（"黑色短碎发"） | 性格（"性格冷酷"） |
| 瞳色（"深棕瞳色"） | 眼神（"眼神深邃"） |
| 脸型/疤痕/痣的**具体位置**（"左眉尾一道浅疤"） | 气质（"看起来很忧郁"） |
| 体型（"瘦高身形"） | 年龄形容词（"十七岁"——写进 `appearance`） |
| 固定配饰/道具（"左手戴老式金属表"） | 临时状态（"手上有机油"——那是画面不是设定） |
| 服装的**颜色 + 款式 + 材质**（"深蓝棉布工作围裙"） | 剧情（"被雨淋湿"——那是某一格的事） |

数量 3~6 条，每条 4~12 字。**太多会互相稀释**（模型抓不住重点），
太少就压不住（1 条"黑发"谁都符合）。

实测产出（可以当模板看）：

```
# chen       陈默（主角）
     特征词：黑色短碎发、深棕瞳色、窄长脸、右手背机油污渍、左眉尾一道浅疤
     配色：深蓝 #2B3A55、灰白 #D9D9D2、暗棕 #5A3E2B
     外形：十七岁少年，瘦高身形，清瘦稚气
     服装：深蓝色棉布工作围裙配灰白衬衫，袖口卷至小臂
     禁项：不要胡须、不要眼镜
```

### `palette`：配色（软约束）

1~3 条 `{"name": "深蓝", "hex": "#2B3A55"}`。`name` 会被逐字核对（配色漂移检测），
所以用**常用的中文颜色名**（深蓝/灰白/暗红/墨绿），不要生造词——
生造词不但模型看不懂，闸门也核不准。

配色是**风格软约束**：默认只报告不拦（`--min-palette-ratio 0`）。
人物配色讲道理上应该一致，但强光和夜戏本来就会改变感知色，
一刀切硬拦会造成大量误报。要做硬约束就把阈值调到 0.5 之类。

### `negative`：这个角色不该出现什么

"不要胡须""不要眼镜""不要浓妆"。**负面约束比正面描述更容易被忽略**，
所以只在真的踩过坑时写，不要堆。

### 断点 key 里的「角色设定卡」那一维

`charsheet_digest` 只取**这一格实际出场角色**的卡片内容做摘要。好处是：

- 改了一个本格没出场的角色 → 本格**不重出**（省钱）
- 改了本格出场角色的**任何一个字** → 本格**必重出**（防静默复用旧脸）

## 三、硬约束提示词的结构（`shots`）

一个能压住一致性的分镜提示词，骨架是五段：

```
[画风块] + [景别/机位] + [主体：角色名 + 全部特征词] + [动作与环境] + [光线]
```

实测的一条真提示词（本包真机运行产出）：

```
写实厚涂漫画，细密铅笔线稿，低饱和冷调，雨夜高对比侧光。中景正面。
钟表修理铺柜台前，墨绿雨衣女人，黑色齐肩直发、浅灰瞳色、鹅蛋脸、左耳垂小痣、雨帽檐滴水，
墨绿与深灰与暗红配色，把一只停摆铜壳怀表轻轻放下；
柜台内侧陈默，黑色短碎发、深棕瞳色、窄长脸、右手背机油污渍、左眉尾一道浅疤，
深蓝与灰白与暗棕配色，侧光切过两人。
```

注意几件事：

- **特征词是逐字复述的**，不是改写。闸门按去标点后的原文核对，
  把"银灰色短发"写成"银灰短发"就算漏词——这是刻意的严格：
  改写的边界没法用规则判定，逐字复核是唯一客观的口径。
- **配色词也写进去了**（深蓝/灰白/暗棕），否则会记配色漂移
- **画面描述与台词分家**：台词不进提示词，出图不画字
- **不要文字**：写成"不要在画面上生成任何文字、字幕、招牌字"
  ——但这句**压不住**（见下面「已知边界」），所以加字这一步留给后期

## 四、参考图怎么用（`images --ref-mode`）

上游的 `submit` 支持 `action=edit` + `image_urls`（最多 12 张，schema 实查
`max_reference_images = 12`）。这是**把"和上一格同一间屋子、同一套衣服"钉住**的主要手段。

| 模式 | 参考图从哪来 | 适用 |
|---|---|---|
| `prev`（默认） | **上一格任务返回的 `image_url`** | 同场景连续、同画风连续、同服装连续 |
| `anchor` | 设定卡里的 `anchor_urls`，或 `--anchor chen=<URL>` | **把角色的脸钉住**（最有效） |
| `both` | 锚点图 + 上一格 | 既要脸稳又要场景连贯 |
| `none` | 无 | 空镜、转场、每格都是独立画面时 |

**参考图必须是公网可访问的 HTTP/HTTPS 地址**（上游 `image_urls` 的口径），
本地文件传不上去。本包**不做上传**：schema 里没有实测过的图片上传路径，
与其编一个不如把边界写清楚。两个可行做法：

1. 用本包先出一张**角色设定图**（一格里只画这个角色的正脸 + 全身），
   拿它返回的 `image_url` 当锚点，后面所有格都 `--anchor chen=<那个 URL>`
2. 把已有素材放到自己可公开访问的地址上

### 实测边界（**这段很重要，别当成"参考图能解决一切"**）

真机测了 2 格：第 1 格 `generate`，第 2 格 `edit` + 第 1 格的 `image_url`。

**压住了的**：同一间钟表铺、同一盏台灯、同一个窗口、同一种光线方向与画风——
场景连续性非常好，读者一眼看出是同一个地方。

**没压住的**：第 2 格的提示词里写了两个人（女人 + 学徒），产出**仍是单人主体**。
`action=edit` 倾向于"改这张图"，而不是"在这张图里加一个人"。

所以口径是：

| 你要什么 | 该怎么做 |
|---|---|
| 同场景/同画风/同服装连续 | `prev` 很有效 |
| 同一个角色的脸稳定 | `features` + 角色锚点图（`anchor`） |
| **多人同框** | **别指望上一格带出来**：把这一格当独立镜头写清楚站位与谁在前谁在后，或一图一角色分开出 |
| 大幅改变构图 | 用 `none` 或只挂锚点图；挂着上一格又要求大改构图，模型会两头不讨好 |

另外记住：**参考图变了，断点 key 就变**（`refs` 是八维之一），所以改参考图会重出并重新扣费——
这是设计如此（输入变了就该重画）。

## 五、闸门做什么、**不做什么**

### 做

逐字核对每一格的出图提示词，报出「第几格 · 哪个角色 · 漏了哪个词」：

```
  ✗ chen       出场  3 格，特征词 5 条，漏词的格：3
     !! 第 3 格 · 陈默（chen）漏了特征词「左眉尾一道浅疤」
  结论：不通过（漏词如上）
```

退出码 3，`images` 在提交任何任务之前就拦下（不花一分钱）。

### 不做（**这三条是刻意的**）

1. **不替模型补特征词。** 如果脚本自动把特征词拼进提示词，闸门就永远绿了——
   那是**假绿闸门**。同族踩过的坑：只信模型自报的字段做判定，真正该判命的那条恰好漏判，
   闸门绿着，问题留到用户手上才炸。所以本包只核对、不代写。
2. **不把画风块算进核对范围。** `style_bible` 是全篇共用的；
   如果特征词能靠它满足，某一格漏写照样绿。所以特征词只在**该格自己的 `prompt`** 里找。
3. **不判"像不像"。** 我们没有（也不打算假装有）图像级的角色识别。
   "这两张脸是不是同一个人"最终还是要人眼过一遍——
   闸门能保证的是**输入约束没被漏掉**，这是它唯一能客观保证的事。

## 六、画风统一（`style_bible`）

全篇一个画风块，六个数：

| 维度 | 例子 |
|---|---|
| 画种/媒介 | 黑白网点漫画 / 写实厚涂 / 水彩 / 国风水墨 / 赛璐璐 |
| 线条 | 硬朗线稿 / 细密铅笔 / 无描线厚涂 |
| 明暗 | 高对比侧光 / 平光 / 逆光剪影 |
| 色彩倾向 | 低饱和冷调 / 高饱和暖调 / 无彩 |
| 质感 | 胶片颗粒 / 纸张纹理 / 干净数码 |
| 参考感 | 港漫写实 / 日式少年漫 / 欧美图像小说（**只写风格方向，不要写具体作品名**） |

画风块由 `characters` 产出（`style_bible`），`shots` 会把它写进每一格的提示词里，
`images` 也会把它拼进最终请求（如果分镜提示词里还没有的话）。
要临时换风格：`shots --style "…"` 会覆盖设定卡里的那一句。

**画风块进断点 key 吗？** 进——但它通过"提示词全文摘要"这一维间接进入
（画风块是最终提示词的一部分），不需要单独一维。

## 七、常见坑（一致性相关）

| 现象 | 原因 | 处理 |
|---|---|---|
| 一致性闸门报"某一格漏词" | 模型偷懒没复述全部特征词 | 重跑 `shots`；或手改那一格 `prompt` 补上，只重出这一格 |
| 主角稳、配角漂 | 配角出场少、参考图少 | 给配角也做锚点图；或在设定卡里把配角特征减到 3 条以内并选最显眼的 |
| 改了设定卡但图没变 | 断点命中 | 本包不会发生：`charsheet_digest` 是 key 的一维。若真没变，看 stderr 的"不复用旧图"提示 |
| 每格都是同一个构图 | 提示词照抄了示例 | `prompt_echo` 闸门会拦；检查是不是把示例文本留在了模板里 |
| 图上长出了字 | 扩散模型会把环境纹理读成文字 | 加"不要文字"能减少但压不住（实测门上的 `TIME REPAIR` 与镜像 `OPENING`）；**加字交给后期** |
| 参考图挂了但画风变了 | 参考图与提示词冲突 | 参考图只钉"长什么样"，画风仍由提示词决定；两者要一致 |
| 锚点图挂太多 | 超过 12 张 | 上游上限 12；本包超了直接报错，不会静默截断（截断会静默改变输入） |
