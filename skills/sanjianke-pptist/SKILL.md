# 三剪客 · 在线 PPT 编辑器

要在自己的产品里做一套**网页版幻灯片编辑器**——不是调用别人的服务，而是真的自己拥有一套编辑/演示的
前后端底座——`PPTist` 就是这个底座。它用 Vue 3 + TypeScript 实现，不依赖 UI 组件库，
把文字、图片、形状、线条、图表、表格、视频、音频、公式这些元素类型和编辑交互都做好了，
还带播放（放映）模式、批注、动画、主题。

**先说清楚一件事**：它**不是**开箱即用的工具，官方在原仓库第一段就写了「不应该直接将本项目作为工具使用，
也不支持开箱即用」。你如果是想找个在线做 PPT 的网站，它不解决你的问题；你要的是**拿它的代码做二次开发**。

**上游项目**：`PPTist`　**仓库**：https://github.com/pipipi-pikachu/PPTist

## 什么时候用 / 不用

**用它**：

- 你要**自己做一个 Web 幻灯片产品**，需要一个可改造的编辑器 + 放映器底座。
- 你要在现有系统里嵌入**在线演示文稿编辑能力**（低代码平台里的演示模块、在线课件等）。
- 你要做**模板式 AI 生成 PPT**：AI 只负责产出结构化数据，PPTist 作为承载与二次编辑的底座。
- 你要一个**纯前端的 PPTX 预览**（官方称对常见内容还原度约 85%+，用于浏览与轻量校对）。
- 你要往幻灯片里加**自定义元素类型 / 自定义主题 / 自定义快捷键**，需要源码级改造空间。

**不要用它**：

- 想找「打开就能用的在线 PPT 工具」——它不提供在线服务，也不开箱即用；直接去用成熟产品。
- 想把 PPTX 当唯一数据格式做**无损往返编辑**——官方明确说无法 100% 还原，动画、特殊图表、
  多层嵌套、高级样式都会丢。
- **闭源商用**：项目是 AGPL-3.0，网络服务也会触发开源义务；不接受就换 Apache 2.0 的旧版本
  （已停止维护）或联系作者付费授权。
- 把**复杂 PPT 转成高质量 PDF / 图片**当主业——它的 PDF 导出是走浏览器打印，官方建议正式环境
  用后端方案（如 Puppeteer）。
- 只想让 AI 生成一份 PPT 交付——AIPPT 在这里只是「一小部分功能」的 DEMO，官方自称参考实现，
  效果取决于模型能力与模板数量。

## 安装

环境要求：**Node.js ≥ 20**。

```bash
# 拉完整源码（不是 npm 包——官方明确说明它不做成 npm 包）
git clone https://github.com/pipipi-pikachu/PPTist.git
cd PPTist

npm install
npm run dev
# 浏览器访问 http://127.0.0.1:5173/
```

`package.json` 里的其它脚本：

```bash
npm run build        # 类型检查 + 生产构建（run-p type-check "build-only {@}"）
npm run build-only   # 只构建，不做类型检查
npm run type-check   # vue-tsc --build --force
npm run preview      # 本地预览构建产物
npm run lint         # eslint 检查并自动修复
```

国内网络可从镜像仓库拉取（Gitee / GitCode，官方 README 里列了同步镜像地址）。

没有官方 Docker 镜像；部署就是 `npm run build` 之后把产物当静态站点发布。

## 常用操作

**1. 本地起开发服务器**

```bash
npm install
npm run dev
```

**2. 生产构建并预览**

```bash
npm run build
npm run preview
```

**3. 找数据在哪：接后端时改这里**

幻灯片数据的核心在 `src/store/slides.ts`（Pinia store）。要持久化，通常是把 state 里的
这几项存到数据库：

- `title`：幻灯片标题 / 文件名
- `slides`：页面数组，每页含 ID、元素、备注、背景、动画、切页方式
- `theme`：主题（背景色、主题色、字体颜色、字体）
- `viewportSize`：可视区域宽度基数（默认 1000，即 1000 × 562.5 画布）
- `viewportRatio`：可视区域比例（默认 16:9）
- `templates`：幻灯片模板

完整类型定义见仓库 `src/types/slides.ts`。

**4. 目录结构速查（改代码时先认路）**

```
src/
├── assets/       静态资源（在线字体、样式）
├── components/   与业务无关的通用组件
├── configs/      画布尺寸、字体、动画、快捷键、预置形状/线条等配置
├── hooks/        跨组件复用的 hooks
├── mocks/        mock 数据
├── plugins/      自定义 Vue 插件
├── services/     API 方法
├── types/        类型定义
├── store/        Pinia store
├── utils/        通用工具方法
└── views/        业务组件：Editor（编辑）/ Screen（播放）/ Mobile（移动端）
```

**5. 做模板式 AIPPT**

流程（官方文档给的）：

1. 打开 PPTist，手工制作模板页面；
2. 用左上角菜单的「幻灯片类型标注」，给页面标页面类型、给元素标节点类型；
3. 导出 JSON，这就是 AIPPT 模板（本质上就是标了类型的普通页面）。

数据格式参考 `public/mocks/AIPPT.json`，类型定义在 `src/types/AIPPT.ts`；
模板最少 13 页、建议 30 页以上（封面、目录、过渡、内容、结束页各若干）。
想跳过模板直接让 AI 出页面数据，参考仓库里的 `AI_PPT_SCHEMA.md`。

**6. 加一个自定义元素类型**

看仓库 `doc/CustomElement.md`；画布与元素的基本原理看 `doc/Canvas.md`；
整体目录与数据看 `doc/DirectoryAndData.md`。

## 常见坑

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 刷新页面后刚才做的 PPT 没了 | 演示版是**纯前端**，没有后端，不保存任何数据 | 要么自己接后端持久化 `src/store/slides.ts` 的 state，要么在演示站上别当真用 |
| 插入本地图片后越来越卡 | 无后端时图片以 **Base64** 内联，数据体积暴涨 | 生产环境改成「先上传拿 URL，再引用地址」 |
| 快捷键按了没反应 | 焦点位置不对：翻页快捷键要焦点在左侧缩略图，元素快捷键要焦点在画布 | 先点一下对应区域再按；自定义快捷键改 `src/configs` 里的快捷键配置 |
| 粘贴没反应 | 浏览器剪贴板权限没给 | 允许浏览器访问系统剪贴板（且注意 HTTPS / localhost 限制） |
| 应用了预置主题但老页面没变 | 主题只对**新加**的元素和页面生效 | 用「应用主题到全部」把当前主题刷到所有页面 |
| 设置在线字体没立刻生效 | 需要先下载字体文件，文件较大 | 等下载完；或把字体文件放本地 `src/assets/fonts` |
| 打印 / 导出 PDF 和网页上不一样 | PDF 走浏览器打印，受打印设置影响 | 打印对话框里：边距选「默认」、取消「页眉和页脚」、勾选「背景图形」；正式环境改用后端渲染（如 Puppeteer） |
| 导出 PPTX 丢动画 / 样式偏了 | 导出基于 PptxGenJS，该库本身做不了的部分（如动画）项目也无能为力 | 把它当「尽量一致」而非一比一还原；关键样式导出后人工核一遍 |
| Safari 下有兼容问题 | 官方只优先兼容 Chrome、Firefox，不兼容 IE | 目标用户用 Safari 的话要自己测并修 |
| 移动端功能少 | 官方定位移动端为「临时应急的简单处理」 | 真正的设计制作在 PC 端做；移动端要完整功能得二次开发 |
| 导入 JSON 直接把入口给用户 | 官方不建议把 JSON 这种格式暴露给终端用户（有安全与校验问题） | 要导入 JSON 就在服务端做，并做好数据校验 |
| 商用被合规卡住 | AGPL-3.0，网络服务也触发开源义务 | 遵守 AGPL，或换已停维护的 Apache 2.0 旧版本，或付费拿独立商业授权 |

## 能力边界

**覆盖**：

- Web 幻灯片**编辑**：文字（富文本）、图片、形状、线条、图表（柱/条/折/面积/散点/饼/环/雷达）、
  表格、视频、音频、公式（LaTeX）
- 页面与元素操作：增删、拖拽排序、复制粘贴、组合、锁定、对齐分布、层级、吸附、缩放旋转
- 幻灯片级能力：背景、画布尺寸、主题、模板、分节、网格标尺、查找替换、批注、演讲者备注
- 动画：翻页动画、元素入场/退场/强调动画
- **放映**：画笔标注、黑板模式、缩略图导航、计时器、激光笔、自动放映、演讲者视图 / 观众视图
- 导入导出：PPTX（导入导出）、JSON、图片、PDF（打印）、项目自有 pptist 格式
- 模板式 AIPPT：页面 / 节点类型标注 + 结构化数据 + 模板拼接
- 移动端基础编辑与预览
- 可扩展：自定义元素类型、主题、快捷键、素材

**不覆盖**：

- 不是开箱即用的工具或在线服务，不提供 API / SDK / 托管服务
- 不做后端：不提供账号、存储、协作、版本管理，持久化要自己写
- 不保证 Office PPTX 的 100% 无损往返（动画、特殊图表、嵌套结构、高级样式会丢）
- 不保证像素级还原 PPTX（官方口径是常见内容约 85%+ 还原度）
- AIPPT 不是完整方案：不含模型接入、提示词工程、素材生成/检索、更多模板
- 不负责高质量 PDF 生成（走浏览器打印，官方建议正式环境用后端方案）
- 不兼容 IE，Safari 有兼容风险

## 依赖条件

- **Node.js ≥ 20**，包管理器用 npm（脚本定义在 `package.json`，可换 pnpm/yarn，官方脚本按 npm 写）
- 前端栈：Vue 3.5、TypeScript ~5.3、Pinia 3、Vite 5、Sass
- 关键第三方库：pptxtojson（导入 PPTX）、pptxgenjs（导出 PPTX）、echarts（图表）、
  ProseMirror 系列（富文本）、dexie（本地存储）、file-saver、html-to-image
- 浏览器：优先 Chrome / Firefox，不兼容 IE
- 不需要账号或 API Key（AIPPT 要接 AI 能力时才需要自行配置，且不能放前端密钥）

## 已知限制

1. 官方明确「不支持开箱即用」，必须做二次开发才能变成产品。
2. 不做成 npm 包：只能拉完整仓库改造，无法作为依赖库嵌入（官方专门解释了原因）。
3. 演示版纯前端、不保存数据；本地图片走 Base64，会导致性能问题。
4. PPTX 导入导出必然丢细节，动画等 PptxGenJS 不支持的特性无法导出。
5. 项目**没有完整开发文档**，官方只给了几篇辅助文档，上手需要读源码。
6. 若仓库内 `doc/Q&A.md` 说「导入 PPTX 暂无方案」，与较新的 README（称导入还原度约 85%+）不一致，
   以你实际拉到的那个版本的功能为准，别照抄旧结论。
7. AGPL-3.0 对闭源商用与网络服务都是硬约束。
