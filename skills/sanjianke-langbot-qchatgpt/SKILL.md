# 三剪客 · 多平台 IM 接大模型的机器人平台

你自己的大模型 API Key 放在那里吃灰，而客户和同事全在微信、企微、飞书、钉钉、QQ 群里——LangBot 就是把这两头接起来的中间层。它跑一个常驻进程，向上接各家 IM 平台，向下接大模型或 LLMOps 平台，中间用网页配置面板让你点选而不是改配置文件。装完之后你会得到一个 `http://<你的机器>:5300` 的控制台，机器人、模型、对话流水线、插件全在那里面加。

它不是一个聊天软件，也不是一个模型。它是"消息通道 + 模型路由 + 会话管理"的组合体，价值在于**一次配置、多平台复用同一套提示词与知识库**。

**上游项目**：`LangBot（原 QChatGPT）`　**仓库**：https://github.com/langbot-app/LangBot

## 什么时候用 / 不用

**用它**：

- 要在微信 / 企业微信 / 飞书 / 钉钉 / QQ / Discord / Telegram / Slack 里挂一个能对话的 AI，而不是只在网页对话框里用模型。
- 同一套人设与知识库要同时投放到 2 个以上 IM 平台，不想为每个平台各写一份对接代码。
- 想把已有的 Dify / Coze / n8n / Langflow 工作流直接搬到群里用，而不是重新搭一套调度。
- 需要给机器人加访问控制、限速、敏感词过滤、调用量监控这些"生产才需要"的东西。
- 想让编码 Agent 通过 `/mcp` 端点程序化管理机器人、流水线、插件和模型，而不点网页。

**不要用它**：

- 只是自己一个人在本机跟模型对话——直接用模型官方客户端或通用的本地对话前端更省事，LangBot 的收益全在"多平台分发"上。
- 目标是替换整套企业办公套件（文档、审批、日历、会议）——它只管即时消息这一层。
- 需要模型推理能力本身（微调、量化、跑本地权重）——它只负责调用，不负责产出模型。
- 所在 IM 平台不提供任何可用的机器人接入方式（无开放接口、无第三方协议、也无法自建通道）——LangBot 再全平台也接不上。
- 不愿承担个人号协议接入的账号风险与合规风险——这类风险不会因为换了框架而消失。

## 安装
三条路，按"先用起来"到"上生产"排。**具体以官方文档与 `--help` 为准**，下面只写真实存在的入口。

### 方式一：免安装直接跑（最快）

```bash
uvx langbot
```

需要先装 [uv](https://docs.astral.sh/uv/getting-started/installation/)。跑完访问 `http://localhost:5300`。

### 方式二：Docker Compose（推荐用于长期运行）

```bash
git clone https://github.com/langbot-app/LangBot
cd LangBot/docker
docker compose --profile all up -d
```

### 方式三：源码手动部署（需要改代码或调试时）

先从 Releases 页下载带 WebUI 的整包 `langbot-xxx-all.zip` 并解压（**不要下 Source Code 压缩包，里面不含 WebUI**），然后在解压目录执行：

```bash
pip install uv
uv sync
uv run main.py
```

默认安装不包含可选的 SeekDB 支持；若要用 SeekDB 向量库或内置嵌入模型：

```bash
uv sync --extra seekdb
```

国内网络可换源安装：

```bash
pip install uv -i https://pypi.tuna.tsinghua.edu.cn/simple
uv sync
```

首次 `uv run main.py` 会自动生成 `data/config.yaml`，终端会列出缺失并已生成的文件；按需改完后重启程序。

## 常用操作

```bash
# 1. 免安装启动，控制台默认在 5300 端口
uvx langbot

# 2. Docker 方式整体起停（在 LangBot/docker 目录下执行）
docker compose --profile all up -d
docker compose --profile all down

# 3. 看日志，排查机器人不上线 / 模型报错
docker compose logs -f

# 4. 源码方式运行，改配置后重启生效
uv run main.py

# 5. 更新依赖（升级代码后执行）
uv sync
```

界面里的操作路径（版本间菜单文案可能不同，以实际界面为准）：

1. **配置机器人**：在"机器人"里新增目标平台，填平台侧的机器人凭证与回调地址。各平台所需字段差异很大，逐平台照官方文档《配置机器人》一节填。
2. **配置模型**：在"模型"里选择提供方（OpenAI / Anthropic / DeepSeek / Gemini / Ollama / LM Studio / Dify 等），填 API Key 或本地服务地址。
3. **配置对话流水线**：把"机器人"和"模型"串成一条流水线，人设、知识库、工具调用都在这一层配。多流水线可以给不同群配不同机器人。
4. **接 MCP**：在 Web 面板的"API 与 MCP"标签页配置。服务端暴露在 `/mcp`，用同一套 API Key 鉴权（可在 `config.yaml` 里设全局 Key，或用用户级 Key），无需登录流程。

## 常见坑

| 现象 | 原因 | 怎么办 |
|---|---|---|
| `uvx: command not found` | 只装了 Python，没装 uv | 先按 uv 官方安装说明装 uv；或改走 Docker 方式 |
| `uv sync` 报无匹配的 Python | 版本不在支持的区间内（当前要求 Python 3.10 ~ 3.13） | 切到区间内的解释器再 `uv sync`；`uv python install` 可装指定版本 |
| 解压后网页打不开 | 下载的是 Source Code 包，不含 WebUI | 改下 Releases 里 `langbot-*-all.zip` 的整包 |
| 改完 `config.yaml` 没反应 | 配置只在启动时读取 | 完整重启进程；Web 面板里改的配置一般会提示需重启 |
| 机器人接了但收不到消息 | 平台侧回调地址 / 令牌配错，或外网进不来 | 先在平台后台确认回调 URL 可达，再查服务器端口与反向代理是否放行 |
| 重启容器后配置和会话全没了 | Compose 未挂载卷，数据留在容器内 | 给 `data` 等目录挂持久化卷；上生产前先确认卷映射 |
| 模型一直超时 | 服务器出网受限，或 Key 额度用尽 | 先测内网到模型服务的连通性，再核对 Key 与配额 |
| 在公开演示环境填了真实资料 | 演示站是共享环境 | 演示站只用来试功能，永远不要填敏感信息 |
| 群里加了机器人但没人理它 | 未配置触发规则/前缀，或被访问控制拦掉 | 检查该流水线的触发方式与访问控制白名单 |

## 能力边界

**覆盖**：

- 多 IM 平台的统一接入层与统一配置面板（QQ、微信、企业微信、飞书、钉钉、Discord、Telegram、Slack、LINE、KOOK、Satori、Matrix、Email 等，具体以实际版本支持列表为准）。
- 多模型与多 LLMOps 平台的路由，含本地模型服务（Ollama、LM Studio）与网关型聚合平台。
- 对话流水线编排：人设、多轮上下文、知识库、插件、工具调用、MCP。
- 生产向的运营能力：访问控制、限速、敏感词、监控面板、异常处理。
- 面向 Agent 的 `/mcp` 管理端点与仓库内的 Skills / AGENTS.md 约定。

**不覆盖**：

- 不做模型训练与推理；不提供 GPU 算力。
- 不做 IM 平台本身的部署、账号注册与资质申请。
- 不做官方的账号解封、协议合规背书。
- 替代不了完整的企业办公套件（文档、审批、日程、会议）。
- 不负责知识库原始数据的采集与清洗，只负责把它挂到对话里。

## 依赖条件

- Python 3.10 ~ 3.13（源码方式）；或 Docker 与 Docker Compose v2（容器方式）。
- 包管理器 uv（源码方式与免安装方式都要）。
- 至少一个大模型或 LLMOps 平台的可用凭证；本地模型需自备 Ollama / LM Studio 之类的服务端。
- 目标 IM 平台侧开通机器人能力并拿到凭证；对外提供服务时通常还需要域名、反向代理与 TLS。
- 服务器需要有稳定的出网能力（连模型服务、连平台回调）。

## 已知限制

- IM 平台接入能力受上游开放程度限制：个人号协议类接入存在账号风险与合规风险，框架无法消除。
- 各平台机器人凭证字段、回调机制、消息类型支持度差异很大，同一功能并非全平台等价可用。
- 平台侧接口变更可能导致某个接入在某个版本失效，需要跟随版本升级。
- 机器人的能力上限是你接的那个模型与知识库的上限；检索差、提示词乱，表现就差。
- 免费或演示环境不适合承载真实业务流量与真实数据。

## 自检清单

执行前：

- [ ] 确认 Python 版本在支持区间内，或已装好 Docker 与 Compose v2。
- [ ] 确认 5300 端口未被占用，且部署机对目标 IM 平台与模型服务双向可达。
- [ ] 明确要接哪几个平台、每个平台是否已具备机器人资质与凭证。
- [ ] 明确模型的提供方与计费方式，确认 Key 有额度和权限。

执行后：

- [ ] 控制台能打开，机器人列表里目标平台显示已连接。
- [ ] 在真实群里发一条消息，能得到完整回复（不是超时或空回复）。
- [ ] 重启一次进程/容器，确认配置与数据仍然存在（卷挂载正确）。
- [ ] 确认配置与 Key 没有以明文形式进入代码仓库或公开渠道。
- [ ] 若对外开放，确认已过反向代理并启用 TLS。
