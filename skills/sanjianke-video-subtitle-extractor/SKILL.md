# 三剪客 · 视频硬字幕提取成 SRT

有些视频的字幕是**烧进画面里**的——不是内嵌字幕轨，而是画面的一部分，用播放器关不掉、用普通工具也抽不出来。要把这种字幕变成一份可编辑的 SRT，只能靠「逐帧找字幕出现的时刻 + 对字幕区域做 OCR」。

这个项目就是干这件事的：视频进去，SRT（或纯文本）出来。OCR 全程本地跑，不需要接任何在线识别服务，支持 GPU 加速，也支持一次处理多个视频。

**上游项目**：`video-subtitle-extractor`　**仓库**：https://github.com/YaoFANGUK/video-subtitle-extractor

## 零安装用法（推荐先看这个）

### 先把最重要的一句说清楚

**硬字幕（烧进画面里的字）需要 OCR，而平台没有 OCR 接口。**
所以「硬字幕视频 → 文字」这件事，**本 Skill 的零安装脚本不覆盖**。
平台 `api.a7w.cn` 上没有 OCR app，零安装脚本也无法截图、无法做图像文字识别。

零安装脚本真正能做的是它的**另一半**，也是绝大多数「视频 → 字幕」需求的真实形态：

> **视频里有人说话 → 把话转成文字与 SRT**（走 `voice_tts/stt`，读的是**音轨**）。

| 你的素材 | 零安装脚本能不能做 | 怎么办 |
|---|---|---|
| 视频有人在说话，你要文字/字幕 | ✅ **能做**，这是本脚本的定位 | 下面那几条命令 |
| 字幕是**独立字幕轨**（mkv/mp4 里可开关的） | ❌ 不是 OCR 也不是语音 | 用 `ffmpeg -i in.mkv -map 0:s:0 out.srt` 直接抽，最快最准 |
| 字幕**烧在画面上**（硬字幕） | ❌ **本脚本不覆盖** | 用上游本地版（Python 3.12 + PaddlePaddle + CUDA）；平台侧无解 |
| 画面里的水印 / 台标 / 场景文字 | ❌ 同上，都是 OCR | 同上 |

**不需要装 Python 3.12、不需要 PaddlePaddle、不需要 CUDA、不需要下模型权重。**
本 Skill 自带一个只用 Python 标准库的脚本：

```bash
python3 scripts/run.py 视频.mp4                  # 音轨转写，打印文字
python3 scripts/run.py 视频.mp4 --srt            # 顺便输出同名 .srt
python3 scripts/run.py 视频.mp4 --lang zh        # 指定语言，默认自动检测
python3 scripts/run.py 视频.mp4 --srt -o 成片.srt # 指定 SRT 落点
python3 scripts/run.py 视频.mp4 --offset -0.5    # 时间轴整体提前 0.5 秒
python3 scripts/run.py --url https://example.com/v.mp4  # 用公网媒体地址，免上传
```

**第一次要配 Key**（三种方式任选一种）：

```bash
python3 scripts/run.py 视频.mp4 --key sk-xxxx     # 临时指定
export A7W_API_KEY=sk-xxxx                        # 环境变量
# 或到 https://api.a7w.cn/ 注册领取 Key，写入 ~/.a7w/config.json
```

> 走平台 `voice_tts/stt` 接口，按次 40 点（实测值，以平台实时价为准）。
> 上传上限约 50MB / 单条 30 分钟；超长素材先切片。

`--crop ymin,ymax,xmin,xmax` 这个参数**只把字幕区域登记在返回结果里做参考**，
本脚本**不截帧、不做画面 OCR**；要用它真去裁区域，请用上游本地版。

**什么时候才需要看下面的传统装法**：素材的字幕是**烧进画面**的、要识别水印与
台标文字、要批量处理分辨率各异的硬字幕片源——这些都得回到本地版。反过来，
素材**有音轨**、你只要文字与字幕，上面那条命令就够了，不必装那一整套 CUDA 环境。

## 什么时候用 / 不用

**用它**：

- 「这个视频的字幕是烧在画面上的，帮我导出成 SRT」——它的核心场景，也是唯一无可替代的场景。
- 「要一份本地 OCR、不调用任何在线服务的方案」——官方明确说明本地识别，不必接百度、阿里这类在线的服务。
- 「要批量提取」——支持一次选多个视频，前提是**各视频的分辨率与字幕区域一致**。
- 「素材语言不是中英」——官方列出的支持语言达 87 种，覆盖简体中文（含中英双语）、繁体中文、英文、日语、韩语、越南语、阿拉伯语、法语、德语、俄语、西班牙语、葡萄牙语、意大利语等。
- 「画面里有些固定文字要去掉或替换」——可以通过配置里的替换表把指定文本改掉或清空，用来处理水印、台标、错别字。
- 「有 GPU 想快一点」——支持 CUDA、DirectML、ONNX 多种加速路径，也支持纯 CPU。

**不要用它**：

- **要抽的是内嵌字幕轨**——如果字幕是独立的一条字幕流（mkv 里那种可以开关的），用 ffmpeg 直接抽更快也更准，不需要 OCR。
- **要识别画面里的对话文字/硬字幕之外的内容**——这是「字幕提取」工具，不是通用视频 OCR。
- **视频路径含中文或空格**——官方用加粗加感叹号强调过：路径不要带中文和空格，否则可能出现未知错误。
- **要处理分辨率或字幕位置各不相同的批量素材**——批量模式要求各视频的字幕区域保持一致。
- **不想装 Python 3.12+ 那一整套环境**——官方给的最低版本是 Python 3.12，且要装 PaddlePaddle 与一大堆依赖。官方建议先用打包好的压缩包试跑。
- **只有 NVIDIA 50 系显卡、又不想折腾**——官方说明 50 系需要 CUDA 12.8.0 及以上，但当前的 Paddle 版本尚未支持，建议改用 DirectML 通用版本。
- **要保证零错字、零丢轴**——官方自己给每种模式都标注了代价：快速模式可能丢少量字幕、存在少量错别字；精准模式不丢字幕但**非常慢**。没有任何模式承诺完美。

## 安装

**官方推荐路径：先下载打包好的压缩包直接解压运行**。官方 README 的说法是：直接下载压缩包解压运行，**如果不能运行再**按下面的教程走源码安装。压缩包在仓库的 Releases 页面。别一上来就折腾源码环境。

> 关于打包版与源码版是否完全等价：官方没有说明打包版包含哪些组件（例如是否内置了那个外部字幕检测程序），如果解压后跑不起来，直接转到源码安装即可。

下面是**源码安装**。

### 1）Python

需要 **Python 3.12+**。

- Windows：从 Python 官网下载安装。
- macOS：`brew install python@3.12`
- Ubuntu/Debian：`sudo apt update && sudo apt install python3.12 python3.12-venv python3.12-dev`

### 2）建虚拟环境并激活

官方要求用虚拟环境管理依赖，避免污染系统环境。

```bash
python -m venv videoEnv
```

Windows：

```powershell
videoEnv\Scripts\activate
```

macOS / Linux：

```bash
source videoEnv/bin/activate
```

### 3）切到源码目录

```bash
cd <源码所在目录>
```

官方举例：源码放在 `D:/tools/video-subtitle-extractor-main`，就 `cd D:/tools/video-subtitle-extractor-main`。

### 4）按你的硬件选一套环境（四种模式选一）

**（1）CUDA —— NVIDIA 显卡用户**

官方推荐 CUDA 11.8，对应 cuDNN 8.6.0。CUDA 与 cuDNN 要到 NVIDIA 官网下载安装，安装方法以 NVIDIA 官方文档为准。

```shell
pip install paddlepaddle-gpu==3.3.1 -i https://www.paddlepaddle.org.cn/packages/stable/cu118/
pip install -r requirements.txt
```

**（2）DirectML —— AMD、Intel 等 GPU/APU 用户（Windows）**

适用 Windows 上的 AMD/NVIDIA/Intel GPU。官方在 50 系显卡的说明里把它点名为推荐替代方案。

```shell
pip install paddlepaddle==3.3.1 -i https://www.paddlepaddle.org.cn/packages/stable/cpu/
pip install -r requirements.txt
pip install -r requirements_directml.txt
```

**（3）ONNX —— macOS、AMD ROCm 等环境**

官方注明这条路径**未测试，使用此方式部署请勿反馈 Issues**。基础环境与 DirectML 方式一致，然后按官方文档挑选适合你设备的执行后端，参考 `requirements_directml.txt` 改成自己环境需要的依赖。官方举的例子：

```shell
pip install paddlepaddle==3.3.1 -i https://www.paddlepaddle.org.cn/packages/stable/cpu/
pip install -r requirements.txt

# 例如 requirements_coreml.txt：
#   paddle2onnx==1.3.1
#   onnxruntime-coreml==1.13.1
pip install -r requirements_coreml.txt
```

**（4）CPU —— 没有 GPU 或不打算用 GPU**

```shell
pip install paddlepaddle==3.3.1 -i https://www.paddlepaddle.org.cn/packages/stable/cpu/
pip install -r requirements.txt
```

### 5）运行

图形界面版：

```bash
python gui.py
```

命令行版：

```bash
python ./backend/main.py
```

## 常用操作

**1）图形界面（推荐给单文件、手工操作）**

```bash
python gui.py
```

界面流程是官方的原话：点【打开】选视频文件 → 调整字幕区域 → 点【运行】。

- **单文件提取**：打开时只选**一个**视频。
- **批量提取**：打开时选**多个**视频，但必须确保**每个视频的分辨率、字幕区域保持一致**。

**2）命令行版**

```bash
python ./backend/main.py
```

它不是一个「带一堆 flag」的 CLI，而是**交互式问答**的：程序依次问你视频路径、字幕区域坐标，之后按需要再问水印相关问题。按官方源码，问答顺序是：

1. `InputVideo` —— 输入视频路径。
2. `ChooseSubArea` —— 输入字幕区域，格式是 `ymin ymax xmin xmax`（**四个整数，空格分隔，顺序就是这四个**）。这一项**可以跳过**：直接回车即视为不指定区域，程序转入自动检测流程。
3. 如果没指定区域，程序会先问一句视频是否**有水印**（输入 `y` 才算有），有水印就进入水印区域确认流程。
4. 之后还会再问一次根据统计得出的字幕区域是否正确（回车或 `y` 表示接受）。

> 具体提问文案与取值以实际运行时的提示为准；本 Skill 只保证上面这套**顺序与格式**来自源码。

**3）结果的落点**

- 按官方源码，最终 SRT 的写入路径是「**视频文件同目录、同名的 `.srt`**」。
- 过程产物放在源码目录上一级的 `output/<视频名>/` 下，包含 `frames`、`subtitle`（其中有 `raw.txt` 原始识别文本与 `raw_vsf.srt`）等临时文件。
- 官方源码里还有一个默认**开启**的「清理缓存」行为，跑完会把这些中间产物删掉；排查问题时要先找到并关掉这个开关，否则你来不及看。
- 官方还提到可以额外生成一份 `.txt` 纯文本。**这一项的实际落点与开关名以你的版本为准，跑完确认一下输出目录。**

**4）去掉/替换特定文本（水印、台标、错别字）**

编辑 `backend/configs/typoMap.json`，把要处理的文本加进去。官方给的格式示例（此处为说明结构，非原文照抄）：

```json
{
  "要替换的写法": "替换成的写法",
  "另一个要干掉的文本": ""
}
```

规则是：键是**被替换的内容**，值是**替换后的内容**；值写成空字符串 `""` 就等于把这串文本**删掉**。官方说明这个替换会作用于识别结果中出现的所有匹配文本。它既是错别字修正表，也是去水印/去台标的工具。

**5）语言与模式**

这两项在图形界面上选。模式的含义按官方说明：

| 模式 | 硬件 | 说明 |
|---|---|---|
| 快速 | 有/无 GPU | 用轻量模型，速度快，**可能丢少量字幕、存在少量错别字** |
| 自动 | 有 GPU | 自动判断模型，用精准模型，速度较慢，可能丢少量字幕、几乎无错别字 |
| 自动 | 无 GPU | 自动判断模型，用轻量模型 |
| 精准 | 有/无 GPU | 用精准模型、GPU 下逐帧检测，**不丢字幕**、几乎无错别字，但速度**非常慢** |

官方明确建议：优先用快速/自动模式，只有前两种丢轴较多时再上精准模式。

**6）想确认自己的显卡支持哪个 CUDA 版本**

官方给了一条自查路径：参考 NVIDIA 官方公布的各 GPU 型号计算能力列表（CUDA GPUs 页面）判断。

## 常见坑

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 各种「未知错误」、跑不起来 | **视频路径或程序路径里含中文或空格**。官方用加粗加感叹号强调过这一点 | 把视频和源码都挪到纯英文、无空格的路径下再跑。反例：`D:\下载\vse\运行程序.exe`、`E:\study\kaoyan\sanshang youya.mp4` |
| CUDA / cuDNN 相关报错，或运行没结果 | 显卡型号、驱动版本与所装的 CUDA/cuDNN 不匹配 | 按自己的显卡型号与驱动版本装对应的组合；官方推荐 CUDA 11.8 + cuDNN 8.6.0，装法以 NVIDIA 官方文档为准。先用 NVIDIA 的计算能力列表确认你的卡该配哪个 CUDA |
| 50 系显卡装不上/跑不了 | 官方说明 50 系需要 CUDA 12.8.0 及以上，而当前 Paddle 版本尚未支持 | 按官方建议改用 **DirectML 通用版本**，别在 CUDA 上死磕 |
| 7z 压缩包解压报错 | 解压程序版本太老 | 把 7-Zip 升到最新版再解 |
| 批量处理结果错乱 | 各视频的分辨率或字幕区域不一致 | 批量前先人工确认分辨率与字幕区域统一；不一致就拆成单文件逐个跑 |
| 精准模式慢到无法接受 | 官方原话就是「非常慢」，GPU 下逐帧检测 | 除非确实丢轴严重，否则别用精准模式；优先快速/自动 |
| 丢字幕轴、出现错别字 | 这是快速/自动模式的已知代价 | 先换模式，再用 `typoMap.json` 修正常见错字；实在不行才上精准模式 |
| 画面里的台标/水印被识别成字幕 | OCR 认的是画面上的所有文字 | 用 `backend/configs/typoMap.json` 把这些文本替换成空串删掉；也可以在指定字幕区域时把水印排除在框外 |
| 中间产物找不到了 | 跑完默认会清理缓存目录 | 排查问题前先关掉清理开关，保留 `output/<视频名>/` 下的帧与 `raw.txt` |
| 想直接抽内嵌字幕轨却用了它 | 工具定位是**硬字幕**（烧进画面的那种） | 内嵌字幕轨用 ffmpeg 之类的工具直接抽，又快又准，不要过 OCR |
| 没指定字幕区域，结果多出一堆场景文字 | 不指定区域时会走自动检测，可能把画面里的其他文字也算进来 | 尽量显式给出 `ymin ymax xmin xmax`；自动模式下程序会二次确认它推算的区域，认真看那一问 |
| 照着别人的命令加参数报错 | 命令行版不是 flag 式 CLI，它是交互式问答 | 按提示逐项输入；视频路径是第一个问题，区域是第二个 |

## 能力边界

> **平台侧的硬边界（务必先看）**：`api.a7w.cn` 上**没有 OCR 接口**。
> 所以零安装脚本（`scripts/run.py`）**不做硬字幕提取**，它做的是
> 「**有音轨的视频 → 文字 / SRT**」（走 `voice_tts/stt`）。
> **硬字幕场景本脚本不覆盖**，请用上游本地版（Python 3.12 + PaddlePaddle + CUDA）。
> 内嵌字幕轨请直接用 `ffmpeg -map 0:s:0` 抽，两条路都不需要 OCR。

**下面列的是上游项目（本地版）的能力边界**：

**覆盖**：

- 从**硬字幕**视频中提取字幕文本并生成 SRT 字幕文件（也可输出纯文本）。
- 完整链路：抽取关键帧 → 检测帧内文本位置 → 识别文本内容 → 过滤非字幕区域文本 → 去除重复字幕行 → 生成字幕文件。
- 批量提取（要求各视频分辨率与字幕区域一致）。
- 87 种语言的字幕提取，含中英双语混排、繁体中文及多种拉丁/非拉丁语系。
- 三种识别模式（快速 / 自动 / 精准），在速度与「丢轴、错别字」之间取舍。
- 硬件加速路径：CUDA、DirectML、ONNX，以及纯 CPU。
- 水印与台标文本的处理：通过替换表删除或替换指定文本；也支持人工确认水印区域。
- 图形界面与命令行两种入口。

**不覆盖**：

- 内嵌字幕轨的抽取。那是容器级操作，用 ffmpeg 之类的工具做，不需要 OCR。
- 视频转码、剪辑、压制、去水印（画面层面的擦除）。官方只提到「去除水印**文本**」，是把识别结果里的文字删掉，不是修画面；画面级去字幕属于另一类工具。
- 语音转写。它读的是画面上的字，不是听声音；视频没有硬字幕它就无从下手。
- 字幕翻译、时间轴精修、样式与字体设置。它只产出 SRT/文本，后续处理要另配工具。
- 保证准确率。官方对每种模式都标注了代价，没有「零错字且不丢轴且快」的选项。
- 跨视频的说话人/角色归属。它只给文本与时间，不做说话人区分。
- macOS 上 ONNX 路径的可用性保证。官方明确标注该路径未测试、请勿就此反馈问题。

## 依赖条件

- **Python 3.12+**（官方给的最低版本）。
- 必须使用虚拟环境（官方要求），避免与系统环境冲突。
- **PaddlePaddle**：按加速方式二选一装 GPU 版或 CPU 版。官方给的版本是 `paddlepaddle-gpu==3.3.1`（CUDA 11.8 源）与 `paddlepaddle==3.3.1`（CPU 源）。
- **CUDA / cuDNN**（走 CUDA 路径时）：官方推荐 CUDA 11.8 配 cuDNN 8.6.0，需按 NVIDIA 官方文档安装；50 系显卡需要 CUDA 12.8.0 及以上，而当前 Paddle 尚未支持。
- `requirements.txt`；走 DirectML 还要 `requirements_directml.txt`；走 ONNX 要自备合适的 onnxruntime 后端依赖。
- 素材与程序路径必须是**纯英文、无空格**。
- 首次运行需要能下载 OCR 模型权重。
- 不需要账号或 API Key。

## 已知限制

- **路径不能含中文或空格**是硬性约束，不是建议。官方把它列为「否则可能出现未知错误」。
- 三种模式都有明确的取舍：快速/自动会丢少量字幕与出现少量错别字，精准不丢但非常慢。**没有全都要的选项。**
- 官方对精度没有任何量化承诺（没有给出准确率数字），上线前必须用你自己的素材实测。
- 批量模式依赖「分辨率 + 字幕区域一致」这一前提，素材多样性高时批量收益有限。
- ONNX 路径官方标注未测试，稳定性无保证。
- 中间产物默认会被清理，排错窗口很窄，得先关掉清理开关。
- 处理耗时与硬件强相关，官方没有给出可引用的速度基准，只给了「精准模式非常慢」这样的定性描述。
- 视频画面本身的复杂度（背景干扰、字幕样式花哨、低对比度）会直接影响结果，工具本身没有针对性的预处理承诺。
- **零安装脚本 `scripts/run.py` 的边界**（与本项目的硬字幕提取完全是两件事）：
  - **不做硬字幕提取**：平台**没有 OCR 接口**，硬字幕场景本脚本**不覆盖**。
  - 它做的是**音轨转写**：视频里得有人说话，没音轨或纯音乐就没结果。
  - 不做内嵌字幕轨抽取（那是容器操作，用 ffmpeg）。
  - 不做画面级去水印、不做台标过滤、不做 `typoMap` 替换词表。
  - 只有整条时间轴平移（`--offset`），没有波形对轴与逐条校对；不保证「不丢轴」。
  - OCR 三档模式（快速/自动/精准）、批量处理、GPU 加速都是**本地版**的特性，
    零安装脚本一个都没有——它的取舍是「不必装环境」，不是「效果一样」。
  - **标点是「回填」来的，不是原生的**：平台 `segments[].text` **不带标点**
    （标点只出现在整段 `text` 里）。脚本会把整段文本逐字对齐回字符级分段补回标点；
    **一旦对不齐就原样返回、不补**，此时字幕会是无标点的硬切行句。这是保守设计，
    宁可不补也不补错位——遇到这种情况请人工过一遍标点。

## 自检清单

**先决定走哪条路（零安装 还是 本地版）**：

- [ ] 素材的字幕是**烧在画面上**的吗？是 → 只能走本地版，**平台没有 OCR 接口，零安装脚本不覆盖**。
- [ ] 字幕是**独立字幕轨**吗？是 → `ffmpeg -map 0:s:0` 直接抽，不必 OCR、也不必转写。
- [ ] 素材**有音轨、你要的是文字/字幕**吗？是 → 走零安装：`python3 scripts/run.py 视频.mp4 --srt`。
- [ ] 走零安装时先确认 Key 就位（`--key` / `A7W_API_KEY` / `~/.a7w/config.json`）。

**走本地版（硬字幕 OCR）时，执行前**：

- [ ] 确认要提的是**硬字幕**（烧进画面的），不是内嵌字幕轨——后者请换 ffmpeg。
- [ ] 确认视频与程序路径**纯英文、无空格**。
- [ ] 确认 Python ≥ 3.12，且已激活虚拟环境。
- [ ] 确认按自己的硬件选了正确的加速路径（NVIDIA → CUDA；AMD/Intel 或 50 系 → DirectML；macOS/ROCm → ONNX，且接受其未测试状态；无卡 → CPU）。
- [ ] 确认该装的 PaddlePaddle 版本与 `requirements.txt` 都装完了。
- [ ] 批量任务先确认所有视频的分辨率与字幕区域一致。
- [ ] 先试打包版；打包版跑不通再走源码。

执行中：

- [ ] 优先选快速或自动模式；只有确认丢轴严重才切精准模式。
- [ ] 尽量显式给出字幕区域 `ymin ymax xmin xmax`，而不是完全依赖自动检测。
- [ ] 自动检测流程里程序问「是否有水印」「这个区域对不对」时，认真回答，别一路回车。
- [ ] 排错前先关掉缓存清理开关，保留 `output/<视频名>/` 下的中间产物。

执行后：

- [ ] 打开 SRT 抽查：时间轴对不对、有没有丢轴、有没有明显错别字。
- [ ] 检查是否混入了台标/水印/场景文字，必要时补进 `typoMap.json` 重跑。
- [ ] 确认字幕文件落点与文件名符合交付要求（默认是与视频同目录同名的 `.srt`）。
- [ ] 记录本次使用的模式、语言与关键配置，便于批量复现。
- [ ] 确认素材授权：提取字幕后如何使用与发布，取决于你自己的授权情况。
