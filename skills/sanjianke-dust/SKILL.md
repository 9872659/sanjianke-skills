# 三剪客 · 磁盘占用可视化的命令行工具

`dust` 用一条命令回答「这个目录到底是哪些东西在吃空间」：它自己遍历目录树，把最大的子目录和文件按占用排序打印出来，并画出百分比条。你不需要先 `du` 再 `sort -h` 再 `head`，默认给你一屏最有价值的结果。换算单位、排序、递归找大头这三件事它都内置了，适合排查磁盘告警、定位日志与缓存目录的体积。

**上游项目**：`dust`　**仓库**：https://github.com/bootandy/dust

## 什么时候用 / 不用

**用它**：

- 用户说「磁盘满了」「根分区不够了」「这个目录怎么这么大」，需要几分钟内定位到最大的目录与文件。
- 想直接看「前 N 个最大条目」，而不是自己拼 `du | sort | head`。
- 需要按维度收窄视野：只看目录（`-D`）、只看最大的文件（`-F`）、按文件类型归类（`-t`）。
- 结果要进脚本或报表：需要 JSON（`-j`）、需要按大小阈值过滤（`-z`）、需要正则包含（`-e`）或排除（`-v`）。
- 小文件极多、目录树很深导致 `du` 很慢，或目标在网络挂载上、想提高并发遍历效率（`-T`）。

**不要用它**：

- 想要交互式钻取、就地删文件或移动文件——`dust` 是「打印一次结果」的统计工具，不是可操作的界面。
- 只是想知道还剩多少空间——`df -h` 直接给答案，不用绕一圈。
- 需要跨机器、跨对象存储或调用远端接口汇总占用——它只遍历本地文件系统。
- 需要精确对齐 `du`/`df` 的数字口径——它默认按磁盘占用计、不重复统计硬链接，与 `du` 的默认口径并不总是一致。
- 需要历史趋势、监控告警、定时报表——它只给当前这一次快照。

## 安装

各平台命令（包名以发行版为准，拿不准先搜一下 `dust`）：

```bash
# Rust 工具链（跨平台通用）
cargo install du-dust

# macOS / Linux（Homebrew）
brew install dust

# Fedora
sudo dnf install du-dust

# Debian / Ubuntu 侧的两个第三方包管理器
deb-get install du-dust
pacstall -I dust-bin

# conda-forge / mise / x-cmd
conda install -c conda-forge dust
mise use -g dust
x env use dust
```

Windows：

```powershell
scoop install dust
# 或
cargo install du-dust
```

项目还提供一个安装脚本，直接下载对应平台的可执行文件：

```bash
curl -sSfL https://raw.githubusercontent.com/bootandy/dust/refs/heads/master/install.sh | sh
```

该域名在你的网络下不可达时，改用上面的包管理器，或从发行版页面下载压缩包后手工安装：

```bash
tar -xvf dust-<平台>.tar.gz
sudo mv dust /usr/local/bin/
```

注意：MSVC 构建的 Windows 版需要系统里有 `VCRUNTIME140.dll`（装 VC++ 运行库），否则启动即报缺 DLL；GNU 版没有这个问题。

## 常用操作

```bash
# 1) 默认视角：统计当前目录，按占用从大到小，条数自动跟随终端高度
dust

# 2) 指定目录并控制深度与条数：看 /var/log 的前两层、最多 30 行
dust -d 2 -n 30 /var/log

# 3) 只要目录 / 只要最大的文件
dust -D ~/projects        # 隐藏文件条目，只看目录体积
dust -F -n 20 ~           # 反过来：列出家里最大的 20 个文件

# 4) 换口径与过滤：表观大小、忽略名字、大小阈值、扩展名正则
dust -s /srv/data                     # 表观大小（文件长度），方便与 du 的对应口径对齐
dust -X node_modules ~/projects       # 忽略所有名为 node_modules 的条目
dust -z 100M /data                    # 只列出大于 100M 的条目
dust -e '\.(mov|iso)$' /data          # 只看匹配这个正则的文件

# 5) 喂给脚本：JSON 输出、从清单读取待扫描路径
dust -j /data > usage.json            # JSON 表示，便于 jq 或报表消费
find /data -maxdepth 2 -type d -print0 | dust --files0-from=- -n 10

# 6) 网络盘 / 高延迟存储：加大遍历线程，并限制在同一文件系统
dust -T 32 -x /mnt/nfs
```

把常用参数固化到配置文件，键名就是长参数名的 kebab-case：

```bash
cat ~/.config/dust/config.toml
# reverse=true
# limit-filesystem=true
```

配置文件位置：`$XDG_CONFIG_HOME/dust/config.toml`（未设置时回退到 `~/.config/dust/config.toml`），或直接使用 `~/.dust.toml`。

## 常见坑

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 数字和 `du -sh` 对不上 | 默认按磁盘块占用计，且不重复统计硬链接，口径与 `du` 不同 | 用 `dust -s` 按表观大小；要计入重复 inode 用 `dust -f -s`；对比前先统一口径 |
| 明明有更大的目录却没显示 | 默认只打印大约一屏条数，超出部分被省略 | 用 `-n` 提高条数（如 `-n 50`），或用 `-d` 控制展示深度 |
| 输出看不清谁属于谁 | 灰阶深浅表示父子归属，不是缩进层级 | 深色终端上加 `--dim` 调暗百分比条；只想看纯数据用 `-b` 去掉条和百分比 |
| 扫描网络挂载非常慢 | 默认遍历线程数等于 CPU 核数，高延迟存储上并发不足 | `dust -T 32 <dir>` 提高线程数；不需要跨文件系统时加 `-x` |
| 权限错误刷屏或看不到 | 无权读取的目录只会被提示一次，这是设计行为 | 确实需要看全就提权运行，但提权后所有文件元数据都可读，注意影响面 |
| 隐藏的大 dotfile 干扰判断 | 默认包含隐藏文件 | 加 `-i` 不显示隐藏文件 |
| 结果管进管道后混进颜色与进度字符 | 颜色和实时统计默认写终端 | JSON 用 `-j`；纯文本管道场景用 `-b -c`，需要时加 `-P` 关进度提示 |
| 配置文件写了没生效 | 位置不对，或键名没按长参数名的 kebab-case 写 | 确认文件在 `~/.config/dust/config.toml` 或 `~/.dust.toml`；键名参照项目自带的配置样例 |
| Windows 双击报缺 DLL | 用的是 MSVC 构建 | 安装 VC++ 运行库（提供 `VCRUNTIME140.dll`），或改用 GNU 版与 `scoop` 包 |
| 用 snap 装的版本统计不到 `/home` 以外 | snap 沙箱只能访问 `/home` | 换成发行版包或 `cargo install`，别用 snap 版排查系统盘 |
| `-f` 计数结果比预期少 | 按 inode 计数时重复硬链接默认只算一次 | 明确要「文件条目数」时用 `-f -s`，并记住它统计的是条目不是字节 |

## 权限与用途说明

| 能力 | 是否申请 | 用途 |
|---|---|---|
| 网络访问 | 否 | 统计过程完全本地；只有你用安装脚本或包管理器时才联网下载 |
| 读取文件 | 是 | 遍历目标目录的元数据（大小、类型、父子关系）以汇总占用；不读取文件内容 |
| 写入文件 | 否 | 只读工具，不修改也不删除被扫描的文件；配置文件需你自行创建 |
| 凭证 | 否 | 不需要账号、Token 或 API Key |
| 子进程 / 后台常驻 | 否 | 一次性前台进程，跑完即退出，不驻留、不写缓存目录 |

## 能力边界

**覆盖**：

- 单次、只读的本地磁盘占用统计：目录树按大小排序，并可视化百分比与层级归属。
- 维度收窄：深度 `-d`、条数 `-n`、大小阈值 `-z`、名字排除 `-X`、正则包含 `-e` 与排除 `-v`、按类型归类 `-t`。
- 视图切换：只看目录 `-D`、只看文件 `-F`、反向排序 `-r`、单色 `-c`、去条 `-b`、屏幕阅读器友好 `-R`。
- 口径控制：表观大小 `-s`、按 inode 计数 `-f`、限制同一文件系统 `-x`、默认不重复计硬链接。
- 机器可读与批处理：JSON 输出 `-j`、从文件或标准输入读路径清单（`--files-from` 与 `--files0-from`）、多线程遍历 `-T`。
- 用 TOML 配置文件固化常用参数。

**不覆盖**：

- 交互式浏览、就地删除、移动或重命名文件（没有任何写操作）。
- 远端或对象存储统计：不调用云盘接口，也不做跨机器汇总。
- 历史趋势、定时报表、容量预测、告警。
- 内容级去重：相同内容的文件放在不同路径会各自计数。
- 单个文件内部的构成分析（这不是目录占用问题）。
- 精度保证：与 `du`/`df` 的数字不会天然一致，需要自己统一口径后再比较。

## 依赖条件

- 可直接下载对应平台的预编译可执行文件；自行构建需要 Rust 工具链（`cargo`，包名 `du-dust`）。
- 支持 Linux、macOS、Windows（GNU 与 MSVC 两种构建；MSVC 版需要 VC++ 运行库）。
- 纯本地运行：不需要网络、不需要账号或 Key、不需要数据库。
- 权限：能读到目标目录即可正常运行；无权限的目录会被跳过并只提示一次。

## 已知限制

- 默认不重复统计硬链接，改为计入需要 `-s` 参与，口径变化会影响与 `du` 的对比结论。
- 展示条数默认跟随终端高度，非交互场景（重定向到文件）应显式给 `-n`。
- snap 分发版受沙箱限制，只能统计 `/home` 下的内容。
- 只统计本地文件系统遍历的结果，远端接口与对象存储不在范围内。
- 配置文件键名与长参数一一对应，写错通常不报错、只是不生效；可用参数以所用版本的 `--help` 为准。

## 自检清单

执行前：

- 目标路径存在，且当前用户能读到（读不到就只能看到被跳过的结果）。
- 明确要的是「磁盘占用」还是「表观大小」，这决定是否加 `-s`。
- 明确是否要包含隐藏文件、是否要跨文件系统（`-i` 与 `-x`）。
- 结果要给别人看时先定好 `-n` 与 `-d`，避免默认条数随终端高度变化。

执行后：

- 核对最大的几项是否符合预期，有没有漏掉已知的大目录。
- 要进脚本或报表时，确认用了 `-j`，或已用 `-b -c -P` 去掉颜色、条和进度。
- 把结论和 `df -h` 的剩余空间对照，确认清理候选确实是最大收益项。
- 如果为了看全而提权运行，确认没有在同一个目录里做过任何写操作。
