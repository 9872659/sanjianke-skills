# 群聊协作指南

多角色群聊的活儿分四步：**定角色 → 定发言人 → 定收口 → 控成本**。
这份文档讲怎么把每一步做对，以及模型入口怎么指向 `api.a7w.cn`。

---

## 一、把模型客户端指向网关

多智能体框架的模型客户端通常是一个类实例，构造时传 `model` / `base_url` / `api_key`：

```python
model_client = OpenAIChatCompletionClient(
    model="DeepSeek-V4-Flash",
    base_url="https://api.a7w.cn/api/v1",
    api_key="sk-你的key",
)
```

也可以纯用 OpenAI SDK 自己写循环：

```python
import os
from openai import OpenAI

client = OpenAI(
    base_url="https://api.a7w.cn/api/v1",
    api_key=os.environ["A7W_API_KEY"],
)
```

| 场景 | 接口 |
|---|---|
| 角色发言、评审 | `POST /api/v1/chat/completions` |
| 需要看图的角色 | 同上，`model` 换视觉模型 |
| 生成类产物（语音 / 图像 / 视频） | `POST /api/v1/apps/<应用代号>/<接口代号>` |

## 二、按环节分档选模型

**多角色群聊里最值钱的一条**：不是所有角色都需要最强模型。

| 环节 | 要求 | 建议档位 | 例 |
|---|---|---|---|
| 出稿 / 执行 / 检索 | 快、便宜、能听话 | 快模型 | `DeepSeek-V4-Flash`、`Qwen3.6-Flash` |
| 讨论 / 分析 | 表达与逻辑稳 | 中档 | `Qwen3.7-Plus`、`GLM-5`、`MiniMax-M3` |
| 评审 / 定稿 | 能挑毛病、能推理 | 强模型 | `DeepSeek-V4-Pro`、`GLM-5.2`、`Kimi-K2.6` |
| 看图 / 读图 | 支持视觉输入 | 视觉模型 | `Qwen3-VL-30B-A3B-Instruct`、`ERNIE-4.5-Turbo-VL`、`qwen3.6-plus` |

换模型就是换一个字符串：**不用换 base_url、不用换 Key、账单还是同一份**。

> 模型清单会变。调用前读一次 `GET /api/v1/models`，以接口返回为准。

## 三、发言策略怎么选

| 策略 | 什么时候用 | 代价 |
|---|---|---|
| **固定顺序轮流** | 角色少、流程确定（写 → 审 → 改） | 便宜、可预测；顺序不灵活 |
| **模型动态点名** | 角色多、该谁说话要看内容 | 每次多一次「点名」调用，更贵 |
| **交接式** | 像「转专员」那样把活交给下一个角色 | 适合有明确升级路径的流程 |

**从固定顺序起步**：确定、便宜、好排查。等流程稳定了再上动态点名。

```python
# 固定顺序：轮流
agent = AGENTS[i % len(AGENTS)]
```

```python
# 动态点名：让一个模型根据上下文挑下一个发言人（示意）
picker = client.chat.completions.create(
    model="DeepSeek-V4-Flash",           # 点名用快模型就够
    messages=[{"role": "user",
               "content": "根据下面的对话，只回复下一个该发言的角色名：\n" + transcript}],
)
next_name = picker.choices[0].message.content.strip()
```

## 四、终止条件：两类都要设

| 类型 | 作用 | 例 |
|---|---|---|
| **关键词触发** | 正常收口 | 评审输出 `APPROVE` 就停 |
| **步数上限** | 异常兜底 | 最多 6–8 轮 |

**只设关键词的风险**：触发词写错、模型不按格式输出，就会变成无限循环，
账单会一直涨。**步数上限是必须的兜底。**

**还要做的一件事**：把触发词写进评审角色的系统提示，例如

```
认可时在回复里明确写出 APPROVE。
```

角色不知道要输出什么词，终止条件就永远不会触发。

## 五、工具调用与轮数上限

Agent 挂了工具后（函数调用、外部服务等），**一定设调用轮数上限**
（常见参数名 `max_tool_iterations` 一类）。

不设的话，Agent 走完一轮工具调用就停，很容易「以为它做完了其实没做完」。

```python
agent = {
    "name": "执行",
    "model": "DeepSeek-V4-Flash",
    "system": "...",
    "max_tool_iterations": 10,      # 允许连续多轮工具调用
}
```

## 六、状态与重置

多角色会话**是有状态的**：跑完一次直接再跑，就是**接着上次的上下文继续**。

| 情况 | 怎么做 |
|---|---|
| 新任务与上一个**不相关** | 先重置会话，再跑 |
| 新任务是上一个的**延续** | 直接续跑，让它带着上下文 |
| 需要中途掐断 | 用框架提供的取消机制（取消令牌一类） |

**判断口径**：第二个任务需不需要第一个任务的产出？不需要就重置。

## 七、成本估算

```
单次任务调用数 ≈ 角色数 × 平均轮数
              （动态点名策略还要 + 轮数）
单次任务成本   ≈ 调用数 × 单次调用 tokens × 对应模型的单价
```

**例**：2 个角色、评审循环 3 轮 ≈ 6 次调用。

**三个降本手段**：

1. **按环节分档选模型** —— 最直接。
2. **把终止条件设准** —— 少转两轮就少一整轮全链路调用。
3. **固定顺序起步** —— 动态点名每次都多一次调用。
