# 三剪客 · 自托管团队知识库 Skill

用 Docker 自建一个团队知识库站点：数据库接入、权限分组、全文检索与 GraphQL API，以及多副本、附件权限、证书续期这些实战坑。

---

## 前置条件

- 一个数据库实例（空库 + 独立账号）。官方首推 PostgreSQL 9.5 及以上；用 Docker 起 `postgres` 容器是最省事的方式。
- Docker（推荐路径，镜像内已含 Node.js 运行时）。
- 若走原生安装：Node.js 24（24.0+）或 Node.js 22（22.0+）（自 v2.5.302 起支持）。
- 独立域名或子域。官方明确不支持把它映射到已有站点的子目录。
- 机器配置：Linux 至少 1GB 内存，官方建议 2 核以上；磁盘按文本量估算，含附件时另留空间。
- 若要用内置 Let's Encrypt：域名解析就绪、HTTP 端口可从公网访问、一个管理员邮箱。

---

## 使用

1. 先起好数据库，再按 `SKILL.md` 的「安装」一节填 `DB_*` 环境变量或用官方 Compose 模板起 Wiki.js。
2. 浏览器打开站点走完设置向导，创建管理员账号并填最终对外地址。
3. 在管理后台配置用户组与页面权限、启用全文检索、按需配置邮件、存储、认证与 API。
4. 需要程序化读写时，在 **API Access** 生成带权限范围的 token，调用 `/graphql`。
5. 多副本部署必须开 `HA_ACTIVE` 且只能用 PostgreSQL；升级前先备份数据库与附件。
6. 排障优先看「常见坑」表：镜像 tag、`DB_HOST`、子目录、证书续期、权限与检索扩展都在里面。

## 依赖

- 数据库：PostgreSQL 9.5+（首选）；MySQL 8.0+、MariaDB 10.2.7+、MS SQL Server 2012+、SQLite 3.9+ 当前可用，但官方已说明未来大版本不再支持。
- 容器运行时：Docker / Docker Compose（或 Kubernetes 等多副本编排）。
- 可选：反向代理（用于更细的网络与 DNS 配置）。
- 可选：对象存储或云盘（附件外置）、外部搜索引擎（更强检索）、企业身份源（LDAP / SAML / OIDC 等）。
- 使用 PostgreSQL 检索模块时，数据库侧需具备 `pg_trgm` 扩展（官方镜像已自带）。

---

## 安全

- 不内嵌任何密钥；数据库密码、管理员账号、API token、SMTP 与第三方密钥都由使用方配置与保管。
- 镜像默认以非 root 用户运行；只有在挂载文件权限实在无法协调时才用 `-u root` 兜底，并清楚这放宽了容器权限。
- GraphQL API token 按最小权限范围签发，不要写进前端代码或提交到仓库。
- 使用内置 HTTPS 时，HTTP 端口需要长期开放用于证书签发与续期；这是官方设计，不是漏洞，但仍应配合防火墙只开放必要端口。
- 附件存储、数据库卷与配置文件都要纳入备份，并验证过能恢复。
- 生产环境不要用 SQLite；官方明确指出其并发与可靠性不适合生产部署。
