# 三剪客 · 开源任务与项目管理 Skill

Vikunja：开源任务与项目管理 的安装、常用命令与避坑要点

---

## 前置条件

- 一台可长期运行的服务器（或本机用于试跑），已安装 Docker / Docker Compose，或准备用发行版软件包 / 二进制部署。
- 明确数据库选型：先用 SQLite 验证没问题再换 PostgreSQL / MySQL 也可以，但**用户量上来后官方建议用 PostgreSQL 或 MySQL**；用 MySQL / MariaDB 且内容含非拉丁字符时，数据库必须是 utf8 兼容配置。
- 一个可写的数据目录：附件与项目背景图需要独立存放；容器方式下要在启动前创建该目录并设置好属主。
- 准备两项必设配置：**公网地址**（设置它，或改为关闭 CORS）和**固定的实例签名密钥**（不设则每次启动随机生成，重启会让已签发的令牌全部失效）。
- 若要发提醒或做密码重置，需要一套可用的 SMTP 服务。
- 若要对公网提供服务，准备域名与反向代理；若要启用 Webhook，接收端要能处理签名校验并快速应答。
- 明确一件不可逆的事：**项目删除是永久的，没有回收站**。开始用之前就要有备份策略。

## 使用

1. 按 `SKILL.md` 的「安装」一节选一种方式把实例跑起来。默认监听 `3456`。
2. 启动前先建目录并授权（容器方式下官方要求 `mkdir` 并把属主设为 uid 1000），否则附件上传必然失败。
3. 起来后先访问信息接口确认可达，再打开首页注册第一个账号。
4. 跑一次 `vikunja doctor` 做体检：配置、数据库、文件可写性、磁盘空间、可选服务都会过一遍。
5. 按需配置：注册完用户后关闭自助注册、设置默认语言、按需开启链接分享、配置邮件与真实客户端 IP 提取（放在反代后面时）。
6. 需要程序化操作时，在网页端创建 API 令牌，用 Bearer 头调接口；新集成直接用 v2，列表结果读 `items` 字段、创建用 `POST`、局部更新用 `PATCH`。
7. 需要事件通知时配置 Webhook，并在接收端校验签名（对原始请求体做 HMAC-SHA256）。
8. 上线前跑通一次备份：`vikunja dump` 或按数据库类型导出 + 拷贝附件目录，并验证还原流程。
9. 排错顺序建议：`vikunja doctor` → 启动日志（容器无 shell，用 `docker logs`）→ 数据库连通性与主机名 → 目录权限与公网地址 / CORS 配置。

## 依赖

- **容器方式**：Docker 或兼容运行时；compose 方式还需要 Docker Compose。官方镜像基于 scratch 构建，容器内没有 shell，也不支持 `PUID` / `PGID`。
- **数据库**：PostgreSQL 12+、MySQL 8.0+ / MariaDB 10.2+、SQLite 三选一；数据库可以是独立容器，也可以是外部实例。
- **缓存（可选）**：Redis，用户量少时不需要。
- **邮件（可选）**：SMTP 服务器；不配置邮件则用户注册后直接激活且无法走密码重置。
- **反向代理（常用）**：nginx / Caddy / Apache 或面板类代理；注意上传大小限制要与应用侧保持一致。
- **文件存储**：本地目录，或兼容 S3 的对象存储后端。
- **运行环境**：软件包 / 二进制方式需要一个 Linux 发行版与 init 系统（如 systemd）；官方同时提供 Windows 与 macOS 发行包。
- **凭据**：数据库口令、实例签名密钥、可选的 SMTP 与对象存储凭据，均由使用者自备，本 Skill 不提供也不内置。

## 安全

- 不内嵌任何密钥，仓库中不含数据库口令、SMTP 凭据或对象存储密钥。
- 实例签名密钥请显式配置并妥善保管；使用默认的随机生成行为会让每次重启都作废此前签发的会话与令牌。
- 数据库口令、SMTP 口令等敏感配置建议走环境变量或「从文件读取配置值」的方式，不要明文提交到版本库。
- 上线后按需关闭自助注册；分享链接功能如果不打算用就关掉，减少意外的数据暴露面。
- 放在反向代理后面时，正确配置真实客户端 IP 的提取方式与可信代理网段，否则限流与审计会把来源搞错。
- 启用 Webhook 时注意出站安全：多用户实例上，出站请求可能被用作探测内网的手段，官方建议通过出站代理收敛流量。
- Webhook 接收端必须校验 `X-Vikunja-Signature`，并且要能快速应答——投递失败不会重试。
- `restore` 与 `repair` 都会真实改动数据；`repair` 先用 `--dry-run` 预演，`restore` 前确认清楚数据会被覆盖。
- 项目删除不可逆，务必把备份纳入例行流程，并验证过还原真的可用。
