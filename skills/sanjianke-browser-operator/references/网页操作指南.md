# 网页操作指南

浏览器自动化的活儿分四步：**写任务 → 挑模型 → 控步数 → 收结果**。
这份文档讲怎么把每一步做对，以及模型入口怎么指向 `api.a7w.cn`。

---

## 一、把模型对象指向网关

浏览器自动化框架的模型对象一般是构造时传参，改 `base_url` 与 `api_key` 即可：

```python
llm = ChatOpenAI(
    model="Qwen3-VL-30B-A3B-Instruct",
    base_url="https://api.a7w.cn/api/v1",
    api_key="sk-你的key",
)
```

纯用 OpenAI SDK 自己写循环：

```python
import os
from openai import OpenAI

client = OpenAI(
    base_url="https://api.a7w.cn/api/v1",
    api_key=os.environ["A7W_API_KEY"],
)
```

| 场景 | 接口 |
|---|---|
| 每一步的页面理解与决策 | `POST /api/v1/chat/completions` |
| 需要读截图时 | 同上，`model` 换支持视觉的模型 |
| 生成类产物（语音 / 图像 / 视频） | `POST /api/v1/apps/<应用代号>/<接口代号>` |

## 二、任务描述的四要素

**目标 + 边界 + 输出格式 + 只读/可写。**

| 要素 | 作用 | 例 |
|---|---|---|
| **目标** | 要拿到什么 | 「把本月所有订单号与金额抄下来」 |
| **边界** | 只在哪几页 / 哪几个区域操作 | 「只在订单列表页，不要进详情页」 |
| **输出格式** | JSON / 表格 / 纯文本 | 「输出 JSON 数组，字段为 order_id、amount」 |
| **只读/可写** | 明确允许什么动作 | 「只读不点任何提交按钮」 |

**对比**：

| 写得好的任务 | 写得糟的任务 |
|---|---|
| 「打开后台的订单页，把本月所有订单号与金额抄下来，输出 JSON 数组；只读不点提交按钮」 | 「看看后台」 |
| 「在这个比价页找到价格最低的一项，取回名称、价格、链接，输出表格」 | 「找最便宜的」 |
| 「把这页表格的 3 列数字抄下来，输出 JSON」 | 「抓一下数据」 |

## 三、按页面形态挑模型

浏览器任务的模型分工很明确：

| 页面形态 | 需要什么能力 | 建议档位 | 例 |
|---|---|---|---|
| 结构化 DOM（列表、表格、表单） | 文本理解 | 快模型 | `DeepSeek-V4-Flash`、`Qwen3.6-Flash` |
| 图形化界面、复杂布局 | **视觉理解** | 支持视觉的模型 | `Qwen3-VL-30B-A3B-Instruct`、`ERNIE-4.5-Turbo-VL`、`qwen3.6-plus` |
| 多步跳转、需要规划 | 推理与长上下文 | 强模型 | `DeepSeek-V4-Pro`、`GLM-5.2`、`Kimi-K2.6` |

**落地策略**：**先用快模型跑一遍，失败率高的步骤再换视觉模型或强模型。**
两个档位可以在同一个任务里混用 —— 换 `model` 就是换模型，账单还是同一份。

> 模型清单会变。调用前读一次 `GET /api/v1/models`，以接口返回为准。

## 四、让模型输出结构化动作

不要让模型「自由发挥下一步做什么」，而是让它输出固定格式的动作 JSON，
由你的代码执行：

```json
{
  "action": "click | type | scroll | extract | done",
  "target": "按钮或输入框的可读描述",
  "value": "要输入的内容",
  "result": "extract 时取回的数据"
}
```

**好处**：

1. 你的代码能做**白名单校验** —— 不在允许列表里的动作直接拒绝。
2. 出错时能**精确定位**是哪一步的动作不对。
3. 便于**记录执行轨迹**，方便复跑与排错。

## 五、步数上限与安全边界

### 步数上限必设

任务失败时，模型会一直尝试下一步。**没有步数上限，账单会一直涨。**

```python
for _ in range(max_steps):        # 常见取值 10–20
    ...
    if done:
        return result
return "达到步数上限，已停止"       # 明确报告，而不是静默失败
```

### 只读优先

任务描述里写清「不要点击提交 / 支付 / 删除类按钮」，
并在代码层的动作白名单里**真的拦掉**这些动作。

| 操作类型 | 建议 |
|---|---|
| 读页面、翻页、展开 | 可以自动 |
| 填表单（不提交） | 可以自动，但要注意别误触提交 |
| **提交、支付、删除、发布** | **必须人工确认** |

## 六、真实浏览器与无头环境的差异

| 环境 | 适用 | 注意 |
|---|---|---|
| **本机带界面的浏览器** | 需要你已登录的后台、复杂交互 | 登录态来自你自己的浏览器配置 |
| **无头浏览器（服务器 / CI）** | 公开页面、批量任务 | 没有显示器；复杂页面渲染可能不同 |
| **云端浏览器** | 需要固定出口环境、批量并发 | 属于额外服务，注意成本 |

**最常见的故障模式**：本地跑通、服务器跑不起来。
排查顺序：

1. 目标环境有没有浏览器运行时？
2. 有没有显示器（无头环境需要无头模式）？
3. 需要登录的页面，登录态在目标环境里存在吗？

## 七、成本估算

```
单次任务调用数 ≈ 页面步数
单次任务成本   ≈ 步数 × 单步 tokens（含页面内容）× 模型单价
```

**页面内容是大头**：一页 HTML 可能几千到上万 tokens，
而每多走一步，整段上下文都要重发一次。

**三个降本手段**：

1. **缩小页面范围** —— 只传目标区域或精简后的页面文本，别整页塞进去。
2. **限制步数** —— 上限设小，失败就停并报告。
3. **分档用模型** —— 快模型打底，难点再换视觉或强模型。

---

## 八、合规边界

- **只在自有账号或已获授权的页面上操作。**
- 目标站点的服务条款、robots 与数据合规由使用者自行确认。
- 涉及个人信息的采集，请确认符合你的合规要求。
- **写操作给人工确认**，尤其是金融交易与不可逆动作。
- 采集频率控制在合理范围，不要给目标站点造成压力。
