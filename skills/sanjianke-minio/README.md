# 三剪客 · 自建 S3 对象存储 Skill

MinIO：自建 S3 对象存储 的安装、常用命令与避坑要点

---

## 前置条件

- **获取方式先确认**：社区版当前按源码分发（需要 Go 工具链）或自行构建容器镜像；历史预编译二进制仍可下载但已不再维护。不要默认「官网有安装包」。
- 一台（或几台）你自己的服务器/NAS/主机，磁盘为**本地直连**存储——不能是 NFS / SMB 网络共享目录。
- 规划两个端口：对象 API（默认 `9000`）与控制台（建议显式指定，如 `9001`），并在防火墙/安全组放行。
- 一个强 root 口令。默认值 `minioadmin:minioadmin` 只能用于本机一次性验证，绝不能用在对网络开放的实例上。
- 多节点部署额外要求：节点间网络互通、所有节点启用时钟同步。
- 客户端侧准备 `mc`（命令行客户端），用于配置别名、建桶与排障。
- 许可证前提：AGPLv3。自用、二次开发或对外分发前，先确认你的使用方式是否满足其义务。

## 使用

最短跑通路径：

1. 启动服务端（前台先验证一次，数据目录用空目录）：

   ```bash
   MINIO_ROOT_USER=admin MINIO_ROOT_PASSWORD='替换成强口令' \
     minio server /srv/minio/data --console-address ":9001"
   ```

2. 启动日志里会打印 API 与控制台地址。浏览器打开控制台，用你设置的 root 账号登录。
3. 客户端加别名并确认连通：

   ```bash
   mc alias set local http://127.0.0.1:9000 admin '替换成强口令'
   mc admin info local
   ```

4. 建桶并跑一遍读写验证：

   ```bash
   mc mb local/media
   mc cp ./demo.mp4 local/media/
   mc ls local/media/
   mc cp local/media/demo.mp4 ./downloaded.mp4
   ```

5. 给应用发一对独立凭证（不要给应用 root）：

   ```bash
   mc admin user add local appuser '应用侧口令'
   mc admin policy attach local readwrite --user appuser
   ```

6. 用标准 S3 工具验证兼容性：

   ```bash
   aws --endpoint-url http://127.0.0.1:9000 s3 ls
   ```

7. 验证通过后交给容器或 init 系统常驻，并把「当前是单节点、没有高可用」写进你的部署记录。

分布式与容器化部署的具体命令、目录集合与扩容方式以官方部署文档为准，不要照搬单机写法扩规模。

## 依赖

- **服务端**：单文件二进制。源码安装需要 Go 工具链；容器安装需要容器运行时。
- **客户端**：`mc` 命令行客户端（可选但强烈建议）；任何 S3 兼容 SDK/CLI 也可以直连。
- **存储**：本地直连磁盘或块设备；容量按对象总量 + 版本控制留存 + 未完成分片预留。
- **系统**：多节点部署必须有时钟同步服务；生产建议 Linux。
- **网络**：对客户端开放 API 端口与控制台端口；分布式部署节点间需互通。
- **无模型、无 API Key 依赖**：它是存储服务，不涉及大模型调用或 GPU 算力。

## 安全

- 不内嵌任何密钥；本 Skill 示例中的口令都要你自行替换为强口令。
- 默认 root 凭证 `minioadmin:minioadmin` 必须在对外提供服务前替换掉；如果实例曾以默认口令对网络开放，按「凭证已泄露」处理并轮换。
- root 凭证只用于管理动作；应用一律使用单独用户 + 最小权限策略，不要图省事把 root 发给应用。
- `mc` 客户端会把 Access Key / Secret Key 存在自己的配置目录里，注意该目录的文件权限与备份策略，别把配置目录提交到版本库或打进镜像。
- 控制台是管理面：只对内网开放，或经反向代理加鉴权；不要把控制台端口直接暴露到公网。
- 桶权限要逐桶确认：默认私有、按需公开，公开桶等于任何人可读。
- 数据目录不要放在网络共享盘上，也不要与其他写入方（如数据库、虚拟机）共用；除了一致性风险，也容易做出权限混乱。
- 使用他人数据前确认你有权存储与分发；对象存储只是保存介质，不改变内容的授权状态。
