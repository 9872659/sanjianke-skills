# 角色与职权设计

> 这份资料回答一个问题：**为什么本包是「多智能体协作」，而不是「一个模型分五次扮演不同角色」。**
> 判断口径不是"调了几次模型"，而是三件事：每个角色有没有**自己的目标函数与产出物**、
> 角色之间**能不能否掉彼此**、有没有**明确的裁决与出口**。

## 一、四个角色的职权表

| 角色 | 目标函数（它想要什么） | 产出物（它交什么） | 否决权 | 谈不拢的出口 |
|---|---|---|---|---|
| **教研** `designer` | 这门课值不值得学、给谁学、学完能做到什么、拿什么考核 | 课程设计卡：课程目标 / 受众 / 前置知识 / 逐单元学习目标 / 考核标准 / 术语表 | **能否掉自己的设计并重开**（上限 `--design-retries`） | `design_retries_exhausted` → 升级给人看 |
| **讲师** `instructor` | 每一节都要讲透：目标落到可观察的行为、例子能跟着做、过渡接得上下一节 | 逐节讲义正文 + 自评 `self_check` | **无** —— 只能改，不能否掉课件或质检的结论 | 不适用 |
| **课件** `slides` | 每一页放不放得下、版式能不能看 | 逐页课件方案（页型 / 标题 / 要点 / 备注）+ **放不下清单** | **能说「这页放不下」**并要求讲师拆（上限 `--slide-rework`） | `slide_rework_exhausted` → 带未决项产出 |
| **质检** `inspector` | 前后一致 + 事实与合规：这门课能不能交（不问它写得好不好） | 问题清单（**每条必须引用讲义原句**）+ 风险裁决 + 合规结论 | **能否决**（`pass` / `fix` / `send_back` / `veto`） | `inspect_send_back_exhausted` / `veto` → 带未决项产出 |

零成本看这张表：

```bash
python3 scripts/run.py roles          # 人读
python3 scripts/run.py roles --json   # 机器读（含信息不对称设计与课程特有闸门）
```

## 二、为什么"一个模型演四个角色"不成立

那种做法最致命的地方是**四个角色共享同一份上下文**：

- 课件永远看得到一个它不该看到的「讲师自评」，于是它的"独立判断"其实是顺着作者
  的自我评价走的；
- 质检永远知道课件已经逐页验过了，于是它不会再独立去挑版式与内容量的问题；
- 最坏的情况是：整条链看起来有四个声音，实际上是**同一个声音的自言自语**，
  而报告里写着一堆"多方确认"。

本包用**两个机制**把这件事做成结构性的，而不是靠提示词里的一句叮嘱：

### 机制一：字段白名单（物理上没有进入 prompt 的路径）

`run.py` 里的 `ROLES[*]["inputs"]` 与 `["forbidden"]` 不是文档，是
`build_*_prompt()` 真实读的那份数据。提示词模板按它拼装，被排除的字段在物理上
不可能出现在提示词里。

| 角色 | 允许进入上下文 | **被显式排除** |
|---|---|---|
| 教研 `designer` | 用户材料、规模参数 | （无 —— 它是第一环，没有上游） |
| 讲师 `instructor` | 用户材料、设计卡（含学习目标）、前面各节的术语摘要、单节篇幅 | 考核标准 `assessment` |
| 课件 `slides` | 用户材料、**课程结构窄字典**（课程名 + 逐单元标题）、讲义正文、页数上限 | 讲师自评 `self_check` |
| 质检 `inspector` | 用户材料、完整设计卡、讲义正文 | 讲师自评 `self_check`、课件放不下清单 `slide_issues`、课件结论 `slides_verdict` |

三条排除各自解决一个具体问题：

1. **讲师自评不进课件** —— 作者说"我觉得这段讲得清楚"会污染版式判断。
2. **讲师自评 + 课件意见都不进质检** —— 质检的提示词里明写
   「**本团队内部没有向你提供任何风险结论**，也不提供课件侧的意见」。
   质检若知道课件已经验过，就会顺着放行。
3. **考核标准只给质检、不给讲师** —— 讲师一旦看到"考核标准"，就会把讲义写成
   对着考点划重点的形态，那是备考资料，不是课。

### 机制二：调用前实检（`assert_isolation()`）

光有白名单还不够 —— 白名单说的是"模板应该怎么写"，实检说的是"这一次真实发出去的
提示词到底写了什么"。每次调用前，脚本拿被禁字段的**标记词**去扫**真实提示词文本**：

| 被禁字段 | 标记词（任一命中即判泄漏） |
|---|---|
| `self_check` | `自评` / `self_check` / `我认为讲得好的地方` / `我自己的评价` |
| `slide_issues` | `放不下清单` / `课件的意见` / `slide_issues` / `页数不够` / `这一页放不下` |
| `slides_verdict` | `课件结论` / `slides_verdict` / `课件已经验过` / `课件已通过` |

判定结果**逐条写进产物与 `REPORT.md`**（`isolation` 字段：阶段 / 轮次 / 提示词字符数 /
排除的字段 / 检查了几个标记词 / 有没有泄漏），外部可复核。
泄漏不是"打个警告"：**抛 `IsolationBreach`、中止这次调用、一个字都不发出去**，
退出码 3。理由很直接 —— 如果课件真的看到了讲师自评，这一轮产出的"独立判断"就是假的，
整条链的结论都不能用，宁可停下报错。

### 真机实测（可复核）

一次 1 单元 1 节的完整运行，5 次调用逐次实检：

| 阶段 | 轮次 | 提示词字符数 | 排除的字段 | 检查的标记词数 | 泄漏 |
|---|---|---|---|---|---|
| `designer` | 1 | 1529 | 无 | 0 | 无 |
| `instructor` | 1 | 1695 | 无 | 0 | 无 |
| `slides` | 1 | 2436 | `self_check`、`instructor_self_check` | 6 | 无 |
| `inspector` | 1 | 3373 | `self_check`、`slide_issues`、`slides_verdict` | 13 | 无 |
| `inspector` | 2 | 3373 | 同上 | 13 | 无 |

`information_asymmetry.all_ok = true`，且
`self_check_excluded_from_slides = true`、
`self_check_and_slide_issues_excluded_from_inspector = true`。

**反向验证**（零成本，本地算）：往课件的提示词里注入一句「顺带附上：讲师自评如下」→
当场拦下并抛 `IsolationBreach`；往质检的提示词里注入「课件结论：放不下清单已处理」→
三个标记词同时命中。

## 三、谁是串行、谁是并行

```
教研 design ──▶ 讲师 lecture ──▶ 课件 slides ──┬─ fits ──────▶ 质检 inspect ──┬─ pass/fix ─▶ 交付
   ▲                     ▲                    │                          ├─ send_back ─┐
   │                     └── 放不下清单（引讲义原句）┘ cannot_fit               └─ veto ──────┼─▶ 带未决项产出
   └── 设计卡不达标 / 重开（上限 --design-retries）      └──── 讲师按反馈改写（上限给定）──┘
```

**三个否决是串行关系，不是投票**：

- 设计卡不达标就轮不到讲师（`design_retries_exhausted`）；
- 课件说放不下就先让讲师改讲义，改完课件再看一遍；
- 质检在课件之后仍可**独立**否决 —— 它不看课件的结论。

串行是有意的：投票会把"谁更该让步"这个问题交给数量，而这里需要的是**职权**。

## 四、每条否决都必须留得下理由

`check_ruling_completeness()` 在收口时把 `log` 里所有裁决过一遍：
凡是 `send_back` / `veto` / `cannot_fit` / `rejected` / `ineffective` 这类**否决性裁决**，
理由少于 8 个字就判「无理由裁决」，整次运行落到退出码 3 并逐条列出是哪一条。

这一条不是装饰。没有它，"打回"可以是一句空话；有了它，报告里每条否决都得说清
「凭什么」。真机运行的裁决记录长这样（3 条裁决，全部留有理由）：

```
[1] 教研 r1 → accepted   | 设计卡达标：目标可考核、每单元有考核标准、前置知识非空
[2] 质检 r1 → send_back  | 讲义仅覆盖 u1s1，逐条按四条口径核查后…
[3] 质检 r2 → send_back  | 对 u1s1 逐条过口径：目标可考核性方面…
[slide 1] 课件 r1 → fits | 本节内容量适中，四页可容纳：封面、拉片方法、两个常见错误、小结…
```

## 五、信息不对称的代价与边界（诚实说明）

- **代价**：因为质检拿不到课件的结论，它可能重复发现课件已经发现的问题。这是
  **刻意付的代价** —— 换来的是一条不能被上游结论污染的独立判断。
- **边界**：四个角色都是同一个模型（默认 `deepseek-chat`）扮演的。信息不对称能挡住
  "上下文泄漏"这一种假对抗，挡不住"同一个模型有系统性偏好"这一种。想进一步分离，
  用 `--model` 给不同阶段换模型（本包所有角色共用一个 `--model`，这是已知限制）。
- **边界二**：本包不校验讲师有没有真的按"必须修清单"改对内容。它只做三件机械的事：
  正文相似度、自报修改条数占比、以及**下一轮质检还会不会再点到同一段文字**
  （`stalled_same_quote` 出口）。
