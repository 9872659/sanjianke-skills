# 成本与排错

> 这份资料回答两件事：**这次协作要花多少**、**跑不通时先看哪里**。
> 全部数字来自真机实测，不编。

## 一、成本口径（**只出 token，不编价**）

文本模型网关**不公布单价**：`/api/v1/models` 的返回里没有价格字段，
`usage` 里也没有 `points_cost`。所以本包的 `cost` 子命令在没给单价时
**只出 token、不给金额**，并且明说原因。

要知道金额，得你自己传账号的单价（单位「点/百万 token」）：

```bash
python3 scripts/run.py cost --file 材料.md --chapters 3 --sections-per-chapter 1 \
    --target-chars 800 --price-in 1000 --price-out 2000
```

### `--budget` 的单位是**元**，而且必须配单价

- `--budget` 是**元**（`POINTS_PER_YUAN = 100`，即 1 元 = 100 点）；
- 用了 `--budget` 却**没给** `--price-in / --price-out` → **退出码 2**。
  理由是：没有单价时金额未知，`over_budget()` 永远返回 false ——
  那等于用户设了一个**看起来生效、实际永远不触发**的假保险丝；
- 预算校验**提到每个会花钱子命令的第一步**：超了就地停，**一次调用都不发**。

### 字符 → token 的标定（同族实测值，不是厂商文档）

| 方向 | 比值 |
|---|---|
| 输入 | 1 token ≈ 1.61 字符 |
| 输出 | 1 输出字符 ≈ 1.11 token |

## 二、真机实测（三个数都是 `usage` 原文）

### 运行逐次用量

| 运行 | 规模 | 调用次数 | `usage` 原文 | 折算（按 1000/2000 点每百万 token） |
|---|---|---|---|---|
| **A** | 3 单元 × 1 节，单节 700 字，页数上限 8 | 6 | `prompt_tokens 11439 / completion_tokens 9236 / total_tokens 20675` | 29.911 点 ≈ ¥0.299 |
| **B** | 1 单元 × 1 节，单节 400 字，页数上限 4 | 5 | `prompt_tokens 8696 / completion_tokens 3699 / total_tokens 12395` | 16.094 点 ≈ ¥0.161 |
| **C** | 3 单元 × 1 节（被自己的预算闸门在第一次调用前拦下） | 0 | `prompt 0 / completion 0 / total 0` | ¥0 |

平均：每次调用的输入约 **1.5k~3.4k token**、输出约 **0.7k~1.5k token**。
输入 token 比输出大，因为每次调用都要带上用户材料与整份产出。

> **上线前调试期累计**：A + B 两轮跑通共 **13 次调用、38841 token**
> （`prompt 22564 / completion 16277`），按上面那档单价折算 **55.118 点 ≈ ¥0.551**。
> 调试期还发生过一次参数未定型的试跑（3 次调用，退出码 3），它的 `usage`
> 没有留存成独立产物，所以**不在上面的数里**。
> 这两组数只说明一件事：**一节讲义一次调用、一次调用一两千 token 是常态**。

### 一次运行的调用构成（A，6 次）

| # | 角色 | 调用 | 说明 |
|---|---|---|---|
| 1 | 教研 | 课程设计卡 × 1 | 真机上第一次被网络抖动打断，退避重试后成功 |
| 2 | 讲师 | 讲义 u1s1 | |
| 3 | 讲师 | 讲义 u2s1 | |
| 4 | 讲师 | 讲义 u3s1 | |
| 5 | 讲师 | 讲义 u3s1（**重试**） | 前一次的输出 JSON 解析失败，重跑了一次 |
| 6 | 课件 | 逐页方案 × 1 | 结论 `cannot_fit`，但定位不到具体的节 |

### 报价 vs 实测

`cost` 是**最坏情况上界**（含设计重开、课件重做、质检打回各一次）。运行 B 的实际
5 次调用低于上界；真正跑起来之后金额以账户流水为准。

## 三、预算闸门的两个单位坑（都踩过）

### 坑一：`--budget` 是元，`points` 是点

`over_budget()` 早先直接写 `pts > self.budget`，等于把 **0.5 元当成 0.5 点** ——
预算瞬间变成一百分之一，**任何一次调用都会被判超预算、一个 token 都发不出去**。
真机第一次跑就是这样被自己的闸门挡在门外的（退出码 5，`已用 0 次调用`）。
现在两处口径都过 `POINTS_PER_YUAN`。

### 坑二：估算用的输出 token 取太大，正常预算会被卡死

`DESIGN_OUT_TOKENS` 早先标 1800，按 2000 点/百万的输出单价就是 3.6 点，
0.5 元的预算**还没开始花就"超了"**。这三个常量（设计 / 课件 / 质检的输出上界）
现在按"3 单元 3 节、单节 700 字"的默认规模标定成
1200 / 1200 / 1000。

## 四、退出码

| 码 | 含义 |
|---|---|
| 0 | 收敛：课件逐页放得下 + 质检 `pass`/`fix` + 硬闸门全过 |
| 2 | 用法 / 配置错（文件不存在、`--outdir` 在包内、`--budget` 没配单价、参数超区间、长选项缩写） |
| 3 | **硬闸门命中**，或**未收敛**（含质检否决） |
| 4 | 调用失败（网络 / 鉴权 401 / 点数 402 / 模型名 404） |
| 5 | 预算超限，**已就地中止，未发起任何调用** |
| 130 | 用户中断（Ctrl+C） |
| 1 | **没预料到的异常**（代码 bug）：`--json` 下给 `internal` 信封 + **完整 traceback 到 stderr** |

`2 / 3 / 4 / 5` 分开是有意的：`2` = "你命令写错了"、`3` = "上游没问题，是被本地规则拦了"、
`4` = "上游/网络有问题"、`5` = "你自己的预算上限"。CI 里这四种要采取完全不同的动作。

## 五、`--json` 输出契约

**`--json` 写在子命令前面或后面都可以**（父级与每个子命令各注册一个同 dest 的开关，
`default=argparse.SUPPRESS` 保证父级设过的值不被覆盖）。

- **成功**：结果对象里多一个 `"ok": true`；顶层是数组时包成
  `{"ok": true, "data": [...]}`
- **失败**：stdout 输出 `{"ok": false, "exit": <码>, "error": {"kind": …, "message": …}}`，
  `exit` 就是本次真实退出码，`kind` 取 `usage` / `gate` / `call` / `budget` /
  `interrupt` / `internal`；
  **只有在本次还没吐过任何 JSON 结果时才补信封** —— 否则 stdout 上会有两个 JSON 文档，
  `json.loads` 直接 `Extra data: line N column 1`
- **`internal`** 是没预料到的异常的兜底：stdout 给信封、**完整 traceback 原样打到
  stderr**、退出码固定 1 —— 报 bug，不藏 bug
- 人读文案照旧走 stderr；**退出码语义一个都不变**；非 `--json` 模式输出一个字符都不变
- 所有 JSON 都经 `_json_write()` 写**真 stdout**，绕开任何临时的 stdout 重定向

> ⚠️ **Windows PowerShell 5.1 的 `>` 重定向会写成 UTF-16LE**。
> 想存 `--json` 的结果请用 `| Out-File -Encoding utf8 <文件>`，
> 或让脚本自己的 `--out` 参数写（脚本一律写 UTF-8 无 BOM）。
> 读回时 `log` 子命令用 `utf-8-sig` 解码，容忍 BOM。

## 六、`allow_abbrev=False`：为什么长选项不许缩写

事故复盘（同族自测踩到的真实坑）：子命令上同时有 `--outdir` 时，用户写
`--out report.json` 想输出结果文件，argparse 默认允许**前缀缩写**，于是 `--out`
被当成 `--outdir` 的缩写匹配上了 —— 结果产出目录变成了一个叫 `report.json` 的目录，
而且**不报任何错**。这类"参数被静默吃成另一个参数"的错误最难查，因为命令行看起来是对的。

关掉缩写后，`--out` 直接报 `unrecognized arguments`（退出码 2），一眼能看出问题。

`allow_abbrev=False` **必须在父 parser 与每个子 parser 上都设**（缩写开关是每个
parser 各自的属性，只在父级设一遍不够 —— 子 parser 是另造的实例）。
本包用 `parser_class=partial(_parser)` 统一处理。

## 七、断点续跑

`run` 会把每步产出的 `state.json` 写在 `--outdir` 里。**同一目录原样重跑只花钱在
真正变化的维度上**，已完成的步骤直接跳过并打印「已在断点里，跳过（零成本）」。

断点 key 含**全部影响产出的维度**：

| 维度 | 为什么必须进 key |
|---|---|
| 用户材料摘要 + 字符数 | 材料变了必须重跑（摘要防"改了一个字却复用"） |
| 设计卡摘要 | 教研重开过设计卡 → 下游全部要重做 |
| 当前产物摘要 | 讲义 / 方案变了，这一轮产出必然不同 |
| **节 id** | 逐节调用必须区分是哪一节 |
| 单节篇幅 `--target-chars` | 篇幅影响讲师怎么写 |
| **课程规模**（单元数 / 每单元节数） | 规模变了，节列表就变了 |
| **页数上限 `--max-pages`** | 换了上限，课件方案的结论就不同 |
| 模型 / 温度 | 换模型或换温度就是换产出 |
| 轮次号 | 第几轮；轮次不同产物不同 |
| 角色 / 提示词 / 裁决口径版本 | 改了口径却不改 key，续跑会复用上一版口径的旧产物 |

想强制重跑用 `--force`（**key 没命中就会重新花钱**）。

## 八、排错表

| 现象 / 报错 | 原因 | 怎么办 |
|---|---|---|
| `没有找到 API Key` | 三处都没有 | `--key` / `A7W_API_KEY` / `a7w.py login` 三选一 |
| `鉴权失败（401）` | Key 无效或已过期 | 到 https://api.a7w.cn/ 重新创建 |
| `点数不足（402）` | 账号点数用完 | 充值后重试 |
| `模型不存在（404）` | 模型名写错或已下架 | `run.py models` 现查在架模型名 |
| 上游 `502 / 503 / 504` | 网关到上游的瞬时抖动，**实测很常见** | 脚本已内置退避重试 4 次；连续失败就换模型或分批跑 |
| `网络抖动（[WinError 10054]…）` | 远程主机强制断开，**实测出现过** | 同样是退避重试；真机上重试一次就成功了 |
| `模型返回的不是合法 JSON` | 输出里有围栏或多吐了字符 | 脚本用 `json.JSONDecoder().raw_decode()` 扫第一个完整对象；仍失败就 `--no-json-mode` |
| `预估成本已超预算，**未发起这次调用**`（退出码 5） | 单价 × 上界 token 超了 `--budget` | 提高 `--budget`、减少节数/篇幅，或先 `cost` 试算 |
| `用了 --budget 就必须给 --price-in / --price-out`（退出码 2） | 没给单价 | 补上单价（点/百万 token） |
| `产出目录不能落在 Skill 包内`（退出码 2） | `--outdir` 指到包内了 | 换到包外，例如 `%TEMP%\...` |
| `--sections N 超过上限 12`（退出码 2） | 一次要写的节太多 | 拆成两次跑，第二次交给同一个 `--outdir` 续跑 |
| `unrecognized arguments: --out`（退出码 2） | 长选项前缀缩写被关掉了 | 写全（`--outdir` / `--target-chars`） |
| `出口 = design_retries_exhausted` | 设计卡连续不达标 | **这是真实结论**。看 `unresolved` 里逐条列出的原因（通常是目标不可考核），改 `--design-retries` 或人工介入 |
| `出口 = slide_rework_exhausted` | 课件说放不下，重做上限用尽 | 看放不下清单要拆哪几页；低于该页的内容量，或提高 `--max-pages` |
| `出口 = inspect_send_back_exhausted` | 质检打回次数用尽仍不放行 | 看 `reason` 与必须修清单；提高 `--inspect-rework` 或人工定口径 |
| `出口 = no_effective_change` | 讲师在原地打转（正文相似度 ≥ 0.86） | **继续加轮次只会烧钱**，看必须修清单是不是写得太抽象 |
| `出口 = stalled_same_quote` | 质检两次指向同一段文字 | 通常那两个要求互相冲突，需要人来定口径 |
| `出口 = rounds_exhausted` | 轮次用尽 | 加 `--rounds` 或人工介入 |
| 质检裁决是 `send_back`，但 `issues` 是空的 | 本地兜底改判（模型自报 `pass`，本地闸门命中） | 看「质检（本地兜底）」那条裁决的 `forced_by_local`，里面写清了是哪条本地闸门 |
| `[前置缺失]` 里出现明显不是术语的词 | 术语抽取的已知误报面 | 看 `references/课程设计与考核.md` 第五节；把该短语写进设计卡的 `prerequisites` 也可以放行 |
| 断言「课件说放不下，但定位不到具体的节」 | 放不下清单里 `section` 与 `page` 都填不上 | 已实现「节 id → 页 id → 引文唯一锚点」三级回退；三级都失败才会报这个 |
| Windows 下中文乱码 | 控制台代码页不是 UTF-8 | 脚本已把 stdout/stderr 切成 UTF-8；仍有问题先 `chcp 65001` 或设 `PYTHONIOENCODING=utf-8` |
| `.pyc` 会不会害上传被拒 | **不会** | `__pycache__` 与 `*.pyc` 在 CLI 的排除清单里，本来就不会被打包。跑完 `py_compile` 顺手清掉 `__pycache__` 只是让包干净 |

**收集排错信息时请附上**：完整命令、`--dry-run` 的输出、`REPORT.md` 的内容、
`log.json`、原始报错文本。**不要在报错信息或截图里带上你的 API Key。**

## 九、零成本自检（复核本包的说法）

```bash
# 1) 四个角色与信息不对称设计，不花钱
python3 scripts/run.py roles

# 2) 报价，不花钱（不给单价就只出 token）
python3 scripts/run.py cost --file 材料.md --chapters 3 --sections-per-chapter 1

# 3) 只看提示词，不调模型
python3 scripts/run.py run --brief 材料.md --dry-run

# 4) 跑完之后：包里不该出现任何 .pyc
python3 -c "import pathlib,sys; p=[x for x in pathlib.Path('.').rglob('*.pyc')]; \
print('.pyc 数量:', len(p)); sys.exit(1 if p else 0)"

# 5) 跑完之后：全过程记录 —— 如果「否决 / 打回」是 0，说明互审没有真的发生
python3 scripts/run.py log --outdir <你的 outdir>
```
