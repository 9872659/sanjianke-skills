# 三剪客 · 课程教研组

**给一个课程主题，四个立场不同的角色从课程设计开始协作，一条命令出一门课。**

- 产出的不是一篇稿子，而是**整门课**：课程设计卡 + 逐节讲义 + 逐页课件方案 +
  质检记录 + 裁决记录。
- **角色之间真的能否掉彼此**：教研能否掉自己的设计并重开，课件**能说「这页放不下」**
  并要求讲师拆，质检**能否决**。
- **信息隔离是结构性的**：讲师自评不进课件、不进质检；课件意见不进质检；
  考核标准只给质检不给讲师。每次调用前对真实提示词做文本级检查，泄漏就中止调用。
- **谈不拢有明确出口**：六种显式出口，未收敛会明说并附未决项，**不假装谈拢**。

零第三方依赖，纯文本产出，只走 `api.a7w.cn` 的 OpenAI 兼容端点。

## 一、这是产品线 L3

| 层 | 形态 | 同族已有的包 |
|---|---|---|
| **L1 单点生成型** | 一个输入 → 一个产出 | 爆款标题工坊、一稿多平台改写 |
| **L2 智能体型** | **单循环**：抽档 → 写 → 自检 → 迭代（**一个声音在自我迭代**） | 课程生产线、课件配图与排版、内容质量闭环 |
| **L3 多智能体协作型** | **多角色分工互审**，一条命令出成品 | 内容团队、评审委员会、短剧剧组、**← 本包** |

**判断口径不是"调了几次模型"**，而是三件事：

1. 每个角色有**自己的目标函数与产出物**；
2. 角色之间**能不能否掉彼此**；
3. 有没有**明确的裁决与终止条件**。

> **L3 最容易做假的地方**：一个模型分五次扮演四个角色，共享同一份上下文。
> 那种情况下课件永远看得到一个它不该看到的自评、质检永远顺着课件的结论走 ——
> **对抗是假的**，报告里的"多方确认"是同一个声音的自言自语。
> 本包用「字段白名单 + 调用前实检」两层机制挡住这件事，并把每次实检的结果
> 写进产物，让你自己复核（详见 `references/角色与职权设计.md`）。

## 二、三方分界表（**改代码前先读这张表**）

| | `sanjianke-course-outline` | `sanjianke-slide-kit` | **本包** |
|---|---|---|---|
| 产品线 | L2（单角色自我迭代） | L2（单角色自我迭代） | **L3（多角色分工互审）** |
| 输入 | 一个主题 | 一份讲义 | **一个主题**（**从课程设计开始**） |
| 产出 | 大纲 / 讲义 / 习题（**纯文本三件套**） | 逐页 PNG + 备注 + `deck.html`（**排版产物**） | 设计卡 + 讲义 + 课件方案 + 质检记录 + 裁决（**纯文本**） |
| 最小单位 | **节**（1500~3000 字散文） | **页**（页型 + 标题 + 要点 + 备注） | **整门课**（节 + 页 + 裁决一起交付） |
| 角色数 | 1 | 1 | **4**（教研 / 讲师 / 课件 / 质检） |
| 谁能否谁 | 没有人能否任何人，只有结构校验与评分 | 没有人能否任何人，只有像素级溢出判定 | 教研**能否掉设计**、课件**能说「这页放不下」**、质检**能否决** |
| 上下文 | 单条链共享 | 单条链共享 | **信息不对称**（三条排除 + 调用前实检） |
| 课程特有的闸门 | 大纲结构校验（章节 / 小节 / 学习目标是否为空话） | 文字溢出（真实字体排版后量像素） | **学习目标可考核性 / 知识点依赖 / 术语一致性** |
| 出图 / 排版 | 不出 | **逐页 PNG + 可选 HTML**（需要 `pillow` 与中文字体） | **不出图、不出 PPTX**（`python-pptx` 不是标准库） |
| 谁该用 | 要**大纲 / 讲义 / 习题的纯文本** | 要**能投在墙上的课件** | 要**从课程设计开始的分工与对抗**，以及**谁否掉了什么的记录** |

**一句话**：`course-outline` 回答"讲义怎么写"、`slide-kit` 回答"这页放不放得下"，
本包回答"**这门课该不该这么设计、谁说了算**"。

### 三条不要选本包的情形

- 只要大纲 / 讲义 / 习题 → 用 `course-outline`（4~5 次调用，更省）；
- 要成片课件（PNG / 排版 / 配图）→ 用 `slide-kit`；
- 想要的是"多跑几次模型"而不是"多角色互审" → 本包并不便宜。

**本包的 `deck.json` 可以直接交给 `slide-kit` 那一类排版包去做渲染**
（本包只出文本方案，不出图）。

## 三、四个角色

| 角色 | 目标函数 | 产出物 | 否决权 |
|---|---|---|---|
| **教研** | 这门课值不值得学、给谁学、学完能做到什么、拿什么考核 | 课程设计卡 | **能否掉自己的设计并重开**（`--design-retries`） |
| **讲师** | 每一节都要讲透 | 逐节讲义 + 自评（`self_check`） | 无 |
| **课件** | 每一页放不放得下、版式能不能看 | 逐页方案 + **放不下清单** | **能说「这页放不下」**（`--slide-rework`） |
| **质检** | 前后一致 + 事实与合规 | **问题清单（每条引用讲义原句）** + 风险裁决 | **能否决**（`--inspect-rework`） |

```
教研 design ──▶ 讲师 lecture ──▶ 课件 slides ──┬─ fits ──────▶ 质检 inspect ──┬─ pass/fix ─▶ 交付
   ▲                     ▲                    │                          ├─ send_back ─┐
   │                     └── 放不下清单（引讲义原句）┘ cannot_fit               └─ veto ──────┼─▶ 带未决项产出
   └── 设计卡不达标 / 重开（上限 --design-retries）      └──── 讲师按反馈改写（上限给定）──┘
```

**三个否决是串行关系，不是投票。** 投票会把"谁更该让步"交给数量，而这里需要的是**职权**。

## 四、它到底能不能跑通（真机实测，含"是不是假协作"）

**真机跑过两次完整流程，`usage` 原文如下（不编）：**

| 运行 | 规模 | 调用 | `usage` 原文 | 结果 |
|---|---|---|---|---|
| A | 3 单元 × 1 节 | 6 | `prompt 11439 / completion 9236 / total 20675` | **课件说「放不下」1 次**、教研重开 1 次 → 出口 `slide_rework_exhausted` |
| B | 1 单元 × 1 节 | 5 | `prompt 8696 / completion 3699 / total 12395` | **质检打回 2 次并真的改了讲义** → 出口 `inspect_send_back_exhausted` |

**这四个角色是真的在互相否，不是各写各的**，证据：

- 运行 A：课件给出「这一页放不下」的诉求（引讲义原句），**强制讲师改写讲义**；
  同时教研的设计卡被本地判过一次不达标、重开一次。
- 运行 B：质检两轮都判 `send_back`，**讲师按必须修清单真的改了一版讲义**
  （动作流水里有 `revise 讲师 r1` 这一条），改完质检再审第二轮。
- 反过来也说明本包的诚实性：两次运行**都没有收敛**，退出码都是 3，
  报告里逐条列了未决项。**它没有把"改了但没改好"讲成"已经改好"。**

真机上还抓到并修掉了四类问题（都在 `references/` 里留了复盘）：
目标可考核性闸门误伤合格目标、术语抽取把「老板讲用料」当术语（台账 17 条 → 3 条）、
课件说放不下却**定位不到具体的节**（否决权被废）、以及 `inspect` 路径
**漏跑**了合规 / 占位符 / 照抄示例三道闸门。

## 五、三道课程特有的闸门

| 闸门 | 拦什么 | 例子 |
|---|---|---|
| **学习目标可考核性** | 「了解 / 熟悉 / 掌握 XX」这类**无法考核**的目标 | 「了解内容运营的整体思路」❌ /「能写出 3 个候选开场钩子并挑出 1 个」✅ |
| **知识点依赖** | 讲义里用到但**前面从没讲过**的术语 | 第 2 节用了「完播率」，第 1 节从没讲过 → 前置缺失 |
| **术语一致性** | 同一节里同一概念的两种叫法 | 「完播率」与「完看率」 |

再加上合规 / 占位符 / 照抄示例 / 质检锚点 / 成本与产出路径，共 **八道本地硬闸门**。
命中一律：**压分 + 标红 + stderr 汇总 + 退出码非 0**，不是"提示一下"。

## 六、怎么用

```bash
# 第 1 步：零成本自检（不联网、不花钱）
python3 scripts/run.py roles
python3 scripts/run.py cost --file 材料.md --chapters 3 --sections-per-chapter 1
python3 scripts/run.py run --brief 材料.md --dry-run

# 第 2 步：一条命令出整门课
python3 scripts/run.py run --brief 材料.md --chapters 3 --sections-per-chapter 1 \
    --target-chars 800 --max-pages 8 --outdir /tmp/cc

# 第 3 步：读回全过程记录（谁否掉了什么、引用哪句原话）
python3 scripts/run.py log --outdir /tmp/cc
```

也可以一个角色一个角色地跑：`design` → `lecture` → `slides` → `inspect`，
每一步都能单独拿去用，也能交给下一步（`--design` / `--lectures`）。

**`--outdir` 一定要指到包外。** Skill 包的上传白名单只收
`.md .py .txt .json .sh .js .yaml .yml .csv`，产出写进包里会污染交付物，
脚本会直接 `exit=2` 拦住。

## 七、成本

**只出 token，不编价。** 文本模型网关不公布单价（`/api/v1/models` 里没有价格字段），
所以 `cost` 在没给单价时只说 token；要金额就传你自己账号的单价（点/百万 token）。

```bash
python3 scripts/run.py cost --file 材料.md --chapters 3 --sections-per-chapter 1 \
    --price-in 1000 --price-out 2000 --budget 0.5
```

- `--budget` 的单位是**元**（1 元 = 100 点），而且**必须配单价** ——
  不给单价时金额未知，那个上限会变成一个永远不触发的**假保险丝**，所以本包直接报用法错。
- 预算校验**提到每个会花钱子命令的第一步**：超了就地停，**一次调用都不发**。
- 实测单次调用输入约 1.5k~3.4k token、输出约 0.7k~1.5k token。

## 八、退出码

| 码 | 含义 |
|---|---|
| 0 | 收敛：课件逐页放得下 + 质检放行 + 硬闸门全过 |
| 2 | 用法 / 配置错（文件不存在、`--outdir` 在包内、`--budget` 没配单价、参数超区间） |
| 3 | **硬闸门命中**，或**未收敛**（含质检否决） |
| 4 | 调用失败（网络 / 鉴权 401 / 点数 402 / 模型名 404） |
| 5 | 预算超限，已就地中止（未发起任何调用） |
| 130 | 用户中断 |
| 1 | 没预料到的异常：`--json` 下给 `internal` 信封 + **完整 traceback 到 stderr** |
