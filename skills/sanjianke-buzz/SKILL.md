# 三剪客 · 离线音视频转字幕

有一类素材不适合上传到云端处理：客户给的访谈、还没发布的成片、涉及隐私的会议录音。Buzz 的思路是把转写整件事放到本机做——装上它，拖进音频或视频文件，它在本机跑模型出字幕，素材不出本地。除文件外它也接受视频链接，还能从麦克风实时转写，做现场演示时的字幕投屏。转写结果可以导出成 TXT、SRT、VTT，直接进剪辑流程。

需要在离线环境批量出字幕、或者想用图形界面给不写代码的同事用时，用它。

**上游项目**：`Buzz`　**仓库**：https://github.com/chidiwilliams/buzz

## 什么时候用 / 不用

**用它**：

- 素材不能外传：访谈、内部会议、未发布内容，要全程本地转写。
- 想用图形界面而不是命令行：导入文件、选模型、看转写结果、导出字幕都在一个窗口里完成。
- 要实时字幕：现场演讲、直播辅助，从麦克风边录边出字，还能开演示窗口放大显示。
- 要批量出字幕文件：用命令行把一批文件排进队列，统一导出 SRT / VTT / TXT。
- 想用不同推理后端对比速度与质量：它支持多个 whisper 系后端，含 CUDA 与 Vulkan 加速路线。

**不要用它**：

- 想要逐词级时间戳与高精度对轴：它的定位是句子/片段级字幕，要词级精度得换专门做强制对齐的工具。
- 要精确的多人说话人身份标注：它提供说话人识别能力，但不要期望达到专业分离系统的准确度。
- 无图形界面的纯服务器环境只想跑批：命令行界面是基于 Qt 的，装起来比纯 CLI 工具重。
- 要翻译成英语以外的目标语言：它的翻译任务是转写成英语，不是任意语种互译。
- 需要云端协作、团队共享词库与集中管理：它是本地桌面应用，没有这些能力。

## 安装
前置：系统需有 ffmpeg。从 PyPI 安装的方式要求 Python 3.12 环境。

```bash
# Linux：Flatpak
flatpak install flathub io.github.chidiwilliams.Buzz

# Linux：Snap（先补系统库）
sudo apt-get install libportaudio2 libcanberra-gtk-module libcanberra-gtk3-module
sudo snap install buzz

# PyPI 安装（需要 Python 3.12，并先装好 ffmpeg）
pip install buzz-captions
python -m buzz
```

```powershell
# Windows 与 macOS：从官方发布页下载安装包
# Windows 的安装包未签名，安装时会出现安全提示，需选择「更多信息」再继续
# macOS 现在要求 Apple 芯片；最后支持 Intel 的版本是 1.4.5
```

## 常用操作

命令行只提供了一个子命令 `add`，用来把一批文件或链接排进转写任务；参数按功能分成「做什么」「用什么模型」「输出成什么」三组。

```bash
# 1) 最简：转写一个文件，任务跑完就退出（不弹主窗口）
buzz add --hide-gui audio.mp3

# 2) 指定后端与模型大小，并导出 SRT
buzz add -m whisper -s small --srt -d ./out audio.mp3

# 3) 走 whisper.cpp 后端（可配 Vulkan 加速），指定模型大小
buzz add -m whispercpp -s base --txt -d ./out recording.wav

# 4) 用 Hugging Face 上的 whisper 系模型，必须给模型 ID
buzz add -m huggingface --hfid openai/whisper-tiny --srt -d ./out audio.mp3

# 5) 翻译成英语而不是原样转写
buzz add -t translate -m whisper -s small --srt -d ./out interview.mp3

# 6) 指定语言（留空则自动检测），并给初始提示词帮助识别专有名词
buzz add -l zh -p "以下是一段关于视频剪辑的访谈。" --srt -d ./out talk.mp3

# 7) 开逐词时间戳、转写前先做语音分离（嘈杂素材更准）
buzz add -w -e -m whisper -s small --srt -d ./out noisy.mp3

# 8) 一次处理多个文件、几种格式一起出
buzz add --srt --vtt --txt -d ./out a.mp3 b.mp4 c.wav

# 9) 直接给视频链接，让它自己取
buzz add --srt -d ./out "https://example.com/video"

# 10) 走在线接口而不是本地模型（需要访问令牌）
buzz add -m openaiapi --openai-token "$OPENAI_API_KEY" --srt -d ./out audio.mp3

# 11) 看当前版本支持的全部参数
buzz add --help
```

图形界面侧的常用动作（在窗口里操作，不涉及命令）：导入文件或链接、选择模型与后端、开始转写、在转写查看器里搜索与调速回放、导出字幕、开启监听文件夹让它自动处理新进来的文件。

## 常见坑

| 现象 | 原因 | 怎么办 |
|---|---|---|
| Windows 装的时候被系统拦下 | 安装包没有代码签名 | 在提示里选「更多信息」再继续安装；只从官方发布渠道下载 |
| Mac 上装不上或跑不起来 | 新版本只支持 Apple 芯片 | Intel 机器只能用 1.4.5 及更早版本；否则换 Apple 芯片机器 |
| 命令行敲了但报「没有输入文件」 | `add` 之后的第一个位置参数被当作子命令本身，文件要从第二个开始 | 按 `buzz add [选项] 文件...` 的形态写，确认文件路径跟在选项后面 |
| 命令行启动报显示或平台插件相关错误 | 命令行界面是基于 Qt 的，需要图形环境 | 本机用就正常终端运行；纯无界面服务器要考虑虚拟显示方案，或改用别的转写工具 |
| 指定了模型大小却不生效 | 该参数只对 whisper / whisper.cpp / faster-whisper 三类后端有效 | 换成这三类后端，或按后端要求改用 `--hfid` / 自定义模型 ID |
| 用 Hugging Face 模型时报缺少模型 ID | 该后端必须显式给模型 ID | 加 `--hfid <模型ID>`，例如 `openai/whisper-tiny` |
| 选 openaiapi 后端报没有令牌 | 在线接口需要访问令牌，命令里没给也没有已保存的令牌 | 用 `--openai-token` 传，或先在界面里保存一次令牌 |
| 语言参数被拒绝 | 语言码不在支持列表里 | 用标准的语言码（如 `zh`、`en`），或留空让程序自动检测 |
| 只给了格式开关却没出文件 | 没指定输出目录时会落在默认位置，或格式开关拼写不对 | 显式加 `-d ./out`；格式开关是 `--srt` / `--vtt` / `--txt`，不写则沿用界面里的默认行为 |
| 第一次转写卡很久 | 首次使用要下载对应模型 | 预留下载时间与磁盘空间，或预先在界面里把模型下载好 |
| GPU 没被用上、还是慢 | 只装了 PyPI 版但没装带 CUDA 的 torch，或显卡加速组件没装 | 按上面两条路线补齐 CUDA 支持；Apple 芯片与部分集显走的是另外的加速路线 |

## 权限与用途说明

| 能力 | 是否申请 | 用途 |
|---|---|---|
| 网络访问 | 是 | 下载模型；处理视频链接时要取网络内容；用在线接口后端时会外发音频 |
| 读取文件 | 是 | 读取待处理的音频/视频、监听文件夹中的新文件、本地模型缓存 |
| 写入文件 | 是 | 导出 TXT / SRT / VTT 与转写记录，写入模型缓存 |
| 凭证 | 视情况 | 只有走在线接口后端时才需要访问令牌；本地模型路线不需要 |
| 子进程 / 后台常驻 | 是 | 桌面应用与监听文件夹都是常驻进程；命令行任务在跑完后退出 |
| 麦克风 | 是（实时转写时） | 现场实时转写需要采集麦克风输入 |

## 能力边界

**覆盖**：

- 音频与视频文件转写，导出 TXT / SRT / VTT
- 视频链接转写
- 麦克风实时转写，并带演示窗口便于现场显示
- 转写前做语音分离，提升嘈杂素材的准确度
- 说话人识别
- 多种推理后端：whisper、whisper.cpp、faster-whisper、Hugging Face 上的 whisper 系模型，以及在线接口后端
- GPU 加速路线：NVIDIA CUDA、Apple 芯片、以及面向大多数显卡（含集显）的 Vulkan
- 转写查看器：搜索、回放控制、调速、快捷键
- 监听文件夹自动处理新文件
- 命令行界面用于脚本化批处理
- 插件机制（如摘要生成、转写内容自动重排）

**不覆盖**：

- 不做逐词级强制对齐，时间戳精度定位在片段级
- 不提供专业级说话人分离的准确度保证
- 不做音频编辑、降噪修复、后期混音
- 不做视频剪辑、压制、上传发布
- 不做除「翻译成英语」以外的语言互译
- 没有团队协作、云端同步、术语库集中管理
- 不提供托管算力；本地推理速度取决于你的机器

## 依赖条件

- 系统需安装 ffmpeg
- PyPI 安装路线要求 Python 3.12
- 桌面运行环境（图形界面），Linux 下走 Flatpak / Snap 或发行版等价方式
- NVIDIA 加速需装带 CUDA 的 torch 与配套 CUDA 库；Apple 芯片与 Vulkan 路线按平台条件
- 首次使用需联网下载模型，并预留模型缓存空间
- 实时转写需要可用的麦克风与系统音频输入权限
- 走在线接口后端时需要对应服务的访问令牌

## 已知限制

- 命令行界面基于 Qt，纯无图形环境使用不便
- 模型大小与速度、准确度是此消彼长的关系，需要按素材手调
- 首次运行必须联网下载模型，完全离线的机器要提前把模型准备好
- 视频链接转写依赖外部网络与站点可用性，链接失效即失败
- 各平台安装包与系统兼容性有差异（如 macOS 只支持 Apple 芯片的新版本）
- 转写质量受素材本身影响很大：强噪声、重叠说话、口音重都会明显掉点

## 自检清单

执行前：

- [ ] 确认 ffmpeg 可用、磁盘留够模型与输出空间
- [ ] 明确走本地模型还是在线接口；在线接口要准备好令牌
- [ ] 选好后端与模型大小：先用小模型试跑，满意再换大模型
- [ ] 明确输出格式与输出目录，避免找不到成品
- [ ] 素材涉及隐私时确认全程本地处理，不要误选在线后端

执行后：

- [ ] 抽查字幕与音频是否同步、有没有整段漏字
- [ ] 检查专有名词与数字的识别是否准确，必要时用初始提示词重跑
- [ ] 确认导出格式能被下游剪辑软件正确导入
- [ ] 若结果不满意，记录所用后端与模型，换一档再对比
