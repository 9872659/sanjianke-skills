# 检查点与偏离处理

执行协议解决了「一段怎么做完」。这一份解决另一半问题：**什么时候必须停下来，重新看一眼计划本身。**

停下来是有成本的，所以不能频繁停，也不能不停。这一份给三个东西：什么时候停（检查点排布）、什么样的现象必须停（偏离信号清单）、停下来之后怎么办（继续 / 回退 / 改计划的分流）。

---

## 一、检查点的四种类型

检查点不是「阶段汇报」，它是**对计划本身的一次核对**。区别在于：汇报问「做到哪了」，检查点问「计划还对吗」。

| 类型 | 触发时机 | 核什么问题 | 输出 |
|---|---|---|---|
| 段检查点（P1） | 每段退出检查之后 | 这一段的结果和计划里的预期一致吗 | 通过 / 段内返工 |
| 里程碑检查点（P2） | 完成一组相关段之后（通常 3–6 段） | 这一组拼起来，还指向原目标吗 | 继续 / 调序 / 补段 |
| 风险检查点（P3） | 出现任一偏离信号时 | 计划的哪条前提被推翻了 | 继续 / 回退 / 改计划 |
| 时间盒检查点（P4） | 每 60 分钟（半天任务）/ 每半天（多天任务） | 时间花得值吗，还要多久 | 继续 / 砍范围 / 升级 |

P1 是高频低成本的，默认每段都做，30 秒。P3 是这套体系的重点，它由**信号**触发，不由时间触发。

### 检查点的时长预算

不要开大会。检查点超时了，说明它被当成了汇报会：

| 类型 | 时长上限 | 参与 |
|---|---|---|
| P1 | 1 分钟 | 执行者自己 |
| P2 | 10 分钟 | 执行者 + 一个能判目标的人 |
| P3 | 15 分钟 | 同上，必要时加上游依赖方 |
| P4 | 3 分钟 | 执行者自己 |

超过上限就先结束，把没议完的转成一条待决项，单独排时间。**把检查点开成会，是检查点制度最常见的死法。**

## 二、偏离信号清单

下面每一条都写成**可观察的现象**，不是感受。「我感觉有点乱」不算信号。

### A 类 · 前兆信号（出现即降低推进速度，安排 P4）

| # | 信号 | 观察方式 | 常见根因 |
|---|---|---|---|
| A1 | 单段耗时超出时间盒 50% | 时间盒到点还在做同一段 | 段划得太粗，或范围没圈定 |
| A2 | 旁支清单单段新增 ≥ 3 条 | 数清单行数 | 范围没圈定（E4 跳过） |
| A3 | 「意外条目」单段 ≥ 3 条 | 数 `!` 行 | 用的假设没验证过 |
| A4 | 连续两段没有可展示产物 | 回顾留痕 | 在做「看不见的活」，或方向偏了 |
| A5 | 一直在等别人 | 阻塞项停留 > 1 个时间盒 | 依赖没前置，或该拆出并行段 |

A 类信号本身不要求停下手上的活，但它要求**在这一段结束时做一次 P4**，并且在下一次 P2 上明确提出来。

### B 类 · 必须停下来重新对计划的信号

**B 类出现任意一条，立刻停下手上的动作，做 P3。** 不要在段中间把它绕过去。

| # | 信号 | 为什么必须停 |
|---|---|---|
| B1 | 发现计划里没提到、但必须做的一项工作，且它不是小事（> 1 个时间盒） | 计划的段划分已经不成立了，继续做是在给一个错误的计划加料 |
| B2 | 计划里的某条前提被证伪 | 「这个接口是幂等的」被证伪之后，后面每一段的前提都要重验 |
| B3 | 做出来的东西，和计划描述的目标**不是同一个东西** | 继续做只会把偏差放大；这是最贵的一类，越早停越省 |
| B4 | 同一处已经返工 3 次仍不过退出检查 | 第 3 次失败说明问题不在实现层，在目标或检查层 |
| B5 | 退出检查被连续放宽 2 次 | 放宽检查是「把标尺改短」，等于放弃验收 |
| B6 | 需要越过的边界超出授权：动了计划范围外的系统、要改别人负责的模块、要动生产数据 | 停下来确认授权，不要先做后说 |
| B7 | 发现计划的验收标准和真实需求对不上 | 验收标准错了，做完也是白做 |
| B8 | 关键依赖方给出与计划冲突的信息（接口要变、需求要改、排期推了） | 外部前提变了，计划必须重算 |

**B1 和 B3 是这套体系里最值钱的两条。** 它们对应两种最典型的失控：计划外扩容、以及「做得挺顺但做错了东西」。前者靠 E4 + 旁支清单能防住大半，后者只能靠检查点的对照动作发现。

### C 类 · 已经偏离的确认信号

出现下面这些，说明偏离已经发生了一段时间（通常 1–2 个时间盒起步），要做的不只是停下，而是**回到上一个可靠的里程碑重新对齐**。

| # | 信号 | 含义 |
|---|---|---|
| C1 | 留痕出现跳段：段号不连续，且没有记录为什么 | 计划已经实际被放弃了，只是没说出口 |
| C2 | 有 3 段以上的退出检查记录是「先跳过，后面补」 | 检查已失效，进度数字不可信 |
| C3 | 计划的「已完成比例」和「可用产物」严重不符 | 完成度是自我感觉，不是事实 |
| C4 | 需要向别人解释「为什么不按原计划做」才能说清进度 | 计划已经成了负担，该重写而不是继续解释 |
| C5 | 同一段的时间被重复延后 ≥ 2 次 | 这段要么被高估了能力，要么本来就不该做 |

C 类的处理是 P2 级别的：**回退到最后一个所有退出检查都通过的里程碑**，从那里重新排段。不要在原计划上打补丁——补丁摞补丁的计划，读的人（包括未来的你）已经无法判断哪条还有效。

## 三、停下来的处理流程

P3 是一个有固定步骤的动作，不靠现场发挥。全程 ≤ 15 分钟。

### 第 1 步 · 冻结（1 分钟）

**停手。不要「先把手头这个改完」。** 手头这个改完，往往就把偏离固化进产物里了。

记录：当前段号、当前动作、停手时的状态（是否可运行）、最后一次提交。

### 第 2 步 · 重述目标（2 分钟）

用自己的话，不看计划原文，说出这次要达成的最终结果。写完再回去和计划原文对。

两者不一致 → 那基本就是 B3，问题在计划的理解，不在执行。

### 第 3 步 · 定位被推翻的前提（5 分钟）

逐条列出「我是基于什么假设计划可行的」，然后标记每一条的当前状态：

| 假设 | 状态 | 证据 |
|---|---|---|
| 接口是幂等的 | 已证伪 | 本轮遇 2 次重复写入 |
| 有 12 个调用方 | 成立 | S1 清单 |
| 下周能拿到 schema | 未知 | 对方未回复 |

**被证伪的假设，就是偏离的坐标。** 处理方案总是从这些行里长出来的。

### 第 4 步 · 选分流（5 分钟）

见下一节。四选一，必须明确选一个，并写出理由。

### 第 5 步 · 落痕并重启（2 分钟）

把这次 P3 的结论写进留痕（格式见 `references/evidence-and-examples.md`），然后**从新的一段重新过进入条件门禁**，不要从停手的地方直接续上。

最后一步的意义：它强制你确认「停手处的状态」和「新计划的要求」是否对得上。不对上，就说明还有东西没处理完。

## 四、分流决策：继续 / 补段 / 回退 / 改计划

### 决策树

```text
偏离信号出现
│
├─ 目标没变、范围没变，只是实现遇到坎？
│   └─ 是 → 【继续】按原计划走，本段内解决，加一条意外条目
│            条件：修复成本 < 1 个时间盒，且不引入新依赖
│
├─ 目标没变，但发现了计划里漏掉的工作？
│   ├─ 漏掉的工作 < 1 个时间盒 → 【补段】就地插入 S<n>.1，不重排后续段号
│   └─ 漏掉的工作 ≥ 1 个时间盒 → 【改计划】重排段，重估时间，做 P2
│
├─ 目标没变，但当前路径已被证明走不通？
│   ├─ 有可用的替代路径，且已知成本 → 【回退】退到最近一个绿色里程碑，换路径重排
│   └─ 替代路径未知 → 【改计划】先插入一个「调研段」，限时 1 个时间盒，
│                        产出「可行路径清单」，再决定
│
└─ 目标本身变了，或验收标准对不上？
    └─ 【改计划】停掉后续所有段，重写计划。
       不要试图复用旧段号——旧段号承载的是旧目标的证据，
       复用会让留痕无法核验。
```

### 四种分流的判据表

| 分流 | 适用条件 | 代价 | 留痕里要写什么 |
|---|---|---|---|
| 继续 | 目标、范围、验收标准都没变 | 0 | 意外条目 + 为什么判定不影响计划 |
| 补段 | 漏项局部，不影响后续段的前提 | 小（段号加小数位） | 新段的目标、进入条件、退出检查 |
| 回退 | 当前路径失效，有已知替代；且回退点可靠 | 中（丢弃已完成的工作） | 回退到哪个段/提交、丢弃了什么、为什么必须丢 |
| 改计划 | 目标变、验收变、或前提大面积被推翻 | 大（重排全部） | 旧计划哪里失效、新计划的段划分、变更原因 |

### 回退的纪律

回退最容易被做错：人们倾向于「保留已完成的工作，只补一部分」。

规则：**回退就是回到一个所有退出检查都通过的状态，中间的半成品一律丢弃或隔离到独立分支。**

理由很实际：半成品之所以是半成品，是因为它的前提已经不成立了。把它留在主线里，后面每一段都要背着它走，而且它会污染退出检查（你分不清失败是新的改动导致的，还是旧的半成品导致的）。

丢弃之前，把它记在留痕里（改了什么、为什么丢、有没有可复用的部分）。**记录本身就是保留价值的方式，不必保留代码。**

### 什么情况下不要回退

- 回退点之后的工作已经产生了**对外承诺的产物**（已发布的接口、已交付给别人的数据）。此时回退的代价包含「撤回承诺」，要走改计划路线，并明确对外沟通。
- 当前问题只在**局部**，且局部隔离成本低于回退成本。那就补段修局部，不要为了「整齐」而回退。

## 五、改计划怎么写才不算白改

改计划不是重写一遍愿望清单。一次合格的改计划，产出必须包含下面五样，缺一样就还是会在下一轮偏：

1. **失效说明**：旧计划的哪一条前提/验收标准不成立，证据是什么。一句话一条。
2. **保留清单**：旧计划里哪些部分继续有效，段号保持不变（这是留痕能延续的关键）。
3. **新段划分**：按 `references/execution-protocol.md` 的粒度规则重排，每段带进入条件、退出检查。
4. **重估时间**：明确给出新的总时长，并写出和旧估值的差额来自哪里。
5. **新回退点**：改完之后，最近一个可靠回退点是哪个段。

常见错误：只写第 3 条。结果是新计划看起来很清楚，但它和旧的留痕对不上，第三方核验时会发现断链。

### 改计划的频率上限

**同一个目标，改计划超过 3 次，问题通常不在计划，在目标本身。**

第 3 次改计划时，强制回答一个问题：这个目标现在还是我真正要的东西吗？如果答不清，正确的动作不是改第 4 次计划，而是**回到目标层重做决策**。这一条能挡掉大量「计划改了无数次、什么都没交付」的情形。

## 六、检查点排布模板

半天任务的检查点排布（可直接套用）：

```text
09:00  P2 开局：确认目标一句话、验收标准、段划分、时间盒
09:00–10:00  S1 → P1
10:00–11:00  S2 → P1
11:00  P4 时间盒检查：进度 vs 时间盒，偏了就砍范围
11:00–12:00  S3 → P1
13:30  P2 中点：P2 级核对，看 3 段拼起来是否还指向目标
13:30–15:00  S4 → P1
15:00  P4
15:00–16:30  S5 → P1
16:30  P2 收尾：整体对照验收标准，产出留痕汇总

全程：任一 B 类信号出现 → 立即插入 P3
```

多天任务把 P4 换成「每半天一次」，P2 换成「每天一次」，其余不变。

## 七、偏离处理速查

```text
信号分级：
  A 类（前兆）→ 段末 P4，下次 P2 提出
  B 类（必须停）→ 立刻 P3，不绕
  C 类（已偏离）→ 回退到最近的绿色里程碑，重排

P3 五步：
  冻结 → 重述目标 → 定位被推翻的前提 → 选分流 → 落痕并重过进入条件

分流四选一：
  继续（目标范围验收都没变）
  补段（漏项 < 1 个时间盒，不影响后续前提）
  回退（路径失效 + 有替代 + 回退点可靠；半成品一律丢弃并记录）
  改计划（目标/验收/前提大面积变；产出失效说明+保留清单+新段+重估+新回退点）

红线：
  退出检查不放宽（放宽 2 次即 P3）
  同一目标改计划不超过 3 次，超过就回到目标层
```

配套阅读：`references/evidence-and-examples.md`（把上面每个动作写成可被别人核验的记录）。
