# 三剪客 · 计划执行与检查点

把写好的计划一段段执行下去并在关键处停下核对，解决计划完整却跑偏

计划写得很完整，做起来却跑偏——这件事几乎不用解释，因为大多数人都经历过。真正值得问的是：**它为什么必然发生？**

因为计划活在「行」这一层，执行活在「分钟」这一层。中间那一层没人负责。计划说「补测试」，可没人说过补到哪几个用例、什么算补完；计划说「先灰度」，可没人说过灰度到什么指标算过。这一层的空缺，每个执行者只能自己填——你填一个理解，他填另一个，填完之后谁都没意识到大家在做不同的东西。

这套 Skill 要补的就是这一层。它给一份**执行协议**：把计划里每一行拆成段，每段有进入条件、执行动作、退出检查；给一份**偏离信号清单**：什么样的现象出现时必须停下手，重新核对计划；给一套**留痕格式**：让进度变成一个第三方能自己核验的东西，而不是一句「差不多了」。

它不教你怎么写计划——假设你已经有一份计划了。它只管一件事：**让计划在执行中不走形，走形了能被及时看见。**

**读完你会拿到**：3 份参考文件（执行协议 / 检查点与偏离处理 / 留痕模板与实战示例）、1 套段的五条固定记录格式、8 条 B 类强制停机信号、1 棵分流决策树（继续 / 补段 / 回退 / 改计划），以及 3 个走完整流程的真实实例。

## 权限与用途说明

| 能力 | 是否申请 | 用途 |
|---|---|---|
| 网络访问 | 否 | 本 Skill 全程离线。协议、清单元数据、模板全在本地 Markdown 文件里，不抓网页、不调用任何远程接口 |
| 读取文件 | 是（工作区内） | 只读你已有的计划文档、执行目录、`progress/` 留痕目录和相关产物文件，用来比对「计划预期」与「实际产出」的差异 |
| 写入文件 | 是（工作区内，需你确认） | 在 `progress/` 下生成留痕目录（`00-plan.md` / `01-log.md` / `02-checkpoints.md` / `03-open-items.md` / `evidence/`），按段追加记录。**只追加不篡改历史行**；要更正就另起一行并注明更正内容 |
| 凭证 | 否 | 不读取、不写入、不转发任何密钥、Token、Cookie 或账号密码。留痕模板与示例一律用占位符，不落真实凭证 |
| 子进程 / 后台常驻 | 否 | 不常驻任何进程，不装依赖，不注册定时任务。仅在跑退出检查（如测试、grep、构建）时执行一次性命令，命令由你指定 |

**关于第三方服务**：本 Skill 不接入任何外部服务，不内嵌任何密钥，也不要求你提供凭证。参考文件里出现的 `grep`、`pytest`、`git`、校验脚本都是你环境里已有的东西，用不用、用哪个由你决定。

**关于你的数据**：留痕是长期保留的东西，而且是为了给别人看而写的。往 `01-log.md` 和 `evidence/` 里贴日志、命令输出、报错堆栈、接口样例之前，先过一遍脱敏——真实密钥、内部域名、客户名、个人手机号一律去掉或替换成占位符。**证据文件一旦被手工编辑，就不再是证据**，所以脱敏要在采集时做，不要事后回头改。

## 触发场景

- 「计划我列得挺细的，做着做着就不知道偏到哪去了。」
- 「这个任务做到一半，发现还有一堆计划里没写的事，我现在该继续做还是重排？」
- 「我不知道自己现在是该硬着头皮往下做，还是退回去重来。」
- 「老板问我进度，我说『快好了』，他明显不信，可我也说不清到底到哪了。」
- 「长任务做到一半被叫去开会，回来完全接不上，前面半小时全废了。」
- 「我一天下来感觉很忙，但说不出今天到底完成了什么。」
- 「两个人（或两个 Agent 会话）接力做同一件事，交接完对方还是不知道从哪接。」

## 快速开始

最小可用路径 **20 分钟**，产出是一个 `progress/` 目录和第一段的完整记录，不是一篇长文。

**第 1 步 · 建留痕目录（2 分钟）**

```bash
mkdir -p progress/evidence
touch progress/01-log.md progress/02-checkpoints.md progress/03-open-items.md
# 把现有计划粘进 00-plan.md，这一份从此冻结，改计划时追加变更记录而不是直接改
```

**第 2 步 · 把手上的计划拆成段（8 分钟）**

拿计划里的一行，逐条过四问。**四条全过才算一段**：

| 问 | 过不了怎么办 |
|---|---|
| 单一意图？一句话说完，不带「并且」 | 拆成两段 |
| 有可观察产物？结束时能拿出一个别人看得见的东西 | 补一个明确的产出物 |
| 有退出检查？有一条命令或一次计数能判定成没成 | 换成能量化的判定 |
| 失败可回退？知道退回哪个状态 | 补回退点；补不出说明这段太大 |

粒度按**退出检查的时间间隔**定：半天任务 30–60 分钟一段（5–8 段最舒服），≤1 小时的任务 10–20 分钟一段。段号写成 `S1 S2 S3`，**一旦分配就不再复用**，中途插入用 `S3.1`。

**第 3 步 · 动工前过进入条件门禁（每段 1 分钟）**

```text
E1 上一段退出检查过了吗（有证据）    E2 一句话能说清目标吗
E3 资源/权限/依赖齐吗                E4 改动范围圈定了吗（哪几个文件/表/接口）
E5 回退点在哪                        E6 时间盒设了吗
→ 任意一条不过：补齐，或拆段，或标阻塞先做别的段
```

E4 最常被跳过，也最贵——跳过它，动手之后才发现「还有 6 个地方也调了这个接口」，这段就失控了。

**第 4 步 · 执行，只做这一段的事（核心纪律）**

三条，全都关于「忍住」：

- **旁支进清单，不现场动手。** 顺手修是偏离的第一号来源：单次成本小，但它让退出检查失去意义。
- **先跑通，再做好。** 反过来做会得到「处处精致但跑不起来」的产物。
- **意外先记录，不改计划。** 撞上和计划不符的现实，记成 `!` 意外条目，在本段内找绕法。改计划是段末检查点的事——在段中间改计划，等于把偏离当成常态。

**第 5 步 · 跑退出检查并留痕（每段 3 分钟）**

产物一出来就立刻验，**不攒到段末或一天结束**。命令型优先：`pytest -q`、`tsc --noEmit`、`grep -c`、`git diff --stat`。不通过就不进下一段，哪怕只差一点点。

留痕五条固定字段，缺一条这段就不可核验：

```text
### S3 · 迁移第一批调用方
- 区间：14:05 → 14:52（时间盒 60 分钟）
- 进入条件：E1 ✅（证据 evidence/S2-tests.txt）· E4 范围=清单第 1–3 项 ✅
- 动作：改 src/a.ts、src/b.ts、src/c.ts，改用 loadConfig()
- 产物：commit 4f2a1c9；diff 见 evidence/S3-diff.txt
- 退出检查：grep 旧路径 → 3 处清零（evidence/S3-grep.txt）✅
- 意外：无
```

失败也要留，而且要更详细——写「期望 / 实际 / 证据」三行。**没有「期望」的失败记录无法核验**，别人不知道你拿什么标准判定的。

**第 6 步 · 段末分诊，然后接下一段**

关掉旁支清单（本轮做 / 排后续段 / 记待办 / 丢弃），写完交接五件事（落盘状态、清清单、补留痕、预告下段、确认回退点），然后**从进入条件重新过一遍门禁**——不要因为「刚才是连续做的」就跳过。

**遇到任何一条 B 类偏离信号，立刻停手做 P3。** 别绕。B 类信号和 P3 五步流程见 `references/checkpoints-and-drift.md`。

## 能力边界

**覆盖**：

- 把一份已写好的计划拆成可执行的段，并给出粒度判据（半天任务 5–8 段，按退出检查间隔定）
- 提供每段的进入条件六条门禁（E1–E6）、执行三条纪律（A1–A3）、四类退出检查
- 提供四类检查点（段 / 里程碑 / 风险 / 时间盒）的触发时机与时长上限，避免把检查点开成汇报会
- 提供 8 条 B 类强制停机信号 + 5 条 A 类前兆信号 + 5 条 C 类已偏离信号，全部写成可观察的现象
- 提供 P3 五步流程（冻结 → 重述目标 → 定位被推翻的前提 → 选分流 → 落痕重启）与分流决策树（继续 / 补段 / 回退 / 改计划）
- 提供回退的纪律：回到所有退出检查都通过的状态，半成品丢弃并记录
- 提供留痕目录结构和段记录五字段格式，使进度可被第三方独立核验
- 提供中断处理流程，把恢复成本从 20–40 分钟压到 3–5 分钟

**不覆盖**：

- **不替你写计划。** 它假设你已经有一份计划了。计划本身对不对、目标该不该设，不在范围内——一个错误的目标，执行得再规范也只是规范地做错事。
- **不做任务分解的方法论。** 怎么把一个模糊需求拆成工作项，是另一件事。这里只处理「已经有了工作项，怎么把它执行完」。
- **不做时间估算。** 协议里的时间盒来自你的估算，它只负责在超时的时候把信号暴露出来。估不准是常态，本 Skill 不改这个事实。
- **不做自动化跟踪。** 留痕是 Markdown 文件，靠纪律维护，不接看板、不接 Issue 系统、不生成图表。也没有任何脚本强制你遵守——**这是提示词层的约定，理论上可以不遵守**。
- **不替代验收与测试。** 退出检查用的是你已有的检查手段。本 Skill 能发现「检查被放宽了」，不能替你写测试。
- **不做人员绩效判断。** 留痕是给任务核验用的，不是拿来评人的工具。拿来评人会让留痕迅速退化成自我美化。
- **不处理多任务并行调度。** 协议描述的是单个任务内部的推进。多个任务怎么抢时间、怎么排优先级，需要另行决定。

## 依赖条件

- **必需**：一份已经写好的计划（哪怕只有几行）。没有计划的话，先有目标再去拆段。
- **必需**：能读写 Markdown 文件，且有地方存放 `progress/` 目录（本地目录或仓库都行）。纯文本即可，不需要任何额外工具链。
- **必需**：至少一种可执行的检查手段——测试命令、类型检查、grep、构建、或者一次人工对照。**一个检查手段都没有的任务，退出检查会退化成自我确认**，这套协议的效果会大幅下降。
- **推荐**：git 或等价的版本控制。回退点的可靠性直接依赖它；没有版本控制时，回退点只能靠手工备份，可靠性打折。
- **推荐**：一个能帮你跑退出检查的执行环境（终端或 Agent 运行时）。
- **不需要**：网络、API Key、数据库、Docker、任何付费服务、任何项目管理软件。

## 已知限制

1. **留痕靠纪律，不靠强制。** 没有任何机制阻止你跳过记录。省掉留痕的那一刻省下 3 分钟，代价是任务后半段无法核验——这个交换通常不划算，但没人会当场拦住你。
2. **检查点的收益滞后。** 段检查点、时间盒检查在做的当下感觉是纯开销。收益要到一个任务偏了 3 小时才显现。这是这套协议最难推行的地方，只能靠前几次真实收益建立信任。
3. **粒度表是经验值。** 「半天任务 5–8 段」来自常见工程任务的统计感觉，不是物理定律。探索性任务、研究型任务天然难以分段，此时应把「调研」本身作为一段，并给它一个时间盒，而不是硬把调研结果拆出来。
4. **B 类信号的判定有主观成分。** 「这不是小事（> 1 个时间盒）」这个阈值需要判断。阈值定低了会频繁停下来，定高了会错过偏离。建议第一次用的时候阈值定低一点——多停几次的成本，远低于一次 4 小时的跑偏。
5. **信号清单覆盖的是常见模式，不是全集。** 它来自对「计划落空」这一现象的归纳，会漏掉特定领域的偏离形态。用的时候把它当起点：你的领域里反复出现的偏离，应该补进你自己的清单。
6. **流水账 ≠ 留痕。** 记了五条固定字段不等于留痕有用。判断标准是「别人能不能独立核验」——如果 `evidence/` 里全是「已确认」，字段再全也没有核验价值。
7. **改计划三次上限只是提示。** 它不会阻止第 4 次。真正的决定权在你——但第 4 次改计划之前，请先回答「这个目标还是我要的东西吗」。

## 自检清单

**开一段之前**

- [ ] 这一段能一句话说完，且不含「并且」「顺便」
- [ ] 结束时会产生一个别人看得见的东西（文件 / 提交 / 命令输出 / 数据状态）
- [ ] 有一条命令或一次计数能判定它成没成
- [ ] 知道失败了退回哪个状态
- [ ] 改动范围圈定了：具体哪几个文件 / 表 / 接口
- [ ] 上一段的退出检查通过了，且证据在 `evidence/` 里
- [ ] 时间盒设了

**执行之中**

- [ ] 只做这一段的事；旁支进了清单，没有现场动手
- [ ] 意外记成了 `!` 条目，没有在段的中间改计划
- [ ] 中途被打断时，落了中断点并提交了一次

**收一段时**

- [ ] 退出检查跑了，而且是命令型或计数型，不是「确认无误」
- [ ] 结果在产物出来之后立刻验的，没有攒
- [ ] 留痕五字段齐（区间 / 进入条件 / 动作 / 产物 / 退出检查）
- [ ] 失败的记录也留了，含「期望 / 实际 / 证据」三行
- [ ] 旁支清单关掉了，未决和阻塞进了 `03-open-items.md`
- [ ] 下一段的段号、目标、还差的进入条件写清了
- [ ] 回退点确认了

**出现偏离时**

- [ ] 我对照过 B 类信号清单，确认是真的需要停（不是躲难点）
- [ ] 停手了，没有「先把手头这个改完」
- [ ] 重述了目标，并和 `00-plan.md` 原文对过
- [ ] 列出了被推翻的前提，每条带证据
- [ ] 明确选了继续 / 补段 / 回退 / 改计划中的一个，并写了理由
- [ ] 回退的话，半成品丢弃了并记录在留痕里
- [ ] 改计划的话，五样产出齐（失效说明 / 保留清单 / 新段 / 重估 / 新回退点）

**能不能给别人核验**

- [ ] 把摘要单独发给一个不了解任务的人，他能说出「到哪了、卡在哪、什么时候有结果」
- [ ] `evidence/` 里是原始输出，没有被手工编辑过
- [ ] 留痕里没有真实密钥、内部域名、客户名、个人手机号
- [ ] 进度摘要写了时间差额的来源（为什么慢了）
