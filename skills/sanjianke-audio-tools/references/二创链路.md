# 二次创作链路：从一条素材到 60fps

这份文档讲「拿到一条素材之后怎么走」，比命令表多一点判断：哪一步该花钱、哪一步
该在本机跑、每一步的产物长什么样。

---

## 一、五个阶段与产物

| 阶段 | 输入 | 动作 | 产物 | 花费 |
|---|---|---|---|---|
| 1 素材准备 | 本地 mp3 / mp4 | `upload --file` | 平台托管地址（约 24 小时） | 0 点 |
| 2 换 ID | 平台地址 | `audio-id --audio-url` | `audio_id` | 39 点 |
| 3 分离 | `audio_id` | `split --audio-id` | 人声轨 / 伴奏轨 | 42 点 |
| 4 改词 | 两段歌词 | `mashup --a-file --b-file` | 新歌词（带分段标记） | 36 点 |
| 5 补帧 | 平台视频地址 | `interp --video-url --seconds` | 60fps 成片 | 25 点/秒 |

第 2、3 步是一条链，`chain` 能一次跑完；第 4、5 步可以单独跑，也能用
`chain --with-mashup --with-interp` 挂上去。

## 二、三种常见活儿，怎么最省

| 活儿 | 路线 | 点数 | 说明 |
|---|---|---|---|
| 只想拿伴奏做个 remix | 1 → 2 → 3，取伴奏轨 | 81 | 0.81 元；比重新编曲便宜一个量级 |
| 拆完换一版词，重新唱 | 1 → 2 → 3 → 4 → 再进 `create`（`type=cover`） | 117 起 | `create` 的钱另算，看实测区间 |
| 30 秒素材补 60fps | 1 → 5 | 750 | 7.50 元；本机 ffmpeg 是 0 元但要等 |
| 整条链路（30 秒片） | 1 → 2 → 3 → 4 → 5 | 867 | 8.67 元一条，含改词 |

判断口径很简单：

- **要「重新唱」就必须有分离后的伴奏**，这条钱省不掉；
- **只要「画面顺」可以先试本机补帧**，`interp` 25 点/秒是按秒走的，30 秒就是 7.5 元；
- **只要歌词、不要新音频**，`mashup` 36 点比任何文本模型都便宜（2000 字的文本模型
  要几百点，`models --need relabel` 有对照）。

## 三、本机兜底命令（0 点）

### 3.1 补帧到 60fps

```bash
# 30fps -> 60fps，光流插值；慢，但一分钱不花
ffmpeg -i in.mp4 \
  -vf "minterpolate=fps=60:mi_mode=mci:mc_mode=aobmc:vsbmc=1" \
  -c:v libx264 -crf 19 -preset slow -pix_fmt yuv420p -movflags +faststart \
  -c:a copy out_60fps.mp4
```

- `mi_mode=mci` 是运动补偿插值，画质最好也最慢；`blend` 快一档但会糊
- 2 分钟以内的素材在普通笔记本上大概 3 到 8 分钟
- 原音轨用 `-c:a copy` 直接搬，不要重编码

只补一段（比如只补最后 5 秒），先切再补再拼：

```bash
ffmpeg -i in.mp4 -ss 0  -t 25 -c copy head.mp4
ffmpeg -i in.mp4 -ss 25 -c:v libx264 -crf 19 -c:a aac tail_60.mp4   # 对 tail_60.mp4 跑上面那条
ffmpeg -f concat -safe 0 -i list.txt -c copy out.mp4
```

### 3.2 人声与伴奏的配比

拿到两条轨之后，混音比例比想象中重要。一个能直接用的起点：

```bash
# 人声 0dB、伴奏 -12dB，人声侧链压缩伴奏（人声一响伴奏让路）
ffmpeg -i vocal.wav -i inst.wav -filter_complex "
[0:a]volume=1.0[v];
[1:a]volume=0.25[i];
[i][v]sidechaincompress=threshold=0.05:ratio=6:attack=5:release=200[ic];
[v][ic]amix=inputs=2:duration=longest:dropout_transition=0,
  alimiter=limit=0.95[a]" -map "[a]" -c:a aac -b:a 192k mix.m4a
```

- 短视频里人声通常再提 2 到 3 dB，伴奏压到 -14dB 左右
- `alimiter` 必须留在最后，侧链压缩容易过载

### 3.3 交付参数（抖音 / 视频号 / 小红书都吃）

```bash
ffmpeg -i mix.mp4 -r 60 \
  -c:v libx264 -crf 19 -preset slow -profile:v high -level 4.1 \
  -pix_fmt yuv420p -g 120 -movflags +faststart \
  -c:a aac -b:a 192k -ar 48000 out_final.mp4
```

- `-r 60` 写在编码前，关键帧 `-g 120`（2 秒一个关键帧，拖动不卡）
- 竖屏记得先 `-vf scale=1080:1920:force_original_aspect_ratio=decrease,pad=1080:1920:(ow-iw)/2:(oh-ih)/2`

## 四、改词这一步怎么写才不白花钱

`mashup_lyrics` 吃两段**已经很整齐**的歌词，输出会带 `[singer A]` / `[transition]` /
`[singer B]` 分段。想让它好用，输入按这个格式整理：

```
# a.txt
[singer A]
霓虹在窗上流成一条河
我把没说的话都折进纸鹤

# b.txt
[singer B]
鼓点踩过凌晨三点的街
你把耳机递给我说别停
```

- 一段控制在 4 到 8 句，太长了输出会稀释
- 两段的「人称」尽量一致（都用「我 / 你」），混搭出来才像一首歌
- 输出拿到之后先读一遍韵脚，再决定要不要进 `create`（`type=cover`）重唱

## 五、检查清单（交付前逐条过）

- [ ] 人声没有齿音爆点（`alimiter` 压住了）
- [ ] 伴奏没盖住人声（侧链压缩开了）
- [ ] 60fps 是**真插帧**，不是把 30fps 重复帧标成 60（`ffprobe` 看 `avg_frame_rate`）
- [ ] 时长与原片一致（补帧不会变时长，变短了说明切点错了）
- [ ] 音频采样率 48k、AAC 192k
- [ ] 竖屏安全区：上下各留 250px 给平台 UI
- [ ] 转存产物链接（`upload` 地址 24 小时过期，成片链接更短）

## 六、一次跑完的推荐顺序

```bash
# 先看钱
python3 scripts/run.py cost --seconds 30

# 干跑，确认每一步发什么
python3 scripts/run.py chain --file hook.mp3 --seconds 30 \
  --with-interp --video-url "https://oss.gpu.likeadmin.cn/openapi/xxx.mp4" --dry-run

# 真跑（第 1 步免费，第 2 步起扣点）
python3 scripts/run.py chain --file hook.mp3 --seconds 30 \
  --with-interp --video-url "https://oss.gpu.likeadmin.cn/openapi/xxx.mp4" --yes

# 事后对账
python3 scripts/run.py models --need split --pages 70
python3 scripts/run.py log --limit 20
```
