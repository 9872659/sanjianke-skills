# 三剪客 · 知识库与协作白板 Skill

AFFiNE：知识库与协作白板 的安装、常用命令与避坑要点

---

## 前置条件

- **只用客户端**：从项目官网下载页取对应平台客户端即可，也可以用官方在线实例先试；连自托管实例时准备好服务器地址。
- **要自托管**：装好 Docker 与 Docker Compose v2；官方建议至少 4 核 CPU、2 GB 内存（大量长文档时 4 GB）；服务端自身约需 1.5 GB 空闲磁盘，另按内容量预留数据库与附件空间。
- 对外提供服务需要域名、HTTPS 证书与反向代理。
- 需要自备：数据库口令、对象存储凭据（如果不用本地目录存储）；启用 AI 时还需自备模型服务商 Key。
- 必备组件是 Postgres 与 Redis，缺任一都跑不起来。

---

## 使用

1. 建部署目录并取官方 Compose 文件与 `config.json` 模板。
2. 编辑 `config/config.json`，把 `server.externalUrl` 设成用户实际访问的地址。
3. `docker compose up -d`，确认迁移容器成功退出、其余容器运行中。
4. 浏览器打开该地址，按引导创建初始管理员账户。
5. 之后再做三件事：配域名与 HTTPS、把备份跑通并验证一次恢复、规划升级窗口。
6. 备份要同时覆盖 Postgres、附件存储目录与配置文件，三者缺一都不算完整备份。

变量含义、恢复命令与典型报错排查见 `SKILL.md`。

## 依赖

- Docker 与 Docker Compose v2（官方推荐的部署方式）。
- Postgres——唯一受支持的数据库；官方 Compose 使用带 `pgvector` 的镜像用于 AI 检索，自维护 Postgres 时需手动安装该扩展。
- Redis——缓存、后台任务与同步的基础组件。
- 对象存储——默认用本地目录，可替换为 S3 兼容服务。
- 可选：AI 功能的模型服务商 Key（BYOK 模式）、SMTP（邮件通知）、OAuth 2.0 应用凭据（第三方登录）、监控组件。

## 安全

- 不内嵌任何密钥
- `DB_PASSWORD` 必须在 Postgres 首次初始化**之前**设定为强口令；已初始化的库改配置文件不会改变实际密码。
- `./data`、`./config` 与备份归档都包含全部内容数据，不要提交进版本库，也不要暴露在公网可访问的目录。
- 官方 Compose 默认不对外发布 Postgres 与 Redis 端口，数据库的信任认证只在内部网络有效；如果你把数据库端口暴露出去或把不受信任的容器接入该网络，必须先配置密码认证。
- 对外提供服务前配好 HTTPS 与反向代理；`server.externalUrl` 决定生成出去的链接指向哪里。
- 恢复操作前先停主服务，不要覆盖唯一一份数据库，也不要在验证恢复结果之前删掉旧数据目录。
- AI 功能走 BYOK，模型 Key 由部署方保管，调用产生的费用与数据流出由该服务商的政策决定。
