# 三剪客 · 小红书笔记工厂

> ## ⚠️ 先申请你自己的 API Key
>
> **本 Skill 不内嵌任何密钥，也不代付费用。** 请到
> **[算力集市 api.a7w.cn](https://api.a7w.cn/)** 注册并创建**你自己的** API Key
> （新用户有赠送点数，可以先免费试跑一两条）。
>
> 拿到后填进环境变量 `A7W_API_KEY`，或直接传给 `--key` 参数。
> **请勿使用他人提供的 Key** —— 用量与费用都记在 Key 所属账号上。

## 能做什么

给**一个产品或主题**（一篇母稿、一段产品说明、一份原始素材），批量产出**可以直接发的小红书笔记**：

```
母稿 ──► angles：N 个互不重复的切入角度（默认零成本）
      ──► notes ：每个角度独立一次调用 → 正文 + 话题标签 + 封面文案
      ──► covers：3:4 封面图（含大字标题），先报价再出图
      ──► check ：本地合规自检（零成本，不调模型）
```

它替代的不是"写文案"，是运营每天真正在做的那个动作：**把一份素材按不同角度铺成 N 条笔记**。

| 子命令 | 干什么 | 花钱吗 |
|---|---|---|
| `angles` | 出 N 个切入角度（人群 × 场景 × 情绪 × 落点） | **默认零成本**（本地 30 个角度库）；`--strategy llm` 一次调用 |
| `notes` | 按角度逐篇写正文 + 标签 + 封面文案 | **花钱**（一篇一次调用，实测 3 篇约 5554 token） |
| `covers` | 出封面图（3:4，大字标题） | **真花钱**，先报价，要 `--yes` 或 `--budget` |
| `check` | 对已有笔记跑全部本地闸门 | **零成本**，纯本地，跑两次结果一样 |
| `all` | 整条链路，**断点续跑** | 按阶段花钱，已完成的阶段直接跳过 |
| `cost` | 只算钱 | 零成本 |
| `models` | 现查 api.a7w.cn 在架模型 | 零成本 |

| 你最关心 | 答案 |
|---|---|
| 多少钱 | 文本按 token（网关不公布文本单价，**金额要你自己填**）；封面实测 **24 点/张 = 0.24 元**（1K） |
| 要多久 | 实测 3 篇文本约 40 秒；1 张封面 5~30 秒 |
| 要装什么 | **什么都不用装**，只用 Python 标准库 |
| N 篇会不会是同一篇换皮 | 有专门的闸门量它，实测 3 篇最大相似度 **0.183**（阈值 0.65）。见下面「跨篇换皮」 |
| 会瞎编吗 | 不提供 `--evidence` 就不许编数字，这条写死在提示词里 |
| 中断了怎么办 | **断点续跑**：已完成的阶段与图直接跳过，已提交未完成的任务用 `task_id` 续查，不重复扣费（**封面断点按「笔记 id + 比例 + 分辨率 + 封面文案」判定**：改了 `cover_text` / `cover_desc`、或换了 `--resolution` 再重跑，**只重出改过的那一条笔记的封面**并重新扣费，不会整批重扣；只改标点或空白不算改动，仍然跳过） |

### 三个子命令的边界是刻意的

- `angles` **默认不花钱**：30 个角度（新手踩坑 / 算账派 / 反常识 / 横向对比 / 清单体 /
  省时间 / 防割韭菜 / 懒人版 / 细节控 / 空间受限 / 带娃族 / 预算党 / 打工人 / 宅家派 /
  长期主义 / 差点放弃 / 单品深挖 / 应急方案 / 心态篇 / 工具流 / 自动化 / 一个人做 /
  零预算起步 / 下班后做 / 数据复盘 / 错误清单 / 时间点切入 / 第一周记录 / 同行复盘 / 答疑体），
  全放在 `scripts/run.py` 的 `ANGLES` 表里 —— **角度是数据，不是提示词散文**。
- `notes` **一个角度一次调用**。这是本包最重要的一条设计取舍，见下。
- `covers` **在提交任何任务之前报价**，且"没有 `--yes` 也没有 `--budget`"时只报价不动作。

### 跨篇换皮：本包最该有的一道闸门

批量出笔记的失败模式不是"某一篇写坏了"，而是：

> **N 篇其实是同一篇换了个开场。** 单看每一篇都像样，合起来等于只写了一篇。

人眼很难发现（尤其 N 篇不并排看），但字符二元组 Jaccard 一眼看穿。两道防线：

1. **一个角度一次调用**。如果让模型一次产出 N 篇，它会先写最好写的那篇，
   再把剩下的裁剪出来 —— 实测在多平台改写场景就是这么失败的。
   本包还把"同批其它角度的名字"写进提示词明确禁止重复（**只给角度名，不给其它篇正文** ——
   给了正文模型就会照着那篇改）。
2. **本地换皮闸门**。两两比较正文，两边都 ≥ 150 字才比，**≥ 0.65 判疑似换皮** → 标红 + 退出码 3。

**实测（本包真机跑，同一份 678 字母稿，独立跑两轮）**：

| 轮次 | 角度（n01 / n02 / n03） | 正文字数 | 段落数 | 开场形态 | 两两相似度 | 换皮判定 |
|---|---|---|---|---|---|---|
| 第 1 轮 | 新手踩坑 / 算账派 / 反常识 | 568 / 552 / 619 | 22 / 12 / 17 | 我以为最难的是剪辑 / 上个月对账 / 我信过一个说法 | 0.126 · 0.154 · **0.183** | 0 对 |
| 第 2 轮 | 同上 | 542 / 618 / 558 | 9 / 18 / 13 | 我以为三天能收工结果前三步全走歪了 / 我把花销按小时记了三个月 / 一开始我也信那句 | 0.109 · 0.148 · **0.169** | 0 对 |

两轮的**最大相似度只有 0.169~0.183，离阈值 0.65 有 3.5 倍以上余量** ——
N 篇确实是 N 篇，不是一篇的 N 张皮。同一份母稿两轮跑出来的正文互不相同，
也说明模型没有被某个固定句式锚住。

对照：把同一篇正文复制成两篇，实测相似度 **1.000**，闸门必然拦下（有坏数据用例）。

### 出图比例：只认真实像素

⚠️ **上游按 32 对齐给像素**，请求 3:4 **实测拿到 864x1184 = 0.7297（3:4 = 0.75），偏差 2.70%**。
这不是网关 bug，是扩散模型先定总像素、再把每边向下取整到 32 的常规做法。
所以"请求比例 == 产出比例"这个断言对一半的比例天然不成立。

本包的闸门**只读文件头里的宽高**（`scripts/imgprobe.py`，纯标准库 struct），
不采信接口自报的 `aspect_ratio`：

- 默认容差 **3%**：容差**内**不算"假"，但**一定打印真实像素与偏差**，不藏；
- 超容差 → 标红 + 退出码 3；
- `--snap`：本地按 3:4 精确裁到 **864x1152**，裁完**再读一次文件头复核**。
  实测：裁剪前 864x1184（偏差 2.70%）→ `pil` 裁剪框 `(0, 16, 864, 1152)` → 裁剪后 864x1152（偏差 **0.00%**）。

## 怎么用（命令行）

### 第 0 步：获取 API Key

到 **[api.a7w.cn](https://api.a7w.cn/)** 注册，创建一个 API Key（形如 `sk-...`）。

### 第 1 步：装依赖

**零依赖。** 不需要 `pip install` 任何东西，只要机器上有 Python 3.7+：

```bash
python3 --version
```

`scripts/a7w.py` 是零依赖客户端（只用 `urllib` / `json` / `mimetypes`），
**逐字节等于规范版**（SHA256 `EACD2E4F…B465`），任何包都不许为了业务改它；
本包的图片探针与裁剪都在自己的模块（`scripts/imgprobe.py` + `run.py`）里。

### 第 2 步：填 Key

```bash
# Linux / macOS
export A7W_API_KEY=sk-你的key

# Windows PowerShell
$env:A7W_API_KEY="sk-你的key"
```

也可以存进配置文件反复用（推荐）：

```bash
python3 scripts/a7w.py login --key sk-你的key
```

### 第 3 步：先出角度（零成本，可反复跑）

```bash
python3 scripts/run.py angles --file 母稿.md --count 5
```

不联网、不花钱。看一遍角度合不合你的主题：合就直接用，不合就
`--strategy llm` 让模型针对材料重出（生成失败会**自动回落**到本地库）。

### 第 4 步：出笔记（花钱，先看预估）

```bash
# 先算 token（不给单价就只报 token 数，不编金额）
python3 scripts/run.py cost --file 母稿.md --count 5 --cover-count 5

# 出笔记，落盘 notes.json（--outdir 必须在包外）
python3 scripts/run.py notes --file 母稿.md --count 5 \
    --outdir "$TEMP/xhs-notes" --json --out "$TEMP/xhs-notes/notes.json"
```

只有 3 篇、先试水也可以：

```bash
python3 scripts/run.py notes --text "产品/主题的一段说明" --count 3 --outdir "$TEMP/xhs-notes"
```

### 第 5 步：出封面（真花钱，先报价）

```bash
# 报价（不提交任何任务）
python3 scripts/run.py covers --notes "$TEMP/xhs-notes/notes.json" --outdir "$TEMP/xhs-notes"

# 确认后出 2 张，并裁到像素级精确的 864x1152
python3 scripts/run.py covers --notes "$TEMP/xhs-notes/notes.json" --count 2 \
    --outdir "$TEMP/xhs-notes" --yes --snap
```

### 第 6 步：本地合规自检（零成本）

```bash
python3 scripts/run.py check --file "$TEMP/xhs-notes/notes.json"
```

### 一句话跑完整条链路

```bash
python3 scripts/run.py all --file 母稿.md --count 5 \
    --outdir "$TEMP/xhs-notes" --yes --snap --budget 200 --json
```

**断点续跑**：重跑同一条命令，已完成的阶段直接跳过（输出会说"跳过（断点续跑）"），
已提交未完成的出图任务用 `task_id` 续查，**不重复扣费**。

> 这一条的条件是**产出与断点文件都还在、没加 `--force`、且封面文案与分辨率都没变**。本包的封面断点
> 按「笔记 id + 比例 + 分辨率 + 封面文案」判定，所以改了 `cover_text` / `cover_desc`、
> 或换了 `--resolution`（1K ↔ 2K ↔ 4K）再重跑会
> **自动重出那一条笔记的封面**（只重出改过的那条，不会整批重扣）—— 封面文案变了就必须
> 重新出图，否则你拿到的会是配着旧文案的旧图；分辨率变了也一样，否则你要 4K 拿到的却是 1K。
> 断点记录里存的文案或分辨率与本次不一致时，
> 脚本会打印一行提示并**强制重出**，不会静默复用旧图。只改标点或空白不算改动，
> 仍然跳过、不重新扣费。
>
> ⚠️ **跨版本升级的正常代价**：旧版本的断点文件（1.0.3 及更早）里没有封面文案这一维，
> 1.0.4 及更早也没有分辨率这一维，
> 所以升级后**第一次重跑会把已有的封面再出一次**（同样会重新扣费）。删断点文件也免不掉
> 这一次 —— 旧记录里的封面文案已无从核对，本包宁可重出，也不复用说不清来历的旧图。

### 直接用 curl 调（不依赖本包脚本）

写文案底层就是一个标准的 OpenAI 兼容调用：

```bash
curl -sS -X POST "https://api.a7w.cn/api/v1/chat/completions" \
  -H "Authorization: Bearer $A7W_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "deepseek-chat",
    "messages": [{"role": "user", "content": "把下面这份素材写成一篇小红书笔记，只输出 JSON：……"}],
    "temperature": 0.8,
    "max_tokens": 8192,
    "response_format": {"type": "json_object"}
  }'
```

> **成功响应不带 `code` 字段。** 实测调用成功时返回的就是标准 OpenAI 形态
> （`id` / `object` / `created` / `model` / `choices` / `usage` / `system_fingerprint`），
> `"code" in payload` 为 `False`。`code==1` 那套信封**只用于生成应用的响应**
> （出图那个端点是用的），所以别拿 `code` 判文本调用的成败。

出图是异步任务：

```bash
# 1) 提交
curl -sS -X POST "https://api.a7w.cn/api/v1/apps/nano_banana/submit" \
  -H "Authorization: Bearer $A7W_API_KEY" -H "Content-Type: application/json" \
  -d '{"prompt":"竖版 3:4 小红书封面，大字标题…","action":"generate",
       "model":"nano-banana","resolution":"1K","aspect_ratio":"3:4"}'
# 2) 轮询（把 <task_id> 换掉）
curl -sS "https://api.a7w.cn/api/v1/tasks/<task_id>" \
  -H "Authorization: Bearer $A7W_API_KEY"
```

> ⚠️ **`status` 在 `data` 顶层，不在 `data.result` 里。** 平台文档写的是
> `data.result.status`，**实测不对**。照文档写会永远读不到状态、一路轮询到超时。
> 实测完成态的结构：
> `{"code":1,"msg":"success","data":{"status":"completed","task_id":"…",
>  "usage":{"points_cost":24},"result":{"image_url":"…","success":true}}}`
> 另外 `result.data[0].image_url` 与 `result.results[0].image_url` 也可能有图，
> 本包做深度搜索把所有 `image_url` 收齐，不只取第一处。

## 参数说明

### 全局

| 参数 | 说明 |
|---|---|
| `--key` | 临时指定 Key；优先级最高。**别把它写进脚本或文档** |
| `--json` | 以 JSON 输出，**写在子命令前面或后面都可以**；JSON 模式下 stdout 只有一个完整 JSON，进度走 stderr |
| `--out <文件>` | 把结果写到文件 |

### 母稿输入（`angles` / `notes` / `all` / `cost` 共用）

| 参数 | 说明 |
|---|---|
| `--file <文件>` | 母稿 / 产品信息（`.md` / `.txt`）。自动剥掉 UTF-8 BOM |
| `--text "正文"` | 直接给素材；与 `--file` 同时给时以 `--text` 为准 |
| `--count <N>` | 篇数 / 角度数，默认 5 |
| `--brief "要求"` | 作者的要求（口述意图） |
| `--evidence "素材"` | 可以使用的真实素材。**没写就不许编数字** |

### `angles` —— 出角度

| 参数 | 说明 |
|---|---|
| `--strategy local` | 默认。本地 30 个角度库，**零成本、可复现** |
| `--strategy llm` | 针对材料出角度（一次调用）；失败或条数不够自动回落本地库 |

### `notes` —— 出笔记

| 参数 | 说明 |
|---|---|
| `--outdir <目录>` | 输出目录（`notes.json` 落在这里）。**必须在包外** |
| `--price-in` / `--price-out` | 文本单价（点/百万 token）。不给我就只报 token、**不编金额** |
| `--budget` | 预算上限（点）。超了就地中止，退出码 5；用 `--budget` 必须给单价 |
| `--model` | 默认 `deepseek-chat`（实测可用） |
| `--temperature` | 默认 0.8 |
| `--max-tokens` | 默认 8192 |
| `--dry-run` | 只打印将发送的提示词，**不调模型、不花钱** |
| `--no-json-mode` | 不要求上游返回 JSON 对象（个别模型不支持 `response_format` 时用） |

### `covers` —— 出封面

| 参数 | 说明 |
|---|---|
| `--notes <notes.json>` | **必填**。`notes` 生成的笔记文件 |
| `--count <N>` / `--only n01` | 只出前 N 张 / 只出指定 id |
| `--yes` | 确认这是一次真花钱的操作；**不给 `--yes` 也不给 `--budget` 就只报价** |
| `--budget <点>` | 预算上限。超了在**提交之前**就中止，退出码 5 |
| `--snap` | 出图后按 3:4 裁到 864x1152（裁完复核） |
| `--ratio-tolerance` | 比例容差，默认 0.03；地板 0.0025 |
| `--resolution` | 默认 1K（**只有 1K 有实测价 24 点/张**）；2K/4K 必须配 `--points-per-image`。**这一维进了封面断点 key**：换了档位重跑会重出该条封面（否则你要 4K 却拿到 1K 的图） |
| `--points-per-image` | 覆盖实测单价 |
| `--force` | 忽略断点重出（**会重复扣费**） |
| `--no-wait` | 只提交不等待（之后用 `task_id` 续查） |
| `--allow-prompt-hits` | 封面提示词命中闸门也照出（默认拦截，不花钱） |

### `check` —— 本地自检

| 参数 | 说明 |
|---|---|
| `--file <notes.json>` | **必填**。跑合规 / 占位符 / 照抄示例 / 笔记规格 / 跨篇换皮五类检查 |

**纯本地**：不调模型、不花钱，同一个文件跑两次结果完全一样。

### `cost` —— 只算钱

| 参数 | 说明 |
|---|---|
| `--cover-count <N>` | 要出几张封面（默认 0，只算文本） |
| `--price-in` / `--price-out` | 文本单价（点/百万 token） |
| `--budget` | 预算上限；给了就必须给文本单价，否则退出码 2 |

**为什么不给默认文本单价**：实测接口的 `GET /api/v1/pricing` 只有 6 条规则
（一条全局 `*` + `full_video` / `asr` / `flashvsr` / `action_transfer` /
`person_replacement` 等特例），**不含文本大模型**；`GET /api/v1/models` 的记录里
**没有任何价格字段**；`chat/completions` 的成功响应 `usage` 只有
`prompt_tokens` / `completion_tokens` / `total_tokens`（外加缓存命中统计），**没有点数**。
所以**拿不到可信的文本模型单价，本包拒绝凭空编一个** ——
token 数我们估（实测标定），金额必须由你给单价。出图的钱是实测价，可以直接算。

### 七道硬闸门

**硬闸门 = 命中即拦截 + 标红 + stderr 汇总 + 退出码非 0。不许只警告。**

| # | 闸门 | 判什么 | 退出码 |
|---|---|---|---|
| 1 | **合规** | 广告法违禁词 + **小红书特有红线**（站外导流、**医疗/功效宣称**、绝对化） | 3 |
| 2 | **占位符残留** | `{}`、`[待填]`、`XXX`、`（此处省略）`、`TODO`/`TBD` | 3 |
| 3 | **`prompt_echo`** | 去标点后相等 / 二元组 Jaccard ≥ **0.75** / 覆盖度 ≥ **0.60**（三条判据任一即命中） | 3 |
| 4 | **笔记规格** | 正文 **≤ 1000 字**、话题标签 **5~8 个**、**首行必须是钩子** | 3 |
| 5 | **跨篇换皮** | N 篇两两相似度 ≥ **0.65**（两边都 ≥ 150 字才比） | 3 |
| 6 | **出图比例真伪** | 读**真实像素**，不信自报；超容差 3% 即不合格 | 3 |
| 7 | **成本上限** | 出图前报价 + `--budget` 超限就地中止（用**真实扣费**累计） | 5 |

外加两条**参数级**拦截：`--outdir` 指到包内 → **退出码 2**（包内不许有任何图片，
且是在花钱之前就拦下）；给了 `--budget` 却没给文本单价 → 退出码 2（拒绝编价）。

**哪些只扣分不拦截**：标题长度（8~24 字）、标签数量偏少这类**风格问题**只扣分。
标准是「发出去会出事」—— 合规违禁会被罚，标题长两个字不会。

### 退出码（可直接用于 CI）

| 退出码 | 含义 |
|---|---|
| `0` | 全部干净 |
| `1` | 没预料到的异常（代码 bug）；`--json` 下给 `kind=internal` 信封 + stderr 打完整栈 |
| `2` | **参数/配置错误**（含 `--outdir` 指到包内、给了 `--budget` 却没给单价） |
| `3` | **有硬闸门命中**（合规/占位符/照抄示例/笔记规格/跨篇换皮/出图比例） |
| `4` | 调用失败（网络 / 鉴权 / 点数 / 模型名 / 出图任务失败） |
| `5` | **预算超限，已就地中止** |
| `130` | 用户中断 |

**`--json` 输出契约**（给流水线与 agent 消费，**只在 `--json` 下生效**）：

- 成功：结果对象里多一个 `"ok": true`；顶层是数组时包成 `{"ok": true, "data": [...]}`
- 失败：stdout 输出一个 JSON 信封，形如
  `{"ok": false, "exit": 3, "error": {"kind": "gate", "message": "…"}}`
  （`exit` 就是本次真实退出码），`kind` 取 `gate` / `usage` / `budget` / `call` /
  `interrupt` / `internal`
- **文字闸门命中属于"跑成功了但结果不合格"**：此时已经产出结果，`ok` 写在那个结果对象里，
  进程退出码仍是 3 —— 于是"两个位置都 `exit=0`（进程正常退出，没有异常）且 `json.loads` 过"
  这条不变量同时成立
- `internal` 是**没预料到的异常**（代码 bug）的兜底：stdout 给信封、
  **完整 traceback 原样打到 stderr**、退出码固定 1 —— 报 bug，不藏 bug
- 人读文案照旧走 stderr；**退出码语义一个都不变**；非 `--json` 模式输出与普通 CLI 一致
- `--json` 写在子命令**前面或后面都可以**

### 三个真实事故写进了代码

**1. `prompt_echo`：模型会照抄提示词里的示例，哪怕标着「这是错的写法」。**

本库标题工坊实测过两次，其中一次**一字不差就是提示词示例，而且拿了那一轮的最高分 89.0** ——
最高分变成"抄标准答案"而不是"真的最好"，排序就废了。

所以本包：**提示词里不出现任何一句可复制的完整中文句子**，举例只用描述性语言 +
登记在 `PROMPT_SAMPLES` 里的**跨主题**示例（主题刻意选「阳台种小番茄 / 入门吉他」，
与小红书笔记业务明显不搭）；万一有人把真实示例加回去，闸门会兜住。

判定分三层，**为什么要第三层**：长正文有几万字，示例只有二三十字，
整段算 Jaccard 的分母被撑大、永远接近 0 —— 模型把示例原样抄进某一段，这道闸门完全看不见。
所以整段比一次（只认 exact / jaccard）+ **逐句再比一次**（含覆盖度）。
但拆句只在 `。！？；` 和换行处切、**不在逗号处切**，模型把示例揉进自己那句话里时
比对单位被撑到 30~36 字，Jaccard 又被摊薄 —— 实测 `示例1 独立成句 Jaccard 1.000（抓住）`、
`揉进 36 字长句 Jaccard 0.576（漏）但覆盖度 1.000（抓住）`。
**逐句层只兜得住"示例自己独立成句"，覆盖度不是冗余而是互补。**

阈值标定：196 条正常产出与跨主题示例的最高相似度只有 **0.174**，
而"少两个字的同构照抄"是 **0.765** —— 0.75 离正常上限有 4 倍余量。
长度守卫是**相对**的：`max(6, len(示例)//2)`，短串不比。

**2. 一次调用写 N 篇 = 换皮。**（见上文「跨篇换皮」，两轮实测最大 0.183 / 0.169 vs 阈值 0.65。）

**3. 合规闸门自己也会误伤，而误伤会让闸门废掉。这一条踩了两次。**

- 第一次（继承自多平台改写）：真实原稿里「回头翻一条自己播放量最低的视频」
  被「最X」规则判成高风险并整篇拦截 —— **诊断是错的**，那是在描述自己的数据。
  加了一条很窄的豁免（计量类名词 + 「的/之」），**放过但登记，不静默**。
- **第二次（本包真机实测第一轮）**：3 篇笔记**全部**因为"命中『第一』类排他性表述"被拦，
  真实原文是「第一个坑就来了」「第一个月做了 4 部」「第一部 80 集的剧」——
  **三篇全红、理由全错**。同样加了窄豁免（「第」+ 数字 + 量词 = 叙事序数），
  并给那条正则补了 `(?<![国网史])`，免得「全国第一」多报一条理由不对的「第一」。
- 还有一处同源：「唯一入口」这类**否定式**用法（"不该当成唯一入口"）其实是在反对排他，
  所以只在「唯一 + 名词」时才判命中。

**结论写在这里，改闸门之前先读**：「宁可多报也别漏报」在有误伤时是错的 ——
一个正确写法的稿子被判违规，使用者就会开始无视闸门。豁免必须窄、但必须有；
豁免的每一处都要在报告里明确打印。

### 成本口径（实测标定）

| 方向 | 标定值 | 依据 |
|---|---|---|
| 文本**输入** | 1 原始字符 ≈ **0.621** token（1 token ≈ 1.61 字） | 实测 3 次调用 prompt_tokens 1299 / 1298 / 1292，极稳 |
| 文本**输出** | 1 原始字符 ≈ **1.11** token | 实测均值；平台间差异主要来自换行数 |
| 封面出图 | **24 点/张**（1K）= 0.24 元 | 实测任务返回 `usage.points_cost = 24`，两张共 48 点 |
| 货币 | 1 元 = 100 点 | 平台口径 |

**实测文本用量**（3 篇笔记，同一份 678 字母稿，两次独立跑）：
`prompt_tokens 3889 + completion_tokens 1665 = 5554 token`、`3895 + 1600 = 5495 token`，
3 次调用。响应里还带 `prompt_cache_hit_tokens: 1152`（每篇都命中同一段系统提示词缓存）——
这是网关侧的缓存统计，**不要拿它去算钱**，算钱只看 `prompt_tokens`。

## 排错

| 现象 / 报错 | 原因 | 怎么办 |
|---|---|---|
| `Missing or invalid relay API key`（HTTP 401） | Key 无效、过期或写错 | 重新到 https://api.a7w.cn/ 领取；确认没把 `Bearer` 重复写进环境变量 |
| 点数不足（HTTP 402） | 账号点数用完 | 到 https://api.a7w.cn/ 充值后重试 |
| 模型不存在（HTTP 404） | 模型名写错或已下架 | `python3 scripts/run.py models` 现查在架模型名 |
| 上游 `502` / `upstream timeout` | 网关到上游的瞬时抖动，**实测很常见** | 脚本已内置退避重试（最多 4 次）。连续失败就换模型 |
| `参数错误：输出目录 … 在 Skill 包内`（exit 2） | 包内不许有任何图片 | 换到包外，例如 `%TEMP%/xhs-note-factory` |
| `配置错误：给了 --budget 就必须给单价` | 预算没有单价就没意义 | 补 `--price-in` / `--price-out`（点/百万 token） |
| `!! 预估成本 … 已超过 --budget … 就地中止` | 预估闸门在花钱之前就拦下了 | 少出几篇 / 少出几张，或调低 `--max-tokens`，或提高预算 |
| `!! 已花 … 点，超过 --budget`（exit 5） | 真实扣费累计超了 | 已完成的产出仍在，从断点继续 |
| `这是一次真花钱的操作…确认后加 --yes`（exit 2） | 成本前置生效，**这是正常的**，不是错误 | 看过报价后加 `--yes` 或 `--budget` 重跑 |
| `!! 有 N 篇被硬闸门拦下`（exit 3） | 合规 / 占位符 / 照抄示例 / 笔记规格 / 跨篇换皮 | 看 stderr 的逐条原因；改素材或改 `--brief` 后重跑 |
| 合规命中「第一」但你看不出问题 | 可能是**叙事序数**之外的形态 | 已知过度报告的残留。要么改措辞，要么人工确认后放行；**不要改成只警告** |
| `!! 跨篇换皮`（exit 3） | 两篇正文太像 | 用 `check` 看是哪一对；减少 `--count`，或换 `--strategy llm` 让角度更分开 |
| 字数标红「超过上限」 | 模型写超了 1000 字 | 在 `--brief` 里说清"只讲一件事"；或分段拆成两篇。**别靠删段落凑数** |
| 首行「未识别出钩子」 | 首行不在本包认可的钩子形态里 | 看 `references/note-methodology.md` 的钩子表；在 `--brief` 里点名要哪种开场 |
| 封面提示词命中闸门被拦（exit 3） | 封面文案里有违禁词 | 改 `cover_text` / `cover_desc` 后重跑（**没花钱**）；确实要带词出图加 `--allow-prompt-hits` |
| `封面大字标题 N 字 > 上限 20 字`（exit 3） | `cover_text` 超过一行放得下的字数 | 把超出的部分移到正文或 `cover_desc` 里再重跑（**没花钱**）。**不接受 `--allow-prompt-hits` 放行** —— 放行等于回到静默截断，你会以为改了、其实图一模一样。上限与依据见 `references/cover-and-size.md` |
| 改了 `--resolution` 但图还是 1K 的 | 1.0.5 起分辨率已进断点 key，正常会重出 | 仍拿到旧图只可能是命中了 1.0.4 及更早写的旧断点（那时 key 不含分辨率）：重跑一次，新断点写入后即生效；要无条件重出加 `--force`（**会重新扣费**） |
| `真实像素 864x1184 … 偏差 2.70%` | 上游按 32 对齐，**不是错误** | 想要像素级精确加 `--snap`（裁到 864x1152）。容差内不会拦 |
| 出图卡在 `processing` 到超时 | 上游排队 | 本包有 `--poll-timeout`（默认 600 秒）与断点；重跑会用 `task_id` 续查，**不重新提交、不重复扣费** |
| 图下载失败 | 结果 URL 过期或网络问题 | 断点里存了 `image_url`，可以直接重跑续；也可以手动下载 |
| 封面文案改了，图还是旧的 | 断点记录里的封面文案与本次对不上 | **正常情况会重出**（见上面「断点续跑」）。仍拿到旧图只有两种可能：① 命中的是 1.0.3 及更早写的旧断点，重跑一次，新断点写入后即生效；② 你以为改了内容，其实只动了标点/空白 —— 那不算改动，旧图本来就是对的。要无条件重出加 `--force`，**那一次会重新扣费** |
| `模型返回的不是合法 JSON` | 模型在 JSON 前后多吐了字符 | 脚本已用 `json.JSONDecoder().raw_decode()` 扫第一个完整对象。仍失败就加 `--no-json-mode` 并换模型 |
| `模型没返回 choices` / 产出为空 | `max_tokens` 截断 | 加大 `--max-tokens`。注意 `models` 列表里的推理模型会先花 token 出思维链 |
| `HTTP 200 但 model:null`、内容为空 | 实测把 `deepseek-flash`（`deepseek-chat` 的路由**目标名**）当**请求名**用就是这个结果——**静默失败**，状态码骗人 | 请求名用 `deepseek-chat`；要换模型就用 `models` 列表里的名字 |
| 母稿第一个字是乱码 / 字数偏 1 | UTF-8 BOM（Windows `Out-File`、记事本另存为） | 脚本已自动剥掉 BOM；若仍异常，另存为「UTF-8 无 BOM」 |
| Windows 下中文乱码 | 控制台代码页不是 UTF-8 | `chcp 65001`，或加 `PYTHONIOENCODING=utf-8` |
| `argparse: conflicting option string` | 改代码时重复定义了同参数 | 见「文件结构」一节的约定：同类开关只有一个定义处 |

**收集排错信息时请附上**：完整命令、`--dry-run` 的输出、原始报错文本、退出码。
