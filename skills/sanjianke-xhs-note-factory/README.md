# 三剪客 · 小红书笔记工厂

给**一个产品或主题**，批量产出**可以直接发的小红书笔记**：
母稿 → N 个互不重复的切入角度 → 每角度独立一次调用写正文 + 话题标签 → 每篇配 3:4 大字标题封面 → 本地合规自检。

## 30 秒上手

```bash
# 0) 到 https://api.a7w.cn/ 注册领 Key
export A7W_API_KEY=sk-你的key          # Windows: $env:A7W_API_KEY="sk-你的key"

# 1) 出角度（零成本，可反复跑）
python3 scripts/run.py angles --file 母稿.md --count 5

# 2) 出笔记（花钱，一篇一次调用）
python3 scripts/run.py notes --file 母稿.md --count 5 --outdir "$TEMP/xhs-notes"

# 3) 合规自检（零成本）
python3 scripts/run.py check --file "$TEMP/xhs-notes/notes.json"

# 4) 出封面（真花钱，先报价；确认后加 --yes）
python3 scripts/run.py covers --notes "$TEMP/xhs-notes/notes.json" --outdir "$TEMP/xhs-notes"
python3 scripts/run.py covers --notes "$TEMP/xhs-notes/notes.json" --count 2 \
    --outdir "$TEMP/xhs-notes" --yes --snap
```

一条命令跑完（断点续跑）：

```bash
python3 scripts/run.py all --file 母稿.md --count 5 \
    --outdir "$TEMP/xhs-notes" --yes --snap --budget 200 --json
```

## 这个包解决的是什么问题

批量出笔记的失败模式**不是**"某一篇写坏了"，而是：

> **N 篇其实是同一篇换了个开场。** 单看每一篇都像样，合起来等于只写了一篇。

人眼很难发现（尤其 N 篇不并排看）。本包两道防线：

1. **一个角度一次调用** —— 让模型一次产出 N 篇，它会先写最好写的那篇再裁剪出其余几篇；
2. **本地跨篇换皮闸门** —— 两两比正文，相似度 ≥ 0.65 标红，退出码 3。

**真机实测 3 篇（同一份母稿，独立跑两轮）**：

| 轮次 | 角度 | 正文字数 | 段落数 | 开场 |
|---|---|---|---|---|
| 1 | 新手踩坑 / 算账派 / 反常识 | 568 / 552 / 619 | 22 / 12 / 17 | 「我以为最难的是剪辑」/「上个月对账…」/「我信过一个说法…」 |
| 2 | 同上 | 542 / 618 / 558 | 9 / 18 / 13 | 「我以为三天能收工，结果前三步全走歪了」/「我把花销按小时记了三个月」/「一开始我也信那句」 |

两轮两两相似度 **0.126 / 0.154 / 0.183** 与 **0.109 / 0.148 / 0.169** ——
最大 0.183 离阈值 0.65 有 3.5 倍以上余量，**角度与正文是真的分开了**。
（把同一篇复制成两篇的相似度是 1.000，闸门必然拦下 —— 有坏数据用例。）

## 七道硬闸门

命中即**标红 + stderr 汇总 + 退出码非 0**，可以直接进 CI。

| # | 闸门 | 判什么 |
|---|---|---|
| 1 | 合规 | 广告法违禁词 + 小红书特有红线（站外导流、医疗/功效宣称、绝对化） |
| 2 | 占位符残留 | `{}`、`[待填]`、`XXX`、`（此处省略）`、`TODO` |
| 3 | `prompt_echo` | 照抄提示词示例：去标点相等 / Jaccard ≥ 0.75 / 覆盖度 ≥ 0.60 |
| 4 | 笔记规格 | 正文 ≤ 1000 字、话题标签 5~8 个、**首行必须是钩子** |
| 5 | 跨篇换皮 | N 篇两两相似度 ≥ 0.65 |
| 6 | 出图比例真伪 | 读**真实像素**，不信自报；超容差 3% 即不合格 |
| 7 | 成本上限 | 出图前报价 + `--budget` 超限就地中止（用真实扣费累计） |

退出码：`0` 干净 / `2` 参数配置错（含 `--outdir` 指到包内）/ `3` 硬闸门命中 /
`4` 调用失败 / `5` 预算超限 / `130` 中断。

## 两个实测到的上游特性（写在这里免得你踩）

1. **请求 3:4 拿到的不是 3:4。** 上游按 32 对齐给像素，实测 **864x1184**（偏差 2.70%）。
   容差 3% 内不拦，但一定打印真实像素与偏差；要像素级精确用 `--snap` 裁到 **864x1152**（偏差 0.00%）。
2. **出图任务的 `status` 在 `data` 顶层，不在 `data.result` 里。** 平台文档写的是
   `data.result.status`，照文档写会永远读不到状态、一路轮询到超时。
