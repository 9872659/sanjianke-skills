## 一、为什么"一篇母稿"不能直接发 N 遍

运营最常见的做法是：写好一篇，改个标题、换个开头，发 N 条。
**这是批量出笔记最容易踩的坑，也是本包存在的理由。**

失败模式不是"某一篇写坏了"，而是：

> N 篇其实是同一篇换了个开场。单看每一篇都像样，合起来等于只写了一篇。

人眼很难发现这件事（尤其 N 篇不并排看），机器一眼看穿。
本包用两道防线：

1. **一个角度一次调用**（不让模型一次写完 N 篇，否则它一定先写最好写的那篇再裁剪）；
2. **本地跨篇换皮闸门**（字符二元组 Jaccard ≥ 0.65 就标红，退出码 3）。

### 实测数据（本包真机跑 3 篇，同一份母稿）

| | n01 | n02 | n03 |
|---|---|---|---|
| 角度 | 新手踩坑 | 算账派 | 反常识 |
| 标题字数 / 正文字数 | 16 / 568 | 18 / 552 | 15 / 619 |
| 段落数 | 22 | 12 | 17 |
| 开场 | "我以为最难的是剪辑" | "上个月对账，发现…" | "我信过一个说法…" |

两两 Jaccard 相似度：`n02↔n03 0.183`、`n01↔n02 0.154`、`n01↔n03 0.126`（阈值 0.65）。
**最大 0.183，离阈值 3.5 倍余量** —— 这三篇是真的三篇，不是一篇的三张皮。

对照：把同一篇正文复制成两篇，实测相似度 **1.000**，闸门必然拦下（有坏数据用例）。

## 二、切角度的四个维度

一个"角度"要能在四个维度上说清，否则它就不是角度，是形容词：

| 维度 | 问什么 | 反例 |
|---|---|---|
| **人群**（persona） | 写的人是谁？ | 「大家」「所有人」= 没人群 |
| **场景**（scene） | 具体到哪一步、哪个时刻？ | 「做这件事的时候」= 没场景 |
| **情绪**（emotion） | 什么情绪基调？自嘲？冷静？疲惫？ | 不写情绪，稿子就会通篇一个调 |
| **落点**（focus） | 这一篇落笔讲什么、砍什么？ | 「讲讲这件事」= 没落点 |

判断两个角度是不是真的不同：**四个维度里至少有两个不同**。
「新手踩坑」vs「老手复盘」——人群和场景都不同，是真的两个角度；
「新手踩坑」vs「新手避坑」——四个维度全同，是同一个角度换词。

本包内置 30 个角度（`scripts/run.py` 的 `ANGLES` 表），按四维度成对设计。
`angles --strategy local` 零成本按序取；`--strategy llm` 让模型针对你的材料重出，
生成失败或条数不够会**自动回落**到本地库（不让一次角度生成失败挂掉整条流水线）。

## 三、正文怎么写（本包的硬规格都在这里）

### 3.1 首行必须是钩子

首行决定点不点开。**不是"写得吸引人"，是有明确的形态**：

| 钩子类型 | 形态 | 例子（**非本包产出**，仅说明形态） |
|---|---|---|
| 疑问式 | 句尾问号，或含"为什么/怎么/是不是/要不要" | —— |
| 数字切入 | 出现阿拉伯数字或中文数量词 | —— |
| 身份自报 | 以"我/本人/作为/身为/干了…"起头 | —— |
| 反常识/劝阻 | 以"别/先别/千万别/劝你/其实/不是"起头 | —— |
| **先立后破** | "都说…""一开始我也信…" | —— |
| **认知反转** | "我以为…后来发现…" | —— |
| **代价自述** | "我走了三段弯路""我踩了三个坑" | —— |
| 冲突悬念 | 含"结果/才发现/没想到/直到/差点" | —— |

**明确拦掉的**：以"大家好 / 哈喽 / 今天来分享 / 很高兴 / 记录一下 / 碎碎念"起头。

判定的单位是**首行整行**，不是首句 —— 实测踩过：模型写的
「刚碰短剧二创那半年，我以为最难的是剪辑。后来发现…」里，
"我以为"出现在逗号之后，取首句就截不到，直接被误判成"未识别出钩子"。

### 3.2 字数与段落

| 项 | 口径 | 为什么 |
|---|---|---|
| 正文字数 | **≤ 1000 字**（本包下限 260） | 小红书正文上限是经验口径；太短的笔记讲不清一件事 |
| 段落 | 每段 1~3 行，段间空行 | 手机上段太长会被跳过 |
| 标题 | 8~24 字，口语 | 长了在小红书列表页被截断 |

**字数口径**：去掉所有空白字符后的字符数（中文一个字算一个，emoji 算一个）。
为什么去空白：同一个内容"排成一段"和"排成十行"会差出十几个字，
不去空白就没人能对上数。

### 3.3 话题标签：5~8 个

- 放在正文最后（本包把标签放在单独的 `hashtags` 字段，不写进 `body`，
  避免标签把字数口径搞乱；如果模型自己写进了正文，本包会自动拆出来）。
- 每个标签以 `#` 开头、不带空格。
- 数量不足会**标红并拦截**——标签太少直接影响曝光入口。

### 3.4 诚实原则：不编数字

母稿里没有的数字、品牌、他人评价、检测结论，一律不许编。
材料不够时宁可写主观感受（"我用下来觉得"），也不写客观结论。
这一条写死在系统提示词里，且 `--evidence` 是"可以使用的素材"白名单。

## 四、一次出几篇

不是越多越好。经验值：

| 目的 | 篇数 | 说明 |
|---|---|---|
| 测方向 | 3~5 篇 | 用不同角度试哪一类数据好，成本约 5000 token / 3 篇（实测） |
| 铺一个话题 | 5~8 篇 | 角度库前半段（新手/算账/反常识/对比/清单…）覆盖主流需求 |
| 矩阵测试 | 10 篇以上 | 建议 `--strategy llm` 让角度更贴题，并**抽查跨篇相似度** |

**不要一篇母稿一次出 30 篇就发**：角度库只有 30 个，
到了 20 篇以上，角度之间的边界会开始模糊，跨篇相似度会爬上来。
本包会把相似度打出来 —— 看到超过 0.5 就该停下来换母稿或换角度。

## 五、封面与正文的分工

封面**不是**正文的摘要。它的唯一任务是让人在信息流里停一下：

- 封面大字（`cover_text`）建议 12~18 字、**硬上限 20 字**（超了会报错退出，不会静默截断），一眼读完；
- 正文标题可以更长、更完整；
- 封面画面（`cover_desc`）30~60 字，写清场景与主体，不要写违禁词。

详细尺寸与出图口径见 `references/cover-and-size.md`。
