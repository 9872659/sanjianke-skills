# 封面与尺寸规范（小红书 3:4）

## 一、为什么封面必须是 3:4

小红书信息流里笔记封面是**竖版 3:4**的展示位。比例不对的封面会被平台二次裁切，
**裁哪儿你说了不算** —— 大字标题经常正好被裁掉。

所以本包：

- 出图固定请求 `aspect_ratio=3:4`；
- 出图后**读文件头的真实像素**核对比例（不看接口自报的 `aspect_ratio`）；
- 想要像素级精确就加 `--snap`，本地裁到 **864x1152**。

---

## 二、⚠️ 上游按 32 对齐，请求 3:4 拿到的不是 3:4

**实测（本包真机跑，两次独立任务都一致）**：

```
请求 aspect_ratio = 3:4，resolution = 1K
真实像素 = 864 x 1184
真实比例 = 864/1184 = 0.7297  （3:4 = 0.7500）
偏差 = 2.70%
```

原因不是网关 bug：扩散模型先定总像素、再把每边**向下取整到 32 的倍数**，
3:4 这种比例天然给不出像素级精确的结果。10 种常用比例里有一半如此。

**本包的处理方式（三条一起用）**：

| 做法 | 说明 |
|---|---|
| 默认容差 3% | 容差**内**不算"假"，但**一定打印真实像素与偏差**，不藏 |
| 超容差 → 标红 | 计入闸门失败，退出码 3 |
| `--snap` | 按请求比例居中裁掉多余像素，裁完**再读一次文件头复核**，裁准了才记 exact |

实测 `--snap` 的效果：

```
裁剪前：864x1184 → 比例 27:37 = 0.7297，偏差 2.70%
裁剪方式：pil，裁剪框 (0, 16, 864, 1152)
裁剪后：864x1152 → 比例 3:4  = 0.7500，偏差 0.00%
```

**`--snap` 的语义是"我要像素级等于请求比例"，不是"容差内就不裁"。**
本包实测踩过这个坑：原来写成 `if snap and not ok:`，于是 2.70% 偏差落在 3% 容差内、
根本不裁 —— 加了 `--snap` 却什么也没发生。现在只要给了 `--snap` 就一律裁。

`--ratio-tolerance` 有地板 **0.0025**：像素只能是整数，"裁到精确比例"本身就有量化误差，
把容差调得比它还小会把"必须存在的舍入误差"判成不合格。

## 三、封面提示词怎么写

本包自动生成的封面提示词包含四段：

1. 任务与比例（"为一条小红书笔记做封面图，竖版 3:4"）
2. 画面主体（来自笔记的 `cover_desc`）
3. **大字标题**（来自 `cover_text`，带引号原样给出，要求醒目、粗体、可读）
4. 风格与禁令（干净背景、主体清晰、留文字区、不要水印/二维码/站外联系方式）

`cover_text` 与 `cover_desc` 由 `notes` 阶段一起产出，所以**改封面先改笔记**，
不要直接手改 `covers.json`（改了也能用，但下次跑 `all` 会被覆盖）。

### 实操建议

| 项 | 建议 |
|---|---|
| 大字标题 | 建议 12~18 字。**硬上限 20 字**（`COVER_TEXT_MAX`）：超过 20 字会**报错退出（exit 3）**，实际长度、上限、多出来的字都打印出来，**不会偷偷截掉后半句** |
| 画面主体 | 写**场景**不写**概念**："电脑前的剪辑时间轴 + 一杯凉咖啡"好过"专注的氛围" |
| 文字位置 | 提示词里已要求"留出文字区域、文字不要压在主体上" |
| 一图一意 | 一张封面只讲一件事，别把两个卖点塞进一张图 |

> **为什么超长是报错而不是截断**：送进提示词的文案只有前 20 字（一行放得下），
> 断点 key 取的是**完整**文案的摘要。若静默截断，只改第 21 字之后就会出现
> 「key 变了 → 重新出图、重新扣费，送去的提示词却逐字相同 → 图一模一样」——
> 用户付了钱、什么也没变。1.0.5 起改为显式闸门，超出的部分自己移到正文
> 或 `cover_desc` 里。这一条**不接受 `--allow-prompt-hits` 放行**。

## 四、成本

| 项 | 数值 | 来源 |
|---|---|---|
| nano_banana 1K 单张 | **24 点 = 0.24 元** | 实测（任务返回 `usage.points_cost`） |
| 提交时冻结 | 实测 `frozen_points = 31.2` | **只是预冻结，不是最终扣费**；失败全额退回 |
| 1 元 | 100 点 | 平台口径 |
| 2K / 4K | **没有实测价** | 必须自己给 `--points-per-image`，本包拒绝猜 |

本包**只信 `usage.points_cost`**。平台的 `pricing_matrix` / `tenant_*` 字段在本库其他
包上验证过半数不可信（`image_human` 字段写 1.5/2/4/8 点/秒、实测 2/3/6/12），
所以那些字段只当参考，绝不写进结算口径。

出图前一定先报价：`covers` 不给 `--yes` 也不给 `--budget` 时**只报价不提交**。

## 五、断点续跑

出图是真花钱，所以状态都落盘（`<outdir>/xhs-note-factory-state.json`）：

| 状态 | 重跑时的行为 |
|---|---|
| `completed` | **跳过**，不重复扣费（要重出得加 `--force`） |
| `pending`（已提交未完成） | 用 `task_id` **续查**，不重新提交（点数已冻结） |
| 未提交 | 正常提交 |

达到 `--budget` 时**就地停下**，已完成的图与断点都保留，直接重跑即可续。

---

## 六、红线：图不能落在 Skill 包内

包内不许有任何图片（上传白名单只收 `.md .py .txt .json .sh .js .yaml .yml .csv`）。
所以：

- `--outdir` 指到 Skill 包内 → **参数错误，退出码 2**，而且是在**花钱之前**就拦下；
- 默认输出目录是 `%TEMP%/xhs-note-factory`（包外）；
- 想整理成品，直接把包外那个目录里的文件拷走，别往回拷进包里。
