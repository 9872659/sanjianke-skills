# 三剪客 · 桌面划词翻译与文本润色

它解决的是「读外文时的打断感」：你在浏览器、PDF 阅读器或任意桌面软件里选中一段文字，按一次快捷键，译文就近弹出，不用切窗口、不用复制粘贴到网页翻译里。它和普通翻译插件最大的区别是把大模型的三种用法做成了同一套入口——**翻译**之外还有**润色**和**总结**，所以同一段英文既可以直译，也可以改成更地道的表达，或者直接压成要点。

适合做外语资料的日常阅读、跨语言沟通草稿，以及在浏览器和桌面软件中都想要同一套快捷键的人。

**上游项目**：`nextai-translator`　**仓库**：https://github.com/nextai-translator/nextai-translator

## 什么时候用 / 不用

**用它**：

- 要在任意桌面软件里划词即译：桌面端应用与浏览器插件两套形态，覆盖 Windows / macOS / Linux。
- 需要的不只是直译：同一段文字可以切到「润色」改表达，或切到「总结」压成要点。
- 要读图里的字：内置截图翻译，框选屏幕区域后直接出译文。
- 阅读外文时需要边看边记：带生词本，并能基于生词本里的词生成帮助记忆的内容。
- 想要流式输出与外文朗读：译文逐字出现，长段落不用干等，也能直接听。
- 手上有现成的 OpenAI 兼容入口或 Azure OpenAI 资源，想直接接进来用。

**不要用它**：

- 想拿命令行工具或 HTTP 接口做批量翻译：它是 GUI 产品，没有面向脚本的批量入口；批量任务应该走别的工具链。
- 要做整篇文档的保留版式翻译：它面向划词与短段落，不做 PDF / Word 的排版还原。
- 没有可用的模型服务：它自己不带模型，必须配置服务商与对应凭证才能出结果。
- 要离线、不出网：默认走云端接口，涉密内容也会发往你配置的服务商，先过一遍合规判断。
- 想离线识别图片文字且不依赖模型看图：截图翻译走的是模型识图，不是纯本地的传统 OCR 引擎。
- 期待稳定的官方技术支持：这是社区开源项目，出问题走上游 Issues。

## 安装
桌面端与浏览器插件是两条独立路线，按需装；先看 [Latest Release](https://github.com/nextai-translator/nextai-translator/releases/latest) 页面上的实际文件名与版本。

**Windows**：下载以 `.exe` 结尾的安装包，双击安装。若被提示来源不安全，点「更多信息」→「仍要运行」。

**macOS**：下载对应芯片的 `.dmg`（Apple Silicon 机器用 aarch64 版本），拖进「应用程序」。首次打开若提示无法验证开发者，去「设置 → 隐私与安全性」点「仍要打开」；若找不到该选项或提示文件损坏，在终端执行下面这条再重启应用：

```bash
sudo xattr -d com.apple.quarantine /Applications/NextAI\ Translator.app
```

**Linux**：从 Release 页面取对应发行版产物安装（上游 README 未给出 Linux 的包管理器命令，以 Release 页面说明为准）。

**浏览器插件**：在 Chrome 应用商店或 Firefox 附加组件商店搜索并安装，装完点插件图标，把 API Key 填进弹出的配置界面，然后刷新页面生效。

**从源码构建（开发者）**：仓库是 TypeScript + Rust 的双形态工程，包管理器锁定 `pnpm@9.1.3`，桌面端外壳用 Tauri，浏览器插件用 Vite 构建。脚本名以 `package.json` 为准，上游 README 没有给完整的源码构建步骤。

```bash
git clone https://github.com/nextai-translator/nextai-translator.git
cd nextai-translator
pnpm install
pnpm dev-tauri        # 桌面端开发模式（需 Rust 工具链）
pnpm build-tauri      # 桌面端打包
pnpm dev-chromium     # 浏览器插件开发（Chromium）
```

## 常用操作

**1）配好服务商与凭证**（第一步，不做这步快捷键按了也没结果）

打开设置，选服务商，填 API Key。上游列出支持的服务商包括 OpenAI、Azure OpenAI Service、MiniMax，以及内置的 TeamoRouter（一个 OpenAI 兼容网关，选中它再填 Key 即可）。要接自建或第三方兼容端点，在设置里改接口地址。

**2）配置 Azure OpenAI Service**：上游给出的三条地址规则如下，照着填就不会拼错。

```text
API_URL      = https://{resourceName}.openai.azure.com
API_URL_PATH = /openai/deployments/{deployName}/chat/completions?api-version={apiVersion}
```

- `resourceName`：你的 Azure OpenAI Service 资源名
- `deployName`：你的模型部署名（改这里就是换模型）
- `apiVersion`：`2023-05-15` 或更新的版本；受支持列表看 Azure 官方文档

**3）设快捷键并划词翻译**：在设置里给「划词翻译」绑定快捷键，之后在任意软件里选中文本按快捷键即可。浏览器里也可以直接选中后点插件图标。

**4）切换三种模式**：译文面板上可在「翻译 / 润色 / 总结」之间切换。做外语精读时常用「润色」把生硬机翻改成自然表达，做资料速读时用「总结」。

**5）截图翻译**：按截图翻译快捷键，框选屏幕上的文字区域，识别后直接给译文。适合处理图片、扫描件、视频截图里的文字。

**6）生词本与记忆内容**：把查过的词收进生词本，之后可以让它基于生词本里的词生成帮助记忆的内容，用来做复习清单。

**7）桌面端划词扩展**：桌面端在各系统上拿不到统一的「当前选中文本」接口，所以它借成熟的划词软件来实现：

```text
macOS   ：装 PopClip 后，下载 nextai-translator.popclipextz（Release 页有直链），双击安装并在 PopClip 中启用。
Windows ：装 SnipDo 后，下载 nextai-translator.pbar，双击安装并在 SnipDo 设置里启用。
```

**8）验证是否通**：随便选一句话翻译，看是否流式出字。若报鉴权类错误，先查 Key、接口地址、模型名三处，再查网络。

## 常见坑

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 装完按快捷键没反应 | 还没配服务商与 API Key，或快捷键被别的软件占用 | 先确认设置里服务商与凭证已填且能出译文，再换一个不冲突的快捷键组合 |
| macOS 提示「无法验证开发者」/「文件已损坏」 | 应用没做公证签名，系统加了隔离标记 | 走「隐私与安全性 → 仍要打开」；找不到该选项就执行 `sudo xattr -d com.apple.quarantine` 把隔离属性摘掉 |
| macOS 每次打开都弹权限提示，或划词翻译失效 | 辅助功能权限记录失效 | 到「设置 → 隐私与安全性 → 辅助功能」里移除本应用再重新添加 |
| Azure 报 404 / 模型找不到 | 地址拼装错，或部署名与模型名混用 | 严格按 `https://{resourceName}.openai.azure.com` + `/openai/deployments/{deployName}/chat/completions?api-version={apiVersion}` 三段拼；`deployName` 是部署名不是模型名 |
| 报 api-version 不受支持 | 用了过旧的 API 版本 | 换成 `2023-05-15` 或更新版本，具体以 Azure 官方受支持列表为准 |
| 浏览器插件装好仍不能翻译 | 配置没保存成功，或页面是安装前打开的 | 在插件弹窗里确认 Key 已保存，然后刷新页面重试 |
| 请求长时间无响应或超时 | 网络到服务商不通，或接口地址填错 | 先用 curl 验证该地址能否返回结果；不通就换服务商或走代理/网关；报错信息会指向具体环节 |
| 翻译结果被截断、不完整 | 单次送入文本过长，或输出被截断 | 分段翻译；长文先切「总结」模式压缩再翻 |
| 接自建 / 第三方兼容端点失败 | 地址少了 `/v1` 之类的路径前缀，或模型名不被对端识别 | 用对端文档给的完整 base URL 与模型名，先用 curl 验证该端点能返回结果再回填 |
| 在个别软件里划词取不到选中文本 | 该软件不走系统剪贴板 / 无障碍接口，扩展拿不到文本 | 改用截图翻译，或先复制文本再触发输入翻译；这是桌面端划词的通用限制 |
| 处理敏感内容前没做合规判断 | 文本与截图会发往所选服务商 | 内部资料先脱敏，或改接内网 / 本地兼容端点 |

- 「这张截图里的英文我看不懂，翻译一下」

## 能力边界

**覆盖**：

- 划词翻译、输入翻译、截图翻译三类交互入口
- 翻译 / 润色 / 总结三种模式
- 上游说明的 55 种语言之间的互译、润色与总结
- 流式输出、一键复制、文本朗读
- 生词本与基于生词本的记忆内容生成
- 多服务商接入：OpenAI、Azure OpenAI Service、MiniMax，以及内置的 OpenAI 兼容网关
- 桌面端（Windows / macOS / Linux）与浏览器插件（Chrome / Firefox）两种形态
- 桌面端集成外部划词软件扩展（PopClip / SnipDo）

**不覆盖**：

- 不提供命令行或 HTTP API 形式的批量翻译入口
- 不做文档级排版还原（PDF / Word / PPT 版式保留）
- 不自带模型与算力，必须由使用者提供可用的服务商与凭证
- 不做语音识别、不做实时语音同传；语音能力限于把文本读出来
- 不做翻译记忆库、术语库、团队协作等翻译项目管理能力
- 不承诺离线可用：默认形态是联网调用云端接口
- 不提供官方技术支持与 SLA，问题走上游仓库 Issues

## 依赖条件

- 桌面端：Windows / macOS / Linux 桌面环境；macOS 需在「辅助功能」「隐私与安全性」中给相应授权，截图功能另需屏幕录制权限
- 浏览器插件：Chrome 或 Firefox 的较新版本
- 一个可用的模型服务与凭证：OpenAI API Key、Azure OpenAI Service 的端点与 Key，或其它 OpenAI 兼容入口的地址与 Key
- 使用 Azure OpenAI Service 时，需要该订阅下的资源名、部署名与可用的 api-version
- 从源码构建另需 Node.js 与 `pnpm@9.1.3`（包管理器版本由仓库锁定）、Rust 工具链（桌面端外壳）
- 网络：能访问所选服务商的接口域名

## 已知限制

- 快捷键、划词、截图这类能力强依赖操作系统权限，权限没给全时表现为「按了没反应」而不是明确报错
- 划词取文本依赖系统剪贴板与无障碍接口，个别应用里天生取不到
- 截图翻译是把图交给模型看，识别质量受图像清晰度与排版影响，表格类内容容易错位
- 输出质量等于所配模型的质量，同一段话换模型结果差异明显
- 桌面端「当前选中文本」没有跨系统统一方案，因此强依赖 PopClip / SnipDo 这类外部软件
- 上游 README 未提供完整的源码构建与命令行使用说明，二次开发需自行阅读仓库代码
- 项目在历史上改过名，检索资料时旧名与新名指向同一产品，看到旧名不必认为装错了
