# 流水线搭建：切分 → 召回 → 拼上下文 → 生成

这份文档给出一套**只用 Python 标准库**的完整实现。检索侧完全本地、完全免费，
只有最后的生成走 `api.a7w.cn` 的网关。

---

## 1. 切分：按结构切，不要按字数切

| 策略 | 怎么做 | 什么时候用 |
|---|---|---|
| **按标题层级**（推荐） | 先按 Markdown / 文档标题切成节，节内再按段落切 | 手册、规范、条款类文档 |
| **按段落**（推荐） | 以空行分段，段落超过阈值再拆 | 通用 |
| **定长滑窗** | 固定字数，前后重叠 | 无结构的连续文本 |

**中文建议参数**：

| 参数 | 建议值 | 说明 |
|---|---|---|
| `size` | 300~500 字 | 太短语义不足，太长稀释相似度 |
| `overlap` | `size` 的 10%~15% | 防止答案正好被切断 |
| 保留标题 | 每块前面拼上所属标题路径 | 显著提升召回准确率 |
| 丢掉噪声 | 目录、参考文献、页眉页脚、附录 | 对问答毫无贡献，还占 token |

```python
import re

def split_text(text, size=400, overlap=60):
    """定长滑窗切分（无结构文本的兜底方案）。"""
    text = re.sub(r"\s+", " ", text).strip()
    if not text:
        return []
    step = max(1, size - overlap)
    return [text[i:i + size] for i in range(0, len(text), step)]

def split_with_heading(text, size=400, overlap=60):
    """带标题路径的切分：每块前面拼上所属标题，召回更准。"""
    chunks, heading, buf = [], "", []
    for line in text.splitlines():
        if line.startswith("#"):
            if buf:
                chunks.extend(_flush("".join(buf), heading, size, overlap))
                buf = []
            heading = line.lstrip("#").strip()
        else:
            buf.append(line)
    if buf:
        chunks.extend(_flush("".join(buf), heading, size, overlap))
    return chunks

def _flush(body, heading, size, overlap):
    prefix = ("【%s】" % heading) if heading else ""
    return [prefix + c for c in split_text(body, size, overlap)]
```

## 2. 召回：纯标准库的 BM25（零依赖、免费）

中文没有空格，这里用**字 bigram** 当词元，效果对中文检索足够好，而且不需要任何分词库。

```python
import math, re

def tokens(text):
    text = text.lower()
    latin = re.findall(r"[a-z0-9]+", text)
    han = re.findall(r"[\u4e00-\u9fff]", text)
    bigrams = ["".join(p) for p in zip(han, han[1:])] or han
    return latin + bigrams

class BM25:
    """纯标准库 BM25。docs 是切好的文本块列表。"""

    def __init__(self, docs, k1=1.5, b=0.75):
        self.docs = list(docs)
        self.k1, self.b = k1, b
        self.tfs = [self._tf(tokens(d)) for d in self.docs]
        self.lens = [sum(tf.values()) for tf in self.tfs]
        self.avg = (sum(self.lens) / len(self.lens)) if self.lens else 0.0
        df = {}
        for tf in self.tfs:
            for w in tf:
                df[w] = df.get(w, 0) + 1
        n = len(self.docs)
        self.idf = {w: math.log(1 + (n - d + 0.5) / (d + 0.5)) for w, d in df.items()}

    @staticmethod
    def _tf(ws):
        tf = {}
        for w in ws:
            tf[w] = tf.get(w, 0) + 1
        return tf

    def search(self, query, top_k=3):
        q = tokens(query)
        scored = []
        for i, tf in enumerate(self.tfs):
            s = 0.0
            L = self.lens[i] or 1
            for w in q:
                f = tf.get(w)
                if not f:
                    continue
                s += self.idf.get(w, 0.0) * (f * (self.k1 + 1)) / (
                    f + self.k1 * (1 - self.b + self.b * L / (self.avg or 1)))
            scored.append((s, i))
        scored.sort(reverse=True)
        return [{"text": self.docs[i], "score": round(s, 4)} for s, i in scored[:top_k]]
```

**想升级成语义检索**：把每一块用 `POST /api/v1/embeddings` 向量化后落盘，
查询时把问题向量化再算余弦相似度即可。BM25 与向量两路召回结果合并，效果更稳。

## 3. 拼上下文：模板与三条纪律

```python
SYSTEM = (
    "你是一个严谨的知识库助手。只能根据「资料」回答；"
    "资料里没有的信息就说「资料中没有提到」，不要编造。"
    "回答末尾用 [编号] 标注引用的资料。"
)

def build_messages(question, hits):
    ctx = "\n\n".join("[%d] %s" % (i + 1, h["text"]) for i, h in enumerate(hits))
    return [
        {"role": "system", "content": SYSTEM},
        {"role": "user", "content": "资料：\n%s\n\n问题：%s" % (ctx, question)},
    ]
```

三条纪律：

1. **必须写「资料里没有就说不知道」** —— 这是压制幻觉最有效的一句话。
2. **要求标注引用编号** —— 让答案可核对，也方便你定位召回问题。
3. **块数控制在 3~5 条** —— 给多了既贵又跑题，还容易超上下文。

## 4. 端到端：切分 → 召回 → 生成（可复制运行）

```python
import json, os, re, urllib.request

HOST = "https://api.a7w.cn"
KEY = os.environ["A7W_API_KEY"]
MODEL = "DeepSeek-V4-Flash"          # 以 GET /api/v1/models 的返回为准

def chat(messages, temperature=0.2, max_tokens=800):
    body = {"model": MODEL, "messages": messages,
            "temperature": temperature, "max_tokens": max_tokens}
    req = urllib.request.Request(
        HOST + "/api/v1/chat/completions",
        data=json.dumps(body, ensure_ascii=False).encode("utf-8"),
        headers={"Authorization": "Bearer " + KEY,
                 "Content-Type": "application/json"},
        method="POST")
    with urllib.request.urlopen(req, timeout=180) as r:
        res = json.loads(r.read().decode("utf-8"))
    if res.get("code") not in (None, 1, 200):        # 成功码是 1
        raise RuntimeError(res.get("msg"))
    return res["choices"][0]["message"]["content"]

if __name__ == "__main__":
    raw = open("我的资料.txt", encoding="utf-8").read()
    chunks = split_with_heading(raw)
    index = BM25(chunks)

    question = "退款期限是多久？"
    hits = index.search(question, top_k=3)
    print(chat(build_messages(question, hits)))
```

## 5. 评测与调优（不花点数）

**只测召回**：把 `hits` 直接打印出来，人工看正确的那块有没有进 top-3。
召回不对，后面模型再强也救不回来。

| 症状 | 先改哪里 |
|---|---|
| 正确答案根本没被召回 | 切分粒度（块太小/太大）、是否丢了标题、是否该加语义检索 |
| 召回了但答非所问 | 块数太多、上下文里混进了无关内容 |
| 答案里有编造 | system 提示词是否写了「资料里没有就说不知道」 |
| 中文专有名词命中不了 | 保持 bigram 词元，别只用单字 |
| 长文档召回差 | 给每块拼上标题路径；或先做一次章节级摘要再检索 |

**只测生成**：把已经确认正确的 3 条资料固定下来，换不同 `model` 跑同一题，
比较答案质量 —— 这样每次比较的变量只有一个。

## 6. 参数速查

| 参数 | 位置 | 建议 |
|---|---|---|
| `size` | 切分 | 300~500 字 |
| `overlap` | 切分 | `size` 的 10%~15% |
| `top_k` | 召回 | 3~5 |
| `temperature` | 生成 | 0.2~0.3（抽取类任务用 0） |
| `max_tokens` | 生成 | 512~1200，**推理型模型要给足** |
| `model` | 生成 | 以 `GET /api/v1/models` 为准，随时可换 |
