# 三剪客 · 工程师技能体系 Skill

把工程经验沉淀成可复用 Agent Skill：怎么切分、怎么写、怎么在团队里落地。

---

## 前置条件

- 一个本地代码仓库，且有写权限（技能要跟着代码一起版本化）
- 能读写 Markdown 文件的编辑器或 Agent 运行时
- 推荐装 git：技能的演化历史是它最有价值的部分
- **不需要**网络、API Key、数据库、Docker 或任何付费服务

---

## 使用

这是一个纯指导型 Skill，没有可执行入口。在 Agent 会话里直接描述你的处境即可，例如：

- 「我们团队的经验都散着，想搞一套自己的 Skill 库，从哪儿下手？」
- 「这个事我要不要写成 Skill？」
- 「我写了个 800 行的 Skill，Agent 用起来反而变笨了，怎么拆？」
- 「技能怎么评审、怎么发版、谁来维护？」

Agent 会按 `SKILL.md` 的工作流路由，取用对应的参考文件：

| 你要做什么 | 看哪份 |
|---|---|
| 判断该不该沉淀、怎么切分 | `references/skill-splitting.md` |
| 动手写正文、瘦身 | `references/writing-a-skill.md` |
| 评审门禁与团队排期 | `references/team-rollout.md` |
| 排查已有技能的问题 | `references/anti-patterns.md` |

最小可用路径：先过一遍九问判据（`SKILL.md` 快速开始），有 4 条答不上「是」就先别写。

## 安全

- 不内嵌任何密钥
- 全程离线，不发起任何网络请求
- 不读取、不写入、不转发任何凭证、Token、Cookie
- 写入前不覆盖已有文件；目标存在时先给出差异
- 不常驻进程、不装依赖、不注册定时任务、不改系统配置
- 本 Skill 反复强调的一条：往技能正文里放日志、报错、内网信息前先脱敏——技能的读者是所有能拉到该仓库的人
