# 三剪客 · 一稿多平台改写

给**一篇原稿**，自动改写成**五个平台的规格**：公众号长文、小红书笔记、抖音口播稿、
知乎回答、头条短文。

面向每天要把同一份内容发到多个渠道的新媒体运营。

这是产品线里的 **L1 单点生成型**技能包：一个输入 → 一组产出，开箱即用。

## 它解决什么问题

运营最熟悉的一个动作是**复制粘贴**：把公众号长文贴进小红书、把口播稿贴进知乎。

数据不会好。而原因通常被误判成「内容不行」——**真正的问题是形态不对**：

- 公众号长文贴到小红书，读起来像说明书
- 口播稿贴到知乎，读起来像营销号
- 知乎那种「先说结论」的开场放进短视频，前 3 秒就划走了

问题的根源是**开场、段落、信息密度、结尾**这四件事在每个平台都不一样，
而且原因不是审美，是**分发机制**：公众号的读者是主动打开的，小红书的读者是滑到的，
抖音的读者 3 秒内决定留不留，知乎的读者在找答案，头条的读者是泛人群。

**换词解决不了这个。** 本包做的是按平台重写结构。

## 六个子命令

| 子命令 | 干什么 | 花不花钱 |
|---|---|---|
| `platforms` | 列出支持的平台与完整规格 | **零网络，不花钱** |
| `plan` | 读原稿 → 出改写方案（各平台怎么改、保留什么、砍什么、缺什么） | 一次调用 |
| `rewrite` | 按平台改写（`--platform` 单个 / 可重复 / `--all` 全跑） | 一个平台一次调用 |
| `diff` | 原稿与改写的**结构性对比**（字数/段数/开场/结尾） | **纯本地，不花钱** |
| `cost` | 只算钱（token 估算 / 按单价折算 / 读真实调用记录） | **不调模型** |
| `models` | 列出 api.a7w.cn 当前在架的模型 | 免费 |

## 平台规格是数据，不是写死在提示词里

五个平台的字数区间、段长、段数、开场方式、结尾引导、标签数量、emoji 策略、标题风格，
全部放在 `scripts/run.py` 的 `PLATFORMS` 常量里。**提示词和本地闸门都从这张表读。**

**改规格只改表，不改逻辑。**

| key | 平台 | 正文区间（目标字数） | 段数 | 单段字数 | 标签 | emoji |
|---|---|---|---|---|---|---|
| `wechat` | 公众号 | 1200~2200（1550） | 6~12 | 80~220 | 0 | 否 |
| `xiaohongshu` | 小红书 | 350~800（508） | 4~10 | 10~60 | 5~8 | 可 |
| `douyin` | 抖音 | 300~600（405） | 6~14 | 8~40 | 3~5 | 否 |
| `zhihu` | 知乎 | 800~1500（1045） | 5~12 | 60~260 | 0~3 | 否 |
| `toutiao` | 头条 | 600~1200（810） | 5~12 | 30~120 | 0~3 | 否 |

目标字数 = 区间下限 + 35% × 区间长度。**提示词里给的是目标字数而不是上限**——
给上限模型就会顶到上限然后写超。

完整规格（含每个平台的开场方式、结尾引导、硬性要求、特有红线）
见 [`references/platform-specs.md`](references/platform-specs.md)，或跑 `platforms`。

## 平台差异是真的吗（实测）

一次真实 `rewrite --all`，原稿 400 字：

| 平台 | 字数（区间） | 段数 | 均段长 | 标签 | 开场类型 |
|---|---|---|---|---|---|
| 公众号 | 1335（1200~2200）✅ | 13 | **102.7** | 0 | 疑问式 |
| 小红书 | 396（350~800）✅ | 19 | 20.8 | 6 | 第一人称代入 |
| 抖音 | 394（300~600）✅ | 26 | **15.2** | 4 | 劝阻/警告式 |
| 知乎 | 1075（800~1500）✅ | 12 | **89.6** | 3 | 结论前置 |
| 头条 | 635（600~1200）✅ | 13 | 48.8 | 3 | 共鸣/现象式 |

**均段长从 15.2 字到 102.7 字，差 6.8 倍；开场类型五个各不相同；
字数五个平台全部落在区间内。**

跨平台二元组相似度最高 **0.572**，只有 `小红书 ↔ 抖音` 这一对踩线（阈值 0.55），
被换皮闸门标出；其余 9 对都 ≤ 0.464。

对照：在提示词里加上「不许整句搬运原稿措辞」「信息出场顺序也可以不一样」之前，
那一版最高相似度是 **0.71**，被本地换皮闸门当场拦下。**这两条改进有实测依据。**

**字数区间返工过一次，值得说清楚。** 第一版提示词写的是「没有把握时宁可贴住区间下限」，
结果 5 个平台里 3 个不达标（公众号 992/1200、抖音 284/300、头条 511/600）——
**那句"保险"提示词正是造成不达标的原因**。改成把算好的目标字数
（`下限 + 35% × 区间长度`）直接给模型、措辞改成「**绝不能低于下限**，也不要顶到上限」之后，
同一份原稿再跑，5 个平台全部落在区间内（上表）。

**残留难点**：`小红书 ↔ 抖音` 是最容易踩线的一对——两者目标长度区间重叠，
原稿短的时候都在讲同一个故事。闸门会标出来但不自动改，改法是换切入角度或干脆不发那一篇。

## 六道硬闸门

**硬闸门 = 命中即拦截 + 标红 + 汇总到 stderr + 退出码非 0。不许只警告。**

| # | 闸门 | 判什么 | 扣分 / 退出码 |
|---|---|---|---|
| 1 | **合规** | 广告法违禁词（最/第一/国家级/100%/绝对化/根治/保本/包过…）+ **平台特有红线**（小红书站外导流、知乎私域引流、抖音禁止外链…） | 高 40 / 中 20 / 低 8，退出码 3 |
| 2 | **占位符残留** | `{}`、`[待填]`、`XXX`、`（此处省略）`、`待补充`、`TODO`/`TBD` | 40，退出码 3 |
| 3 | **`prompt_echo`** | 与提示词示例去标点后相等、字符二元组 Jaccard ≥ **0.75**、或示例二元组**覆盖度 ≥ 0.60**。标题比整条；正文**整段 + 逐句两层都查** | 30，退出码 3 |
| 4 | **字数区间** | 必须落在该平台的目标区间，超出/不足按偏离程度扣分 | 上限 60，退出码 3 |
| 5 | **结构完整性** | 必须有 标题 + 正文 + 结尾引导，且结尾要含**该平台的**行动指令 | 每项 25，退出码 3 |
| 6 | **成本上限** | `--budget` 超了就地中止（**用真实 usage 累计，超了就停**） | 退出码 5 |

外加一道**跨平台换皮检测**（本地）：两两比较正文的字符二元组 Jaccard，
两篇都 ≥ 200 字才比较，≥ **0.55** 判为疑似换皮 → 标红 + 退出码 3。

**为什么只有这五项算硬闸门**：硬闸门的标准是「发出去会出事」。
字数不够是**质量不达标**，合规违禁是**会被罚**，两者不是一回事。
话题标签数、emoji 策略、段落风格只扣分不拦截——
把风格问题也做成硬闸门，工具会在正常使用中频繁返回非 0，最后没人看退出码，闸门就废了。

## 三个真实事故写进了代码

### 1. 模型会照抄提示词里的示例，哪怕标着「这是错的写法」

本库标题工坊实测过两次：提示词里写过的示例句子，模型直接产出。
其中一次**一字不差就是提示词示例，而且拿了那一轮的最高分 89.0**——
最高分变成「抄标准答案」而不是「真的最好」，排序就废了。

所以本包：提示词里**不出现任何一句可复制的完整中文句子**，
举例只用描述性语言 + 登记在 `PROMPT_SAMPLES` 里的**跨主题**示例
（主题刻意选「电动车充电桩」，与三剪客真实业务明显不搭）；
万一有人把真实示例加回去，闸门会兜住。

**阈值 0.75 的标定依据**：196 条正常产出与跨主题示例的最高相似度只有 0.174，
而「少两个字的同构照抄」是 0.765——0.75 有 4 倍以上的安全距离。

**闸门写完要用坏数据喂一遍。** 自测时发现原来只比「整段正文」是不行的：
正文 1000+ 字、示例二三十字，Jaccard 的分母被撑到 1000 多，
**模型把示例原样抄进正文的某一段时，这道闸门完全看不见**——
而长文场景下「抄示例」恰恰就是「有一段是抄的」。
所以改成整段比一次 + **逐句再比一次**。这个漏洞是喂罐头数据喂出来的，不是看代码看出来的。

### 2. 一次调用写五个平台 = 换皮

如果让模型一次同时产出五个平台的稿子，它会先写最好写的那一份，再裁剪成另外四份。
所以本包**一个平台一次调用**。

### 3. 合规闸门自己也会误伤，而误伤会让闸门废掉

实测原稿里有一句「回头翻一条自己播放量最低的视频」，
被「最X」规则判成高风险「广告法第九条禁止最高级用语」并整篇拦截。
**这个诊断是错的**——那是在描述自己的数据，不是商品宣称。

所以加了一条**很窄**的语境豁免：`最X` 前一个字是计量类名词
（量/率/数/分/位/条/次/段/部/集/页/个/天/月/年）且后面紧跟「的/之」时，
**放过但在报告里登记**（`gates.compliance.exempted`）——**不静默放过**。

豁免词表刻意不含 `价/时/款/种/家`：「课时最低的课程」「单价最低」都是真实的
价格宣称形态，必须照拦。

## 成本口径

**本包拒绝凭空编一个单价。** 实测：

- `GET /api/v1/pricing` 只有 6 条规则（全局 `*` + `full_video` / `asr` / `flashvsr` /
  `action_transfer` / `person_replacement`），**不含文本大模型**
- `GET /api/v1/models` 的 75 条记录里**没有任何价格字段**
- `POST /api/v1/chat/completions` 的成功响应里 `usage` 只有
  `prompt_tokens` / `completion_tokens` / `total_tokens`，**没有点数**

所以：token 数我们估（实测标定），**金额必须由你给单价**（`--price-in` / `--price-out`，
单位「点/百万 token」）。不给单价就只报 token，不给金额。

实测标定（一次 `rewrite --all` 的 5 次调用）：

| 方向 | 标定值 | 平台间波动 |
|---|---|---|
| 输入 | 1 原始字符 ≈ **0.621** token | 极小：5 个平台 1.609~1.615 字/token |
| 输出 | 1 原始字符 ≈ **1.11** token | 较大：知乎 0.93 · 公众号 0.99 · 头条 1.18 · 小红书 1.33 · **抖音 1.63** |

输出侧平台间差异几乎全部来自**换行数**：抖音一句一行（26 行），每个换行都是一个 token。

## 退出码（可直接用于 CI）

| 退出码 | 含义 |
|---|---|
| `0` | 全部干净 |
| `2` | 参数/配置错误（例如给了 `--budget` 却没给单价） |
| `3` | 有硬闸门命中（合规/占位符/照抄示例/字数区间/结构/跨平台换皮） |
| `4` | 调用失败（网络 / 鉴权 / 点数 / 模型名） |
| `5` | 预算超限，已就地中止 |
| `130` | 用户中断 |

## 算力接入

只用大模型，端点：`POST https://api.a7w.cn/api/v1/chat/completions`
（OpenAI 兼容协议）。模型清单用 `GET https://api.a7w.cn/api/v1/models` 现查。

- **不留任何密钥在代码或文档里**，Key 从环境变量 `A7W_API_KEY` 读
- **模型名会变，用 `models` 子命令现查，别写死**
- `deepseek-chat` 这个别名**实测可用**，且**实测确认路由到 `deepseek-flash`**
  （请求 `deepseek-chat` → 响应 `model: "deepseek-flash"`）；
  但它**不在** `/api/v1/models` 里（该列表给的是 `DeepSeek-V4-Pro` /
  `DeepSeek-V4-Flash` / `DeepSeek-V3.2` 这些版本号名，响应里又变成小写形式）——
  **列表名、请求名、响应名三者不一定一致**
- **反例**：`deepseek-flash` 当**请求名**用是失败的——实测 HTTP 200 但
  `model:null`、内容与 usage 全空（静默失败）。它只是路由的目标名
- **推理模型的坑**：`models` 列表里的 `DeepSeek-V4-Pro` 与 `DeepSeek-V3.2` 是推理模型，
  会先花 completion token 出思维链。实测一句两字的回复：`DeepSeek-V3.2`
  （路由到 `deepseek-v3.2-think`）花掉 **105** 个 reasoning token，`DeepSeek-V4-Pro` 花掉 **54** 个。
  用它们跑公众号长文要么提高 `--max-tokens`，要么就用默认的 `deepseek-chat`
- **成功响应不带 `code` 字段**；`code==1` 那套信封只用于生成应用的响应，不适用于本端点
- 大模型调用带退避重试（网关 `upstream timeout` / HTTP 502 实测很常见）
- JSON 解析用 `json.JSONDecoder().raw_decode()` 扫描第一个完整对象，
  模型在合法 JSON 后多吐字符也不会炸
