# 三剪客 · 一稿多平台改写

> ## ⚠️ 先申请你自己的 API Key
>
> **本 Skill 不内嵌任何密钥，也不代付费用。** 请到
> **[算力集市 api.a7w.cn](https://api.a7w.cn/)** 注册并创建**你自己的** API Key
> （新用户有赠送点数，可以先免费试跑一两条）。
>
> 拿到后填进环境变量 `A7W_API_KEY`，或直接传给 `--key` 参数。
> **请勿使用他人提供的 Key** —— 用量与费用都记在 Key 所属账号上。

## 能做什么

给**一篇原稿**，自动改写成**五个平台的规格与语感**：公众号长文、小红书笔记、
抖音口播稿、知乎回答、头条短文。

它替代的不是「润色」，是运营每天真正在做的那个动作：**把一篇稿子按分发渠道重做一遍**。
最常见的做法是复制粘贴，然后数据不好，然后把原因误判成「内容不行」——
其实问题是形态不对：公众号长文贴到小红书像说明书，口播稿贴到知乎像营销号。

**这不是换词，是按平台重写结构。** 每个平台改四件事：

| 改什么 | 为什么 |
|---|---|
| **开场** | 公众号有耐心铺现象，小红书第一句必须自报身份，抖音前 3 秒不出钩子就没了 |
| **段落** | 公众号一段 80~220 字，小红书的段不能超过 3 行，抖音一行一个气口 |
| **信息密度** | 小红书一个点一段，知乎要给边界条件，头条一段只讲一件事 |
| **结尾** | 结尾不是「总结一下」，是让读者做一件事——做什么事每个平台不一样 |

三个子命令串起完整流程：

| 子命令 | 干什么 |
|---|---|
| `plan` | 读原稿 → 出改写方案：各平台保留什么、砍什么、原稿还缺什么 |
| `rewrite` | 按平台改写（`--platform` 单个 / 可重复 / `--all` 全跑） |
| `diff` | 原稿与改写的**结构性对比**（字数/段数/开场/结尾）——**纯本地，不花钱** |

外加 `platforms`（零网络看规格表）、`cost`（只算钱）、`models`（现查在架模型）。

| 最关心 | 答案 |
|---|---|
| 多少钱 | 按 tokens 计费。实测一次 `rewrite --all`（5 个平台）约 **1.14 万 token**，很便宜 |
| 要多久 | 实测 **24~28 秒**跑完 5 个平台（一个平台一次调用，约 4~8 秒/平台） |
| 要装什么 | **什么都不用装**。只用 Python 标准库，不需要 pip install 任何东西 |
| 平台差异是真的吗 | 是。见下面「平台差异」一节，有实测数字 |
| 会瞎编数据吗 | 不提供 `--evidence` 就不许编数字，提示词里写死了这条约束 |

### 平台规格是数据，不是写死在提示词里

五个平台的字数区间、段长、段数、开场方式、结尾引导、标签数量、emoji 策略、
标题风格，全部放在 `scripts/run.py` 的 `PLATFORMS` 常量里，
**提示词和本地闸门都从这张表读**。

**改规格只改表，不改逻辑。** 完整表见 `references/platform-specs.md`，
也可以零成本看：`python3 scripts/run.py platforms`。

### 平台差异（实测，原稿 400 字 / 一次真实 `rewrite --all`）

| 平台 | 字数（区间） | 段数 | 均段长 | 标签 | 开场类型 | 实测标题 |
|---|---|---|---|---|---|---|
| 公众号 | 1335（1200~2200）✅ | 13 | **102.7** | 0 | 疑问式 | 二创被质疑不算原创，问题可能出在你讲的是剧情 |
| 小红书 | 396（350~800）✅ | 19 | 20.8 | 6 | 第一人称代入 | 做短剧二创，到底算不算原创啊😭 |
| 抖音 | 394（300~600）✅ | 26 | **15.2** | 4 | 劝阻/警告式 | 剪了三个月短剧，我才搞懂播放量为什么卡住 |
| 知乎 | 1075（800~1500）✅ | 12 | **89.6** | 3 | 结论前置 | 短剧二创被质疑不算原创，问题到底出在哪一步 |
| 头条 | 635（600~1200）✅ | 13 | 48.8 | 3 | 共鸣/现象式 | 剪了几十条播放量卡在几千，问题出在哪一步 |

**均段长从 15.2 字到 102.7 字，差 6.8 倍；开场类型五个各不相同；
字数五个平台全部落在区间内。** 这不是同一套话换皮。

对照：本地跨平台二元组相似度最高 **0.572**，只有 `小红书 ↔ 抖音` 这一对踩线
（阈值 0.55），被换皮闸门标出；其余 9 对都 ≤ 0.464。
**这一对是真实的难点**：小红书（350~800）和抖音（300~600）的目标长度区间重叠，
原稿只有 400 字，两个平台都在「把整个故事讲一遍」，很难不撞。
改法是在 `--brief` 里给其中一个换切入角度，或者接受这篇只有 3 个平台值得发。

**字数区间：这个包在这一项上返工过一次，值得说清楚。**

第一版提示词里写的是「没有把握时宁可贴住区间下限」，结果 5 个平台里 3 个不达标
（公众号 992/1200、抖音 284/300、头条 511/600）——**这句我自己写的"保险"提示词，
正是造成不达标的原因**。

改法是把「目标字数」算出来直接给模型（`目标 = 下限 + 35% × 区间长度`），
并把措辞从「宁可靠近下限」改成「**绝不能低于下限**，也不要顶到上限」。
改完同一份原稿再跑，**5 个平台全部落在区间内**（上表）。
所以 `platforms` 子命令里会额外打印一列「目标字数」——
它是算出来的，不是手填的，改区间会自动跟着变。

## 怎么用（命令行）

### 第 0 步：获取 API Key

到 **[api.a7w.cn](https://api.a7w.cn/)** 注册，创建一个 API Key（形如 `sk-...`）。

### 第 1 步：装依赖

**零依赖。** 不需要 `pip install` 任何东西，只要机器上有 Python 3.7+：

```bash
python3 --version
```

包里自带的 `scripts/a7w.py` 是零依赖客户端（只用 `urllib` / `json` / `mimetypes`），
`scripts/run.py` 也只用标准库。

### 第 2 步：填 Key

```bash
# Linux / macOS
export A7W_API_KEY=sk-你的key

# Windows PowerShell
$env:A7W_API_KEY="sk-你的key"
```

也可以存进配置文件反复用（推荐）：

```bash
python3 scripts/a7w.py login --key sk-你的key
```

### 第 3 步：先看规格表（免费，零网络）

```bash
python3 scripts/run.py platforms
```

这个命令不联网、不花钱，直接打印五个平台的完整规格。
**先看它，再决定要不要改 `PLATFORMS` 表。**

### 第 4 步：确认网关通（免费，不花点数）

```bash
python3 scripts/run.py models
```

这个命令打的是 `GET https://api.a7w.cn/api/v1/models`，会列出当前在架的模型。

> **模型名会变，一定用 `models` 子命令现查，别写死在脚本里。**
> 但要注意：`deepseek-chat` 这个别名**实测可用**，且**实测确认路由到 `deepseek-flash`**
> （看响应的 `model` 字段：请求 `deepseek-chat`，返回 `model: "deepseek-flash"`）。
> 而它**不在** `/api/v1/models` 的返回列表里（实测该列表给的是 `DeepSeek-V4-Pro` /
> `DeepSeek-V4-Flash` / `DeepSeek-V3.2` 这些**版本号名**，
> 响应里又变成小写的 `deepseek-v4-flash` / `deepseek-v3.2-think`）——
> 所以「列表里没有」不等于「不能用」，而且**列表名、请求名、响应名三者不一定一致**。
>
> 反过来也踩过一个坑：**`deepseek-flash` 当请求名用是失败的**——
> 实测 HTTP 200，但 `model:null`、内容为空、`usage` 也是空的（静默失败）。
> 它只是路由的**目标名**，不是可用的请求名。

### 第 5 步：先出方案，再改写

```bash
# 1) 出改写方案（一次调用，不写正文）
python3 scripts/run.py plan --file 原稿.md

# 2) 全平台改写，落盘 JSON
python3 scripts/run.py rewrite --file 原稿.md --all --json --out out.json

# 3) 结构性对比（纯本地，不花钱）
python3 scripts/run.py diff --file out.json
```

只想改一个平台：

```bash
python3 scripts/run.py rewrite --file 原稿.md --platform xiaohongshu
# 想改两个就重复写
python3 scripts/run.py rewrite --file 原稿.md --platform xiaohongshu --platform douyin
```

想先看不花钱的提示词：

```bash
python3 scripts/run.py rewrite --file 原稿.md --platform douyin --dry-run
```

### 完整工作流（含预算控制）

```bash
# 1) 先算钱（不调模型）。没给单价就只报 token，不给金额
python3 scripts/run.py cost --file 原稿.md --all

# 2) 给单价后算点数与金额；配上 --budget 就是硬上限
python3 scripts/run.py cost --file 原稿.md --all --price-in 1 --price-out 2 --budget 1

# 3) 带预算跑。超了就就地中止，退出码 5，不会把钱花出去
python3 scripts/run.py rewrite --file 原稿.md --all \
    --price-in 1 --price-out 2 --budget 1 --json --out out.json

# 4) 用真实 token 数核算（不是估算）
python3 scripts/run.py cost --from-result out.json --price-in 1 --price-out 2
```

### 直接用 curl 调（不依赖本包脚本）

改写底层就是一个标准的 OpenAI 兼容调用：

```bash
curl -sS -X POST "https://api.a7w.cn/api/v1/chat/completions" \
  -H "Authorization: Bearer $A7W_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "deepseek-chat",
    "messages": [{"role": "user", "content": "把下面这篇稿子改写成抖音口播稿规格，只输出 JSON：……"}],
    "temperature": 0.7,
    "max_tokens": 4096,
    "response_format": {"type": "json_object"}
  }'
```

> **成功响应不带 `code` 字段。** 实测调用成功时返回的就是标准 OpenAI 形态
> （`id` / `object` / `created` / `model` / `choices` / `usage` / `system_fingerprint`），
> `"code" in payload` 为 `False`。`code==1` 那套信封**只用于生成应用的响应**，
> 不适用于本端点——所以别拿 `code` 判成败。

## 参数说明

### 全局

| 参数 | 说明 |
|---|---|
| `--key` | 临时指定 Key；优先级最高。**别把它写进脚本或文档** |
| `--json` | 以 JSON 输出，**写在子命令前面或后面都可以**（`rewrite --json --out out.json` 可直接喂给 `diff` / `cost --from-result`）；JSON 模式下 stdout 只有一个完整 JSON，进度走 stderr |
| `--out <文件>` | 把结果写到文件 |
| `--model` | 模型名，默认 `deepseek-chat`（实测可用）。用 `models` 现查在架模型 |
| `--temperature` | 采样温度，默认 `0.7` |
| `--max-tokens` | 最大输出 token，默认 `4096`（公众号长文别低于这个数） |
| `--dry-run` | 只打印将发送的提示词，**不调模型、不花钱** |
| `--no-json-mode` | 不要求上游返回 JSON 对象（个别模型不支持 `response_format` 时用） |

### 原稿输入（`plan` / `rewrite` / `cost` 共用）

| 参数 | 说明 |
|---|---|
| `--file <文件>` | 原稿文件（`.md` / `.txt`）。自动剥掉 UTF-8 BOM |
| `--text "正文"` | 直接给原稿正文；与 `--file` 同时给时以 `--text` 为准 |
| `--platform <key>` | 目标平台，**可重复多次**：`--platform wechat --platform douyin` |
| `--all` | 全平台都跑（5 个）。与 `--platform` 同时给时以 `--all` 为准 |

平台 key：`wechat` / `xiaohongshu` / `douyin` / `zhihu` / `toutiao`。

### `plan` —— 出改写方案

| 参数 | 说明 |
|---|---|
| `--brief "要求"` | 改写要求（作者口述的意图） |

输出的方案含：`keep`（必须保留的信息点）、`cut`（可以砍的，附原因）、
`needs`（**原稿缺什么，如实说，不补编**）、每个平台的 `strategy` / `opening_plan` /
`ending_plan` / `est_chars`、以及 `risks`（这次最可能踩的坑）。

### `rewrite` —— 按平台改写

| 参数 | 说明 |
|---|---|
| `--brief "要求"` | 改写要求 |
| `--evidence "素材"` | 可以使用的真实素材。**没写就不许编数字** |
| `--price-in` | 输入单价（点/百万 token），配合 `--budget` 用 |
| `--price-out` | 输出单价（点/百万 token） |
| `--budget` | 预算上限（点）。超了就地中止，退出码 5 |

### `diff` —— 结构性对比（纯本地）

| 参数 | 说明 |
|---|---|
| `--file <结果.json>` | **必填**。`rewrite --json --out` 的结果文件 |

输出：各平台字数 / 段数 / 均段长 vs 原稿的 delta、开场类型、
**开场是否真的换了**（与原稿开场句相似度 < 0.6 才算换了）、
结尾引导与行动指令、与原稿的整体相似度，以及平台两两之间的相似度。
**不调模型、不花钱**，同一个文件跑两次结果完全一样。

### `cost` —— 只算钱

| 参数 | 说明 |
|---|---|
| `--file` / `--text` / `--platform` / `--all` | 按原稿估算 token 与费用 |
| `--from-result <结果.json>` | 读真实调用记录里的 token 数算钱（**不是估算**） |
| `--price-in` / `--price-out` | 单价，单位「点/百万 token」 |
| `--budget` | 预算上限（点）。给了 `--budget` 就必须给单价，否则退出码 2 |

**为什么不给默认单价**：实测接口的 `GET /api/v1/pricing` 只有 6 条规则
（一条全局 `*` + `full_video` / `asr` / `flashvsr` / `action_transfer` /
`person_replacement` 等特例），**不含文本大模型**；`GET /api/v1/models` 的
75 条记录里**也没有任何价格字段**；`chat/completions` 的成功响应里
`usage` 只有 `prompt_tokens` / `completion_tokens` / `total_tokens`，**没有点数**。
所以**拿不到可信的文本模型单价，本包拒绝凭空编一个**——
token 数我们估（实测标定），金额必须由你给单价。

### `platforms` —— 列规格表（零网络）

| 参数 | 说明 |
|---|---|
| `--json` | 输出整张规格表 + 平台红线 + 标定比例 |

### `models` —— 列出在架模型

| 参数 | 说明 |
|---|---|
| `--type` | 模型类型，默认 `text`；传 `all` 看全部 |
| `--json` | 原始 JSON |

### 六道硬闸门

**硬闸门 = 命中即拦截 + 标红 + stderr 汇总 + 退出码非 0。不许只警告。**

| # | 闸门 | 判什么 | 扣分 |
|---|---|---|---|
| 1 | **合规** | 广告法违禁词（最/第一/国家级/100%/绝对化/根治/保本/包过…）+ **平台特有红线**（小红书站外导流、知乎私域引流、抖音禁止外链…） | 高 40 / 中 20 / 低 8 |
| 2 | **占位符残留** | `{}`、`[待填]`、`XXX`、`（此处省略）`、`待补充`、`TODO`/`TBD`、`[请填写…]` | 40 |
| 3 | **`prompt_echo`** | 与提示词示例去标点后相等、字符二元组 Jaccard ≥ **0.75**、或示例二元组**覆盖度 ≥ 0.60**。标题比整条；正文**整段 + 逐句两层都查** | 30 |
| 4 | **字数区间** | 必须落在该平台的目标区间，超出/不足按偏离程度扣分 | 上限 60 |
| 5 | **结构完整性** | 必须有 标题 + 正文 + 结尾引导，且结尾要含**该平台的**行动指令 | 每项 25 |
| 6 | **成本上限** | `--budget` 超了就地中止（**用真实 usage 累计，超了就停**） | 退出码 5 |

外加一道**跨平台换皮检测**（本地）：两两比较正文的字符二元组 Jaccard，
两篇都 ≥ 200 字才比较，≥ **0.55** 判为疑似换皮 → 标红 + 退出码 3。

**为什么只有这五项算硬闸门**：硬闸门的标准是「发出去会出事」。
标题字数不够是**质量不达标**，合规违禁是**会被罚**，两者不是一回事。
话题标签数、emoji 策略、段落风格只扣分不拦截——
把风格问题也做成硬闸门，工具会在正常使用中频繁返回非 0，最后没人看退出码，闸门就废了。

### 退出码（可直接用于 CI）

| 退出码 | 含义 |
|---|---|
| `0` | 全部干净 |
| `2` | 参数/配置错误（例如给了 `--budget` 却没给单价） |
| `3` | **有硬闸门命中**（合规/占位符/照抄示例/字数区间/结构/跨平台换皮） |
| `4` | 调用失败（网络 / 鉴权 / 点数 / 模型名） |
| `5` | **预算超限，已就地中止** |
| `130` | 用户中断 |

**`--json` 输出契约**（给流水线与 agent 消费，**只在 `--json` 下生效**）：

- 成功：结果对象里多一个 `"ok": true`；顶层是数组时包成 `{"ok": true, "data": [...]}`
- 失败：stdout 输出一个 JSON 信封，形如
  `{"ok": false, "exit": 3, "error": {"kind": "gate", "message": "…"}}`（`exit` 就是本次真实退出码），
  `kind` 取 `gate` / `usage` / `budget` / `call` / `interrupt` / `internal`。
  `internal` 是**没预料到的异常**（代码 bug）的兜底：此时 stdout 给信封、
  **完整 traceback 原样打到 stderr**、退出码固定 1 —— 报 bug，不藏 bug
  —— 只有在**本次还没吐过任何 JSON 结果**时才补这个信封；已经吐过结果时
  （例如跑到一半才发现比例不合格），`ok` 就写在那个结果里，退出码不变
- 人读文案照旧走 stderr；**退出码语义一个都不变**；非 `--json` 模式输出与以前完全一致
- `--json` 写在子命令**前面或后面都可以**


### 三个真实事故写进了代码

**1. `prompt_echo`：模型会照抄提示词里的示例，哪怕标着「这是错的写法」。**

本库标题工坊实测过两次：提示词里写过的示例句子模型直接产出，
其中一次**一字不差就是提示词示例，而且拿了那一轮的最高分 89.0**——
最高分变成「抄标准答案」而不是「真的最好」，排序就废了。

所以本包：**提示词里不出现任何一句可复制的完整中文句子**，
举例只用描述性语言 + 登记在 `PROMPT_SAMPLES` 里的**跨主题**示例
（主题刻意选「电动车充电桩」，与三剪客真实业务明显不搭）；
万一有人把真实示例加回去，闸门会兜住。
**阈值 0.75 的标定依据**：196 条正常产出与跨主题示例的最高相似度只有 0.174，
而「少两个字的同构照抄」是 0.765——0.75 有 4 倍以上的安全距离。

**闸门写完必须用坏数据喂一遍。** 自测时发现原来只比「整段正文」是不行的：
正文 1000+ 字、示例二三十字，Jaccard 的分母被撑到 1000 多，
**模型把示例原样抄进正文的某一段时，这道闸门完全看不见**——
而长文场景下「抄示例」恰恰就是「有一段是抄的」。
所以改成整段比一次 + **逐句再比一次**。这个漏洞是喂罐头数据喂出来的，不是看代码看出来的。

**第二轮又补了第三条判据（覆盖度）。** 逐句比对的**比对单位是一句话**，
而拆句只在 `。！？；` 和换行处切、**不在逗号处切**：
模型把示例揉进自己那句话里（不在示例末尾断句）时，比对单位被撑到 30~36 字，
Jaccard 又被摊薄。实测（示例主题充电桩，去标点后 16~21 字）：

| 形态 | 逐句 Jaccard | 覆盖度 | 逐句层 | 加覆盖度后 |
|---|---|---|---|---|
| 示例1 独立成句 | 1.000 | 1.000 | 抓住 | 抓住 |
| 示例1 揉进长句（36 字） | 0.576 | **1.000** | **漏** | 抓住 |
| 示例2 揉进长句（33 字） | 0.645 | **1.000** | **漏** | 抓住 |
| 示例3 揉进长句（30 字） | 0.517 | **1.000** | **漏** | 抓住 |

五条示例的单句逃逸临界长度是 21~27 字，而长文里 27 字以上的句子是常态。
所以覆盖度不是与逐句层冗余，而是互补：**逐句层只兜得住「示例自己独立成句」**。
判定用 `ECHO_CONTAIN = 0.60`（示例二元组里有多大比例出现在被比对象中）；
长度守卫是相对的 `max(6, 示例长度/2)`。误伤实测：45 条真实历史句子/标题，
覆盖率最大只有 **0.105**（余量 5.7 倍），误伤 0 条。

**2. 一次调用写五个平台 = 换皮。**

如果让模型一次同时产出五个平台的稿子，它会先写最好写的那一份，
再裁剪成另外四份。所以本包**一个平台一次调用**，
并且在提示词里明确要求「不许整句搬运原稿措辞」「信息的出场顺序也可以不一样」。
实测把这两条加上之后，跨平台最高相似度从 **0.71 降到 0.525**（另一次跑是 0.572）。

**残留难点**：`小红书 ↔ 抖音` 这一对在本包里是最容易踩线的
（两者目标长度区间重叠，原稿短的时候都在讲同一个故事）。
闸门会把这一对标出来，但**不自动改**——改法是给它换切入角度，或者干脆不发那一篇。

**3. 合规闸门自己也会误伤，而误伤会让闸门废掉。**

实测原稿里有一句「回头翻一条自己播放量最低的视频」，
被「最X」规则判成高风险「广告法第九条禁止最高级用语」并整篇拦截。
**这个诊断是错的**——那是在描述自己的数据，不是商品宣称。
所以加了一条**很窄**的语境豁免：`最X` 前一个字是计量类名词（量/率/数/分/位/条/次/段/部/集/页/个/天/月/年）
且后面紧跟「的/之」时，**放过但在报告里登记**（`gates.compliance.exempted`）——
**不静默放过**。豁免词表刻意不含 `价/时/款/种/家`：
「课时最低的课程」「单价最低」都是真实的价格宣称形态，必须照拦。

### 成本口径（实测标定）

拿一次真实 `rewrite --all` 的 5 次调用，用 `usage` 除以实际字符数标定：

| 方向 | 标定值 | 平台间波动 |
|---|---|---|
| **输入** | 1 原始字符 ≈ **0.621** token（1 token ≈ 1.61 字） | 极小：5 个平台 1.609~1.615 |
| **输出** | 1 原始字符 ≈ **1.11** token | 较大：知乎 0.93 · 公众号 0.99 · 头条 1.18 · 小红书 1.33 · **抖音 1.63** |

输出侧平台间差异几乎全部来自**换行数**：抖音一句一行（18 行），
每个换行都是一个 token，所以最费。用哪个数都是**估算**，真实账单看账户流水。

## 排错

| 现象 / 报错 | 原因 | 怎么办 |
|---|---|---|
| `Missing or invalid relay API key`（HTTP 401） | Key 无效、已过期或写错 | 重新到 https://api.a7w.cn/ 领取；确认没把 `Bearer` 重复写进环境变量 |
| 点数不足（HTTP 402） | 账号点数用完 | 到 https://api.a7w.cn/ 充值后重试 |
| 模型不存在（HTTP 404） | 模型名写错或已下架 | `python3 scripts/run.py models` 现查在架模型名 |
| 上游 `502` / `upstream timeout` | 网关到上游的瞬时抖动，**实测很常见** | 脚本已内置退避重试（最多 4 次）。连续失败就换模型 |
| `配置错误：给了 --budget 就必须给单价` | 预算没有单价就没意义 | 补 `--price-in` / `--price-out`（点/百万 token） |
| `!! 预估成本 … 已超过 --budget … 就地中止` | 预估闸门在花钱之前就拦下了 | 跑单平台、调低 `--max-tokens`，或提高预算 |
| `!! 已花 … 点，超过 --budget` | 真实 usage 累计超了（退出码 5） | 已完成的平台结果仍会输出，从断点继续 |
| 字数标红「不在区间」 | 模型没数准字数。本包的提示词会给一个算出来的「目标字数」（下限 + 35% 区间），实测 5 平台全部达标；但换模型 / 换原稿仍可能偏 | 用 `--evidence "更多真实素材"` 给它东西写（**别加长度约束凑字**，那只会换来重复表达）；或调 `PLATFORMS` 里的区间 |
| `!! 有 N 个平台被硬闸门拦下` | 合规命中等 | 看 stderr 的逐条原因；改完重跑。退出码 3 |
| 合规命中「最X」但你看不出问题 | 可能是程度副词作描述（如「冲突最强的那一段」） | 已知过度报告的残留（同族「播放量最低的」已豁免）。要么改措辞，要么人工确认后放行；**不要改成只警告** |
| `!! 跨平台换皮` | 两个平台的正文太像 | 用 `diff` 看是哪一对；重跑该平台，或在 `--brief` 里指定该平台换一个切入角度 |
| `模型返回的不是合法 JSON` | 模型在 JSON 前后多吐了字符 | 脚本已用 `json.JSONDecoder().raw_decode()` 扫第一个完整对象。仍失败就加 `--no-json-mode` 并换模型 |
| `模型没返回 choices` / 产出为空 | 输出被 `max_tokens` 截断 | 加大 `--max-tokens`（公众号长文建议 4096 以上）。**注意下面那条推理模型的坑** |
| 换了在架模型后正文被截断、或只吐出一段思考 | **实测 `models` 列表里的 `DeepSeek-V4-Pro` 与 `DeepSeek-V3.2` 是推理模型**，会先花 completion token 出思维链再给答案。实测一句两字的回复：`DeepSeek-V3.2`（路由到 `deepseek-v3.2-think`）花掉 **105** 个 reasoning token，`DeepSeek-V4-Pro` 花掉 **54** 个 | 用默认的 `deepseek-chat`（实测非推理、最快）；非要用推理模型就把 `--max-tokens` 提高 1.5~2 倍 |
| HTTP 200 但 `model:null`、内容为空、usage 为空 | 实测把 `deepseek-flash`（`deepseek-chat` 的路由**目标名**）当**请求名**用就是这个结果——**静默失败**，状态码骗人。脚本会报「模型没返回 choices」而不是产出空文件 | 请求名用 `deepseek-chat`；要换模型就用 `models` 列表里的名字（如 `DeepSeek-V4-Flash`） |
| `参数错误：找不到原稿文件` / `结果文件不是合法 JSON`（退出码 2） | 路径写错，或 `diff` / `cost --from-result` 拿到的不是本包生成的结果文件 | 这两个命令要的是 `rewrite --json --out` 生成的**结果文件**，不是原稿。检查路径 |
| 原稿第一个字是乱码 / 字数偏 1 | UTF-8 BOM（Windows `Out-File`、记事本另存为） | 脚本已自动剥掉 BOM；若仍异常，把原稿另存为「UTF-8 无 BOM」 |
| Windows 下中文乱码 | 控制台代码页不是 UTF-8 | `chcp 65001`，或加 `PYTHONIOENCODING=utf-8` |

**收集排错信息时请附上**：完整命令、`--dry-run` 的输出、原始报错文本、退出码。
**不要在报错信息或截图里带上你的 API Key。**
