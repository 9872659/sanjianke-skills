# 发散方法库

发散阶段唯一的任务是**把宽度铺出来**，不判断质量。这一份资料解决三件事：从哪六个口子进去问、怎么在 20 分钟里凑够 15 个候选、卡住不动时怎么救。

---

## 一、发散的物理前提

在讲方法之前，先立三条会决定成败的物理规矩。它们跟"技巧"无关，但不做这三件事，任何技巧都会失效。

### 1. 先写问题陈述，再开始想

问题陈述的固定形状：

```text
在〔真实约束〕下，让〔对象〕达到〔可观测的结果〕。
```

- **真实约束**：时间、预算、人手、合规、已有的技术栈、已经签的承诺。写"尽量快""尽量省"等于没写约束。
- **对象**：具体到人或具体的系统，不是"用户"这种笼统说法。
- **可观测的结果**：一个月后能拿什么数字或事实来判定做没做成。写"体验更好"不算。

三个位置空一个，就先补问题，别急着发散。**问题错了，发散的宽度会全部浪费在错误的方向上。**

### 2. 不评判要变成一条可执行的规则，而不是一种态度

"大家不要急着否定"这种话没有约束力。可执行的版本是：

> **任何否定、担忧、疑问，都不许当场说出口，一律先写进"暂存区"。**

暂存区就是一张两列的纸：左边写否定的内容，右边写它是针对哪个候选的。发散结束时才允许回看。这样做的意义不是让人憋着，而是让**否定不再打断产出节奏**——因为一次否定平均会让接下来 3 分钟没人提新东西。

### 3. 每说一个候选，必须编号并写下来

口头说过但没写下来的候选，在收敛阶段会消失。消失的通常是那个"听起来不太对"的——也就是最可能有价值的那个。规矩是：

> **候选池是唯一的真相来源。没进候选池的东西，在收敛阶段不存在。**

---

## 二、六类发散入口

每类入口的价值不是"换个角度"，而是**专门补某一类系统性盲区**。同一个问题上用不同入口，得到的是不同形状的解空间。

选入口的原则：**至少 3 类，且优先选你最不想选的那一类。**最不想选的那类通常正对着你的盲区。

---

### 入口 1 · 目标反推

**补的盲区**：路径依赖——你一直在优化"怎么做现在这件事"，而不是"怎么达到结果"。

核心动作是**把手段和目标切开**。先写下目标，然后强迫自己列举**不通过当前手段**也能达到目标的路径。

问句库：

- 如果现在这套做法完全不允许使用，还有什么办法能达到同样的结果？
- 这个目标里，哪一个词是硬的（真的不能改），哪一个词其实是习惯？
- 假设预算只有现在的十分之一，最省的那条路长什么样？
- 假设预算十倍，完全不受限的那条路长什么样？它比现在这条路好在哪？
- 如果必须明天就交付一个能跑的版本，我会砍掉什么、留下什么？
- 这个目标是为谁设的？如果把"为谁"换掉，目标还成立吗？

**产出目标**：≥ 3 个候选。理想情况下，至少一个候选不含你现在方案里的核心组件。

**常见陷阱**：把"用另一种技术做同一件事"当成反推。那还是同一条路，只是换了零件。判据是——**如果这条路径成功，它会改变你后续要做的事吗？**不会，就还不是本质不同。

---

### 入口 2 · 现状拆解

**补的盲区**：惯性冗余——因为一直这么做，所以没人问这些步骤还在不在。

核心动作是**把现状拆成步骤，然后逐个问"整段拿掉会怎样"**。

问句库：

- 现在这套流程有几步？每一步的产出是什么？哪一步的产出其实没人看？
- 哪一步是"以前需要、现在不需要"的？它当初为什么存在？
- 如果只能保留两步，保留哪两步？
- 哪一步的耗时最长但价值最低？
- 这个环节存在的理由是"风险控制"吗？它真的控制住了哪一个具体风险，有记录吗？
- 把这一步自动化之后，人还需不需要复核？如果不需要，为什么现在还在复核？

**产出目标**：≥ 3 个候选，每个候选的形式是"删掉 X 步 / 合并 X 和 Y / 把 X 挪到后面"。

**常见陷阱**：只敢拆执行层，不敢拆决策层。真正贵的往往是审批、复核、对齐这些"看起来不出活"的步骤。

---

### 入口 3 · 类比迁移

**补的盲区**：视野窄——只在这个行业、这个领域里找解，而同类难点在别处早被解过。

核心动作不是"找个像的东西"，而是**先把难点抽象成一句话，再去找同样有这句话的场景**。

抽象句式：「在一个〔条件〕的环境里，要让〔对象〕做到〔结果〕，而资源只有〔限制〕。」

问句库：

- 这个难点的抽象形态是什么？哪个行业天天在解这道题？
- 谁已经花了十年解决类似问题？他们的标准解法是什么？
- 有没有一个更小的领域，那里的做法可以直接搬过来？
- 物理世界怎么解这个问题？（排队、分诊、缓存、限流其实都来自现实场景）
- 如果把时间尺度换掉——按天做不到的事，按季度怎么做？
- 有没有一个失败案例，它的做法刚好是我的备选方案？

**产出目标**：≥ 3 个候选，每个必须写清"从哪来、凭什么能迁移过来、哪里不一样"。

**常见陷阱**：迁移了表面形式，没迁移约束条件。类比必须有一步"哪里不一样"的检查，否则会得到看起来很美但落不了地的候选。

---

### 入口 4 · 反向求解

**补的盲区**：风险盲区——正向思考天然倾向于找可行路径，看不见失败路径。

核心动作是**把问题倒过来问：怎么让这件事彻底失败？**

问句库：

- 如果我是想搞垮这个项目的人，我会攻击哪里？
- 要保证半年后这件事毫无成果，最有效的做法是什么？
- 什么情况下一上线就出事故？出的是什么事故？
- 哪个环节只有一个人懂？他离职了怎么办？
- 什么样的数据会让我承认这条路走不通？我现在有采集它吗？
- 最坏情况能坏到什么程度？它可逆吗？恢复要多久？
- 有没有一种失败是"表面成功但目标没达成"？

**产出目标**：≥ 3 个候选。反向入口产出的往往不是"另一个方案"，而是**给已有候选加装条件**（比如"先做灰度""先补监控"），这也是合法的候选。

**关键提醒**：反向入口的候选要**照常编号进池**，不要在发散阶段就把它们当作"风险备注"记在旁边。它们是方案的一部分。

---

### 入口 5 · 维度切分

**补的盲区**：一刀切——用一个方案覆盖所有情况，结果对每类情况都不最优。

核心动作是**先找切分维度，再在每个维度上问"分块后的最优解"**。

常用切分维度（挑 2~3 个用，不要全用）：

| 维度 | 切出来的块 |
|---|---|
| 人群 | 新用户 / 老用户 / 高价值 / 长尾 |
| 场景 | 高频刚需 / 低频高价值 / 应急 |
| 渠道 | 站内 / 站外 / 私域 / 合作 |
| 时段 | 平时 / 高峰期 / 异常期 |
| 成熟度 | 从零开始 / 已有存量 / 已有惯性 |
| 规模 | 单点验证 / 小批量 / 规模化 |

问句库：

- 哪一类人最痛？如果只服务这一类人，方案会变成什么样？
- 有没有一类情况可以完全不管？明确不管，方案能简化多少？
- 能不能前 10% 用 A 方案、后 90% 用 B 方案？拼装版的候选长什么样？
- 如果按规模分两段，第一段和第二段的最优解是同一个吗？
- 哪些块之间有冲突？冲突时牺牲谁？

**产出目标**：≥ 3 个候选，形式包括"只做 X 类""按 Y 分两阶段""A 管前段 B 管后段"。

**常见陷阱**：切得很细但没合并，产出 20 个碎片而不是 3 个方案。切分的目的是**重新组合**，不是无限细分。

---

### 入口 6 · 干系人换位

**补的盲区**：单方视角——方案只对提出它的人最优。

核心动作是**逐一把方案放到别人的位置上过一遍**，看他最在意什么、最怕什么。

换位清单：

| 干系人 | 问他一句 | 他要的 | 他怕的 |
|---|---|---|---|
| 最终用户 | 我为什么要在意这个？ | 立刻省事 | 学新东西 / 被改变习惯 |
| 审核 / 合规 | 这条能不能过？依据是什么？ | 有出处、可追溯 | 无先例、责任不清 |
| 一线执行者 | 这活儿落到我头上是什么样？ | 少加活、少背锅 | 增加了动作却不减负 |
| 运维 / 客服 | 出问题时我怎么发现、怎么处理？ | 可观测、可回滚 | 静默失败 |
| 财务 / 审批 | 这笔钱怎么算、算谁的？ | 口径统一 | 沉没成本无出口 |
| 下游消费者 | 上游改了我要不要跟着改？ | 接口稳定 | 被迫返工 |

问句库：

- 如果我是最不想配合的那个人，我会用什么理由拒绝？
- 这个方案里，谁的工作量增加了？他被说服了吗？
- 哪个干系人到现在还没被问过？
- 如果只能让一个人满意，应该是谁？为什么是他？

**产出目标**：≥ 3 个候选，形式通常是"把触发时机换掉""把默认值反过来""先给谁看不给谁看"。

**常见陷阱**：把换位做成"替别人想他很需要这个"，那是自我确认。真正的换位会产出**与你原意相反**的候选。

---

## 三、二十分钟凑够十五个：扩量技巧

数量目标（≥ 15 个 / ≥ 4 条本质不同路线）看起来吓人，实际用下面五个动作可以稳定达标。

**动作 1 · 强制配额，不做筛选**
每类入口硬性 3 个，选 3 类就是 9 个，选 6 类就是 18 个。配额的作用是**堵住"够了"这个念头**——第 3 个候选永远比第 1 个难想，第 3 个往往才是好材料。

**动作 2 · 反转已有候选**
拿已经写下的每一个候选，问"它的反面是什么"。反面通常是一个合法候选（"每天推一次"的反面是"用户来才给"）。这个动作几乎不花思考成本，却能让池子翻倍。

**动作 3 · 极端参数法**
把某个参数推到荒谬值，看方案变形：预算 ÷10、×10；时间 ÷10、×10；人数 1 人、100 人；覆盖 1 个用户、全部用户。每次极端化都会逼出一条新路线。

**动作 4 · 加法与减法各来一遍**
- **减法**：从现方案里删掉一个组件，剩下的还能跑吗？能跑就是新候选。
- **加法**：加上一个组件（一层审核、一个缓存、一个兜底），变好还是变重？也是新候选。

**动作 5 · 三分钟静默书写**
所有人不说话，各自写 3 分钟，写完再统一念。这一个动作解决的是一言堂——**第一个开口的人会锚定所有人的思路**，静默书写是唯一能真正绕开锚定的做法。

---

## 四、卡住不动时怎么办

发散到第 8~10 个候选时几乎必然会卡。卡住是正常现象，不是失败信号。按下面的顺序试：

| 症状 | 处理动作 |
|---|---|
| 想不出新的，觉得"该想的都想了" | 换一个入口，不要在原入口里硬想。入口 4（反向）和入口 5（切分）最容易破冰 |
| 想到的都是同类 | 强制"这一条必须跟前面任何一条都不共享核心组件"，逼出异类 |
| 有人开始说"这个不现实" | 立刻记入暂存区，并追问："那什么样的条件下它才会现实？"——这个问题本身常产出一个新候选 |
| 全场沉默 | 上三分钟静默书写，不许口头讨论 |
| 讨论开始收敛到某个方案 | 明确宣布"现在是发散时间"，并让每个人再写 2 条 |
| 候选越写越细，变成实现细节 | 把粒度拉回方案层：一句话说清"做的是什么、不做的是什么" |
| 出现"这个我们已经试过了" | 记进候选池，并在旁边写"上次失败的具体原因是什么"——失败原因往往指出一个未被尝试的变体 |

**一条底线**：卡住时**不要降低数量目标**。宁可换入口重来一轮，也不要带着 8 个候选进收敛阶段。

## 五、发散不足的修复路径

如果自检查出「发散不足」，按命中体征对症修：

| 命中体征 | 修复动作 |
|---|---|
| 数量不够（< 10） | 换 2 个没用过的入口，每类补 3 个；用扩量技巧的动作 2、3 |
| 同源（说不出根本分歧） | 做一次"强制异类"：新候选不许与已有候选共享核心组件；用入口 1 的预算 ÷10 / ×10 两问各产 1 个 |
| 无代价（全是安全牌） | 用入口 4（反向求解）产出失败路径；再补一个"资源十倍"候选 |
| 无前提拆解 | 回到问题陈述，追问三句：这事非得做吗？非得现在做吗？非得做成这个形状吗？每一句产出一个候选 |
| 太快（< 15 分钟） | 作废本轮，重新开；加三分钟静默书写 |
| 一言堂 | 全员静默书写后统一念；念的顺序从职位最低的人开始 |

修复完之后**重新跑一遍发散不足自查**，仍然命中 2 条以上就再修一轮。这里多花 15 分钟，比在收敛阶段拿 8 个同源候选假装做选择便宜得多。

## 六、发散阶段的产出模板

填完这张表才算出阶段：

```text
问题陈述：在〔约束〕下，让〔对象〕达到〔结果〕。

候选池
| 编号 | 一句话说明（做的是什么 / 不做的是什么） | 入口 | 本质路线 |
|---|---|---|---|
| A1 | | 目标反推 | 路线一 |
| A2 | | 目标反推 | 路线一 |
| A3 | | 目标反推 | 路线二 |
| ... | | | |

本质路线归纳
- 路线一：（一句话说清它的根本主张）
- 路线二：
- 路线三：
- 路线四：

暂存区（发散期禁止讨论的否定意见）
| 针对候选 | 内容 |
|---|---|

阶段门自查：发散不足六体征命中 ___ 条（≥2 条不许进收敛）
```

**"本质路线"这一列是这份表的关键。**它逼你回答"这些候选到底有没有真的不一样"。如果 A1~A15 只能归纳出 2 条路线，那这一轮发散的宽度是不够的，数量再多也没用。
