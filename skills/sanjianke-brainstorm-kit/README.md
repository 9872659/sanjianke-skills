# 三剪客 · 发散与收敛 Skill

先用多个方向把方案铺开，再按统一标尺收敛成一个，专治想到第一个方案就开干

---

## 前置条件

本 Skill 不内嵌任何密钥，也不调用任何第三方接口；它是一套思考协议，不含代码依赖。

## 使用

最小可用路径，四步，一轮 40~60 分钟或一次对话：

1. **写问题陈述**（3 分钟）。一句话，形如「在〔约束〕下，让〔对象〕达到〔可观测的结果〕」。约束必须是真的（时间、预算、人手、合规），不是「尽量」。
2. **发散**（20~30 分钟）。从六类入口里**至少选 3 类**，每类硬性产出 3 个候选，累计 **≥ 15 个**，其中**≥ 4 个属于本质不同的路线**。全程不评判，任何「这个不行」都记到暂存区里，不打断。
3. **过阶段门**。用「发散不足六体征」自查，命中 2 条以上就回到第 2 步换入口重来。
4. **收敛**（15~25 分钟）。用五维打分卡给**每一个**候选打分，按淘汰规则砍到 1 个主选 + 1 个备选，写下决策记录（选了什么、砍了什么、关键判据是什么、什么条件下翻案）。

产出物固定为三张表：**候选池**（编号 + 一句话 + 来自哪类入口）、**打分卡**（候选 × 五维 + 总分 + 理由）、**决策记录**（主选 / 备选 / 淘汰名单 / 翻案条件）。

完整走一遍看 `references/03-worked-example.md`。

## 依赖

- 一个说清楚的问题陈述：约束、对象、可观测的结果。三样缺一样就先补问题，不要开始发散
- 至少 2 个参与者（真实的人，或宿主 Agent 扮演的不同视角角色）。单人发散几乎必然同源
- 一场 40 分钟以上不被打断的时间，或一次完整对话。中途换上下文会毁掉发散阶段的不评判氛围
- 不需要任何工具、账号、网络；一张能记下 15 行候选的纸或文档即可
