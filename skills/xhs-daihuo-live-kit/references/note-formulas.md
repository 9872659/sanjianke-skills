# 商品笔记公式

## 1. 标题：五种钩子，一次给五条

同一篇笔记先写 5 条标题，分属不同钩子类型，再挑一条做正文标题。

### 痛点型 —— 人群 + 具体窘境

- 租房党最怕的衣柜味道，被这招解决了
- 小桌子放不下东西，我最后只留了这一件
- 早上赶时间做早饭，这个救了我

### 对比型 —— 之前 vs 之后

- 用了两周，我把旧的那个扔了
- 从 199 换到 89，我没觉得降级
- 试过四种除味方式，只留下这个

### 攻略型 —— 数字 + 清单

- 3 个细节，判断这个到底值不值
- 买收纳盒前先看这 4 点，能省一半钱
- 5 个尺码问题，问清楚再下单

### 反常识型 —— 否定共识

- 别再买贵的了，这个反而更耐用
- 收纳不是买更多盒子，而是先扔东西
- 香味越浓的除味剂，越要小心

### 价格型 —— 价格锚点 + 结果

- 89 块的快乐，比想象中耐用
- 一顿饭钱，换回一整年不返味
- 五十块以内，我回购了三次

**硬性要求**：

- 每条 ≤ 20 字，手机上一行能看完
- 至少含 1 个用户会去搜的词（收纳、敏感肌、通勤、租房）
- 不用极限词（最、第一、根治、全网最低）
- 不出现联系方式、外站平台名

## 2. 正文：三段式骨架

```
[开头 2 行]  关我什么事 —— 用场景把人拉进来
[中间 3–6 段] 证据 —— 参数、实测、对比、真实体验
[结尾 2 行]  行动指令 —— 什么情况下适合买、怎么用
```

### 开头

- 第一人称，交代身份与场景：「租房三年，我试过四种除味方式」
- 第二行给出价值：「最后只留下这个，因为两点」
- **禁止**以「本产品」「该商品」开头

### 中间（证据）

- 一个卖点一段，不堆砌
- 具体 > 形容词：「续航 12 小时」而不是「续航超长」
- 有实测讲实测（数据必须真实可验证），没有就写使用感受
- **至少给 1 个「不适合谁」的反向说明**，可信度显著提高
- 每 3–4 行断句，单行不超过 60 字

### 结尾

- 给行动指令：「如果你也是 xx 情况，直接买基础款就够」
- 不要用「赶紧下单」「手慢无」这类逼单话术（那是直播的语言）

## 3. 分品类内容角度

| 品类 | 最有效的角度 | 必须出现的信息 |
|---|---|---|
| 家居清洁 | 脏→干净对比、低成本改造 | 容量、适用面积、是否留味 |
| 食品 | 口感描述 + 食用场景 | 净含量、保质期、储存方式 |
| 美妆护肤 | 肤质 + 使用周期记录 | 成分、适用肤质、注意事项 |
| 服饰 | 身高体重 + 尺码适配 | 尺码表、材质、版型 |
| 3C 数码 | 参数翻译成体验 | 续航、接口、兼容性 |
| 母婴 | 月龄分段 + 安全细节 | 材质、适龄、清洗方式 |
| 家电 | 解决什么家务负担 | 功率、噪音、占地、售后 |

详细打法见 `references/category-playbooks.md`。

## 4. 话题标签：6–10 个的组合公式

```
1 个大词（品类/场景）
+ 2–3 个精准词（人群/痛点）
+ 1 个长尾词（具体问题）
+ 1–2 个品牌词 / 品类词
```

- 大词流量大但竞争重，最多 2 个
- 精准词是转化主力，优先保证
- 长尾词用来抓搜索意图明确的用户
- 不要 10 个全是大词，也不要堆无关热词

## 5. 封面大字：≤ 9 字，独立可懂

| 原则 | 说明 |
|---|---|
| 独立可懂 | 不看正文也知道在说什么 |
| 有对象 | 点出人群或场景，而不是只写商品名 |
| 有信息 | 给一个具体数字或结论 |
| 不违规 | 不用「最」「第一」「根治」 |
| 不复述标题 | 封面和标题应该是两句不同的话 |

示例结构：`人群 + 结论`（租房党 别再买贵的）｜`数字 + 结果`（用两周 换掉旧的）。

### 3:4 竖版封面构图规范

小红书封面是 3:4 竖版（建议 1242 × 1660 px）。给设计或出图工具时按这套规则：

| 区域 | 占比 | 内容 |
|---|---|---|
| 上部留白 | 顶部 15% | 不放文字，避免被顶部元素遮挡 |
| 主体画面 | 中部 55% | 产品/场景实拍，主体不居中偏下 |
| 大字号 | 下部 30% | 大字文案，左对齐，最多 2 行 |
| 安全边距 | 四周 8% | 文字不贴边 |

**排版规则**：

- 大字最多 2 行，每行不超过 9 字
- 字号要保证在信息流缩略图尺寸下仍能看清（以手机端 1/3 屏宽预览为准）
- 文字与背景对比要够，深底浅字或浅底深字，不要用花哨字体
- 一屏一个信息点，不要封面塞卖点清单

## 6. 常见失败模式

| 现象 | 原因 | 改法 |
|---|---|---|
| 曝光高、点击低 | 封面与标题没给理由 | 标题改成痛点型或对比型 |
| 点击高、互动低 | 正文全是形容词 | 换成具体参数与实测 |
| 互动高、转化低 | 没交代使用场景 | 补「适合谁 / 不适合谁」 |
| 数据好但被限流 | 命中违禁词或导流词 | 跑 `compliance_check.py` |
| 每篇都差不多 | 一个钩子写到底 | 五类钩子轮换 |
| 收藏高但涨粉少 | 内容无个人标识 | 加入稳定的身份与立场 |

## 7. 交付格式（严格遵循，脚本依赖此格式）

`note_score.py` 按下面的结构解析，务必保持一致：

```
## 标题候选
1. 标题一
2. 标题二
3. 标题三
4. 标题四
5. 标题五
## 正文
第一段……
第二段……
## 标签
#标签1 #标签2 #标签3 #标签4 #标签5 #标签6
## 封面大字
1. 大字一
2. 大字二
3. 大字三
```

交付后自检：

```bash
python3 scripts/note_score.py --file note.md            # 打分与改进项
python3 scripts/compliance_check.py --file note.md      # 合规扫描
```

完整交付模板：

```

## 正文

【合规自检】high x ｜ medium x
```
