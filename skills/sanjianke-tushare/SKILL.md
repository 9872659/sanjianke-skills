# 三剪客 · A股行情与财务数据接口

要给策略、研报或数据看板喂 A 股行情和财务数据时，真正的麻烦不是算，而是「数据从哪来、字段怎么对齐、频率会不会被掐」。这个工具把这条链路收敛成两件事：注册拿一个 token，然后调接口——返回的通常是可以直接进 pandas 的 DataFrame。

它的价值在于**接口覆盖面广且调用范式统一**：行情、财务三表、指数、基金、期货、可转债、港股美股、宏观数据共用同一套写法，学会一个接口，其余接口基本照搬。

**上游项目**：`tushare`　**仓库**：https://github.com/waditu/tushare

## 什么时候用 / 不用

**用它**：

- 用户说「拉一下某只票或某段区间的日线 / 周线 / 月线」，或者「把全市场某天的行情导出来」。
- 需要上市公司的结构化财务数据：利润表、资产负债表、现金流量表、财务指标、业绩预告 / 快报。
- 要按股票列表、交易日历、指数成分、行业分类这类基础数据搭一张自己的分析底表。
- 做因子或回测，需要复权行情、每日指标、涨跌停价、停复牌、资金流向、龙虎榜这类衍生数据。
- 需要把数据落到本地数据库或 CSV 长期积累，而不是每次现查现算。

**不要用它**：

- **要逐笔成交（Level-2 / 秒级 tick）做高频**。高频与 Tick 级数据的权限门槛明显更高，普通账号不保证拿得到完整数据；这类需求要单独确认权限或换数据源。
- **要盘中实时推送行情**。它的主体是「按交易日拉取入库」的离线取数方式，不是行情推送通道。
- **要下单、交易、账户资金操作**。它只提供数据，不提供任何委托或账户能力。
- **没有 token、也没有对应积分就想拉全量**。接口按积分分级授权，频次按积分分档；没确认权限前不要承诺「全市场历史数据都能拉下来」。
- **只是本地已有 CSV，想画个图**。那是可视化库的活，不必绕到这里。

```bash
conda activate tushare
```

```bash

pip install tushare --upgrade
```

```bash

```

```bash

```

## 常用操作

**1. 拿 token 并初始化 Pro 接口**

token 在平台个人中心的「账号与TOKEN」里获取；它是调取数据的唯一凭证，若怀疑泄露，可在同一页面刷新使其作废。

```python
import os
import tushare as ts

# 推荐走环境变量，不要把 token 写死进代码或提交进仓库
pro = ts.pro_api(os.environ["TUSHARE_TOKEN"])
# 也可以先设置全局 token，再直接 pro_api()
# ts.set_token(os.environ["TUSHARE_TOKEN"])
# pro = ts.pro_api()
```

**2. 取单只股票的区间日线（未复权）**

```python
df = pro.daily(ts_code="000001.SZ", start_date="20180701", end_date="20180718")
print(df.head())
```

**3. 取某个交易日的全市场行情（推荐写法）**

```python
# 按交易日取全市场，比按代码循环高效得多
df = pro.daily(trade_date="20180810")
```

**4. 只取需要的字段，减少返回体积**

```python
df = pro.daily(trade_date="20180810", fields="ts_code,open,high,low,close,vol,amount")
```

**5. 拿基础底表：股票列表与交易日历**

```python
stocks = pro.stock_basic(exchange="", list_status="L",
                         fields="ts_code,symbol,name,area,industry,list_date")
cal = pro.trade_cal(exchange="SSE", start_date="20240101", end_date="20240131")
```

**6. 取财务数据（以利润表为例）**

```python
income = pro.income(ts_code="000001.SZ", start_date="20200101", end_date="20231231")
```

**7. 不走 Python SDK：直接用 HTTP 取数**

平台另提供 HTTP 获取方式，适合非 Python 环境或只想快速验证。端点、请求体字段与返回结构请以官方文档「获取方式 · 通过HTTP获取数据」的当前内容为准。

**8. 落到本地长期积累**

```python
df = pro.daily(trade_date="20180810")
df.to_csv("daily_20180810.csv", index=False)   # 也可写 MySQL / MongoDB
```

## 常见坑

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 提示 token 无效或取不到数据 | token 没设置、复制错、被刷新过，或该接口需要更高积分 | 到个人中心「账号与TOKEN」重新复制；用 `ts.set_token()` / `pro_api(token)` 显式传入后重试；再确认接口的积分门槛 |
| 提示没有访问该接口的权限 | 接口按积分分级授权，积分不够就是拿不到 | 换用当前积分档可用的接口，或按平台规则提升权限；不要靠反复重试解决 |
| 请求被限流、报频率超限 | 调取频次按积分分档（基础档为每分钟若干次量级），循环里高频调用极易触发 | 拉全市场历史用「循环日期」而不是「循环 ts_code」；批量请求之间加节流；结果及时落盘复用 |
| 日期条件查不到数据、结果为空 | 日期必须是 `YYYYMMDD` 格式，写成 `2018-07-18` 不会被解析 | 统一用 `YYYYMMDD` 字符串；先用交易日历接口确认该日确实是交易日 |
| 股票代码查不到 | 代码需要交易所后缀，`000001` 与 `000001.SZ` 不是一回事 | 用规范后缀：沪市 `.SH`、深市 `.SZ`、北交所 `.BJ`、港股 `.HK`；先跑 `stock_basic` 拿正确代码 |
| 拿到的价格和行情软件对不上 | `daily` 是**未复权**行情，且停牌期间不提供数据 | 复权场景改用复权行情 / 复权因子类接口；对齐口径前先确认对方用的是前复权还是后复权 |
| 照旧文档写的 `get_hist_data` 之类接口跑不通 | 仓库 README 记录的是旧版接口，新平台接口在站点上维护，两套并不通用 | 以平台站点的数据接口文档为准；旧接口只作参考，不要混用两套 API |
| 单次拉全市场多年历史特别慢甚至中断 | 单次返回有行数上限，跨年数据必然要分段 | 按交易日或按年份切段循环，每段落盘；避免在交互式会话里跑超长循环 |

## 能力边界

**覆盖**：

- 数据域：股票（行情、基础数据、财务、参考数据、特色数据、资金流向、两融）、指数、公募基金、期货、期权、可转债与债券、外汇、港股、美股、宏观经济。
- 取数方式：Python SDK（`pro_api()` 后按接口名调用）与 HTTP 接口两种。
- 数据形态：以结构化表格为主，便于直接进 pandas、落库、参与后续计算。
- 交易日历、股票列表、复权因子等配套底表，可用来对齐时间轴与代码体系。

**不覆盖**：

- 不做交易执行、下单、账户与资金操作。
- 不提供行情推送通道；盘中实时数据的获取方式与权限需单独确认。
- 不做回测框架、指标计算、选股策略——它只给数据。
- 不做数据清洗与缺失值修补；复权口径、单位等字段语义要使用者自己确认。
- 高频 / Tick 级数据权限门槛较高，普通账号不保证可得。

## 依赖条件

- Python 3 运行环境。
- pandas（安装时作为依赖一并装好）。
- 平台账号与 token；部分接口还需满足对应的积分要求。
- 网络可访问数据平台；受限网络环境需自行确认出口是否放行。
- 需要长期积累数据时，自备存储（本地文件、MySQL、MongoDB 等）。

## 已知限制

- 接口按积分分级授权，且有每分钟调用次数与单次返回行数上限，全量历史必须分段拉取。
- `daily` 等接口是未复权口径，复权要另取；停牌日不提供数据。
- 仓库 README 记录的旧版接口与新平台接口不通用，混用会踩坑；接口清单以平台站点文档为准。
- 平台的接口、积分规则与频次档位会调整，执行前应以官方文档当前内容为准。
- 具体版本号、发布日期与 star 数请以仓库及 PyPI 页面实时信息为准，此处不做断言。
