## 三条干货（别人不写进文档的）

1. **数字人那条 schema 接口是收费的。** `GET /api/v1/apps/pic_lipsync` 会命中 `/apps/<app>/*` 的通配计价，按该应用 flat 单价即时扣费、不退（实测 dressing_diffusion 200 点、nano_banana 72 点各一笔）。本包只用 `GET /api/v1/apps` 列表 + `GET /api/v1/pricing` 两条 cost:0 确认 pic_lipsync 在架，`doctor` 一条 submit 都不发。
2. **「缺参数会停在扣费之前」在 pic_lipsync 上不成立。** `/submit` 是 reserve_sync 口径：先按秒冻结点数，再参数校验，再全额退——净额 0，但钱包被短暂动过。所以本包不给它做探针，估时直接按 15 点/秒算。
3. **text 模式自带口播，一条片子只要一次 avatar。** `content` 给文案，`audio_url` 只当参考音色，数字人段不用再单独出 tts；只有空镜那段才走 `voice`。顺手记一条：pic_lipsync 输出实测 480x832 / 24fps，成片合成时再放大到 1080x1920。

## 合规检查（`qc` 已经做成默认动作）

- **六类限定零出现**：年龄、性别、婚育、户籍、身高体重、形象。岗位要求换成能力描述：「能独立负责一条业务线」比「35 岁以下」招得准。
- **薪资写区间与结构**：`15-25K·14薪` 一处一个数字，「薪资面议」这类写法换掉。
- **招聘主体照写**：公司全称写进文案，内推码与官网入口一致，投递入口带截止日期。
- **成长路径给具体名词**：职级表起点与终点、训练营名字、导师带教、轮岗月数、去年走通的人数与平均年限。
- **夸大与承诺换成可核对数字**：团队人数、晋升年限、截止日期、初筛时效；员工见证写事不写形容词（14 字内讲一件具体的事）。

退出码：`0` 成功 / `2` 用法错 / `3` 自检或合规没过 / `4` 缺 `--yes` / `5` 超预算且一个请求都没发 / `6` 调用失败 / `1` 内部错 / `130` 中断。`--json` 成功是 `{"ok": true, ...}`，失败是 `{"ok": false, "exit": 5, "error": {"kind": "budget", "message": "…"}}`，stdout 只有一个 JSON 文档；`--json` 写在子命令前后都可以。
