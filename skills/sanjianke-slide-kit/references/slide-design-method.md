# 课件设计方法论

> 这份文档回答的是「**怎么把一份讲义变成一份讲得清的课件**」。
> 命令与参数见 `SKILL.md`；画布 / 字号这些数字口径见 `layout-specs.md`。

## 一、为什么课件不是"把讲义切段"

最省事的做法是把讲义按段落切成 N 份，一段一页。这样产出的东西**能看，但不能讲**：

- 一页里塞了三个概念，讲师只能加快语速糊过去；
- 每页的要点是完整的句子，讲师会照着念，学员一眼看完就不再听；
- 没有备注，讲师临场组织语言，讲法每场都不一样；
- 图只是"配个图"，跟这一页要讲的事毫无关系。

课件与讲义的差别在**单位**上：讲义的单位是"节"（一段完整的论述），
课件的单位是"**页**"（一次呼吸能讲完的一件事）。

所以本包的第一条命令是 `outline`（分页），而不是直接生成内容——
**分页分错了，后面每一页都是错的**。

## 二、怎么分页

### 2.1 一条页只讲一件事

判断标准很朴素：**这一页讲完之后，讲师需要停下来喝水吗？**
如果需要，说明一页塞了两件事，该拆。

经验值（本包的默认上限就是照这个定的）：

| 项 | 上限 | 为什么 |
|---|---|---|
| 页标题 | 30 字 | 再长就不叫标题了，叫句子；投影上会断成两三行 |
| 每页要点 | 1~6 条 | 少于 1 条是空页；多于 6 条学员记不住，也放不下 |
| 单条要点 | 40 字（闸门硬限 48） | 超过 40 字会在有图版式里断成 3 行 |
| 页数 | 一节讲义约 2~4 页 | 一节课 40 分钟，按 1~2 分钟一页算 |

### 2.2 页型决定节奏

四种页型不是装饰，是**节奏工具**：

| 页型 | 作用 | 用几次 |
|---|---|---|
| `cover` 封页 | 告诉学员"今天学什么、学完能做到什么" | **恰好 1 次**，第一页 |
| `section` 章节页 | 一次大转折；让学员知道"上一段结束了" | 每个章节 1 次 |
| `content` 内容页 | 真正讲内容 | 绝大多数 |
| `summary` 小结页 | 收束 + 承接下一讲 | 建议最后 1 页 |

> `outline` 会把**第一页必须是 cover** 作为建议项报出来（不拦），
> 但把"页数对不上"作为硬闸门——页数是规模的直接体现，偏太多说明模型没有按你的要求分页。

### 2.3 一条实测出来的教训：`kind` 必须由分页阶段定死

本项目在真机上踩过一次**只有肉眼看图才能发现**的坑：

`pages`（展开成成稿）这一步拿到的模型返回里**没有** `kind` 字段
（提示词也没要求它返回），于是缺省值把它补成了 `content`，
而合并逻辑又把模型的值写了回去——**首尾页的 cover / section / summary 被静默降级成全篇 content**。
结果是封面页丢掉了"整幅铺底压暗压字"的版式，看起来和普通内容页一模一样，
而**所有闸门、所有像素检查全绿**。

修法：分页结果另存一份**不可变的 `skeleton_pages`**，`pages` 永远从它展开，
`kind` 只认骨架。这条经验的通用形态是：

> **页型是"结构决策"，内容展开是"填充"；填充阶段不许改结构决策。**

## 三、要点怎么写

### 3.1 要点是"提示词"，不是"讲稿"

这是最容易被搞反的一件事。

| | 写在 `bullets` 里（投影上给学员看的） | 写在 `notes` 里（只给讲师看的） |
|---|---|---|
| 长度 | ≤ 40 字 | 80~400 字 |
| 形式 | 短语 / 短句，一眼扫完 | 完整的话，可以照着说 |
| 作用 | 帮学员**抓住**你已经讲过的 | 帮讲师**记住**要讲什么 |

反面例子（真实会出现的形态）：

- ❌ `bullets`：`剪辑的第一步是把素材里没有信息、没有情绪、没有动作的片段全部删掉，
  只留下真正有用的部分` —— 这是讲稿，学员会在你开口前读完，然后不再听。
- ✅ `bullets`：`粗删：只看有没有用`
- ✅ `notes`：`粗删阶段不看细节，只判断"这段有没有用"。三个问题：有没有新信息、
  有没有推进情绪或动作、删了会不会看不懂。三个都答"没有"就删。`

### 3.2 要点之间要有关系

一页的 3~5 条要点最好构成**一个结构**：并列（三个抽屉）、递进（先删后加）、
或对照（对的做法 / 错的做法）。互不相干的三句话放一页，学员记不住任何一条。

### 3.3 不许编数据

提示词里写死了：**不许编造讲义里没有的数字、人名、机构、结论**。
这不是"礼貌要求"，是因为课件比讲义更"权威"——学员会以为投影上的数字是真的。
合规闸门会拦下违禁词与效果承诺，但它**拦不住编造**，所以这一条靠提示词 + 你复核。

## 四、讲稿备注写什么

备注是这份课件**最值钱**的部分，也是最容易被省掉的部分。

一条好的备注回答三个问题：

1. **这一页你打算怎么讲**（开场 / 铺垫 / 直接点题）
2. **要强调什么**（哪一句必须说，哪一句可以省）
3. **学员容易在哪里卡住**（预判误区，提前拆掉）

反面例子：`备注：介绍三段式` —— 这不是备注，这是标题的复述。

正面例子（真机产出）：

> `强调顺序不能反：先加音乐再删素材，会为了卡点留下本该删掉的镜头。`

**本包默认对"缺备注"只告警不拦截**（因为有人确实想要一份无备注的纯投影稿），
但加 `--strict-notes` 就会把它变成硬闸门。真要做课，建议一直开着。

## 五、配图的意图怎么写

### 5.1 画面里不许有文字

这是本包和同族 `image-factory` / `cover-factory` 最大的设计差异。

出图模型画中文大字**基本是错的**：缺笔画、错字、糊成一团。
所以本包的做法是「**背景图无字 + 本地渲染压字**」：
`image_intent` 里明确要求"画面里没有任何文字"，
页上的标题与要点由 `render` 用**系统字体**画上去——文字清晰度与出图模型无关。

`images` 阶段还会在提示词末尾再加一句"画面里不要出现任何文字、字母、数字或水印"，
双保险。

### 5.2 配图意图写什么

一条合格的 `image_intent` 包含五件事（95~150 字）：

1. **主体**：画面里有什么
2. **构图**：俯拍 / 侧逆光 / 居中 / 大面积留白
3. **光线**：清晨侧逆光 / 冷色工作灯 / 柔和顶光
4. **色调**：暖灰调 / 冷调偏蓝 / 中性暖白
5. **质感**：浅景深纪实摄影 / 胶片颗粒 / 简洁静物

**不要写抽象概念**（"体现专业感"）——那不是画面描述，模型画不出来。
**不要写这一页的要点内容**——那会把文字引回画面里。

### 5.3 每页一图还是数页一图

`--every N` 控制：页序为 `1, 1+N, 1+2N…` 的页面配图，其余页走**无图版式**。

- `--every 1`：每页一图。视觉最统一，也最贵（24 点/页）。
- `--every 2` 或 `3`：数页一图。**省钱，但要注意**：无图页的文字区更宽（限宽 70%），
  同一份内容在无图页装得下、在有图页可能装不下 —— 所以**内容闸门是按"这一页有没有图"
  分别判的**。

> 实测：7 页 / `--every 3` → 3 张图（79 万~105 万字节），其余 4 页无图（7 万~8.6 万字节）。

## 六、一条完整链路长什么样

以本包真机实测的"零基础短视频剪辑"为例：

```
讲义（1 节约 1200 字）
   ↓ outline --pages 6
7 页分页方案（模型给了 7 页，±1 容差内放行）
  p01 cover   零基础短视频剪辑：先做减法
  p02 content 新手最容易犯的错：先找转场
  p03 section 核心方法：三段式顺序
  p04 content 粗删、精修、包装分别做什么
  p05 content 判断废片的三个问题
  p06 content 整理素材：只用一个抽屉标准
  p07 summary 小结：先做减法，再做加法
   ↓ pages（3 批）
每页 1~6 条要点 + 80~400 字讲稿备注
   ↓ images --every 3
3 张无字配图（1344x768，偏差 1.56%）
   ↓ render（0.7 秒，零成本）
7 张 1920x1080 的逐页 PNG + notes.md + deck.html + AUDIT.md
```

## 七、什么时候不该用本包

- **只要讲义，不做课件** → 用 `sanjianke-course-outline`（纯文本三件套，更便宜）。
- **要的是文章配图，不是课件** → 用 `sanjianke-image-factory`。
- **要的是封面/头图** → 用 `sanjianke-cover-factory`。
- **必须要 `.pptx` 文件本体** → 本包不给（`python-pptx` 不是标准库，不依赖）。
  折中做法：用本包出的 `deck.html`（每页一张图，`@media print` 里一页一屏）
  在浏览器里打印成 PDF，或把 `slides/*.png` 逐页插入 PPT。
- **课件里有大量公式 / 图表 / 代码** → 本包的版式是"标题 + 要点 + 一图"，
  不擅长这类页面；这类课件更适合手工排版。
