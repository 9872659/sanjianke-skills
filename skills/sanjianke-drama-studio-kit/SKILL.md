# 三剪客 · AI 短剧创作台

要自建一套 AI 短剧创作台，最贵的错误不是写错代码，而是**选错了底座**：
把 AGPL 项目当闭源 SaaS 商用、按分镜计费的模型被当成按次计费、GPU 预算全砸在
推理上却发现瓶颈在 FFmpeg 合成。这份 Skill 把决策压在动手之前。

它管三段事：**要不要自建、选哪个底座、怎么搭起来并且能持续跑下去**。
不教你写剧本，也不生成画面——那是创作环节的事，这里只管创作台本身。

## 权限与用途说明

| 能力 | 是否申请 | 用途 |
|---|---|---|
| 网络访问 | **不申请** | 本 Skill 全程离线，不联网、不探活、不下载依赖 |
| 读取文件 | 仅读取用户主动指定的路径 | 读取部署配置、日志片段、目录清单用于诊断 |
| 写入文件 | 仅在用户指定输出路径时 | 测算脚本仅把结果打印到终端，不落地文件 |
| 凭证 | **不读取** | 不接触 API Key、数据库口令、OSS AK/SK；文中出现的变量名均为占位符 |
| 子进程 / 后台常驻 | 不申请 | 测算脚本为纯计算，执行完即退出，不驻留 |

**本 Skill 不内嵌任何密钥，也不访问任何外部地址。** 文中涉及的模型供应商、
对象存储、数据库都需要使用者自行申请与部署；本 Skill 只提供判断依据、
配置骨架和离线测算工具，不代为调用任何服务。

### 第三方与合规提示

选型对象若采用 **AGPL-3.0** 一类带网络服务条款的强著佐权许可，把它作为
对外可访问的在线服务运行，通常需要向使用者提供对应源代码。这属于许可
义务而非技术问题，务必在上线前由法务或合规负责人确认。详见
`references/ops-and-compliance.md`。

## 触发场景

- 「我们想做短剧，是自己搭一套还是直接买现成的？」
- 「这个开源短剧平台能不能商用？许可有没有坑？」
- 「服务器买好了，MySQL、Redis、FFmpeg 这些都怎么装？」
- 「画面出来了但是配音和口型对不上，合成出来时长总是错位。」
- 「对象存储账单超预算了，出片成本到底花在哪一块？」
- 「用哪家的模型？文本、图片、视频、配音能不能混着用？」

**不适用于**：只想剪一条已经拍好的片子（那是剪辑工具的活）、
只想写剧本不打算落地系统、以及期望本 Skill 直接产出一部成片。

## 快速开始

先回答三个问题，路径就唯一了：

1. **谁用**——只有自己团队用，还是要给外部客户开账号？
2. **许可**——底座是不是 AGPL 这类强著佐权？要商用就得先过法务。
3. **量级**——每月出多少集？决定算力是走按量 API 还是自建推理。

```bash
# 第 1 步：先算钱。改参数即可，不联网、不写文件
python scripts/cost_estimate.py --episodes 30 --minutes 2 \
  --gen-image 40 --gen-video 30 --gen-tts 30

# 第 2 步：按打分表定底座（五项加权，低于 3.0 不建议自建）
#   见 references/selection-scorecard.md

# 第 3 步：照部署清单搭环境（依赖版本、库表字符集、发布方式）
#   见 references/deploy-and-configure.md

# 第 4 步：上线前过一遍检查项，并确认许可义务
#   见 references/ops-and-compliance.md
```

## 工作流 A：先做决策，再碰服务器

用户一上来就问「怎么部署」时，**不要直接给安装步骤**。先按顺序问清：

| 必须问清 | 为什么 |
|---|---|
| 底座许可类型 | AGPL 类许可对外提供服务会触发源码披露义务，这一条能直接否掉方案 |
| 使用范围（内部 / 对外） | 决定要不要做多租户、配额、审计，工作量差一倍以上 |
| 每月目标集数 | 决定按量 API 和自建推理哪个更省，拐点通常在每月百集量级 |
| 团队现有技能栈 | Java + Vue 一条线、Python 一条线，选错会让迭代速度腰斩 |
| 硬件预算 | 瓶颈常在 CPU 转码而非 GPU 推理，配错机器钱白花 |

打分口径与自建 / 采购 / SaaS 三种路线的取舍表，见
`references/selection-scorecard.md`。**五项加权低于 3.0 分时要明确建议
不要自建**，并说明是哪几项拖了后腿。

---

## 工作流 B：部署与配置

确认要走自建后，按这条路走，**每一步都要能验收再进下一步**：

1. **基线**：核对 CPU、内存、磁盘与转码能力，别只看 GPU
2. **依赖**：数据库、缓存、多媒体工具三件套装好并验证版本
3. **库表**：建库建表时把字符集定成 `utf8mb4`，中文标题和台词踩坑都在这
4. **密钥**：模型与存储凭证一律走环境变量或密文配置，**不进代码库**
5. **模型**：按文本 / 图片 / 视频 / 配音四类分别指定供应商，别只配一个
6. **存储**：对象存储与 CDN 打通，确认回源域名和跨域设置
7. **构建**：前端构建产物交给 Nginx，后端以常驻服务方式托管
8. **联调**：走一遍最小闭环——建项目 → 拆镜头 → 出图 → 出片 → 整集合成

命令、配置文件骨架、字符集与跨域的具体写法，见
`references/deploy-and-configure.md`。

**最低成本验证法**：先用一个镜头跑通全链路再批量投入。
很多团队直接批量生成，结果在最后才发现配音时长对齐策略有问题，
前面的生成费用全部作废。

## 工作流 C：运维、成本与合规

上线不是终点。三件事要固定成例行动作：

- **巡检**：任务队列积压、失败率、磁盘余量、证书有效期
- **对账**：把模型调用、对象存储、回源带宽、转码算力四笔账分开记
- **备份与演练**：数据库定期备份，**并且真的恢复过一次**

对外提供服务前必须确认许可义务（AGPL 类需提供源码）；同时确认生成内容的
标识与备案要求。故障定位顺序、账单异常特征、上线检查项与许可义务说明，
见 `references/ops-and-compliance.md`。

## 已知限制

- 上游项目迭代较快，表结构、配置项与路由**都可能变动**；
  文档中的字段与路径以骨架示例的性质给出，落地前请以目标版本自身的
  配置文件与建表语句为准。
- 各家模型的价格与限流策略变动频繁，测算脚本中的单价只是**默认示例值**，
  必须替换成当期报价再采信结论。
- 成本测算为量级估算，未计入重试、失败重跑与人工返工带来的额外消耗，
  实际支出通常高于测算值。
- 本 Skill 不判断某个具体项目是否适合你的团队，只提供判断框架。

## 自检清单

部署前：

- [ ] 已确认底座许可类型，并判断对外服务是否触发源码披露义务
- [ ] 已确认使用范围（内部自用 / 对外经营），并据此确定是否需要多租户
- [ ] 已明确每月目标集数，并据此选好按量 API 或自建推理
- [ ] 已完成五维打分，加权分与结论一致
- [ ] 数据库字符集为 `utf8mb4`，已用中文标题实测插入与查询
- [ ] 所有密钥走环境变量或密文配置，代码库中没有任何明文凭据
- [ ] 四类模型供应商分别配置完成，并各做过一次真实调用
- [ ] 对象存储回源域名与跨域设置已验证
- [ ] 已用单个镜头跑通全链路，再放大到批量

上线后：

- [ ] 后台任务失败率与积压量在观测范围内
- [ ] 数据库备份已实际恢复验证过一次
- [ ] 四笔成本账分开记录，且能定位异常波动来源
- [ ] 生成内容的标识与备案要求已确认
