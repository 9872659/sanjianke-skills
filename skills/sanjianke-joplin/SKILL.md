# 三剪客 · 开源笔记与知识同步

Joplin 解决的是「笔记放在哪里、归谁管」这件事。笔记本体是 Markdown，全部落在你自己的电脑或手机上，再通过你指定的存储（本地目录、WebDAV、网盘、对象存储或自建服务）在多设备之间对齐。所以它适合那些不想把资料托管给笔记厂商、又需要手机和电脑看到同一份内容的人。

除了桌面和手机图形界面，它还带一个终端版本：可以用一条条命令批量建笔记、导入导出、跑定时同步，这正是把笔记接进自动化流程的入口。

**上游项目**：`Joplin`　**仓库**：https://github.com/laurent22/joplin

## 什么时候用 / 不用

**用它**：

- 用户说「笔记要存在自己电脑上，不能只放在某个网盘或笔记 App 里」——Joplin 是离线优先的，没网也能看全部内容。
- 要**从 Evernote 搬家**：支持导入 `.enex` 导出文件，格式、图片附件和元数据一起带过来。
- 要**用命令行批量处理笔记**：一次建几十个笔记本、成批导入多个 `.enex`、写脚本定时同步、导出成 Markdown 喂给别的工具。
- 团队或个人想**自选同步后端**：本地网络目录、WebDAV、Nextcloud、S3、Dropbox、OneDrive 都能当同步目标，不被单一厂商绑住。
- 笔记需要**长期归档与可迁移**：导出的就是 Markdown 或者 Joplin 自己的打包格式，换工具不至于全丢。

**不要用它**：

- 需要**多人实时协同编辑**同一篇笔记。Joplin 是单人笔记模型，没有在线协同编辑和权限体系。
- 需要给外部客户开**只读分享链接、网页发布**这类能力。它不提供托管式分享站点。
- 想要**纯 API 集成**去读写笔记。终端版带的本地 API 服务上游自己标注为实验性，不建议当稳定接口用。
- 团队要的是**看板、甘特、多维表格**一类数据库型协作工具。Joplin 的组织单位是笔记本 + 标签，不是关系型视图。
- 只想**临时记两句话**、不需要同步和结构。装一套客户端 + 配同步反而更重，先用系统便签更省事。

## 安装

### 桌面端与移动端（普通用户）

从上游的发布页下载对应平台安装包即可，Windows、Linux、macOS、Android、iOS 都覆盖；浏览器扩展是 Web Clipper。安装包与最新版本号**以上游仓库 Releases / 官网为准**，不要凭记忆写版本号。

### 终端版（CLI，本 Skill 的重点）

上游针对 macOS、Linux、Windows（走 WSL）给出的官方方式是先装 Node，再用 npm 全局安装：

```bash
# 1) 先准备 Node 环境（上游文档给的下限是 Node 12+）
node -v

# 2) 装到用户目录下的独立前缀，避开系统目录权限问题
NPM_CONFIG_PREFIX=~/.joplin-bin npm install --loglevel=error -g joplin

# 3) 做软链接，让 joplin 命令进 PATH
sudo ln -s ~/.joplin-bin/bin/joplin /usr/local/bin/joplin

# 4) 启动
joplin
```

如果你的 npm 全局目录本来就归当前用户所有，直接 `npm -g install joplin` 也可以。安装二进制默认落在 `~/.joplin-bin`，这个目录可以自己换。

### 不推荐但存在的途径

社区打包渠道（例如发行版 AUR 里的 `joplin` 包）不属于上游支持的安装方式，出问题要去找对应打包方。只想体验的话不建议走这条路。

### 同步后端

不需要额外装东西，同步目标在应用内配置即可；只有选到需要凭证的后端时，才要准备账号。

## 常用操作

下面都是终端版 Shell 模式可直接执行的命令。想不起来有哪些命令时先跑 `joplin help all` 拿到完整清单。

**1. 建笔记本、切进去、建笔记**

```bash
joplin mkbook "项目资料"
joplin use "项目资料"
joplin mknote "会议纪要 0312"
```

**2. 查看当前笔记本里的笔记（带 ID 的长格式）**

```bash
joplin ls -l
# fe889 07/12/2017 17:57 My note
```

拿到 ID 之后可以精确改标题、改正文：

```bash
joplin set fe889 title "新标题"
```

**3. 从 Evernote 导入**

先在源笔记里把笔记本导出成 `.enex` 文件，然后：

```bash
joplin import /path/to/notebook.enex
```

导入会按文件名新建一个笔记本。多个笔记本就多跑几次。

**4. 导出成 Markdown 或 Joplin 打包格式**

```bash
# 全库导出为 Markdown
joplin export /path/to/backup --format md

# 只导出某个笔记本
joplin export /path/to/backup --format md --notebook "项目资料"
```

`--format` 还支持 `jex`（Joplin 打包文件）、`raw`、`md_frontmatter`。

**5. 手动同步 / 定时同步**

```bash
joplin sync
```

放进 crontab 可以做到无人值守同步，上游文档给的是每 30 分钟一次：

```bash
*/30 * * * * /path/to/joplin sync
```

**6. 写命令文件批量执行**

把一批命令写进一个文本文件，一行一条，然后：

```bash
joplin batch /path/to/commands.txt
```

## 常见坑

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 装好之后怎么改笔记都不出现在手机上 | `sync.target` 默认是 `0 (None)`，等于没配同步，数据只在本地 | 先设同步目标：`joplin config sync.target <编号>`，再补上该目标需要的 `sync.N.*` 参数，最后 `joplin sync` |
| 换了同步目录后，同步一跑本地内容大量消失 | 上游提示过：改动 `sync.N.path` 这类位置前，必须先把已有内容完整拷到新位置再同步，否则会被当成需要清理的数据 | 换路径之前先手动全量复制，确认新位置内容完整，再执行同步；界面里的「Fail-safe」`sync.wipeOutFailSafe` 默认开启，别去关它 |
| 终端版和桌面版同时开着，互相报同步锁冲突 | 两边都在跑同步，且共用同一个 profile，本地锁会互相顶 | 别让两个客户端同时同步；要长期并行就用 `--profile` 把终端版的数据目录和桌面端分开 |
| 导入时提示格式不对或只建了个空笔记本 | `.enex` 与 Joplin 的 `jex`/Markdown 是不同格式，默认自动识别不一定命中 | 显式指定：`joplin import <path> --format enex`；重复导入会重复建笔记，导入前确认目标笔记本是新建的空本 |
| 按文档里的 `~/.joplin-bin` 和 `ln -s` 在 Windows 上跑不通 | 那是 macOS / Linux 的路径与软链接写法，Windows 需要用 WSL 走这套流程 | 原生 Windows 直接用默认全局目录 `npm install -g joplin`；或者干脆按上游建议装 WSL 再执行上面的命令 |
| 同步一直失败，界面只说失败 | 多数是 WebDAV / Nextcloud 的 URL 或密码不对，报错细节在日志里而不在界面 | 去看 profile 目录下的日志（Linux 上通常是 `~/.config/joplin`），里面会写清楚具体是哪一步错了 |
| 想用 `joplin server start` 提供本地 API | 这个能力上游明确标注为实验性，且建议**单独开一个 profile** 跑服务，避免两个进程同时读写同一份数据 | 要试就 `joplin --profile <独立目录> server start`，并且不要把它当作对外稳定接口依赖 |
| 附件在导出后变成一串 ID，打不开 | Markdown 里资源是以资源 ID 引用的，脱离 Joplin 库直接看文件就找不到实体 | 导出时按需选 `raw` / `jex` 保留资源，或者导出 Markdown 时连同资源目录一起搬走；单独看 `body` 字段不等于完整笔记 |

## 权限与用途说明

| 能力 | 是否申请 | 用途 |
|---|---|---|
| 网络访问 | 按需 | 仅在使用云同步目标（Dropbox / OneDrive / Nextcloud / WebDAV / S3 / 自建服务）时需要；纯本地模式不联网。终端版运行时会尝试起一个本地小服务来缩短长链接，也属于本机通信 |
| 读取文件 | 是 | 读取 profile 目录下的笔记数据库与资源文件；`import` 读入 `.enex` / Markdown 来源文件；`attach` 读取要挂进笔记的本地文件 |
| 写入文件 | 是 | 写入笔记库、附件资源；`export` 向指定目录写出导出结果；配置文件与日志也写在 profile 目录下 |
| 凭证 | 按需 | 同步后端所需的账号密码或 Access Key。终端版保存为配置项，`config --export` 会把含敏感项在内的全部配置以 JSON 输出，注意别外泄 |
| 子进程 / 后台常驻 | 是 | 终端版本身可长期运行，配合 crontab 定时 `joplin sync`；编辑动作可以调用外部编辑器（`config editor "..."` 指定），会拉起对应进程 |

## 能力边界

**覆盖**：

- 桌面端 / 移动端 / 终端版三端的安装路径选择，以及官方支持的 CLI 安装命令。
- 同步目标的选型与配置思路：本地目录、WebDAV、Nextcloud、S3、Dropbox、OneDrive、自建服务各自对应哪类 `sync.*` 配置。
- Shell 模式下的笔记与笔记本管理：建、列、改、移、删、打标签、待办开关。
- 导入导出：`.enex` 迁移、`jex`/`raw`/Markdown 导出、批量命令文件。
- 定时同步与多 profile 隔离这类运行层面的操作。

**不覆盖**：

- 上游应用源码的编译与二次开发，不涉及插件、主题的编写。
- 具体同步后端的账号开通流程（各家网盘、对象存储的开通与授权在对应服务商侧完成）。
- 多人实时协作、在线分享页面、企业权限体系——这些不在该项目的能力范围内。
- 任何具体版本号、发布时间的承诺，命令与参数以实际安装版本和上游文档为准。

## 依赖条件

- 终端版需要 Node 运行环境与 npm（上游文档给出的 Node 下限是 12+），以及能执行软链接的系统权限（或改用默认全局目录）。
- 桌面端与移动端按平台下载安装包，不依赖 Node。
- 同步需要一个可用的存储位置：本地路径、WebDAV/Nextcloud 地址、S3 兼容存储，或相应网盘账号。
- 启用端到端加密时，需要自己保管主密码——丢了无法恢复内容。

## 已知限制

- 单用户笔记模型，没有团队协同编辑与细粒度权限。
- 终端版与桌面版共用同一 profile 时不要同时同步，否则容易撞锁。
- 终端版内置的 API 服务是实验性能力，接口可能变动。
- 大量笔记 + 首次全量同步会比较慢，`sync.maxConcurrentConnections` 默认值不大，网络差时调整它才有意义。
- 导出的 Markdown 中，附件是以资源引用形式存在的，脱离笔记库需要一并处理资源文件。

## 自检清单

执行前：

- [ ] 明确用的是桌面端、移动端还是终端版——命令只对终端版成立
- [ ] 确认 `sync.target` 是否已设置，没设置就别承诺「已同步到多设备」
- [ ] 动手改 `sync.N.path` 之前，先确认旧位置内容已完整复制到新位置
- [ ] 导入前确认目标笔记本是否为新建的空本，避免重复导入
- [ ] 涉及凭证的命令不要在共享终端里明文回显

执行后：

- [ ] `joplin status` / `joplin ls -l` 确认笔记数量与内容符合预期
- [ ] 需要同步的场景，跑一次 `joplin sync` 并在另一端验证内容确实到了
- [ ] 导出结果抽查几篇，确认正文与附件都在
- [ ] 汇报时只讲实测到的行为，不编造版本号与参数
