# 扩展与排错

覆盖范围：怎么给平台加东西（技能、插件、工具、provider、通道），坏掉时按什么阶梯查（网关 / 通道 / 工具 / 模型四类），以及回滚迁移、日志审计、卸载清理与常见误判。

读法说明：本地 Agent 平台品类的通用指南。操作写成中性描述，字段名按你的实现对齐。

---

## 1. 扩展点怎么选

| 你缺什么 | 扩展点 | 判断依据 |
|---|---|---|
| 一套可复用的工作流、审查标准、命令序列或操作约束 | **技能**（`SKILL.md`） | agent 已经有工具了，缺的是「怎么做」 |
| 一个新的集成、运行时能力、凭证或生命周期钩子 | **插件** | 有能力代码，需要打包与安装 |
| 就是让 agent 多会一个动作 | **工具** | 通常是插件的一部分 |
| 一条新的消息出入口 | **通道扩展** | 走通道 SDK |
| 一个新的模型 / 推理后端 | **provider 扩展** | 走 provider SDK |

优先级建议：**能用技能解决的不要写插件，能写插件的不要改核心**。技能的边际成本最低、回滚最容易；插件能改的东西最多，风险也最大。

另外记住一条：**接一个 OpenAI 兼容端点不需要写任何代码**——在 `models.providers` 里配一个自定义 provider 就够了。只有当鉴权方式或协议不兼容时才需要 provider 扩展。

## 2. 写一个技能

### 2.1 最小形态

`SKILL.md` 的 frontmatter 最少需要 `name` 与 `description`：

```markdown
---
name: image-lab
description: 用算力集市支撑的图像工作流生成或编辑图片
---

当用户要求生成图片时……
```

- 正文里引用同目录的脚本与素材要用**技能目录变量**，不要写死绝对路径——沙箱化运行时读到的是物化副本，路径会变。
- frontmatter 先按 YAML 解析，失败则退回单行解析器；嵌套的 `metadata` 块会被压成 JSON 字符串再按 JSON5 解析，所以块状写法可用。

### 2.2 可选 frontmatter 键

| 键 | 类型 / 默认 | 作用 |
|---|---|---|
| `homepage` | string | 在桌面端技能界面显示为「官网」 |
| `user-invocable` | boolean，默认 `true` | 是否把它暴露成一个用户可调的斜杠命令 |
| `disable-model-invocation` | boolean，默认 `false` | 为真时不把技能说明放进常规提示词；若同时 `user-invocable: true`，它仍作为斜杠命令可用 |
| `command-dispatch` | `"tool"` | 设为 `tool` 时，斜杠命令绕过模型直接派发给已注册工具 |
| `command-tool` | string | 派发时要调用的工具名 |
| `command-arg-mode` | 默认 `raw` | 工具派发时把原始参数串直接透传 |

### 2.3 组织与共享

- 个人独占用 `~/.agent/skills`；项目内共享用 `<workspace>/skills` 或 `<workspace>/.agent/skills`；全机共享用受管技能目录（安装时选「全局」）。
- 同名技能按加载优先级覆盖，**顺序不直观**：workspace/skills → workspace/.agent/skills → 个人技能目录 → 受管技能目录 → 额外目录与插件内置技能。调试「为什么我的技能没生效」第一件事就是按这张表找同名。
- 技能可被 agent 白名单限制；插件也能打包技能一起分发。
- 团队场景建议走一套受管的**提议 / 修订 / 应用 / 拒绝 / 隔离**流程，把临时经验沉淀成受管技能，而不是让每个人往自己的目录里丢。
- **注意 token 成本**：技能说明会进提示词，塞太多技能会挤占上下文。用 `disable-model-invocation` 或收窄加载范围来控制。

### 2.4 校验口径

装完必须做三件事：

1. **能列出来**：技能出现在列表里，路径与优先级符合预期；
2. **能生效**：在目标 workspace 的一次真实对话里确认它被引用；
3. **能追溯**：来源（本地目录 / 市场 / 归档）可查，并有内容校验（可信信封或哈希），便于发现被替换。

三条缺一条，都算没装好——「列表里有但没生效」是技能类问题里最常见的形态。

## 3. 写一个插件

### 3.1 生命周期

插件通常有这几步（中性描述）：脚手架初始化 → 构建产物 → 校验清单与依赖 → 打包 → 安装到平台 → 查看详情 → 一致性自检 → 启用 / 停用 → 更新 → 卸载。

### 3.2 包形态的硬要求

包元数据必须声明扩展入口，且指向**构建后的**运行时文件（通常是 `./dist/index.js`），不是源码入口：

```json
{
  "name": "agent-gateway-plugin-demo",
  "version": "1.2.3",
  "agentGateway": {
    "extensions": ["./dist/index.js"]
  }
}
```

报「包元数据缺少扩展入口」就是这个形态不对：补上声明 → 重新构建发布 → 再安装。指向源码入口的写法在开发环境可能碰巧能跑，装到平台里一定失败。

### 3.3 安全姿势

- 插件清单会在导入运行时代码**之前**被校验；但原生插件最终仍在进程内运行，**没有沙箱**。
- 缓解手段：允许列表、安装策略钩子、锁版本、锁依赖、CI 强制的 SDK 边界。
- 三条硬规矩：**只装可信来源**；**固定版本与依赖**（不要用浮动范围）；**每次更新后跑一致性自检并复核权限面**——插件新增的权限往往是全量的。

### 3.4 用插件接模型提供方

接一个新的模型后端本质是写一个 provider 扩展，要声明四样东西：**base_url、鉴权方式、模型清单、能力标记**（是否支持视觉、是否支持工具调用、是否支持流式）。

如果只是接一个 OpenAI 兼容端点（例如算力集市 `https://api.a7w.cn/api/v1`），按配置接即可：

```json5
{
  "models": {
    "providers": {
      "a7w": {
        "type": "openai-compatible",
        "baseUrl": "https://api.a7w.cn/api/v1",   // 宿主自补 /v1 的场景填 https://api.a7w.cn/api
        "apiKeyRef": "env:A7W_API_KEY",
        "models": ["DeepSeek-V4-Flash", "Qwen3.6-Plus", "Kimi-K2.6", "GLM-5.2"]
      }
    }
  }
}
```

## 4. 排错阶梯：先跑这几类只读检查

按顺序，不跳步：

| 顺序 | 检查 | 通过的样子 |
|---|---|---|
| 1 | **总体分诊** | 产出一份脱敏的、可直接交给 agent 的诊断；网关可达时还会附支持归档。**在你没有选择把它交给某个 agent 之前，什么都不会离开本机**，而且提示里排除了密钥、token、原始聊天负载与原始日志 |
| 2 | **配置与依赖状态** | 配置的通道都在，没有认证错误 |
| 3 | **完整状态报告** | 产出完整、可分享的报告 |
| 4 | **服务探针** | 可达性为「是」。读作用域不足导致的「降级」**不是**连接失败 |
| 5 | **服务与稳定性状态** | 进程在跑、端口在听、能力级别合理 |
| 6 | **通道逐账号探测** | 拿到每个账号的真实传输状态；只有在不可达时才退回只读配置摘要 |
| 7 | **日志（跟随）** | 有稳定活动，没有反复出现的致命错误 |

分诊是前门：它做只读健康检查、生成脱敏提示，然后**询问**要不要把这份诊断交给本机检测到的编码 agent；也可以选择「只打印命令」自己跑。

**这七条都是只读的。** 排错时先把只读证据拿全，再动手改配置——直接改配置最常见的后果是把现场破坏了。

## 5. 第一类：网关起不来

| 症状 | 先查什么 |
|---|---|
| 端口被占 | 对照配置里的绑定端口与系统侧端口占用。开发实例与生产实例的端口必须错开 |
| 拒绝启动并提示 token 有问题 | 检查是不是把文档里的占位示例原样粘进了网关 token。网关会明确拒绝占位值 |
| 前台能跑、装成服务后不行 | 服务托管方式按平台不同（LaunchAgent / systemd 用户单元 / 计划任务）；Windows 计划任务创建被拒会回退到启动文件夹登录项，**确认回退路径是否真的生效** |
| 启动即退、有锁相关报错 | 同一主机只能有一个网关持有某个消息账号的会话。确认没有第二个实例在跑 |
| 升级后启动异常 | 先跑依赖与配置自检（必要时带自动修复），走状态库迁移；再考虑回滚 |
| 状态目录 / 配置路径串了 | 具名 profile 与开发模式都会改状态目录；显式设过状态目录与配置路径的以显式值为准。**服务环境不加载你的 shell profile**，环境变量要写进服务定义或 `.env` |

诊断资产（中性描述）：导出网关诊断包 → 查看稳定性指标 → 重启服务 → 兜底做法是卸掉托管服务再装一次，把服务定义刷成新版本。

## 6. 第二类：通道连不上

按这个顺序查：

1. **逐账号真实状态**。只看配置摘要会骗你。
2. **死信队列**：列出积压消息，处理完显式重投。
3. **通道日志**：按通道过滤。
4. **它不回消息**：群聊默认靠 @ 提及激活；私聊默认对未知发件人走配对——查有没有卡住的待批请求。
5. **登录态过期**：登出后重新登录；扫码类通道要重新扫码。
6. **机器人权限不够**：不同平台要求不同（消息内容意图、被拉进目标群、管理权限）。平台侧改完记得重启网关。
7. **能力不对**：先查这条通道支持哪些消息动作——很多「命令没反应」其实是不支持。
8. **新设备连不上**：非本地连接一律要显式配对批准，只有本地回环才有自动批准。这条最常被误判成「网络不通」，占掉最多排错时间。

## 7. 第三类：工具像被阉割了

「它只会聊天不干活」几乎都是工具可见性问题。按这个顺序查：

1. **档位**：当前是 `minimal` / `messaging` / `coding` / `full` 里的哪一个？`minimal` 只给会话状态查询。
2. **按 agent 的覆盖**：agent 级配置可能在根档位之上又收窄了。
3. **允许 / 拒绝策略**：被全局或按 agent 拒绝的工具，开沙箱也救不回来。
4. **沙箱生效配置**：看生效模式、宿主 workspace、运行时工作目录、挂载与工具策略——它会直接告诉你该改哪个键。
5. **通道权限**：同一个工具在某个通道里可能没有权限。
6. **插件是否启用**：列插件看状态，跑一致性自检。
7. **审批与执行策略**：**命令被拦不等于工具不存在**。查当前审批策略与执行策略；会话级收紧只能紧不能松，放宽要改配置。
8. **作用域**：网关认证如果没有读作用域，很多诊断会降级显示，看起来像「工具没了」，其实是「你看不到」。

一行心法：**先工具策略，再沙箱，最后才是模型。**

## 8. 第四类：模型报错

模型统一接在 `https://api.a7w.cn/api/v1`（宿主自补 `/v1` 的场景填 `https://api.a7w.cn/api`），鉴权是 `Authorization: Bearer <你的 API Key>`。

| 症状 | 处置 |
|---|---|
| 加了认证但用起来还是老模型 | **增加一组认证不会改默认模型**。显式切换默认模型 |
| 认证明明配了却不生效 | 确认认证存在；看轮换顺序；再核对环境变量与配置键的优先级（配置内联值常常优先于环境变量兜底） |
| **HTTP 401** | Key 无效或过期：换 Key、续期。不要改 base_url |
| **HTTP 402** / 业务码 402 | 点数不足：到 [算力集市](https://api.a7w.cn/) 充值后重试。不是模型不存在 |
| **HTTP 404** | base_url 多写或少写了一段 `/v1`。宿主自补 `/v1` 的填 `https://api.a7w.cn/api`，接受完整 base_url 的填 `https://api.a7w.cn/api/v1` |
| 「模型不存在」 | 模型编码写错或已下架：**以现场拉取 `GET /api/v1/models` 得到的编码为准**，逐字一致、大小写敏感。不要抄别人的清单 |
| 返回内容为空、`finish_reason` 为 `length` | 推理模型把 token 花在思维链上了：把 `max_tokens` 提到 256 以上 |
| 流式解析拿不到思维链 | 字段名可能是 `reasoning` 或 `reasoning_content`，两个都要兼容 |
| 长上下文返回 429 | 这是模型服务侧的上下文 / 配额限制：先降上下文（压缩、裁剪会话、拆子任务），或换到配额更宽的模型 |
| 直连能用、经网关就失败 | 基本不是网络问题，查 base_url 与请求整形规则；先用**一次最小调用**复现，再改 provider 配置 |
| 主模型挂了整个任务失败 | 配降级链（同为 OpenAI 兼容端点，可跨厂商）；图像类另配图像降级链。认证轮换与模型降级是两件事，都要配 |
| 长异步任务轮询报连接重置 | 网关会重置长轮询连接，属正常抖动：**退避重试，不要重复提交**（重复提交等于重复计费） |

## 9. 升级、迁移与回滚

原则：

- **升级前必备份并验证归档**。版本检查只能守卫升级，不保证每一次升级都成功。
- 状态是带 schema 版本的、迁移有归属。正规做法是「**迁移由自检修复流程负责、可回退由备份负责**」，而不是就地手改状态库。
- 旧版本遗留的会话级执行策略在新版本里可能**不再被运行时读取**，要经自动修复流程迁移；限制性策略在迁移时不会放宽——所以不要指望升级帮你收紧。
- 跨机器迁移用平台提供的迁移流程，不要直接拷状态目录整目录。
- 运维姿态：把部署当**可替换基础设施**——坏了按验证过的备份重部署，而不是就地修。

流程口径：

```
更新状态查询 → 备份并验证归档 → 演练实例先跑通 → 正式升级 → 自动修复与状态库迁移
→ 依赖与配置自检 → 通道路由核对 → 一次真实对话验收
```

任一步失败就回滚到上一个归档，并回到上一个版本。**回滚方案要在升级前写下来**，不是等出事再想。

## 10. 日志、审计与可观测

| 面 | 看什么 |
|---|---|
| 运行日志 | 服务活动、错误、崩溃栈；支持按级别过滤与跟随 |
| 操作审计 | 谁在什么时候做了什么（工具调用、审批、配置变更） |
| 安全体检 | 外发面、绑定范围、权限模式、暴露面 |
| 密钥体检 | 有没有凭证被写进配置、日志或转录；轮换是否到期 |
| 消息审计 | 通道侧收发记录与死信 |
| 用量与成本 | 模型调用量与消耗，便于对账与限额 |

可观测导出的三条口径：

- **导出目标是你的**：保留策略、采样率、告警阈值都归你。包括「数据被丢」这件事本身也要监控——静默丢数据比报错更难查。
- **遥测默认口径要写进部署文档**。通常只做每日一次版本检查，匿名功能统计默认关闭；要彻底关掉就把版本检查也设成关闭，并在文档里写清是哪两个开关。
- **审计要按检查项设告警**，不要只看「今天有没有红字」。定期跑一次深度安全体检，把新增的暴露面当成待办。

## 11. 卸载与清理

卸载前想清楚四件事：

1. 状态目录里有哪些**凭证与记忆**要留档（凭证目录、会话库、记忆索引）；
2. **系统服务定义**（LaunchAgent / systemd 单元 / 计划任务）是否随之移除；
3. 容器化部署下**卷与镜像**要不要一起删；
4. **通道侧的平台配置**（机器人、webhook、回调地址）要不要一起撤——留着就是一个指向已停服务的入口。

**命令跑完不等于文件没了。** 卸载后自己核对：状态目录、服务定义、容器与卷，以及模型服务侧不再使用的 Key（应当吊销，而不是留着）。

## 12. 常见误判（写下来省时间）

| 误判 | 事实 |
|---|---|
| 「装了就有沙箱保护」 | 沙箱与执行审批**默认关闭**。默认形态是受信任的单操作者助手 |
| 「一个网关能给多个租户用」 | 一个网关就是一个信任域。多租户要一租户一网关 |
| 「插件是隔离运行的」 | 原生插件在当前进程内跑，没有沙箱 |
| 「角色配置就是安全边界」 | 角色与会话归属只是协作护栏，不是隔离机制 |
| 「配对过了就随便连」 | 非本地连接每次都要走配对批准；只有本地回环才有自动批准 |
| 「出口白名单能拦住一切外发」 | 它只覆盖配合的流量；未沙箱化的宿主命令发出的原始 socket 归你的代理或宿主策略管 |
| 「删了记忆就没了」 | 删除只覆盖被追踪的产物；直接写入、钩子写入与原始转录不在范围内 |
| 「升级是安全的，因为发布有签名」 | 签名与版本守卫保证的是「可追溯、有检查」，不保证升级一定成功 |
| 「Key 存着就一定能调」 | 401 是 Key 问题、402 是余额问题、404 通常是 base_url 问题——三种现象三种处置，别混 |
| 「模型清单可以抄」 | 模型上下架频繁。**唯一可靠来源是现场拉取 `/api/v1/models`** |
| 「异步任务提交了就一定出结果」 | 提交只代表入队。没有轮询与超时兜底，失败会静默变成「没结果」 |
| 「卸载命令跑完就干净了」 | 服务定义、容器卷、通道侧配置与模型 Key 都还在，要逐个核对 |
