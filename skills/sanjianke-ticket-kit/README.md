# 三剪客 · 任务票据拆分 Skill

把需求或方案拆成一张张可跟踪、可独立交付的任务票据，写清边界、依赖与验收条件

---

## 前置条件

- 能读写 Markdown 或 CSV 文件即可，纯文本工作流，**不需要装任何依赖**
- 手上要有需求的原文（一句话也行）；只有转述的需求，拆出来的票会继承转述的失真
- 建议先导出一份现有票据列表（哪怕只有标题），用来查重和识别既有依赖
- 不需要网络、API Key、数据库、Docker，也不需要任何项目管理平台的账号

---

## 使用

**五步走，单张票约 10 分钟，一个中等需求（5~8 张票）约 40 分钟。**

1. **过三道闸**：可独立交付吗 / 可独立验收吗 / 值不值得建票。
   三道全过才建票，任何一道不过就先不拆。
2. **按七字段落内容**：标题 → 背景 → 范围 → 不做的事 → 依赖 → 验收条件 → 预估。
   顺序不要变，尤其 `不做的事` 必须紧跟 `范围`。
3. **给验收条件做可判定性体检**：对每条问「谁判、判什么、什么算不过」。
   用 L0~L3 四级标尺定级，L2 是合格线。
4. **画依赖、找环**：统一方向为「本票等谁」，有环就回去重切，不要靠排期解决。
5. **过出口检查**：跑一遍 `SKILL.md` 末尾的自检清单（15 条）。
   任何一条打不上勾，先别派票。

**按需求查资料**：

| 你要做什么 | 打开哪份 |
|---|---|
| 判断该不该拆、拆多大、按什么维度切 | `references/splitting-criteria.md` |
| 填票据字段、写验收条件、看完整示例票 | `references/ticket-template.md` |
| 表达依赖、拆循环依赖、排查常见错误 | `references/dependency-and-pitfalls.md` |

## 依赖

- **必需**：Markdown 或 CSV 编辑器（普通文本编辑器即可）
- **必需**：需求或方案原文
- **推荐**：现有票据列表导出
- **推荐**：一个能画箭头的载体（白板 / 表格 / 纯文本都行）
- **不需要**：网络、API Key、数据库、Docker、任何付费服务

---

## 安全

- 不内嵌任何密钥、Token、Cookie 或账号密码
- 全程离线，不访问网络，不调用任何远程接口
- 不登录、不同步任何项目管理平台（Jira / 飞书 / TAPD / GitHub Issues 都不接）
- 不覆盖已有文件：目标文件存在时先给出差异，由使用者决定合并或新建
- 示例票均为脱敏的合成案例，项目名、人名、指标数字都是构造的
- 提醒：背景与验收条件里常见日志、报错堆栈、客户名、内网域名，写入前请自行脱敏
