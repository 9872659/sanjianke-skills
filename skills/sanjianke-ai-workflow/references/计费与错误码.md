# 计费与错误码

## 点数口径

- 计价单位是**点数**：**1 元 = 100 点、1 点 = ¥0.01**。
- 体验包 ¥10 = 600 点（含 7 天会员权益），标准包 ¥99 = 10000 点，**点数永久有效**。
- **没有月费**，用多少扣多少。

| 能力 | 计费单位 |
|---|---|
| 文本 | **点数/百万 tokens**（输入输出分别计价） |
| 图像 | **点数/张** 或按参数档位 |
| 视频生成 / 超分 | **点数/秒**（按分辨率档位） |
| 数字人 | **点数/次** 或按时长 |
| TTS / 音色克隆 | **点数/千字** |
| 语音识别 ASR | **点数/分钟** |
| 工具类 | **点数/次** |

**流式与非流式同价。** 换模型不换账单，所有能力记在同一份账上。

## 先冻结、后结算

- 消费优先扣会员点数，不足再扣充值额度。
- **调用失败直接退款；异步任务失败，冻结点数全额退回。**
- 只有成功产出才按实际用量结算。
- 上游调价会同步调整，但**不影响已充值的点数余额**。

> **异步任务在提交时就预冻结点数**，完成后按实际用量多退少补。
> 所以**不要重复提交同一个任务** —— 网络超时也先查 `task_id` 再决定要不要重提。

## 两套价格字段（最容易算错预算的地方）

| 字段 | 含义 |
|---|---|
| `fixed_price` / `input_price` | **标准价**，对外公示用 |
| `tenant_fixed_points` / `tenant_points_per_1k_input` | **你所在租户的实际结算价** |

两者可能差很多。**做预算一律用 `tenant_*`，最终以账号里实际扣费为准。**

### 怎么拿到逐接口真实价

```bash
# 规则表（全局 markup + 少量特例），不含全部接口
python3 scripts/a7w.py schema <app>     # 读 tenant_*，这才是逐接口真实价
```

`GET /api/v1/pricing` 只是**规则表**，不是逐接口价目表，别拿它当唯一依据。

### 怎么对账

- 每次响应里的 **`data.usage.points_cost`** 就是本次真实扣费。
- 任务列表里的结算字段是 **`actual_points`**。
- **翻页请用 `--page-no`**，`page_size` 参数会被上游忽略。

## 余额与额度

| 接口 | 返回 |
|---|---|
| `GET /api/v1/user/balance` | 裸对象：`{"available_points":…,"currency":"points"}` |
| `GET /api/v1/pricing` | 裸对象：`{currency, markupPercent, note, pricing}` |

> **裸对象端点没有 `code/msg/data` 外壳。** 不能用「有没有 `data` 字段」判断成功，
> 否则会把可用端点误判为不可用。

## 错误码排查手册

| HTTP | code | 含义 | 怎么处理 |
|---|---|---|---|
| 400 | `invalid_request` | 参数缺失或格式错误 | 用 `schema <app>` 核对参数名与必填项 |
| 401 | `auth_failed` | API Key 缺失或无效 | 重新 `login`，确认没多空格 |
| 402 | `insufficient_points` | **账号**点数余额不足 | 充值；错误里有本次所需点数 |
| 402 | `key_quota_exceeded` | **该 Key** 的点数额度打满 | 调高 / 重置 Key 的 quota，或换 Key |
| 403 | `permission_denied` | 该 Key 无权调用此模型或应用 | 检查模型是否已开通、Key 是否被限权 |
| 404 | `not_found` | 模型 / 应用 / 任务不存在 | 核对代码拼写，用 `apps`、`models` 拿真名 |
| 429 | `queue_limit_exceeded` | 排队任务已达上限 | 降并发，等队列消化后重试 |
| 5xx | `server_error` | 服务异常 | 退避重试；仍失败换模型 / 线路 |

### 两个必须知道的判定规则

1. **业务成败看 `code`，不看 HTTP 状态码。**
   实测：`POST` 一个**不存在的接口**返回的是 **HTTP 200** + `{"code":0,"msg":"应用或 API 不可用或未配置价格"}`；
   而 `POST` 一个**不存在的应用**返回 **HTTP 404 且响应体为空**。
   成功码是 **`1`**（`{"code":1,"msg":"success"}`），`0` 是失败。

2. **402 有两种，别混。**
   `insufficient_points` 是账号没钱，`key_quota_exceeded` 是 Key 自己的额度满。
   查错时先分清是哪一种，否则会去充一个根本不需要充的账户。

## 省钱的四个习惯

1. **先跑小样**：长文档 / 长视频先切一小段验证参数，再批量。
2. **失败先查再重提**：异步任务用 `task_id` 去重，别让重试变成重复消费。
3. **预算按 `tenant_*` 算**：公示标准价与实际结算价不是一回事。
4. **推理模型给足 `max_tokens`**：给少了 token 全花在思维链上，等于白扣一次。
