# 三剪客 · 个人微信号自动化接口

ItChat 是早年很流行的一个 Python 库：扫码登录个人微信号之后，用装饰器注册消息处理器，就能做关键词自动回复、附件自动下载、群消息监听这类事情。它的接口设计很干净——`auto_login` 登录、`msg_register` 注册、`run` 开始循环，几十行就能跑起一个机器人。

**但必须先说清楚现状**：它走的是网页版登录通道，而该通道自 2017 年起先对新注册账号关闭、2019 年起进一步整体收紧，登录阶段会返回「为你的帐号安全，此微信号不能登录网页微信」这类错误。仓库本身也长期没有更新，文档标注的 Python 支持是 2.7 与 3.5。所以它的现实价值主要在**读接口设计、维护历史脚本、理解个人号自动化的技术路线**，而不是拿来做新项目。真要落自动化，应优先考虑平台官方提供的开放接口或企业侧方案。

**上游项目**：`ItChat`　**仓库**：https://github.com/littlecodersh/ItChat

> 本文接口名与参数名取自该仓库 README 与其官方文档站；登录状态与账号能否使用受平台策略影响，实测结论会随时间变化。

## 什么时候用 / 不用

**用它**：

1. 手上有一份基于它的旧脚本需要读懂或做最小改动——接口名和数据结构查本文即可对上。
2. 做技术调研，想了解个人号自动化里「扫码登录 + 消息注册 + 处理器回调」这套模型长什么样。
3. 把它的消息对象设计当参考，去设计自己的回调式消息分发结构。
4. 做离线实验：用假消息对象跑一遍处理函数的逻辑，不碰真实账号。
5. 写技术文档或教程时，需要一份准确的接口与参数对照，而不是二手转述。

**不要用它**：

1. 新项目要接微信做自动化——它的登录通道已被平台限制，装上了也未必登得进去，别把工期押在这上面。
2. 生产环境的通知 / 客服 / 群管理——仓库已长期无更新，出了问题没人修，风险不可控。
3. 任何批量加好友、群发、营销推广用途——账号封禁风险极高，且大概率违反平台规则。
4. 需要长期无人值守稳定运行——登录态会过期，掉线后需要重新扫码，做不到真正的无人值守。
5. 需要官方支持与合规背书——个人号自动化本身处在平台规则的灰色地带，不要向业务方承诺可靠性。
6. 需要小程序、支付、企业微信等官方能力——这些不在它的接口范围内。

## 常用操作

以下示例均取自仓库 README 与官方文档站。**注意**：下面的代码在语法与接口名上准确，但能否登录成功取决于平台对网页版通道的策略，不能保证可跑通。

**1. 登录并给文件传输助手发一条消息**

```python
import itchat

itchat.auto_login()

itchat.send('Hello, filehelper', toUserName='filehelper')
```

**2. 回复发给自己的文本消息（最小可用机器人）**

```python
import itchat

@itchat.msg_register(itchat.content.TEXT)
def text_reply(msg):
    return msg.text

itchat.auto_login()
itchat.run()
```

处理函数的返回值会被当作回复内容发回去。

**3. 命令行里显示二维码（适合服务器环境）**

```python
itchat.auto_login(enableCmdQR=True)
```

文档给出的两个调节用法：

```python
# 部分 Linux 系统块字符宽度是 1 个字符（正常应为 2），用倍数校准
itchat.auto_login(enableCmdQR=2)

# 控制台背景是浅色时传负值
itchat.auto_login(enableCmdQR=-1)
```

**4. 关闭程序后短时间内免扫码**

```python
itchat.auto_login(hotReload=True)
```

登录态会落到本地状态文件，进程重启后在一定时间内可以复用。

**5. 按消息类型注册处理器 + 附件下载**

```python
import itchat
from itchat.content import *

@itchat.msg_register([TEXT, MAP, CARD, NOTE, SHARING])
def text_reply(msg):
    msg.user.send('%s: %s' % (msg.type, msg.text))

@itchat.msg_register([PICTURE, RECORDING, ATTACHMENT, VIDEO])
def download_files(msg):
    msg.download(msg.fileName)
    typeSymbol = {PICTURE: 'img', VIDEO: 'vid'}.get(msg.type, 'fil')
    return '@%s@%s' % (typeSymbol, msg.fileName)

@itchat.msg_register(FRIENDS)
def add_friend(msg):
    msg.user.verify()
    msg.user.send('Nice to meet you!')

@itchat.msg_register(TEXT, isGroupChat=True)
def text_reply(msg):
    if msg.isAt:
        msg.user.send('@%s I received: %s' % (msg.actualNickName, msg.text))

itchat.auto_login(True)
itchat.run(True)
```

要点：传列表可一次注册多种类型；`isGroupChat=True` 注册群消息；`msg.isAt` 判断是否被 @；`msg.user` 是发送者对象，可以直接 `.send()`。

**6. 搜索用户 / 多开 / 登录与退出回调**

```python
# 获取自己的用户信息
itchat.search_friends()
# 按 UserName 精确获取
itchat.search_friends(userName='@abcdefg1234567')
# 备注、微信号、昵称任意一项匹配
itchat.search_friends(name='somebody')
# 分别指定微信号
itchat.search_friends(wechatAccount='somebody')
```

```python
import itchat

newInstance = itchat.new_instance()
newInstance.auto_login(hotReload=True, statusStorageDir='newInstance.pkl')

@newInstance.msg_register(itchat.content.TEXT)
def reply(msg):
    return msg.text

newInstance.run()
```

```python
def lc():
    print('finish login')

def ec():
    print('exit')

itchat.auto_login(loginCallback=lc, exitCallback=ec)
itchat.logout()
```

文档说明：不设置 `loginCallback` 时，登录后会默认删除二维码文件并清空命令行显示。

## 常见坑

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 扫码后登录失败，提示该微信号不能登录网页微信 | 网页版登录通道自 2017 年起先对新注册账号关闭、2019 年起进一步整体收紧，与本地代码无关 | 换用平台官方开放接口或企业侧方案；不要在这条路上继续投入工期 |
| 装上了但发现接口行为和网上文章不一致 | 网上大量教程针对的是后来出现的分支版本（如带 UOS 字样的变体），与原始仓库的接口并不等同 | 先确认你装的是哪个包，再对照对应版本的官方文档，别混着抄 |
| 中文文件名上传失败 | 仓库 FAQ 明确这是底层 `requests` 的编码问题，并给出了自行替换其文件上传模块的绕行方式 | 按 FAQ 的说明处理，或干脆避开中文文件名的上传场景 |
| 程序关了我还要重新扫码 | 登录态有有效期，`hotReload` 只在有限时间内有效 | 用 `hotReload=True` 并指定独立的状态存储路径；但不要指望长期免扫码 |
| 自己给自己发消息失败 | FAQ 说明：部分账号天生无法给自己发消息 | 文档建议改用文件传输助手（filehelper）作为收发端点 |
| 账号被限制或封禁 | 个人号自动化本身处在平台规则限制范围内，批量行为尤其敏感 | 不要在真实账号上做群发、加好友等操作；先评估合规与账号风险 |
| 现代 Python 下安装或运行报错 | 该库面向 Python 2.7 / 3.5 时期的生态，未对当前 Python 版本做兼容承诺 | 用独立虚拟环境隔离；不要为它降级主环境；把兼容性问题当预期而非意外 |

## 权限与用途说明

| 能力 | 是否申请 | 用途 |
|---|---|---|
| 网络访问 | 需要 | 与平台服务端通信完成扫码登录、收发消息、拉取联系人；这是本库运行的前提 |
| 读取文件 | 需要 | 读取本地保存的登录状态文件以实现免重复扫码；读取要发送的附件 |
| 写入文件 | 需要 | 写登录状态文件；`msg.download()` 把收到的图片 / 语音 / 文件存到本地；登录后默认还会生成并删除二维码图片 |
| 凭证 | 需要 | 登录态本身就是凭证，等价于你的个人账号身份；不要把它传播给他人，也注意状态文件不要泄露 |
| 子进程 / 后台常驻 | 需要 | `itchat.run()` 是阻塞式消息循环，必须以常驻进程方式运行；登录态过期后需要人工扫码 |
