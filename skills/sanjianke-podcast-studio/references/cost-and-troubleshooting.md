# 成本口径与排错手册

## 一、币值与换算

- **1 元 = 100 点**（1 点 = 0.01 元）
- **结算只认 `usage.points_cost`**。
  平台的 `pricing_matrix` / `tenant_*` 字段**半数不可信**——本包不拿它们算钱，
  只用**实测常量**做报价，再用真实扣点做对账。

---

## 二、实测单价（本包自己跑出来的）

| 项目 | 实测单价 | 样本 | 说明 |
|---|---|---|---|
| 配音 `voice_tts/tts` | **50 点/千字** | 21 / 24 / 46 / 52 / 57 字五组 + 7 字一组 | 逐条严格线性，**无最低消费** |
| 配乐 `music_generation/create` | **65 点/次** | 1 次实测 | 与报价完全一致 |
| 歌词 `music_generation/lyrics` | **12 点/次** | 未实测（平台口径） | `--with-lyrics` 时计 |
| 语音转文字 `voice_tts/stt` | 40 点/次 | 未实测（平台口径） | 本包未使用，仅登记 |

### 配音单价的实测校验（本包最重要的一条对账）

```
21 字 → 1.05 点    1.05 / 21 × 1000 = 50.0
24 字 → 1.20 点    1.20 / 24 × 1000 = 50.0
46 字 → 2.30 点    2.30 / 46 × 1000 = 50.0
52 字 → 2.60 点    2.60 / 52 × 1000 = 50.0
57 字 → 2.85 点    2.85 / 57 × 1000 = 50.0
 7 字 → 0.35 点    0.35 /  7 × 1000 = 50.0
────────────────────────────────────────────
200 字 → 10.00 点  →  实测 50.0 点/千字（与申报口径完全一致）
```

**结论：「50 点/千字」成立，且无最低消费**——21 字的短句按比例收 1.05 点，
没有被向上取整到某个最小值。这条很重要：它意味着**合并台词不会省钱，
拆开也不会多花钱**，于是切块策略可以纯按"重试成本"来定。

### 30 分钟一期的成本口径

| 项目 | 数量 | 点数 | 金额 |
|---|---|---|---|
| 配音 | 7950 字 | 397.5 | 3.98 元 |
| 配乐（片头 + 转场 + 片尾） | 3 次 | 195 | 1.95 元 |
| **合计** | | **592.5** | **5.93 元** |

（语速口径 265 字/分钟，见 `podcast-script-method.md`。）

### 文本大模型的单价：平台不公开，本包不编

`/api/v1/models` 的返回里**没有任何价格字段**，`/api/v1/pricing` 也不覆盖
`chat/completions`。所以：

- `cost` 不给 `--points-per-ktok` 时**只报 token 数，不报金额**；
- 平台任务列表里**看不到**同步 chat 调用的逐条扣费（本包实测确认），
  所以只能从 token 数看规模。

实测 token 规模（8 分钟一期）：

| 步骤 | prompt | completion | total |
|---|---|---|---|
| `outline` | 444 | 767 | 1211 |
| `script` | 1162 | 3205 | 4367 |

对照平台上历史 chat 任务的 `actual_points`（0.04 ~ 1.54 点/次），
文本环节的成本量级是**几分钱到一两毛**，不是成本大头。

## 三、报价与预算：两道而不是一道

```
$ python3 scripts/run.py voice --outdir D:/podcast/ep01

=== 配音（5 个片段 / 200 字） 成本前置报价 ===
  · 配音 voice_tts/tts                       10.0 点  ≈ 0.1 元
  合计 10.0 点 ≈ 0.1 元（1 元 = 100 点；结算只认 usage.points_cost）
✗ !! 没有确认就开跑：请加 --yes 明确同意，或用 --budget N 封顶。
```

| 情形 | 结果 |
|---|---|
| 既没 `--yes` 也没 `--budget` | **exit=2**，一分钱不花 |
| 报价 > `--budget` | **exit=5**，就地中止（还没花钱） |
| 跑的过程中真实扣费 > `--budget` | **exit=5**，就地中止，已完成的片段保留 |
| 正常 | 每块都打印 `实际扣费 X 点 ≈ Y 元` |

**为什么是两道**：

- 没有报价就开跑 → 用户不知道要花多少，被动扣费；
- 有报价没预算 → 报价算漏了（稿子比预期长）就会一路花下去。

每次调用后都会把报价与实际**对账**，差得明显时明确标出：

```
  配音 001-主持人.mp3：实际扣费 2.3 点 ≈ 0.023 元
  配乐 intro：实际扣费 65.0 点 ≈ 0.65 元（与报价 65.00 点相差 +0.00 点，以实际为准）
```

## 五、排错手册

### 1. `code=0「任务处理失败，请稍后重试」`（配音）

九成是 **`reference_id` 抄短了**：`list_voices` 的 `id` 是 **32 位十六进制**。

```bash
python3 scripts/run.py voices          # 整条复制，别手打
```

判断方法：去掉 `--voice-a` / `--voice-b` 再跑一次。不指定音色用平台默认音色，
能成功就是音色 ID 的问题。

### 2. `401 / 402 / 404`

| 码 | 含义 | 处理 |
|---|---|---|
| 401 | Key 无效或过期 | 到 https://api.a7w.cn/ 重新领 |
| 402 | 点数不足 | 充值后重试（失败任务平台会退回点数） |
| 404 | 模型不存在 | `run.py models` 现查在架模型名 |

`deepseek-chat` 这个别名实测可用，但它**不在** `/api/v1/models` 的返回列表里——
"列表里没有"不等于"不能用"。

### 3. 时长闸门总在拦

- 模型写少了 → 重跑 `script`（提示词里已按章给配额）；还短就换模型或调大 `--max-tokens`
- 语速口径不对 → `--chars-per-minute` 改成自己节目的值

### 4. 对话结构闸门报「只有 1 个角色」

模型写了朗读稿。检查 `--role-a` / `--role-b` 有没有被改成同一个名字；重跑通常就好。
**本包不提供单角色的绕过开关**——那道闸门就是这个包的立身之本。

### 5. `--outdir 指到了包内`

产出音频会让整个包在 SkillHub 上 400（白名单只放
`.md .py .txt .json .sh .js .yaml .yml .csv`）。换到包外目录，
例如 `%TEMP%\podcast` 或 `D:/podcast/ep01`。

### 6. `Task 轮询超时`

异步任务（长文本配音 / 配乐）默认 1800 秒超时。超时后任务**可能还在跑**：

```bash
python3 scripts/a7w.py task <task_id>
```

`a7w.call` 内部对网络类错误（含 `WinError 10054 远程主机强迫关闭了一个现有的连接`）
有退避重试——长异步任务几乎必踩这个，不重试会让已冻结的点数白丢。

### 7. ffmpeg 报 `Error opening output ... Permission denied`

先换系统里另一个 ffmpeg 构建试试。实测环境里有一个构建在 `%TEMP%` 下写文件被拒，
另外几个正常——这是环境限制，不是磁盘权限问题。

### 8. 报价与实扣不一致

以 `usage.points_cost` 为准。本包的报价常量来源见上面第二节；
如果平台调价，`_report_spend` 会在差值超过 5%（且 ≥ 0.5 点）时明确标出来。

## 六、`--json` 契约

```bash
python3 scripts/run.py cost --minutes 30 --json      # --json 写在后面
python3 scripts/run.py --json cost --minutes 30      # 写在前面也认
```

| 情形 | stdout |
|---|---|
| 成功 | 结果对象 + `"ok": true` |
| 失败（本次还没吐过结果） | `{"ok": false, "exit": N, "error": {"kind": ..., "message": ...}}` |
| 失败（结果已经吐过了） | `ok` 写在那个结果里（不再补信封，守住"stdout 只有一个 JSON"） |
| 未预料异常 | `{"ok": false, "exit": 1, "error": {"kind": "internal", ...}}`，完整栈打 stderr |

退出码语义**一个都不变**；非 `--json` 模式的输出一个字符都不变。

## 七、这条链路的钱花在哪（结论）

| 环节 | 占成本 | 能不能省 |
|---|---|---|
| 配音 | **约 67%** | 稿子短一点最直接；`--sample-chars` 先试链路 |
| 配乐 | **约 33%** | 只做片头（65 点）比三个都做省 130 点；纯器乐不生成歌词省 12 点/次 |
| 文本 | 可忽略 | — |

**先跑 `--sample-chars 200` + `--cues intro` 验证链路（约 75 点 ≈ 0.75 元），
确认音色与风格对了，再跑整期。**
