# 三剪客 · 想法压力测试 Skill

一套原创的深度追问方法，围绕用户的想法连续追问，把隐藏假设、遗漏前提和内在矛盾一层层问出来。

重要决定前的自查、选题策划、新项目立项——凡是「自己越想越觉得能做、但心里没底」的时刻，都适用。

---

## 前置条件

- **不需要**任何网络、API Key、账号、软件或插件。纯方法论，一张纸就能跑。
- **需要**一个愿意把想法讲完整的提出者（可以是你自己）。
- **需要**一个能容纳「我的想法有漏洞」这句话的场合。有领导在场且结论已定时，这套流程会被走成表演。
- **建议**准备纸笔或一份可写的文档。六层追问的产出是**写下来的句子**，纯口头追问会在十分钟内退化成聊天。

---

## 使用

最小可用路径：**先过十分钟速问版**，答不上四个，就先回去补调研；答得上，再走完整流程。

### 十分钟速问版

拿你的想法，依次回答这六个问题，每问限三句话，答不上来就写「答不上来」——那四个字本身就是结论。

| # | 问题 | 答不上来意味着 |
|---|---|---|
| 1 | 这件事做成了，指标动的是哪个数？现在是几，目标几？ | 目标还没确权 |
| 2 | 我亲眼见过的事实有哪些？哪些是听来的、读来的、推出来的？ | 证据层薄 |
| 3 | 这个方案要成立，必须先成立的三件事是什么？ | 假设还是隐形的 |
| 4 | 有没有一种合理的情况会让它彻底失败？具体到人和月份。 | 没想过失败路径 |
| 5 | 最坏情况下我要赔进去什么？上限是多少？ | 代价没上界 |
| 6 | 如果不做这件事，会怎样？ | 还没把「不做」当成一个选项 |

### 完整流程（45~90 分钟）

```text
第 0 步（2 分钟）  复述：用追问者自己的话把想法说一遍，请提出者纠正
第 1 轮（15 分钟） 目标层 → 事实层      产出：成功标准 + 事实/推理/传闻对照表
第 2 轮（20 分钟） 假设层 → 反例层      产出：三条致命假设 + 三条反例
第 3 轮（20 分钟） 代价层 → 替代层      产出：代价上限 + 两个替代方案
第 4 步（5 分钟）  打分卡 + 止损线      产出：分数、结论、未决清单
第 5 步（5 分钟）  行动项回执           产出：谁、在什么时候、验证哪一条
```

### 六层框架速查

| 层 | 它回答什么 | 产物 |
|---|---|---|
| 一 · 目标 | 我们到底在争什么 | 一句可检验的成功标准 + 底线清单 |
| 二 · 事实 | 其中有多少是真的 | 事实 / 推理 / 传闻三分表 |
| 三 · 假设 | 什么必须成立 | 三条致命假设 + 各自验证成本 |
| 四 · 反例 | 什么情况会让它死 | 三条反例 + 预警信号 + 可逆性 |
| 五 · 代价 | 值不值 | 六栏代价表 + 最坏情况上限 |
| 六 · 替代 | 是不是最优解 | 两个替代方案 + 「不做」的结论 |

### 打分与止损

六层每层 0~4 分，满分 24：20~24 可走；15~19 补验证再推进；10~14 回炉补事实层与代价层；5~9 降级为低成本试探；0~4 先回去把目标层答完。

四条止损线（任一条触发，立刻停止追问、当场给结论）：目标层 0 分 / 假设层连续两条无法验证 / 代价层出现无法承受的上限 / 发现「不做」比做更好。

## 依赖

- **必需**：一个提出者 + 一份可写的载体（纸、文档、白板皆可）。
- **推荐**：一个中立的追问者。互问时最容易出的问题是两个人都在讲方案、没人提问——角色要分开。
- **不需要**：网络、API Key、数据库、Docker、任何付费服务、任何运行脚本。

---

## 安全

- 不内嵌任何密钥，不读取任何凭证。
- 不联网、不调用任何远程接口，因此不会把内容发往外部地址。
- 不读文件、不写文件、不执行子进程、不常驻后台。
- 追问会触及内部信息（预算、瓶颈、人事、未公开计划）。本 Skill 不做任何存储与转发，但对话记录归你的客户端管。涉及保密内容时，用「一笔预算」「一个关键人」这类占位说法代替真实数字与姓名，框架一样跑得通。
- 权限范围已在 `SKILL.md` 的「权限与用途说明」中逐项列明，能力边界见同文件的「能力边界」一节。
