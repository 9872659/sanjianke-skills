# 三剪客 · 想法压力测试

一套原创的深度追问方法，围绕用户的想法连续追问，把隐藏假设、遗漏前提和内在矛盾一层层问出来。

大多数想法不是被否掉的，是被**绕过**的。你把方案讲了一遍，对面点头说「挺好」，两周后它卡在一个谁都没提过的前提上。因为讲方案的时候，说话的人和听的人都在自动补全——你默认对方知道背景，对方默认你算过账。补全的那部分没人检查，它才是真正的风险所在。

这套 Skill 做的事情很窄：**不给建议，只问问题**，按固定顺序把一个想法拆成六层，一层层把「默认成立」的东西变成「写出来的句子」。写出来了，才谈得上验证；没写出来，双方争的其实是两个不同版本的同一个词。

**读完你会拿到**：3 份参考文件、1 套六层追问框架、1 份 110 条按层分类的问句库、1 张五档评分表、4 条止损线、3 个完整示例（选题 / 立项 / 个人决策）。

## 快速开始

### 十分钟速问版（先问下来再说）

拿你的想法，依次回答这六个问题，**每问限三句话**，答不上来就写「答不上来」——那四个字本身就是结论。

| # | 问题 | 答不上来意味着 |
|---|---|---|
| 1 | 这件事做成了，**指标动的是哪个数**？现在是几，目标几？ | 目标还没确权，后面全是空谈 |
| 2 | 我**亲眼见过**的事实有哪些？哪些是听来的、读来的、推出来的？ | 证据层薄，先补一轮调研 |
| 3 | 这个方案要成立，**必须先成立的三件事**是什么？ | 假设还是隐形的，风险不可见 |
| 4 | 有没有一种**合理的情况**会让它彻底失败？具体到人和月份。 | 没想过失败路径，先想 |
| 5 | 最坏情况下我要**赔进去什么**？上限是多少？ | 代价没上界，投入会失控 |
| 6 | 如果**不做**这件事，会怎样？ | 你还没把「不做」当成一个选项 |

六问能答上四个以上，值得往下走完整流程；低于四个，先回去补调研，别急着开评审会。

### 完整流程（45~90 分钟）

```text
第 0 步（2 分钟）  复述：用追问者自己的话把想法说一遍，请提出者纠正
第 1 轮（15 分钟） 目标层 → 事实层      产出：一句可检验的成功标准 + 一张事实/推理/传闻对照表
第 2 轮（20 分钟） 假设层 → 反例层      产出：三条致命假设 + 三条反例
第 3 轮（20 分钟） 代价层 → 替代层      产出：代价上限 + 两个替代方案
第 4 步（5 分钟）  打分卡 + 止损线      产出：分数、结论、未决清单
第 5 步（5 分钟）  行动项回执           产出：谁、在什么时候、验证哪一条
```

每一层的完整问题清单、判据和产出物格式见 `references/grill-framework.md`。**顺序不能跳**：目标没对齐就直接挖假设，你挖的是一堆无关的假设。

### 一个演示片段

> **提出者**：我想做一个「给中小企业做 AI 落地陪跑」的服务，按季度收费。
>
> **追问者**：你上一句说「中小企业」——你手上现在有几个这样的客户，还在合作？
>
> **提出者**：说实话，一个，是朋友介绍的。
>
> **追问者**：好，那这是一条事实：客户数 = 1，来源是熟人。那么在什么条件下，这个 1 会变成 5？
>
> **提出者**：……得先证明交付不是我亲自盯着的。
>
> **追问者**：这句话就是你的第一条致命假设，我们记下来：**交付可脱离创始人**。

注意追问者全程没说过「你这个不靠谱」，只是在**区分事实和推理**、在**把形容词换成句子**。

## 追问的六层框架（速查）

| 层 | 它回答什么 | 一句话判据 | 产出 |
|---|---|---|---|
| 一 · 目标 | 我们到底在争什么 | 成功标准能被第三方检验吗？ | 一句可检验的成功标准 + 一条不做清单 |
| 二 · 事实 | 其中有多少是真的 | 每条信息能追溯到来源和时间吗？ | 事实 / 推理 / 传闻三分表 |
| 三 · 假设 | 什么必须成立 | 假设被说出口了吗？说出口就写成「只有…才…」 | 三条致命假设 + 各自验证成本 |
| 四 · 反例 | 什么情况会让它死 | 反例具体到人和月份，还成立吗？ | 三条反例 + 各自的预警信号 |
| 五 · 代价 | 值不值 | 代价有数额、有时间、有上限吗？ | 代价表 + 最坏情况上限 |
| 六 · 替代 | 是不是最优解 | 「不做」被认真算过吗？ | 两个替代方案 + 不做方案 |

前四层是**拆**，五、六层是**称重**。第六层问完还没出现任何动摇，答案不是「想法很好」，而是「你可能没给它最坏的那一版假设」。

## 打分判据（五档）

六层每层 0~4 分，满分 24。逐层的打分锚点、扣分理由怎么写见 `references/grill-framework.md`。

| 分数 | 结论 | 该做什么 |
|---|---|---|
| 20~24 | 论证扎实 | 可以走，但要留一条与假设挂钩的回滚线 |
| 15~19 | 方向基本成立，证据偏薄 | 补 1~2 条关键验证再推进 |
| 10~14 | 证据不足 | 回炉：先补齐事实层与代价层 |
| 5~9 | 目标与假设都没有成形 | 不要立项；把结论降级成一次低成本试探 |
| 0~4 | 还只是一个愿望 | 停。先回去把第一层答完 |

**四条止损线**（任一条触发，立刻停止追问，当场给结论）：

1. **目标层得 0 分**——几方对「做成什么样」各说各话。此时继续追问只会加深误伤，先回去对齐目标。
2. **假设层连续两条无法验证**——不要再往下挖，把它们转成待验证行动项，带着任务散会。
3. **代价层出现你无法承受的上限**——不再讨论收益，直接进入止损方案设计。
4. **替代层你发现「不做」比做更好**——坦白说出来。这套方法的目的是找到更好的决定，不是证明你能把想法扛下去。

## 能力边界

**覆盖**：

- 一套有固定顺序的六层追问框架，从「到底在争什么」走到「是不是最优解」
- 110 条按层分类、可直接照抄的问句，含少量高质疑密度的强问句与配套承接句
- 追问顺序的原理说明：为什么目标层必须在最前、为什么反例必须晚于假设、什么顺序会伤到人
- 五档打分锚点、四条止损线、结论模板与未决清单格式
- 三种真实场景的完整示例，含提出者的真实反应与追问者的处理
- 单人自问、双人互问、团队评审三种走法，以及六类常见反应的处理话术

**不覆盖**：

- **不查证事实。** 本 Skill 全程离线，不联网、不读文件。它只能把「听来的」标成待查，不能告诉你那个数是不是真的。事实真伪取决于你自己去核。
- **不给建议、不给方案。** 当提出者问「那你觉得我该怎么做」时，正确回应是把问题递回去。想法归你，方法不归它。
- **不做领域判断。** 它不知道你的行业毛利应该是多少、你的转化率算不算正常、这个赛道还有没有窗口。领域真理得由你和你的数据负责。
- **不做市场调研、不建财务模型、不算投资回报。** 代价层会逼你把数写出来，但数从哪来是你的事。
- **不保证问出真问题。** 判据是「**只有能改变结论的问题才算核心问题**」。问一百条无关的，不如问三条能翻盘的。
- **不适合日常小事。** 午饭吃什么、周报怎么写，不值得走这套流程。它给重要决定用。
- **不适合情绪急救。** 当对方正处于挫败或焦虑中，先处理情绪。追问在这个时候只会变成二次伤害。
- **不是评审淘汰工具。** 它的产物是一份更清楚的想法，不是一张否决票。拿它当枪使，团队很快就不说了。

## 依赖条件

- **必需**：一个愿意把想法讲完整的提出者（可以是你自己）。
- **必需**：能容纳「我的想法有漏洞」这句话的场合。有领导在场且结论已定时，这套流程会被走成表演，不如不跑。
- **推荐**：一个中立的追问者。互问时最容易出的问题是两个人都在讲方案、没人提问——角色要分开。
- **推荐**：纸笔或一份可写的文档。六层追问的产出是**写下来的句子**，口头的追问会在十分钟内退化成聊天。
- **不需要**：网络、API Key、任何软件、任何账号。一张纸就够。

## 已知限制

1. **提问者的水平就是结论的上限。** 一个自己没做过这类判断的人来问，问出来的多半是通用问题。框架能保证你**不问漏**，不能保证你**问得深**。
2. **对「数据本来就不存在」的领域会空转。** 全新品类、没有先例的事，事实层可能一片空白。这时正确的动作是把打分整体下调一档，并用最小成本试探代替论证。
3. **六层是顺序，不是真理。** 它覆盖的是最常见的漏洞位置，不覆盖全部。有的想法死法很怪（例如死于合规、死于关键人离职），需要你临时加一层——加层的写法见 `references/grill-framework.md`。
4. **强问句会被误读成人身攻击。** `references/question-bank.md` 里的强问句标注了高质疑密度，脱离承接句单独使用会伤关系。
5. **打分存在主观性。** 同一份想法，不同追问者给出的分层分可能差 2~3 分。分数的价值在于**暴露分歧在哪一层**，不在于绝对高低。
6. **一次追问改不掉深层执念。** 如果提出者的结论其实早就定了，追问会被逐条挡回来。止损线第 4 条就是为这种情况准备的——发现自己在替一个已定结论补论证时，直接说出来。
7. **本 Skill 不落盘、不留痕。** 追问结论只在对话里。需要留档请自己整理，否则下次还得从头问一遍。

## 自检清单

当你要追问一个想法（或自问），逐条打勾：

- [ ] **已复述**：我用提出者的话把想法说了一遍，并得到他一句「对，就这个意思」
- [ ] **目标先行**：第一层就问成功标准，没有跳到方案细节
- [ ] **事实分离**：表里出现了「听到的 / 读到的 / 推出来的」标记，不只是「我认为」
- [ ] **假设写成了句子**：「只有 X 成立，这个才成立」——X 是名词短语加数字，不是形容词
- [ ] **反例具体**：至少一条反例带上了具体的人和具体的月份，不是「万一不顺利」
- [ ] **代价有数**：钱、时间、机会、关系四栏至少三栏填了数或明确写「未知」
- [ ] **不做算过**：「不做」被当成一个正式方案，写了它的收益和损失
- [ ] **核心问题判据**：我提的每条问题都答得上一句「它改变哪个结论」
- [ ] **有温度**：全程至少说过一次「这一点你是对的」，没有人被逼到墙角
- [ ] **有行动项**：散会前每条未决假设都落到「谁、什么时候、验证什么」
- [ ] **没越界**：我没有替对方做决定，也没有替他宣布结论
- [ ] **止损线检查**：四条止损线我逐条看过了，没有触发或已按触发的处理方式执行
