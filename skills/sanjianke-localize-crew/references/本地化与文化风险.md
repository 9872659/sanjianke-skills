# 本地化与文化风险

本包的本地化判定**不靠模型自报**。术语一致性与数字单位保全都是**纯本地、确定性**的：
同一个输入跑两次结果完全一样，可以进 CI，也可以零成本重跑。

---

## 一、术语一致性（`glossary_check`，纯本地零成本）

### 判定流程

1. 按**句子**找术语表里每个源词在源文里的出现位置 → 得到出现位置集合
2. 用译文返回的逐句对齐（源句 ↔ 译句）定位每一处对应的目标句
3. 逐处检查该目标句里有没有**规范译法的变体**
4. 判定：

| 情况 | 判定 | 是否硬闸门 |
|---|---|---|
| 有 ≥1 处用了规范译法、又有 ≥1 处没用 | **不一致（同词多译）** | **是** |
| 一处都没用规范译法，但该词在源文里出现 ≥2 次 | **术语表未落地** | **是** |
| 只出现一次且译法不同 | 单处译法不同（可能是合理意译） | 否，仅提示 |
| 同一源词出现 0 次 | 词表项已忽略 | 否 |
| 全篇都用规范译法 | 全篇一致 | 否 |

**报告必须给出全部出现位置**：第几句源文、对应第几句译文、那一句译文是什么。
只说"术语不一致"而不说在哪，等于没说。

### 归一化为什么是必需的

`Short Drama` / `short-drama` / `short dramas` 在术语一致这件事上是**同一个译法**。
不做归一化，闸门会把格式差异报成"同词多译"：

| 归一动作 | 处理的形态 |
|---|---|
| 转小写 | `Short Drama` vs `short drama` |
| 抹掉标点与空白 | `short-drama` / `short drama` / `short  drama` |
| 去英文复数尾 `-s` / `-es` | `short dramas` vs `short drama` |
| 只对英文类目标语言做复数归一 | 中文 / 日文不该被去尾 |

**归一不到位，闸门第一天就会被刷爆，第二天就没人看了。**

### 为什么这件事必须本地做

如果只让模型"自己检查一下术语一致吗"，你会得到三种不可用的结果：

1. **自报不一致但指不出位置** —— 没法改
2. **明明不一致却说一致** —— 不可复现，也没法零成本重跑
3. **同样的问题这次报、下次不报** —— 温度一变就变，CI 里没法用

本地判定没有这三个问题。代价是它只能识别"字面不一致"，
**看不出"两个不同写法在语义上等价"** —— 后者需要人看，所以单处不同只提示、不拦。

### 怎么用

```bash
python3 scripts/run.py glossary_check --file 源文.md --market us \
    --translation /tmp/lc/translation.json \
    --glossary /tmp/lc/glossary.json
```

退出码：`0` 全篇一致 / `3` 有不一致。**不花钱，可以反复跑。**

## 二、数字与单位保全（纯本地）

### 抽取与换算

从源文里抽「数字 + 单位」（确定性），再按**目标市场**算期望值：

| 量纲 | 登记的单位 | 基准 | 目标市场用英制时换算成 |
|---|---|---|---|
| 质量 | 斤(=0.5kg) / 公斤 / 千克 / 克 / 磅 / lb | kg | **lb**（×2.2046226218） |
| 长度 | 米 / 厘米 / 毫米 / 公里 / 英里 / 英尺 / 英寸 | m | **ft**（×3.280839895） |
| 面积 | 平方米 / 亩 / 公顷 / 平方英尺 | m² | **sq ft**（×10.76391042） |
| 温度 | 摄氏度 / 华氏度 | — | 摄氏→华氏 `C×9/5+32` |

`IMPERIAL_MARKETS = {"us"}`。公制市场（eu / jp / sea / me / br）下，
源文用公制就不需要换算；源文用英制则换算回公制。

### 判定口径（这里返工过一次，写清楚免得再想错）

对每一条「数字 + 单位」事实：

| 需要换算吗 | 原数字在译文里吗 | 换算后的值在译文里吗 | 判定 |
|---|---|---|---|
| 是 | — | **在** | ✅ 这个事实保住了（3 斤 → 3.31 lb 是合格的） |
| 是 | 在 | 不在 | ⚠️ **没本地化 / 算错**（3 斤 译成 3 kg 落这里） |
| 是 | 不在 | 不在 | ❌ **丢数字** |
| 否 | 在 | — | ✅ |
| 否 | 不在 | — | ❌ **丢数字** |

**关键点**：需要换算时，**换算后的值在就等于这个事实在** ——
不能因为"原文的 3 没出现"就判丢数字，那样每一处合格换算都会被误报。
报告里同时给 `present`（是否保住）与 `number_as_source`（原数字在不在）两栏，
遇到争议时按这两栏分开看。

### 「数字还在」的宽松判据

`number_in_text()` 认这些写法，都是"数字还在"：

- 直接形态：`3` / `3.0` / `3.00`
- **中文数字**：`三` / `一百`
- **英文拼写**：`three` / `twenty` / `one hundred`
- 换算形态（在换算判定那一层）

宽松是故意的：这条闸门要抓的是**数字整条消失**，不是"写法变了"。
把"3"改成"三"就报警的闸门，第一天就会被关掉。

### 货币：不给汇率就不猜

| 情况 | 行为 |
|---|---|
| 没给 `--fx-rate` | **只查数字与货币符号在不在**，不判断金额对不对 |
| 给了 `--fx-rate` | 对 `us`/`eu`/`jp` 三个市场做 CNY 换算，并检查换算后的金额是否出现 |

本包**不提供、不缓存任何汇率数据** —— 汇率是外部输入，随时间变动，
编一个"大概的"汇率比不换算更糟。

### 误报的可能形态

- 「3 斤」译成「约 1.5 公斤」—— 数量级对了但数值不同，会落进"没本地化"。
  提示词里已明确要求按标准系数换算并登记 `unit_notes`，模型没做就会命中。
- 「88 元」在公制市场被译成「88 yuan」—— 数字在，判过。
  货币符号本地化不在本闸门职责内（它只管数字与单位），交给那一席模型判断。

遇到这两类，先看报告里 `expected` 那一栏（期望值是什么、依据什么系数），
再决定是改译文、改提示词，还是人工确认。

## 三、六个市场的文化与非合规红线

`--market` 同时决定文化适配的规则包与合规的法域。**市场进断点 key** ——
换成日本市场而复用上一次的合规结论，是这类工具最危险的一种静默复用。

### 3.1 美国 `us`

| 类别 | 内容 |
|---|---|
| 宗教 | 基督教（新教/天主教）为主，同时有大量犹太教、穆斯林、无宗教人群 |
| 要盯 | 宗教符号与节日的商业化边界；种族/移民/原住民/奴隶制历史（极敏感）；个人隐私与数据；性别与身体表述；枪支/酒精/大麻/处方药；夸张宣传的法律后果 |
| 颜色 | 红色可以；避免中式"黑色=丧事"联想；彩虹色在部分语境会被读成政治立场 |
| 数字 | `13`（部分酒店楼层跳过）；`4` 不是禁忌 |
| 幽默 | 反讽与自嘲有效；对宗教、种族、体型的玩笑几乎必然翻车 |
| 政治 | 党争、选举、移民政策、堕胎、枪支管制 —— 一律不碰 |
| 法域 | FTC 广告规则（宣称必须有可举证依据）+ 各州消费者保护法 |
| 平台 | Meta / TikTok / Amazon 均要求可举证；Amazon 禁止在 listing 里写竞品名 |

### 3.2 欧盟 `eu`

| 类别 | 内容 |
|---|---|
| 要盯 | 各国差异极大（北欧/南欧/东欧不能当同一个市场）；环保与可持续宣称受强力监管；GDPR；动物福利/劳工权益/性别平等；历史符号（纳粹、极权、殖民）零容忍 |
| 颜色 | 因国而异：德国忌黑/棕，法国忌墨绿，比利时忌蓝（政治联想） |
| 数字 | `13`（多国）、意大利忌 `17` |
| 幽默 | 英式自嘲可以；对宗教/战争/民族的玩笑零容忍 |
| 政治 | 党争、难民政策、脱欧、俄乌 —— 一律不碰 |
| 法域 | UCPD（不公平商业行为指令）附件一 31 项「永远不公平」的商业行为 + GDPR + 各国广告法 |
| 平台 | TikTok EU / Meta 对 greenwashing 与健康宣称会直接拒登 |

### 3.3 日本 `jp`

| 类别 | 内容 |
|---|---|
| 要盯 | 敬语层级（です/ます ↔ である）与受众身份必须匹配；「本音/建前」——直白否定式读起来很冲；数字与谐音禁忌；对"效果绝对"类宣称容忍度极低 |
| 颜色 | 白（丧事）、黑（丧事）慎用于喜庆场景 |
| 数字 | `4`（し=死）、`9`（く=苦）、`42`（死に） |
| 幽默 | 偏轻自嘲与共感；直接调侃受众会适得其反 |
| 政治 | 靖国、战争责任、天皇、在日外国人 —— 一律不碰 |
| 法域 | 景品表示法（優良誤認・有利誤認）+ 薬機法（功效宣称）+ 特定商交易法 |
| 平台 | Yahoo!広告 / Meta JP 对「No.1」类表示要求出典标注，否则拒登 |

### 3.4 东南亚 `sea`（印尼 / 泰国 / 越南 / 菲律宾）

| 类别 | 内容 |
|---|---|
| 要盯 | **印尼：清真（Halal）认证是硬门槛**，猪/酒精/非清真成分不能出现；**泰国：王室不可戏谑**（法律后果极重）、佛像不得商用、头部神圣；越南/菲律宾：语言本地化程度要求高；价格敏感但偏好本地化过的品牌；肤色相关表述极敏感 |
| 颜色 | 泰国忌黑（丧）与对王室的颜色联想；印尼绿色是宗教色，不可轻用 |
| 数字 | 无强禁忌；泰国部分语境忌 `6` |
| 幽默 | 依赖语言双关，直译过去大多失效；不要拿宗教与王室开玩笑 |
| 政治 | 王室（泰国）、宗教派别（印尼）、南海议题（越南）—— 一律不碰 |
| 法域 | 印尼 BPOM / Halal 认证 + 泰国 Consumer Protection Act + 越南 Advertising Law |
| 平台 | Shopee / Lazada / TikTok Shop 印尼站要求 Halal 与 BPOM 资质才允许上架 |

### 3.5 中东（海湾六国）`me`

| 类别 | 内容 |
|---|---|
| 要盯 | **清真：猪、酒精、非清真成分一律不能出现，明示或暗示都不行**；斋月期间的排期与文案语气要专门处理；女性形象须保守呈现、不得物化；左手/鞋底朝向等符号禁忌 |
| 颜色 | 绿色是宗教色（不可轻用）；金色/白色可；避免用于宗教器物的图形 |
| 数字 | 无强数字禁忌 |
| 幽默 | 反讽常被读成冒犯，不宜使用 |
| 政治 | 宗教、教派、以色列/巴勒斯坦、王室 —— 一律不碰 |
| 法域 | 各国广告法（以伊斯兰教义与公共道德为底线）+ 沙特 GAMR 广告审批 + 阿联酋 NMO |
| 平台 | Snapchat / TikTok 中东站点要求斋月期间用专用素材，宗教内容需审核 |

### 3.6 巴西 / 拉美 `br`

| 类别 | 内容 |
|---|---|
| 要盯 | 葡语（巴西）与西语（拉美）**不能混用**；家庭与社交场景权重极高；肤色与阶层（不得暗示阶层优越感）；本地节日（狂欢节、亡灵节）不能当通用道具 |
| 颜色 | 紫色与丧事相关，慎用为喜庆主色 |
| 数字 | `13`（部分人群） |
| 幽默 | 自嘲与夸张式幽默有效；宗教与性别的玩笑风险高 |
| 政治 | 军政时期、原住民议题、党争 —— 一律不碰 |
| 法域 | 巴西 CDC（消费者保护法典）+ CONAR 广告自律准则 |
| 平台 | Meta BR 对医疗与金融类广告要求资质文件；TikTok BR 禁止未成年人形象用于带货 |

## 四、合规的两侧口径（本包照抄同族 `review-board` 的教训）

同族 `review-board` 真机踩过一次，很典型：合规官写

> 「无法举证为 100% 成立」「明确禁止代发、代拍、刷量」「第一反应不是厉害」

这是在**要求删除 / 指出风险**，不是自己在做违规宣称 —— 而 `100%`、`刷量`、`第一`
都被当成命中拦下了。**这类误报会让用户干脆关掉整个合规闸门，那比漏报更糟。**

### 本包的做法：材料侧与产出侧分开

| 侧 | 扫什么 | 口径 |
|---|---|---|
| **材料侧**（源文） | 全扫高 / 中 / 低 | 源文是要被翻出去的东西，**照查**；只豁免登记的普通用法（如「这笔账里最大的一块」） |
| **产出侧**（译文 + 各席裁决文书） | 只扫**高风险** | 三条收窄规则见下 |

产出侧的三条规则（**都能解释**，不是拍脑袋）：

1. **只查高风险**。中低风险项与 `最X` 列进 `contextual_only` 提示人工看，**不拦**。
   裁决文书里「这笔账里最大的一块」是普通中文程度用法，不是商品宣称。
2. **引用材料**：该词在源文/译文里本来就有 → 判为引用，不计命中。
3. **警告语境**：命中所在**整个小句**里有禁止/举证/风险类标记词 → 判为"提到/在禁止"，
   不计命中。

### 两个必须注意的实现细节（都是真机踩出来的）

**细节一：标记词必须落在命中词本身之外。**

`META_CONTEXT_RE` 里有「保证」。而「本方案**保证**过审」里的命中词**就是**「保证」——
于是"自己在承诺"被读成"在禁止承诺"，闸门直接失去牙。
所以判定时要检查标记词的位置与命中词的位置有没有重叠，**重叠就不算"提到"**。

**细节二：窗口必须是整个小句，不能是固定 24 字。**

「本稿禁止使用 guaranteed 这类绝对化用语」里，命中词与标记词隔了十几个字，
24 字的窗口不够，会把"在禁止"误判成"在主张"。
所以 `_ctx_window()` 取**命中所在小句的全部文字**，且**不跨句末标点** ——
跨句取词会把上一句的"禁止"借给下一句的违规宣称。

### 被排除的**全部留原因**

每条被排除的命中都带 `not_counted_reason`，进
`gates.compliance_quoted` / `gates.compliance_mentioned` / `gates.compliance_contextual_only`。
**不静默丢弃** —— 否则"闸门为什么没拦"永远查不清。
