# 三剪客 · 语音识别与说话人分离工具箱 Skill

FunASR：语音识别与说话人分离工具箱 的安装、常用命令与避坑要点

---

## 前置条件

- 一台能装 Python 的机器（Windows / macOS / Linux 均可），Python 3.8 及以上（以上游文档为准）
- **先装 PyTorch 与 torchaudio，再装 FunASR**：这是上游明确要求的顺序，装反了会在导入或推理时报错
- GPU 路线需要可用的 NVIDIA 驱动与匹配的 CUDA wheel；装完先用 `python -c "import torch; print(torch.cuda.is_available())"` 确认能否用 GPU，打印 False 就只能走 CPU
- 磁盘留出数 GB 空间：PyTorch 本体加上模型权重（按 checkpoint 从几百 MB 到数 GB 不等）
- 素材要先能拿到音轨：视频文件请先用剪辑或转码工具取出音频，本工具处理的是音频
- 需要转写服务化时，准备 `fastapi` / `uvicorn` / `python-multipart`，并接受"服务默认无鉴权、要先绑回环地址"这条前提

---

## 使用

这个 Skill 教 Agent 做四件事：

1. **判断该不该用**——音频只有一两分钟、只需要一次转写时，装环境的时间比转写本身长，应该先劝退
2. **装起来并跑通第一条**——按"先 PyTorch 后 FunASR"的顺序装，用命令行或 Python SDK 把一段音频转成文字/字幕
3. **选对模型组合**——离线还是流式、要不要标点、要不要说话人区分、要不要情绪标签，分别对应哪个 checkpoint 和哪个参数
4. **避开已知的坑**——流式缺字、说话人编号被误当人名、长音频内存爆掉、本地服务无鉴权

典型请求：

- "把这个音频转成 srt 字幕"
- "这段访谈分一下谁说的哪句"
- "识别结果没标点，整理一下"
- "我要在服务器上自建一个转写接口"
- "直播要实时字幕"

具体命令与参数见 `SKILL.md` 的「安装」「常用操作」「常见坑」三节。文中所有命令与参数名均取自上游仓库的公开说明；不同版本可能调整，执行前请对照仓库最新文档与 `--help` 输出。

## 依赖

- `funasr`（本体，PyPI 可装）
- `torch` + `torchaudio`（必须先装，版本与硬件匹配）
- 可选：`fastapi`、`uvicorn`、`python-multipart`（本地 HTTP 服务）
- 可选：`funasr[silero]`（换用 silero-vad 做语音活动检测）
- 可选：`vllm`（GPU 大批量加速路径，版本要求以仓库文档为准）
- 可选：`soundfile`（流式示例读音频用）
- 外部件：Docker（容器部署）、ffmpeg（若素材是视频，需先取音轨）
- 模型权重：首次调用按 checkpoint 自动下载，体积从几百 MB 到数 GB 不等

## 安全

- 不内嵌任何密钥：本 Skill 只记录命令与参数，本地推理路径本身不需要账号或 Key
- 模型权重从公开仓库下载，请确认下载来源与网络环境可信；权重许可证与工具箱许可证分开，使用前看清单个模型的卡片
- **本地 HTTP 服务默认没有鉴权**：上游明确建议先绑定回环地址（`127.0.0.1`），对外暴露前必须先加鉴权与访问控制。不要直接绑 `0.0.0.0` 放到公网，那等于开放一个免费转写接口
- 语音素材常含个人信息（声音、姓名、对话内容）。转写结果与中间文件按敏感数据处理，别随手放到共享目录或同步盘
- 说话人输出是一段录音内部的匿名编号，**不能当作身份识别结论**，也不要在对外文案里把人名与编号对应起来
- 长任务注意显存与端口残留：异常退出可能留下占着显卡或端口的进程
