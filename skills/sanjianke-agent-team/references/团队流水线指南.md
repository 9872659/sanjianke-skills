# 团队流水线指南

多角色流水线的活儿分四步：**拆角色 → 定 SOP → 传产出 → 落盘**。
这份文档讲怎么把每一步做对，以及模型入口怎么指向 `api.a7w.cn`。

---

## 一、把模型入口指向网关

框架通常把模型配置集中放在一处（YAML 文件或环境变量），改掉地址与 Key 即可：

```yaml
llm:
  api_type: "openai"
  model: "DeepSeek-V4-Pro"
  base_url: "https://api.a7w.cn/api/v1"
  api_key: "sk-你的key"
```

或：

```bash
export OPENAI_API_KEY=sk-你的key
export OPENAI_BASE_URL=https://api.a7w.cn/api/v1
```

纯用 OpenAI SDK：

```python
import os
from openai import OpenAI

client = OpenAI(
    base_url="https://api.a7w.cn/api/v1",
    api_key=os.environ["A7W_API_KEY"],
)
```

| 场景 | 接口 |
|---|---|
| 角色推理、文档生成 | `POST /api/v1/chat/completions` |
| 需要看图的角色 | 同上，`model` 换视觉模型 |
| 生成类产物（语音 / 图像 / 视频） | `POST /api/v1/apps/<应用代号>/<接口代号>` |

## 二、角色分工与产出清单

| 角色 | 干什么 | 产出 |
|---|---|---|
| **产品** | 理解需求、拆用户故事 | 用户故事、竞品分析、需求清单与优先级 |
| **架构** | 定结构与接口 | 数据结构、模块划分、接口设计 |
| **项目** | 排期与拆任务 | 任务清单、里程碑、依赖关系 |
| **实现** | 写代码骨架 | 目录结构、文件清单、可运行的最小闭环 |
| **复核** | 找边界与遗漏 | 用例清单、边界条件、验收结论 |

**每个角色的产出都要落成文件。** 这样进度可见、可回溯，中途停下来也能交接。

---

## 三、按角色分档选模型

**这是整条流水线里最值钱的一条**：不是每个角色都需要最强模型。

| 角色 | 建议档位 | 例 |
|---|---|---|
| 需求拆解 / 文档整理 | 快模型 | `DeepSeek-V4-Flash`、`Qwen3.6-Flash` |
| 方案设计 / 内容撰写 | 中档 | `Qwen3.7-Plus`、`GLM-5`、`MiniMax-M3` |
| 架构设计 / 核心实现 | 强模型 | `DeepSeek-V4-Pro`、`GLM-5.2`、`Kimi-K2.6` |

换模型就是换一个字符串：**不用换 base_url、不用换 Key、账单还是同一份**。

> 模型清单会变。调用前读一次 `GET /api/v1/models`，以接口返回为准。

## 四、需求怎么写

需求质量直接决定产出质量。

| 写得好的需求 | 写得糟的需求 |
|---|---|
| 「做一个命令行待办工具，支持增删改查，数据存本地 JSON 文件，一条命令列出未完成项」 | 「做个有用的工具」 |
| 「一个小游戏：2048，键盘方向键操作，显示分数与最高分，游戏结束可重开」 | 「做个游戏」 |
| 「一个 CSV 清洗脚本：去掉空行、统一列名大小写、把日期列格式化成 YYYY-MM-DD」 | 「处理一下数据」 |

**判断口径**：需求里能不能看出**验收标准**？
看不出来就先补需求 —— 补需求花一分钟，返工花的是钱和时间。

**另外**：先拿小需求试跑（命令行小工具、小游戏这类边界清晰的），
看一次消耗多少点，再决定要不要上更大的需求。

## 五、产物目录

产物统一落在工作目录下的**独立子目录**（常见命名是 `workspace/` 一类），
**不要直接写进源码目录**。

跑之前确认三件事：

1. **产物根目录在哪** —— 跑完之后你知道去哪儿找。
2. **磁盘够不够** —— 一个完整项目就是一堆文件。
3. **有没有加进版本控制的忽略规则** —— 别让产物污染仓库。

---

## 六、成本估算

```
单次任务调用数 ≈ 角色数 × 每个角色的平均调用次数
单次任务成本   ≈ 调用数 × 单次调用 tokens × 对应模型的单价
```

**估算口径**：一条需求会触发几十次调用（五个角色、每个角色多轮），
**先跑一个小需求实测一次总消耗**，再按日任务量放大。

**三个降本手段**：

1. **按角色分档选模型** —— 最直接。
2. **需求写清楚** —— 返工一次就是整条链路重跑。
3. **拿小需求校准** —— 别拿模糊的大需求直接开跑。

---

## 七、产出怎么用

这类流水线产出的是**原型与骨架**，不是生产级工程：

- **可以拿**：需求文档、数据结构、接口设计、目录结构、可运行的最小闭环。
- **要自己补**：边界处理、错误处理、测试覆盖、性能与安全检查。

**正确姿势**：把它当「起步脚手架 + 设计文档生成器」，
拿到之后自己接手完善 —— 这比从零开始快得多。

---

## 八、上线自检

- [ ] `base_url` 指向 `https://api.a7w.cn/api/v1`，Key 走环境变量或配置文件
- [ ] 配置文件没有提交进仓库（已加忽略规则）
- [ ] 每个角色的 `model` 从模型清单里拿，不是猜的
- [ ] 需求写了明确的验收标准
- [ ] 产物目录确定，磁盘空间够
- [ ] 已用小需求实测过单次总消耗
- [ ] 网络超时后没有直接重提付费请求
- [ ] 产出被定位为骨架，接手后有补测试与边界处理的计划
