# 三剪客 · 跨平台聊天机器人框架 Skill

Koishi：跨平台聊天机器人框架 的安装、常用命令与避坑要点

---

## 前置条件

- 明确这个机器人要接**哪些聊天平台**，并已拿到对应平台的机器人凭据（token、App ID / Secret，或账号）。框架不代办平台侧的注册与认证。
- 选定一种安装方式，并准备好它需要的东西：
  - 启动器：目标操作系统在官方支持清单内；无需自行装运行环境。
  - Docker / Podman：宿主机已装容器运行时，并规划好数据目录与端口。
  - 模板项目 / 依赖调用：本机已装 Node.js（官方最低 v18，推荐 LTS），并有一个路径不含中文与空格的干净目录。
- 需要保存用户、频道等数据时，先确定用哪种数据库服务插件（框架本体不自带数据库实现）。
- 若要让外部访问控制台或接受平台回调，准备好公网地址、域名与反向代理；国内服务器还要考虑备案信息。
- 建议先明确「不做什么」：本 Skill 只负责框架的安装、配置与排错思路，不替使用者选业务插件，也不对其安全性背书。

## 使用

1. 按 `SKILL.md` 的「安装」一节选一种方式把应用跑起来。默认控制台在 `http://localhost:5140`。
2. 打开控制台，用「沙盒」先做无账号调试：添加虚拟用户，发 `help` 看指令列表，发 `echo 你好` 验证插件生效。
3. 在「插件市场」装所需插件，再到「插件配置」中**手动启用**并填好必填配置项。插件依赖的服务（数据库、资源存储、渲染等）要先有实现插件在跑。
4. 接入真实平台：添加对应适配器插件的配置，填入凭据。建议凭据走环境变量或 `.env.local`，不要写进配置文件明文提交。
5. 用过滤器与触发前缀把功能限定到正确的群 / 频道，用权限等级控制谁能调什么指令。
6. 需要对外提供服务时，调整 server 插件的 `host` 与 `selfUrl`，先开启登录保护，再配反代（注意转发 WebSocket）。
7. 长期运行交给 `koi daemon`、Docker 或 systemd；需要多份配置时用插件别名区分。
8. 排错顺序建议：先看控制台日志 → 确认插件是否已启用 → 确认依赖服务是否存在 → 确认过滤器与受理人是否把它挡掉了。

## 依赖

- **运行环境**：Node.js ≥ v18（推荐 LTS）；随附的启动器安装包会自行处理运行环境。
- **包管理器**：npm（Node.js 自带），官方亦推荐 yarn；国内建议配置 npm 镜像源。
- **容器方案**：Docker 或 Podman，仅在选用容器部署时需要。
- **浏览器内核**：图片渲染类插件通常依赖 Chromium；官方容器标准镜像已预装，轻量标签不含。
- **数据库**：按需安装数据库服务插件，框架本体不自带实现。
- **网络**：访问 npm 源以安装 / 更新依赖，访问聊天平台接口以收发消息；对外开放时需要一个可用端口（默认 5140）与可选的反向代理。
- **平台凭据**：由使用者自备，本 Skill 不提供也不内置。

## 安全

- 不内嵌任何密钥，仓库中不含任何平台 token 或账号信息。
- 机器人凭据、数据库口令等敏感值请放环境变量或 `.env.local`，并确认这些文件不会被提交到版本库。
- 控制台默认只监听本机；改成对外监听前**必须**先启用登录保护，否则等于把机器人管理权限公开在网络上。
- 使用反向代理时同时处理好 TLS 与 WebSocket 转发，不要为了省事把服务裸暴露在公网。
- 插件市场中的第三方插件不受官方安全保证，安装前确认来源与用途，谨慎授权其访问文件、网络与子进程能力。
- 机器人可以读取群聊内容并代表账号发言，接入前请确认所在群 / 组织的使用规范与合规要求。
- 控制台「依赖管理」会实际改动本地依赖树，生产环境操作前先确认版本与回滚方式。
