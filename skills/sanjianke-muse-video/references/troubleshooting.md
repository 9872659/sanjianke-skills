# Muse Video 出片台 —— 排错

**先跑 `python3 scripts/run.py doctor`** —— 免费、不扣费，能一次排掉一半问题。

---

## 一、提交被拒（400，不扣费）

### `400 field prompt is required`

`--prompt` 是空的。**注意**：`--first-frame` 不能代替 `--prompt`，图生视频也要写"怎么动"。

### `400 Model name not specified, model name cannot be empty`

请求里没带 `model`。本包一定带，正常不会遇到；如果你自己拼请求，记得加 `"model": "muse-video"`。

### `400 seconds 只支持 4 到 180 的整数`

`--seconds` 必须是 **4–180 的整数**。

**常见错**：写 `8.5`（带小数）、写 `0`、写 `200`。
**本包在本地就拦**，退 `2`。

### `400 只支持横屏 1280x720 或竖屏 720x1280`

`--size` 只能这两个。**不支持方形，也不支持 1080P** —— 这是模型本身的限制，不是参数没写对。

### `400 prompt 不能超过 4000 个字`

`--prompt` 太长。拆成"场景 + 动作 + 镜头"三句就够，不用堆形容词。

### `400 参考图最多 4 张`

`--ref` 最多 4 次。

### `400 参考图只支持 png/jpeg/webp`

本地图格式不对（例如 HEIC、AVIF）。先转成 PNG 或 JPEG。

### `400 参考图要给图片 URL 或 data URL，不支持 file id`

文档明确：**不支持文件 ID**。给公网 URL，或让本包把本地文件转成 data URL（`--first-frame` / `--ref` 传本地路径即可）。

### `400 第 N 张参考图……`

后面会跟具体原因。常见：

- 链接打不开 → 确认公网能直接访问（不能是内网、不能要登录）
- 链接过期 → 带签名的临时链接要确认**提交时**未过期
- 超过大小 → 单张 ≤10 MB，合计 ≤24 MB

**data URL 会比原图大约 1/3**，图尽量先压小。

## 二、提交成功但任务失败（预扣全额退回）

### `error.code = video_generation_failed`

模型没出片。三个常见原因：

1. **内容不合规** → 换提示词
2. **提示词与参数冲突** → 例如 `--seconds 5` 但提示词里写"三分钟的旅程"
3. **上游临时出错** → 稍后重试

### `error.code = video_rejected`

成片不合格（横竖不对、比买的短、没画面），已作废。**直接重试**即可。

### `error.code = not_found`

任务记录丢失。**重新提交**。

> 以上三种都会**全额退回**预扣金额。

## 三、⚠️ 最贵的一个坑：重复提交

**症状**：等了很久没动静，你又提交了一次，结果被扣了两次钱。

**原因**：任务**一旦创建就会跑完** —— 客户端断开、等待超时、网络中断都**不影响任务本身**。

**所以：**

```
超时了 → 用 status <id> 查，或用 wait <id> 继续等
       → 绝对不要重新 gen
```

本包的超时报错会明确写：

```
失败：等待超时（60 分钟）—— 任务可能仍在生成。
  不要重新提交（重提会再扣一次钱）。稍后用：
    python3 scripts/run.py wait task_xxxx --outdir .
```

**这句是专门为这个坑写的。**

## 四、等待相关

### `exit 7`：等待超时

任务**可能仍在生成**。用同一个 `id` 继续：

```bash
python3 scripts/run.py wait task_xxxx --outdir .
```

或先看一眼状态：

```bash
python3 scripts/run.py status task_xxxx
```

### `progress` 停在 99

**正常。** 文档说明：`progress` 到 99 时平台在**核对成片**（时长、横竖），这时 `in_progress` 可能多持续几分钟。

**判断完成看 `status == "completed"`，不看 `progress`。**

### 任务一直是 `queued`

高峰排队。继续查，**别重提**。

### 等待上限怎么调

```bash
python3 scripts/run.py gen ... --wait --limit 7200    # 2 小时
python3 scripts/run.py wait task_xxxx --limit 7200
```

默认 3600 秒（60 分钟）。**轮询间隔默认 15 秒**，可 `--every 30` 放宽。

## 五、下载相关

### 下载失败，但链接能打开

本包会打印：

```
⚠️ 下载失败：<原因>
   链接仍可用，手动下载：https://cdn3.saasos.cn/vr/xxxx.mp4
```

**链接不需要密钥**，浏览器直接打开就能存。

### 链接 404 了

两个原因：

1. **超过 24 小时** —— 平台成品只保留一天
2. 任务还没 `completed`

### 长片下载很慢 / 内存爆掉

180 秒的成片可能超 100 MB。本包**边收边写盘**（64 KB 一块），不会整个读进内存。
如果网络慢，手动用 `curl -O <video_url>` 或支持断点续传的下载器。

## 六、尺寸与画面

### 出片是横的，但我要竖的

`--size 720x1280`。

**而且首帧图的横竖要和它一致** —— 竖图配 `720x1280`，横图配 `1280x720`。不一致会失败或效果差。

### 能出 1080P 吗

**不能。** 文档明确：`muse-video` 只出 **720P**。要更高分辨率得换别的模型，或用超分后处理。

### 能出方形吗

**不能。** 只有 `1280x720`（16:9）和 `720x1280`（9:16）。

### 60 秒以上的片子，人物中途变了

**已知行为。** 文档：61–180 秒会分成 2–3 部分**同时生成**再拼接，**部分之间会换镜头**，人物外貌/服装/场景可能变化。

**解法**：传一张人物参考图（`--ref`），每一部分都会用同一组参考图。

### 提示词里写"硬切""分镜"，结果是一个长镜头

**已知行为。** 文档：11–60 秒是分段生成的，提示词里写"硬切""分镜"**多半会变成长镜头里的运镜和转场**。

**要真正的多镜头**，用 61 秒以上（分部分生成会换镜头）。

## 七、Key 与钱

### `失败：没有 API Key`（exit 2）

三处都没读到：

1. `--key sk-...`
2. `echo $env:A7W_API_KEY` / `echo $A7W_API_KEY`
3. `~/.a7w/config.json` 里的 `{"key": "sk-..."}`

```bash
python3 scripts/a7w.py login --key sk-你的key
```

### `失败：预计 N 点超过 --budget M 点`（exit 5）

闸门在工作。调大 `--budget` 或减少 `--seconds`。

**`--budget` 单位是「点」**（1 元 = 100 点），默认 2000 点（约 181 秒）。

### `失败：这会真实出片并预扣约 N 点`（exit 4）

缺 `--yes`。**故意的**。

想先看请求：

```bash
python3 scripts/run.py gen --prompt "..." --seconds 5 --dry-run
```

### 余额不足

**不会创建任务**（文档：余额不足直接报错）。充值后再提交。

### 一张到底多少钱

**11 点/秒 × 你填的秒数。** 5 秒 = 55 点 = ¥0.55；30 秒 = 330 点 = ¥3.30。

**失败全额退回。**

## 八、自检三项分别是什么意思

```
✓ Key 有效性 + 模型目录可达     ← GET /api/v1/models 通了
✓ 模型 muse-video 在架          ← 目录里找得到
✓ 提交端点可用（400 缺 prompt）  ← POST /api/v1/videos 带着 model 但不带 prompt，
                                   返回 400 "field prompt is required"
```

第三项是**端点探针**：如果它失败，说明端点路径或请求形态不对，**别急着花 55 点去试**。

**注意**：空 body 会先报 "Model name not specified"，看不到 prompt 校验 ——
所以探针必须**带 model**，这是本包 `doctor` 的设计依据。
