# 接口契约（文档原文 + 实测）

> 权威来源：网关文档 `https://api.a7w.cn/docs.html#/docs/muse-video-xt`（「Muse Video · 完整接入文档」）
> 数据源：`https://api.a7w.cn/assets/docdata.json`（17,153 B）

---

## 一、接入信息

| 项目 | 值 |
|---|---|
| 接口根地址 | `https://api.a7w.cn/api/v1` |
| 提交视频 | `POST https://api.a7w.cn/api/v1/videos` |
| 查询任务 | `GET https://api.a7w.cn/api/v1/videos/{id}` |
| 鉴权 | `Authorization: Bearer <你的 API 密钥>` |
| 模型名 | `muse-video` |

**兼容路径**：`POST /api/v1/videos/generations` 与 `/api/v1/videos` **等价**，两者都能用。

---

## 二、提交任务

`POST /api/v1/videos`，请求体 JSON。

> 只上传**一张本地首帧图**时，也可以用 `multipart/form-data`。

| 参数 | 必填 | 说明 |
|---|---|---|
| `model` | 是 | `muse-video` |
| `prompt` | 是 | ≤**4000 字**；写清主体、怎么动、镜头怎么走 |
| `seconds` | 否 | **4–180 整数**；不填按 4 秒算 |
| `size` | 否 | `1280x720`（横，默认）/ `720x1280`（竖）|
| `input_reference` | 否 | 一张图，作**首帧** |
| `images` | 否 | 数组，**最多 4 张**；第 1 张＝开头画面，2–4 张＝参考 |

### 返回（提交成功）

```json
{
  "id": "task_9xQe2Lm7Vb4R...",
  "object": "video",
  "model": "muse-video",
  "status": "queued",
  "progress": 0,
  "created_at": 1793962453
}
```

### 实测：参数校验的错误结构有两套 ⚠️

| 请求 | 返回 |
|---|---|
| `{}` | 400 `{"error":{"code":"","message":"Model name not specified, model name cannot be empty (request id: …)","type":"new_api_error"}}` |
| `{"model":"muse-video"}` | 400 `{"code":"plugin_request_invalid","message":"field prompt is required","data":null}` |
| `{"model":"muse-video","prompt":"x","seconds":"3"}` | 400 `{"code":"fail_to_fetch_task","message":"seconds 只支持 4 到 180 的整数 (muse-video: 4-180 seconds)","data":null}` |

**注意**：缺 model 时 `message` 在 `error` 里；缺 prompt / 参数不合规时 `message` 在**顶层**。
所以 `doctor` 探端点必须**带上合法 model**，才能走到 prompt 校验 —— 否则只会看到 "Model name not specified"，误判成"端点有问题"。

## 三、查询任务

`GET /api/v1/videos/{id}`

### 状态

| `status` | 含义 | 下一步 |
|---|---|---|
| `queued` | 排队中 | 继续查 |
| `in_progress` | 生成中，`progress` 是粗略进度 | 继续查 |
| `completed` | 完成 | 去下载 |
| `failed` | 失败，**暂扣金额全额退回** | 看 `error.message` |
| `unknown` | 平台在确认状态 | 继续查（确认前保持暂扣，不重复扣费）|

### 返回字段

| 字段 | 说明 |
|---|---|
| `id` | 任务 ID |
| `object` | 固定 `video` |
| `model` | `muse-video` |
| `status` | 任务状态 |
| `progress` | 0–100，**仅供参考** |
| `created_at` / `completed_at` | Unix 秒 |
| `seconds` | 你请求的秒数（＝计费秒数），**不是实际时长** |
| `size` | 出片尺寸 |
| `video_url` | 完成后才有；**不需要密钥** |
| `expires_at` | `video_url` 过期时间（Unix 秒）|

> `progress` 到 99 时平台在核对成片（时长、横竖），可能多持续几分钟。**判断完成看 `status`。**

---

## 四、下载

- 直接用 `video_url`，**不需要带密钥**，在 `expires_at` 之前有效
- 支持 `Range` 请求，可续传、可拖动
- 成片是 **MP4、带声音**
- 大小：10 秒以内几 MB，60 秒几十 MB，180 秒可能超 100 MB
- 长片下载建议给足 10 分钟以上，**边收边写盘**，不要整个读进内存
- **平台成品只保留 24 小时**

---

## 五、计费

| 项目 | 值 |
|---|---|
| 单价 | **11 点/秒（¥0.11）** |

| 秒数 | 价格 | 秒数 | 价格 |
|---|---|---|---|
| 4 | 44 点 | 10 | 110 点 |
| 5 | 55 点 | 15 | 165 点 |
| 6 | 66 点 | 30 | 330 点 |
| 8 | 88 点 | 60 | 660 点 |

- **按请求秒数计费**：费用 = `seconds` × 11；不填按 4 秒算
- **凑档不加钱**：填 17 秒出 20 秒，只收 17 秒
- **传图不加钱**：不传、1 张、4 张一个价
- **提交时预扣**：余额不足直接报错、**不创建任务**
- **失败全额退回**（含成片不合格作废）
- **参数不对不扣费**：秒数、尺寸、分辨率、图片不合规 → 400，不创建任务
- **任务一旦创建就会跑完**：客户端断开、等待超时都不影响；超时后**用 `id` 继续查，不要重复提交**

> ⚠️ **`/api/v1/pricing` 里没有 `muse-video` 的专属规则** —— 单价 11 点/秒来自文档，

## 六、时长档位

| 填写 | 出片 |
|---|---|
| 4、5 | 5 秒 |
| 6 | 6 秒 |
| 7、8 | 8 秒 |
| 9、10 | 10 秒 |
| 11 以上 | 凑到 5 的倍数（11–15→15，16–20→20 …… 176–180→180）|

**即 5、6、8、10 秒，以及 15–180 之间 5 的倍数，出多少就是多少。**
填 4、7、9、11 也能用，只是出片比买的长一点，**钱按填的算**。

**小于 4、大于 180 或带小数（如 8.5）→ HTTP 400，不扣费。**

---

## 七、镜头结构

- **10 秒以内**：一个连续镜头
- **11–60 秒**：分成每段 5–10 秒生成，后一段从前一段**最后一帧**接着拍，最后拼成一条，**接缝处画面连续**
  （提示词里写「硬切」「分镜」多半会变成长镜头里的运镜和转场）
- **61–180 秒**：分成 2–3 部分**同时生成**，每部分 ≤60 秒且尽量等长
  （90 秒=45+45、120 秒=60+60、180 秒=60+60+60），再按顺序拼接
  **部分之间会换镜头，人物外貌/服装/场景可能有变化** → 要人物一致就传参考图，每一部分都会用同一组参考图

---

## 八、图片输入

- **一张图**：用 `input_reference`，这张图就是首帧，视频从它开始动
- **多张图**：用 JSON 的 `images` 数组，**最多 4 张**。第 1 张是开头画面，第 2–4 张是参考图（人物长相、衣服、场景、画风、配色）；**最后一张不会当结尾画面**
- multipart 只能传一个 `input_reference` 文件；多张本地图片请转成 data URL 放进 `images`
- 多张图**全放进 `images`，不要再另传 `input_reference`**
- 支持 **PNG / JPEG / WebP**；可传图片 URL 或 data URL，**不支持文件 ID**
- 图片 URL 必须公网可直接打开，不能是内网地址或需登录的地址；带签名的临时链接要确认提交时未过期
- **单张 ≤10 MB，合计 ≤24 MB**；data URL 比原图大约 1/3，图尽量先压小
- **首帧图横竖要和 `size` 一致**（竖图配 `720x1280`，横图配 `1280x720`）

## 九、出片时间

| 请求秒数 | 一般耗时 |
|---|---|
| 4–10 秒 | 1.5–2.5 分钟，慢的 4 分钟左右 |
| 11–30 秒 | 3–5.5 分钟，慢的 7 分钟左右 |
| 31–60 秒 | 5–13 分钟 |
| 61–180 秒 | 8–15 分钟 |

高峰排队更久。程序里的等待上限建议设 **60 分钟**；到上限任务可能仍在生成，**继续用同一个 `id` 查询，不要重新提交**。

## 十、错误

### 提交返回 400（不扣费、不创建任务）

| 情况 | 提示中会出现 |
|---|---|
| 没写 prompt | `prompt is required` |
| prompt 超 4000 字 | `prompt 不能超过 4000 个字` |
| 秒数不在 4–180 或带小数 | `seconds 只支持 4 到 180 的整数` |
| 要了 720p 以外分辨率 | `muse-video 只出 720p` |
| 尺寸不是 1280x720 / 720x1280 | `只支持横屏 1280x720 或竖屏 720x1280` |
| 图片传了文件 ID | `参考图要给图片 URL 或 data URL，不支持 file id` |
| 图片格式不对 | `参考图只支持 png/jpeg/webp` |
| 参考图超过 4 张 | `参考图最多 4 张` |
| 图片链接打不开/过期/非公网 | `第 N 张参考图……` 后接具体原因 |
| 单张 >10 MB 或合计 >24 MB | `超过 10 MiB` / `参考图总大小超过 24 MiB` |

### 任务失败（`failed`，预扣全额退回）

| `error.code` | 原因 | 怎么办 |
|---|---|---|
| `video_generation_failed` | 模型没出片：内容不合规、提示词与参数冲突、上游临时出错 | 改写提示词或稍后重试 |
| `video_rejected` | 成片不合格（横竖不对、比买的短、没画面），已作废 | 直接重试 |
| `not_found` | 任务记录丢失 | 重新提交 |

### 其他

- **余额不足**：先充值再提交
- **400 `task_not_exist`**：任务 ID 不存在或不属于你的账户
- **提交 503**：服务临时维护，几分钟内恢复
- **查询偶尔 5xx**：隔十几秒再查，任务不受影响
- **下载报错**：任务还没 `completed`，或已失败，先查状态

## 十一、使用建议（文档原文）

- **prompt 写清三件事**：主体是什么、怎么动、镜头怎么走
- **时长和横竖以参数为准**：提示词里别写与 `seconds`、`size` 矛盾的内容，否则模型可能反问而不出片（任务失败退款）
- **多张图写清用处**：第 1 张开头画面，其余作参考，prompt 里写明每张图干什么
- **要准确时长就买整档**：5、6、8、10，以及 15–180 之间 5 的倍数
- **60 秒以内适合一个连贯场景**：写清场景和镜头运动，比写分镜效果好
- **60 秒以上按时间顺序写故事**：120 秒写前后两半，180 秒写三幕
- **长片多等一会**：30 秒以上通常 5–15 分钟；轮询 15 秒，上限 60 分钟
- **及时下载**：平台成品只保留 24 小时
