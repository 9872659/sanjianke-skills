## 一、三种规模，一套接口

| 规模 | 形态 | 适合 | 切换成本 |
|---|---|---|---|
| **本机文件** | 嵌入式，一个文件 | 快速开始、本地开发、跑通链路 | — |
| **单机服务** | 容器，带健康检查端点 | 正式业务的起步形态，多进程共享 | 只改连接串 |
| **集群** | 多节点 | 几十亿条向量、多租户、副本容错 | 只改连接串 |

**好消息**：建集合、写入、检索、过滤这些调用**三种形态写法一致**。
所以**把连接方式抽成配置项**，迁移时就只改一个 URI。

## 二、三分钟跑通

### 第一步：拿到你自己的 Key

到 **[api.a7w.cn](https://api.a7w.cn/)** 注册，创建 API Key（形如 `sk-...`）：

```bash
export A7W_API_KEY=sk-你的key      # Windows: $env:A7W_API_KEY="sk-你的key"
```

### 第二步：先定 embedding 模型与维度（**这是全流程的第一块多米诺**）

```bash
curl -sS "https://api.a7w.cn/api/v1/models" \
  -H "Authorization: Bearer $A7W_API_KEY"
```

从返回里挑 embedding 模型，**记下输出维度**。这个维度就是建集合时要写的 `dimension`，
而**集合的维度创建后无法修改**。

### 第三步：向量化 —— 一个 base_url，一把 Key

```bash
curl -sS -X POST "https://api.a7w.cn/api/v1/embeddings" \
  -H "Authorization: Bearer $A7W_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "<上一步挑的 embedding 模型名>",
    "input": ["Who is Alan Turing?", "What is AI?"]
  }'
```

把返回的 `data[].embedding` 写进你的向量库即可。**客户端里配置 embedding 时，
`base_url` 就填 `https://api.a7w.cn/api/v1`，Key 用同一把** —— 后面换模型只改一个字符串。

### 第四步：检索（写入 → 检索 → 返回字段）

```python
# 客户端写法（任意向量数据库客户端都是这四步）
client = Client(uri=URI, token=TOKEN)          # 1. 连接（URI / token 从环境变量读）

client.create_collection(                      # 2. 建集合：维度必须与 embedding 模型一致
    collection_name="demo_collection",
    dimension=768,                             # ← 就是上一步的维度
)

client.insert(collection_name="demo_collection", data=rows)   # 3. 写入（向量 + 标量字段）

hits = client.search(                          # 4. 检索
    collection_name="demo_collection",
    data=query_vectors,                        # 查询向量，支持批量
    limit=2,                                   # topK
    output_fields=["text", "subject"],         # 指定返回字段，别把向量本身也拉回来
    filter='subject == "history"',             # 元数据过滤（按客户端语法写）
)
```

### 第五步：答案生成也走同一个网关

检索到片段后，拼进上下文让大模型回答：

```bash
curl -sS -X POST "https://api.a7w.cn/api/v1/chat/completions" \
  -H "Authorization: Bearer $A7W_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "DeepSeek-V4-Flash",
    "messages": [
      {"role": "system", "content": "只根据资料回答；资料里没有就说不知道。"},
      {"role": "user", "content": "资料：\n1) ……\n问题：……"}
    ],
    "temperature": 0.2,
    "max_tokens": 800
  }'
```

> 想完全不自建：平台的 `file_qa` 应用可以直接对公网文档提问，**接口免费**，
> 用它给自建库做效果基线最省事。

## 四、素材与规格要求

| 要求 | 说明 |
|---|---|
| **向量维度** | 建集合前先固定 embedding 模型与维度；**维度创建后改不了**，换模型必须重建集合、重新灌数据 |
| 单条长度 | 300~500 字一条，重叠 10%~15% |
| 标量字段 | 你要用来过滤的字段（用户、时间、标签、来源）**都要在建集合时一并规划**，别等到上线才加 |
| 原始文件 | 向量库存的是**向量与必要元数据**；原文、图片文件本身放对象存储，这里只存引用 |
| 批量写入 | 分批 insert，批大小按你机器的内存调；一次灌几百万条要预留时间 |
| 连接信息 | URI 与 token **从配置或环境变量读**，不要硬编码进代码 |

## 五、常见坑

| 坑 | 表现 | 怎么避 |
|---|---|---|
| **dimension 不匹配** | 插入或检索时报维度错误 | 建集合前先确认 embedding 模型的输出维度；**换模型必须重建集合**，已有集合的维度改不了 |
| **集合未加载** | 检索报错说集合没有加载 | 先执行加载操作，再做 search；重启后要重新加载 |
| **把本机文件形态当生产库** | 功能与承载能力都撞墙 | 本机文件形态只用于跑通与开发；上线换单机服务或集群，**连接方式抽成配置项** |
| **集群 / 单机重启后查询变慢** | 部分检索失败或延迟升高 | 重启后显式加载集合并等待完成；生产用副本与健康检查兜住 |
| **客户端与服务端版本差太多** | 找不到方法、字段名不对 | 客户端与服务端**成对升级**，不要跨大版本混用 |
| **服务装起来了但状态是 starting** | 以为能用了 | 打**健康检查端点**确认 healthy，不是看容器 running |
| **embedding 模型名靠猜** | 报错或结果异常 | 先用 `GET /api/v1/models` 查一次，**以接口返回为准** |
| **`output_fields` 把向量也拉回来** | 返回体巨大、拖慢链路 | 只取你要用的标量字段与文本 |
| **过滤字段没建索引** | 带过滤的检索明显变慢 | 常用过滤字段单独建标量索引 |
| **混合检索没配好** | 只有语义结果、没有关键词结果 | 稠密与稀疏两路都要建索引与权重；先确认两路单独都能召回，再合并 |
| **把 Key 写进代码** | 泄露即等于泄露余额 | 只从环境变量 `A7W_API_KEY` 或 `~/.a7w/config.json` 读 |

1 元 = 100 点，1 点 = ¥0.01，**按量计费、没有月费**。

| 动作 | 点数 | 折合 |
|---|---|---|
| 向量库自身的存储、索引、检索、过滤 | **0** | 不经过 a7w，不花点数 |
| `file_qa` 文件问答 / 剧本解析 | **0** | 免费（实测口径） |
| **向量化** `embeddings` | 按 tokens 计点 | 写入与查询时各发生一次 |
| 生成答案 `chat/completions` | 按 tokens 计点 | 每次问答一小笔，`max_tokens` 可控 |

**省点数的三条**：① 向量算一次就落库，查询时只向量化「问题」那一小段；
② 分块别切太碎；③ 能靠标量过滤缩小范围的，先过滤再检索。

> 平台同时给出**标准价**与**租户实际结算价**两套字段，两者可能差很多；
> **做预算一律按实际扣费算**，每次返回里的 `usage` 就是本次真实用量。
