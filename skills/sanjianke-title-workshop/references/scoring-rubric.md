# 四维评分标准（scoring-rubric）

`run.py gen` 和 `run.py score` 都用这四个维度打分，各 **1~10**，
再按下面的权重合成 **总分（满分 100）**：

```
总分 = (点击欲望 × 0.35 + 信息量 × 0.25 + 平台适配 × 0.25 + 合规 × 0.15) × 10
```

**为什么这么配权重**：标题的第一职责是让人停下（点击欲望最重），
但只有点击没有信息量的标题会把完读率做烂（信息量次之）；
平台适配是"能不能被看见"的硬条件；合规权重最低，
但它是**一票否决**——所以单独给它一条本地压制规则（见最后一节）。

---

## 一、点击欲望（click）· 权重 35%

问自己一个问题：**一个完全不认识你的人，在信息流里扫过这行字，会不会停一下？**

| 分数 | 判定标准 | 例子（跨主题，勿照抄） |
|---|---|---|
| 1~2 | 完全无钩子，或钩子与主题无关 | 「关于充电桩的一些想法」 |
| 3~4 | 陈述事实，信息平铺，无情绪无悬念 | 「充电桩的安装说明」 |
| 5~6 | 有明确信息点，但开头不够抓人 | 「充电桩的 5 个使用场景」 |
| 7~8 | 前 3 个字就有身份/冲突/悬念 | 「装了半年，我的电费反而降了」 |
| 9~10 | 强身份筛选 + 强未满足感，看到就想知道答案 | 「装了三个充电桩后，我才明白贵的差在哪」 |

**容易误判的地方**：不要把"信息完整"当成"点击欲望高"。
「充电桩选购指南：功率、线长、安装条件全解析」信息很全，
但作为标题它只有 4 分——因为它没有让人"非点不可"的理由。

## 二、信息量（info）· 权重 25%

问：**看完标题，我是否已经知道"点进去能得到什么"？**

| 分数 | 判定标准 | 例子（跨主题，勿照抄） |
|---|---|---|
| 1~2 | 只有情绪，什么也没承诺 | 「救命！太绝了！」 |
| 3~4 | 承诺了价值但极其模糊 | 「一篇讲透」 |
| 5~6 | 有具体品类/场景，但没说清收获 | 「聊聊充电桩怎么选」 |
| 7~8 | 明确给出收获类型（清单/对比/避坑/方法） | 「选购要点，第 3 条最容易踩坑」 |
| 9~10 | 具体到能被验证，且有边界 | 「7kW 以下别装：功率到底怎么选」 |

**和点击欲望的张力**：信息量加到极致的标题往往点击率低
（「充电桩的功率、线长、安装条件、兼容性对比评测」），
所以两者要平衡——**总分最高的标题一般是 7 分点击 + 8 分信息**，
而不是单项满分。这也是四维加权而不是单项排序的理由。

## 三、平台适配（platform_fit）· 权重 25%

对照 `title-formulas.md` 里该平台的字数上限与语感口径。

| 分数 | 判定标准 |
|---|---|
| 1~2 | 超字数上限 10 字以上，或语感完全不属于该平台（如给抖音写书面长句） |
| 3~4 | 超上限 6~10 字，念出来别扭，或塞了明显不该有的符号 |
| 5~6 | 超上限 1~5 字；或字数对但语感偏书面/偏跳脱 |
| 7~8 | 字数达标，语感基本对路，个别用词可以更口语 |
| 9~10 | 字数在安全区，语感完全贴平台，念出来就是该平台的人会说的话 |

**脚本会强制压分**：标题字符数超过 `PLATFORMS[platform]["limit"]` 时，
`run.py` 会把这一维直接压到 **5 分**（超 5 字以上压到 **3 分**），
不采信模型的自我评估——因为模型经常为了写得漂亮而无视字数。

## 四、合规（compliance）· 权重 15%

| 分数 | 判定标准 |
|---|---|
| 1~2 | 命中广告法明令禁止用语（最高级、绝对化、虚假承诺、医疗功效） |
| 3~4 | 命中中度风险表述（独家/唯一/纯天然/限时/站外导流） |
| 5~6 | 无明确违禁词，但有夸大倾向（"颠覆""逆天"这类） |
| 7~8 | 表述克制，无可举证问题，个别措辞可再稳一点 |
| 9~10 | 干净，且有具体可举证的事实支撑 |

详细词表与红线见 `compliance.md`。

**脚本会强制压分**：本地违禁词表命中时，合规维度按风险等级封顶——
高风险压到 **1 分**、中风险 **4 分**、低风险 **7 分**，
且低于任何由模型给出的分数。**模型给的合规高分不能覆盖本地命中。**

### 模板污染：同一维度的第二个硬闸门

合规维还承担一类与"违规"无关、但**同样不可直接发布**的缺陷：**模板污染**。
它指标题里混进了"编稿脚手架"而不是内容：

| 形态 | 例子 | 为什么不可发布 |
|---|---|---|
| 公式名被当文案 | `结论前置：便携榨汁杯不适合三类人` | `结论前置：` 是编辑术语，读者看不懂也占字数 |
| 公式名 + 分隔符起头 | `双段式｜便携榨汁杯别急着买` | 同上，且暴露了内容是套模板生成的 |
| 占位符没替换 | `{结论要点}，三个理由` | 直接是半成品，发出去是事故 |

处理方式与违禁词**完全一致**：合规维封顶到 **3 分**、标红、
汇总到 stderr、退出码变 `3`。判定用**两路取并集**——模型自报的 `formula`
字段，加上该平台**已知公式名全集**。为什么要取并集：模型经常在 `formula`
里自己发挥（实测把 `结论前置` 写成过 `结论前置+人群排除`），
只信它自报的值会漏判，闸门就形同虚设。

> 这条闸门的由来是一次真实事故：知乎「结论前置」模板写作 `{结论}，三个理由`，
> 模型把公式名当成了标题前缀（形态就是"结论前置"四个字后面跟一个冒号再接内容），
> 那条还拿了 **89.0 分（全批最高）**。缺陷标题排到第一比排到末位糟糕得多——
> 用户只看前三条，第一条就是废的。
> （上面只描述形态，刻意不写完整标题——**本文档里凡带「例子」字样的都是反例，
> 一律不要照抄**。）

### prompt_echo：抄提示词示例也按模板污染处理

还有一个更隐蔽的坑：**模型会锚定提示词里的示例**。实测有两例：

1. 提示词里写过一条正例 → 模型直接产出结构完全一样的标题
2. 提示词里留过一条完整标题 → 某一轮**最高分 89.0 那条一字不差就是它**

第 2 例比第 1 例严重：最高分那条是"抄了标准答案"，不是"真的最好"，
而**排序正是这个包的核心产出**。

三道防线：

| 防线 | 做法 |
|---|---|
| 治因 | 提示词里**不许出现任何一条可直接复制的完整中文标题**。讲形态只用描述性语言，或使用**完全不同的主题**（本包统一用"电动车充电桩"，与真实主题明显不搭，抄过去不成立） |
| 加闸门 | 提示词示例文本存进 `PROMPT_SAMPLES` 常量，生成标题按下面**三条判据**（任一命中即判 `prompt_echo`），与模板污染同档：合规维封顶到 3 分、标红、stderr 汇总、退出码 3 |
| 勤加样 | 新增提示词示例时**必须**同步登记到 `run.py` 的 `PROMPT_SAMPLES`，否则这条闸门护不住它 |

**三条判据与阈值**（去掉标点与空白后再比，只留中文/字母/数字）：

| # | 判据 | 阈值 | 抓的是什么 |
|---|---|---|---|
| 1 | 去标点后**完全相同** | — | 逐字照抄、只改标点 |
| 2 | 字符二元组 **Jaccard** 相似度 | ≥ `ECHO_SIM` = **0.75** | 长度相当的同构改写（换个词、少两个字） |
| 3 | 示例二元组的**覆盖度** | ≥ `ECHO_CONTAIN` = **0.60** | 把示例**夹带进更长的标题**里 |

判据 3 是补上的漏洞。Jaccard 的分母是两份二元组的**并集**，产出越长示例那一侧被摊得越狠，
示例原样嵌进去也会掉到 0.75 以下：本包实测（示例「电动车充电桩到底值不值得装，三个理由」，
去标点后 17 字 / 16 个二元组）

- 示例原样嵌入 + 补 7 个字 = **24 字**（正好在公众号/知乎 25 字上限内）
  → Jaccard `16/23 = 0.696`（旧判据**放行**）、覆盖度 `16/16 = 1.000`（新判据**拦下**）
- 同一条示例原样嵌进 52 字的产出 → Jaccard `0.314`（漏）、覆盖度 `1.000`（抓住）

覆盖度只看"示例被抄了多少"，不看产出有多长，所以长度摊薄对它无效。阈值取 0.60 的依据：
34 条真实历史标题 + 同主题（充电桩）对抗样本 15 条，**覆盖度最大只有 0.500**，误伤 0 条。

另有一条长度守卫，门槛是**相对**的：目标归一化长度 < `max(6, len(示例)//2)` 就不比
相似度与覆盖度（短串二元组太少，指标会虚高）。本包示例 15~17 字 → 门槛 7~8。
用绝对阈值 12 会把「≤11 字的截断照抄」整档放过：实测「小区充电桩的安装条件别」11 字、
覆盖度 0.714，绝对阈值下漏、相对阈值下拦。四个包逐档实测（对每条示例做逐字截断，
共 321 个档位）：相对阈值比绝对阈值多抓 **5 档**、少抓 **0 档**。

## 五、总分怎么用

1. **先看两道闸门**：违禁词命中、或模板污染（含 `prompt_echo`）的标题**不要发**，
   先改文案或删掉前缀，改完重跑 `score`。
2. **再看总分排序**：总分只用于"选谁先测"，不是"选谁发布"。
   `total` 相差 3 分以内视为同一档，直接交给 A/B 测试裁决。
3. **别只看第一名**：`run.py ab` 会从排行里挑"只差一个变量"的配对，
   这比把第一名发出去更有价值——它告诉你的不是"哪句话好"，
   而是"你这类受众吃哪一套"，可以复用到之后几十条内容。
4. **分数是相对值**：同一批次内的相对排序有意义，跨批次、跨主题的绝对分数没有可比性
   （因为打分的是同一轮大模型，它有自己的标尺漂移）。

## 六、让打分更稳的三个技巧

**技巧 1：给证据，分才会准。**
```bash
python3 scripts/run.py gen --topic "便携榨汁杯" \
  --evidence "实测一次榨 350ml、清洗 40 秒、USB-C 充电 90 分钟满"
```
给了证据，模型写出来的标题才有具体数字可用，信息量维度也才有东西可打高分。

**技巧 2：要拉开差距。**
提示词里明确写了"别都给高分"，如果整批分数挤在 8.0~8.4 之间，
说明模型没在区分——把 `--temperature` 提到 1.0 重跑，或者换一个模型重跑。

**技巧 3：人工补一列。**
脚本给的是**语义分**，它不知道你的账号历史数据。
把 `gen --json --out titles.json` 的结果导进表格，
旁边加一列你自己的判断（"这条像我账号会说的话"），
两者一致度低的那几条，往往就是你账号调性和通用方法论的分歧点。
