# 产线手册 · 八道工序怎么衔接

一条短剧产线 = **八道工序 + 每道工序的验收标准**。
本文只讲衔接与验收；质量判断标准看 `质量门禁.md`，接口参数看 `接口速查.md`。

---

## 全景

```
小说 / 大纲
   │
   ├─① 策划  模型网关        → 改编可行性 + 核心矛盾 + 金手指
   ├─② 编剧  模型网关        → 分集大纲 + 每集剧本（含台词）
   ├─③ 分镜  模型网关        → 分镜表 JSON（镜号/画面/台词/时长/过渡）
   │
   ├─④ 出图  nano_banana    → 角色形象图 + 场景图 + 每镜首帧
   ├─⑤ 出片  full_video     → 每个片段 4～15 秒视频
   ├─⑥ 配音  voice_tts      → 角色音色 + 逐句台词音频
   ├─⑦ 口型  lipsync        → 对口型后的片段
   ├─⑧ 混音  music_generation / music_search / mmaudio
      超分  flashvsr
   │
   └─ 本地 ffmpeg 按分镜时间轴拼接、混音、压字幕 → 成片
```

**关键顺序约束**：

- ④ 必须**全部完成并人工过一遍**再开始 ⑤ —— 首帧图定了，视频才稳定
- ⑥ 的音色要先克隆一次，后面所有台词复用同一个 `reference_id`
- ⑦ 依赖 ⑤ 的视频和 ⑥ 的音频，**两边文件要对得上号**
- ⑧ 的 BGM 单独做，**不要写进分镜提示词**（会和 ⑦ 的声音打架）

---

## ① 策划 · 定方向

| 项 | 内容 |
|---|---|
| 输入 | 小说梗概 / 前三章 |
| 输出 | 可行性结论、核心矛盾（强欲望 + 强阻碍）、矛盾等级、金手指与约束 |
| 验收 | 结论明确（适合改 / 需要大改 / 不适合改）；矛盾 ≥ 3 级；金手指有约束 |

**换模型就是换 `model`**：`DeepSeek-V4-Pro` 长文本分析稳，
`Qwen3.7-Max` 结构感强，`GLM-5.2` 中文叙事细腻。

---

## ② 编剧 · 出剧本

| 项 | 内容 |
|---|---|
| 输入 | 故事骨架 + 分集数 + 单集时长 |
| 输出 | 分集大纲（每集 3～5 个情节点）+ 每集剧本（场景 / 动作 / 台词） |
| 验收 | 每集有集末钩子；台词量匹配时长（2 分钟一集约 1200～1800 字）；付费卡点落在 N×10/30/50/70/90% |

**要求模型输出结构化 JSON**，别要散文 —— 后面分镜要机器可读。

---

## ③ 分镜 · 出分镜表

| 项 | 内容 |
|---|---|
| 输入 | 单集剧本 |
| 输出 | 分镜表 JSON 数组，每项含：`shot_id` / `duration` / `visual` / `dialogue` / `transition` |
| 验收 | 六条铁律全过（见 `质量门禁.md`）；单片段 ≤ 15 秒；每段挂了过渡桥梁 |

参考结构：

```json
[
  { "shot_id": 1, "duration": 5,
    "visual": "中景，女主站在落地窗前，背对镜头，缓缓转身",
    "dialogue": "我等这一天，等了整整十年。",
    "transition": "动作衔接：转身动作接下一镜的抬头" }
]
```

> `visual` 里**不要写服装、发型、长相** —— 那些交给④的角色图资产，
> 写进分镜只会让每个镜头的角色长得不一样。

---

## ④ 出图 · 角色与首帧

| 项 | 内容 |
|---|---|
| 应用 | `nano_banana` · `submit` |
| 输入 | 分镜的 `visual` + 角色形象描述 |
| 输出 | 角色定妆图、场景图、每个镜头的首帧 |
| 验收 | 同一角色跨镜头长相一致；画幅 9:16；主体清晰 |

**两轮做法**：

1. **先出角色定妆图**（`action=generate`），人工挑一张作为基准。
2. **再出各镜首帧**（`action=edit` + `image_urls:[定妆图]`），锁住长相。

> 第一步挑图这一步别省。基准图没选好，后面几十张首帧全要重来。

---

## ⑤ 出片 · 逐段生成

| 项 | 内容 |
|---|---|
| 应用 | `full_video`（通用首选）/ `happy_horse`（声画一起出）/ `seedance`（分辨率分档） |
| 输入 | 首帧图 + 运镜与动作描述 |
| 输出 | 4～15 秒视频片段 |
| 验收 | 动作自然、无穿模；画幅与首帧一致；时长与分镜表一致 |

**时长只能 4～15 秒整数。** 分镜里超过 15 秒的段落，先拆镜再提交。

---

## ⑥ 配音 · 先克隆后合成

| 项 | 内容 |
|---|---|
| 应用 | `voice_tts` · `clone_voice` + `tts_async` |
| 输入 | 参考音频（克隆）+ 台词文本（合成） |
| 输出 | 角色音色 ID + 逐句台词音频 |
| 验收 | 音色和角色设定匹配；语气与剧情情绪一致；文件按 `shot_id` 命名 |

**每个主要角色克隆一次即可**，之后所有台词都传同一个 `reference_id`。
短台词用同步 `tts`，长台词（>500 字）用异步 `tts_async`。

---

## ⑦ 口型 · 让画面开口

| 项 | 内容 |
|---|---|
| 应用 | `lipsync`（已有视频）/ `image_human`（只有图） |
| 输入 | 视频 + 音频，或 图 + 音频 |
| 输出 | 对口型后的片段 |
| 验收 | 口型与语音同步；头部动作自然；没有音画错位 |

`lipsync` 的 `model` 支持 `xiaojiayu1.0` / `2.0` / `3.0`（也接受简写 `1.0` / `2.0` / `3.0`）。

---

## ⑧ 混音与超分

| 要什么 | 用什么 | 说明 |
|---|---|---|
| 原创 BGM | `music_generation` · `create` | `instrumental: true` 出纯伴奏；`style` 描述情绪 |
| 现成配乐 | `music_search` · `search` | 按关键词搜，出候选再挑 |
| 环境音 / 音效 | `mmaudio` · `submit` | 给视频配环境音与拟音 |
| 歌词卡点 | `music_generation` · `timing` | 出歌词时间轴，做卡拉 OK 字幕 |
| 成片超分 | `flashvsr` · `submit` | 只吃公网 URL；`duration` 不传则平台自行探测 |

---

## 本地合成（最后一步）

各片段、配音、BGM 都拿到之后，用本地 ffmpeg 按分镜表时间轴拼接：

```
1. 按 shot_id 顺序拼片段        → 视频轨
2. 按场景拼台词音频              → 对白轨
3. BGM 压低 12～18 dB 垫底       → 音乐轨
4. 环境音效按时间点叠加           → 音效轨
5. 烧字幕 / 挂 SRT               → 成片
```

**合成放本地做**：便宜、可反复修改，不用重复扣点。
改一版字幕、调一次音量，不应该产生任何费用。

## 每道工序的产物命名约定（建议）

```
proj/
├── 00-原著/            原文与梗概
├── 01-骨架/            story.json
├── 02-剧本/            ep01.md …
├── 03-分镜/            ep01.shots.json …
├── 04-图片/            char-女主.png / ep01-shot01.png …
├── 05-片段/            ep01-shot01.mp4 …
├── 06-配音/            ep01-shot01.mp3 …  voices.json
├── 07-口型/            ep01-shot01-lip.mp4 …
├── 08-音乐/            bgm-ep01.mp3 / sfx/ …
├── 09-成片/            ep01.mp4 …
└── tasks.csv           task_id / 素材 URL / 状态 / 点数
```

**`tasks.csv` 是断点续跑的命根子**：每次提交任务就写一行，
重跑时只补 `failed` 的行，不重做已经成功的镜头。
