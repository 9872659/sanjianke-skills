# 成本与排产

一部剧 30 集、每集 15 个片段，就是 **450 次视频生成**。
到这个量级，「排产」比「调参」重要得多 —— 一个参数失误乘 450 就是几百块。

---

## 一、成本结构（2 分钟一集，含 30% 废片率）

| 项目 | 数量 | 点数 | 折合 | 占比 |
|---|---|---|---|---|
| **视频生成** | 120 秒 × 1.3 | 3,120 | 31.20 元 | **78.6%** |
| **出图** | 约 24 张 | 576 | 5.76 元 | **14.5%** |
| 口型 / 数字人 | 60 秒 | 120 | 1.20 元 | 3.0% |
| 配音 | 约 1,800 Token | 90 | 0.90 元 | 2.3% |
| BGM | 1 首 | 65 | 0.65 元 | 1.6% |
| **合计** | | **3,971** | **约 39.71 元/集** | 100% |

> 单价是**参考默认值**，不是报价。用 `scripts/cost_estimate.py` 传真实单价重算。

---

## 二、省钱的两个方向（按优先级）

### 方向一：减少要生成的视频秒数（占八成，最有效）

| 手法 | 怎么做 |
|---|---|
| **减镜头** | 同样的信息用更少的镜头说完；3 个反应镜头能并成 1 个 |
| **复用镜头** | 环境空镜、过场镜头、回忆镜头跨集复用 |
| **拉长单镜头** | 能用 10 秒说完的，不要拆成两个 5 秒（省不省取决于单价口径，先算再定） |
| **静态对话改「图片 + 口型」** | 对话戏不需要运镜，用首帧图 + `image_human` / `lipsync` 比全片生成便宜得多 |
| **降分辨率** | 竖屏短剧平台会二次压缩，`720P` 通常够；要母版才上 1080P |

### 方向二：复用图片资产（占约 15%，容易漏）

| 手法 | 怎么做 |
|---|---|
| **角色图只出一次** | 定妆图锁定后，所有首帧都用 `action=edit` + 同一张参考图 |
| **场景图复用** | 同一场景只出一次，多镜共享 |
| **别每镜重出** | 分镜顺序排好再批量出图，避免同一张图出两三遍 |

---

## 三、排产原则

| 原则 | 做法 | 为什么 |
|---|---|---|
| **先跑通一条** | 单个片段走通「图 → 视频 → 配音 → 口型 → 混音」再放大 | 很多问题在最后一步才暴露，前面的钱全废 |
| **先图后视频** | 所有角色图、首帧图**先全部出完并人工过一遍** | 首帧定了，视频才稳定；否则整批重来 |
| **控制并发** | 视频生成从 **2～4 路**起步 | `429` 是排队上限到了；并发太高反而更慢 |
| **断点续跑** | 每个任务写一行到 `tasks.csv`，重跑只补失败行 | 长任务链路一定会断，能续跑才敢批量 |
| **分批验收** | 每集出完立刻抽查口型、画幅、音量 | 问题早发现在便宜的阶段 |
| **金额设上限** | 给 Key 设 quota，跑批量前先估总点数 | 参数写错时能止损 |

## 四、任务表结构（断点续跑的命根子）

`tasks.csv` 每个任务一行：

```csv
shot_id,stage,app,api,task_id,status,points,input_url,output_url,updated_at
ep01-s01,image,nano_banana,submit,task_aaa,completed,24,,"https://.../s01.png",2026-01-01T10:00:00
ep01-s01,video,full_video,submit,task_bbb,completed,100,"https://.../s01.png","https://.../s01.mp4",2026-01-01T10:05:00
ep01-s01,dub,voice_tts,tts_async,task_ccc,failed,,,,2026-01-01T10:06:00
```

**关键字段**：

- `shot_id` —— 与分镜表一一对应
- `stage` —— 工序（`image` / `video` / `dub` / `lip` / `bgm` / `upscale`）
- `task_id` —— 平台任务 ID，用来查状态、避免重复提交
- `status` —— `pending` / `completed` / `failed`
- `points` —— 实际扣点，用来对账

**重跑规则**：只跑 `status != completed` 的行。
`failed` 的行先看错误原因（素材问题还是参数问题），改完再重提。

## 五、批量脚本骨架

```python
import csv, json, os, time, urllib.request

HOST = "https://api.a7w.cn"
KEY = os.environ["A7W_API_KEY"]
POLL = 5


def call(app, api, body):
    """调一次应用接口，返回响应 data。"""
    req = urllib.request.Request(
        "%s/api/v1/apps/%s/%s" % (HOST, app, api),
        data=json.dumps(body, ensure_ascii=False).encode(), method="POST",
        headers={"Authorization": "Bearer " + KEY, "Content-Type": "application/json"})
    with urllib.request.urlopen(req, timeout=300) as r:
        d = json.load(r)
    if d.get("code") not in (1, 200):
        raise RuntimeError(d.get("msg"))
    return d.get("data") or {}


def wait(task_id, timeout=1800):
    """轮询到终态。"""
    end = time.time() + timeout
    while time.time() < end:
        time.sleep(POLL)
        req = urllib.request.Request("%s/api/v1/tasks/%s" % (HOST, task_id),
                                     headers={"Authorization": "Bearer " + KEY})
        with urllib.request.urlopen(req, timeout=120) as r:
            t = json.load(r)
        st = t.get("status")
        if st in ("completed", "failed", "cancelled", "error"):
            return st, t
    return "timeout", {}


def load_done(path):
    """读出已完成的任务，用于断点续跑。"""
    if not os.path.isfile(path):
        return set()
    with open(path, encoding="utf-8") as f:
        return {r["task_id"] for r in csv.DictReader(f)
                if r.get("status") == "completed"}


def append(path, row):
    new = not os.path.isfile(path)
    with open(path, "a", newline="", encoding="utf-8") as f:
        w = csv.DictWriter(f, fieldnames=list(row))
        if new:
            w.writeheader()
        w.writerow(row)
```

**并发做法**：用线程池（`concurrent.futures.ThreadPoolExecutor`），
`max_workers` 从 **2～4** 起步，每提交一个记一行，收结果只补失败行。
**不要一把梭全提交** —— 排队上限一到，后面的全部失败，还可能白冻结点数。

## 六、对账

| 对什么 | 怎么对 |
|---|---|
| **本次真实扣费** | 每次返回里的 `data.usage.points_cost` |
| **任务级用量** | `GET /api/v1/tasks/{task_id}` 的 `usage` |
| **账号流水** | 用户中心的用量流水，可按 Key 与时间筛选 |
| **单集成本** | `tasks.csv` 按集汇总 `points` 求和 ÷ 100 = 元 |

> 平台同时给出**标准价**（`fixed_price` / `input_price`）与
> **租户实际结算价**（`tenant_*`）。**做预算一律用租户价，最终以实际扣费为准。**

## 七、把成本压下来的实操顺序

1. **先算一集** —— `python3 scripts/cost_estimate.py --minutes 2`
2. **只跑通 1 个片段** —— 验证全链路，成本几块钱
3. **出全部首帧图并人工过一遍** —— 这一步花的是小钱，省的是大钱
4. **降分辨率到够用档** —— 竖屏短剧 720P 起步
5. **对话戏改「图片 + 口型」** —— 直接砍掉大段视频生成
6. **跑一集完整对账** —— 确认单集成本符合预算再上批量
7. **上批量 + 断点续跑** —— 并发 2～4 路起步，每集出完立刻验收
