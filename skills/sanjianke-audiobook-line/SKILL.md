## 能做什么

给一本**小说或长文本**，一条链路产出一本**能听的有声书**：

```
split   →   cast    →   voice   →   subtitle  →   join
章节切分    对白/旁白    分角色      字级时间戳    章节清单 +
（纯本地）   分配音色     逐章配音     SRT / VTT    时长台账
```

它替代的是有声书生产里最卡人的那一段：不是"读不出来"，而是
"一本书怎么切章、谁在说、说了多久、字幕对不对得上"。这四件事定不清楚，
录出来就是一堆正确但没人听得下去的音频。

| 子命令 | 做什么 | 花不花钱 | 产出 |
|---|---|---|---|
| `split` | 章节切分 | **纯本地，零调用** | `chapters.json` + `chapters.md` |
| `cast` | 识别对白 / 旁白 + 分配音色 | 本地零成本；`--llm` 才逐章一次文本调用 | `cast.json` + `cast.md` |
| `voice` | 逐章配音（多音色） | **先报价**，按千字计费 | `voice/*.mp3` + `voice/index.json` |
| `subtitle` | 字级时间戳出 SRT / VTT | **先报价**，按次计费 | `subtitle/*.srt` + `*.vtt` + `book.srt` |
| `join` | 章节拼接 + 章节清单与时长台账 | **纯本地，零调用** | `book.mp3`（或 `book.wav`）+ `chapters.json` + `playlist.txt` |
| `all` | 串起来跑完整条链路 | 先报价，**断点续跑** | 上面全部 |
| `cost` | 只算钱 | 零网络零成本 | 成本表 |
| `models` | 现查在架模型 | 免费 | 模型清单 |
| `voices` | 现查可用音色（拿 `reference_id`） | 免费 | 音色清单 |

| 你最关心 | 答案 |
|---|---|
| 多少钱 | 配音 **50 点/千字**（实测）、字幕 **40 点/次**（实测，与文本长度无关）；1 元 = 100 点。中篇 20 万字 ≈ 10000 点配音 + 字幕 ≈ **116 元** |
| 要多久 | 实测 2 章 145 字：12 个片段配音约 40 秒；字幕 2 段约 15 秒。长书的瓶颈是**片段数**，不是字数 |
| 要装什么 | **什么都不用装**。只用 Python 标准库；`join` 有 ffmpeg 更好（没有也能拼 wav，见下） |
| 中断了怎么办 | **断点续跑**：已完成的片段与字幕直接跳过（实测 12 段全跳过、**0 次调用、0 点**）。**但断点 key 含正文全文 + 音色 + 模型 + 格式 + 语速 + 采样率 + 比特率 + 端点 + 章节 + 分块共十一维** —— 改任何一维都会重配重扣 |
| 会瞎编吗 | `--llm` 模式下**强制校验逐字一致**：模型返回的片段拼起来与原文不逐字相等就直接报错，不采纳 |
| 说话人识别不准怎么办 | 本地正则搞不定的会归到「旁白」并在 `cast.unassigned_speakers` 里登记数量；要更准加 `--llm` |

### 七道硬闸门（都是拦截，不是提醒）

命中即**标红 + stderr 汇总 + 退出码非 0**，可直接进 CI；`--json` 下走统一信封。

| # | 闸门 | 判定口径 | 退出码 |
|---|---|---|---|
| 1 | 合规 | 广告法违禁词 + 音频口播红线；「最X」按**可枚举语境**豁免（见下） | 3 |
| 2 | 占位符残留 | `{}`、`[待填]`、`XXX`、`此处省略`、`TODO` | 3 |
| 3 | prompt_echo | 去标点相等 / 二元组 Jaccard ≥ 0.75 / 示例覆盖度 ≥ 0.60 | 3 |
| 4 | **章节结构** | **章数为 0 或存在空章 → 拦**；空标题、超长标题（>40 字）也拦 | 3 |
| 5 | **角色一致性** | 同一角色在全书中必须用**同一个音色**；分配了却没用到的角色也拦 | 3 |
| 6 | 成本上限 | `voice`/`subtitle`/`all` 跑前必须报价；`--yes` 或 `--budget` 二选一，超预算就地中止 | 2 / 5 |
| 7 | 产出位置 | `--outdir` 指到包内直接 `exit=2` | 2 |

### 为什么第 4、5 道闸门是本包最值钱的两道

**章节结构**：有声书与"一段长音频"的分水岭就是章节。听书的人靠章节跳转、
平台靠章节做付费切分。一份切不出章节的长文本，配出来只是一条几小时的音频——
它不会报错、字数也对、读起来也顺，但**没法上架**。
同理，**空章**（有目录没正文）听出来就是一段静音，平台直接判残包。

这道闸门不采信内存里的对象，而是拿正则去读**渲染后的成品 Markdown**：

```
## 第 1 章　雨夜的书店
```

读不出章节标题、或某一章正文为空，一律拦。

**角色一致性**：有声书的听感靠**音色认人**。同一个角色在两章里换了音色，
听众立刻跳戏——这不会报错、不会被平台拦、字数时长全对，
又是一个"表面上完全正确的错误"。

它同时又是一道**成本闸门**：音色一换就必须重配，重配就是重扣费。
所以它在配音**之前**就要过（零成本本地校验），而不是等配完几千个片段才发现。

### 「最X」的语境豁免（照抄全库统一逻辑）

「回头翻一条自己播放量最低的视频」这种话是在**描述自己的数据**，
不是对商品做绝对化宣称。小说正文天然会写「最深的那道疤」「最慢的一步」，
不豁免的话一次实测就会被误拦整篇——而闸门一旦开始误伤，使用者就会无视它。

全库为它定了一条很窄的豁免：

- `最X` 前一个字是计量类名词（量 / 率 / 数 / 分 / 位 / 条 / 次 / 段 / 部 / 集 / 页 / 个 / 天 / 月 / 年）
- **且** `最X` 后面紧跟「的」或「之」

命中豁免时**整处放过，但在产出里登记**（`gates.compliance.exempted`），
报告里会明说"本地放过了 N 处疑似绝对化用语"，**不静默放过**。
句首的「最好 / 最低」**不豁免**（代码里靠 `before and` 这一步实现）；
豁免词表刻意不含 `时 / 款 / 种 / 家 / 价`，
因为「课时最低的课程」「单价最低」都是真实的价格宣称形态，必须照拦。

### prompt_echo：模型会照抄示例

本库实测过两次：提示词里写过正例，模型就产出了几乎一字不差的标题；
其中一次那条还拿了**最高分**——不是"真的最好"，是"抄了标准答案"。

所以本包的提示词里**不出现任何一句可直接复制的完整中文句子**，
举例只用描述性说明；真实示例（跨主题，取自「旧书摊的收书账」，与有声书业务不搭）
登记在 `PROMPT_SAMPLES`，并由 `prompt_hygiene()` 对**即将发送的提示词**做前置自检。

三条判据缺一不可，第三条是补漏：

| 判据 | 抓什么 | 为什么必须有 |
|---|---|---|
| 去标点后完全相等 | 直接照抄 | 抄示例往往只改标点 |
| 二元组 Jaccard ≥ 0.75 | 长度相当的同构改写 | 本库实测：正常产出与跨主题示例最高 0.174，「少两个字的同构照抄」是 0.765 |
| 示例覆盖度 ≥ 0.60 | 示例被夹带进更长的句子 | 实测：示例揉进 36 字长句时 Jaccard 只有 0.576（**漏**），覆盖度 1.000（抓住） |

长度守卫是**相对**的：目标归一化长度 < `max(6, len(示例)//2)` 就不比——
短串的二元组集合太小，指标会虚高。

## 怎么用（命令行）

```bash
# 1) 配 Key（三种方式任选）
export A7W_API_KEY="<你的Key>"            # Windows: $env:A7W_API_KEY="<你的Key>"
#   或者 --key <你的Key>，或者 python3 scripts/a7w.py login --key <你的Key>

# 2) 章节切分（纯本地，不花钱，先跑这一步看切得对不对）
python3 scripts/run.py split --text novel.txt --outdir D:/book/b01
python3 scripts/run.py split --text novel.txt --outdir D:/book/b01 \
        --heading-pattern "^第[0-9]+话"

# 3) 角色分配（默认本地零成本；先看音色池）
python3 scripts/run.py voices
python3 scripts/run.py cast --outdir D:/book/b01 --voice-pool 6
python3 scripts/run.py cast --outdir D:/book/b01 --limit 3 --llm     # 只用前 3 章试

# 4) 配音：先报价，确认了再加 --yes（或用 --budget 封顶）
python3 scripts/run.py voice --outdir D:/book/b01
python3 scripts/run.py voice --outdir D:/book/b01 --yes --budget 3000
python3 scripts/run.py voice --outdir D:/book/b01 --sample-chars 300 --yes  # 试链路

# 5) 字级时间戳字幕（SRT + VTT）
python3 scripts/run.py subtitle --outdir D:/book/b01 --yes

# 6) 章节拼接 + 章节清单与时长台账
python3 scripts/run.py join --outdir D:/book/b01 --title "旧城拾光"

# 7) 整条链路（断点续跑，中断了原样重跑即可）
python3 scripts/run.py all --text novel.txt --outdir D:/book/b01 --budget 3000

# 只算钱，一次调用都不发
python3 scripts/run.py cost --chars 200000 --chapters 40
```

真实端点（都在 api.a7w.cn 上）：

| 用途 | 端点 |
|---|---|
| 大模型（`cast --llm`） | `POST /api/v1/chat/completions` |
| 模型清单 | `GET /api/v1/models` |
| 配音（同步，≤500 字） | `POST /api/v1/apps/voice_tts/tts` |
| 配音（异步，长文本 ≈10000 字） | `POST /api/v1/apps/voice_tts/tts_async` |
| 音色列表 | `POST /api/v1/apps/voice_tts/list_voices` |
| **字级时间戳** | `POST /api/v1/apps/voice_tts/stt` |
| 任务轮询 | `GET /api/v1/tasks/<task_id>` |

**开工前先现查一遍 schema，别照抄记忆**：

```bash
python3 scripts/a7w.py schema voice_tts
```

三条实测确认的接口事实（本包就是踩过才写下来的）：

1. **配音的音色参数叫 `reference_id`，不叫 `voice_id`**。值是 `list_voices` 返回的
   `id` / `model_id`，**32 位十六进制，抄短一位就得到「任务处理失败」**。
   语速是 `prosody.speed`（**对象**），不是顶层 `speed`；格式参数叫 `format`。
2. **`voice_tts/tts` 的 schema 原文是「同步接口建议不超过 500 字符」**。
   所以逐块按 500 字硬上限拆；单块超过 5000 字才切 `tts_async`（异步约 10000 字符）。
   最长的那份"看不出来"的失败就是被上游悄悄截断——音频少一句但没有任何报错。
3. **字级时间戳来自 `voice_tts/stt` 的 `ignore_timestamps: false`**。
   平台默认是 `true`，那一档 `result.segments` 是**空数组**（只有整段文本）。
   显式传 `false` 后，中文实测**一字一段**：
   `result.segments = [{"text":"旧","start":0.08,"end":0.16}, ...]`。
   本包不拿字数估算冒充时间戳——抠不出 segments 就直接失败。

另外两条平台口径：

- `/chat/completions` 的**成功响应不带 `code` 字段**；生成应用（配音 / 语音识别）
  **`code == 1` 才是成功**。两者不能互相套用。
- 异步任务的 **`status` 在任务 `data` 顶层**，不在 `data.result` 里（平台文档写错了）。
  客户端读的就是 `data.status`，实测正确。

## 参数说明

### 通用

| 参数 | 说明 |
|---|---|
| `--outdir` | 产出目录。**不许指到包内**（指到包内 `exit=2`），默认 `./audiobook-out` |
| `--json` | JSON 输出，写在子命令**前后都可以**；失败走 `{"ok":false,"exit":N,"error":{...}}` |
| `--key` | 临时指定 API Key（也可用 `A7W_API_KEY` 或 `~/.a7w/config.json`） |
| `--chars-per-minute` | 语速口径（字/分钟），默认 250。**同时**影响成本报价、时长估算、join 兜底时长 |
| `--out` | 把结果写到指定文件（人读模式写 Markdown，`--json` 模式写 JSON） |

### split（章节切分，纯本地）

| 参数 | 说明 |
|---|---|
| `--text` | **必填**。小说 / 长文本文件；UTF-8 / GBK / Big5 / UTF-16 自动识别 |
| `--heading-pattern` | 自定义章节标题正则，覆盖内置的 5 套 |
| `--chunk-blocks` | 没识别到标题时按空行分块（**不是**按作者章节切，产出里会登记） |
| `--minutes` | 目标总时长，只用于时长估算 |

内置的 5 套章节标题形态（都**行首锚定**，且标题部分必须够短）：

| 形态 | 例子 |
|---|---|
| 第N章 | `第一章　雨夜的书店`、`第 12 节`、`第3回`、`第2卷`、`第5话` |
| Chapter N | `Chapter 12`、`Ch.7` |
| 数字标题 | `1. 开场`、`01、雨夜` |
| 卷 / 部 | `卷一　少年时`、`上部` |
| 特殊章 | `楔子`、`序章`、`尾声`、`番外2`、`大结局` |

三条切分规则的来由（都是真机读中文小说踩出来的）：

1. **必须行首锚定**。正文里写「他翻到第一章」太常见了，不锚行首会把每一句
   提到章节名的话都当成标题。
2. **标题行要短且不带句末标点**。`第一章　他说，算了。` 是正文不是标题；
   超过 40 字基本是把正文吞进来了。
3. **标题前缀的正文归第一章**。书名 / 作者 / 简介丢了就是**静默丢内容**。

### cast（识别对白 / 旁白，分配音色）

| 参数 | 说明 |
|---|---|
| `--chapters` | 章节文件，默认 `<outdir>/chapters.json`（也认 `.md`） |
| `--limit N` | 只处理前 N 章（**省钱预演用**） |
| `--llm` | 用大模型逐章切段与标注（更准，但每章一次文本调用） |
| `--no-fetch-voices` | 只做切分，不拉音色池（纯离线，零调用） |
| `--voice-pool N` | 自动取用多少个音色，默认 6 |
| `--narrator-voice` | 旁白音色 `reference_id` |
| `--voice-map` | `"主角=<reference_id>,配角=<reference_id>"` |

**说话人归属规则（两轮）**：

1. 逐处引号独立判定：引号前紧贴引导词 → 用它；引号后紧跟引导词 → 用它；
   引号前是**人物动作**（`林砚把伞收起来，`）→ 用动作主语；都没有 → 记待定。
2. 对**待定**的引号做段内一致性推断：段内候选唯一 → 用它；
   多个候选 → 用"离得最近的已判定说话人"。

仍推不出来的引号**归到旁白并在产出里登记数量**（`cast.unassigned_speakers`），
要更准就 `--llm`。这里**不静默丢掉任何一个字**——丢掉就是整句内容消失，
是最坏的那种静默失败。

**`--llm` 的强制校验**：模型只被允许"切段 + 标角色"，返回的片段拼起来
（去掉标点与空白后）必须与原文**逐字一致**，不一致就直接报错。
理由：音频是逐字念出来的，模型顺手润色一个字，字幕和音频就对不上，
而且**肉眼看不出来**。

### voice（逐章配音）

| 参数 | 说明 |
|---|---|
| `--cast` | 角色分配文件，默认 `<outdir>/cast.json` |
| `--chapters` | 只配这些章（逗号分隔章号，例如 `1,2`） |
| `--narrator-voice` / `--voice-map` | 覆盖旁白 / 角色音色（会写回 `cast.json`） |
| `--format` | 音频格式：`mp3` / `wav` / `pcm` / `opus`，默认 `mp3` |
| `--tts-model` | TTS 模型：`s1` / `s2-pro`，默认 `s2-pro` |
| `--speed` | 语速（`prosody.speed`，1.0 为原速） |
| `--sample-rate` | 采样率 |
| `--mp3-bitrate` | MP3 比特率：64 / 128 / 192 |
| `--sample-chars N` | **只配前 N 个字**（试链路省钱用；0 = 全部） |
| `--points-per-1k` | 覆盖配音单价（点/千字），默认用实测值 50 |
| `--timeout` | 单个任务轮询超时（秒），默认 1800 |
| `--force` | 忽略断点全部重配（**会重复扣费**） |
| `--yes` / `--budget` | 确认报价 / 预算封顶，二者给其一 |

**分块策略**：同章内、同角色且音色相同的**连续片段合成一块**（≤500 字）。
实测配音无最低消费（50 点/千字严格线性），合并不会多花钱，
但能把调用次数从几万次压到几百次——调用次数直接决定失败率与重试成本。
一本中篇的台词条数是以万计的。

### subtitle（字级时间戳出 SRT / VTT）

| 参数 | 说明 |
|---|---|
| `--voice-index` | 配音台账，默认 `<outdir>/voice/index.json` |
| `--chapters` | 只处理这些章（逗号分隔） |
| `--limit N` | 只处理前 N 个片段（**省钱预演用**） |
| `--language` | 识别语言（不给则上游自动检测） |
| `--chars-per-line` | 一条字幕最多几个字，默认 16 |
| `--max-seconds` | 一条字幕最多停留几秒，默认 8 |
| `--points-per-call` | 覆盖字幕单价（点/次），默认用实测值 40 |
| `--budget` / `--yes` | 同 `voice` |

**为什么要把字级 segment 聚成字幕条**：逐字出一条字幕，一本有声书会有几十万条 SRT，
播放器直接卡死、人也没法读。所以按两条上限聚合（最多 16 字 / 最多 8 秒）。

**字幕文字用 ASR 回读，不用原文**：回读文字与时间戳是**对齐的**（同一个来源），
而原文与时间戳只是"应该对齐"。回读有误差（实测专有名词会错，属上游能力边界），
差异逐条登记在 `subtitle.json` 的 `text_mismatch` 里，**不掩盖**。

### join（章节拼接 + 清单）

| 参数 | 说明 |
|---|---|
| `--chapters` | 只拼这些章（逗号分隔） |
| `--ffmpeg` | ffmpeg 路径（默认找 PATH 与 `FFMPEG` 环境变量） |
| `--filename` | 合并音频文件名，默认 `book.mp3`（无 ffmpeg 且是 wav 时 `book.wav`） |
| `--title` | 书名（写进清单） |

**时长的三个来源，按可靠性排序**：

| 优先级 | 来源 | 精度 |
|---|---|---|
| 1 | `stt` 的字级时间戳（`result.duration`） | 精确 |
| 2 | wav 文件头（自己解析 RIFF，不依赖 ffprobe） | 精确 |
| 3 | 字数估算 | **估算**，会在产出里逐章标注 |

只有 1、2 都拿不到时才退回 3，并在 `chapters.json` 的 `basis` 字段里
明确写出「字数估算（**不是真实时长**）」，不静默估算。

### all / cost / voices / models

`all` 的参数是各子命令参数的并集，额外有 `--skip-subtitle`（只出章节音频）。
`cost` 接收 `--chars` / `--minutes` / `--chapters`，
以及 `--points-per-1k` / `--points-per-call` / `--points-per-ktok` 三个单价覆盖。
`voices` 有 `--tag` / `--title-search` / `--language` / `--page-size`。
`models` 有 `--type`（默认 `text`，传 `all` 看全部）。

## 断点 key 含哪些维度（**这一节是本包最该看的一节**）

断点 key 少一维的后果**不是报错**，而是「用户以为改了、其实静默复用了旧产物」——
用户听到的还是旧音色 / 旧语速 / 旧格式，而命令行的输出一切正常。

同族包已实测踩过三种形态：提示词截断到 24 字（改第 25 字之后 key 没变）、
`resolution` 不入 key（从 1K 改到 4K 拿回的还是 1K）、死参数
（参数在命令行存在、在 key 里不存在，改了什么都不会变）。

所以本包把音频断点 key 做成**显式白名单**，共十一维：

| 维度 | 为什么必须进 key |
|---|---|
| `text` | 正文全文（**不截断**，整段入 hash） |
| `role` | 换角色 = 换音色 = 必须重配 |
| `reference_id` | 音色本身；空字符串（平台默认音色）与指定了音色是两回事 |
| `model` | `s1` / `s2-pro` 音色表现不同 |
| `format` | `mp3` / `wav` / `pcm` / `opus`：拿 wav 的脚本拿到 mp3 会静默出错 |
| `speed` | `prosody.speed` |
| `sample_rate` | 采样率 |
| `mp3_bitrate` | MP3 比特率 |
| `endpoint` | `tts` / `tts_async`：上游不同实现，产物不同 |
| `chapter` | 归属章节，决定 `join` 的拼接顺序 |
| `part` | 同章同角色被 500 字上限拆开后的第几块 |

字幕断点 key 六维：`audio_sig`（上游音频指纹）/ `language` /
`ignore_timestamps` / `chars_per_line` / `max_seconds` / `endpoint`。

实测（13 组改动逐一验证，见 README 的「真机实测」章节）：
改任何一维，`sig` 都变，都会重配而不是复用旧音频。

**新增任何影响音频的参数，都必须同时加进 `VOICE_KEY_FIELDS` 并登记到本节。**

## 产出目录长这样

```
D:/book/b01/
├── chapters.json / chapters.md     章节切分结果（闸门读的就是 chapters.md）
│                                   `join` 会在 chapters.json 里**追加**一个 `join` 段
│                                   （章节清单 + 时长台账），**不覆盖 `chapters` 数组**
├── cast.json     / cast.md         角色与音色分配 + 逐片段角色标注
├── voice/                          逐片段音频 + index.json（含 audio_url，字幕要用）
├── subtitle/                       book.srt / book.vtt + 逐片段 srt/vtt + subtitle.json
├── audiobook-state.json            断点文件 + 成本台账（cost.items 可逐笔核对）
├── book.mp3（有 ffmpeg）或 book.wav（无 ffmpeg 且是 wav 输出）
└── playlist.txt                    播放清单（起点 / 章号 / 时长 / 角色）
```

音频与字幕一律落在**包外**的 `--outdir` 里。

## 没有 ffmpeg 时会怎样

`join` 有两条路：

| 情况 | 行为 |
|---|---|
| 有 ffmpeg | 按章节顺序拼成一条 **mp3**，写 ffmpeg metadata 章节标记（平台 / 播放器识别） |
| 无 ffmpeg，音频是 **wav / pcm** | **纯标准库**把 PCM wav 逐块接起来并重建 RIFF 头，产出真 `book.wav` |
| 无 ffmpeg，音频是 **mp3** | mp3 是压缩格式、不能靠拼字节接起来 → 写出章节清单与播放清单，**明确报"没有产出合并音频"**（`exit=2`），不假装成功 |

第三种情况下装上 ffmpeg 后**原样重跑同一条命令即可**——断点续跑，
不会重复扣配音与字幕的钱。

wav 逐块拼接前会校验**参数一致性**（采样率 / 声道 / 位宽）；
不一致就直接拒绝，因为硬拼会得到一条变速或变调的音频，
那种错误听起来像"设备有问题"，很难查。

## 排错

| 现象 | 原因与解法 |
|---|---|
| `code=0 任务处理失败`（配音） | **`reference_id` 不完整或不存在**。用 `run.py voices` 整条复制（32 位十六进制）。去掉 `--narrator-voice` 可立刻区分是音色问题还是文本问题 |
| `stt 没有返回字级时间戳` | `ignore_timestamps` 没传 `False`（平台默认 `true`，那档 `segments` 是空数组）。本包已固定传 `False`，出现这条说明上游改了行为 |
| `有 N 段引号里的话推不出说话人` | 本地启发式的能力边界。加 `--llm`；或给 `--voice-map` 手工指派 |
| `拒绝执行：--outdir 指到了包内` | 产出音频不许进包。换 `%TEMP%\audiobook` 或 `D:/book/b01` |
| `报价 X 点已超过 --budget` | 钱还没花就中止了。核对 `--chars-per-minute`（语速口径影响报价）或提高预算 |
| `跑前必须报价并确认` | 加 `--yes`，或用 `--budget N` 封顶 |
| `有 1 章正文为空` | 切分把正文吞进了标题行，或原文那一章确实是空的。看 `chapters.md` 手工修，或换 `--heading-pattern` |
| `角色音色不一致` | 同一角色在两章用了不同 `reference_id`。用 `--voice-map` 统一；**这条不修就会重配重扣** |
| 重跑又扣了一次钱 | 断点 key 含十一维。改了正文 / 音色 / 格式 / 语速 / 采样率 / 比特率里任何一项都会重配。重跑前先用 `cost` 核价，或看 `audiobook-state.json` 的 `cost.items` |
| `本机没有 ffmpeg，音频是 mp3` | 见上「没有 ffmpeg 时会怎样」。装 ffmpeg 后原样重跑 |
| `读不出这个文本文件的编码` | 试过 utf-8 / gb18030 / big5 / utf-16。先用编辑器转成 UTF-8 |
| 时长台账标了「字数估算」 | 该片段既没有字幕时间戳、也不是可解析的 wav。跑 `subtitle` 可拿到精确时长 |
| 字幕文字和原文对不上几个字 | ASR 回读误差（专有名词尤其明显），属上游能力边界。逐条差异在 `subtitle.json` 的 `text_mismatch` |

## 已知取舍（如实登记，不掩饰）

1. **本地说话人识别是启发式**。两轮规则能处理中文小说的主流形态
   （`「…」他说` / `他说：「…」` / `他做了个动作，「…」`），
   但代词主语的连续对话、倒装、无引导词的对话会判不出来——
   那种情况**归旁白并登记数量**，不猜。要准就 `--llm`。
2. **字幕文字用 ASR 回读，与原文可能有出入**。这是为了让文字与时间戳同源对齐；
   差异逐条登记。若要"字幕必须与原文逐字一致"，请自行把 `book.srt` 的文字
   用原文替换（时间戳不受影响）。
3. **`cast --llm` 的文本单价平台不公开**，所以 `cost` 不给 `--points-per-ktok`
   就**只报 token 数、不报金额**——不编单价。
4. **平台 `pricing_matrix` / `tenant_*` 字段半数不可信**，本包不拿它们算钱。
   报价用实测常量（配音 50 点/千字、字幕 40 点/次），
   结算只认 `usage.points_cost`，两者不一致时会**明确报出来**。
5. **字幕按片段计次**（40 点/次）。片段数是「同章同角色连续片段合并」之后的数量，
   通常远小于"章数 × 角色数"。精确片段数看 `voice` 的报价输出。
6. **图片 / 音频 / 二进制一律不进包**。包内只有 `.md .py .txt .json .sh .js .yaml .yml .csv`。
