# 有声书演播方法（章节 / 角色 / 多音色 / 字幕）

这份文档讲的是**方法**：一本书怎么切章、谁在说、多音色怎么分、
字幕怎么排。命令与参数见 `SKILL.md`，计费口径见 `cost-and-troubleshooting.md`。

---

## 一、章节切分：先确认切得对，再花钱

`split` 是纯本地步骤，**零调用、零成本**，所以任何时候都应该先跑它。
切错的代价不是报错，而是**后面每一步都白做**：配音按错章的片段配、
字幕按错章的时间轴拼、章节清单给平台时对不上目录。

### 1.1 内置的五套标题形态

| 形态 | 正则意图 | 例子 |
|---|---|---|
| 第N章 | `第` + 数字（阿拉伯或汉字）+ 章/回/节/卷/部/篇/话/集 | `第一章　雨夜的书店`、`第 12 节`、`第3回`、`第2卷` |
| Chapter N | 拉丁文 `Chapter` / `Ch.` + 数字 | `Chapter 12`、`Ch.7` |
| 数字标题 | 行首数字 + 分隔符 + 标题 | `1. 开场`、`01、雨夜` |
| 卷 / 部 | `卷X` / `卷之X` / `上部` / `中部` / `下部` | `卷一　少年时` |
| 特殊章 | 固定词表 | `楔子`、`序章`、`引子`、`尾声`、`番外2`、`大结局` |

### 1.2 三重判据（顺序不能换）

一行要被认定为章标题，必须**同时**满足：

1. **行首锚定**。正文里写「他翻到第一章」太常见了，
   不锚行首会把每一句提到章节名的话都当成标题，把一章切成几十段。
2. **行足够短**。代码用「行长度 > `max_heading_len + 24`」先做粗筛，
   再在闸门里用 `max_heading_len`（40 字）严格判——
   超过 40 字的"标题"基本是把正文吞进来了。
3. **行尾不带句末标点**。`第一章　他说，算了。` 是正文不是标题。
   判据是行尾不在 `。！？!?；;…` 里。

三条都是被真实中文小说逼出来的。少任何一条，误判都会让整本书的章节结构垮掉。

### 1.3 归入第一章的前缀正文

标题之前的文字（书名、作者、简介、题记）**不能丢**——丢了就是**静默丢内容**，
而那是最坏的一种 bug：产出看起来完全正常，只是少了一段。

本包的做法：把第一个真章节之前的所有非空文本拼到**第一章的正文开头**，
用空行与原有正文隔开。实测产出：

```markdown
## 1　雨夜的书店

旧城拾光
作者：三剪客

楔子

雨下了整整一夜。林砚站在旧书店门口……

林砚推开门，铜铃响了一声。……
```

注意：这里的 `楔子` 也被当成前缀吞进第一章了。如果原文里有**独立的楔子章节**
并且你要单独成章，用 `--heading-pattern` 显式指定，或者手工在 `chapters.md` 里
把它拆出来（`cast` / `voice` 都认 `.md`）。

### 1.4 切不动的时候：两条降级路，都不假装切对了

| 情况 | 行为 | 产出里的登记 |
|---|---|---|
| 只认出一个标题 | 按「整篇一章」处理（一个标题不构成"切动"） | `method = 未识别到章节标题，整体作为一章` |
| 一个标题都没有 + `--chunk-blocks` | 按空行分块 | `method = 按空行分块（**不是**按作者章节切，请人工确认）`，且 stderr 会提示 |
| 一个标题都没有，也没给 `--chunk-blocks` | 按「整篇一章」处理 | 同上 |

`--heading-pattern` 是第四路：直接给正则。例如某本书用的是
`【第001章】` 这种形态：

```bash
python3 scripts/run.py split --text novel.txt --outdir D:/book/b01 \
        --heading-pattern "^【第[0-9]+章】"
```

### 1.5 闸门四拦什么

| 判定 | 为什么拦 |
|---|---|
| 章数 = 0 | 完全没切动，后面所有步骤都在做白工 |
| 存在空章（正文 0 字） | 有目录没内容，听出来就是一段静音；平台直接判残包 |
| 存在空标题 | 标题为空说明把正文吞进标题行了 |
| 标题 > 40 字 | 同上 |

拦下时的退出码是 **3**，并且会打章号，方便直接去 `chapters.md` 里修。

## 二、角色分配：本地启发式 vs 大模型

### 2.1 为什么默认走本地

说话人识别**只影响音色分配**，不影响正文、不影响音频长度、不影响字幕时间戳。
启发式做不对的代价是"某个配角用了旁白音色"，而不是"内容错了"。

本地分词的好处：**零成本、可复现、离线可跑**。
一本 40 章的书用 `--llm` 就是 40 次大模型调用——钱不多，但没有必要每次都花。

### 2.2 本地分词的规则（两轮）

**第一轮**：逐处引号独立判定。中文小说的对白形态很固定：

| 形态 | 例子 | 判定 |
|---|---|---|
| 引导词在引号前 | `老人说：「你来晚了。」` | 说话人 = 老人 |
| 引导词在引号后 | `「你来晚了。」老人说。` | 说话人 = 老人 |
| 动作在引号后 | `「三年？」林砚皱眉。` | 说话人 = 林砚（动作主语） |
| 都没有 | `「不知道。」` | 记待定 |

**第二轮**：对**待定**的引号做段内一致性推断。

- 段内已判定的候选**唯一** → 用它（中文对话段基本是两人一来一回，这个推断很稳）
- 段内候选**多个** → 用"离得最近的已判定说话人"
- 仍定不下来 → 保持待定，**归到旁白**

引号外的文字**全归旁白**。这是实测踩出来的规则：第一版把 `「你好」他说`
里的 `他说` 也算进了对白文本，于是音频里念出了"他说"两个字。
对白文本必须**只取引号内部**。

### 2.3 「归到旁白 + 登记」而不是「猜一个」

推不出说话人的引号归到旁白，并在 `cast.unassigned_speakers` 里登记**数量**，
stderr 也会提示。为什么宁可不猜：

> 猜错等于给主角配了配角的声音，而且**结果看起来完全正常**——
> 角色表上有名有姓，配音也成功，只有听众能听出不对。

数量登记让用户知道"这段需要用 `--llm` 或 `--voice-map` 补"，
而不是以为一切正常。

### 2.4 `--llm` 模式：只允许标注，不允许改写

`--llm` 的提示词把模型锁死在「切段 + 标角色」这件事上，
并且**强制校验**：模型返回的片段拼起来（去掉标点与空白后）
必须与原文**逐字一致**，不一致就直接报错，不采纳。

理由：音频是逐字念出来的。模型顺手润色一个字：

1. 音频念的是"润色后"的（因为配音用的是片段文本）
2. 字幕用的是 ASR 回读（与音频对得上）
3. 正文用的是原文

三者就开始互相漂移，而且**肉眼看不出来**。与其事后查，不如在入口拒掉。

用法建议：

```bash
# 先只用前 3 章试，确认标注质量与成本
python3 scripts/run.py cast --outdir D:/book/b01 --limit 3 --llm --json
```

### 2.5 音色怎么分

| 角色类型 | 默认取法 | 覆盖方式 |
|---|---|---|
| 旁白 | `--narrator-voice`；没给就用 `--voice-map` 里的；再没有就取第一个可用音色 | `--narrator-voice <ID>` |
| 对白角色 | `--voice-map` 里指定的优先；没给的按音色池依次分配 | `--voice-map "角色=<ID>,角色=<ID>"` |

音色池默认取 6 个（`--voice-pool`）。先用 `voices` 看清单，
把 **32 位十六进制的 `reference_id` 整条复制**——抄短一位就会得到
「任务处理失败」。

## 三、多音色演播的几条实务口径

### 3.1 音色要拉开距离，但别跨性别乱配

- **旁白**用一个**平稳、辨识度高**的中性音色。旁白占据全书 60~80% 的时长，
  选错了整本书的听感就定了。
- **主角**要与旁白**明显不同**（性别或音域差异），否则听众分不清谁在说话。
- **同性配角**尽量用音区差异（一个明亮、一个低沉）而不是"两个都差不多"。

### 3.2 章与章之间保持一致

这是**闸门五**管的事：同一个角色在全书中必须用**同一个 `reference_id`**。
角色音色一换，听众立刻跳戏；而且**音色一换就必须重配，重配就是重扣费**。
所以这道闸门在配音**之前**就过（零成本本地校验）。

分配了音色却全书没出现过的角色也会被拦——那是白占一个音色位
（也说明角色识别出了冗余项）。

### 3.3 片段合并不多花钱

同章内、同角色且音色相同的**连续片段会合成一块**（≤500 字）。
实测配音**无最低消费**（50 点/千字严格线性），所以合并：
- 不多花钱
- 把调用次数从几万次压到几百次
- 调用次数直接决定失败率与重试成本

代价是**同一块内的语气无法分别控制**。要逐句控语气就拆开配
（本包不提供逐句语气参数，因为 `voice_tts` 的 schema 里没有这个能力）。

### 3.4 语速口径（`--chars-per-minute`）

默认 250 字/分钟。它是**唯一的口径**，同时影响三处：

1. 成本报价（字数 → 点）
2. 时长估算（字数 → 分钟）
3. `join` 的兜底时长（两级真实来源都拿不到时）

改它的建议：

| 内容类型 | 建议值 |
|---|---|
| 严肃文学、慢节奏 | 220~240 |
| 通俗小说、网文 | 250~270 |
| 快节奏爽文 | 270~290 |

实测：某次真实演播音频 124 字 / 29.76 秒 → **250 字/分钟**。
用它做基准，再用真实音频的 `stt` 时长反校准，是最稳的做法。

## 四、字幕排版

### 4.1 为什么要聚合，不能逐字出

`stt` 返回的是**字级** segment（中文实测一字一段）。
逐字出一条字幕：

- 一本 20 万字的有声书 → 20 万条 SRT
- 播放器直接卡死
- 人也没法读

所以按两条上限聚合：

| 上限 | 默认 | 参数 |
|---|---|---|
| 一条字幕最多几个字 | 16 | `--chars-per-line` |
| 一条字幕最多停留几秒 | 8 | `--max-seconds` |

任一条触发就断条。

### 4.2 字幕文字用 ASR 回读，不用原文

这是**有意**的选择，不是偷懒：

| 方案 | 文字与时间戳的关系 | 风险 |
|---|---|---|
| 用 ASR 回读文字 | **同源、天然对齐** | 回读有误差（专有名词尤其明显） |
| 用原文 | 只是"应该对齐" | 一旦上游切分口径有差异，整条字幕就会错位，而人眼很难发现 |

本包取第一种，并把**逐条差异登记**在 `subtitle.json` 的 `text_mismatch` 里
（含 ASR 回读、原文、各自字数），不掩盖。
如果业务要求"字幕必须与原文逐字一致"，请自行把 `book.srt` 的文字用原文替换
（时间戳不受影响）。

### 4.3 输出的三类字幕文件

| 文件 | 用途 |
|---|---|
| `subtitle/00001.srt`、`00001.vtt` | **逐片段**字幕（时间从片段开头算） |
| `subtitle/book.srt`、`book.vtt` | **全书合并**字幕（时间已加上前面所有片段的偏移） |
| `subtitle/subtitle.json` | 台账：逐片段的时长、条数、ASR 回读、差异登记 |

`book.srt` 的时间轴与 `join` 的章节台账**同源**（都用逐片段的真实时长累加），
所以字幕与章节清单能对得上。

## 五、一条推荐的完整流程

```bash
# 1) 先切章，人工看一眼切得对不对（零成本）
python3 scripts/run.py split --text novel.txt --outdir D:/book/b01
#    看 chapters.md，重点看：章数对不对、有没有空章、标题有没有被吞

# 2) 角色分配（零成本），看角色表合不合理
python3 scripts/run.py voices                     # 拿 reference_id
python3 scripts/run.py cast --outdir D:/book/b01 --voice-pool 6
#    看 cast.md：角色数、每人片段数、unassigned_speakers 有多少

# 3) 先拿一小段试链路（几毛钱）
python3 scripts/run.py voice --outdir D:/book/b01 --sample-chars 300 --yes
python3 scripts/run.py subtitle --outdir D:/book/b01 --limit 2 --yes
python3 scripts/run.py join --outdir D:/book/b01
#    听一遍音频、看一遍 srt，确认音色与断句都对

# 4) 全量跑（先核价）
python3 scripts/run.py cost --chars 200000 --chapters 40
python3 scripts/run.py all --text novel.txt --outdir D:/book/b01 --budget 12000
```

第 3 步是关键：**几毛钱换一份"音色与断句都对"的确认**，
比全量跑完再发现旁白选错了要便宜三个数量级。
