# 成本与排错（单价 / 报价口径 / 断点 key / 事故复盘）

这份文档讲**钱与坑**：实测单价、报价 vs 实际的对账口径、
断点 key 为什么有十一维、以及一份按现象索引的排错表。

---

## 一、实测单价（只登记我们真跑出来过的）

| 接口 | 实测单价 | 依据 |
|---|---|---|
| `voice_tts/tts` | **50 点 / 千字** | 6 组样本严格线性、**无最低消费**；本包复测 15 字 = 0.75 点，一字不差 |
| `voice_tts/tts_async` | 与 `tts` 同价（按字数） | 同上游实现 |
| `voice_tts/stt` | **40 点 / 次** | 与文本长度无关（2.795 秒的音频实测 40 点，长音频同样 40 点） |
| `voice_tts/list_voices` | **免费** | 同步、不扣点 |
| `voice_tts/clone_voice` | **未实测** | 本包不封装，也**不报价** |
| 平台换算 | **1 元 = 100 点** | 平台公开口径（1 点 = 0.01 元） |

### 1.1 为什么单价写成常量而不是现拉

平台的 `GET /api/v1/pricing` **只覆盖少数接口**，`voice_tts` 不在里面；
`/api/v1/apps/<app>` 的 `tenant_*` 字段我们验证过**半数与结算价不一致**。

所以本包的口径是：

- **报价**用实测常量（`TTS_POINTS_PER_1K_CHARS` / `STT_POINTS_PER_CALL`）
- **对账**只认 `usage.points_cost`
- 两者不一致时**明确报出来**，不糊过去

```python
def _report_spend(label, quoted, actual):
    """把**真实扣点**打出来，并与报价对账。不一致就明说。"""
```

实际输出长这样（真机原文）：

```
  配音 00001-旁白.mp3：实际扣费 1.75 点 ≈ 0.0175 元
  字幕 1：实际扣费 40.0 点 ≈ 0.4 元
```

报价与实际差超过 `max(0.5, 报价 × 5%)` 时会追加一句
`（与报价 X 点相差 +Y 点，以实际为准）`。

### 1.2 一次真实试跑的完整账单

| 步骤 | 规模 | 扣点 | 折算 |
|---|---|---|---|
| `voice` | 145 字 / 12 个片段 | **7.25 点** | 0.0725 元 |
| `subtitle` | 2 个片段（`--limit 2`） | **80 点** | 0.80 元 |
| **合计** | | **87.25 点** | **≈ 0.87 元** |

报价 7.25 点，实际逐片段相加 **正好 7.25 点**（1.75 + 0.25 + 0.70 + 0.35
+ 0.75 + 0.35 + 0.15 + 0.25 + 0.10 + 0.30 + 0.85 + 1.45 = 7.25）。
**50 点/千字严格线性**这条实测结论再次得到验证。

### 1.3 规模口径（用 `cost` 算，别拍脑袋）

```bash
python3 scripts/run.py cost --chars 200000 --chapters 40
```

| 规模 | 配音 | 字幕（按 40 章粗估） | 合计 |
|---|---|---|---|
| 短篇 2 万字 | 1000 点 | 1600 点 | 26 元 |
| 中篇 20 万字 | 10000 点 | 1600 点 | **116 元** |
| 长篇 100 万字 | 50000 点 | 1600 点 | 516 元 |

⚠️ 字幕那一列的"章数"只是**粗估**。真实计次单位是**片段数**
（「同章同角色连续片段合并」之后的数量），
精确数字看 `voice` 的报价输出——它会打「N 个片段」。

字幕成本**可能比配音还高**（按次计费，一次 40 点），
这是本包最容易被低估的一笔钱。好消息是断点续跑让它不会重复花。

## 二、成本前置：报价 → 确认 → 累计对账

### 2.1 两道闸门，不是一道

| 只有报价 | 只有预算 |
|---|---|
| 用户不知道要花多少，被动扣费 | 报价算漏了（正文比预期长）就会一路花下去 |

所以口径是：**跑前必须报价，且要么 `--yes` 明确同意，要么 `--budget` 封顶**。
两个都没有 → `exit=2`，**一分钱都不花**。

```
=== 配音（12 个片段 / 145 字 / 3 个角色） 成本前置报价 ===
  · 配音 voice_tts/tts                         7.25 点  ≈ 0.0725 元
  合计 7.25 点 ≈ 0.0725 元（1 元 = 100 点；结算只认 usage.points_cost）
```

### 2.2 累计对账用**真实扣点**，不是报价值

每配一个片段就把 `usage.points_cost` 累加进 `spent`，
`--budget` 是这条累加线的上限，超了**立刻停**（不是配完才检查）：

```
!! 配音已花 X 点超过 --budget Y 点，就地中止（已完成 N 个片段）
```

同时每笔都记进 `audiobook-state.json` 的 `cost.items`，
可以逐笔核对"钱花在哪了"。

### 2.3 `all` 的预算要拆两段

`all` 里配音先花钱，剩下的额度才给字幕。代码里是
`a.budget_after_voice = a.budget`——具体实现细节不重要，
重要的是：**`--budget` 是整条链路的上限，不是每一步的上限**。

### 2.4 有声书为什么必须比播客更严格

播客一期 30 分钟 ≈ 8000 字 ≈ 400 点 ≈ 4 元。报价错一位数，损失可见。

有声书：一本中篇 20 万字 = **10000 点 = 100 元**。
报价错一位数（比如把千字当万字算）就是 1000 元。
再叠字幕的按次计费，**"睡一觉起来钱没了"是完全可能的**。

所以本包的口径是：**任何付费步骤都必须先有报价，且必须有 `--yes` 或 `--budget`**。
没有例外、没有"这个步骤很便宜所以放过去"。

## 三、断点 key：十一维，少一维就静默复用旧产物

### 3.1 问题的本质

断点 key 少一维的后果**不是报错**，而是：

> 用户以为改了、其实静默复用了旧产物。
> 听到的还是旧音色 / 旧语速 / 旧格式，而命令行的输出一切正常。

这是同族包实测踩过的，共三种形态：

| 形态 | 表现 |
|---|---|
| 提示词截断到 24 字 | 改了提示词第 25 字之后，key 没变，静默复用旧图 |
| `resolution` 不入 key | 从 1K 改到 4K，拿回的还是 1K 的图 |
| 死参数 | 参数在命令行存在、在 key 里不存在，改了什么都不会变 |

### 3.2 本包的白名单（音频，十一维）

```python
VOICE_KEY_FIELDS = (
    "text",           # 正文全文（**不截断**）
    "role",           # 角色名（换角色 = 换音色 = 必须重配）
    "reference_id",   # 音色（空字符串代表平台默认音色，与"指定了音色"是两回事）
    "model",          # TTS 模型（s1 / s2-pro 音色表现不同）
    "format",         # mp3 / wav / pcm / opus
    "speed",          # prosody.speed
    "sample_rate",    # 采样率
    "mp3_bitrate",    # MP3 比特率
    "endpoint",       # tts / tts_async
    "chapter",        # 归属章节，决定 join 的拼接顺序
    "part",           # 同章同角色被 500 字上限拆开后的第几块
)
```

指纹算法：把这十一维按字段名排序后 JSON 序列化 + sha256 取前 16 位。
`None` 统一成 `"null"`，避免 `speed=None` 与 `speed=0` 撞在一起。

字幕另有一组（六维）：`audio_sig`（上游音频指纹）/ `language` /
`ignore_timestamps` / `chars_per_line` / `max_seconds` / `endpoint`。

### 3.3 实测：13 组改动，全部换 key

| 改动维度 | sig 是否变 |
|---|---|
| `text` 改一个字（尾部） | ✅ 变 |
| `text` 改一个字（第 20 字之后） | ✅ 变 |
| `role` 改 | ✅ 变 |
| `reference_id` 改 | ✅ 变 |
| `reference_id` 空 → 填 | ✅ 变 |
| `chapter` 改 | ✅ 变 |
| `part` 改 | ✅ 变 |
| `model` 改 `s1` | ✅ 变 |
| `format` 改 `wav` | ✅ 变 |
| `speed` 改 1.2 | ✅ 变 |
| `sample_rate` 改 44100 | ✅ 变 |
| `mp3_bitrate` 改 192 | ✅ 变 |

**没有一维是静默复用的。** 特别是"`text` 改一个字（第 20 字之后）"这一组——
它是专门为"提示词截断到 24 字"那个事故设计的对照测试：
本包的文本维度**整段入 hash，不截断**。

### 3.4 续跑有多省

同一批参数重跑 `voice`：

```
  [1/12] 00001-旁白.mp3 已存在，跳过（断点续跑，不重复扣费）
  ...
- 片段：12 个（跳过 12 个已完成的）
- 实际扣费：0.0 点 ≈ 0.0 元
```

**12 段全跳过、0 次调用、0 点。**

### 3.5 什么时候会重扣（必看）

改**任何一个**上面十一维 → 对应片段重配重扣。实践中会触发的场景：

| 操作 | 会不会重扣 |
|---|---|
| 只改 `--yes` / `--budget` | ❌ 不会 |
| 改 `--sample-chars`（配更多字） | 只重配**新覆盖到的**片段（已配好的 key 没变） |
| 改一角色台词（编辑 `cast.json`） | 该片段重配，其余不动 |
| 换旁白音色 | **旁白的所有片段**重配 |
| 改 `--format` | **所有片段**重配 |
| 改 `--speed` / `--sample-rate` / `--mp3-bitrate` | **所有片段**重配 |
| 改 `--tts-model` | **所有片段**重配 |
| 加 `--force` | **所有片段**重配 |
| 改 `--voice-map` 里某个角色 | 该角色所有片段重配 |

**重跑前先核价**：`cost` 或直接看 `audiobook-state.json` 的 `cost.items`。

## 四、排错表（按现象索引）

### 4.1 配音相关

| 现象 | 原因 | 解法 |
|---|---|---|
| `code=0 任务处理失败` | `reference_id` 不完整 / 不存在 | `run.py voices` 整条复制（32 位十六进制）。去掉 `--narrator-voice` 可区分是音色问题还是文本问题 |
| 音色没生效（用了默认音色） | 参数名写成了 `voice_id` | 必须是 `reference_id`。`schema voice_tts` 现查 |
| 语速没生效 | 写成了顶层 `speed` | 必须是 `prosody.speed`（对象） |
| 音频少了一句 | 单块超过 500 字符被上游截断 | 本包已按 500 字硬拆；若仍出现，检查是否有单句本身超过 500 字 |
| `点数不足（402）` | 余额不够 | 到 https://api.a7w.cn/ 充值 |
| `鉴权失败（401）` | Key 无效 / 过期 | 重新创建 Key，写进 `~/.a7w/config.json` 或 `A7W_API_KEY` |
| 任务一直 pending | 长异步任务的正常态 | 本包轮询到 `data.status` 进终态；`--timeout` 可调 |

### 4.2 字幕相关

| 现象 | 原因 | 解法 |
|---|---|---|
| `stt 没有返回字级时间戳` | `ignore_timestamps` 没传 `False` | 本包已固定传 `False`。出现这条说明上游改了行为，`schema voice_tts` 复查 |
| `有 N 个片段没有 audio_url` | 配音台账里没有 `url` 字段（旧版台账 / 手工造的） | 重跑 `voice` 让它把 `url` 记进台账（**断点续跑会跳过已配好的片段，不会重复扣费**） |
| 字幕文字与原文差几个字 | ASR 回读误差（专有名词尤其明显） | 属上游能力边界。差异逐条在 `subtitle.json` 的 `text_mismatch`；要逐字一致就自行用原文替换 |
| 字幕条太长 / 太碎 | 聚合口径不合口味 | 调 `--chars-per-line` / `--max-seconds`（**这两维在字幕断点 key 里，改了会重做字幕**） |
| 字幕时间轴与音频错位 | 音频被替换过但台账没更新 | 台账的 `sig` 会检测到，重跑 `subtitle` 即可（**会重新扣字幕的钱**，因为音频指纹变了） |

### 4.3 章节与角色相关

| 现象 | 原因 | 解法 |
|---|---|---|
| `一章都没解析出来` | 标题形态不在内置的 5 套里 | `--heading-pattern` 指定；或 `--chunk-blocks` 先跑通 |
| `有 1 章正文为空` | 切分把正文吞进标题行了，或那一章确实是空的 | 看 `chapters.md` 手工修；或换 `--heading-pattern` |
| `有 N 章标题超过 40 字` | 把正文行当成标题了 | 同上 |
| 章节数比实际少很多 | 标题行带句末标点，被规则 3 排除了 | 检查原文的标题行格式 |
| `角色音色不一致` | 同一角色用了不同 `reference_id` | `--voice-map` 统一。**不修就会重配重扣** |
| `分配了音色但全书没出现过的角色` | 角色识别出了冗余项 | 从 `cast.json` 里删掉那个角色，或忽略（但闸门会拦） |
| `有 N 段引号里的话推不出说话人` | 本地启发式的能力边界 | 加 `--llm`；或 `--voice-map` 手工指派 |
| `模型把原文改了` | `--llm` 返回的片段与原文不逐字一致 | **这是设计好的拦截**。重跑一次；或去掉 `--llm` 用本地分词 |

### 4.4 产出与拼接相关

| 现象 | 原因 | 解法 |
|---|---|---|
| `拒绝执行：--outdir 指到了包内` | 产出音频不许进包 | 换 `%TEMP%\audiobook` 或 `D:/book/b01` |
| `本机没有 ffmpeg，音频是 mp3` | mp3 压缩格式不能靠拼字节接起来 | 装 ffmpeg 后原样重跑；或一开始就用 `--format wav` |
| `参数不一致（采样率/声道/位宽）` | 混用了不同参数的 wav | 让 `voice` 统一产出（本包默认统一） |
| `时长台账标了「字数估算」` | 该片段既没字幕时间戳、也不是可解析 wav | 跑 `subtitle` 可拿到精确时长 |
| `读不出这个文本文件的编码` | 试过 utf-8 / gb18030 / big5 / utf-16 | 先用编辑器转成 UTF-8 |

### 4.5 参数与契约相关

| 现象 | 原因 | 解法 |
|---|---|---|
| `报价 X 点已超过 --budget` | 钱还没花就中止了 | 核对 `--chars-per-minute`（它影响报价）或提高预算 |
| `跑前必须报价并确认` | 两个确认开关都没给 | 加 `--yes`，或用 `--budget N` 封顶 |
| `--chars-per-minute 要在 100~500 之间` | 口径越界 | 语速口径的合理区间 |
| `unrecognized arguments` | 参数写错位置 | `--json` 前后都可以；但子命令自己的参数必须在子命令之后 |
| `--json` 输出被表格污染 | 不可能发生 | JSON 走真 stdout，人读表格只在非 `--json` 时打。若真出现，报 bug |

## 五、事故复盘（写这些代码时实际踩到的）

### 5.1 「引号外全归旁白」

第一版本地分词把 `「你好」他说` 里的 `他说` 也算进了对白文本，
于是音频里念出了"他说"两个字。

**修正**：对白文本**只取引号内部**，引号外的字一个不留。
`split_dialogue_local()` 里这一条有注释，别改。

### 5.2 说话人的「极性」

第一版的归属规则是"引号前后最近的 `某某说` 都算"，于是
`「你来晚了。」老人说。「路上堵车。」林砚说。`
里的第二句被判给了**老人**（因为 `老人说` 离它更近）。

**修正**：引号**前**的引导词若以句号结尾（`老人说。`），
说明那句已经讲完了，不能算作**后一句**的说话人。
`_speaker_before()` 的注释里写了这条极性规则。

### 5.3 `章节切分` 的误报

只按「行首 + `第N章`」匹配，会在正文出现「他翻到第一章」时炸出几十个假章节。

**修正**：三重判据（行首 + 标题长度 ≤ 40 + 行尾不带句末标点），
并且要求**至少两个命中**才算"切动"（一个命中可能只是正文提了一次）。

### 5.4 「一个命中」的边界

上面的"至少两个命中"带来一个副作用：一本只有一章的短篇
（或者只有 `楔子` 一个标题的文本）会被判成"未识别到章节标题，整体作为一章"。

**这是有意的取舍**：宁可把它当一章正文（用户可以手工拆），
也不要因为一个假命中把正文切成碎片。产出里会登记
`method = 未识别到章节标题，整体作为一章`，不假装切对了。

### 5.5 `basis` 列的重复爆炸

`join` 的时长台账要标"这一章的时长是怎么来的"。第一版把每个片段的
basis 直接拼起来，于是同一章有 11 个片段时，那一列会变成：

```
stt 时间戳 + 字数估算（**不是真实时长**） + 字数估算（**不是真实时长**） + ...
```

**修正**：按章**去重**后再拼（`_bases` 列表）。
这类问题不影响正确性，但会让产出没法读。

### 5.6 `--json` 与降级状态的 `ok` 字段

`join` 在没有 ffmpeg 且音频是 mp3 时会降级（写清单但不产出合并音频），
退出码 `2`。第一版这时仍然 `_emit(..., ok=True)`，
于是信封里是 `{"ok": true}` 而退出码是 `2`——**两个互相打脸的信号**。

**修正**：降级时 `ok=False`。信封的 `ok` 必须与退出码一致。

### 5.7 PowerShell 吞掉退出码

这不是包的 bug，但会影响你验证它：
`python run.py ... 2>&1 | ...` 之后 `$LASTEXITCODE` 会变成 1（PowerShell 的
native-command 语义），而不是 Python 真实的退出码。

**验证退出码的正确写法**：

```powershell
python -u scripts\run.py join --outdir D:\book\b01 2>$err
$rc = $LASTEXITCODE      # ← 在管道/重定向之前取
```
