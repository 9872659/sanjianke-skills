# 电商合规红线与六道闸门口径

> ⚠️ **本文件与包内所有合规判定，都是启发式自检工具**：按子串 / 正则匹配，
> **不理解语义、不看图片、不做谐音识别**。不构成法律意见，也不代表任何平台的官方审核标准。
> 高风险类目（食品、保健食品、医疗器械、母婴、化妆品、3C 认证）**必须人工复核**。

## 一、广告法违禁词（绝对化用语）

《广告法》第九条禁止使用「国家级」「最高级」「最佳」等用语。电商主图与卖点文案同样适用。

| 类别 | 典型词 | 风险 |
|---|---|---|
| 绝对化用语 | 国家级 / 世界级 / 最高级 / 最佳 / 最优 / 最强 / 最好 / 第一品牌 / 全国第一 / 排名第一 | **高** |
| 「最」字系列 | 最X（低价、便宜、先进、领先…）、全网最低、史上最低 | **高** |
| 绝对化承诺 | 100% / 百分之百 / 绝对有效 / 绝对安全 / 保证正品 / 保证最低 | **高** |
| 虚构权威 | 国家认证 / 免检 / 央视推荐 / 官方推荐 / 权威认证 / 国际认证 | **高** |
| 医疗功效 | 根治 / 治愈 / 药到病除 / 包治 / 特效 / 无副作用 / 抗癌 / 降血压 | **高**（普通商品禁用） |
| 投资承诺 | 稳赚 / 保本 / 保收益 / 零风险 / 躺赚 / 包过 | **高** |
| 排他性 | 首个 / 首创 / 独家 / 唯一 / 填补空白 | 中（需可举证） |
| 站外导流 | 加微信 / 私信我 / 扫码加 / 免费领 | 中（平台普遍限制） |
| 促销时限 | 秒杀 / 抢购 / 最后一天 / 仅限今天 | 中（须与真实活动一致） |
| 成分材质 | 纯天然 / 无添加 / 零添加 / 无毒无害 / 食品级 / 婴儿级 | 中（须与检测报告一致） |

## 二、「最X」的上下文豁免（这是本包与一刀切做法的区别）

中文里「最大」大量出现在**普通比较句**里：「和同类产品**最大**的区别是……」「这个价位里
**最**省事的做法是……」。一刀切拦下来，运营会成天在改根本不违规的句子。

**闸门一旦变成噪音，人就会加 `--allow-prompt-hits` 把它关掉——那时真正该拦的也拦不住了。**
所以本包加一层上下文豁免，但**豁免范围写死在代码里、可枚举、可复核**，不是一句「人工判断」。

两个条件**缺一不可**：

| 条件 | 内容 |
|---|---|
| 1. 后文落在**可枚举**的豁免表里 | `不同 区别 差异 共同 相同 相似 常见 容易 重要 关键 主要 先 后 基本 简单 难 麻烦 省事 常用 合适 适合 保险 稳妥`，加纯程度/比较词（`多 少 大 小 好 差 近 远 快 慢 重 轻 薄 厚 长 短 宽 窄 高 低 贵 便宜`） |
| 2. **不在句首** | 句首的「最大区别是…」经常正是标题式的最高级宣称，**照拦** |

**豁免只允许一个「的」/「了」**。

| 输入 | 结果 | 为什么 |
|---|---|---|
| `它和同类产品最大的区别是重量` | **放行** | 非句首 + 后接「区别」 |
| `最大的区别是它更耐用` | **拦** | **句首**，不豁免 |
| `这是最好的工具` | **拦** | 非句首，但后接「的」+「工具」不在豁免表里 |
| `找出占比最高、且最容易改的那一个环节` | **拦** | **逗号不开豁免**（见下） |

### 为什么不为逗号/顿号开豁免

实测踩到过上面第四句被拦。想放开它只有两条路，**两条都不该走**：

- 往豁免表里加「且」——那是在**自行扩张模板的打分口径**，越走越松；
- 让分隔标点豁免生效——那样「最好的工具，值得买」也会被放行，
  等于给最高级广告语开了一个后门（标点后面跟什么都行）。

所以这是**已知的保守行为**，靠改文案解决（把「最高」换成「比较高」），不靠放松规则解决。

## 三、电商专属：不伪造销量 / 评价 / 资质 / 检测报告

这一组是**电商场景独有的高风险项**，也是本包区别于其他合规扫描器的地方。

| 判据 | 命中的写法（示例） | 为什么拦 |
|---|---|---|
| **不伪造销量** | `销量第一`、`月销10万+`、`已售 50000`、`10万+ 用户已购`、`3000 家庭在用` | 销量必须来自**平台后台真实数据**；主图与文案不得自造 |
| **不伪造评价** | `好评率100%`、`零差评`、`好评如潮`、`全部五星`、`真实评价 2000 条` | 平台规则与广告法都禁止伪造评价或评价率 |
| **不伪造资质** | `权威检测报告`、`国家级认证`、`SGS`、`CMA`、`CNAS`、`专利技术`、`独家配方`、`特供`、`专供` | 必须**真实存在且能出示**证书编号与颁发机构 |
| **不伪造检测结论** | `质检合格`、`检测报告编号：X-2024`、`通过检测认证` | 同上；**本包不生成资质，也不替你编结论** |

### 「可出示的证据」是这道闸门的设计前提

`sellpoints` 的 `--evidence` 参数就是为这条设计的：**只有你写进来的证据才可以被写成证据型文案。**
不填就按「无证据」处理，卖点只能写看得见的外观与规格——**不许**写检测、认证、销量、评价、疗效。

真机实测（本包 v1.0.0）：模型拿到 `--evidence "自有实拍图与拆解视频"` 后，
五张位的「卖点依据」都落在实拍与规格上，没有编造检测报告。这条输入是**便宜的保险**。

⚠️ 但闸门只管**文案**。如果第 5 位资质图没有真实材料，模型仍可能画出一张**看起来像资质的图**。
本包在这种情况下会**明确警告**：「产出的是示意版式、不是资质本身，不许当作资质材料上架」。
**闸门拦不住你自己拿去上架——这一条请当红线记住。**

## 四、六道闸门口径（都是硬拦，不是警告）

| # | 闸门 | 判据 | 触发后 |
|---|---|---|---|
| 1 | 电商合规 | 上文第一~三节 | 拦截、标红、退出码 3（`compliance` 用 1） |
| 2 | 占位符残留 | `{}` / `{{标题}}` / `[待填]` / `[待补充]` / `XXX` / `待补充` / `TODO` / `TBD` | 同上 |
| 3 | `prompt_echo` | 去标点相等 **或** 字符二元组 Jaccard ≥ 0.75 **或** 示例覆盖度 ≥ 0.60 | 同上 |
| 4 | 出图比例真伪 | **读文件头真实像素**，容差 3%（容差内也打印偏差） | 同上 |
| 5 | 主图位完整性 | 五张位缺位 | 同上 |
| 6 | 成本上限 / 产出图落点 | 超 `--budget`；`--outdir` 在包内 | 退出码 3 / 2 |

### 闸门 2 的细节：`[1]` 与 `[图 2]` 不误判

`[1]`（引用序号）、`[图 2]`（配图位）是**正常写法**，
一刀切按括号内容判会把好文案全拦下。所以只匹配 `[待填]` / `[待补充]` 这类**枚举**内容。

### 闸门 3 的细节（照抄示例）

**事故来源**：提示词里写过的示例，哪怕明确标着「这是错的写法」，模型照样照抄——
标题工坊实测那一轮**最高分 89.0 的标题一字不差就是提示词里的示例**，
最高分变成「抄标准答案」，排序就废了。

出图场景更隐蔽：你不会一眼看出这张主图和示例长得一样，而是「看起来挺正常」，
直到发现五张主图是同一个模子。

**为什么必须有第三条判据（覆盖度）**：出图提示词动辄 60~120 字而示例只有 25 字，
Jaccard 的分母是两份二元组的**并集**，示例那一侧被长提示词**摊薄**得极狠。实测：

| 输入 | Jaccard | 覆盖度 | 结果 |
|---|---|---|---|
| 示例原样当作整条提示词 | 1.000 | 1.000 | 拦 |
| 示例原样 + 补 9 个字 | 0.727 | **1.000** | 旧口径放行 ❌ → 新口径拦 ✓ |
| 示例原样嵌进 102 字提示词 | **0.245** | **1.000** | 旧口径放行 ❌ → 新口径拦 ✓ |
| 只改标点 | 1.000 | 1.000 | 拦 |
| 少两个字 | 0.917 | 0.917 | 拦 |
| 同构改写（换一个词） | 0.917 | 0.917 | 拦 |
| 真实业务提示词 A | 0.000 | 0.000 | 放行 |
| 真实业务提示词 B | 0.000 | 0.000 | 放行 |

覆盖度只看「示例被抄了多少」，**不看提示词有多长**，所以摊薄对它无效。

**长度守卫（本包与同族的口径差异，是刻意的）**：同族守卫是 `max(6, len(示例)//2)`
（示例 25 字 → 门槛 12），因为内容平台的出图提示词本来就是 60~120 字。
但**电商主图的**出图提示词惯常只有 30~50 字，沿用门槛 12 会漏掉
「示例原样当作整条提示词」这一最直接的照抄。所以本包收紧成
`min(20, max(6, len(示例)//4))`（示例 25 字 → 门槛 6）。

⚠️ **只改门槛，三条判据的阈值一个都没动**（去标点相等 / 0.75 / 0.60），
且「去标点后完全相同」**不受长度门槛约束**。

### 闸门 5 的细节

五张位缺位 → `images` 默认**拦截**（退出码 3）。
只想出已有图位就加 `--allow-missing-slots`。
第 5 位资质位没有真实材料时**额外警告**（见第三节末）。

## 五、成本与计费口径

| 项 | 实测 |
|---|---|
| `nano_banana` 1K 出图 | **24 点/张** = 0.24 元 |
| 1 元 | 100 点 |
| 提交时冻结 `frozen_points` | 实测 **31.2**（**预冻结，不是最终扣费**） |
| 完成后结算 `usage.points_cost` | **24** |
| 失败 | 全额退回 |
| 2K / 4K | **没有实测单价** → 拒绝估算（退出码 3），要用就自己给 `--points-per-image` |
| 查任务 | **免费** |

**只信 `usage.points_cost`。** 平台的 `pricing_matrix` / `tenant_*` 字段我们验证过**半数不可信**：
`image_human` 字段写 1.5/2/4/8 点/秒、实测 2/3/6/12；`voice_tts/stt` 字段写 30、实扣 40。

`frozen_points` 也**不是**最终扣费：实测冻结 31.2、实扣 24，差 30%。
照 `frozen_points` 做成本控制会高估 30%。

## 六、接口层踩过的坑（与合规无关，但会让你白花钱）

| 坑 | 表现 | 正确做法 |
|---|---|---|
| 成功码判断错 | 明明成功却判成失败 | 网关信封里 **`code == 1`** 才是成功，不是 `0` |
| 状态字段位置错 | 永远读不到状态、一路轮询到超时 | 平台文档写 `data.result.status`，**实测 `status` 在 `data` 顶层** |
| 凭记忆造端点 | 404 | **没有 `/generate` 这个端点**；「文生图」是 `submit` 的 `action=generate` 参数 |
| 参数名写错 | 参数不生效 | 用 `python3 scripts/a7w.py schema nano_banana` **现查** |
| 用 `frozen_points` 对账 | 金额对不上 | 只信 `usage.points_cost` |
