# 各平台主图规格、安全区与详情页拼接

> 规格会变。本文件的口径是**写代码时（2026 年）实查与实测的结果**，
> 上架前请以平台后台当期的要求为准。命令见 `SKILL.md`。

## 一、平台规格速查（`python3 scripts/run.py specs` 会打出这张表）

| preset | 平台 | 主图像素 | 设计比例 | 生成用的 aspect_ratio | 第 1 张白底 |
|---|---|---|---|---|---|
| `taobao` | 淘宝 / 天猫 | 800x800 | 1:1 | `1:1` | **是** |
| `taobao34` | 淘宝 3:4 竖版主图 | 750x1000 | 3:4 | `3:4` | 否 |
| `1688` | 1688 | 800x800 | 1:1 | `1:1` | **是** |
| `pinduoduo` | 拼多多 | 800x800 | 1:1 | `1:1` | **是** |
| `douyin` | 抖音商城 | 1200x1600 | 3:4 | `3:4` | 否 |
| `detail` | 详情页长图 | 750x不限 | 1:3（单屏记录口径） | `3:4` | 否 |

**`design_ratio` 与 `gen_ratio` 是两件事**：前者是平台要求的比例，后者是喂给上游
`nano_banana` 的 `aspect_ratio`。大多数情况两者相同；不同的场景见下节。

## 二、上游「按 32 对齐」这件事（决定了容差为什么是 3%）

`nano_banana` **不是按比例给像素**，而是先定总像素、再把每边向下取整到 **32 的倍数**。
所以 10 种比例里有 5 种给不出像素级精确比例——这**不是网关 bug**，是扩散模型常规做法。

1K 档实测（真实生成，非推算）：

| 请求 aspect_ratio | 实测像素 | 实际数值比例 | 最简标签 | 偏差 |
|---|---|---|---|---|
| `1:1` | 1024x1024 | 1.0000 | 1:1 | **0.00%** |
| `3:4` | 864x1184 | 0.7297 | 27:37 | **2.70%** |
| `4:3` | 1184x864 | 1.3704 | 4:3 | 2.78% |
| `16:9` | 1344x768 | 1.7500 | 7:4 | 1.56% |
| `9:16` | 768x1344 | 0.5714 | 4:7 | 1.59% |
| `21:9` | 1536x672 | 2.2857 | 16:7 | 2.04% |
| `2:3` | 832x1248 | 0.6667 | 2:3 | **0.00%** |
| `3:2` | 1248x832 | 1.5000 | 3:2 | **0.00%** |
| `4:5` | 896x1152 | 0.7778 | 7:9 | 2.78% |
| `5:4` | 1152x896 | 1.2857 | 9:7 | 2.86% |

**含义**：

- 只有 `1:1` / `2:3` / `3:2` 在 1K 档拿得到像素级精确比例；
- 淘宝/1688/拼多多要的 `1:1` **正好精确**，所以白底主图不需要裁；
- 抖音商城的 `3:4` **必然偏 2.70%**，要精确就加 `--snap`。

**默认容差 3%** 就是这么定的：容差内不算「假」，但**真实像素与偏差照样打印出来，不藏**。
超出容差则标红 + 计入闸门失败 + 退出码 3。

**`--snap` 做什么**：按请求比例居中裁剪，裁完**再读一次文件头复核**，只有真裁准的才记合格。
优先用 PIL；没有 PIL 时回落到内置的 8 位 PNG 裁剪器（只用 `zlib` + `struct`）。
两条路都走不通时**如实报告「没能裁」**，不假装成功。实测（真产物）：

```
裁剪前 864x1184（27:37，偏差 2.70%）
裁剪后 864x1152（3:4，偏差 0.00%）   ← PIL 与内置 stdlib-png 得到同一个裁剪框 (0, 16, 864, 1152)
```

⚠️ **像素只能是整数**，所以「裁到精确比例」本身有量化误差（相邻整数像素间隔约 0.27%）。
用户把 `--ratio-tolerance` 调到比这还小时，会把**本来就必须存在**的舍入误差判成不合格。
所以本包有 **0.0025 的容差地板**，仍能抓住真错（请求 3:4 却给 2:3 的偏差是 9.46%，比地板大 37 倍）。

## 三、安全区与压字区

平台会在商品图上叠自己的东西（角标、价格标、店铺标、播放按钮），所以主体不要贴边。

| 平台 | 安全区口径 |
|---|---|
| 淘宝 / 天猫 | 四周各留 **5%~8%**；主体占比 70%~85%；白底主图**不压字** |
| 1688 | 同正方形口径；批发场景可放宽留白，但**信息要放主体之外** |
| 拼多多 | 四周各留 **5%** 以上；价格/规格信息密度高，但别压住主体 |
| 抖音商城 3:4 | **上下各留约 8%**（顶部有商品卡、底部有购买条）；主体居中不压边 |

**压字（后期自己加的文字）**：

- 主图位可压 1 行短文案，**≤ 14 字**，位置放顶部或底部留白区
- 不要压在主体验上
- 压字用本地排版工具做，**不要用 AI 出图生成文字**（AI 出图的文字基本都是错的）

## 四、详情页长图与本地拼接

上游单张出不了长图，所以**按屏出图 + 本地拼接**：

```bash
# 1) 把该屏的产出统一到 750 宽（等比缩放；如需裁切用 crop）
ffmpeg -i screen01.png -vf "scale=750:-2" s01.png

# 2) 依次拼接（纵向）
ffmpeg -i s01.png -i s02.png -i s03.png -filter_complex \
  "[0:v][1:v][2:v]vstack=inputs=3" detail.png

# 屏幕多时用 concat 文本更省事
# 文件里每行 file 's01.png'
ffmpeg -f concat -safe 0 -i screens.txt -vf "scale=750:-2" detail.png
```

**注意事项**：

- 单屏高度不要求严格 3:4，拼接后总高按内容定；但**每屏宽度必须一致**（否则 vstack 会报错）
- `-2` 表示「按比例算高度并对齐到偶数」——偶数高度是视频编码器与多数平台的要求
- 长图很大时（十几屏）注意单文件体积上限，必要时压缩
- 第 7 屏这类**参数表文字屏**用本地排版做，不要 AI 出图

## 五、常见规格坑

| 坑 | 表现 | 怎么避 |
|---|---|---|
| 主图不是正方 | 淘宝/1688/拼多多后台报尺寸不符 | 用 `taobao` / `1688` / `pinduoduo` preset（`1:1`，实测精确） |
| 抖音商城主图偏 2.70% | 上传后位置有轻微偏移 | 加 `--snap` 裁到精确 3:4 |
| 白底位忘了写「纯白」 | 背景是浅灰 | 本包会在 `taobao`/`1688`/`pinduoduo` 的第 1 位**自动补**「纯白背景」 |
| 详情页各屏宽度不一致 | 拼接失败 | 拼接前统一 `scale=750:-2` |
| 把 `4:3` 当 `3:4` 用 | 横竖颠倒 | `aspect_ratio` 是「宽:高」，`3:4` 是竖的 |
| 以为 `21:9` 能出 2.35:1 | 差 2.04% | 上游最宽只到 `21:9`；要精确就 `--snap` |

## 六、别的平台比例怎么办

本包的 preset 表在 `scripts/run.py` 的 `PLATFORMS` 里，是**结构化字典**：

```python
"taobao": {
    "name": "淘宝 / 天猫",
    "main_px": "800x800",
    "design_ratio": "1:1",
    "gen_ratio": "1:1",          # 喂给上游的 aspect_ratio
    "slot1_white_bg": True,      # 第 1 位是否强制纯白背景
    "note": "…",
},
```

要加自己的平台（例如某垂直平台要 750x1000 竖版），
照这个结构加一条即可——`gen_ratio` **必须是** `ASPECT_RATIOS` 里的值
（`auto/1:1/16:9/9:16/4:3/3:4/3:2/2:3/5:4/4:5/21:9`），
平台要求超出这个集合的比例，就选最接近的生成 + `--snap` 裁准。

⚠️ 改 `run.py` 属于改本包代码；`scripts/a7w.py` **不许改**（它按 SHA256 与规范版对齐）。
