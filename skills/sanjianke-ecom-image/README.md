# 三剪客 · 电商主图工厂

给商品信息（标题 / 类目 / 规格 / 卖点 / 商品实物图 URL），**批量产出符合电商平台规格的主图与详情图**：
白底主图 / 场景图 / 卖点图 / 细节图 / 资质图，按平台规格出图（淘宝 800x800、1688、拼多多、
抖音商城 3:4、详情页长图），卖点文案**按主图位分配**，含电商合规自检。

走算力集市 **api.a7w.cn** 的 `nano_banana`，零第三方依赖，成本前置，断点续跑。

## 这个包解决什么问题

运营每天最琐碎的不是「没有图」，而是「**五张主图每张该说什么**」：

- 第 1 张放什么？（利益点——决定点击率）
- 第 2 张放什么？（规格与适用——买家在确认「我能不能用」）
- 资质位拿什么填？（**这张本包不替你画**）

本包把这几件事做成一条可跑的流水线：**先认规格 → 再分卖点 → 最后才花钱出图**，
每一步花不花钱是分开的，这是刻意的。

## 能做什么

| 命令 | 做什么 | 花钱吗 |
|---|---|---|
| `specs` | 列出各平台主图规格、五张主图位的语义、上游实测像素表 | **零网络、零成本** |
| `sellpoints` | 从商品信息提炼卖点并**按主图位分配** | **只花文本钱**（实测一次约 1824 tokens） |
| `images` | 批量出图 | **真花钱**，先报价，要 `--yes` 才提交 |
| `compliance` | 卖点文案合规自检 | **零成本、纯本地** |
| `cost` | 只算钱不出图 | 零成本 |
| `all` | `sellpoints` → `images` 一条龙 | 同上 |
| `models` | 列出在架应用与模型 | 只读 |

| 你最关心 | 答案 |
|---|---|
| 多少钱 | 实测 **24 点/张**（1K）= **0.24 元/张**，1 元 = 100 点 |
| 要多久 | 单张实测 **5~30 秒**完成 |
| 要装什么 | **什么都不用装**，只用 Python 标准库（Python 3.7+） |
| 支持哪些平台 | 淘宝/天猫 800x800、淘宝 3:4、1688、拼多多、抖音商城 3:4、详情页长图 |
| 中断了怎么办 | **断点续跑**：已出完的跳过、已提交未完成的用 `task_id` 续查，不重复扣费 |
| 2K/4K 呢 | **没有实测单价，拒绝凭猜估算**（退出码 3）。要用就自己给 `--points-per-image` |

## 电商主图位（顺序即平台语义）

| 第几张 | slot | 名称 | 任务 |
|---|---|---|---|
| 1 | `main` | 主图 | 利益点：一句话说清「买它解决什么问题」，主体大、留白够；白底平台必须纯白背景 |
| 2 | `spec` | 规格图 | 规格与适用：尺寸/容量/材质/型号 + 适用人群或不适用人群 |
| 3 | `selling` | 卖点图 | 细节与工艺：放大一个可验证的做工细节，配一句证据型文案 |
| 4 | `scene` | 场景图 | 场景与人群：商品在真实使用场景里，让买家代入 |
| 5 | `qualification` | 资质图 | 资质与售后（**用你真实持有的材料**，本包只改版式、不生成内容） |

**为什么卖点要「按位分配」而不是「平均分给几张图」**：电商主图位是**平台固定的语义槽**，
不是一篇文章里的插图位置。买家划到第 2 张想看的是「这东西多大、我能不能用」，
不是又一句利益点。乱塞会把五张图变成五张重复的主图。

## 与同族包的区别（不是「换个比例 + 换个提示词」）

| 维度 | 新媒体配图工厂 | 小红书带货作战包 | **本包** |
|---|---|---|---|
| 输入 | 文稿 / 主题 | 商品名与价格 | **商品信息 + 商品实物图 URL** |
| 输出语义单位 | 文章插图角色 | 文案（笔记/脚本） | **平台固定的主图位** |
| 比例表 | 内容平台封面比例 | 笔记封面 3:4 | **电商平台规格**（800x800 正方白底 / 3:4） |
| 出图能力 | 只用 `generate` | 手工调用 | **`generate` + `edit`**（实物图/资质图改版式） |
| 合规重点 | 广告法违禁词 | 广告法 + 平台规则（只扫文案） | 广告法 + **不伪造销量/评价/资质/检测报告**，且扫文案与提示词 |
| 特有闸门 | 比例、成本、违禁词、照抄示例 | 违禁词四级结论 | 上列之外加 **主图位完整性** |

## 怎么用（命令行）

### 一、配 Key

包里**不内嵌任何密钥**，Key 由你自己提供，三种方式任选一种：

```bash
python3 scripts/a7w.py login --key sk-xxxx     # 验证并写入 ~/.a7w/config.json
export A7W_API_KEY=sk-xxxx                     # Windows: $env:A7W_API_KEY="sk-xxxx"
python3 scripts/run.py specs --key sk-xxxx     # 单次传参
```

Key 到 [算力集市](https://api.a7w.cn/) 注册领取（新用户有赠送点数）。

### 二、先认规格（零网络、零成本）

```bash
python3 scripts/run.py specs
```

会打印每个平台的主图像素与设计比例、五张主图位的语义、
以及上游 1K 档 **10 种比例的真实像素与偏差**（含 3:4 实得 864x1184、偏差 2.70%）。

### 三、提炼卖点并按主图位分配（只花文本钱）

```bash
python3 scripts/run.py sellpoints \
    --product "便携榨汁杯 600ml" --platform taobao \
    --specs "容量600ml，杯身Tritan，刀头304不锈钢可拆洗，USB-C充电" \
    --usp "一杯一袋、单手开盖、可整杯冲洗" \
    --audience "通勤上班族、健身人群" \
    --evidence "自有实拍图与拆解视频" \
    --out plan.json
```

`--evidence` 是**这道流程的关键输入**：只有你写进来的证据才可以被写成证据型文案。
不填就按「无证据」处理，卖点只能写看得见的外观与规格——**不许**写检测、认证、销量、评价、疗效。

### 四、先算钱（不出图）

```bash
python3 scripts/run.py cost --count 5
# 预估成本：5 张 × 24 点 = 120 点 = 1.20 元

python3 scripts/run.py cost --count 5 --budget 100
# 超预算 → 返回退出码 3
```

### 五、出图（真花钱）

```bash
# 先不带 --yes：只报价，一个任务都不提交
python3 scripts/run.py images --plan plan.json --outdir ./out

# 确认了再加 --yes
python3 scripts/run.py images --plan plan.json --outdir ./out --yes --snap \
    --budget 200 --report evidence.json
```

**图片一定要输出到包外**（`./out`、`%TEMP%\...`）。包的上传白名单只收文本文件，
脚本也会拒绝把 `--outdir` 指到包内（退出码 2）。

只想先出两张看看效果：

```bash
python3 scripts/run.py images --plan plan.json --slot main --slot scene \
    --outdir ./out --allow-missing-slots --yes --snap
```

### 六、发布前做合规自检（零成本）

```bash
python3 scripts/run.py compliance --text "全网最低价，销量第一，好评率100%"
python3 scripts/run.py compliance --file plan.json --strict   # CI 卡门禁
```

### 直接用 curl 调（不依赖本包脚本）

出图是**两步异步任务**（**没有 `/generate` 这个端点**，「文生图」是 `submit` 的
`action=generate` 参数）：

```bash
# 算力集市 api.a7w.cn · nano_banana 提交出图（真花钱，1K 约 24 点/张）
curl -sS -X POST "https://api.a7w.cn/api/v1/apps/nano_banana/submit" \
  -H "Authorization: Bearer $A7W_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "prompt": "纯白背景，一只透明便携榨汁杯放正中央，柔光棚拍，正面平视，浅景深，无文字",
    "action": "generate",
    "model": "nano-banana",
    "resolution": "1K",
    "aspect_ratio": "1:1"
  }'

# 拿 data.task_id 去轮询（⚠️ status 在 data 顶层，不在 data.result）
curl -sS "https://api.a7w.cn/api/v1/tasks/task_xxxxxxxxxxxx" \
  -H "Authorization: Bearer $A7W_API_KEY"
```

出方案那一步走的是 OpenAI 兼容的 `POST /api/v1/chat/completions`。

|---|---|
| `--key` | 临时指定 Key；优先级最高。**别把它写进脚本或文档** |
| `--json` | 以 JSON 输出，**写在子命令前面或后面都可以**；JSON 模式下 stdout 只有一个完整 JSON |

### `specs`

| 参数 | 说明 |
|---|---|
| `--platform` | 只看某平台，可重复：`taobao` / `taobao34` / `1688` / `pinduoduo` / `douyin` / `detail` |

### `sellpoints`

| 参数 | 说明 |
|---|---|
| `--product` | **必填**。商品标题 |
| `--platform` | 目标平台，可重复，默认 `taobao` |
| `--specs` / `--usp` / `--audience` / `--price` | 规格参数 / 已知卖点 / 目标人群 / 售价 |
| `--evidence` | **可出示的证据**；不填按「无证据」处理 |
| `--product-image` | 商品实物图 URL（资质位走 `action=edit` 时用） |
| `--no-edit` | 禁止 `action=edit`，全部用 `generate` |
| `--resolution` | 出图分辨率，默认 `1K` |
| `--out` | 把方案写成 JSON，`images` 要用它 |
| `--dry-run` | 只打印将发送的提示词，**不调模型、不花钱** |

### `images`

| 参数 | 说明 |
|---|---|
| `--plan` | `sellpoints` 产出的方案 JSON；不给就用 `--product` 现出方案 |
| `--slot` | 只出某几个图位，可重复：`main`/`spec`/`selling`/`scene`/`qualification` |
| `--platform` / `--count` | 平台过滤 / 最多出几张 |
| `--resolution` | 覆盖分辨率；**写进断点 key**（1K/2K/4K 是三个不同断点） |
| `--image-model` | 出图模型，默认 `nano-banana`；**也写进断点 key** |
| `--outdir` | 图片输出目录，默认 `%TEMP%\ecom-image-out`；**不可是包内目录** |
| `--budget` | 成本上限（**点**）。预估超了直接停；每次提交前还会再核一次 |
| `--yes` | 确认真的花钱。**不加就只报价、一个任务都不提交** |
| `--snap` | 出图后按比例精确裁剪（上游按 32 对齐） |
| `--snap-on-design` | 按平台设计比例裁（`--snap` 时默认就按设计比例） |
| `--ratio-tolerance` | 比例容差，默认 `0.03`；有 0.0025 的量化地板 |
| `--poll-timeout` | 单张轮询超时秒数，默认 `600`（**上限，不是期望时长**） |
| `--max-seconds` | 整批最长耗时，到点中断（退出码 5，可续跑） |
| `--state` | 断点文件路径，默认 `<outdir>/ecom-image-state.json` |
| `--force` | 忽略断点全部重出（**会重复扣费**） |
| `--allow-prompt-hits` | 即使文案命中闸门也出图（默认**拦截**） |
| `--allow-missing-slots` | 主图位不齐也照出（默认**拦截**） |
| `--stop-on-error` | 一张失败就整体停 |
| `--report` | 把本次证据（请求参数 / 任务原文 / 真实像素）写成 JSON |

| 参数 | 说明 |
|---|---|
| `--text` | 待检文案，可重复 |
| `--file` | 待检文案文件 |
| `--strict` | 非 `pass` 结论一律退出码 1（CI 卡门禁） |

### `cost`

| 参数 | 说明 |
|---|---|
| `--count` | **必填**。要出几张 |
| `--resolution` | `1K`（默认）/ `2K` / `4K` |
| `--points-per-image` | 覆盖单张单价（点）。**2K/4K 必须给** |
| `--budget` | 预算上限（点），超了退出码 3 |

## 六道本地硬闸门

都是**拦截 + 标红 + stderr 汇总 + 非 0 退出码**，不是「提示一下」。因为出图是按次扣费的。

| # | 闸门 | 口径 | 退出码 |
|---|---|---|---|
| 1 | **电商合规** | 广告法违禁词（最/第一/国家级/100%）+ 不伪造销量/评价/资质/检测报告；「最X」有**可枚举的上下文豁免 + 句首不豁免** | 3（`compliance` 专用 1） |
| 2 | **占位符残留** | `{}` / `[待填]` / `XXX` / `待补充` | 3 |
| 3 | **`prompt_echo`** | 去标点相等 / Jaccard ≥ 0.75 / 覆盖度 ≥ 0.60 + 相对长度守卫 | 3 |
| 4 | **出图比例真伪** | **读文件头真实像素**，不信自报字段；容差 3%，容差内也打印偏差；`--snap` 裁准 | 3 |
| 5 | **主图位完整性** | 五张位缺位标红；资质位没真实材料时明确警告 | 3 |
| 6 | **成本上限** | 提交前先算总价；每次提交前再核一次；2K/4K 无实测单价拒绝估算；产出图不许进包 | 3 / 2 |

**关于「最X」的豁免**：电商文案里「最好」「最强」照拦没错，但中文里「最大」也大量出现在
**普通比较句**里（「和同类产品最大的区别是……」）。一刀切会让闸门变成噪音，
而**闸门一旦变成噪音，人就会加 `--allow-prompt-hits` 把它关掉，那时真正该拦的也拦不住了**。
所以：后文落在**可枚举**豁免表里、**且不在句首**，才放行。豁免只允许一个「的」/「了」，
逗号顿号不开豁免——「最好的工具，值得买」照样拦。

**关于 `prompt_echo` 的第三条判据**：出图提示词动辄 60~120 字而示例只有 25 字，
Jaccard 的分母是并集，示例那一侧被摊薄得极狠。实测「示例原样嵌进 102 字提示词」
Jaccard 只有 0.245（会被漏掉），但**覆盖度是 1.000**（抓住）。覆盖度只看示例被抄了多少。

## 排错

| 现象 / 报错 | 原因 | 怎么办 |
|---|---|---|
| `鉴权失败（401）` | Key 无效、过期或写错 | 到 https://api.a7w.cn/ 重新领取 |
| 点数不足（HTTP 402） | 账号点数用完 | 到 https://api.a7w.cn/ 充值后重试 |
| `code: 0` 但 HTTP 是 200 | **`code == 1` 才是成功，不是 0** | 看 body 里的 `msg`；别把判断改成 `code == 0` |
| 轮询一直读不到状态 | 平台文档写 `data.result.status`，**实测 status 在 `data` 顶层** | 本包已按实测结构取 |
| `当前请求未命中可用计费规格` | `model` 与 `resolution` 组合不支持 | 普通 `nano-banana` 只支持 `1K`；要高清换 `nano-banana-2:official` 之类 |
| 上游 `502` / `upstream timeout` / `Remote end closed` | 网关到上游的瞬时抖动，**实测很频繁**（真机 2 张遇到 1 次） | 已内置退避重试（4 次）；连续失败就降低批次 |
| 真实像素和请求比例差 1%~3% | **上游按 32 对齐**，不是 bug | 加 `--snap` 精确裁；或放宽 `--ratio-tolerance` |
| `预估 N 点超过预算上限` | 超了 `--budget` | 提高预算、减少张数，或先 `cost` 试算 |
| `2K 档没有实测单价，拒绝凭猜估算` | 我们没有 2K/4K 的实测价 | 给 `--points-per-image`，或先用 1K |
| `输出目录 ... 在 Skill 包内` | `--outdir` 指到了包里的目录 | 换到包外（包内放图片会让上传 400） |
| `主图位缺位 ...` | 方案少了必填图位 | 补位后重跑；只想出已有图位就加 `--allow-missing-slots` |
| 资质位产出的是「示意版式」 | 没提供真实资质图 | 本包**不生成资质**；请提供你真实持有的资质图，**不要拿示意图上架** |
| 重跑又扣了一次钱 | 提示词/分辨率/模型/比例/参考图改了 → 断点 key 变了 | 设计如此（否则会**静默复用旧图**）。想省钱就别改，直接重跑即可跳过 |
| `没有找到 API Key` | 三种方式都没配 | `--key` / `A7W_API_KEY` / `a7w.py login` |
| Windows 下中文乱码 | 控制台代码页不是 UTF-8 | 先 `chcp 65001`，或设 `PYTHONIOENCODING=utf-8` |

**收集排错信息时请附上**：完整命令、`--report` 产出的证据 JSON、原始报错文本。
**不要在报错信息或截图里带上你的 API Key。**

### 退出码

| 退出码 | 含义 |
|---|---|
| `0` | 全部成功且闸门全绿 |
| `1` | 合规自检未通过（`compliance` 的 `blocked`，或 `--strict` 下非 pass） |
| `2` | 调用失败（网络 / 鉴权 / 点数 / 模型名 / 输出目录不合法 / 方案文件读不动） |
| `3` | **闸门拦下**：比例不符、超预算、违禁词、占位符、照抄示例、主图位缺位、无实测单价 |
| `4` | 需要 `--yes` 确认（还没花钱，也没提交） |
| `5` | 达到 `--max-seconds` 上限中断（可续跑） |
| `130` | 用户中断（Ctrl+C） |

## 已知边界（不藏）

- **白底图的「纯白」是设计要求，不是自动判定**。本包会把「纯白背景」写进提示词、
  白底位缺这句时自动补上，但**不会检测产出图的背景像素是否真的纯白**——仍需人工看一眼。
- **详情页长图不直接生成**。上游单张出不了长图，本包按屏出图（单屏 3:4），
  拼接在本地做，命令见 `references/platform-specs.md`。
- **不生成资质**。第 5 位只改你真实持有材料的版式。
- **AI 出图的文字基本都是错的**，所以一律要求「不要在图上生成文字」，压图文字后期自己加。
- 合规闸门是**启发式自检工具**，按子串/正则匹配，不理解语义、不看图片、不做谐音识别。

| 提交时冻结 | 实测 `frozen_points = 31.2`（**预冻结，不是最终扣费**） |

| 失败 | 全额退回 |
| `sellpoints` 出方案 | 纯文本钱，实测一次 1824 tokens |

**只信 `usage.points_cost`。** 平台的 `pricing_matrix` / `tenant_*` 字段我们验证过**半数不可信**：
`image_human` 字段写 1.5/2/4/8 点/秒、实测 2/3/6/12；`voice_tts/stt` 字段写 30、实扣 40。
