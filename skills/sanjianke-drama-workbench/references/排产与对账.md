# 排产与对账

工作台跑起来之后，真正的瓶颈不是「会不会调接口」，而是
**多项目并行时怎么不乱、断了怎么续、钱花在哪怎么看得见**。

---

## 一、目录与任务表约定

```
proj/
├── <项目A>/
│   ├── 01-图片/       shot01.png …
│   ├── 02-台词/       shot01.mp3 …
│   ├── 03-片段/       shot01.mp4 …
│   ├── 04-口型/       shot01-lip.mp4 …
│   ├── 05-音乐/       bgm.mp3 / sfx/ …
│   ├── 06-成片/       ep01.mp4 …
│   └── tasks.csv      ← 命根子
└── <项目B>/ …
```

`tasks.csv` 字段：

| 字段 | 说明 |
|---|---|
| `shot_id` | 与分镜表一一对应 |
| `stage` | 工序：`image` / `dub` / `video` / `lip` / `sfx` / `bgm` / `upscale` |
| `app` | 应用代号，用来按应用汇总成本 |
| `api` | 接口代号 |
| `task_id` | 平台任务 ID，**用去重与续跑** |
| `status` | `pending` / `completed` / `failed` |
| `points` | 实际扣点，用对账 |
| `input_url` | 该步的输入，便于复现 |
| `output_url` | 该步的产出，下一步直接用 |
| `updated_at` | 时间戳 |

---

## 二、断点续跑规则

```
1. 提交前先读 tasks.csv，跳过 status == completed 的 (shot_id, stage)
2. 提交后立刻追加一行 status=pending 并写入 task_id
3. 收到终态后把该行更新为 completed / failed，并回填 points 与 output_url
4. 重跑只处理 failed 与 pending
```

**为什么必须这样做**：长链路一定会断（断网、进程挂了、队列超时）。
没有任务表，一次中断就要么漏做、要么重做一遍多花钱。

**重提之前先查状态**：`pending` 的行先用 `task_id` 查一次，
确认是真的失败再重提 —— 网络超时里的任务可能已经成功了。

---

## 三、并发怎么定

| 阶段 | 建议并发 | 说明 |
|---|---|---|
| 出图 | 4～8 路 | 单张便宜、耗时短，可以高一些 |
| 视频生成 | **2～4 路** | 最贵最慢；`429` 说明排队上限到了 |
| 配音 | 4～8 路 | 音频短，吞吐高 |
| 口型 | 2～4 路 | 依赖视频，通常跟着视频节奏走 |
| 超分 | 2 路 | 吃带宽，别和视频生成抢 |

**判断并发是否过高**：出现 `429 queue_limit_exceeded`，或失败率明显上升。
并发越高不一定越快 —— 排队 + 重试可能比低并发更慢更贵。

## 四、按应用对账

```powershell
# 本项目各应用的扣点汇总
Import-Csv proj/ep01/tasks.csv | Group-Object app |
  ForEach-Object {
    "{0,-22} {1,10:N0} 点  {2,8:N2} 元" -f $_.Name,
      (($_.Group | Measure-Object points -Sum).Sum),
      ((($_.Group | Measure-Object points -Sum).Sum) / 100)
  }
```

```bash
# 失败的任务有哪些
python3 -c "
import csv
for r in csv.DictReader(open('proj/ep01/tasks.csv', encoding='utf-8')):
    if r['status'] != 'completed':
        print(r['shot_id'], r['stage'], r['app'], r['status'])
"
```

**四笔账分开记**：

| 账 | 来源 |
|---|---|
| 生成类（图 / 视频 / 口型 / 超分） | `tasks.csv` 按 `app` 汇总 |
| 语音类（配音 / 克隆 / 音色） | 同上，`app=voice_tts` |
| 音乐类（BGM / 搜曲 / 音效） | 同上，`app` 为音乐类 |
| 突发（重试 / 废片） | `points` 与预估的差额 |

**对账口径**：每次调用返回的 `data.usage.points_cost` 是本次真实扣费；
任务级用量在 `GET /api/v1/tasks/{task_id}` 的 `usage` 字段；
账号级流水在用户中心。

> 平台同时给出**标准价**（`fixed_price` / `input_price`）与
> **租户实际结算价**（`tenant_*`）。**做预算一律用 `tenant_*`，最终以实际扣费为准。**

## 五、多项目并行的三条纪律

| 纪律 | 做法 | 为什么 |
|---|---|---|
| **画幅 / 分辨率全项目锁死** | 开工就把 `9:16` + 目标分辨率写进所有调用 | 中途换尺寸，最后拼接一定要重裁 |
| **一个项目一张任务表** | 不要几个项目共用一个 `tasks.csv` | 混在一起就无法按项目对账 |
| **给 Key 设消费上限** | 批量前把 quota 设成预算的 1.2 倍 | 参数写错时能止损 |

## 六、成片抽检清单

每集出完立刻抽查（不要等全剧跑完）：

- [ ] **缺镜**：分镜表里的每个 `shot_id` 都在成片里有对应片段
- [ ] **口型**：有台词的镜头口型同步，无音画错位
- [ ] **画幅**：全片比例一致，没有黑边或拉伸
- [ ] **音量**：台词清晰；BGM 不盖过台词；无爆音
- [ ] **时长**：每段与分镜表一致，总时长符合投放要求
- [ ] **衔接**：相邻片段之间有过渡，没有明显「跳」
- [ ] **标识**：需要 AI 生成标识的渠道，确认标识已加

## 七、批量脚本骨架（续跑版）

```python
import csv, json, os, time, urllib.request

HOST = "https://api.a7w.cn"
KEY = os.environ["A7W_API_KEY"]
CSV = "proj/ep01/tasks.csv"
FIELDS = ["shot_id", "stage", "app", "api", "task_id", "status",
          "points", "input_url", "output_url", "updated_at"]


def rows():
    if not os.path.isfile(CSV):
        return []
    with open(CSV, encoding="utf-8") as f:
        return list(csv.DictReader(f))


def write_all(rs):
    with open(CSV, "w", newline="", encoding="utf-8") as f:
        w = csv.DictWriter(f, fieldnames=FIELDS)
        w.writeheader()
        w.writerows(rs)


def done(rs, shot_id, stage):
    return any(r["shot_id"] == shot_id and r["stage"] == stage
               and r["status"] == "completed" for r in rs)


def post(app, api, body):
    req = urllib.request.Request(
        "%s/api/v1/apps/%s/%s" % (HOST, app, api),
        data=json.dumps(body, ensure_ascii=False).encode(), method="POST",
        headers={"Authorization": "Bearer " + KEY, "Content-Type": "application/json"})
    with urllib.request.urlopen(req, timeout=300) as r:
        d = json.load(r)
    if d.get("code") not in (1, 200):
        raise RuntimeError(d.get("msg"))
    return d.get("data") or {}


def task(task_id):
    req = urllib.request.Request("%s/api/v1/tasks/%s" % (HOST, task_id),
                                 headers={"Authorization": "Bearer " + KEY})
    with urllib.request.urlopen(req, timeout=120) as r:
        return json.load(r)


def run(stage, app, api, body_for, shots):
    """按阶段批量跑；已完成的自动跳过。"""
    rs = rows()
    for shot_id in shots:
        if done(rs, shot_id, stage):
            print("skip", shot_id, stage)
            continue
        data = post(app, api, body_for(shot_id))
        tid = data.get("task_id")
        rs.append({"shot_id": shot_id, "stage": stage, "app": app, "api": api,
                   "task_id": tid, "status": "pending", "points": "",
                   "input_url": "", "output_url": "",
                   "updated_at": time.strftime("%Y-%m-%dT%H:%M:%S")})
        write_all(rs)
        # 轮询到终态后回填（此处略，按需实现）
```

**要点**：每提交一个就落盘一次，进程挂了也能从 `tasks.csv` 续上。
