# 三剪客 · AI 短视频自动化生产框架

> ## ⚠️ 先申请你自己的 API Key
>
> **本 Skill 不内嵌任何密钥，也不代付费用。** 请到
> **[算力集市 api.a7w.cn](https://api.a7w.cn/)** 注册并创建**你自己的** API Key
> （新用户有赠送点数，可以先免费试跑几条）。
>
> 拿到后填进环境变量 `A7W_API_KEY`，或直接传给 `--key` 参数。
> **请勿使用他人提供的 Key** —— 用量与费用都记在 Key 所属账号上。


做矩阵号或批量口播内容时，真正耗时间的不是创意，而是「脚本 → 配音 → 找素材 → 上字幕 → 渲染」这条链上反复的手工搬运。ShortGPT 把这条链收进一个框架：给主题，它负责生成脚本、合成配音、从素材站检索画面、对齐字幕，最后渲染成片。

它同时提供**短视频、长视频、整片翻译配音**三类引擎，以及一套面向大模型的剪辑标记语言（用 JSON 描述剪辑块），所以它不只是个成品工具，也能当自动化剪辑的底座来用。

**上游项目**：`ShortGPT`　**仓库**：https://github.com/RayVentura/ShortGPT

## 零安装用法（推荐先看这个）

**不需要 Docker、不需要 Colab、不需要备三类外部服务的密钥。** 本 Skill 自带一个
只用 Python 标准库的脚本，主题直接送到 `api.a7w.cn` 出片：

```bash
python3 scripts/run.py "一只金毛犬在海边奔跑，夕阳西下" --out dog.mp4
python3 scripts/run.py "城市清晨延时，镜头缓慢推进" --ratio 9:16 --duration 5 --out v.mp4
python3 scripts/run.py "产品展示：白色耳机悬浮旋转" --res 1080P --out product.mp4
```

可选参数：`--out`（保存路径）、`--ratio`（16:9 / 9:16 / 1:1 / 4:3 / 3:4 / adaptive）、
`--duration`（4~15 秒整数，默认 4）、`--res`（480P / 768P / 1080P / 2K / 4K，默认 480P）、
`--watermark`（加 AIGC 生成标识）、`--task-id`（见下）。

**视频任务又慢又贵，脚本为此做了两件事**：

```bash
# 断线 / 关掉终端后，把已提交的任务接着取回来，不会重复扣费
python3 scripts/run.py --task-id task_xxxxxxxx --out v.mp4
```

- 提交后脚本自己轮询，**查询遇到网络抖动会自动重试**，不会因为一次连接被重置就丢掉任务；
- 万一还是断了，用 `--task-id` 接着取即可，**不要重新提交**（重新提交会再扣一次费）。

**第一次要配 Key**（三种方式任选一种）：

```bash
python3 scripts/run.py "主题" --key sk-xxxx     # 临时指定
export A7W_API_KEY=sk-xxxx                      # 环境变量
# 或到 https://api.a7w.cn/ 注册领取 Key，写入 ~/.a7w/config.json
```

> 走平台 `full_video/submit` 接口（异步任务，脚本自动轮询到出片再下载）。
> **按「分辨率 × 秒数」计量，视频比图片贵得多**：先用 480P / 4 秒试通再放大，
> 以平台实时价为准。

**零安装版到底覆盖了原项目流水线的哪一段（务必先看）**

ShortGPT 原项目的链路是「自动写稿 → 配音 → 素材检索匹配 → 字幕对齐 → 渲染成片」。
平台**只覆盖最后一段「生成视频」**，而且要你自己把提示词写好：

| 原项目环节 | 零安装版 | 说明 |
|---|---|---|
| 自动写稿（脚本生成） | ❌ 不覆盖 | 平台没有文案 / 脚本生成接口，提示词要自己给 |
| 配音（TTS） | ❌ 不覆盖 | 平台有独立的 `voice_tts` 接口，但不在这条流水线里，需另行调用 |
| 素材检索匹配 | ❌ 不覆盖 | 平台不检索素材站；这里是**直接生成画面**，不是拼现成素材 |
| 字幕生成与烧入 | ❌ 不覆盖 | 出的是无字幕的裸视频，字幕要自己加 |
| 整片翻译配音 | ❌ 不覆盖 | 平台没有翻译接口 |
| 渲染成片 | ✅ 覆盖 | 文本 → 一段 4~15 秒的成片，这是零安装版提供的全部能力 |

也就是说：**它是「文生视频」，不是「一键出短视频」**。要完整流水线，可用这里的出片
结果作素材，再回到下面传统装法的 ShortGPT 里做后续拼接。

**什么时候才需要看下面的传统装法**：要多语言整片翻译配音、要自动检索真实素材、
要平台元数据生成、要把写稿到渲染整条链自动化时。

## 什么时候用 / 不用

**用它**：

- 用户说「给我批量做短视频 / 口播视频」，且愿意接受自动化产出的脚本与素材匹配质量。
- 需要把**已有视频翻译配音**成另一种语言，并保留字幕与画面节奏。
- 要搭一条**可配置的内容流水线**：主题进去，成片出来，中间环节可替换模型与素材源。
- 想把「脚本生成 + 配音 + 素材检索 + 渲染」当成一个整体来复用，而不是每次手写胶水代码。
- 手上有 API Key 预算，接受脚本生成、配音、素材检索都走外部服务。

**不要用它**：

- **对成片质感和镜头语言有要求**。它是自动化拼接，不是人工剪辑的替代品。
- **不想申请任何第三方密钥**。脚本生成、素材检索、配音这三块都依赖外部服务，无密钥基本跑不动。
- **只能用 CPU、没有 Docker、也不打算用 Colab**。它的图像与音频依赖很重，本地从零装环境成本高。
- **要精细控制每一帧、每一处转场**。它给你的是块级编辑语言，不是时间线级精修。
- **要商用级版权确定性**。素材来自公开素材站与图片搜索，商用授权与平台条款需要你自己逐项确认。
- **要把它当稳定的生产服务**。它更像实验性框架，上游文档明确说更多文档还在补。

## 常用操作

**1. 起网页界面（本地）**

```bash
python runShortGPT.py
# 界面地址：http://localhost:31415
```

界面分三块：内容自动化（短视频 / 长视频 / 多语言配音）、素材库、配置。内容自动化区先选任务类型，再填主题或素材等参数。

**2. 起网页界面（Colab）**

```bash
python runShortGPTColab.py
```

Colab 环境下界面会以可分享链接形式暴露，方便在浏览器里操作。

**3. 用 Docker 带密钥启动**

```bash
docker run -p 31415:31415 --env-file .env short_gpt_docker:latest
```

密钥通过 `--env-file` 注入，不要写进镜像或代码里。

**4. 在界面里配置密钥与素材**

界面有独立的配置页与素材库页。密钥既可以在 `.env` 里准备，也可以通过界面的配置入口填写；素材库用来管理本地素材，供剪辑时调用。

**5. 按任务选引擎（框架层）**

框架按用途分成四块，选错引擎比参数调错更浪费时间：

| 引擎 | 适用任务 |
|---|---|
| `ContentShortEngine` | 短内容：从脚本生成到成片渲染，包含平台元数据生成 |
| `ContentVideoEngine` | 长视频：生成音频、自动检索背景画面、字幕时间对齐、背景素材准备 |
| `ContentTranslationEngine` | 整片配音翻译：输入视频文件或链接，转写、翻译、用目标语言配音、加字幕，输出另一种语言的新视频 |
| `EditingEngine` | 自动化剪辑底座：用编辑标记语言与 JSON 把剪辑拆成可配置、可被大模型理解的块 |

这几个类在仓库的引擎目录下，具体构造参数与调用签名请直接读仓库内对应模块（以仓库当前代码为准），不要在没看过源码的情况下照搬参数。

**6. 批量出片的思路**

跑通一条之后再走批量：把主题、语言、配音音色、水印等做成可替换的输入，逐条调同一套引擎，中间产物（脚本、配音、素材、字幕）分别落盘，便于单环节返工而不必整条重跑。

## 常见坑

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 启动报缺少 API Key 或调用直接返回鉴权错误 | 脚本生成、配音、素材检索分别依赖不同的外部服务，缺任何一个都会在对应环节失败 | 按 `SKILL.md` 里的 `.env` 示例补全密钥，并确认 `docker run` 带了 `--env-file .env` |
| 按文档填的密钥变量名和代码里读的不一致 | 仓库的配置模块实际读取的变量名与 README 示例并不完全对齐，配音服务还另有单独的用户名/密钥变量 | 以仓库配置模块里实际读取的环境变量名为准，先跑一次启动自检，看哪个环节报缺密钥就补哪个 |
| 本地从零装完还是跑不起来 | 上游对 Python 版本、ffmpeg 版本、语音转写依赖有明确要求，版本不匹配会在导入或渲染阶段炸 | 对齐上游安装说明给出的组合；实在折腾不动就换 Docker 或 Colab |
| 用 `pip install` 装完导入报缺模块 | PyPI 包的依赖清单与仓库 `requirements.txt` 不完全一致，且包内子模块不会在导入顶层包时自动加载 | 改用 Docker / Colab；或按仓库 `requirements.txt` 补齐缺失依赖，并显式导入需要的子模块 |
| ffmpeg 报找不到动态库 | 自编译 ffmpeg 后动态链接库路径没进环境 | 按上游说明把库路径写入 shell 配置并重新加载，或改用系统包管理器安装的 ffmpeg |
| 渲染特别慢或内存吃满 | 图像与音视频依赖很重，容器/机器资源不足 | 给容器更多内存与 CPU；长视频先切段做；Colab 上注意运行时会话时长限制 |
| 素材检索结果与主题不相关 | 素材来自公开素材站与图片搜索，检索质量取决于关键词与外部服务 | 把主题描述写得更具体；或先在素材库里准备好本地素材再走剪辑 |
| 出片看起来像机械拼接 | 这是自动化流水线的固有形态：块级拼接、素材一刀切 | 把成片当粗剪，用它省下搬运时间，人再做精修；对质感有硬要求的任务别用它 |
| 处理别人视频做翻译配音 | 涉及原始内容的版权与声音权益 | 只在获得授权或自有素材上使用；产出物对外发布前自行确认授权范围 |

## 能力边界

**覆盖**：

- 脚本与提示词的自动化生成（面向多种自动剪辑流程的现成模板）。
- 语音合成配音：支持多种语言，多语言覆盖依靠免费的语音合成通道可扩展到相当多的语种。
- 自动生成并烧入视频字幕。
- 素材检索：从网络与素材站拉取图片和视频画面。
- 长视频处理：音频生成、背景画面自动检索、字幕时间对齐。
- 整片配音翻译：转写 → 翻译 → 目标语言配音 → 加字幕 → 输出新视频。
- 块级自动化剪辑：用编辑标记语言与 JSON 描述剪辑，便于大模型理解与生成。
- 可配置项：语言、水印等。
- 变量持久化：用本地嵌入式数据库保存自动化剪辑过程的中间变量。
- 使用形态：Docker 容器、Colab notebook、本地网页界面。

**不覆盖**：

- 不是人工剪辑软件，不做时间线级精修。
- 不做真人出镜、数字人、口型驱动。
- 不保证素材的商用授权；素材来源是公开素材站与图片搜索。
- 不做视频超分、去背景、去水印这类画面修复。
- 不提供稳定的对外 API 契约（它的形态是网页界面 + 框架库，更多文档上游仍在补）。
- 不包含任何模型权重，全部能力依赖外部服务。

### 零安装版（走 `api.a7w.cn`）的边界

**覆盖**：

- 文生视频：给一段主题 / 画面提示词，出一段 4~15 秒、480P~4K 的成片。
- 可选画幅比例、时长、分辨率与 AIGC 生成标识。

**不覆盖**——原项目那条流水线里，平台**只覆盖「视频生成」这一段**：

- **自动写稿**：平台没有文案 / 脚本生成接口，提示词必须由使用者自己给。
- **配音**：平台有独立的 `voice_tts` 接口，但它是另一个应用，不在这条出片链路里，要另行调用。
- **素材检索匹配**：平台不检索素材站与图片搜索；这里是**按提示词直接生成画面**，
  不是从现成素材里挑片段拼接。
- **字幕生成与烧入**：出的是无字幕的裸视频。
- **整片翻译配音**：平台没有翻译接口，也没有「转写 → 翻译 → 目标语言配音」这条链。
- **块级剪辑标记语言 / EditingEngine**：没有对应的编辑语言或 JSON 剪辑块接口。
- 网页界面、素材库、变量持久化这些框架层能力：零安装版只有命令行脚本。

## 依赖条件

- Docker（推荐路线）或可用的 Colab 环境。
- 本地路线需要上游指定版本的 Python、ffmpeg 与较新的语音转写依赖；具体版本以仓库安装说明为准。
- 三类外部服务的密钥：脚本生成、语音合成、素材检索；另需为翻译配音准备对应的语音服务配置。
- 网络可访问上述服务。
- 足够的磁盘与内存：素材下载与视频渲染都很吃资源。
- 本地或容器形态会监听 31415 端口。
