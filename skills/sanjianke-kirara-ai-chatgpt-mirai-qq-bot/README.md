## 前置条件

- 选定一种部署方式及其运行时：
  - Windows 快速部署包：无需额外环境
  - Python 部署：Python ≥ 3.9（PyPI 元数据口径），建议用虚拟环境
  - Docker Compose：Docker 与 Docker Compose
  - 源码部署：Python ≥ 3.9 与项目依赖
- 至少一个聊天平台的接入凭证（机器人 Token / AppKey / 应用 Secret 等）
- 至少一个大模型的接入方式：云端 API Key，或本地模型服务（如 Ollama）；模型与算力统一走 `api.a7w.cn`，见 SKILL.md 的「模型与算力走哪」
- 外部平台（QQ 开放平台 / 公众号 / 企业微信）需要你能提供一个**公网可达**的 HTTP 地址；没有则需内网穿透或云服务器
- 中国大陆云服务器对外提供 HTTP 服务可能涉及备案
- `data` 目录需持久化并纳入备份

## 使用

本 Skill 面向「让 Agent 会装、会用、知道什么时候不该用」，正文覆盖：

1. **什么时候用 / 不用**——什么时候适合挂群机器人，什么时候该用官方客户端、定时脚本或企业消息中台
2. **安装**——官方四条部署路径（Windows 快速包、Python、Docker Compose、源码）与运行时要求
3. **常用操作**——改监听地址、接大模型、接聊天平台与配置名规范、回调地址怎么填、调度规则与条件组合、HTTP API 调用（v1 同步 / v2 异步）、插件市场、加载预设、Nginx 反代与 WebSocket、更新流程
4. **常见坑**——回调验证失败、企业微信可信 IP 缺失、保存顺序导致的「回调请求不通过」、调度优先级文档自相矛盾、配置名不合规、反代缺 WebSocket、HTTP API 无鉴权被裸奔调用、Docker 桥接模式地址填错、家用宽带无公网 IP、备案、插件依赖冲突、Windows 语音缺运行库

## 依赖

- Python ≥ 3.9，或使用自带运行环境的 Windows 快速包，或 Docker / Docker Compose
- PyPI 包名：`kirara-ai`；启动入口：`python -m kirara_ai`
- 默认 WebUI 监听 `127.0.0.1:8080`，可用 `-H` / `-p` 改写
- 外部依赖：聊天平台接入凭证、大模型 API Key 或本地模型服务
- Docker 部署需挂载数据目录到宿主机
- 插件会引入额外 Python 依赖，建议虚拟环境隔离

---

## 安全

- 不内嵌任何密钥；平台 Token、模型 API Key、HTTP API Key 全部在 WebUI 里配置并存于本地数据目录
- WebUI 默认只监听 `127.0.0.1`；**暴露到公网前必须设强密码**，并建议按官方 Nginx 方案只公开 `/im` 回调路径，把管理台 `/backend-api/` 限制在可信 IP
- HTTP API 服务的 API Key 留空时**所有请求都会被处理**；公网或共享环境下必须填 Key 并带上 `Authorization: Bearer`
- `data` 目录包含配置、记忆与媒体数据，可能含敏感对话内容：做好权限控制与备份，不要提交到仓库
- 机器人以自身身份在群里发言，会真实影响群内秩序；上线前在测试群验证触发条件，避免刷屏
- 使用第三方模型服务与平台接入需遵守各自条款；把模型能力接到群聊场景时，注意内容合规与他人隐私
- 依赖个人号逆向登录的方案不在本项目的推荐路径内，存在账号风险，请勿用于生产
