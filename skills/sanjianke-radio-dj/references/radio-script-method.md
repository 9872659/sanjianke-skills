# 电台串词方法：三段结构、时长换算、字数配额

本文件是 `plan` / `script` 两个子命令的方法论底稿。它解释的是
**为什么提示词长成那样**、**闸门在量什么**，以及**你自己改稿时该守什么规矩**。

---

## 一、电台节目与"一个歌单"的分水岭

同一批歌、同样的顺序，两种产出：

| | 歌单 | 电台节目 |
|---|---|---|
| 开场 | 无（直接进第一首） | 有人告诉你这一期听什么、为什么值得听下去 |
| 歌与歌之间 | 硬切 / 淡入淡出 | 一条过渡把上一首的情绪接到下一首上 |
| 结尾 | 最后一首放完就结束 | 一个能被单独转述的收束句 |

关键点在于：**左边那种产出在任何一道常规质检里都是合格的**——字数对、时长对、
合规干净、读起来也顺。它不报错，只是形态不对。所以本包把
「开场 + 每首前一条过渡 + 结尾」做成**结构闸门**，而不是写在文档里的建议。

### 三段的职责（照这个写，不要写成报幕）

**开场（只有一个）**
把这一期的听觉场景与情绪基调先立住。不是"欢迎收听 XX 节目，今天我们来聊聊……"，
而是直接把人放进场景里：在哪、什么时候、什么状态、这一期陪你走多远。

**过渡 i（每首歌一条，条数 = 歌曲数）**
承接上一首留下的情绪，给出下一首为什么此刻响起的理由。
可以点出歌名与歌手，但**不要把歌名歌手堆在一句话里报完**——那是报幕。

**结尾（只有一个）**
给一个能被单独转述的收束句，让听众知道这一期到此完整了。
不要只是道别（"今天就到这里，我们下期再见"不是结尾，是关麦）。

## 二、时长换算：一期节目是怎么被拆开的

```
目标总时长 T
  ├── 歌曲时长 S = 曲目数 × 曲长
  └── 串词时长 R = T − S        ← 这才是"说话"的时间
        ├── 开场
        ├── 过渡 1..N
        └── 结尾
```

本包的默认口径（都在 `run.py` 的 `SHOW` 表里，改一处全链路跟着改）：

| 口径 | 默认值 | 依据 |
|---|---|---|
| 语速 `chars_per_minute` | **250 字/分钟** | 电台主持人是**独白**（不是播客的双人对白），有停顿、有留白、要报歌名歌手、要跟音乐起落配合；实测落在 220~260，取中位偏上 |
| 曲长假设 `song_seconds_fallback` | **190 秒** | 这是"装得下多少串词"的分母，不是"歌有多长"的事实；拿到本地文件后一律以真实时长为准 |
| 歌曲占比上限 `song_share_max` | **0.75** | 音乐占七成上下是电台常态；再高，串词就只剩报幕的份 |
| 每首最小占用 `min_seconds_per_song` | **300 秒** | 190 秒曲 + 约 110 秒过渡；用来反推推荐曲目数 |
| 时长容差 `duration_tolerance` | **±25%** | 对白语速因人因题能差 15% 左右，25% 留了余量 |

### 推荐曲目数是怎么算出来的

```
推荐曲目数 = (目标分钟 × 60 × 0.75) ÷ 300
```

| 目标时长 | 推荐曲目数 | 留给串词 |
|---|---|---|
| 8 分钟 | 1 首 | ≈ 4.8 分钟 |
| 15 分钟 | 2 首 | ≈ 10.4 分钟 |
| 30 分钟 | 4 首 | ≈ 17.3 分钟 |
| 60 分钟 | 9 首 | ≈ 31 分钟 |

不给 `--songs` 就按这个数走。**这不是最优解，是"装得下"**：
想多放歌当然可以，但那时的正确做法是同步加长节目或调短曲长。

### 反例：30 分钟塞 8 首

```
30 分钟 − 8 首（190 秒/首 ≈ 25.3 分钟，占 84%）≈ 留给串词 4.7 分钟
```

4.7 分钟要装下开场 + 8 条过渡 + 结尾。这不是"参数没调好"，
是**这档规格本身不成立**——所以本包在参数解析处就拦（`exit=2`，不花钱），
而不是等时长台账在写完之后拦。

## 三、字数配额为什么要摊到每一段

实测三次，同一个坑：

| 提示词里写了什么 | 模型写了多少 |
|---|---|
| 只写「目标总时长 30 分钟」 | 771 字（应约 3792 字） |
| 只写「串词合计约 3792 字」 | 623 字 ← 总数它在括号里看到了，但不当回事 |
| **逐段写「开场约 X 字 / 过渡 i 各约 Y 字 / 结尾约 Z 字」+ 句数** | 2499~3226 字，闸门通过 |

结论（同族播客包的定稿口径，本包照抄）：**给模型的约束要落在它能逐项对齐的粒度上**。
只给总数，它会写一半；给到"每段多少字、不少于几句"，它才逐段对齐。

配额表由 `script_quotas()` 生成，上限的口径是：

- **两头（开场/结尾）封在 `open_max_chars`/`close_max_chars` 的 3 倍**：
  再长，"开场"就比一首歌还长，形态又不对了
- **过渡封在 `trans_max_chars` 的 5 倍**：长节目里过渡本来就承担更多内容，
  但"过渡"这个位置的语义决定它不该是一段独白

配额表**不追求各段之和恰好等于目标**。前两版都做过这个回填，结果都一样蠢：
30 分钟只放 4 首时，唯一能装下余数的位置是开场，于是排成
「开场 2052 字 + 4 条过渡 325 字」。配额表的作用是让模型逐段对齐，不是做账；
真正的验收在时长台账那道闸门——它读的是成品稿的真实字数，
对"两头写长一点、过渡写短一点"这种自然分布本来就是容错的。

## 四、改稿时该守的规矩

自己动手改 `script.md` 之后重跑 `voice` / `mix` 时，注意四件事：

1. **段落标题格式不许改**：必须是 `## 【开场】` / `## 【过渡 3】` / `## 【结尾】`。
   闸门读的就是这些标题，改了就读不出结构。手工稿是按**顺序**重编过渡号的，
   但标题的行文格式必须保持。
2. **过渡条数必须等于曲目数**。改了曲目数就重跑 `script`，或给
   `script --songs N` 指明数量。
3. **不要在段落之外留正文**。闸门会把"孤儿正文"判为不合格——那些内容配不出来，
   也没被任何一道检查看过。
4. **改台词就会重配重扣**。配音的断点 key 含正文、音色、语速、模型、格式五项，
   任一项变化都会重新合成那一段（这是刻意的：改了台词却复用旧音频是静默错误）。
