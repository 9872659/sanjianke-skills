# 成本与排错：实测单价、报价口径、六道闸门的退出码

本文件是 `cost` 子命令与所有报错路径的底稿。

---

## 一、实测单价（只放真跑出来的数）

| 端点 | 单价 | 样本 |
|---|---|---|
| `voice_tts/tts` | **50 点 / 千字** | 278 字 → 13.9 点；318 字 → 15.9 点；496 字 → 24.8 点（三组逐条吻合，**无最低消费**） |
| `music_search/search` | **10 点 / 次** | `page_size=3` → 10 点；`page_size=2` → 10 点（**与 page_size 无关**） |
| `music_generation/create` | **65 点 / 次** | 一次 create → `usage.points_cost = 65` |
| `music_generation/lyrics` | 12 点 / 次 | 同族包实测，本包仅登记 |
| `voice_tts/stt` | 40 点 / 次 | 本包没用到，仅登记 |

换算口径：**1 元 = 100 点**（1 点 = 0.01 元）。

### 为什么单价写成常量，而不是现拉

- 平台的 `GET /api/v1/pricing` 只覆盖少数接口，`voice_tts` / `music_search` /
  `music_generation` **都不在**里面
- `/api/v1/apps/<app>` 返回的 `tenant_*` / `pricing_matrix` 字段**实测半数与结算价不一致**

所以本包的口径是「**实测常量做报价，`usage.points_cost` 做对账**」：
每次调用后都把真实扣点打出来，与报价差得明显时明确标出来（`_report_spend`），
不糊过去。

### 文本大模型的单价本包不报

`/api/v1/models` 里**没有任何价格字段**，`pricing` 也不覆盖 `chat/completions`。
所以 `cost` 不给 `--points-per-ktok` 就**只报 token 数、不报金额**——**不编单价**。

## 二、成本前置：报价 → `--yes` 或 `--budget`

```
$ python3 scripts/run.py voice --outdir D:/radio/ep01

=== 配音（1 个片段 / 278 字） 成本前置报价 ===
  · 串词配音 voice_tts/tts                           13.9 点  ≈ 0.139 元
  合计 13.9 点 ≈ 0.139 元（1 元 = 100 点；结算只认 usage.points_cost）
✗ !! 没有确认就开跑：请加 --yes 明确同意，或用 --budget N 封顶。
```

跑前必须报价，且**要么 `--yes` 明确同意，要么 `--budget` 封顶**。
两个都没有 → `exit=2`，**一分钱都不花**。

为什么报价与预算是**两道**而不是一道：

- 没有报价就开跑 = 用户不知道要花多少，被动扣费
- 有报价没预算 = 报价算漏了（稿子比预期长）就会一路花下去

累计对账用**真实 `usage.points_cost`**，不是报价值；超了立刻停（`exit=5`），
并把已经完成的片段落盘（断点续跑不会白花）。

### 30 分钟一期的成本

`cost --minutes 30`（自动推荐 4 首）的口径：

| 项目 | 数量 | 点数 | 金额 |
|---|---|---|---|
| 串词配音 | 约 1900 字 | 约 95 点 | 0.95 元 |
| 选曲（若走在线搜索） | 4~5 次 | 40~50 点 | 0.40~0.50 元 |
| 垫乐（若需要） | 1 次 | 65 点 | 0.65 元 |
| 文本大模型 | — | **未计**（平台未公开，给 `--points-per-ktok` 才计） | — |

## 三、退出码

| 码 | 含义 | 典型成因 |
|---|---|---|
| 0 | 全部干净 | — |
| **1** | 未捕获异常（`--json` 下走 `kind:"internal"` 信封 + 完整 traceback 到 stderr） | 代码 bug——**报 bug，不藏 bug** |
| **2** | 参数/配置/环境错误 | `--outdir` 指到包内、没报价就开跑、缺 ffmpeg、规格装不下、找不到稿件 |
| **3** | 硬闸门命中 | 合规 / 占位符 / 照抄示例 / 串词结构 / 时长台账 |
| **4** | 调用失败 | 网络、鉴权（401）、点数（402）、模型名（404）、音色 ID |
| **5** | 预算超限，已就地中止 | 报价超 `--budget`，或累计扣点超预算 |
| 130 | 用户中断 | Ctrl+C |

## 四、六道闸门各自的排错

### 闸门 1：合规

```
[合规] 「最好」(高/广告法：广告法第九条禁止「最高级」用语)
```

命中高风险就改稿，没有开关可以绕。**「最X」的语境豁免**只放过
「不在句首 + 前一个字是计量类名词 + 后面紧跟「的/之」」这一种形态
（例「播放量最低的视频」），并且会在产出里登记、在 stderr 里明说——
**不静默放过**。句首的「最好/最低」一律不豁免。

### 闸门 2：占位符残留

```
[占位符] 残留了占位符大括号 `{}`，模板没被替换干净
```

通常是把别处的模板稿直接喂进来了。注意本包的 `prompt_hygiene()` 用的是
**比闸门更窄**的一套形态：提示词里的 `{title, host}` 是 JSON 结构说明，
不是"没填干净的模板"——一个为**产出**设计的检查，不能直接拿去扫**输入**。

### 闸门 3：照抄示例

```
[照抄示例] 稿子里的「…」有 100% 的内容来自提示词示例「…」（覆盖度 ≥ 0.60 即判照抄；Jaccard 会随句子变长被摊薄）
```

**模型会照抄示例，哪怕那个示例标着「这是错的写法」**（本库实测两次，
其中一次那条还拿了最高分——不是"真的最好"，是"抄了标准答案"）。
所以提示词里不出现任何一句可直接复制的完整中文句子。清掉那几句重跑。

### 闸门 4：串词结构

```
[串词结构] **缺开场**：成品稿里读不出「【开场】」段。…
[串词结构] 过渡段有 4 条，但歌曲有 4 首——**每条过渡对应一首歌**，数量必须相等…
[串词结构] **缺过渡**：成品稿里一条「【过渡 i】」段都没有。…
[串词结构] 有 3 行**不在任何段落里**的正文（例：「…」）——这些内容配不出来…
```

改稿时最容易踩的是最后一条：在段落之外补了一句话。把它挪进对应段落里。

**过渡编号不连续不会拦**：手工稿会按稿子里的顺序重编 1..N，并在 stderr 提示。
（拦"编号写法不同"只会让一份内容完整的稿子白跑一轮配音。）
真正拦的是**条数**——少一条过渡就意味着有一首歌是硬切进去的。

### 闸门 5：时长台账

```
[时长台账] 串词 1554 字 ÷ 250 字/分钟 ≈ 6.2 分钟；4 首歌 ≈ 12.7 分钟；
合计 ≈ 18.9 分钟；目标 30.0 分钟，容差 25%（22.5~37.5 分钟）
```

三种成因，处理方式不同：

| 症状 | 成因 | 处理 |
|---|---|---|
| 字数远低于配额 | 模型写少了 | 重跑 `script`；换模型；调大 `--max-tokens` |
| 怎么算都差一截 | 语速口径不对 | `--chars-per-minute` 改成你的值（闸门与报价会一起改） |
| 歌曲那一段偏了 | 曲长假设值 | `--song-seconds` 给真实平均曲长，或先 `pick` 拿到本地文件 |

**注意**：拿不到本地音频文件时，曲长用的是**假设值**（默认 190 秒/首），
产出里会标 `song_seconds_source: assumed`。只有 `mix` 报出的时间轴是真实时长。

### 闸门 6：成本上限

```
✗ !! 报价 150 点已超过 --budget 100 点，就地中止（还没花钱）。
```

**先报价后扣费**：报价超预算时一分钱都没花。跑到一半才超预算时，
已经完成的片段会落盘，`exit=5` 退出，重跑会跳过它们。

## 五、平台错误码

| 码 | 含义 | 处理 |
|---|---|---|
| 401 | Key 无效或已过期 | 重新到 https://api.a7w.cn/ 领一个 |
| 402 | 点数不足 | 充值后重试（失败任务平台会退回点数） |
| 404 | 模型不存在 | `run.py models` 现查在架名字。**`deepseek-chat` 实测可用但它不在列表里**——"列表里没有"不等于"不能用"，也不等于"有价格" |
| 429 | 限流 | 本包自动退避重试（3s / 6s / 9s） |
| 502/503/504 | 上游抖动 | 本包自动退避重试；实测网关 `upstream timeout` 很常见 |

## 六、三条容易踩的接口口径

1. **`/chat/completions` 的成功响应不带 `code`**；生成应用（配音 / 选曲 / 配乐）
   **`code == 1` 才是成功**。两者不能互相套用。
2. **异步任务的 `status` 在任务 `data` 顶层**，不在 `data.result` 里（平台文档写错了）。
   实测原文：`data.status = 'completed'`、`data.result.status = None`。
3. **`music_search` 的 `usage` 在 `data` 里**，不在 `data.result` 里。
   本包的 `points_of()` 会把 `usage` / `data.usage` / `result.usage` 三个位置都试一遍。

## 七、`--json` 契约（给流水线与 agent 消费）

```bash
# 成功：stdout 只有一个 JSON 文档，带 "ok": true
python3 scripts/run.py cost --json --minutes 30 > out.json

# 失败：{"ok": false, "exit": N, "error": {"kind": "...", "message": "..."}}
python3 scripts/run.py voice --outdir D:/radio/ep01 --json
```

- **`--json` 写在子命令前后都认**（`cost --json` 与 `--json cost` 等价）
- `kind` 取值：`usage` / `gate` / `call` / `budget` / `interrupt` / `internal`
- **`internal` 是未预料异常**：stdout 给信封，**完整 traceback 原样打到 stderr**——
  报 bug，不藏 bug
- `all --json` 会把子步骤产出收集成**一份**再吐（不收集的话 stdout 会出现多个
  JSON 文档，`json.loads` 直接 `Extra data`）
