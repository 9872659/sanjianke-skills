## 前置条件

- 一台 amd64（x86_64）架构的机器；原生 arm64 镜像尚未就绪，Apple Silicon 上性能会明显受影响。
- 已安装 Docker 与 Docker Compose v2；一个带 curl 等基础工具的 bash 环境。
- 资源建议 4 CPU / 8GB 内存以上，磁盘按数据量与附件量单独规划。
- 宿主机 80 / 443 端口可用于容器映射（或改用其他端口并在 `.env` 里调整）。
- 若要从别的机器访问，需要准备对外地址（域名或 IP）与反向代理 / 网关配置。
- 若要用邮件、短信、第三方登录等能力，需要各自的账号与配置——这些默认不启用。

## 使用

1. **先想清楚是不是真的自托管**：只想试功能就用官方托管版本或演示环境，能省掉整套组件运维。
2. **正式部署走官方安装脚本**：`curl https://apitable.github.io/install.sh | bash`，跑完访问 `http://localhost:80`；首次启动要等几分钟让初始化容器跑完。
3. **只用仓库 Compose 自行部署时**：仓库自带 `docker-compose.yaml` 与 `.env` 模板，先按自己的环境改好 `.env`（口令、端口、时区、对外地址、存储配置），再执行 `docker compose --env-file .env -f docker-compose.yaml up -d`。
4. **演示可用 all-in-one 镜像**：`sudo docker run -d -v ${PWD}/.data:/apitable -p 80:80 --name apitable apitable/all-in-one:latest`。该镜像仅 amd64，**不要用于企业或生产**。
5. **进界面后的顺序**：建空间 → 建表与字段 → 加视图 → 配行/列权限 → 需要给系统调用就打开 API 面板取调用方式 → 需要自动化就配机器人。
6. **变量与命令以仓库当前文件为准**：`.env` 的变量名和 Compose 的服务名会随版本变化，改配置前先读一遍文件本身。完整排查表见 `SKILL.md`。

## 依赖

- **容器运行时**：Docker + Docker Compose v2。
- **部署编排包含的组件**：Web 服务、后端服务、Room 服务、数据总线服务、网关（对外暴露 80 / 443）、MinIO（对象存储）、MySQL、Redis、RabbitMQ，以及 `init-db`、`init-appdata` 两个一次性初始化容器。
- **持久化**：MySQL 数据、MinIO 对象与配置、Redis 数据、RabbitMQ 数据都落在 `${DATA_PATH}/.data` 之下，务必用绝对路径且不要随启动目录变化。
- **外部服务（可选）**：邮件服务、短信服务、第三方登录、外部自动化编排工具。
- **网络**：拉取镜像出网；若从外部访问，需要入站可达并正确配置对外地址变量。

## 安全

- 不内嵌任何密钥；数据库、缓存、消息队列、对象存储的口令全部由使用者在 `.env` 中提供。
- `.env` 模板里带的是示例口令，**上线前必须全部替换**；该文件不要提交到代码仓库。
- 关闭或收紧跨域来源限制：模板里给的是宽松值，对外服务时应改成真实的前端来源。
- 生产环境不要保留测试用的注册校验跳过开关，也不要使用 all-in-one 演示镜像。
- 对外只暴露网关端口，MySQL / Redis / RabbitMQ / MinIO 等组件端口不要直接映射到公网。
- 附件默认存在对象存储里，定期检查桶的读写策略，避免上传内容被公开列举。
- 启用反向代理时记得配置 TLS，并确认客户端访问的是加密地址。
- 数据与附件目录需纳入备份计划；升级前先备份再动容器。
