# 三剪客 · BGE 向量检索与重排序工具箱 Skill

做语义检索和 RAG 重排时用得上的向量工具箱：装法、各类模型的加载方式、检索指令与归一化的正确用法、微调入口，以及分数异常时该先查什么。

---

## 前置条件

- 一个可用的 Python 环境与 PyTorch；具体版本区间以仓库打包文件与官方文档为准。
- 只手推理的话，`pip install -U FlagEmbedding` 就够，不需要装微调依赖。
- **GPU 强烈建议**：编码和重排序都是模型前向计算，CPU 能跑但慢；`use_fp16` 这类加速参数依赖 GPU。
- 首次使用需要联网从模型托管站下载权重，按模型规模从几百 MB 到数 GB，请预留磁盘与时间；完全离线的环境要提前准备好本地权重路径。
- 不需要账号或 API Key（拉取私有模型仓库除外）。
- 要微调的话，额外需要 `[finetune]` 附加依赖和足够的显存。

---

## 使用

1. 先判断这次是「建索引」还是「重排序」——前者用 embedder 编码向量，后者用 reranker 对候选打分，两条路线的模型和接口都不一样。
2. 选模型：中文语料用 zh 系列，多语种语料用多语种系列，要同时具备稠密/稀疏/多向量检索就用支持多表示的模型。
3. 编码时守住一条铁律：**短查询侧加检索指令，段落侧不加**，直接用 `encode_queries` / `encode_corpus` 分工最稳妥。
4. 算相似度按所加载模型当前的官方示例来做（是否归一化、是否要乘缩放系数因家族而异），跨模型只比排序、不比绝对分值。
5. 要重排序就上交叉编码器模型，只排序用原始 logits，要阈值判断再加 `normalize=True`。
6. 加载自己微调的模型必须显式给 `model_class`；不确定用哪个封装类就走自动类。
7. 微调与评测走仓库 `examples/` 下的脚本，参数以脚本 `--help` 和官方文档为准。完整示例见 `SKILL.md`。

## 依赖

- 上游仓库：https://github.com/FlagOpen/FlagEmbedding
- 核心依赖：Python + PyTorch。
- 可选附加依赖：`FlagEmbedding[finetune]`（微调与评测所需的训练侧依赖）。
- 模型权重：按模型名从模型托管站按需下载，不随包分发。
- 替代接入方式：sentence-transformers、transformers、LangChain（各自独立安装）。
- 不含向量数据库：索引存储与在线检索要另外接一个向量库。

## 安全

- 不内嵌任何密钥；公开模型不需要任何 Token。
- 网络出站只发生在下载模型权重与公开数据集时；生产环境建议预置离线权重，避免运行时对外发起请求。
- 权重仓库可能要求加载其中的自定义建模代码（`trust_remote_code` 一类机制），这等同于执行远端代码：只对可信来源开启，并尽量固定到具体版本而不是跟随主干。
- 微调会读取你自己的业务语料：确认语料授权范围，并注意编码产物与缓存目录里的内容是否需要按数据合规要求清理。
- 检索与重排序结果会进入下游决策，建议保留可回溯的原始段落引用，不要把模型分数当作事实判断。
- 评测脚本可能把数据或结果写到工作目录，容器化部署时注意挂载范围，避免把宿主机敏感目录写进去。
