# 三剪客 · 即时通讯服务端 Skill

自建 IM 服务端的协议选型、部署、消息可靠性与集群扩展实战

---

## 前置条件

| 项 | 要求 |
|---|---|
| 运行时 | Java 8 兼容 JRE（自建 IM 服务端多为 Java 8 字节码产物） |
| 构建工具 | Maven 3.x（源码编译路线需要） |
| 数据库 | 内置嵌入式库（验证/小规模）或 MySQL 5.7+（生产建议），MySQL 事务隔离级别须为 `READ-COMMITTED` |
| 容器（可选） | Docker 20.10+ |
| 服务托管（可选） | Linux + systemd |
| 主机资源 | 单节点验证 512MB 内存起；生产按在线连接数与消息吞吐压测后定 |
| 客户端 | 任一支持该协议栈的开源客户端，用于联调 |

---

## 使用

1. **先定形态**：读 `references/deployment.md` 第一节，按规模与合规要求选单机 / MySQL 单机 / 集群 / 容器化。
2. **定端口与目录**：同一份文件第二、三节给出端口职责划分与目录规划，以及必须可写的目录清单。
3. **跑通最小闭环**：按 `SKILL.md` 的「快速开始」四步走，先让 `curl http://<host>/api/version` 返回 JSON。
4. **接协议**：读 `references/protocol-and-message-model.md`，确认消息 ID、会话序号、ACK 语义、离线补偿窗口。
5. **上规模与运维**：读 `references/cluster-and-ops.md`，配置集群成员发现、监控告警、备份与恢复演练。

排错时直接跳 `references/cluster-and-ops.md` 第八节的故障排查决策树，按现象定位。

---

## 安全

- 不内嵌任何密钥、Token、Cookie
- 不留存、不上传用户的会话数据、账号数据、数据库口令
- 管理接口密钥、token 签发密钥等敏感项**只给替换指引，不给默认值**——默认示例值是公开的，照抄等于没有鉴权
- 推荐把含密钥的配置文件设为 `chmod 600`，不要写进命令行参数或镜像层
- 容器化部署时，配置文件必须显式挂载，避免把调试用配置带上生产
- 文中不给出可直接使用的生产口令；所有口令占位符都需要你替换
